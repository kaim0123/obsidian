# ノート（md）→ 解説HTML

`docs/<章>/` のノートを読み、`public/<章>/` に解説HTMLを作る。お手本は 71〜74章（共通CSSを読むページ）。41章は CSS をページに埋め込んだ古い形式なので、新しく作るときは真似しない。

## 0. 前提（このリポジトリの決まりごと）

- 原本：ノートは `docs/`、解説HTMLは `public/<章>/`。`docs/` のノートは書き換えない（N-06）
- サイト（Astro）は `public/` をそのまま配信する。`public/<章>/*.html` は自動でトップの一覧に載り、配信時だけ全体ナビ（`/_site/site-nav.js`）が差し込まれる。**HTML 側にサイトへの依存（`/_site/…` など）は書かない**
- 見た目のテーマは `node scripts/apply-explainer-theme.mjs` が `public/_解説HTML/style.css` に書き込む。**ページにも style.css にも手で色を書かない**
- 使えるクラスは `public/_解説HTML/style.css` にあるものだけ（部品の書き方は [references/components.md](references/components.md)）

## 1. 準備：ノートを読んで構成を決める

1. `docs/<章>/` を一覧する（`00_全体像/MOC_*.md` があれば最初に読む）。フォルダ構成は `10_xxx`、`20_xxx` … のように番号付き
2. 対象フォルダのノートを**全部読む**。動画メモ・書籍メモ・自分のまとめが同じテーマで複数あることが多い
3. ページ割りを決める：**1ページ＝1テーマ（ノート1〜数本をまとめる）**。重複するノートは1ページに統合し、もとにしたノートを全部 `meta` と「参考資料」に書く
4. ページ割りの案（ファイル名・もとにするノート・1行説明）をユーザーに見せてから書き始める。章まるごと作るときは特に

### ファイル名

- 置き場：`public/<章フォルダ名>/`（例：`public/75_セキュリティ教養/`）。docs と同じ章フォルダ名にする
- 目次：`00-0_目次.html`、全体像：`00-1_<章テーマ>の全体像.html`
- 各ページ：`<フォルダ番号>-<通し番号>_<タイトル>.html`（例：`10-1_Cookieの仕組み.html`、`30-2_JWTの構造と検証.html`）
- フォルダ番号は docs のフォルダ番号（`10_クッキー` → `10`）。ファイル名の数字順＝読む順になるようにする
- 「解説_」などの接頭辞は付けない。空白は使わない（`・` や全角文字は可）

## 2. ページを書く

[references/template.html](references/template.html) をコピーして埋める。骨組み（topbar / layout / toc / hero / pager / script）は変えない。

### パス（重要）

ファイルは `public/<章>/` 直下に置くので、**1階層上がるだけ**：

| 参照先 | 書き方 |
|---|---|
| 共通CSS / JS | `../_解説HTML/style.css`、`../_解説HTML/script.js` |
| 同じ章のページ | `10-1_Cookieの仕組み.html` |
| 他の章のページ | `../72_Web脆弱性対策/20-1_XSSの基本.html` |

既存の 71〜74章には `../../_解説HTML/…` や `../../72_Web脆弱性対策/00_全体像/…` という古い書き方（docs の `00_全体像/` に置いていた頃のもの）が残っている。**新しいページでは真似しない**。

### 内容のルール

- 初心者向け、です・ます調
- **元ノートの内容は削らない**。ノートにない内容は最小限（補うなら公式ドキュメント・RFC など出典を参考資料に書く）
- 専門用語は初出で一言説明する（例：「**共有ストア**（複数のサーバーから使える共通の置き場）」）
- 冒頭（hero の直後）に `callout key`「ひとことで言うと」を置く
- `h2` は `<span class="num">1.</span>` で番号付き、`id="sec-1"`。`h3` は `1.1 …` で `id="sec-1-1"`
- 最後の `h2` は順に「まとめ」「理解度チェック」（`details` で 5〜8問）「参考資料」（番号なし、`id="sources"`）
- 図は流れ・位置関係を示す箇所だけ。インラインSVG、1ページ0〜3枚、`d-*` クラスのみ使用（色を直接書かない）。`aria-label` に図の内容を文章で書き、`figcaption` を付ける
- それ以外は文章・表・カード・コード比較（`code-label bad`「✕ 危険な例」／`code-label good`「◯ 安全な例」）で表す
- コード内の `<` `>` `&` はエスケープする
- **他の章と重なる内容は書き直さずリンク**する（71〜75 のセキュリティ系、41〜48 の設計系など）。リンク先が存在するか確かめる
- 動画・記事の URL はノートに書いてあるものをそのまま参考資料に載せる

### 前後ページ送り（pager）

- ファイル名の数字順でつなぐ。`00-0_目次` → `00-1_全体像` → `10-1` → … → 最後
- 目次ページ：左は `<span class="empty"></span>`、中央は `<span class="idx">目次</span>`
- 最後のページ：右は `<span class="empty"></span>`
- **ページを足したら、前後のページの pager も直す**

## 3. 目次ページ（00-0_目次.html）

既存の `public/74_セッション管理/00-0_目次.html` を見本にする。

1. 「このサイトの読み方」＋ `h3` おすすめの読む順（`ol.steps`、フォルダごとに1行）。隣の章へのリンクもここに書く
2. フォルダごとに `h2`（例：`3. 10 クッキー`）＋1文の説明＋表（ページ｜内容）。内容欄はそのページで扱う項目を「、」で並べる
3. 最後に「関連するフォルダ」の表（他の章の目次へのリンク）
4. 目次ページにはまとめ・理解度チェックは不要

ページを足したときは目次の表にも行を足す。

## 4. 確認

1. 検査スクリプトを実行し、エラーが無くなるまで直す：
   ```
   node .claude/skills/md-to-explainer-html/scripts/check.mjs public/<章>
   ```
   見るもの：リンク切れ・未定義クラス・必須見出し・pager の前後・目次への載せ漏れ・SVG の marker id 重複・古い `../../` パス
2. テーマを当てる：`node scripts/apply-explainer-theme.mjs`
3. ブラウザで表示して、図の崩れ（文字のはみ出し・矢印の向き）を見る：`npm run dev` → `http://localhost:4321/<章>/00-0_目次.html`。トップ（`/`）の一覧に章が出ていることも確認
4. ユーザーへの報告：作ったページ一覧、もとにしたノートの対応、ノートに無く補った内容、検査結果
