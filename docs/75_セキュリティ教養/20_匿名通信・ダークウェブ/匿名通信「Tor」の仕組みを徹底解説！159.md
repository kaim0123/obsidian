## 詳しい要約

**テーマ：インターネットに匿名性がない理由と、Tor（オニオンルーティング）が匿名通信を実現する仕組み**

インターネットは IP アドレス付きの「送り状」をすべてのパケットに付けて送るため、原理的に匿名ではない。Tor は、複数の中継者それぞれにしか開けられない暗号で玉ねぎのように何重にも包むことで、「誰と誰が通信しているかを全部知る者が誰もいない」状態を作る。宅配便（アダルトグッズ通販）のたとえで解説する回。

---

### インターネットは匿名ではない

- 匿名アカウントで書き込んでも **IP アドレス開示請求** で個人が特定され、慰謝料を請求されることがある。
- **IP アドレス** はインターネット上の住所のような数字の組み合わせ。URL（ドメイン）は IP アドレスに対応づけられている。QR コードは URL を符号化したものにすぎない。
- ネットにつながる機器（PC・スマホ・テレビ・加湿器などの IoT 機器）はすべて IP アドレスを持つ。IPv6 のアドレスは 16 進数で表記される。

### パケット通信の仕組みと弱点

- データは **パケット**（小包）に細切れにされ、空き具合に応じてバラバラのルートで送られ、受け手側で連番を頼りに復元される。
- 電話のように最初に回線を確立して常時つなぐ方式とは逆で、一見非効率だが、回線確立が不要・一部の経路が切れても迂回できるという点で通信のブレイクスルーになった。
- ただし、全パケットに **送り主と送り先が書かれた送り状** が付いているため、原理的に匿名性がない。
- HTTPS（SSL）で暗号化されるのは **中身だけ**。送り状まで暗号化すると中継者が次にどこへ送ればいいか分からなくなるので、送り状は暗号化できない。
- たとえ：中身は南京錠付きのアタッシュケースで守られていても、送り状に「H ショップ」と書いてあればバレる。独裁国家の住人が外国と通信していることが知られるリスクなども同じ構造。

### 匿名通信のトリック（宅配便のたとえ）

- 運送業者が「自社だけが開けられる鍵」を提供し、届いたケースを開けて中の送り状に従って転送するサービスを考える。
- 業者が 1 社だけだと、その業者が「どこから来てどこへ行くか」を両方知ってしまう。
- 解決策：**中継業者を 2 社以上挟む**。
  - 佐川の鍵で閉めたケースを、さらにヤマトの鍵で閉める（マトリョーシカ状）
  - ヤマトは外側を開けて「佐川へ送れ」と知るだけ。佐川は「受け手へ送れ」と知るだけ
  - 外側のケースは捨てられていくので、各業者は **直前と直後しか知らない**
- 闇バイトや特殊詐欺が中継役を増やして全貌を隠すのと同じ発想。中継を 10〜20 と増やし、国をまたげば追跡は事実上不可能になる。
- 厳密には「原理的に匿名」ではなく、**全貌を明らかにするコストが極めて高い** 仕組み。
- 送り手が受け手の住所を知らなくて済むよう、最後の地元業者だけが分かる「あだ名」（ドメイン名のようなもの）で宛先を指定するイメージも示される。

### Tor の実際

- この方式は **Tor（The Onion Router）** という通信規格。玉ねぎの皮をむくようにパケットの暗号を 1 層ずつ外していくことが名前の由来。
- 中継者は正確には **ノード**（ここではルーターと理解してよい）。ネットワーク用語は同じものを何通りにも呼ぶので混乱しやすい。
- 普段使っているのは **IP（インターネットプロトコル）**。Tor は専用の **Tor ブラウザ** をインストールすれば使える。
- 欠点は **遅いこと**。特に最初の「接続を確立しています」（経路と鍵の準備）に時間がかかる。
- 普通の人にとっては、IP アドレスから個人情報をたどるにはプロバイダへの開示請求が必要で、それが認められるケースはまれなので、現実的には気にしなくてよい範囲。ただし IP アドレスは変わりうるので公開はしない方がよい。
- 厳密に定められた一連の手順はすべて **アルゴリズム** であり、Tor も「巧妙なトリック」の一例。
- 次回予告：この技術で作られた、普通の人が目にしないネットの世界 **ダークウェブ** を扱う。

### まとめ

- インターネットの匿名性のなさは、全パケットに送り状を付けるパケット通信の方式そのものに由来する。
- HTTPS が隠すのは中身だけで、「誰が誰に送ったか」は隠せない。
- Tor は複数の中継者に別々の鍵で多重暗号化し、各中継者が前後しか知らない状態を作って匿名性を実現する（代わりに遅い）。
