## 詳しい要約

### エピソードの位置づけ

「ハッキングって具体的に何をやっているのか」を、**防御のための知識**として解説する回。ニュースでよく見る「脆弱性を攻撃され個人情報が流出」——その**攻撃者の作業内容**を、代表的な手法から順に紹介する。**他人のマシンへの攻撃は犯罪**であり、推奨ではない（全ての参考資料にも同様の断りがある）。

### ハッキングの本質：見えない内部を想像する

ログインやフォーム入力は、ユーザーには見えない**サーバー内部の処理**（SQL文など）を動かしている。ハッキングは、その内部構造を**推測し、意図しない入力で挙動を変える**作業。鍵ピッキングのように「この音がするなら内部はこうなっているはず」と**想像力**から始まる——これがハッキング精神の第一。

### SQLインジェクション（今回のメイン）

**最も典型的な攻撃**の一つ。ログインフォームに特殊な文字列を入力し、内部のSQL文を改変する。

**通常のログイン処理（イメージ）**：

```sql
SELECT * FROM users WHERE email='入力メール' AND password='入力パスワード'
```

登録ユーザーの表から、メールとパスワードが一致する行を取ってくる——これがログイン。

**攻撃例**：メール欄に `' OR 1=1 --` を入力

- シングルクォート `'` でメールアドレスの記述を**途中で閉じる**（小説でセリフの `"` を閉じて以降の叙述を自由に操る発想と同型）。
- `OR 1=1` は**常に真**になる条件。
- `--` は以降を**コメントアウト**（パスワード条件を無視）。

結果、**条件に合う最初のユーザー**（多くの場合ユーザー番号1番＝**管理者**の可能性）でログインできてしまう。任意のユーザー指定も可能。

**防御策**：

| 方法 | 内容 |
|------|------|
| **サニタイズ** | シングルクォート等の危険文字を入力不可にする |
| **入力制約** | `@` 必須など、変な入力を減らす |
| **プリペアドステートメント** | SQL文を固定し、入力は**データとしてのみ**受け付ける。**最強の対策** |

### インジェクション系攻撃の共通点

SQLインジェクションに限らず、**入力フォームに命令を紛れ込ませる**攻撃が多数存在する。

- **XSS**（クロスサイトスクリプティング）
- **OSコマンドインジェクション**
- **ディレクトリトラバーサル**

入力フォームを安全に作るのは難しい。昔のWebサイトは脆弱性まみれだったが、**WordPress**・**Ruby on Rails** 等のテンプレートエンジンやフレームワークは、多くの対策を**自動で**行ってくれる。Googleフォーム等も当然想定して防御している。

### パスワード攻撃：堀本さんになりすますには

ゆるゲ語学ラジオのログインフォームを例に、堀本さんのアカウントへの侵入方法を検討。

1. **ソーシャルエンジニアリング**（現在最強）
   - 人との会話からパスワードの傾向・関連情報を聞き出し絞り込む。
   - **守り買い**：常にパスワードの法則性を漏らさない。

2. **ブルートフォース（総当たり）**
   - 0, 1, 2…と全組み合わせを試す。ダイヤル錠と同型。
   - 1文字94種（英大小＋数字＋記号）×8桁 ≒ **一兆通り**——現実的ではない。
   - ログイン失敗回数制限がなければ理論上可能だが、非効率。

3. **辞書攻撃**（実用的）
   - **rockyou.txt** 等、過去のパスワード流出事件（LinkedIn約3200万件等）から作られた**実績のあるパスワードリスト**を上から試す。
   - 人はランダム文字列より**ありがちなパスワード**を使うため、総当たりより圧倒的に効率的。

**rockyou.txt のパスワードランキング（例）**：

| 順位 | パスワード |
|------|-----------|
| 1位 | 123456 |
| 2位 | 12345 |
| 4位 | password |
| 5位 | iloveyou |
| 他 | princess, monkey, lovely, jessica 等 |

日本人なら **「開けゴマ」** も辞書に載りそう。`I love you` の次に `princess` が来るなど、英語圏のロマンチックさが浮かぶ。

**Hydra（ヒュドラ）**：辞書を使って自動でパスワードを大量試行するツール。ギリシャ神話の首が何本も生える怪物にちなむ。**擬似環境（攻撃OKの練習用マシン）** で試した体験談あり。

### ハッキング精神 第二：トライアンドエラー

空振りしまくるのが当たり前。**諦めずに試し続ける**ことが重要。ただ闇雲な総当たりではなく、**辞書攻撃のような工夫**で効率化する——泥臭さと頭の良さの両立。

**ユーザー側の防御**：

- `iloveyou` 等の**よくあるパスワードを使わない**
- **パスワードマネージャー**でランダムな長い文字列を生成（Chrome等でアカウント同期すればPC・スマホ間も共有可能）
- **同じパスワードを使い回さない**——1回流出すると辞書に載り、即突破される
- **haveibeenpwned.com** 等で、自分のメールアドレスが過去の流出事件に含まれていたか確認

### ハッキングの参入障壁は驚くほど低い

- **『7日間でハッキングを始める本』**——Day1準備、Day2初ハッキング…と優しく段階的
- **ハッキング用OS**（Kali Linux等）：Hydra、**Metasploit** 等のツールが最初から入っている
- **Metasploit**：既知の脆弱性に**ワンコマンド**で攻撃できる超強力ツール。知識ゼロでも他人のマシンを攻撃可能——一見「社会にとって危険」に見える

### Metasploitの理念：オープンにした方が安全

1980年代の**隠蔽によるセキュリティ**（脆弱性情報や攻撃ツールを隠せば安全）→ 破壊的な混乱が繰り返され、**オープンにした方が良い**という思想へ。

**Metasploitを公開する理由**（大麻合法化の議論と同型）：

- ダークウェブでは攻撃キットは**既に溢れている**
- 違法化・秘匿化すると、**真面目なセキュリティ担当者が試せなくなる**
- **ペネトレーションテスト**（侵入テスト）・**ペンテスター**という職業が、Metasploit等を使って攻撃を試し、防御を強化する
- トップページの理念：**「知識こそ力なり（Knowledge is power）」**——共有された知識はより強い力になる

**性教育との類似**：隠して黙っていたせいで不幸が生まれた → オープンに教える方が社会全体のため、という流れと同じ。

### 現代セキュリティの考え方

- **攻撃側の視点を理解しないと、何を守ればいいか分からない**
- 攻撃用ツール・本・練習サイト（「攻撃していい」と明示されたもの）を**意図的に公開**している
- セキュリティ担当者はまず**攻められる側**を学ぶ——攻撃こそが防御の第一歩
- 『ハッキング 美しき作望』等の本も、**防御のため**の理解を目的としている

### まとめ

ハッキングは**想像力**と**トライアンドエラー**から始まり、SQLインジェクション・辞書攻撃など具体的な手法がある。参入障壁は低く、ツールも本もOSも手に入る。しかし現代のセキュリティ思想は、それらを**オープンに共有**することで防御側が一歩先を行ける——**オープンソース思想**がセキュリティの世界でも機能している、という結論。
