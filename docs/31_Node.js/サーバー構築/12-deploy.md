## デプロイとは？
- 開発したアプリケーションを本番環境に公開・運用すること
- サーバー構築、環境変数、プロセスマネージャ、CI/CDなどが関係

## デプロイの流れ
1. 本番用ビルド・依存関係のインストール
2. サーバーへのアップロード
3. 環境変数の設定
4. プロセスマネージャで起動・監視
5. ドメイン・SSL設定

## よく使われるデプロイ先
| サービス | 特徴 |
|----------|------|
| Vercel/Netlify | 静的・サーバーレス向け、無料枠あり |
| Render | Node.js公式サポート、無料枠あり |
| Heroku | 簡単デプロイ、無料枠縮小傾向 |
| AWS EC2 | 柔軟・本格運用向け |
| VPS（さくら等） | 自由度高いが管理も必要 |

## 環境変数の管理
- `.env`ファイルやサーバー側の設定で管理
- `dotenv`パッケージで読み込み

```bash
npm install dotenv
```

```javascript
require('dotenv').config();
const port = process.env.PORT || 3000;
```

## プロセスマネージャの活用
- サーバーの自動再起動・監視・ログ管理
- 代表例：PM2

```bash
npm install pm2 -g
pm run build # 必要に応じて
pm start    # または pm2 start app.js
```

### PM2の基本コマンド
| コマンド | 説明 |
|----------|------|
| pm2 start app.js | アプリ起動 |
| pm2 stop app | 停止 |
| pm2 restart app | 再起動 |
| pm2 logs | ログ確認 |
| pm2 list | プロセス一覧 |
| pm2 monit | モニタリング |

## CI/CDの導入
- GitHub ActionsやGitLab CIで自動テスト・自動デプロイ
- 例：mainブランチpushで自動デプロイ

## ログ管理・監視
- PM2ログ、外部サービス（Datadog, Sentry, NewRelic等）
- エラー通知やパフォーマンス監視

## バックアップとリカバリ
- データベースの定期バックアップ
- サーバー設定や.envファイルのバックアップ

## 練習問題
