## 詳しい要約

**テーマ：ブラウザと CDN の写し（キャッシュ）は、いつ使われ、いつサーバーに聞きに行くのか**

キャッシュは速さの味方だが、デプロイ後の不具合や情報漏れの原因にもなる。すべては「写しがどこに、いつまで残るか」の1点に集約される。期限内は聞きに行かず、期限が切れたら「変わった？」と確かめる（304）のが基本で、デプロイ事故は**ファイル名に中身の指紋を入れて長い期限をつける**ことで、個人情報の漏れは **private** で防ぐ、という回。

---

### よくある場面

- デプロイしたのに「直っていない」と言われ、自分の画面では再現しない。キャッシュを消してもらうと直る
- 画像を差し替えたのに古い画像が出続ける
- 逆に写しが効いていないと、人が集まったときにサーバーが重くなる

### 写しの置き場

- 登場人物は **ブラウザ・CDN・元のサーバー**。CDN は利用者の近くに置かれた写しの置き場で、各地域にあり近い場所が答える
- 初回は CDN に写しがないので CDN が元のサーバーへ取りに行き、200（どうぞ）で本体が返る。帰り道で **CDN とブラウザの2か所に写しが残る**

### 期限内は聞きに行かない

- 期限内に同じページを開くと、ブラウザは手元の写しで即答。ネットに一度も出ず、サーバーは開かれたことすら知らない（最速・最安）
- 別の人 B さんが初めて開いても、CDN に写しがあれば CDN がその場で答える
- **ブラウザの写しは自分だけ、CDN の写しはみんなで共有**。1万人が開いてもサーバーに来るのは最初の1回だけ、ということもあり、急な集中に強い

### 期限はサーバーが書いて渡す

- 返事のヘッダーの **Cache-Control** で指定。`max-age=86400` は1日聞かずに使ってよいという意味
- **no-cache** は「持っていてよいが、使う前に毎回確かめて」。本当に持たせたくないときは **no-store**（名前と意味が逆っぽく紛らわしい）
- **ETag** は中身から作った目印で、中身が変われば変わる

### 期限が切れたら「変わった？」

- 期限切れでも捨てずに、手元の目印を添えて「この目印のを持っています、変わりましたか？」と聞く
- 同じなら **304（変わっていない）**。本体を含まない短い返事なので軽く、期限がもう一度延びる
- 変わっていれば **200** で新しい本体が返る
- 裏を返すと、**期限内はサーバー側が変わっても気づかない**

### デプロイ後に古い JS が残る事故

- HTML は毎回確かめる、JS は1日持つ設定のとき、新しい HTML が新しい JS にしかない関数を呼ぶデプロイをする
- 利用者が開くと HTML は新しくなるが、JS は手元の写しが期限内なので古いまま → ボタンを押しても何も起きない
- 人によって写しの期限が違うので、壊れる人と大丈夫な人がいる。開発者はキャッシュを消すと直るので気づきにくい
- 強めの再読み込みをしても、**CDN が多くの場合自分の古い写しを返す**。しかも共有の置き場なので、初めて開く人にも古い JS が配られ被害が全員に広がる
- CDN に写しを捨てさせる **パージ** は対策の1つだが、毎回忘れず行う人の注意に頼る仕組みで、ブラウザの写しは捨てられない

### 名前に中身の指紋を入れる

- ビルドツールが中身から作る短い文字（ハッシュ）をファイル名に付ける。中身が1文字でも変われば名前も変わる
- 指紋付きファイルには **1年など長い期限**をつける（同じ名前なら中身は必ず同じなので確かめる必要もない）
- **HTML は毎回確かめる**。HTML の中に指紋付きの名前が書いてあるので、新しい HTML が新しい名前の JS を求め、どこにも写しがないのでサーバーから一発で届く
- 古い写しは誰にも呼ばれなくなるだけ。「古いのを消す」のではなく「新しい名前で呼ぶ」発想で、パージも人の注意もいらない
- 事故の根っこは「**名前が同じなのに中身が違う**」こと

### 人ごとの中身を共有の置き場に置かない

- ログイン後のマイページに速さのため10分の期限をつけると、CDN が A さんの名前・住所入りのページを写しに取る
- 3分後に B さんが同じアドレスを開くと、**A さんのページが B さんに見える**。CDN は誰のページか区別しない。表示の不具合ではなく**個人情報の漏洩事故**
- 人ごとに中身が違う返事には **private**（本人のブラウザだけが持ってよい）。CDN などの共有の置き場は写しに取らない。ブラウザにも残したくなければ **no-store** も付ける
- 期限をつけるときは、それが誰の中身かを先に確かめる

### AIに書かせたときのチェックポイント

1. 返事にキャッシュの期限の指定が付いているか（付いていないとブラウザや CDN が自分の判断で持つことがある）
2. 人ごとの返事に private や no-store があるか（「速くして」と頼むと AI は全部に期限をつけることがある）
3. 長い期限をつけたファイルに指紋付きの名前があるか
4. HTML は毎回確かめる設定になっているか（入り口が新しければ、残りも指紋付きの名前で新しくなる）

### まとめ

- 写しの置き場はブラウザ（自分だけ）と CDN（みんなで共有）
- 期限内は聞かない、切れたら「変わった？」と聞く（304 なら使い続け、200 なら差し替え）。no-cache は毎回確かめる、no-store は持たない
- ファイル名に指紋を入れて長い期限、HTML だけは毎回確かめる → デプロイ後の古い JS は起きない
- 人ごとの中身は private で、共有の置き場に置かない（CDN 製品ごとの設定や指示子の細部は覚えなくてよい）
