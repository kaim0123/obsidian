## 詳しい要約

**テーマ：ORM「Prisma」で Node.js から PostgreSQL を操作し、CRUD API を作る**

Prisma は SQL を書かずにメソッドで RDB を操作できる次世代オープンソース **ORM**。ORM の考え方を説明したあと、Express サーバーに Prisma を導入し、PostgreSQL と接続してモデル定義 → マイグレーション → CRUD API → リレーション（1対多）の定義までをハンズオンで行う入門動画。

---

### ORM とは

- **ORM（Object-Relational Mapping）**：オブジェクト（プロパティとメソッドを持つもの）とリレーショナル DB のテーブルを対応づける（マッピングする）仕組み。
- RDB のテーブルを操作するには本来 SQL（INSERT・UPDATE など）が必要だが、ORM なら `create`・`update`・`delete` のような JavaScript のメソッドで操作できる。
- 大規模なアプリでは細かな指定に SQL の知識が必要になるが、小規模なアプリや初心者は ORM から入り、次に SQL を学ぶステップでもよい。
- Django や Ruby on Rails などのフレームワークには ORM が組み込まれているので普段は意識しないことが多い。

### 構成と準備

- サーバー：Node.js + Express、DB：PostgreSQL（MySQL など他の RDB でも可）、両者をつなぐのが Prisma、クライアントは Postman。
- `npm i prisma express nodemon @prisma/client`（`@prisma/client` がデータの挿入・削除などに使うモジュール）。
- `npx prisma init` で `schema.prisma` と `.env` が生成される。`.env` の `DATABASE_URL` にユーザー名・パスワード・ポート・DB 名を設定（誤りがあると migrate で接続エラーになる）。
- SQL Shell で `CREATE DATABASE sampledb;` を実行して DB だけ作り、テーブルは Prisma 側で作る。

### モデル定義とマイグレーション

- `schema.prisma` に `model Post { id Int @id @default(autoincrement()) title String body String }` を書く。
- `npx prisma migrate dev` で **マイグレーション**。`migrations` フォルダに CREATE TABLE の SQL が自動生成され、テーブルが作られる。
- `npx prisma studio` でブラウザからテーブルの中身を確認できる。

### CRUD API

| 操作 | メソッド | Prisma の呼び出し |
| --- | --- | --- |
| 作成 | POST `/` | `prisma.post.create({ data: { title, body } })` |
| 全件取得 | GET `/` | `prisma.post.findMany()` |
| 1件取得 | GET `/:id` | `prisma.post.findUnique({ where: { id: Number(id) } })` |
| 更新 | PUT `/:id` | `prisma.post.update({ where: { id: Number(id) }, data: { body } })` |
| 削除 | DELETE `/:id` | `prisma.post.delete({ where: { id: Number(id) } })` |

- `new PrismaClient()` でインスタンス化し、モデル名は小文字（`prisma.post`）で呼ぶ。非同期なので `await` が必要。
- つまずきポイント：`app.use(express.json())` がないと req.body が読めない／`req.params.id` は文字列なので `Number()` でキャストが必要。

### リレーション（1対多）

- 1つの記事に複数のコメントがつく **1対多** を定義。`Comment` モデルに `postId Int` と `post Post @relation(fields: [postId], references: [id])` を書き、`Post` 側に `comments Comment[]` を持たせる。
- 再度 migrate すると、外部キー（foreign key）付きの Comment テーブルが作られる。外部キーにより「記事削除時にコメントも消す」「コメントが残っていれば記事を消せない」といった制約を設けられる。

### まとめ

- Prisma を使えば SQL を書かずに `create` / `findMany` / `findUnique` / `update` / `delete` で CRUD ができる。
- スキーマにモデルを書いて `prisma migrate dev` でテーブルを作り、`prisma studio` で中身を確認する。
- リレーションは `@relation(fields, references)` で外部キーとして定義する。
