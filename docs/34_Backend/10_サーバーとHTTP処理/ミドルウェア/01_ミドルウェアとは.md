# ミドルウェアとは

## 📖 概要

**ミドルウェア（Middleware）**は、Webアプリケーションにおいて、**リクエストとレスポンスの間で実行される処理**のことです。すべてのリクエストに対して共通の処理を実行するために使用されます。

## 🎯 なぜミドルウェアが必要なのか

### 問題：重複コードの発生

ミドルウェアがない場合、各ルート（エンドポイント）で同じ処理を繰り返し書く必要があります。

```typescript
// ❌ ミドルウェアがない場合（悪い例）
app.get('/dashboard', (req, res) => {
  // 認証チェック（毎回書く必要がある）
  const token = req.headers.authorization;
  if (!token) {
    return res.status(401).json({ error: '認証が必要です' });
  }
  
  // 実際の処理
  res.json({ message: 'ダッシュボードデータ' });
});

app.get('/profile', (req, res) => {
  // また認証チェック（同じコードを繰り返す）
  const token = req.headers.authorization;
  if (!token) {
    return res.status(401).json({ error: '認証が必要です' });
  }
  
  // 実際の処理
  res.json({ message: 'プロフィールデータ' });
});
```

### 解決：ミドルウェアで共通処理を分離

ミドルウェアを使うことで、共通処理を1箇所にまとめることができます。

```typescript
// ✅ ミドルウェアを使う場合（良い例）
// 認証ミドルウェア（1回だけ定義）
const authMiddleware = (req, res, next) => {
  const token = req.headers.authorization;
  if (!token) {
    return res.status(401).json({ error: '認証が必要です' });
  }
  next(); // 次の処理に進む
};

// ルートで使用（シンプルに）
app.get('/dashboard', authMiddleware, (req, res) => {
  res.json({ message: 'ダッシュボードデータ' });
});

app.get('/profile', authMiddleware, (req, res) => {
  res.json({ message: 'プロフィールデータ' });
});
```

## 🏠 日常生活での例え

ミドルウェアは、**建物のセキュリティゲート**のようなものです。

```
訪問者（リクエスト）
    ↓
【セキュリティゲート（ミドルウェア）】
  - 身分証チェック（認証）
  - 手荷物検査（ログ記録）
  - 訪問者リスト確認（認可）
    ↓
目的の部屋（ルートハンドラー）
    ↓
応対（レスポンス）
```

すべての訪問者は、目的の部屋に到達する前に、必ずセキュリティゲートを通ります。これにより、各部屋で個別にセキュリティチェックを行う必要がなくなります。

## 🔄 リクエストの流れ

```
1. ユーザーがリクエストを送信
   ↓
2. ミドルウェア1が実行（例：ログ記録）
   ↓
3. ミドルウェア2が実行（例：認証チェック）
   ↓
4. ミドルウェア3が実行（例：データ変換）
   ↓
5. ルートハンドラーが実行（実際の処理）
   ↓
6. レスポンスを返す
```

## 💡 ミドルウェアの主な用途

### 1. 認証・認可
ユーザーがログインしているか、適切な権限を持っているかをチェック

```typescript
// ログインしていない場合はログインページにリダイレクト
if (!isLoggedIn) {
  return redirect('/login');
}
```

### 2. ログ記録
リクエストの情報を記録（デバッグ、監視、分析など）

```typescript
// リクエストの情報をログに記録
console.log(`${req.method} ${req.path} - ${new Date()}`);
```

### 3. データ変換・検証
リクエストデータの形式を変換したり、バリデーションを行う

```typescript
// リクエストボディをパース
const data = JSON.parse(req.body);
```

### 4. エラーハンドリング
エラーをキャッチして、適切なエラーレスポンスを返す

```typescript
try {
  // 処理
} catch (error) {
  return res.status(500).json({ error: 'サーバーエラー' });
}
```

### 5. セキュリティヘッダーの設定
セキュリティに関するHTTPヘッダーを追加

```typescript
res.setHeader('X-Content-Type-Options', 'nosniff');
res.setHeader('X-Frame-Options', 'DENY');
```

### 6. レート制限
同じIPアドレスからの過度なリクエストを制限

```typescript
// 1分間に10回まで
if (requestCount > 10) {
  return res.status(429).json({ error: 'リクエストが多すぎます' });
}
```

## 🎨 ミドルウェアの特徴

### ✅ メリット

1. **コードの重複を削減**
   - 共通処理を1箇所にまとめられる

2. **保守性の向上**
   - 変更が必要な場合、1箇所を修正するだけで済む

3. **関心の分離**
   - 認証、ログ、エラーハンドリングなどを分離できる

4. **再利用性**
   - 複数のルートで同じミドルウェアを使える

5. **柔軟性**
   - 必要なルートにだけ適用できる

### ⚠️ 注意点

1. **実行順序が重要**
   - ミドルウェアは定義した順番で実行される

2. **`next()`を呼ぶ必要がある**
   - 次の処理に進むために`next()`を呼ばないと、リクエストが止まる

3. **パフォーマンスへの影響**
   - 多くのミドルウェアを追加すると、処理が遅くなる可能性がある

## 📝 まとめ

- **ミドルウェア**は、リクエストとレスポンスの間で実行される共通処理
- **重複コードを削減**し、**保守性を向上**させる
- **認証、ログ、エラーハンドリング**など、様々な用途で使用される
- **セキュリティゲート**のように、すべてのリクエストが通る共通の処理ポイント
