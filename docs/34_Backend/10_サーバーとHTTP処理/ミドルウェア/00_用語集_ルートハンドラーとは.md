# ルートハンドラー（Route Handler）とは

## 📖 概要

**ルートハンドラー（Route Handler）**または単に**ハンドラー（Handler）**は、**特定のURLパス（ルート）に対するリクエストを処理する関数**です。ミドルウェアが共通処理を行うのに対し、ハンドラーは**各ルート固有の処理**を実行します。

## 🎯 ハンドラーとは何か

### 簡単な説明

ハンドラーは、**「このURLにアクセスされたら、この処理を実行する」**という指示を定義する関数です。

```typescript
// 例：/api/users にGETリクエストが来たら、ユーザー一覧を返す
app.get('/api/users', (req, res) => {
  // この関数が「ハンドラー」
  res.json({ users: [] });
});
```

### 日常生活での例え

ハンドラーは、**レストランの注文処理**のようなものです。

```
お客様（クライアント）
    ↓
「ハンバーガーください」（リクエスト: GET /menu/burger）
    ↓
ウェイター（ルーティングシステム）
    ↓
「ハンバーガー担当のシェフ」（ハンドラー）
    ↓
ハンバーガーを作る（処理を実行）
    ↓
お客様に提供（レスポンス）
```

- **ルート（/menu/burger）**: 注文の種類
- **ハンドラー**: その注文を処理するシェフ
- **レスポンス**: 完成した料理

## 🔄 ミドルウェアとハンドラーの違い

### ミドルウェア

- **共通処理**を実行
- **すべてのルート**または**複数のルート**に適用される
- **`next()`を呼ぶ**必要がある（次の処理に進むため）

```typescript
// ミドルウェア：すべてのリクエストに適用
app.use((req, res, next) => {
  console.log('リクエスト:', req.path);
  next(); // 次の処理に進む
});
```

### ハンドラー

- **特定のルート**の処理を実行
- **1つのルート**にのみ適用される
- **レスポンスを返す**（`next()`は不要）

```typescript
// ハンドラー：/api/users にのみ適用
app.get('/api/users', (req, res) => {
  res.json({ users: [] }); // レスポンスを返す
});
```

## 📍 リクエストの流れ

```
1. クライアントがリクエストを送信
   GET /api/users
   ↓
2. ミドルウェア1が実行（ログ記録）
   ↓
3. ミドルウェア2が実行（認証チェック）
   ↓
4. ミドルウェア3が実行（データ変換）
   ↓
5. ルートハンドラーが実行 ← ここ！
   - データベースからユーザーを取得
   - レスポンスを返す
   ↓
6. クライアントにレスポンスが返る
```

## 💻 実装例

### Express.jsでの例

```typescript
import express from 'express';
const app = express();

// ハンドラーの定義
app.get('/api/users', (req, res) => {
  // この関数が「ハンドラー」
  const users = [
    { id: 1, name: '田中' },
    { id: 2, name: '佐藤' }
  ];
  res.json({ users });
});

// 別のハンドラー
app.post('/api/users', (req, res) => {
  // POSTリクエスト用のハンドラー
  const newUser = req.body;
  // ユーザーを作成する処理
  res.status(201).json({ message: 'ユーザーを作成しました', user: newUser });
});

// パラメータ付きのハンドラー
app.get('/api/users/:id', (req, res) => {
  // :id はパラメータ
  const userId = req.params.id;
  // 特定のユーザーを取得
  res.json({ userId, name: '田中' });
});
```

### Next.jsでの例

#### Pages Router

```typescript
// pages/api/users.ts
import type { NextApiRequest, NextApiResponse } from 'next';

// この関数が「ハンドラー」
export default function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  if (req.method === 'GET') {
    res.status(200).json({ users: [] });
  } else if (req.method === 'POST') {
    res.status(201).json({ message: 'ユーザーを作成しました' });
  } else {
    res.status(405).json({ error: 'Method not allowed' });
  }
}
```

#### App Router

```typescript
// app/api/users/route.ts

// GETリクエスト用のハンドラー
export async function GET() {
  const users = await getUsers();
  return Response.json({ users });
}

// POSTリクエスト用のハンドラー
export async function POST(request: Request) {
  const body = await request.json();
  const user = await createUser(body);
  return Response.json(user, { status: 201 });
}
```

## 🎨 ハンドラーの種類

### 1. シンプルなハンドラー

```typescript
app.get('/hello', (req, res) => {
  res.send('Hello, World!');
});
```

### 2. 非同期ハンドラー

```typescript
app.get('/api/posts', async (req, res) => {
  // データベースからデータを取得（非同期処理）
  const posts = await db.getPosts();
  res.json({ posts });
});
```

### 3. エラーハンドリング付きハンドラー

```typescript
app.get('/api/posts', async (req, res) => {
  try {
    const posts = await db.getPosts();
    res.json({ posts });
  } catch (error) {
    res.status(500).json({ error: 'サーバーエラーが発生しました' });
  }
});
```

### 4. ミドルウェアと組み合わせたハンドラー

```typescript
// 認証ミドルウェア
const authMiddleware = (req, res, next) => {
  const token = req.headers.authorization;
  if (!token) {
    return res.status(401).json({ error: '認証が必要です' });
  }
  next();
};

// ハンドラー（ミドルウェアの後に実行される）
app.get('/api/dashboard', authMiddleware, (req, res) => {
  res.json({ message: 'ダッシュボードデータ' });
});
```

## 🔑 重要なポイント

### 1. ハンドラーはレスポンスを返す

```typescript
// ✅ 正しい：レスポンスを返す
app.get('/api/data', (req, res) => {
  res.json({ data: 'データ' });
});

// ❌ 間違い：レスポンスを返さない
app.get('/api/data', (req, res) => {
  console.log('データ取得');
  // レスポンスを返していない → クライアントは待ち続ける
});
```

### 2. 1つのルートに複数のハンドラーは設定できない

```typescript
// ❌ 間違い：同じルートに複数のハンドラー
app.get('/api/users', handler1);
app.get('/api/users', handler2); // handler1が上書きされる

// ✅ 正しい：異なるHTTPメソッド
app.get('/api/users', getHandler);    // GETリクエスト
app.post('/api/users', postHandler);  // POSTリクエスト
```

### 3. ハンドラーは最後に実行される

```typescript
app.use(middleware1);  // 1番目
app.use(middleware2);  // 2番目
app.get('/api/data', handler);  // 3番目（最後）
```

## 📝 用語の整理

| 用語 | 説明 | 例 |
|------|------|-----|
| **ルート（Route）** | URLパス | `/api/users` |
| **ハンドラー（Handler）** | ルートを処理する関数 | `(req, res) => { ... }` |
| **ルートハンドラー** | ルートとハンドラーの組み合わせ | `app.get('/api/users', handler)` |
| **エンドポイント** | ルートとHTTPメソッドの組み合わせ | `GET /api/users` |

## 🎯 まとめ

- **ハンドラー**は、特定のルートに対するリクエストを処理する関数
- **ミドルウェア**は共通処理、**ハンドラー**はルート固有の処理
- ハンドラーは**必ずレスポンスを返す**必要がある
- ハンドラーは**ミドルウェアの後に実行**される
