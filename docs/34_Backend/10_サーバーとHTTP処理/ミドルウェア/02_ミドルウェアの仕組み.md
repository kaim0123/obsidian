# ミドルウェアの仕組み

## 🔄 リクエスト・レスポンスの流れ

### 基本的な流れ

```
┌─────────────────┐
│  クライアント    │
│  (ブラウザなど)  │
└────────┬────────┘
         │ リクエスト送信
         ↓
┌─────────────────────────────────────┐
│        ミドルウェアスタック          │
│  ┌──────────────────────────────┐  │
│  │ ミドルウェア1: ログ記録       │  │
│  └───────────┬──────────────────┘  │
│              ↓                      │
│  ┌──────────────────────────────┐  │
│  │ ミドルウェア2: 認証チェック   │  │
│  └───────────┬──────────────────┘  │
│              ↓                      │
│  ┌──────────────────────────────┐  │
│  │ ミドルウェア3: データ変換     │  │
│  └───────────┬──────────────────┘  │
└──────────────┼──────────────────────┘
               ↓
┌─────────────────────────────────────┐
│      ルートハンドラー                │
│  (実際の処理を実行)                  │
└───────────┬──────────────────────────┘
            ↓
┌─────────────────────────────────────┐
│      レスポンス生成                  │
└───────────┬──────────────────────────┘
            ↓
┌─────────────────┐
│   クライアント   │
│  (レスポンス受信)│
└─────────────────┘
```

## 🔗 ミドルウェアチェーン

### チェーンの概念

ミドルウェアは**チェーン（鎖）**のように連続して実行されます。各ミドルウェアは、次のミドルウェアに処理を渡すために`next()`を呼び出します。

```typescript
// ミドルウェアチェーンの例
app.use(middleware1);  // 1番目に実行
app.use(middleware2);  // 2番目に実行
app.use(middleware3);  // 3番目に実行

app.get('/api/data', handler);  // 最後に実行
```

### 実行順序の例

```typescript
// ミドルウェア1: ログ記録
const logger = (req, res, next) => {
  console.log('1. ログ記録:', req.method, req.path);
  next(); // 次のミドルウェアに進む
};

// ミドルウェア2: 認証チェック
const auth = (req, res, next) => {
  console.log('2. 認証チェック');
  if (req.headers.authorization) {
    next(); // 認証OK → 次の処理に進む
  } else {
    res.status(401).json({ error: '認証が必要です' });
    // next()を呼ばない → ここで処理が止まる
  }
};

// ミドルウェア3: データ変換
const transform = (req, res, next) => {
  console.log('3. データ変換');
  req.timestamp = new Date();
  next();
};

// ルートハンドラー
const handler = (req, res) => {
  console.log('4. ルートハンドラー実行');
  res.json({ 
    message: 'データ',
    timestamp: req.timestamp 
  });
};

// 適用順序
app.use(logger);
app.use(auth);
app.use(transform);
app.get('/api/data', handler);
```

**実行結果（認証成功時）:**
```
1. ログ記録: GET /api/data
2. 認証チェック
3. データ変換
4. ルートハンドラー実行
```

**実行結果（認証失敗時）:**
```
1. ログ記録: GET /api/data
2. 認証チェック
（ここで処理が止まる。レスポンスが返される）
```

## 🔑 `next()`の役割

### `next()`とは

`next()`は、**次のミドルウェアまたはルートハンドラーに処理を渡す関数**です。

```typescript
const middleware = (req, res, next) => {
  // 何か処理を行う
  console.log('ミドルウェア実行中');
  
  // next()を呼ぶ → 次の処理に進む
  next();
  
  // ⚠️ next()を呼ばないと、リクエストがここで止まる
};
```

### `next()`を呼ばない場合

```typescript
const blockingMiddleware = (req, res, next) => {
  console.log('処理開始');
  
  // next()を呼ばない
  // → リクエストがここで止まる
  // → ルートハンドラーは実行されない
  // → クライアントはレスポンスを待ち続ける
};

app.use(blockingMiddleware);
app.get('/api/data', (req, res) => {
  // このコードは実行されない
  res.json({ message: 'データ' });
});
```

### エラーを`next()`に渡す

エラーが発生した場合、`next(error)`でエラーハンドリングミドルウェアに渡すことができます。

```typescript
const errorMiddleware = (req, res, next) => {
  try {
    // 何か処理
    if (someError) {
      throw new Error('エラーが発生しました');
    }
    next();
  } catch (error) {
    // エラーを次のエラーハンドラーに渡す
    next(error);
  }
};

// エラーハンドリングミドルウェア
app.use((error, req, res, next) => {
  console.error('エラー:', error);
  res.status(500).json({ error: error.message });
});
```

## 📍 ミドルウェアの適用範囲

### グローバルミドルウェア

すべてのリクエストに適用されるミドルウェア

```typescript
// すべてのリクエストに適用
app.use(logger);
app.use(cors);

app.get('/api/users', handler1);
app.get('/api/posts', handler2);
// どちらもloggerとcorsが適用される
```

### ルート固有のミドルウェア

特定のルートにだけ適用されるミドルウェア

```typescript
// 特定のルートにだけ適用
app.get('/api/admin', authMiddleware, adminHandler);
app.get('/api/public', publicHandler);
// /api/adminにはauthMiddlewareが適用される
// /api/publicには適用されない
```

### パスパターンで適用

特定のパスパターンに一致するルートに適用

```typescript
// /api/* に一致するすべてのルートに適用
app.use('/api', apiMiddleware);

app.get('/api/users', handler1);      // 適用される
app.get('/api/posts', handler2);     // 適用される
app.get('/public', handler3);        // 適用されない
```

## 🔄 ミドルウェアの実行タイミング

### 実行順序の詳細

```typescript
// 1. グローバルミドルウェア（定義順）
app.use(middleware1);
app.use(middleware2);

// 2. ルート固有のミドルウェア
app.get('/api/data', 
  middleware3,  // このルートにだけ適用
  middleware4,  // このルートにだけ適用
  handler       // 最後に実行
);
```

**実行順序:**
1. `middleware1`
2. `middleware2`
3. `middleware3`
4. `middleware4`
5. `handler`

### 注意：定義順序が重要

```typescript
// ❌ 間違った順序
app.get('/api/data', handler);
app.use(logger);  // このルートには適用されない

// ✅ 正しい順序
app.use(logger);  // 先に定義
app.get('/api/data', handler);
```

## 🎯 実践的な例

### 完全なミドルウェアチェーンの例

```typescript
// 1. ログ記録ミドルウェア（すべてのリクエスト）
app.use((req, res, next) => {
  console.log(`${new Date().toISOString()} - ${req.method} ${req.path}`);
  next();
});

// 2. CORS設定（すべてのリクエスト）
app.use((req, res, next) => {
  res.header('Access-Control-Allow-Origin', '*');
  res.header('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE');
  next();
});

// 3. ボディパーサー（POST/PUTリクエスト）
app.use(express.json());

// 4. 認証ミドルウェア（/api/protected/* のみ）
app.use('/api/protected', (req, res, next) => {
  const token = req.headers.authorization;
  if (!token) {
    return res.status(401).json({ error: '認証が必要です' });
  }
  next();
});

// 5. ルートハンドラー
app.get('/api/public/data', (req, res) => {
  res.json({ message: '公開データ' });
});

app.get('/api/protected/data', (req, res) => {
  res.json({ message: '保護されたデータ' });
});
```

**リクエスト: GET /api/public/data**
```
1. ログ記録 → next()
2. CORS設定 → next()
3. ボディパーサー → next()
4. 認証ミドルウェア（スキップ）
5. ルートハンドラー実行
```

**リクエスト: GET /api/protected/data**
```
1. ログ記録 → next()
2. CORS設定 → next()
3. ボディパーサー → next()
4. 認証ミドルウェア → next()
5. ルートハンドラー実行
```

## 📝 まとめ

- **ミドルウェアチェーン**: ミドルウェアは連続して実行される
- **`next()`**: 次の処理に進むために必須
- **実行順序**: 定義した順番で実行される
- **適用範囲**: グローバル、ルート固有、パスパターンで制御できる
- **エラーハンドリング**: `next(error)`でエラーを渡せる
