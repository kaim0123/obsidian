# フレームワーク別のミドルウェア

各フレームワークでのミドルウェアの実装方法を解説します。

## 🚀 Next.js

### 基本的な実装

Next.jsでは、`middleware.ts`（または`middleware.js`）をプロジェクトのルートに配置します。

```typescript
// middleware.ts（プロジェクトのルートに配置）
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  // リクエストのログ記録
  console.log('リクエスト:', request.nextUrl.pathname);
  
  // 認証チェック
  const token = request.cookies.get('auth-token');
  
  if (!token && request.nextUrl.pathname.startsWith('/dashboard')) {
    // ログインページにリダイレクト
    return NextResponse.redirect(new URL('/login', request.url));
  }
  
  // 次の処理に進む
  return NextResponse.next();
}

// どのパスでミドルウェアを実行するかを指定
export const config = {
  matcher: [
    '/dashboard/:path*',
    '/api/protected/:path*'
  ]
};
```

### Next.jsの特徴

- **Edge Runtimeで実行**: デフォルトでEdge Runtimeで実行される（高速）
- **`middleware.ts`ファイル**: プロジェクトルートに1つだけ配置
- **`matcher`設定**: 特定のパスにだけ適用可能
- **`NextRequest`と`NextResponse`**: Next.js専用のリクエスト/レスポンスオブジェクト

### 実践例：認証ミドルウェア

```typescript
// middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  const token = request.cookies.get('auth-token');
  const { pathname } = request.nextUrl;
  
  // 保護されたルート
  const protectedPaths = ['/dashboard', '/profile', '/settings'];
  const isProtectedPath = protectedPaths.some(path => 
    pathname.startsWith(path)
  );
  
  // ログインページへのアクセス（既にログインしている場合）
  if (pathname === '/login' && token) {
    return NextResponse.redirect(new URL('/dashboard', request.url));
  }
  
  // 保護されたルートへのアクセス（未ログインの場合）
  if (isProtectedPath && !token) {
    return NextResponse.redirect(new URL('/login', request.url));
  }
  
  return NextResponse.next();
}

export const config = {
  matcher: [
    '/dashboard/:path*',
    '/profile/:path*',
    '/settings/:path*',
    '/login'
  ]
};
```

### 実践例：ヘッダーの設定

```typescript
export function middleware(request: NextRequest) {
  const response = NextResponse.next();
  
  // セキュリティヘッダーを追加
  response.headers.set('X-Content-Type-Options', 'nosniff');
  response.headers.set('X-Frame-Options', 'DENY');
  response.headers.set('X-XSS-Protection', '1; mode=block');
  
  return response;
}
```

## 🌐 Express.js

### 基本的な実装

Express.jsでは、`app.use()`でミドルウェアを登録します。

```typescript
import express from 'express';

const app = express();

// グローバルミドルウェア
app.use((req, res, next) => {
  console.log('リクエスト:', req.method, req.path);
  next();
});

// ルート固有のミドルウェア
app.get('/api/data', (req, res, next) => {
  // 認証チェック
  const token = req.headers.authorization;
  if (!token) {
    return res.status(401).json({ error: '認証が必要です' });
  }
  next();
}, (req, res) => {
  res.json({ message: 'データ' });
});
```

### Express.jsの特徴

- **柔軟な適用**: グローバル、ルート固有、パスパターンで適用可能
- **チェーン可能**: 複数のミドルウェアを連続して適用できる
- **`next()`関数**: 次のミドルウェアに処理を渡す

### 実践例：認証ミドルウェア

```typescript
// auth.middleware.ts
export const authMiddleware = (req, res, next) => {
  const token = req.headers.authorization?.replace('Bearer ', '');
  
  if (!token) {
    return res.status(401).json({ error: '認証トークンが必要です' });
  }
  
  try {
    // JWTトークンの検証
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = decoded; // ユーザー情報をリクエストに追加
    next();
  } catch (error) {
    return res.status(401).json({ error: '無効なトークンです' });
  }
};

// 使用例
app.get('/api/dashboard', authMiddleware, (req, res) => {
  res.json({ 
    message: 'ダッシュボード',
    user: req.user 
  });
});
```

### 実践例：エラーハンドリング

```typescript
// エラーハンドリングミドルウェア（最後に配置）
app.use((error, req, res, next) => {
  console.error('エラー:', error);
  
  const statusCode = error.statusCode || 500;
  const message = error.message || 'サーバーエラーが発生しました';
  
  res.status(statusCode).json({
    error: message,
    ...(process.env.NODE_ENV === 'development' && {
      stack: error.stack
    })
  });
});
```

### よく使われるExpress.jsミドルウェア

```typescript
import express from 'express';
import cors from 'cors';
import helmet from 'helmet';
import morgan from 'morgan';
import cookieParser from 'cookie-parser';

const app = express();

// セキュリティヘッダー
app.use(helmet());

// CORS設定
app.use(cors({
  origin: 'https://example.com',
  credentials: true
}));

// ログ記録
app.use(morgan('combined'));

// クッキーパーサー
app.use(cookieParser());

// JSONボディパーサー
app.use(express.json());

// URLエンコードされたボディパーサー
app.use(express.urlencoded({ extended: true }));
```

## 🎯 NestJS

### 基本的な実装

NestJSでは、クラスベースまたは関数ベースのミドルウェアを作成できます。

```typescript
// logger.middleware.ts
import { Injectable, NestMiddleware } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';

@Injectable()
export class LoggerMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    console.log(`[${new Date().toISOString()}] ${req.method} ${req.path}`);
    next();
  }
}
```

### モジュールでの登録

```typescript
// app.module.ts
import { Module, NestModule, MiddlewareConsumer } from '@nestjs/common';
import { LoggerMiddleware } from './logger.middleware';

@Module({
  // ...
})
export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer
      .apply(LoggerMiddleware)
      .forRoutes('*'); // すべてのルートに適用
  }
}
```

### NestJSの特徴

- **クラスベース**: TypeScriptのクラスで実装
- **依存性注入**: `@Injectable()`デコレータでDI可能
- **柔軟な適用**: ルート、メソッド、コントローラー単位で適用可能

### 実践例：認証ミドルウェア

```typescript
// auth.middleware.ts
import { Injectable, NestMiddleware, UnauthorizedException } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';
import * as jwt from 'jsonwebtoken';

@Injectable()
export class AuthMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    const token = req.headers.authorization?.replace('Bearer ', '');
    
    if (!token) {
      throw new UnauthorizedException('認証トークンが必要です');
    }
    
    try {
      const decoded = jwt.verify(token, process.env.JWT_SECRET);
      req.user = decoded;
      next();
    } catch (error) {
      throw new UnauthorizedException('無効なトークンです');
    }
  }
}
```

### 実践例：関数ベースのミドルウェア

```typescript
// logger.middleware.ts
import { Request, Response, NextFunction } from 'express';

export function logger(req: Request, res: Response, next: NextFunction) {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.path}`);
  next();
}

// app.module.ts
consumer
  .apply(logger)
  .forRoutes('*');
```

### 特定のルートに適用

```typescript
// app.module.ts
export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer
      .apply(AuthMiddleware)
      .forRoutes(
        { path: 'dashboard', method: RequestMethod.GET },
        { path: 'profile', method: RequestMethod.ALL },
        DashboardController  // コントローラー全体に適用
      );
  }
}
```

## 🔄 フレームワーク比較

| 特徴 | Next.js | Express.js | NestJS |
|------|---------|------------|--------|
| **ファイル配置** | `middleware.ts`（ルート） | 任意の場所 | モジュール内 |
| **実行環境** | Edge Runtime（デフォルト） | Node.js | Node.js |
| **適用方法** | `matcher`設定 | `app.use()` | `MiddlewareConsumer` |
| **実装スタイル** | 関数 | 関数 | クラス/関数 |
| **型安全性** | TypeScript | 任意 | TypeScript（推奨） |
| **依存性注入** | ❌ | ❌ | ✅ |

## 📝 まとめ

各フレームワークでのミドルウェアの特徴：

- **Next.js**: Edge Runtimeで高速実行、`middleware.ts`で一元管理
- **Express.js**: 柔軟でシンプル、広く使われている
- **NestJS**: クラスベース、依存性注入、型安全

フレームワークに応じて適切な実装方法を選択しましょう。
