## 詳しい要約

**テーマ：サーバーから画面へ新着を知らせる方法 — ポーリングとWebSocket**

Web の普通の約束では、サーバーは聞かれないと答えられない。そのため新着を届けるには「何度も聞きに行く（ポーリング）」か「つなぎっぱなしにする（WebSocket）」のどちらかになる。ポーリングは間隔が遅れと無駄を同時に決め、WebSocket は切れたときに黙って取りこぼすので、**「最後に受け取った番号」の次から取り直す**ことが鍵、という回。

---

### よくある相談

- 社内チャットで、再読み込みしないと新しいメッセージが出ない
- 数秒ごとに聞きに行くよう直したら「サーバーが重い」と言われる
- つなぎっぱなし方式に変えたら「電車でメッセージが抜ける」と言われる
- どれも手元の速いネットでは気づきにくい

### サーバーは聞かれないと答えられない

- Web の普通の約束は「ブラウザが聞いて、サーバーが答える」の順番だけ。電話はかけられるが、かかってはこないイメージ
- サーバーに届いたメッセージは、ブラウザが聞きに来るまでサーバーの中で**待たされる**。今夜の道具はすべて、この待ちを縮める工夫

### ポーリング（何度も聞きに行く）

- 決まった間隔（例: 2秒ごと）で自動的に聞きに行く
- 20秒で10回聞いて5回が空振り。**聞く間隔がそのまま遅れの上限**になる
- 間隔を縮めると遅れは減るが空振りが増える（1秒ごとなら20回中15回が空振り）
- 1万人が1秒ごとに聞けば毎秒1万回、5秒ごとなら毎秒2000回だが最大5秒遅れる。**間隔を1つ決めると遅れと無駄が一緒に決まる**取引
- 通知の数のように数秒遅れても困らないものなら、これで十分なことも多い

### ロングポーリング（返事を待たせる）

- 聞きに行くと、サーバーは新しいものが来るまで返事を**保留**し、来た瞬間に返す。受け取ったらすぐ次を聞きに行く
- 遅れも空振りも少ないが、聞くたびに問い合わせを作り直し、保留の時間もある

### WebSocket（つなぎっぱなしにする）

- 最初に1回だけ通り道をつなぎ、つながっている間は**サーバーから話しかけられる**
- 同じ通り道でブラウザからも送れる＝**双方向にいつでも話せる**。チャットや対戦ゲームの合図向き
- 待ちも空振りもないが、**この1本はずっと続く保証がない**

### コードで見る

- ポーリングのコード：**最後に受け取った番号**を覚え、「この番号より後をください」と頼む。受け取ったら番号を進める（同じものが二重に出ない）
- WebSocket の素朴なコード：つないで、届いたら画面に出すだけ。すっきりしているが、**切れたときの処理も番号もない**。AI に書かせるとこの形がよく出る

### 電車で1本が切れる

- トンネルで通り道が切れている間に届いた2番・3番は、サーバーは送ろうとするが途中で消える
- つなぎ直すと4番・5番は届くが、**2番・3番は抜けたまま**。本人は抜けたことに気づけない
- 再読み込みすると出る（サーバーには残っている）ので、たまにしか起きず手元で再現しない

### 最後の番号から取り直す

- つなぎ直すときに「1番まで受け取った、その次からください」と伝えれば、サーバーが2番・3番をまとめて返す
- **サーバー側もメッセージを番号付きで残しておく**必要がある（送ったら捨てる作りだと渡せない）
- 取り直しと通常の配信が重なることがあるので、**番号で見分けて二重表示を防ぐ**
- 切れたらつなぎ直すが、**時間にばらつき（例: 1〜4秒）を入れる**。サーバー入れ替え時に1万人が同じ瞬間につなぎ直すと押し寄せてまた落ちるため

### どちらを選ぶか

| | ポーリング | WebSocket |
|---|---|---|
| 仕組み | 普通の問い合わせと同じ。今ある仕組みにそのまま乗る | 1本つないで双方向にすぐ話せる |
| 遅れ | 聞く間隔次第 | ほぼなし |
| 弱点 | 空振りが多い | サーバーが接続数分の通り道を抱え続ける（どのサーバーにつながっているかも気にする必要）。切れる前提で番号から取り直す |
| 向く用途 | 数秒遅れても困らないもの | チャット、対戦ゲーム、共同編集 |

- どちらが上かではなく、何を届けたいかで選ぶ。どちらでも**番号で取り直す考え方は同じ**

### AIに書かせたときのチェックポイント

1. 切れたときにつなぎ直す処理があるか
2. 最後に受け取った番号を覚え、その次から取り直しているか
3. つなぎ直す時間をばらけさせているか
4. ポーリングなら間隔が短すぎないか（利用者数を掛け算してから決める）
- 「切る」「増やす」の2つを頭の中で試してから読む

### ケーススタディ：トンネルの後だけ抜ける

- WebSocket で1秒後につなぎ直すチャットで、電車で時々数件が出ない（再読み込みで出る）
- 選択肢：A 1秒ごとのポーリングに戻す / B 最後の番号を覚えてその次から取り直す / C つなぎ直しをすぐにする
- 正解は **B**。サーバーには残っているので番号で頼めば戻る。C はトンネル内ではそもそもつながらず、取り直さない限り抜けた分は戻らない（さらに一斉に押し寄せる）。A は1万人なら毎秒1万回の空振り

### まとめ

- サーバーは聞かれないと答えられない。届ける方法は「聞く」か「つなぐ」
- ポーリングは間隔が遅れと無駄を決める
- WebSocket は双方向にすぐ届くが、1本は必ずいつか切れる
- 切れる前提で、最後に受け取った番号の次から取り直す（ハンドシェイクの中身やライブラリごとの書き方は知らなくてよい）
