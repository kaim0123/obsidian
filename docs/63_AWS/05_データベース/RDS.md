## RDSとは

**Amazon RDS (Relational Database Service)** は、AWSが提供するマネージドリレーショナルデータベースサービスです。クラウド上でリレーショナルデータベースを簡単にセットアップ、運用、スケールできるサービスです。

### RDSの基本概念

```
RDS = マネージドデータベースサービス
├── データベースエンジンの管理
├── 自動バックアップ
├── パッチ適用
├── 監視・メトリクス
└── スケーリング
```

## マネージドサービスの概念

### 責任分担モデル

添付の画像で示されているように、AWSのマネージドサービスでは責任が明確に分離されています：

#### オンプレミス環境
```
ユーザー責任: 100%
├── HW調達・電源など
├── OSインストール
├── ミドルウェアインストール
├── パッチ当て
├── バックアップ
└── アプリからの利用
```

#### MySQL on EC2
```
AWS責任: インフラ層
├── HW調達・電源など
└── OSインストール

ユーザー責任: アプリケーション層
├── ミドルウェアインストール
├── パッチ当て
├── バックアップ
└── アプリからの利用
```

#### Amazon RDS
```
AWS責任: 運用・管理層
├── HW調達・電源など
├── OSインストール
├── ミドルウェアインストール
├── パッチ当て
└── バックアップ

ユーザー責任: アプリケーション層
└── アプリからの利用
```

### マネージドサービスのメリット

#### 1. 機能をサービスとして提供
- **構築にかかる工数を減らせる**: データベースのセットアップや管理に時間を費やす必要がない
- **ベストプラクティスを「利用」できる**: AWSが業界標準のベストプラクティスを実装済み

#### 2. Undifferentiated Heavy Lifting を回避
- **重い作業をAWSに委任**: インフラ管理、パッチ適用、バックアップなどの定型作業
- **利用者への価値創出に注力**: アプリケーション開発やビジネス価値の創出に集中できる

## RDSの基本構成

### インスタンスクラス

#### 汎用インスタンス (db.t3, db.m5, db.m6i)
```yaml
用途: 汎用的なワークロード
特徴:
  - バランスの取れた性能
  - コスト効率
  - 中小規模アプリケーション

例:
  - db.t3.micro (1 vCPU, 1 GB RAM)
  - db.m5.large (2 vCPU, 8 GB RAM)
  - db.m6i.xlarge (4 vCPU, 16 GB RAM)
```

#### メモリ最適化インスタンス (db.r5, db.r6i, db.x1e)
```yaml
用途: メモリ集約型ワークロード
特徴:
  - 大容量メモリ
  - 高速I/O
  - 大規模データベース

例:
  - db.r5.large (2 vCPU, 16 GB RAM)
  - db.r6i.xlarge (4 vCPU, 32 GB RAM)
  - db.x1e.8xlarge (32 vCPU, 976 GB RAM)
```

#### バースト可能インスタンス (db.t3, db.t4g)
```yaml
用途: 開発・テスト環境
特徴:
  - ベースライン性能
  - CPUクレジットシステム
  - 低コスト

例:
  - db.t3.micro (1 vCPU, 1 GB RAM)
  - db.t4g.micro (2 vCPU, 1 GB RAM)
```

### ストレージタイプ

#### 汎用SSD (gp3)
```yaml
特徴:
  - バランスの取れた性能
  - 3,000 IOPS（最大16,000 IOPS）
  - 最大1,000 MiB/s
  - コスト効率

用途:
  - 汎用的なワークロード
  - 中小規模データベース
```

#### プロビジョンドIOPS SSD (io2)
```yaml
特徴:
  - 高性能・低レイテンシ
  - 最大64,000 IOPS
  - 最大1,000 MiB/s
  - 99.999%耐久性

用途:
  - 大規模データベース
  - 高負荷ワークロード
```

#### マグネティック (標準)
```yaml
特徴:
  - 低コスト
  - 最大40,000 IOPS
  - 最大500 MiB/s

用途:
  - 開発・テスト環境
  - アクセス頻度の低いデータ
```

## 実践的な設定例

### 基本的なRDSインスタンス作成

#### AWS CLIでの作成例
```bash
# MySQLインスタンス作成
aws rds create-db-instance \
    --db-instance-identifier mydbinstance \
    --db-instance-class db.t3.micro \
    --engine mysql \
    --engine-version 8.0.35 \
    --master-username admin \
    --master-user-password MyPassword123 \
    --allocated-storage 20 \
    --storage-type gp3 \
    --vpc-security-group-ids sg-12345678 \
    --db-subnet-group-name mydbsubnetgroup \
    --backup-retention-period 7 \
    --multi-az \
    --storage-encrypted \
    --enable-cloudwatch-logs-export mysql
```

#### CloudFormationテンプレート例
```yaml
Resources:
  MyDBInstance:
    Type: AWS::RDS::DBInstance
    Properties:
      DBInstanceIdentifier: mydbinstance
      DBInstanceClass: db.t3.micro
      Engine: mysql

      StorageType: gp3
      VPCSecurityGroups:
        - !Ref DatabaseSecurityGroup

        - !Ref PrivateSubnet1

        - Key: Name
          Value: MyDBSubnetGroup
```

## よくある質問

### Q1: RDSとEC2でMySQLを動かすのでは、どちらがコスト効率が良いですか？

**A**: **用途と運用体制によって異なります**。

#### 短期的なコスト比較
```yaml
EC2 + MySQL:
  - インスタンス料金のみ
  - 運用コストは別途必要

Amazon RDS:
  - インスタンス料金 + 管理費
  - 運用コストは大幅削減
```

#### 長期的な総コスト
```yaml
EC2 + MySQL:
  - 初期コスト: 低い
  - 運用コスト: 高い
  - 総コスト: 運用負荷に依存

Amazon RDS:
  - 初期コスト: やや高い
  - 運用コスト: 低い
  - 総コスト: 一般的に低い
```

### Q2: RDSのバックアップはどの程度の精度で復旧できますか？

**A**: **5分単位の精度で復旧可能です**。

#### バックアップの精度
```yaml
ポイントインタイム復旧:
  - 精度: 5分単位
  - 保持期間: 1-35日
  - 復旧範囲: データベース全体
  - 整合性: トランザクション整合性保証
```

#### 復旧手順
```bash
# ポイントインタイム復旧の例
aws rds restore-db-instance-to-point-in-time \
    --source-db-instance-identifier mydbinstance \
    --target-db-instance-identifier mydbinstance-restored \
```
