# 基本的性能指標

## 概要

サーバーの性能指標は、システムの動作状況を定量的に評価するための重要な指標です。適切な性能指標の監視により、システムの健全性を把握し、問題の早期発見と対処が可能になります。また、性能指標は、システムの設計や運用の改善点を特定するための重要な情報源となります。

## 性能指標の分類

### 1. リソース使用率指標

システムリソースの使用状況を表す指標です。

#### CPU 使用率

- **定義**: CPU の使用時間の割合
- **単位**: パーセント（%）
- **正常値**: 70%以下
- **異常値**: 90%以上
- **監視方法**: top、htop、sar、vmstat

#### メモリ使用率

- **定義**: メモリの使用量の割合
- **単位**: パーセント（%）、バイト（B）
- **正常値**: 80%以下
- **異常値**: 95%以上
- **監視方法**: free、top、sar、vmstat

#### ディスク使用率

- **定義**: ディスク容量の使用量の割合
- **単位**: パーセント（%）、バイト（B）
- **正常値**: 80%以下
- **異常値**: 90%以上
- **監視方法**: df、du、iostat

#### ネットワーク使用率

- **定義**: ネットワーク帯域の使用量の割合
- **単位**: パーセント（%）、ビット/秒（bps）
- **正常値**: 70%以下
- **異常値**: 90%以上
- **監視方法**: iftop、nethogs、sar

### 2. 応答時間指標

システムの応答速度を表す指標です。

#### レスポンス時間

- **定義**: リクエスト送信からレスポンス受信までの時間
- **単位**: ミリ秒（ms）、秒（s）
- **正常値**: 100ms 以下
- **異常値**: 1s 以上
- **監視方法**: アプリケーションログ、APM

#### レイテンシ

- **定義**: データ送信から受信までの時間
- **単位**: ミリ秒（ms）
- **正常値**: 10ms 以下
- **異常値**: 100ms 以上
- **監視方法**: ping、traceroute、ネットワーク監視

#### スループット

- **定義**: 単位時間あたりの処理量
- **単位**: リクエスト/秒（rps）、バイト/秒（Bps）
- **正常値**: 設計値の 80%以上
- **異常値**: 設計値の 50%以下
- **監視方法**: アプリケーションログ、APM

### 3. 可用性指標

システムの稼働状況を表す指標です。

#### 稼働率

- **定義**: システムが正常に動作している時間の割合
- **単位**: パーセント（%）
- **正常値**: 99.9%以上
- **異常値**: 99%以下
- **監視方法**: ヘルスチェック、監視システム

#### MTBF（平均故障間隔）

- **定義**: 故障と故障の間の平均時間
- **単位**: 時間（h）、日（d）
- **正常値**: 1000 時間以上
- **異常値**: 100 時間以下
- **監視方法**: 障害ログ、監視システム

#### MTTR（平均復旧時間）

- **定義**: 故障から復旧までの平均時間
- **単位**: 時間（h）、分（m）
- **正常値**: 1 時間以下
- **異常値**: 4 時間以上
- **監視方法**: 障害ログ、監視システム

## 主要な性能指標

### 1. CPU 性能指標

#### CPU 使用率

```bash
# topコマンドでの確認
top -p 1

# sarコマンドでの確認
sar -u 1 5

# vmstatコマンドでの確認
vmstat 1 5
```

#### CPU 負荷平均

- **定義**: 1 分、5 分、15 分の平均負荷
- **単位**: 数値
- **正常値**: CPU コア数以下
- **異常値**: CPU コア数の 2 倍以上
- **監視方法**: uptime、top、sar

#### CPU コンテキストスイッチ

- **定義**: プロセス間の切り替え回数
- **単位**: 回数/秒
- **正常値**: 1000 回/秒以下
- **異常値**: 10000 回/秒以上
- **監視方法**: vmstat、sar

### 2. メモリ性能指標

#### メモリ使用率

```bash
# freeコマンドでの確認
free -h

# topコマンドでの確認
top -p 1

# sarコマンドでの確認
sar -r 1 5
```

#### メモリスワップ

- **定義**: メモリ不足時のディスク使用
- **単位**: バイト（B）
- **正常値**: 0 バイト
- **異常値**: 1GB 以上
- **監視方法**: free、vmstat、sar

#### メモリページフォルト

- **定義**: ページ不在時のページ読み込み回数
- **単位**: 回数/秒
- **正常値**: 100 回/秒以下
- **異常値**: 1000 回/秒以上
- **監視方法**: vmstat、sar

### 3. ディスク性能指標

#### ディスク使用率

```bash
# dfコマンドでの確認
df -h

# duコマンドでの確認
du -sh /path/to/directory

# iostatコマンドでの確認
iostat -x 1 5
```

#### ディスク I/O

- **定義**: ディスクの読み書き速度
- **単位**: バイト/秒（Bps）、IOPS
- **正常値**: 設計値の 80%以下
- **異常値**: 設計値の 95%以上
- **監視方法**: iostat、iotop、sar

#### ディスク待機時間

- **定義**: ディスク I/O の待機時間
- **単位**: ミリ秒（ms）
- **正常値**: 10ms 以下
- **異常値**: 100ms 以上
- **監視方法**: iostat、iotop

### 4. ネットワーク性能指標

#### ネットワーク使用率

```bash
# iftopコマンドでの確認
iftop -i eth0

# nethogsコマンドでの確認
nethogs

# sarコマンドでの確認
sar -n DEV 1 5
```

#### パケット損失率

- **定義**: 送信パケットの損失割合
- **単位**: パーセント（%）
- **正常値**: 0.1%以下
- **異常値**: 1%以上
- **監視方法**: ping、traceroute、ネットワーク監視

#### ネットワークレイテンシ

- **定義**: ネットワーク通信の遅延時間
- **単位**: ミリ秒（ms）
- **正常値**: 10ms 以下
- **異常値**: 100ms 以上
- **監視方法**: ping、traceroute

## アプリケーション性能指標

### 1. Web アプリケーション

#### レスポンス時間

- **定義**: HTTP リクエストの応答時間
- **単位**: ミリ秒（ms）
- **正常値**: 200ms 以下
- **異常値**: 1s 以上
- **監視方法**: APM、ログ分析

#### スループット

- **定義**: 単位時間あたりの HTTP リクエスト数
- **単位**: リクエスト/秒（rps）
- **正常値**: 設計値の 80%以上
- **異常値**: 設計値の 50%以下
- **監視方法**: APM、ログ分析

#### エラー率

- **定義**: HTTP エラーの発生割合
- **単位**: パーセント（%）
- **正常値**: 1%以下
- **異常値**: 5%以上
- **監視方法**: APM、ログ分析

### 2. データベース

#### クエリ実行時間

- **定義**: SQL クエリの実行時間
- **単位**: ミリ秒（ms）
- **正常値**: 100ms 以下
- **異常値**: 1s 以上
- **監視方法**: データベース監視、ログ分析

#### 接続数

- **定義**: データベースへの同時接続数
- **単位**: 数値
- **正常値**: 最大接続数の 80%以下
- **異常値**: 最大接続数の 95%以上
- **監視方法**: データベース監視

#### ロック待機時間

- **定義**: データベースロックの待機時間
- **単位**: ミリ秒（ms）
- **正常値**: 10ms 以下
- **異常値**: 100ms 以上
- **監視方法**: データベース監視

#### メモリ最適化

- **スワップ**: スワップの無効化
- **NUMA**: メモリアクセスの最適化

#### ディスク最適化

- **RAID**: 冗長化と性能向上
- **SSD**: 高速ストレージの使用
- **ファイルシステム**: 最適なファイルシステムの選択
- **I/O スケジューラー**: I/O 処理の最適化

#### ネットワーク最適化

- **帯域幅**: 十分な帯域幅の確保
- **レイテンシ**: ネットワーク遅延の削減
- **プロトコル**: 効率的なプロトコルの使用
- **負荷分散**: トラフィックの分散

### 2. アプリケーション最適化

#### コード最適化

- **アルゴリズム**: 効率的なアルゴリズムの選択
- **データ構造**: 適切なデータ構造の使用
- **メモリ管理**: 効率的なメモリ使用
- **並行処理**: マルチスレッド・非同期処理

#### データベース最適化

- **インデックス**: 適切なインデックスの設定
- **クエリ最適化**: 効率的な SQL の作成
- **正規化**: データベース設計の最適化

#### キャッシュ戦略

## 性能テスト

### 1. 負荷テスト

#### 負荷テストの種類

- **単体テスト**: 個別コンポーネントのテスト
- **統合テスト**: 複数コンポーネントのテスト
- **システムテスト**: システム全体のテスト
- **受け入れテスト**: ユーザー要件のテスト

#### 負荷テストツール

- **JMeter**: Apache 製の負荷テストツール
- **LoadRunner**: 商用負荷テストツール
- **Gatling**: 高性能な負荷テストツール
- **Artillery**: Node.js 製の負荷テストツール

### 2. パフォーマンステスト

#### テストシナリオ

- **通常負荷**: 通常の使用状況でのテスト
- **ピーク負荷**: 最大負荷でのテスト
- **ストレステスト**: 限界を超えた負荷でのテスト
- **耐久テスト**: 長時間の負荷でのテスト

#### テスト結果の分析

- **レスポンス時間**: 応答時間の分析
- **スループット**: 処理能力の分析
- **リソース使用率**: システムリソースの分析
- **エラー率**: エラーの発生状況の分析

## まとめ

基本的な性能指標は、システムの健全性を把握し、問題の早期発見と対処を行うための重要な情報源です。適切な性能指標の監視により、システムの性能を維持し、ユーザー体験を向上させることができます。また、性能最適化により、システムの効率性を向上させ、コストを削減することができます。継続的な性能監視と最適化により、安定したシステム運用を実現することができます。
