# サービス管理

## サービスとは

**サービス（Service）**は、Linux システムでバックグラウンドで実行されるプログラムです。システムの起動時に自動的に開始され、システムの終了時に適切に停止されるように設計されています。

## サービス管理システム

### systemd

- 現代の Linux ディストリビューションの標準
- プロセスの並列起動
- 依存関係の自動解決
- ログ管理の統合

### 従来のシステム

- **SysV init**: 従来の初期化システム
- **Upstart**: Ubuntu の初期化システム

## systemctl コマンド

### 基本的な使用方法

#### サービスの状態確認

```bash
# サービスの状態を確認
systemctl status service_name

# すべてのサービスの状態を確認
systemctl list-units --type=service

# 実行中のサービスのみ表示
systemctl list-units --type=service --state=running

# 失敗したサービスのみ表示
systemctl list-units --type=service --state=failed
```

#### サービスの制御

```bash
# サービスを開始
sudo systemctl start service_name

# サービスを停止
sudo systemctl stop service_name

# サービスを再起動
sudo systemctl restart service_name

# サービスを再読み込み
sudo systemctl reload service_name

# サービスを有効化（自動起動）
sudo systemctl enable service_name

# サービスを無効化（自動起動を停止）
sudo systemctl disable service_name
```

### サービスの状態

#### 状態の種類

- **active (running)**: 実行中
- **active (exited)**: 正常終了
- **inactive (dead)**: 停止中
- **failed**: 失敗
- **activating**: 起動中
- **deactivating**: 停止中

#### 状態の確認

```bash
# サービスの詳細状態
systemctl show service_name

# サービスの依存関係
systemctl list-dependencies service_name

# サービスのログ
journalctl -u service_name
```

## サービスの設定

### サービスファイル

#### サービスファイルの場所

```bash
# システムサービス
/etc/systemd/system/

# ユーザーサービス
~/.config/systemd/user/

# パッケージ提供のサービス
/lib/systemd/system/
```

#### サービスファイルの例

```ini
[Unit]
Description=My Service
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/my-service
Restart=always
User=myuser
Group=mygroup

[Install]
WantedBy=multi-user.target
```

### サービスの作成

#### 基本的なサービスファイル

```bash
# サービスファイルを作成
sudo nano /etc/systemd/system/my-service.service

# サービスファイルの内容
[Unit]
Description=My Custom Service
After=network.target

[Service]
Type=simple
ExecStart=/path/to/my-script.sh
Restart=always
User=myuser

[Install]
WantedBy=multi-user.target
```

#### サービスの有効化

```bash
# サービスファイルを再読み込み
sudo systemctl daemon-reload

# サービスを有効化
sudo systemctl enable my-service

# サービスを開始
sudo systemctl start my-service
```

## サービスの監視

### ログの確認

#### journalctl コマンド

```bash
# サービスのログを表示
journalctl -u service_name

# リアルタイムでログを監視
journalctl -u service_name -f

# 特定の時間範囲のログ
journalctl -u service_name --since "2024-01-01" --until "2024-01-02"

# ログの詳細表示
journalctl -u service_name -l
```

#### ログの管理

```bash
# ログのサイズを確認
journalctl --disk-usage

# 古いログを削除
sudo journalctl --vacuum-time=7d

# ログの最大サイズを設定
sudo journalctl --vacuum-size=100M
```

### サービスの監視

#### 監視スクリプトの例

```bash
#!/bin/bash
# サービス監視スクリプト

services=("nginx" "apache2" "mysql" "postgresql")

for service in "${services[@]}"; do
    if systemctl is-active --quiet "$service"; then
        echo "$service is running"
    else
        echo "$service is not running"
        # 必要に応じてサービスを開始
        # sudo systemctl start "$service"
    fi
done
```

## サービスの自動化

### 自動起動の設定

#### サービスの有効化

```bash
# サービスを自動起動に設定
sudo systemctl enable service_name

# サービスの自動起動を無効化
sudo systemctl disable service_name

# 自動起動の状態を確認
systemctl is-enabled service_name
```

#### 依存関係の設定

```bash
# サービスの依存関係を確認
systemctl list-dependencies service_name

# サービスの依存関係を表示
systemctl show service_name --property=Requires
```

### サービスの監視と自動復旧

#### 監視スクリプト

```bash
#!/bin/bash
# サービス監視と自動復旧スクリプト

SERVICE_NAME="nginx"
LOG_FILE="/var/log/service-monitor.log"

check_service() {
    if ! systemctl is-active --quiet "$SERVICE_NAME"; then
        echo "$(date): $SERVICE_NAME is not running. Attempting to start..." >> "$LOG_FILE"
        sudo systemctl start "$SERVICE_NAME"

        if systemctl is-active --quiet "$SERVICE_NAME"; then
            echo "$(date): $SERVICE_NAME started successfully." >> "$LOG_FILE"
        else
            echo "$(date): Failed to start $SERVICE_NAME." >> "$LOG_FILE"
        fi
    fi
}

# 監視ループ
while true; do
    check_service
    sleep 60
done
```

## トラブルシューティング

### 一般的な問題

#### サービスが起動しない

```bash
# サービスの状態を確認
systemctl status service_name

# サービスのログを確認
journalctl -u service_name

# サービスの依存関係を確認
systemctl list-dependencies service_name
```

#### サービスの設定問題

```bash
# サービスファイルの構文チェック
systemd-analyze verify /etc/systemd/system/service_name.service

# システムの設定を再読み込み
sudo systemctl daemon-reload
```

#### サービスの権限問題

```bash
# サービスの実行ユーザーを確認
systemctl show service_name --property=User

# サービスの権限を確認
systemctl show service_name --property=Group
```

### ログの分析

```bash
# エラーログの検索
journalctl -u service_name | grep -i error

# 警告ログの検索
journalctl -u service_name | grep -i warning

# 特定の時間のログ
journalctl -u service_name --since "1 hour ago"
```

## まとめ

サービス管理は、Linux システムの運用において重要な機能です。systemctl コマンドを使用して、サービスの開始、停止、再起動、有効化、無効化などの操作が可能です。適切なサービス管理により、システムの安定性と可用性を維持できます。特に、ログの監視、依存関係の管理、自動復旧の設定により、効率的なシステム運用が実現できます。定期的な監視と適切な設定により、信頼性の高いシステム運用が可能になります。
