### 目的

AWSにおけるネットワークセキュリティをOSI7層で整理し、設計時の抜け漏れを減らすための要点をまとめます。多層防御を前提とし、低層ほど汎用的・高層ほどアプリ固有の対策になります。

### OSIレイヤーの考え方（超入門）
- ネットワークでデータが届くまでを7つの階層に分けて考える枠組みです。
- パケットは下から上へ評価されます。下位で止めればそれ以降の処理は発生しません。
- 設計は「外側（下位層）で粗くブロック、内側（上位層）で細かく制御」の順で積み上げます。

---

### レイヤー別整理（初心者向け説明 + AWS対応）

#### 1. 物理層 (L1)
- **なにをする層？** ケーブルや電気信号など、物理的にビットを運ぶ層。
- **どんな問題を防ぐ？** 断線や単一回線障害で通信が切れること。
- **AWSでの考え方** AWSの責任範囲が大きい。オンプレ接続では Direct Connect の冗長回線がポイント。
- **主な機能/サービス** Direct Connect、ロケーション二重化
- **確認ポイント** 回線冗長（異キャリア・異経路）/ フェイルオーバー手順の明文化

#### 2. データリンク層 (L2)
- **なにをする層？** 同じセグメント内でフレームを届ける層（MACアドレスの世界）。
- **どんな問題を防ぐ？** 同一リンクでの盗聴・改ざん、リンク障害。
- **AWSでの考え方** DC接続の暗号化や帯域/冗長性確保が中心。
- **主な機能/サービス** MACsec(Direct Connect 暗号化)、LAG、VLAN
- **確認ポイント** MACsec有効化 / LAG構成（容量・冗長性）

#### 3. ネットワーク層 (L3)
- **なにをする層？** IPアドレスでネットワーク間の経路を決める層。
- **どんな問題を防ぐ？** 想定外ネットワークへの到達、ルーティングの誤設定。
- **AWSでの考え方** 到達範囲を最小化し、経路を明示的に制御。ここで大枠を締める。
- **主な機能/サービス** VPC/サブネット、ルートテーブル、Network ACL、Transit Gateway、VPC Peering、Site-to-Site VPN(IPsec)、NAT Gateway、AWS Network Firewall(ステートフル/レス)
- **設定例** パブリック/アプリ/DBにサブネット分割、インターネット到達はALB配下のみ、アウトバウンドはNAT経由に限定
- **よくあるミス** 0.0.0.0/0 へ過剰に開放、経路が複雑で意図せぬ到達が可能
- **確認ポイント** ルート最小化 / 経路の単純化 / Flow Logsで想定外経路を検知

#### 4. トランスポート層 (L4)
- **なにをする層？** TCP/UDPとポート番号でアプリへの“入り口”を決める層。
- **どんな問題を防ぐ？** 不要なポート開放、到達制御の甘さ。
- **AWSでの考え方** セキュリティグループ(SG)を中心に、必要な方向・ポートのみ許可。
- **主な機能/サービス** セキュリティグループ、Network ACL、Network Load Balancer、ヘルスチェック
- **設定例** インバウンドは443のみ、管理系はVPN/踏み台からだけ許可
- **よくあるミス** SGの送信（アウトバウンド）を無制限に放置
- **確認ポイント** SGはホワイトリスト原則 / 双方向の想定を明記

#### 5. セッション層 (L5)
- **なにをする層？** 通信の開始・維持・再開（セッション管理）。
- **どんな問題を防ぐ？** 接続ドロップによるユーザー体験の劣化、負荷分散との相性問題。
- **AWSでの考え方** 必要な場合のみスティッキーを使い、タイムアウトを適切化。
- **主な機能/サービス** ALBスティッキーセッション、TLSセッション再開（実装依存）
- **設定例** 認証状態を維持するならCookieベースで最小限に / アイドルタイムアウトを調整
- **確認ポイント** ステートフル依存を最小化しスケール/復旧に強くする

#### 6. プレゼンテーション層 (L6)
- **なにをする層？** データの表現や暗号化（見た目や形式）を扱う層。
- **どんな問題を防ぐ？** 平文通信の盗聴、弱い暗号による解読。
- **AWSでの考え方** TLSを強制し、証明書はACMで一元管理。HSTSで常時HTTPS。
- **主な機能/サービス** TLS/SSL、AWS Certificate Manager、CloudFrontのTLSポリシー、HSTS
- **設定例** TLS1.2/1.3、強い暗号スイート、証明書の自動更新
- **確認ポイント** 古いTLS/暗号スイートの無効化 / 証明書期限の監視

#### 7. アプリケーション層 (L7)
- **なにをする層？** HTTP/HTTPSやアプリ特有のプロトコル処理。リクエストの中身で判断。
- **どんな問題を防ぐ？** SQLi・XSS・Bot・DDoS・認証/認可不備など、アプリ固有の攻撃。
- **AWSでの考え方** 入力内容・レート・ユーザー属性で制御。公開点はALB/CloudFrontに集約。
- **主な機能/サービス** AWS WAF、AWS Shield、ALB(L7ルール)、API Gateway、Amazon Cognito(認証/認可)、Route 53 DNSSEC、Firewall Manager、Gateway Load Balancer + パートナーIPS
- **設定例** WAFマネージドルール/レート制限、Bot対策、ALBのパス/ホストルーティング、APIのJWT検証、DNSSEC署名、Shield AdvancedでL3–7 DDoS対策
- **確認ポイント** 最小権限の認可、リクエスト検証、スロットリング、監査ログ

### 設計チェックリスト（実務向け）
- **セグメント分割**: 役割ごとにサブネット分離、最小経路のみ許可
- **ファイアウォール**: NACL/SG/Network Firewallを重層適用
- **IDS/IPS**: Network Firewall、GWLB連携で侵入検知/防御
- **IP秘匿**: NAT Gateway/PrivateLinkで私設化、Egress制御
- **公開点の集約**: ALB/NLB/CloudFrontに集約し、ワークロードは非公開
- **暗号化**: エンドツーエンドTLS、証明書/暗号スイート標準化
- **L7保護**: WAF/Shield、入力検証、レート制御、認証認可
- **監視**: VPC Flow Logs、NFW/ALB/WAF/CloudFront/Route53ログ、Security Hubで集約
