# ルートユーザー

## 概要

**ルートユーザー**は、AWSアカウントを作成した時に自動的に作成される、最も権限の強いユーザーです。

## 特徴

### 1. 完全な権限
- AWSアカウント内のすべてのリソースとサービスにアクセス可能
- 他のユーザーやロールでは実行できない操作も可能
- アカウントレベルの設定変更が可能

### 2. 削除不可
- ルートユーザーは削除できません
- アカウントの所有者として永続的に存在
- アカウント削除時のみ消滅

### 3. アカウント作成時のみ
- 新規作成はできません
- 1つのAWSアカウントに1つのルートユーザーのみ
- 他のユーザーからルートユーザーに昇格することは不可能

## ルートユーザーの権限

### 1. アカウント管理
```json
{
  "Effect": "Allow",
  "Action": [
    "aws-portal:*Billing",
    "aws-portal:*Account",
    "organizations:*",
    "account:*"
  ],
  "Resource": "*"
}
```

**実行可能な操作:**
- ✅ アカウントの削除
- ✅ 請求情報の変更
- ✅ 支払い方法の変更
- ✅ アカウント名の変更
- ✅ サポートプランの変更

### 2. セキュリティ設定
```json
{
  "Effect": "Allow",
  "Action": [
    "iam:*",
    "cloudtrail:*",
    "config:*",
    "securityhub:*"
  ],
  "Resource": "*"
}
```

**実行可能な操作:**
- ✅ セキュリティ設定の変更
- ✅ IAMユーザーの作成・削除
- ✅ ポリシーの作成・変更
- ✅ MFA設定の変更
- ✅ パスワードポリシーの設定

### 3. サービス制限の変更
```json
{
  "Effect": "Allow",
  "Action": [
    "servicequotas:*",
    "support:*"
  ],
  "Resource": "*"
}
```

**実行可能な操作:**
- ✅ サービス制限の引き上げ申請
- ✅ サポートケースの作成
- ✅ 緊急時のアクセス復旧

## ルートユーザーの識別方法

### 1. コンソールでの確認
```
AWS Management Console
↓
右上のアカウント名をクリック
↓
「セキュリティ認証情報」を選択
↓
「ルートユーザー」セクションで確認
```

### 2. CLIでの確認
```bash
# 現在のユーザー情報を確認
aws sts get-caller-identity

# 出力例
{
    "UserId": "AIDACKCEVSQ6C2EXAMPLE",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:root"
}
```

### 3. ルートユーザーの特徴
- **ARN**: `arn:aws:iam::123456789012:root`
- **ユーザーID**: `AIDACKCEVSQ6C2EXAMPLE`（固定）
- **ユーザー名**: なし（ルートユーザーは名前を持たない）

## ルートユーザーの保護

### 1. 多要素認証（MFA）の設定

#### ハードウェアMFAデバイス
```bash
# ハードウェアMFAデバイスの設定
aws iam create-virtual-mfa-device \
    --virtual-mfa-device-name MyMFADevice \
    --outfile QRCode.png \
    --bootstrap-method QRCodePNG
```

#### ソフトウェアMFAアプリケーション
```bash
# ソフトウェアMFAの設定
aws iam enable-mfa-device \
    --user-name root \
    --serial-number arn:aws:iam::123456789012:mfa/root-account-mfa-device \
    --authentication-code1 123456 \
    --authentication-code2 789012
```

### 2. アクセスキーの管理

#### アクセスキーの作成（非推奨）
```bash
# アクセスキーの作成（緊急時のみ）
aws iam create-access-key \
    --user-name root
```

#### アクセスキーの削除
```bash
# 不要なアクセスキーの削除
aws iam delete-access-key \
    --user-name root \
    --access-key-id AKIAIOSFODNN7EXAMPLE
```

### 3. パスワードの強化

#### 強力なパスワードの要件
```
✅ 最低12文字以上
✅ 大文字・小文字・数字・記号を含む
✅ 辞書に載っていない単語
✅ 個人情報を含まない
✅ 定期的な変更（90日ごと推奨）
```

#### パスワードポリシーの設定
```json
{
  "MinimumPasswordLength": 12,
  "RequireSymbols": true,
  "RequireNumbers": true,
  "RequireUppercaseCharacters": true,
  "RequireLowercaseCharacters": true,
  "MaxPasswordAge": 90,
  "PasswordReusePrevention": 5
}
```


### 2. アカウントレベルの設定変更
```
シナリオ: 請求情報の変更が必要
解決策: ルートユーザーで設定を変更
```

### 3. セキュリティインシデント対応
```
シナリオ: 不正アクセスの疑い
解決策: ルートユーザーで緊急対応
```

## ルートユーザーの制限事項

### 1. 日常使用の制限
- **セキュリティリスク**: 完全な権限による危険性
- **監査の困難**: 操作の追跡が困難
- **誤操作の影響**: 大きな損害の可能性

### 2. アクセス制限
- **IP制限**: 特定のIPからのみアクセス
- **時間制限**: 特定の時間帯のみアクセス
- **デバイス制限**: 特定のデバイスからのみアクセス

### 3. 監視の強化
- **CloudTrail**: すべての操作をログ記録
- **CloudWatch**: 異常なアクセスの監視
- **GuardDuty**: 脅威の検出

## ベストプラクティス

### 1. アクセス制限
```
✅ 特定のIPからのみアクセス
✅ 特定の時間帯のみアクセス
✅ 特定のデバイスからのみアクセス
✅ VPN経由でのアクセス
```

### 2. 監視とアラート
```
✅ すべての操作をCloudTrailで記録
✅ 異常なアクセスをCloudWatchで監視
✅ 緊急時のアラート設定
✅ 定期的なアクセスログの確認
```

### 3. 代替手段の準備
```
✅ 管理者IAMユーザーの作成
✅ 緊急時連絡先の設定
✅ アクセス復旧手順の文書化
✅ 定期的な復旧手順のテスト
```

## トラブルシューティング

### 1. ルートユーザーにアクセスできない場合

#### パスワードを忘れた場合
```
1. AWSサポートに連絡
2. 本人確認書類の提出
3. パスワードリセットの実行
```

#### MFAデバイスを紛失した場合
```
1. AWSサポートに連絡
2. 本人確認書類の提出
3. MFAデバイスの無効化
4. 新しいMFAデバイスの設定
```

### 2. セキュリティインシデント対応

#### 不正アクセスの疑い
```
1. 即座にパスワードを変更
2. すべてのアクセスキーを削除
3. MFAデバイスを再設定
4. CloudTrailログを確認
5. 影響範囲を調査
```
