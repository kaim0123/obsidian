## 目的
AWS上でのアプリ開発〜運用までの標準フローを、選択肢別に横串で整理する。

## 開発スタイルの選択肢
- ローカルPC + クラウド実行（Lambda/ECS/EKS/Amplify など）
- ローカルPC + EC2 リモート開発（SSH/SSM 経由で Cursor/VS Code から接続）
- フルマネージドIDE（AWS Cloud9）

## 推奨の考え方（結論）
- 小〜中規模/サーバーレス適性あり: Lambda + API Gateway（IaC + CI/CD前提）
- コンテナ化済み/標準Web: ECS on Fargate（Blue/Green と IaC）
- OS依存/レガシー移行/要フル制御: EC2（SSM優先、直接SSHは極力最小化）

## 共通フェーズ
1. 要件とアーキテクチャの選定（コスト・可用性・運用）
2. 開発環境の選定（ローカル/EC2/Cloud9/サーバーレス）
3. ソース管理（GitHub/GitLab, ブランチ戦略）
4. IaC 準備（Terraform または AWS CDK）
5. セキュリティ基盤（IAM・KMS・ネットワーク・Secrets 管理）
6. CI/CD（CodePipeline/GitHub Actions）
7. 監視・ログ・運用（CloudWatch/CloudTrail/SSM/Backup）

## 入口の分岐
- EC2 + SSH/Cursor から始めるのは「OS前提」「既存資産の移行」「一時的に早く動かしたい」場合に有効。一般論としては、まずはマネージド/サーバーレスを検討し、妥当でなければEC2に落とす。
