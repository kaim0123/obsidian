# ルーティング

## 概要

ルーティング（Routing）は、ネットワーク上でデータパケットを正しい宛先に転送する仕組みです。ルーターがルーティングテーブルを参照して、最適な経路を決定し、パケットを転送します。

## ルーティングの基本概念

### ルーターの役割

1. **経路決定**: パケットの宛先に最適な経路を選択
2. **パケット転送**: 決定した経路でパケットを転送
3. **ルーティングテーブル管理**: ネットワーク情報の維持・更新

### ポート番号の基本概念

ネットワーク通信において、ポート番号は特定のサービスやアプリケーションを識別するために使用されます。

#### よく使用されるポート番号

| ポート番号 | プロトコル | 用途                       |
| ---------- | ---------- | -------------------------- |
| 22         | SSH        | セキュアなリモートログイン |
| 80         | HTTP       | Web サーバー（暗号化なし） |
| 443        | HTTPS      | Web サーバー（暗号化あり） |
| 25         | SMTP       | メール送信                 |
| 53         | DNS        | ドメイン名解決             |

#### SSH ポート 22 について

**SSH（Secure Shell）**は、ネットワーク経由でサーバーに安全にログインするためのプロトコルです。

**特徴:**

- **暗号化通信**: すべての通信が暗号化される
- **認証機能**: パスワード認証や公開鍵認証をサポート
- **ポート番号 22**: デフォルトでポート 22 を使用
- **セキュリティ**: Telnet（ポート 23）の安全な代替手段

**使用例:**

```bash
# SSH接続の例
ssh -p 22 username@server-ip-address
```

**セキュリティ考慮事項:**

- ポート 22 は攻撃者に狙われやすいため、非標準ポートへの変更を推奨
- ファイアウォールでアクセス元 IP アドレスを制限
- 公開鍵認証の使用を推奨

#### HTTP ポート 80 について

**HTTP（HyperText Transfer Protocol）**は、Web ページを取得するための基本的なプロトコルです。

**特徴:**

- **非暗号化通信**: データが平文で送信される
- **ステートレス**: 各リクエストは独立して処理される
- **ポート番号 80**: デフォルトでポート 80 を使用
- **Web の基盤**: インターネット上の Web サイトの標準

**使用例:**

```bash
# HTTP アクセスの例
curl http://example.com
# ブラウザで http://example.com にアクセス
```

**セキュリティ考慮事項:**

- パスワードや個人情報は暗号化されない
- HTTPS への移行を推奨
- ファイアウォールで適切なアクセス制御を設定

#### HTTPS ポート 443 について

**HTTPS（HTTP Secure）**は、HTTP に暗号化機能を追加したセキュアなプロトコルです。

**特徴:**

- **暗号化通信**: SSL/TLS による暗号化
- **認証機能**: サーバーの身元確認
- **ポート番号 443**: デフォルトでポート 443 を使用
- **データ保護**: 機密情報の安全な送信

**使用例:**

```bash
# HTTPS アクセスの例
curl https://example.com
# ブラウザで https://example.com にアクセス
```

**セキュリティ考慮事項:**

- SSL/TLS 証明書の適切な管理
- 強力な暗号化アルゴリズムの使用
- 証明書の有効期限管理

#### SMTP ポート 25 について

**SMTP（Simple Mail Transfer Protocol）**は、メール送信のためのプロトコルです。

**特徴:**

- **メール送信**: 電子メールの送信専用
- **非暗号化**: 基本的には平文で送信
- **ポート番号 25**: デフォルトでポート 25 を使用
- **メールサーバー間通信**: サーバー間でのメール転送

**使用例:**

```bash
# SMTP サーバーへの接続テスト
telnet smtp.example.com 25
```

**セキュリティ考慮事項:**

- スパム対策のための認証設定
- 送信元 IP アドレスの制限
- 暗号化版（SMTPS）の使用を推奨

#### DNS ポート 53 について

**DNS（Domain Name System）**は、ドメイン名を IP アドレスに変換するシステムです。

**特徴:**

- **名前解決**: ドメイン名から IP アドレスへの変換
- **階層構造**: 分散型のデータベースシステム
- **ポート番号 53**: デフォルトでポート 53 を使用
- **インターネットの基盤**: すべての Web アクセスに必要

**使用例:**

```bash
# DNS クエリの例
nslookup example.com
dig example.com
```

**セキュリティ考慮事項:**

- DNS キャッシュポイズニング攻撃への対策
- DNSSEC の導入を検討
- 信頼できる DNS サーバーの使用

### ルーティングテーブル

ルーティングテーブルは、宛先ネットワークと次の転送先（ネクストホップ）の対応表です。

```
宛先ネットワーク    ネクストホップ      インターフェース
192.168.1.0/24     直接接続          eth0
10.0.0.0/8         192.168.1.1       eth0
0.0.0.0/0          192.168.1.1       eth0 (デフォルトルート)
```

## ルーティングの種類

### 1. スタティックルーティング

管理者が手動でルートを設定する方法：

**特徴:**

- 設定が簡単
- ネットワーク帯域を消費しない
- 障害時の自動切り替えなし

**例:**

```
宛先: 10.0.0.0/8
ネクストホップ: 192.168.1.1
```

### 2. ダイナミックルーティング

ルーティングプロトコルを使用して自動的にルートを学習する方法：

**特徴:**

- 自動的な経路学習
- 障害時の自動切り替え
- 設定が複雑

**主要なプロトコル:**

- RIP (Routing Information Protocol)
- OSPF (Open Shortest Path First)
- BGP (Border Gateway Protocol)

## ルーティングの決定プロセス

### 1. 最長一致の原則

最も具体的な（プレフィックス長が長い）ルートを選択：

```
ルーティングテーブル:
192.168.1.0/24    → 直接接続
192.168.0.0/16    → 192.168.1.1
0.0.0.0/0         → 192.168.1.1

宛先: 192.168.1.10
選択されるルート: 192.168.1.0/24 (最長一致)
```

### 2. 管理距離

同じ宛先への複数のルートがある場合、管理距離が小さいものを選択：

| ルートソース | 管理距離 |
| ------------ | -------- |
| 直接接続     | 0        |
| スタティック | 1        |
| EIGRP        | 90       |
| OSPF         | 110      |
| RIP          | 120      |

## AWS でのルーティング

### VPC のルーティング

```
VPC: 10.0.0.0/16
├─ メインルートテーブル
│  ├─ 10.0.0.0/16 → ローカル
│  └─ 0.0.0.0/0 → igw-xxxxx (インターネットゲートウェイ)
└─ カスタムルートテーブル
   ├─ 10.0.0.0/16 → ローカル
   └─ 0.0.0.0/0 → nat-xxxxx (NATゲートウェイ)
```

### ルートテーブルの種類

#### 1. メインルートテーブル

- VPC 作成時に自動作成
- すべてのサブネットに適用（明示的に変更しない限り）

#### 2. カスタムルートテーブル

- ユーザーが作成
- 特定のサブネットに明示的に関連付け

### AWS のルートターゲット

| ターゲット                   | 用途               | 例                      |
| ---------------------------- | ------------------ | ----------------------- |
| ローカル                     | VPC 内通信         | 10.0.0.0/16 → ローカル  |
| インターネットゲートウェイ   | インターネット接続 | 0.0.0.0/0 → igw-xxxxx   |
| NAT ゲートウェイ             | アウトバウンド専用 | 0.0.0.0/0 → nat-xxxxx   |
| VPC ピアリング               | VPC 間通信         | 10.1.0.0/16 → pcx-xxxxx |
| 仮想プライベートゲートウェイ | VPN 接続           | 0.0.0.0/0 → vgw-xxxxx   |

## 実践的なルーティング設計

### 3 層アーキテクチャでのルーティング

```
インターネット
    ↓
インターネットゲートウェイ
    ↓
パブリックサブネット (10.0.1.0/24)
├─ ルートテーブル:
│  ├─ 10.0.0.0/16 → ローカル
│  └─ 0.0.0.0/0 → igw-xxxxx
    ↓
プライベートサブネット (10.0.2.0/24)
├─ ルートテーブル:
│  ├─ 10.0.0.0/16 → ローカル
│  └─ 0.0.0.0/0 → nat-xxxxx
    ↓
データベースサブネット (10.0.3.0/24)
├─ ルートテーブル:
│  └─ 10.0.0.0/16 → ローカル (インターネットアクセスなし)
```

### マルチ AZ 設計

```
AZ-A:
├─ パブリックサブネット: 10.0.1.0/24
├─ プライベートサブネット: 10.0.2.0/24
└─ データベースサブネット: 10.0.3.0/24

AZ-B:
├─ パブリックサブネット: 10.0.4.0/24
├─ プライベートサブネット: 10.0.5.0/24
└─ データベースサブネット: 10.0.6.0/24

共通ルート:
├─ 10.0.0.0/16 → ローカル
└─ 0.0.0.0/0 → igw-xxxxx (パブリック) / nat-xxxxx (プライベート)
```

## ルーティングのトラブルシューティング

### よくある問題

#### 1. ルートの欠落

```
症状: 特定のネットワークにアクセスできない
原因: ルーティングテーブルに該当するルートがない
解決: 適切なルートを追加
```

#### 2. ルートの競合

```
症状: 予期しない経路でパケットが転送される
原因: 複数のルートが存在し、優先順位が不明確
解決: 管理距離の調整または不要なルートの削除
```

#### 3. ループの発生

```
症状: パケットが無限に転送される
原因: ルーティングテーブルの設定ミス
解決: ルーティングテーブルの見直し
```

### 確認コマンド

```bash
# ルートテーブル確認
aws ec2 describe-route-tables

# 特定のサブネットのルートテーブル確認
aws ec2 describe-route-tables --filters "Name=association.subnet-id,Values=subnet-xxxxx"

# ルートの追加
aws ec2 create-route --route-table-id rtb-xxxxx --destination-cidr-block 0.0.0.0/0 --gateway-id igw-xxxxx
```

## セキュリティとルーティング

### ネットワーク ACL

サブネットレベルでのトラフィック制御：

```
インバウンドルール:
- 100: HTTP (80) を 0.0.0.0/0 から許可
- 200: HTTPS (443) を 0.0.0.0/0 から許可
- 300: SSH (22) を 10.0.0.0/16 から許可
- 32767: すべてを拒否

アウトバウンドルール:
- 100: すべてのトラフィックを 0.0.0.0/0 へ許可
- 32767: すべてを拒否
```

### セキュリティグループ

インスタンスレベルでのトラフィック制御：

```
Webサーバー用セキュリティグループ:
- HTTP (80): 0.0.0.0/0 から許可
- HTTPS (443): 0.0.0.0/0 から許可
- SSH (22): 管理用IP から許可
```

## まとめ

ルーティングはネットワーク通信の基盤です。AWS の VPC 設計において、適切なルートテーブルの設定、インターネットゲートウェイや NAT ゲートウェイの活用、セキュリティの考慮が重要です。パブリック・プライベートサブネットの分離、マルチ AZ 設計、トラフィック制御の組み合わせで、安全で効率的なネットワークを構築できます。
