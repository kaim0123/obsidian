# サブネット

## 概要

サブネット（Subnet）は、大きなネットワークを小さなネットワークに分割したものです。セキュリティの向上、トラフィックの制御、管理の効率化を目的として使用されます。

## サブネットの基本概念

### なぜサブネットが必要なのか

1. **セキュリティの向上**: ネットワークを分離してアクセス制御
2. **トラフィックの制御**: 不要な通信を減らし、パフォーマンス向上
3. **管理の効率化**: 小さな単位でネットワークを管理
4. **IP アドレスの有効活用**: 限られた IP アドレスを効率的に使用

### サブネットマスク

サブネットマスクは、IP アドレスのどの部分がネットワーク部で、どの部分がホスト部かを示します。

```
IPアドレス: 192.168.1.10
サブネットマスク: 255.255.255.0
結果: 192.168.1.0/24 ネットワーク
```

## サブネットマスクの種類

### クラス別サブネットマスク

| クラス | デフォルトマスク    | 例             | 利用可能ホスト数 |
| ------ | ------------------- | -------------- | ---------------- |
| A      | 255.0.0.0 (/8)      | 10.0.0.0/8     | 16,777,214       |
| B      | 255.255.0.0 (/16)   | 172.16.0.0/16  | 65,534           |
| C      | 255.255.255.0 (/24) | 192.168.1.0/24 | 254              |

### 可変長サブネットマスク（VLSM）

同じネットワーク内で異なるサイズのサブネットを作成：

```
元のネットワーク: 192.168.1.0/24
├─ サーバー用: 192.168.1.0/26 (62台)
├─ PC用: 192.168.1.64/26 (62台)
├─ プリンター用: 192.168.1.128/27 (30台)
└─ 管理用: 192.168.1.160/28 (14台)
```

## サブネットの計算方法

### 基本的な計算

```
ネットワーク: 192.168.1.0/24
サブネットマスク: 255.255.255.0
二進数: 11111111.11111111.11111111.00000000
```

### 利用可能な IP アドレス数

- **総 IP 数**: 2^ホストビット数
- **使用可能 IP 数**: 総 IP 数 - 2（ネットワークアドレス + ブロードキャストアドレス）

### 計算例

```
/24 サブネット:
- ホストビット: 8ビット
- 総IP数: 2^8 = 256
- 使用可能IP数: 256 - 2 = 254

/26 サブネット:
- ホストビット: 6ビット
- 総IP数: 2^6 = 64
- 使用可能IP数: 64 - 2 = 62
```

## AWS でのサブネット

### VPC とサブネットの関係

```
VPC: 10.0.0.0/16
├─ パブリックサブネット: 10.0.1.0/24
│  ├─ インターネットゲートウェイへのルート
│  └─ パブリックIPアドレスを持つリソース
├─ プライベートサブネット: 10.0.2.0/24
│  ├─ インターネットアクセスなし
│  └─ プライベートIPアドレスのみ
└─ データベースサブネット: 10.0.3.0/24
   └─ データベース専用
```

### サブネットの種類

#### 1. パブリックサブネット

- **特徴**: インターネットゲートウェイへのルートがある
- **用途**: Web サーバー、ロードバランサー
- **IP アドレス**: パブリック IP アドレスを割り当て可能

#### 2. プライベートサブネット

- **特徴**: インターネットゲートウェイへのルートがない
- **用途**: アプリケーションサーバー、データベース
- **IP アドレス**: プライベート IP アドレスのみ

#### 3. データベースサブネット

- **特徴**: さらに厳格なセキュリティ
- **用途**: RDS、ElastiCache
- **アクセス**: 特定のサブネットからのみ

## サブネット設計のベストプラクティス

### 1. 適切なサイズの選択

```
小規模環境:
- VPC: /16 (65,536 IP)
- サブネット: /24 (256 IP)

中規模環境:
- VPC: /16 (65,536 IP)
- サブネット: /22 (1,024 IP)

大規模環境:
- VPC: /12 (1,048,576 IP)
- サブネット: /20 (4,096 IP)
```

### 2. 可用性ゾーンの考慮

```
リージョン: ap-northeast-1
├─ AZ: ap-northeast-1a
│  ├─ パブリックサブネット: 10.0.1.0/24
│  └─ プライベートサブネット: 10.0.2.0/24
├─ AZ: ap-northeast-1c
│  ├─ パブリックサブネット: 10.0.3.0/24
│  └─ プライベートサブネット: 10.0.4.0/24
└─ AZ: ap-northeast-1d
   ├─ パブリックサブネット: 10.0.5.0/24
   └─ プライベートサブネット: 10.0.6.0/24
```

### 3. セキュリティの階層化

```
インターネット
    ↓
パブリックサブネット (Web層)
    ↓
プライベートサブネット (アプリ層)
    ↓
データベースサブネット (DB層)
```

## 実践例

### 3 層アーキテクチャ

```
VPC: 10.0.0.0/16

Web層 (パブリック):
- 10.0.1.0/24 (ap-northeast-1a)
- 10.0.2.0/24 (ap-northeast-1c)

アプリ層 (プライベート):
- 10.0.10.0/24 (ap-northeast-1a)
- 10.0.11.0/24 (ap-northeast-1c)

DB層 (プライベート):
- 10.0.20.0/24 (ap-northeast-1a)
- 10.0.21.0/24 (ap-northeast-1c)
```

## トラブルシューティング

### よくある問題

1. **IP アドレス不足**: サブネットサイズが小さすぎる
2. **ルーティング問題**: サブネット間の通信設定ミス
3. **セキュリティグループ**: サブネット間のアクセス制御

### 確認方法

```bash
# サブネット情報確認
aws ec2 describe-subnets

# ルートテーブル確認
aws ec2 describe-route-tables
```

## まとめ

サブネットはネットワークの基本単位です。AWS の VPC 設計において、セキュリティ、可用性、管理性を考慮した適切なサブネット設計が重要です。パブリック・プライベートの分離、可用性ゾーンへの分散、適切なサイズの選択が成功の鍵となります。
