# CIDR 表記

## 概要

CIDR（Classless Inter-Domain Routing）表記は、IP アドレスとサブネットマスクを簡潔に表現する方法です。従来のクラスベースのアドレッシングの制限を克服し、より柔軟なネットワーク設計を可能にします。

## CIDR 表記の基本

### 表記方法

```
IPアドレス/プレフィックス長
例: 192.168.1.0/24
```

### プレフィックス長とは

- ネットワーク部のビット数を示す
- 0〜32 の数値で表現
- サブネットマスクの 1 の数を表す

### 従来の表記との比較

```
従来の表記:
IPアドレス: 192.168.1.0
サブネットマスク: 255.255.255.0

CIDR表記:
192.168.1.0/24
```

## プレフィックス長とサブネットマスク

### 主要なプレフィックス長

| プレフィックス長 | サブネットマスク | 利用可能 IP 数 | 例             |
| ---------------- | ---------------- | -------------- | -------------- |
| /8               | 255.0.0.0        | 16,777,214     | 10.0.0.0/8     |
| /16              | 255.255.0.0      | 65,534         | 172.16.0.0/16  |
| /24              | 255.255.255.0    | 254            | 192.168.1.0/24 |
| /25              | 255.255.255.128  | 126            | 192.168.1.0/25 |
| /26              | 255.255.255.192  | 62             | 192.168.1.0/26 |
| /27              | 255.255.255.224  | 30             | 192.168.1.0/27 |
| /28              | 255.255.255.240  | 14             | 192.168.1.0/28 |
| /30              | 255.255.255.252  | 2              | 192.168.1.0/30 |
| /32              | 255.255.255.255  | 1              | 192.168.1.1/32 |

## CIDR 表記の計算方法

### 二進数での理解

```
192.168.1.0/24 の場合:
IPアドレス: 11000000.10101000.00000001.00000000
プレフィックス: 11111111.11111111.11111111.00000000
ネットワーク部: 11000000.10101000.00000001.00000000 (24ビット)
ホスト部: 00000000 (8ビット)
```

### 利用可能 IP 数の計算

```
/24 の場合:
- ホストビット数: 32 - 24 = 8ビット
- 総IP数: 2^8 = 256
- 使用可能IP数: 256 - 2 = 254
  (ネットワークアドレス + ブロードキャストアドレス)
```

## AWS での CIDR 表記

### VPC の CIDR ブロック

```
VPC CIDR: 10.0.0.0/16
- 利用可能IP数: 65,536
- 範囲: 10.0.0.0 〜 10.0.255.255
```

### サブネットの CIDR ブロック

```
VPC: 10.0.0.0/16
├─ パブリックサブネット: 10.0.1.0/24
├─ プライベートサブネット: 10.0.2.0/24
└─ データベースサブネット: 10.0.3.0/24
```

### セキュリティグループの CIDR

```
インバウンドルール:
- プロトコル: HTTP
- ポート: 80
- ソース: 0.0.0.0/0 (すべてのIPから)

アウトバウンドルール:
- プロトコル: HTTPS
- ポート: 443
- 宛先: 0.0.0.0/0 (すべてのIPへ)
```

## サブネット分割の例

### /16 を/24 に分割

```
元のネットワーク: 10.0.0.0/16
分割後:
├─ 10.0.1.0/24
├─ 10.0.2.0/24
├─ 10.0.3.0/24
├─ ...
└─ 10.0.255.0/24
```

### 可変長サブネットマスク（VLSM）

```
元のネットワーク: 192.168.1.0/24
分割例:
├─ サーバー用: 192.168.1.0/26 (62台)
├─ PC用: 192.168.1.64/26 (62台)
├─ プリンター用: 192.168.1.128/27 (30台)
└─ 管理用: 192.168.1.160/28 (14台)
```

### 企業ネットワーク設計

本社ネットワーク: 10.0.0.0/16
├─ 管理部門: 10.0.1.0/24
├─ 営業部門: 10.0.2.0/24

支社ネットワーク: 10.1.0.0/16

```
リージョン1 (ap-northeast-1):
- VPC: 10.0.0.0/16

リージョン2 (us-east-1):
- VPC: 10.1.0.0/16

リージョン3 (eu-west-1):
- VPC: 10.2.0.0/16
```

## CIDR 表記の利点

### 1. 柔軟性

- 任意のサイズのサブネットを作成可能
- クラス制限からの解放

### 2. 効率性

- IP アドレスの有効活用
- ルーティングテーブルの集約

### 3. 簡潔性

- 短い表記でネットワークを表現
- 設定の簡素化

## よくある CIDR 表記

### 特殊な表記

| CIDR 表記      | 意味                 | 用途             |
| -------------- | -------------------- | ---------------- |
| 0.0.0.0/0      | すべての IP アドレス | デフォルトルート |
| 127.0.0.0/8    | ループバック         | ローカル通信     |
| 169.254.0.0/16 | リンクローカル       | DHCP 失敗時      |
| 224.0.0.0/4    | マルチキャスト       | グループ通信     |

### プライベート IP アドレス範囲

| CIDR 表記      | 範囲                         | 用途       |
| -------------- | ---------------------------- | ---------- |
| 10.0.0.0/8     | 10.0.0.0〜10.255.255.255     | 大規模組織 |
| 172.16.0.0/12  | 172.16.0.0〜172.31.255.255   | 中規模組織 |
| 192.168.0.0/16 | 192.168.0.0〜192.168.255.255 | 小規模組織 |

## トラブルシューティング

### よくある問題

1. **CIDR 重複**: 異なるサブネットで同じ IP 範囲を使用
2. **サイズ不足**: サブネットサイズが小さすぎる
3. **ルーティング問題**: CIDR 設定とルートテーブルの不整合

### 確認方法

```bash
# サブネット一覧確認
aws ec2 describe-subnets --query 'Subnets[*].[SubnetId,CidrBlock]'

# ルートテーブル確認
aws ec2 describe-route-tables --query 'RouteTables[*].[RouteTableId,Routes[*].DestinationCidrBlock]'
```

## まとめ

CIDR 表記は現代のネットワーク設計の基本です。AWS の VPC、サブネット、セキュリティグループの設定で頻繁に使用されます。プレフィックス長の理解、適切なサイズの選択、重複の回避が、効果的なネットワーク設計の鍵となります。
