# Transit Gateway とは

## 概要

Transit Gateway は、**複数の VPC やオンプレミス環境を中央集権的に接続**する AWS のサービスです。従来の VPC ピアリング接続では、VPC 間の接続が複雑になりがちでしたが、Transit Gateway を使用することで、**ハブ・アンド・スポーク**モデルでシンプルにネットワークを構築できます。

## なぜ Transit Gateway が必要なのか？

### 1. ネットワークの簡素化

- 複数の VPC 間の接続を一元管理
- ハブ・アンド・スポークモデルの実現
- 接続数の大幅な削減

### 2. スケーラビリティの向上

- 最大 5,000 個の VPC 接続
- 複数リージョンでの利用
- 自動スケーリング

### 3. コストの削減

- VPC ピアリング接続の削減
- 管理コストの削減
- 運用の簡素化

## Transit Gateway の構成要素

### 1. Transit Gateway

**中央のハブ**として機能

#### 特徴

- リージョン内で利用可能
- 複数の VPC やオンプレミス環境を接続
- ルーティングの中央管理

### 2. アタッチメント（Attachment）

**Transit Gateway に接続するリソース**

#### 種類

- **VPC アタッチメント**：VPC との接続
- **VPN アタッチメント**：サイト間 VPN との接続
- **Direct Connect アタッチメント**：Direct Connect との接続
- **Transit Gateway ピアリング**：他の Transit Gateway との接続

### 3. ルートテーブル

**トラフィックの転送先を決定**

#### 特徴

- 各アタッチメントにルートテーブルを関連付け
- 動的ルーティングと静的ルーティングの両方をサポート
- 細かい制御が可能

## Transit Gateway の仕組み

### 1. ハブ・アンド・スポークモデル

```
Transit Gateway（ハブ）
├── VPC A（スポーク）
├── VPC B（スポーク）
├── VPC C（スポーク）
├── オンプレミス環境（スポーク）
└── 他のTransit Gateway（スポーク）
```

### 2. ルーティングの流れ

```
VPC A → Transit Gateway → VPC B
VPC A → Transit Gateway → オンプレミス環境
オンプレミス環境 → Transit Gateway → VPC C
```

## 実際の構成例

### 1. 基本的な構成

```
Transit Gateway
├── 本番環境VPC（10.0.0.0/16）
├── ステージング環境VPC（10.1.0.0/16）
├── 開発環境VPC（10.2.0.0/16）
└── 共有サービスVPC（10.3.0.0/16）
```

### 2. マルチリージョン構成

```
リージョンA（東京）
├── Transit Gateway A
├── VPC A1
└── VPC A2
    ↓
Transit Gatewayピアリング
    ↓
リージョンB（大阪）
├── Transit Gateway B
├── VPC B1
└── VPC B2
```

### 3. ハイブリッドクラウド構成

```
Transit Gateway
├── 本番環境VPC
├── ステージング環境VPC
├── オンプレミス環境（Direct Connect）
└── オンプレミス環境（VPN）
```

## ルーティングの設定

### 1. ルートテーブル

```
例：本番環境用ルートテーブル
- 10.1.0.0/16 → ステージング環境VPC
- 10.2.0.0/16 → 開発環境VPC
- 10.3.0.0/16 → 共有サービスVPC
- 192.168.0.0/16 → オンプレミス環境
```

### 2. ルートの種類

- **静的ルート**：手動で設定
- **動的ルート**：BGP で自動学習
- **プロパゲーション**：他のルートテーブルから学習

### 3. ルートの優先順位

1. 静的ルート
2. プロパゲーションされたルート
3. デフォルトルート

## セキュリティ機能

### 1. セキュリティグループ

- アタッチメントレベルでのセキュリティ制御
- インスタンスレベルでの制御
- 動的なルール設定

### 2. ネットワーク ACL

- サブネットレベルでのセキュリティ制御
- ステートレスな制御
- 許可・拒否ルールの設定

### 3. ルートフィルタリング

- 特定のルートの広告を制御
- セキュリティポリシーの実装
- 細かい制御が可能

## 料金について

### 1. Transit Gateway

- **時間料金**：$0.05/時間（約$36/月）
- **データ転送料金**：$0.02/GB

### 2. アタッチメント

- **VPC アタッチメント**：$0.05/時間（約$36/月）
- **VPN アタッチメント**：$0.05/時間（約$36/月）
- **Direct Connect アタッチメント**：$0.05/時間（約$36/月）

### 3. データ転送

- **同一リージョン内**：$0.02/GB
- **異なるリージョン間**：$0.02/GB

## VPC ピアリングとの比較

| 項目             | Transit Gateway | VPC ピアリング |
| ---------------- | --------------- | -------------- |
| 接続数           | 最大 5,000 個   | 最大 125 個    |
| 管理             | 中央集権的      | 分散的         |
| コスト           | 中程度          | 低い           |
| スケーラビリティ | 高い            | 低い           |
| 複雑さ           | 低い            | 高い           |

## まとめ

Transit Gateway は、複数の VPC やオンプレミス環境を中央集権的に管理する強力なサービスです。ハブ・アンド・スポークモデルを実現することで、ネットワークの簡素化、スケーラビリティの向上、コストの削減を同時に実現できます。
