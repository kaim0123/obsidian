## VPCが必要な理由

### 1. セキュリティの向上
VPCを使用しない場合、AWSクラウド内の他のユーザーのリソースと同じネットワーク空間を共有することになります。VPCにより、完全に分離されたプライベートネットワーク環境を構築できます。

```
従来の共有環境:
┌─────────────────────────────────┐
│         AWSクラウド             │
│  ┌─────┐ ┌─────┐ ┌─────┐      │
│  │ あなた │ │他人A│ │他人B│      │
│  │のEC2 │ │のEC2│ │のEC2│      │
│  └─────┘ └─────┘ └─────┘      │
│    ↑ 直接アクセス可能            │
└─────────────────────────────────┘

VPC環境:
┌─────────────────────────────────┐
│         AWSクラウド             │
│  ┌─────────┐   ┌─────────┐     │
│  │ あなたのVPC │   │ 他人のVPC │     │
│  │ ┌─────┐ │   │ ┌─────┐ │     │
│  │ │EC2  │ │   │ │EC2  │ │     │
│  │ └─────┘ │   │ └─────┘ │     │
│  └─────────┘   └─────────┘     │
│     ↑ 完全に分離               │
└─────────────────────────────────┘
```

### 2. ネットワーク制御の柔軟性
- **IPアドレス範囲の自由設定**: 自分の好きなIPアドレス範囲を使用可能
- **サブネットの細かい分割**: 用途別にネットワークを分離
- **ルーティングの完全制御**: どのトラフィックをどこに送るかを自由に決定

### 3. 既存インフラとの統合
```
オンプレミス環境:
┌─────────────┐
│ 本社ネットワーク │
│ 192.168.1.0/24│
└──────┬──────┘
       │ VPN接続
       ▼
┌─────────────┐
│ VPC          │
│ 10.0.0.0/16  │
└─────────────┘
```

### 4. コンプライアンス要件の対応
- **データの地理的制限**: 特定のリージョンにデータを保持
- **監査要件**: ネットワークアクセスの完全なログ取得
- **業界規制**: 金融、医療等の厳格なセキュリティ要件への対応

## 主要な専門用語の説明

### ルートテーブル（Route Table）
ネットワークトラフィックの転送先を決定するルールセットです。パケットがどこに送られるべきかを指定します。

```
ルートテーブルの例：
宛先             ターゲット
10.0.0.0/16     local（VPC内の通信）
0.0.0.0/0       igw-12345678（インターネットゲートウェイ）
```

### インターネットゲートウェイ（Internet Gateway, IGW）
VPCとインターネット間の通信を可能にするゲートウェイです。水平スケーラブルで高可用性を持ちます。

### NATゲートウェイ（NAT Gateway）
プライベートサブネットからインターネットへのアウトバウンド接続を提供します。インターネットからのインバウンド接続は不可です。

### Elastic IP（EIP）
インターネット経由で到達可能な固定のグローバルIPv4アドレスです。EIPは任意のタイミングで別のENI/インスタンス/NAT Gateway/NLBに再割り当てでき、障害時の切り替えが容易です。

- **主な用途**
  - NAT Gateway に必須（各AZのNAT GWごとにEIPが必要）
  - 踏み台EC2（Bastion）など、固定の送信元IPが必要な運用
  - Network Load Balancer（NLB）でAZごとに静的IPを確保
- **課金のポイント**
  - 2024年以降、IPv4アドレスはアタッチ状態でも時間課金（未アタッチは引き続き課金）
  - 不要なEIPは即時解放してコスト最適化
- **制限（クォータ）**
  - リージョンあたりの保有数に上限。必要に応じて増枠申請
- **設計上の注意**
  - ALB は EIP を直接割り当て不可（NLB は可）。ALB で固定IPが必要なら Global Accelerator も選択肢
  - EIP の乱用はセキュリティ/コストの観点で非推奨。可能なら **IPv6**、**VPCエンドポイント/PrivateLink**、**SSM Session Manager** を活用
  - 送信元固定IPが必要なアウトバウンドは、NAT Gateway（EIP）を経由させるのが一般的

### セキュリティグループ（Security Group）
EC2インスタンスのファイアウォールとして機能し、インバウンド・アウトバウンドルールを定義します。ステートフル（接続許可時、戻りのトラフィックも自動許可）です。

### ネットワークACL（Network ACL, NACL）
サブネットレベルでのセキュリティ制御を行います。ステートレス（明示的に戻りのルールも設定が必要）です。

### VPCエンドポイント（VPC Endpoint）
VPC内のリソースがAWSサービスにプライベートに接続できるようにするサービスです。インターネットゲートウェイやNATゲートウェイを経由せずに接続可能です。

### ピアリング接続（VPC Peering Connection）
異なるVPC間でプライベート接続を確立する機能です。同じリージョン内のVPC間で使用できます。

## VPCとは何か

**VPC（Virtual Private Cloud）** は、AWSクラウド内に構築できる論理的に分離された仮想ネットワークです。従来のデータセンター内のネットワークと同じように、独自のIPアドレス範囲、サブネット、ルートテーブル、ゲートウェイを定義できます。

### なぜVPCが必要なのか？

- **セキュリティ**: 他のAWSユーザーから完全に分離された環境
- **制御**: ネットワークの設定を完全にコントロール可能
- **柔軟性**: 既存のインフラストラクチャと統合可能
- **スケーラビリティ**: 必要に応じてリソースを拡張可能

## VPCの基本概念

### 1. CIDRブロック
VPCは**CIDRブロック**（Classless Inter-Domain Routing）でIPアドレス範囲を定義します。

```
例：10.0.0.0/16
- 10.0.0.0: ネットワークアドレス
- /16: サブネットマスク（最初の16ビットがネットワーク部分）
- 利用可能IPアドレス: 10.0.0.1 ～ 10.0.255.254（65,534個）
```

### 2. リージョンとアベイラビリティゾーン
- **リージョン**: VPCは単一のAWSリージョン内に作成される
- **AZ**: サブネットは複数のアベイラビリティゾーンに分散配置可能

### 3. デフォルトVPC vs カスタムVPC
- **デフォルトVPC**: AWSアカウント作成時に自動生成されるVPC
- **カスタムVPC**: ユーザーが独自に設計・作成するVPC

## VPCの主要コンポーネント

### 1. サブネット（Subnet）
VPC内のIPアドレス範囲を分割した小さなネットワーク単位

```
例：VPC 10.0.0.0/16 の場合
├── パブリックサブネット: 10.0.1.0/24
├── プライベートサブネット: 10.0.2.0/24
└── データベースサブネット: 10.0.3.0/24
```

**パブリックサブネット**
- インターネットゲートウェイへの直接ルートがある
- インターネットからアクセス可能
- Webサーバーやロードバランサーに使用

**プライベートサブネット**
- インターネットへの直接ルートがない
- インターネットからアクセス不可
- アプリケーションサーバーやデータベースに使用

### 2. インターネットゲートウェイ（IGW）
- VPCとインターネット間の通信を可能にする
- 水平スケーラブルで高可用性
- パブリックIPアドレスを持つリソースに必要

### 3. ルートテーブル（Route Table）
ネットワークトラフィックの転送先を決定するルールセット

```
ルートテーブルの例：
宛先             ターゲット
10.0.0.0/16     local
0.0.0.0/0       igw-12345678 (インターネットゲートウェイ)
```

### 4. セキュリティグループ（Security Group）
- EC2インスタンスのファイアウォール
- インバウンド・アウトバウンドルールを定義
- ステートフル（接続許可時、戻りのトラフィックも自動許可）

### 5. ネットワークACL（NACL）
- サブネットレベルでのセキュリティ制御
- ステートレス（明示的に戻りのルールも設定が必要）
- デフォルトでは全トラフィックを許可

### 6. NATゲートウェイ/インスタンス
- プライベートサブネットからインターネットへのアウトバウンド接続を提供
- インターンットからのインバウンド接続は不可
- ソフトウェア更新や外部API呼び出しに使用

## VPCの作成とセットアップ

### ステップ1: VPCの作成
1. AWSマネジメントコンソール → VPC → Create VPC
2. 名前タグとIPv4 CIDRブロックを設定
3. 例：`MyVPC` / `10.0.0.0/16`

### ステップ2: サブネットの作成
```bash
# パブリックサブネット（us-east-1a）
名前: PublicSubnet1
CIDR: 10.0.1.0/24
AZ: us-east-1a

# プライベートサブネット（us-east-1b）
名前: PrivateSubnet1
CIDR: 10.0.2.0/24
AZ: us-east-1b
```

### ステップ3: インターネットゲートウェイの作成と接続
1. Internet Gatewayを作成
2. VPCにアタッチ
3. ルートテーブルにルートを追加

### ステップ4: セキュリティグループの設定
```bash
# Webサーバー用セキュリティグループ
インバウンドルール:
- HTTP (80) from 0.0.0.0/0
- HTTPS (443) from 0.0.0.0/0
- SSH (22) from 10.0.0.0/16

# データベース用セキュリティグループ
インバウンドルール:
- MySQL (3306) from 10.0.0.0/16
```

## ネットワーク設定とルーティング

### ルートテーブルの設定例

**パブリックサブネット用ルートテーブル**
```
宛先CIDRブロック    ターゲット
10.0.0.0/16        local
0.0.0.0/0          igw-12345678
```

**プライベートサブネット用ルートテーブル**
```
宛先CIDRブロック    ターゲット
10.0.0.0/16        local
0.0.0.0/0          nat-12345678
```

### VPCピアリング
異なるVPC間でプライベート接続を確立

```bash
# ピアリング接続の作成
1. リクエスターVPC: 10.0.0.0/16
2. アクセプターVPC: 10.1.0.0/16
3. 両方のVPCのルートテーブルにピアリングルートを追加
```

## セキュリティ機能

### 1. セキュリティグループのベストプラクティス
```bash
# 最小権限の原則
- 必要なポートのみ開放
```

### 2. ネットワークACLの活用
```bash
# サブネットレベルでの追加セキュリティ
- デフォルトルールを拒否に変更
- 明示的に必要なトラフィックのみ許可
```

- VPC、サブネット、ENIレベルでのネットワークトラフィック監視
- CloudWatch LogsまたはS3に送信
- セキュリティ監査とトラブルシューティングに活用

## ベストプラクティス

### 1. ネットワーク設計
- **適切なCIDRサイズの選択**: 将来の拡張を考慮

## よくある質問

### Q1: VPCとサブネットの違いは何ですか？
**A**: VPCは大きなネットワーク全体、サブネットはその中の小さな区画です。VPCは10.0.0.0/16のような大きな範囲、サブネットは10.0.1.0/24のような小さな範囲を定義します。

### Q2: デフォルトVPCを使っても大丈夫ですか？
**A**: 開発・テスト環境では問題ありませんが、本番環境では独自のVPCを設計することを推奨します。セキュリティと制御の観点から、要件に応じた設計が可能です。

### Q3: パブリックサブネットにデータベースを配置できますか？
**A**: 技術的には可能ですが、セキュリティ上の理由から推奨されません。データベースはプライベートサブネットに配置し、アプリケーション層からのみアクセス可能にするべきです。

### Q4: VPCの料金はどのくらいですか？
**A**: VPC自体は無料ですが、以下のリソースに料金が発生します：
- NATゲートウェイ: 時間あたり$0.045 + データ処理料金
- VPCエンドポイント: 時間あたり$0.01
- データ転送料金

### Q5: 複数のVPC間で通信する方法は？
**A**: 以下の方法があります：
- VPCピアリング: 同じリージョン内
- Transit Gateway: 複数のVPCやオンプレミス接続
- VPN接続: オンプレミスとの接続

## まとめ

VPCはAWSクラウドで安全で柔軟なネットワーク環境を構築するための重要なサービスです。適切な設計と設定により、セキュリティ、可用性、スケーラビリティを確保できます。

初心者の方は、まずデフォルトVPCで基本操作を学び、徐々にカスタムVPCでの複雑な構成に挑戦することをお勧めします。セキュリティグループの設定から始めて、段階的にネットワーク設計のスキルを向上させていきましょう。
