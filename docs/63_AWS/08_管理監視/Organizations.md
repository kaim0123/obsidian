## AWS Organizationsとは

AWS Organizationsは、複数のAWSアカウントを一元的に管理するためのサービスです。企業や組織が複数のAWSアカウントを持っている場合、これらを効率的に管理・統制するために使用されます。

### なぜAWS Organizationsが必要なのか？

- **セキュリティの向上**: 複数アカウント間での一貫したセキュリティポリシーの適用
- **コスト管理**: 全アカウントの請求を統合し、コストを可視化
- **運用効率化**: 一箇所から複数アカウントを管理
- **コンプライアンス**: 組織全体でのポリシー準拠の確保

## 主要な機能

### 1. 統合請求（Consolidated Billing）
- 複数のAWSアカウントの請求を1つのアカウントに統合
- ボリューム割引の適用
- 全アカウントのコストを一括で確認可能

### 2. 組織単位（Organizational Units: OU）
- アカウントを論理的にグループ化
- 部門別、環境別（本番・開発・テスト）などで分類可能

### 3. サービス制御ポリシー（SCP: Service Control Policies）
- アカウントやOUに対して適用できるポリシー
- 特定のAWSサービスの使用を制限
- セキュリティとコンプライアンスの確保

### 4. リソースコントロールポリシー（Resource Control Policies）
- アカウントやOU内のリソース作成を制御
- 特定のリソースタイプの作成を制限
- リソースの設定やタグ付けを強制
- コスト管理とセキュリティの向上

### 5. アカウント管理
- 新しいアカウントの自動作成
- 既存アカウントの招待
- アカウントの移動と削除

## 組織構造の概念

```
マスターアカウント（ルート）
├── 本番環境OU
│   ├── 本番アカウント1
│   └── 本番アカウント2
├── 開発環境OU
│   ├── 開発アカウント1
│   └── 開発アカウント2
└── サンドボックスOU
    └── 実験用アカウント
```

### 重要な用語

- **マスターアカウント**: 組織のルートとなるアカウント
- **メンバーアカウント**: 組織に参加している他のアカウント
- **ルート**: 組織の最上位レベル
- **OU（組織単位）**: アカウントをグループ化する論理的なコンテナ

## セットアップ手順

### ステップ1: 組織の作成
1. AWSマネジメントコンソールにログイン
2. AWS Organizationsサービスを選択
3. 「組織を作成」をクリック
4. 組織名を入力して作成

### ステップ2: アカウントの招待
1. 「アカウントを招待」をクリック
2. 招待したいアカウントのメールアドレスを入力
3. 招待メールが送信される
4. 招待されたアカウントで招待を受け入れる

### ステップ3: OUの作成
1. 「組織単位を作成」をクリック
2. OU名を入力（例：「本番環境」「開発環境」）
3. 適切なアカウントをOUに移動

### ステップ4: ポリシーの適用
1. サービス制御ポリシー（SCP）を作成
2. リソースコントロールポリシーを作成
3. 必要なOUやアカウントに適用

## リソースコントロールポリシー（RCP）の詳細

### リソースコントロールポリシーとは

リソースコントロールポリシー（Resource Control Policies: RCP）は、AWS Organizationsの機能の一つで、組織内のアカウントやOUで作成されるリソースを制御するためのポリシーです。SCPがサービスレベルの制御を行うのに対し、RCPはリソースレベルの制御を行います。

### 主な機能

#### 1. リソース作成の制限
- 特定のリソースタイプの作成を禁止
- 特定の設定でのリソース作成を制限
- リソースの数やサイズを制限

#### 2. タグ付けの強制
- 必須タグの設定
- タグの値の検証
- タグ付けなしのリソース作成を禁止

#### 3. リソース設定の標準化
- セキュリティ設定の強制
- 暗号化の強制
- バックアップ設定の強制

### リソースコントロールポリシーの例

#### 例1: EC2インスタンスの制限
```json
{
  "Version": "2021-09-30",
  "Statement": [
    {
      "Sid": "DenyLargeEC2Instances",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "ec2:RunInstances",
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "ec2:InstanceType": [
            "t2.micro",
            "t2.small",
            "t3.micro",
            "t3.small"
          ]
        }
      }
    }
  ]
}
```

#### 例2: 必須タグの強制
```json
{
  "Version": "2021-09-30",
  "Statement": [
    {
      "Sid": "RequireCostCenterTag",
      "Effect": "Deny",
      "Principal": "*",
      "Action": [
        "ec2:RunInstances",
        "rds:CreateDBInstance",
        "s3:CreateBucket"
      ],
      "Resource": "*",
      "Condition": {
        "Null": {
          "aws:RequestedRegion": "false",
          "aws:TagKeys": "false"
        },
        "ForAllValues:StringNotEquals": {
          "aws:TagKeys": "CostCenter"
        }
      }
    }
  ]
}
```

#### 例3: 特定リージョンの制限
```json
{
  "Version": "2021-09-30",
  "Statement": [
    {
      "Sid": "DenyNonApprovedRegions",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "*",
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:RequestedRegion": [
            "ap-northeast-1",
            "us-east-1"
          ]
        }
      }
    }
  ]
}
```

### RCPの適用方法

#### 1. ポリシーの作成
1. AWS Organizationsコンソールにアクセス
2. 「ポリシー」セクションを選択
3. 「リソースコントロールポリシー」を選択
4. 「ポリシーを作成」をクリック
5. ポリシー名とJSONポリシードキュメントを入力

#### 2. ポリシーの適用
1. 作成したポリシーを選択
2. 「アカウントまたはOUにアタッチ」をクリック
3. 対象のアカウントまたはOUを選択
4. 「アタッチ」をクリック

### SCPとRCPの違い

| 項目 | SCP（サービス制御ポリシー） | RCP（リソースコントロールポリシー） |
|------|---------------------------|-----------------------------------|
| 制御レベル | サービスレベル | リソースレベル |
| 制御内容 | サービスの使用可否 | リソースの作成・設定 |
| 適用範囲 | アカウント・OU全体 | 特定のリソースタイプ |
| 使用例 | EC2サービスの使用禁止 | 特定サイズのEC2インスタンス作成禁止 |

## よくある質問

### Q: マスターアカウントとメンバーアカウントの違いは？
A: マスターアカウントは組織を管理する権限を持ち、メンバーアカウントは組織に参加しているアカウントです。マスターアカウントは他のアカウントを招待・削除できます。

### Q: 既存のアカウントを組織に参加させることはできますか？
A: はい、既存のアカウントを招待して組織に参加させることができます。ただし、そのアカウントの管理者が招待を受け入れる必要があります。

### Q: 組織からアカウントを削除した場合、そのアカウントはどうなりますか？
A: アカウント自体は削除されません。組織から外れるだけで、独立したAWSアカウントとして残ります。

### Q: サービス制御ポリシー（SCP）はどのような場合に使用しますか？
A: セキュリティ要件に基づいて特定のAWSサービスの使用を制限したい場合や、コスト管理のために高額なサービスの使用を制限したい場合に使用します。

### Q: 組織の構造を後から変更することはできますか？
A: はい、OUの作成・削除、アカウントの移動など、組織構造は柔軟に変更できます。

### Q: リソースコントロールポリシー（RCP）とサービス制御ポリシー（SCP）の違いは何ですか？
A: SCPはサービスレベルの制御（例：EC2サービスの使用禁止）を行い、RCPはリソースレベルの制御（例：特定サイズのEC2インスタンス作成禁止）を行います。RCPはより細かい制御が可能です。

### Q: リソースコントロールポリシーはどのような場面で使用しますか？
A: コスト管理（高額なリソースの作成制限）、セキュリティ強化（暗号化の強制）、コンプライアンス（必須タグの設定）などの目的で使用します。

### Q: リソースコントロールポリシーを適用した後、既存のリソースに影響はありますか？
A: リソースコントロールポリシーは新しいリソースの作成時のみに適用されます。既存のリソースには影響しません。

## まとめ

AWS Organizationsは、複数のAWSアカウントを効率的に管理するための強力なツールです。適切に設定することで、セキュリティの向上、コスト管理の効率化、運用の簡素化を実現できます。

初心者の方は、まず小規模な組織から始めて、徐々に複雑な構造に発展させていくことをお勧めします。また、セキュリティとコンプライアンスを最優先に考え、段階的にポリシーを適用していくことが重要です。
