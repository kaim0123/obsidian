# ユーザー定義型ガード（`x is T`）

> 標準の `typeof` / `instanceof` / `in` では絞り込めない型を、**自分で「これは T だ」と判定する関数**を書いて narrowing する仕組みです。便利ですが、**手書きの判定はミスの温床**。乱用せず、本当に必要な場面だけに限定して使うのがコツです。

## 1. ユーザー定義型ガードとは

戻り値型に **`v is T`**（type predicate）と書いた関数。

```typescript
function isString(v: unknown): v is string {
  return typeof v === "string";
}

function f(value: unknown) {
  if (isString(value)) {
    value.toUpperCase(); // ✅ string に絞り込まれる
  }
}
```

### 構文

```typescript
function isXxx(arg: 引数の型): arg is 絞り込み後の型 {
  // 真偽値を返す
}
```

戻り値型 `arg is 型` が「**この関数が `true` を返したら、`arg` は型 `T` である**」とTypeScriptに伝える。

---

## 2. なぜ必要か

`typeof` / `instanceof` / `in` で表現できない型は多い。

```typescript
type User = { id: string; name: string };

function isUser(v: unknown): v is User {
  return (
    typeof v === "object" &&
    v !== null &&
    "id" in v && typeof (v as any).id === "string" &&
    "name" in v && typeof (v as any).name === "string"
  );
}

function process(v: unknown) {
  if (isUser(v)) {
    v.name.toUpperCase(); // ✅ User として扱える
  }
}
```

`typeof v === "User"` のような構文はないので、**自分でチェックを書く**しかない。

---

## 3. ユーザー定義型ガードを使うべき場面

### (1) `unknown` を独自型に絞り込む

```typescript
function isUser(v: unknown): v is User { ... }

const data: unknown = JSON.parse(raw);
if (isUser(data)) {
  data.name; // ✅
}
```

### (2) ユニオン型から特定のメンバーを絞る

```typescript
type Animal = Dog | Cat | Bird;

function isDog(a: Animal): a is Dog {
  return a.kind === "dog";
}

const animals: Animal[] = [...];
const dogs: Dog[] = animals.filter(isDog); // ✅ 型が絞られる
```

→ `filter` の戻り値型が **`Dog[]`** に絞られるのが大きなメリット。

### (3) 標準クラスでない値の判定

```typescript
function isError(v: unknown): v is Error {
  return v instanceof Error;
}
```

（この例は `v instanceof Error` で十分なので不要だが、複雑な判定を共通化するのに便利）

---

## 4. 配列の `filter` での威力

```typescript
const items: (string | undefined)[] = ["a", undefined, "b"];

const filtered = items.filter(x => x !== undefined);
// 型: (string | undefined)[]（絞られない！）

function isDefined<T>(x: T | undefined): x is T {
  return x !== undefined;
}

const filtered2 = items.filter(isDefined);
// 型: string[]（絞られる）
```

`filter` のコールバックは普通の関数だと**戻り値型を絞ってくれない**。`is` 述語を使うことで、**戻り値の配列要素型を変えられる**。

→ **「`undefined` を取り除く」**ような汎用ヘルパは型ガードで書く。

---

## 5. 落とし穴: TypeScriptは中身を検証してくれない

ここが最大の罠。`is T` は「**こう判定したらこの型と扱え**」と**プログラマが宣言**するもの。**実装が正しいかは検査されない**。

```typescript
function isString(v: unknown): v is string {
  return typeof v === "number"; // ❌ 嘘の判定
}

function f(v: unknown) {
  if (isString(v)) {
    v.toUpperCase(); // 実行時エラー（実は number）
  }
}
```

→ 手書きの型ガードは**実装ミスでバグが静かに混入**する。

### 対策

#### (1) シンプルに保つ

```typescript
function isString(v: unknown): v is string {
  return typeof v === "string";
}
```

複雑な判定を1関数に詰め込まない。

#### (2) Zod等のバリデータを優先

```typescript
import { z } from "zod";

const UserSchema = z.object({
  id: z.string(),
  name: z.string(),
});

function isUser(v: unknown): v is User {
  return UserSchema.safeParse(v).success;
}
```

→ スキーマと型が**一元管理**できる。手書きより遥かに安全。

```typescript
type User = z.infer<typeof UserSchema>; // スキーマから型を導出
```

## 6. 型ガード関数の書き方パターン

### (1) プリミティブの簡単な判定

```typescript
function isString(v: unknown): v is string {
  return typeof v === "string";
}

function isNumber(v: unknown): v is number {
  return typeof v === "number";
}
```

### (2) `null`/`undefined` を除外

```typescript
function isDefined<T>(v: T | null | undefined): v is T {
  return v !== null && v !== undefined;
}
```

→ `filter(isDefined)` で配列から `null`/`undefined` を一括除去。

### (3) オブジェクトの形を判定

```typescript
function isUser(v: unknown): v is User {
  return (
    typeof v === "object" &&
    v !== null &&
    "id" in v &&
    "name" in v
  );
}
```

ただし**フィールドの型まで厳密にチェック**しないと、不完全なオブジェクトを通してしまう。Zodなどを推奨。

### (4) ユニオンから特定のメンバー

```typescript
type Animal = Dog | Cat;

function isDog(a: Animal): a is Dog {
  return a.kind === "dog";
}
```

ただし**判別可能ユニオンなら型ガード関数は不要**（`a.kind === "dog"` で直接narrowingできる）。型ガード関数は「**外部から `unknown` で受けたとき**」に効果的。

### (5) ジェネリックな配列の型ガード

```typescript
function isArrayOf<T>(
  v: unknown,
  guard: (x: unknown) => x is T
): v is T[] {
  return Array.isArray(v) && v.every(guard);
}

const data: unknown = ["a", "b", "c"];
if (isArrayOf(data, isString)) {
  data; // string[]
}
```

汎用ユーティリティ。

---

## 7. 「型ガードに見えるが違うもの」: 普通の `boolean` 戻り値関数

```typescript
function check(v: string | undefined): boolean {
  return v !== undefined;
}

function f(v: string | undefined) {
  if (check(v)) {
    v.toUpperCase(); // ❌ narrowing されない
  }
}
```

戻り値型を **`boolean`** にすると narrowing は効きません。**`v is string`** にしないと意味なし。

---

## 8. メソッドとして書くこともできる

```typescript
class UserChecker {
  isUser(v: unknown): v is User {
    return ...;
  }
}

const checker = new UserChecker();
const v: unknown = ...;
if (checker.isUser(v)) {
  v.name; // ✅
}
```

クラス内の `is` 述語も普通に動く。

---

## 9. アロー関数でも書ける

```typescript
const isString = (v: unknown): v is string => typeof v === "string";
```

シンプルなものはアロー関数で。

---

## 10. ユーザー定義型ガードを「使わない方がよい」場面

### (1) **判別可能ユニオン**で済む場面

```typescript
// ❌ 型ガードを書くまでもない
function isAdd(a: Action): a is { type: "ADD"; payload: number } {
  return a.type === "ADD";
}

// ✅ 直接narrowing
if (action.type === "ADD") {
  action.payload;
}
```

判別ユニオンならそのまま narrowing できる。

### (2) **`typeof` / `instanceof`** で済む場面

```typescript
// ❌ 不要
function isString(v: unknown): v is string {
  return typeof v === "string";
}

// ✅ 直接
if (typeof v === "string") { ... }
```

ただし**ヘルパとして再利用**するなら型ガード化する価値あり。

### (3) 厳密なバリデーションが必要な場面

```typescript
function isUser(v: unknown): v is User {
  return ...; // 手書き
}
```

→ Zod等を使う方が安全・保守的。

## 11. 型ガードと `assertion function`（次章）の違い

| 観点 | 型ガード（`is T`） | アサーション関数（`asserts T`） |
|---|---|---|
| 戻り値 | `boolean` | `void`（外れたら throw） |
| 使い方 | `if (isT(v)) { ... }` | `assertT(v); /* ↓ T として使える */` |
| narrowing 範囲 | `if` ブロック内 | 関数呼び出し以降全部 |

詳細は [[04-assertsアサーション関数]] へ。

---

## 12. 型ガードを安全に使うルール

1. **シンプルなものに留める**（複雑なら Zod へ）
2. **テストを書く**（特にオブジェクト判定）
3. **`unknown` の絞り込み**を中心に使う
4. **判別可能ユニオン**で済むならそちらを優先
5. **公開ライブラリの境界**で使う（内部のロジックでは不要）

---

## 13. 実践例: `unknown` から型へ

```typescript
async function loadUser(id: string): Promise<User | null> {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) return null;

  const data: unknown = await res.json();

  if (isUser(data)) {
    return data;
  }
  console.error("Invalid user data:", data);
  return null;
}
```

「**外部から来た値を `unknown` で受け、型ガードで絞り込んで内部の型世界に取り込む**」 ── これが型ガードの正しい使い方。

---

## 14. まとめ

- ユーザー定義型ガード = **戻り値型に `v is T` を書く関数**
- 標準演算子で表現できない判定を**自前で書く**ためのもの
- `filter(isXxx)` で**配列要素の型を絞れる**のが強力
- 落とし穴: **実装の正しさは検査されない**（嘘を書ける）
- 推奨: **Zod等のバリデータを優先**、シンプルなヘルパだけ手書き
- 判別可能ユニオン・`typeof` / `instanceof` で済むなら型ガードは不要

> 型ガードは「**型システムへの宣言**」。実装が間違っていれば嘘の型情報が伝染するので、**シンプルに、テストして、できればバリデータに任せる**のがプロのスタイルです。
