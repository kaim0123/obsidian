# ユニオン型と合成の考え方

> ユニオン型 `A | B` は「**AかBのどちらか**」を表す型。たったこれだけですが、TypeScriptの設計力はユニオン型をいかに使いこなすかで決まります。**「あり得る状態を全部列挙する」**という発想がここから始まります。

## 1. ユニオン型の基本

`|` で区切ると「**いずれかの型**」を表せます。

```typescript
type Id = string | number;

const a: Id = "abc";   // ✅
const b: Id = 42;      // ✅
const c: Id = true;    // ❌
```

数学の集合で言えば「**和集合**」（OR）。

### プリミティブのユニオン

```typescript
type StringOrNumber = string | number;
type Status = "loading" | "success" | "error"; // リテラル型のユニオン
```

### オブジェクトのユニオン

```typescript
type Animal = { kind: "dog"; bark(): void } | { kind: "cat"; meow(): void };
```

→ 判別可能ユニオン（discriminated union）の基礎。

---

## 2. ユニオン型の値で「使えるメソッド」

ユニオン型の値では、**全メンバーに共通するメンバーしか使えません**（共通部分集合）。

```typescript
type T = string | number;

const x: T = ...;
x.toString();    // ✅ 両方にある
x.toUpperCase(); // ❌ string だけにある
x.toFixed(2);    // ❌ number だけにある
```

→ 使うには **narrowing**（型の絞り込み）が必要。

```typescript
if (typeof x === "string") {
  x.toUpperCase(); // ✅
} else {
  x.toFixed(2);    // ✅
}
```

詳しくは [[6章]] で詳述。

---

## 3. ユニオン型 = 「**あり得る状態の列挙**」

これがユニオン型の本質的な使い方。

### 例: フォームの入力値

```typescript
// ❌ どんな文字列も入れられる
type FormValue = string;

// ✅ 取りうる値を列挙
type FormValue = "" | "loading" | "valid" | "invalid";
```

### 例: ロード状態

```typescript
type LoadState =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: User }
  | { status: "error"; error: string };
```

各状態で**持つフィールドが違う**ことを型で表現。

### 例: アクション（Reduxパターン）

```typescript
type Action =
  | { type: "INCREMENT" }
  | { type: "DECREMENT" }
  | { type: "SET"; value: number }
  | { type: "RESET" };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case "INCREMENT": return { count: state.count + 1 };
    case "DECREMENT": return { count: state.count - 1 };
    case "SET": return { count: action.value }; // ✅ value にアクセス可
    case "RESET": return { count: 0 };
  }
}
```

`action.type` で絞り込めば、各ケースで必要なフィールドが安全に使える。

## 4. 判別可能ユニオン（Discriminated Union）

ユニオン型の中で**全メンバーが共通のリテラル型フィールド**を持つもの。

```typescript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number }
  | { kind: "rectangle"; width: number; height: number };
```

`kind` が**判別子（discriminator）**。`if`/`switch` で `kind` を見れば、TypeScriptが残りのフィールドを自動で絞り込んでくれる。

### narrowing の例

```typescript
function area(s: Shape): number {
  switch (s.kind) {
    case "circle":    return Math.PI * s.radius ** 2;     // s: 円
    case "square":    return s.side ** 2;                  // s: 正方形
    case "rectangle": return s.width * s.height;            // s: 長方形
  }
}
```

これは [[6章]] の「narrowing」と直結する基礎。

### 判別子の選び方

- 名前は `kind` / `type` / `tag` などが定番
- 値は**リテラル型**（`"circle"`, `"square"`...）
- 全メンバーで**共通フィールドかつ重複しない値**

## 5. ユニオン型の合成パターン

### (1) 既存の型を `|` で並べる

```typescript
type A = { name: string };
type B = { age: number };
type AorB = A | B;

const x: AorB = { name: "Alice" };       // ✅
const y: AorB = { age: 30 };              // ✅
const z: AorB = { name: "Bob", age: 25 }; // ✅（両方持っていてもOK）
```

「AまたはB」なので、**両方持っていても可**（A ∪ B）。

### (2) リテラル型ユニオン

```typescript
type Direction = "up" | "down" | "left" | "right";
type Dice = 1 | 2 | 3 | 4 | 5 | 6;
```

選択肢を列挙する典型パターン。

### (3) `null` / `undefined` を含めるユニオン

```typescript
type Name = string | null;
type Email = string | undefined;
```

`strictNullChecks: true` 前提の世界では、`null`/`undefined` はユニオンで明示する。

### (4) 関数オーバーロードの代替

```typescript
function format(value: string | number | Date): string { ... }
```

ユニオンで複数型を受け、内部で `typeof` / `instanceof` で分岐。

## 6. ユニオン型と配列

```typescript
type Mixed = (string | number)[];
const a: Mixed = [1, "a", 2];

const b: string | number[] = ...; // ❌ 違う意味
// （string、または number の配列）
```

カッコの位置に注意:

- `(string | number)[]` = 「string または number」の配列
- `string | number[]` = 「string」または「number の配列」

---

## 7. ユニオン型の `Exclude` / `Extract`

ユニオン型から**特定のメンバーを除外/抽出**できる。

```typescript
type T = "a" | "b" | "c";

type WithoutA = Exclude<T, "a">;      // "b" | "c"
type OnlyA = Extract<T, "a" | "x">;   // "a"

type Nullable<T> = T | null | undefined;
type NonNull<T> = Exclude<T, null | undefined>;
type X = NonNull<string | null>; // string
```

`Exclude` / `Extract` は条件型（後述）と分配法則を使った標準ユーティリティ型。

## 8. ユニオンの「広がり」と推論

### `let` での widening

```typescript
let x = "loading"; // x: string（リテラル "loading" には絞られない）

let s: "a" | "b" = "a";
s = "c"; // ❌
```

明示的にユニオン型を書かないと、`let` の値は広がる（[[05-リテラル型とas-const]] 参照）。

### 関数の戻り値推論

```typescript
function status(n: number) {
  if (n > 0) return "positive";
  if (n < 0) return "negative";
  return "zero";
}
// 戻り値型: "positive" | "negative" | "zero"
```

戻り値もリテラル型のユニオンとして推論される。

## 9. ユニオン型の落とし穴

### (1) オブジェクトユニオンで「共通プロパティ」だけにアクセス可能

```typescript
type T = { a: number; b: string } | { a: number; c: boolean };

const x: T = ...;
x.a; // ✅ 共通
x.b; // ❌ 一方にしかない
x.c; // ❌ 一方にしかない
```

→ 判別子で絞り込む。

### (2) 余分なプロパティチェック

```typescript
type A = { x: number };
type B = { y: string };

const a: A | B = { x: 1, y: "hello", extra: true };
// ❌ extra はどちらにもない
```

ユニオン型でも、**両方の型に含まれないプロパティ**は警告される。

### (3) 配列のユニオン型と「`map` の戻り値」

```typescript
const arr: (string | number)[] = [1, "a"];
const out = arr.map(x => typeof x === "string" ? x.length : x);
// out: number[]
```

絞り込みを使えば各要素の型を確定できる。

### (4) 判別子なしのオブジェクトユニオンは扱いづらい

```typescript
type T = { name: string } | { age: number };

function f(v: T) {
  if ("name" in v) {
    v.name; // ✅
  }
}
```

判別子がないと `in` 演算子で絞る必要がある。**設計時に判別子を入れる**のが鉄則。

### (5) `as` で「無理やり」絞らない

```typescript
function f(v: string | number) {
  const n = v as number; // ❌ 嘘の可能性
  n.toFixed();
}
```

→ `typeof` などで絞り込む。

## 10. ユニオン型と関数の引数（contravariant の注意）

```typescript
type Handler<T> = (v: T) => void;

const stringHandler: Handler<string> = (s) => s.toUpperCase();
const unionHandler: Handler<string | number> = stringHandler;
// ❌ string | number を受ける関数として、string しか扱えない実装は不適切
```

ユニオン型を引数にとる関数を、**狭い型を受ける関数で代用してはいけない**（[[02-関数型とコールバック]] の共変・反変参照）。

---

## 11. ユニオン型の使い所まとめ

| 用途 | 例 |
|---|---|
| 型の選択肢を列挙 | `string \| number` |
| リテラル型を列挙 | `"a" \| "b" \| "c"` |
| 判別可能ユニオン | `\| { kind: "x" } \| { kind: "y" }` |
| Nullable | `string \| null` |
| 関数の多様な引数 | `format(v: string \| number)` |
| アクション・状態 | Redux的なAction型 |

---

## 12. まとめ

- ユニオン型 = **「AかBのどちらか」**（和集合）
- 値では**共通メンバーしか使えない** → narrowingで絞る
- 真価は **「あり得る状態を列挙する」設計力**
- **判別可能ユニオン**（`kind` フィールドで分岐）は最も価値あるパターン
- `Exclude` / `Extract` でユニオンから取り出せる
- カッコの位置に注意（`(A | B)[]` vs `A | B[]`）

> ユニオン型を「**設計の道具**」として使えるようになると、TypeScriptは一気に強力になります。「**この値はあり得る状態を全部表現できているか？**」を毎回自問する癖をつけましょう。
