# 分配法則（distributive conditional types の入口）

> 「ジェネリクスにユニオン型を渡すと、**自動でユニオンの各メンバーに条件型が分配される**」── これが TypeScript の分配法則です。`Exclude` や `NonNullable` などの標準ユーティリティ型はすべてこれで動いています。仕組みを理解すると、複雑な型変換が読み解けるようになります。

## 1. 条件型（Conditional Types）の基礎

まず**条件型**を押さえましょう。「**型のif文**」のような構文です。

```typescript
type IsString<T> = T extends string ? true : false;

type A = IsString<string>;  // true
type B = IsString<number>;  // false
```

### 構文

```typescript
T extends U ? X : Y
```

「`T` が `U` に**代入可能**なら `X`、そうでなければ `Y`」。

### 例: 値を取り出す

```typescript
type ElementType<T> = T extends (infer U)[] ? U : never;

type A = ElementType<string[]>;  // string
type B = ElementType<number[]>;  // number
type C = ElementType<string>;     // never（配列ではない）
```

`infer` で「配列の要素型」を取り出している。詳しくは「14章 型レベルプログラミング」で扱います。

---

## 2. 分配法則（Distributive Conditional Types）

ここが本題。**ジェネリクスの型引数にユニオン型を渡すと、条件型が各メンバーに分配される**。

```typescript
type ToArray<T> = T extends any ? T[] : never;

type A = ToArray<string | number>;
//   ^ string[] | number[]
```

これが分配法則です。一見「`(string | number)[]`」になりそうですが、**ユニオン型が分解されて各メンバーに条件型が適用**され、結果がユニオンに戻る。

### 何が起きているか（手順）

1. `ToArray<string | number>` が呼ばれる
2. `string | number` がユニオン型なので、**各メンバーに分配**:
   - `ToArray<string>` → `string extends any ? string[] : never` → `string[]`
   - `ToArray<number>` → `number extends any ? number[] : never` → `number[]`
3. 結果を**ユニオンに戻す**: `string[] | number[]`

---

## 3. 分配法則が起きる条件

分配法則が発動するのは、以下の**2条件すべて**を満たすとき:

1. **裸の型変数**（naked type parameter）が `extends` の左側にある
2. その型変数に**ユニオン型**が渡される

### 「裸の型変数」とは

ジェネリクスの型引数 `T` を、**そのまま** `extends` の左に書くこと。

```typescript
type A<T> = T extends ...   // ✅ 裸（分配される）
type B<T> = [T] extends ... // ❌ タプルで包んでいる（分配されない）
type C<T> = { x: T } extends ... // ❌ オブジェクトで包んでいる（分配されない）
```

### 包めば分配を止められる

```typescript
type ToArrayDistributive<T> = T extends any ? T[] : never;
type ToArrayNonDistributive<T> = [T] extends [any] ? T[] : never;

type A = ToArrayDistributive<string | number>;
//   ^ string[] | number[]（分配される）

type B = ToArrayNonDistributive<string | number>;
//   ^ (string | number)[]（分配されない）
```

→ **分配を止めたいときは `[T]` で包む**。これは実装上の重要なテクニック。

---

## 4. 分配法則を使った標準ユーティリティ型

### `Exclude<T, U>`

```typescript
type Exclude<T, U> = T extends U ? never : T;
```

- `T` が `U` に代入可能なら `never`、そうでなければ `T` を残す
- ユニオン型に分配されるので、「**`U` に該当するメンバーを除外**」が実現される

```typescript
type T = "a" | "b" | "c";
type WithoutA = Exclude<T, "a">;
//   ^ "b" | "c"

// 内部の動き:
// "a" extends "a" → never
// "b" extends "a" → "b"
// "c" extends "a" → "c"
// 結果: never | "b" | "c" = "b" | "c"（never は消える）
```

### `Extract<T, U>`

```typescript
type Extract<T, U> = T extends U ? T : never;
```

`Exclude` の逆。

### `NonNullable<T>`

```typescript
type NonNullable<T> = T extends null | undefined ? never : T;
```

`null` / `undefined` を除外する。

```typescript
type A = NonNullable<string | null | undefined>; // string
```

### 共通点

すべて「**裸の `T extends ...`**」 ── 分配法則を活用している。

---

## 5. `never` の特殊な振る舞い

ユニオン型から `never` が**消える**のは、分配法則の副作用。

```typescript
type T = string | never;  // string（never は消える）
type U = string | number | never;  // string | number
```

理由: `never` は「値が存在しない」型なので、和集合に何も追加しない。

### `Exclude<T, T>` の挙動

```typescript
type T = "a" | "b" | "c";
type Empty = Exclude<T, T>;  // never
```

「`T` を `T` で除外」すると、すべてが `never` になり、`never | never | never = never`。

### `never` を分配するとどうなる？

```typescript
type ToArray<T> = T extends any ? T[] : never;
type A = ToArray<never>;  // never（!）
```

`never` は「メンバーが0個のユニオン」と解釈され、分配の対象が空 → 結果も `never`。

これは時々ハマるので覚えておく。

## 6. 分配法則の実用例

### (1) ユニオンから特定型のメンバーだけ取り出す

```typescript
type Action =
  | { type: "ADD"; value: number }
  | { type: "REMOVE"; id: string }
  | { type: "RESET" };

type FilterAction<T extends Action["type"]> = Extract<Action, { type: T }>;

type AddAction = FilterAction<"ADD">;
//   ^ { type: "ADD"; value: number }
```

### (2) ユニオンの各メンバーに変換を適用

```typescript
type Wrap<T> = T extends any ? { value: T } : never;

type A = Wrap<string | number>;
//   ^ { value: string } | { value: number }
```

### (3) ユニオンから関数型を作る

```typescript
type EventName = "click" | "hover" | "submit";
type EventHandler<E extends EventName> = (e: { type: E }) => void;
type AllHandlers = EventHandler<EventName>;
//   ^ EventHandler<"click"> | EventHandler<"hover"> | EventHandler<"submit">
//   = ((e: { type: "click" }) => void) | ((e: { type: "hover" }) => void) | ...
```

## 7. 分配を止めたいケース

### (1) ユニオン全体を判定したいとき

```typescript
// ❌ 分配される: 各メンバーが string か判定
type IsString<T> = T extends string ? true : false;
type A = IsString<string | number>; // boolean (= true | false)

// ✅ 分配しない: ユニオン全体が string か判定
type IsString<T> = [T] extends [string] ? true : false;
type B = IsString<string | number>; // false
```

「**全部 string か？**」のような判定では、分配を止める。

### (2) ユニオンを保ったまま型変換

```typescript
// ❌ 分配される
type ToArray<T> = T extends any ? T[] : never;
type A = ToArray<string | number>; // string[] | number[]

// ✅ 分配しない: ユニオン全体を配列に
type ToArray<T> = [T] extends [any] ? T[] : never;
type B = ToArray<string | number>; // (string | number)[]
```

## 8. 分配法則と `keyof` の組み合わせ（やや高度）

```typescript
type T = { a: number; b: string };
type Keys = keyof T;  // "a" | "b"

type ValueOf<T> = T[keyof T];
type V = ValueOf<{ a: number; b: string }>;
//   ^ number | string
```

`keyof` で取り出したユニオンに `T[K]` を適用すると、各キーの値型のユニオンが取れる。**Mapped Type** と組み合わせるとさらに強力。

## 9. 分配法則を理解するためのデバッグテクニック

### (1) 中間型を切り出して確認

```typescript
type Step1 = "a" | "b";
type Step2<T> = T extends "a" ? true : false;
type Result = Step2<Step1>; // boolean ←分配されている
```

VSCode で型をホバーすると展開された結果が見える。

### (2) `[T]` で分配を止めて比較

```typescript
type A<T> = T extends string ? true : false;
type B<T> = [T] extends [string] ? true : false;

type R1 = A<string | number>; // boolean
type R2 = B<string | number>; // false
```

挙動の違いを目で見比べる。

## 10. 落とし穴

### (1) 分配されることに気付かず複雑な結果になる

```typescript
type Wrap<T> = T extends any ? { x: T } : never;

type A = Wrap<{ a: number } | { b: string }>;
//   ^ { x: { a: number } } | { x: { b: string } }
//   （オブジェクト型のユニオンも分配される）
```

「ユニオン型はジェネリクスに渡した瞬間に分解されうる」と覚えておく。

### (2) `never` の分配で結果が消える

```typescript
type A<T> = T extends any ? T : never;
type B = A<never>; // never（分配対象が0個）
```

「ジェネリクスに `never` を渡したら結果が `never` になった」というバグはほぼこれ。

### (3) 「同時に複数のユニオンに分配」される

```typescript
type Cross<T, U> = T extends any ? (U extends any ? [T, U] : never) : never;

type R = Cross<"a" | "b", 1 | 2>;
//   ^ ["a", 1] | ["a", 2] | ["b", 1] | ["b", 2]
```

**入れ子の条件型**で**直積**が作れる。標準ライブラリには無いが、知っておくと便利。

---

## 11. 「分配法則を理解した先」にあるもの

分配法則を理解すると、以下が読めるようになります:

- 標準ユーティリティ型（`Exclude`, `Extract`, `NonNullable`, `ReturnType`...）
- 自作のユーティリティ型（プロジェクト固有の型変換）
- ライブラリの複雑な型定義（React の hooks, Redux Toolkit, tRPC...）

ここから先は「14章 型レベルプログラミング」へ続く。**型を計算する世界**の入口です。

---

## 12. まとめ

- **条件型**: `T extends U ? X : Y`（型のif）
- **分配法則**: 裸の型変数 + ユニオン型 → **各メンバーに分配されてユニオンに戻る**
- 標準の `Exclude` / `Extract` / `NonNullable` はこの仕組みで動く
- **分配を止めたい**ときは `[T] extends [U]` のように包む
- `never` は分配対象が0個 → 結果も `never`
- 入れ子の条件型で直積も作れる

> 分配法則は「**ジェネリクスがユニオン型と組み合わさったときの自動的な振る舞い**」。理解すれば標準ユーティリティ型の中身が読め、自作の型変換も書けるようになります。中級から上級への分水嶺です。
