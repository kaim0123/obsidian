# 交差型（intersection）とその注意点

> 交差型 `A & B` は「**AかつB**」── と直訳すると、オブジェクト型での挙動で必ず混乱します。実は「**両方の制約を満たす型**」と理解すると正しく使えます。プリミティブで使うと `never` になる、`extends` の代替として便利、など実務上の感覚を整理します。

## 1. 交差型の基本

`&` で型を結合すると、**両方のプロパティを全部持つ型**になります。

```typescript
type Named = { name: string };
type Aged = { age: number };

type Person = Named & Aged;
// { name: string; age: number }

const p: Person = { name: "Alice", age: 30 }; // ✅
const q: Person = { name: "Bob" };             // ❌ age がない
```

オブジェクト型では「**両方のプロパティを合体する**」効果。

---

## 2. ユニオン型との違い

| 観点 | ユニオン `A \| B` | 交差 `A & B` |
|---|---|---|
| 集合論的に | 和集合（OR） | 積集合（AND） |
| オブジェクト型で | どちらかの形 | 両方のプロパティを持つ |
| 値で使えるメンバー | 共通メンバーのみ | 両方のメンバーすべて |
| プリミティブで | 例: `string \| number` | 例: `string & number` → `never` |

```typescript
type T = string | number;  // string か number
type U = string & number;  // string でかつ number → 不可能 → never
```

---

## 3. プリミティブの交差型は `never`

```typescript
type X = string & number;     // never
type Y = "a" & "b";           // never
type Z = boolean & string;    // never
```

「string でかつ number」のような値は**存在しない**ため、`never` になります。これは「論理的に不可能な型」を示す TypeScript の正しい挙動。

### 自分で `T & 何か` を作ったら never になっていた、という時

```typescript
type T = "a" | "b";
type U = T & "c"; // never（"a"|"b" と "c" は重ならない）
```

→ **実装ロジックの間違い**。条件型やジェネリクスの設計ミスを示している。

---

## 4. オブジェクト型の交差: プロパティの「合体」

```typescript
type A = { x: number };
type B = { y: string };

type AB = A & B;
// { x: number; y: string }
```

ここまでは直感通り。

### 同じプロパティ名を持つ場合

```typescript
type A = { x: number };
type B = { x: string };

type AB = A & B;
// { x: number & string } = { x: never }（実質使えない）
```

**両方の型のプロパティが共存できる必要がある**。`number` と `string` の交差は `never` なので、結果のプロパティも `never` に。

### 一方が広い型なら絞られる

```typescript
type A = { x: number | string };
type B = { x: string };

type AB = A & B;
// { x: string }（number | string と string の交差 = string）
```

→ 交差は「**より厳しい制約**」を取る。

---

## 5. オブジェクトの拡張に交差型を使う

`interface` の `extends` と同等の効果が、`type` の `&` で得られる。

```typescript
type Animal = { name: string };
type Dog = Animal & { bark(): void };

const d: Dog = {
  name: "Pochi",
  bark: () => console.log("woof"),
};
```

### `extends` との違い

```typescript
interface Animal { name: string }
interface Dog extends Animal { bark(): void }
```

機能的にほぼ同じだが、

- `extends` は `interface` 同士のみ
- `&` は `type` でも `interface` でも、**任意の型**で使える
- `&` は同名プロパティを「合体」する（`interface` の同名プロパティは互換性チェックでエラーになる）

詳しい使い分けは [[03-型エイリアスと設計指針]] と [[interface vs type]] へ。

---

## 6. 関数型の交差（オーバーロード）

複数の関数型を `&` で結合すると、**オーバーロードを表現**できる。

```typescript
type Format =
  & ((value: string) => string)
  & ((value: number) => string);

const format: Format = (v: string | number) => String(v);

format("hello");  // ✅
format(42);       // ✅
```

これは `interface` でメソッドオーバーロードを書くのと同じ。あまり書かないが、ライブラリの型定義で見ることがある。

---

## 7. ジェネリクスとの組み合わせ

### 制約の追加

```typescript
function entries<T extends object>(obj: T): [keyof T, T[keyof T]][] {
  return Object.entries(obj) as any;
}
```

`T extends object & { ... }` のような形で**追加の制約**を与えられる。

```typescript
function id<T extends { id: string } & { name: string }>(obj: T): string {
  return `${obj.name} (${obj.id})`;
}
```

---

## 8. 「ミックスイン」パターン

複数の型を組み合わせて1つの型を作るパターン。

```typescript
type Timestamped = { createdAt: Date; updatedAt: Date };
type Identifiable = { id: string };
type Named = { name: string };

type User = Identifiable & Named & Timestamped;
// { id: string; name: string; createdAt: Date; updatedAt: Date }
```

**横断的な属性**（タイムスタンプ、ID、論理削除フラグなど）を切り出して合成できる。設計力が上がる。

---

## 9. 交差型の落とし穴

### (1) 同名プロパティの型衝突

```typescript
type A = { kind: "a"; x: number };
type B = { kind: "b"; y: string };

type AB = A & B;
// { kind: "a" & "b"; x: number; y: string }
// = { kind: never; x: number; y: string }
```

`kind` が `"a" & "b"` で `never` になり、**実質作成不可能**な型に。

→ こういう場合は**ユニオン**を使う:

```typescript
type AB = A | B;
```

### (2) 関数の引数の交差

```typescript
type FA = (x: string) => void;
type FB = (x: number) => void;

type F = FA & FB;
// オーバーロード: (x: string) => void と (x: number) => void

const f: F = (x: string | number) => {};
f("a"); // ✅
f(1);   // ✅
```

これはオーバーロード扱いになる（メリット）。

ただし、**引数のユニオンと混同しやすい**:

```typescript
type G = (x: string & number) => void; // x: never → 実質呼べない関数
```

### (3) ネストしたオブジェクトの交差

```typescript
type A = { config: { theme: string } };
type B = { config: { lang: string } };

type AB = A & B;
// { config: { theme: string } & { lang: string } }
// = { config: { theme: string; lang: string } }
```

ネストも自動でマージされる。便利だが、想定外の合成にならないか注意。

### (4) `Pick` や `Omit` との順序

```typescript
type A = { x: number; y: string };
type B = Omit<A, "x"> & { x: string };
// { x: string; y: string }
```

`Omit` で1つのプロパティを取り除いて、`&` で**型を上書き**するパターン。
→ プロパティの「**型を変えたい**」ときに使える。

---

## 10. 交差型の使い所まとめ

| 用途 | 例 |
|---|---|
| 型の拡張 | `Animal & { bark(): void }` |
| ミックスイン | `Identifiable & Named & Timestamped` |
| オーバーロード | `((s: string) => void) & ((n: number) => void)` |
| プロパティの上書き | `Omit<T, "x"> & { x: 新しい型 }` |
| ジェネリクス制約 | `T extends { id: string } & SomeConstraint` |

---

## 11. 交差型 vs ユニオン型 早見表

| やりたいこと | 使う型 |
|---|---|
| AまたはB | `A \| B` |
| AかつB（プロパティを全部持つ） | `A & B` |
| 既存型を拡張 | `Base & { 追加 }` |
| 状態を列挙 | `\| { kind: "a" } \| { kind: "b" }` |
| 異なる型の選択肢 | `string \| number` |
| 共通の属性を合成 | `Identifiable & Named` |

---

## 12. 「交差型は集合の積」── 厳密な理解

数学的に言うと、`A & B` は「**A の値の集合と B の値の集合の積集合**」。

- **プリミティブ**: ほぼ `never`（重なる値が存在しないため）
- **オブジェクト**: 「両方のプロパティを満たす値の集合」 → プロパティが合体する
- **同名プロパティ**: 「両方の型を同時に満たす値」 → 各プロパティの値型も `&`

この視点で考えると、「交差型がなぜそう動くか」が一貫して理解できます。

---

## 13. まとめ

- 交差型 `A & B` = **「両方の制約を満たす型」**（積集合）
- **オブジェクト型**: プロパティが合体（拡張に使える）
- **プリミティブ型**: ほぼ `never` になる
- 同名プロパティは「両方を満たす」型に絞られる（衝突すると `never`）
- `extends` の代替・ミックスイン・プロパティ上書きで活躍
- 設計時は **ユニオン or 交差** を意識して使い分ける（OR か AND か）

> 交差型は「**型の拡張・合成**」の道具。`extends` と違って `type` でも使え、ミックスインや属性切り出しに便利。**プリミティブで使うと `never` になる**ことだけ覚えておけば、誤用は避けられます。
