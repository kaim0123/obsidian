# オーバーロード（必要なときだけ）

> 関数オーバーロードは「**1つの関数が複数のシグネチャを持つ**」機能です。便利に見えますが、**ジェネリクスやユニオン型で代替できることがほとんど**。本当に必要な場面を見極めて使うのが鉄則です。

## 1. オーバーロードとは

「**呼び出し方によって引数や戻り値の型が変わる**」関数を表現する仕組み。

```typescript
function format(value: string): string;
function format(value: number): string;
function format(value: Date): string;
function format(value: string | number | Date): string {
  // 実装は1つ
  if (typeof value === "string") return value;
  if (typeof value === "number") return value.toFixed(2);
  return value.toISOString();
}

format("hello");   // ✅ 戻り値: string
format(3.14);      // ✅ 戻り値: string
format(new Date()); // ✅ 戻り値: string
format(true);       // ❌ どのオーバーロードにも合わない
```

### 構造

1. **シグネチャ宣言**を複数書く（実装はない、`{}` を書かない）
2. その後ろに**実装シグネチャ**を1つだけ書く（`{}` を書く）
3. 実装シグネチャの引数型は、すべてのオーバーロードを**包含する**ように書く

実装シグネチャは外部からは**見えない**。呼び出し時はオーバーロード宣言だけが候補になります。

---

## 2. オーバーロードが効く例: 戻り値型が引数で変わる

```typescript
function getValue(key: "name"): string;
function getValue(key: "age"): number;
function getValue(key: "active"): boolean;
function getValue(key: string): string | number | boolean {
  // 実装
  return DB[key];
}

const n = getValue("name");   // string
const a = getValue("age");    // number
const x = getValue("active"); // boolean
```

引数のリテラル値によって戻り値型が変わる ── これがオーバーロードの典型的な利点。

---

## 3. オーバーロードを使わない方がいい場面

ほとんどのケースは**ジェネリクスやユニオン型で十分**で、オーバーロードを使うと逆に複雑になります。

### (1) ユニオン型で済むケース

```typescript
// ❌ オーバーロード（過剰）
function f(x: string): string;
function f(x: number): string;
function f(x: string | number): string {
  return String(x);
}

// ✅ ユニオンで十分
function f(x: string | number): string {
  return String(x);
}
```

### (2) ジェネリクスで済むケース

```typescript
// ❌ オーバーロード
function first(arr: string[]): string | undefined;
function first(arr: number[]): number | undefined;
function first(arr: any[]): any {
  return arr[0];
}

// ✅ ジェネリクス
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}
```

ジェネリクスの方が**柔軟・短い・型安全**。

### (3) 引数の有無だけが違うケース

```typescript
// ❌
function greet(): string;
function greet(name: string): string;
function greet(name?: string): string {
  return name ? `Hi ${name}` : "Hi";
}

// ✅ 省略可能引数
function greet(name?: string): string {
  return name ? `Hi ${name}` : "Hi";
}
```

## 4. オーバーロードが本当に必要なケース

### (1) 引数の値（リテラル）で戻り値型が決まる

```typescript
function createElement(tag: "img"): HTMLImageElement;
function createElement(tag: "input"): HTMLInputElement;
function createElement(tag: "div"): HTMLDivElement;
function createElement(tag: string): HTMLElement {
  return document.createElement(tag);
}

const img = createElement("img"); // HTMLImageElement
img.src = "...";                  // ✅
```

これは標準DOM APIの `createElement` と同じパターン。**条件付き型**で書くこともできますが、オーバーロードの方が読みやすい。

### (2) 引数の数や組み合わせで挙動が変わる（ライブラリ作者向け）

```typescript
function format(value: number): string;
function format(value: number, decimals: number): string;
function format(value: number, decimals: number, locale: string): string;
function format(value: number, decimals = 2, locale = "ja-JP"): string {
  return value.toLocaleString(locale, { maximumFractionDigits: decimals });
}
```

ただし**省略可能引数 + デフォルト値**で済むなら、そちらの方がシンプル:

```typescript
function format(value: number, decimals = 2, locale = "ja-JP"): string {
  return value.toLocaleString(locale, { maximumFractionDigits: decimals });
}
```

### (3) ライブラリAPIの後方互換性

「古いシグネチャを残しつつ、新しいシグネチャを追加する」場面で使う。アプリ側ではほぼ出てこない。

## 5. オーバーロードの落とし穴

### (1) 実装シグネチャは「外から見えない」

```typescript
function f(x: string): string;
function f(x: number): number;
function f(x: string | number): string | number {
  return x;
}

f(true); // ❌ 実装シグネチャの string | number は外には見えない
```

実装シグネチャの **「広い引数型」を呼び出し側から使うことはできない**。

### (2) 実装シグネチャの戻り値型と整合性が取れていないとバグる

```typescript
function f(x: string): string;
function f(x: number): number;
function f(x: string | number): string | number {
  return String(x); // string しか返していない
}

const n: number = f(42); // string が来る（ランタイムエラーの原因）
```

オーバーロード宣言は「**契約**」。実装が裏切るとバグります。**実装の中で正しく分岐**することが必須。

### (3) ジェネリクスとオーバーロードの混在は地獄

```typescript
function f<T>(x: T): T;
function f<T>(x: T[]): T[];
function f(x: any): any { return x; }
```

→ ジェネリクスとオーバーロードを混ぜると、推論が複雑になり、メンテが難しくなります。**条件型** で書ける場合が多い:

```typescript
function f<T>(x: T): T extends any[] ? T : T {
  return x;
}
```

### (4) アロー関数では書けない

```typescript
// ❌ アロー関数でオーバーロード宣言は書けない
const f = (x: string): string => x;
   (x: number): number => x;
```

オーバーロードは `function` 宣言（または `interface` のメソッド・コールシグネチャ）でしか書けません。

## 6. メソッドオーバーロード

クラスや `interface` のメソッドにもオーバーロードが書けます。

```typescript
interface Repo {
  find(id: string): User;
  find(criteria: { name: string }): User[];
}

class UserRepo implements Repo {
  find(id: string): User;
  find(criteria: { name: string }): User[];
  find(arg: string | { name: string }): User | User[] {
    if (typeof arg === "string") return loadById(arg);
    return loadByName(arg.name);
  }
}
```

実装は1つ、宣言は複数 ── 関数オーバーロードと同じ構造。

## 7. コールシグネチャでのオーバーロード

`type` や `interface` の中で複数のシグネチャを並べると、オーバーロード型になります。

```typescript
interface Format {
  (value: string): string;
  (value: number): string;
  (value: Date): string;
}

const format: Format = (value: any): string => String(value);

format("a"); // ✅
format(1);   // ✅
```

ライブラリの型定義でよく見るパターン。

---

## 8. ユニオン型との比較

| 観点 | ユニオン型 | オーバーロード |
|---|---|---|
| 書きやすさ | ◎ 短い | × 冗長 |
| 戻り値型を引数で変える | △ 条件型が必要 | ◎ 自然 |
| 実装の単純さ | ◎ | × 実装で分岐が必要 |
| 推論 | ◎ | △ 候補が複数で曖昧 |
| 後方互換性 | × | ◎ |

→ **デフォルトはユニオン型 + ジェネリクス**、特殊な戻り値推論が必要なときだけオーバーロード。

---

## 9. 条件型での代替

「引数によって戻り値が変わる」をオーバーロードではなく**条件型**で書くこともできます。

```typescript
type ElementMap = {
  img: HTMLImageElement;
  input: HTMLInputElement;
  div: HTMLDivElement;
};

function createElement<K extends keyof ElementMap>(tag: K): ElementMap[K] {
  return document.createElement(tag) as ElementMap[K];
}

const img = createElement("img"); // HTMLImageElement
```

**マップ型**を使うと、オーバーロードを大量に書かずに済みます。ライブラリの型定義ではこちらが主流。

---

## 10. 「ほぼ使わない」けど「読めると便利」

実務でオーバーロードを**自分で書く**ことは滅多にありません。ただし:

- DOMの `createElement` / `querySelector` などの型定義
- 古いライブラリ（jQuery等）の型定義
- `Array.prototype` の `concat`, `slice` などの組み込みメソッド

これらは**オーバーロードで定義**されているので、エディタに表示される型を読むときに知識として必要。

---

## 11. オーバーロードを書く前のチェックリスト

オーバーロードを書きたくなったら、まず以下を考える:

- [ ] **ユニオン型**で済まないか？（`x: A | B`）
- [ ] **ジェネリクス**で済まないか？（`<T>`）
- [ ] **省略可能引数 + デフォルト**で済まないか？（`x?: T`, `x = 0`）
- [ ] **オブジェクト引数 + オプショナルフィールド**で済まないか？
- [ ] **条件型 + マップ型**で表現できないか？

すべて「No」なら、初めてオーバーロード。

---

## 12. まとめ

- オーバーロード = **1関数で複数シグネチャ**を持たせる
- 構造: **シグネチャ宣言（複数）+ 実装シグネチャ（1つ、外には非公開）**
- 使うべき場面: **引数のリテラル値で戻り値型が変わる**, ライブラリの後方互換
- 使わない方がよい場面: ユニオン型・ジェネリクス・省略可能引数で済むケース（ほとんど）
- 落とし穴: 実装シグネチャは外から見えない / 実装の分岐ミスでバグる
- アプリ開発では**自分で書く機会はほぼない**。読めれば十分

> オーバーロードは「**最後の手段**」。ジェネリクスとユニオン型でほとんど解決できると覚えて、まずはそちらを使い倒すのが正解です。
