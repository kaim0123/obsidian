# 引数・戻り値・省略可能引数・デフォルト引数

> 関数はTypeScriptの「**型の入口・出口**」。引数と戻り値の型をどう書くかで、コードの安全性も読みやすさも決まります。省略可能引数とデフォルト引数の違い、戻り値推論の落とし穴 ── ここを正確に押さえると、関数まわりのバグが激減します。

## 1. 関数の基本構文（おさらい）

TypeScriptには関数を書く方法がいくつかあります。

### (1) 関数宣言

```typescript
function add(a: number, b: number): number {
  return a + b;
}
```

### (2) 関数式

```typescript
const add = function (a: number, b: number): number {
  return a + b;
};
```

### (3) アロー関数

```typescript
const add = (a: number, b: number): number => a + b;
```

機能的にはほぼ同じ。**`this` の挙動だけが違う**（[[05-thisと関数の落とし穴]] で解説）。

---

## 2. 引数の型

### 必須引数

```typescript
function greet(name: string) {
  return `Hello, ${name}`;
}

greet("Alice"); // ✅
greet();        // ❌ Expected 1 arguments, but got 0.
```

引数の型は**必ず注釈する**（`noImplicitAny: true` で強制される）。

### 引数の数のチェック

JavaScriptと違い、TypeScriptは**引数の数も厳密にチェック**します。

```typescript
function add(a: number, b: number) { return a + b; }
add(1);            // ❌ 1個足りない
add(1, 2, 3);      // ❌ 1個多い
```

---

## 3. 省略可能引数（Optional Parameter）

引数名の後ろに `?` を付けると「**渡しても渡さなくてもよい**」引数になります。

```typescript
function greet(name: string, title?: string) {
  if (title) {
    return `Hello, ${title} ${name}`;
  }
  return `Hello, ${name}`;
}

greet("Alice");        // ✅
greet("Alice", "Dr."); // ✅
```

### `?` を付けた引数の型は `T | undefined`

```typescript
function f(x?: number) {
  // x の型は number | undefined
  x.toFixed(); // ❌ undefinedの可能性
  if (x !== undefined) {
    x.toFixed(); // ✅
  }
}
```

省略可能引数を**そのまま使うとエラー**。必ず `undefined` チェックが必要。

### 省略可能引数は「末尾にだけ」置ける

```typescript
function f(a?: number, b: number) { ... } // ❌
function f(a: number, b?: number) { ... } // ✅
```

途中に `?` 引数を置くと、後ろの引数が判別不能になるためです。

---

## 4. デフォルト引数（Default Parameter）

引数に `= 値` を付けると、**省略時のデフォルト値**が指定できる。

```typescript
function greet(name: string, title: string = "Mr./Ms.") {
  return `Hello, ${title} ${name}`;
}

greet("Alice");        // "Hello, Mr./Ms. Alice"
greet("Bob", "Dr.");   // "Hello, Dr. Bob"
```

### 型推論が効く

```typescript
function greet(name: string, title = "Mr./Ms.") {
  // title の型は string と推論される（デフォルト値から）
}
```

明示しなくても**デフォルト値の型から自動推論**される。

### デフォルト引数も「末尾にだけ」が安全

```typescript
function f(a = 1, b: number) { ... } // ⚠️ 動くが分かりにくい
// 呼び出し: f(undefined, 2) でデフォルトを発動させる必要あり
```

末尾に置くか、オブジェクト引数にするのがベター。

---

## 5. `?` と `= デフォルト値` の違い

似ているようで意味が違う:

| 観点 | `?` | `= デフォルト値` |
|---|---|---|
| 省略可能か | はい | はい |
| 省略時の値 | `undefined` | デフォルト値 |
| 型 | `T \| undefined` | `T`（デフォルト値の型） |
| `undefined` を明示的に渡せるか | はい | はい（→デフォルトが使われる） |

```typescript
function f(x?: number)      { /* x: number | undefined */ }
function g(x: number = 0)   { /* x: number */ }

f();           // x = undefined
g();           // x = 0
g(undefined);  // x = 0（明示的undefinedでもデフォルトが効く）
```

→ **使えるならデフォルト引数の方が安全**（`undefined` チェックが要らない）。

## 6. レストパラメータ（Rest Parameters）

「**任意個の引数**」を配列として受け取る。

```typescript
function sum(...nums: number[]): number {
  return nums.reduce((a, b) => a + b, 0);
}

sum(1, 2, 3);       // 6
sum();              // 0
sum(1, 2, 3, 4, 5); // 15
```

### タプル型のレスト

```typescript
function f(...args: [string, number, boolean]) { ... }
f("a", 1, true); // ✅
f("a");          // ❌
```

「**型と個数を固定したレスト**」も書ける。

### 関数の合成によく使う

```typescript
function logged<T extends any[], R>(
  fn: (...args: T) => R
): (...args: T) => R {
  return (...args) => {
    console.log("called with", args);
    return fn(...args);
  };
}
```

ジェネリックなラッパー関数の引数転送に必須。

## 7. 戻り値の型

### 明示する書き方

```typescript
function add(a: number, b: number): number {
  return a + b;
}
```

### 推論に任せる

```typescript
function add(a: number, b: number) {
  return a + b; // 戻り値は number と推論
}
```

### どちらにすべきか

[[01-型注釈と型推論]] で詳述したように:

- **公開API**（exportされる関数）→ **明示**する
- **小さな内部関数** → 推論に任せる

明示するメリット:

- 内部実装を変えても戻り値型が意図せず変わらない（インターフェース安定）
- エラーがその関数の中で止まる
- 関数の意図を読み手に伝えられる

### 戻り値推論の落とし穴

```typescript
function findUser(id: string) {
  if (id === "admin") return { name: "Admin" };
  // 他は undefined を返す
}

const u = findUser("xxx");
u.name; // ❌ u は { name: string } | undefined
```

`return` 文を全パスに書かないと、暗黙の `undefined` がユニオンに混入する。**戻り値を明示**するとここで気付ける。

```typescript
function findUser(id: string): { name: string } {
  if (id === "admin") return { name: "Admin" };
  // ❌ Function lacks ending return statement
}
```

```typescript
function log(msg: string): void {
  console.log(msg);
}
```

## 9. 引数オブジェクト化（Named Arguments パターン）

引数が3つを超えるなら、**オブジェクトで受ける**のがベストプラクティス。

```typescript
// ❌ 引数が多くて呼び出し側で何が何だか分からない
function createUser(name: string, age: number, email: string, isAdmin: boolean) { ... }
createUser("Alice", 30, "a@e.com", true);

// ✅ オブジェクトで受ける
type CreateUserParams = {
  name: string;
  age: number;
  email: string;
  isAdmin?: boolean;
};

function createUser(params: CreateUserParams) { ... }

createUser({
  name: "Alice",
  age: 30,
  email: "a@e.com",
  isAdmin: true,
});
```

### メリット

- 呼び出し側で**順序を間違えない**
- **省略可能なフィールドが自然**（`?` でOK）
- **追加・削除に強い**（型を変えるだけ）
- **デフォルト値を分割代入で書ける**

```typescript
function createUser({
  name,
  age,
  email,
  isAdmin = false,
}: CreateUserParams) {
  // ...
}
```

### 「3つ以上ならオブジェクト」を目安に

引数が2個までなら位置引数、3個以上はオブジェクト。**多くのチームの規約**になっています。

## 10. 関数のジェネリクス（型引数）

引数や戻り値の型が「**呼び出し側で決まる**」場合、ジェネリクスを使う。

```typescript
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const n = first([1, 2, 3]);    // n: number | undefined
const s = first(["a", "b"]);   // s: string | undefined
```

ジェネリクスを使うと、`any` を使わずに「色んな型を受け入れる」関数が書けます。詳細は [[09-ジェネリクス]] で。

---

## 11. アロー関数特有の注意

アロー関数で**型引数を書くとき**、JSXと混同しやすい:

```typescript
// ❌ JSXとして解釈される（.tsx ファイル）
const f = <T>(x: T) => x;

// ✅ extends を付けると区別できる
const f = <T,>(x: T) => x;        // カンマで回避
const f = <T extends unknown>(x: T) => x; // extends で回避
```

`.ts` ファイルなら問題ありませんが、`.tsx` ではこの工夫が必要。

## 12. よくある間違い

### (1) 引数の型を書き忘れる

```typescript
function greet(user) { ... } // ❌ user: any
```

→ `noImplicitAny: true` を有効に。

### (2) 戻り値の型を「念のため」書きすぎる

```typescript
const double = (n: number): number => n * 2; // 短い関数なら推論で十分
```

→ 公開APIや複雑な関数だけ明示する。

### (3) 省略可能引数 + デフォルト値の混在

```typescript
function f(x?: number = 0) { ... } // ❌ 構文エラー
```

`?` と `= デフォルト値` は**同時に書けません**（デフォルト値があれば自動的に省略可能）。

```typescript
function f(x: number = 0) { ... } // ✅
```

### (4) 引数を `let` で再代入

```typescript
function f(x: number) {
  x = x * 2; // 動くが推奨されない
}
```

引数を直接書き換えると意図が読みにくい。**新しい変数を導入**する方が安全。

```typescript
function f(x: number) {
  const doubled = x * 2;
}
```

---

## 13. 関数の引数・戻り値 早見表

| やりたいこと | 書き方 |
|---|---|
| 必須引数 | `f(x: T)` |
| 省略可能引数 | `f(x?: T)` |
| デフォルト引数 | `f(x: T = 値)` |
| 任意個の引数 | `f(...xs: T[])` |
| 引数を多く取る | オブジェクトで受ける |
| 戻り値の型を明示 | `f(): T { ... }` |
| 戻り値を推論に任せる | `f() { ... }` |
| 戻り値なし | `f(): void` |
| 戻ってこない | `f(): never` |

---

## 14. まとめ

- 引数の型は**必ず明示**（`noImplicitAny: true` で強制）
- **省略可能 `?`** より **デフォルト値 `=`** の方が安全（`undefined` チェック不要）
- 戻り値型は**公開APIで明示**、内部の小さな関数は推論に任せる
- 引数が**3個以上ならオブジェクトで受ける**
- レストパラメータは**ジェネリックなラッパー**で多用する
- 戻り値推論で暗黙の `| undefined` が混入しないよう注意

> 関数の入口・出口を意識して書くだけで、TypeScriptの「型で守られている感覚」が一気に増します。**境界には書く、内側は任せる**を関数でも徹底しましょう。
