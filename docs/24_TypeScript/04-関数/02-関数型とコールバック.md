# 関数型とコールバック・シグネチャ

> 関数を「**値として渡す・受け取る・戻す**」のがTypeScriptの日常です。コールバックの型を正しく書けるようになると、`map` / `filter` / イベントハンドラ / ミドルウェアなど、現代的なJSコードのほとんどで型が効いてくるようになります。

## 1. 関数も「値」── 型を持つ

JavaScriptでは関数は **第一級オブジェクト**（変数に代入できる、引数に渡せる、戻り値にできる）。

TypeScriptでは関数の値にも型を付けます。

```typescript
const add = (a: number, b: number): number => a + b;
//    ^ 型: (a: number, b: number) => number
```

この `(a: number, b: number) => number` が**関数型**です。

---

## 2. 関数型の書き方

### (1) アロー記法（型としての）

```typescript
type BinaryOp = (a: number, b: number) => number;

const add: BinaryOp = (a, b) => a + b;
const sub: BinaryOp = (a, b) => a - b;
```

`BinaryOp` を使うと、引数と戻り値が**自動推論**される。

### (2) コールシグネチャ（オブジェクト型の中で）

```typescript
type Logger = {
  (msg: string): void;
};

const log: Logger = (msg) => console.log(msg);
log("hello"); // ✅
```

「**呼び出し可能なオブジェクト**」を型で表現したいときに使う。あまり使わないが、後述のオーバーロードで登場します。

### (3) `interface` で書く

```typescript
interface BinaryOp {
  (a: number, b: number): number;
}
```

`type` と機能的にほぼ同じ。

---

## 3. コールバック関数の型

「関数を引数として受け取る関数」のことをコールバックと呼びます。

```typescript
function map<T, U>(arr: T[], fn: (item: T) => U): U[] {
  const out: U[] = [];
  for (const item of arr) out.push(fn(item));
  return out;
}

map([1, 2, 3], n => n * 2);     // ✅ 推論: (item: number) => number
map(["a", "b"], s => s.length);  // ✅ 推論: (item: string) => number
```

引数 `fn` に関数型を書くだけ。**呼び出し時にコールバックの引数型は推論される**ので、書く側は型を書かなくてOK。

---

## 4. コールバックの引数推論（contextual typing）

TypeScriptは「**親関数の型から、コールバックの引数型を推論**」します。これを **contextual typing**（文脈型）と呼びます。

```typescript
const arr = [1, 2, 3];

arr.map(n => n.toFixed());      // n: number と推論される
arr.filter(n => n > 1);         // n: number と推論される
arr.forEach(n => console.log(n)); // n: number
```

→ コールバック内の引数に**注釈を書く必要はほぼない**。書くと冗長。

```typescript
arr.map((n: number) => n.toFixed()); // ❌ 冗長
arr.map(n => n.toFixed());            // ✅
```

## 5. コールバックを受ける関数の典型パターン

### (1) 配列メソッド系

```typescript
type Predicate<T> = (item: T) => boolean;
type Mapper<T, U> = (item: T) => U;
```

### (2) イベントハンドラ系

```typescript
type ClickHandler = (e: MouseEvent) => void;

button.addEventListener("click", (e) => {
  // e: MouseEvent と推論される
});
```

### (3) Promiseの `then`

```typescript
fetch("/api").then(res => res.json()); // res: Response
```

### (4) 自作関数のフック

```typescript
function withRetry<T>(
  fn: () => Promise<T>,
  retries: number = 3
): Promise<T> {
  // ...
}
```

## 6. コールバックの戻り値型

戻り値も型で表現できます。

```typescript
type EventHandler = (e: Event) => void;          // 戻り値を使わない
type Validator = (value: string) => boolean;       // 真偽値を返す
type Transformer<T, U> = (input: T) => U;          // 任意の変換
type AsyncFetcher<T> = () => Promise<T>;           // 非同期
```

### コールバックの「戻り値 `void`」の罠（重要）

`void` を返すコールバック型は、**実際に値を返す関数も受け入れます**。これは TypeScript の意図的な仕様。

```typescript
type Handler = (item: number) => void;

const h: Handler = (n) => n * 2; // ✅ 通る（戻り値は使われない前提）
```

便利ですが、`forEach` で要注意:

```typescript
const arr = [1, 2, 3];
const out: number[] = [];

arr.forEach(n => out.push(n)); // ✅ push の戻り値 (number) は無視される
```

→ ただし、**戻り値があるかも**と勘違いすると以下のようなバグに:

```typescript
[1, 2, 3].forEach(async n => {  // ❌ async は Promise を返すが、forEach は待たない
  await something(n);
});
```

→ `forEach` で非同期処理は使わない。`for...of` か `Promise.all(arr.map(...))` を使う。

## 7. 関数の引数・戻り値の互換性（共変・反変）

ここはやや高度ですが、**実務でハマる**ので最低限。

### 引数: 反変（contravariant）

「**親の関数型 = 引数を広く受ける**」関数は、サブタイプとして使える。

```typescript
type Wide = (x: string | number) => void;
type Narrow = (x: string) => void;

const wide: Wide = (x) => { ... };
const narrow: Narrow = wide; // ✅ wide は narrow より広く受けるので互換
```

### 戻り値: 共変（covariant）

「**親の関数型 = 戻り値を狭く返す**」関数は、サブタイプとして使える。

```typescript
type Returns<T> = () => T;

const fn: Returns<string> = () => "hello";
const fn2: Returns<string | number> = fn; // ✅ string は string | number に代入可
```

### 何が困るか

```typescript
type Animal = { name: string };
type Dog = Animal & { bark(): void };

type AnimalHandler = (a: Animal) => void;
type DogHandler = (d: Dog) => void;

const handleAnimal: AnimalHandler = (a) => { ... };
const handleDog: DogHandler = handleAnimal; // ✅
// handleAnimal は Animal しか触らないので Dog でも安全

const handleDog2: DogHandler = (d) => { d.bark(); };
const handleAnimal2: AnimalHandler = handleDog2; // ❌（strictFunctionTypes 有効時）
// handleDog2 は bark を呼ぶので、Animal しか来ないと壊れる
```

`tsconfig.json` の `strictFunctionTypes: true`（または `strict: true`）を有効にすると、関数引数のチェックが厳密になります。

詳しくは [[共変と反変]]。

## 8. 関数型を `interface` でもらう「呼び出し可能型」

オブジェクトに**プロパティもメソッドもある**型を作るときに便利:

```typescript
interface Counter {
  (start: number): string;       // 関数として呼べる
  count: number;                 // プロパティを持つ
  reset(): void;                 // メソッドを持つ
}
```

これを使うと、関数なのに状態も持つ「**カウンタ関数**」のようなものが型で表現できます。

```typescript
const counter: Counter = (() => {
  let n = 0;
  const fn = ((start: number) => `start: ${start}, count: ${n}`) as Counter;
  fn.count = 0;
  fn.reset = () => { n = 0; };
  return fn;
})();
```

実装は煩雑なので、**標準ライブラリやReactのフックでよく見るパターン**として読めれば十分。

## 9. 高階関数（Higher-order function）の型

「関数を返す関数」もよく書きます。

```typescript
function multiplier(n: number): (x: number) => number {
  return (x) => x * n;
}

const double = multiplier(2);
const triple = multiplier(3);

double(5); // 10
triple(5); // 15
```

戻り値の型 `(x: number) => number` は**省略しても推論される**。

## 10. 関数型の使い所まとめ

| パターン | 関数型の例 |
|---|---|
| 配列メソッド | `(item: T) => U` |
| イベントハンドラ | `(e: MouseEvent) => void` |
| バリデーション | `(v: T) => boolean` |
| 比較関数 | `(a: T, b: T) => number` |
| 非同期取得 | `() => Promise<T>` |
| エラーハンドラ | `(err: unknown) => void` |
| 高階関数の戻り値 | `(x: T) => U` |

## 11. よくある間違い

### (1) コールバックの引数に毎回型を書く

```typescript
arr.map((item: string) => item.length); // 冗長
arr.map(item => item.length);            // ✅ 推論される
```

### (2) `void` を返すコールバックで戻り値を使ってしまう

```typescript
[1, 2, 3].forEach(n => n * 2); // n * 2 はどこにも行かない
```

→ 戻り値が必要なら `map` を使う。

### (3) `async` 関数を `forEach` に渡す

```typescript
arr.forEach(async (item) => {
  await something(item); // 待たれない
});
```

→ `for...of + await`、または `Promise.all(arr.map(...))`。

### (4) コールバックのオプション引数を期待しない

`map` のコールバックは `(item, index, array) => U` の3引数を取れます。

```typescript
arr.map((item, index) => `${index}: ${item}`); // ✅ index が推論される
```

ただし、引数を全部書く必要はない（後ろは省略OK）。

### (5) 関数型と関数値の混同

```typescript
type Greet = (name: string) => string;

const greet: Greet = (name) => `Hi ${name}`;
const wrong: Greet = "hello";  // ❌ 値（string）を関数型に代入
```

---

## 12. まとめ

- 関数も**値**であり**型を持つ**: `(args) => returnType`
- 関数型は **`type`** か **`interface`** で名前を付けて再利用
- コールバックの引数型は**親関数から推論**される（contextual typing）
- 戻り値 `void` のコールバックは**戻り値を返す関数も受け入れる**（`forEach`の罠）
- 引数は**反変**、戻り値は**共変**（`strictFunctionTypes` を有効に）
- 関数型 + プロパティ = **呼び出し可能型**（`interface` で表現）

> 関数型を読み書きできるようになると、配列メソッド・Promise・イベント処理など**現代的なJSコードのほぼすべて**に型が効いてくるようになります。ここを越えるとTypeScriptが一気に楽しくなります。
