# 共変（Covariant）と反変（Contravariant）

## 共変・反変とは？

「**型の関係（A は B のサブタイプ）が、それを使う型でどう伝わるか**」を表す概念です。
特に **関数の引数と戻り値** で重要になります。

最初は難しく感じますが、「**安全に置き換えられるか？**」という観点で考えると理解しやすくなります。

## 用語の整理

|名前|意味|例|
|---|---|---|
|共変（covariant）|サブタイプの関係が **そのまま** 伝わる|`Dog` は `Animal` → `Dog[]` は `Animal[]`|
|反変（contravariant）|サブタイプの関係が **逆に** なる|関数引数|
|双変（bivariant）|どっちでも OK（だが危険）|TS のデフォルト関数引数|
|非変（invariant）|サブタイプの関係が **伝わらない**|可変参照などで起こる|

## 共変の例

```typescript
class Animal { name = ""; }
class Dog extends Animal { bark() {} }

const dogs: Dog[] = [new Dog()];
const animals: Animal[] = dogs; // OK：Dog は Animal なので OK
```

「より具体的なものを、より抽象的なものとして扱う」ことは安全です。

## 反変の例：関数の引数

関数を「**呼ぶ側**」の立場で考えます。

```typescript
type AnimalHandler = (a: Animal) => void;

const handleDog: (d: Dog) => void = (d) => d.bark();
const handleAnimal: AnimalHandler = (a) => console.log(a.name);

let h: AnimalHandler;
h = handleAnimal; // OK
// h = handleDog;   // 本来は NG（引数は反変）
```

`AnimalHandler` は「**任意の Animal を受け取れる関数**」を期待しています。
`handleDog` は `Dog` しか受け取れないので、`Animal` を渡されたら困ります。
よって、**`Animal → void` の代入先に、`Dog → void` を入れるのは危険**。これが反変です。

> 「引数は反変」「戻り値は共変」と覚えれば OK。

## TypeScript のデフォルト：双変

実は TypeScript はデフォルトで関数の引数を **双変（bivariant）** として扱います。
これは便利な反面、本来不安全なコードを通してしまうことがあります。

```typescript
// strictFunctionTypes: false の世界
let h: (a: Animal) => void = (d: Dog) => d.bark(); // 通ってしまう
h(new Animal()); // 実行時に bark できない
```

## strictFunctionTypes で反変を厳密に

`strict` を有効にすると、`strictFunctionTypes` が ON になり、
関数型の引数が正しく **反変** として扱われるようになります。

```typescript
// strictFunctionTypes: true
let h: (a: Animal) => void = (d: Dog) => d.bark();
// エラー：(d: Dog) => void は (a: Animal) => void に代入できない
```

**メソッド構文（`m(d: Dog): void`）はまだ双変扱い** という例外があるので注意。

```typescript
type T = {
  m(d: Dog): void; // 双変扱い（メソッド構文）
  f: (d: Dog) => void; // 反変扱い（プロパティ + 関数型）
};
```

## 配列は要注意：「共変だが書き換え可能」

配列は要素アクセスでは共変ですが、要素を **書き込めるとき** は本当は安全ではありません。

```typescript
const dogs: Dog[] = [new Dog()];
const animals: Animal[] = dogs;
animals.push(new Animal()); // 本来 dogs に Animal を入れるのは危険
```

TypeScript はここを厳密にはチェックしません（人間がガードする想定）。
**読み取り専用配列 (`readonly Dog[]` → `readonly Animal[]`)** にすると安心です。

## まとめ

- **共変**：サブタイプ関係がそのまま伝わる（戻り値、配列要素の参照）
- **反変**：サブタイプ関係が逆になる（関数の引数）
- TypeScript デフォルトは引数が双変だが、**`strictFunctionTypes`** で反変に
- メソッド構文はまだ双変扱い（落とし穴）
- 配列の共変は危険：書き込みする型は `readonly` を検討
- 「**安全に置き換えられるか？**」を軸に考えるとブレない
