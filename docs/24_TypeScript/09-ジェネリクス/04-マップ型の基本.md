# マップ型（Mapped Types）の基本

> マップ型は「**既存の型のキーをループして、新しい型を作る**」仕組み。`Partial` `Required` `Readonly` `Record` などの標準ユーティリティ型はすべてこれで書かれています。理解すると、**型から型を生成する**設計ができるようになり、コードのDRYさが一段上がります。

## 1. マップ型とは

「**型のループ**」のような構文。`[K in 型] : 値の型` で、各キーに対して新しいプロパティを定義する。

```typescript
type T = {
  [K in "a" | "b" | "c"]: string;
};
// { a: string; b: string; c: string }
```

これがマップ型の最小例。**ユニオン型の各メンバーをキーにして、値型をマップする**。

---

## 2. `keyof` と組み合わせる定番形

```typescript
type CopyOf<T> = {
  [K in keyof T]: T[K];
};

type User = { id: string; name: string };
type CopyUser = CopyOf<User>;
// { id: string; name: string }
```

→ **元の型をそっくりコピー**するマップ型。実用的には何もしないが、**マップ型の基本構造**として大事。

これに修飾子や変換を加えていくのがマップ型の使い方。

---

## 3. 標準ユーティリティ型はマップ型でできている

### `Partial<T>` ── 全プロパティを optional に

```typescript
type Partial<T> = {
  [K in keyof T]?: T[K];
};

type PartialUser = Partial<User>;
// { id?: string; name?: string }
```

### `Required<T>` ── 全プロパティを必須に

```typescript
type Required<T> = {
  [K in keyof T]-?: T[K]; // -? で optional を取り除く
};
```

### `Readonly<T>` ── 全プロパティを readonly に

```typescript
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};
```

### `Record<K, V>` ── 任意キー → V のマップ

```typescript
type Record<K extends keyof any, V> = {
  [P in K]: V;
};
```

→ **これらは全部、たった数行のマップ型**。中身を知ると応用が利く。

---

## 4. 修飾子の追加・除去

マップ型では `?` と `readonly` を**追加** / **除去**できる。

| 記号 | 意味 |
|---|---|
| `?` | optional を**追加** |
| `-?` | optional を**除去** |
| `readonly` | readonly を**追加** |
| `-readonly` | readonly を**除去** |

```typescript
type Mutable<T> = {
  -readonly [K in keyof T]: T[K]; // readonly を外す
};

type ReadonlyUser = { readonly id: string };
type MutableUser = Mutable<ReadonlyUser>;
// { id: string }
```

```typescript
type RequiredAll<T> = {
  [K in keyof T]-?: T[K];
};

type Optional = { name?: string };
type Req = RequiredAll<Optional>;
// { name: string }
```

## 5. 値の型を変換する

各プロパティの**型**を一律に変換できる。

### 全プロパティを文字列に

```typescript
type Stringify<T> = {
  [K in keyof T]: string;
};

type S = Stringify<{ a: number; b: boolean }>;
// { a: string; b: string }
```

### 全プロパティを Promise に

```typescript
type Promisify<T> = {
  [K in keyof T]: Promise<T[K]>;
};

type P = Promisify<{ user: User; posts: Post[] }>;
// { user: Promise<User>; posts: Promise<Post[]> }
```

### 全プロパティを `null` 許容に

```typescript
type Nullable<T> = {
  [K in keyof T]: T[K] | null;
};
```

### 全プロパティの値を関数化

```typescript
type Getters<T> = {
  [K in keyof T]: () => T[K];
};

type G = Getters<{ name: string; age: number }>;
// { name: () => string; age: () => number }
```

---

## 6. キーの変換（Key Remapping）── TS 4.1+

`as` を使うと、**キー自体も変換**できる。

```typescript
type WithGetters<T> = {
  [K in keyof T as `get${Capitalize<K & string>}`]: () => T[K];
};

type G = WithGetters<{ name: string; age: number }>;
// { getName: () => string; getAge: () => number }
```

→ React の props や Vuex の getter 生成などで活用。

### キーを除外する（`never` で消す）

```typescript
type RemoveProperty<T, K extends keyof T> = {
  [P in keyof T as P extends K ? never : P]: T[P];
};

type R = RemoveProperty<{ a: number; b: string; c: boolean }, "b">;
// { a: number; c: boolean }
```

→ **`Omit` の挙動**を自前で書ける。

### キー名にプレフィックス

```typescript
type Prefixed<T, P extends string> = {
  [K in keyof T as `${P}_${K & string}`]: T[K];
};

type P = Prefixed<{ name: string; age: number }, "user">;
// { user_name: string; user_age: number }
```

## 7. 条件型と組み合わせる

マップ型の中で**条件型**を使うと、プロパティごとに型を変えられる。

```typescript
type ToStringOnly<T> = {
  [K in keyof T]: T[K] extends string ? T[K] : never;
};

type S = ToStringOnly<{ a: string; b: number; c: string }>;
// { a: string; b: never; c: string }
```

`never` のプロパティを取り除きたいなら、Key Remapping と組み合わせる:

```typescript
type StringKeysOnly<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

type R = StringKeysOnly<{ a: string; b: number; c: string }>;
// { a: string; c: string }
```

## 8. 実例: API レスポンスの型変換

### `string` で来た日付を `Date` に

```typescript
type Parse<T> = {
  [K in keyof T]: T[K] extends string ? Date | T[K] : T[K];
};
```

### nullable なフィールドを optional に

```typescript
type NullToOptional<T> = {
  [K in keyof T as T[K] extends null | undefined ? K : never]?: T[K];
} & {
  [K in keyof T as T[K] extends null | undefined ? never : K]: T[K];
};
```

ややこしいが、**フィールドの型に応じてプロパティの形を変える**ことができる。

---

## 9. 実例: フォームステート

```typescript
type FormState<T> = {
  values: T;
  errors: Partial<Record<keyof T, string>>;
  touched: Partial<Record<keyof T, boolean>>;
};

type LoginFormState = FormState<{ email: string; password: string }>;
// {
//   values: { email: string; password: string };
//   errors: { email?: string; password?: string };
//   touched: { email?: boolean; password?: boolean };
// }
```

→ 1つの型 `T` から、**3つの関連した型**を自動生成。

## 10. ネストしたマップ型（DeepReadonly / DeepPartial）

### DeepReadonly

```typescript
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object
    ? DeepReadonly<T[K]>
    : T[K];
};

type Frozen = DeepReadonly<{
  user: { name: string };
  arr: number[];
}>;
// {
//   readonly user: { readonly name: string };
//   readonly arr: readonly number[];
// }
```

### DeepPartial

```typescript
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};
```

→ **再帰的なマップ型**。設定オブジェクトの一部更新などで便利。

## 11. マップ型の落とし穴

### (1) `keyof T` がインデックスシグネチャを含むと予想外のキー

```typescript
type Dict = { [key: string]: number };
type K = keyof Dict;  // string | number
type Mapped = {
  [K in keyof Dict]: string;
};
// { [x: string]: string }
```

→ インデックスシグネチャを持つ型でマップ型を使うと、意図と違う結果になることも。

### (2) `as` でキーが `never` になると消える

```typescript
type Remove<T, K> = {
  [P in keyof T as P extends K ? never : P]: T[P];
};
```

`never` キーは結果の型から**消える**。これは仕様。

### (3) Mapped Type で**オブジェクト型以外**を渡す

```typescript
type Wrong<T> = { [K in keyof T]: T[K] };

type W = Wrong<string>; // string のメソッド名がキーになる
```

→ プリミティブを渡すとメソッド名がキーになり、意図と違う。`extends object` で制約しよう:

```typescript
type Mapped<T extends object> = { [K in keyof T]: T[K] };
```

### (4) **再帰の深さ**

`DeepReadonly` のような再帰マップ型は、**深いネストでパフォーマンスが落ちる**ことがある。実用上は3〜5階層程度なら問題なし。

### (5) Key Remapping は TS 4.1 以降

古いTypeScriptでは `as` での remap は使えない。バージョン確認を。

## 12. ベストプラクティス

### (1) **標準ユーティリティ型を最大限使う**

`Partial` `Required` `Readonly` `Pick` `Omit` `Record` で済むことは多い。

### (2) **マップ型を使うのは「複数の関連型を導出」したいとき**

```typescript
// 1つのソース型から複数の派生型を作る
type User = { ... };
type PartialUser = Partial<User>;
type UpdateUser = Pick<User, "name" | "email">;
type UserKeys = keyof User;
```

### (3) **複雑なマップ型は型エイリアスにまとめる**

```typescript
type ApiResponse<T> = Readonly<{
  data: T;
  meta: { timestamp: string; requestId: string };
}>;
```

### (4) **テストする（実際の使用例で確認）**

複雑なマップ型は、実際のオブジェクトに適用して**型展開を VSCode で確認**する。

## 13. マップ型・早見表

| 書きたいこと | マップ型 | 標準ユーティリティ |
|---|---|---|
| 全 optional | `{ [K in keyof T]?: T[K] }` | `Partial<T>` |
| 全 required | `{ [K in keyof T]-?: T[K] }` | `Required<T>` |
| 全 readonly | `{ readonly [K in keyof T]: T[K] }` | `Readonly<T>` |
| 全 readonly 解除 | `{ -readonly [K in keyof T]: T[K] }` | (標準なし) |
| 任意キー → V | `{ [K in K]: V }` | `Record<K, V>` |
| 値型を変換 | `{ [K in keyof T]: U }` | (標準なし) |
| キー名を変換 | `{ [K in keyof T as ...]: T[K] }` | (標準なし) |
| 一部キー除外 | `{ [K in keyof T as K extends X ? never : K]: T[K] }` | `Omit<T, X>` |

---

## 14. まとめ

- マップ型 = **`[K in 型]: 値型`** で型のキーをループして新しい型を作る
- **`keyof T` + マップ型**で既存の型を変換する基本パターン
- 修飾子: **`?` / `-?` / `readonly` / `-readonly`**
- **Key Remapping (`as`)** でキー自体を変換可能（TS 4.1+）
- 条件型と組み合わせると強力
- 標準の `Partial` `Required` `Readonly` `Record` `Pick` `Omit` は全部マップ型ベース
- 再帰マップ型（`DeepReadonly` 等）も書ける

> マップ型を理解すると、「**型を計算する**」という新しい世界に入れます。設定オブジェクト・APIレスポンス・フォームステートなど、**1つの型から複数の関連型を自動生成**できるようになり、保守性が一段上がります。
