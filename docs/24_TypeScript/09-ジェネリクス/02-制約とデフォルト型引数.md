# 制約（`extends`）とデフォルト型引数

> ジェネリクスの `T` は「**何でもOK**」だと、関数の中で何もできません。**制約 `T extends ...`** で「最低限の形」を要求し、**デフォルト型引数 `T = ...`** で「省略時の値」を指定する ── この2つで、ジェネリクスは実用的になります。

## 1. ジェネリクスの「制約のなさ」の問題

```typescript
function logLength<T>(x: T) {
  console.log(x.length); // ❌ T に length があるとは限らない
}
```

`T` が任意なので、`length` プロパティへのアクセスができない。

→ **「`T` は最低限 `length` を持つ」** と要求したい。これが**制約**。

---

## 2. `extends` 制約の基本

`T extends 型` で「**Tは指定の型に代入可能でなければならない**」と制約する。

```typescript
function logLength<T extends { length: number }>(x: T) {
  console.log(x.length); // ✅ length があると保証される
}

logLength("hello");        // ✅ string は length を持つ
logLength([1, 2, 3]);       // ✅ array
logLength({ length: 5 });    // ✅ length を持つオブジェクト
logLength(42);              // ❌ number は length を持たない
```

「**制約 = `T` の最低条件**」と覚える。

---

## 3. 典型的な制約パターン

### (1) オブジェクト型を要求

```typescript
function printName<T extends { name: string }>(x: T) {
  console.log(x.name);
}

printName({ name: "Alice", age: 30 }); // ✅
printName({ age: 30 });                  // ❌
```

### (2) 特定のクラスのインスタンス

```typescript
function process<T extends Error>(err: T) {
  console.log(err.message);
}

process(new Error("oops"));      // ✅
process(new TypeError("type"));   // ✅（TypeError は Error の派生）
process({ message: "fake" });     // ❌
```

### (3) 配列を要求

```typescript
function first<T extends unknown[]>(arr: T): T[0] {
  return arr[0];
}

const a = first([1, 2, 3]);     // number
const b = first([1, "a", true]); // number（タプルの0番目）
```

### (4) 関数を要求

```typescript
function callFn<T extends (...args: any[]) => any>(fn: T): ReturnType<T> {
  return fn();
}
```

### (5) 文字列リテラル

```typescript
function greet<T extends "morning" | "evening">(time: T) { ... }

greet("morning"); // ✅
greet("night");    // ❌
```

---

## 4. 制約の効果: 「型の幅」を狭めずに使える

制約があっても、**呼び出し側で渡した具体的な型は保たれる**。

```typescript
function copy<T extends object>(obj: T): T {
  return { ...obj };
}

const u = copy({ name: "Alice", age: 30 });
u.name; // ✅ string（型情報は失われない）
u.age;  // ✅ number
```

→ 制約は「**最低条件**」であり、**実際の型が `T extends object` の `object` に丸められない**のがポイント。

---

## 5. 複数の制約

`&` を使って複数の制約を交差させる:

```typescript
function f<T extends { name: string } & { age: number }>(x: T) {
  console.log(x.name, x.age);
}

f({ name: "Alice", age: 30, extra: true }); // ✅
```

ただし**読みづらくなる**ので、制約を**型エイリアスにまとめる**のがおすすめ:

```typescript
type Person = { name: string; age: number };
function f<T extends Person>(x: T) { ... }
```

---

## 6. `keyof` と組み合わせる強力なパターン

`keyof T` を使うと、「**T のキーの中の1つ**」を制約できる。

```typescript
function getValue<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { name: "Alice", age: 30 };

const name = getValue(user, "name");    // ✅ string
const age = getValue(user, "age");      // ✅ number
const x = getValue(user, "wrong");      // ❌ "wrong" is not in keyof user
```

→ **存在するキーしか渡せない、戻り値型も正確**。実務頻出パターン。

詳しくは [[03-keyofとインデックスアクセス型]] へ。

## 7. デフォルト型引数

`T = デフォルト型` で、省略時の型を指定できる。

```typescript
type Container<T = string> = {
  value: T;
};

const a: Container = { value: "hello" };       // T = string
const b: Container<number> = { value: 42 };     // T = number
```

### 関数でも

```typescript
function create<T = string>(): T {
  return ... as T;
}

const a = create();          // T = string
const b = create<number>();  // T = number
```

### Promiseのデフォルト

```typescript
type AsyncResult<T = void> = Promise<T>;

const a: AsyncResult = something(); // Promise<void>
const b: AsyncResult<User> = ...;    // Promise<User>
```

### Result型のデフォルト

```typescript
type Result<T, E = Error> =
  | { ok: true; value: T }
  | { ok: false; error: E };

const r: Result<User> = ok(...);  // E = Error
const r2: Result<User, "not_found"> = err("not_found"); // E = "not_found"
```

→ よく使う型を省略可能にできる。

---

## 8. 制約とデフォルトの組み合わせ

```typescript
type Container<T extends object = {}> = {
  data: T;
};

type A = Container;          // data: {}
type B = Container<User>;    // data: User
```

「**制約 + デフォルト**」を組み合わせると、柔軟かつ安全な型ができる。

---

## 9. 実例: `pluck` 関数

オブジェクト配列から特定のキーの値を取り出す:

```typescript
function pluck<T, K extends keyof T>(arr: T[], key: K): T[K][] {
  return arr.map(item => item[key]);
}

const users = [
  { name: "Alice", age: 30 },
  { name: "Bob", age: 25 },
];

const names = pluck(users, "name"); // string[]
const ages = pluck(users, "age");    // number[]
const wrong = pluck(users, "x");     // ❌
```

→ ジェネリクス + 制約 + インデックスアクセス型の組み合わせ。

---

## 10. 実例: `merge` 関数

2つのオブジェクトをマージ:

```typescript
function merge<T extends object, U extends object>(a: T, b: U): T & U {
  return { ...a, ...b };
}

const result = merge({ name: "Alice" }, { age: 30 });
// 型: { name: string } & { age: number }
result.name; // ✅
result.age;  // ✅
```

---

## 11. 実例: `omit` の自作

標準の `Omit` の動きを真似:

```typescript
function omit<T extends object, K extends keyof T>(
  obj: T,
  ...keys: K[]
): Omit<T, K> {
  const result = { ...obj };
  for (const k of keys) delete result[k];
  return result;
}

const user = { id: "1", name: "Alice", password: "secret" };
const safe = omit(user, "password"); // { id: string; name: string }
```

## 12. ジェネリクスの「制約付き」の落とし穴

### (1) 制約を**広く**しすぎる

```typescript
function f<T extends any>(x: T) { ... } // any はほぼ制約なし
function f<T extends object>(x: T) { ... } // 多くの場面で十分
```

→ 制約は**必要最小限**に。`any` への extends は意味がない。

### (2) 制約を**狭く**しすぎる

```typescript
function f<T extends { name: string; age: number; email: string }>(x: T) { ... }
// → 必要なフィールドだけに絞る方が再利用性UP
```

### (3) 制約と引数型がずれる

```typescript
function pluck<T, K extends string>(arr: T[], key: K): T[K] {
  // ❌ K が必ず keyof T とは限らない
  return arr[0][key];
}
```

→ `K extends keyof T` にする。

### (4) デフォルト型引数を使いすぎる

```typescript
type Box<T = any> = { value: T };
const b: Box = { value: 42 }; // T = any（実質型安全性なし）
```

→ デフォルトを `any` にすると意味がない。**最も使うであろう型**を入れる。

### (5) 制約を `interface` の継承で書こうとする

```typescript
function f<T>(x: T extends Foo) { ... } // ❌ 構文エラー
function f<T extends Foo>(x: T) { ... } // ✅
```

`extends` は型引数宣言の中で書く。

---

## 13. ジェネリクスの「型関数」としての側面

ジェネリクス型は「**型を入れて型を返す関数**」と見なせる。

```typescript
type Box<T> = { value: T }; // 入力 T → 出力 { value: T }

type A = Box<string>;  // { value: string }
type B = Box<number>;  // { value: number }
```

→ 型レベルで関数のように振る舞う。`Pick` `Omit` `ReturnType` などすべて同じ発想。

詳しくは「14章 型レベルプログラミング」で扱います。

## 14. ベストプラクティス

### (1) 制約は**そのジェネリクスで実際に使う最低限**だけ

```typescript
function logLength<T extends { length: number }>(x: T) {
  console.log(x.length);
}
// length しか使わないので制約は length だけ
```

### (2) デフォルト型引数は**最も多用される型**を指定

```typescript
type Result<T, E = Error> = ...;
// 多くの場合 E は Error なのでデフォルト
```

### (3) 制約 `extends` を `keyof` と組み合わせる

```typescript
function get<T, K extends keyof T>(obj: T, key: K): T[K] { ... }
```

→ 「型に存在するキーだけを受け付ける」が表現できる。

### (4) 「**制約なしでも書けるならジェネリクスにしない**」

```typescript
function add(a: number, b: number) { return a + b; } // ジェネリクス不要
```

→ 「**型を変えたい場面だけ**」ジェネリクス化。

---

## 15. まとめ

- **`T extends ...`**: ジェネリクスに**最低条件**を課す
- 制約があっても、**呼び出し側の具体型は保たれる**（広い型に丸められない）
- 典型: `extends keyof T` / `extends object` / `extends (...args: any[]) => any`
- **デフォルト型引数 `T = ...`**: 省略時の型を指定
- 組み合わせ: `T extends object = {}` のように
- 落とし穴: 制約が広すぎ・狭すぎ / デフォルトを `any` に / `K extends string` の罠

> 制約を使いこなせるようになると、ジェネリクスは「**何でも入る箱**」から「**正しい形のものだけ受け入れる賢い箱**」になります。`keyof T` と組み合わせる**`get` パターン**は、最初に身につけたい必修テクニックです。
