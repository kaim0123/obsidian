# ジェネリクス関数とジェネリクス型

> 「**型を引数として受け取る**」── これがジェネリクスの本質です。`any` を使わずに「色んな型を受け入れる」関数や型を書けるようになり、TypeScriptの真価がここから始まります。最初は `<T>` という記号にアレルギーが出ますが、**「`Array<string>` の `string` を自分で書ける側になる」**と思えば腹落ちします。

## 1. ジェネリクスとは

「**型を後から決められる関数・型**」を作る仕組み。

```typescript
function identity<T>(x: T): T {
  return x;
}

const a = identity<string>("hello"); // a: string
const b = identity<number>(42);      // b: number
const c = identity("hello");          // 推論: T = string
```

`<T>` の `T` は **型引数（type parameter）**。呼び出すたびに `T` が決まる。

### `any` との違い

```typescript
// ❌ any: 型情報が消える
function identity(x: any): any {
  return x;
}
const a = identity("hello"); // a: any （.length などの型補完なし）

// ✅ ジェネリクス: 型情報が保たれる
function identity<T>(x: T): T {
  return x;
}
const b = identity("hello"); // b: string（補完が効く）
```

→ **入力の型を出力の型と関連づけて保つ**のがジェネリクス。

## 2. なぜ必要か（モチベーション）

### `any` だと型が崩れる

```typescript
function first(arr: any[]): any {
  return arr[0];
}

const x = first([1, 2, 3]); // x: any（number と分からない）
x.toFixed(); // 通る（実は number だが any なので無検査）
```

### ユニオン型では限界

```typescript
function first(arr: (string | number)[]): string | number {
  return arr[0];
}

const x = first([1, 2, 3]); // x: string | number （number と特定できない）
```

### ジェネリクスで完全に解決

```typescript
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const x = first([1, 2, 3]); // x: number | undefined ✅
const y = first(["a", "b"]); // y: string | undefined ✅
```

→ **入力から出力の型が自動推論**される。

---

## 3. ジェネリクス関数の構文

### 基本

```typescript
function 関数名<T>(引数: T): 戻り値の型 {
  // ...
}
```

`<T>` で型引数を宣言、本体や引数で `T` を使う。

### 複数の型引数

```typescript
function pair<A, B>(a: A, b: B): [A, B] {
  return [a, b];
}

const p = pair("hello", 42); // [string, number]
```

### アロー関数の場合

```typescript
const identity = <T>(x: T): T => x;
```

`.tsx` ファイルではJSXと衝突するため、**`<T,>`** や **`<T extends unknown>`** で回避:

```typescript
const identity = <T,>(x: T): T => x;
const identity = <T extends unknown>(x: T): T => x;
```

### メソッドの場合

```typescript
class Box {
  wrap<T>(value: T): { value: T } {
    return { value };
  }
}
```

クラスメソッドにも `<T>` を付けられる。

## 4. 型引数の推論

ほとんどの場合、**呼び出し時に明示しなくても推論**される。

```typescript
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const a = first([1, 2, 3]);    // T = number
const b = first(["a", "b"]);    // T = string

// 明示も可能（普通は不要）
const c = first<number>([1, 2, 3]);
```

### 推論できないとき

```typescript
function create<T>(): T {
  return ... as T;
}

const x = create(); // ❌ T が推論できない（unknown または any）

// 明示する
const x = create<User>();
```

引数から推論できる型は省略、できない場合は明示。

---

## 5. ジェネリクス型（型エイリアス）

関数だけでなく、`type` や `interface` にも型引数を付けられる。

```typescript
type Box<T> = {
  value: T;
};

const a: Box<number> = { value: 42 };
const b: Box<string> = { value: "hello" };
```

### `interface` でも

```typescript
interface Box<T> {
  value: T;
}
```

### 複数の型引数

```typescript
type KeyValue<K, V> = {
  key: K;
  value: V;
};

const kv: KeyValue<string, number> = { key: "age", value: 30 };
```

### 標準ライブラリの例

`Array<T>` `Promise<T>` `Map<K, V>` `Set<T>` `Record<K, V>` ── すべて TypeScript の標準ジェネリクス型。

```typescript
const arr: Array<number> = [1, 2, 3];
const p: Promise<string> = fetch("/api").then(r => r.text());
const m: Map<string, User> = new Map();
```

## 6. ジェネリクスの典型パターン

### (1) コレクション操作

```typescript
function map<T, U>(arr: T[], fn: (item: T) => U): U[] {
  return arr.map(fn);
}

function filter<T>(arr: T[], pred: (item: T) => boolean): T[] {
  return arr.filter(pred);
}
```

### (2) Promise系

```typescript
function delay<T>(ms: number, value: T): Promise<T> {
  return new Promise(resolve => setTimeout(() => resolve(value), ms));
}

const p = delay(1000, "hello"); // Promise<string>
```

### (3) ラッパー / コンテナ

```typescript
type Result<T, E = Error> =
  | { ok: true; value: T }
  | { ok: false; error: E };

function ok<T>(v: T): Result<T> { return { ok: true, value: v }; }
function err<E>(e: E): Result<never, E> { return { ok: false, error: e }; }
```

### (4) リトライ・キャッシュ・ロガーなど（HOF）

```typescript
function withRetry<T>(
  fn: () => Promise<T>,
  retries: number = 3
): Promise<T> {
  // ...
}

function memoize<A extends any[], R>(
  fn: (...args: A) => R
): (...args: A) => R {
  const cache = new Map<string, R>();
  return (...args) => {
    const key = JSON.stringify(args);
    if (!cache.has(key)) cache.set(key, fn(...args));
    return cache.get(key)!;
  };
}
```

### (5) APIクライアント

```typescript
async function get<T>(url: string): Promise<T> {
  const res = await fetch(url);
  return res.json();
}

const user = await get<User>("/api/user/1"); // user: User
```

## 7. 型引数の命名規則

| 慣例 | 用途 |
|---|---|
| `T` | 一般的な型（最頻出） |
| `U`, `V`, `W` | 2つ目以降 |
| `K` | キー（`Map`, `Record` など） |
| `V` | 値 |
| `R` | 戻り値（return） |
| `E` | エラー（error） |
| `A`, `B` | 関数の引数列 |

```typescript
type Map<K, V> = ...;
type Result<T, E> = ...;
type Func<A extends any[], R> = (...args: A) => R;
```

「**意味のある名前**」（`TKey`, `TValue`）を使うチームもあります。

## 8. ジェネリクスとオーバーロードの関係

オーバーロードでも複数の型を受けられますが、**ジェネリクスの方が柔軟**:

```typescript
// オーバーロード: 型を列挙
function first(arr: number[]): number | undefined;
function first(arr: string[]): string | undefined;
function first(arr: any[]): any { return arr[0]; }

// ジェネリクス: 任意の型に対応
function first<T>(arr: T[]): T | undefined { return arr[0]; }
```

[[04-オーバーロード]] で詳述したように、**ジェネリクスで済むならジェネリクスを優先**。

## 9. ジェネリクスと型推論の限界

### (1) 戻り値型から逆推論はされない

```typescript
function create<T>(): T { return ... as T; }

const u: User = create(); // T = User と推論されない
const u = create<User>(); // 明示が必要
```

### (2) コールバック内の型推論

```typescript
function compose<A, B, C>(f: (a: A) => B, g: (b: B) => C): (a: A) => C {
  return a => g(f(a));
}

const fn = compose(
  (s: string) => s.length,  // A=string, B=number
  n => n.toFixed()           // n: number と推論される
);
```

→ 連鎖的に推論される。

### (3) 部分推論はサポートされない

```typescript
function pair<A, B>(a: A, b: B): [A, B] { return [a, b]; }

pair<string>("a", 1); // ❌ B も指定する必要あり
pair<string, number>("a", 1); // ✅
```

「Aだけ指定して、Bは推論」はできない（TS 5.x で `Partial Type Argument Inference` 提案中、まだ標準ではない）。

## 10. ジェネリクスの落とし穴

### (1) 型引数を**使わない**のに付ける

```typescript
function f<T>(x: number): number { // T を使ってない
  return x;
}
```

→ 不要な型引数は外す。

### (2) 型引数を `any` 化してしまう

```typescript
function f<T>(x: T): any { // 戻り値が any
  return x;
}
```

→ `T` を使う意味が消える。`: T` を返す。

### (3) ユニオンとジェネリクスの混同

```typescript
function f<T>(x: T) { ... }

f<string | number>("hello"); // T = string | number
f<string>("hello");           // T = string

// ユニオンで受けたい場合は明示する
```

### (4) 引数で `T[]` の中身を強制したいなら制約を

```typescript
function pluck<T>(arr: T[], key: string): any[] { // ❌ key の安全性なし
  return arr.map(item => (item as any)[key]);
}

// ✅ 制約つき（後述）
function pluck<T, K extends keyof T>(arr: T[], key: K): T[K][] {
  return arr.map(item => item[key]);
}
```

→ [[02-制約とデフォルト型引数]] / [[03-keyofとインデックスアクセス型]] へ。

### (5) ジェネリクスを使いすぎて読めない

```typescript
function f<T extends Record<string, U>, U extends V[], V>(): ...
```

→ 型引数3つ以上はだいたい設計の見直しサイン。

## 11. 実例: Reactのフック

```typescript
function useState<T>(initial: T): [T, (v: T) => void] {
  // ...
}

const [count, setCount] = useState(0);    // T = number
const [name, setName] = useState("");      // T = string
const [user, setUser] = useState<User | null>(null);
```

→ 初期値から推論、または明示。

```typescript
function useFetch<T>(url: string): { data: T | null; loading: boolean } {
  // ...
}

const { data, loading } = useFetch<User>("/api/user");
```

→ APIレスポンス型を明示。

## 12. ジェネリクスを書くタイミング

「**この関数、複数の型で動かしたい**」と思ったらジェネリクス化。

### Before（具体型）

```typescript
function firstNumber(arr: number[]): number | undefined { return arr[0]; }
function firstString(arr: string[]): string | undefined { return arr[0]; }
```

### After（ジェネリクス）

```typescript
function first<T>(arr: T[]): T | undefined { return arr[0]; }
```

→ **コードの重複が消える**。

ただし「使うのは1パターンだけ」なら具体型の方がシンプル。**汎用性が必要になったらジェネリクス化**。

---

## 13. まとめ

- ジェネリクス = **型を引数として受け取る**仕組み
- `any` と違い、**入出力の型関連が保たれる**
- 関数: `function f<T>(x: T): T`、型: `type Box<T> = { value: T }`
- 推論されるので、呼び出し時の `<T>` は**省略OK**
- 命名: `T`, `U`, `K`, `V`, `R`, `E` の慣例
- 「**複数の型で動かしたくなった**」がジェネリクス化のサイン
- 落とし穴: 型引数を使わない / `any` で終わる / 過剰な型引数

> ジェネリクスは「**型で抽象化する**」第一歩。`<T>` という記号に慣れれば、`Array<string>` の中身を自分で設計できる側に立てます。これが越えられると、TypeScript は段違いに楽しくなります。
