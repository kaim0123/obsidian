# 条件型（Conditional Types）

## 条件型とは？

**条件型**は、型の世界で書く `if` 文のようなものです。

```typescript
T extends U ? X : Y
```

「`T` が `U` に代入できるなら `X`、そうでなければ `Y`」という意味です。

```typescript
type IsString<T> = T extends string ? "yes" : "no";

type A = IsString<"hello">; // "yes"
type B = IsString<42>;       // "no"
```

## 何のために使う？

「**入力の型によって、出力の型を変えたい**」という場面で使います。
標準ライブラリの `Exclude`、`ReturnType`、`NonNullable` などはすべて条件型でできています。

```typescript
type NonNullable<T> = T extends null | undefined ? never : T;

type X = NonNullable<string | null>; // string
```

## ユニオン型と「分配（distributive）」

条件型の特徴的な動きが **分配** です。
`T` がユニオン型のとき、各メンバーごとに条件が評価され、結果も union として組み合わさります。

```typescript
type ToArray<T> = T extends any ? T[] : never;

type R = ToArray<string | number>;
// 評価: ToArray<string> | ToArray<number>
//     = string[] | number[]
```

`T` を **「裸（naked）」**で書いたときだけ分配が起きます。

### 分配を止めたいとき

`[T]` のようにタプルで包むと、分配されなくなります。

```typescript
type ToArrayNoDist<T> = [T] extends [any] ? T[] : never;

type R = ToArrayNoDist<string | number>;
// (string | number)[]
```

「ユニオン全体を 1 つの値として扱いたい」ときに使います。

## never との関係

- ユニオンの中の `never` は **消滅** する：`A | never = A`
- `never extends T` は **常に分配で消える** ため、結果も `never` になる

```typescript
type X = ToArray<never>; // never
```

これを利用して「ユニオンから特定のメンバーを取り除く」ような型が書けます（→ `Exclude` の中身）。

## 入れ子の条件型

`if-else if-else` のような書き方もできます。

```typescript
type TypeName<T> =
  T extends string ? "string" :
  T extends number ? "number" :
  T extends boolean ? "boolean" :
  T extends Function ? "function" :
  "object";

type A = TypeName<"hi">;     // "string"
type B = TypeName<() => 1>;  // "function"
```

## infer と組み合わせる

条件型のパワーが本領発揮するのが、`infer` 句との組み合わせです（→ `infer.md`）。

```typescript
type ReturnType<T> =
  T extends (...args: any[]) => infer R ? R : never;
```

「マッチした位置の型を `R` として取り出す」と書けます。

## まとめ

- 条件型は型レベルの `if` 文
- ユニオン型に対しては自動で **分配** が起きる
- 分配を止めたいときは `[T] extends [U]` の形にする
- `infer` を使えば、型の一部を取り出して再利用できる
- 標準ライブラリの多くのユーティリティ型は条件型でできている
