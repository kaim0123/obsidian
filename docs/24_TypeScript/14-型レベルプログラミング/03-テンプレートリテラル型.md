# テンプレートリテラル型（Template Literal Types）

> 「**型レベルで文字列を組み立てる**」── これがテンプレートリテラル型の世界です。`Hello, ${string}` のような型を書け、文字列リテラル型から新しい文字列リテラル型を**計算**できます。Reduxの action type、CSS-in-JS、ルーティング ── 「文字列の規約を型で守りたい」場面で活躍します。

## 1. テンプレートリテラル型とは

JavaScript のテンプレートリテラル `` `Hello, ${name}` `` の**型版**。

```typescript
type Greeting = `Hello, ${string}`;

const a: Greeting = "Hello, Alice";   // ✅
const b: Greeting = "Hello, World";    // ✅
const c: Greeting = "Hi, Alice";       // ❌
```

→ 型レベルで「**文字列のパターン**」を表現。

---

## 2. リテラルユニオンとの組み合わせ

文字列の組み合わせを**自動展開**:

```typescript
type Direction = "top" | "bottom" | "left" | "right";
type Side = `border-${Direction}`;
// "border-top" | "border-bottom" | "border-left" | "border-right"
```

→ ユニオン × ユニオン = 直積で展開される。

```typescript
type Color = "red" | "blue";
type Shade = "light" | "dark";
type ColorShade = `${Shade}-${Color}`;
// "light-red" | "light-blue" | "dark-red" | "dark-blue"
```

→ 全パターンが**型レベルで自動生成**。

---

## 3. プリミティブ型との組み合わせ

```typescript
type T1 = `${number}px`;   // "0px", "1px", "100px", ... （任意の数字 + "px"）
type T2 = `${boolean}`;     // "true" | "false"
type T3 = `${string}@${string}.com`; // 任意のメールっぽい文字列
```

→ `string` / `number` / `boolean` を埋め込める。

---

## 4. 文字列を分解する `infer`（4.1+）

`infer` と組み合わせると、**文字列を型レベルで分解**できる:

```typescript
type Split<S extends string, D extends string> =
  S extends `${infer Head}${D}${infer Tail}`
    ? [Head, ...Split<Tail, D>]
    : [S];

type R = Split<"a,b,c", ",">; // ["a", "b", "c"]
```

→ 文字列を区切り文字で分割する型関数。

### キーから「最後のセグメント」を取る

```typescript
type LastSegment<S extends string> =
  S extends `${string}.${infer Rest}` ? LastSegment<Rest> : S;

type R = LastSegment<"a.b.c.d">; // "d"
```

## 5. Intrinsic ユーティリティ（組み込み変換）

文字列リテラル型の**変換**用組み込み型:

| 型 | 例 |
|---|---|
| `Uppercase<T>` | `"abc"` → `"ABC"` |
| `Lowercase<T>` | `"ABC"` → `"abc"` |
| `Capitalize<T>` | `"abc"` → `"Abc"` |
| `Uncapitalize<T>` | `"Abc"` → `"abc"` |

```typescript
type A = Uppercase<"hello">;     // "HELLO"
type B = Capitalize<"alice">;     // "Alice"
```

### 組み合わせ

```typescript
type Getter<K extends string> = `get${Capitalize<K>}`;

type A = Getter<"name">; // "getName"
type B = Getter<"age">;   // "getAge"
```

---

## 6. キーの変換（Mapped Type と組み合わせ）

```typescript
type Getters<T> = {
  [K in keyof T as `get${Capitalize<K & string>}`]: () => T[K];
};

type User = { name: string; age: number };
type G = Getters<User>;
// {
//   getName: () => string;
//   getAge: () => number;
// }
```

→ React の hooks や class methods の**自動生成**に活用。

## 7. 実例: イベント名

```typescript
type EventMap = {
  click: MouseEvent;
  hover: MouseEvent;
  submit: SubmitEvent;
};

type EventName = keyof EventMap;
// "click" | "hover" | "submit"

type EventListener = `on${Capitalize<EventName>}`;
// "onClick" | "onHover" | "onSubmit"

type Listeners = {
  [K in EventName as `on${Capitalize<K>}`]: (e: EventMap[K]) => void;
};
// {
//   onClick: (e: MouseEvent) => void;
//   onHover: (e: MouseEvent) => void;
//   onSubmit: (e: SubmitEvent) => void;
// }
```

## 8. 実例: ルート型

URL のパスパターンから**動的セグメント**を抽出:

```typescript
type ExtractParams<S extends string> =
  S extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ExtractParams<`/${Rest}`>
    : S extends `${string}:${infer Param}`
    ? Param
    : never;

type Params = ExtractParams<"/users/:id/posts/:postId">;
// "id" | "postId"
```

→ Next.js / Remix / Hono などのルーティングで応用。

---

## 9. 実例: CSS 単位

```typescript
type Unit = "px" | "em" | "rem" | "%";
type CSSValue = `${number}${Unit}`;

const a: CSSValue = "10px";    // ✅
const b: CSSValue = "1.5em";    // ✅
const c: CSSValue = "100%";     // ✅
const d: CSSValue = "10";       // ❌
```

## 10. 実例: Redux アクション型

```typescript
type Resource = "user" | "post";
type Action = "create" | "update" | "delete";
type ActionType = `${Resource}/${Action}`;
// "user/create" | "user/update" | "user/delete"
//   | "post/create" | "post/update" | "post/delete"
```

→ `slice/action` 形式の Redux Toolkit パターン。

## 11. 文字列の数値変換 (TS 4.7+)

`infer N extends number` で**数値型**を取り出せる:

```typescript
type ParseInt<S extends string> =
  S extends `${infer N extends number}` ? N : never;

type A = ParseInt<"42">;    // 42
type B = ParseInt<"3.14">;   // 3.14
type C = ParseInt<"hello">;  // never
```

---

## 12. 実例: バージョン番号の比較

```typescript
type ParseVersion<S extends string> =
  S extends `${infer Major extends number}.${infer Minor extends number}.${infer Patch extends number}`
    ? { major: Major; minor: Minor; patch: Patch }
    : never;

type V = ParseVersion<"1.2.3">;
// { major: 1; minor: 2; patch: 3 }
```

→ semver 風の文字列を**型レベルで分解**。

## 13. 落とし穴

### (1) ユニオン同士の直積は**爆発**する

```typescript
type Big = `${"a" | "b" | "c"}-${"x" | "y" | "z"}-${"1" | "2" | "3"}`;
// 27パターン

// もっと増やすと数千〜数万パターンになる
```

→ TypeScript の制約で **10000要素超のユニオン**が作れないこともある。

### (2) `${string}` は無限に近い

```typescript
type T = `prefix-${string}`;
// 任意の文字列が prefix- の後に続く。実質的に「制約のない文字列」
```

→ 型としては有効だが、**実用上の絞り込みが弱い**。

### (3) `infer` のパターンマッチが曖昧

```typescript
type T<S extends string> =
  S extends `${infer A}-${infer B}` ? [A, B] : never;

type R = T<"a-b-c">;
// ["a", "b-c"] （最初の `-` で分割）
```

→ **左から最短マッチ**するので、結果が予想と違うことも。

### (4) 大文字小文字変換は **ASCII** のみ

```typescript
type A = Uppercase<"はい">; // "はい" （変わらない）
```

`Uppercase` / `Lowercase` は ASCII 範囲のみ。日本語等は変換されない。

### (5) 再帰の深さ制限

```typescript
type Split<S extends string, D extends string> =
  S extends `${infer H}${D}${infer T}` ? [H, ...Split<T, D>] : [S];

type R = Split<"a,b,c,d,...,zzzzzzzz", ",">;
// 数百要素を超えると Type instantiation is excessively deep
```

→ TS の再帰深さ制限（〜45ぐらい）に注意。詳しくは [[04-再帰型]]。

## 15. ベストプラクティス

### (1) **アプリ用途では「規約の型化」に留める**

```typescript
type ActionType = `${Resource}/${Action}`;
type CSSValue = `${number}${Unit}`;
```

→ 文字列ルールを型で守る程度。深いパースは避ける。

### (2) **複雑なパースはランタイム + Zod**

```typescript
const VersionSchema = z.string().regex(/^\d+\.\d+\.\d+$/);
```

→ 型で全部やるより、**ランタイムバリデータ**の方が読みやすく安全。

### (3) **直積の爆発に注意**

ユニオン × ユニオン は要素数を意識。

### (4) **JSDocで意図を残す**

```typescript
/**
 * URL パターンから動的セグメントを抽出する。
 * @example
 * type T = ExtractParams<"/users/:id">; // "id"
 */
type ExtractParams<S extends string> = ...;
```

### (5) **ライブラリ用と割り切る**

業務コードで再帰的な文字列パース型を書きたくなったら、**設計を見直す**サイン。

---

## 16. まとめ

- **テンプレートリテラル型**: 文字列リテラル型を**組み立て・分解**できる
- ユニオン同士の組み合わせで**直積**が自動展開
- **`Uppercase` / `Lowercase` / `Capitalize` / `Uncapitalize`** が標準で用意
- **`infer` と組み合わせ**で文字列をパース可能
- **`infer N extends number`**（4.7+）で文字列から数値型を取り出し
- 落とし穴: 直積の爆発 / 再帰深さ制限 / ASCII限定
- 実用: アクション型 / CSS単位 / イベント名 / ルートパラメータ

> テンプレートリテラル型は「**文字列の規約を型で守る**」道具。深いパースまでやろうとすると沼ですが、**ルールの強制**程度に使うとTSの強さが一段増します。
