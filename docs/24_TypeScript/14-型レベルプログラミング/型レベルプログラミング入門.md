# 型レベルプログラミング入門

## 型レベルプログラミングとは？

通常のプログラミングは「**値を計算**」しますが、TypeScript の型は **型自身を計算** することができます。
これを **型レベルプログラミング**と呼びます。

たとえば「2 つのオブジェクト型をマージして新しい型を作る」「文字列パターンから情報を抽出する」など、**型から型を生む** ことができます。

```typescript
type Merge<A, B> = { [K in keyof A | keyof B]:
  K extends keyof B ? B[K] :
  K extends keyof A ? A[K] :
  never
};

type R = Merge<{ a: 1; b: 2 }, { b: 3; c: 4 }>;
// { a: 1; b: 3; c: 4 }
```

## なぜ型レベルでプログラムを書くのか？

- **重複を消せる**：実装の型を流用すれば、二重管理が要らない
- **API の使い方を強制できる**：誤った組み合わせをコンパイル時に弾ける
- **ドキュメントになる**：型定義がそのまま「使い方の説明」になる

過剰になると複雑すぎて誰も読めない型ができあがるので、**目的を絞ることが大事** です。

## ミニ例 1：配列の長さを型で持つ

```typescript
type Length<T extends readonly any[]> = T["length"];

type L1 = Length<[1, 2, 3]>;        // 3
type L2 = Length<readonly []>;     // 0
```

タプル型の `length` プロパティはリテラル数値として取れます。

## ミニ例 2：ユニオンをタプルに（要注意）

ユニオン型をタプル化することも可能ですが、順序保証がなく **本格運用には向きません**。
こうした型は「面白いけど避ける」ぐらいの距離感がちょうどいいです。

## ミニ例 3：ドット区切り文字列のキー型

```typescript
type Path<T, Prefix extends string = ""> = {
  [K in keyof T & string]:
    T[K] extends object
      ? `${Prefix}${K}` | Path<T[K], `${Prefix}${K}.`>
      : `${Prefix}${K}`;
}[keyof T & string];

type P = Path<{ a: { b: { c: string }; d: number } }>;
// "a" | "a.b" | "a.b.c" | "a.d"
```

i18n キーや lodash の `get` のような API で活躍します。

## 設計のコツ

- **入力と出力をテストする**：`expectType` 系のヘルパで、結果型をスナップショットしておく
- **エイリアスで段階的に組み立てる**：1 行に詰め込まず、中間型を切って読みやすく
- **再帰の深さに注意**：深い再帰は TS の制限に引っかかる
- **明示的な `never` フォールバック**：マッチしないときに何が返るかを残す

## やりすぎ注意：そもそも書くべきか？

型レベルで全部解決しようとすると、**コンパイルが遅くなり、エラーメッセージが読めなくなる**ことが多々あります。
迷ったら、

1. **ライブラリ（Zod など）に任せられないか**
2. **シンプルな型 + 単純な関数で代替できないか**
3. **本当にこの抽象が複数箇所で必要か**

をまず考えてください。

## まとめ

- 型レベルプログラミング＝**型を計算して新しい型を生む**
- 武器は「条件型 / `infer` / マップ型 / テンプレートリテラル / `keyof`」
- 強力だが複雑になりやすいので、**目的を絞って慎重に**
- 標準ユーティリティ型を読み解くだけでも、設計の引き出しが大きく広がる
