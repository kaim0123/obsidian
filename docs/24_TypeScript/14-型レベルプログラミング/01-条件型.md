# 条件型（Conditional Types）

> 「**型の if 文**」と呼ばれる条件型は、型レベルで分岐するための仕組み。`Exclude` `NonNullable` `ReturnType` ── 標準ユーティリティ型の多くがこれで書かれています。読めるようになると、ライブラリの型定義を理解でき、自作の型変換も書けるようになります。

## 1. 条件型とは

「**型の if 文**」のような構文。

```typescript
T extends U ? X : Y
```

「`T` が `U` に**代入可能**なら `X`、そうでなければ `Y`」。

### 最小の例

```typescript
type IsString<T> = T extends string ? true : false;

type A = IsString<"hello">;  // true
type B = IsString<42>;        // false
```

### 構文のポイント

- **値の `if` ではなく、型の if**
- `extends` は「**サブタイプ関係**」（代入可能性）
- 結果は**型**

---

## 2. ジェネリクスと組み合わせる

ジェネリクスを使って「**型を入れたら型が返る**」関数のように書ける:

```typescript
type ToArray<T> = T extends string ? T[] : never;

type A = ToArray<"hello">;  // "hello"[]
type B = ToArray<42>;        // never
```

→ **型関数**として動作する。

---

## 3. 標準ユーティリティ型はほぼ条件型

### `Exclude<T, U>`

```typescript
type Exclude<T, U> = T extends U ? never : T;
```

→ T が U に代入できるなら `never`、そうでなければ T。

### `Extract<T, U>`

```typescript
type Extract<T, U> = T extends U ? T : never;
```

### `NonNullable<T>`

```typescript
type NonNullable<T> = T extends null | undefined ? never : T;
```

### `ReturnType<T>`

```typescript
type ReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : any;
```

→ `infer` を使った条件型（次章 [[02-inferの基本]]）。

---

## 4. 「分配法則」が働く（最重要）

ジェネリクスの**裸の型変数**にユニオン型を渡すと、**各メンバーに分配**されます。

```typescript
type ToArray<T> = T extends any ? T[] : never;

type A = ToArray<string | number>;
// → ToArray<string> | ToArray<number>
// = string[] | number[]
```

→ 詳しくは [[04-分配法則の入口]]。

### 分配を止める: `[T] extends [U]`

```typescript
type ToArrayStrict<T> = [T] extends [any] ? T[] : never;

type A = ToArrayStrict<string | number>;
// (string | number)[]
```

ユニオンを**ひとまとめ**で扱いたいときは `[T]` で包む。

---

## 5. ネストした条件型

`if-else if-else` のチェーンができる:

```typescript
type Categorize<T> =
  T extends string ? "string" :
  T extends number ? "number" :
  T extends boolean ? "boolean" :
  "other";

type A = Categorize<"hello">; // "string"
type B = Categorize<42>;       // "number"
type C = Categorize<{}>;       // "other"
```

→ 縦に並べると読みやすい。

---

## 6. オブジェクト型の条件型

```typescript
type HasName<T> = T extends { name: string } ? true : false;

type A = HasName<{ name: "Alice"; age: 30 }>; // true
type B = HasName<{ age: 30 }>;                 // false
```

→ オブジェクトの**形**でも分岐できる。

---

## 7. `infer` で型を取り出す（次章で詳述）

```typescript
type ElementType<T> = T extends (infer U)[] ? U : never;

type A = ElementType<string[]>;   // string
type B = ElementType<number[]>;   // number
type C = ElementType<string>;      // never
```

→ **配列の要素型**を抽出する例。詳しくは [[02-inferの基本]]。

---

## 8. `extends` の挙動を理解する

`A extends B` は「**A が B のサブタイプ**」を意味します。

### プリミティブ型

```typescript
type T1 = "hello" extends string ? true : false; // true
type T2 = string extends "hello" ? true : false; // false
type T3 = 42 extends number ? true : false;       // true
```

### オブジェクト型

```typescript
type T1 = { a: 1; b: 2 } extends { a: 1 } ? true : false; // true
type T2 = { a: 1 } extends { a: 1; b: 2 } ? true : false; // false
```

→ **プロパティが多い方が「狭い」型**（より具体的）。

### 関数型

```typescript
type T1 = ((x: number) => void) extends ((x: number | string) => void) ? true : false;
// true （広く受ける関数は、狭く受ける関数のサブタイプ）
```

→ 関数引数の**反変性**。詳しくは [[共変と反変]]。

### `any` / `unknown`

```typescript
type T1 = any extends string ? true : false;     // boolean (true | false)
type T2 = unknown extends string ? true : false;  // false
type T3 = string extends unknown ? true : false;  // true
```

→ `any` は特殊（`any` は何にでも `extends` する）。

### `never`

```typescript
type T1 = never extends string ? true : false; // never （!）
```

→ `never` を直接渡すと条件型は `never` を返す（分配対象が0個のため）。

---

## 9. 実例: 関数の引数型を取り出す

```typescript
type Parameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;

type A = Parameters<(a: string, b: number) => void>;
// [a: string, b: number]
```

### 関数の戻り値型

```typescript
type ReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : any;

type A = ReturnType<() => string>; // string
```

### Promise の中身

```typescript
type Awaited<T> = T extends Promise<infer U> ? U : T;

type A = Awaited<Promise<string>>;  // string
type B = Awaited<string>;           // string （Promise でなければそのまま）
```

→ 標準の `Awaited` はもっと再帰的だが、概念はこれ。

---

## 10. 実例: 配列・オブジェクトから型を取り出す

```typescript
type ArrayElement<T> = T extends (infer E)[] ? E : never;

type A = ArrayElement<number[]>;        // number
type B = ArrayElement<readonly string[]>; // string
type C = ArrayElement<[1, 2, 3]>;         // 1 | 2 | 3
```

```typescript
type ValueOf<T> = T[keyof T];

type A = ValueOf<{ a: number; b: string }>; // number | string
```

---

## 11. 実例: 「キーから対応する値の型」を引く

```typescript
type ApiMap = {
  "/users": User[];
  "/users/:id": User;
  "/posts": Post[];
};

type ResponseOf<P extends keyof ApiMap> = ApiMap[P];

type A = ResponseOf<"/users">; // User[]
type B = ResponseOf<"/posts">;  // Post[]
```

これは条件型を直接使っていないが、**インデックスアクセス型**（[[03-keyofとインデックスアクセス型]]）と組み合わせる典型パターン。

---

## 12. 条件型の実用テクニック

### ユニオンから特定型のメンバーだけ取り出す

```typescript
type FilterByKind<T, K extends string> = T extends { kind: K } ? T : never;

type Action =
  | { kind: "ADD"; value: number }
  | { kind: "REMOVE"; id: string };

type A = FilterByKind<Action, "ADD">;
// { kind: "ADD"; value: number }
```

→ `Extract` の応用。

### 関数が同期か非同期か判定

```typescript
type IsAsync<T> = T extends (...args: any) => Promise<any> ? true : false;

type A = IsAsync<() => Promise<string>>; // true
type B = IsAsync<() => string>;           // false
```

### 必須プロパティのみ抽出

```typescript
type RequiredKeys<T> = {
  [K in keyof T]-?: {} extends Pick<T, K> ? never : K;
}[keyof T];

type T = { a: string; b?: number; c: boolean };
type R = RequiredKeys<T>; // "a" | "c"
```

→ Mapped Type と条件型の組み合わせ。

## 13. 条件型の落とし穴

### (1) `boolean extends ...` で分配が起きる

```typescript
type T = boolean extends true ? "yes" : "no";
// boolean = true | false なので分配される
// → ("yes" or "no") | ("yes" or "no") = "yes" | "no"
```

→ 直感に反する結果になることがある。

### (2) `never` を渡すと結果が `never`

```typescript
type T<X> = X extends any ? X[] : never;
type R = T<never>; // never
```

→ 分配対象が0個 → 結果も `never`。

### (3) 「裸の型変数」かどうかで挙動が変わる

```typescript
type A<T> = T extends any ? T[] : never;        // 分配される
type B<T> = [T] extends [any] ? T[] : never;     // 分配されない
```

→ 意図的に使い分け。

### (4) `extends` の方向

```typescript
type A<T> = T extends string ? "yes" : "no";

type R1 = A<"hello">;    // "yes"
type R2 = A<string>;      // "yes"
type R3 = A<"a" | 1>;     // "yes" | "no" （分配）
```

→ 「サブタイプ関係」を理解していないとハマる。

### (5) 複雑になりすぎる

```typescript
type X<T> = T extends infer U
  ? U extends string
    ? `${U}!`
    : U extends number
    ? U[]
    : never
  : never;
```

→ 読めなくなったら**中間型に分解**。詳しくは [[05-読める型のための命名と分割]]。

---

## 14. 条件型の使い所

### 使うべき

- ユニオン型から特定メンバーを取り出す
- 関数型から戻り値・引数を取り出す（`infer`）
- 入力の型に応じて出力の型を変える
- 標準ユーティリティ型の自作版

### 使わない方がよい

- 「サブタイプ判定」で代用できるとき（`if` 文の代わりに型で書く必要なし）
- アプリケーションコードの分岐（**ランタイムで分岐**すべき）
- ライブラリの型定義に閉じる方がよい場合

---

## 15. 「分かりやすさ」とのトレードオフ

条件型は**強力だが読みにくい**。乱用すると保守不能に。

### 推奨

- **ユーティリティ型レベル**で使う
- 標準型で済むなら標準型
- 自作するなら**JSDocコメント + 実例**を添える

```typescript
/**
 * 配列型から要素型を取り出す
 * @example
 * type T = ArrayElement<number[]>; // number
 */
type ArrayElement<T> = T extends (infer E)[] ? E : never;
```

---

## 16. まとめ

- 条件型 = **`T extends U ? X : Y`**（型のif）
- **裸の型変数 + ユニオン**で**分配法則**が働く
- **`[T] extends [U]`** で分配を止められる
- **`infer`** で型を取り出せる（次章へ）
- 標準型 (`Exclude` / `Extract` / `ReturnType` 等) はすべて条件型ベース
- 「**読めない型は書かない**」が現代のマナー、自作時はコメント必須

> 条件型は「**型を計算する**」世界の入口。`if-then-else` の発想で型変換を組み立てれば、ライブラリの型定義が読めるようになり、自作型の表現力も飛躍します。
