# オブジェクト型（プロパティ・オプション・インデックスシグネチャ）

> オブジェクト型はTypeScriptで**最も使う型**です。プロパティの宣言、オプション `?`、`readonly`、インデックスシグネチャ ── ここを正確に書けるかどうかで、コードの安全性が大きく変わります。

## 1. オブジェクト型の基本

### インライン記法

```typescript
const user: { name: string; age: number } = {
  name: "Alice",
  age: 30,
};
```

`{ プロパティ: 型; ... }` の形でその場で書ける。

### 型エイリアスで切り出す

```typescript
type User = {
  name: string;
  age: number;
};

const u: User = { name: "Alice", age: 30 };
```

複数箇所で使うなら **`type` か `interface`** で切り出す。

### `interface` での書き方

```typescript
interface User {
  name: string;
  age: number;
}
```

`type` と `interface` は使い分けの議論があるが、初期はどちらでもOK（[[interface vs type]] 参照）。**チームで統一**するのが大事。

---

## 2. プロパティの区切り文字

オブジェクト型は **`;` でも `,` でも改行でもOK**。

```typescript
type A = { name: string; age: number };  // セミコロン
type B = { name: string, age: number };  // カンマ
type C = {                                 // 改行
  name: string
  age: number
};
```

統一しておくこと。Prettier等のフォーマッタに任せれば自動で揃う。

---

## 3. オプションプロパティ（`?`）

「**あってもなくてもよい**」プロパティ。

```typescript
type User = {
  name: string;
  email?: string; // ← オプション
};

const u1: User = { name: "Alice" };                    // ✅
const u2: User = { name: "Bob", email: "b@e.com" };    // ✅
const u3: User = { name: "C", email: undefined };      // ✅（後述の例外あり）
```

### `?` がついた値の型は `T | undefined`

```typescript
type User = { name?: string };

function greet(u: User) {
  u.name.toUpperCase(); // ❌ u.name は string | undefined
  if (u.name) {
    u.name.toUpperCase(); // ✅
  }
}
```

オプションを参照したら、必ず `undefined` チェック。

### `?` と `| undefined` の違い（重要）

```typescript
type A = { name?: string };           // プロパティ自体を省略可能
type B = { name: string | undefined }; // プロパティ必須、値は undefined OK

const a: A = {};                  // ✅
const b: B = {};                  // ❌ name がない
const b2: B = { name: undefined }; // ✅
```

意味が違うので注意:

- **`?`**: オブジェクトのキーに `name` がなくてもよい
- **`| undefined`**: キーは必須だが、値が `undefined` でもよい

`exactOptionalPropertyTypes: true` を有効にすると、`A` に `{ name: undefined }` を渡せなくなる（厳密化）。詳しくは [[exactOptionalPropertyTypes]]。

## 4. `readonly` プロパティ

「**書き換え不可**」のプロパティ。

```typescript
type Point = {
  readonly x: number;
  readonly y: number;
};

const p: Point = { x: 10, y: 20 };
p.x = 100; // ❌ Cannot assign to 'x' because it is a read-only property.
```

### 使い所

- 不変オブジェクト（イミュータブルデータ）の表現
- DTO（Data Transfer Object）として呼び出し側に書き換えさせない
- React の props（書き換え不可が前提）

### `Readonly<T>` で全プロパティを readonly にする

```typescript
type User = { name: string; age: number };
type FrozenUser = Readonly<User>;
// { readonly name: string; readonly age: number }
```

ユーティリティ型 `Readonly<T>` で一括適用できる。

### `readonly` はシャロー

```typescript
type Group = {
  readonly members: string[];
};

const g: Group = { members: ["a", "b"] };
g.members = [];        // ❌
g.members.push("c");   // ✅ 中身は変更できる！
```

完全な不変にしたいなら `readonly string[]` のように内側にも書く。

## 5. ネストしたオブジェクト型

```typescript
type User = {
  name: string;
  address: {
    city: string;
    zip: string;
  };
};

const u: User = {
  name: "Alice",
  address: { city: "Tokyo", zip: "100-0001" },
};
```

ネストが深くなったら**型を切り出す**。

```typescript
type Address = { city: string; zip: string };
type User = { name: string; address: Address };
```

## 6. インデックスシグネチャ（Index Signature）

「**任意のキー名**」を許容する書き方。

```typescript
type StringMap = {
  [key: string]: string;
};

const m: StringMap = {
  apple: "りんご",
  orange: "オレンジ",
  any_key: "any_value",
};
```

### 構文

```typescript
{ [key: KeyType]: ValueType }
```

- `KeyType`: `string` / `number` / `symbol` のいずれか
- `ValueType`: 値の型

### よくある使い方

```typescript
// 翻訳辞書
type Dict = { [lang: string]: string };

// IDをキーにしたオブジェクト
type UsersById = { [id: string]: User };

// 設定オブジェクト
type Config = { [option: string]: string | number | boolean };
```

### 通常プロパティとの併用

```typescript
type Mixed = {
  id: string;          // 必須プロパティ
  [key: string]: any;  // それ以外は何でも
};
```

ただし併用時は「**通常プロパティの型がインデックスシグネチャの値型に代入可能**」である必要がある。

```typescript
type Bad = {
  id: string;
  [key: string]: number; // ❌ id (string) が number に代入できない
};
```

## 7. インデックスシグネチャの罠

### (1) 存在しないキーも `T` で返ってくる

```typescript
type Dict = { [key: string]: string };
const d: Dict = { a: "A" };

const v = d.unknown; // 型は string（実際は undefined）
v.toUpperCase();     // 実行時エラー
```

→ `noUncheckedIndexedAccess: true` を有効にすると、戻り値が `string | undefined` になり、安全になります。

```typescript
// noUncheckedIndexedAccess: true 有効時
const v = d.unknown; // string | undefined
v.toUpperCase();     // ❌ undefinedの可能性
```

**インデックスシグネチャを使うなら、このオプションは事実上必須**。

### (2) 型補完が効かない

```typescript
type Status = { [key: string]: string };
const s: Status = { ok: "OK" };
s. // 補完候補: なし（任意のキーなので）
```

**選択肢が決まっているならリテラルユニオン**を使う方が良い:

```typescript
type Status = { [K in "loading" | "success" | "error"]: string };
// または
type Status = Record<"loading" | "success" | "error", string>;
```

→ 補完が効く。詳しくは [[04-Recordの基本]]。

### (3) `Record<K, V>` の方が読みやすい

`{ [key: string]: V }` は `Record<string, V>` と等価。**新規コードでは `Record` を推奨**。

```typescript
type Dict1 = { [key: string]: number }; // 古い書き方
type Dict2 = Record<string, number>;     // 推奨
```

## 8. 余分なプロパティチェック（excess property check）

オブジェクトリテラルを直接渡すとき、TypeScriptは「**型に書かれていないプロパティ**」を警告します。

```typescript
type User = { name: string };

function greet(u: User) { ... }

greet({ name: "Alice", age: 30 });
// ❌ Object literal may only specify known properties, and 'age' does not exist in type 'User'.
```

これは「**タイポを防ぐためのお節介**」。`age: 30` は型エラーではないが、たぶん意図と違うはず、という警告。

### 回避策

```typescript
const u = { name: "Alice", age: 30 };
greet(u); // ✅ 変数経由なら通る（リテラルではないため）
```

**変数経由の代入では発生しない**ので、変数に入れれば通る。ただし「タイポを防ぎたい」のが本来の目的なので、無理に回避しない。

## 9. `object` / `Object` / `{}` の違い

紛らわしい3つを整理。

| 型 | 意味 |
|---|---|
| `object` | プリミティブ以外（オブジェクト・配列・関数）。プロパティアクセスは制限される |
| `Object` | グローバルの `Object` 型。ほぼ何でも代入可（推奨されない） |
| `{}` | 「プロパティのないオブジェクト」と読みがちだが、実は `null/undefined 以外`なんでも |

```typescript
const a: object = { x: 1 };  // ✅
const b: object = "hello";   // ❌
const c: {} = "hello";       // ✅（紛らわしい）
const d: {} = null;          // ❌
```

**`{}` は使わない**のが安全。「オブジェクトを受けたい」なら `object` か、`Record<string, unknown>` を使う。

## 10. オブジェクト型の合成

### ユニオン型

```typescript
type A = { kind: "a"; x: number };
type B = { kind: "b"; y: string };
type AorB = A | B;

function f(v: AorB) {
  if (v.kind === "a") {
    v.x; // ✅
  } else {
    v.y; // ✅
  }
}
```

判別可能ユニオンの基本（[[06-narrowing]] で詳しく）。

### 交差型（intersection）

```typescript
type Named = { name: string };
type Aged = { age: number };
type Person = Named & Aged;
// { name: string; age: number }

const p: Person = { name: "Alice", age: 30 };
```

両方のプロパティを**全部持つ**型を作る。

### 拡張（interface のみ）

```typescript
interface Animal { name: string }
interface Dog extends Animal {
  breed: string;
}
```

`extends` は `interface` のみ。`type` では交差型 `&` で代用。

---

## 11. プロパティ順序は型に影響しない

```typescript
type User = { name: string; age: number };

const a: User = { name: "Alice", age: 30 }; // ✅
const b: User = { age: 30, name: "Alice" };  // ✅
```

JavaScriptオブジェクトのプロパティ順序は基本的に保たれますが、**型システム上は順序を気にしない**。

---

## 12. まとめ

- オブジェクト型は `{ key: 型; ... }` で書く
- **`?` (オプション)** と **`| undefined`** は意味が違う（`exactOptionalPropertyTypes` で厳密化）
- **`readonly`** で書き換え不可。シャロー（ネストには効かない）
- **インデックスシグネチャ** `{ [key: string]: T }` は便利だが、`noUncheckedIndexedAccess` で安全に
- **`Record<K, V>`** は新規コードで推奨
- 余分なプロパティチェックはタイポ防止。回避するときは意図的に
- **`object` / `Object` / `{}`** は意味が違う。`{}` は使わない

> オブジェクト型は「**何が必須で何が任意か**」「**書き換えていいか**」を型で明示できる場所。ここを丁寧に書くと、コードの意図が読み手に伝わり、バグも減ります。
