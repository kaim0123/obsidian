# プリミティブ型（string / number / boolean / bigint / symbol / null / undefined）

> プリミティブ型はTypeScriptの**最小単位**。一見当たり前ですが、`number` の罠、`null` と `undefined` の使い分け、`bigint` / `symbol` の存在意義など、初心者がつまづくポイントが意外と多い領域です。

## 1. プリミティブ型の全体像

JavaScriptには7種類のプリミティブ値があり、TypeScriptはそれぞれに対応する型を持ちます。

| 型 | 例 | 用途 |
|---|---|---|
| `string` | `"hello"` `'a'` `` `t${x}` `` | 文字列 |
| `number` | `42` `3.14` `Infinity` `NaN` | 整数・浮動小数（共通） |
| `boolean` | `true` `false` | 真偽値 |
| `bigint` | `42n` `BigInt(10)` | 任意精度整数 |
| `symbol` | `Symbol("id")` | ユニークな識別子 |
| `null` | `null` | 「意図的になし」 |
| `undefined` | `undefined` | 「未定義/未初期化」 |

`object` はプリミティブではない（参照型）。配列も関数もオブジェクトに分類されます。

---

## 2. `string`

### 基本

```typescript
let a: string = "hello";
let b: string = 'world';
let c: string = `template ${a}`;
```

ダブル/シングル/テンプレートリテラルすべて `string` 型。

### よく使うメソッド

```typescript
"hello".length;            // 5
"hello".toUpperCase();     // "HELLO"
"hello".includes("ll");    // true
"a,b,c".split(",");        // ["a", "b", "c"]
"  trim  ".trim();         // "trim"
```

### リテラル型としての文字列

```typescript
let s: "loading" = "loading"; // "loading" 以外NG
```

`string` の代わりに**特定の値**を型として使えます（[[05-リテラル型とas-const]]）。

### `String` ではなく `string`

```typescript
let a: string = "ok";   // ✅ 小文字
let b: String = "ng";   // ❌ 大文字はラッパーオブジェクト型（使わない）
```

JavaScriptには `String`（オブジェクト）と `string`（プリミティブ）があり、TypeScriptでは**常に小文字 `string` を使う**。`String` を使う理由はほぼありません。

---

## 3. `number`

### 整数も小数も同じ型

```typescript
let i: number = 42;
let f: number = 3.14;
let neg: number = -10;
let inf: number = Infinity;
let nan: number = NaN;
```

JavaScriptには整数型と小数型の区別がありません（IEEE 754の倍精度浮動小数点1種類）。すべて `number`。

### 安全な整数の上限

```typescript
Number.MAX_SAFE_INTEGER; // 2^53 - 1 = 9007199254740991
```

これを超える整数は**精度が失われます**。

```typescript
9007199254740992 === 9007199254740993; // true（！？）
```

巨大な整数（IDなど）は `string` か `bigint` で扱う。

### NaN の罠

```typescript
NaN === NaN; // false（！）
isNaN(NaN);    // true
Number.isNaN(NaN); // true（こちらが推奨：型安全）
```

`NaN` は自分自身と等しくないため、`===` で判定できません。`Number.isNaN()` を使う。

### 数値リテラル

```typescript
const dec = 100;        // 10進
const hex = 0xff;       // 16進 = 255
const oct = 0o755;      // 8進 = 493
const bin = 0b1010;     // 2進 = 10
const exp = 1.5e3;      // 1500
const sep = 1_000_000;  // 区切り（1000000、ES2021）
```

`1_000_000` のアンダースコア区切りは可読性向上に便利。

## 4. `boolean`

```typescript
let b: boolean = true;
let c: boolean = false;
```

文字通り `true` / `false` のみ。

### 「truthy / falsy」と型の関係

JavaScriptでは `boolean` 以外も条件式で評価されます。これに釣られて型がズレることがあります。

```typescript
function check(s: string | undefined) {
  if (s) {
    s.toUpperCase(); // ✅ ここでは string（undefined は除外）
  }
}
```

ただし `0` や `""` は falsy なので注意:

```typescript
function check(n: number | undefined) {
  if (n) {
    // n === 0 のときも除外されてしまう
  }
  if (n !== undefined) {
    // ✅ こちらが安全
  }
}
```

→ **`null` / `undefined` のチェックは `=== null` / `!== undefined` で明示的に**書く方が安全。

---

## 5. `bigint`

ES2020で追加された任意精度整数。`Number.MAX_SAFE_INTEGER` を超える整数を扱える。

```typescript
const big: bigint = 9007199254740993n; // 末尾に n
const big2: bigint = BigInt("9007199254740993");

big + 1n;     // ✅
big + 1;      // ❌ Cannot mix BigInt and other types
```

### 注意点

- `number` と**直接演算できない**
- `JSON.stringify` でエラーになる（カスタム処理が必要）
- `tsconfig.json` の `target` が ES2020 以上である必要あり

実務では「**巨大な整数を扱う必要があるときだけ**」使う。普段は `number` で十分。

## 6. `symbol`

ユニークな識別子を作る型。`Symbol()` で生成された値はすべて**重複しない**。

```typescript
const a = Symbol("desc");
const b = Symbol("desc");
a === b; // false（説明文字列が同じでも別物）
```

### 使い所: オブジェクトの「衝突しないキー」

```typescript
const SECRET = Symbol("secret");

const obj = {
  name: "Alice",
  [SECRET]: "internal-data",
};

obj[SECRET]; // "internal-data"
```

外部のコードが `obj["secret"]` で偶然アクセスすることを防げます。

### `unique symbol`

```typescript
const KEY: unique symbol = Symbol("key");
type T = { [KEY]: string };
```

`unique symbol` は「**この特定のsymbol**」を型として表現できる稀な機能。Reactなどのフレームワーク内部で使われることが多い。

実務で `symbol` を自分で書く機会は少ない。**読めれば十分**。

## 7. `null` と `undefined`

### 違い

| 観点 | `null` | `undefined` |
|---|---|---|
| 意味 | 意図的に「なし」を表す | 値が未定義/未初期化 |
| 出現する場所 | プログラマが明示的に代入 | 未代入の変数 / 戻り値なしの関数 / 存在しないプロパティ |
| `typeof` | `"object"`（仕様の歴史的バグ） | `"undefined"` |

### TypeScriptでは厳密に区別される

`tsconfig.json` で `"strictNullChecks": true`（または `"strict": true`）が有効だと、`null` と `undefined` は他の型と**別物**として扱われます。

```typescript
let s: string = "hello";
s = null;      // ❌
s = undefined; // ❌

let s2: string | null = "hello";
s2 = null;     // ✅
s2 = undefined; // ❌（| undefined を別途追加する必要あり）
```

### どちらを使うか

プロジェクトの方針次第ですが、よくある選択:

- **`undefined` 派**（多数派）: JavaScriptが自然に返す値（未定義引数・存在しないプロパティ）と一致するため一貫性がある
- **`null` 派**: 「意図的になし」を明示できる。DB のNULL値と一致しやすい

**チームで統一する**のが大事。混在するとバグの温床。

### `?` と `| undefined` の違い

```typescript
type A = { name?: string };          // name?: string | undefined （プロパティ自体が省略可能）
type B = { name: string | undefined }; // name は必須（値は undefined でもよい）

const a: A = {};                    // ✅
const b: B = {};                    // ❌ name がない
const b2: B = { name: undefined };  // ✅
```

`?` は**プロパティ省略を許す**、`| undefined` は**値が undefined を取りうる**。意味が違うので使い分け。詳細は `exactOptionalPropertyTypes` の章も参照。

## 8. プリミティブ型のユニオン

複数のプリミティブを許容するなら、ユニオン型で書く。

```typescript
function format(value: string | number | boolean): string {
  if (typeof value === "string") return value;
  if (typeof value === "number") return value.toFixed(2);
  return value ? "yes" : "no";
}
```

`typeof` で絞り込めば、それぞれの型のメソッドが安全に使えます。

## 9. プリミティブ型に共通する注意点

### (1) ラッパーオブジェクト型は使わない

`String` / `Number` / `Boolean` / `BigInt` / `Symbol`（先頭大文字）は **ラッパーオブジェクト型**で、使うとバグります。

```typescript
let s: String = "hello"; // ❌
s === "hello";            // false の可能性あり
```

**常に小文字（`string` `number` ...）を使う**。

### (2) `typeof null === "object"`

```typescript
typeof null;       // "object"（バグ）
typeof undefined;  // "undefined"
```

`null` の判定は `=== null` を使う。`typeof v === "object"` だけでは `null` も含まれてしまう。

```typescript
if (typeof v === "object" && v !== null) {
  // ✅ ここで v は object（null除く）
}
```

### (3) 数値の精度問題

```typescript
0.1 + 0.2 === 0.3; // false（0.30000000000000004）
```

金額計算は `number` ではなく `string` または `bigint`、または専用ライブラリ（decimal.js等）を使う。

## 10. プリミティブ型 早見表

| 型 | リテラル | 注意点 |
|---|---|---|
| `string` | `"a"` `'a'` `` `a` `` | `String` は使わない |
| `number` | `42` `3.14` | NaN・浮動小数誤差 |
| `boolean` | `true` `false` | `0` `""` も falsy なので明示比較を |
| `bigint` | `42n` | `number` と混ぜられない |
| `symbol` | `Symbol("d")` | 衝突しないキー用途 |
| `null` | `null` | `typeof` は `"object"` |
| `undefined` | `undefined` | `?` と `\| undefined` の違いに注意 |

---

## 11. まとめ

- プリミティブ型は7種。常に**小文字**で書く（`string`、not `String`）
- `number` は整数も浮動小数も共通。**NaN・精度・MAX_SAFE_INTEGER** に注意
- `null` と `undefined` は別物。`strictNullChecks` を有効にして厳密に扱う
- `?` と `| undefined` は意味が違う
- `bigint` / `symbol` は使う場面を理解できれば十分（自分で書く機会は少ない）

> プリミティブ型は「分かったつもり」になりやすい領域。**`null`/`undefined` の使い分け、NaN、浮動小数誤差**の3つだけは、必ず手を動かして確認しておきましょう。
