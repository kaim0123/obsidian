# 型と値の混同

TypeScript には **「型の世界」と「値の世界」** という 2 つの世界があります。
これらは **完全に別の名前空間** に存在し、意外と混乱しやすいポイントです。

## 型と値は別の世界

```typescript
// 型の宣言（コンパイル時にしか存在しない）
type User = { name: string };

// 値の宣言（実行時にも存在する）
const user = { name: "Alice" };
```

- **型**：JS にコンパイルされた瞬間に **消える**
- **値**：コンパイル後の JS にも **残る**

```typescript
console.log(typeof User); // ❌ User はランタイムに存在しない（実は値の typeof）
```

## 同じ名前を別の意味で使える

型と値は別空間なので、**同じ名前** を別の意味で使えます。

```typescript
class Person {
  constructor(public name: string) {}
}

// Person は値（コンストラクタ関数）でもあり、型（インスタンス型）でもある
const p: Person = new Person("Alice");
```

クラスと `enum` は **値と型を兼ねる** 例外的な存在です。

## typeof：値から型を取り出す

「型の世界」で **`typeof 値`** と書くと、その値の型を取り出せます。
JS の `typeof` 演算子（`typeof x === "string"`）とは別物です。

```typescript
const config = { url: "/api", timeout: 5000 };

type Config = typeof config;
// { url: string; timeout: number }
```

「**実装から型を起こす**」便利な方法です。

## keyof：型からキーを取り出す（型）

```typescript
type User = { id: number; name: string };
type K = keyof User; // "id" | "name"
```

`keyof` は **型** に対する操作で、結果も **型** です。

## Object.keys との混同

```typescript
const user: User = { id: 1, name: "Alice" };
const keys = Object.keys(user); // string[]（"id" | "name" ではない）
```

`Object.keys` は実行時の関数なので、戻り値は **`string[]`** です。
「`("id" | "name")[]` になってほしい」と思っても、TypeScript は **`Object.keys` の戻りを `keyof` の結果に絞ってくれません**（オブジェクトに余分なプロパティがある可能性があるから）。

絞りたいなら型アサーションかヘルパー関数を使います。

```typescript
const keys = Object.keys(user) as (keyof User)[];
```

## interface・type は実行時に存在しない

```typescript
interface Foo { x: number }

if (something instanceof Foo) {} // エラー：Foo は値ではない
```

`interface` / `type` は **コンパイル時の存在**。`instanceof` で使うことはできません。
`instanceof` で判定したいなら **クラス** を使います。

## import type と import の違い

```typescript
import type { User } from "./user"; // 型だけ取り込む（出力に残らない）
import { User } from "./user";       // 値も取り込む（class/関数なら残る）
```

`import type` は **JS 出力に何も残さない** ため、循環依存の解消やバンドルサイズ削減に役立ちます。

## ハマりやすい場面

### 1. 型を「変数のように」使う

```typescript
type Status = "ok" | "ng";
console.log(Status); // エラー：型は値ではない
```

ユニオン型は **どこにも値が存在しない**ので、ランタイムで参照できません。

### 2. enum は両方になる

```typescript
enum Color { Red, Blue }

const c: Color = Color.Red; // 値として使う
type T = Color;              // 型として使う
```

「両方使えて便利」と感じる反面、ランタイムにオブジェクトが残るデメリットもあります（→ `enum_vs_const_assertions.md`）。

## まとめ

- TypeScript には **型の世界**と**値の世界**があり、別々の名前空間を持つ
- `class` / `enum` は両方の世界に同名で存在する例外
- **`typeof 値`** で値から型を取り出せる
- **`keyof 型`** はあくまで型の世界の操作
- `interface` / `type` はランタイムに存在しないので `instanceof` には使えない
- `import type` は出力に残らないのでバンドルサイズや循環依存対策に便利
