# 再発防止アクションの管理

ポストモーテムで最もよくある失敗は、**アクションを書いたのに実行されない**ことです。数か月後に同じ障害が起き、過去のポストモーテムを開くと、同じ対策が「未着手」のまま残っている──これでは書いた意味がありません。この章では、実行されるアクションの書き方、優先順位の付け方、完了までの追い方を整理します。

---

## 1. よいアクションの条件

| 条件 | 悪い例 | よい例 |
|------|--------|--------|
| **具体的** | 監視を強化する | 決済ブランド別の 5xx 率アラート（>2% が 5 分）を追加する |
| **検証できる** | テストを充実させる | 決済 SDK のタイムアウト値を検証する統合テストを CI に追加する |
| **担当者がいる** | チームで対応 | 佐藤 |
| **期限がある** | できるだけ早く | 2026-10-10 |
| **チケットがある** | ポストモーテム内のメモ | JIRA PAY-1234 |
| **仕組みを変える** | 今後は気をつける | デプロイ前チェックリストに項目を追加し CI で強制する |

「気をつける」「周知する」「再教育する」は、それだけではアクションになりません。Google SRE Workbook のポストモーテムの章でも、人の注意に頼る対策より**システムで防ぐ対策**を優先するよう勧めています。

---

## 2. 対策の強さ

対策には効き目の強さがあります。医療安全の分野で使われる「対策の階層」の考え方を、ソフトウェアに当てはめると次のようになります。

| 強さ | 種類 | 例 |
|------|------|----|
| 強い | **なくす・自動化する** | 危険な手動操作をなくし、スクリプト化する |
| 強い | **強制する** | CI で検証し、通らなければデプロイできない |
| 中 | **影響を小さくする** | カナリアリリース、Feature Flag、自動ロールバック |
| 中 | **早く気づく** | アラート追加、ダッシュボード改善 |
| 弱い | **手順を書く** | ランブック、チェックリスト |
| 弱い | **注意を促す** | 周知、教育、ダブルチェック |

弱い対策しかない場合は、強い対策を検討したかどうかをレビューで確認します。

---

## 3. 優先順位の付け方

| 優先度 | 基準 | 期限の目安 |
|--------|------|------------|
| **P0** | 同じ障害がすぐ再発しうる。対策するまで危険 | 数日以内 |
| **P1** | 再発の可能性や影響が大きい | 1〜4 週間 |
| **P2** | 改善すべきだが急がない | 四半期内 |

- P0 は、ポストモーテムの完成を待たずに着手する。
- アクションの数は**絞る**。20 個並べて何も終わらないより、3 個を確実に終わらせるほうがよい。
- やらないと決めた対策は、**理由とともに**書いておく（「コストに見合わないため見送り」）。

---

## 4. 完了まで追う仕組み

```mermaid
flowchart LR
  A[ポストモーテム] --> B[チケット作成<br>ラベル postmortem]
  B --> C[通常のバックログで<br>優先度付け]
  C --> D[定例で進捗確認]
  D --> E[完了・検証]
  E --> F[ポストモーテムに<br>完了を記録]
```

- **通常のバックログに入れる**：別管理にすると忘れられる。`postmortem` などのラベルで絞り込めるようにする。
- **定例で確認する**：週次や隔週の運用定例で、期限切れのアクションを確認する。
- **完了率を追う**：「P0/P1 のアクションのうち期限内に完了した割合」を指標にする。Google SRE 本 16章でも、アクションの追跡を文化として根付かせることの重要性が述べられています。
- **完了後に検証する**：アラートを追加したなら、実際に鳴ることを確認する。ゲームデイで再現してもよい（[[02_ゲームデイ]]）。

---

## 5. エラーバジェットとの関係

アクションが後回しにされる最大の理由は、**機能開発との取り合い**です。

- SLO とエラーバジェットの方針で、「バジェットを使い切ったら信頼性の作業を優先する」と合意しておくと、アクションに時間を確保しやすくなります（[[03_エラーバジェット方針]]）。
- P0/P1 アクションは、スプリントの一定割合（例：20%）を信頼性作業に当てる、というルールも有効です。
