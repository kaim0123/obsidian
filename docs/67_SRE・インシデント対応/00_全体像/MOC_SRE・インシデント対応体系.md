# MOC_SRE・インシデント対応体系

67_SRE・インシデント対応 の入口ノート。**信頼性をどこまで求めるかを決め、障害が起きたときに素早く直し、そこから学ぶ**ための型を扱う。Google SRE 本（Part II 原則 / Part III 実践）と SRE Workbook を軸にしている。62〜69 全体の地図は [[MOC_運用領域マップ]]。

## フォルダ構成

| フォルダ | 役割 |
|---|---|
| 00_全体像 | 本MOC |
| 10_SREの原則 | リスクの受け入れ、エラーバジェット方針、トイル削減、自動化 |
| 20_オンコール | ローテーション、ランブック、ページング、疲弊対策、引き継ぎ |
| 30_インシデント対応 | 基本フロー、重大度、インシデントコマンダー、初動、告知 |
| 40_ポストモーテム | 非難なき文化、雛形、根本原因分析、再発防止アクション管理 |
| 50_障害タイプ別ランブック | DBダウン、外部APIダウン、OOM、キュー詰まり など |
| 60_カオスエンジニアリング・DR | ゲームデイ、障害注入、DR訓練 |

運用ルール（旧 Operations 目次より）: **手順（Runbook）と判断（Decision）を分けて書く**。インシデントは必ず記録し、実際の事例は 91 に置いてここからリンクする。

| テーマ | 本拠地 |
|---|---|
| 実際に起きた事故の記録 | 91_トラブルシューティング事例集 |
| SLI/SLO の定義・計測・アラート | 65_可観測性/60 |
| ロールバック手順 | 63_リリース・デプロイ/40 |
| 障害耐性パターン（リトライ・サーキットブレーカー） | 69_分散システム/60 |
| セキュリティインシデント対応 | 71_セキュリティ基礎/50 |
| オンコール文化・組織論 | 020Management |
