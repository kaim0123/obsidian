# HTTPクライアントとは

> **ひとことで言うと**：HTTPクライアントは「サーバーに注文書（リクエスト）を送り、返事（レスポンス）を受け取る係」。ブラウザや Node.js には標準の `fetch` があり、ky や Axios はその上に「毎回書くお決まりの処理」を足した道具。

## たとえ話で理解する

レストランの注文にたとえると：

| 役割 | HTTPでいうと |
|---|---|
| 注文書を書く | リクエストを組み立てる（URL・メソッド・ヘッダー・ボディ） |
| 厨房に渡す | ネットワークで送信する |
| 料理が出てくる／「品切れです」と言われる | レスポンス（ステータスコード・ボディ）を受け取る |
| 30分来なければ催促・キャンセル | タイムアウト・キャンセル |
| 店員が伝え間違えたらもう一度頼む | リトライ |

`fetch` は「注文書を渡して返事を受け取る」ところまでしかやってくれません。「品切れならエラー扱い」「30分で諦める」「失敗したらもう一回」は自分で書く必要があります。ここを肩代わりするのが ky や Axios です。

## 3つの層で考える

```
┌─────────────────────────────────────┐
│ アプリのコード（画面・hooks）        │  ← getUser(42) を呼ぶだけ
├─────────────────────────────────────┤
│ APIレイヤー（api/users.ts など）     │  ← エンドポイントごとの関数・型
├─────────────────────────────────────┤
│ 共通クライアント（apiClient）        │  ← baseURL・認証・エラー・リトライ
├─────────────────────────────────────┤
│ fetch / ky / Axios                  │  ← 実際に通信する道具
└─────────────────────────────────────┘
```

- 下の2層の作り方が [[01_共通クライアントを1つ作る]]・[[03_APIレイヤーのフォルダ構成]]
- 取ってきたデータをキャッシュ・再取得する層は **36_状態管理/40_サーバー状態**（TanStack Query など）の担当。HTTPクライアントは「1回の通信を確実にこなす」ところまでを受け持つ

## 2026年時点の道具の選び方

| 道具 | サイズ感 | 向いている場面 |
|---|---|---|
| `fetch`（標準） | 0KB | 小さなアプリ、自前の薄いラッパーで足りるとき。Node.js 18+ でも標準 |
| ky | 約5KB | fetch ベースでリトライ・タイムアウト・フックが欲しい新規プロジェクトの第一候補 |
| Axios | 約40KB | 既存コード資産が多い、インターセプター文化、アップロード進捗、古い Node |
| OpenAPI 生成クライアント | — | バックエンドに OpenAPI 定義があるなら、手書きより生成（[[02_OpenAPIからクライアントを生成する]]） |

詳しい比較は [[HTTPクライアント・ユーティリティ比較]]。
