# リクエストとレスポンスの組み立て

> **ひとことで言うと**：リクエストは「どこへ（URL）・何をしに（メソッド）・添え状（ヘッダー）・中身（ボディ）」の4点セット。レスポンスは「結果の番号（ステータス）・添え状（ヘッダー）・中身（ボディ）」。ボディは**一度しか読めない**点に注意。

## リクエストの4点セット

```ts
const res = await fetch("https://api.example.com/users?page=2", { // どこへ
  method: "POST",                                                 // 何をしに
  headers: {                                                      // 添え状
    "Content-Type": "application/json",
    Accept: "application/json",
  },
  body: JSON.stringify({ name: "Taro" }),                         // 中身
});
```

### クエリ文字列は URLSearchParams で作る

文字列連結だと `&` や日本語のエスケープ漏れが起きます。

```ts
const url = new URL("/users", "https://api.example.com");
url.search = new URLSearchParams({ q: "山田 太郎", page: "2" }).toString();
// → https://api.example.com/users?q=%E5%B1%B1%E7%94%B0+...&page=2
```

### ボディの種類と Content-Type

| 送るもの | body に渡す値 | Content-Type |
|---|---|---|
| JSON | `JSON.stringify(obj)` | `application/json`（自分で付ける） |
| フォーム（ファイルあり） | `FormData` | **付けない**（ブラウザが boundary 付きで自動設定） |
| URLエンコードのフォーム | `URLSearchParams` | 自動で `application/x-www-form-urlencoded` |
| バイナリ | `Blob` / `ArrayBuffer` | ファイルの種類に合わせる |

よくあるミス：`FormData` を送るときに `Content-Type: multipart/form-data` を手で書くと、boundary が無くてサーバーが読めなくなる。

## レスポンスの読み方

```ts
res.status      // 200, 404, 500 ...
res.ok          // 200〜299 なら true
res.headers.get("Content-Type")

await res.json()   // JSON として読む
await res.text()   // 文字列として読む
await res.blob()   // ファイルとして読む
```

- **ボディは一度しか読めない**：`res.json()` のあとに `res.text()` を呼ぶとエラー。両方必要なら `res.clone()` してから読む
- **204 No Content** は中身が空なので `res.json()` すると失敗する。ステータスを見てから読む
- エラー時も JSON が返ってくることが多い（`{ "message": "..." }`）。エラー処理でもボディを読む → [[01_HTTPエラーの扱い]]

## ブラウザと Node.js の違い（つまずきポイント）

| 項目 | ブラウザ | Node.js（18+ の fetch = undici） |
|---|---|---|
| CORS | 別オリジンへはサーバーの許可が必要 | 関係なし（CORS はブラウザの仕組み） |
| Cookie | `credentials: "include"` で送る | 自動では持たない。ヘッダーで明示 |
| 相対URL `/api/users` | 今のページ基準で解決 | **使えない**。絶対URLが必要 |
| プロキシ | OS/ブラウザ設定 | 環境変数や dispatcher の設定が必要 |

Next.js のサーバーコンポーネントなど「同じコードがサーバーでも動く」環境では、相対URLと Cookie の違いで事故が起きやすい。
