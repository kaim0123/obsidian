# ユーティリティライブラリの選び方

> **ひとことで言うと**：まず**標準機能（ES2023+）で書けないか**を確かめ、足りないもの（`debounce`・深い比較・`groupBy` の細かい版など）だけをライブラリで補う。2026年の新規プロジェクトなら Lodash より **es-toolkit**（速い・小さい・型付き）が第一候補。

## たとえ話で理解する

工具箱を買うとき、家にもうあるドライバーまでセットで買う必要はない。昔は家に工具が少なかった（JavaScript の標準機能が貧弱だった）ので Lodash のような大きな工具セットが必須だったが、今は家の工具（標準機能）がかなり揃った。**足りない1本だけ買い足す**のが今のやり方。

## 標準機能で置き換えられるもの

| やりたいこと | Lodash | 標準 |
|---|---|---|
| 配列の平坦化 | `_.flatten` | `arr.flat()` |
| 存在チェック付きのプロパティ取得 | `_.get(obj, "a.b.c")` | `obj?.a?.b?.c` |
| 既定値 | `_.defaultTo(x, 0)` | `x ?? 0` |
| グループ分け | `_.groupBy` | `Object.groupBy(arr, fn)` / `Map.groupBy` |
| 深いコピー | `_.cloneDeep` | `structuredClone(obj)` |
| 重複除去 | `_.uniq` | `[...new Set(arr)]` |
| 最後の要素 | `_.last` | `arr.at(-1)` |
| 非破壊ソート | `_.sortBy`（一部） | `arr.toSorted(fn)` |
| 範囲の配列 | `_.range(5)` | `Array.from({ length: 5 }, (_, i) => i)` |

## ライブラリが今も役に立つもの

- `debounce` / `throttle`（キャンセル・`leading`/`trailing` オプション込み）
- 深い比較 `isEqual`
- `pick` / `omit` / `mapValues` などオブジェクト操作の型付き版
- `chunk`、`partition`、`intersectionBy` など配列操作の小物
- `retry`・`delay`・`Mutex` などの非同期ユーティリティ（es-toolkit にある）

## 主な選択肢（2026年）

| ライブラリ | 特徴 | 向いている場面 |
|---|---|---|
| **es-toolkit** | Lodash の2〜3倍速く、関数単位で最大97%小さい。TypeScript 製。`es-toolkit/compat` で Lodash 互換 | 新規プロジェクト、Lodash からの移行 |
| Lodash | 実績と網羅性。`lodash-es` なら tree-shaking しやすい | 既存コード、互換性重視 |
| Remeda | データを最後に受け取る「パイプ」向き、型推論が強い | 関数型スタイル |
| Radash | 非同期ユーティリティが充実、独自API | 新しい書き方で始めたい |

## 選ぶときのチェック

- **tree-shaking できるか**：`import _ from "lodash"` は全部入ってしまう。`import { debounce } from "es-toolkit"` のように名前付きで読む
- **型が付くか**：TypeScript で `any` が漏れないか
- **サイズを測る**：86_QAプロセス のバンドルサイズ予算（size-limit）で見張る
- **依存を増やしすぎない**：1関数のためにライブラリを足すなら、数行で自作してテストを書くほうがよいこともある。2026年3月の Axios 乗っ取り事件のように、依存はサプライチェーン攻撃の入口にもなる
