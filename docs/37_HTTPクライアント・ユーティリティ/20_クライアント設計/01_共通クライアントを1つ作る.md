# 共通クライアントを1つ作る

> **ひとことで言うと**：`fetch` や `axios.get` を画面のあちこちで直接呼ばず、**設定済みのクライアントを1つだけ作って全員がそれを使う**。baseURL・共通ヘッダー・タイムアウト・エラー処理を1か所で変えられるようになる。

## たとえ話で理解する

会社の郵便を、社員が各自バラバラの封筒・切手で出していると、「差出人住所が変わった」ときに全員に伝えなければならない。**総務の窓口を1つ作って全部そこから出す**ようにすれば、変更は窓口1か所で済む。共通クライアントはこの「総務の窓口」。

## なぜ必要？（困りごと）

| 直接呼びだと… | 共通クライアントなら |
|---|---|
| `https://api.example.com` が50か所に散らばる | baseURL を1か所で設定 |
| 認証ヘッダーの付け忘れ | 自動で付く（[[02_インターセプターとフック]]） |
| 4xx を見落とす画面と見る画面が混在 | エラー処理が統一される |
| タイムアウトが無い通信が紛れ込む | 既定値が全通信に効く |
| テストで通信を差し替えにくい | 窓口1つをモックすればよい |

## 実装例

### fetch で薄いラッパーを書く

```ts
// lib/apiClient.ts
const BASE_URL = import.meta.env.VITE_API_BASE_URL;

export async function apiFetch<T>(path: string, init: RequestInit = {}): Promise<T> {
  const res = await fetch(new URL(path, BASE_URL), {
    ...init,
    headers: { Accept: "application/json", ...init.headers },
    signal: init.signal ?? AbortSignal.timeout(10_000), // 既定のタイムアウト
  });
  if (!res.ok) throw await ApiError.from(res);          // 30_エラー処理を参照
  return res.status === 204 ? (undefined as T) : res.json();
}
```

### ky の場合（v2）

```ts
import ky from "ky";

export const api = ky.create({
  prefix: import.meta.env.VITE_API_BASE_URL, // v1 では prefixUrl
  timeout: 10_000,
  retry: { limit: 2 },
});

const user = await api.get("users/42").json<User>();
```

### Axios の場合

```ts
import axios from "axios";

export const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10_000,
});

const { data: user } = await api.get<User>("/users/42");
```

## 設計のコツ

- **クライアントは「接続先ごと」に1つ**：自社API・決済API・外部の天気APIなど、認証方式や baseURL が違う相手ごとに分ける
- **環境変数で baseURL を切り替える**：本番・ステージング・ローカルをコードの変更なしで切り替える
- **呼び出し側に `Response` を漏らさない**：戻り値はパース済みのデータ（とエラー）だけにすると、道具を ky → fetch などに入れ替えても呼び出し側は変わらない
- **やりすぎない**：キャッシュや再取得は TanStack Query（36_状態管理/40）に任せ、クライアントは「1回の通信」に集中させる
