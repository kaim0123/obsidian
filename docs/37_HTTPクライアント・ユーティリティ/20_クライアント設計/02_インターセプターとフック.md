# インターセプターとフック

> **ひとことで言うと**：すべての通信の「出発前」と「到着後」に必ず通る検問所を置き、そこで認証ヘッダーを付ける・ログを取る・エラーを整形する。Axios では **interceptor**、ky では **hooks**、openapi-fetch では **middleware** と呼ぶ。

## たとえ話で理解する

空港の保安検査場。どの便に乗る人も、出発前に必ず同じ検査を通る（リクエスト側）。到着したら全員が入国審査を通る（レスポンス側）。便ごとに検査員を配置するより、**通り道に1か所置く**ほうが漏れがない。

## 何を差し込むか

| タイミング | よくある処理 |
|---|---|
| リクエスト前 | 認証トークン付与、テナントIDや言語などの共通ヘッダー、リクエストIDの付与、ログ |
| レスポンス後（成功） | 共通のラッパー `{ data: ... }` を剥がす、日付文字列を変換、計測 |
| レスポンス後（失敗） | 401 ならトークン更新して再送、エラーを自前の `ApiError` に整形、エラー通知 |
| リトライ前 | ログ、トークンの再取得 |

## ライブラリ別の書き方

### Axios：interceptors

```ts
api.interceptors.request.use((config) => {
  config.headers.Authorization = `Bearer ${getAccessToken()}`;
  return config;
});

api.interceptors.response.use(
  (res) => res,
  (error) => Promise.reject(toApiError(error)),
);
```

### ky（v2）：hooks

v2 から、フックは **状態オブジェクト1つ** を受け取る形になった（v1 は `(request, options)` のように引数が分かれていた）。

```ts
const api = ky.create({
  hooks: {
    beforeRequest: [
      ({ request }) => {
        request.headers.set("Authorization", `Bearer ${getAccessToken()}`);
      },
    ],
    afterResponse: [
      ({ request, response }) => {
        if (response.status === 401) { /* 更新して再送など */ }
      },
    ],
    beforeError: [
      ({ error }) => error, // v2 では HTTPError 以外のエラーでも呼ばれる
    ],
  },
});
```

### fetch：自分で関数を重ねる

fetch には仕組みが無いので、[[01_共通クライアントを1つ作る]] のラッパー関数の中に「前処理 → fetch → 後処理」を書く。

## 注意点

- **順番が大事**：Axios のリクエストインターセプターは「後に登録したものが先に動く」。依存関係のある処理は1つにまとめるか、順番を明記する
- **重い処理を入れない**：全通信が遅くなる
- **例外を握りつぶさない**：失敗側のインターセプターで `return` してしまうと、呼び出し側は成功したと思い込む。必ず `Promise.reject` / `throw` する
- **画面遷移をここでしない**：「401 なら `/login` へ飛ばす」をインターセプターに直接書くと、テストやサーバー側で動かしにくい。イベントを発行して画面側で処理するほうが疎結合
