# A08: ソフトウェアとデータの整合性の不備（Software and Data Integrity Failures）

## はじめに

**整合性**（Integrity）とは、「データやコードが、正規のまま、改ざんされていない」ことを保証する性質です。

この項目は、**信頼できないソースからコードやデータを取り込み、検証せずに使ってしまう** ことで起きる問題を扱います。2021年版で新設されました。

### 具体例でイメージする

- npm のパッケージが乗っ取られ、正規のライブラリを装ったマルウェアが配布される
- CDN から取得する JavaScript が差し替えられ、全ユーザーで悪意あるコードが走る
- Jenkins のプラグインや CI/CD パイプラインが改ざんされ、ビルド成果物にバックドアが埋め込まれる
- 署名検証しない自動アップデートで、偽のファームウェアを配られる
- 信頼できないデータをデシリアライズして、リモートコード実行される

---

## 現実に起きた事件

### SolarWinds事件（2020年）

ネットワーク監視ソフト「SolarWinds Orion」のビルドシステムが侵害され、**正規の署名付きアップデート** にバックドアが仕込まれました。18,000の組織（米国政府機関含む）が影響を受けた史上最大級のサプライチェーン攻撃。

### event-stream事件（2018年）

npm の人気パッケージ `event-stream` のメンテナ権限が悪意ある第三者に譲渡され、依存パッケージに暗号通貨を盗むコードが埋め込まれました。

### Codecov事件（2021年）

CIツール Codecov の Bash Uploader スクリプトが改ざんされ、CI環境の環境変数（APIキー、トークン）が外部に送信されていました。

---

## 3つのリスクカテゴリ

### 1. ソフトウェアの整合性不備

**信頼できないソースからコードを取得して実行してしまう**。

- npm / PyPI / Docker Hub の汚染
- CDN JavaScript の改ざん
- ビルドシステム / CI/CD の侵害（サプライチェーン攻撃）

### 2. CI/CDパイプラインの整合性不備

パイプライン自体が守られていないと、そこで作られた成果物も信頼できません。

- CI/CD の権限管理が甘い
- ビルド環境が共有されて汚染される
- デプロイ時に署名検証しない

### 3. 安全でないデシリアライゼーション

**シリアライズされたデータ**（JSON、YAML、XML、Javaオブジェクト、Python pickle など）を、信頼せずデシリアライズすると、任意のコードが実行される恐れがあります。

---

## 安全でないデシリアライゼーション

### ❌ 悪い例: Python pickle

```python
import pickle
data = pickle.loads(user_input)  # ← 超危険
```

pickleはPythonオブジェクトを復元する過程で **任意のコードを実行できます**。攻撃者は仕掛けをしたデータを送るだけでサーバーを乗っ取れます。

### ❌ 悪い例: Java Deserialization

Java標準の `ObjectInputStream.readObject()` に信頼できないデータを渡すと、ガジェットチェーン（既存クラスを連鎖させた攻撃）でリモートコード実行される脆弱性が多発しています。

### ✅ 良い例: JSON / Protocol Buffers を使う

- **JSON** はコード実行能力がない、安全なフォーマット
- **Protocol Buffers**、**MessagePack** など、コード実行を含まないフォーマットを選ぶ
- どうしてもネイティブシリアライズが必要なら、**署名検証** と **許可リスト型の復元** を組み合わせる

## 対策1: 信頼できるソースからのみ取得

### パッケージ管理

```bash
# npm: 公式レジストリのみ
npm config set registry https://registry.npmjs.org/

# インストール時スクリプトを無効化（サプライチェーン対策）
npm install --ignore-scripts

# 内部プロキシを経由（Artifactory、Nexus など）
npm config set registry https://npm.internal.company/
```

### ロックファイル + 完全性検証

`package-lock.json` や `yarn.lock` には、各パッケージの **ハッシュ値**（integrity）が記録されます。

```json
{
  "lodash": {
    "version": "4.17.21",
    "integrity": "sha512-v2kDEe57lecTulaDIuNTPy3Ry4gLGJ6Z1O3vE1krgXZNrsQ+LFTGHVxVjcXPs17LhbZVGedAJv8XZ1tvj5FvSg=="
  }
}
```

インストール時にハッシュが一致しないと失敗するので、改ざんを検知できます。

### `npm ci` を本番で使う

```bash
# ❌ 開発用（依存関係を更新する可能性あり）
npm install

# ✅ 本番・CI用（ロックファイルに厳密に従う）
npm ci
```

## 対策2: CDN の JavaScript には SRI

外部CDNからJSを読む場合、改ざんを検知するために **SRI**（Subresource Integrity）を使います。

```html
<!-- ❌ SRIなし -->
<script src="https://cdn.example.com/lib.js"></script>

<!-- ✅ SRI付き -->
<script
  src="https://cdn.example.com/lib.js"
  integrity="sha384-oqVuAfXRKap7fdgcCY5uykM6+R9GqQ8K/uxy9rx7HNQlGYl1kPzQho1wx4JwY8wC"
  crossorigin="anonymous"
></script>
```

ハッシュが一致しなければブラウザがスクリプトを実行しません。

## 対策3: コード署名と検証

### アプリ配布

- アプリ配布時に **コード署名**（Apple Developer Certificate、Microsoft Authenticode）を行う
- アップデート取得時に **署名検証** を必ず行う
- 自動アップデート機構（Sparkle、Squirrel）の署名検証を有効化

### コンテナイメージ

```bash
# Docker Content Trust
export DOCKER_CONTENT_TRUST=1
docker push myimage:v1  # 署名付きでpush
docker pull myimage:v1  # 署名検証してpull
```

**Sigstore / Cosign** も広く使われています。

### Gitコミット署名

```bash
git config --global commit.gpgsign true
git config --global user.signingkey <key-id>
```

GitHubで「Verified」バッジが付くようになります。

## 対策4: CI/CDパイプラインを守る

### 1. 権限の分離と最小化

- ビルド用ロボットアカウントは必要最小限の権限
- 本番デプロイには人間の承認ステップを必須に
- CI環境の機密情報（APIキー等）は必要なジョブにだけ渡す

### 2. ビルド環境の隔離

- 各ビルドを独立したコンテナ・VMで実行（前のビルドの影響を受けない）
- プルリクエストのビルドは権限を制限

### 3. GitHub Actions のセキュリティ

```yaml
# ❌ サードパーティアクションをタグ参照（すり替えリスク）
- uses: someone/action@v1

# ✅ コミットSHA固定
- uses: someone/action@abc1234567890abcdef1234567890abcdef12

# デフォルト権限は最小化
permissions:
  contents: read
```

### 4. SLSA（Supply-chain Levels for Software Artifacts）

Google主導の **サプライチェーンセキュリティ成熟度フレームワーク**。Level 1〜4まであり、段階的に対策を強化します。SBOM、署名、改ざん検知、独立したビルド環境などの要求事項が定められています。

## まとめ

- A08 は **サプライチェーン時代の新たな脅威** を反映したカテゴリ
- **信頼できないソースからのコード・データを検証せず実行しない**
- ロックファイル、SRI、コード署名、CI/CD保護が基本対策
- デシリアライゼーションは **pickleやJavaのObjectInputStreamを避け、JSONへ**
- SLSA など新しいフレームワークで、サプライチェーン全体を守る時代
