# 第5章：セキュリティツールと情報基盤

第1〜4章で脅威、分析手法、用語、防御技術を学んだ。本章では、それらを **実務で支えるツールと情報源** を整理する。

セキュリティエンジニアは「ツールを全部使いこなす」必要はない。ただし **どんな場面で何のツールが使われるか** を知っておくと、調査・設計・インシデント対応の会話に参加しやすくなる。

---

## 1. ツールの全体像

セキュリティツールは、大きく **5つのフェーズ** に分けて理解できる。

```
【事前調査・評価】  ファイル/Web/ドメインの評価、脆弱性スキャン
【監視・検知】      SIEM、ログ管理、イベント処理
【分析・調査】      フォレンジック、バイナリ解析
【攻撃シミュレーション】 ペネトレーションテスト
【知識・基準】      フレームワーク、エクスプロイト/マルウェアDB
```

---

## 2. セキュリティ情報とイベント管理（SIEM）

### 2.1 SIEM とは

**Security Information and Event Management（セキュリティ情報およびイベント管理）**

複数のソースから **ログとセキュリティイベントを集約し、相関分析・アラート・調査** を行う中核プラットフォーム（第2章・第4章で触れた SIEM の詳細）。

| 機能 | 説明 |
|------|------|
| **ログ集約** | ファイアウォール、サーバー、EDR、クラウド等のログを一か所に |
| **正規化** | 異なる形式のログを共通フォーマットに変換 |
| **相関分析** | 複数イベントを関連づけて異常を検出 |
| **アラート** | ルールに基づく自動通知 |
| **ダッシュボード** | 可視化・レポート |
| **インシデント調査** | タイムライン再構成、検索 |

**代表製品：** Splunk、Microsoft Sentinel、Elastic SIEM、IBM QRadar、Google Chronicle

**初心者のポイント：** SIEM は「ログが集まる場所」であり、SOC（セキュリティ運用センター）の中心になる。

---

### 2.2 セキュリティログ／イベント管理ツール

SIEM に近いが、**ログの収集・保存・検索** に特化したツールもある。

| 種類 | 役割 | 例 |
|------|------|-----|
| **ログ管理（Log Management）** | ログの収集・保存・検索 | Elasticsearch + Logstash + Kibana（ELK）、Graylog |
| **イベント管理** | セキュリティイベントの記録・追跡 | OSSEC、Wazuh |
| **SIEM** | 上記 + 相関分析 + アラート + インシデント管理 | Splunk、Sentinel |

**SIEM との違い（ざっくり）：**
- ログ管理 → 「ログを貯めて探す」
- SIEM → 「ログを貯めて、自動で異常を見つけて知らせる」

---

### 2.3 セキュリティイベント処理ツール（SOAR）

**Security Orchestration, Automation and Response**

検知されたイベントに対する **対応を自動化・ワークフロー化** するツール（第4章の SOAR）。

| 機能 | 説明 |
|------|------|
| **オーケストレーション** | 複数ツールを連携させて一連の処理を実行 |
| **自動化** | 定型的な対応（IPブロック、アカウント無効化）を自動実行 |
| **プレイブック** | インシデント種別ごとの対応手順を定義 |

**SIEM との関係：**
```
SIEM（検知）→ SOAR（自動対応）→ 各ツール（FW、EDR、Active Directory 等）
```

**代表製品：** Palo Alto Cortex XSOAR、Splunk SOAR、IBM Resilient

---

## 3. 評価・調査ツール（Threat Intelligence / Reputation）

不審なファイル、URL、ドメインなどを **外部の知見データベースと照合して危険度を判定** するツール群。

### 3.1 ファイル評価ツール

**ファイル（実行ファイル、PDF、Office文書等）が安全かどうかを判定する。**

| 手法 | 説明 |
|------|------|
| **ハッシュ照合** | ファイルの SHA-256 等を既知マルウェアDBと比較 |
| **サンドボックス実行** | 隔離環境で実行し、挙動を観察 |
| **静的解析** | 実行せずにコード・文字列・構造を分析 |

**代表サービス・ツール：**

| 名称 | 特徴 |
|------|------|
| **VirusTotal** | 60以上のAVエンジン + サンドボックスで評価。最も広く使われる |
| **Hybrid Analysis** | 無料のサンドボックス解析 |
| **Any.Run** | インタラクティブなサンドボックス（操作しながら観察） |
| **Joe Sandbox** | 商用サンドボックス |

**使い方の例：**
```
不審なメール添付ファイルを受信
    ↓
SHA-256 ハッシュを VirusTotal で検索
    ↓
0/70 検出 → 怪しい → サンドボックスで動的解析
```

**注意：** 機密ファイルを外部サービスにアップロードすると、サンプルが共有される場合がある。

---

### 3.2 Webサイト評価ツール

**URL や Web ページがフィッシング・マルウェア配布サイトでないかを判定する。**

| サービス | 特徴 |
|----------|------|
| **VirusTotal（URL）** | URL を複数エンジンで評価 |
| **Google Safe Browsing** | Chrome 等に組み込まれた危険サイトDB |
| **urlscan.io** | Web ページのスクリーンショット・リダイレクト・技術情報を可視化 |
| **PhishTank** | ユーザー報告ベースのフィッシングURL DB |

**使い方の例：**
```
不審なリンクをクリックする前に urlscan.io で調査
→ リダイレクト先、使用技術、過去の評判を確認
```

---

### 3.3 ドメイン評価ツール

**ドメイン名の評判・登録情報・関連インフラを調査する。**

| 調査項目 | 説明 |
|----------|------|
| **WHOIS** | ドメイン登録者、登録日、有効期限 |
| **DNS レコード** | A、MX、NS レコードの確認 |
| **レピュテーション** | 過去の悪用履歴、ブラックリスト掲載 |
| **関連ドメイン** | 同じ IP や登録者の他ドメイン |

**代表ツール・サービス：**

| 名称 | 用途 |
|------|------|
| **WHOIS 検索** | 登録情報の確認（whois.domaintools.com 等） |
| **Passive DNS** | 過去の DNS 解決履歴（SecurityTrails、VirusTotal） |
| **DomainTools Iris** | ドメイン調査の統合プラットフォーム（商用） |
| **Crt.sh** | SSL 証明書の透明性ログ（サブドメイン発見） |

**フィッシング判定のヒント：**
- 登録から数日の新しいドメイン
- 正規サイトに似せたタイポスクワッティング（`arnazon.com` 等）
- 正規ドメインと無関係な WHOIS 情報

---

### 3.4 インターネットリソース評価ツール

**IP アドレス、ASN（自律システム番号）、ホスト等、より広いインターネット上のリソースを評価する。**

| リソース | 調査内容 | ツール例 |
|----------|----------|----------|
| **IP アドレス** | 地理的位置、AS、過去の悪用履歴 | AbuseIPDB、Shodan、VirusTotal |
| **ASN** | どの組織・ISP が管理するネットワークか | BGPView、RIPE |
| **ホスト・サービス** | 公開ポート、稼働サービス、バナー情報 | Shodan、Censys |
| **SSL/TLS 証明書** | 発行者、有効期限、関連ドメイン | Crt.sh、SSL Labs |

**Shodan / Censys の特徴：**
- インターネット上のデバイス・サービスを **能動的にスキャン** したデータベース
- 「この IP には何が公開されているか」を調べられる
- 攻撃者も使うため、**自社の公開面を把握する** 目的でも重要

## 4. エクスプロイトとマルウェアデータベース

**既知の攻撃コードやマルウェアの情報を蓄積・公開する** データベース。脅威インテリジェンス（Threat Intelligence）の基盤。

### 4.1 マルウェアデータベース

| データベース | 内容 | 用途 |
|--------------|------|------|
| **VirusTotal** | ファイルハッシュ、振る舞い、関連 IOC | ファイル評価、IOC 検索 |
| **MalwareBazaar** | マルウェアサンプルとメタデータ（abuse.ch） | 最新サンプルの取得・研究 |
| **URLhaus** | マルウェア配布 URL（abuse.ch） | URL ブロックリスト作成 |
| **Malpedia** | マルウェアファミリーの百科事典 | マルウェア種別の理解 |

---

### 4.2 エクスプロイトデータベース

| データベース | 内容 | 用途 |
|--------------|------|------|
| **Exploit Database（Exploit-DB）** | 公開されたエクスプロイトコード | 脆弱性の悪用可能性確認 |
| **Metasploit Modules** | Metasploit に組み込まれたエクスプロイト | ペンテスト、概念実証 |
| **NVD / CVE** | 脆弱性の公式情報（第3章） | パッチ優先度の判断 |
| **CISA KEV** | 実際に悪用された脆弱性リスト（第3章） | 最優先パッチの判断 |

**初心者のポイント：**
- Exploit-DB に載っている = **その脆弱性は実際に悪用可能** という強いシグナル
- 防御側は「自社に該当 CVE があるか」を定期的に照合する

---

## 5. 脆弱性スキャナー

**システムやアプリケーションの既知脆弱性を自動で検出する** ツール。

### 5.1 種類

| 種類 | スキャン対象 | 代表ツール |
|------|--------------|------------|
| **ネットワークスキャナー** | IP、ポート、サービス、OS | Nessus、OpenVAS、Nmap |
| **Web アプリスキャナー** | Web ページの脆弱性（SQLi、XSS 等） | OWASP ZAP、Burp Suite、Nikto |
| **コンテナスキャナー** | Docker イメージの脆弱性 | Trivy、Clair、Snyk |
| **クラウド設定スキャナー** | クラウドリソースの設定ミス | Prowler、Scout Suite、AWS Inspector |
| **依存関係スキャナー（SCA）** | ライブラリ・パッケージの脆弱性 | Dependabot、Snyk、OWASP Dependency-Check |

### 5.2 スキャナーの使い分け

```
【外部から】 ネットワークスキャナー → 公開ポート・サービスの把握
【Web アプリ】 Web アプリスキャナー → SQLi、XSS 等
【開発中】   SCA → 使っているライブラリの CVE 確認
【クラウド】  設定スキャナー → S3 公開、過剰権限等
```

**注意：** スキャナーは **偽陽性（誤検知）** がある。結果は人間が確認・検証する。

## 6. ペネトレーションツール

**攻撃者の視点でシステムの弱点を探す** ツール。許可を得た上でのセキュリティテスト（ペネトレーションテスト）に使う。

### 6.1 ペネトレーションテストとは

組織の許可を得て、**実際の攻撃手法を使い、防御の穴を見つける** 活動（第2章・第4章で触れた攻撃手法の実践）。

### 6.2 代表ツール

| フェーズ | ツール | 用途 |
|----------|--------|------|
| **情報収集** | Nmap、Recon-ng、theHarvester | ポート、サービス、メールアドレスの収集 |
| **脆弱性スキャン** | Nessus、OpenVAS | 既知脆弱性の検出 |
| **エクスプロイト** | Metasploit、Exploit-DB | 脆弱性の悪用（概念実証） |
| **Web 攻撃** | Burp Suite、OWASP ZAP | SQLi、XSS、認証突破 |
| **パスワード攻撃** | Hashcat、John the Ripper | ハッシュの解読、パスワード総当たり |
| **ワイヤレス** | Aircrack-ng | Wi-Fi 暗号の解析 |
| **ソーシャルエンジニアリング** | GoPhish | フィッシング訓練の実施 |

### 6.3 ペンテストと脆弱性スキャンの違い

| | 脆弱性スキャン | ペネトレーションテスト |
|---|--------------|----------------------|
| **目的** | 脆弱性の「存在」を見つける | 実際に「侵入できるか」を確認 |
| **手法** | 自動スキャンが中心 | 手動 + 自動、攻撃の連鎖 |
| **深度** | 浅い（リストアップ） | 深い（実害の概念実証まで） |
| **頻度** | 定期的（月次〜四半期） | 年1〜2回程度 |

## 7. バイナリ解析ツール

**実行ファイル（バイナリ）の内部構造や動作を解析する** ツール（第2章のリバースエンジニアリング）。

### 7.1 静的解析ツール

**プログラムを実行せずに** 構造を調べる。

| ツール | 特徴 |
|--------|------|
| **Ghidra** | NSA 製、無料。逆コンパイル機能が強力 |
| **IDA Pro** | 業界標準の逆アセンブラ（商用） |
| **Binary Ninja** | モダンな UI の逆アセンブラ（商用） |
| **PEStudio / Detect It Easy** | PE ファイルの表層解析（高速スクリーニング） |
| **strings** | バイナリ内の文字列を抽出（Linux 標準コマンド） |

---

### 7.2 動的解析・デバッガ

**プログラムを実行しながら** 動作を追跡する。

| ツール | 対象 |
|--------|------|
| **x64dbg** | Windows 32/64bit バイナリ |
| **GDB** | Linux バイナリ |
| **WinDbg** | Windows カーネル・クラッシュダンプ |
| **dnSpy** | .NET アセンブリ |
| **Process Monitor / Process Hacker** | プロセス・ファイル・レジストリの監視 |

---

### 7.3 解析の流れ（復習）

```
表層解析（PEStudio、strings、VirusTotal）
    ↓
静的解析（Ghidra、IDA で逆コンパイル）
    ↓
動的解析（x64dbg + サンドボックス + Process Monitor）
    ↓
IOC 抽出 → SIEM / EDR の検知ルールに反映
```

---

## 8. フォレンジックツール

**インシデント発生後に、証拠を収集・分析する** ツール（第2章のフォレンジック）。

### 8.1 種類別ツール

| 対象 | ツール | 用途 |
|------|--------|------|
| **ディスク** | FTK Imager、Autopsy、EnCase | ディスクイメージの取得・ファイル復元 |
| **メモリ** | Volatility 3、Rekall | メモリダンプからプロセス・ネットワーク接続を抽出 |
| **ネットワーク** | Wireshark、NetworkMiner | パケットキャプチャの分析 |
| **ログ** | Log2Timeline（Plaso） | 複数ソースのログをタイムライン統合 |
| **モバイル** | Cellebrite、Autopsy（Android） | スマートフォンのフォレンジック |

### 8.2 フォレンジックの基本原則

| 原則 | 説明 |
|------|------|
| **証拠の保全** | オリジナルは改変しない。コピー（イメージ）を分析する |
| **チェーン・オブ・カストディ** | 誰がいつ証拠を触ったか記録する |
| **再現性** | 同じ手順で同じ結果が得られること |

## 9. データ処理ツール

セキュリティ調査で扱う **大量データの加工・変換・可視化** に使うツール。

| 用途 | ツール | 説明 |
|------|--------|------|
| **ログ解析** | jq、grep、awk | JSON/テキストログのフィルタ・変換 |
| **データ正規化** | Logstash、Fluentd | 異なる形式のログを共通フォーマットに |
| **可視化** | Kibana、Grafana | ダッシュボード・グラフ作成 |
| **スクリプト処理** | Python（pandas、scapy）、PowerShell | 自動化・カスタム分析 |
| **IOC 管理** | MISP、OpenCTI | 侵害指標の共有・管理 |
| **タイムライン** | Timesketch、Log2Timeline | イベントの時系列再構成 |

**Python が重要な理由：**
- セキュリティコミュニティで広く使われる
- Scapy（パケット操作）、pefile（PE解析）、Volatility 等のライブラリが豊富
- 自動化スクリプトの作成に必須

## 10. セキュリティフレームワーク

**セキュリティの考え方・手順・管理項目を体系化した枠組み。** ツールではなく「設計図・チェックリスト」。

### 10.1 主要フレームワーク

| フレームワーク | 正式名称 | 用途 |
|----------------|----------|------|
| **NIST CSF** | Cybersecurity Framework | 組織のセキュリティ成熟度評価（Identify, Protect, Detect, Respond, Recover） |
| **ISO 27001** | 情報セキュリティマネジメント | 国際標準の ISMS（認証取得も可能） |
| **CIS Controls** | Critical Security Controls | 優先度付きの具体的防御策リスト |
| **MITRE ATT&CK** | Adversarial Tactics, Techniques, and Common Knowledge | 攻撃手法の知識ベース（第2章） |
| **OWASP Top 10** | — | Web アプリの最重要脆弱性リスト |
| **NIST SP 800-53** | Security and Privacy Controls | 米国連邦政府向けセキュリティ管理策 |

### 10.2 フレームワークの使い分け

```
【組織全体の設計】  NIST CSF、ISO 27001
【具体的な対策】    CIS Controls
【攻撃の理解】      MITRE ATT&CK
【開発・Web】       OWASP Top 10、OWASP ASVS
【インシデント対応】 NIST SP 800-61
```

**初心者のポイント：** フレームワークは「全部やる」必要はない。**自組織のフェーズに合ったもの** から始める。

---

## 11. ツールの全体マップ

```
【評価・調査（事前）】
  ファイル評価 ─── VirusTotal、Hybrid Analysis
  Web/URL評価 ─── urlscan.io、Safe Browsing
  ドメイン評価 ─── WHOIS、Passive DNS、DomainTools
  IP/ホスト評価 ─ Shodan、Censys、AbuseIPDB

【監視・検知（常時）】
  SIEM ─────────── Splunk、Sentinel、Elastic
  ログ管理 ─────── ELK、Graylog、Wazuh
  イベント処理 ─── SOAR（XSOAR、Splunk SOAR）

【脆弱性・攻撃テスト（定期）】
  脆弱性スキャナー ─ Nessus、OpenVAS、ZAP、Trivy
  ペンテスト ───── Metasploit、Burp Suite、Nmap

【分析・調査（インシデント時）】
  バイナリ解析 ─── Ghidra、IDA、x64dbg
  フォレンジック ── Volatility、Autopsy、Wireshark
  データ処理 ───── Python、jq、Timesketch

【知識基盤】
  マルウェアDB ─── VirusTotal、MalwareBazaar、URLhaus
  エクスプロイトDB ─ Exploit-DB、Metasploit、KEV
  フレームワーク ── NIST CSF、MITRE ATT&CK、OWASP
```

## 12. ツール選定の考え方（初心者向け）

| 場面 | 最初に覚えるツール | 理由 |
|------|-------------------|------|
| 不審ファイル | VirusTotal | 無料、即座に評価 |
| 不審URL | urlscan.io | 視覚的に確認できる |
| ログ調査 | grep / jq → SIEM | 小規模は CLI、大規模は SIEM |
| ネットワーク | Wireshark | パケットの読み方の基本 |
| 脆弱性確認 | Nmap + OpenVAS | 無料で始められる |
| バイナリ解析 | Ghidra + x64dbg | 無料で高機能 |
| 攻撃の理解 | MITRE ATT&CK | 体系化された知識 |

**覚えておくこと：**
- ツールは **目的に合わせて選ぶ**（全部使う必要はない）
- **無料ツール**（Ghidra、OpenVAS、Wazuh、ELK）だけでも相当なことができる
- ツールの出力は **必ず人間が検証する**（特にスキャナーの偽陽性）

## 13. この章のまとめ

| カテゴリ | 覚えておくこと |
|----------|----------------|
| **SIEM** | ログ集約・相関分析の中核。SOC の中心 |
| **評価ツール** | ファイル/URL/ドメイン/IP を外部DBと照合 |
| **DB** | VirusTotal、Exploit-DB、KEV が日常で使われる |
| **スキャナー** | 脆弱性の「存在」を見つける（定期実行） |
| **ペンテスト** | 実際に「侵入できるか」を確認（許可必須） |
| **バイナリ/フォレンジック** | インシデント時の深掘り調査 |
| **フレームワーク** | 設計図。NIST CSF と ATT&CK から始める |

第1〜4章の知識と組み合わせ、本章のツールを **いつ・何のために使うか** がわかれば、SOC やインシデント対応の現場で「会話に参加できる」状態になる。まずは VirusTotal、Wireshark、Ghidra の3つから触ってみるのがおすすめ。
