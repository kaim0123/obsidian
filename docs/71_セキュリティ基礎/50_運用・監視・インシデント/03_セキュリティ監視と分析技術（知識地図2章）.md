# 第2章：セキュリティ監視と分析の技術

第1章で「脅威と脆弱性」の全体像を学んだ。本章では、侵害が起きたとき・起きそうなときに使う **監視・分析・調査の技術** を整理する。

セキュリティエンジニアの仕事は「攻撃を防ぐ」だけでなく、**異常を検知し、原因を突き止め、再発を防ぐ** ことまで含む。用語が多いが、大きな流れは次の3段階と覚えるとよい。

```
監視（Detect）→ 分析（Analyze）→ 対応（Respond）
```

---

## 1. セキュリティ監視

**常時または定期的にシステムの状態を見張り、攻撃や異常の兆候を早期に発見する** 活動。インシデント対応の入口になる。

### 1.1 監視の4つの柱

| 監視対象 | 何を見るか | 主なツール・手法 |
|----------|------------|------------------|
| **ネットワークトラフィック** | 通信の量・宛先・プロトコル・不審なパターン | ファイアウォールログ、NetFlow、パケットキャプチャ（Wireshark 等） |
| **システムログ** | ログイン失敗、権限変更、サービス起動・停止 | OSログ、Webサーバーログ、クラウド監査ログ |
| **IDS / IPS** | 既知の攻撃シグネチャや異常行動 | Snort、Suricata、商用IDS/IPS |
| **エンドポイント監視** | PC・サーバー上のプロセス、ファイル変更、マルウェア兆候 | EDR、ウイルス対策、OSのセキュリティログ |

### 1.2 IDS と IPS の違い

| 種類 | 正式名称 | 動作 | イメージ |
|------|----------|------|----------|
| **IDS** | Intrusion Detection System（侵入検知） | 攻撃を**検知してアラート** | 防犯カメラ＋警報 |
| **IPS** | Intrusion Prevention System（侵入防止） | 攻撃を**検知してブロック** | 防犯カメラ＋自動シャッター |

どちらも、ルールベース（既知パターン）と異常検知（通常と違う行動）の2つのアプローチがある。

### 1.3 SIEM（ログの集約と相関分析）

複数ソースのログを **一か所に集め、関連づけて分析** する仕組み（Splunk、Elastic SIEM、Azure Sentinel など）。

**できること：**
- ログイン失敗が続いた直後に管理者権限が使われた、などの **時系列の関連** を見つける
- ダッシュボードで異常の傾向を可視化する
- アラートルールで自動通知する

**初心者が押さえるポイント：** ログがなければ調査は始まらない。監視設計では「何を・どこまで・どのくらいの期間」残すかが重要。

## 2. マルウェア分析

不審なファイルやプログラムが届いたとき、**中身を調べて危険度と挙動を把握する** 作業。SOC（セキュリティ運用センター）やインシデント対応チームの核心スキルのひとつ。

### 2.1 分析の3つのアプローチ

| 手法 | 別名・関連語 | 何をするか | いつ使うか |
|------|--------------|------------|------------|
| **表層解析** | ベーシック解析、メタデータ解析 | ファイル名、ハッシュ値、ヘッダ情報、文字列など**実行せずに**表面を調べる | まず最初のスクリーニング |
| **静的解析** | Static Analysis | プログラムを**実行せずに**コードや構造を読む | 難読化前のロジック把握、IOC抽出 |
| **動的解析** | Dynamic Analysis | **隔離環境で実際に実行**し、挙動を観察する | 実際の通信先・ファイル改変・レジストリ変更の確認 |

```
表層解析（安全・高速）
    ↓ 怪しければ
静的解析（コードを読む）
    ↓ さらに詳しく
動的解析（サンドボックスで実行）
```

### 2.2 表層解析で見るもの

| 項目 | 説明 | 例 |
|------|------|-----|
| **ハッシュ値** | ファイルの指紋（MD5、SHA-256） | VirusTotal で既知マルウェアと照合 |
| **ファイル形式** | PE（Windows実行ファイル）、ELF、PDF など | 拡張子と実体の不一致は要注意 |
| **文字列** | バイナリ内のURL、IP、コマンド | `http://悪意のあるサイト` の痕跡 |
| **署名・メタデータ** | デジタル署名の有無、作成者情報 | 署名なしの「正規ソフト風」ファイル |

### 2.3 静的解析で見るもの

- どのAPI（Windows API など）を呼んでいるか
- 難読化・パッキング（解析を困難にする圧縮・暗号化）の有無
- 暗号化ルーチン、ネットワーク通信の準備コード

**注意：** 高度なマルウェアは静的解析だけでは見えない部分が多い。動的解析と組み合わせる。

### 2.4 動的解析で見るもの

| 観察対象 | 具体例 |
|----------|--------|
| **ファイルシステム** | 新規ファイル作成、既存ファイルの改ざん |
| **レジストリ**（Windows） | 自動起動設定の追加 |
| **プロセス** | 子プロセスの生成、インジェクション |
| **ネットワーク** | C2サーバー（攻撃者の司令塔）への通信 |
| **メモリ** | 実行時にのみ展開されるペイロード |

**必ずサンドボックス（後述）で行う。** 本番環境や日常PCでの実行は厳禁。

### 2.5 分析の成果物（IOC）

調査結果は **IOC（Indicators of Compromise：侵害指標）** として記録し、組織全体の検知ルールに活かす。

| IOCの種類 | 例 |
|-----------|-----|
| ファイルハッシュ | `SHA-256: abc123...` |
| IPアドレス・ドメイン | マルウェアの通信先 |
| URL | ダウンロード元 |
| レジストリキー・ファイルパス | 感染の痕跡 |

## 3. リバースエンジニアリングの基礎

**プログラムの内部動作を、ソースコードなしに理解する** 技術。マルウェア分析・脆弱性調査・フォレンジックの土台になる。

### 3.1 リバースエンジニアリングとは

通常のソフトウェア開発は「設計 → コーディング → ビルド」だが、リバースエンジニアリングは **逆方向** にたどる。

```
【開発の流れ】  ソースコード → コンパイル → 機械語（バイナリ）
【リバース】    バイナリ → ？？？ → 動作の理解
```

完全に元のソースコードに戻すことは難しいが、**「何をしているか」は十分把握できる** ことが多い。

### 3.2 逆アセンブリと逆コンパイル

| 手法 | 出力 | 読みやすさ | 主なツール例 |
|------|------|------------|--------------|
| **逆アセンブリ** | アセンブリ言語（CPU命令に近い低レベル表現） | 難しいが正確 | Ghidra、IDA Pro、objdump |
| **逆コンパイル** | C言語に近い疑似コード | 読みやすいが推測を含む | Ghidra、IDA Pro、dnSpy（.NET） |

**初心者向けの理解：**
- **逆アセンブリ** ＝ 機械語を1命令ずつ人間が読める形に戻す（精密だが大変）
- **逆コンパイル** ＝ それをさらに高級言語風に推測して表示（概要把握に便利）

マルウェア分析では、まず逆コンパイルで全体像を掴み、重要な部分だけ逆アセンブリで詳しく見る、という使い分けが多い。

### 3.3 デバッガーツール

プログラムを **1ステップずつ実行しながら、メモリやレジスタの状態を観察する** ツール。

| ツール | 主な用途 |
|--------|----------|
| **x64dbg / OllyDbg** | Windowsネイティブバイナリの動的解析 |
| **GDB** | Linuxバイナリのデバッグ |
| **WinDbg** | Windowsカーネル・クラッシュダンプ解析 |
| **dnSpy** | .NET アセンブリのデバッグ・改変 |

**デバッガでできること：**
- 特定の関数がいつ呼ばれるか追跡する
- 暗号化された文字列がメモリ上で復号される瞬間を捉える
- 難読化されたコードの実際の分岐を確認する

**注意：** マルウェアはデバッガ検知（解析環境だと動作を変える）機能を持つことがある。サンドボックスと組み合わせる。

## 4. ネットワークの分析

攻撃の痕跡は **通信の中** に残ることが多い。パケットを読めると、インシデント調査の幅が大きく広がる。

### 4.1 ネットワーク分析で分かること

| 調査内容 | 例 |
|----------|-----|
| **通信相手の特定** | マルウェアが接続したC2サーバーのIP |
| **データ漏洩の検知** | 不審な大量アップロード |
| **攻撃の種類の判別** | ポートスキャン、SQLインジェクションの試行 |
| **タイムラインの再構成** | いつ・誰が・何と通信したか |

### 4.2 主な手法とツール

| 手法 | 説明 | ツール例 |
|------|------|----------|
| **パケットキャプチャ** | ネットワーク上を流れる生データを記録 | Wireshark、tcpdump |
| **フロー分析** | 通信の概要（誰と誰が・いつ・どれだけ）を集計 | NetFlow、sFlow |
| **プロキシ・ファイアウォールログ** | HTTP/HTTPSの宛先、ブロック履歴 | 各種FW、Webプロキシログ |
| **DNSログ** | 名前解決の履歴（マルウェアのドメイン発見に有効） | DNSサーバーログ、Passive DNS |

### 4.3 初心者が覚えるプロトコル

| プロトコル | 役割 | 調査での注目点 |
|------------|------|----------------|
| **TCP / UDP** | 通信の基盤 | ポート番号、接続の開始・終了 |
| **HTTP / HTTPS** | Web通信 | URL、User-Agent、POSTデータ（HTTPSは復号には追加設定が必要） |
| **DNS** | ドメイン名の名前解決 | 不審なドメインへの問い合わせ |
| **SMTP** | メール送信 | フィッシングメールの追跡 |

## 5. メモリフォレンジック

**コンピュータのメモリ（RAM）から証拠を収集・分析する** 手法。ディスク上には残らない情報が、メモリには一時的に存在することが多い。

### 5.1 なぜメモリが重要か

| 理由 | 説明 |
|------|------|
| **ファイルレスマルウェア** | ディスクにファイルを書かず、メモリ上だけで動作 |
| **実行中の状態** | 開いているネットワーク接続、復号されたパスワード、暗号化前のデータ |
| **ルートキットの痕跡** | ディスク上のツールでは見えないプロセスがメモリ解析で露呈することも |

### 5.2 基本的な流れ

```
1. メモリダンプの取得（被害端末・サーバー）
      ↓
2. ダンプファイルの解析
      ↓
3. プロセス一覧、ネットワーク接続、注入コード、マルウェア痕跡の抽出
```

### 5.3 主なツール

| ツール | 用途 |
|--------|------|
| **Volatility / Volatility 3** | メモリダンプ解析の定番フレームワーク |
| **WinPmem / LiME** | Windows / Linux のメモリ取得 |
| **Rekall** | メモリフォレンジック（Volatility の代替） |

### 5.4 メモリ解析で見つかるものの例

- 実行中だったがディスクに痕跡のないマルウェア
- 正規プロセスに注入（インジェクション）された悪意のあるコード
- ブラウザやアプリに残る認証トークン
- 攻撃者が使ったコマンドの履歴（一部）

## 6. サンドボックス環境の構築

マルウェアや不審なプログラムを **安全に隔離して実行・観察する** ための環境。動的解析・リバースエンジニアリングの前提となる。

### 6.1 サンドボックスとは

本番ネットワークや日常PCと **完全に切り離した仮想環境** で、サンプルを実行する仕組み。

```
【本番ネットワーク】  ← 絶対に触らない
        ↑ 物理的・論理的に隔離
【サンドボックス】      ← ここでマルウェアを実行・観察
```

### 6.2 構築のポイント

| 項目 | 内容 |
|------|------|
| **仮想化** | VirtualBox、VMware、Hyper-V などで隔離VMを用意 |
| **スナップショット** | 解析前の状態にいつでも戻せるようにする |
| **ネットワーク隔離** | インターネット接続は制御（完全遮断 or 偽C2への誘導） |
| **監視ツールの組み込み** | Process Monitor、Wireshark、APIモニタなど |
| **使い捨て運用** | 1サンプルごとにVMを破棄・再構築する |

### 6.3 商用・オープンソースのサンドボックス

| 種類 | 例 | 特徴 |
|------|-----|------|
| **オンラインサービス** | VirusTotal、Any.Run、Hybrid Analysis | 手軽だが機密ファイルには注意 |
| **自社構築** | Cuckoo Sandbox | カスタマイズ可能、内部向け |

**注意：** 社外のオンラインサンドボックスにアップロードすると、サンプルが第三者に共有される場合がある。機密性の高いファイルは自社サンドボックスを使う。

## 7. 暗号技術（分析の視点）

暗号は「防御」だけでなく、マルウェア分析でも頻出する。**暗号化・難読化・ハッシュ** の違いを押さえておく。

### 7.1 分析で遭遇する暗号の使われ方

| 用途 | 攻撃者側の使い方 | 分析者の対応 |
|------|------------------|--------------|
| **ハッシュ** | パスワードの保存、ファイルの整合性確認 | レインボーテーブル、辞書攻撃で照合 |
| **対称暗号（AES等）** | 通信の暗号化、ランサムウェアのファイル暗号化 | 鍵の奪取、既知の弱点、メモリ上の平文を捕捉 |
| **非対称暗号（RSA等）** | 鍵交換、署名 | 鍵長・実装の確認 |
| **難読化** | コードや文字列の読み取りを困難に | アンパック、動的解析で復号タイミングを捕捉 |
| **エンコード（Base64等）** | 単純な隠蔽（暗号ではない） | デコードするだけで読めることも |

### 7.2 分析者が知っておくべき基本用語

| 用語 | 意味 |
|------|------|
| **平文（plaintext）** | 暗号化前の読めるデータ |
| **暗号文（ciphertext）** | 暗号化後のデータ |
| **鍵（key）** | 暗号化・復号に使う秘密情報 |
| **ソルト（salt）** | パスワードハッシュに加えるランダム値（レインボーテーブル対策） |
| **デジタル署名** | 改ざん検知と送信者認証 |

### 7.3 暗号とセキュリティの原則

- **暗号化されていても、鍵や平文がメモリにあれば奪われうる**
- **HTTPSは通信の盗聴を防ぐが、マルウェア自体は配信されうる**
- 分析では「どの暗号が・どこで・いつ使われるか」を追う

## 8. 攻撃手法の理解（防御・分析のため）

セキュリティエンジニアは攻撃を「実行する」ためではなく、**検知・防御・調査するために攻撃手法を理解する** 必要がある。第1章の脅威を、分析者の視点で見直す。

### 8.1 攻撃のライフサイクル（Kill Chain）

攻撃は一度の操作で終わらず、段階を踏む。各段階で防御・検知のポイントがある。

```
1. 偵察（Reconnaissance）     … 標的の情報収集
2. 武器化（Weaponization）    … マルウェアや攻撃ツールの準備
3. 配送（Delivery）           … メール添付、悪意のあるURL
4. 悪用（Exploitation）       … 脆弱性の突き破り
5. インストール（Installation）… マルウェアの常駐
6. C2（Command & Control）    … 攻撃者との通信確立
7. 目的達成（Actions）        … データ窃取、破壊、横展開
```

**監視の設計：** どの段階でログやアラートが取れるかを意識する。

### 8.2 分析者が重点的に追う攻撃手法

| 攻撃手法 | 分析での注目点 |
|----------|----------------|
| **フィッシング＋添付ファイル** | メールヘッダ、添付のハッシュ、URL |
| **エクスプロイト（脆弱性悪用）** | どのCVEか、対象ソフトのバージョン |
| **ラテラルムーブメント（横展開）** | 侵害後、他システムへの移動経路 |
| **権限昇格** | 一般ユーザーから管理者権限への奪取 |
| **データ流出（Exfiltration）** | 大量通信、クラウドストレージへのアップロード |
| **永続化（Persistence）** | 再起動後も残る仕組み（レジストリ、タスクスケジューラ等） |

### 8.3 MITRE ATT&CK フレームワーク

攻撃手法を **戦術（Tactic）** と **技術（Technique）** に体系化した知識ベース。SOC設計や脅威ハンティングで広く使われる。

- 例：戦術「初期侵入（Initial Access）」→ 技術「フィッシング（T1566）」
- 自組織のログと照らし、「この技術の痕跡は取れているか」を確認するのに有用

> 詳細は [MITRE ATT&CK](https://attack.mitre.org/) を参照。

## 9. 技術の全体マップ（整理）

```
【監視フェーズ】
  ネットワーク監視 ─┬─ トラフィック分析（Wireshark、NetFlow）
  ログ分析 ─────────┼─ SIEM、IDS/IPS
  エンドポイント監視 ┴─ EDR、アンチウイルス

【分析フェーズ】
  マルウェア分析 ────┬─ 表層解析 → 静的解析 → 動的解析
  リバースエンジニアリング ├─ 逆アセンブリ / 逆コンパイル（Ghidra等）
                     └─ デバッガ（x64dbg、GDB等）
  ネットワーク分析 ─── パケットキャプチャ、DNS/プロキシログ
  メモリフォレンジック ─ Volatility 等
  暗号の理解 ───────── 難読化・通信暗号・ハッシュの識別

【基盤】
  サンドボックス環境 ─ 隔離VM、スナップショット、使い捨て運用
  攻撃手法の知識 ──── Kill Chain、MITRE ATT&CK
```

## 10. 典型的なインシデント調査の流れ

初心者が「全体の流れ」をイメージするための例。

```
1. アラート発生（SIEM / EDR / ユーザー報告）
      ↓
2. 初期トリアージ
   - 影響範囲は？ 緊急度は？
   - 表層解析（ハッシュ、VirusTotal）
      ↓
3. 封じ込め
   - 感染端末のネットワーク隔離
   - 侵害アカウントの無効化
      ↓
4. 詳細分析
   - 動的解析（サンドボックス）
   - ログ・ネットワーク・メモリの調査
   - IOC の抽出
      ↓
5. 根絶・復旧
   - マルウェア除去、パッチ適用
   - 侵害アカウントのパスワード変更
      ↓
6. 事後対応
   - 検知ルールの追加（IOCベース）
   - 再発防止策の文書化
```

## 11. この章のまとめ

| 覚えておくこと | 内容 |
|----------------|------|
| 監視がなければ分析は始まらない | ログ設計・保持期間は投資対象 |
| マルウェア分析は段階的に | 表層 → 静的 → 動的の順で安全に進める |
| リバースエンジニアリングは土台 | 逆アセンブリ・デバッガは深掘りの武器 |
