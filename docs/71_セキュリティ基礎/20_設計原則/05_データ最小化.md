# データ最小化（Data Minimization）

## はじめに

**データ最小化**とは、

> **「必要なデータだけを、必要な期間だけ持つ」**

という原則です。GDPR の基本原則のひとつで、日本の個人情報保護法でも「利用目的の達成に必要な範囲」での取り扱いと、不要になったデータの消去（努力義務）が定められています。

### 一言でいうと

> 「**持っていないデータは漏れない**」

[[01_最小権限の原則]] が「権限」を絞るのに対し、データ最小化は **攻撃者が手にできるデータそのもの** を絞ります。

---

## なぜ重要なのか

2026年の国内の情報漏洩では、**持ち続けていたデータ** が被害を大きくした例が目立ちました。

| 事例 | 持ちすぎていたもの |
|---|---|
| KDDI ISP向けメール基盤 | **解約済みユーザー** の情報も残っていた |
| タイムズカー | **運転免許証などの画像** 約160万件。パスワードと違い、本人が変更できない |
| 米国防総省 DMDC（海外） | **暗号化していない** 個人情報をファイル共有システムに置いていた |
| 各種会員システム | 退会者を **論理削除**（`deleted_at` を立てるだけ）のまま残していた例が指摘されている |

パスワードは漏れても変えられますが、**氏名・生年月日・免許証の画像・口座番号は変えられません**。漏れたときの被害は長く続きます。

---

## データ最小化の4つの観点

### 1. 集めない（収集の最小化）

- 入力フォームの各項目に「何に使うのか」を答えられるか確かめる
- 年齢確認なら生年月日ではなく「18歳以上か」だけで足りることもある

### 2. 持たない（保存の最小化）

- **カード情報**：決済代行会社のトークンだけを持つ（PCI DSS の対象範囲も小さくなる）
- **本人確認書類**：eKYC 事業者に確認を任せ、結果（確認済みフラグ・日時）だけを持つ。画像が必要なら、確認が終わったら削除する
- **ログ**：個人情報や秘密を書かない（[[03_ログに書くこと・書かないこと]]）

### 3. 期限を決めて消す（保存期間の最小化）

- データの種類ごとに **保存期間** を決める（例：退会者は法定保存期間を過ぎたら削除、申込み途中のデータは 30 日で削除）
- **論理削除ではなく物理削除**。論理削除はアプリから見えないだけで、DB を盗まれれば全部読める
- バックアップやデータウェアハウス、ログ基盤にあるコピーも対象にする

### 4. 分ける・隠す（アクセスの最小化）

- 機密度の高いデータ（本人確認書類・口座情報）は **会員 DB と別の保管場所** に置き、アクセスできるサービスを限る
- 項目単位で暗号化する（[[A02_暗号化の不備]]）
- 分析用には **仮名化・マスキング** したデータを使う。本番データをテスト環境にコピーしない

## 実装例

### 保存期間を過ぎたデータの削除バッチ

```sql
-- 退会から 1 年たったユーザーを物理削除する（関連テーブルは ON DELETE CASCADE）
DELETE FROM users
WHERE withdrawn_at IS NOT NULL
  AND withdrawn_at < NOW() - INTERVAL '1 year';

-- 申込みを途中でやめたデータは 30 日で削除する
DELETE FROM applications
WHERE status = 'draft'
  AND updated_at < NOW() - INTERVAL '30 days';
```

- 毎日のジョブとして実行し、削除件数をメトリクスとして記録する
- 大きなテーブルは日付で **パーティション分割** し、古いパーティションごと `DROP` すると速い
- S3 などのオブジェクトストレージは **ライフサイクルルール** で自動削除できる

### 本人確認書類を会員 DB に置かない

```
❌ users テーブルに license_image_url があり、会員 API と同じ権限で読める
✅ 確認は eKYC 事業者に任せ、users には kyc_verified_at だけを持つ
✅ 画像を残す必要があるなら、別アカウントの暗号化ストレージに置き、
   参照できるのは審査サービスだけにする。審査が終わったら削除する
```

## アンチパターン

1. **「いつか分析に使うかも」で全部残す**：使われないまま、攻撃者に価値のあるデータがたまっていく
2. **論理削除で消したつもり**：`deleted_at` が立っていても、DB を盗まれれば全部読める
3. **本番データをテスト環境にコピー**：テスト環境は本番より守りが弱いことが多い
4. **バックアップだけ永久保存**：本番から消してもバックアップに残っている

## まとめ

- データ最小化は **「持っていないデータは漏れない」**
- **集めない・持たない・期限を決めて消す・分ける** の4つで考える
- **論理削除では消したことにならない**
- 本人確認書類のような **変更できない情報** ほど持たない設計にする
