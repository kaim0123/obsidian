# アタックツリー — 攻撃経路の可視化

## はじめに

**アタックツリー**（Attack Tree）とは、**攻撃者が最終目的を達成するための経路** を木構造で可視化する手法です。暗号学者 Bruce Schneier が1999年に提唱しました。

### 一言でいうと

> 「**攻撃者の"If this, then that"** を木に書き出す」

STRIDE が「どんな脅威カテゴリがあるか」を網羅的に洗い出すのに対して、アタックツリーは **1つの攻撃目標を、どうやって達成できるか** を深掘りします。

---

## 基本構造

### 根ノード = 攻撃者の最終目標

```
          [金庫を開ける]
```

「攻撃者は何を達成したいか？」を頂点に置きます。

### 中間・葉ノード = 達成方法

その下に、**目標を達成する方法** をぶら下げていきます。

```
              [金庫を開ける]
            /       |        \
     [鍵を入手]  [暗証番号を知る]  [金庫を壊す]
       / \          / | \            |
   [盗む][複製] [盗聴][推測][買収]  [爆破]
```

さらに深く展開すると、葉（leaf）は **「具体的な攻撃アクション」** になります。

---

## AND / OR ノード

アタックツリーの枝には、2種類の結合があります。

### OR ノード（デフォルト）

子ノードのうち **どれか1つ** が成功すれば、親ノードも成功。

```
[金庫を開ける] ← OR
 ├─ [鍵を入手]
 ├─ [暗証番号を知る]
 └─ [金庫を壊す]
```

攻撃者は最も簡単な方法を選べます。

### AND ノード

子ノードの **すべて** が成功して初めて、親ノードが成功。

```
[2要素認証を突破] ← AND
 ├─ [パスワードを入手]
 └─ [スマホを入手]
```

どれか1つでも防げれば、親ノードの攻撃は成立しません。

図では「AND」の文字やアーク（円弧）で明示することが多いです。

---

## 各ノードに属性を付ける

ノードに **属性**（コスト、成功確率、所要時間、法的リスク等）を付けると、より定量的に議論できます。

```
[鍵を複製]
  - コスト: $500
  - 成功確率: 40%
  - 所要時間: 1日
  - 必要スキル: 錠前師レベル
```

### 属性の例

| 属性 | 意味 |
|------|------|
| **可能/不可能** | 技術的・物理的に実行可能か |
| **コスト** | 攻撃に必要な費用 |
| **スキル** | 要求される専門知識レベル |
| **時間** | 準備〜実行の所要時間 |
| **検知確率** | 防御側に気付かれる可能性 |
| **法的リスク** | 逮捕される可能性 |

---

## 属性の親ノードへの伝播

子の値から、親の値を自動計算できます。

### OR ノードの場合

- **最小コスト**: 子の中で最も安い方法のコスト
- **最大成功確率**: 子の中で最も成功しやすい方法の確率
- **可能/不可能**: どれか1つでも可能なら親も可能

### AND ノードの場合

- **合計コスト**: 子のコストの合計
- **最小成功確率**: 子の確率の積
- **可能/不可能**: すべて可能なら親も可能

### 例

```
[金庫を開ける]  OR
 ├─ [鍵を入手]      コスト $500
 ├─ [暗証番号を知る] コスト $1,000
 └─ [金庫を壊す]    コスト $200  ← 最安

→ 親のコスト: $200（最小値）
```

攻撃者は **最小コスト経路** を選ぶと想定するのが基本。

## アプリケーションの例

### 例: Web アプリの管理者アカウント奪取

```
[管理者アカウントに侵入]  OR
├─ [パスワードを入手]  OR
│   ├─ [総当たり攻撃]         レート制限あり: 低確率
│   ├─ [フィッシング]         中確率
│   ├─ [パスワードリスト攻撃] MFAで無効化
│   └─ [メモを盗む]          物理的アクセス必要
│
├─ [セッションを盗む]  OR
│   ├─ [XSS]                  CSP で緩和
│   ├─ [MITM]                 HTTPSで緩和
│   └─ [Cookie盗難]           HttpOnlyで緩和
│
├─ [2FA を回避]  AND  （MFA有効時）
│   ├─ [パスワードを入手]
│   └─ [TOTP トークンを入手]  SMS swap 等
│
└─ [脆弱性悪用]  OR
    ├─ [SQLi で認証回避]       パラメタ化クエリで緩和
    ├─ [権限昇格バグ]         認可テストで緩和
    └─ [依存ライブラリの CVE]  Dependabot で緩和
```

この木を見ると:

- **どの経路が「最弱」か** が見える（最も安い、最も速い経路が攻撃者に選ばれる）
- **AND ノード** を作ると攻撃コストが跳ね上がる（MFAの効果がわかる）
- **既存の対策がどこに効くか** をマッピングできる

## 使い方のステップ

### Step 1: 守りたいもの・攻撃者の目標を明確化

「何が最悪か」を1文で書く。複数あるなら、**目標ごとに別ツリー** を作ります。

例:
- 顧客データが漏洩する
- 全サービスが停止する
- 不正送金される

### Step 2: 最上位の攻撃方法を列挙（第1階層）

「この目標を達成する方法は、大きく分けて何がある？」をブレインストーミング。5〜10個くらい。

### Step 3: 各方法を細分化

各ノードに対して「どうやって？」を繰り返し、具体的な攻撃アクションまで掘り下げます。

### Step 4: 属性を付けて評価

コスト、成功確率、対策の有無などを記載。

### Step 5: 弱い経路を特定 → 対策強化

- **最小コスト経路** は？ ここを最優先で潰す
- **AND化** できないか？（複数要素を要求する）
- **既存対策** で防げる経路はどれ？ 防げない経路はどれ？

---

## アタックツリーの強み・弱み

### 強み

- **攻撃者視点** で考えられる
- 防御策がどの経路に効くか、**対応づけが明確**
- **非技術者にも説明しやすい** 図
- 「最小コスト経路を潰せば攻撃者を脱落させられる」という **合理的な判断** ができる

### 弱み

- **網羅性の保証がない**（思いつかない攻撃は書けない）
- 属性の見積もりが **主観的**
- 大規模システムだとツリーが巨大化
- 定期メンテナンスが必要（新しい攻撃手法は日々増える）

## STRIDE との使い分け

| | STRIDE | アタックツリー |
|---|--------|---------------|
| 観点 | ボトムアップ（部品から脅威へ） | トップダウン（目標から経路へ） |
| 強み | 網羅性 | 深さ、攻撃者視点 |
| 用途 | 一般的な脅威チェック | 特定目標の徹底分析 |
| 規模 | コンポーネントごと | 重要な攻撃目標ごと |

**併用** が効果的です。まず STRIDE で広く脅威を洗い出し、その中で特に重要な脅威を **アタックツリーで深掘り** する、という流れ。

## 実践のコツ

### 1. 小さく始める

最初から完璧な木を描こうとしない。**主要な経路3〜5本** で十分。

### 2. 攻撃者のペルソナを設定

- **外部攻撃者**（匿名、ツール利用者）
- **組織犯罪グループ**（リソース豊富）
- **国家レベル**（無制限リソース）
- **内部犯**（認証情報・権限あり）

ペルソナによって現実的な経路が変わります。

### 3. 既知の攻撃パターンを参考に

- **MITRE ATT&CK**（攻撃手法の体系化されたデータベース）
- **Kill Chain モデル**（偵察→武器化→配送→攻撃実行→インストール→C2→目的達成）
- 過去のインシデント事例

### 4. 対策マッピング

各ノードに「この対策が効く」とタグ付け。対策の投資対効果を議論しやすくなる。

## まとめ

- アタックツリーは **攻撃者の目標 → 経路** をトップダウンに可視化する手法
- **AND / OR ノード** で攻撃経路の論理を表現
- **属性**（コスト、確率等）で定量評価し、最弱経路を特定
- **STRIDE と併用** すると、幅と深さの両方を確保できる
- 対策の投資判断・非技術者への説明にも役立つ
