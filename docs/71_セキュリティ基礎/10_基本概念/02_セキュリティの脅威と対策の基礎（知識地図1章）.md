# 第1章：セキュリティの脅威と対策の基礎

この章では、セキュリティエンジニアが最初に押さえるべき「脅威」と「脆弱性」の全体像を整理する。用語の羅列ではなく、**何が起きるのか・なぜ危険なのか・どう防ぐのか**の順で理解できるようにまとめた。

---

## 1. 脅威とは何か

**脅威（Threat）** とは、システムや情報に害を与えようとする行為や主体のこと。相手は必ずしも外部のハッカーとは限らず、設定ミスや古いソフトウェアなど、**意図しない形で生まれる弱点**も攻撃の入口になる。

大きく分けると次の2つがセットで考える。

| 概念 | 意味 | 例 |
|------|------|-----|
| **脅威** | 攻撃そのもの、または攻撃者 | マルウェア、フィッシング、内部犯行 |
| **脆弱性** | 攻撃が成功しやすい弱点 | 未修正のバグ、弱いパスワード、設定ミス |

> 脅威 × 脆弱性 → インシデント（被害）が起きる、という関係を覚えておく。

---

## 2. 技術的脅威の概要

コンピュータやネットワークを直接狙う代表的な攻撃。

### 2.1 マルウェア（Malware）

**悪意のあるソフトウェア**の総称。ユーザーが気づかないうちにインストールされ、情報窃取・破壊・遠隔操作などを行う。

| 種類 | 概要 | 特徴 |
|------|------|------|
| **ウイルス** | 他のプログラムに寄生して増殖 | 実行ファイルへの感染が典型 |
| **ワーム** | ネットワーク経由で単独に拡散 | 人の操作なしに広がる |
| **トロイの木馬** | 正規ソフトのふりをして侵入 | バックドア設置などに使われる |
| **ランサムウェア** | データを暗号化して身代金を要求 | 企業被害が増加傾向 |
| **スパイウェア** | 行動をこっそり監視・収集 | キーロガーを含むことも |
| **アドウェア** | 不要な広告を表示 | 他のマルウェアの入口にも |
| **ルートキット** | OSの深部に潜んで検知を回避 | 除去が難しい |
| **ボットネット** | 感染端末を遠隔操作するネットワーク | DDoS攻撃の実行元になりやすい |
| **キーロガー** | キーボード入力を記録 | パスワード窃取に直結 |

**主な感染経路：** 添付ファイル付きメール、不正なダウンロード、脆弱なソフトウェア、USBメディア

**対策の基本：** ウイルス対策ソフト、OS・アプリの更新、不審なリンク・添付を開かない、最小権限の原則

---

### 2.2 ハッキング（不正侵入）

許可なくシステムやネットワークに**侵入し、データを盗んだり操作したりする行為**。

- **外部からの侵入：** 公開サーバーの脆弱性、弱い認証情報の悪用
- **内部からの不正：** 権限のあるアカウントの悪用、退職者アカウントの放置

**対策の基本：** パッチ管理、多要素認証（MFA）、アクセス権限の最小化、ログ監視

---

### 2.3 DDoS攻撃（Distributed Denial of Service）

多数の端末から**同時に大量のリクエストを送り、サービスを利用不能にする攻撃**。「可用性（Availability）」を狙う。

- 例：ECサイトがアクセス不能になり売上損失、政府サイトの停止
- ボットネットを使った大規模攻撃が多い

**対策の基本：** CDN・DDoS緩和サービス、レート制限、冗長構成、インシデント対応計画

---

### 2.4 フィッシング（Phishing）※概要

**正規の連絡を装って、パスワードや個人情報を騙し取る**手法。技術的脅威というより「人を騙す」攻撃だが、最も頻度が高い入口のひとつ。

詳細は [[#5. フィッシングの種類]] を参照。

---

## 3. 脆弱性（Vulnerability）

システムや運用の**設計・実装・設定上の弱点**。攻撃者がここを突く。

### 3.1 ソフトウェア・アーキテクチャの脆弱性

| 種類 | 説明 |
|------|------|
| **未パッチの既知脆弱性** | 修正プログラムは出ているが、適用されていない状態（CVE などで公開される） |
| **ゼロデイ脆弱性** | まだ修正がなく、攻撃に使われ始めている未知の弱点 |
| **不適切な設計** | 最初からセキュリティを考慮していない構成（例：平文でパスワード保存） |
| **セキュリティコントロールの欠如** | 認証・暗号化・ログなど、必要な防御が実装されていない |

**ハードウェア・低レイヤー系：**

| 種類 | 説明 |
|------|------|
| **CPUの脆弱性** | Spectre、Meltdown など、プロセッサ設計に起因する問題 |
| **ファームウェアの脆弱性** | BIOS/UEFI など、OSより下の層の弱点。更新が難しく影響が大きい |

**アプリケーション実装の典型：**

| 種類 | 説明 |
|------|------|
| **バッファオーバーフロー** | 想定より多くのデータを書き込み、メモリを破壊して任意コード実行につながる |
| **コマンドインジェクション** | ユーザー入力がOSコマンドに混ざり、サーバー上でコマンドが実行される |

---

### 3.2 設定ミスによる脆弱性

ソフトウェア自体にバグがなくても、**運用設定の誤り**で穴が開く。クラウド環境では特に多い。

| 設定ミス | リスク |
|----------|--------|
| **不適切なアクセス権限** | 必要以上の人・サービスがデータに触れる |
| **過剰な権限設定** | 侵害された1アカウントから全体が乗っ取られる |
| **暗号化の不備** | 通信や保存データが平文のまま漏洩する |
| **不要なサービスの有効化** | 使っていないポートや機能が攻撃面を広げる |
| **セキュリティ機能の無効化** | ファイアウォール、ログ、MFA などをオフにしたまま運用 |

**対策の基本：** セキュリティベースライン、設定の定期監査、Infrastructure as Code による標準化

---

### 3.3 Webアプリケーションの脆弱性

ブラウザ経由で攻撃される代表的な弱点（OWASP Top 10 などで整理されている）。

| 脆弱性 | 概要 | 被害の例 |
|--------|------|----------|
| **SQLインジェクション** | SQL文に悪意のある入力を混ぜる | データベース全体の漏洩・改ざん |
| **クロスサイトスクリプティング（XSS）** | 他ユーザーのブラウザで悪意のあるスクリプトを実行 | セッション窃取、フィッシング表示 |
| **クロスサイトリクエストフォージェリ（CSRF）** | ログイン中のユーザーに意図しない操作をさせる | 送金、設定変更 |
| **セッションハイジャック** | 他人のセッションIDを奪ってなりすます | アカウント乗っ取り |
| **ディレクトリトラバーサル** | `../` などで本来アクセス不可のファイルを読む | 設定ファイル・ソースコード漏洩 |
| **オープンリダイレクト** | 任意の外部URLへ誘導する脆弱なリダイレクト | フィッシングサイトへの誘導 |

**対策の基本：** 入力値の検証・エスケープ、パラメータ化クエリ、CSRFトークン、セキュアなセッション管理

---

### 3.4 サプライチェーン攻撃

自社が直接書いていない**外部の部品・ライブラリ・ツール**を経由した攻撃。

| 攻撃の形 | 説明 |
|----------|------|
| **依存ライブラリの脆弱性** | npm、PyPI などの古い・脆弱なパッケージを利用 |
| **OSSの脆弱性** | オープンソースの既知脆弱性が未修正のまま本番利用 |
| **パッケージのハイジャック** | 正規パッケージ名に似せた悪意のあるパッケージを公開 |
| **バージョン汚染** | 依存関係の解決ミスで意図しない（危険な）版が入る |

**対策の基本：** SBOM（ソフトウェア部品表）の管理、依存関係の定期スキャン、信頼できるレジストリのみ利用

---

## 4. 認証情報を狙う攻撃

パスワードやログイン情報は、多くの攻撃の「鍵」になる。

### 4.1 パスワードに対する攻撃

| 攻撃 | 仕組み | 対策のヒント |
|------|--------|--------------|
| **ブルートフォース** | 全パターンを総当たり | アカウントロック、レート制限 |
| **辞書攻撃** | よく使われるパスワードリストで試行 | 複雑なパスワード、パスワードマネージャ |
| **パスワードスプレー** | 少数のよくあるパスワードを多数アカウントに試す | MFA、ログ監視 |
| **クレデンシャルスタッフィング** | 他サイトで漏洩したID/パスワードの使い回しを試す | MFA、漏洩パスワードの検知 |
| **リプレイ攻撃** | 傍受した認証情報をそのまま再利用 | ワンタイムパスワード、タイムスタンプ |
| **レインボーテーブル** | ハッシュの事前計算表でパスワードを逆算 | ソルト付きハッシュ（bcrypt 等） |
| **キーロギング** | 入力を記録するマルウェア | 端末保護、MFA |
| **ショルダーハック** | 肩越しにパスワード入力を覗き見 | 画面の向き、プライバシーフィルター |

---

### 4.2 なりすまし（スプーフィング）

**送信元や通信相手を偽装**して、相手を騙す手法。

| 種類 | 説明 |
|------|------|
| **メールスプーフィング** | 送信者アドレスを偽装（From の改ざん） |
| **DNSスプーフィング** | DNS応答を偽造し、偽サイトへ誘導 |
| **セッションハイジャック** | 正規ユーザーのセッションを奪って本人になりすます |

**対策の基本：** SPF/DKIM/DMARC（メール認証）、HTTPS、セキュアなCookie設定、短いセッション有効期限

---

## 5. フィッシングの種類

人間の心理を利用する攻撃。種類ごとに入口が異なる。

| 種類 | 概要 | 例 |
|------|------|-----|
| **メールフィッシング** | 大量の不特定宛メール | 「荷物の確認」「口座確認」 |
| **スピアフィッシング** | 特定の個人・組織を狙った精密なメール | 役職者を名指しした偽メール |
| **SMSフィッシング（スミッシング）** | ショートメッセージ経由 | 偽の配送通知リンク |
| **ボイスフィッシング（ヴィッシング）** | 電話で個人情報を聞き出す | 偽の銀行・サポート窓口 |
| **フォーミング** | 偽のWebフォームで情報収集 | 偽ログインページ |
| **QRコードフィッシング** | QRコードでフィッシングサイトへ誘導 | 駐車場・イベントの偽QR |

**共通の対策：** URLを直接クリックしない、公式アプリ・ブックマークからアクセス、不審な連絡は別経路で確認

---

## 6. ソーシャルエンジニアリング

**人の信頼や心理を操作して、情報やアクセス権を引き出す**手法。フィッシングと重なる部分も多い。

| 手法 | 説明 |
|------|------|
| **プリテキスティング** | 事前に標的について調査し、信頼できるふりをする |
| **ベイト攻撃** | 無料ソフト、USBメモリなど「おいしい餌」で感染させる |
| **ビジネスメール詐欺（BEC）** | 経営者や取引先を装い、送金や情報開示を要求 |
| **ウォーターホール攻撃** | 標的がよく訪れるサイトを侵害し、そこから感染させる |

**対策の基本：** セキュリティ教育、送金・機密開示の二重確認プロセス、異常な依頼は電話など別チャネルで確認

---

## 7. 脅威の全体マップ（整理）

```
【技術的脅威】
  ├─ マルウェア（ウイルス、ワーム、ランサムウェア…）
  ├─ ハッキング（不正侵入）
  └─ DDoS（サービス停止）

【弱点（脆弱性）】
  ├─ ソフトウェア・アーキテクチャ（未パッチ、ゼロデイ、設計不備）
  ├─ ハードウェア・低レイヤー（CPU、ファームウェア）
  ├─ 実装バグ（バッファオーバーフロー、コマンドインジェクション）
  ├─ 設定ミス（権限、暗号化、不要サービス）
  ├─ Webアプリ（SQLi、XSS、CSRF…）
  └─ サプライチェーン（依存ライブラリ、パッケージ改ざん）

【人を狙う攻撃】
  ├─ フィッシング（各種）
  ├─ ソーシャルエンジニアリング
  ├─ パスワード攻撃
  └─ なりすまし（スプーフィング）
```

## 8. セキュリティアーキテクチャの実装（対策の柱）

脅威を理解したうえで、組織・システムに**防御の仕組み**を組み込む。

### 8.1 セキュリティ技術の導入と管理

| 技術 | 役割 |
|------|------|
| **ファイアウォール** | 許可された通信だけを通し、境界を守る |
| **IDS/IPS（侵入検知・防止）** | 不審な通信や攻撃パターンを検知・ブロック |
| **エンドポイント保護（EDR）** | PC・サーバー上のマルウェアや異常動作を検知 |

運用では、ルールの定期見直し、ログの集約、インシデント時の連携が重要。

---

### 8.2 暗号化の実装

| 対象 | 目的 |
|------|------|
| **通信の暗号化（TLS）** | ネットワーク上の盗聴を防ぐ |
| **保存データの暗号化** | ディスク紛失・漏洩時の情報保護 |
| **鍵管理** | 暗号化の強度は鍵の管理品質に依存 |

暗号化だけでは不十分。**誰が復号できるか（アクセス制御）** もセットで設計する。

---

### 8.3 脆弱性管理

継続的なプロセスとして運用する。

1. **資産の把握** — 何がネットワークに繋がっているか
2. **スキャン・評価** — 既知脆弱性の検出、重要度の判定
3. **パッチ適用・緩和** — 修正できない場合は回避策（WAF、ネットワーク分離など）
4. **検証** — 修正後の再テスト
5. **記録・報告** — 対応履歴と残リスクの可視化

---

## 9. この章のまとめ

| 覚えておくこと | 内容 |
|----------------|------|
| 脅威と脆弱性はセット | 攻撃手法と、それが成功する弱点の両方を見る |
| 技術と人の両方 | マルウェア対策だけではフィッシングは防げない |
| 防御は多層で | ファイアウォール＋パッチ＋教育＋監視の組み合わせ |
| 継続が前提 | 一度設定したら終わりではなく、更新・監査が必要 |

次の章では、これらの脅威に対応する**具体的なフレームワークや役割分担**（リスク管理、コンプライアンスなど）に進むと理解が深まる。
