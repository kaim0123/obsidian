# 安全なWebアプリケーションの作り方（第4章）

## インジェクション系脆弱性

| 脆弱性名 | インターフェース | 悪用手口 |
|---------|----------------|---------|
| クロスサイトスクリプティング | HTML | JavaScript の注入 |
| HTTPヘッダインジェクション | HTTP | HTTPレスポンスヘッダの注入 |
| SQLインジェクション | SQL | SQL文の注入 |
| OSコマンド | シェルスクリプト | コマンドの注入 |
| メールヘッダインジェクション | Sendmailコマンド | メールヘッダ・本文の注入 |

---

## 🔄 アプリの「入力‐処理‐出力」モデル

Webアプリケーションは、大きく **入力 → 処理 → 出力** の3段階で動作します。インジェクション系の脆弱性は、この流れのどこかで **外部からのデータが意図しない形で使われる** ときに起きます。

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│  入力   │ ──→ │  処理   │ ──→ │  出力   │
│ Input   │     │ Process │     │ Output  │
└─────────┘     └─────────┘     └─────────┘
```

### 各段階の例

| 段階 | 具体例 |
|------|--------|
| **入力** | フォーム送信、URLパラメータ、Cookie、HTTPヘッダ、ファイルアップロード |
| **処理** | 入力値の検証、DB検索、計算、メール送信、シェルコマンド実行 |
| **出力** | HTMLページ表示、JSONレスポンス、HTTPヘッダ、メール本文 |

### インジェクションとの関係

| 段階 | 起きやすい問題 | 例 |
|------|--------------|-----|
| **入力** | 不正なデータを受け入れる | `<script>` タグ、SQL断片、改行コード |
| **処理** | 入力をそのまま命令に混ぜる | SQL文への連結、シェルコマンドへの連結 |
| **出力** | エスケープせずに表示 | XSS（HTMLへのそのまま出力） |

### 防御の基本方針

```
入力  → 検証・正規化（ここで不正データを弾く）
処理  → パラメータ化・安全なAPI（命令とデータを分離）
出力  → エスケープ（表示先に合わせて変換）
```

**重要:** 入力値検証だけでは不十分です。処理と出力でも、それぞれ適切な対策が必要です。

---

## 📥 入力値に対して

ユーザーから送られてくるデータ（入力値）は、**常に信頼できない** 前提で扱います。処理に渡す前に、次の3つのステップを順に行います。

```
1. 文字エンコーディングの妥当性検証
        ↓
2. 文字エンコーディングの変換
        ↓
3. 入力値の妥当性検証
        ↓
   処理へ渡す
```

---

## 🔤 文字エンコーディングの妥当性検証

**文字エンコーディング** とは、文字をコンピュータが扱えるバイト列に変換する方式のことです。Webでは **UTF-8** が標準です。

### なぜ検証が必要か

| 問題 | 説明 |
|------|------|
| **文字化け** | 想定外のエンコーディングで解釈すると文字が壊れる |
| **エンコーディング攻撃** | 同じ文字列でも解釈を変えてフィルタをすり抜ける |
| **不正バイト列** | UTF-8として解釈できないデータが混入する |

### 検証の内容

- 受け取ったデータが **UTF-8として正しいか** を確認する
- 不正なバイト列が含まれていれば **拒否または除去** する
- 複数のエンコーディング（Shift_JIS、EUC-JP 等）を受け付ける場合は、**先に統一形式に変換** する

```javascript
// Node.js の例：UTF-8 として妥当かチェック
function isValidUtf8(buffer) {
  try {
    const decoder = new TextDecoder('utf-8', { fatal: true });
    decoder.decode(buffer);
    return true;
  } catch {
    return false;  // 不正な UTF-8
  }
}
```

---

## 🔁 文字エンコーディングの変換

検証のあと、システム内部で使う **統一のエンコーディング（通常は UTF-8）** に変換します。

### 変換が必要な場面

| 場面 | 例 |
|------|-----|
| レガシーシステム連携 | Shift_JIS のファイルを UTF-8 に変換 |
| ブラウザからの送信 | `application/x-www-form-urlencoded` のデコード |
| ファイルアップロード | CSV（CP932）を UTF-8 に読み替え |

### 注意点

- **変換前後で文字が失われないか** 確認する（「髙」など機種依存文字）
- 変換後に **再度バリデーション** を行う（変換で想定外の文字が生じる場合がある）
- エンコーディングを **推測で決め打ちしない**（可能なら明示的に指定）

```javascript
// iconv-lite 等で Shift_JIS → UTF-8 に変換する例
const iconv = require('iconv-lite');
const utf8String = iconv.decode(shiftJisBuffer, 'Shift_JIS');
```

## ✅ 入力値の妥当性検証

エンコーディングを整えたうえで、**ビジネスルールに沿っているか** を検証します。「この値はアプリとして受け入れてよいか？」を判断する段階です。

### ホワイトリスト vs ブラックリスト

| 方式 | 考え方 | 評価 |
|------|--------|------|
| **ホワイトリスト** | 許可する形式・値だけを定義 | ✅ 推奨 |
| **ブラックリスト** | 禁止する文字・パターンを定義 | ❌ 漏れが生じやすい |

```
ホワイトリスト例：ユーザー名は「英小文字と数字、3〜16文字」のみ許可
ブラックリスト例：「<」「>」「'」を禁止  → 見落としやすい
```

### 検証すべき項目

| 項目 | 例 |
|------|-----|
| **型** | 数値フィールドに文字列が来ていないか |
| **形式** | メールアドレス、電話番号、日付の形式 |
| **範囲** | 年齢 0〜150、数量 1〜999 |
| **長さ** | コメント 500文字以内 |
| **許可値** | 都道府県は定義済みリストからのみ |

### 検証のタイミング

- **サーバー側で必ず検証** する（クライアント側だけでは不十分）
- 可能な限り **処理の直前** に行う
- 検証に失敗したら **明確にエラーを返す**（曖昧な値で処理を続けない）

## 🛡️ 入力値検証

**入力値検証（バリデーション）** は、入力値の妥当性検証を具体的なチェック項目に落とし込んだものです。インジェクション攻撃を防ぐ第一の防御線になります。

### 制御文字のチェック

**制御文字** は、画面に表示されない特殊な文字です（改行、タブ、NULL など）。HTTPヘッダインジェクションやログ改ざんの原因になります。

| 制御文字 | コード | 危険性 |
|---------|--------|--------|
| 改行（LF） | `\n` (0x0A) | HTTPヘッダの注入 |
| 復帰（CR） | `\r` (0x0D) | HTTPヘッダの注入 |
| NULL | `\0` (0x00) | 文字列の途中で切れる |
| タブ | `\t` (0x09) | ログの改ざん |

```javascript
// 制御文字を含むかチェック（改行・NULL 等）
function containsControlChars(str) {
  return /[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]/.test(str);
}

// メールアドレス入力で改行が混入 → ヘッダインジェクションの恐れ
// 悪意ある入力: "user@example.com\r\nBcc: attacker@evil.com"
```

**対策:** 制御文字を検出したら拒否するか、除去する。

### 文字数のチェック

入力値の **長さに上限・下限** を設けます。

| 目的 | 例 |
|------|-----|
| **バッファオーバーフロー防止** | ユーザー名 最大64文字 |
| **DoS対策** | コメント 最大5000文字 |
| **業務ルール** | パスワード 最小8文字 |

```javascript
function validateLength(str, min, max) {
  if (str.length < min) return '短すぎます';
  if (str.length > max) return '長すぎます';
  return null;  // OK
}

validateLength(username, 3, 64);
```

**注意:** 文字数は **バイト数** と **文字数** が異なる場合がある（日本語1文字 = UTF-8で3バイト）。どちらで制限するかを決めておく。

### 数値の最小値・最大値のチェック

数値入力には **型の確認** と **範囲の確認** の両方が必要です。

```javascript
function validateAge(value) {
  const num = Number(value);

  // 型チェック
  if (!Number.isInteger(num)) {
    return '整数で入力してください';
  }

  // 範囲チェック
  if (num < 0 || num > 150) {
    return '0〜150の範囲で入力してください';
  }

  return null;  // OK
}
```

| チェック | 防げる問題 |
|---------|-----------|
| 整数かどうか | `"abc"` や `"1.5"` の混入 |
| 最小値 | マイナスの数量（`-1` 個注文） |
| 最大値 | 異常に大きな値によるオーバーフロー |

## 🔍 正規表現を使った入力値検証

形式チェック（メールアドレス、電話番号など）には **正規表現（Regular Expression）** がよく使われます。以下は正規表現の基本要素です。

※ 原文の「u装飾」「i装飾」は **修飾子**、「量子指定」は **量詞指定** の意味です。

### 修飾子（フラグ）

正規表現の末尾に付けるオプションです。

| 修飾子 | 意味 | 例 |
|--------|------|-----|
| **i** | 大文字・小文字を区別しない | `/abc/i` → `ABC` にもマッチ |
| **u** | Unicode モード（サロゲートペア等を正しく扱う） | `/^[あ-ん]+$/u` |
| **g** | 全文からすべてのマッチを検索 | `/\d/g` |
| **m** | 複数行モード（`^` `$` が行単位） | `/^test$/m` |

```javascript
// i 修飾子：大文字小文字を無視
/^[a-z]+$/i.test('Hello');  // true

// u 修飾子：絵文字なども1文字として扱う
/^.{1,10}$/u.test('こんにちは🎉');  // 文字数を正しくカウント
```

### 文字と文字クラス

| 記法 | 意味 | 例 |
|------|------|-----|
| `.` | 任意の1文字 | `a.c` → `abc`, `a1c` |
| `\d` | 数字 `[0-9]` | `\d\d\d` → `123` |
| `\w` | 英数字とアンダースコア | `\w+` → `user_name` |
| `\s` | 空白文字 | `\s` → スペース、タブ |
| `[abc]` | a, b, c のいずれか1文字 | `[aeiou]` → 母音 |
| `[a-z]` | a〜z の範囲 | `[0-9]` → 数字 |
| `[^abc]` | a, b, c **以外** | `[^0-9]` → 数字以外 |
| `\|` | OR | `cat\|dog` → cat または dog |

```javascript
// 郵便番号（123-4567 形式）
/^\d{3}-\d{4}$/.test('123-4567');  // true

// 英小文字と数字のみ（ユーザー名）
/^[a-z0-9]{3,16}$/.test('yamada123');  // true
```

### 量詞指定

直前のパターンが **何回繰り返されるか** を指定します。

| 量詞 | 意味 | 例 |
|------|------|-----|
| `*` | 0回以上 | `\d*` → 数字が0個以上 |
| `+` | 1回以上 | `\d+` → 数字が1個以上 |
| `?` | 0回または1回 | `\d?` → 数字が0個か1個 |
| `{n}` | ちょうど n 回 | `\d{3}` → 数字3桁 |
| `{n,}` | n 回以上 | `\d{3,}` → 数字3桁以上 |
| `{n,m}` | n 回以上 m 回以下 | `\d{3,5}` → 数字3〜5桁 |

```javascript
// パスワード：8文字以上
/^.{8,}$/.test('password123');  // true

// 電話番号：10〜11桁の数字
/^\d{10,11}$/.test('09012345678');  // true
```

### アンカー（位置指定）

| 記法 | 意味 |
|------|------|
| `^` | 文字列の先頭 |
| `$` | 文字列の末尾 |

```javascript
// ^ と $ で「文字列全体」がパターンに一致することを保証
/^[a-z]+$/.test('abc123');  // false（末尾まで英小文字だけではない）
/^[a-z]+$/.test('abc');     // true
```

**重要:** 検証には `^` と `$` を付けて **部分一致ではなく全体一致** にすることが多い。

### 実践例：メールアドレスの簡易検証

```javascript
// 簡易的な形式チェック（厳密なRFC準拠ではない）
const emailPattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

emailPattern.test('yamada@example.com');  // true
emailPattern.test('invalid-email');       // false
```

### 正規表現を使うときの注意

| 注意点 | 理由 |
|--------|------|
| **複雑すぎる正規表現は避ける** | 保守が難しく、バグの温床になる |
| **ReDoS（正規表現DoS）に注意** | 悪意ある入力で処理が極端に遅くなる |
| **正規表現だけに頼らない** | 型・長さ・範囲チェックと組み合わせる |
| **ライブラリの活用** | メール等は `validator.js` 等の実績あるライブラリを検討 |

## 📝 まとめ

| トピック | 要点 |
|---------|------|
| 入力‐処理‐出力モデル | 各段階で検証・安全な処理・エスケープが必要 |
| エンコーディングの妥当性検証 | UTF-8 として正しいか確認 |
| エンコーディングの変換 | 内部形式（UTF-8）に統一 |
| 入力値の妥当性検証 | ホワイトリスト方式で形式・範囲をチェック |
| 制御文字のチェック | 改行・NULL 等の混入を防ぐ |
| 文字数のチェック | 最小・最大長で制限 |
| 数値の範囲チェック | 型・最小値・最大値を確認 |
| 正規表現 | 修飾子（i, u）、文字クラス、量詞で形式を検証 |

```
外部からの入力
    │
    ├─ 1. エンコーディング検証・変換
    ├─ 2. 制御文字・文字数・数値範囲のチェック
    ├─ 3. 正規表現による形式チェック（ホワイトリスト）
    │
    ▼
安全な処理へ
```
