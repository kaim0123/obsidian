# CORSとは

## CORSとは何か

CORS（Cross-Origin Resource Sharing）は、**異なるオリジン間でリソースを共有するための仕組み**です。

## オリジンとは

オリジンは、**プロトコル + ドメイン + ポート番号**の組み合わせです。

### オリジンの例

以下のURLは全て**異なるオリジン**です：

```
https://example.com         ← オリジン1
http://example.com          ← オリジン2（プロトコルが違う）
https://api.example.com     ← オリジン3（ドメインが違う）
https://example.com:8080    ← オリジン4（ポート番号が違う）
https://www.example.com     ← オリジン5（サブドメインが違う）
```

以下のURLは**同じオリジン**です：

```
https://example.com/page1   ← オリジン1
https://example.com/page2   ← オリジン1（パスが違うだけ）
https://example.com/api     ← オリジン1（パスが違うだけ）
```

### パスはオリジンの一部ではない

重要なポイント：
- `/page1`、`/page2` などのパスは**オリジンの一部ではありません**
- `https://example.com/page1` と `https://example.com/page2` は**同じオリジン**です

## 同一オリジンポリシーとは

ブラウザには**同一オリジンポリシー**というセキュリティ機能があります。

これは：
- **同じオリジン**からのリクエストのみ許可する
- **異なるオリジン**からのリクエストは基本的にブロックする

というルールです。

### なぜ同一オリジンポリシーが必要なのか

悪意のあるサイトから、別のサイトのデータを勝手に取得することを防ぐためです。

**悪い例（同一オリジンポリシーがない場合）**:
1. 悪意のあるサイト（`evil.com`）を開く
2. そのサイトが、バックグラウンドで `bank.com` にリクエストを送る
3. ログイン中の銀行サイトから情報を盗む

同一オリジンポリシーがあるため、このような攻撃を防ぐことができます。

## CORSが必要な理由

現代のWebアプリケーションでは、以下のような構成が一般的です：

```
フロントエンド: https://myapp.com
バックエンドAPI: https://api.myapp.com
```

これらは**異なるオリジン**です（ドメインが違う）。

同一オリジンポリシーにより、フロントエンドからバックエンドAPIへのリクエストがブロックされてしまいます。

**解決策**: CORSを設定することで、異なるオリジン間での通信を安全に許可できます。

## CORSの簡単な例え

### 例え1: 銀行の窓口

- **同一オリジン**: 自分が開設した銀行の支店に行く → OK
- **異なるオリジン**: 別の銀行の支店に行く → 基本的にはNG（ただし、事前に手続きをすればOK）

CORSは、その「事前の手続き」のようなものです。

### 例え2: 学校の教室

- **同一オリジン**: 自分のクラスの教室に入る → OK
- **異なるオリジン**: 他のクラスの教室に入る → 基本的にはNG（ただし、許可証があればOK）

CORSは、その「許可証」のようなものです。

## CORSが動作する場面

### 1. ブラウザからのリクエストのみ

重要なポイント：
- **CORSはブラウザの機能**です
- サーバー間の通信ではCORSは関係ありません
- `curl`や`Postman`などのツールでは、CORSエラーは発生しません

### 2. 異なるオリジンへのリクエスト

同じオリジンへのリクエストでは、CORSは関係ありません。

## CORSエラーが発生する例

### よくあるシナリオ

```javascript
// フロントエンド（https://myapp.com）から
fetch('https://api.example.com/users')
  .then(response => response.json())
  .catch(error => {
    // CORSエラーが発生する可能性がある
    console.error('CORS Error:', error);
  });
```

この場合、ブラウザは以下のように判断します：
- リクエスト元: `https://myapp.com`
- リクエスト先: `https://api.example.com`
- → **異なるオリジン**なので、CORSの確認が必要

### CORSエラーのメッセージ

ブラウザのコンソールに以下のようなエラーが表示されます：

```
Access to fetch at 'https://api.example.com/users' from origin 'https://myapp.com' 
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present 
on the requested resource.
```

## CORSを理解するポイント

1. **オリジンは「プロトコル + ドメイン + ポート」の組み合わせ**
2. **同じオリジンからのリクエストは常に許可される**
3. **異なるオリジンからのリクエストは、CORS設定が必要**
4. **CORSはブラウザの機能であり、セキュリティのためのもの**
5. **サーバー側で適切な設定を行う必要がある**

## まとめ

- CORS（Cross-Origin Resource Sharing）は、異なるオリジン間でリソースを共有するための仕組み
- オリジンは「プロトコル + ドメイン + ポート」の組み合わせ
- 同一オリジンポリシーにより、異なるオリジンからのリクエストは基本的にブロックされる
- CORSを設定することで、安全に異なるオリジン間での通信を許可できる
- CORSエラーはブラウザでのみ発生する
