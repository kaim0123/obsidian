**テーマ：同一オリジンポリシー・CORS と Cookie の属性**

別のサイトから勝手にデータを読まれないようにするブラウザの仕組み（同一オリジンポリシーと CORS）と、Cookie に付ける印（HttpOnly・Secure・SameSite）の意味を解説する動画。ブラウザごとの細かい実装差は扱わない。

### 同一オリジンポリシーと CORS

- **オリジン**とは何か、ブラウザがなぜ「門番」をしているのかを説明する
- ブラウザが止めているのは送信そのものではなく、**レスポンスを「読むこと」**
- **CORS** は、サーバーが出す「許可の札」として読めるようにする仕組み
- 本番の前に**プリフライト**（事前の問い合わせ）が行われる場合がある
- コード例でも確認する

### Cookie

- Cookie がリクエストにどう付いていくのか
- Cookie に付ける印：**HttpOnly・Secure・SameSite**
- **SameSite** は、勝手な送信（他サイトからのリクエストに Cookie が付くこと）を止めるためのもの
- 画面と API を別のオリジンに分けたときの例も扱う
