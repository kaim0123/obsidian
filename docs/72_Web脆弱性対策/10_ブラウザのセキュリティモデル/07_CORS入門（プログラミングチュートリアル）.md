## 詳しい要約

**テーマ：CORS（オリジン間リソース共有）の意味・存在理由と、Node.js/Express での CORS エラー回避**

Web 開発で必ず出会う「blocked by CORS policy」エラーについて、オリジンの意味から同一生成元ポリシーの目的までをスライドで説明し、後半はハンズオンで実際にエラーを起こして `cors` モジュールで解決する。結論は「サーバー側でアクセスを許可するオリジンを指定すれば解決できる」。

---

### CORS とオリジン

- CORS は **Cross-Origin Resource Sharing**（オリジン間リソース共有）の略。リソース＝データなので「オリジン間でのデータ共有」と読み替えてよい。
- **オリジン** ＝ **スキーム（プロトコル）＋ドメイン＋ポート番号** の組み合わせ（例: `https` + `youtube.com` + `443`）。
  - スキーム：通信のルール（鬼ごっこのルールを決めるのと同じ）
  - ドメイン：重複できない名前
  - ポート：部屋番号のようなもの（https は 443、http は 80）
- 「始まり・起源」の意味。そこを起点に各ページへ遷移するのでオリジンと呼ぶのでは、というのは話者の私見。
- CORS は「別オリジン間（例: YouTube と Twitter）でもデータのやり取りを許可する」ための決まり。

### なぜエラーになるのか：同一生成元ポリシー

- Web はデフォルトで **同一オリジン間でしかリソースのやり取りを許可しない**（**同一生成元ポリシー**／Same-Origin Policy）。
- 例：`mywebsite.com` から `mywebsite.com/users.json` は OK。`api.mywebsite.com`（サブドメイン違い）や `randomwebsite.com` は別オリジンなので NG。
- たとえ話：国王だけが集まる城の門番が、名簿を見て国王だけを通し、市民は通さない。
- **存在理由はセキュリティ**：悪意あるサイト（evil site）に誘導されても、そこから銀行サイト（別オリジン）へのアクセスがブロックされ、勝手に送金されるような被害を防げる。

### 開発者にとっての不便さと解決策

- フロント（例: `localhost:5500`）とバックエンド（例: `localhost:5000`）はポートが違う＝別オリジンなので、fetch するとエラーになる。
- 解決策：**サーバー側で許可を出す**。レスポンスヘッダーに **`Access-Control-Allow-Origin: http://localhost:5500`** のように付ける。

### ハンズオン（Express + cors）

1. `server` ディレクトリで `npm init`、`express` と `nodemon` をインストールし、`app.listen(5000)` でサーバーを起動。
2. `/data` エンドポイントで名前と年齢を JSON で返す。
3. `client` 側に `index.html` と `script.js`（`defer` 付きで読み込み）を作り、VS Code の Live Server（ポート 5500）で開く。
4. `fetch("http://localhost:5000/data")` → `.then(res => res.json())` で取得すると、**「No 'Access-Control-Allow-Origin' header」エラーが再現**される。
5. `npm i cors` し、`app.use(cors({ origin: "http://127.0.0.1:5500" }))` をミドルウェアとして設定 → データ取得に成功（オリジン末尾に `/` を付けるとダメだった点に注意）。

### オプション

- **`methods`**：`["GET", "POST"]` のように許可する HTTP メソッドを指定できる。PUT で送るとエラーになり、ヘッダーの `Access-Control-Allow-Methods` で確認できる。
- **`credentials: true`**：Cookie のやり取りを許可する。クライアント側は fetch に `credentials: "include"` を付ける。ヘッダーに `Access-Control-Allow-Credentials: true` が付く。
- エラー調査には開発者ツールの **Network タブ**（リクエスト/レスポンスの詳細）、Cookie は **Application タブ** で確認するのがおすすめ。

### まとめ

- オリジン＝スキーム＋ドメイン＋ポート。どれか一つでも違えば別オリジン。
- 同一生成元ポリシーはユーザーを守るためのブラウザの仕組みで、それを例外的に緩めるのが CORS。
- CORS エラーは **サーバー側で許可オリジン（必要ならメソッド・credentials）を設定** すれば解決する。
