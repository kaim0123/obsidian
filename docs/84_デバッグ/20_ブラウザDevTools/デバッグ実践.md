# デバッグ実践

## デバッグとは
プログラムの問題（バグ）を見つけて修正することです。ブラウザのDevToolsを使えば、効率的にデバッグできます。

## 基本的なデバッグの流れ

1. **問題の特定**: 何がおかしいのか
2. **原因の調査**: なぜ起きているのか
3. **修正**: どう直すか
4. **確認**: 正しく動作するか

## よくある問題とデバッグ方法

### 1. 画面に何も表示されない

#### Console で確認
```javascript
// エラーメッセージがないか確認
// よくあるエラー:
// - Uncaught ReferenceError
// - Uncaught TypeError
// - Failed to fetch
```

#### Elements で確認
- HTMLが正しく読み込まれているか
- CSSで `display: none` になっていないか
- 要素が存在するか

#### Network で確認
- JavaScriptファイルが読み込まれているか（200 OK）
- APIからデータが取得できているか

### 2. ボタンが動かない

#### イベントの確認
```javascript
// Consoleで確認
const button = document.querySelector('#myButton');
console.log(button);  // null の場合は要素が見つからない

// イベントリスナーが登録されているか
button.addEventListener('click', () => {
  console.log('クリックされました');
});
```

#### Elementsで確認
1. ボタン要素を選択
2. Event Listeners タブを開く
3. 'click' イベントが登録されているか

### 3. データが表示されない

#### API呼び出しの確認
```javascript
// Console で実行
fetch('https://api.example.com/data')
  .then(res => {
    console.log('Status:', res.status);
    return res.json();
  })
  .then(data => {
    console.log('Data:', data);
  })
  .catch(err => {
    console.error('Error:', err);
  });
```

#### Network で確認
1. Fetch/XHR でフィルター
2. リクエストのステータス確認
3. Responseタブでデータ確認

### 4. スタイルが反映されない

#### Elements で確認
```
1. 要素を選択
2. Styles パネルで確認
   - 取り消し線 → 上書きされている
   - グレーアウト → 無効なプロパティ
3. Computed タブで最終的な値を確認
```

#### よくある原因
- セレクタの優先度が低い
- スペルミス
- CSSファイルが読み込まれていない
- キャッシュの問題

## ブレークポイントを使ったデバッグ

### Sourcesパネルでブレークポイント設定

#### 1. ファイルを開く
- `Ctrl + P` でファイル検索
- 対象のJSファイルを開く

#### 2. ブレークポイントを設定
- 行番号をクリック
- 青いマーカーが表示される

#### 3. コードを実行
- ページをリロードまたは操作
- ブレークポイントで一時停止

#### 4. ステップ実行
- **Step over** (F10): 次の行へ
- **Step into** (F11): 関数の中へ
- **Step out** (Shift + F11): 関数から出る
- **Resume** (F8): 次のブレークポイントまで実行

### 変数の確認

#### Scopeパネル
- Local: ローカル変数
- Global: グローバル変数

#### Watchパネル
- 監視したい変数や式を追加
- 実行中の値を確認

#### Consoleで確認
ブレークポイント中にConsoleで変数を参照可能
```javascript
console.log(変数名);
```

## 条件付きブレークポイント

特定の条件でのみ停止

1. 行番号を右クリック
2. "Add conditional breakpoint"
3. 条件を入力

```javascript
// 例: i が 5 の時だけ停止
i === 5
```

## ログポイント

コードを変更せずにログ出力

1. 行番号を右クリック
2. "Add logpoint"
3. 出力したい内容を入力

```javascript
// 例
'i の値:', i
```

## 実践的なデバッグ例

### 例1: 合計が正しく計算されない

```javascript
function calculateTotal(items) {
  let total = 0;
  for (let i = 0; i < items.length; i++) {
    total += items[i].price;
  }
  return total;
}

const items = [
  {name: 'りんご', price: 100},
  {name: 'バナナ', price: 200},
  {name: 'オレンジ', price: '150'}  // ← 文字列になっている！
];

console.log(calculateTotal(items));  // 期待: 450, 実際: "300150"
```

#### デバッグ手順
1. ブレークポイントをループ内に設定
2. `total` と `items[i].price` の値を確認
3. 型が違うことを発見
4. 修正: `total += Number(items[i].price);`

### 例2: APIからデータが取得できない

```javascript
async function fetchUsers() {
  try {
    const response = await fetch('https://api.example.com/user');  // ← sが抜けている
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error('エラー:', error);
  }
}
```

#### デバッグ手順
1. Network パネルを開く
2. リクエストを確認 → 404 Not Found
3. URLのスペルミスを発見
4. 修正: `/users` に変更

### 例3: 非同期処理の問題

```javascript
let userData;

fetch('https://api.example.com/user/1')
  .then(res => res.json())
  .then(data => {
    userData = data;
  });

console.log(userData);  // undefined ← まだデータが取得されていない
```

#### デバッグ手順
1. Console で `undefined` と表示される
2. 非同期処理の理解不足と判明
3. 修正: Promise を正しく扱う

```javascript
fetch('https://api.example.com/user/1')
  .then(res => res.json())
  .then(data => {
    userData = data;
    console.log(userData);  // ここで表示
  });

// または async/await
async function getUser() {
  const res = await fetch('https://api.example.com/user/1');
  const userData = await res.json();
  console.log(userData);
}
```

## デバッグのコツ

### 1. console.log を活用
```javascript
console.log('この行は実行されました');
console.log('変数の値:', myVariable);
console.log('配列の長さ:', myArray.length);
```

### 2. 小さく分けて確認
```javascript
// 一度にすべて書かずに、段階的に確認
const result = data
  .filter(item => item.active)
  .map(item => item.name)
  .join(', ');

// ↓ 段階的に確認
const filtered = data.filter(item => item.active);
console.log('フィルター後:', filtered);

const mapped = filtered.map(item => item.name);
console.log('マップ後:', mapped);

const result = mapped.join(', ');
console.log('最終結果:', result);
```

### 3. エラーメッセージをよく読む
- 何が問題か
- どこで起きたか（ファイル名と行番号）
- エラーの種類

### 4. 変更を一つずつ
- 複数箇所を同時に変更しない
- 一つ変更したら動作確認
- どの変更が効果的か把握

### 5. コメントアウトで切り分け
```javascript
// 動かない箇所をコメントアウト
// problemCode();

// シンプルなコードで動作確認
console.log('ここまでは動く');
```

## よく使うデバッグテクニック

### 型の確認
```javascript
console.log(typeof myVariable);
console.log(Array.isArray(myArray));
console.log(myValue === null);
console.log(myValue === undefined);
```

### オブジェクトの詳細確認
```javascript
console.dir(myObject);
console.table(myArray);
```

### スタックトレースの確認
```javascript
console.trace();  // どこから呼ばれたか
```

### パフォーマンス計測
```javascript
console.time('処理時間');
// 処理
console.timeEnd('処理時間');
```

## まとめ

良いデバッグのために:
1. **慌てない**: 落ち着いてエラーを読む
2. **仮説を立てる**: 何が原因か予想
3. **検証する**: DevToolsで確認
4. **記録する**: 同じミスを繰り返さない
5. **学ぶ**: エラーから学習する

DevToolsを使いこなせば、デバッグは怖くありません！
