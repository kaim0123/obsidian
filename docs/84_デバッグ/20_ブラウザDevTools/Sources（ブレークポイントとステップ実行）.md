# Sources（ブレークポイントとステップ実行）

**Sources パネル**は、ブラウザで動いている JavaScript を止めて、その瞬間の変数や呼び出し履歴を調べるための場所です。行番号をクリックする基本のブレークポイントは [[デバッグ実践]] で扱っているので、ここでは**行が分からないときに使うブレークポイント**や、ソースマップ・ステップ実行のコツなど、一歩進んだ使い方をまとめます（Chrome を前提にしていますが、Edge も同じです）。

---

## 1. パネルの構成

| 場所 | 役割 |
|------|------|
| 左：Page / Workspace / Overrides / Snippets | ファイルの一覧 |
| 中央：エディタ | コードの表示、ブレークポイントの設定 |
| 右：Debugger | 実行の制御、Watch、Breakpoints、Scope、Call Stack |

- `Ctrl + P`（Mac は `Cmd + P`）でファイルを名前で開く。
- `Ctrl + Shift + F` で全ファイルを文字列検索する。

---

## 2. ステップ実行

| ボタン | ショートカット | 動き |
|--------|----------------|------|
| Resume | `F8` | 次のブレークポイントまで進む |
| Step over | `F10` | 次の行へ（関数の中には入らない） |
| Step into | `F11` | 関数の中に入る |
| Step out | `Shift + F11` | 今の関数を抜けて、呼び出し元に戻る |
| Step | `F9` | 非同期の処理も含めて、次に実行される文へ |

- **Continue to here**：行番号を右クリックして「Continue to here」で、その行まで一気に進める。
- **Restart frame**：Call Stack の関数を右クリックして「Restart frame」で、その関数の最初からやり直せる（副作用は元に戻らないので注意）。

---

## 3. 行が分からないときのブレークポイント

原因の場所が分からなくても、「何が起きたとき」で止められます。右側の Debugger ペインで設定します。

| 種類 | 止まるとき | 使いどころ |
|------|------------|------------|
| **例外で止める**（Pause on exceptions） | 例外が投げられたとき（キャッチされたものも含めるか選べる） | エラーの発生元を探す |
| **XHR / fetch ブレークポイント** | 指定した文字列を含む URL にリクエストを送るとき | 「この API を誰が呼んでいるか」を探す |
| **DOM ブレークポイント** | 要素の子要素・属性が変わった、要素が削除された | 「誰がこの要素を書き換えたか」を探す（Elements パネルで要素を右クリック → Break on） |
| **イベントリスナーのブレークポイント** | click・keydown・setTimeout などのイベントが起きたとき | クリックしたときに何が動くかを探す |
| **条件付きブレークポイント** | 条件が true のとき | ループの特定の回だけ止める |
| **ログポイント** | 止まらずに Console にログを出す | コードを変えずにログを足す |

### 例外で止めるときのコツ

- 「Pause on caught exceptions」まで有効にすると、ライブラリの中でキャッチされる例外でも止まってうるさいことがあります。まずは「uncaught」だけで試す。
- `debugger;` 文をコードに書くと、DevTools が開いているときだけそこで止まります（コミットしないよう注意）。

---

## 4. 止まっているときに見るもの

| ペイン | 見るもの |
|--------|----------|
| **Scope** | ローカル変数・クロージャの変数・グローバル |
| **Watch** | 自分で登録した式（`user?.id`、`items.length` など）の値 |
| **Call Stack** | ここに来るまでの呼び出し履歴。行をクリックすると、その時点の変数が見られる |
| **Console** | 止まっている時点のスコープで、任意の式を実行できる |

- コード上の変数にマウスを乗せると、値がポップアップで表示されます。
- **Console で値を書き換えて、そのまま実行を続ける**こともできます（「この値だったら直るか」をその場で試せる）。

## 5. ソースマップと Ignore List

### ソースマップ

- Vite・Next.js の開発サーバーでは、ビルド後のコードではなく**元の TypeScript / JSX** が表示され、そこにブレークポイントを置けます。
- 元のファイルが見えないときは、Settings → Preferences → Sources の「Enable JavaScript source maps」を確かめる。

### Ignore List（無視リスト）

ステップ実行で React や node_modules の中に入ってしまうのを防ぎます。

- ファイルを右クリック → 「Add script to ignore list」。
- Chrome は `node_modules` を標準で無視リストに入れる設定があります（Settings → Ignore List）。
- 無視したファイルは Call Stack でも折りたたまれ、**自分のコードの流れだけ**が見やすくなります。

---

## 6. 非同期のコードを追う

- Call Stack には `await` や `setTimeout` をまたいだ**非同期の呼び出し元**も表示されます（「async」と区切られた部分）。
- Promise の reject を追うときは、「Pause on exceptions」と async スタックを組み合わせると、reject した場所と、その Promise を作った呼び出し元の両方が分かります。

---

## 7. 便利な機能

| 機能 | 使い方 | 用途 |
|------|--------|------|
| **Snippets** | Sources → Snippets に JS を保存し、`Ctrl + Enter` で実行 | よく使う調査用スクリプト（ストレージを消す、状態を出力する） |
| **Local Overrides** | Overrides でフォルダを指定し、ファイルを編集して保存 | 本番サイトの JS・CSS を手元で書き換えて試す（リロードしても残る） |
| **Workspace** | ローカルのプロジェクトフォルダを追加 | DevTools で編集した内容をファイルに保存 |
| **Pretty print** | 圧縮されたコードの `{}` ボタン | ソースマップがないコードを読める形にする |
