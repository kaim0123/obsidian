## 1. AAAの3つの機能

**AAA**は、アクセスを管理する3つの機能の頭文字です。

| 機能 | 問い | 例 |
|---|---|---|
| 認証（Authentication） | **あなたは誰か** | ユーザー名とパスワードで本人確認 |
| 認可（Authorization） | **何をしてよいか** | このユーザーは `show` だけ、あのユーザーは `configure` も可 |
| アカウンティング（Accounting） | **何をしたか** | 誰が、いつログインし、どのコマンドを実行したかを記録 |

```
 ユーザー ──①ログイン──> [ルータ] ──②「この人は本物？」──────> [AAAサーバ]
                                 <──③認証OK───────────────────
          ──④コマンド──> [ルータ] ──⑤「このコマンドを許可する？」─> （認可）
                                 <──⑥許可/拒否─────────────────
                         [ルータ] ──⑦「誰が何をしたか」の記録──> （アカウンティング）
```

「ログインしたユーザーが、どのコマンドを実行できるかを制御する」は**認可（Authorization）**です。暗号化はAAAの要素ではありません。

**なぜAAAサーバを使うのか**: 機器が100台あると、ローカルユーザーを100台それぞれで作成・変更・削除しなければなりません。AAAサーバ（例：**Cisco ISE**）を使えば、ユーザーを一元管理でき、退職者のアカウントの無効化も1か所で確実に行えます。

## 2. TACACS+ と RADIUS

機器（ルータ、スイッチ、WLCなど）とAAAサーバの間の通信には、TACACS+ か RADIUS を使います。

| 項目 | TACACS+ | RADIUS |
|---|---|---|
| 開発・標準 | **Cisco**が開発 | **IETF**の標準（オープン） |
| トランスポート | **TCP 49** | **UDP 1812（認証/認可）、1813（アカウンティング）**（古い実装では1645/1646） |
| 暗号化の範囲 | パケットの**本文全体**を暗号化 | **パスワードだけ**を暗号化 |
| AAAの扱い | 認証・認可・アカウンティングを**個別**に扱える | 認証と認可を**まとめて**扱う |
| コマンドごとの認可 | できる | 基本的にできない |
| 主な用途 | **ネットワーク機器にログインする管理者**の認証とコマンド制御 | **ネットワークを利用するユーザー**の認証（無線LANの802.1X、有線802.1X、VPN接続） |

覚え方:

```
TACACS+ … TCP / 全体暗号化 / Cisco / 機器の管理者（デバイス管理）
RADIUS  … UDP / パスワードだけ / IETF標準 / ネットワーク利用者（ネットワークアクセス）
```

TACACS+の特徴は「TCP（49番）を使い、パケットの本文全体を暗号化する」です。「UDPでパスワードだけ暗号化」はRADIUSの特徴、「IEEEが定めたオープンな標準」は誤り（TACACS+はCisco開発、RADIUSはIETF標準）、「無線LANの暗号化方式」はWPA2/WPA3のことです。

## 3. IOSでのAAA設定と方法リスト

```
R1(config)# username admin secret Local!Backup1          ! サーバ障害時の予備のローカルユーザー
R1(config)# aaa new-model                                 ! ① AAAを有効化（すべての始まり）
R1(config)# tacacs server TAC1                            ! ② TACACS+サーバの定義
R1(config-server-tacacs)# address ipv4 192.168.100.10
R1(config-server-tacacs)# key T@cacsKey
R1(config-server-tacacs)# exit
R1(config)# aaa authentication login default group tacacs+ local    ! ③ 認証の方法リスト
R1(config)# aaa authorization exec default group tacacs+ local      ! （認可）
R1(config)# aaa accounting commands 15 default start-stop group tacacs+   ! （アカウンティング）
```

### 方法リストの評価

`aaa authentication login default group tacacs+ local` は、認証方法を**左から順に**試します。ただし「次へ進む」のは**前の方法が使えない（エラー・無応答）ときだけ**です。

```
ログイン要求
   │
   v
[TACACS+サーバに問い合わせ]
   │
   ├─ 応答あり：認証成功 ──────> ログイン許可
   ├─ 応答あり：認証失敗（PASS/FAIL の FAIL）──> ログイン拒否（ここで終了。local は試さない）
   └─ 応答なし（サーバ停止・到達不能＝ERROR）
          │
          v
     [ローカルユーザー（local）で認証]
          ├─ 成功 ─> ログイン許可
          └─ 失敗 ─> ログイン拒否
```

| 解釈 | 正誤 |
|---|---|
| TACACS+サーバに**到達できない場合に**ローカルユーザーで認証する | ◯ |
| TACACS+とローカルの**両方**で成功する必要がある | ✕（予備であって二重認証ではない） |
| TACACS+で**パスワードが間違っていた**場合にローカルで再認証 | ✕（サーバが「失敗」を返したらそこで終了） |
| ローカルを優先し、ないユーザーだけTACACS+ | ✕（書いた順＝TACACS+が優先） |

AAAサーバが故障したり、ネットワークが切れたりしたときに誰もログインできなくなるのを防ぐため、**最後に local を入れる**のが一般的で、そのためにローカルユーザーを作っておきます。

## 4. 802.1X（ポートベースの認証）

**802.1X**は、LANのポート（有線ならスイッチのポート、無線ならAPとの接続）を、認証に成功した端末にだけ開放する仕組みです。3つの役割があります。

| 役割 | 担当する機器 | 内容 |
|---|---|---|
| サプリカント（要求者） | PCなどの端末（802.1Xクライアントソフト） | 認証を**受ける側** |
| オーセンティケータ（認証者） | **スイッチ**、無線AP/WLC | 端末とRADIUSサーバの間で認証のやり取りを**中継**し、結果に応じて**ポートを開く** |
| 認証サーバ | RADIUSサーバ（例：Cisco ISE） | ユーザー情報を持ち、実際に認証を**判断**する |

```
 [PC]                        [スイッチ]                       [RADIUSサーバ / ISE]
 サプリカント               オーセンティケータ                  認証サーバ
    │  ── EAPoL（EAP over LAN）──>  │  ── RADIUS（EAPを中継）──>  │
    │  <────────────────────────── │  <──────────────────────── │
    │                               │      Access-Accept / Reject │
    │                     認証成功ならポートを開放
    │                     （成功するまでは EAPoL 以外は通さない）
```

有線LANの802.1Xで、PCを接続された**スイッチ**の役割は**オーセンティケータ**です。DHCPサーバは802.1Xの3つの役割に含まれません。

認証に成功するまで、スイッチのポートは認証用の通信（EAPoL）以外を通さないので、**許可されていない端末をLANにつないでも通信できません**。無線LANのエンタープライズモードも同じ仕組みで、オーセンティケータが無線AP/WLCになります。

```
SW(config)# aaa new-model
SW(config)# radius server ISE
SW(config-radius-server)# address ipv4 192.168.100.20 auth-port 1812 acct-port 1813
SW(config-radius-server)# key R@diusKey
SW(config)# aaa authentication dot1x default group radius
SW(config)# dot1x system-auth-control
SW(config)# interface g0/1
SW(config-if)# switchport mode access
SW(config-if)# authentication port-control auto
SW(config-if)# dot1x pae authenticator
```

## ひっかけポイント・よくある誤解

- 「どのコマンドを実行できるか」は**認可**。認証（本人確認）、アカウンティング（記録）と区別する。**暗号化はAAAの要素ではない**。
- **TACACS+＝TCP 49・全体暗号化・Cisco**、**RADIUS＝UDP 1812/1813・パスワードのみ暗号化・IETF標準**。逆にしたひっかけが多い。「IEEE標準」も誤り。
- TACACS+やRADIUSは無線LANの**暗号化方式ではない**（それはWPA2/WPA3）。
- 方法リストの local は「**サーバに到達できないときの予備**」。サーバが「認証失敗」と答えたら local は試さない。両方での認証でも、ローカル優先でもない。
- 802.1Xでスイッチは**オーセンティケータ**。サプリカントは端末、認証サーバはRADIUS。DHCPサーバは無関係。

## 押さえておくポイント

- AAA＝認証（誰か）→認可（何をしてよいか）→アカウンティング（何をしたか）。AAAサーバ例：Cisco ISE。
- TACACS+は機器管理者のコマンド制御向け、RADIUSはネットワーク利用者（802.1X、VPN）の認証向け。
- `aaa new-model` で開始。方法リストは左から順、次へ進むのはエラー（無応答）時のみ。最後に `local`。
- 802.1Xの3役割：サプリカント・オーセンティケータ・認証サーバ。認証前はEAPoLのみ通過。
