## 1. ルーティングの基本とルーティングテーブルの読み方

### 1.1 ルータは「次に渡す相手」だけを決める

ルータの仕事は、受け取ったパケットの**宛先IPアドレス**を見て、**ルーティングテーブル**から使うルートを選び、そのルートが示す**ネクストホップ（次にパケットを渡すルータ）**または出力インターフェースへ送り出すことです。

重要なのは、ルータは宛先までの全経路を知っているわけではない、という点です。各ルータは「この宛先なら次はあのルータへ渡せばよい」ということだけを知っていて、それを経路上のすべてのルータが繰り返すことで、パケットは最終的に宛先に届きます（ホップバイホップ転送）。

```
 PC-A                                                         Server
192.168.1.10                                                 10.2.1.50
   |                                                             |
   | G0/0          G0/1        G0/0          G0/1        G0/0     |
  [R1]---------------------[R2]---------------------[R3]---------+
 .1  192.168.1.0/24  .1  192.168.12.0/24 .2  192.168.23.0/24 .3  10.2.0.0/16

 R1 の判断:「10.2.1.50 宛て？ → 10.2.0.0/16 は via 192.168.12.2（R2）へ」
 R2 の判断:「10.2.1.50 宛て？ → 10.2.0.0/16 は via 192.168.23.3（R3）へ」
 R3 の判断:「10.2.1.50 宛て？ → 10.2.0.0/16 は直接接続（C）。ARPで相手を探して直接届ける」
```

R1 は R3 の存在すら意識していません。R1 が知っているのは「10.2.0.0/16 宛ては 192.168.12.2 へ渡す」ということだけです（ic-007）。

### 1.2 ルーティングテーブルに載るルートの種類

ルーティングテーブルのルートは、どこから知ったかによって次のように分類されます。

| 種類 | どうやって載るか | コード | AD（デフォルト） |
|---|---|---|---|
| 直接接続ルート | インターフェースにIPアドレスを設定し、up/up になると自動で載る | `C` | 0 |
| ローカルルート | 同上。インターフェース自身のアドレスを /32 で載せる | `L` | 0 |
| スタティックルート | 管理者が `ip route` で手動設定する | `S`（デフォルトルートなら `S*`） | 1 |
| EIGRP（内部） | EIGRPで学習 | `D` | 90（外部ルートは170） |
| OSPF | OSPFで学習 | `O`（エリア間は `O IA`、外部は `O E2` など） | 110 |
| RIP | RIPで学習 | `R` | 120 |

コードの意味は `show ip route` の出力の冒頭に凡例として表示されます。

- `C`＝Connected（直接接続）
- `L`＝Local（ローカル、インターフェース自身のアドレス、/32）
- `S`＝Static（スタティック）
- `O`＝OSPF
- `D`＝EIGRP。EIGRPのアルゴリズム名 **DUAL**（Diffusing Update Algorithm）の頭文字に由来します。「E」ではないので注意（`E` はかつてのEGP用に使われていた文字です）。
- `R`＝RIP
- `*`＝デフォルトルートの候補（candidate default）

### 1.4 1行のエントリを分解して読む（ic-005, ic-006, ic-007）

試験で最もよく出るのが、OSPFルートの1行を分解する問題です。

```
O    10.2.0.0/16 [110/20] via 192.168.1.2, 00:01:23, GigabitEthernet0/1
|    |           |   |        |            |         |
|    |           |   |        |            |         +-- ⑥ 出力インターフェース
|    |           |   |        |            +------------ ⑤ ルートを学習してからの経過時間（1分23秒）
|    |           |   |        +------------------------- ④ ネクストホップ（via の後ろ）
|    |           |   +---------------------------------- ③ メトリック（OSPFなら宛先までの合計コスト）
|    |           +-------------------------------------- ② AD（アドミニストレーティブディスタンス）
|    +-------------------------------------------------- 宛先ネットワーク/プレフィックス長
+------------------------------------------------------- ① コード（O＝OSPF）
```

| 部分 | 意味 | よくある誤答 |
|---|---|---|
| `O` | OSPFで学習したルート | 「直接接続」は `C`、「スタティック」は `S`、「EIGRP」は `D` |
| `10.2.0.0/16` | 宛先**ネットワーク**。テーブルにはホスト単位ではなくネットワーク単位で載る | 「宛先ホストのアドレス」ではない |
| `[110/20]` の 110 | **AD**。`[AD/メトリック]` の左側 | 「メトリック」は右側の20 |
| `[110/20]` の 20 | **メトリック**。OSPFでは宛先までの合計コスト | 「ホップ数」ではない（ホップ数を使うのはRIP） |
| `via 192.168.1.2` | **ネクストホップ** | 「ルータ自身のアドレス」は `L` のエントリ、「ルータID」はテーブルに出ない |
| `00:01:23` | 学習してからの経過時間（1分23秒） | 「110」が経過秒数というのは誤り |
| `GigabitEthernet0/1` | 出力インターフェース | |

**OSPFのルータIDはルーティングテーブルには表示されません。**ルータIDは `show ip ospf`、`show ip protocols`、`show ip ospf neighbor`（Neighbor ID列＝相手のルータID）などで確認します。

### 1.5 直接接続ルート（C）とローカルルート（L）（ic-027）

インターフェースにIPアドレスを設定して有効化（`no shutdown`）し、インターフェースが **up/up** になると、ルーティングテーブルに**2つ**のルートが自動で追加されます。

```
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# no shutdown

R1# show ip route connected
      192.168.1.0/24 is variably subnetted, 2 subnets, 2 masks
C        192.168.1.0/24 is directly connected, GigabitEthernet0/1
L        192.168.1.1/32 is directly connected, GigabitEthernet0/1
```

| エントリ | 何を表すか | 役割 |
|---|---|---|
| `C 192.168.1.0/24` | そのインターフェースがつながっている**ネットワーク全体** | このネットワーク内のホスト宛てのパケットを、そのインターフェースから直接送り出す（ARPで宛先MACを調べる） |
| `L 192.168.1.1/32` | **ルータ自身のインターフェースのアドレス**（ローカルルート） | ルータ自身宛てのパケット（ping、SSH、ルーティングプロトコルなど）を**ルータ自身が受信する**ためのルート |

`L` のルートは「192.168.1.1 宛てのパケットを破棄するルート」ではありません。破棄ではなく、ルータ自身が受け取るためのルートです。また `L` は /32 なので、ロンゲストマッチ上は最も具体的なルート（ホストルート）でもあります。

> 補足: ローカルルート（L）は IOS 15 以降で表示されるようになりました。古い資料では C だけが表示されています。

### 1.6 直接接続ルートが表示されないとき（ic-028）

直接接続ルートは**インターフェースが up/up のときだけ**テーブルに載ります。ルーティングプロトコルやスタティックルートは不要です。逆に言うと、IPアドレスを設定したのに `C` が出ないなら、まず疑うべきはインターフェースの状態です。

```
R1# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0     203.0.113.2     YES manual up                    up
GigabitEthernet0/1     192.168.1.1     YES manual administratively down down
GigabitEthernet0/2     10.0.0.1        YES manual down                  down
```

| Status / Protocol | 意味 | 主な原因 |
|---|---|---|
| up / up | 正常 | — |
| administratively down / down | 管理者が無効化している | `shutdown` されている（Ciscoルータのインターフェースは初期状態で shutdown されていることが多い）→ `no shutdown` |
| down / down | 物理層の問題 | ケーブルが抜けている、対向機器の電源が切れている、対向が shutdown |
| up / down | データリンク層の問題 | カプセル化の不一致、キープアライブの問題など（シリアルで多い） |

**ひっかけ**: 「OSPFが設定されていないから」「デフォルトルートがないから」「同じネットワークへのスタティックルートを設定していないから」はいずれも誤りです。直接接続ルートは、ルーティングプロトコルやスタティックルートとは無関係に、インターフェースが up/up になれば自動で載ります。

### 1.7 Gateway of last resort（ic-008）

`show ip route` の上部に表示される `Gateway of last resort` は、**デフォルトルートのネクストホップ**を示します。ルーティングテーブルのどのルートにも一致しない宛先のパケットは、ここへ送られます。

```
! デフォルトルートがある場合
Gateway of last resort is 203.0.113.1 to network 0.0.0.0

! デフォルトルートがない場合
Gateway of last resort is not set
```

`not set` の状態で一致するルートがない宛先のパケットが来ると、ルータはそのパケットを**破棄**します（送信元へは ICMP の到達不能メッセージを返します）。

PC に設定する「デフォルトゲートウェイ」と名前が似ていますが、別物です。

| 用語 | どこの設定か | 意味 |
|---|---|---|
| デフォルトゲートウェイ | PC（ホスト）側 | 自分のサブネット以外へ送るときに、まず渡すルータのアドレス |
| Gateway of last resort | ルータの `show ip route` | ルータのデフォルトルート（0.0.0.0/0）のネクストホップ |

また、Gateway of last resort は「最後に追加されたルート」や「ADが最も大きいルート」とは関係ありません。ルーティングテーブルにルートが追加された順番は表示されませんし、ADは信頼度の値です。

### ひっかけポイント・よくある誤解

- `[110/20]` の **左がAD、右がメトリック**。逆に覚えないこと（ic-006）。
- OSPFのメトリックは**コスト**であって**ホップ数ではない**。ホップ数はRIP（ic-006）。
- `via` の後ろは**ネクストホップ**。宛先ホストでもルータ自身でもルータIDでもない（ic-007）。
- ルーティングテーブルの宛先は**ネットワーク単位**（ホスト単位ではない。ただし /32 のホストルートは例外的に1台を表す）（ic-007）。
- EIGRPのコードは `E` ではなく **`D`**（DUAL由来）（ic-005）。
- デフォルトルートのスタティックは `S*` と表示される（ic-005）。
- `L` は「破棄」ではなく「ルータ自身が受信」するための /32 ルート（ic-027）。
- 直接接続ルートが出ないときは、OSPFやスタティックではなく**インターフェースの up/up** を疑う（ic-028）。
- Gateway of last resort は PC のデフォルトゲートウェイではない（ic-008）。

### 試験のポイント

- コード: C＝直接接続、L＝ローカル（/32）、S＝スタティック、O＝OSPF、D＝EIGRP、R＝RIP、`*`＝デフォルトルート候補。
- エントリの並び: コード → 宛先/プレフィックス長 → [AD/メトリック] → via ネクストホップ → 経過時間 → 出力インターフェース。
- インターフェースが up/up になると C（ネットワーク）と L（自アドレス/32）の2つが載る。
- 確認コマンド: `show ip interface brief`（Status と Protocol が両方 up か）。
- `Gateway of last resort is not set` なら、一致するルートのない宛先は破棄される。

## 2. ルートの選択：ロンゲストマッチ → AD → メトリック

ルーティングの問題で最も大事な考え方がこの章です。ルータが「どのルートを使うか」は、次の3つの基準で決まります。

```
 ┌─────────────────────────────────────────────────────────────────┐
 │ ① プレフィックス長（ロンゲストマッチ）                           │
 │    パケット転送時、宛先に一致するルートのうち最も具体的なものを選ぶ │
 ├─────────────────────────────────────────────────────────────────┤
 │ ② AD（アドミニストレーティブディスタンス）                        │
 │    宛先とプレフィックス長が「同じ」ルートを、異なる情報源（プロトコル）│
 │    から学習したとき、ADが小さい方をテーブルに載せる                 │
 ├─────────────────────────────────────────────────────────────────┤
 │ ③ メトリック                                                    │
 │    同じプロトコルで学習した、同じプレフィックスのルート同士で比べ、 │
 │    小さい方を載せる（等しければ負荷分散＝ECMP）                     │
 └─────────────────────────────────────────────────────────────────┘
```

（ic-001, ic-029）

### 2.1 ロンゲストマッチ（最長一致）

ルーティングテーブルの各ルートは「宛先ネットワーク/プレフィックス長」で表されます。プレフィックス長は「先頭から何ビットが一致していればよいか」を示します。プレフィックス長が**長いほど範囲が狭く、具体的**です。

| プレフィックス | 含むアドレス数 | 具体性 |
|---|---|---|
| 0.0.0.0/0 | すべて（約43億） | 最も曖昧（デフォルトルート） |
| 10.0.0.0/8 | 16,777,216 | |
| 10.1.0.0/16 | 65,536 | |
| 10.1.1.0/24 | 256 | |
| 10.1.1.128/25 | 128 | |
| 10.1.1.10/32 | 1 | 最も具体的（ホストルート） |

パケットの宛先に**一致するルートが複数**あるとき、ルータは**プレフィックス長が最も長いルート**を選びます。これがロンゲストマッチです。「範囲の広い方」でも「先に登録された方」でもありません（登録順は関係しません）。

#### 代表問題の解き方① ic-001（10.1.0.0/16 と 10.1.1.0/24、宛先 10.1.1.5）

1. **宛先を確認**: 10.1.1.5
2. **各ルートに一致するか確認**:
   - 10.1.0.0/16 → 先頭16ビット（10.1）が一致すればよい。10.1.1.5 の先頭は 10.1 → **一致**
   - 10.1.1.0/24 → 先頭24ビット（10.1.1）が一致すればよい。10.1.1.5 の先頭は 10.1.1 → **一致**
3. **一致したルートの中でプレフィックス長が最長のもの**: /24
4. **答え**: 10.1.1.0/24 で転送する。

/16 は、/24 に一致しない宛先（例：10.1.2.5）のときにだけ使われます。また「両方で負荷分散」にはなりません。負荷分散が起きるのは、**宛先とプレフィックス長が同じで、ADとメトリックも等しい**ルートが複数ある場合だけです。

#### 代表問題の解き方② ic-010（4つのルート、宛先 172.16.5.130）

ルート: 0.0.0.0/0、172.16.0.0/16、172.16.5.0/24、172.16.5.128/25

1. **各ルートの範囲を求める**:

   | ルート | 範囲 | 172.16.5.130 は含まれるか |
   |---|---|---|
   | 0.0.0.0/0 | すべて | 含まれる |
   | 172.16.0.0/16 | 172.16.0.0 〜 172.16.255.255 | 含まれる |
   | 172.16.5.0/24 | 172.16.5.0 〜 172.16.5.255 | 含まれる |
   | 172.16.5.128/25 | 172.16.5.128 〜 172.16.5.255 | 含まれる |

2. /25 の範囲を2進数で確かめる: 第4オクテットの先頭1ビットがネットワーク部。
   - 130 ＝ `1`0000010 → 先頭ビットが 1 → .128〜.255 側 → **一致**
3. **4つとも一致**するので、最長の **/25** が選ばれる。
4. もし宛先が 172.16.5.100 なら、100 ＝ `0`1100100 → 先頭ビットが 0 → .0〜.127 側なので /25（.128〜.255）には**一致しない**。その場合は /24 が使われる。

> コツ: /25 は第4オクテットを 0〜127 と 128〜255 に二分する。/26 なら 64 刻み（0, 64, 128, 192）、/27 なら 32 刻み、/28 なら 16 刻み。ブロックサイズ ＝ 256 − マスクの値（/25 のマスク 128 → 256−128 ＝ 128）で範囲を素早く出せる。

#### デフォルトルートとロンゲストマッチ

デフォルトルート 0.0.0.0/0 はすべての宛先に一致しますが、プレフィックス長は 0 で**最も短い**ので、ほかに一致するルートがない場合にだけ使われます（ic-004, ic-010）。

### 2.2 AD（アドミニストレーティブディスタンス）

ADは**ルート情報の信頼度**を表す値で、**小さいほど優先**されます。同じ宛先（同じプレフィックス）へのルートを複数の方法で知った場合、ADが小さい方がルーティングテーブルに載ります（ic-002）。

| ルートの情報源 | デフォルトAD | 覚え方 |
|---|---|---|
| 直接接続 | 0 | 自分につながっているので最も確実 |
| スタティックルート | 1 | 管理者が手で設定したので信頼度が高い |
| EIGRP（内部） | 90 | |
| OSPF | 110 | |
| RIP | 120 | |
| EIGRP（外部） | 170 | |
| 到達不能（使用しない） | 255 | このADのルートはテーブルに載らない |

（参考: eBGP 20、iBGP 200 も出ることがあります）

ADは `show ip route` の `[AD/メトリック]` の左側で確認できます。

```
S    10.1.0.0/16 [1/0] via 192.168.1.2        ← AD 1、メトリック 0
O    10.2.0.0/16 [110/20] via 192.168.1.2     ← AD 110、メトリック 20
D    10.3.0.0/16 [90/2816] via 192.168.1.2    ← AD 90、メトリック 2816
R    10.4.0.0/16 [120/1] via 192.168.1.2      ← AD 120、メトリック 1（ホップ数）
```

#### 代表問題の解き方③ ic-009（OSPF メトリック20 と RIP メトリック1、宛先 10.0.0.0/8）

1. **プレフィックス長を比べる**: どちらも 10.0.0.0/8 で同じ → ロンゲストマッチでは決まらない。
2. **情報源が異なる**（OSPF と RIP）→ **ADで比べる**。OSPF 110 < RIP 120。
3. **答え**: OSPFのルートがテーブルに載る。
4. メトリック（20 と 1）は**比べない**。OSPFのメトリックはコスト、RIPのメトリックはホップ数で、意味も単位も違うため、異なるプロトコル間では比較できない。
5. 「両方載って負荷分散」にもならない。負荷分散されるのは同じプロトコルで学習した、ADとメトリックが等しいルート同士だけ。「先に学習した方」も誤り（学習順は関係ない）。

### 2.3 メトリック

メトリックは**同じルーティングプロトコル内**で、どの経路が良いかを表す値です。小さいほど良い経路です。

| プロトコル | メトリック |
|---|---|
| RIP | ホップ数（経由するルータの数、最大15） |
| OSPF | コスト（参照帯域幅 ÷ インターフェース帯域幅 の合計） |
| EIGRP | 帯域幅と遅延から計算する複合メトリック |
| スタティック | 0（メトリックを指定するパラメータはない） |

同じプロトコルで、同じプレフィックスへのメトリックが等しいルートが複数あれば、両方をテーブルに載せて**負荷分散（ECMP）**します（第9章 ic-031）。

### 2.4 ADとロンゲストマッチの関係（最頻出のひっかけ）

ADとメトリックは、**同じプレフィックスのルートのうち、どれをテーブルに載せるか**を決めるために使います。プレフィックス長が違うルート（例：10.1.0.0/16 と 10.1.1.0/24）は**別の宛先**として扱われ、両方ともテーブルに載ります。そしてパケット転送時には、テーブルに載ったルートの中からロンゲストマッチで選びます。

つまり、**/16 と /24 があれば、ADに関係なく /24 が優先**されます（ic-029）。

#### 代表問題の解き方④ ic-030（S 10.1.0.0/16 [1/0] と O 10.1.1.0/24 [110/30]、宛先 10.1.1.10）

```
S    10.1.0.0/16 [1/0] via 192.168.1.2
O    10.1.1.0/24 [110/30] via 192.168.2.2
```

1. **宛先に一致するルートを探す**: 10.1.1.10 は 10.1.0.0/16 にも 10.1.1.0/24 にも一致する。
2. **プレフィックス長を比べる**: /24 の方が長い。
3. この時点で決まる。**ADは比べない**（ADは同じプレフィックス同士でしか比べない）。
4. **答え**: 192.168.2.2（OSPFのルート）へ転送。
5. 宛先が 10.1.2.10 なら、/24（10.1.1.0〜10.1.1.255）には一致しないので /16 のスタティックルート（192.168.1.2）が使われる。

「ADが小さい方が優先」とだけ覚えていると「スタティック（AD 1）」を選んでしまう、頻出のひっかけです。また、プレフィックス長が違うルート同士で負荷分散されることもなく、一致するルートがあるので破棄もされません。

### 2.5 判断フローチャート

```
            パケット受信（宛先 X）
                    │
                    ▼
     テーブル内で X に一致するルートは？ ──なし──▶ デフォルトルートがあれば使う
                    │                              なければ破棄（Gateway of last resort is not set）
                   あり
                    ▼
     一致したルートのうちプレフィックス長が最長のものを使う
     （そのプレフィックスのルートが複数あれば、すでに AD → メトリック で
       選ばれた結果がテーブルに載っている。メトリックも等しければ負荷分散）
```

### ひっかけポイント・よくある誤解

- 「範囲の広いルートが優先」→ 誤り。**具体的（長い）方が優先**（ic-001）。
- 「先にテーブルに登録された方」「先に学習した方」→ **順番は関係ない**（ic-001, ic-009）。
- 「メトリックが小さいRIPのルートを使う」→ 異なるプロトコルの**メトリックは比較できない**。先にADで比べる（ic-009）。
- 「ADが小さいスタティックが常に勝つ」→ ADは**同じプレフィックス同士でしか比べない**。プレフィックス長が違えばロンゲストマッチが優先（ic-030, ic-029）。
- 「プレフィックス長の違うルート同士で負荷分散」→ されない（ic-030, ic-001）。
- RIPのADは120、ホップ数をメトリックに使う古いプロトコル。EIGRP内部は90、外部は170（ic-002）。

### 試験のポイント

- 比べる順番は **①プレフィックス長 → ②AD → ③メトリック**。
- デフォルトAD: 直接接続 0、スタティック 1、EIGRP内部 90、OSPF 110、RIP 120、EIGRP外部 170。
- ADは小さいほど優先。メトリックも小さいほど優先。
- 0.0.0.0/0 は最も短いので「最後の手段」。
- ロンゲストマッチの計算は「各ルートの範囲を出し、一致するものの中で最長を選ぶ」。

### 関連問題

ic-001, ic-002, ic-009, ic-010, ic-029, ic-030

## 3. IPv4のスタティックルート

### 3.1 スタティックルートとは

スタティックルートは、管理者が `ip route` コマンドで手動設定するルートです。ルーティングプロトコルがなくてもテーブルに載り、ADは **1** です（ic-002）。小規模なネットワーク、スタブネットワーク（出口が1つしかないネットワーク）、インターネットへの出口（デフォルトルート）、バックアップ経路などで使います。

### 3.2 基本の書式（ic-011）

```
ip route <宛先ネットワーク> <サブネットマスク> {<ネクストホップ> | <出力インターフェース> [<ネクストホップ>]} [<AD>]
```

```
R1(config)# ip route 192.168.2.0 255.255.255.0 10.0.0.2
```

| よくある誤り | なぜダメか |
|---|---|
| `ip route 192.168.2.0/24 10.0.0.2` | Cisco IOS の **IPv4** スタティックルートでは /24 のような**プレフィックス表記は使えない**。マスクで書く（IPv6の `ipv6 route` はプレフィックス表記） |
| `ip route 10.0.0.2 255.255.255.0 192.168.2.0` | **宛先とネクストホップの順番が逆** |
| `ip route 192.168.2.0 0.0.0.255 10.0.0.2` | 0.0.0.255 は**ワイルドカードマスク**。ip route では**サブネットマスク**を使う（ワイルドカードマスクを使うのはOSPFの network コマンドやACL） |

設定の確認:

```
R1# show ip route static
      192.168.2.0/24 is subnetted, 1 subnets
S        192.168.2.0 [1/0] via 10.0.0.2
```

### 3.3 転送先の指定方法3種類（ic-033）

| 指定方法 | 例 | 特徴 |
|---|---|---|
| ネクストホップのみ | `ip route 192.168.3.0 255.255.255.0 10.0.0.2` | ルータがネクストホップへのルートを調べ（再帰検索）、出力インターフェースを決める |
| 出力インターフェースのみ | `ip route 192.168.3.0 255.255.255.0 Serial0/0/0` | ポイントツーポイントのリンク向け。テーブル上は「directly connected」と表示される |
| 両方（**完全指定のスタティックルート**） | `ip route 192.168.3.0 255.255.255.0 GigabitEthernet0/1 10.0.0.2` | どのインターフェースから、どのルータへ送るかがすべて明確 |

イーサネットで出力インターフェースだけを指定すると、ルータは宛先がそのリンク上に直接いるものとして扱い、**宛先IPアドレスごとにARP**を行うことになります（対向ルータのプロキシARPに依存し、ARPキャッシュも膨らむ）。そのため、イーサネットでは**ネクストホップも指定する**のが推奨されます。

```
! 出力インターフェースのみ（イーサネットでは非推奨）
S        192.168.3.0/24 is directly connected, GigabitEthernet0/1
! 完全指定
S        192.168.3.0/24 [1/0] via 10.0.0.2, GigabitEthernet0/1
```

スタティックルートの名称の整理（ic-033 の選択肢）:

| 名称 | 定義 |
|---|---|
| 完全指定のスタティックルート | 出力インターフェースとネクストホップの両方を指定 |
| フローティングスタティックルート | ADを大きくしてバックアップ用にしたスタティックルート |
| デフォルトルート | 宛先を 0.0.0.0 0.0.0.0（/0）にしたルート |
| ホストルート | マスクを 255.255.255.255（/32）にした、1台のホストへのルート |

### 3.4 デフォルトルート（ic-004）

```
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
```

- 宛先 0.0.0.0、マスク 0.0.0.0（/0）は**すべての宛先に一致**します。
- ロンゲストマッチでは**最も短い**ルートなので、ほかに一致するルートがない宛先にだけ使われます。
- インターネットへの出口などに使います。最後の 203.0.113.1 は**ネクストホップ**（次に渡すルータ＝ISPのルータ）のアドレスです。
- テーブルでは `S*` と表示され、`Gateway of last resort is 203.0.113.1 to network 0.0.0.0` となります。

```
R1# show ip route | include 0.0.0.0|Gateway
Gateway of last resort is 203.0.113.1 to network 0.0.0.0
S*    0.0.0.0/0 [1/0] via 203.0.113.1
```

ic-004 の誤答の整理:

| 誤答 | 正しくは |
|---|---|
| 203.0.113.1 への通信をすべて破棄するルート | 通信を破棄するルートは、転送先を **Null0** インターフェースにして作る（例: `ip route 10.99.0.0 255.255.0.0 Null0`） |
| 203.0.113.1 をルータ自身のIPアドレスにする | インターフェースのアドレスは `interface` 配下の `ip address` で設定する |
| OSPFで 0.0.0.0 のネットワークを広報 | OSPFの設定は `router ospf` の中で行う。OSPFでデフォルトルートを広報するのは `default-information originate`（第6章） |

### 3.5 ホストルート（ic-012）

1台のホスト（例：サーバ 10.1.1.10）だけを宛先とするルートは **/32**（マスク 255.255.255.255）です。32ビットすべてがネットワーク部なので、1つのアドレスだけを表します。

```
R1(config)# ip route 10.1.1.10 255.255.255.255 192.168.1.2
```

ロンゲストマッチでは /32 が最も具体的なので、「そのホスト宛ての通信だけ別の経路を通したい」ときに使えます。ルーティングテーブルのコード `L`（ローカル）も /32 のホストルートです。

| プレフィックス長 | アドレス数 | 用途 |
|---|---|---|
| /0 | すべて | デフォルトルート |
| /24 | 256 | 一般的なLAN |
| /30 | 4（ホスト用2） | ルータ間のポイントツーポイントリンク |
| /31 | 2 | ポイントツーポイントリンク（RFC 3021） |
| /32 | 1 | ホストルート、ループバック、L ルート |

### 3.6 ネクストホップに到達できないとテーブルに載らない（ic-034）

ルータは、**ネクストホップのアドレスへのルート（通常は直接接続ルート）があるときだけ**、スタティックルートをテーブルに載せます。

```
R1(config)# ip route 192.168.5.0 255.255.255.0 10.0.0.2
R1# show ip route static
（何も表示されない）
R1# show ip interface brief | include 10.0.0
GigabitEthernet0/2     10.0.0.1        YES manual down                  down
```

10.0.0.0/30 を持つインターフェースがダウンしているので、10.0.0.2 へのルートがなく、スタティックルートはテーブルに載りません。インターフェースが up になれば自動で載ります（設定自体は running-config に残っています）。

| 誤答 | なぜ違うか |
|---|---|
| ADが1だから | AD 1は他より優先されるための値で、表示されない原因ではない |
| OSPFが動作していないから | スタティックルートはルーティングプロトコルなしでテーブルに載る |
| 192.168.5.0/24 のホストがまだ通信していないから | ルートがテーブルに載るかは、宛先ホストの通信とは無関係 |

この「インターフェースがダウンするとルートが消える」性質は、次のフローティングスタティックルートでの切り替えにも利用されます。

### 3.7 フローティングスタティックルート（ic-013, ic-035）

ADをわざと大きくして、普段は使われないようにした**バックアップ用**のスタティックルートを**フローティングスタティックルート**と呼びます。

```
! メイン: OSPFで学習するデフォルトルート（AD 110）
! バックアップ: AD 200 のスタティックルート
R1(config)# ip route 0.0.0.0 0.0.0.0 10.1.1.1 200
```

末尾の `200` は **AD** です。メトリックではありません（スタティックルートにはメトリックを指定するパラメータはありません）。有効期限でもありません（スタティックルートは削除するまで残ります）。プレフィックス長は2つ目の 0.0.0.0（サブネットマスク）で指定しています。

動作のイメージ:

```
【平常時】
 OSPFのデフォルトルート  AD 110  ← テーブルに載る（110 < 200）
 スタティック            AD 200  ← 載らない（設定には残っている）

 R1# show ip route 0.0.0.0
 O*E2  0.0.0.0/0 [110/1] via 192.168.12.2, 00:10:00, GigabitEthernet0/0

【OSPFの経路が障害で消えた】
 スタティック            AD 200  ← テーブルに載る（浮かび上がる＝floating）

 R1# show ip route 0.0.0.0
 S*    0.0.0.0/0 [200/0] via 10.1.1.1
```

#### 代表問題の解き方⑤ ic-035（OSPFのバックアップにどのADを指定するか）

1. **メインのルートのADを確認**: OSPF ＝ 110。
2. **バックアップは、メインより大きいADにする**必要がある（メインがある間はメインが勝つように）。
3. 選択肢を評価:
   - 1 → スタティックのデフォルト値。OSPFより優先されてしまい、バックアップにならない。
   - 90 → 110 より小さいので、スタティックが常に優先されてしまう。
   - 110 → OSPFと同じ値。どちらが使われるか明確にならず、バックアップとして確実ではない。
   - **120 → 110 より大きい。正解**。
4. 一般則: メインがOSPF（110）なら **111以上**、EIGRP（90）なら **91以上**。

### ひっかけポイント・よくある誤解

- IPv4の `ip route` は**プレフィックス表記不可**、**ワイルドカードマスク不可**、**順番は 宛先 → マスク → ネクストホップ**（ic-011）。
- 通信を破棄するルートは **Null0** を転送先にする（ic-004）。
- `ip route ... 200` の末尾は**AD**。スタティックにメトリックのパラメータはない（ic-013）。
- フローティングスタティックのADは**メインより大きく**。同じ値ではダメ（ic-035）。
- スタティックルートが表示されない → **ネクストホップに到達できない**（出力インターフェースのダウンなど）（ic-034）。
- 「出力インターフェース＋ネクストホップ」＝**完全指定**。フローティングやホストルートと混同しない（ic-033）。

### 試験のポイント

- `ip route 宛先 マスク ネクストホップ [AD]`。
- デフォルトルート: `ip route 0.0.0.0 0.0.0.0 <ネクストホップ>` → `S*`、Gateway of last resort。
- ホストルート: マスク 255.255.255.255（/32）。
- フローティングスタティック: メインのADより大きいADを末尾に付ける。
- イーサネットでは出力インターフェースだけの指定は避け、ネクストホップを指定する。
- 確認: `show ip route static`、`show ip route`。

### 関連問題

ic-004, ic-011, ic-012, ic-013, ic-033, ic-034, ic-035

## 4. IPv6のルーティングとスタティックルート

### 4.1 ipv6 unicast-routing（ic-037）

Ciscoルータでは、**IPv4のルーティングはデフォルトで有効**ですが、**IPv6のルーティングはデフォルトで無効**です。インターフェースにIPv6アドレスを設定しただけでは、ルータはIPv6パケットを別のネットワークへ転送しません。グローバル設定で次のコマンドが必要です。

```
R1(config)# ipv6 unicast-routing
```

このコマンドを有効にすると:

1. ルータがIPv6パケットを**転送**するようになる。
2. ルータが**ルータ広告（RA）**を送るようになり、LAN上のPCは **SLAAC** でIPv6アドレスを自動設定できるようになる。

| コマンド | 意味 |
|---|---|
| `ipv6 unicast-routing`（グローバル） | **IPv6のルーティング（転送）を有効化**。正解 |
| `ipv6 enable`（インターフェース） | インターフェースでIPv6を有効にし、**リンクローカルアドレスを自動生成**する。ルーティングは有効にならない |
| `ip routing`（グローバル） | **IPv4**のルーティングを有効化（ルータではデフォルトで有効。L3スイッチで使うことが多い） |
| `ipv6 address autoconfig`（インターフェース） | そのインターフェースのIPv6アドレスを**SLAAC**で自動設定する |
| `ipv6 address 2001:db8:1::1/64`（インターフェース） | グローバルユニキャストアドレスを手動設定（リンクローカルも自動生成される） |

### 4.2 IPv6スタティックルートの書式（ic-014）

```
ipv6 route <宛先プレフィックス>/<長さ> {<ネクストホップ> | <出力インターフェース> [<ネクストホップ>]} [<AD>]
```

IPv4と違い、**プレフィックス表記（/64 など）を使います**。

```
R1(config)# ipv6 route 2001:db8:2::/64 2001:db8:12::2
R1(config)# ipv6 route ::/0 2001:db8::1          ← IPv6のデフォルトルート
```

### 4.3 IPv6のデフォルトルート ::/0（ic-014）

| 表記 | 意味 |
|---|---|
| `::/0` | **すべての宛先に一致**。IPv6のデフォルトルート（IPv4の 0.0.0.0/0 に相当） |
| `::/128` | **未指定アドレス**（::）という1つのアドレス。アドレスがまだないときの送信元などに使う（IPv4の 0.0.0.0 に相当）。デフォルトルートではない |
| `::1/128` | **ループバックアドレス**（IPv4の 127.0.0.1 に相当） |

`ip route 0.0.0.0 0.0.0.0 2001:db8::1` は、IPv4用の `ip route` にIPv6アドレスを書いているので誤りです。IPv6には `ipv6 route` を使います。

```
R1# show ipv6 route static
IPv6 Routing Table - default - 5 entries
Codes: C - Connected, L - Local, S - Static, U - Per-user Static route
       ...
S   ::/0 [1/0]
     via 2001:DB8::1
S   2001:DB8:2::/64 [1/0]
     via 2001:DB8:12::2
```

### 4.4 リンクローカルアドレスをネクストホップにする場合（ic-036）

IPv6ではルーティングプロトコル（OSPFv3など）がネイバーのリンクローカルアドレスをネクストホップとして使うのが普通で、スタティックルートでもリンクローカルアドレスを使えます。ただし条件があります。

**リンクローカルアドレス（FE80::/10）は各リンクの中だけで有効**なので、インターフェースが違えば同じ FE80::2 が別のルータを指すこともあります。そのため、ネクストホップにリンクローカルアドレスを使う場合は、**出力インターフェースの指定が必須**です。

```
                  G0/1                         G0/2
   [R2] FE80::2 -------- [R1] -------- FE80::2 [R3]
                                ↑
              どちらも FE80::2 なので、アドレスだけでは区別できない

R1(config)# ipv6 route 2001:db8:2::/64 GigabitEthernet0/1 FE80::2   ← 正しい
R1(config)# ipv6 route 2001:db8:2::/64 FE80::2                      ← 設定できない（インターフェースが必要）
```

| 誤答 | なぜダメか |
|---|---|
| `ipv6 route 2001:db8:2::/64 FE80::2` | リンクローカルアドレスだけでは、どのインターフェースの先にいるルータか判断できない |
| `ip route 2001:db8:2::/64 FE80::2` | `ip route` はIPv4用 |
| `ipv6 route FE80::2 2001:db8:2::/64` | 宛先とネクストホップの順番が逆 |

**グローバルユニキャストアドレス**（2001:db8::/32 の例など）をネクストホップにする場合は、ネクストホップだけでも設定できます（ルータが再帰検索で出力インターフェースを決められるため）。

### ひっかけポイント・よくある誤解

- IPv6ルーティングは**デフォルト無効**。`ipv6 enable` ではなく **`ipv6 unicast-routing`**（ic-037）。
- `ip routing` はIPv4用（ic-037）。
- IPv6のデフォルトルートは **`::/0`**。`::/128`（未指定アドレス）や `::1/128`（ループバック）と混同しない（ic-014）。
- IPv6のスタティックルートは `ipv6 route` で、**プレフィックス表記**。IPv4の `ip route` はマスク表記（ic-014, ic-011）。
- リンクローカルのネクストホップには**出力インターフェースが必須**（ic-036）。

### 試験のポイント

- `ipv6 unicast-routing` → 転送とRA送信が始まり、PCがSLAACできる。
- `ipv6 route ::/0 <ネクストホップ>` がIPv6のデフォルトルート。
- `ipv6 route <プレフィックス> <インターフェース> FE80::x`（リンクローカル時はインターフェース必須）。
- IPv6でもADやロンゲストマッチの考え方はIPv4と同じ。

### 関連問題

ic-014, ic-036, ic-037

## 5. OSPFの基礎：リンクステート、SPF、エリア

### 5.1 OSPFとは（ic-003）

OSPF（Open Shortest Path First）は、IETFが標準化した**リンクステート型**の内部ゲートウェイプロトコル（IGP）です。

| 特徴 | OSPF | 比較: RIP | 比較: EIGRP |
|---|---|---|---|
| 種類 | **リンクステート型** | ディスタンスベクター型 | 拡張ディスタンスベクター型（ハイブリッド） |
| 標準/独自 | **IETF標準**（他社機器とも使える） | 標準 | Cisco開発（現在は一部公開） |
| メトリック | **コスト**（帯域幅から計算） | ホップ数 | 帯域幅・遅延など |
| アルゴリズム | **SPF（ダイクストラ）** | ベルマン・フォード | DUAL |
| 更新 | **変化があったときだけ**送る（Helloで隣接維持） | **30秒ごと**にテーブル全体を送る | 変化時のみ |
| AD | 110 | 120 | 90（内部）/170（外部） |
| コード | O | R | D |

OSPFでは、各ルータがネットワーク全体の構成（リンク状態）を共有し、**それぞれが自分で**最短経路を計算します。変化があったときだけ情報を送るので、ネットワークの変化に素早く対応できます（**収束が速い**）。

### 5.2 リンクステート型の動作の流れ（ic-045）

```
 ① Helloでネイバーを見つける
        │   （224.0.0.5 宛てに Hello を送り合う）
        ▼
 ② LSA（リンク状態の情報）を交換し、エリア内のすべてのルータが
    同じ LSDB（リンクステートデータベース）を持つ
        │
        ▼
 ③ 各ルータが SPF（ダイクストラ）アルゴリズムで、
    自分を根（起点）とした最短経路の木（SPFツリー）を計算する
        │
        ▼
 ④ 計算結果をルーティングテーブルに載せる（コード O）
```

- **LSA**（Link State Advertisement）: 「自分にはこういうリンクがあり、コストはいくつ」という情報の単位。
- **LSDB**（Link State Database）: 集めたLSAのデータベース。エリア内の全ルータで同一になる＝エリアの「地図」。
- **SPF（ダイクストラ）アルゴリズム**: 地図から、自分を起点として**合計コストが最小**となる経路の木を計算する。

ほかのアルゴリズムとの区別（ic-045 の誤答）:

| アルゴリズム/プロトコル | 使われる場所 |
|---|---|
| SPF（ダイクストラ） | **OSPF**（正解） |
| DUAL | EIGRP |
| ベルマン・フォード | RIP などのディスタンスベクター型 |
| スパニングツリー（STP） | L2のループ防止。ルーティング計算には使わない |

確認コマンド例:

```
R1# show ip ospf database

            OSPF Router with ID (1.1.1.1) (Process ID 1)

                Router Link States (Area 0)

Link ID         ADV Router      Age         Seq#       Checksum Link count
1.1.1.1         1.1.1.1         120         0x80000003 0x00A1B2 3
2.2.2.2         2.2.2.2         118         0x80000002 0x003C4D 2
3.3.3.3         3.3.3.3         115         0x80000002 0x0055E6 2

                Net Link States (Area 0)

Link ID         ADV Router      Age         Seq#       Checksum
192.168.123.3   3.3.3.3         115         0x80000001 0x00ABCD
```

### 5.3 エリアとバックボーンエリア（ic-015）

OSPFはネットワークを**エリア**に分けて管理できます。エリアを分けると、LSAのやり取りやSPF計算の範囲がエリア内に限定され、大規模ネットワークでも負荷を抑えられます。

```
          エリア 1            エリア 0（バックボーン）           エリア 2
     [R4]----[R5]----ABR----[R1]----[R2]----[R3]----ABR----[R6]----[R7]
                   (R5兼)                           (R6兼)
     ※ すべてのエリアはエリア0に接続する必要がある
     ※ ABR（エリア境界ルータ）: 複数のエリアに属するルータ
```

- **エリア0＝バックボーンエリア**。OSPFの中心となるエリアです。
- **シングルエリア**で構成する場合は、通常 **エリア0** を使います。
- マルチエリア構成では、**すべてのエリアがエリア0に接続**する必要があります。
- エリア1など他の番号も設定はできますが、シングルエリアなら通常エリア0です。
- CCNA 200-301 では主に**シングルエリア（エリア0のみ）のOSPFv2**が出題範囲です。

**プロセスIDとエリア番号は無関係**です。`router ospf 1` の「1」は**プロセスID**で、そのルータ内でだけ意味を持つ番号です（ネイバー同士で一致させる必要もありません。ic-018）。

また、OSPFではインターフェースごとに所属するエリアを**必ず指定**します（network コマンドの `area` か、`ip ospf <プロセスID> area <エリア>`）。「エリア番号は指定しない」は誤りです。

### ひっかけポイント・よくある誤解

- 「ディスタンスベクター型でホップ数」「30秒ごとにテーブル全体を送る」→ これは **RIP**（ic-003）。
- 「Cisco独自」→ OSPFは**IETF標準**。Ciscoが開発したのは**EIGRP**（ic-003）。
- DUAL＝EIGRP、ベルマン・フォード＝RIP、スパニングツリー＝L2ループ防止（ic-045）。
- プロセスIDとエリア番号は無関係（ic-015）。

### 試験のポイント

- OSPF＝リンクステート型、IETF標準、メトリックはコスト、SPF（ダイクストラ）、AD 110。
- 流れ: Hello → LSA交換 → LSDB同期 → SPF計算 → ルーティングテーブル。
- エリア0＝バックボーン。シングルエリアはエリア0。全エリアはエリア0に接続。

### 関連問題

ic-003, ic-015, ic-045

## 6. OSPFの設定

この章で扱う設定例のトポロジ:

```
                        Loopback0 1.1.1.1/32
   PC LAN                                          ISP
192.168.1.0/24                                  203.0.113.1
     |                                               |
     | G0/0 .1                               G0/2 .2 | 203.0.113.0/30
    [R1]--------------------------------------------+
     | G0/1 .1
     |  10.0.12.0/30
     | G0/0 .2
    [R2] Loopback0 2.2.2.2/32
     | G0/1 .1
     |  192.168.2.0/24（PC LAN）
```

### 6.1 OSPFの有効化：network コマンド（ic-016）

```
R1(config)# router ospf 1
R1(config-router)# network 192.168.1.0 0.0.0.255 area 0
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0
```

| 部分 | 意味 |
|---|---|
| `router ospf 1` | OSPFプロセス（プロセスID 1）を作成し、OSPFの設定モードに入る（グローバル設定モードで実行） |
| `network 192.168.1.0` | 対象とするアドレス |
| `0.0.0.255` | **ワイルドカードマスク** |
| `area 0` | 所属させるエリア番号 |

`network` コマンドは「**この範囲のIPアドレスを持つインターフェースでOSPFを有効にする**」という意味です。「このネットワークを広報する」と直接書いているのではなく、条件に一致したインターフェースでOSPFが有効になり、その結果としてそのインターフェースのネットワークが広報されます。

#### ワイルドカードマスク

ワイルドカードマスクは、各ビットについて

- **0** ＝「このビットは**一致が必要**」
- **1** ＝「このビットは**どんな値でもよい**」

を意味します。サブネットマスクと0/1が逆になるので、**サブネットマスクを反転したもの**（各オクテットについて 255 − 値）として求められます。

| サブネットマスク | ワイルドカードマスク | 計算 |
|---|---|---|
| 255.255.255.0（/24） | 0.0.0.255 | 255−255, 255−255, 255−255, 255−0 |
| 255.255.255.252（/30） | 0.0.0.3 | 255−252 ＝ 3 |
| 255.255.255.240（/28） | 0.0.0.15 | 255−240 ＝ 15 |
| 255.255.0.0（/16） | 0.0.255.255 | |
| 255.255.255.255（/32） | 0.0.0.0 | 特定の1アドレスに完全一致 |
| 0.0.0.0（/0） | 255.255.255.255 | すべてに一致 |

`192.168.1.0 0.0.0.255` は 192.168.1.0 〜 192.168.1.255 を表します。ワイルドカードマスクは**ACL**でも同じ考え方を使います。

```
! よく使う書き方のバリエーション
network 192.168.1.1 0.0.0.0 area 0        ← そのアドレスを持つインターフェース1つだけ
network 0.0.0.0 255.255.255.255 area 0    ← すべてのインターフェースでOSPFを有効化
```

`network 0.0.0.0 255.255.255.255 area 0` は**すべてのインターフェースでOSPFを有効にする**コマンドであって、デフォルトルートを配布するコマンドではありません（ic-039 の誤答）。

ic-016 の誤答の整理:

| 誤答 | 正しくは |
|---|---|
| サブネットマスク | サブネットマスクなら 255.255.255.0 と書く。ワイルドカードマスクは0と1が逆 |
| OSPFのルータID | ルータIDは `router-id` コマンドなどで設定 |
| エリア番号 | エリア番号は末尾の `area 0` |

### 6.2 インターフェースでの有効化：ip ospf <プロセスID> area <エリア>（ic-040）

network コマンドを使わずに、インターフェース設定モードで直接OSPFを有効化することもできます。

```
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip ospf 1 area 0
```

| 方法 | 設定場所 | 特徴 |
|---|---|---|
| `network <アドレス> <ワイルドカード> area <エリア>` | `router ospf` の中 | アドレスの範囲で、一致するインターフェースをまとめて指定 |
| `ip ospf <プロセスID> area <エリア>` | インターフェース | どのインターフェースで有効かが一目でわかる |

紛らわしいインターフェースコマンドの整理（ic-040 の誤答）:

| コマンド | 実行するモード | 意味 |
|---|---|---|
| `ip ospf 1 area 0` | インターフェース | **このインターフェースでOSPFを有効化** |
| `router ospf 1` | グローバル | OSPFプロセスを作成し、OSPF設定モードに入る |
| `ip ospf priority 1` | インターフェース | DR選出のプライオリティ。OSPFは有効にならない |
| `ip ospf cost 1` | インターフェース | インターフェースのコスト。OSPFは有効にならない |

### 6.3 passive-interface（ic-038）

PCだけがつながるLAN側のインターフェースからHelloを送っても意味がありません。それどころか、悪意のある機器がOSPFのネイバーになって**偽のルートを流し込む危険**もあります。

`passive-interface` を設定すると:

- そのインターフェースから **Helloを送らなくなる**（受信したHelloも処理しないので、ネイバーにならない）
- しかし **そのインターフェースのネットワークは引き続きOSPFで他のルータへ広報される**
- インターフェース自体は動作し続け、PCとの通信もできる（shutdown ではない）
- コストとは無関係

```
R1(config)# router ospf 1
R1(config-router)# passive-interface GigabitEthernet0/0

! すべてを passive にしてから、必要なものだけ戻す書き方
R1(config-router)# passive-interface default
R1(config-router)# no passive-interface GigabitEthernet0/1
```

`passive-interface default` は**すべてのインターフェースを passive にする**コマンドです（ic-039 の誤答）。

確認:

```
R1# show ip protocols
*** IP Routing is NSF aware ***

Routing Protocol is "ospf 1"
  Outgoing update filter list for all interfaces is not set
  Incoming update filter list for all interfaces is not set
  Router ID 1.1.1.1
  Number of areas in this router is 1. 1 normal 0 stub 0 nssa
  Maximum path: 4
  Routing for Networks:
    10.0.12.0 0.0.0.3 area 0
    192.168.1.0 0.0.0.255 area 0
  Passive Interface(s):
    GigabitEthernet0/0
  Routing Information Sources:
    Gateway         Distance      Last Update
    2.2.2.2              110      00:05:12
  Distance: (default is 110)
```

### 6.4 デフォルトルートの配布：default-information originate（ic-039）

インターネットにつながるルータ（R1）だけにデフォルトルートを設定し、それをOSPFで社内の他のルータに配布できます。

```
! ① R1自身にデフォルトルートを設定（router ospf の外、グローバル設定）
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1

! ② OSPFで配布する
R1(config)# router ospf 1
R1(config-router)# default-information originate
```

R2 では次のように見えます。

```
R2# show ip route ospf
Gateway of last resort is 10.0.12.1 to network 0.0.0.0

O*E2  0.0.0.0/0 [110/1] via 10.0.12.1, 00:00:21, GigabitEthernet0/0
      192.168.1.0/24 ...
O        192.168.1.0/24 [110/2] via 10.0.12.1, 00:10:03, GigabitEthernet0/0
```

- `O*E2`: OSPFの外部ルート（タイプ2）で、`*` はデフォルトルートの候補。
- すべてのルータが個別にデフォルトルートを設定しなくて済む。
- `default-information originate` は、**自分のルーティングテーブルにデフォルトルートがあるときに**それを広報します（`always` キーワードを付けると、デフォルトルートがなくても広報）。そのため、①の `ip route 0.0.0.0 0.0.0.0 ...` だけでは配布されず、②だけでも（always なしでは）配布されません。

### 6.5 ルータIDの決定（ic-017）

**ルータID**はOSPFルータを識別する 32 ビットの値で、`1.1.1.1` のような **IPv4アドレスの形式**で表します。OSPFドメイン内でルータごとに**異なる**必要があります（重複するとネイバー関係やLSAで問題が起きる）。

ルータIDは次の優先順位で決まります。

| 優先順位 | 決定方法 | 備考 |
|---|---|---|
| ① 最優先 | `router-id` コマンドで**手動設定**した値 | 明示的に設定した値がそのまま使われる |
| ② | **ループバックインターフェース**のうち**最大**のIPアドレス | 手動設定がない場合。ループバックは物理的にダウンしないので安定したIDになる |
| ③ | **アップ状態の物理インターフェース**のうち**最大**のIPアドレス | 手動設定もループバックもない場合 |

```
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1

R1# show ip ospf
 Routing Process "ospf 1" with ID 1.1.1.1
 ...
```

#### 代表問題の解き方⑥ ルータIDの判定

例: R1 に router-id の設定がなく、次のインターフェースがある。

```
Loopback0        10.10.10.1
Loopback1        10.1.1.1
G0/0 (up)        192.168.100.1
G0/1 (up)        172.16.1.1
```

1. `router-id` の手動設定は？ → なし。
2. ループバックはある？ → ある。ループバックの中で最大は **10.10.10.1**（10.10 > 10.1）。
3. → ルータIDは **10.10.10.1**。物理インターフェースの 192.168.100.1 の方が大きいが、ループバックが優先されるので使われない。

### 6.6 ルータIDの変更は再起動まで反映されない（ic-041）

決定したルータIDは、**ルータの再起動**か **`clear ip ospf process`** を実行するまで変わりません。ルータIDはネイバー関係やLSAの識別に使われるため、動作中に勝手に変わると混乱が起きるからです。

```
R1(config)# router ospf 1
R1(config-router)# router-id 2.2.2.2
% OSPF: Reload or use "clear ip ospf process" command, for this to take effect

R1# clear ip ospf process
Reset ALL OSPF processes? [no]: yes

R1# show ip ospf | include ID
 Routing Process "ospf 1" with ID 2.2.2.2
```

| 誤答 | なぜダメか |
|---|---|
| ループバックインターフェースを作成する | 手動の router-id の方が優先されるので変わらない。反映にはやはりプロセスの再起動が必要 |
| しばらく待つと自動で反映される | ルータIDはプロセス起動時に決まり、自動では変わらない |
| router-id をもう一度入力する | 同じコマンドを再入力しても、動作中のプロセスには反映されない |

`clear ip ospf process` は**ネイバー関係がいったん切れる**ので、実務では影響を考えて実行します。

### ひっかけポイント・よくある誤解

- network コマンドの `0.0.0.255` は**ワイルドカードマスク**（サブネットマスクではない）（ic-016）。
- `router ospf 1` の 1 は**プロセスID**。エリア番号でもルータIDでもない（ic-015, ic-040）。
- `ip ospf priority` / `ip ospf cost` ではOSPFは有効にならない（ic-040）。
- passive-interface は**広報を止めない**。止めるのはHello（ic-038）。shutdown でもない。
- デフォルトルートの配布は `default-information originate`。`network 0.0.0.0 255.255.255.255 area 0` は全インターフェースの有効化、`passive-interface default` は全インターフェースのpassive化（ic-039）。
- ルータIDの優先順位は **手動 → ループバック最大 → 物理（up）最大**（ic-017）。
- ルータIDの変更は `clear ip ospf process` か再起動が必要（ic-041）。

### 試験のポイント

- `router ospf <PID>` → `network <addr> <wildcard> area <id>`、またはインターフェースで `ip ospf <PID> area <id>`。
- ワイルドカード ＝ 255 − サブネットマスク（各オクテット）。
- `passive-interface <if>`: Hello停止、ネットワークは広報される。
- `default-information originate`: 自分のデフォルトルートをOSPFで配布（他ルータでは `O*E2`）。
- ルータID: `router-id` → ループバック最大 → up物理最大。変更反映は `clear ip ospf process`。
- 確認: `show ip ospf`、`show ip protocols`、`show ip ospf interface`。

## 7. OSPFネイバー

### 7.1 ネイバーになるための条件（ic-018, ic-043）

OSPFルータは Hello パケットを交換して、Helloの中身が自分と合っている相手とだけネイバーになります。

| 項目 | 一致が必要か | 補足 |
|---|---|---|
| **エリアID** | **一致が必要** | 同じリンク上のインターフェースは同じエリアに所属している必要がある |
| **サブネット（ネットワークアドレスとマスク）** | **一致が必要** | 同じサブネットにいる必要がある |
| **Helloインターバル / Deadインターバル** | **一致が必要** | タイマーが一致しないとネイバーにならない |
| **認証の設定** | **一致が必要** | 認証の種類とパスワード |
| **スタブエリアのフラグ** | **一致が必要** | Helloに含まれる |
| **MTU** | 一致が必要（FULLになるため） | MTUはHelloには含まれず、不一致だとネイバー自体は見えるが、DBD交換の段階（ExStart/Exchange）で止まり、FULLにならない |
| **ルータID** | **異なる必要がある** | 重複してはいけない |
| **プロセスID** | 一致しなくてよい | ルータ内でだけ意味を持つ番号 |

ネイバーにならないときのトラブルシューティングで頻出のポイントです。

#### 代表問題の解き方⑦ ic-043（R1 はエリア0、R2 はエリア1）

1. 直結リンクの両端でエリアIDが違う。
2. HelloパケットにはエリアIDが含まれており、受信したHelloのエリアIDが自分と一致しないと、そのHelloは破棄される。
3. → **ネイバーにならない**。
4. エリアが自動で変わること、ルータIDの大きい方のエリアに統一されることはない。「ネイバーになってエリア0とエリア1のルートを交換する」も誤り（同じリンク上のインターフェースは同じエリアでなければならない）。

確認・調査のコマンド:

```
R1# show ip ospf interface GigabitEthernet0/1
GigabitEthernet0/1 is up, line protocol is up
  Internet Address 10.0.12.1/30, Area 0, Attached via Network Statement
  Process ID 1, Router ID 1.1.1.1, Network Type BROADCAST, Cost: 1
  Transmit Delay is 1 sec, State DR, Priority 1
  Designated Router (ID) 1.1.1.1, Interface address 10.0.12.1
  No backup designated router on this network
  Timer intervals configured, Hello 10, Dead 40, Wait 40, Retransmit 5
  ...
  Neighbor Count is 0, Adjacent neighbor count is 0

R1# debug ip ospf adj
OSPF-1 ADJ   Gi0/1: Rcv pkt from 10.0.12.2, area 0.0.0.0, mismatched area 0.0.0.1 in the header
```

`show ip ospf interface` で各インターフェースのエリア、タイマー、ネットワークタイプ、コスト、プライオリティ、DR/BDRを確認でき、`debug ip ospf adj` で不一致の内容を調べられます。

### 7.2 Hello / Dead インターバル（ic-019）

OSPFルータは Hello パケットを定期的に送ってネイバーの生存を確認します。**Deadインターバル**の間Helloが届かないと、そのネイバーはダウンしたと判断します。

| ネットワークタイプ | Hello | Dead |
|---|---|---|
| ブロードキャスト（イーサネット） | **10秒** | **40秒** |
| ポイントツーポイント | 10秒 | 40秒 |
| NBMA（フレームリレーなど） | 30秒 | 120秒 |

Deadインターバルはデフォルトで**Helloの4倍**です。値は変更できますが、**ネイバー同士で一致**させる必要があります。

```
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip ospf hello-interval 5
R1(config-if)# ip ospf dead-interval 20
```

似た数字との混同（ic-019 の誤答）:

| 数字 | 正体 |
|---|---|
| 10 / 40 | **OSPF（ブロードキャスト、P2P）** |
| 30 / 120 | OSPF（NBMA） |
| 2 / 20 | **STP**のHelloタイマー（2秒）と最大エージタイマー（20秒）。転送遅延は15秒 |
| 30 / 180 | **RIP**の更新タイマー（30秒）と無効タイマー（180秒） |

### 7.3 ネイバーの状態遷移（ic-024）

```
 Down ─▶ Init ─▶ 2-Way ─▶ ExStart ─▶ Exchange ─▶ Loading ─▶ Full
  │       │        │         │           │           │         │
  │       │        │         │           │           │         └ LSDBが同期完了（完全な隣接）
  │       │        │         │           │           └ 足りないLSAを要求・受信中
  │       │        │         │           └ DBD（データベースの要約）を交換中
  │       │        │         └ マスター/スレーブを決め、DB交換の準備
  │       │        └ お互いのHelloに自分のルータIDが入っている（双方向確認）
  │       │           ※ ここでDR/BDR選出が行われる
  │       └ 相手のHelloを受信したが、相手はまだ自分を認識していない
  └ Helloを受信していない
```

| 状態 | 意味 | 止まっているときに疑うこと |
|---|---|---|
| INIT | 相手のHelloを受信したが、相手のHelloに自分のルータIDがまだ入っていない | 片方向の通信、ACLでHelloが遮断 |
| 2-WAY | お互いのHelloを確認できた | **DROTHER同士ならこれが正常**（異常ではない） |
| EXSTART | データベース交換を始める準備 | **MTUの不一致**、ルータIDの重複 |
| EXCHANGE | DBDの交換中 | MTUの不一致 |
| **FULL** | **LSDBが同期し、隣接関係が完全に確立**。ルーティング情報の交換が完了 | — |

ブロードキャスト型ネットワークでは、すべてのルータがDR/BDRとFULLになり、**DROTHER同士は 2-WAY のまま止まります**。これは正常な状態です（第8章）。

### 7.4 show ip ospf neighbor の読み方（ic-044）

```
R1# show ip ospf neighbor

Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           1   FULL/BDR        00:00:35    192.168.123.2   GigabitEthernet0/0
3.3.3.3         100   FULL/DR         00:00:31    192.168.123.3   GigabitEthernet0/0
4.4.4.4           1   2WAY/DROTHER    00:00:38    192.168.123.4   GigabitEthernet0/0
5.5.5.5           0   FULL/  -        00:00:33    10.0.15.2       GigabitEthernet0/1
```

| 列 | 意味 |
|---|---|
| Neighbor ID | **相手のルータID** |
| Pri | 相手のOSPFプライオリティ |
| State | `<ネイバーとの状態>/<ネイバー（相手）の役割>` |
| Dead Time | 残り時間。これが0になるまでにHelloが来ないとダウン扱い |
| Address | 相手インターフェースのIPアドレス |
| Interface | 自分側のインターフェース |

State 列の読み方:

| 表示 | 意味 |
|---|---|
| `FULL/DR` | 相手がDRで、完全な隣接関係 |
| `FULL/BDR` | 相手がBDRで、完全な隣接関係 |
| `2WAY/DROTHER` | 相手もDROTHERで、DROTHER同士なので2WAYで止まっている＝**正常**（自分もDROTHERの場合） |
| `FULL/ -` | ポイントツーポイントなど、DR/BDRがないリンク |

**「/」の右はネイバー（相手）の役割**です。R1 自身の役割は `show ip ospf interface` の `State DR` などで確認します。また接続が切れたネイバーは一覧から消えます（Down）。

#### 代表問題の解き方⑧ ic-044（FULL/BDR）

1. 「/」の左 `FULL` → R1とそのネイバーの隣接は完全に確立（情報の交換は完了している）。
2. 「/」の右 `BDR` → **そのネイバー（相手）**がBDR。
3. → 「そのネイバーはBDRで、R1との隣接関係は完全に確立している」が正解。「R1自身がBDR」は誤り。

### ひっかけポイント・よくある誤解

- ネイバーの条件で「ルータIDが一致」→ 逆。**ルータIDは異なる必要がある**（ic-018）。
- 「プロセスIDが一致」→ **一致しなくてよい**（ic-018）。
- エリアIDが違うとネイバーにならない。自動修正も統一もされない（ic-043）。
- 10/40 は OSPF、2/20 は STP、30/180 は RIP、30/120 は OSPF NBMA（ic-019）。
- 2-WAY で止まるのは DROTHER 同士なら**正常**（ic-024）。
- EXSTART で止まる → **MTU不一致**を疑う（ic-024）。
- `FULL/BDR` の BDR は**相手**の役割（ic-044）。

### 試験のポイント

- 一致が必要: エリアID、サブネット、Hello/Dead、認証、スタブフラグ（＋FULLになるにはMTU）。
- 異なる必要: ルータID。どうでもよい: プロセスID。
- デフォルト: Hello 10秒 / Dead 40秒（Deadは4倍）。
- 状態: Down → Init → 2-Way → ExStart → Exchange → Loading → Full。
- 確認: `show ip ospf neighbor`、`show ip ospf interface`、`debug ip ospf adj`。

### 関連問題

ic-018, ic-019, ic-024, ic-043, ic-044

## 8. DR/BDRとOSPFのネットワークタイプ

### 8.1 DR/BDRが必要な理由（ic-020）

イーサネットのように、1つのセグメントに多数のルータがつながる**ブロードキャスト型ネットワーク**で、全員が互いに完全な隣接関係（FULL）を作ると、関係の数は

```
N × (N − 1) / 2
```

に増えてしまいます。たとえばルータ5台なら 5×4/2 ＝ 10、10台なら 45 の隣接関係が必要で、LSAのやり取りも重複します。

そこで、セグメントごとに**DR（代表ルータ）**を1台決め、各ルータは**DRとBDRとだけFULL**になります。LSAはDRが代表して取りまとめ・配布します。**BDR（バックアップ代表ルータ）**は、DRが故障したときにすぐ引き継ぐ予備です。DRでもBDRでもないルータは**DROTHER**と呼ばれます。

```
 DR/BDRなし（全員がFULL）            DR/BDRあり
                                       
   R1───R2                             R1(DR)   R2(BDR)
   │ ╲ ╱ │                              │ ╲      ╱ │
   │  ╳  │      10本                     │   ╲  ╱   │
   │ ╱ ╲ │                              │    ╳     │     DROTHER同士（R3-R4, R3-R5, R4-R5）は
   R3───R4  ＋R5                        R3  R4  R5        2-WAY のまま（正常）
                                     各DROTHERはDRとBDRだけとFULL
```

- DROTHER → DR/BDR 宛てのLSAは **224.0.0.6**（AllDRouters）
- DR → 全OSPFルータ宛ては **224.0.0.5**（AllSPFRouters、Helloもこのアドレス）

### 8.2 DR/BDRが選出されるネットワークタイプ（ic-020, ic-042）

| ネットワークタイプ | 例 | DR/BDR | Hello/Dead |
|---|---|---|---|
| **ブロードキャスト** | イーサネット（デフォルト） | **選出される** | 10/40 |
| **ポイントツーポイント** | シリアル回線（HDLC/PPP）、`ip ospf network point-to-point` を設定したイーサネット | **選出されない**（ルータが2台しかいないので不要） | 10/40 |
| NBMA | フレームリレー | 選出される | 30/120 |

「どのネットワークタイプでも必ず選出される」「OSPFではDR/BDRは使われない」はどちらも誤りです。

### 8.3 DRの選出ルール（ic-021, ic-022）

DRの選出は、各インターフェースのOSPFプライオリティとルータIDを使って次の順で行われます。

| 順番 | 比較する値 | 優先 |
|---|---|---|
| ① | インターフェースの**OSPFプライオリティ** | **大きい方**が優先（デフォルト **1**、範囲 **0〜255**） |
| ② | （①が同じなら）**ルータID** | **大きい方**が優先 |

- 1位がDR、2位がBDRになります。
- **プライオリティ0** のルータは**DR/BDRの選出に参加しない**（DRにもBDRにもならない）。OSPFは動作し、ネイバー関係も作ります。
- IPアドレスそのものやOSPFのコストは比較に使いません（コストは経路の選択に使う値）。
- **DRにはプリエンプションがない**: 選出後にプライオリティの高いルータが加わっても、DRは交代しません。DRが故障して初めて、BDRがDRに昇格し、新しいBDRが選出されます。

```
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip ospf priority 255   ← DRになりやすくする（最大255）
R4(config-if)# ip ospf priority 0     ← DR/BDRにしない
```

**STPとの違いに注意**: STPのルートブリッジ選出は、ブリッジID（プライオリティ＋MAC）が**小さい方**が優先です。OSPFのDR選出は**大きい方**が優先なので、逆です。

#### 代表問題の解き方⑨ DR/BDR選出

あるイーサネットセグメントに、次の4台が同時に起動した。

| ルータ | プライオリティ | ルータID |
|---|---|---|
| R1 | 1 | 1.1.1.1 |
| R2 | 1 | 4.4.4.4 |
| R3 | 100 | 2.2.2.2 |
| R4 | 0 | 9.9.9.9 |

1. **プライオリティ0を除外**: R4 は選出に参加しない（ルータIDが最大でもDROTHER）。
2. **プライオリティで比較**: R3（100）が最大 → **R3がDR**。
3. **残り（R1, R2）はプライオリティ1で同じ** → ルータIDで比較。4.4.4.4 > 1.1.1.1 → **R2がBDR**。
4. R1, R4 は DROTHER。R1 と R4 の間は 2-WAY のまま（正常）。
5. その後、プライオリティ200のR5が加わっても、**DRはR3のまま**（プリエンプションなし）。

R1 で見ると:

```
R1# show ip ospf neighbor
Neighbor ID     Pri   State           Dead Time   Address         Interface
4.4.4.4           1   FULL/BDR        00:00:36    192.168.10.2    GigabitEthernet0/0
2.2.2.2         100   FULL/DR         00:00:33    192.168.10.3    GigabitEthernet0/0
9.9.9.9           0   2WAY/DROTHER    00:00:39    192.168.10.4    GigabitEthernet0/0
```

ic-022 の誤答の整理（`ip ospf priority 0`）:

| 誤答 | 正しくは |
|---|---|
| 必ずDRになる | DRになりやすくするには、プライオリティを大きくする（最大255） |
| OSPFが無効になる | OSPFは動作し、ネイバー関係も作る。DR/BDRにならないだけ |
| コストが0になる | コストは `ip ospf cost` で設定する別の値 |

性能の低いルータや、DRにしたくないルータのプライオリティを0にしておくと、DR/BDRの役割を他のルータに任せられます。

### 8.4 ip ospf network point-to-point（ic-042）

2台のルータだけをイーサネットで直結している場合でも、イーサネットのデフォルトのネットワークタイプは**ブロードキャスト**なので、DR/BDRの選出が行われます。選出には**Waitタイマー**（デフォルトでDeadインターバルと同じ40秒）がかかり、FULLになるまでに時間がかかります。

両端で `ip ospf network point-to-point` を設定すると:

- **DR/BDRの選出が行われず**、隣接関係が早く確立する（すぐにFULLになる）
- Helloは送られる（Helloを止めるのは passive-interface）
- コストは変わらない
- ルートは通常どおり広報される
- **両端の設定をそろえる**必要がある（片側だけだと、ネイバーにはなってもLSDBの解釈がずれて正しくルートが計算されないことがある）

```
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip ospf network point-to-point

R1# show ip ospf interface GigabitEthernet0/1 | include Network Type
  Process ID 1, Router ID 1.1.1.1, Network Type POINT_TO_POINT, Cost: 1

R1# show ip ospf neighbor
Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           0   FULL/  -        00:00:37    10.0.12.2       GigabitEthernet0/1
```

### ひっかけポイント・よくある誤解

- DR/BDRはポイントツーポイントでは選出されない（ic-020）。
- DR選出の最初の比較は**プライオリティ（大きい方）**。ルータIDも**大きい方**。STP（小さい方）と逆（ic-021）。
- IPアドレス、コストは DR 選出に使わない（ic-021）。
- プライオリティ0 ＝ DR/BDRにならないだけで、OSPF自体は有効（ic-022）。
- DRは**プリエンプションなし**（ic-021）。
- `ip ospf network point-to-point` は Hello を止めない・コストを変えない・広報を止めない（ic-042）。

### 試験のポイント

- DR/BDR はブロードキャスト（とNBMA）で選出。関係の数 N(N−1)/2 を減らすため。
- 選出: プライオリティ最大 → ルータID最大。デフォルト1、範囲0〜255、0は不参加。
- DRはプリエンプトしない。BDRは予備。それ以外はDROTHER。
- DROTHER同士は2-WAY（正常）、DR/BDRとはFULL。
- P2Pリンクは `ip ospf network point-to-point` で選出を省略し、素早くFULLに。

### 関連問題

ic-020, ic-021, ic-022, ic-042

## 9. OSPFのコストと経路選択

### 9.1 コストの計算式（ic-023）

OSPFのコストは次の式で計算されます。

```
コスト ＝ 参照帯域幅 ÷ インターフェースの帯域幅
（参照帯域幅のデフォルト ＝ 100 Mbps）
```

- コストは**整数**で、**最小値は1**（1未満は1に切り上げ）。
- 小数点以下は切り捨て。

| インターフェース | 参照帯域幅 100Mbps（デフォルト） | 参照帯域幅 1000Mbps | 参照帯域幅 10000Mbps |
|---|---|---|---|
| 10 Mbps（Ethernet） | 10 | 100 | 1000 |
| 100 Mbps（FastEthernet） | **1** | **10** | 100 |
| 1 Gbps（GigabitEthernet） | **1**（計算上0.1） | **1** | 10 |
| 10 Gbps | 1 | 1 | 1 |
| 1.544 Mbps（T1シリアル） | 64 | 647 | 6476 |

デフォルトでは **100Mbps以上のリンクはすべてコスト1** になり、速さの違いが区別できません。そのため実際のネットワークでは、`router ospf` の中で `auto-cost reference-bandwidth` を大きくすることが多いです。この値は**全ルータでそろえる**必要があります（そろえないと、ルータごとにコストの基準が違い、最適でない経路が選ばれる）。

```
R1(config)# router ospf 1
R1(config-router)# auto-cost reference-bandwidth 10000
% OSPF: Reference bandwidth is changed.
        Please ensure reference bandwidth is consistent across all routers.
```

（`auto-cost reference-bandwidth` の単位は Mbps）

#### 代表問題の解き方⑩ ic-023（100Mbps と 1Gbps のコスト）

1. 参照帯域幅 ＝ 100 Mbps。
2. 100 Mbps: 100 ÷ 100 ＝ **1**。
3. 1 Gbps（1000 Mbps）: 100 ÷ 1000 ＝ 0.1 → 1未満は **1**。
4. → 100Mbps＝1、1Gbps＝1。
5. 誤答の正体:
   - 10 と 1 → 参照帯域幅を **1000Mbps** に変更した場合の値。
   - 19 と 4 → **STP**のデフォルトパスコスト（ショート方式: 10M＝100、100M＝19、1G＝4、10G＝2）。
   - 1 と 0.1 → OSPFのコストは**整数**で最小値1。

### 9.2 コストを変える3つの方法（ic-046）

| 方法 | コマンド（モード） | 影響範囲 | 優先度 |
|---|---|---|---|
| ① コストを直接指定 | `ip ospf cost <値>`（インターフェース） | そのインターフェースだけ | **最優先**（帯域幅からの自動計算より優先） |
| ② 帯域幅を変更 | `bandwidth <kbps>`（インターフェース） | そのインターフェースの計算結果 | |
| ③ 参照帯域幅を変更 | `auto-cost reference-bandwidth <Mbps>`（router ospf） | すべてのインターフェースの計算基準 | |

```
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip ospf cost 50

R1# show ip ospf interface brief
Interface    PID   Area            IP Address/Mask    Cost  State Nbrs F/C
Gi0/1        1     0               10.0.12.1/30       50    P2P   1/1
Gi0/0        1     0               192.168.1.1/24     1     DR    0/0
```

紛らわしいコマンド（ic-046 の誤答）:

| コマンド | 意味 |
|---|---|
| `ip ospf cost 50` | **OSPFのインターフェースコストを50に**（正解） |
| `ip ospf priority 50` | DR選出のプライオリティ。経路選択には影響しない |
| `auto-cost reference-bandwidth 50` | router ospf で全インターフェースの計算基準を変える |
| `spanning-tree cost 50` | **STP**のポートコスト。名前が似ているので混同に注意 |

`bandwidth` コマンドはコスト計算（やEIGRPのメトリック）に使われる値を変えるだけで、実際の通信速度は変わりません。

### 9.3 経路の合計コスト（ic-032）

OSPFのメトリックは、宛先までの経路上の**各ルータの出力インターフェースのコストを合計**したものです。OSPFは合計コストが最も小さい経路を選びます。**経由するルータの数（ホップ数）は関係ありません**。

#### 代表問題の解き方⑪ ic-032（R1 から R4 への経路）

```
               (10)          (10)
         ┌──────────▶ R2 ──────────┐
         │                          ▼
        R1 ──(5)──▶ R3 ──(20)───▶ R4
         │                          ▲
         └──(5)──▶ R5 ──(5)──▶ R6 ─(5)┘
  （数字は各ルータの出力インターフェースのコスト）
```

1. 各経路のコストを足し算する:

   | 経路 | 計算 | 合計 | 経由ルータ数 |
   |---|---|---|---|
   | R1 → R2 → R4 | 10 ＋ 10 | 20 | 1台 |
   | R1 → R3 → R4 | 5 ＋ 20 | 25 | 1台 |
   | R1 → R5 → R6 → R4 | 5 ＋ 5 ＋ 5 | **15** | 2台 |

2. 最小は **15** → R1 → R5 → R6 → R4 が選ばれる。
3. 経由するルータが最も多い経路が選ばれている点に注目。「経由するルータが最も少ない経路」を選ぶのは**RIP**（ホップ数）。
4. このとき R1 の `show ip route` では `O ... [110/15] via <R5のアドレス>` となる（宛先が R4 の先のネットワークなら、さらにそのリンクのコストも加わる）。

> 注意: コストは**出力方向**のインターフェースで数えます。行きと帰りで経路のコストが異なる（非対称）こともあります。

### 9.4 等コストマルチパス（ECMP）（ic-031）

同じ宛先への経路が複数あり、合計コストが**等しい**場合、OSPFは**両方の経路をルーティングテーブルに載せて負荷分散**します。これを**等コストマルチパス（ECMP）**と呼びます。

- デフォルトで最大 **4本**（`maximum-paths` で変更できる。上限はIOSやプラットフォームによる）
- `show ip route` では、1つの宛先の下に `via` が複数行表示される

```
R1# show ip route 10.4.0.0
O     10.4.0.0/16 [110/20] via 10.0.12.2, 00:02:11, GigabitEthernet0/1
                  [110/20] via 10.0.13.3, 00:02:11, GigabitEthernet0/2

R1(config)# router ospf 1
R1(config-router)# maximum-paths 8
```

| 誤答 | なぜ違うか |
|---|---|
| 先に学習した経路だけを使う | コストが等しければ両方使われる |
| ルータIDが大きいネイバー経由の経路だけを使う | ルータIDは経路の選択には使わない |
| どちらも使わず破棄する | 等コストの経路があっても破棄することはない |

### ひっかけポイント・よくある誤解

- 1Gbpsのコストは「0.1」ではなく**1**（最小値1、整数）（ic-023）。
- 「19と4」はSTPのコスト（ic-023）。「10と1」は参照帯域幅1000Mbpsのとき（ic-023）。
- `ip ospf priority` は DR 選出用、`spanning-tree cost` は STP 用。コストを直接指定するのは `ip ospf cost`（ic-046）。
- OSPFは**ホップ数ではなく合計コスト**（ic-032）。
- 等コストなら**負荷分散**。ルータIDや学習順では選ばない（ic-031）。

### 試験のポイント

- コスト ＝ 参照帯域幅（デフォルト100Mbps）÷ 帯域幅。最小1。
- 100Mbps以上は全部コスト1 → `auto-cost reference-bandwidth` を全ルータで同じ値に上げる。
- 変更方法: `ip ospf cost`（最優先）、`bandwidth`、`auto-cost reference-bandwidth`。
- 経路のメトリック ＝ 出力インターフェースのコストの合計。最小を選ぶ。
- 等コストはECMP（デフォルト最大4本、`maximum-paths`）。

### 関連問題

ic-023, ic-031, ic-032, ic-046

## 10. FHRP：HSRP / VRRP / GLBP

### 10.1 FHRPの目的（ic-025）

PCに設定できるデフォルトゲートウェイは通常**1つだけ**です。そのため、デフォルトゲートウェイのルータが故障すると、PCはサブネットの外と通信できなくなります。

**FHRP（First Hop Redundancy Protocol、ファーストホップ冗長化プロトコル）**は、**デフォルトゲートウェイを冗長化**するための仕組みです。複数のルータで**1つの仮想ルータ**を作り、**仮想IPアドレス**（と仮想MACアドレス）を共有します。担当ルータが故障すると、別のルータが自動で引き継ぎます。

```
                        インターネット / 社内WAN
                         │                 │
                    G0/0 │                 │ G0/0
                       [R1]              [R2]
                 Active │ .1           .2 │ Standby
                 Pri 110│                 │ Pri 100
                        └──────┬──────────┘
                               │  192.168.1.0/24
                  仮想IP 192.168.1.254 / 仮想MAC 0000.0c07.ac01
                               │
                 ┌─────────────┼─────────────┐
                PC1           PC2           PC3
        デフォルトゲートウェイ = 192.168.1.254（仮想IP）
```

ic-025 の誤答の整理（他の技術の目的）:

| 目的 | 技術 |
|---|---|
| **デフォルトゲートウェイの冗長化** | **FHRP**（HSRP / VRRP / GLBP） |
| L2ネットワークのループ防止 | STP |
| 端末へのIPアドレス自動割り当て | DHCP |
| 宛先までの最短経路の計算 | OSPFなどのルーティングプロトコル |

### 10.2 HSRPの動作（ic-026）

HSRP（Hot Standby Router Protocol）は**Cisco独自**のFHRPです。

- グループ内で **アクティブルータ** が仮想IPアドレスと仮想MACアドレスで応答し、**実際の転送**を行う。
- **スタンバイルータ** は普段は転送を担当しない。アクティブの故障時に引き継ぐ予備。
- アクティブルータが故障すると、スタンバイルータが**仮想IP/仮想MACを引き継ぐ**。
- PCから見ると、ゲートウェイのIPアドレスもMACアドレスも変わらないので、**設定を変えずに通信を続けられる**（ARPキャッシュの更新も不要）。

**PCのデフォルトゲートウェイには HSRP の仮想IPアドレスを設定**します（ic-026）。

| 誤答 | なぜダメか |
|---|---|
| アクティブルータの実際のIPアドレス | アクティブが故障するとそのアドレスに届かなくなり、冗長化の意味がない |
| スタンバイルータの実際のIPアドレス | スタンバイは普段は転送を担当しない |
| HSRPの仮想MACアドレス | デフォルトゲートウェイにはIPアドレスを設定する。仮想MACは、PCがARPで仮想IPを問い合わせたときに返される |

HSRPの仮想MACアドレス:

- HSRPv1: `0000.0c07.acXX`（XX はグループ番号の16進数。グループ1なら `0000.0c07.ac01`）
- HSRPv2: `0000.0c9f.fXXX`

### 10.3 アクティブルータの選出（ic-047）

| 順番 | 比較する値 | 優先 |
|---|---|---|
| ① | **HSRPプライオリティ** | **大きい方**（デフォルト **100**、範囲 0〜255） |
| ② | （同じなら）インターフェースの**IPアドレス** | **大きい方** |

HSRPは**ルータID**を使いません（ルータIDはOSPFの用語）。MACアドレスも比較しません（MACアドレスの小さい方が選ばれるのは、優先度が同じ場合のSTPのルートブリッジ選出）。

```
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# standby version 2
R1(config-if)# standby 1 ip 192.168.1.254      ← 仮想IPアドレス
R1(config-if)# standby 1 priority 110          ← プライオリティ（デフォルト100）
R1(config-if)# standby 1 preempt               ← プリエンプトを有効化

R2(config)# interface GigabitEthernet0/1
R2(config-if)# ip address 192.168.1.2 255.255.255.0
R2(config-if)# standby version 2
R2(config-if)# standby 1 ip 192.168.1.254
```

```
R1# show standby brief
                     P indicates configured to preempt.
                     |
Interface   Grp  Pri P State   Active          Standby         Virtual IP
Gi0/1       1    110 P Active  local           192.168.1.2     192.168.1.254

R2# show standby brief
Interface   Grp  Pri P State   Active          Standby         Virtual IP
Gi0/1       1    100   Standby 192.168.1.1     local           192.168.1.254
```

#### 代表問題の解き方⑫ HSRPのアクティブ選出

| ルータ | プライオリティ | IPアドレス |
|---|---|---|
| R1 | 100（デフォルト） | 192.168.1.1 |
| R2 | 100（デフォルト） | 192.168.1.2 |
| R3 | 90 | 192.168.1.3 |

1. プライオリティを比較 → R1, R2 が 100 で最大（R3 は 90 で脱落）。
2. 同じなので IPアドレスを比較 → 192.168.1.2 > 192.168.1.1 → **R2がアクティブ**、次点の R1 がスタンバイ。
3. ※ ただし、すでに動作しているグループに後から加わった場合は、プリエンプトの有無で結果が変わる（次節）。

### 10.4 プリエンプト（ic-048）

**HSRPのプリエンプトはデフォルトで無効**です。そのため、一度アクティブが入れ替わると、プライオリティの高いルータが故障から復旧して戻ってきても、**アクティブの役割は交代しません**。

意図したルータを常にアクティブにしたい場合は、**プライオリティを高くしたうえで `standby <グループ> preempt` も設定**します。

```
 時刻   R1（Pri 110, preempt なし）     R2（Pri 100）
 ──────────────────────────────────────────────────────
  t0    Active                          Standby
  t1    故障                            Active に昇格
  t2    復旧 → Standby のまま           Active のまま   ← プリエンプトがないので戻らない
 ──────────────────────────────────────────────────────
        R1 に standby 1 preempt を設定していれば、t2 で R1 が Active を取り戻す
```

| 誤答 | なぜダメか |
|---|---|
| `standby 1 priority 100` | プライオリティをデフォルト値にするだけ。プリエンプトがなければ役割は交代しない |
| `standby 1 ip 192.168.1.254` | 仮想IPアドレスを設定するコマンド |
| `spanning-tree portfast` | STPの機能で、HSRPとは関係ない |

プリエンプトのデフォルト:

| プロトコル | プリエンプトのデフォルト |
|---|---|
| HSRP | **無効** |
| VRRP | **有効** |
| GLBP（AVG） | 無効 |
| OSPFのDR | そもそもプリエンプションの仕組みがない |

### 10.5 HSRP / VRRP / GLBP の比較（ic-025, ic-049）

| 項目 | HSRP | VRRP | GLBP |
|---|---|---|---|
| 標準/独自 | **Cisco独自** | **IETF標準**（RFC 5798） | **Cisco独自** |
| 転送役 | **アクティブ**（1台） | **マスター**（1台） | **AVF**（複数台が同時に転送） |
| 予備 | スタンバイ | バックアップ | — |
| 負荷分散 | グループ内では不可（1台のみ転送） | グループ内では不可（1台のみ転送） | **可能**（グループ内の複数ルータで負荷分散） |
| デフォルトプライオリティ | 100 | 100 | 100 |
| プリエンプト | デフォルト無効 | デフォルト有効 | デフォルト無効 |
| 仮想MAC | 0000.0c07.acXX（v1） | 0000.5e00.01XX | 0007.b400.XXYY |
| マルチキャスト | 224.0.0.2（v1）/ 224.0.0.102（v2） | 224.0.0.18 | 224.0.0.102 |

**GLBP（Gateway Load Balancing Protocol）**は、1つの仮想IPアドレスに対して、**ルータごとに異なる仮想MACアドレス**をARP応答で答えて、PCごとに通信を振り分けます。

- **AVG**（Active Virtual Gateway）: ARPに応答し、どの仮想MACを返すかを割り振る役（1台）
- **AVF**（Active Virtual Forwarder）: 実際に転送する役（最大4台）

```
 PC1 ─ARP「192.168.1.254 のMACは？」→ AVG ─応答→ 「0007.b400.0101（R1の仮想MAC）」 → PC1 は R1 経由
 PC2 ─ARP「192.168.1.254 のMACは？」→ AVG ─応答→ 「0007.b400.0102（R2の仮想MAC）」 → PC2 は R2 経由
```

HSRPやVRRPでも、**VLANごとにアクティブ（マスター）のルータを分ける**ことで、ネットワーク全体として負荷を分散する設計はできます（例：VLAN10 は R1 がアクティブ、VLAN20 は R2 がアクティブ）。ただし1つのグループ内で同時に転送するのは1台だけです。

OSPFはルーティングプロトコルであり、デフォルトゲートウェイの冗長化（FHRP）ではありません（ic-049 の誤答）。

### ひっかけポイント・よくある誤解

- FHRPの目的はデフォルトゲートウェイの冗長化。STP（ループ防止）、DHCP（アドレス割当）、OSPF（経路計算）と混同しない（ic-025）。
- PCのゲートウェイは**仮想IP**。実IPでも仮想MACでもない（ic-026）。
- HSRPのアクティブは**プライオリティが大きい方**（同じならIPアドレスが大きい方）。ルータIDやMACは使わない（ic-047）。
- HSRPのプリエンプトは**デフォルト無効**。復旧後に戻すには `standby <グループ> preempt`（ic-048）。VRRPはデフォルト有効。
- グループ内で負荷分散できるのは **GLBP** だけ（ic-049）。
- HSRP＝アクティブ/スタンバイ、VRRP＝マスター/バックアップ（用語を取り違えない）。

### 試験のポイント

- FHRP＝仮想IP/仮想MACを共有してデフォルトゲートウェイを冗長化。
- HSRP: Cisco独自、アクティブ/スタンバイ、プライオリティ100、大きい方が優先、preemptはデフォルト無効。
- VRRP: 標準、マスター/バックアップ、preemptはデフォルト有効。
- GLBP: Cisco独自、ルータごとに異なる仮想MACで負荷分散。
- 設定: `standby <grp> ip <VIP>`、`standby <grp> priority <値>`、`standby <grp> preempt`。確認: `show standby brief`。

### 関連問題

ic-025, ic-026, ic-047, ic-048, ic-049

## 11. まとめ：まぎらわしい数値・大小関係の総整理

### 11.1 「大きい方が優先」か「小さい方が優先」か
