# コメントの書き方

## はじめに

コードにコメントを書くことは、コードを理解しやすくするために重要です。しかし、コメントの書き方にはコツがあります。

この章では、効果的なコメントの書き方を学びます。

## コメントの目的

コメントは以下の目的で使います：

1. **「なぜ」を説明する**：コードの意図や理由を説明
2. **複雑な処理を説明する**：理解が難しい部分を補足
3. **使い方を説明する**：関数やクラスの使い方を示す（docstring）

## 良いコメントと悪いコメント

### 悪いコメントの例

#### 1. コードの動作をそのまま書く

```python
# 悪い例
# 変数xに10を代入
x = 10

# 変数yに20を代入
y = 20

# xとyを足す
z = x + y
```

コードを見れば分かることを書いても意味がありません。

#### 2. 古いコードを残す

```python
# 悪い例
# x = 10  # 古いコード
x = 20
```

古いコードは削除しましょう。バージョン管理システム（Git）があれば、過去のコードは見られます。

#### 3. 意味のないコメント

```python
# 悪い例
# ここから処理開始
def process_data():
    pass

# 処理終了
```

意味のないコメントは書かない方がマシです。

### 良いコメントの例

#### 1. 「なぜ」を説明する

```python
# 良い例
# パフォーマンスのため、キャッシュを使う
# （データベースへのアクセスを減らすため）
cached_data = get_cached_data()

# 税込価格を計算
# 注：消費税率は2024年10月時点の10%を使用
total = price * 1.1
```

コードを見れば「何をしているか」は分かりますが、「なぜそうしているか」はコメントで説明する必要があります。

#### 2. 複雑な処理を説明する

```python
# 良い例
def calculate_fibonacci(n):
    """
    フィボナッチ数列のn番目の値を計算する
    
    再帰ではなく反復を使う理由：
    - 再帰はnが大きいとスタックオーバーフローが発生する
    - 反復の方がメモリ効率が良い
    """
    if n <= 1:
        return n
    
    a, b = 0, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b
```

複雑なアルゴリズムや、なぜその実装方法を選んだかを説明します。

#### 3. 注意事項を書く

```python
# 良い例
# 警告：この関数は副作用があります
# 元のリストを変更するため、コピーを渡すことを推奨
def process_list(items):
    items.sort()  # 元のリストを変更
    return items

# 注意：この値は外部APIから取得するため、
# ネットワークエラーが発生する可能性がある
data = fetch_from_api()
```

他の開発者への注意事項を書きます。

## Docstring（ドキュメント文字列）

Pythonでは、関数やクラスの説明を**docstring**として書きます。

### 基本的な書き方

```python
def calculate_total(price, tax_rate):
    """
    税込価格を計算する
    
    Args:
        price: 税抜き価格
        tax_rate: 消費税率（0.1 = 10%）
    
    Returns:
        税込価格
    
    Example:
        >>> calculate_total(1000, 0.1)
        1100.0
    """
    return price * (1 + tax_rate)
```

### クラスのdocstring

```python
class BankAccount:
    """
    銀行口座を表すクラス
    
    このクラスは、預金、引き出し、残高照会の機能を提供します。
    
    Attributes:
        balance: 口座残高
        account_number: 口座番号
    """
    
    def __init__(self, account_number, initial_balance=0):
        """
        口座を初期化する
        
        Args:
            account_number: 口座番号
            initial_balance: 初期残高（デフォルトは0）
        """
        self.account_number = account_number
        self.balance = initial_balance
```

## コメントの種類

### 1. インラインコメント

コードの行の後ろに書くコメントです。

```python
# 良い例
total = price + tax  # 税込価格を計算
```

```python
# 悪い例
total = price + tax  # priceとtaxを足す（自明）
```

### 2. ブロックコメント

コードのブロックの前に書くコメントです。

```python
# 良い例
# ユーザー認証を行う
# パスワードはハッシュ化して比較する
if verify_password(user_input, stored_hash):
    login_user()
```

### 3. TODOコメント

後で実装する予定のことを書きます。

```python
# TODO: エラーハンドリングを追加する
def process_data(data):
    # 現在はエラーチェックなし
    return data.upper()

# FIXME: パフォーマンスの問題がある
def slow_function():
    pass

# NOTE: この実装は一時的なもの
def temporary_solution():
    pass
```

## コメントを書くタイミング

### 書くべき時

1. **複雑なアルゴリズム**：理解が難しい処理
2. **ビジネスロジック**：なぜその計算をするのか
3. **外部依存**：外部APIやライブラリの仕様
4. **ハックや回避策**：一時的な対処法

### 書かなくても良い時

1. **自明なコード**：コードを見れば分かること
2. **良いコード**：コード自体が説明になっている

```python
# 悪い例：コメントが不要
# ユーザー名を取得
name = user.get_name()

# 良い例：コード自体が説明になっている
user_name = user.get_name()
```

## 実践例

### 例1：コメントを改善

**改善前**：
```python
# xに10を代入
x = 10
# yに20を代入
y = 20
# xとyを足す
z = x + y
```

**改善後**：
```python
# 商品価格（税抜き）
price = 10

# 消費税額
tax = 20

# 税込価格を計算
total = price + tax
```

### 例2：docstringを追加

**改善前**：
```python
def calc(x, y):
    return x + y
```

**改善後**：
```python
def calculate_sum(number1, number2):
    """
    2つの数の合計を計算する
    
    Args:
        number1: 最初の数
        number2: 2番目の数
    
    Returns:
        2つの数の合計
    
    Example:
        >>> calculate_sum(10, 20)
        30
    """
    return number1 + number2
```

## まとめ

- コメントは「なぜ」を説明する
- コードを見れば分かることは書かない
- 複雑な処理や注意事項を説明する
- docstringで関数やクラスの使い方を説明する
- 良いコードはコメントが少なくて済む

コメントは、コードを理解しやすくするための補助です。コード自体を読みやすくすることも忘れずに！
