# 変数名の略語（e, t, i など）— よくある意味と読み方

プログラミングで `e` や `t` のように **1文字（または短い略語）で変数名が書かれる**ことがあります。
これは多くの場合、言語仕様で決まっているものではなく、**「その文脈で頻出するものを短く書く」慣習**です。

このノートでは、よく見る略語の「元の英単語」と「日本語での意味」をセットでまとめます。

---

## まず大事な前提：略語は“文脈依存”

同じ `e` でも、コードの文脈によって意味が変わります。

- **イベント処理の `e`** → `event`（イベント）
- **例外処理の `e`** → `error / exception`（エラー / 例外）

迷ったら、**短くしすぎずに `event`, `error`, `time` のように書く**のが安全です（読みやすさ優先）。

---

## `e` は何の略？

### `e = event`

- **英単語**: event
- **日本語の意味**: イベント（クリック・入力・送信など、ユーザー操作やブラウザ内の出来事）
- **よくある場面**: React/DOM のイベントハンドラ

例（雰囲気）：
- `onClick={(e) => ...}`
- `onChange={(e) => ...}`

### `e = error / exception`

- **英単語**: error / exception
- **日本語の意味**: エラー / 例外（処理に失敗した情報、投げられた例外オブジェクト）
- **よくある場面**: `try/catch` の `catch (e)`、Promise の `catch(e => ...)`

※最近は `e` よりも `err`（errorの略）や `error` と書くプロジェクトも多いです。

### `e = element`（たまに）

- **英単語**: element
- **日本語の意味**: 要素（DOM要素など）
- **よくある場面**: DOM操作・UI部品参照

※ただし `el` のほうが「elementっぽさ」が出て誤読が減ります。

---

## `t` は何の略？

### `t = time`

- **英単語**: time
- **日本語の意味**: 時間・時刻
- **よくある場面**: タイムスタンプ、経過時間、計測

関連する略：
- `ts` = timestamp（タイムスタンプ：時刻を表す数値/文字列）

### `t = text`

- **英単語**: text
- **日本語の意味**: 文章・文字列（人が読むテキスト）
- **よくある場面**: 入力値、表示文言

### `t = translation`（超定番）

- **英単語**: translation
- **日本語の意味**: 翻訳（多言語化で文言を別言語に変換すること）
- **よくある場面**: i18n（国際化）ライブラリの翻訳関数

例（雰囲気）：
- `t("common.save")` のように「キー」を渡して翻訳文を取る

---

## ほかによく出る短い名前（英語の意味つき）

### ループ・配列でよく見る

- `i` = index（**添字**：配列の何番目かを表す番号）
- `j`, `k` = index（入れ子のループなどで2つ目・3つ目の添字）
- `n` = number / count（**個数**・件数・要素数）

### データの前後関係

- `prev` = previous（**前の**）
- `next` = next（**次の**）

### コールバック・関数

- `cb` = callback（**呼び戻し関数**：後で呼ばれる関数）
- `fn` = function（**関数**）

### 設定・文脈

- `cfg` / `conf` = configuration / config（**設定**）
- `ctx` = context（**文脈**：この処理が置かれている状況・周辺情報）

### Web/サーバで定番

- `req` = request（**リクエスト**：クライアント→サーバへの要求）
- `res` = response（**レスポンス**：サーバ→クライアントへの返答）

### UI/DOM で定番

- `el` = element（**要素**）
- `btn` = button（**ボタン**）

### メッセージ/一時変数

- `msg` = message（**メッセージ**）
- `tmp` = temporary（**一時的な**：仮の値）

### 識別子

- `id` = identifier（**識別子**：一意に区別するためのID）

---

## 使い分けのガイド（実務で困りにくい）

- **狭いスコープなら短くてもOK**: 1〜3行で完結する処理なら `i` や `e` でも読みやすいことが多い
- **スコープが広いなら具体名にする**: 画面全体・長い関数・共有ロジックでは `event`, `error`, `timestamp` などにする
- **曖昧な1文字は避ける**: `t` が time なのか translation なのか、`e` が event なのか error なのかが迷う場合は具体名へ

---

## ちょいメモ：チームの規約が最優先

略語の好みはチーム・リポジトリで違います。
既存コードが `err` 派なら `err`、`event` 派なら `event` に合わせると、読みやすさが揃います。
