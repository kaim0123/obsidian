# 命名規則とコーディング規約

## はじめに

コードを書く時、変数名や関数名の付け方には一定のルールがあります。これを**命名規則**といいます。また、コードの書き方のルールを**コーディング規約**といいます。

このドキュメントでは、命名規則・よく使われる変数名・関数名の動詞パターン・コーディング規約を体系的にまとめています。

**重要：** 専門用語が含まれるセクションには用語解説を追加しています。分からない言葉があれば確認してください。

# Part 1：命名規則

## 1. 命名ケースの種類と使い分け

### 用語解説

- **キャメルケース（camelCase）**：単語の最初の文字を小文字にし、2つ目以降の単語の最初の文字を大文字にする書き方。例：`userName`、`isActive`
- **パスカルケース（PascalCase）**：すべての単語の最初の文字を大文字にする書き方。例：`UserName`、`UserProfile`
- **スネークケース（snake_case）**：単語をアンダースコア（`_`）でつなぐ書き方。例：`user_name`、`is_active`
- **ケバブケース（kebab-case）**：単語をハイフン（`-`）でつなぐ書き方。例：`user-name`、`main-content`

### ケース一覧

| ケース名 | 書き方 | 使用例 | 主な用途 |
|----------|--------|--------|----------|
| camelCase（キャメルケース） | `userName` | JS/TSの変数・関数 | JavaScript, TypeScript, Java |
| PascalCase（パスカルケース） | `UserName` | クラス名、Reactコンポーネント | 全言語共通でクラス名 |
| snake_case（スネークケース） | `user_name` | Pythonの変数・関数 | Python, Ruby, Rust |
| SCREAMING_SNAKE_CASE | `MAX_RETRY` | 定数 | 全言語共通 |
| kebab-case（ケバブケース） | `user-name` | CSSクラス名、URLパス、ファイル名 | HTML/CSS, URL |
| dot.case（ドットケース） | `user.name` | 設定ファイルのキー | YAML, TOML, プロパティファイル |

### 言語別の使い分け早見表

| 対象 | JavaScript/TS | Python | Go | Java | CSS |
|------|--------------|--------|-----|------|-----|
| 変数 | camelCase | snake_case | camelCase | camelCase | -- |
| 関数 | camelCase | snake_case | PascalCase(公開) / camelCase(非公開) | camelCase | -- |
| クラス | PascalCase | PascalCase | PascalCase | PascalCase | -- |
| 定数 | SCREAMING_SNAKE | SCREAMING_SNAKE | PascalCase | SCREAMING_SNAKE | -- |
| ファイル名 | camelCase or kebab-case | snake_case | snake_case | PascalCase | kebab-case |
| CSSクラス | -- | -- | -- | -- | kebab-case or BEM |

### JavaScript/TypeScript

- 変数・関数：キャメルケース（`camelCase`）
- クラス：パスカルケース（`PascalCase`）
- 定数：大文字とアンダースコア（`CONSTANT_NAME`）

### Python（PEP 8）

Pythonでは、**PEP 8**という公式のコーディング規約があります。

- 変数・関数：スネークケース（`snake_case`）
- クラス：パスカルケース（`PascalCase`）
- 定数：大文字とアンダースコア（`CONSTANT_NAME`）

### React

- コンポーネント：パスカルケース（`UserProfile`）
- props：キャメルケース（`onClick`, `isActive`）
- フック：`use`で始める（`useState`, `useEffect`）

## 2. 名前の付け方の基本ルール

### 変数名と関数名（Pythonの場合）

- **スネークケース（snake_case）**を使う
- 小文字とアンダースコア（`_`）で構成

```python
# 良い例
user_name = "太郎"
total_price = 1000
calculate_total = lambda x: x * 1.1

# 悪い例
userName = "太郎"  # キャメルケース（Pythonでは非推奨）
TotalPrice = 1000  # 大文字で始まっている（定数と混同）
```

### クラス名

- **パスカルケース（PascalCase）**を使う
- 各単語の最初の文字を大文字にする

```python
# 良い例
class UserAccount:
    pass

class ShoppingCart:
    pass

# 悪い例
class user_account:  # スネークケース（クラス名には不適切）
    pass
```

### 定数

- **大文字とアンダースコア**を使う
- 変更されない値に使う

```python
# 良い例
MAX_RETRY_COUNT = 3
DEFAULT_TIMEOUT = 30
PI = 3.14159

# 悪い例
maxRetryCount = 3  # キャメルケース
default_timeout = 30  # 小文字（定数と分からない）
```

### プライベート変数・メソッド

- 先頭にアンダースコア1つ（`_`）を付ける
- クラス内部でのみ使うことを示す

```python
class BankAccount:
    def __init__(self, balance):
        self.balance = balance
        self._transaction_history = []  # プライベート変数

    def deposit(self, amount):
        self.balance += amount
        self._record_transaction("deposit", amount)  # プライベートメソッド

    def _record_transaction(self, type, amount):
        """内部で使うメソッド"""
        self._transaction_history.append((type, amount))
```

### 意味のある名前を使う

```python
# 悪い例
x = 10
y = 20
z = x + y

# 良い例
price = 10
tax = 20
total = price + tax
```

```javascript
// 悪い例
const d = new Date();
const x = 10;
const temp = data;

// 良い例
const currentDate = new Date();
const maxRetries = 10;
const userData = data;
```

### 略語を避ける（一般的でない場合）

```python
# 悪い例
usr_nm = "太郎"
calc_tot = lambda x: x * 1.1

# 良い例
user_name = "太郎"
calculate_total = lambda x: x * 1.1

# 一般的な略語はOK
id = 123
url = "https://example.com"
msg = "Hello"
```

### ブール値には`is`、`has`、`can`、`should`を使う

```python
# 良い例
is_active = True
has_permission = False
can_edit = True

# 悪い例
active = True  # ブール値かどうか分からない
permission = False
```

```javascript
// 良い例
const isActive = true;
const hasPermission = false;
const canEdit = true;

// 悪い例
const active = true;  // ブール値かどうか分からない
const permission = false;
```

### 関数名は動詞から始める

```python
# 良い例
def get_user_name():
    pass

def calculate_total():
    pass

def validate_input():
    pass

# 悪い例
def user_name():  # 名詞（何を返すか分からない）
    pass
```

```javascript
// 良い例
const getUser = () => {};
const calculateTotal = () => {};
const validateInput = () => {};

// 悪い例
const user = () => {};  // 何をする関数か分からない
const total = () => {};
```

### 配列は複数形にする

```javascript
// 良い例
const users = [user1, user2];
const items = [item1, item2];

// 悪い例
const user = [user1, user2];  // 配列かどうか分からない
```

## 3. 接頭辞の使い分けとニュアンス

変数名や関数名には、特定の意味を示す接頭辞（最初に付ける単語）がよく使われます。これらの接頭辞を知ることで、コードの意図を理解しやすくなります。

### `on` - イベントが発生した時に実行される関数

**ニュアンス**：「〜の時に」「〜が起きた時に」という意味。イベントが発生した時に自動的に呼び出される関数に使う。

**使用例**：
```javascript
// Reactのpropsやイベント属性
<button onClick={handleClick}>クリック</button>
<input onChange={handleChange} />
<form onSubmit={handleSubmit} />

// イベントリスナー
element.onclick = handleClick;
element.onchange = handleChange;
```

**使い分け**：
- `on`は**イベント属性やprops**に使う（`onClick`、`onChange`など）
- 実際の処理関数には`handle`を使う（`handleClick`、`handleChange`など）

---

### `handle` - イベントを処理する関数

**ニュアンス**：「処理する」「扱う」という意味。イベントが発生した時に実行する処理を書いた関数に使う。

**使用例**：
```javascript
// クリックイベントを処理する関数
const handleClick = (event) => {
  console.log('クリックされました');
};

// フォーム送信を処理する関数
const handleSubmit = (event) => {
  event.preventDefault();
  // 送信処理
};

// 値の変更を処理する関数
const handleChange = (event) => {
  setValue(event.target.value);
};
```

**使い分け**：
- `handle`は**実際の処理を書く関数**に使う
- `on`はイベント属性に使うが、`handle`は関数名に使う
- 例：`onClick={handleClick}` → `onClick`は属性、`handleClick`は関数

---

### `is` - 「〜であるかどうか」を表すブール値

**ニュアンス**：「〜です」「〜である」という状態を表す。`true`か`false`のどちらかの値を持つ。

**使用例**：
```javascript
// 状態を表す
const isActive = true;        // アクティブである
const isLoading = false;      // 読み込み中である
const isVisible = true;       // 表示されている
const isOpen = false;         // 開いている
const isSelected = true;      // 選択されている
const isDisabled = false;     // 無効化されている
const isError = false;        // エラーである
```

**使い分け**：
- **状態や属性**を表す時に使う
- 「〜である」という**現在の状態**を表す
- 例：`isActive` = 「アクティブであるかどうか」

---

### `has` - 「〜を持っているかどうか」を表すブール値

**ニュアンス**：「〜を持っている」「〜がある」という意味。何かが存在するかどうかを表す。

**使用例**：
```javascript
// 何かを持っているかどうか
const hasError = true;           // エラーを持っている（エラーがある）
const hasPermission = false;      // 権限を持っている
const hasChildren = true;         // 子要素を持っている
const hasData = false;            // データを持っている
const hasAccess = true;           // アクセス権を持っている
```

**使い分け**：
- **所有や存在**を表す時に使う
- 「〜を持っている」という**所有関係**を表す
- `is`との違い：
  - `isError` = 「エラーである」（エラーそのものかどうか）
  - `hasError` = 「エラーを持っている」（エラーがあるかどうか）

---

### `can` - 「〜できるかどうか」を表すブール値

**ニュアンス**：「〜できる」「〜可能である」という意味。能力や権限を表す。

**使用例**：
```javascript
// 能力や権限を表す
const canEdit = true;         // 編集できる
const canDelete = false;      // 削除できる
const canAccess = true;       // アクセスできる
const canSubmit = false;      // 送信できる
const canView = true;         // 閲覧できる
```

**使い分け**：
- **能力や権限**を表す時に使う
- 「〜できる」という**可能性や許可**を表す
- 例：`canEdit` = 「編集する能力があるか、編集する権限があるか」

---

### `should` - 「〜すべきかどうか」を表すブール値

**ニュアンス**：「〜すべきである」「〜する必要がある」という意味。推奨や必要性を表す。

**使用例**：
```javascript
// 推奨や必要性を表す
const shouldUpdate = true;        // 更新すべき
const shouldRefresh = false;     // リフレッシュすべき
const shouldValidate = true;     // 検証すべき
const shouldSave = false;         // 保存すべき
```

**使い分け**：
- **推奨や必要性**を表す時に使う
- 「〜すべき」という**判断や推奨**を表す
- 例：`shouldUpdate` = 「更新する必要があるかどうか」

---

### `get` - 値を取得する関数

**ニュアンス**：「取得する」「取り出す」という意味。データを取得する関数に使う。

**使用例**：
```javascript
// 値を取得する関数
const getUser = (id) => { ... };           // ユーザーを取得
const getData = () => { ... };             // データを取得
const getName = () => { ... };             // 名前を取得
const getValue = () => { ... };            // 値を取得
```

**使い分け**：
- **値を返す関数**に使う
- 副作用（データの変更など）がない、純粋に値を取得する関数

---

### `set` - 値を設定する関数

**ニュアンス**：「設定する」「変更する」という意味。値を設定・変更する関数に使う。

**使用例**：
```javascript
// 値を設定する関数
const setUser = (user) => { ... };         // ユーザーを設定
const setValue = (value) => { ... };       // 値を設定
const setName = (name) => { ... };         // 名前を設定

// ReactのuseState
const [value, setValue] = useState(0);     // setValueは値を設定する関数
```

**使い分け**：
- **値を変更する関数**に使う
- 状態を更新する関数によく使われる

---

### `is` vs `has` vs `can` vs `should` の使い分けまとめ

| 接頭辞 | 意味 | 使用例 | ニュアンス |
|--------|------|--------|-----------|
| `is` | 〜である | `isActive` | 現在の状態を表す |
| `has` | 〜を持っている | `hasError` | 所有や存在を表す |
| `can` | 〜できる | `canEdit` | 能力や権限を表す |
| `should` | 〜すべき | `shouldUpdate` | 推奨や必要性を表す |

**具体例で比較**：
```javascript
// 状態を表す
const isActive = true;        // アクティブな状態である

// 所有を表す
const hasPermission = true;   // 権限を持っている

// 能力を表す
const canEdit = true;         // 編集する能力がある

// 推奨を表す
const shouldUpdate = true;   // 更新すべきである
```

## 4. よく使われる変数名一覧

### データ関連

#### 用語解説

- **パラメータ（params）**：関数やAPIに渡す値のこと。例：`fetchUser({ id: 1 })` の `{ id: 1 }` がパラメータ
- **引数（arguments）**：関数を呼び出す時に渡す値のこと。パラメータと同じ意味で使われることが多い
- **ペイロード（payload）**：送信するデータ本体のこと。APIでデータを送る時に使う
- **リクエストボディ（body）**：HTTPリクエストで送るデータ本体のこと。ペイロードと同じ意味
- **設定（config）**：プログラムの動作を決める情報のこと。例：APIキー、タイムアウト時間など
- **オプション（options）**：選択できる設定項目のこと。例：リクエストの設定、関数の動作を変える設定など

#### 基本的なデータ変数

| 変数名 | 意味 | 使用例 |
|--------|------|--------|
| `data` | 一般的なデータ | `const data = await fetchData();` |
| `item` | リストや配列の1つの要素 | `items.map(item => ...)` |
| `items` | 複数の要素のリスト | `const items = [1, 2, 3];` |
| `result` | 処理結果 | `const result = calculate();` |
| `value` | 値 | `const value = input.value;` |
| `values` | 複数の値 | `const values = [1, 2, 3];` |
| `content` | コンテンツ内容 | `const content = article.content;` |
| `payload` | APIリクエスト/レスポンスのデータ本体 | `const payload = { name: "John" };` |
| `body` | リクエストボディ | `request.body` |
| `params` | パラメータ | `function fetchUser(params) { ... }` |
| `args` | 引数（arguments） | `function sum(...args) { ... }` |
| `config` | 設定情報 | `const config = { apiKey: "xxx" };` |
| `options` | オプション設定 | `fetch(url, options)` |

### API・通信関連

#### 用語解説

- **API（Application Programming Interface）**：他のプログラムとやり取りするための仕組み。Webアプリでは、サーバーからデータを取得したり送信したりする時に使う
- **リクエスト（request）**：サーバーに「データをください」とお願いすること
- **レスポンス（response）**：サーバーからの返事やデータのこと
- **URL（Uniform Resource Locator）**：WebページやAPIの場所を示すアドレス。例：`https://example.com`
- **エンドポイント（endpoint）**：APIの特定の機能にアクセスするためのURL。例：`/api/users` はユーザー情報を取得するエンドポイント
- **HTTPヘッダー（headers）**：リクエストやレスポンスに付ける追加情報。例：データの形式（JSONなど）、認証情報など
- **クエリパラメータ（query）**：URLの後ろに付ける追加情報。例：`?page=1&limit=10` の `page=1&limit=10` の部分

| 変数名 | 意味 | 使用例 |
|--------|------|--------|
| `request` | リクエスト | `const request = new Request(url);` |
| `response` | レスポンス | `const response = await fetch(url);` |
| `req` | リクエスト（短縮形） | `app.get('/api', (req, res) => ...)` |
| `res` | レスポンス（短縮形） | `app.get('/api', (req, res) => ...)` |
| `url` | URL文字列 | `const url = "https://example.com";` |
| `endpoint` | APIエンドポイント | `const endpoint = "/api/users";` |
| `headers` | HTTPヘッダー | `const headers = { "Content-Type": "application/json" };` |
| `query` | クエリパラメータ | `const query = "?page=1&limit=10";` |
| `body` | リクエストボディ | `fetch(url, { body: JSON.stringify(data) })` |

---

### イベントハンドラー関連

#### 用語解説

- **イベント（event）**：ユーザーの操作やシステムの動作のこと。例：クリック、キー入力、マウス移動など
- **イベントハンドラー（event handler）**：イベントが起きた時に実行する関数のこと。例：ボタンをクリックした時に実行する関数
- **フォーカス（focus）**：入力欄などにカーソルが当たっている状態のこと。例：テキストボックスをクリックするとフォーカスが当たる
- **フォーカス外れ（blur）**：フォーカスが外れること。例：テキストボックスからカーソルが離れること
- **イベントオブジェクト（event/e）**：イベントに関する情報が入ったオブジェクト。例：どの要素がクリックされたか、キーコードなど

#### React・フロントエンド

| 変数名 | 意味 | 使用例 |
|--------|------|--------|
| `onClick` | クリックイベントハンドラー | `<button onClick={handleClick}>` |
| `onSubmit` | フォーム送信ハンドラー | `<form onSubmit={handleSubmit}>` |
| `onChange` | 値変更ハンドラー | `<input onChange={handleChange}>` |
| `onInput` | 入力イベントハンドラー | `<input onInput={handleInput}>` |
| `onFocus` | フォーカスイベントハンドラー | `<input onFocus={handleFocus}>` |
| `onBlur` | フォーカス外れハンドラー | `<input onBlur={handleBlur}>` |
| `onKeyDown` | キー押下ハンドラー | `<input onKeyDown={handleKeyDown}>` |
| `onKeyUp` | キー離しハンドラー | `<input onKeyUp={handleKeyUp}>` |
| `onMouseEnter` | マウス進入ハンドラー | `<div onMouseEnter={handleEnter}>` |
| `onMouseLeave` | マウス退出ハンドラー | `<div onMouseLeave={handleLeave}>` |
| `handleClick` | クリック処理関数 | `const handleClick = () => { ... };` |
| `handleSubmit` | 送信処理関数 | `const handleSubmit = (e) => { ... };` |
| `handleChange` | 変更処理関数 | `const handleChange = (e) => { ... };` |
| `event` | イベントオブジェクト | `const handleClick = (event) => { ... };` |
| `e` | イベントオブジェクト（短縮形） | `const handleClick = (e) => { ... };` |

### DOM・要素関連

#### 用語解説

- **DOM（Document Object Model）**：HTMLの要素をプログラムで操作するための仕組み
- **DOM要素（element）**：HTMLのタグ（`<div>`、`<button>`など）をプログラムで扱う時の呼び方
- **DOMノード（node）**：DOM要素と同じ意味。HTMLの構造を表す単位
- **コンテナ要素（container）**：他の要素を入れるための箱のような要素
- **ラッパー要素（wrapper）**：他の要素を包む要素。スタイルを適用したり、グループ化するために使う
- **親要素（parent）**：他の要素を包んでいる要素。例：`<div><p>テキスト</p></div>` では、`<div>`が親要素
- **子要素（child）**：親要素の中に入っている要素。例：上記では`<p>`が子要素
- **参照（ref）**：DOM要素や値を直接参照するための仕組み。Reactなどで使う

| 変数名 | 意味 | 使用例 |
|--------|------|--------|
| `element` | DOM要素 | `const element = document.getElementById('id');` |
| `el` | DOM要素（短縮形） | `const el = document.querySelector('.class');` |
| `node` | DOMノード | `const node = document.createElement('div');` |
| `container` | コンテナ要素 | `const container = document.querySelector('.container');` |
| `wrapper` | ラッパー要素 | `const wrapper = document.createElement('div');` |
| `parent` | 親要素 | `const parent = element.parentElement;` |
| `child` | 子要素 | `const child = element.firstElementChild;` |
| `children` | 子要素のリスト | `const children = element.children;` |
| `target` | ターゲット要素 | `event.target` |

### ループ・反復処理関連

#### 用語解説

# Part 2：コーディング規約

## 1. インデント

- **スペース4つ**を使う（タブは使わない）
- 多くのエディタは自動で変換してくれます

```python
# 良い例
if x > 0:
    print("正の数です")
    if x > 10:
        print("10より大きいです")

# 悪い例（タブとスペースが混在）
if x > 0:
	print("正の数です")  # タブ
    print("エラー")  # スペース
```

## 2. 行の長さ

- 1行は**79文字以内**を推奨（厳密でなくても80文字程度）
- 長い場合は改行する

```python
# 長い行の例
result = calculate_total_price(item_price, tax_rate, discount_rate, shipping_cost)

# 改行する
result = calculate_total_price(
    item_price,
    tax_rate,
    discount_rate,
    shipping_cost
)
```

## 3. 空行

- 関数やクラスの定義の前後には2行の空行
- クラス内のメソッドの間には1行の空行

```python
# 良い例
def function_a():
    pass


def function_b():
    pass


class MyClass:
    def method_a(self):
        pass

    def method_b(self):
        pass
```

## 4. インポート

- 標準ライブラリ → サードパーティ → ローカルモジュールの順
- 各グループの間には空行を入れる

```python
# 標準ライブラリ
import os
import sys

# サードパーティ
import requests
import numpy as np

# ローカルモジュール
from mymodule import my_function
```

## 5. 演算子の周りのスペース

- 演算子の前後にはスペースを入れる
- ただし、優先順位を示す場合は省略可

```python
# 良い例
x = 1 + 2
y = 3 * 4
z = (a + b) * (c + d)

# 悪い例
x=1+2
y=3*4
```

## 6. カンマの後にはスペース

```python
# 良い例
items = [1, 2, 3]
person = {"name": "太郎", "age": 25}

# 悪い例
items = [1,2,3]
person = {"name":"太郎","age":25}
```

## 7. コメント

- コメントは英語でも日本語でもOK（プロジェクトで統一）
- コメントの前にはスペースを2つ

```python
# 良い例
def calculate_total(price, tax):
    # 税込価格を計算
    return price * (1 + tax)

# 悪い例
def calculate_total(price, tax):
#コメント（スペースがない）
    return price * (1 + tax)
```

## 実践例

### 例1：命名規則を改善

**改善前**：
```python
def calc(x, y):
    z = x + y
```

**改善後**：
```python
def calculate_sum(number1, number2):
```

### 例2：コーディング規約に従う

```python
class user:
    def __init__(self,n):
```

**改善後**：

```python
class User:

        return self.name
```

## 命名で迷った時のチェックリスト

1. **何をする関数か？** → 適切な動詞を選ぶ（この文書の動詞一覧を参照）
2. **何に対する操作か？** → 対象の名詞を付ける（`User`, `Item`, `Config`等）
3. **戻り値はブール値か？** → `is`, `has`, `can`, `should` で始める
4. **配列か単数か？** → 複数形にする（`users` vs `user`）
5. **対になる操作があるか？** → 対義語ペアを使う（`open`/`close`等）
6. **言語の規約に合っているか？** → ケースの使い分け表を確認
7. **略語は一般的か？** → `id`, `url`, `msg` はOK。`usr`, `nm` は避ける
8. **名前だけで意味が伝わるか？** → コメント不要なほど明確か確認

## まとめ

### 命名規則

- 変数・関数：言語に合わせたケースを使う（JS → camelCase、Python → snake_case）
- クラス：パスカルケース（`PascalCase`）
- 定数：大文字とアンダースコア（`CONSTANT_NAME`）
- プライベート：先頭にアンダースコア（`_private`）
- ブール値：`is`, `has`, `can`, `should` で始める
- 関数名：動詞から始める
- 配列：複数形にする
- 意味のある名前を使い、不必要な略語を避ける

### コーディング規約

- インデント：スペース4つ
- 行の長さ：80文字程度
- 演算子・カンマの周りにスペース
- インポートは標準→サードパーティ→ローカルの順

コーディング規約に従うことで、コードが読みやすくなり、チーム開発でも協力しやすくなります。習慣づけましょう！
