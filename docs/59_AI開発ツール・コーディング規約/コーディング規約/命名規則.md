# 命名規則 — 識別子・ファイル名・公開API

## はじめに

**「良いコードは、半分は命名で決まる」** と言われます。変数・関数・ファイルの名前が分かりやすければ、コードはコメントがなくても読めるようになります。

命名規則は **言語・プロジェクトごとに慣習** がありますが、**考え方そのものはどの言語でも共通** です。この章ではその基本を学びます。

---

## 命名の基本原則

### 1. 何をするものかが名前で分かる

```javascript
// ❌ 悪い
function fn(a, b) { return a + b; }

// ✅ 良い
function calculateTotal(price, tax) { return price + tax; }
```

### 2. 略さない

```javascript
// ❌ 悪い（意味不明）
const usr = getUsr();
const btn = document.getElementById('btn');

// ✅ 良い
const user = getUser();
const submitButton = document.getElementById('submit-button');
```

### 3. 長さより意味を優先

**短すぎる** のも **長すぎる** のも問題。**意味が伝わる最短の長さ** を選びます。

```javascript
// 短すぎ
const d = new Date();

// 長すぎ
const currentLocalDateAndTimeObject = new Date();

// ちょうどいい
const now = new Date();
```

### 4. 同じものは同じ名前

プロジェクト内で **同じ概念に複数の名前** を使わない。

```javascript
// ❌ 悪い
class UserManager { ... }
class UserService { ... }
class UserController { ... } // 責務が分からない
```

## ケース（記法）の種類

| 名前 | 例 | 主な用途 |
|------|-----|---------|
| camelCase | `userName` | 変数・関数（JS, Java, Kotlin） |
| PascalCase | `UserProfile` | クラス・型・コンポーネント |
| snake_case | `user_name` | 変数・関数（Python, Ruby, SQL） |
| SCREAMING_SNAKE_CASE | `MAX_RETRY_COUNT` | 定数 |
| kebab-case | `user-profile` | CSSクラス・URL・ファイル名 |

### 言語ごとの慣習

| 言語 | 変数・関数 | クラス | 定数 | ファイル |
|------|-----------|-------|------|---------|
| JavaScript/TS | camelCase | PascalCase | SCREAMING_SNAKE | camelCase or kebab |
| Python | snake_case | PascalCase | SCREAMING_SNAKE | snake_case |
| Java | camelCase | PascalCase | SCREAMING_SNAKE | PascalCase.java |
| Go | camelCase | PascalCase | camelCase | snake_case.go |
| Rust | snake_case | PascalCase | SCREAMING_SNAKE | snake_case.rs |

**その言語・プロジェクトの慣習に従う** のが一番。

## 変数の命名

### 名詞を使う

変数は「物」なので、**名詞** で名付けます。

```javascript
const userName = 'Alice';     // 名詞
const orderCount = 5;         // 名詞
const isActive = true;        // 真偽値は is/has/can で始める
```

### bool（真偽値）は質問形

- `is` / `has` / `can` / `should` で始める

```javascript
const isLoggedIn = true;
const hasPermission = false;
const canEdit = user.role === 'admin';
```

### 配列・複数

**複数形** を使う。

```javascript
const users = [...];   // 配列
const userIds = [...]; // 配列
```

### 単位を含める

数値は **単位** を名前に入れると誤用を防げる。

```javascript
const timeoutMs = 5000;        // ミリ秒
const fileSizeBytes = 1024;    // バイト
const delaySeconds = 10;       // 秒
```

## 関数の命名

### 動詞で始める

関数は「処理」なので、**動詞** で名付けます。

```javascript
getUser()       // 取得
createOrder()   // 作成
updateUser()    // 更新
deleteUser()    // 削除
calculateTotal() // 計算
validateEmail() // 検証
```

### 対になる動詞

よく使われる対：

- `get` / `set`
- `start` / `stop`
- `open` / `close`
- `enable` / `disable`
- `add` / `remove`
- `push` / `pop`

統一して使いましょう。

### 副作用があるかで分ける

```javascript
// 返す（副作用なし）
function getUserName(user) { return user.name; }

// 変更する（副作用あり）
function setUserName(user, name) { user.name = name; }
```

**見ただけで副作用の有無が分かる** 命名を心がけます。

## クラスの命名

- **PascalCase**
- **名詞**
- **単数形**

```javascript
class User { }
class Order { }
class EmailSender { }
class PaymentProcessor { }
```

### 責務別の接尾辞

| 接尾辞 | 意味 |
|-------|------|
| -Service | アプリケーション層のサービス |
| -Repository | データアクセス |
| -Controller | HTTPエンドポイント |
| -UseCase | ユースケース |
| -Factory | 生成 |
| -Manager | 管理系（濫用注意） |

`UserManager` のような **汎用的な名前は濫用注意**。責務が曖昧になる。

---

## 定数の命名

- **SCREAMING_SNAKE_CASE**
- **何を表す値か** を明示

```javascript
const MAX_RETRY_COUNT = 3;
const DEFAULT_TIMEOUT_MS = 5000;
const API_BASE_URL = 'https://api.example.com';
```

### Magic Number を定数化

```javascript
// ❌ 悪い
if (user.age >= 20) { ... }

// ✅ 良い
const ADULT_AGE = 20;
if (user.age >= ADULT_AGE) { ... }
```

## ファイル名

### プロジェクトで統一する

- JavaScript/TypeScript: `userProfile.ts` or `user-profile.ts` or `UserProfile.ts`
- Python: `user_profile.py`
- Go: `user_profile.go`
- React: `UserProfile.tsx`

**バラバラにしない**。ESLintなどで強制可能。

### 名前 = そこに何があるか

- `UserService.ts` の中身は `UserService` クラス
- `useAuth.ts` の中身は `useAuth` フック
- `calculateTotal.ts` の中身は `calculateTotal` 関数

## 公開API（Public API）の命名

ライブラリやモジュールの **外に出す名前** は特に慎重に。

### 1. 変更しにくいので慎重に

一度公開すると **簡単には変えられない**。時間をかけて選ぶ。

### 2. 名前空間を意識する

```typescript
// export される名前
export function parse() {} // 何の parse?

// 呼ぶ側で
import { parse } from 'csv-lib'; // csvLib.parse() と書きたい

// → 呼び出し側で意味が通るようにする
export function parseCSV() {}
```

### 3. 動詞 + 名詞のペアを意識

```typescript
// 関数名
readFile(), writeFile(), deleteFile()
parseJSON(), stringifyJSON()
createUser(), updateUser(), deleteUser()
```

## 避けるべき命名

### 1. 意味のない名前

`data`, `info`, `tmp`, `foo`, `bar`

### 2. 型情報を繰り返す（ハンガリアン記法）

```javascript
// ❌ 型が分かっている（TSなど）なら不要
const strName = 'Alice';
const intAge = 20;
```

現代の型付き言語では不要。型システムに任せる。

### 3. 否定形

```javascript
// ❌ 否定の否定が混乱する
if (!isNotReady) { ... }

// ✅ 肯定形で
if (isReady) { ... }
```

### 4. 紛らわしい似た名前

```javascript
const ordersById;
const orderById; // 1つ？

// → 明確に
const ordersByIdMap; // Map<string, Order[]>
const orderById;     // Map<string, Order>
```

---

## まとめ

1. **何をするものか名前で分かる**
2. **略さず、長すぎず、意味を優先**
3. **言語・プロジェクトの慣習に従う**
4. **変数=名詞、関数=動詞、bool=質問形**
5. **クラスは単数・PascalCase**
6. **定数は SCREAMING_SNAKE**
7. **意味のない名前・否定形は避ける**

「**書く時間より読む時間が長い**」ことを忘れずに。
