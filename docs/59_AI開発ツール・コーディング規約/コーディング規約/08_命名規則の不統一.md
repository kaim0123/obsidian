# 命名規則の不統一

AIが生成するコードには、命名規則が統一されていない場合があります。この章では、適切な命名規則とその重要性について解説します。

## 📖 命名規則の重要性

統一された命名規則は、コードの可読性と保守性を向上させます。命名規則が不統一だと、以下のような問題が発生します：

**よくある問題**:

- キャメルケースとスネークケースが混在
- 関数名と変数名が不適切
- 略語の使用が一貫していない
- 意味が分かりにくい名前
- コードの理解が困難になる

## 1. ケーススタイルの混在

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 命名規則が不統一
const user_name = 'John';  // スネークケース
const userEmail = 'john@example.com';  // キャメルケース
const UserID = 123;  // パスカルケース

function get_user_data() {  // スネークケース
  // ...
}

function getUserData() {  // キャメルケース
  // ...
}

class User_Profile {  // スネークケース（クラス名）
  // ...
}
```

**問題点**:
- コードの一貫性が失われる
- どの命名規則を使うべきか判断に迷う
- コードレビューが困難になる

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 命名規則を統一（JavaScriptの場合はキャメルケース）
const userName = 'John';
const userEmail = 'john@example.com';
const userId = 123;

function getUserData() {
  // ...
}

function createUser() {
  // ...
}

class UserProfile {  // クラス名はパスカルケース
  // ...
}
```

**言語別の命名規則**:

- **JavaScript/TypeScript**: 変数・関数はキャメルケース、クラスはパスカルケース
- **Python**: 変数・関数はスネークケース、クラスはパスカルケース
- **Java**: 変数・関数はキャメルケース、クラスはパスカルケース
- **C#**: 変数・関数はキャメルケース、クラスはパスカルケース

## 2. 意味が分かりにくい名前

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 意味が分かりにくい名前
const d = new Date();
const u = getUser();
const x = calculateTotal();
const temp = processData();

function fn() {
  // ...
}

function doSomething() {
  // ...
}
```

**問題点**:
- 変数の目的が分からない
- コードの理解が困難
- デバッグが困難

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 意味が明確な名前
const currentDate = new Date();
const currentUser = getUser();
const orderTotal = calculateTotal();
const processedData = processData();

function calculateOrderTotal() {
  // ...
}

function validateUserInput() {
  // ...
}
```

## 3. 略語の不統一

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 略語の使用が不統一
const usr = getUser();
const usrId = getUserId();
const user = getCurrentUser();
const userId = getCurrentUserId();

function getUsrInfo() {
  // ...
}

function getUserInformation() {
  // ...
}
```

**問題点**:
- 同じ概念に対して異なる略語が使われる
- コードの一貫性が失われる

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 略語を統一（または略語を使わない）
const user = getUser();
const userId = getUserId();
const userInfo = getUserInfo();  // または getUserInformation()

function getUserInfo() {
  // ...
}

function getUserProfile() {
  // ...
}
```

**略語の使用方針**:
- 一般的に使われる略語はOK（例: `id`, `url`, `api`）
- プロジェクト内で統一する
- 分かりにくい略語は避ける

## 4. ブール値の命名

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: ブール値の命名が不適切
const flag = checkUser();
const status = isActive();
const result = validate();

if (flag) {
  // ...
}

if (status) {
  // ...
}
```

**問題点**:
- ブール値かどうかが分からない
- 意味が不明確

### ✅ 正しい実装例

```javascript
// ✅ 良い例: ブール値は is/has/can/should で始める
const isUser = checkUser();
const isActive = checkActive();
const isValid = validate();

if (isUser) {
  // ...
}

if (isActive) {
  // ...
}

// その他のブール値の命名パターン
const hasPermission = checkPermission();
const canEdit = checkEditPermission();
const shouldUpdate = checkUpdateCondition();
```

## 5. 関数名の命名

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 関数名が不適切
function process() {
  // 何を処理するのか分からない
}

function handle() {
  // 何を処理するのか分からない
}

function doSomething() {
  // 何をするのか分からない
}
```

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 関数名は動詞で始める
function processUserData() {
  // ...
}

function handleUserRequest() {
  // ...
}

function validateUserInput() {
  // ...
}

function calculateOrderTotal() {
  // ...
}

function sendEmail() {
  // ...
}
```

**関数名の命名パターン**:
- `get...`: データを取得する
- `set...`: データを設定する
- `create...`: 新規作成する
- `update...`: 更新する
- `delete...`: 削除する
- `validate...`: 検証する
- `calculate...`: 計算する
- `send...`: 送信する

## 6. クラス名の命名

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: クラス名が不適切
class user {
  // ...
}

class userData {
  // ...
}

class process {
  // ...
}
```

### ✅ 正しい実装例

```javascript
// ✅ 良い例: クラス名は名詞で、パスカルケース
class User {
  // ...
}

class UserData {
  // ...
}

class OrderProcessor {
  // ...
}

class EmailService {
  // ...
}
```

## 7. 定数の命名

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 定数の命名が不統一
const maxRetry = 3;
const TIMEOUT = 5000;
const pageSize = 20;
```

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 定数は大文字のスネークケース
const MAX_RETRY = 3;
const TIMEOUT = 5000;
const PAGE_SIZE = 20;
const API_BASE_URL = 'https://api.example.com';
```

## 8. ファイル名の命名

### ❌ 問題のあるコード例

```
❌ 悪い例: ファイル名が不統一
user_controller.js
UserController.js
userController.js
user-controller.js
```

### ✅ 正しい実装例

```
✅ 良い例: ファイル名を統一（プロジェクトの規約に従う）
user_controller.js  (スネークケース)
または
UserController.js   (パスカルケース)
または
user-controller.js  (ケバブケース)
```

**言語・フレームワーク別のファイル名規則**:
- **Node.js/Express**: スネークケースまたはケバブケース
- **React**: パスカルケース（コンポーネント）
- **Python**: スネークケース
- **Java**: パスカルケース

## ✅ 命名規則チェックリスト

コードを書く際に、以下の点を確認しましょう：

- [ ] 変数名はキャメルケース（またはスネークケース）で統一されているか
- [ ] 関数名は動詞で始まり、意味が明確か
- [ ] クラス名は名詞で、パスカルケースか
- [ ] 定数は大文字のスネークケースか
- [ ] ブール値は is/has/can/should で始まっているか
- [ ] 略語の使用が統一されているか
- [ ] 意味が分かりやすい名前になっているか
- [ ] ファイル名が統一されているか

## 🎯 まとめ

統一された命名規則は、コードの可読性と保守性を向上させます。以下の点に注意することが重要です：

1. **一貫性**: プロジェクト全体で同じ命名規則を使用
2. **明確性**: 意味が分かりやすい名前を使用
3. **適切性**: 言語やフレームワークの慣習に従う
4. **統一性**: 略語やケーススタイルを統一

AIが生成するコードには、命名規則が不統一な場合があるため、必ず確認し、必要に応じて修正することが大切です。
