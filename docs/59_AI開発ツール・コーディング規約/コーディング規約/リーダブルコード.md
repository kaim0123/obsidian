
## 選び方のチェックリスト

1. **戻り値は boolean か？** → `is` / `has` / `can` / `should` のどれが一番の「問い」に近いか
2. **イベントか？** → 外部の口は `on` 、中の処理は `handle`
3. **読むだけか、書くか？** → 取得系か変更系かで動詞を分ける
4. **`get` / `set` で十分か？** → 非同期・ネットワーク・ファイル・永続化なら `fetch` / `download` / `save` など具体語へ
5. **副作用はあるか？** → 真偽値関数に副作用を入れない

---

## よくある改善例

| 改善前 | 改善後 | 理由 |
| --- | --- | --- |
| `getDataFromApi()` | `fetchData()` | 非同期 API であることが伝わる |
| `getFile()` | `downloadReport()` | ファイルのダウンロード意図が明確 |
| `setDataToDb()` | `saveContract()` | 永続化の意図が明確 |
| `checkPermission()` | `hasPermission()` / `canEdit()` | 戻り値が boolean と分かる |
| `clickHandler()` | `handleClick()` | イベント処理の慣習に沿う |
| `onClickHandler()` | `onClick` （props）+ `handleClick` （実装） | 入口と実装を分離 |

## 変数

**camelCase** を使う。再代入しない値は `const` 、再代入する値は `let` を使う（ `var` は使わない）。

```
const userName = 'KeiyakuONE';
let count = 0;
const isValid = formValidate.email(email);
```

## 命名のコツ

| 種類 | 付け方 | 例 |
| --- | --- | --- |
| 通常の値 | 名詞または名詞句 | `email`, `postalCode`, `raw` |
| 真偽値 | `is` / `has` / `can` + 形容詞・名詞 | `isValid`, `hasError`, `canSubmit` |
| 配列 | 複数形 | `announcements`, `items` |
| React の state | `[値, 更新関数]` のペア | `error`, `setError` |
| イベントハンドラ | `on` または `handle` + イベント名 | `onChange`, `handleSubmit` |

## 真偽値の接頭辞（is / has / can）

真偽値（ `boolean` ）には **意味が伝わる接頭辞** を付ける。どれも「はい / いいえ」を表すが、 **何についてのはい / いいえか** が接頭辞で区別できる。

| 接頭辞 | 意味 | よく使う場面 |
| --- | --- | --- |
| **`is`** | **状態・性質** であるかどうか | 形容詞・過去分詞が続く。「今そうなのか」を表す |
| **`has`** | **所有・含有** があるかどうか | 名詞が続く。「〜を持っているか」を表す |
| **`can`** | **能力・許可** があるかどうか | 動詞が続く。「〜できるか」を表す |

### is — 状態・性質

「〜 **である** 」「〜 **になっている** 」という **現在の状態** を表す。

```
const isValid = formValidate.email(email);       // 入力が有効か
const isSubmitting = true;                        // 送信中か
const isOpen = false;                             // メニューが開いているか
const isDisabled = count === 0;                   // 無効状態か
const isLoading = response.status === 'pending';  // 読み込み中か
const isEmpty = items.length === 0;               // 空か
const isRequired = field.required;                // 必須項目か
```

### has — 所有・含有

「〜 **を持っている** 」「〜 **が含まれる** 」という **存在・付随** を表す。

```
const hasError = error !== null;           // エラーがあるか
const hasValue = raw.trim().length > 0;    // 値が入っているか
const hasPermission = user.role === 'admin'; // 権限を持っているか
const hasChildren = node.children.length > 0;  // 子要素があるか
const hasChanges = dirtyFields.length > 0;   // 未保存の変更があるか
```

### can — 能力・許可

「〜 **できる** 」「〜 **してよい** 」という **可能性・条件** を表す。

```
const canSubmit = isValid && agreed && !isSubmitting; // 送信してよいか
const canEdit = user.role === 'editor';               // 編集できるか
const canDelete = isOwner || isAdmin;                 // 削除できるか
const canRetry = retryCount < MAX_RETRY;              // 再試行できるか
```

### 使い分けの例（同じフォームでも意味が違う）

```
const isValid = validateEmail(email);   // 入力内容自体が正しいか（is = 状態）
const hasError = error !== null;        // エラーメッセージが表示されているか（has = 含有）
const canSubmit = isValid && agreed;    // ボタンを押してよいか（can = 許可）
```

状態が単純で接頭辞が不要な場合もある（例: `agreed` = 同意済み）。 **読み手が迷うとき** は `is` / `has` / `can` を付ける。

## イベントハンドラ（on と handle の使い分け）

イベントを受け取る関数は **`on` + イベント名** または **`handle` + イベント名** を使う。どちらも camelCase。

### 基本の違い

| 接頭辞 | 意味・役割 | 向いている場面 |
| --- | --- | --- |
| **`on`** | React / DOM の **イベント prop 名** （ `onClick`, `onChange` ）と **同じ語彙** | JSX にそのまま渡す関数、フックから返すコールバック、コンポーネントの props |
| **`handle`** | コンポーネント **内部の処理** であることを示す | 複数処理をまとめる、内部実装と prop 名を区別したいとき |

### on を使う場合

- **DOM / React のイベント prop と 1 対 1** で対応するとき
- **カスタムフックが `{ onChange, onBlur }` を返す** とき（本プロジェクトの hooks がこのパターン）
- **子コンポーネントに渡すコールバック prop** を定義するとき（例: `onValueChange` ）

```
// フック内 — JSX の onChange / onBlur にそのまま渡す
const onChange = (event: ChangeEvent<HTMLTextAreaElement>) => {
  const raw = event.currentTarget.value;
  // ...
};

return { error, onChange, onBlur, validate };

// コンポーネント — フックの戻り値を JSX に接続
const { onChange: onEmailChange, onBlur: onEmailBlur } = useEmailField();

<Input onChange={onEmailChange} onBlur={onEmailBlur} />;

// フォーム送信 — onSubmit として form に直接渡す
const onSubmit = async (event: SubmitEvent<HTMLFormElement>) => {
  event.preventDefault();
  // ...
};

<form onSubmit={onSubmit}>...</form>
```

### handle を使う場合

- コンポーネント内で **ビジネスロジックを組み立てる本体** として定義し、JSX 側は prop 名 `onXxx` のままにしたいとき
- **1 つの操作が複数イベントや state 更新をまたぐ** とき（検証 → API 呼び出し → リダイレクトなど）
- **`on` という prop 名と関数本体を名前で区別** したいとき

```
// 内部は handle、JSX の prop 名は onSubmit のまま
const handleSubmit = async (event: FormEvent<HTMLFormElement>) => {
  event.preventDefault();
  if (!canSubmit) return;
  await sendForm(formData);
};

<form onSubmit={handleSubmit}>...</form>

// クリックで複数処理をまとめる
const handleMenuToggle = () => {
  setIsOpen((prev) => !prev);
  trackEvent('menu_toggle');
};

<button onClick={handleMenuToggle}>メニュー</button>
```

| パターン | 例 | 読み方 |
| --- | --- | --- |
| 動詞 + 名詞 | `getUserName`, `sendForm`, `validateEmail` | 「ユーザ名を取得する」「フォームを送る」 |
| 動詞 + 形容詞 + 名詞 | `getDisplayName`, `formatJapaneseDate` | 修飾語で対象を具体化 |

## よく使う動詞一覧

操作の **意図** に合った動詞を選ぶ。似た動詞（類語）や **反対の操作** （対義語）も意識すると、名前のブレが減る。

### データの取得・設定

| 動詞 | 意味 | 例 | 類語 | 対義語 | 使い分け |
| --- | --- | --- | --- | --- | --- |
| **`get`** | 既にある値を **読み取る** | `getDisplayName`, `getUserById` | `find`, `read`, `extract` | `set`, `write` | 副作用なし・計算や参照が主目的のとき |
| **`fetch`** | **外部** （API 等）から取得する | `fetchAnnouncements`, `fetchUserProfile` | `load`, `request` | — | ネットワーク越しの取得。ローカルなら `get` |
| **`set`** | 値を **代入・更新** する | `setError`, `setIsOpen` | `assign`, `write` | `get`, `read` | React の `setState` やプロパティ設定 |
| **`update`** | 既存のものを **一部変更** する | `updateProfile`, `updateField` | `patch`, `modify`, `edit` | `create`, `delete` | 新規作成でも削除でもない「変更」 |
| **`create`** | 新しいものを **作る** | `createUser`, `createSession` | `build`, `make`, `generate`, `init` | `delete`, `remove` | 以前存在しなかったものができるとき |
| **`delete`** | データを **削除** する | `deleteUser`, `deleteRecord` | `remove`, `destroy`, `clear` | `create`, `add` | 永続的な削除。UI から外すだけなら `remove` も可 |

```
// get — 読み取り専用
function getDisplayName(user: User): string {
  return user.nickname ?? user.email;
}

// fetch — 外部 API
async function fetchAnnouncements(): Promise<Announcement[]> {
  const response = await fetch('/api/announcements');
  return response.json();
}

// set — 状態を書き換える（React）
setError(null);
setIsSubmitting(true);

// update — 既存レコードの部分更新
function updateProfile(id: string, patch: Partial<Profile>): Profile { /* ... */ }

// create / delete — ライフサイクルの両端
function createContact(data: ContactInput): Contact { /* ... */ }
function deleteContact(id: string): void { /* ... */ }
```

### 表示・開閉（UI）

| 動詞 | 意味 | 例 | 類語 | 対義語 | 使い分け |
| --- | --- | --- | --- | --- | --- |
| **`open`** | 閉じていたものを **開く** | `openModal`, `openMenu` | `show`, `expand`, `reveal` | `close`, `hide` | モーダル・メニュー・ドロワーなど |
| **`close`** | 開いているものを **閉じる** | `closeModal`, `closeDialog` | `hide`, `dismiss`, `collapse` | `open`, `show` | ユーザー操作や処理完了後の後始末 |
| **`toggle`** | 開閉を **反転** する | `toggleMenu`, `toggleAccordion` | `switch` | — | `open` / `close` のどちらか不明なとき |

```
function openPrivacyPolicy(): void {
  window.open('/privacy', '_blank');
}

function closeSubmitError(): void {
  setSubmitError(null);
}

function toggleMobileMenu(): void {
  setIsOpen((prev) => !prev);
}
```

### 処理の開始・終了

| 動詞 | 意味 | 例 | 類語 | 対義語 | 使い分け |
| --- | --- | --- | --- | --- | --- |
| **`start`** | 継続的な処理を **始める** | `startPolling`, `startTimer` | `begin`, `launch`, `run`, `enable` | `stop`, `end` | 一定時間または繰り返しが続く操作 |
| **`stop`** | 処理を **止める** | `stopPolling`, `stopTimer` | `end`, `abort`, `cancel` | `start`, `resume` | 完全停止。一時停止なら `pause` |
| **`finish`** / **`complete`** | 正常に **完了** する | `finishUpload`, `completeCheckout` | `done` （非推奨） | `cancel`, `abort` | 成功して終わったとき |

```
function startSubmitting(): void {
  setIsSubmitting(true);
}

function stopSubmitting(): void {
  setIsSubmitting(false);
}

// cancel — ユーザー都合やエラーで中断
function cancelRequest(controller: AbortController): void {
  controller.abort();
}
```

### 送信・通信

| 動詞 | 意味 | 例 | 類語 | 対義語 | 使い分け |
| --- | --- | --- | --- | --- | --- |
| **`send`** | データを **送る** | `sendForm`, `sendEmail` | `post`, `dispatch`, `push` | `receive`, `fetch` | サーバー・外部サービスへ送出 |
| **`submit`** | フォーム等を **提出** する | `submitContactForm` | `send` | — | HTML フォームの文脈では `submit` が自然 |
| **`receive`** | データを **受け取る** | `receiveMessage` | `onMessage` （イベント） | `send` | 受信側の処理。React では `onXxx` も多い |

```
// 本プロジェクト — フォーム送信（fetch で API に POST）
async function onSubmit(event: SubmitEvent<HTMLFormElement>) {
  event.preventDefault();
```

### 検証・計算・整形

| 動詞 | 意味 | 例 | 類語 | 対義語 | 使い分け |
| --- | --- | --- | --- | --- | --- |
| **`validate`** | ルールに **合っているか確認** | `validateEmail`, `validatePhone` | `verify`, `check`, `assert` | `normalize`, `sanitize` | 合否判定。修正はしない |
| **`verify`** | 正しさ・本人性を **確認** | `verifyToken`, `verifySignature` | `validate`, `check` | — | セキュリティ・署名など「本物か」の確認 |
| **`normalize`** | 入力を **統一形式に直す** | `normalizePhone`, `normalizeEmail` | `sanitize`, `clean`, `trim` | `validate` | 検証ではなく変換（全角→半角など） |
| **`calculate`** | 値を **計算して求める** | `calculateTotal`, `calculateTax` | `compute`, `count`, `sum` | `format` | 数値・論理の導出 |
| **`format`** | 人が読む形に **整形** | `formatJapaneseDate`, `formatCurrency` | `stringify`, `display`, `render` | `parse` | 表示・ログ出力向け |
| **`parse`** | 文字列等を **構造に分解** | `parseJson`, `parseDate` | `decode` | `format`, `stringify` | 文字列 → オブジェクト／日付 |

```
// validate — 真偽値を返す（本プロジェクトの formValidate）
export const formValidate = {
  email: (value: string) => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value),
  message: (value: string) => value.trim().length > 0,
};

// normalize — 入力を直してから validate
export const formNormalize = {
  phone: {
    fullWidth: (value: string) => value.replace(/[０-９]/g, /* ... */),
    digits: (value: string) => value.replace(/\D/g, ''),
  },
};

// format — 表示用
function formatJapaneseDate(isoDate: string): string {
  return \`${year}年${month}月${day}日\`;
}

// calculate — 導出
function calculateTotal(items: Item[]): number {
  return items.reduce((sum, item) => sum + item.price, 0);
}
```

| 動詞 | 意味 | 例 | 類語 | 対義語 | 使い分け |

| **`merge`** | 複数を **1 つにまとめる** | `mergeConfig`, `mergeClasses` | `combine`, `join`, `concat`, `union` | `split`, `separate` | 設定・クラス名・配列の統合 |

| やりたいこと | 第一候補 | 類語 | 避けたい混同 |

## クラス

**PascalCase** を使う。クラス名は **名詞** または **名詞 + 役割を示す接尾辞** で、 **何のクラスか** が名前から分かるようにする。

本プロジェクト（KOne-LP）では **関数とオブジェクトを優先** し、クラスは必要なときだけ使う。ただしライブラリや大規模アプリでは、下記の接尾辞がよく使われる。

```
class ContactFormValidator {
  validateEmail(value: string): boolean { /* ... */ }
}
```

- メソッド名は **関数と同じ camelCase** （
- 継承用の抽象クラス・基底クラスも PascalCase（例: `BaseFieldValidator` ）
- ファイル名はクラス名と揃える（例: `ContactFormValidator.ts` ）

## 各接尾辞の意味と使い方

### Service — ビジネスロジック

**アプリケーション固有のルールや手順** を実行する層。データの取得方法（DB / API）や HTTP の詳細は **直接扱わず** 、必要なら Repository や Client に委譲する。

| 項目 | 内容 |
| --- | --- |
| **意味** | 「〜を **行うサービス** 」— ユースケース単位の処理 |
| **向いている処理** | 複数ステップの組み合わせ、ドメインルール、トランザクション的な流れ |
| **メソッド例** | `submitContact`, `publishAnnouncement`, `registerUser` |

```
class ContactSubmissionService {
  constructor(
    private readonly web3FormsClient: Web3FormsClient,
    private readonly validator: ContactFormValidator,
  ) {}

  async submit(formData: ContactFormData): Promise<SubmitResult> {
    if (!this.validator.validate(formData)) {
      return { success: false, message: '入力内容をご確認ください。' };
    }
    return this.web3FormsClient.send(formData);
  }
}
```

**類似:** `UseCase` （クリーンアーキテクチャ）  
**区別:** `Repository` はデータ、 `Client` は外部通信、 `Service` はその上の **業務手順**

---

### Repository — データの永続化

**データの読み書き** を抽象化する層。DB・ファイル・ローカルストレージなど **保存先の詳細を隠す** 。

| 項目 | 内容 |
| --- | --- |
| **意味** | 「〜の **保管場所** 」— CRUD（作成・読取・更新・削除） |
| **向いている処理** | `findById`, `save`, `delete`, `listAll` |
| **メソッド例** | `findById`, `save`, `delete`, `findByCategory` |

```
class AnnouncementRepository {
  async findAll(): Promise<Announcement[]> {
    // DB や CMS API から取得（呼び出し側は保存先を知らない）
    return [];
  }

  async findById(id: string): Promise<Announcement | null> {
    return null;
  }

  async save(announcement: Announcement): Promise<void> {
    // 永続化
  }
}
```

**類似:** `Store`, `Dao` （Data Access Object）  
**区別:** `Client` は **外部 HTTP API** 、 `Repository` は **自アプリのデータ** 向けが多い

---

### Controller — リクエストの入口

**HTTP リクエストやルーティング** を受け取り、適切な Service に渡す **薄い層** 。主にバックエンド（Express, NestJS 等）で使う。

| 項目 | 内容 |
| --- | --- |
| **意味** | 「〜を **制御する** 」— 入り口で振り分ける |
| **向いている処理** | パス・メソッドに応じた処理の開始、ステータスコードの返却 |
| **メソッド例** | `index`, `show`, `create`, `handleRequest` |

```
class ContactController {
  constructor(private readonly contactService: ContactSubmissionService) {}

  async postContact(request: Request): Promise<Response> {
    const body = await request.json();
    const result = await this.contactService.submit(body);
    return Response.json(result, { status: result.success ? 200 : 400 });
  }
}
```

**類似:** `Router`, `Resource`  
**区別:** `Handler` は **1 種類のイベント** 、 `Controller` は **リソース単位の入口** （複数メソッドを持つ）

---

### Manager — 状態・リソースの管理

**ライフサイクルが長いもの** （セッション、キャッシュ、モーダル、接続）を **作成・維持・破棄** する。

| 項目 | 内容 |
| --- | --- |
| **意味** | 「〜を **管理する** 」— 状態を持ち続ける |
| **向いている処理** | 開閉、キャッシュの有効期限、接続プール、シングルトン的な協調 |
| **メソッド例** | `open`, `close`, `get`, `clear`, `register`, `unregister` |

```
class ModalManager {
  private activeModalId: string | null = null;

  open(modalId: string): void {
    this.activeModalId = modalId;
  }

  close(): void {
    this.activeModalId = null;
  }

  isOpen(modalId: string): boolean {
    return this.activeModalId === modalId;
  }
}
```

**類似:** `Registry`, `Pool`  
**区別:** `Service` は **処理の流れ** 、 `Manager` は **状態やリソースの保持**

---

### Handler — 特定イベントへの応答

**1 種類のイベント・例外・メッセージ** にだけ反応する。Controller より **粒度が細かい** 。

| 項目 | 内容 |
| --- | --- |
| **意味** | 「〜を **処理する** 」— イベント 1 件に 1 対 1 |
| **向いている処理** | エラー捕捉、Webhook 受信、フォーム送信、クリック |
| **メソッド例** | `handle`, `handleError`, `handleSubmit`, `onMessage` |

```
class SubmitErrorHandler {
  handle(status: number): string {
    switch (status) {
      case 429:
        return '送信回数の上限に達しました。';
      case 500:
        return 'サーバーで問題が発生しました。';
      default:
        return '送信に失敗しました。';
    }
  }
}

// React では関数 + on/handle 命名の方が多い（→ 01変数.md — イベントハンドラ）
class UnhandledRejectionHandler {
  handle(event: PromiseRejectionEvent): void {
    console.error(event.reason);
  }
}
```

**類似:** `Listener`, `Callback` （関数として実装することも多い）  
**区別:** フロントエンドのクリック処理は **関数** `handleClick` / `onClick` が主流。クラスの `Handler` は **サーバー・ミドルウェア** でより多い

---

### Factory — オブジェクトの生成

**生成ロジックを 1 か所に集約** する。呼び出し側は **具体クラスや設定の詳細を知らなくてよい** 。

| 項目 | 内容 |
| --- | --- |
| **意味** | 「〜を **作る工場** 」— 生成条件の分岐を隠す |
| **向いている処理** | 種類に応じたインスタンス生成、デフォルト値の適用 |
| **メソッド例** | `create`, `build`, `from`, `make` |

```
type FieldType = 'email' | 'phone' | 'message';

class FormFieldFactory {
  create(type: FieldType): FormFieldValidator {
    switch (type) {
      case 'email':
        return new EmailFieldValidator();
      case 'phone':
        return new PhoneFieldValidator();
      case 'message':
        return new MessageFieldValidator();
    }
  }
}

// 設定に応じて Client を作る例
class HttpClientFactory {
  create(baseUrl: string): ApiClient {
    return new ApiClient({ baseUrl, timeout: 10_000 });
  }
}
```

**類似:** `Builder` （段階的に組み立て）、 `Provider` （DI コンテナから供給）  
**区別:** `Factory` は **1 回の生成** 、 `Builder` は **複数プロパティを順に設定**

---

### Validator — 入力・データの検証

**ルールに合っているか** を判定する。通常 **値を変更しない** （変更するなら `Normalizer` / `Sanitizer` ）。

| 項目 | 内容 |
| --- | --- |
| **意味** | 「〜を **検証する** 」— 真偽値やエラー一覧を返す |
| **向いている処理** | フォーム、API リクエスト body、設定ファイル |
| **メソッド例** | `validate`, `validateEmail`, `isValid`, `getErrors` |

```
class ContactFormValidator {
  validateEmail(value: string): boolean {
    return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value);
  }

  validatePhone(digits: string): boolean {
    return digits.length >= 10 && digits.length <= 11;
  }

  validate(data: ContactFormData): boolean {
    return (
      this.validateEmail(data.email) &&
      this.validatePhone(data.phone) &&
      data.message.trim().length > 0
    );
  }
}
```

**類似:** 本プロジェクトの `formValidate` オブジェクト（関数型で同じ役割）  
**区別:** `Validator` は **チェックのみ** 、 `Normalizer` は **直してから** 使う

---

### Client — 外部サービスとの通信

**外部 API やサードパーティ** へのリクエストを担当する。HTTP、gRPC、SDK ラッパーなど。

| 項目 | 内容 |
| --- | --- |
| **意味** | 「〜の **クライアント** 」— 向こう側サービスへの窓口 |
| **向いている処理** | REST 呼び出し、認証ヘッダ付与、リトライ、レスポンスの型付け |
| **メソッド例** | `send`, `fetch`, `get`, `post`, `submit` |

```
class Web3FormsClient {
  private readonly endpoint = 'https://api.web3forms.com/submit';

  async send(formData: FormData): Promise<Web3FormsResponse> {
    const response = await fetch(this.endpoint, {
      method: 'POST',
      body: formData,
    });
    return response.json();
  }
}

class GitHubApiClient {
  constructor(private readonly token: string) {}

  async getIssue(number: number): Promise<Issue> {
    const response = await fetch(\`https://api.github.com/repos/org/repo/issues/${number}\`, {
      headers: { Authorization: \`Bearer ${this.token}\` },
    });
    return response.json();
  }
}
```

**類似:** `Adapter` （インターフェース変換）、 `Gateway` （外部システムへの境界）  
**区別:** `Repository` は **自前データ** 、 `Client` は **外部サービス**

## 接尾辞の関係（レイヤーイメージ）

バックエンドやフルスタックでクラスを分けるときの **よくある配置** です。フロントエンド LP ではすべてをクラスにする必要はありません。

```
HTTP リクエスト
    ↓
Controller   … 入口・ルーティング
    ↓
Service      … ビジネスロジック
    ↓
Repository   … 自前 DB / ストレージ
Client       … 外部 API（Web3Forms 等）

横断:
  Validator  … 入力チェック（Service の手前でも可）
  Factory    … 上記クラスの生成
  Manager    … キャッシュ・セッション等の状態管理
  Handler    … エラー・Webhook 等の単発イベント
```

| やりたいこと | 第一候補 |
| --- | --- |
| お問い合わせ送信の一連の流れ | `ContactSubmissionService` |
| お知らせを DB から取得 | `AnnouncementRepository` |
| POST /contact を受け付ける | `ContactController` |
| モーダルの開閉状態を保持 | `ModalManager` |
| 429 エラーをユーザー向け文言に変換 | `SubmitErrorHandler` |
| フィールド種別ごとに Validator を生成 | `FormFieldFactory` |
| メール形式を検証 | `EmailValidator` / `ContactFormValidator` |
| Web3Forms API を呼ぶ | `Web3FormsClient` |

## 本プロジェクトでの位置づけ

KOne-LP では `formValidate` や `useEmailField` など **関数・フック** で同じ役割を担っていることが多い。クラス名の接尾辞は **大規模化・バックエンド追加・テストのモック分離** するときの参照として使う。

| 接尾辞 | 本プロジェクトでの対応例 |
| --- | --- |
| `Validator` | `formValidate` （ `src/lib/utils.ts` ） |
| `Handler` | `toUserFacingError`, `onSubmit` （関数） |
| `Client` | `fetch('https://api.web3forms.com/submit', …)` （直接呼び出し） |
| `Service` | フック + コンポーネント内の `onSubmit` に相当 |

## ファイル名

拡張子は用途に応じて `.ts` / `.tsx` / `.js` を使う。本プロジェクトでは主に TypeScript（`.ts`, `.tsx` ）です。

## 種類別の規則

| 種類 | ファイル名 | 例 |
| --- | --- | --- |
| React コンポーネント（自前） | **PascalCase**.tsx | `ContactForm.tsx`, `PricingTabs.tsx`, `FAQAccordion.tsx` |
| UI 部品（shadcn/ui 等） | **kebab-case**.tsx | `button.tsx`, `textarea.tsx`, `accordion.tsx` |
| カスタムフック | **camelCase** （ `use` 始まり）.ts | `useMessageField.ts`, `useEmailField.ts` |
| 定数・設定 | **camelCase**.ts | `company.ts`, `announcements.ts` |
| ユーティリティ | **camelCase**.ts | `utils.ts` |
| アイコンコンポーネント | **PascalCase**.tsx | `IconChevronRight.tsx` |
| 型定義のみ | **camelCase**.d.ts など | `global.d.ts` |
| 単体テスト | `<対象>.test.ts(x)` | `utils.test.ts`, `ContactForm.test.tsx` |
| E2E テスト | `<ドメイン>.spec.ts` | `contact-form.spec.ts` |

## ディレクトリ名

**camelCase** または **kebab-case** で、プロジェクト内で揃える。

```
src/
  components/          ← コンポーネント
  hooks/contactForm/     ← ドメインごとのフック
  lib/                   ← 共通ユーティリティ
  constants/             ← 定数
```

## ファイル名と export の対応

- `ContactForm.tsx` → `export function ContactForm` または `export const ContactForm`
- `useMessageField.ts` → `export const useMessageField`
- `company.ts` → `export const COMPANY_INFO` など

**1 ファイルに 1 つの主要 export** を基本とし、ファイル名から中身が推測できるようにする。
