# テストの不足

AIが生成するコードには、テストコードが含まれていない場合があります。この章では、テストの重要性と適切なテストの書き方について解説します。

## 📖 テストの重要性

テストは、コードの品質を保証し、バグを早期に発見するために不可欠です。テストが不足していると、以下のような問題が発生します：

**よくある問題**:

- 単体テストがない
- 統合テストがない
- エッジケースのテストがない
- テストのカバレッジが低い
- リファクタリングが困難

## 1. 単体テストの不足

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: テストコードがない
// models/User.js
class User {
  constructor(id, name, email) {
    this.id = id;
    this.name = name;
    this.email = email;
  }

  validate() {
    if (!this.name) {
      throw new Error('名前が必要です');
    }
    if (!this.email.includes('@')) {
      throw new Error('有効なメールアドレスが必要です');
    }
  }
}
```

**問題点**:
- バリデーションロジックが正しく動作するか確認できない
- リファクタリング時に既存の機能が壊れていないか確認できない
- エッジケースがテストされていない

### ✅ 正しい実装例

```javascript
// ✅ 良い例: テストコードを含める
// models/User.js
class User {
  constructor(id, name, email) {
    this.id = id;
    this.name = name;
    this.email = email;
  }

  validate() {
    if (!this.name || this.name.trim() === '') {
      throw new Error('名前が必要です');
    }
    if (!this.email || !this.email.includes('@')) {
      throw new Error('有効なメールアドレスが必要です');
    }
  }
}

module.exports = User;
```

```javascript
// ✅ 良い例: 単体テスト
// tests/models/User.test.js
const User = require('../../models/User');

describe('User', () => {
  describe('validate', () => {
    it('should throw error if name is empty', () => {
      const user = new User(1, '', 'test@example.com');
      expect(() => user.validate()).toThrow('名前が必要です');
    });

    it('should throw error if name is only whitespace', () => {
      const user = new User(1, '   ', 'test@example.com');
      expect(() => user.validate()).toThrow('名前が必要です');
    });

    it('should throw error if email is invalid', () => {
      const user = new User(1, 'Test User', 'invalid-email');
      expect(() => user.validate()).toThrow('有効なメールアドレスが必要です');
    });

    it('should throw error if email is empty', () => {
      const user = new User(1, 'Test User', '');
      expect(() => user.validate()).toThrow('有効なメールアドレスが必要です');
    });

    it('should not throw error if data is valid', () => {
      const user = new User(1, 'Test User', 'test@example.com');
      expect(() => user.validate()).not.toThrow();
    });
  });
});
```

## 2. 統合テストの不足

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 統合テストがない
// controllers/user_controller.js
const User = require('../models/User');

async function createUser(req, res) {
  const { name, email } = req.body;
  
  const user = new User(null, name, email);
  user.validate();
  
  const result = await db.query(
    'INSERT INTO users (name, email) VALUES (?, ?)',
    [name, email]
  );
  
  res.status(201).json({ userId: result.insertId });
}
```

**問題点**:
- コントローラーとモデルの連携が正しく動作するか確認できない
- データベース操作が正しく実行されるか確認できない
- APIエンドポイント全体の動作が確認できない

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 統合テスト
// tests/integration/user_controller.test.js
const request = require('supertest');
const app = require('../../app');
const db = require('../../config/database');

describe('User Controller Integration Tests', () => {
  beforeEach(async () => {
    // テスト前にデータベースをクリーンアップ
    await db.query('DELETE FROM users');
  });

  afterAll(async () => {
    // テスト後にデータベース接続を閉じる
    await db.end();
  });

  describe('POST /api/users', () => {
    it('should create a new user', async () => {
      const userData = {
        name: 'Test User',
        email: 'test@example.com'
      };

      const response = await request(app)
        .post('/api/users')
        .send(userData)
        .expect(201);

      expect(response.body).toHaveProperty('userId');
      
      // データベースに正しく保存されているか確認
      const [users] = await db.query('SELECT * FROM users WHERE id = ?', [response.body.userId]);
      expect(users).toHaveLength(1);
      expect(users[0].name).toBe(userData.name);
      expect(users[0].email).toBe(userData.email);
    });

    it('should return 400 if name is missing', async () => {
      const userData = {
        email: 'test@example.com'
      };

      const response = await request(app)
        .post('/api/users')
        .send(userData)
        .expect(400);

      expect(response.body).toHaveProperty('error');
    });

    it('should return 400 if email is invalid', async () => {
      const userData = {
        name: 'Test User',
        email: 'invalid-email'
      };

      const response = await request(app)
        .post('/api/users')
        .send(userData)
        .expect(400);

      expect(response.body).toHaveProperty('error');
    });
  });
});
```

## 3. エッジケースのテスト不足

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: エッジケースがテストされていない
// utils/calculator.js
function calculateDiscount(price, discountPercent) {
  return price * (discountPercent / 100);
}

// テスト（正常系のみ）
describe('calculateDiscount', () => {
  it('should calculate discount correctly', () => {
    expect(calculateDiscount(1000, 10)).toBe(100);
  });
});
```

**問題点**:
- 負の値や0の値が渡された場合の動作が確認されていない
- 100%以上の割引が渡された場合の動作が確認されていない
- 境界値がテストされていない

### ✅ 正しい実装例

```javascript
// ✅ 良い例: エッジケースもテスト
// utils/calculator.js
function calculateDiscount(price, discountPercent) {
  if (price < 0) {
    throw new Error('価格は0以上である必要があります');
  }
  if (discountPercent < 0 || discountPercent > 100) {
    throw new Error('割引率は0から100の間である必要があります');
  }
  return price * (discountPercent / 100);
}

module.exports = { calculateDiscount };
```

```javascript
// ✅ 良い例: エッジケースのテスト
// tests/utils/calculator.test.js
const { calculateDiscount } = require('../../utils/calculator');

describe('calculateDiscount', () => {
  describe('正常系', () => {
    it('should calculate discount correctly', () => {
      expect(calculateDiscount(1000, 10)).toBe(100);
    });

    it('should return 0 if discount is 0%', () => {
      expect(calculateDiscount(1000, 0)).toBe(0);
    });

    it('should return full price if discount is 100%', () => {
      expect(calculateDiscount(1000, 100)).toBe(1000);
    });
  });

  describe('エッジケース', () => {
    it('should throw error if price is negative', () => {
      expect(() => calculateDiscount(-100, 10)).toThrow('価格は0以上である必要があります');
    });

    it('should throw error if price is 0', () => {
      expect(() => calculateDiscount(0, 10)).not.toThrow();
      expect(calculateDiscount(0, 10)).toBe(0);
    });

    it('should throw error if discount is negative', () => {
      expect(() => calculateDiscount(1000, -10)).toThrow('割引率は0から100の間である必要があります');
    });

    it('should throw error if discount is over 100%', () => {
      expect(() => calculateDiscount(1000, 150)).toThrow('割引率は0から100の間である必要があります');
    });
  });
});
```

## 4. モックの使用

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 外部APIを直接呼び出すテスト
// services/payment_service.js
async function processPayment(amount, cardNumber) {
  const response = await fetch('https://payment-api.example.com/charge', {
    method: 'POST',
    body: JSON.stringify({ amount, cardNumber })
  });
  return response.json();
}

// テスト（実際のAPIを呼び出してしまう）
describe('processPayment', () => {
  it('should process payment', async () => {
    const result = await processPayment(1000, '1234567890');
    // ❌ 実際のAPIを呼び出してしまう
  });
});
```

**問題点**:
- テストが外部サービスに依存する
- テストが遅くなる
- テストが不安定になる（ネットワークエラーなど）
- テストコストがかかる（実際のAPIを呼び出す）

### ✅ 正しい実装例

```javascript
// ✅ 良い例: モックを使用
// services/payment_service.js
async function processPayment(amount, cardNumber) {
  const response = await fetch('https://payment-api.example.com/charge', {
    method: 'POST',
    body: JSON.stringify({ amount, cardNumber })
  });
  return response.json();
}

module.exports = { processPayment };
```

```javascript
// ✅ 良い例: モックを使用したテスト
// tests/services/payment_service.test.js
const { processPayment } = require('../../services/payment_service');

// fetchをモック化
global.fetch = jest.fn();

describe('processPayment', () => {
  beforeEach(() => {
    fetch.mockClear();
  });

  it('should process payment successfully', async () => {
    // モックのレスポンスを設定
    fetch.mockResolvedValueOnce({
      json: async () => ({ success: true, transactionId: '12345' })
    });

    const result = await processPayment(1000, '1234567890');

    expect(result.success).toBe(true);
    expect(result.transactionId).toBe('12345');
    expect(fetch).toHaveBeenCalledWith(
      'https://payment-api.example.com/charge',
      expect.objectContaining({
        method: 'POST'
      })
    );
  });

  it('should handle API errors', async () => {
    // エラーレスポンスをモック
    fetch.mockRejectedValueOnce(new Error('Network error'));

    await expect(processPayment(1000, '1234567890')).rejects.toThrow('Network error');
  });
});
```

## 5. テストカバレッジの確認

### ✅ 良い例: テストカバレッジの測定

```json
// package.json
{
  "scripts": {
    "test": "jest",
    "test:coverage": "jest --coverage"
  }
}
```

```bash
# テストカバレッジを測定
npm run test:coverage
```

## ✅ テストチェックリスト

コードを書く際に、以下の点を確認しましょう：

- [ ] 単体テストが書かれているか
- [ ] 統合テストが書かれているか
- [ ] エッジケースがテストされているか
- [ ] 正常系と異常系の両方がテストされているか
- [ ] モックが適切に使用されているか（外部依存を排除）
- [ ] テストカバレッジが十分か（80%以上を目標）
- [ ] テストが独立しているか（他のテストに依存しない）
- [ ] テストが高速に実行できるか

## 🎯 まとめ

テストは、コードの品質を保証し、バグを早期に発見するために不可欠です。以下の点に注意することが重要です：

1. **単体テスト**: 各関数やメソッドの動作を確認
2. **統合テスト**: 複数のコンポーネントの連携を確認
3. **エッジケース**: 境界値や異常な入力に対するテスト
4. **モック**: 外部依存を排除してテストを安定化
5. **テストカバレッジ**: 十分なカバレッジを確保

AIが生成するコードには、テストコードが含まれていない場合があるため、必ずテストを追加することが大切です。
