# プロンプトエンジニアリングの基本

AIツールを効果的に使用するためには、適切なプロンプトを書くことが重要です。この章では、プロンプトエンジニアリングの基本について解説します。

## 📖 プロンプトとは

**プロンプト**は、AIに対して送信する指示や質問のことです。適切なプロンプトを書くことで、AIからより良い結果を得ることができます。

### プロンプトの重要性

- **品質の向上**: 適切なプロンプトにより、生成されるコードの品質が向上します
- **効率の向上**: 明確なプロンプトにより、修正の回数が減り、開発効率が向上します
- **ミスの防止**: 具体的な指示により、よくあるミス（MVC違反、セキュリティ対策の不足など）を防げます

## 1. プロンプトの基本構造

効果的なプロンプトは、以下の要素を含みます：

1. **役割の定義**: AIにどのような役割を演じてもらうか
2. **コンテキスト**: プロジェクトやコードの背景情報
3. **具体的な指示**: 何をしてほしいか
4. **出力形式**: どのような形式で出力してほしいか
5. **制約条件**: 守るべきルールや制約

### 基本的なプロンプト例

```
❌ 悪い例: 曖昧なプロンプト
「ユーザー認証を作って」
```

**問題点**:
- 技術スタックが不明
- 要件が不明確
- アーキテクチャパターンが不明
- セキュリティ要件が不明

```
✅ 良い例: 具体的なプロンプト
あなたは経験豊富なNode.js開発者です。
Express.jsを使用して、以下の要件を満たすユーザー認証機能を実装してください。

要件:
- JWTトークンを使用した認証
- パスワードはbcryptでハッシュ化
- セキュリティベストプラクティスに従う
- エラーハンドリングを含める

出力形式:
- コードとコメントを含める
- 各ファイルを分けて提示する
```

## 2. 役割の定義

AIに明確な役割を定義することで、より専門的な回答を得られます。

### 役割定義の例

```
あなたは経験豊富なNode.js + Express.jsの専門家です。
MVCパターンに精通しており、セキュリティベストプラクティスを理解しています。
```

```
あなたはソフトウェアアーキテクトです。
クリーンアーキテクチャとSOLID原則に従った設計を提案してください。
```

```
あなたはセキュリティエキスパートです。
コードのセキュリティ脆弱性をチェックし、改善案を提示してください。
```

## 3. コンテキストの提供

コンテキストを提供することで、AIはより適切なコードを生成できます。

### コンテキストの種類

#### 1. プロジェクト構造

```
このプロジェクトは以下の構造になっています:

project/
├── models/          # データモデル（MVCパターン）
├── controllers/     # コントローラー
├── views/           # ビュー
├── routes/          # ルーティング
├── middleware/      # ミドルウェア
└── utils/           # ユーティリティ

MVCパターンに従っています。
```

#### 2. 技術スタック

```
技術スタック:
- Node.js 18+
- Express.js 4.x
- MySQL 8.0
- JWT認証
- bcrypt（パスワードハッシュ化）
```

#### 3. ビジネスルール

```
ビジネスルール:
- ユーザーはメールアドレスとパスワードで登録
- パスワードは8文字以上、英数字を含む
- メールアドレスは重複不可
- ログイン失敗は5回まで、その後30分ロック
```

#### 4. 既存コードの参照

```
既存のコードスタイルに従ってください:

例:
[既存のコード例を貼り付け]
```

## 4. 具体的な指示

曖昧な指示ではなく、具体的で明確な指示を出します。

### 指示の具体化

```
❌ 悪い例: 曖昧な指示
「エラーハンドリングを追加して」
```

```
✅ 良い例: 具体的な指示
以下のエラーハンドリングを追加してください:
- try-catchブロックで非同期処理を囲む
- バリデーションエラーは400ステータスコードを返す
- データベースエラーは500ステータスコードを返す
- エラーログを記録する
- ユーザーに分かりやすいエラーメッセージを返す
```

### 指示の構造化

複数の要件がある場合は、箇条書きで整理します。

```
要件:
1. MVCパターンに従う
   - モデル層にHTMLを含めない
   - コントローラーは薄く保つ
   - ビジネスロジックはモデルに配置

2. セキュリティ対策
   - SQLインジェクション対策: プリペアドステートメントを使用
   - XSS対策: エスケープ処理を実装
   - 機密情報: 環境変数を使用

3. エラーハンドリング
   - try-catchブロックを使用
   - 適切なHTTPステータスコードを返す
   - エラーログを記録
```

## 5. 出力形式の指定

出力形式を指定することで、必要な情報を効率的に得られます。

### 出力形式の例

```
出力形式:
- 各ファイルを分けて提示
- コードにコメントを追加
- セキュリティ上の注意点を明記
- 改善案を提案
```

```
出力形式:
1. 問題点を箇条書きで提示
2. 各問題に対して改善案を提示
3. 修正後のコード例を提示
4. 変更点の説明
```

## 6. 制約条件の明示

守るべきルールや制約を明示することで、適切なコードを生成できます。

### 制約条件の例

```
制約条件:
- MVCパターンに従う（モデル層にHTMLを含めない）
- DRY原則に従う（コードの重複を避ける）
- 命名規則: キャメルケース（変数・関数）、パスカルケース（クラス）
- インデント: 2スペース
- セミコロン: 使用する
```

## 7. プロンプトのテンプレート

### コード生成テンプレート

```
あなたは[技術スタック]の専門家です。

以下の要件を満たす[機能名]を実装してください:

要件:
- [要件1]
- [要件2]
- [要件3]

技術スタック:
- [技術1]
- [技術2]

アーキテクチャ:
- [アーキテクチャパターン]
- [各層の責務]

セキュリティ要件:
- [セキュリティ要件1]
- [セキュリティ要件2]

出力形式:
- [出力形式1]
- [出力形式2]

制約条件:
- [制約1]
- [制約2]
```

### コードレビューテンプレート

```
以下のコードをレビューし、以下の観点から改善案を提示してください:

レビュー観点:
1. セキュリティ脆弱性（SQLインジェクション、XSSなど）
2. MVCパターンへの準拠
3. エラーハンドリングの適切性
4. コードの重複（DRY原則）
5. 命名規則の一貫性
6. パフォーマンスの問題

コード:
[コードを貼り付け]

出力形式:
- 問題点を箇条書きで提示
- 各問題に対して改善案を提示
- 修正後のコード例を提示
```

### リファクタリングテンプレート

```
以下のコードをリファクタリングしてください:

要件:
1. DRY原則に従い、重複コードを削除
2. 関数を小さく分割（単一責任の原則）
3. 適切な命名規則に従う
4. エラーハンドリングを追加
5. コメントを追加

コード:
[コードを貼り付け]

出力形式:
- リファクタリング前後の比較
- 変更点の説明
- 改善された点の説明
```

## 8. よくあるミスを防ぐプロンプト

### MVC違反を防ぐ

```
以下のコードを生成してください。
MVCパターンに厳密に従い、以下の点を確認してください:
- モデル層にHTMLを含めない
- ビュー層にビジネスロジックを含めない
- コントローラー層に過度なロジックを含めない
```

### セキュリティ対策を含める

```
以下の機能を実装してください。
セキュリティベストプラクティスに従い、以下を含めてください:
- SQLインジェクション対策（プリペアドステートメント）
- XSS対策（エスケープ処理）
- 機密情報の保護（環境変数）
- 認証・認可の実装
```

### エラーハンドリングを含める

```
以下のコードにエラーハンドリングを追加してください:
- try-catchブロックで非同期処理を囲む
- 適切なHTTPステータスコードを返す
- エラーログを記録
- ユーザーに分かりやすいエラーメッセージを返す
```

## ✅ プロンプトチェックリスト

プロンプトを書く際に、以下の点を確認しましょう：

- [ ] 役割が明確に定義されているか
- [ ] コンテキスト（プロジェクト構造、技術スタックなど）が提供されているか
- [ ] 指示が具体的で明確か
- [ ] 出力形式が指定されているか
- [ ] 制約条件が明示されているか
- [ ] よくあるミスを防ぐ指示が含まれているか
- [ ] アーキテクチャパターンが指定されているか
- [ ] セキュリティ要件が含まれているか

## 🎯 まとめ

効果的なプロンプトを書くためには、以下の点が重要です：

1. **明確な役割定義**: AIに専門家の役割を演じてもらう
2. **十分なコンテキスト**: プロジェクトの背景情報を提供
3. **具体的な指示**: 曖昧さを避け、明確に指示
4. **出力形式の指定**: 必要な情報を効率的に得る
5. **制約条件の明示**: 守るべきルールを明確に

適切なプロンプトを書くことで、AIツールからより良い結果を得られ、よくあるミスを防ぐことができます。
