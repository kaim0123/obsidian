# セキュリティ対策の不足

AIが生成するコードには、セキュリティ対策が不十分な場合があります。この章では、よくあるセキュリティの問題と対策について解説します。

## 📖 セキュリティ対策の重要性

Webアプリケーションを開発する際、セキュリティは最優先事項です。AIが生成するコードには、以下のようなセキュリティ脆弱性が含まれることがあります。

**よくある問題**:

- SQLインジェクション対策の不足
- XSS（クロスサイトスクリプティング）対策の不足
- CSRF（クロスサイトリクエストフォージェリ）対策の不足
- 認証・認可の不適切な実装
- 機密情報のハードコーディング

## 1. SQLインジェクション

### 問題点

SQLインジェクションは、悪意のあるSQLコードをアプリケーションに注入する攻撃です。

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: SQLインジェクションの脆弱性
// controllers/user_controller.js
async function getUser(req, res) {
  const username = req.query.username;
  
  // ❌ SQLインジェクションの脆弱性
  // 例: username = "admin' OR '1'='1" とすると、すべてのユーザーが取得される
  const query = `SELECT * FROM users WHERE username = '${username}'`;
  const result = await db.query(query);
  
  res.json(result);
}
```

**攻撃例**:
```
GET /api/users?username=admin' OR '1'='1
```

この攻撃により、以下のようなSQLが実行されます：
```sql
SELECT * FROM users WHERE username = 'admin' OR '1'='1'
```

### ✅ 正しい実装例

```javascript
// ✅ 良い例: プリペアドステートメントを使用
// controllers/user_controller.js
async function getUser(req, res) {
  const username = req.query.username;
  
  // ✅ プリペアドステートメントでSQLインジェクションを防止
  const query = 'SELECT * FROM users WHERE username = ?';
  const result = await db.query(query, [username]);
  
  res.json(result);
}
```

**プリペアドステートメントの利点**:
- ユーザー入力をSQLコマンドとして解釈しない
- パラメータが自動的にエスケープされる
- SQLインジェクション攻撃を防止

## 2. XSS（クロスサイトスクリプティング）

### 問題点

XSSは、悪意のあるJavaScriptコードをWebページに注入する攻撃です。

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: XSSの脆弱性
// views/user_profile.html
<div>
  <h1>こんにちは、${user.name}さん</h1>
  <!-- ❌ ユーザー入力がそのまま表示される（XSS脆弱性） -->
  <p>${user.bio}</p>
</div>
```

**攻撃例**:
ユーザーのbioに以下のような内容が含まれている場合：
```html
<script>alert('XSS攻撃');</script>
<img src="x" onerror="alert('XSS攻撃')">
```

これがそのまま表示されると、JavaScriptが実行されてしまいます。

### ✅ 正しい実装例

```javascript
// ✅ 良い例: XSS対策（エスケープ処理）
// views/user_profile.html
<div>
  <h1>こんにちは、${escapeHtml(user.name)}さん</h1>
  <!-- ✅ エスケープ処理でXSSを防止 -->
  <p>${escapeHtml(user.bio)}</p>
</div>

<script>
  function escapeHtml(text) {
    const div = document.createElement('div');
    div.textContent = text;
    return div.innerHTML;
  }
</script>
```

**エスケープ処理の例**:
```javascript
// サーバーサイドでのエスケープ処理（Node.jsの例）
function escapeHtml(text) {
  if (!text) return '';
  return text
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#039;');
}
```

**フレームワークの機能を活用**:
多くのフレームワークには自動エスケープ機能があります：
- React: 自動的にエスケープ
- Vue.js: `{{ }}` で自動エスケープ
- EJS: `<%= %>` で自動エスケープ

## 3. CSRF（クロスサイトリクエストフォージェリ）

### 問題点

CSRFは、ユーザーが意図しないリクエストを送信させる攻撃です。

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: CSRF対策がない
// controllers/user_controller.js
async function updateUser(req, res) {
  const { name, email } = req.body;
  
  // ❌ CSRFトークンの検証がない
  await db.query(
    'UPDATE users SET name = ?, email = ? WHERE id = ?',
    [name, email, req.user.id]
  );
  
  res.json({ success: true });
}
```

**攻撃例**:
悪意のあるサイトに以下のようなコードが含まれている場合：
```html
<img src="https://example.com/api/users/update?name=Hacker&email=hacker@evil.com">
```

ユーザーがそのサイトを訪問すると、意図しないリクエストが送信されます。

### ✅ 正しい実装例

```javascript
// ✅ 良い例: CSRFトークンの検証
// controllers/user_controller.js
const csrf = require('csurf');
const csrfProtection = csrf({ cookie: true });

async function updateUser(req, res) {
  // ✅ CSRFトークンの検証
  if (!req.csrfToken || req.body._csrf !== req.csrfToken()) {
    return res.status(403).json({ error: 'CSRFトークンが無効です' });
  }
  
  const { name, email } = req.body;
  
  await db.query(
    'UPDATE users SET name = ?, email = ? WHERE id = ?',
    [name, email, req.user.id]
  );
  
  res.json({ success: true });
}
```

**フレームワークの機能を活用**:
- Express.js: `csurf` ミドルウェア
- Django: `{% csrf_token %}` テンプレートタグ
- Rails: `protect_from_forgery` メソッド

## 4. 認証・認可の不適切な実装

### 問題点

認証（誰か）と認可（何ができるか）が適切に実装されていない場合があります。

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 認証チェックがない
// controllers/admin_controller.js
async function deleteUser(req, res) {
  const userId = req.params.id;
  
  // ❌ 認証チェックがない
  await db.query('DELETE FROM users WHERE id = ?', [userId]);
  
  res.json({ success: true });
}
```

```javascript
// ❌ 悪い例: 認可チェックが不十分
// controllers/user_controller.js
async function updateUser(req, res) {
  const userId = req.params.id;
  const { name, email } = req.body;
  
  // ❌ 自分のアカウントかどうかのチェックがない
  await db.query(
    'UPDATE users SET name = ?, email = ? WHERE id = ?',
    [name, email, userId]
  );
  
  res.json({ success: true });
}
```

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 認証・認可のチェック
// middleware/auth.js
function requireAuth(req, res, next) {
  if (!req.user) {
    return res.status(401).json({ error: '認証が必要です' });
  }
  next();
}

function requireAdmin(req, res, next) {
  if (!req.user || req.user.role !== 'admin') {
    return res.status(403).json({ error: '管理者権限が必要です' });
  }
  next();
}

module.exports = { requireAuth, requireAdmin };
```

```javascript
// ✅ 良い例: 認証・認可ミドルウェアを使用
// controllers/admin_controller.js
const { requireAuth, requireAdmin } = require('../middleware/auth');

async function deleteUser(req, res) {
  // ✅ 認証・認可チェック済み（ミドルウェアで）
  const userId = req.params.id;
  
  await db.query('DELETE FROM users WHERE id = ?', [userId]);
  
  res.json({ success: true });
}

// ルーティング
router.delete('/users/:id', requireAuth, requireAdmin, deleteUser);
```

```javascript
// ✅ 良い例: 自分のアカウントかどうかのチェック
// controllers/user_controller.js
const { requireAuth } = require('../middleware/auth');

async function updateUser(req, res) {
  const userId = req.params.id;
  const { name, email } = req.body;
  
  // ✅ 自分のアカウントかどうかをチェック
  if (req.user.id !== parseInt(userId)) {
    return res.status(403).json({ error: '自分のアカウントのみ更新できます' });
  }
  
  await db.query(
    'UPDATE users SET name = ?, email = ? WHERE id = ?',
    [name, email, userId]
  );
  
  res.json({ success: true });
}
```

## 5. 機密情報のハードコーディング

### 問題点

パスワードやAPIキーなどの機密情報をコードに直接書いてしまう問題です。

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 機密情報のハードコーディング
// config/database.js
const dbConfig = {
  host: 'localhost',
  user: 'admin',
  password: 'password123', // ❌ ハードコーディング
  database: 'mydb'
};

// ❌ APIキーのハードコーディング
const apiKey = 'sk-1234567890abcdef';
```

**問題点**:
- コードがGitリポジトリにコミットされると、機密情報が漏洩する
- コードを共有する際に機密情報も共有される
- 環境ごとに異なる設定を使い分けられない

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 環境変数を使用
// config/database.js
const dbConfig = {
  host: process.env.DB_HOST || 'localhost',
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD, // ✅ 環境変数から取得
  database: process.env.DB_NAME
};

// ✅ APIキーも環境変数から取得
const apiKey = process.env.API_KEY;
```

**環境変数の設定例**:
```bash
# .env ファイル（Gitにコミットしない）
DB_HOST=localhost
DB_USER=admin
DB_PASSWORD=secure_password_123
DB_NAME=mydb
API_KEY=sk-1234567890abcdef
```

```javascript
// ✅ .envファイルを読み込む（Node.jsの例）
require('dotenv').config();
```

**`.gitignore`に追加**:
```
.env
.env.local
.env.*.local
```

## ✅ セキュリティチェックリスト

コードを書く際に、以下の点を確認しましょう：

- [ ] SQLインジェクション対策がされているか（プリペアドステートメントを使用）
- [ ] XSS対策がされているか（エスケープ処理）
- [ ] CSRF対策がされているか（CSRFトークンの検証）
- [ ] 認証が適切に実装されているか（ログイン状態の確認）
- [ ] 認可が適切に実装されているか（権限の確認）
- [ ] 機密情報がハードコーディングされていないか（環境変数を使用）
- [ ] パスワードが平文で保存されていないか（ハッシュ化）
- [ ] HTTPSを使用しているか（本番環境）
- [ ] セッション管理が適切か（セッションタイムアウト、セキュアフラグ）

## 🎯 まとめ

セキュリティ対策は、Webアプリケーション開発において最優先事項です。AIが生成するコードには、以下の点を必ず確認し、必要に応じて修正することが重要です：

1. **SQLインジェクション**: プリペアドステートメントを使用
2. **XSS**: エスケープ処理を実装
3. **CSRF**: CSRFトークンの検証
4. **認証・認可**: 適切なミドルウェアとチェック
5. **機密情報**: 環境変数を使用

セキュリティは後から追加するのではなく、最初から設計に組み込むことが重要です。
