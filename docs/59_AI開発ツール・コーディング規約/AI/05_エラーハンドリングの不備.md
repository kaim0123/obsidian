# エラーハンドリングの不備

AIが生成するコードには、エラーハンドリングが不十分な場合があります。この章では、適切なエラーハンドリングの実装方法について解説します。

## 📖 エラーハンドリングの重要性

適切なエラーハンドリングは、アプリケーションの信頼性とユーザー体験を向上させます。エラーハンドリングが不十分だと、以下のような問題が発生します：

**よくある問題**:

- try-catchブロックの不足
- エラーメッセージがユーザーに不親切
- エラーログの記録がない
- 予期しないエラーに対する対策がない
- エラーの種類に応じた適切な処理がない

## 1. try-catchブロックの不足

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: エラーハンドリングがない
// controllers/order_controller.js
async function createOrder(req, res) {
  const { userId, items } = req.body;
  
  // ❌ エラーが発生した場合の処理がない
  const user = await db.query('SELECT * FROM users WHERE id = ?', [userId]);
  const order = await db.query(
    'INSERT INTO orders (user_id) VALUES (?)',
    [userId]
  );
  
  res.json({ orderId: order.insertId });
}
```

**問題点**:
- データベースエラーが発生すると、アプリケーションがクラッシュする
- ユーザーに不親切なエラーメッセージが表示される
- エラーの原因が分からない

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 適切なエラーハンドリング
// controllers/order_controller.js
async function createOrder(req, res) {
  try {
    const { userId, items } = req.body;
    
    // バリデーション
    if (!userId || !items || items.length === 0) {
      return res.status(400).json({
        error: 'ユーザーIDと商品リストが必要です'
      });
    }
    
    // ユーザーの存在確認
    const user = await db.query('SELECT * FROM users WHERE id = ?', [userId]);
    if (!user || user.length === 0) {
      return res.status(404).json({
        error: 'ユーザーが見つかりません'
      });
    }
    
    // 注文の作成
    const order = await db.query(
      'INSERT INTO orders (user_id) VALUES (?)',
      [userId]
    );
    
    res.status(201).json({ orderId: order.insertId });
    
  } catch (error) {
    // エラーログの記録
    console.error('注文作成エラー:', error);
    
    // ユーザーに分かりやすいエラーメッセージを返す
    res.status(500).json({
      error: '注文の作成に失敗しました。しばらくしてから再度お試しください。'
    });
  }
}
```

## 2. エラーメッセージの改善

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: 技術的なエラーメッセージをそのまま返す
async function getUser(req, res) {
  try {
    const user = await db.query('SELECT * FROM users WHERE id = ?', [req.params.id]);
    res.json(user);
  } catch (error) {
    // ❌ 技術的なエラーメッセージをそのまま返す
    res.status(500).json({ error: error.message });
  }
}
```

**問題点**:
- ユーザーには理解できない技術的なメッセージ
- セキュリティリスク（内部構造が漏洩）

### ✅ 正しい実装例

```javascript
// ✅ 良い例: ユーザーに分かりやすいエラーメッセージ
async function getUser(req, res) {
  try {
    const user = await db.query('SELECT * FROM users WHERE id = ?', [req.params.id]);
    
    if (!user || user.length === 0) {
      return res.status(404).json({
        error: 'ユーザーが見つかりません'
      });
    }
    
    res.json(user);
  } catch (error) {
    // エラーログには詳細情報を記録
    console.error('ユーザー取得エラー:', {
      error: error.message,
      stack: error.stack,
      userId: req.params.id
    });
    
    // ユーザーには分かりやすいメッセージを返す
    res.status(500).json({
      error: 'ユーザー情報の取得に失敗しました。しばらくしてから再度お試しください。'
    });
  }
}
```

## 3. エラーの種類に応じた処理

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: すべてのエラーを同じように処理
async function updateUser(req, res) {
  try {
    const { name, email } = req.body;
    await db.query('UPDATE users SET name = ?, email = ? WHERE id = ?', 
      [name, email, req.params.id]);
    res.json({ success: true });
  } catch (error) {
    // ❌ すべてのエラーを500エラーとして処理
    res.status(500).json({ error: 'エラーが発生しました' });
  }
}
```

### ✅ 正しい実装例

```javascript
// ✅ 良い例: エラーの種類に応じた適切な処理
async function updateUser(req, res) {
  try {
    const { name, email } = req.body;
    
    // バリデーションエラー
    if (!name || name.trim() === '') {
      return res.status(400).json({
        error: '名前が必要です'
      });
    }
    
    if (!email || !email.includes('@')) {
      return res.status(400).json({
        error: '有効なメールアドレスが必要です'
      });
    }
    
    // データベースエラー
    const result = await db.query(
      'UPDATE users SET name = ?, email = ? WHERE id = ?',
      [name, email, req.params.id]
    );
    
    if (result.affectedRows === 0) {
      return res.status(404).json({
        error: 'ユーザーが見つかりません'
      });
    }
    
    res.json({ success: true });
    
  } catch (error) {
    // データベース接続エラーなど
    if (error.code === 'ECONNREFUSED') {
      console.error('データベース接続エラー:', error);
      return res.status(503).json({
        error: 'サービスが一時的に利用できません。しばらくしてから再度お試しください。'
      });
    }
    
    // その他のエラー
    console.error('ユーザー更新エラー:', error);
    res.status(500).json({
      error: 'ユーザー情報の更新に失敗しました。しばらくしてから再度お試しください。'
    });
  }
}
```

## 4. エラーログの記録

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: エラーログを記録しない
async function processPayment(req, res) {
  try {
    // 決済処理
    await paymentService.process(req.body);
    res.json({ success: true });
  } catch (error) {
    // ❌ エラーログを記録しない
    res.status(500).json({ error: '決済処理に失敗しました' });
  }
}
```

**問題点**:
- エラーの原因が分からない
- 問題の再現が困難
- デバッグが困難

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 適切なエラーログの記録
const logger = require('./utils/logger');

async function processPayment(req, res) {
  try {
    // 決済処理
    await paymentService.process(req.body);
    res.json({ success: true });
  } catch (error) {
    // ✅ エラーログを記録
    logger.error('決済処理エラー', {
      error: error.message,
      stack: error.stack,
      userId: req.user?.id,
      amount: req.body.amount,
      timestamp: new Date().toISOString()
    });
    
    // ユーザーには分かりやすいメッセージを返す
    res.status(500).json({
      error: '決済処理に失敗しました。しばらくしてから再度お試しください。'
    });
  }
}
```

**ロガーの実装例**:
```javascript
// utils/logger.js
const fs = require('fs');
const path = require('path');

const logger = {
  error: (message, data) => {
    const logEntry = {
      level: 'error',
      message,
      data,
      timestamp: new Date().toISOString()
    };
    
    // コンソールに出力
    console.error(JSON.stringify(logEntry));
    
    // ファイルに記録
    const logFile = path.join(__dirname, '../logs/error.log');
    fs.appendFileSync(logFile, JSON.stringify(logEntry) + '\n');
  }
};

module.exports = logger;
```

## 5. 非同期処理のエラーハンドリング

### ❌ 問題のあるコード例

```javascript
// ❌ 悪い例: Promiseのエラーハンドリングがない
async function fetchUserData(userId) {
  const user = await db.query('SELECT * FROM users WHERE id = ?', [userId]);
  const orders = await db.query('SELECT * FROM orders WHERE user_id = ?', [userId]);
  
  return {
    user: user[0],
    orders: orders
  };
}

// ❌ 呼び出し側でエラーハンドリングがない
app.get('/users/:id', (req, res) => {
  fetchUserData(req.params.id).then(data => {
    res.json(data);
  });
  // ❌ エラーハンドリングがない
});
```

### ✅ 正しい実装例

```javascript
// ✅ 良い例: 適切なエラーハンドリング
async function fetchUserData(userId) {
  try {
    const user = await db.query('SELECT * FROM users WHERE id = ?', [userId]);
    
    if (!user || user.length === 0) {
      throw new Error('ユーザーが見つかりません');
    }
    
    const orders = await db.query('SELECT * FROM orders WHERE user_id = ?', [userId]);
    
    return {
      user: user[0],
      orders: orders
    };
  } catch (error) {
    // エラーを再スローして、呼び出し側で処理
    throw error;
  }
}

// ✅ 呼び出し側でエラーハンドリング
app.get('/users/:id', async (req, res) => {
  try {
    const data = await fetchUserData(req.params.id);
    res.json(data);
  } catch (error) {
    if (error.message === 'ユーザーが見つかりません') {
      return res.status(404).json({ error: error.message });
    }
    
    console.error('ユーザーデータ取得エラー:', error);
    res.status(500).json({
      error: 'ユーザーデータの取得に失敗しました'
    });
  }
});
```

## 6. カスタムエラークラスの使用

### ✅ 良い例: カスタムエラークラス

```javascript
// utils/custom_errors.js
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = 'ValidationError';
    this.statusCode = 400;
  }
}

class NotFoundError extends Error {
  constructor(message) {
    super(message);
    this.name = 'NotFoundError';
    this.statusCode = 404;
  }
}

class DatabaseError extends Error {
  constructor(message) {
    super(message);
    this.name = 'DatabaseError';
    this.statusCode = 500;
  }
}

module.exports = {
  ValidationError,
  NotFoundError,
  DatabaseError
};
```

```javascript
// ✅ カスタムエラークラスを使用
const { ValidationError, NotFoundError } = require('./utils/custom_errors');

async function createUser(req, res) {
  try {
    const { name, email } = req.body;
    
    if (!name || name.trim() === '') {
      throw new ValidationError('名前が必要です');
    }
    
    if (!email || !email.includes('@')) {
      throw new ValidationError('有効なメールアドレスが必要です');
    }
    
    const user = await db.query('SELECT * FROM users WHERE email = ?', [email]);
    if (user && user.length > 0) {
      throw new ValidationError('このメールアドレスは既に使用されています');
    }
    
    const result = await db.query(
      'INSERT INTO users (name, email) VALUES (?, ?)',
      [name, email]
    );
    
    res.status(201).json({ userId: result.insertId });
    
  } catch (error) {
    // カスタムエラーの場合、適切なステータスコードを返す
    if (error instanceof ValidationError) {
      return res.status(error.statusCode).json({ error: error.message });
    }
    
    // その他のエラー
    console.error('ユーザー作成エラー:', error);
    res.status(500).json({
      error: 'ユーザーの作成に失敗しました'
    });
  }
}
```

## ✅ エラーハンドリングチェックリスト

コードを書く際に、以下の点を確認しましょう：

- [ ] try-catchブロックが適切に使用されているか
- [ ] エラーメッセージがユーザーに分かりやすいか
- [ ] エラーログが記録されているか
- [ ] 予期しないエラーに対する対策があるか
- [ ] エラーの種類に応じた適切な処理があるか
- [ ] 非同期処理のエラーハンドリングが適切か
- [ ] 適切なHTTPステータスコードが返されているか
- [ ] 技術的なエラー情報がユーザーに漏洩していないか

## 🎯 まとめ

適切なエラーハンドリングは、アプリケーションの信頼性とユーザー体験を向上させます。以下の点に注意することが重要です：

1. **try-catchブロック**: すべての非同期処理でエラーハンドリングを実装
2. **エラーメッセージ**: ユーザーに分かりやすいメッセージを返す
3. **エラーログ**: デバッグに必要な情報を記録
4. **エラーの種類**: エラーの種類に応じた適切な処理
5. **HTTPステータスコード**: 適切なステータスコードを返す

AIが生成するコードには、エラーハンドリングが不十分な場合があるため、必ず確認し、必要に応じて修正することが大切です。
