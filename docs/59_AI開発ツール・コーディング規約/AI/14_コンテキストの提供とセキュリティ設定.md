# コンテキストの提供とセキュリティ設定

AIツールを効果的に使用するためには、適切なコンテキストを提供し、セキュリティ設定を行うことが重要です。この章では、コンテキストの提供方法とセキュリティ設定について解説します。

## 📖 コンテキストの重要性

AIは、プロジェクトのコンテキストを理解することで、より適切なコードを生成できます。コンテキストが不足していると、以下のような問題が発生します：

- 不適切なアーキテクチャパターンの使用
- セキュリティ対策の不足
- プロジェクトのコーディング規約に従わない
- 既存のコードスタイルと異なる

## 1. コンテキストの提供方法

### 1. プロジェクト構造の説明

プロジェクトの構造を説明することで、AIは適切な場所にコードを生成できます。

#### 例

```
このプロジェクトは以下の構造になっています:

project/
├── models/          # データモデル（MVCパターン）
├── controllers/     # コントローラー
├── views/           # ビュー
├── routes/          # ルーティング
├── middleware/      # ミドルウェア
├── utils/           # ユーティリティ
└── tests/           # テスト

MVCパターンに従っています。
各層の責務:
- モデル: データとビジネスロジック
- ビュー: 表示のみ
- コントローラー: 入力処理と調整
```

### 2. 技術スタックの明示

使用している技術スタックを明示することで、適切なライブラリやフレームワークを使用したコードを生成できます。

#### 例

```
技術スタック:
- Node.js 18+
- Express.js 4.x
- MySQL 8.0
- JWT認証
- bcrypt（パスワードハッシュ化）
- Jest（テストフレームワーク）
```

### 3. ビジネスルールの説明

ビジネスルールを説明することで、適切なロジックを含んだコードを生成できます。

#### 例

```
ビジネスルール:
- ユーザーはメールアドレスとパスワードで登録
- パスワードは8文字以上、英数字を含む
- メールアドレスは重複不可
- ログイン失敗は5回まで、その後30分ロック
- 注文は在庫がある場合のみ可能
- 割引は最大50%まで
```

### 4. 既存コードの参照

既存のコードスタイルに従うことで、一貫性のあるコードを生成できます。

#### 例

```
既存のコードスタイルに従ってください:

例:
[既存のコード例を貼り付け]

このコードスタイルに従って、同様の機能を実装してください。
```

### 5. アーキテクチャパターンの明示

アーキテクチャパターンを明示することで、適切なコード構造を生成できます。

#### 例

```
アーキテクチャパターン:
- MVCパターンに従う
- モデル層にHTMLを含めない
- ビュー層にビジネスロジックを含めない
- コントローラー層に過度なロジックを含めない
- 各層の責務を明確に分離する
```

## 2. Cursorでのコンテキスト提供

### コードベース全体を参照（`Ctrl + Shift + L`）

Cursorでは、`Ctrl + Shift + L` を使用すると、コードベース全体を参照してチャットできます。

#### 良いプロンプト例

```
「このプロジェクトの既存の認証実装を参考に、新しい認証機能を追加してください。
既存のコードスタイルとアーキテクチャパターンに従ってください。」
```

### .cursorrules ファイル

プロジェクトのルートに `.cursorrules` ファイルを作成することで、プロジェクト固有のルールを設定できます。

#### .cursorrules の例

```markdown
# .cursorrules

## プロジェクトの概要
このプロジェクトは、Node.js + Express.js + MySQLを使用したWebアプリケーションです。

## アーキテクチャ
- MVCパターンに従う
- モデル層にHTMLを含めない
- コントローラーは薄く保つ
- ビジネスロジックはモデルに配置

## コーディング規約
- JavaScript: ES6+を使用
- 命名規則: キャメルケース（変数・関数）、パスカルケース（クラス）
- インデント: 2スペース
- セミコロン: 使用する

## セキュリティ
- SQLインジェクション対策: プリペアドステートメントを使用
- XSS対策: エスケープ処理を実装
- 機密情報: 環境変数を使用

## テスト
- 単体テストを必ず書く
- テストカバレッジ80%以上を目標
```

## 3. セキュリティ設定

### 機密情報の保護

AIツールを使用する際は、機密情報が漏洩しないよう注意が必要です。

#### 機密情報の例

- APIキー
- パスワード
- データベース接続情報
- 秘密鍵
- 個人情報

### 設定方法

#### Cursor

```json
{
  "cursor.general.enablePrivacyMode": true
}
```

プライバシーモードを有効にすると、コードがリモートに保存されません。

#### GitHub Copilot

```json
{
  "github.copilot.advanced": {
    "secretKey": "[設定したキー]"
  }
}
```

### ベストプラクティス

1. **環境変数の使用**: 機密情報は環境変数に保存

```javascript
// ❌ 悪い例: ハードコーディング
const apiKey = 'sk-1234567890abcdef';

// ✅ 良い例: 環境変数
const apiKey = process.env.API_KEY;
```

2. **`.gitignore`の設定**: 機密情報を含むファイルを除外

```
# .gitignore
.env
.env.local
*.key
*.pem
config/secrets.js
```

3. **プライバシーモードの活用**: 機密情報を含むコードを扱う際は有効化

4. **コードレビュー**: 生成されたコードに機密情報が含まれていないか確認

5. **会話履歴の管理**: 機密情報を含む会話は削除

## 4. セキュリティチェックリスト

コードを生成する際に、以下の点を確認しましょう：

### 機密情報

- [ ] 機密情報（APIキー、パスワードなど）がコードに含まれていないか
- [ ] 環境変数を使用しているか
- [ ] `.gitignore`に機密情報を含むファイルが追加されているか
- [ ] プライバシーモードが適切に設定されているか

### セキュリティ対策

- [ ] SQLインジェクション対策がされているか（プリペアドステートメント）
- [ ] XSS対策がされているか（エスケープ処理）
- [ ] CSRF対策がされているか（CSRFトークンの検証）
- [ ] 認証・認可が適切に実装されているか
- [ ] パスワードが平文で保存されていないか（ハッシュ化）

### コードレビュー

- [ ] 生成されたコードにセキュリティ脆弱性がないか確認
- [ ] セキュリティベストプラクティスに従っているか確認
- [ ] 機密情報が漏洩していないか確認

## 5. コンテキスト提供のベストプラクティス

### 1. 段階的なコンテキスト提供

一度にすべての情報を提供するのではなく、必要に応じて段階的に提供します。

### 2. 重要な情報を最初に

重要な情報（アーキテクチャパターン、セキュリティ要件など）は、会話の最初に提供します。

### 3. 既存コードの参照

既存のコードを参照することで、一貫性のあるコードを生成できます。

### 4. 定期的なコンテキストの更新

プロジェクトの進捗に応じて、コンテキストを継続的に更新します。

## ✅ コンテキスト提供チェックリスト

AIツールを使用する際に、以下の点を確認しましょう：

- [ ] プロジェクト構造を説明したか
- [ ] 技術スタックを明示したか
- [ ] ビジネスルールを説明したか
- [ ] アーキテクチャパターンを明示したか
- [ ] 既存コードを参照したか
- [ ] セキュリティ要件を含めたか
- [ ] 機密情報を保護しているか

## 🎯 まとめ

コンテキストの提供とセキュリティ設定は、AIツールを効果的に使用するために重要です：

1. **コンテキストの提供**: プロジェクト構造、技術スタック、ビジネスルールなどを提供
2. **セキュリティ設定**: 機密情報の保護、プライバシーモードの設定
3. **ベストプラクティス**: 環境変数の使用、`.gitignore`の設定、コードレビュー

適切なコンテキストを提供し、セキュリティ設定を行うことで、安全で効果的な開発が可能になります。
