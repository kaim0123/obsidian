# ストラテジ系 ① システム戦略・EAとシステム化計画

このノートでは、**情報システム戦略**の考え方、**エンタープライズアーキテクチャ（EA）**、そして**システム化計画と調達**の基礎を整理します。

---

## 1. 情報システム戦略の目的

### 1.1 なぜ戦略が必要か

情報システムには多額の投資が伴います。  
**何のため**に、**どの範囲**で、**どの順番**でシステム化するかを、経営方針や業務方針と整合させて決めることが**情報システム戦略**です。

- 経営目標とIT投資の**整合**
- 投資の**優先順位づけ**と**効果測定**
- 部門ごとの縦割りを減らした**全体最適**

### 1.2 CIO と ITガバナンス

- **CIO（最高情報責任者）**: 情報システム戦略の責任者。経営層の一員として、IT投資と経営目標の整合を図る。
- **ITガバナンス**: 組織がITをどう使うかを決め、統制する仕組み。意思決定の主体、投資判断の基準、リスク管理が含まれる。

---

## 2. エンタープライズアーキテクチャ（EA）

### 2.1 EA とは

**EA**は、組織全体の業務とシステムを**一つの枠組み**で整理し、現状（As-Is）とあるべき姿（To-Be）を描く手法です。

- 部門ごとの縦割りを減らし、**全体最適**なシステム化を進めやすくする。
- 業務・データ・アプリ・技術の**整合性**を保つ。

### 2.2 代表的な視点（アーキテクチャ）

- **ビジネスアーキテクチャ**: 業務の流れ、組織、役割。
- **データアーキテクチャ**: 組織で使うデータの定義、関連。
- **アプリケーションアーキテクチャ**: システムの機能構成、連携。
- **テクノロジアーキテクチャ**: ハードウェア、ネットワーク、ミドルウェアの構成。

ザックマンフレームワークは、これらの視点を「誰が・何を・どのように」などの問いと組み合わせて整理する考え方です。

---

## 3. システム化計画と調達

### 3.1 システム化構想・計画

- 経営方針に基づき、どの業務をどの範囲でシステム化するか、スケジュールと投資を概算する。
- 全体システム化計画と、個別システム化計画の関係を押さえておくとよいです。

### 3.2 要件定義と調達

- **要件定義**: ステークホルダから要求を聞き、**要件**として文書化する。要求分析、ヒアリング、プロトタイプを組み合わせる。
- **調達**: **RFI**（情報提供依頼）、**RFP**（提案依頼）でベンダーから提案を取り、選定する。

### 3.3 契約の種類

- **準委任契約**: 作業の進め方まで発注者が関与する契約。完成責任の所在は発注者寄り。
- **請負契約**: 成果物の完成責任が受注者にある契約。

ソフトウェア開発委託では、IPA の**ソフトウェア開発委託モデル契約**などが参考にされます。

---

## 4. まとめ

- 情報システム戦略では、経営目標とIT投資を整合させ、EA で全体像を描き、要件定義・調達で具体化する。
- EA は、業務・データ・アプリ・技術の視点で整合性を保ち、全体最適を目指す。
- 調達では RFI/RFP と、準委任・請負の違いを理解しておくとよいです。
