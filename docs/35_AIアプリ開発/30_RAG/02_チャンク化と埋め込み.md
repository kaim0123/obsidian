# チャンク化と埋め込み

RAG の検索精度は、**文書をどう分けるか（チャンク化）** と **どう数値に変えるか（埋め込み）** でほぼ決まります。

---

## 1. 埋め込み（embedding）とは

- 文章を **数百〜数千個の数字の並び（ベクトル）** に変換したものです。
- **意味が近い文章ほど、ベクトルも近くなる** ように作られています。「パスワードを忘れた」と「ログインできない」は、単語が違ってもベクトルは近くなります。
- 近さは **コサイン類似度** などで測ります。質問のベクトルに近いチャンクを探すのがベクトル検索です。

| 用語 | 意味 |
|------|------|
| 埋め込みモデル | 文章をベクトルに変換するモデル。回答を作る LLM とは別のもの |
| 次元数 | ベクトルの長さ。大きいほど表現力が高いが、保存量と検索コストが増える |
| ベクトル DB | ベクトルを保存し、近いものを高速に探せる DB（pgvector、Pinecone、Qdrant など） |

- **インデックス作成と検索で、同じ埋め込みモデルを使う** 必要があります。モデルを変えたら全部作り直しです。
- 日本語の文書なら、日本語に強い埋め込みモデルを選びます。

---

## 2. チャンク化

文書を丸ごと 1 つのベクトルにすると、細かい内容が薄まって検索に引っかかりません。逆に細かくしすぎると、文脈が切れて意味が分からなくなります。

| 方法 | 内容 | 向いている文書 |
|------|------|--------------|
| **固定長** | 500 文字ごとなど機械的に切る | 構造のない長文 |
| **構造で切る** | 見出し・段落・条文ごとに切る | マニュアル、Markdown、規程 |
| **重なり（オーバーラップ）を付ける** | 前後のチャンクと 10〜20% 重ねる | 文の途中で切れるのを防ぎたいとき |

- **見出しやタイトルをチャンクに付ける** と精度が上がります。「手順 3：再起動する」だけでは何の手順か分かりません。

```text
【文書】ルーター設定マニュアル >【章】Wi-Fi がつながらないとき
手順 3：ルーターの電源を抜き、30 秒待ってから差し直します。
```

- 「最適なチャンクの大きさ」は文書と質問の種類で変わります。**決め打ちせず、評価セットで比べて決めます**。

---

## 3. 保存しておくメタデータ

| 項目 | 使い道 |
|------|--------|
| 文書 ID・タイトル・URL | 回答に出典を表示する |
| 更新日時 | 古い文書を除外する、再インデックスの判定 |
| 閲覧権限（部署・ユーザー） | **検索時に絞り込む**。見せてはいけない文書を LLM に渡さない |
| カテゴリ | 質問の種類で検索範囲を絞る |

---

## 4. ベクトル DB の選び方

| 選択肢 | 向いている場面 |
|--------|--------------|
| **既存の DB の拡張（PostgreSQL ＋ pgvector など）** | すでに RDB を使っている。件数が数百万件まで。運用を増やしたくない |
| **専用のベクトル DB** | 大量のベクトル、高速な検索、細かいチューニングが必要 |
| **LLM ベンダーのファイル検索機能** | とにかく早く試したい。中身の調整はしにくい |

- 最初は手持ちの DB の拡張で十分なことが多いです。データストア全般の選び方は 68_データアーキテクチャ を参照。
