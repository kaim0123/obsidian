# RAGの仕組み

LLM は学習した時点までの、公開された情報しか知りません。**社内マニュアル、自社の商品データ、昨日の議事録** について聞いても答えられないか、もっともらしい嘘（ハルシネーション）を返します。

**RAG（Retrieval-Augmented Generation：検索拡張生成）** は、質問のたびに関連する資料を検索して、それをプロンプトに入れてから答えさせる手法です。「LLM に資料を見ながら答えてもらう」と考えると分かりやすいです。

---

## 1. 全体の流れ

```
【事前準備（インデックス作成）】
文書 → 分割（チャンク化） → 埋め込みベクトルに変換 → ベクトル DB に保存

【質問のたび（検索と生成）】
質問 → 埋め込みに変換 → 似たチャンクを検索 → 上位 N 件をプロンプトに入れる → LLM が回答
```

|------|--------|
| 分割・埋め込み | [[02_チャンク化と埋め込み]] |
| 検索の精度を上げる | [[03_ハイブリッド検索とリランキング]] |

## 2. 最小の実装イメージ

```ts
// 1. 質問に近いチャンクを検索する（ベクトル DB の API は製品ごとに違う）
const chunks = await vectorStore.search(await embed(question), { topK: 5 });

// 2. 出典が分かる形でプロンプトに入れる
const documents = chunks
  .map((c) => `<doc id="${c.id}" title="${c.title}">\n${c.text}\n</doc>`)
  .join("\n");

// 3. 回答させる
const response = await client.messages.create({
  model: "claude-opus-5-5",
  max_tokens: 16000,
  system:
    "<documents> の内容だけを根拠に答えてください。" +
    "根拠にした doc の id を回答の最後に書いてください。" +
    "資料に答えがなければ、そう伝えてください。",
  messages: [
    { role: "user", content: `<documents>\n${documents}\n</documents>\n\n質問：${question}` },
  ],
});
```

## 3. RAG・ロングコンテキスト・ファインチューニングの使い分け

| 方法 | 向いている場面 | 弱み |
|------|--------------|------|
| **資料を丸ごと入れる** | 資料が少ない（数十ページ程度） | 量が増えると高く・遅くなる |
| **RAG** | 資料が多い、頻繁に更新される、出典を示したい | 検索を外すと答えられない |
| **ファインチューニング** | 口調や出力形式を覚えさせたい | 知識の追加には向かない。更新のたびに学習し直す |

- 最近のモデルはコンテキストが 100 万トークン級まで広がり、**少量の資料なら RAG を作らず全部入れる** ほうが簡単で精度も高いことがあります。まずそれを試し、量やコストが問題になってから RAG にします。
- 知識を足したいならファインチューニングより RAG、が基本です。

## 4. うまくいかない原因の切り分け

RAG の失敗は **「検索の失敗」と「生成の失敗」** に分けて調べます。

| 症状 | 原因 | 対策 |
|------|------|------|
| 正解の資料が検索結果にない | 検索の失敗 | チャンクの切り方、ハイブリッド検索、クエリの書き換え |
| 資料はあるのに間違える | 生成の失敗 | プロンプトの改善、渡す件数を減らす、モデルを変える |
| 資料にないことを答える | ハルシネーション | 「資料にないときは答えない」を指示、出典の明示 |
| 古い情報で答える | インデックスが古い | 文書の更新時に再インデックスする仕組み |

- 検索の精度は **「正解のチャンクが上位 N 件に入った割合（Recall@N）」** で測れます（[[01_LLMアプリの評価（Evals）]]）。

---

## 5. 権限とセキュリティ

- **検索する時点で、そのユーザーが見てよい文書だけに絞ります**。LLM に「この人には見せないで」と頼むのでは守れません。
- 検索対象の文書に悪意ある指示が書かれている可能性があります（間接プロンプトインジェクション：[[08_プロンプトインジェクション]]）。
