# コンテキストエンジニアリング

LLM が 1 回の呼び出しで読める情報の量（**コンテキストウィンドウ**）には上限があります。上限まで入れられたとしても、**入れすぎると料金が上がり、応答が遅くなり、大事な情報が埋もれます**。「何を、どの順番で、どれだけ入れるか」を設計するのがコンテキストエンジニアリングです。

プロンプトの書き方（[[01_アプリに組み込むプロンプト設計]]）が「文章の質」の話なら、こちらは **「入れる情報の取捨選択」** の話です。

---

## 1. コンテキストに入るもの

| 中身 | 増え方 |
|------|--------|
| システムプロンプト | 固定 |
| ツールの定義 | ツールの数に比例 |
| 会話の履歴 | 会話が続くほど増える |
| 参照資料（RAG の結果など） | 質問ごとに変わる |
| ツールの実行結果 | エージェントでは急激に増える |

---

## 2. 基本の考え方

| 方針 | 内容 |
|------|------|
| **必要なものだけ入れる** | 「念のため全部」は逆効果。関係ない資料は判断を鈍らせる |
| **固定 → 変動 の順に並べる** | システムプロンプト・ツール定義を先頭に。キャッシュが効く |
| **大事な指示は明確な場所に** | 長い資料の後ろに質問を置くと、精度が上がりやすい |
| **出典が分かる形で入れる** | 資料に ID やタイトルを付けると、回答で引用させられる |

---

## 3. 会話が長くなったときの対策

| 方法 | 内容 | 向いている場面 |
|------|------|--------------|
| **古い履歴を捨てる** | 直近 N 往復だけ残す | 雑談、単発の質問が続くチャット |
| **要約して圧縮する** | 古い部分を短い要約に置き換える | 長い相談、作業の継続 |
| **古いツール結果を消す** | 使い終わった検索結果などを消す | エージェント |
| **外部メモリに逃がす** | 大事な事実だけファイルや DB に保存し、必要なときに読む | 何日も続く作業 |

- Claude API には、サーバー側で古い履歴を要約する **コンパクション** や、古いツール結果を消す **コンテキスト編集** の機能があります。自前で作る前に、使う API の機能を確認します。
- 履歴を途中で書き換えるとプロンプトキャッシュが無効になります。**基本は「後ろに追記するだけ」** にしておくと、安く速く保てます。

## 4. チェックリスト

- [ ] コンテキストに入れているものを一覧で説明できる
- [ ] 関係ない資料を入れていない
- [ ] 固定の部分を先頭にまとめている
- [ ] 会話が長くなったときの方針（捨てる・要約する）を決めている
