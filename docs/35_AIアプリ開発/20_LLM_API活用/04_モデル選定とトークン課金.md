# モデル選定とトークン課金

LLM API の料金は **トークン** という単位で決まります。モデルによって性能・速度・料金が大きく違うので、機能ごとに「どのモデルで足りるか」を決める必要があります。

---

## 1. トークンとは

- LLM が文章を処理する単位です。英語ならおよそ 1 単語、日本語なら 1〜2 文字程度で 1 トークンになることが多いです（モデルによって変わります）。
- 料金は **入力トークン** と **出力トークン** で別々にかかり、**出力のほうが数倍高い** のが一般的です。
- 正確な数は API のトークン数計測機能や、応答の `usage` で確認します。文字数からの推測に頼らないようにします。

```ts
const response = await client.messages.create({ /* ... */ });
console.log(response.usage.input_tokens, response.usage.output_tokens);
```

---

## 2. 料金の感覚をつかむ

例：Claude の料金（2026 年 10 月時点、100 万トークンあたり）

| モデル | 入力 | 出力 | 向いている用途 |
|--------|------|------|--------------|
| Haiku 5.5 | $0.10 | $0.50 | 大量の分類・抽出、速さ重視 |
| Sonnet 5.5 | $2 | $10 | 日常的なチャット、コーディング、エージェント |
| Opus 5.5 | $4 | $20 | 難しい推論、品質重視 |

**計算例**：入力 2,000 トークン・出力 500 トークンの問い合わせ要約を、1 日 1 万件（月 30 万件）処理する場合

- 入力：2,000 × 300,000 = 6 億トークン、出力：500 × 300,000 = 1.5 億トークン
- Haiku 5.5：600 × $0.10 + 150 × $0.50 = **約 $135 / 月**
- Opus 5.5：600 × $4 + 150 × $20 = **約 $5,400 / 月**

> 料金はすぐ変わります。実装前に必ず各社の公式の料金ページで確認してください。

## 3. モデルの選び方

| 観点 | 確認すること |
|------|------------|
| **品質** | 自分の評価セットで点数を比べる（[[01_LLMアプリの評価（Evals）]]）。ベンチマークの順位より自分のデータ |
| **速度** | 最初の 1 文字が出るまでの時間、全体の応答時間 |
| **料金** | 1 件あたりではなく **1 タスクが完了するまで** の料金で比べる |
| **コンテキスト長** | 入れたい資料の量が入るか |
| **機能** | 画像入力、構造化出力、ツール呼び出し、キャッシュに対応しているか |
| **データの扱い** | 学習に使われないか、保存期間、提供リージョン |

- まず **一番性能の高いモデルで動くものを作り**、評価セットができてから安いモデルや設定に下げられるか試すのが安全です。
- 安いモデルで何度もやり直すほうが、高いモデルで 1 回で済ませるより高くつくこともあります。

---

## 4. 機能ごとに使い分ける

| 処理 | モデル例 |
|------|---------|
| 入力の分類・振り分け | 小さく速いモデル |
| 本番の回答生成 | 中〜大のモデル |
| 評価の採点役（LLM-as-judge） | 採点される側と同等以上のモデル |

- 使い分けると、モデルごとにプロンプトや評価を管理する手間が増えます。**最初は 1 つのモデルで始めて**、コストが問題になってから分けます。
- 具体的な節約の手順は [[02_LLMのコスト最適化]]。
