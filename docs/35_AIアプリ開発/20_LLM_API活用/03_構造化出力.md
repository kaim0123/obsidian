# 構造化出力

LLM の出力を **人が読む** なら普通の文章で構いません。でも **プログラムが読む**（DB に保存する、画面のフォームに入れる、次の処理に渡す）なら、決まった形の JSON で返してもらう必要があります。これが構造化出力です。

---

## 1. なぜ「JSON で返して」と頼むだけではだめか

| 問題 | 例 |
|------|----|
| 前後に説明文が付く | 「はい、こちらが JSON です：```json ...```」 |
| キー名が揺れる | `email` だったり `mail` だったり |
| 型が違う | 数値のはずが `"3"`（文字列） |
| 必須の項目が抜ける | `name` がない |

`JSON.parse` が失敗したり、通ってもアプリが壊れたりします。そこで **API の機能でスキーマ（形）を強制する** のが確実です。

---

## 2. スキーマを指定して返してもらう

Claude API では `output_config.format` にスキーマを渡すと、その形に合った JSON が返ってきます。TypeScript では Zod でスキーマを書けます。

```ts
import Anthropic from "@anthropic-ai/sdk";
import { z } from "zod";
import { zodOutputFormat } from "@anthropic-ai/sdk/helpers/zod";

const InquirySchema = z.object({
  category: z.enum(["故障", "使い方", "返品", "その他"]),
  product: z.string(),
  urgent: z.boolean(),
  summary: z.string(),
});

const client = new Anthropic();

const response = await client.messages.parse({
  model: "claude-opus-5-5",
  max_tokens: 16000,
  messages: [{ role: "user", content: `次の問い合わせを分類して:\n${mailBody}` }],
  output_config: { format: zodOutputFormat(InquirySchema) },
});

const inquiry = response.parsed_output; // 失敗時は null
if (inquiry) await saveInquiry(inquiry);
```

- `enum` で選択肢を決めておくと、分類の揺れがなくなります。
- `parsed_output` が `null` のとき（途中で切れた、拒否されたなど）の処理も書いておきます。

---

## 3. 形が正しくても、中身が正しいとは限らない

スキーマが保証するのは **形** だけです。

| 保証される | 保証されない |
|-----------|-------------|
| キーがそろっている | 値が事実として正しい |
| 型が合っている | 分類が正しい |
| enum の範囲内 | 要約が元の文章に忠実 |

- 中身の正しさは [[01_LLMアプリの評価（Evals）]] で測ります。
- 金額や日付など業務上重要な値は、**アプリ側でも検証** します（範囲チェック、元データとの照合）。

---

## 4. よく使う場面

| 場面 | 例 |
|------|----|
| **抽出** | メール本文から氏名・日付・注文番号を取り出す |
| **分類** | 問い合わせのカテゴリ、感情（ポジ / ネガ） |
| **フォームの自動入力** | 名刺の写真から連絡先を作る |
| **ワークフローのつなぎ** | 1 段目の結果を JSON にして 2 段目に渡す |
