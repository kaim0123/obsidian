# AI機能のUX設計

LLM は **遅く、ときどき間違えます**。この性質を前提に画面と流れを作らないと、ユーザーは「AI が嘘をついた」「固まった」と感じて使わなくなります。

---

## 1. 待ち時間への対策

| 対策 | 内容 |
|------|------|
| **ストリーミング表示** | 生成された文字から順に表示する（[[02_LLM APIの基本とストリーミング]]） |
| **進み具合を見せる** | 「資料を検索中…」「3 件の文書を読んでいます」など、今何をしているかを出す |
| **中断ボタン** | 長い生成を途中で止められるようにする |
| **非同期にする** | 数分かかる処理は「終わったら通知します」にして、画面を占有しない |

---

## 2. 間違える前提の設計

| 対策 | 内容 |
|------|------|
| **出典を表示する** | RAG の回答に、根拠の文書へのリンクを付ける。ユーザーが自分で確かめられる |
| **AI が作ったと分かるようにする** | 「AI による下書き」のラベル |
| **人が確認してから実行** | メール送信・登録・支払いなどは、AI が下書きを作り、人が確認して確定する |
| **編集しやすくする** | 出力をそのまま直せるようにする。「全部やり直し」しかないのは不便 |
| **分からないときは分からないと言う** | 資料にないことは「分かりません」と答え、別の窓口を案内する（[[01_アプリに組み込むプロンプト設計]]） |

- 重要な操作ほど、**AI は提案だけ、決定は人** にします。間違えたときの被害を小さくできます。

---

## 3. 入力の工夫

- 何を聞けばよいか分からないユーザーのために、**質問の例やボタン** を用意します。
- 自由入力だけでなく、選択肢やフォームと組み合わせると、意図がはっきりして精度が上がります。

---

## 4. フィードバックを集める

| 仕組み | 使い道 |
|--------|--------|
| 👍 / 👎 ボタン | 品質の傾向を見る（[[01_LLM呼び出しの可観測性]]） |
| 「どこが違いましたか」の自由記述 | 改善のヒント |
| ユーザーが出力を編集した差分 | 理想の出力の例として使える |

- 👎 や編集が多かった例は、評価セットに足します（[[01_LLMアプリの評価（Evals）]]）。

---

## 5. 信頼とプライバシー

- 入力したデータが **どこに送られ、保存されるか、学習に使われるか** を分かりやすく示します。
- 個人情報や機密情報を入力しないよう注意書きを出す、あるいは送る前に自動で伏せます。
