# MCP（Model Context Protocol）

**MCP** は、LLM アプリと外部のツール・データをつなぐための **共通の規格** です。Anthropic が 2024 年に公開し、いまは多くの AI アプリや開発ツールが対応しています。「AI 向けの USB 端子」とたとえられます。

---

## 1. なぜ必要か

MCP がないと、AI アプリごと・サービスごとにツールのつなぎ込みを書く必要があります。

```
MCP なし：アプリ A × (GitHub, Slack, DB)、アプリ B × (GitHub, Slack, DB) … 組み合わせの数だけ実装
MCP あり：各サービスが MCP サーバーを 1 つ作れば、MCP 対応のどのアプリからも使える
```

---

## 2. 登場人物

| 役割 | 内容 | 例 |
|------|------|----|
| **MCP ホスト** | ユーザーが使う AI アプリ | Claude Desktop、Claude Code、Cursor、自作アプリ |
| **MCP クライアント** | ホストの中で、サーバーとの通信を担当する部分 | — |
| **MCP サーバー** | ツールやデータを提供する側 | GitHub、Slack、ファイルシステム、自社 API |

サーバーが提供できるもの：

| 種類 | 内容 |
|------|------|
| **Tools** | LLM が呼び出せる関数（[[05_ツール呼び出し（Function Calling）]] と同じ考え方） |
| **Resources** | 読み取り用のデータ（ファイル、DB のレコードなど） |
| **Prompts** | 定型のプロンプトのテンプレート |

通信方式は、同じマシン上で動かす **stdio** と、ネットワーク越しの **HTTP** があります。

---

## 3. 使い方は 2 通り

| 立場 | やること |
|------|---------|
| **使う側** | 既存の MCP サーバーを自分のアプリや開発ツールにつなぐ。Claude API には MCP サーバーを直接指定できるコネクタ機能もある |
| **作る側** | 自社のサービスや社内 DB を MCP サーバーとして公開し、いろいろな AI アプリから使えるようにする |

- 自社サービスを AI から使えるようにしたいなら、**API を作る感覚で MCP サーバーを作る** のが今の定番です。設計の考え方は普通の API 設計（45_API設計）と多くが共通です。

---

## 4. セキュリティの注意

| リスク | 対策 |
|--------|------|
| 信頼できない MCP サーバーが悪意ある指示を返す | **入れるサーバーは出どころを確認する**。公式・信頼できる提供元のものを使う |
| サーバーに強すぎる権限を渡す | 必要な範囲のトークンだけを渡す。読み取り専用で済むならそうする |
| ツールの説明文に隠れた指示（ツールポイズニング） | サーバーのツール定義を確認する。更新で中身が変わっていないか見る |
| 外部データ経由のインジェクション | [[08_プロンプトインジェクション]] |
