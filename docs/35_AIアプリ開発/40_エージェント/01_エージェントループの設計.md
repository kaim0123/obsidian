# エージェントループの設計

**エージェント** は、LLM が **計画 → ツールを実行 → 結果を見る → 次の行動を決める** をくり返して、目的を達成する仕組みです。[[05_ツール呼び出し（Function Calling）]] をループで回したもの、と考えられます。

---

## 1. 本当にエージェントが必要か

エージェントは強力ですが、**遅く・高く・失敗の幅が大きい** です。次の 4 つすべてが「はい」のときだけ使います。

| 問い | 「いいえ」なら |
|------|--------------|
| 手順を事前に決めきれないほど複雑か | コードで手順を決めるワークフローにする |
| コストと時間に見合う価値があるか | 1 回の呼び出しで済ませる |
| LLM がその作業を十分こなせるか | 人の作業として残す |
| 失敗しても検知・やり直しができるか | 人の確認をはさむ、範囲を狭める |

---

## 2. ループの基本形

```ts
let messages: Anthropic.MessageParam[] = [{ role: "user", content: task }];

for (let step = 0; step < MAX_STEPS; step++) {   // ① ステップ数の上限
  const response = await client.messages.create({
    model: "claude-opus-5-5",
    max_tokens: 16000,
    tools,
    messages,
  });
  messages.push({ role: "assistant", content: response.content });

  if (response.stop_reason !== "tool_use") break; // 完了、または停止

  const toolResults: Anthropic.ToolResultBlockParam[] = [];
  for (const block of response.content) {
    if (block.type !== "tool_use") continue;
    try {
      const result = await executeTool(block.name, block.input);
      toolResults.push({ type: "tool_result", tool_use_id: block.id, content: result });
    } catch (e) {
      // ② 失敗も結果として返す（LLM が自分で立て直せる）
      toolResults.push({ type: "tool_result", tool_use_id: block.id, content: String(e), is_error: true });
    }
  }
  messages.push({ role: "user", content: toolResults }); // ③ 結果はまとめて 1 メッセージで返す
}
```

- 手書きのループのほかに、SDK のツールランナー（[[05_ツール呼び出し（Function Calling）]] の例）を使うとループ部分を書かずに済みます。

---

## 3. 暴走を防ぐ設計

| 対策 | 内容 |
|------|------|
| **ステップ数の上限** | 同じツールを延々と呼び続けるのを止める |
| **トークン・金額の上限** | 1 タスクあたりの予算を決める |
| **タイムアウト** | 全体の時間に上限を付ける |
| **人の承認** | 削除・送信・支払いなど取り消せない操作の前で止める |
| **最小権限** | ツールに渡す権限を必要最小限にする。読み取り専用で済むならそうする |
| **サンドボックス** | コード実行やファイル操作は隔離された環境で行う |

---

## 4. ツールの設計

- **ツールは少なく、分かりやすく**。似たツールが並ぶと選び間違えます。
- ツールの結果は **必要な部分だけ** 返します。巨大な JSON をそのまま返すと、コンテキストがすぐに埋まります（[[02_コンテキストエンジニアリング]]）。
- 外部の Web ページやメールを読むツールの結果には、悪意ある指示が紛れ込むことがあります（[[08_プロンプトインジェクション]]）。

---

## 5. 評価と観測

- 最終結果だけでなく、**途中の行動（どのツールを、何回、どんな引数で呼んだか）** を記録します（[[01_LLM呼び出しの可観測性]]）。
- 評価では「正しく終わったか」に加えて「何ステップかかったか」「いくらかかったか」も見ます（[[01_LLMアプリの評価（Evals）]]）。
