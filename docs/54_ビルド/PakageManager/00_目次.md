## 第1部：まず全体像（言語に依存しない基礎）

### 1. パッケージ管理とは

- なぜ必要か（再利用、配布、更新、脆弱性対応）
- 「アプリ」と「ライブラリ」の違い
- 依存関係（direct / transitive）と依存地獄

### 2. レジストリ（パッケージ置き場）と配布の仕組み

- レジストリとは（例：PyPI / npm registry など）
- バージョンとタグ（SemVer の考え方）
- ダウンロード・キャッシュの概念

### 3. バージョニングと互換性

- SemVer（MAJOR/MINOR/PATCH）
- バージョン範囲指定（例：固定 / 範囲 / 上限・下限）
- 「壊れない更新」をどう作るか（互換性の考え方）

### 4. ロックファイルと再現性

- なぜロックが必要か
- ロックファイルが保証するもの／しないもの
- チーム開発での扱い（コミットするか、いつ更新するか）

### 5. 依存の解決（Dependency Resolution）の考え方

- 依存解決とは何をしているか
- 競合が起きる典型パターン
- 解決方針（更新 / ピン留め / 置き換え）

### 6. 開発依存と実行依存、環境の分離

- devDependencies / dependencies 的な考え方
- 仮想環境（言語によって仕組みは違うが目的は同じ）
- ローカルとCIで揃える

### 7. セキュリティとメンテナンス

- 脆弱性情報（Advisory）と更新
- 依存の棚卸し（不要依存の削除）
- 供給網（Supply Chain）リスクの基本

## 第2部：運用（プロジェクトで困らないための実践）

### 8. 新規プロジェクトでの基本手順（共通手順）

- 依存を追加する前に決めること（方針、バージョン、ロック）
- 依存追加 → 実行 → テスト → ロック更新 の流れ
- 「とりあえず入れる」を避ける基準

### 9. よくあるトラブルシュート

- インストールが遅い／失敗する
- バージョン競合（解決できない）
- 「動く人と動かない人がいる」（再現性）
- ロック更新の衝突（チームで起きる問題）

### 10. モノレポ／複数パッケージ構成の基礎（触り）

- 何が難しくなるか（共有・バージョン・ビルド）
- ワークスペース的な仕組み（言語ごとの例は後半で）
