# パッケージマネージャーとは

パッケージマネージャーは、ライブラリやツールを管理するためのツールです。この章では、パッケージマネージャーの概念と使い方について初心者向けに解説します。

## 📖 パッケージマネージャーとは何か

**パッケージマネージャー（Package Manager）**は、ライブラリやツール（パッケージ）をインストール・更新・削除するためのツールです。

### 日常生活での例え

パッケージマネージャーは、「アプリストア」のようなものです。

- **アプリストア**: アプリを検索、インストール、更新できる
- **パッケージマネージャー**: ライブラリを検索、インストール、更新できる

## 📦 主なパッケージマネージャー

### 1. npm（Node Package Manager）

Node.jsの標準パッケージマネージャーです。

```bash
# パッケージのインストール
npm install express

# 開発用依存関係のインストール
npm install --save-dev nodemon

# パッケージの更新
npm update express

# パッケージの削除
npm uninstall express

# すべての依存関係をインストール
npm install
```

### 2. yarn

npmの代替として開発されたパッケージマネージャーです。

```bash
# パッケージのインストール
yarn add express

# 開発用依存関係のインストール
yarn add -D nodemon

# パッケージの更新
yarn upgrade express

# パッケージの削除
yarn remove express

# すべての依存関係をインストール
yarn install
```

### 3. pnpm

効率的なパッケージマネージャーです。

```bash
# パッケージのインストール
pnpm add express

# 開発用依存関係のインストール
pnpm add -D nodemon

# パッケージの更新
pnpm update express

# パッケージの削除
pnpm remove express
```

### 4. pip（Python）

Pythonのパッケージマネージャーです。

```bash
# パッケージのインストール
pip install requests

# パッケージの更新
pip install --upgrade requests

# パッケージの削除
pip uninstall requests

# 依存関係ファイルからインストール
pip install -r requirements.txt
```

## 📄 package.json

Node.jsプロジェクトでは、`package.json`ファイルで依存関係を管理します。

### 基本的なpackage.json

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "description": "My application",
  "main": "index.js",
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js",
    "test": "jest"
  },
  "dependencies": {
    "express": "^4.18.2",
    "dotenv": "^16.0.3"
  },
  "devDependencies": {
    "nodemon": "^2.0.20",
    "jest": "^29.0.0"
  }
}
```

### 依存関係の種類

#### dependencies（本番環境で必要）

```json
{
  "dependencies": {
    "express": "^4.18.2"
  }
}
```

#### devDependencies（開発環境でのみ必要）

```json
{
  "devDependencies": {
    "nodemon": "^2.0.20"
  }
}
```

## 🔧 パッケージのバージョン管理

### セマンティックバージョニング

バージョン番号は `メジャー.マイナー.パッチ` の形式です。

- **メジャー**: 互換性のない変更
- **マイナー**: 後方互換性のある新機能
- **パッチ**: バグ修正

### バージョン指定

```json
{
  "dependencies": {
    "express": "^4.18.2",  // 4.18.2以上、5.0.0未満
    "lodash": "~4.17.21",  // 4.17.21以上、4.18.0未満
    "react": "18.2.0"      // 正確に18.2.0
  }
}
```

## 💻 実践例

### プロジェクトの初期化

```bash
# npmでプロジェクトを初期化
npm init -y

# package.jsonが作成される
```

### パッケージのインストール

```bash
# Expressをインストール
npm install express

# 開発用ツールをインストール
npm install --save-dev nodemon

# グローバルにインストール（システム全体で使用）
npm install -g typescript
```

### package.jsonの更新

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js"
  },
  "dependencies": {
    "express": "^4.18.2",
    "dotenv": "^16.0.3"
  },
  "devDependencies": {
    "nodemon": "^2.0.20"
  }
}
```

## 🔍 パッケージの検索

### npmでの検索

```bash
# パッケージを検索
npm search express

# パッケージの情報を表示
npm info express

# パッケージのバージョンを確認
npm list express
```

### オンラインで検索

- **npm公式サイト**: https://www.npmjs.com/
- **GitHub**: パッケージのソースコード

## ⚠️ よくある問題と対処法

### 1. 依存関係の競合

```bash
# 依存関係を確認
npm list

# 競合を解決
npm install --legacy-peer-deps
```

### 2. node_modulesの削除

```bash
# node_modulesを削除して再インストール
rm -rf node_modules
npm install
```

### 3. キャッシュのクリア

```bash
# npmキャッシュをクリア
npm cache clean --force
```

## 🔐 セキュリティ

### 脆弱性のチェック

```bash
# 脆弱性をチェック
npm audit

# 脆弱性を自動修正
npm audit fix
```

### package-lock.json

依存関係の正確なバージョンを記録するファイルです。

```bash
# package-lock.jsonを生成
npm install

# Gitにコミットする（推奨）
git add package-lock.json
```

## 🔁 npm と pnpm の違い

初心者目線で、Node.js でよく使われる **npm** と **pnpm** の違いを整理します。

### インストールの仕組みの違い

- **npm**
  - プロジェクトごとに `node_modules` フォルダの中へ、必要なパッケージを「丸ごとコピー」して保存します。
  - 複数プロジェクトで同じパッケージを使っていても、それぞれのプロジェクトに同じファイルが何度も置かれます。
  - 結果として、**ディスク使用量が多くなりがち**です。

- **pnpm**
  - PC 全体で共通の「ストア」にパッケージを 1 回だけ保存し、各プロジェクトの `node_modules` からは**リンク（ショートカットのようなもの）**で参照します。
  - 同じバージョンのパッケージは 1 つだけで済むため、**ディスク使用量が少なくなりやすく、インストールも速い**のが特徴です。

### 依存関係の扱い

- **npm**
  - 歴史的には、`node_modules` がフラットな構造になることが多く、「たまたま上の階層にあるパッケージが見つかって動く」といったケースがありました（最近は改善されています）。

- **pnpm**
  - `node_modules` の構造をより厳密に管理し、**`package.json` にちゃんと書かれていない依存パッケージは使えない**ようにしています。
  - そのため、依存関係の漏れや間違いに**早く気づきやすい**です。

### 実行するコマンドの違い

基本の使い方はほぼ同じで、コマンド名だけが変わります。

```bash
# npm の例
npm install        # 依存関係のインストール
npm run dev       # スクリプトの実行

# pnpm の例
pnpm install       # 依存関係のインストール
pnpm dev           # "run" を省略して呼び出せる
```

### どちらを選べばよい？

- **npm を選びやすい場面**
  - Node.js に最初から付いてくる「標準」のツールを使いたいとき
  - 小〜中規模のプロジェクトで、特に性能面の不満がないとき

- **pnpm を選びやすい場面**
  - インストールが遅い・`node_modules` が大きすぎる、と感じているとき
  - 複数のプロジェクトやモノレポ（1 つのリポジトリで複数パッケージ管理）を運用したいとき
  - 依存関係をより厳密に管理したいとき

「とりあえず npm から始めて、必要になったら pnpm（や yarn）に乗り換える」という進め方でも問題ありません。

## 📊 パッケージマネージャーの比較

| 項目 | npm | yarn | pnpm |
|------|-----|------|------|
| **速度** | 普通 | 速い | 非常に速い |
| **ディスク使用量** | 多い | 多い | 少ない |
| **互換性** | 標準 | 高い | 高い |
| **ロックファイル** | package-lock.json | yarn.lock | pnpm-lock.yaml |

## 🎯 まとめ

- **パッケージマネージャー**は、ライブラリを管理するツール
- **npm**がNode.jsの標準
- **package.json**で依存関係を管理
- **dependencies**と**devDependencies**を区別する
- **バージョン管理**が重要
- **セキュリティ**を定期的にチェックする
