# ビルドとコンパイルとは

ビルドとコンパイルは、開発したコードを実行可能な形式に変換するプロセスです。この章では、これらの概念について初心者向けに解説します。

## 📖 ビルドとコンパイルとは何か

**コンパイル（Compile）**は、ソースコードを機械語や中間コードに変換することです。  
**ビルド（Build）**は、コンパイルを含む、実行可能な形式を作成する一連のプロセスです。

### 日常生活での例え

- **コンパイル**: 原稿を印刷物に変換する
- **ビルド**: 原稿を編集、印刷、製本する一連の作業

## 🔨 コンパイルとは

### コンパイルの種類

#### 1. ネイティブコンパイル

ソースコードを機械語に変換します。

```c
// C言語の例
// ソースコード: hello.c
#include <stdio.h>
int main() {
    printf("Hello World\n");
    return 0;
}

// コンパイル
gcc hello.c -o hello

// 実行ファイルが生成される
```

#### 2. トランスパイル

ある言語を別の言語に変換します。

```typescript
// TypeScript → JavaScript
// ソースコード: app.ts
function greet(name: string): string {
  return `Hello, ${name}!`;
}

// コンパイル（トランスパイル）
tsc app.ts

// 生成されるJavaScript: app.js
function greet(name) {
  return "Hello, " + name + "!";
}
```

## 🏗️ ビルドとは

### ビルドプロセス

ビルドは、以下のような複数のステップを含みます：

1. **コンパイル/トランスパイル**
2. **バンドル**（複数ファイルを1つにまとめる）
3. **最適化**（コードの圧縮、最適化）
4. **アセットの処理**（画像、CSSなどの処理）

### フロントエンドのビルド例

```javascript
// ソースコード（複数ファイル）
// src/components/Button.jsx
// src/components/Header.jsx
// src/App.jsx

// ビルド後（1つのファイル）
// dist/bundle.js（最適化、圧縮済み）
```

## 💻 実際のビルドツール

### 1. Webpack

```javascript
// webpack.config.js
module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: __dirname + '/dist'
  },
  module: {
    rules: [
      {
        test: /\.js$/,
        use: 'babel-loader'
      }
    ]
  }
};
```

### 2. Vite

```javascript
// vite.config.js
export default {
  build: {
    outDir: 'dist',
    sourcemap: true
  }
};
```

### 3. Next.js

```bash
# ビルド
npm run build

# 生成されるファイル
.next/
  ├── static/
  └── server/
```

## 📦 バンドルとは

### バンドルの目的

複数のファイルを1つにまとめて、読み込みを高速化します。

```javascript
// ビルド前（複数ファイル）
// src/utils/helper.js
export function helper() { ... }

// src/components/Button.jsx
import { helper } from '../utils/helper';

// src/App.jsx
import Button from './components/Button';

// ビルド後（1つのファイル）
// dist/bundle.js（すべてが1つにまとめられている）
```

## ⚡ 最適化

### 1. ミニファイ（Minify）

コードを圧縮してサイズを小さくします。

```javascript
// ビルド前
function greet(name) {
  return "Hello, " + name + "!";
}

// ビルド後（ミニファイ）
function greet(n){return"Hello, "+n+"!"}
```

### 2. ツリーシェイキング

使われていないコードを削除します。

```javascript
// ソースコード
import { func1, func2, func3 } from './utils';

// func1のみ使用
func1();

// ビルド後（func2, func3は削除される）
// バンドルにはfunc1のみが含まれる
```

### 3. コード分割

大きなファイルを小さく分割します。

```javascript
// 動的インポート
const Component = lazy(() => import('./Component'));

// ビルド後、別ファイルとして生成される
// dist/component.chunk.js
```

## 🔧 ビルドの設定例

### package.json

```json
{
  "scripts": {
    "build": "webpack --mode production",
    "dev": "webpack --mode development --watch",
    "start": "node dist/bundle.js"
  }
}
```

### 実行

```bash
# 開発用ビルド
npm run dev

# 本番用ビルド
npm run build
```

## 🎯 ビルドの種類

### 1. 開発ビルド

- 高速なビルド
- ソースマップあり
- 最適化なし

```bash
npm run dev
```

### 2. 本番ビルド

- 最適化あり
- 圧縮あり
- ソースマップなし（オプション）

```bash
npm run build
```

## ⚠️ よくある問題と対処法

### 1. ビルドエラー

```bash
# エラーログを確認
npm run build

# 依存関係を再インストール
rm -rf node_modules
npm install
```

### 2. ビルドが遅い

```javascript
// キャッシュを有効化
module.exports = {
  cache: true,
  // ...
};
```

### 3. ビルド後のファイルサイズが大きい

```javascript
// コード分割を有効化
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all'
    }
  }
};
```

## 🎯 まとめ

- **コンパイル**は、ソースコードを実行可能な形式に変換
- **ビルド**は、コンパイルを含む一連のプロセス
- **バンドル**で複数ファイルを1つにまとめる
- **最適化**でコードを圧縮・最適化
- **開発ビルド**と**本番ビルド**を区別する
- **ビルドツール**（Webpack、Viteなど）を使う
