# GitHub 各タブの機能と使い方

GitHub リポジトリ画面の上部には、複数の「タブ」（Code / Issues / Pull requests / Actions / Projects / Wiki / Security / Insights / Settings など）が並んでいます。

ここでは、それぞれのタブが **何をする場所なのか** と **基本的な使い方** を、実務でよく使う観点からまとめます。

---

## 1. Code タブ

### 1-1. 役割

- **リポジトリの中身（コード・フォルダ構成・README など）を確認する場所**
- ブランチ切り替え・タグ切り替え・ファイルの履歴確認・コミット一覧への導線もここに集約されています。

### 1-2. 画面の主な要素

- **ブランチ/タグ選択ドロップダウン**  
  - `main` など現在のブランチ名が表示され、クリックすると別ブランチ・タグに切り替えられます。
- **ファイルツリー**  
  - リポジトリ内のフォルダ・ファイル一覧。
- **ファイル内容ビュー**  
  - 選択したファイルの内容（コードや Markdown）が表示されます。
- **コミット履歴リンク（"x commits" など）**  
  - そのブランチのコミット履歴画面へのリンク。

### 1-3. よくある使い方

- 初めてリポジトリを開いたときに **README やディレクトリ構成をざっと確認** する。
- 特定ファイルをブラウザ上で開き、**履歴（History）から過去の状態を確認** する。
- ブランチ切り替えで、**リリースブランチや開発ブランチの差を軽く見る**。

---

## 2. Issues タブ

### 2-1. 役割

- **バグ・要望・タスク・質問などを「チケット」として管理する場所**  
  → 詳細な用語は `00-GitHub用語解説.md` の「Issue・プロジェクト管理」を参照。

### 2-2. 画面の主な要素

- **Issue 一覧**  
  - Open / Closed の切り替えが可能。
  - タイトル・ラベル・担当者・マイルストーンなどでフィルタできます。
- **"New issue" ボタン**  
  - 新しい Issue を作成。
- **検索バー / フィルタ**  
  - `is:open label:bug assignee:me` など、クエリで絞り込み可能。

### 2-3. よくある使い方

- バグが見つかったときに **再現手順・期待する動作・実際の動作** を書いて Issue 登録。
- 機能追加の要望を **ユーザー視点でチケット化** し、優先度ラベルを付ける。
- スプリント開始前に、対応予定の Issue に **Assignee（担当者）と Milestone を設定** する。

---

## 3. Pull requests タブ

### 3-1. 役割

- **ブランチの変更を main などの基準ブランチへ取り込む「依頼（PR）」を管理する場所**。
- コードレビューの中心となる画面です。

### 3-2. 画面の主な要素

- **PR 一覧**  
  - Open / Closed / Merged を切り替え表示。
- **"New pull request" ボタン**  
  - ベースブランチ（例: `main`）と比較ブランチ（例: `feature/login`）を指定して PR を作成。
- **個々の PR 詳細画面**  
  - Conversation: 説明・コメント・マージボタンなど。
  - Commits: PR に含まれるコミット一覧。
  - Files changed: 差分表示。レビューコメントはここにつける。

### 3-3. 基本的な使い方の流れ

1. 開発者が `feature/xx` ブランチで作業し、GitHub に push する。
2. `Pull requests` タブ → `New pull request` から PR を作成し、説明や関連 Issue を記載。
3. レビュアーが `Files changed` タブで差分を確認し、コメント・Approve / Request changes を行う。
4. コンフリクトがなければ、レビュー通過後に **Merge**（または Squash and merge / Rebase and merge）する。

---

## 4. Actions タブ

### 4-1. 役割

- **GitHub Actions（CI/CD）のワークフロー実行状況を確認する場所**。
- テスト・ビルド・デプロイの自動化結果をここで確認します。

### 4-2. 画面の主な要素

- **Workflow 一覧**  
  - `.github/workflows/*.yml` で定義されたワークフローごとの実行履歴。
- **個々のジョブのステータス**  
  - 成功（緑）、失敗（赤）、進行中（青）など。
- **ログ画面**  
  - 各ステップ（Job / Step）のログをブラウザ上で閲覧可能。

### 4-3. よくある使い方

- PR 作成後に **テストが通っているかを確認** する。
- ビルド or デプロイ失敗時に、該当ワークフローを開いて **どのステップでエラーになったか調査** する。
- ワークフローを手動トリガー可能な場合、`Run workflow` ボタンから再実行する。

---

## 5. Projects タブ

### 5-1. 役割

- **Issue や PR を、カンバンボードや表形式で管理するプロジェクト管理機能**。
- スプリントボード・ロードマップなどに使われます。

### 5-2. 画面の主な要素

- **ボード/テーブルビュー**  
  - 典型的には「To do / In progress / Done」などのカラム。
- **カード**  
  - Issue や PR がカードとして並ぶ。
- **フィルタ / カスタムフィールド**  
  - 優先度・ステータス・担当などのフィールドを追加し、絞り込み可能。

### 5-3. よくある使い方

- チーム開発で **スプリントボードを運用** する。
- Issue を `To do` → `In progress` → `Review` → `Done` の列に移動しながら進捗を可視化する。
- プロダクトの中長期ロードマップを **Project 上で一覧管理** する。

---

## 6. Wiki タブ

### 6-1. 役割

- **リポジトリに紐づいた Wiki 形式のドキュメント置き場**。
- 仕様書・設計メモ・運用手順などを整理するのに使います。

### 6-2. 画面の主な要素

- **ページ一覧 / ページツリー**  
  - Wiki 内のページ構造。
- **ページ編集画面**  
  - Markdown で編集可能。履歴も残る。

### 6-3. よくある使い方

- README に書ききれない **詳細仕様・運用ルールを Wiki に分離** して整理。
- チーム向けの **オンボーディングガイド（環境構築手順など）** をまとめる。
- インフラ構成や運用フローなど、**コード外の知識を集約** する。

---

## 7. Security タブ

### 7-1. 役割

- **リポジトリのセキュリティ関連情報をまとめて確認する場所**。
- 依存パッケージの脆弱性・Dependabot アラート・コードスキャン結果など。

### 7-2. 画面の主な要素

- **Dependabot alerts**  
  - 脆弱なライブラリバージョンが使われている場合の警告一覧。
- **Code scanning alerts**  
  - 静的解析ツール（CodeQL など）の結果。
- **Secret scanning**  
  - API キーなどの秘匿情報が誤ってコミットされていないかの検出。

### 7-3. よくある使い方

- 定期的に Security タブを確認し、**依存ライブラリの脆弱性を把握** する。
- Dependabot の PR をレビューして、**安全にライブラリアップデート** を行う。
- 機密情報が誤ってコミットされていないか、**Secret scanning の結果をチェック** する。

---

## 8. Insights タブ

### 8-1. 役割

- **リポジトリの活動状況・貢献度・トラフィックなどを可視化する分析タブ**。

### 8-2. 画面の主なサブメニュー例

- **Contributors**:  
  - コミット数や期間別の貢献度グラフ。
- **Traffic**:  
  - リポジトリの閲覧数・クローン数など。
- **Commits / Code frequency**:  
  - どの期間にコミットが多いか、コード増減の傾向。
- **Dependency graph**:  
  - 依存関係の可視化や、脆弱性の確認。

### 8-3. よくある使い方

- プロジェクトの **活動量（コミット数・貢献者数）をざっくり把握** する。
- 公開 OSS の場合に、**どれくらい見られているか（Traffic）を確認** する。
- リリースサイクルや開発の波を **Code frequency で俯瞰** する。

---

## 9. Settings タブ

### 9-1. 役割

- **リポジトリの各種設定を行うタブ**。  
  - リポジトリ名変更、ブランチ保護、コラボレーター追加、Secrets 設定など。

### 9-2. 主な設定項目の例

- **General**  
  - リポジトリ名・説明・公開/非公開設定など。
- **Branches**  
  - ブランチ保護ルール（Protected branches）の設定。
- **Collaborators and teams**  
  - リポジトリへのアクセス権限付与。
- **Secrets and variables**  
  - GitHub Actions などで利用するシークレット値（API キーなど）の登録。
- **Webhooks**  
  - GitHub でのイベント発生時に外部サービスへ通知する設定。

### 9-3. 触るときの注意点

- Settings は **権限の強いユーザーだけが触れる項目が多い** ため、チーム開発では変更前に相談するのが安全です。
- 特に **ブランチ保護ルール・削除関連設定** は、誤設定すると開発フローに大きな影響を与えるため注意が必要です。

---

## 10. まとめ：どのタブをいつ開くか

| シーン | よく使うタブ |
|-------|-------------|
| コードの中身を確認したい | Code |
| バグや要望、タスクを管理したい | Issues |
| 実装をレビューして main に取り込みたい | Pull requests |
| テスト・ビルド・デプロイ結果を確認したい | Actions |
| チームでタスクボードを回したい | Projects |
| 詳細な仕様や運用ルールを共有したい | Wiki |
| 脆弱性やセキュリティリスクを把握したい | Security |
| 活動状況やトラフィックを分析したい | Insights |
| リポジトリ設定や権限を変更したい | Settings |
