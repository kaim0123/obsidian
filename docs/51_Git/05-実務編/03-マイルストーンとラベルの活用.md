# マイルストーンとラベルの活用

## 概要

マイルストーンとラベルを効果的に活用することで、プロジェクトの進捗管理とタスクの分類が容易になります。この章では、実務で役立つマイルストーンとラベルの使い方を詳しく説明します。

## マイルストーン（Milestones）

### マイルストーンとは

マイルストーンは、プロジェクトの重要な目標やリリースを表す機能です。複数のIssueやプルリクエストを1つのマイルストーンにまとめることで、進捗を追跡できます。

### マイルストーンの作成

1. **「Issues」→「Milestones」をクリック**
2. **「New milestone」をクリック**
3. **以下の情報を入力**:
   - **Title**: マイルストーンの名前（例: `v1.0.0 Release`）
   - **Description**: 説明
   - **Due date**: 期限（オプション）

### マイルストーンの命名規則

#### バージョン管理

```
v1.0.0 Release
v1.1.0 Release
v2.0.0 Release
```

#### スプリント管理

```
Sprint 1 - Q1 2024
Sprint 2 - Q1 2024
Sprint 3 - Q2 2024
```

#### 四半期管理

```
Q1 2024
Q2 2024
Q3 2024
Q4 2024
```

#### 機能別

```
User Authentication
Payment System
Dashboard Redesign
```

### Issueとマイルストーンの関連付け

#### Issue作成時

1. **Issue作成画面で「Milestone」を選択**
2. **マイルストーンを選択**

#### Issue編集時

1. **Issueのサイドバーで「Milestone」をクリック**
2. **マイルストーンを選択または変更**

#### 一括操作

```bash
# GitHub CLIを使用して一括でマイルストーンを設定
gh issue list --label "feature" --json number --jq '.[].number' | \
  xargs -I {} gh issue edit {} --milestone "v1.0.0 Release"
```

### マイルストーンの進捗確認

マイルストーンページで以下を確認できます：

- **完了率**: 完了したIssueの割合
- **オープン/クローズ**: Issueの数
- **期限**: 期限までの残り日数

### マイルストーンの例

#### リリースマイルストーン

```
Title: v1.0.0 Release
Description: 初回リリースに向けた機能実装
Due date: 2024-03-31

関連Issue:
- #123: ユーザー認証機能
- #124: ダッシュボード実装
- #125: API統合
```

#### スプリントマイルストーン

```
Title: Sprint 1 - Q1 2024
Description: 2024年第1四半期の最初のスプリント
Due date: 2024-01-15

関連Issue:
- #100: ログイン機能
- #101: パスワードリセット
- #102: セッション管理
```

## ラベル（Labels）

### ラベルの種類

#### 種類ラベル（Type）

```
bug: バグ報告
feature: 新機能
enhancement: 機能改善
documentation: ドキュメント
question: 質問
refactor: リファクタリング
test: テスト関連
chore: 雑務
```

#### 優先度ラベル（Priority）

```
priority: critical: 緊急（赤）
priority: high: 高（オレンジ）
priority: medium: 中（黄）
priority: low: 低（緑）
```

#### ステータスラベル（Status）

```
status: todo: 未着手
status: in-progress: 進行中
status: review: レビュー中
status: testing: テスト中
status: done: 完了
status: blocked: ブロック中
status: on-hold: 保留
```

#### サイズラベル（Size）

```
size: xs: 極小（1時間未満）
size: s: 小（1-4時間）
size: m: 中（4-8時間）
size: l: 大（1-2日）
size: xl: 特大（2日以上）
```

#### 技術ラベル（Tech）

```
tech: frontend: フロントエンド
tech: backend: バックエンド
tech: database: データベース
tech: api: API
tech: ui/ux: UI/UX
```

### ラベルの作成

#### GitHub上で作成

1. **「Issues」→「Labels」をクリック**
2. **「New label」をクリック**
3. **名前、説明、色を設定**
4. **「Create label」をクリック**

#### GitHub CLIで作成

```bash
# ラベルの作成
gh label create "priority: high" \
  --color "d73a4a" \
  --description "High priority issues"

gh label create "status: in-progress" \
  --color "0e8a16" \
  --description "Work in progress"

gh label create "tech: frontend" \
  --color "0052cc" \
  --description "Frontend related"
```

#### 一括作成スクリプト

```bash
#!/bin/bash
# create-labels.sh

# 優先度ラベル
gh label create "priority: critical" --color "b60205" --description "Critical priority"
gh label create "priority: high" --color "d73a4a" --description "High priority"
gh label create "priority: medium" --color "fbca04" --description "Medium priority"
gh label create "priority: low" --color "0e8a16" --description "Low priority"

# ステータスラベル
gh label create "status: todo" --color "ededed" --description "To do"
gh label create "status: in-progress" --color "0e8a16" --description "In progress"
gh label create "status: review" --color "0052cc" --description "Under review"
gh label create "status: done" --color "5319e7" --description "Done"
```

### ラベルの適用

#### Issue作成時

1. **Issue作成画面で「Labels」をクリック**
2. **適用するラベルを選択**

#### Issue編集時

1. **Issueのサイドバーで「Labels」をクリック**
2. **ラベルを追加または削除**

#### 一括適用

```bash
# 特定のラベルが付いたIssueに別のラベルを追加
gh issue list --label "bug" --json number --jq '.[].number' | \
  xargs -I {} gh issue edit {} --add-label "priority: high"
```

### ラベルの検索

```
# ラベルで検索
label:bug
label:"priority: high"

# 複数のラベルで検索（AND）
label:bug label:"priority: high"

# ラベルの除外
-label:documentation

# ラベルのOR検索
label:bug,enhancement
```

## マイルストーンとラベルの組み合わせ

### 実践例

#### リリース計画

```
マイルストーン: v1.0.0 Release
期限: 2024-03-31

Issue分類:
- label:feature + milestone:v1.0.0 → 新機能
- label:bug + milestone:v1.0.0 → バグ修正
- label:"priority: critical" + milestone:v1.0.0 → 緊急対応
```

#### スプリント管理

```
マイルストーン: Sprint 1 - Q1 2024
期限: 2024-01-15

Issue分類:
- label:"status: todo" + milestone:Sprint1 → 未着手タスク
- label:"status: in-progress" + milestone:Sprint1 → 進行中タスク
- label:"status: done" + milestone:Sprint1 → 完了タスク
```

### 進捗の可視化

#### マイルストーンページで確認

1. **マイルストーンページを開く**
2. **ラベルでフィルタリング**
3. **進捗を確認**

#### クエリで確認

```
# マイルストーン内の優先度別Issue数
milestone:"v1.0.0 Release" label:"priority: high" is:open

# マイルストーン内のステータス別Issue数
milestone:"v1.0.0 Release" label:"status: in-progress"
```

## 自動化

### GitHub Actionsで自動ラベル付け

```yaml
# .github/workflows/auto-label.yml
name: Auto Label

on:
  issues:
    types: [opened]
  pull_request:
    types: [opened]

jobs:
  label:
    runs-on: ubuntu-latest
    steps:
      - name: Add triage label
        uses: actions/github-script@v6
        with:
          script: |
            github.rest.issues.addLabels({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              labels: ['triage']
            })
```

### マイルストーン期限の通知

```yaml
# .github/workflows/milestone-reminder.yml
name: Milestone Reminder

on:
  schedule:
    - cron: '0 9 * * *'  # 毎日9時

jobs:
  remind:
    runs-on: ubuntu-latest
    steps:
      - name: Check milestone deadlines
        uses: actions/github-script@v6
        with:
          script: |
            const milestones = await github.rest.issues.listMilestones({
              owner: context.repo.owner,
              repo: context.repo.repo,
              state: 'open'
            });
            
            const today = new Date();
            for (const milestone of milestones.data) {
              if (milestone.due_on) {
                const dueDate = new Date(milestone.due_on);
                const daysLeft = Math.ceil((dueDate - today) / (1000 * 60 * 60 * 24));
                
                if (daysLeft <= 7 && daysLeft > 0) {
                  // 通知を送信
                  console.log(`Milestone ${milestone.title} is due in ${daysLeft} days`);
                }
              }
            }
```

## ベストプラクティス

1. **一貫性**: ラベルの命名規則を統一
2. **適切な数**: ラベルが多すぎると管理が困難
3. **色の使い分け**: 視覚的に分かりやすい色を使用
4. **定期的な整理**: 使用されていないラベルを削除
5. **ドキュメント化**: ラベルの意味をドキュメント化
