# 実務的なワークフロー

## 概要

この章では、GitHub Issues、Projects、マイルストーン、ラベル、GitHub Actionsを組み合わせた実務的なワークフローを紹介します。実際のプロジェクトで使用できる具体的な例を提供します。

## 完全な開発ワークフロー

### ステップ1: タスクの作成と計画

#### Issueの作成

```markdown
## タイトル
[FEATURE] ユーザー認証機能の実装

## 説明
ユーザーがログイン・ログアウトできる機能を実装する。

## 要件
- [ ] ログインフォームの実装
- [ ] 認証APIの実装
- [ ] セッション管理
- [ ] パスワードリセット機能
- [ ] テストの作成

## 関連Issue
#100, #101

## マイルストーン
v1.0.0 Release

## ラベル
feature, priority: medium, tech: backend, tech: frontend
```

#### プロジェクトボードへの追加

1. **Issue作成後、自動的に「To do」カラムに追加**（自動化設定済み）
2. **または手動でプロジェクトに追加**

### ステップ2: 作業の開始

#### ブランチの作成

```bash
# Issue #123 に対応するブランチを作成
git checkout main
git pull origin main
git checkout -b feature/123-user-authentication
```

#### ステータスの更新

1. **Issueにラベル`status: in-progress`を追加**
2. **自動的にプロジェクトボードの「In Progress」カラムに移動**（自動化設定済み）

### ステップ3: 開発とコミット

#### 段階的なコミット

```bash
# 1. ログインフォームの実装
git add src/components/LoginForm.tsx
git commit -m "Add login form component - refs #123"

# 2. 認証APIの実装
git add src/api/auth.ts
git commit -m "Implement authentication API - refs #123"

# 3. セッション管理
git add src/utils/session.ts
git commit -m "Add session management - refs #123"

# 4. テストの追加
git add src/__tests__/auth.test.ts
git commit -m "Add authentication tests - refs #123"
```

#### 定期的なプッシュ

```bash
# 作業をリモートにプッシュ
git push -u origin feature/123-user-authentication
```

### ステップ4: プルリクエストの作成

#### プルリクエストの作成

```markdown
## タイトル
Implement user authentication - Closes #123

## 説明
ユーザー認証機能を実装しました。

### 変更内容
- ログインフォームの追加
- 認証APIの実装
- セッション管理の追加
- テストの追加

### チェックリスト
- [x] コードの実装
- [x] テストの作成
- [x] ドキュメントの更新
- [ ] コードレビュー

Closes #123
```

#### 自動的な処理

1. **プルリクエスト作成時、自動的に「Review」カラムに追加**（自動化設定済み）
2. **ラベル`needs-review`が自動的に付与**（自動化設定済み）

### ステップ5: コードレビュー

#### レビューの実施

1. **レビュアーがコードを確認**
2. **コメントや変更要求を追加**
3. **承認または変更要求**

#### 変更の対応

```bash
# レビューコメントに対応
# ... コードを修正 ...
git add .
git commit -m "Address review comments - refs #123"
git push origin feature/123-user-authentication
```

### ステップ6: マージと完了

#### マージ

1. **レビューが完了したらマージ**
2. **自動的に以下が実行**（自動化設定済み）:
   - Issue #123が自動的に閉じられる
   - プロジェクトボードの「Done」カラムに移動
   - マイルストーンの進捗が更新される

#### ブランチの削除

```bash
# ローカルブランチを削除
git checkout main
git pull origin main
git branch -d feature/123-user-authentication
```

## バグ修正のワークフロー

### 緊急バグの対応

#### Issueの作成

```markdown
## タイトル
[BUG] ログインボタンがクリックできない

## 説明
ログインページでボタンをクリックしても反応しない。

## 再現手順
1. ログインページにアクセス
2. ログインボタンをクリック
3. 何も起こらない

## 優先度
priority: critical

## ラベル
bug, priority: critical, tech: frontend
```

#### 緊急対応

```bash
# 1. ホットフィックスブランチを作成
git checkout main
git checkout -b hotfix/456-fix-login-button

# 2. 修正を実装
# ... バグを修正 ...
git add .
git commit -m "Fix login button click handler - fixes #456"

# 3. プッシュしてプルリクエストを作成
git push -u origin hotfix/456-fix-login-button

# 4. 緊急レビューとマージ
# マージ後、自動的にIssueが閉じられる
```

## スプリント管理のワークフロー

### スプリントの開始

#### マイルストーンの作成

```
Title: Sprint 1 - Q1 2024
Description: 2024年第1四半期の最初のスプリント
Due date: 2024-01-15
```

#### Issueの割り当て

1. **スプリントに関連するIssueにマイルストーンを設定**
2. **優先度に応じてラベルを付与**
3. **担当者を割り当て**

### スプリント中の管理

#### 日次スタンドアップ

1. **プロジェクトボードで進捗を確認**
2. **ブロックされているタスクを特定**
3. **必要に応じてIssueを作成**

#### 進捗の更新

1. **Issueのステータスラベルを更新**
2. **プロジェクトボードでカードを移動**
3. **コメントで進捗を記録**

### スプリントの終了

#### レビュー

1. **完了したIssueを確認**
2. **未完了のIssueを次のスプリントに移動**
3. **レトロスペクティブを実施**

#### レポートの生成

```yaml
# スプリント終了時に自動的にレポートを生成
# .github/workflows/sprint-report.yml
name: Sprint Report

on:
  schedule:
    - cron: '0 18 * * 5'  # 毎週金曜日18時

jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - name: Generate sprint report
        # ... レポート生成のロジック ...
```

## リリース管理のワークフロー

### リリース準備

#### マイルストーンの作成

```
Title: v1.0.0 Release
Description: 初回リリース
Due date: 2024-03-31
```

#### リリースブランチの作成

```bash
# リリースブランチを作成
git checkout develop
git checkout -b release/v1.0.0

# バージョン番号を更新
# ... ファイルを編集 ...
git add .
git commit -m "Bump version to 1.0.0"
```

#### リリースIssueの作成

```markdown
## タイトル
[RELEASE] v1.0.0 Release

## チェックリスト
- [ ] すべての機能が実装済み
- [ ] テストがすべてパス
- [ ] ドキュメントが更新済み
- [ ] リリースノートの作成
- [ ] デプロイの準備

## マイルストーン
v1.0.0 Release
```

### リリースの実行

#### タグの作成

```bash
# リリースブランチをマージ
git checkout main
git merge release/v1.0.0

# タグを作成
git tag -a v1.0.0 -m "Release version 1.0.0"
git push origin v1.0.0
```

#### 自動デプロイ

```yaml
# タグ作成時に自動的にデプロイ
# .github/workflows/deploy.yml
name: Deploy

on:
  push:
    tags:
      - 'v*'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to production
        # ... デプロイのロジック ...
```

## チームコラボレーション

### コードレビューのベストプラクティス

1. **小さなプルリクエスト**: 1つのプルリクエストは1つの機能に集中
2. **明確な説明**: 変更内容を詳しく説明
3. **テストの追加**: テストを必ず含める
4. **迅速な対応**: レビューコメントに迅速に対応

### コミュニケーション

1. **Issueでの議論**: 技術的な議論はIssueで実施
2. **コメントの活用**: 進捗や問題をコメントで共有
3. **通知の設定**: 重要な更新の通知を設定

## ベストプラクティス

1. **一貫性**: ワークフローを一貫して適用
2. **自動化**: 可能な限り自動化を活用
3. **ドキュメント**: ワークフローをドキュメント化
4. **改善**: 定期的にワークフローを見直し
5. **教育**: チーム全体でワークフローを共有

## まとめ

GitHub Issues、Projects、マイルストーン、ラベル、GitHub Actionsを組み合わせることで、効率的なプロジェクト管理とタスク管理が実現できます。このワークフローを参考に、チームに適したワークフローを構築してください。
