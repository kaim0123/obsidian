# ブランチの操作

## 概要

ブランチ（Branch）は、Gitの最も強力な機能の一つです。ブランチを使用することで、メインのコードベースに影響を与えずに、新しい機能の開発やバグ修正を並行して進めることができます。

## ブランチとは

ブランチは、開発履歴を分岐させる機能です。メインブランチから分岐して、独立した開発ラインを作成できます。

### ブランチの利点

1. **並行開発**: 複数の機能を同時に開発できる
2. **安全な実験**: メインコードに影響を与えずに試行錯誤できる
3. **履歴の整理**: 機能ごとに履歴を分けて管理できる
4. **コードレビュー**: プルリクエストを通じて変更をレビューできる

## ブランチの基本操作

### ブランチの一覧表示

```bash
# ローカルブランチの一覧
git branch

# リモートブランチも含めて表示
git branch -a

# リモートブランチのみ表示
git branch -r

# 詳細情報付きで表示
git branch -v

# マージ済み/未マージの情報も表示
git branch --merged
git branch --no-merged
```

### 新しいブランチの作成

```bash
# ブランチを作成（切り替えはしない）
git branch branch-name

# ブランチを作成して切り替え
git checkout -b branch-name

# または（Git 2.23以降）
git switch -c branch-name
```

### ブランチの切り替え

```bash
# ブランチに切り替え
git checkout branch-name

# または（Git 2.23以降）
git switch branch-name

# 前のブランチに戻る
git checkout -
# または
git switch -
```

### ブランチの削除

```bash
# マージ済みのブランチを削除
git branch -d branch-name

# マージしていなくても強制削除
git branch -D branch-name

# リモートブランチの削除
git push origin --delete branch-name
```

## ブランチの命名規則

一般的なブランチ名のパターン：

- `feature/機能名`: 新機能の開発
- `bugfix/バグ名`: バグ修正
- `hotfix/緊急修正名`: 緊急の修正
- `release/バージョン`: リリース準備
- `develop`: 開発用ブランチ
- `main` / `master`: メインブランチ

例：
```bash
git checkout -b feature/user-authentication
git checkout -b bugfix/login-error
git checkout -b hotfix/security-patch
```

## ブランチのマージ

### 基本的なマージ

```bash
# 1. マージ先のブランチに切り替え
git checkout main

# 2. マージするブランチをマージ
git merge feature-branch
```

### マージの種類

#### Fast-forward マージ

分岐後にマージ先に新しいコミットがない場合：

```bash
git merge feature-branch
```

履歴が一直線になります。

#### 3-way マージ

両方のブランチに新しいコミットがある場合：

```bash
git merge feature-branch
```

マージコミットが作成されます。

### マージコミットメッセージの編集

```bash
git merge --no-ff -m "マージメッセージ" feature-branch
```

### マージの取り消し

```bash
# マージを開始したが、まだコミットしていない場合
git merge --abort

# マージコミットを取り消す
git reset --hard HEAD~1
```

## コンフリクトの解決

### コンフリクトが発生した場合

マージ時にコンフリクトが発生すると、以下のような表示が出ます：

```
Auto-merging file.txt
CONFLICT (content): Merge conflict in file.txt
Automatic merge failed; fix conflicts and then commit the result.
```

### コンフリクトの確認

```bash
git status
```

コンフリクトがあるファイルが表示されます。

### コンフリクトの解決

1. **コンフリクトマーカーの確認**

コンフリクトがあるファイルを開くと、以下のようなマーカーが表示されます：

```
<<<<<<< HEAD
現在のブランチの内容
=======
マージしようとしているブランチの内容
>>>>>>> feature-branch
```

2. **手動で解決**

マーカーを削除し、正しい内容に編集します。

3. **解決したファイルをステージング**

```bash
git add resolved-file.txt
```

4. **マージを完了**

```bash
git commit
```

### コンフリクト解決ツールの使用

```bash
# マージツールを起動
git mergetool

# 特定のツールを指定
git mergetool --tool=vimdiff
```

## ブランチの比較

### 2つのブランチの差分

```bash
# ブランチ間の差分
git diff branch1 branch2

# 特定のファイルのみ
git diff branch1 branch2 -- filename.txt

# 統計情報
git diff --stat branch1 branch2
```

### ブランチにのみ存在するコミット

```bash
# branch2にあってbranch1にないコミット
git log branch1..branch2

# 両方向の差分
git log branch1...branch2
```

## ブランチのリネーム

```bash
# 現在のブランチをリネーム
git branch -m new-name

# 特定のブランチをリネーム
git branch -m old-name new-name

# リモートブランチも更新
git push origin -u new-name
git push origin --delete old-name
```

## 実践的なワークフロー

### 例1: 機能開発のワークフロー

```bash
# 1. メインブランチから機能ブランチを作成
git checkout main
git pull origin main
git checkout -b feature/new-feature

# 2. 開発とコミット
# ... コードを編集 ...
git add .
git commit -m "Implement new feature"

# 3. メインブランチに戻ってマージ
git checkout main
git merge feature/new-feature

# 4. ブランチを削除
git branch -d feature/new-feature
```

### 例2: バグ修正のワークフロー

```bash
# 1. バグ修正ブランチを作成
git checkout -b bugfix/fix-login-error

# 2. 修正とコミット
# ... バグを修正 ...
git add .
git commit -m "Fix login error"

# 3. メインブランチにマージ
git checkout main
git merge bugfix/fix-login-error
```

### 例3: 複数ブランチの管理

```bash
# 現在のブランチを確認
git branch

# すべてのブランチの状態を確認
git branch -vv

# マージ済みのブランチを削除
git branch --merged | grep -v "\*\|main\|master" | xargs -n 1 git branch -d
```

## リモートブランチとの連携

### リモートブランチの取得

```bash
# すべてのリモートブランチを取得
git fetch origin

# 特定のブランチを取得
git fetch origin branch-name
```

### リモートブランチの追跡

```bash
# リモートブランチを追跡するローカルブランチを作成
git checkout -b local-branch origin/remote-branch

# または（Git 2.23以降）
git switch -c local-branch origin/remote-branch

# 自動的に追跡ブランチを作成
git checkout --track origin/remote-branch
```

### ブランチのプッシュ

```bash
# ブランチをプッシュ
git push origin branch-name

# 上流ブランチを設定してプッシュ
git push -u origin branch-name

# すべてのブランチをプッシュ
git push --all origin
```

## ブランチの保護

### 重要なブランチを誤って削除しないように

```bash
# ブランチを保護（実際のGit機能ではなく、運用上の注意）
# mainブランチでは直接作業しない
# 常に機能ブランチで作業する
```

## トラブルシューティング

### ブランチを切り替えられない

未コミットの変更がある場合：

```bash
# 変更をコミット
git commit -m "WIP"

# または、変更を一時保存（stash）
git stash
git checkout other-branch
git stash pop
```

### 間違ったブランチにコミットした

```bash
# コミットを保持したままブランチを移動
git log  # コミットハッシュを確認
git checkout correct-branch
git cherry-pick <commit-hash>

# 元のブランチでコミットを取り消し
git checkout wrong-branch
git reset --hard HEAD~1
```
