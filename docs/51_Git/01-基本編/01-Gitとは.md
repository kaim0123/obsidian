# Gitとは

## 概要

Gitは、ソースコードの変更履歴を管理するための**分散型バージョン管理システム**（Distributed Version Control System, DVCS）です。2005年にLinus Torvaldsによって開発され、現在では世界中の開発者に広く使用されています。

## Gitの特徴

### 1. 分散型システム

- **中央集約型との違い**: 従来のCVSやSubversionとは異なり、各開発者のローカル環境に完全なリポジトリのコピーが存在します
- **オフライン作業**: インターネット接続がなくても、ローカルでコミットやブランチ操作が可能です
- **高速な操作**: ほとんどの操作がローカルで完結するため、非常に高速です

### 2. データの整合性

- **SHA-1ハッシュ**: すべてのファイルとコミットはSHA-1ハッシュで識別され、データの改ざんを検出できます
- **チェックサム**: データの完全性が保証されます

### 3. ブランチとマージ

- **軽量なブランチ**: ブランチの作成が非常に高速で、メモリ効率も良いです
- **強力なマージ機能**: 複雑なマージも効率的に処理できます

### 4. 非線形な開発

- **複数のブランチ**: 同時に複数の機能開発を並行して進められます
- **柔軟なワークフロー**: チームの開発スタイルに合わせた柔軟な運用が可能です

## Gitが解決する問題

### バージョン管理の必要性

1. **変更履歴の追跡**: いつ、誰が、何を変更したかを記録
2. **過去の状態への復元**: 以前のバージョンに簡単に戻れる
3. **並行開発**: 複数の開発者が同時に作業しても競合を管理
4. **バックアップ**: コードの安全な保管場所として機能

### 従来の方法との比較

**ファイル名による管理**（例: `document_v1.txt`, `document_v2.txt`）
- ファイルが増えすぎる
- どの変更が何を意味するか分からない
- 複数人での作業が困難

**Gitによる管理**
- 1つのファイルで全履歴を管理
- 変更内容と理由が明確
- 複数人での協調作業が容易

## Gitの基本概念

### リポジトリ（Repository）

- **ローカルリポジトリ**: 開発者のマシン上にあるリポジトリ
- **リモートリポジトリ**: GitHub、GitLabなどのサーバー上にあるリポジトリ

### コミット（Commit）

- ファイルの変更を記録する単位
- 各コミットには一意のハッシュIDが付与される
- コミットメッセージで変更内容を説明

### ブランチ（Branch）

- 独立した開発ライン
- メインブランチ（通常は`main`または`master`）と機能ブランチに分かれる

### マージ（Merge）

- 異なるブランチの変更を統合する操作

## Gitの歴史

- **2005年**: Linus TorvaldsがLinuxカーネルの開発のためにGitを開発
- **2008年**: GitHubがサービス開始
- **現在**: 世界で最も広く使用されているバージョン管理システム

## なぜGitを学ぶべきか

1. **業界標準**: ほとんどのソフトウェア開発プロジェクトで使用されている
2. **就職・転職**: 開発者として働く上で必須のスキル
3. **効率的な開発**: チーム開発を円滑に進められる
4. **オープンソース**: 無料で使用でき、学習リソースが豊富
