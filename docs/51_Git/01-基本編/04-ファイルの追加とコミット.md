# ファイルの追加とコミット

## 概要

Gitで変更を記録するには、**ステージング**と**コミット**という2段階のプロセスを経ます。この章では、ファイルの追加とコミットの詳細な方法を説明します。

## Gitの3つの領域

Gitでは、ファイルの状態を3つの領域で管理します：

1. **作業ディレクトリ（Working Directory）**: 実際にファイルを編集する場所
2. **ステージングエリア（Staging Area / Index）**: コミットに含める変更を準備する場所
3. **リポジトリ（Repository）**: コミットされた変更が永続的に保存される場所

```
作業ディレクトリ → ステージングエリア → リポジトリ
     (編集)          (git add)        (git commit)
```

## ファイルの状態

Gitでは、ファイルは以下のいずれかの状態にあります：

- **Untracked（未追跡）**: Gitが管理していない新しいファイル
- **Modified（変更済み）**: 追跡されているファイルが変更された
- **Staged（ステージ済み）**: コミットに含める準備ができた
- **Unmodified（未変更）**: 最後のコミット以降変更されていない

## git add - ファイルをステージングエリアに追加

### 基本的な使い方

```bash
# 特定のファイルを追加
git add filename.txt

# 複数のファイルを追加
git add file1.txt file2.txt file3.txt

# すべての変更を追加
git add .

# 現在のディレクトリ以下のすべてのファイルを追加
git add -A
# または
git add --all
```

### オプション

#### インタラクティブモード

変更を選択的にステージング：

```bash
git add -i
# または
git add --interactive
```

#### パッチモード

変更の一部のみをステージング：

```bash
git add -p filename.txt
# または
git add --patch filename.txt
```

対話的に変更の一部を選択できます。

#### ドライラン

実際には追加せず、何が追加されるか確認：

```bash
git add --dry-run .
```

#### 強制追加

.gitignoreで除外されているファイルも追加：

```bash
git add -f ignored-file.txt
# または
git add --force ignored-file.txt
```

### パターンマッチング

```bash
# すべての.txtファイルを追加
git add *.txt

# 特定のディレクトリ内のファイルを追加
git add src/

# すべての.jsファイルを追加
git add **/*.js
```

## git status - 状態の確認

現在の状態を確認するには：

```bash
git status
```

### 詳細な表示

```bash
# 短い形式で表示
git status -s
# または
git status --short

# ブランチ情報も表示
git status -b
```

### 出力の例

```
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        new file:   README.md
        modified:   src/index.js

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
        modified:   src/utils.js

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        new-file.txt
```

## git commit - 変更をコミット

### 基本的な使い方

```bash
# コミットメッセージを指定
git commit -m "コミットメッセージ"

# 複数行のメッセージ
git commit -m "最初の行" -m "2行目" -m "3行目"
```

### オプション

#### すべての変更を自動的にステージングしてコミット

```bash
git commit -a -m "コミットメッセージ"
# または
git commit --all -m "コミットメッセージ"
```

**注意**: 新規ファイル（Untracked）は自動的に追加されません。

#### エディタでメッセージを編集

```bash
git commit
# または
git commit --no-edit  # 前回のメッセージを再利用
```

#### 直前のコミットを修正

```bash
git commit --amend
```

コミットメッセージを変更する場合：
```bash
git commit --amend -m "新しいメッセージ"
```

ファイルを追加してコミットを修正：
```bash
git add forgotten-file.txt
git commit --amend --no-edit
```

**警告**: 既にプッシュしたコミットを修正する場合は注意が必要です。

#### 空のコミット

```bash
git commit --allow-empty -m "空のコミット"
```

#### 署名付きコミット

```bash
git commit -S -m "署名付きコミット"
```

### 良いコミットメッセージの書き方

#### 基本ルール

1. **最初の行は50文字以内**: 簡潔な要約
2. **2行目は空行**: 本文と区切る
3. **本文は72文字で折り返し**: 読みやすくする
4. **命令形で書く**: "Add feature" ではなく "Add feature"

#### 例

```
短い要約（50文字以内）

詳細な説明をここに書きます。変更の理由や
背景を説明すると、後で見返したときに
理解しやすくなります。

- 変更点1
- 変更点2
- 変更点3

関連するIssue: #123
```

#### コミットメッセージのプレフィックス

プロジェクトによっては、コミットメッセージにプレフィックスを付けることがあります：

- `feat: 新機能の追加`
- `fix: バグ修正`
- `docs: ドキュメントの変更`
- `style: コードスタイルの変更（機能に影響なし）`
- `refactor: リファクタリング`
- `test: テストの追加・変更`
- `chore: ビルドプロセスやツールの変更`

## ステージングの取り消し

### ステージングエリアからファイルを削除

```bash
# ファイルをステージングから外す（作業ディレクトリの変更は保持）
git restore --staged filename.txt
# または（古いコマンド）
git reset HEAD filename.txt
```

### すべてのステージングを取り消し

```bash
git restore --staged .
```

## 実践例

### 例1: 基本的なワークフロー

```bash
# 1. ファイルを編集
echo "Hello, World!" > hello.txt

# 2. 状態を確認
git status

# 3. ファイルをステージング
git add hello.txt

# 4. コミット
git commit -m "Add hello.txt"
```

### 例2: 複数ファイルのコミット

```bash
# 複数のファイルを編集後...

# すべての変更をステージング
git add .

# コミット
git commit -m "Update multiple files"
```

### 例3: 選択的なステージング

```bash
# ファイルAとBを編集

# ファイルAのみをステージング
git add fileA.txt

# ファイルAのみをコミット
git commit -m "Update fileA"

# 後でファイルBをコミット
git add fileB.txt
git commit -m "Update fileB"
```

### 例4: パッチモードでの部分的な追加

```bash
# ファイルに複数の変更がある場合
git add -p src/index.js

# 対話的に変更を選択
# y: この変更を追加
# n: この変更をスキップ
# s: より小さな単位に分割
# e: 手動で編集
```

## git diff - 変更内容の確認

### 作業ディレクトリとステージングエリアの差分

```bash
git diff
```

### ステージングエリアと最後のコミットの差分

```bash
git diff --staged
# または
git diff --cached
```

### 特定のファイルの差分

```bash
git diff filename.txt
```

### 2つのコミット間の差分

```bash
git diff commit1 commit2
```

## コミット履歴の確認

### 基本的なログ表示

```bash
git log
```

### 1行で表示

```bash
git log --oneline
```

### グラフ表示

```bash
git log --graph --oneline --all
```

### 統計情報付き

```bash
git log --stat
```

### 変更内容も表示

```bash
git log -p
```

## トラブルシューティング

### 誤って追加したファイルを削除

```bash
# ステージングから削除（ファイルは残る）
git restore --staged filename.txt

# ファイルも削除
rm filename.txt
git add filename.txt
git commit -m "Remove filename.txt"
```

### コミットメッセージを間違えた

```bash
git commit --amend -m "正しいメッセージ"
```

### 直前のコミットにファイルを追加

```bash
git add forgotten-file.txt
git commit --amend --no-edit
```
