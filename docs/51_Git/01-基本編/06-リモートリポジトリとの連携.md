# リモートリポジトリとの連携

## 概要

リモートリポジトリは、GitHub、GitLab、Bitbucketなどのサーバー上にあるリポジトリです。リモートリポジトリを使用することで、コードを共有し、チームで協力して開発できます。

## リモートリポジトリとは

リモートリポジトリは、インターネット上や社内ネットワーク上にあるGitリポジトリです。主な用途：

1. **コードの共有**: チームメンバーとコードを共有
2. **バックアップ**: コードの安全な保管場所
3. **コラボレーション**: プルリクエストやマージリクエストを通じた協力
4. **CI/CD**: 自動テストやデプロイのトリガー

## リモートリポジトリの設定

### リモートリポジトリの追加

```bash
# リモートリポジトリを追加
git remote add origin https://github.com/username/repository.git

# 名前を指定して追加
git remote add upstream https://github.com/original/repository.git
```

### リモートリポジトリの一覧表示

```bash
# リモートリポジトリの一覧
git remote

# 詳細情報付き
git remote -v
```

出力例：
```
origin  https://github.com/username/repository.git (fetch)
origin  https://github.com/username/repository.git (push)
```

### リモートリポジトリの情報確認

```bash
# 特定のリモートの詳細
git remote show origin

# URLの確認
git remote get-url origin
```

### リモートリポジトリのURL変更

```bash
# URLを変更
git remote set-url origin https://github.com/username/new-repository.git

# URLを確認
git remote get-url origin
```

### リモートリポジトリの削除

```bash
git remote remove origin
# または
git remote rm origin
```

## git clone - リポジトリのクローン

### 基本的なクローン

```bash
# HTTPSを使用
git clone https://github.com/username/repository.git

# SSHを使用
git clone git@github.com:username/repository.git

# 特定のディレクトリ名でクローン
git clone https://github.com/username/repository.git my-project
```

### オプション

#### 浅いクローン（Shallow Clone）

履歴の一部のみを取得：

```bash
# 最新の1コミットのみ
git clone --depth 1 https://github.com/username/repository.git

# 最新の10コミット
git clone --depth 10 https://github.com/username/repository.git
```

#### 特定のブランチのみクローン

```bash
git clone -b branch-name https://github.com/username/repository.git
```

#### サブモジュールも含めてクローン

```bash
git clone --recursive https://github.com/username/repository.git
```

## git fetch - リモートの変更を取得

### 基本的な使い方

```bash
# すべてのリモートの変更を取得
git fetch

# 特定のリモートから取得
git fetch origin

# 特定のブランチを取得
git fetch origin branch-name

# すべてのブランチを取得
git fetch --all
```

### fetchの動作

- **ローカルには影響しない**: 作業ディレクトリは変更されません
- **リモート追跡ブランチを更新**: `origin/main`などのブランチが更新されます
- **安全な操作**: 現在の作業に影響を与えません

### 取得した変更の確認

```bash
# リモートブランチの一覧
git branch -r

# リモートとローカルの差分
git log HEAD..origin/main

# 取得した変更を確認
git log origin/main
```

## git pull - 取得とマージを同時に実行

### 基本的な使い方

```bash
# リモートの変更を取得してマージ
git pull origin main

# 上流ブランチから取得
git pull
```

### pullの動作

`git pull`は以下の2つの操作を同時に実行します：

```bash
git fetch origin
git merge origin/main
```

### リベースでプル

```bash
# マージではなくリベース
git pull --rebase origin main
```

### プル時のコンフリクト

コンフリクトが発生した場合：

```bash
# 1. コンフリクトを解決
# 2. 解決したファイルをステージング
git add resolved-file.txt

# 3. マージを完了
git commit
```

## git push - ローカルの変更をプッシュ

### 基本的な使い方

```bash
# ブランチをプッシュ
git push origin branch-name

# 上流ブランチを設定してプッシュ
git push -u origin main

# すべてのブランチをプッシュ
git push --all origin

# タグもプッシュ
git push --tags origin
```

### オプション

#### 強制プッシュ（注意が必要）

```bash
# リモートの履歴を上書き（危険）
git push --force origin branch-name

# より安全な強制プッシュ
git push --force-with-lease origin branch-name
```

**警告**: 強制プッシュは、他の開発者の作業に影響を与える可能性があります。共有ブランチでは避けるべきです。

#### 削除したブランチをプッシュ

```bash
# リモートブランチを削除
git push origin --delete branch-name
```

### プッシュの確認

```bash
# プッシュ前に何がプッシュされるか確認
git push --dry-run origin main
```

## 上流ブランチの設定

### 上流ブランチとは

ローカルブランチとリモートブランチを関連付けることで、`git pull`や`git push`を簡潔に実行できます。

### 上流ブランチの設定

```bash
# プッシュ時に設定
git push -u origin branch-name

# 既存のブランチに設定
git branch --set-upstream-to=origin/branch-name branch-name

# または
git branch -u origin/branch-name
```

### 上流ブランチの確認

```bash
git branch -vv
```

出力例：
```
* main    abc1234 [origin/main] Latest commit
  feature def5678 [origin/feature: ahead 2] Feature commit
```

## 複数のリモートリポジトリ

### フォークのワークフロー

```bash
# オリジナルのリポジトリをupstreamとして追加
git remote add upstream https://github.com/original/repository.git

# 自分のフォークをoriginとして使用
git remote -v
```

出力例：
```
origin    https://github.com/your-username/repository.git (fetch)
origin    https://github.com/your-username/repository.git (push)
upstream  https://github.com/original/repository.git (fetch)
upstream  https://github.com/original/repository.git (push)
```

### 複数のリモートからの取得

```bash
# すべてのリモートから取得
git fetch --all

# 特定のリモートから取得
git fetch upstream
```

### 複数のリモートへのプッシュ

```bash
# 両方のリモートにプッシュ
git push origin main
git push upstream main

# または、複数のリモートを設定
git remote set-url --add --push origin https://github.com/user1/repo.git
git remote set-url --add --push origin https://github.com/user2/repo.git
```

## 認証

### HTTPS認証

```bash
# 初回プッシュ時に認証情報を入力
git push origin main

# 認証情報を保存（Git Credential Manager）
git config --global credential.helper store

# macOSの場合
git config --global credential.helper osxkeychain

# Windowsの場合
git config --global credential.helper wincred
```

### SSH認証

1. **SSH鍵の生成**

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```

2. **公開鍵をGitHubなどに登録**

```bash
# 公開鍵を表示
cat ~/.ssh/id_ed25519.pub
```

3. **SSH接続のテスト**

```bash
ssh -T git@github.com
```

## 実践的なワークフロー

### 例1: 新しいリポジトリのセットアップ

```bash
# 1. ローカルでリポジトリを初期化
git init
git add .
git commit -m "Initial commit"

# 2. GitHubでリポジトリを作成後、リモートを追加
git remote add origin https://github.com/username/repository.git

# 3. プッシュ
git push -u origin main
```

### 例2: 既存のリモートリポジトリのクローン

```bash
# 1. クローン
git clone https://github.com/username/repository.git
cd repository

# 2. ブランチを作成
git checkout -b feature/new-feature

# 3. 開発とコミット
# ... コードを編集 ...
git add .
git commit -m "Add new feature"

# 4. プッシュ
git push -u origin feature/new-feature
```

### 例3: フォークの更新

```bash
# 1. オリジナルのリポジトリをupstreamとして追加
git remote add upstream https://github.com/original/repository.git

# 2. upstreamから最新の変更を取得
git fetch upstream

# 3. メインブランチにマージ
git checkout main
git merge upstream/main

# 4. 自分のフォークにプッシュ
git push origin main
```

## トラブルシューティング

### エラー: "remote origin already exists"

```bash
# 既存のリモートを削除
git remote remove origin

# 再度追加
git remote add origin https://github.com/username/repository.git
```

### エラー: "failed to push some refs"

リモートに新しいコミットがある場合：

```bash
# 1. リモートの変更を取得
git fetch origin

# 2. マージまたはリベース
git merge origin/main
# または
git rebase origin/main

# 3. 再度プッシュ
git push origin main
```

### エラー: "permission denied"

認証情報を確認：

```bash
# SSH接続をテスト
ssh -T git@github.com

# 認証情報を再設定
git config --global credential.helper store
```
