# スタッシュとチェリーピック

## 概要

スタッシュ（Stash）とチェリーピック（Cherry-pick）は、Gitの便利な機能です。スタッシュは作業中の変更を一時的に保存し、チェリーピックは特定のコミットを別のブランチに適用します。

## スタッシュ（Stash）

### スタッシュとは

スタッシュは、作業ディレクトリの変更を一時的に保存する機能です。ブランチを切り替える前に、未コミットの変更を保存しておけます。

### 基本的な使い方

#### 変更を一時保存

```bash
# すべての変更をスタッシュ
git stash

# メッセージを付けてスタッシュ
git stash save "作業中の変更を保存"
```

#### スタッシュの一覧表示

```bash
# スタッシュの一覧
git stash list
```

出力例：
```
stash@{0}: WIP on main: abc1234 Latest commit
stash@{1}: On feature: def5678 Feature commit
```

#### スタッシュの適用

```bash
# 最新のスタッシュを適用（スタッシュは保持）
git stash apply

# 特定のスタッシュを適用
git stash apply stash@{1}

# 最新のスタッシュを適用して削除
git stash pop

# 特定のスタッシュを適用して削除
git stash pop stash@{1}
```

#### スタッシュの削除

```bash
# 最新のスタッシュを削除
git stash drop

# 特定のスタッシュを削除
git stash drop stash@{1}

# すべてのスタッシュを削除
git stash clear
```

### オプション

#### 未追跡ファイルも含める

```bash
# 未追跡ファイルもスタッシュに含める
git stash -u
# または
git stash --include-untracked
```

#### すべての変更を含める

```bash
# すべての変更（追跡済み・未追跡）を含める
git stash -a
# または
git stash --all
```

#### スタッシュの内容を確認

```bash
# 最新のスタッシュの内容を表示
git stash show

# 詳細な差分を表示
git stash show -p
# または
git stash show --patch

# 特定のスタッシュの内容を表示
git stash show -p stash@{1}
```

### スタッシュのブランチ作成

スタッシュから新しいブランチを作成：

```bash
# スタッシュからブランチを作成
git stash branch new-branch-name

# 特定のスタッシュからブランチを作成
git stash branch new-branch-name stash@{1}
```

### 実践例

#### 例1: ブランチを切り替える前の保存

```bash
# 作業中の変更を保存
git stash

# 別のブランチに切り替え
git checkout other-branch
# ... 作業 ...

# 元のブランチに戻る
git checkout original-branch

# 保存した変更を復元
git stash pop
```

#### 例2: 複数のスタッシュの管理

```bash
# 最初の作業を保存
git stash save "機能Aの作業"

# 別の作業を保存
git stash save "機能Bの作業"

# スタッシュの一覧を確認
git stash list

# 特定のスタッシュを適用
git stash apply stash@{1}
```

#### 例3: スタッシュからブランチを作成

```bash
# 作業中の変更を保存
git stash

# メインブランチを更新
git checkout main
git pull origin main

# スタッシュから新しいブランチを作成
git stash branch feature/new-feature
```

## チェリーピック（Cherry-pick）

### チェリーピックとは

チェリーピックは、特定のコミットを現在のブランチに適用する機能です。他のブランチの特定のコミットだけを取り込めます。

### 基本的な使い方

#### 単一のコミットを適用

```bash
# 特定のコミットを現在のブランチに適用
git cherry-pick <commit-hash>

# コミットメッセージを保持
git cherry-pick <commit-hash>
```

#### 複数のコミットを適用

```bash
# 複数のコミットを適用
git cherry-pick <commit-hash1> <commit-hash2> <commit-hash3>

# 範囲で指定
git cherry-pick <start-commit>..<end-commit>

# 範囲（開始コミットは含まない）
git cherry-pick <start-commit>^..<end-commit>
```

### オプション

#### コミットメッセージを編集

```bash
# コミットメッセージを編集
git cherry-pick -e <commit-hash>
# または
git cherry-pick --edit <commit-hash>
```

#### コミットを作成せずに適用

```bash
# 変更のみを適用（コミットは作成しない）
git cherry-pick -n <commit-hash>
# または
git cherry-pick --no-commit <commit-hash>
```

#### コミットメッセージを保持

```bash
# 元のコミットメッセージを保持（デフォルト）
git cherry-pick <commit-hash>
```

#### 署名を追加

```bash
# コミットに署名を追加
git cherry-pick -S <commit-hash>
# または
git cherry-pick --signoff <commit-hash>
```

### チェリーピックの中断と続行

#### コンフリクトが発生した場合

```bash
# 1. コンフリクトを解決
# ファイルを編集してコンフリクトを解決

# 2. 解決したファイルをステージング
git add resolved-file.txt

# 3. チェリーピックを続行
git cherry-pick --continue

# チェリーピックを中止
git cherry-pick --abort

# 現在のコミットをスキップ
git cherry-pick --skip
```

### 実践例

#### 例1: バグ修正を別のブランチに適用

```bash
# メインブランチでバグ修正をコミット
git checkout main
# ... バグを修正 ...
git commit -m "Fix critical bug"

# リリースブランチにバグ修正を適用
git checkout release/v1.0
git cherry-pick <bug-fix-commit-hash>
```

#### 例2: 複数のコミットを選択的に適用

```bash
# 機能ブランチから特定のコミットのみを適用
git checkout main
git cherry-pick <commit-hash1> <commit-hash2>
```

#### 例3: コミットを編集して適用

```bash
# コミットを適用して編集
git cherry-pick -n <commit-hash>

# 変更を編集
# ... 変更 ...

# 新しいコミットとして作成
git commit -m "Updated commit message"
```

## スタッシュとチェリーピックの組み合わせ

### 例: 別のブランチの変更を部分的に取り込む

```bash
# 作業中の変更を保存
git stash

# 別のブランチに切り替え
git checkout other-branch

# 特定のコミットをチェリーピック
git cherry-pick <commit-hash>

# 元のブランチに戻る
git checkout original-branch

# 保存した変更を復元
git stash pop
```

## トラブルシューティング

### スタッシュのコンフリクト

スタッシュを適用する際にコンフリクトが発生した場合：

```bash
# コンフリクトを解決
# ファイルを編集してコンフリクトを解決

# 解決したファイルをステージング
git add resolved-file.txt

# スタッシュを削除（必要に応じて）
git stash drop
```

### チェリーピックのコンフリクト

```bash
# コンフリクトを解決
# ファイルを編集してコンフリクトを解決

# 解決したファイルをステージング
git add resolved-file.txt

# チェリーピックを続行
git cherry-pick --continue
```

### スタッシュが見つからない

```bash
# すべてのスタッシュを確認
git stash list

# リフログで確認
git reflog

# スタッシュの内容を確認
git fsck --unreachable | grep commit
```

## ベストプラクティス

### スタッシュ

1. **定期的にクリーンアップ**: 不要なスタッシュは削除
2. **メッセージを付ける**: スタッシュの内容が分かるメッセージを付ける
3. **長期間保存しない**: スタッシュは一時的なもの。早めにコミットやブランチに変換

### チェリーピック

1. **コミットハッシュを確認**: 正しいコミットを選択
2. **コンフリクトに注意**: コンフリクトが発生する可能性を考慮
3. **テスト**: チェリーピック後は必ずテストを実行

## 高度な使い方

### スタッシュの差分表示

```bash
# スタッシュと現在の状態の差分
git diff stash@{0}

# スタッシュと特定のコミットの差分
git diff stash@{0} HEAD
```

### チェリーピックの範囲指定

```bash
# AからBまでのコミット（Aは含まない）
git cherry-pick A..B

# AからBまでのコミット（Aも含む）
git cherry-pick A^..B
```

### チェリーピックの履歴

```bash
# チェリーピックしたコミットを確認
git log --oneline --grep="cherry picked"
```
