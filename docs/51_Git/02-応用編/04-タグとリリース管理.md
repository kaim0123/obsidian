# タグとリリース管理

## 概要

タグ（Tag）は、特定のコミットに名前を付ける機能です。リリースバージョンや重要なマイルストーンをマークするために使用されます。

## タグとは

タグは、特定のコミットを参照する永続的なラベルです。ブランチとは異なり、通常は移動しません。

### タグの種類

1. **軽量タグ（Lightweight Tag）**: 単純な参照
2. **注釈付きタグ（Annotated Tag）**: 作成者情報やメッセージを含む

## タグの作成

### 軽量タグ

```bash
# 現在のコミットにタグを付ける
git tag v1.0.0

# 特定のコミットにタグを付ける
git tag v1.0.0 <commit-hash>
```

### 注釈付きタグ（推奨）

```bash
# メッセージを付けてタグを作成
git tag -a v1.0.0 -m "Release version 1.0.0"

# 特定のコミットに注釈付きタグを付ける
git tag -a v1.0.0 -m "Release version 1.0.0" <commit-hash>
```

### 署名付きタグ

```bash
# GPG署名付きタグを作成
git tag -s v1.0.0 -m "Signed release version 1.0.0"
```

## タグの表示

### タグの一覧

```bash
# すべてのタグを表示
git tag

# パターンで検索
git tag -l "v1.*"

# 詳細情報付きで表示
git tag -n
```

### タグの詳細

```bash
# タグの詳細情報を表示
git show v1.0.0

# タグが指すコミットを表示
git log v1.0.0
```

## タグの削除

### ローカルタグの削除

```bash
# タグを削除
git tag -d v1.0.0
# または
git tag --delete v1.0.0
```

### リモートタグの削除

```bash
# リモートのタグを削除
git push origin --delete v1.0.0
# または
git push origin :refs/tags/v1.0.0
```

## タグのプッシュ

### 単一のタグをプッシュ

```bash
# タグをプッシュ
git push origin v1.0.0

# 注釈付きタグのみをプッシュ
git push origin v1.0.0 --annotate
```

### すべてのタグをプッシュ

```bash
# すべてのタグをプッシュ
git push origin --tags

# 注釈付きタグのみをプッシュ
git push origin --follow-tags
```

### タグの取得

```bash
# リモートのタグを取得
git fetch origin --tags

# 特定のタグを取得
git fetch origin tag v1.0.0
```

## セマンティックバージョニング

### バージョン番号の形式

セマンティックバージョニング（Semantic Versioning）は、`MAJOR.MINOR.PATCH`の形式です：

- **MAJOR**: 互換性のない変更
- **MINOR**: 後方互換性のある新機能
- **PATCH**: 後方互換性のあるバグ修正

例: `v1.2.3`

### プレリリースバージョン

```bash
# アルファ版
git tag -a v1.0.0-alpha.1 -m "Alpha release 1"

# ベータ版
git tag -a v1.0.0-beta.1 -m "Beta release 1"

# リリース候補
git tag -a v1.0.0-rc.1 -m "Release candidate 1"
```

## リリース管理のワークフロー

### 基本的なリリースプロセス

```bash
# 1. リリース用のブランチを作成
git checkout -b release/v1.0.0

# 2. バージョン番号を更新
# ... ファイルを編集 ...

# 3. コミット
git add .
git commit -m "Bump version to 1.0.0"

# 4. タグを作成
git tag -a v1.0.0 -m "Release version 1.0.0"

# 5. メインブランチにマージ
git checkout main
git merge release/v1.0.0

# 6. タグとブランチをプッシュ
git push origin main
git push origin v1.0.0
git push origin --delete release/v1.0.0
```

### GitHub Releasesとの連携

GitHubでは、タグを作成するとリリースノートを作成できます：

1. GitHubでタグを作成
2. "Releases"セクションからリリースを作成
3. リリースノートを記入
4. バイナリファイルを添付（オプション）

## タグからのブランチ作成

```bash
# タグからブランチを作成
git checkout -b hotfix/v1.0.1 v1.0.0
```

## タグの比較

### 2つのタグ間の差分

```bash
# タグ間の差分
git diff v1.0.0 v1.1.0

# 統計情報
git diff --stat v1.0.0 v1.1.0

# コミットの一覧
git log v1.0.0..v1.1.0
```

### タグから現在までの変更

```bash
# タグ以降の変更
git log v1.0.0..HEAD

# 変更されたファイル
git diff --name-only v1.0.0..HEAD
```

## 実践例

### 例1: 初回リリース

```bash
# メインブランチで作業完了
git checkout main
git pull origin main

# タグを作成
git tag -a v1.0.0 -m "Initial release"

# タグをプッシュ
git push origin v1.0.0
```

### 例2: パッチリリース

```bash
# バグ修正をコミット
git checkout main
# ... バグを修正 ...
git commit -m "Fix critical bug"

# パッチバージョンのタグを作成
git tag -a v1.0.1 -m "Patch release: Fix critical bug"

# プッシュ
git push origin main
git push origin v1.0.1
```

### 例3: マイナーバージョンアップ

```bash
# 新機能を追加
git checkout main
# ... 新機能を実装 ...
git commit -m "Add new feature"

# マイナーバージョンのタグを作成
git tag -a v1.1.0 -m "Minor release: Add new feature"

# プッシュ
git push origin main
git push origin v1.1.0
```

### 例4: メジャーバージョンアップ

```bash
# 破壊的変更を実装
git checkout main
# ... 破壊的変更を実装 ...
git commit -m "Breaking changes"

# メジャーバージョンのタグを作成
git tag -a v2.0.0 -m "Major release: Breaking changes"

# プッシュ
git push origin main
git push origin v2.0.0
```

## タグの検証

### 署名付きタグの検証

```bash
# タグの署名を検証
git tag -v v1.0.0
```

### タグの整合性確認

```bash
# タグが指すコミットを確認
git show-ref --tags

# タグの詳細を確認
git show v1.0.0
```

## 自動化

### バージョン番号の自動更新

スクリプト例：

```bash
#!/bin/bash
# 最新のタグを取得
LAST_TAG=$(git describe --tags --abbrev=0)

# バージョン番号をインクリメント
# ... ロジック ...

# 新しいタグを作成
git tag -a "v${NEW_VERSION}" -m "Release version ${NEW_VERSION}"
git push origin "v${NEW_VERSION}"
```

### Gitフックでの自動化

`.git/hooks/post-commit`で自動的にタグを作成することも可能ですが、通常は手動で作成することを推奨します。

## ベストプラクティス

1. **注釈付きタグを使用**: メッセージと作成者情報を含む
2. **セマンティックバージョニング**: 一貫したバージョン番号体系を使用
3. **リリースノート**: タグと一緒にリリースノートを作成
4. **署名**: 重要なリリースには署名を付ける
5. **タグの保持**: リリース後はタグを削除しない

## トラブルシューティング

### タグが見つからない

```bash
# リモートのタグを取得
git fetch origin --tags

# すべてのタグを確認
git tag -l
```

### 誤って作成したタグの削除

```bash
# ローカルで削除
git tag -d v1.0.0

# リモートで削除
git push origin --delete v1.0.0
```

### タグの上書き

```bash
# 既存のタグを削除
git tag -d v1.0.0
git push origin --delete v1.0.0

# 新しいタグを作成
git tag -a v1.0.0 -m "Updated release"
git push origin v1.0.0
```
