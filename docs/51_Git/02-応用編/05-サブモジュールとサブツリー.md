# サブモジュールとサブツリー

## 概要

サブモジュールとサブツリーは、1つのGitリポジトリ内に別のGitリポジトリを含める機能です。外部ライブラリや共通コンポーネントを管理する際に使用されます。

## サブモジュール（Submodule）

### サブモジュールとは

サブモジュールは、別のGitリポジトリを親リポジトリ内のサブディレクトリとして含める機能です。サブモジュールは独立したリポジトリとして管理されます。

### サブモジュールの追加

```bash
# サブモジュールを追加
git submodule add https://github.com/user/repo.git path/to/submodule

# 例
git submodule add https://github.com/jquery/jquery.git lib/jquery
```

これにより：
- `.gitmodules`ファイルが作成される
- サブモジュールのディレクトリが追加される
- サブモジュールが特定のコミットに固定される

### サブモジュールを含むリポジトリのクローン

```bash
# サブモジュールも含めてクローン
git clone --recursive https://github.com/user/parent-repo.git

# または、クローン後に初期化
git clone https://github.com/user/parent-repo.git
cd parent-repo
git submodule init
git submodule update
```

### サブモジュールの更新

```bash
# すべてのサブモジュールを更新
git submodule update --remote

# 特定のサブモジュールを更新
git submodule update --remote path/to/submodule

# 再帰的に更新
git submodule update --remote --recursive
```

### サブモジュールの初期化

```bash
# すべてのサブモジュールを初期化
git submodule init

# 特定のサブモジュールを初期化
git submodule init path/to/submodule
```

### サブモジュールの削除

```bash
# 1. .gitmodulesからエントリを削除
git rm --cached path/to/submodule

# 2. .gitmodulesファイルを編集（必要に応じて）

# 3. .git/modulesから削除
rm -rf .git/modules/path/to/submodule

# 4. サブモジュールのディレクトリを削除
rm -rf path/to/submodule

# 5. 変更をコミット
git commit -m "Remove submodule"
```

### サブモジュール内での作業

```bash
# サブモジュールディレクトリに移動
cd path/to/submodule

# サブモジュールで作業
# ... 変更 ...

# サブモジュールでコミット
git add .
git commit -m "Update submodule"

# 親リポジトリに戻る
cd ../..

# 親リポジトリでサブモジュールの更新をコミット
git add path/to/submodule
git commit -m "Update submodule to latest"
```

### サブモジュールの状態確認

```bash
# サブモジュールの状態を確認
git submodule status

# 詳細な状態
git submodule status --recursive
```

## サブツリー（Subtree）

### サブツリーとは

サブツリーは、別のリポジトリの履歴を現在のリポジトリにマージする機能です。サブモジュールとは異なり、すべての履歴が親リポジトリに含まれます。

### サブツリーの追加

```bash
# サブツリーを追加
git subtree add --prefix=path/to/subtree https://github.com/user/repo.git main --squash

# 例
git subtree add --prefix=lib/library https://github.com/user/library.git main --squash
```

### サブツリーの更新

```bash
# サブツリーを更新
git subtree pull --prefix=path/to/subtree https://github.com/user/repo.git main --squash

# 例
git subtree pull --prefix=lib/library https://github.com/user/library.git main --squash
```

### サブツリーのプッシュ

```bash
# サブツリーの変更を元のリポジトリにプッシュ
git subtree push --prefix=path/to/subtree https://github.com/user/repo.git main

# 例
git subtree push --prefix=lib/library https://github.com/user/library.git main
```

### リモートの設定

サブツリーのリモートを設定すると、コマンドが簡潔になります：

```bash
# リモートを追加
git remote add library https://github.com/user/library.git

# リモートを使用してプル
git subtree pull --prefix=lib/library library main --squash

# リモートを使用してプッシュ
git subtree push --prefix=lib/library library main
```

## サブモジュール vs サブツリー

### サブモジュールの利点

- **独立性**: サブモジュールは独立したリポジトリ
- **サイズ**: 親リポジトリのサイズが小さい
- **更新の明確性**: サブモジュールの更新が明確

### サブモジュールの欠点

- **複雑さ**: クローンや更新が複雑
- **依存関係**: サブモジュールの管理が必要
- **CI/CD**: 継続的インテグレーションが複雑

### サブツリーの利点

- **シンプル**: 通常のGit操作で管理可能
- **統合**: すべての履歴が1つのリポジトリに
- **CI/CD**: 継続的インテグレーションが簡単

### サブツリーの欠点

- **サイズ**: リポジトリのサイズが大きくなる
- **履歴**: サブツリーの履歴が親リポジトリに含まれる
- **更新**: 更新がやや複雑

## 実践例

### 例1: サブモジュールの使用

```bash
# 1. サブモジュールを追加
git submodule add https://github.com/user/shared-lib.git lib/shared

# 2. コミット
git add .gitmodules lib/shared
git commit -m "Add shared library as submodule"

# 3. サブモジュールを更新
cd lib/shared
git pull origin main
cd ../..
git add lib/shared
git commit -m "Update shared library"
```

### 例2: サブツリーの使用

```bash
# 1. サブツリーを追加
git subtree add --prefix=lib/shared https://github.com/user/shared-lib.git main --squash

# 2. サブツリーを更新
git subtree pull --prefix=lib/shared https://github.com/user/shared-lib.git main --squash

# 3. 変更をプッシュ
git subtree push --prefix=lib/shared https://github.com/user/shared-lib.git main
```

### 例3: サブモジュールからサブツリーへの移行

```bash
# 1. サブモジュールを削除
git submodule deinit path/to/submodule
git rm path/to/submodule
rm -rf .git/modules/path/to/submodule

# 2. サブツリーを追加
git subtree add --prefix=path/to/subtree https://github.com/user/repo.git main --squash
```

## トラブルシューティング

### サブモジュールが空のディレクトリ

```bash
# サブモジュールを初期化して更新
git submodule init
git submodule update
```

### サブモジュールの更新が反映されない

```bash
# サブモジュールを更新
git submodule update --remote

# 親リポジトリでコミット
git add path/to/submodule
git commit -m "Update submodule"
```

### サブツリーのコンフリクト

```bash
# コンフリクトを解決
# ... コンフリクトを解決 ...

# コミット
git add .
git commit -m "Resolve subtree conflicts"
```

## ベストプラクティス

### サブモジュール

1. **明示的なバージョン**: サブモジュールを特定のコミットに固定
2. **ドキュメント**: サブモジュールの使用方法をドキュメント化
3. **自動化**: スクリプトでサブモジュールの更新を自動化

### サブツリー

1. **--squashオプション**: 履歴を圧縮して使用
2. **リモートの設定**: リモートを設定してコマンドを簡潔に
3. **定期的な更新**: 定期的にサブツリーを更新
