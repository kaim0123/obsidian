# 変更の取り消しと修正

## 概要

Gitでは、作業中の変更やコミットを取り消したり修正したりする方法が複数あります。状況に応じて適切な方法を選択することが重要です。

## 作業ディレクトリの変更を取り消す

### git restore - ファイルを元に戻す（推奨）

```bash
# 特定のファイルを最後のコミットの状態に戻す
git restore filename.txt

# 複数のファイルを戻す
git restore file1.txt file2.txt

# すべての変更を取り消す
git restore .
```

### git checkout - ファイルを元に戻す（古い方法）

```bash
# 特定のファイルを最後のコミットの状態に戻す
git checkout -- filename.txt

# すべての変更を取り消す
git checkout -- .
```

**注意**: `git checkout`はブランチの切り替えにも使用されるため、`git restore`の使用が推奨されます。

### git reset --hard - すべての変更を破棄（注意）

```bash
# すべての変更とステージングを取り消す
git reset --hard HEAD
```

**警告**: このコマンドは作業ディレクトリのすべての変更を破棄します。使用前に確認してください。

## ステージングエリアの変更を取り消す

### git restore --staged - ステージングを取り消す（推奨）

```bash
# 特定のファイルをステージングから外す
git restore --staged filename.txt

# すべてのステージングを取り消す
git restore --staged .
```

### git reset HEAD - ステージングを取り消す（古い方法）

```bash
# 特定のファイルをステージングから外す
git reset HEAD filename.txt

# すべてのステージングを取り消す
git reset HEAD
```

## コミットの取り消し

### git reset - コミットを取り消す

#### --soft: コミットのみ取り消し

```bash
# 直前のコミットを取り消し、変更はステージングエリアに残る
git reset --soft HEAD~1
```

**使用例**:
- コミットメッセージを変更したい
- ファイルを追加してからコミットしたい

#### --mixed: コミットとステージングを取り消し（デフォルト）

```bash
# 直前のコミットを取り消し、変更は作業ディレクトリに残る
git reset HEAD~1
# または
git reset --mixed HEAD~1
```

**使用例**:
- コミットをやり直したい
- 一部のファイルだけをコミットしたい

#### --hard: すべてを取り消し（注意）

```bash
# 直前のコミットとすべての変更を取り消す
git reset --hard HEAD~1
```

**警告**: このコマンドは変更を完全に削除します。使用前に確認してください。

### 複数のコミットを取り消す

```bash
# 最後の3つのコミットを取り消し
git reset --soft HEAD~3

# 特定のコミットまで戻る
git reset --soft <commit-hash>
```

### git revert - コミットを打ち消す（安全）

既にプッシュしたコミットを取り消す場合：

```bash
# 特定のコミットを打ち消す新しいコミットを作成
git revert <commit-hash>

# 直前のコミットを打ち消す
git revert HEAD

# 複数のコミットを打ち消す
git revert HEAD~3..HEAD
```

**特徴**:
- 新しいコミットが作成される
- 履歴が保持される
- 共有ブランチで安全に使用できる

## コミットの修正

### git commit --amend - 直前のコミットを修正

#### コミットメッセージの変更

```bash
# コミットメッセージを変更
git commit --amend -m "新しいメッセージ"

# エディタでメッセージを編集
git commit --amend
```

#### ファイルを追加してコミットを修正

```bash
# ファイルを追加
git add forgotten-file.txt

# 直前のコミットに含める
git commit --amend --no-edit
```

#### コミットの内容を変更

```bash
# ファイルを編集
# ... 変更 ...

# ステージング
git add modified-file.txt

# 直前のコミットを修正
git commit --amend
```

**注意**: 既にプッシュしたコミットを修正する場合は、強制プッシュが必要になります（共有ブランチでは避けるべき）。

## ブランチの状態をリセット

### リモートブランチの状態に合わせる

```bash
# リモートの最新状態を取得
git fetch origin

# ローカルブランチをリモートの状態にリセット
git reset --hard origin/main
```

**警告**: ローカルの変更がすべて失われます。

### 特定のコミットにリセット

```bash
# 特定のコミットの状態に戻る
git reset --hard <commit-hash>
```

## 特定のファイルを過去の状態に戻す

### 特定のコミットからファイルを復元

```bash
# 特定のコミットからファイルを取得
git restore --source=<commit-hash> filename.txt

# または（古い方法）
git checkout <commit-hash> -- filename.txt
```

### 特定のブランチからファイルを取得

```bash
# 別のブランチからファイルを取得
git restore --source=other-branch filename.txt
```

## 削除したファイルの復元

### コミットから復元

```bash
# ファイルが削除されたコミットの前の状態から復元
git restore --source=HEAD~1 deleted-file.txt

# または
git checkout HEAD~1 -- deleted-file.txt
```

### リフログから復元

```bash
# リフログで削除前の位置を確認
git reflog

# その位置からファイルを復元
git restore --source=HEAD@{n} deleted-file.txt
```

## 実践例

### 例1: コミットメッセージの修正

```bash
# 直前のコミットのメッセージを変更
git commit --amend -m "修正したメッセージ"

# まだプッシュしていない場合、そのまま使用可能
# 既にプッシュしている場合
git push --force-with-lease origin branch-name
```

### 例2: ファイルを追加してコミットを修正

```bash
# ファイルを追加し忘れた
git add forgotten-file.txt

# 直前のコミットに含める
git commit --amend --no-edit
```

### 例3: 誤ってコミットしたファイルを取り消す

```bash
# コミットを取り消し（変更は保持）
git reset --soft HEAD~1

# 不要なファイルをステージングから外す
git restore --staged unwanted-file.txt

# 再度コミット
git commit -m "正しいコミット"
```

### 例4: 作業中の変更を一時的に保存

```bash
# 変更を一時保存
git stash

# 別の作業を行う
git checkout other-branch
# ... 作業 ...

# 元のブランチに戻って変更を復元
git checkout original-branch
git stash pop
```

### 例5: 複数のコミットを1つに統合

```bash
# 最後の3つのコミットを統合
git reset --soft HEAD~3

# すべての変更を1つのコミットとして作成
git commit -m "統合されたコミット"
```

## 危険な操作とその対処

### 強制リセット後の復元

```bash
# リフログで履歴を確認
git reflog

# リセット前の状態に戻す
git reset --hard HEAD@{n}
```

### 誤って削除したブランチの復元

```bash
# リフログでブランチの位置を確認
git reflog

# ブランチを復元
git branch recovered-branch HEAD@{n}
```

### 失ったコミットの復元

```bash
# リフログでコミットハッシュを確認
git reflog

# ブランチを作成して復元
git branch recovered-branch <commit-hash>
```

## ベストプラクティス

1. **プッシュ前の修正**: プッシュする前に`--amend`で修正
2. **共有ブランチではrevert**: 既にプッシュしたコミットは`revert`を使用
3. **バックアップ**: 重要な変更の前にバックアップブランチを作成
4. **リフログの活用**: 失った変更はリフログで復元可能

## トラブルシューティング

### エラー: "Your branch is ahead of 'origin/main'"

強制プッシュが必要な場合：

```bash
git push --force-with-lease origin branch-name
```

### エラー: "cannot lock ref"

別のGitプロセスが実行中の場合、待つかプロセスを終了してください。
