#git

## 要約

`git add` / `commit` / `push` の裏側を説明できる人は少ない。Gitは「バージョン管理」でもあるが、より正確には **コンテンツを追跡する巨大なキーバリューストア**（中身が番地を決める＝**コンテンツアドレス可能ストレージ**）。

### キーバリューストアとしての Git

鍵は人が名付けるのではなく、中身から自動計算される **SHA（40文字のハッシュ）**。同じ中身 → 同じ鍵、1文字でも変われば別鍵。`git hash-object` に `"hello"` を渡すと世界中どこでも同じハッシュが返る。

倉庫に入るのはたった **3種類の箱** だけ。

| オブジェクト | 持つもの | 持たないもの |
| --- | --- | --- |
| **blob** | ファイルの中身だけ | 名前・日付・場所 |
| **tree** | 名前とフォルダ構造（目録） | — |
| **commit** | ある瞬間のスナップショット＋歴史 | — |

### 3つの箱

**blob** … 中身のデータだけ。`report.txt` という名前はどこにもなく、文章だけが入る（名前を捨てる理由は後述の重複排除）。

**tree** … blob が捨てた名前を引き受ける対応表。1行に権限・種類（ファイル／フォルダ）・中身のハッシュ・名前。別の tree を指せるので、フォルダの入れ子＝ tree → tree → blob の木。

**commit** … `git commit` のたびに生まれる箱。持つのは主に:

1. その瞬間のプロジェクト全体を映す **1枚の tree へのハッシュ**  
2. 人間情報（作者・コミッター・日時・メッセージ）  
3. **親コミットへのハッシュ**（矢印）  

親を辿れば生まれた瞬間まで1本道で遡れる——歴史＝コミットが親を指し続ける鎖。

整理: blob＝中身、tree＝名前と構造、commit＝スナップショットと歴史。すべて同じ倉庫に40文字の番地とともに積まれる。

### `.git` フォルダ

`git init` で生まれる隠しフォルダが倉庫の所在。

- **`objects/`** … 本体。最初の2文字がディレクトリ名、残り38文字がファイル名（オブジェクトが増えても探しやすい「棚分け」）
- **`refs/`** と **`HEAD`** … 参照（ブランチ等）の仕組み（後述）

### ワークツリー・ステージ・リポジトリ

ファイルが置かれる3段階:

1. **ワーキングディレクトリ** … 今編集している生の作業（まだ正式記録ではない）  
2. **ステージングエリア（インデックス）** … `git add` で名簿に名前を書き込む出発ロビー。意図したものだけ選ぶ  
3. **リポジトリ** … `git commit` で並んだ荷物をスナップショットとして倉庫に永続保存  

日々の作業はこの3段階の橋をファイルが渡っていくこと。

### ブランチと HEAD の正体

無数のコミットのどれが「今の最新」か——人間が40文字を覚える代わりに **参照（refs）**。代表がブランチ。

よくある誤解: ブランチ＝枝分かれしたコードの束。  
実際: **1つのコミットのハッシュが書かれた小さなテキストファイル**（付箋）。`refs/heads/main` を開くとハッシュ1行だけ。

だからブランチ作成はコードのコピーではなく、同じコミットを指す付箋を1枚貼るだけ——高速・軽い。新コミットのたびに付箋が新しいコミットへ張り替えられ、先端を追い続ける。

**HEAD** はコミットを直接刺さず、多くは `ref: refs/heads/main` のように **ブランチを刺す**（指を刺す指の2段構え）。`checkout` でブランチを移る＝HEAD の中身を書き換えるだけ。

**タグ** は性格が違う——ブランチが追従する生きた付箋なら、タグは一度打つと動かない杭（多くは `v1.0.0` などの記念碑）。動くもの／動かないものの2種類の目印。

### 重複排除：なぜ blob は名前を捨てたか

同じ中身で名前だけ違う2ファイル（configA / configB）があるとする。blob が名前を持つと別箱が2つ必要で二重に容量を食う。名前を持たず中身だけ見ると、同じ中身 → 同じハッシュ → **倉庫内で1つの blob に統合**。tree の目録では別名でも、指す番地は同じ1 blob。

巨大ファイルの1コメントだけ直しても、変わったファイルだけ新 blob、変わっていない何百ファイルは古い blob を指し続ける。だから何千回コミットしても破綻しない——名前と中身の分離が効率の源泉。

### まとめ

- Git＝中身が番地を決める KV 倉庫  
- 箱は blob / tree / commit の3つだけ  
- ブランチ＝コミットを刺す付箋、HEAD＝その付箋を刺す指  
- blob が名前を捨てたから同じ中身を2度保存しない  

次に `git commit` するとき、ハッシュ計算 → 箱詰め → 付箋の張り替えが頭に浮かぶはず。なぜ壊れたか・どう直すかの答えも、この3つの箱と1枚の付箋の中にある。ぜひ自分の `.git` を覗いて確かめる。
