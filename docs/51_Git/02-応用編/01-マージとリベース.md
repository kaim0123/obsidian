# マージとリベース

## 概要

マージとリベースは、異なるブランチの変更を統合する2つの主要な方法です。それぞれに特徴があり、適切に使い分けることで、クリーンで理解しやすい履歴を維持できます。

## マージ（Merge）

### マージとは

マージは、2つのブランチの変更を統合する操作です。マージコミットが作成され、両方のブランチの履歴が保持されます。

### マージの種類

#### 1. Fast-forward マージ

分岐後にマージ先に新しいコミットがない場合に発生します。

```bash
# 例: featureブランチを作成して作業
git checkout -b feature
# ... コミット ...
git checkout main
git merge feature  # Fast-forwardマージ
```

**特徴**:
- 履歴が一直線になる
- マージコミットが作成されない
- シンプルで分かりやすい

#### 2. 3-way マージ

両方のブランチに新しいコミットがある場合に発生します。

```bash
git checkout main
git merge feature  # 3-wayマージ
```

**特徴**:
- マージコミットが作成される
- 両方のブランチの履歴が保持される
- 分岐と統合の履歴が明確

#### 3. マージコミットを強制

Fast-forwardが可能でも、マージコミットを作成したい場合：

```bash
git merge --no-ff feature
```

### マージ戦略

#### Recursive マージ（デフォルト）

```bash
git merge feature
```

最も一般的なマージ戦略です。

#### Ours 戦略

現在のブランチの内容を優先：

```bash
git merge -s ours feature
```

#### Theirs 戦略

マージするブランチの内容を優先：

```bash
git merge -X theirs feature
```

#### Octopus マージ

複数のブランチを一度にマージ：

```bash
git merge branch1 branch2 branch3
```

### マージの取り消し

```bash
# マージを開始したが、まだコミットしていない場合
git merge --abort

# マージコミットを取り消す
git reset --hard HEAD~1
```

## リベース（Rebase）

### リベースとは

リベースは、現在のブランチのコミットを別のブランチの先頭に再適用する操作です。履歴を一直線に保つことができます。

### 基本的なリベース

```bash
# featureブランチで作業中
git checkout feature

# mainブランチの最新変更を取り込む
git rebase main
```

### リベースの動作

1. 現在のブランチのコミットを一時的に保存
2. ベースブランチの最新状態に移動
3. 保存したコミットを順番に再適用

### インタラクティブリベース

コミットを編集しながらリベース：

```bash
# 最後の3つのコミットを編集
git rebase -i HEAD~3

# 特定のコミットから編集
git rebase -i <commit-hash>
```

#### インタラクティブリベースのコマンド

エディタが開き、以下のコマンドを選択できます：

- `pick`: コミットをそのまま使用
- `reword`: コミットメッセージを変更
- `edit`: コミットを編集
- `squash`: 前のコミットと統合
- `fixup`: squashと同様だが、メッセージは破棄
- `drop`: コミットを削除
- `exec`: シェルコマンドを実行

#### 例: コミットの統合

```bash
git rebase -i HEAD~3
```

エディタで：
```
pick abc1234 First commit
squash def5678 Second commit
squash ghi9012 Third commit
```

これにより、3つのコミットが1つに統合されます。

### リベース中のコンフリクト

コンフリクトが発生した場合：

```bash
# 1. コンフリクトを解決
# ファイルを編集してコンフリクトを解決

# 2. 解決したファイルをステージング
git add resolved-file.txt

# 3. リベースを続行
git rebase --continue

# リベースを中止
git rebase --abort

# 現在のコミットをスキップ
git rebase --skip
```

### リベースの取り消し

```bash
# リベースを元に戻す
git reflog
git reset --hard HEAD@{n}  # nはリベース前の位置
```

## マージ vs リベース

### マージの利点

- **履歴の保持**: すべての履歴が保持される
- **安全性**: 既存のコミットを変更しない
- **分岐の明確化**: ブランチの分岐と統合が明確

### マージの欠点

- **履歴の複雑化**: マージコミットが増えると履歴が複雑になる
- **視認性**: 多くのマージコミットがあると、主要な変更が見えにくい

### リベースの利点

- **クリーンな履歴**: 一直線の履歴を維持できる
- **視認性**: 主要な変更が分かりやすい
- **小さなコミットの統合**: インタラクティブリベースで整理できる

### リベースの欠点

- **履歴の書き換え**: 既存のコミットを変更する
- **共有ブランチでは危険**: 既にプッシュしたブランチのリベースは避けるべき
- **コンフリクトの頻発**: 複雑な変更がある場合、コンフリクトが多発する可能性

## 使い分けのガイドライン

### マージを使用する場合

- **共有ブランチ**: 他の開発者と共有しているブランチ
- **公開済みのコミット**: 既にプッシュしたコミット
- **履歴の完全性が重要**: すべての履歴を保持したい場合

### リベースを使用する場合

- **ローカルブランチ**: まだプッシュしていないブランチ
- **クリーンな履歴**: 一直線の履歴を維持したい場合
- **コミットの整理**: コミットメッセージの修正や統合

## 実践例

### 例1: 機能開発のワークフロー（マージ）

```bash
# 1. 機能ブランチで開発
git checkout -b feature/new-feature
# ... コミット ...

# 2. メインブランチにマージ
git checkout main
git pull origin main
git merge feature/new-feature

# 3. プッシュ
git push origin main
```

### 例2: 機能開発のワークフロー（リベース）

```bash
# 1. 機能ブランチで開発
git checkout -b feature/new-feature
# ... コミット ...

# 2. メインブランチの最新を取り込む
git rebase main

# 3. メインブランチにマージ（Fast-forward）
git checkout main
git merge feature/new-feature

# 4. プッシュ
git push origin main
```

### 例3: コミットの整理

```bash
# 最後の5つのコミットを整理
git rebase -i HEAD~5

# エディタで:
# - 不要なコミットをdrop
# - 関連するコミットをsquash
# - コミットメッセージをreword
```

## 高度なテクニック

### リベースのベース変更

```bash
# 別のブランチをベースにリベース
git rebase --onto new-base old-base feature
```

### マージの戦略指定

```bash
# 特定の戦略でマージ
git merge -s recursive -X ours feature
```

### リベースの続行

リベース中にエラーが発生した場合：

```bash
# コンフリクト解決後
git add .
git rebase --continue
```

## トラブルシューティング

### リベース後のコンフリクト

```bash
# コンフリクトを解決
git add .
git rebase --continue

# または中止
git rebase --abort
```

### マージの取り消し

```bash
# マージコミットを取り消し
git reset --hard HEAD~1

# または、マージ前の状態に戻す
git reset --hard ORIG_HEAD
```

### リベースの履歴復元

```bash
# リフログで位置を確認
git reflog

# リベース前の状態に戻す
git reset --hard HEAD@{n}
```

## ベストプラクティス

1. **共有ブランチではマージ**: 既にプッシュしたブランチはマージを使用
2. **ローカルブランチではリベース**: プッシュ前のブランチはリベースで整理
3. **コミットの整理**: プッシュ前にインタラクティブリベースで整理
4. **チームの方針に従う**: チームで決めた方針に従う
