# パフォーマンスの最適化

## 概要

大きなリポジトリや長い履歴を持つリポジトリでは、Gitの操作が遅くなることがあります。この章では、Gitのパフォーマンスを最適化する方法を説明します。

## リポジトリのサイズを確認

### リポジトリのサイズを測定

```bash
# リポジトリのサイズを確認
du -sh .git

# オブジェクトの数を確認
git count-objects -vH

# 大きなファイルを検出
git rev-list --objects --all | \
  git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' | \
  awk '/^blob/ {print substr($0,6)}' | \
  sort --numeric-sort --key=2 | \
  tail -10
```

## 浅いクローン（Shallow Clone）

### 浅いクローンの作成

```bash
# 最新の1コミットのみクローン
git clone --depth 1 https://github.com/username/repository.git

# 最新の10コミットのみクローン
git clone --depth 10 https://github.com/username/repository.git

# 特定のブランチのみ浅くクローン
git clone --depth 1 --branch main https://github.com/username/repository.git
```

### 浅いクローンの更新

```bash
# 履歴を深くする
git fetch --unshallow

# 特定の深さまで取得
git fetch --depth=50
```

## 履歴のクリーンアップ

### ガベージコレクション

```bash
# 標準のガベージコレクション
git gc

# 積極的なガベージコレクション
git gc --aggressive

# すべてのリフログを削除してクリーンアップ
git gc --prune=now --aggressive
```

### 大きなファイルの削除

#### git-filter-repoを使用（推奨）

```bash
# git-filter-repoをインストール
pip install git-filter-repo

# 大きなファイルを履歴から削除
git filter-repo --path large-file.zip --invert-paths

# 10MB以上のファイルを削除
git filter-repo --strip-blobs-bigger-than 10M
```

#### git-filter-branchを使用（非推奨）

```bash
# 大きなファイルを履歴から削除
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch large-file.zip" \
  --prune-empty --tag-name-filter cat -- --all
```

### 未使用のオブジェクトの削除

```bash
# 到達不可能なオブジェクトを削除
git prune

# より積極的に削除
git prune --expire=now
```

## インデックスの最適化

### インデックスの再構築

```bash
# インデックスを再構築
git update-index --refresh

# インデックスをクリアして再構築
rm -f .git/index
git reset
```

### ファイルシステムモニターの使用

```bash
# core.fsmonitorを有効化（Git 2.18以降）
git config core.fsmonitor true

# Watchmanを使用（Facebook製）
brew install watchman  # macOS
git config core.fsmonitor watchman
```

## パックファイルの最適化

### パックファイルの再パック

```bash
# パックファイルを最適化
git repack -a -d --depth=250 --window=250

# より積極的な最適化
git repack -a -d -f --depth=250 --window=250
```

### パックファイルの設定

```bash
# パックファイルの圧縮レベル（0-9、デフォルトは-1）
git config pack.compression 9

# デルタチェーンの深さ
git config pack.depth 250

# デルタウィンドウのサイズ
git config pack.window 250
```

## リモート操作の最適化

### 部分クローン（Partial Clone）

```bash
# ブロブなしでクローン（ファイル内容は取得しない）
git clone --filter=blob:none https://github.com/username/repository.git

# 必要なファイルのみ取得
git sparse-checkout init --cone
git sparse-checkout set 'path/to/directory'

# ファイルを取得
git sparse-checkout add 'path/to/file.txt'
```

### フェッチの最適化

```bash
# 必要なブランチのみフェッチ
git fetch origin branch-name

# タグを取得しない
git fetch --no-tags origin

# 浅いフェッチ
git fetch --depth=10 origin
```

## 設定の最適化

### パフォーマンス関連の設定

```bash
# インデックスの並列読み込み
git config core.preloadindex true

# 並列処理の有効化
git config pack.threads 4

# ファイルシステムのキャッシュ
git config core.untrackedCache true

# ファイルシステムモニター
git config core.fsmonitor true
```

### グローバル設定

```bash
# ~/.gitconfigに追加
[core]
    preloadindex = true
    untrackedCache = true
    fsmonitor = true

[pack]
    threads = 4
    compression = 9
    depth = 250
    window = 250

[gc]
    auto = 256
    autoPackLimit = 4
```

## 大きなファイルの管理

### Git LFSの使用

```bash
# Git LFSをインストール
git lfs install

# 大きなファイルを追跡
git lfs track "*.psd"
git lfs track "*.zip"
git lfs track "*.mp4"

# .gitattributesをコミット
git add .gitattributes
git commit -m "Add Git LFS tracking"
```

### .gitignoreの最適化

```gitignore
# 大きなファイルを除外
*.zip
*.tar.gz
*.mp4
*.psd

# ビルド成果物
dist/
build/
node_modules/
```

## 実践例

### 例1: 大きなリポジトリのクローン

```bash
# 浅いクローン
git clone --depth 1 https://github.com/username/large-repo.git

# 必要な履歴のみ取得
cd large-repo
git fetch --unshallow --depth=50
```

### 例2: 履歴のクリーンアップ

```bash
# 1. 大きなファイルを検出
git rev-list --objects --all | \
  git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' | \
  awk '/^blob/ {print substr($0,6)}' | \
  sort --numeric-sort --key=2 | \
  tail -10

# 2. 大きなファイルを削除
git filter-repo --strip-blobs-bigger-than 10M

# 3. ガベージコレクション
git gc --aggressive --prune=now
```

### 例3: パフォーマンス設定の適用

```bash
# パフォーマンス設定を適用
git config core.preloadindex true
git config core.untrackedCache true
git config pack.threads 4

# インデックスを更新
git update-index --refresh
```

## ベンチマーク

### 操作時間の測定

```bash
# クローン時間を測定
time git clone https://github.com/username/repository.git

# ステータス時間を測定
time git status

# ログ時間を測定
time git log --oneline -100
```

### パフォーマンスの比較

```bash
# 最適化前
time git status

# 最適化後
git config core.preloadindex true
git config core.untrackedCache true
time git status
```

## トラブルシューティング

### メモリ不足

```bash
# パックファイルのスレッド数を減らす
git config pack.threads 1

# ガベージコレクションを実行
git gc
```

### ディスク容量不足

```bash
# 古いオブジェクトを削除
git prune --expire=30.days.ago

# ガベージコレクション
git gc --prune=now
```

### 操作が遅い

```bash
# インデックスを再構築
rm -f .git/index
git reset

# ファイルシステムモニターを有効化
git config core.fsmonitor true
```

## ベストプラクティス

1. **定期的なクリーンアップ**: 定期的に`git gc`を実行
2. **大きなファイルの管理**: Git LFSを使用
3. **浅いクローン**: 必要に応じて浅いクローンを使用
4. **設定の最適化**: パフォーマンス設定を適用
5. **モニタリング**: リポジトリのサイズを定期的に確認

## まとめ

Gitのパフォーマンスを最適化するには：

1. **リポジトリのサイズを管理**: 大きなファイルを削除またはGit LFSで管理
2. **履歴のクリーンアップ**: 定期的にガベージコレクションを実行
3. **設定の最適化**: パフォーマンス関連の設定を適用
4. **浅いクローン**: 必要に応じて浅いクローンを使用
5. **部分クローン**: 大きなリポジトリでは部分クローンを検討

これらの最適化により、Gitの操作を高速化できます。
