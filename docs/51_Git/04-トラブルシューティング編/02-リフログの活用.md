# リフログの活用

## 概要

リフログ（reflog）は、Gitの参照（ブランチ、HEADなど）の変更履歴を記録する機能です。誤って削除したコミットやブランチを復元する際に非常に有用です。

## リフログとは

リフログは、HEADやブランチの移動履歴を記録します。これにより、過去の任意の時点の状態に戻ることができます。

### リフログの特徴

- **自動記録**: Gitが自動的に記録
- **時限的**: デフォルトで90日間保持（設定可能）
- **ローカルのみ**: リモートには送信されない
- **安全**: リポジトリの操作に影響しない

## 基本的な使い方

### リフログの表示

```bash
# すべてのリフログを表示
git reflog

# 特定のブランチのリフログ
git reflog show branch-name

# HEADのリフログ
git reflog show HEAD

# 最後のN件のみ表示
git reflog -n 10
```

### リフログの出力例

```
abc1234 HEAD@{0}: commit: Add new feature
def5678 HEAD@{1}: checkout: moving from main to feature
ghi9012 HEAD@{2}: commit: Update documentation
jkl3456 HEAD@{3}: merge feature: Fast-forward
mno7890 HEAD@{4}: reset: moving to HEAD~1
pqr1234 HEAD@{5}: commit: Initial commit
```

### リフログエントリの読み方

- `abc1234`: コミットハッシュ
- `HEAD@{0}`: 現在の位置
- `HEAD@{1}`: 1つ前の位置
- `commit: Add new feature`: 実行された操作とメッセージ

## 失ったコミットの復元

### コミットを削除した場合

```bash
# 1. リフログで削除前の位置を確認
git reflog

# 2. 削除前のコミットハッシュを確認
# 例: abc1234 HEAD@{3}: commit: Important commit

# 3. そのコミットに戻る
git reset --hard abc1234

# または、リフログの位置を使用
git reset --hard HEAD@{3}
```

### ブランチを削除した場合

```bash
# 1. リフログでブランチの位置を確認
git reflog

# 2. ブランチを復元
git branch recovered-branch <commit-hash>

# または
git branch recovered-branch HEAD@{n}
```

### 強制リセット後の復元

```bash
# 1. リフログでリセット前の位置を確認
git reflog

# 2. リセット前の状態に戻る
git reset --hard HEAD@{n}
```

## リフログを使った操作

### 特定の時点に戻る

```bash
# リフログで位置を確認
git reflog

# 特定の時点に戻る
git checkout HEAD@{5}

# 一時的に確認（detached HEAD状態）
# ブランチを作成して保持
git checkout -b recovered-branch
```

### 過去の状態を確認

```bash
# 過去のコミットを確認
git show HEAD@{10}

# 過去の状態でファイルを確認
git show HEAD@{10}:filename.txt

# 過去の状態でディレクトリを確認
git ls-tree -r HEAD@{10}
```

## リフログの管理

### リフログの有効期限

```bash
# リフログの有効期限を確認
git config gc.reflogExpire

# 有効期限を設定（デフォルトは90日）
git config gc.reflogExpire "180 days"

# 未到達のリフログの有効期限
git config gc.reflogExpireUnreachable "30 days"
```

### リフログのクリーンアップ

```bash
# 古いリフログを削除
git reflog expire --expire=now --all

# ガベージコレクションを実行
git gc --prune=now
```

**注意**: リフログを削除すると、失ったコミットを復元できなくなる可能性があります。

## 実践例

### 例1: 誤って削除したコミットの復元

```bash
# 1. リフログで削除前の位置を確認
git reflog
# 出力:
# abc1234 HEAD@{0}: reset: moving to HEAD~1
# def5678 HEAD@{1}: commit: Important feature

# 2. 削除されたコミットを復元
git reset --hard def5678

# または
git reset --hard HEAD@{1}
```

### 例2: 強制プッシュ前の状態に戻る

```bash
# 1. リフログで強制プッシュ前の位置を確認
git reflog
# 出力:
# abc1234 HEAD@{0}: push: updating refs/heads/main
# def5678 HEAD@{1}: commit: Previous commit

# 2. 強制プッシュ前の状態に戻る
git reset --hard def5678
```

### 例3: マージ前の状態に戻る

```bash
# 1. リフログでマージ前の位置を確認
git reflog
# 出力:
# abc1234 HEAD@{0}: merge feature: Merge made
# def5678 HEAD@{1}: checkout: moving from feature to main

# 2. マージ前の状態に戻る
git reset --hard def5678
```

### 例4: 失ったブランチの復元

```bash
# 1. リフログでブランチの位置を確認
git reflog
# 出力:
# abc1234 HEAD@{5}: checkout: moving from feature to main
# def5678 HEAD@{6}: commit: Feature work

# 2. ブランチを復元
git branch recovered-feature def5678

# または
git branch recovered-feature HEAD@{6}
```

## リフログと他のコマンドの組み合わせ

### リフログとgit log

```bash
# リフログのコミットを確認
git log --oneline --all --reflog

# 特定の範囲のコミットを確認
git log HEAD@{10}..HEAD@{5}
```

### リフログとgit diff

```bash
# 過去の状態との差分
git diff HEAD@{10} HEAD@{5}

# 現在との差分
git diff HEAD@{10} HEAD
```

### リフログとgit show

```bash
# 過去のコミットを表示
git show HEAD@{10}

# 過去の状態のファイルを表示
git show HEAD@{10}:path/to/file.txt
```

## リフログの制限事項

1. **ローカルのみ**: リモートには送信されない
2. **時限的**: デフォルトで90日間のみ保持
3. **ガベージコレクション**: `git gc`で削除される可能性
4. **共有不可**: 他の開発者と共有できない

## ベストプラクティス

1. **定期的な確認**: 重要な操作の前にリフログを確認
2. **バックアップ**: 重要なコミットは別のブランチに保存
3. **タグの使用**: 重要なポイントにタグを付ける
4. **リモートへのプッシュ**: 重要な変更は早めにプッシュ

## トラブルシューティング

### リフログが空

```bash
# リフログが存在するか確認
ls -la .git/logs/

# リフログを有効化（通常は自動）
git config core.logAllRefUpdates true
```

### リフログが見つからない

```bash
# すべてのリフログを確認
find .git/logs -type f

# 特定のブランチのリフログ
cat .git/logs/refs/heads/branch-name
```
