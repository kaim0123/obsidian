# よくある問題と解決方法

## 概要

Gitを使用していると、さまざまな問題に遭遇します。この章では、よくある問題とその解決方法を詳しく説明します。

## コンフリクトの解決

### マージコンフリクト

#### 問題

マージ時にコンフリクトが発生：

```
Auto-merging file.txt
CONFLICT (content): Merge conflict in file.txt
Automatic merge failed; fix conflicts and then commit the result.
```

#### 解決方法

1. **コンフリクトファイルを確認**

```bash
git status
```

2. **コンフリクトマーカーを確認**

```bash
cat file.txt
```

コンフリクトマーカー：
```
<<<<<<< HEAD
現在のブランチの内容
=======
マージしようとしているブランチの内容
>>>>>>> feature-branch
```

3. **コンフリクトを解決**

ファイルを編集して、正しい内容に修正：

```bash
# エディタで編集
vim file.txt
```

4. **解決したファイルをステージング**

```bash
git add file.txt
```

5. **マージを完了**

```bash
git commit
```

#### マージツールの使用

```bash
# マージツールを起動
git mergetool

# 特定のツールを指定
git mergetool --tool=vimdiff
```

### リベースコンフリクト

#### 問題

リベース中にコンフリクトが発生。

#### 解決方法

```bash
# 1. コンフリクトを解決
# ファイルを編集

# 2. 解決したファイルをステージング
git add resolved-file.txt

# 3. リベースを続行
git rebase --continue

# リベースを中止
git rebase --abort
```

## 誤ってコミットした場合

### 直前のコミットを取り消す

#### コミットメッセージを変更

```bash
git commit --amend -m "正しいメッセージ"
```

#### ファイルを追加してコミットを修正

```bash
# ファイルを追加
git add forgotten-file.txt

# 直前のコミットに含める
git commit --amend --no-edit
```

#### コミットを完全に取り消す

```bash
# コミットを取り消し、変更は保持
git reset --soft HEAD~1

# コミットとステージングを取り消し、変更は保持
git reset HEAD~1

# すべてを取り消し（注意）
git reset --hard HEAD~1
```

### 複数のコミットを取り消す

```bash
# 最後の3つのコミットを取り消し
git reset --soft HEAD~3

# 特定のコミットまで戻る
git reset --soft <commit-hash>
```

### 既にプッシュしたコミットを取り消す

```bash
# revertを使用（推奨）
git revert <commit-hash>

# 複数のコミットをrevert
git revert HEAD~3..HEAD
```

## 誤って削除したファイルの復元

### コミットから復元

```bash
# 特定のコミットからファイルを復元
git restore --source=<commit-hash> filename.txt

# または
git checkout <commit-hash> -- filename.txt
```

### リフログから復元

```bash
# リフログで削除前の位置を確認
git reflog

# その位置からファイルを復元
git restore --source=HEAD@{n} filename.txt
```

### 削除されたブランチの復元

```bash
# リフログでブランチの位置を確認
git reflog

# ブランチを復元
git branch recovered-branch HEAD@{n}
```

## 強制プッシュの問題

### 問題

強制プッシュにより、リモートの履歴が上書きされた。

### 解決方法

```bash
# リフログで履歴を確認
git reflog

# 強制プッシュ前の状態に戻す
git reset --hard HEAD@{n}

# 再度プッシュ（注意）
git push --force-with-lease origin branch-name
```

### 予防策

```bash
# --force-with-leaseを使用（より安全）
git push --force-with-lease origin branch-name

# 共有ブランチでは強制プッシュを避ける
```

## 大きなファイルの問題

### 問題

誤って大きなファイルをコミットした。

### 解決方法

#### 履歴から削除

```bash
# git-filter-repoを使用（推奨）
git filter-repo --path large-file.txt --invert-paths

# または、git-filter-branchを使用
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch large-file.txt" \
  --prune-empty --tag-name-filter cat -- --all
```

#### Git LFSの使用

```bash
# Git LFSをインストール
git lfs install

# 大きなファイルを追跡
git lfs track "*.psd"
git lfs track "*.zip"

# .gitattributesをコミット
git add .gitattributes
git commit -m "Add Git LFS tracking"
```

## 認証の問題

### SSH認証エラー

#### 問題

```
Permission denied (publickey).
```

#### 解決方法

```bash
# SSH鍵を確認
ls -la ~/.ssh/

# SSH鍵を生成
ssh-keygen -t ed25519 -C "your_email@example.com"

# 公開鍵を表示
cat ~/.ssh/id_ed25519.pub

# GitHubなどに公開鍵を登録

# 接続をテスト
ssh -T git@github.com
```

### HTTPS認証エラー

#### 問題

```
fatal: Authentication failed
```

#### 解決方法

```bash
# 認証情報を再設定
git config --global credential.helper store

# または、macOSの場合
git config --global credential.helper osxkeychain

# または、Windowsの場合
git config --global credential.helper wincred
```

## リモートリポジトリの問題

### リモートが見つからない

#### 問題

```
fatal: 'origin' does not appear to be a git repository
```

#### 解決方法

```bash
# リモートを確認
git remote -v

# リモートを追加
git remote add origin https://github.com/username/repository.git

# URLを確認
git remote get-url origin
```

### リモートのURLが間違っている

#### 解決方法

```bash
# URLを変更
git remote set-url origin https://github.com/username/new-repository.git

# 確認
git remote -v
```

## パフォーマンスの問題

### リポジトリが大きすぎる

#### 問題

クローンや操作が遅い。

#### 解決方法

```bash
# 浅いクローン
git clone --depth 1 https://github.com/username/repository.git

# 履歴のクリーンアップ
git gc --aggressive --prune=now

# 大きなファイルの削除
git filter-repo --strip-blobs-bigger-than 10M
```

### インデックスの問題

#### 問題

操作が遅い、エラーが発生する。

#### 解決方法

```bash
# インデックスを再構築
git rm -r --cached .
git reset --hard HEAD

# または
rm -rf .git/index
git reset
```

## その他の問題

### 作業ディレクトリが汚れている

#### 問題

ブランチを切り替えられない。

#### 解決方法

```bash
# 変更を一時保存
git stash

# ブランチを切り替え
git checkout other-branch

# 変更を復元
git stash pop
```

### コミットが表示されない

#### 問題

コミットしたが、履歴に表示されない。

#### 解決方法

```bash
# リフログで確認
git reflog

# 失ったコミットを復元
git branch recovered-branch <commit-hash>
```

### マージコミットが多すぎる

#### 問題

履歴が複雑になっている。

#### 解決方法

```bash
# インタラクティブリベースで整理
git rebase -i HEAD~10

# または、履歴を書き換え（注意）
git rebase --onto main feature-branch
```

## 予防策

1. **定期的なバックアップ**: 重要な変更の前にバックアップ
2. **小さなコミット**: 小さな変更を頻繁にコミット
3. **テスト**: コミット前にテストを実行
4. **コードレビュー**: プルリクエストでコードレビュー
5. **ドキュメント**: 変更内容をドキュメント化
