## 監視の基本
- サーバーの稼働状況・リソース使用率・サービスの可用性を常時監視
- 障害や異常を早期発見し、迅速に対応
- パフォーマンス最適化やキャパシティプランニングにも活用

## 主要な監視項目
- **CPU使用率**: 高負荷・ボトルネック検知
- **メモリ使用率**: メモリリーク・不足検知
- **ディスク使用率/IO**: 容量不足・障害検知
- **ネットワーク**: 帯域・遅延・パケットロス
- **プロセス/サービス**: 死活監視・自動再起動
- **アプリケーション**: レスポンスタイム・エラーレート
- **ログ**: エラー・警告・不正アクセス

## ログ管理
- **システムログ**: syslog, journald, rsyslog
- **アプリケーションログ**: 独自ログ、フレームワークログ
- **Web/DBサーバーログ**: Nginx, Apache, MySQL, PostgreSQL など
- **セキュリティログ**: 認証・アクセス・IDS/IPS
- **集中管理**: ELK Stack（Elasticsearch, Logstash, Kibana）、Fluentd、CloudWatch

### ログローテーション
```bash
sudo logrotate /etc/logrotate.conf
```

### ログ監視・分析
- grep, tail, less, journalctl
- Kibana, Grafana Loki, Datadog, Splunk

## アラート・通知
- **閾値監視**: CPU/メモリ/ディスク/レスポンスタイム等
- **死活監視**: サービスダウン時の通知
- **異常検知**: ログのエラー・不正アクセス
- **通知方法**: メール、Slack、Teams、PagerDuty など

## 代表的な監視ツール

### オープンソース
- **Prometheus**: メトリクス収集・アラート
- **Grafana**: ダッシュボード可視化
- **Zabbix**: 総合監視
- **Nagios**: 死活・リソース監視
- **ELK Stack**: ログ収集・分析
- **Fluentd**: ログ集約
- **Netdata**: リアルタイム監視

### クラウドサービス
- **AWS CloudWatch**
- **Google Cloud Monitoring（旧Stackdriver）**
- **Azure Monitor**
- **Datadog**
- **New Relic**

## 監視・ログの設計例

### Prometheus + Grafana
- Node Exporterでサーバーメトリクス収集
- Prometheusで時系列データ保存・アラート
- Grafanaでダッシュボード可視化

### ELK Stack
- Filebeat/Fluentdでログ収集
- Logstashで加工・Elasticsearchで保存
- Kibanaで検索・可視化

### 死活監視スクリプト例
```bash
#!/bin/bash
if ! pgrep nginx > /dev/null; then
  systemctl restart nginx
  echo "$(date) nginx再起動" >> /var/log/nginx_watch.log
fi
```

## ベストプラクティス
- 重要なログは長期保存・バックアップ
- ログの改ざん防止・アクセス制御
- アラートの閾値・通知先の定期見直し
- 監視・ログ設計のドキュメント化
- 定期的なテスト・訓練

## 実践例

### サーバーリソース監視
- Prometheus + GrafanaでCPU/メモリ/ディスク/ネットワークを可視化

### アプリケーション監視
- APM（Application Performance Monitoring）導入
- Datadog, New Relic, Sentry など

### ログ分析
- ELK Stackでエラー・アクセス・セキュリティログを集約・可視化
