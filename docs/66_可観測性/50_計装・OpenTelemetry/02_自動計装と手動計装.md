# 自動計装と手動計装

**計装（Instrumentation）** とは、アプリがテレメトリ（スパン・メトリクス・ログ）を出すようにすることです。OpenTelemetry には、**ライブラリにフックして自動でスパンを作る自動計装**と、**コードに自分でスパンや属性を書く手動計装**の 2 つがあります。実務では「**まず自動計装で入口と出口を押さえ、業務的に大事な処理だけ手動で足す**」のが定石です。この章では、それぞれの仕組みと使い分けを整理します。

---

## 1. 2 つの方式の比較

| 観点 | 自動計装 | 手動計装 |
|------|----------|----------|
| 書くコード | ほぼゼロ（起動時の設定のみ） | 計装したい箇所ごとに書く |
| 取れるもの | HTTP の受信・送信、DB クエリ、Redis、gRPC、メッセージング | 業務ロジックの区間、業務属性（テナント・プラン・件数）、業務メトリクス |
| 属性名 | セマンティック規約どおり | 自分で決める（`app.` 接頭辞推奨） |
| 弱点 | 業務的な意味が分からない。不要なスパンが多い（fs、dns など） | 書き忘れ・書きすぎ。コードが読みにくくなる |
| 例 | `GET /orders/:id`、`SELECT orders` | `checkout.calculate_tax`、属性 `app.order.total=12800` |

『Observability Engineering』は、自動計装だけでは「**ユーザーにとって意味のある問い**」に答えられないと強調しています。「プレミアム会員の決済だけ遅いのでは？」に答えるには、`user.tier` 属性を自分で付ける必要があります。

---

## 2. 自動計装の仕組み（Node.js）

Node.js の自動計装は、`require` / `import` されるモジュールを**読み込み時に書き換え（モンキーパッチ）**、関数の前後にスパンの開始・終了を差し込みます。そのため **アプリのコードより先に SDK を読み込む**必要があります。

```bash
npm install @opentelemetry/api @opentelemetry/auto-instrumentations-node
```

**方法 1：コード変更なし（ゼロコード計装）**

```bash
# CommonJS
node --require @opentelemetry/auto-instrumentations-node/register app.js

# ESM（Node.js 20.6 以降）
node --import @opentelemetry/auto-instrumentations-node/register app.mjs
```

```bash
# 設定は環境変数で
export OTEL_SERVICE_NAME=order-api
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
export OTEL_NODE_ENABLED_INSTRUMENTATIONS=http,express,pg,ioredis,pino
```

**方法 2：自分で SDK の初期化ファイルを書く**（細かく設定したいとき。[[04_Node.jsアプリの計装例]]）

```ts
// instrumentation.ts
import { NodeSDK } from '@opentelemetry/sdk-node';
import { getNodeAutoInstrumentations } from '@opentelemetry/auto-instrumentations-node';

const sdk = new NodeSDK({
  instrumentations: [
    getNodeAutoInstrumentations({
      '@opentelemetry/instrumentation-fs': { enabled: false },   // ノイズが多いので切る
      '@opentelemetry/instrumentation-dns': { enabled: false },
      '@opentelemetry/instrumentation-http': {
        ignoreIncomingRequestHook: (req) => req.url === '/healthz', // ヘルスチェックは除外
      },
    }),
  ],
});
sdk.start();
```

```bash
node --import ./instrumentation.js app.js
```

**ESM の注意点**：ESM では `import` の書き換えに **ローダーフック**が必要です。`--import` で登録ファイルを読み込む方式が推奨で、うまく動かないときは `@opentelemetry/instrumentation` の ESM サポート（`import-in-the-middle`）の状態を公式ドキュメントで確認します。

## 3. 自動計装で取れる主なもの

| ライブラリ | 生成されるスパン | 主な属性 |
|------------|------------------|----------|
| http / https | SERVER・CLIENT スパン | `http.request.method`、`http.response.status_code`、`url.path` |
| express / fastify / koa | ルートハンドラ・ミドルウェアのスパン | `http.route`（`/orders/:id`） |
| pg / mysql2 | クエリのスパン | `db.system.name`、`db.query.text`（パラメータはプレースホルダのまま） |
| ioredis / redis | コマンドのスパン | `db.operation.name`（GET / SET） |
| kafkajs / amqplib / aws-sdk（SQS） | PRODUCER・CONSUMER スパン | `messaging.system`、`messaging.destination.name` |
| pino / winston | （スパンは作らない）ログに trace_id を注入 | `trace_id`、`span_id` |

- 自動計装は **HTTP のメトリクス（`http.server.request.duration` のヒストグラム）** も作ります。RED メソッドのダッシュボードは、これだけでほぼ作れます（[[02_REDメソッドとUSEメソッド]]）。

## 4. 手動計装：スパンを作る

```ts
import { trace, SpanStatusCode } from '@opentelemetry/api';

const tracer = trace.getTracer('checkout', '1.0.0');   // 名前は計装の単位（モジュール名など）

export async function placeOrder(cart: Cart, user: User) {
  return tracer.startActiveSpan('checkout.place_order', async (span) => {
    span.setAttributes({
      'app.user.tier': user.tier,
      'app.cart.item_count': cart.items.length,
    });
    try {
      const total = await calculateTotal(cart);        // この中の DB 呼び出しは子スパンになる
      span.setAttribute('app.order.total', total);
      const order = await saveOrder(cart, total);
      span.addEvent('order saved', { 'app.order.id': order.id });
      return order;
    } catch (err) {
      span.recordException(err as Error);
      span.setStatus({ code: SpanStatusCode.ERROR, message: (err as Error).message });
      throw err;
    } finally {
      span.end();                                     // end() を忘れるとスパンが送られない
    }
  });
}
```

| ポイント | 理由 |
|----------|------|
| `startActiveSpan` を使う | コールバック内がこのスパンの「アクティブなコンテキスト」になり、中の自動計装スパンが**子**として付く |
| `finally` で `end()` | 例外時にも閉じる。閉じ忘れるとメモリに残り、送信もされない |
| スパン名は低カーディナリティ | ID は名前ではなく属性へ（[[03_カーディナリティ問題]]） |
| 業務エラーは自分で `ERROR` にする | 自動計装は HTTP 5xx などしか判定できない |

## 5. 手動計装：スパンを作らずに属性だけ足す

新しいスパンを作るほどでもない場合は、**自動計装が作った現在のスパンに属性を足す**だけで十分なことが多いです。

```ts
// Express のミドルウェアで、認証後にユーザー情報をスパンに付ける
app.use((req, _res, next) => {
  const span = trace.getActiveSpan();
  span?.setAttributes({ 'app.user.tier': req.user?.tier ?? 'anonymous', 'app.tenant.id': req.tenantId });
  next();
});
```

`user.id` のような高カーディナリティの値も、**スパン属性なら問題ありません**（メトリクスのラベルにすると問題になる。[[03_カーディナリティ問題]]）。

## 6. 手動計装：メトリクスを作る

```ts
import { metrics } from '@opentelemetry/api';

const meter = metrics.getMeter('checkout');
const ordersCounter = meter.createCounter('app.orders.placed', { description: '確定した注文数' });
const orderValue = meter.createHistogram('app.order.value', { unit: 'JPY' });

ordersCounter.add(1, { 'app.payment.method': 'card' });   // ラベルは種類の少ないものだけ
orderValue.record(12800);
```

メトリクスの種類の選び方は [[01_メトリクスの種類（カウンタ・ゲージ・ヒストグラム）]]。

## 7. 何を手動で計装するか

| 優先度 | 対象 |
|--------|------|
| 高 | 売上・決済・ログインなど **SLO の対象になる処理**の区間と成否 |
| 高 | リクエスト単位の業務属性（テナント、プラン、機能フラグ、クライアントのバージョン） |
| 中 | 外部 API 呼び出しのうち、自動計装が対応していない SDK |
| 中 | 重い計算・バッチの各ステップ |
| 低 | 小さなユーティリティ関数（スパンが増えるだけでノイズになる） |
