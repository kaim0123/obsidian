# 集約とウィンドウ関数

[[MOC_データアーキテクチャ体系|📚 目次]] ｜ [[03_JOINとサブクエリ|← 前へ]] ｜ [[05_NULLと三値論理|次へ →]]

> [!abstract] この記事で分かること
> - 集約関数（COUNT / SUM / AVG / MIN / MAX）と GROUP BY・HAVING の使い方
> - `COUNT(*)` と `COUNT(列)` と `COUNT(DISTINCT 列)` の違い
> - ウィンドウ関数が「行を減らさずに集計する」仕組み（PARTITION BY / ORDER BY / フレーム）
> - ランキング・累計・前月比を SQL だけで出す実例
> - 再帰 CTE で階層や連番を作る入口
>
> **前提**：[[02_SQLの基本操作（CRUD）]]、[[03_JOINとサブクエリ]] を読んでいると理解しやすいです。

## 1. ひとことで言うと

クラス 40 人のテスト結果を想像してください。

- 「クラスごとの平均点」を出すと、40 行が **クラスの数だけの行** にまとまります。これが **集約（GROUP BY）** です。
- 「各生徒の点数の横に、クラス平均と、クラス内順位を書き足す」と、**40 行のまま** 情報が増えます。これが **ウィンドウ関数** です。

集約は「まとめて行を減らす」、ウィンドウ関数は「行を残したまま、周りの行を窓（window）越しに覗いて計算する」と覚えると区別しやすくなります。

## 2. 集約関数と GROUP BY / HAVING

### 2.1 集約関数

集約関数（Aggregate Function）：複数行の値から 1 つの値を計算する関数 です。

| 関数 | 意味 | NULL の扱い |
|---|---|---|
| `count(*)` | 行数 | 行そのものを数える（NULL も数える） |
| `count(列)` | その列が NULL でない行数 | NULL は数えない |
| `sum(列)` | 合計 | NULL は無視。対象が 0 行なら **NULL** |
| `avg(列)` | 平均 | NULL は無視（分母にも入らない） |
| `min(列)` / `max(列)` | 最小・最大 | NULL は無視 |

```sql
SELECT count(*)                    AS products,        -- 5
       count(category_id)          AS categorized,     -- 4（福袋は NULL）
       count(DISTINCT category_id) AS used_categories, -- 3
       sum(stock)                  AS total_stock,
       avg(price)::int             AS avg_price        -- 2426
FROM products;
```

`count(*)` と `count(category_id)` が食い違うのは、NULL を数えるかどうかの違いです。「件数が合わない」ときはまずここを疑います（詳しくは [[05_NULLと三値論理]]）。

### 2.2 GROUP BY：グループごとに集約

```sql
-- カテゴリごとの商品数と平均価格
SELECT category_id, count(*) AS n, avg(price)::int AS avg_price
FROM products
GROUP BY category_id
ORDER BY category_id;
--  category_id | n | avg_price
-- -------------+---+----------
--            1 | 2 |      3000
--            2 | 1 |       150
--            3 | 1 |       980
--         NULL | 1 |      5000    ← NULL は 1 つのグループにまとまる
```

GROUP BY の後の SELECT には、**グループ化に使った列か、集約関数しか書けません**。グループ内で値が 1 つに決まらない列は表示しようがないからです。

```sql
SELECT category_id, name, count(*) FROM products GROUP BY category_id;
-- ERROR:  column "products.name" must appear in the GROUP BY clause
--         or be used in an aggregate function
```

> [!note] MySQL との違い
> MySQL 5.7 以降はデフォルトの `ONLY_FULL_GROUP_BY` モードで同様にエラーになります。古い MySQL や このモードを外した環境では、グループ内の「どれか 1 行」の値が黙って返るため、不定な結果のバグを生みがちでした。なお PostgreSQL は、主キーで GROUP BY した場合に限り、そのテーブルの他の列を SELECT に書くことを許します（関数従属性を認識するため）。

### 2.3 WHERE と HAVING の違い

- **WHERE**：グループ化 **前** の「元の行」を絞る
- **HAVING**：グループ化 **後** の「グループ」を絞る（集約関数を条件に使える）

```sql
-- 2026 年の注文だけを対象に（WHERE）、購入総額 3000 円以上のユーザー（HAVING）
SELECT o.user_id, sum(oi.quantity * oi.unit_price) AS total
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
WHERE o.ordered_at >= '2026-01-01'
GROUP BY o.user_id
HAVING sum(oi.quantity * oi.unit_price) >= 3000;
```

`WHERE sum(...) >= 3000` と書くとエラーになります。WHERE の時点ではまだ合計が計算されていないからです。この「いつ何が存在するか」は [[06_SQLの実行順序]] で整理します。HAVING に集約と無関係な条件（`HAVING user_id = 1`）を書くのは動きますが、WHERE で先に絞った方が集約対象が減って効率的です。

## 3. ウィンドウ関数の仕組み

ウィンドウ関数（Window Function）：各行について、関連する行の集まり（ウィンドウ）を見て計算し、**結果を行ごとに付け足す** 関数 です。`関数() OVER (...)` の形で書きます。

```sql
関数名(...) OVER (
  PARTITION BY 列   -- どの単位で区切るか（GROUP BY に相当、ただし行は減らない）
  ORDER BY 列       -- 区切りの中での並び順
  ROWS / RANGE ...  -- 並びの中で、どこからどこまでを計算対象にするか（フレーム）
)
```

```
GROUP BY category_id                    OVER (PARTITION BY category_id)
┌───────────────┐                       ┌───────────────────────────────┐
│ cat 1 | avg 3000 │  ← 行が減る       │ SQL入門        | cat 1 | 3000 │
│ cat 2 | avg 150  │                    │ DB設計の教科書 | cat 1 | 3000 │ ← 行は残り
│ cat 3 | avg 980  │                    │ ボールペン     | cat 2 |  150 │   値が付け足される
└───────────────┘                       │ USBケーブル    | cat 3 |  980 │
                                         └───────────────────────────────┘
```

```sql
SELECT name, category_id, price,
       round(avg(price) OVER (PARTITION BY category_id)) AS cat_avg,
       price - round(avg(price) OVER (PARTITION BY category_id)) AS diff
FROM products
WHERE category_id IS NOT NULL;
```

`sum` や `avg` などの通常の集約関数も、`OVER` を付ければウィンドウ関数として使えます。

### フレームのデフォルトに注意

`OVER` の中に `ORDER BY` を書くと、デフォルトのフレームは **「区切りの先頭から、現在の行（と同順位の行）まで」**（`RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`）になります。ORDER BY がなければ区切り全体です。つまり **ORDER BY を書くだけで `sum` が累計に変わります**。これは便利ですが、知らないと驚く挙動です。

## 4. ランキング：ROW_NUMBER / RANK / DENSE_RANK

同点の扱いが違う 3 つの順位関数があります。

```sql
SELECT name, score,
       row_number() OVER (ORDER BY score DESC) AS row_num,
       rank()       OVER (ORDER BY score DESC) AS rnk,
       dense_rank() OVER (ORDER BY score DESC) AS dense
FROM (VALUES ('A', 90), ('B', 85), ('C', 85), ('D', 70)) AS t(name, score);
--  name | score | row_num | rnk | dense
-- ------+-------+---------+-----+------
--  A    |    90 |       1 |   1 |     1
--  B    |    85 |       2 |   2 |     2
--  C    |    85 |       3 |   2 |     2
--  D    |    70 |       4 |   4 |     3
```

| 関数 | 同点のとき | 次の順位 | 用途 |
|---|---|---|---|
| `row_number()` | 必ず別の番号（どちらが先かは不定） | 連番 | 重複排除、ページング |
| `rank()` | 同じ順位 | 飛ぶ（1,2,2,4） | 競技の順位 |
| `dense_rank()` | 同じ順位 | 詰める（1,2,2,3） | 「上位 3 種類の価格帯」など |

### 実例：カテゴリごとの売上トップ N

「各グループの上位 N 件」は ウィンドウ関数の代表的な用途です。ウィンドウ関数は WHERE に直接書けないので、サブクエリ（または CTE）で包みます。

```sql
WITH sales AS (
  SELECT p.category_id, p.name, sum(oi.quantity * oi.unit_price) AS revenue
  FROM order_items oi
  JOIN products p ON p.id = oi.product_id
  GROUP BY p.category_id, p.name
),
ranked AS (
  SELECT *, row_number() OVER (PARTITION BY category_id ORDER BY revenue DESC) AS rn
  FROM sales
)
SELECT category_id, name, revenue FROM ranked
WHERE rn <= 2;
```

「各ユーザーの最新注文 1 件」も同じ形（`PARTITION BY user_id ORDER BY ordered_at DESC` で `rn = 1`）で書けます。

> [!note] PostgreSQL 独自の書き方
> 「各グループ 1 件」だけなら PostgreSQL 独自の `SELECT DISTINCT ON (user_id) ... ORDER BY user_id, ordered_at DESC` も使えます。MySQL にはないので、移植性を重視するなら ROW_NUMBER を使います。

## 5. 累計と前月比：SUM OVER / LAG

### 5.1 月別売上と累計

```sql
WITH monthly AS (
  SELECT date_trunc('month', o.ordered_at) AS month,
         sum(oi.quantity * oi.unit_price)  AS revenue
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.id
  GROUP BY 1                          -- SELECT の 1 列目でグループ化
)
SELECT month::date,
       revenue,
       sum(revenue) OVER (ORDER BY month) AS cumulative     -- 累計
FROM monthly
ORDER BY month;
```

集約（GROUP BY で月ごとに 1 行）→ ウィンドウ（月の行を残したまま累計）の 2 段構えがポイントです。

### 5.2 LAG で前月比

`lag(列, n)`：同じ区切りの中で **n 行前** の値を取る関数（デフォルト n=1）です。逆に後ろの行は `lead` で取れます。

```sql
WITH monthly AS ( /* 上と同じ */ 
  SELECT date_trunc('month', o.ordered_at) AS month,
         sum(oi.quantity * oi.unit_price)  AS revenue
  FROM orders o JOIN order_items oi ON oi.order_id = o.id
  GROUP BY 1
)
SELECT month::date,
       revenue,
       lag(revenue) OVER (ORDER BY month) AS prev,
       round(100.0 * revenue / lag(revenue) OVER (ORDER BY month), 1) AS mom_pct
FROM monthly
ORDER BY month;
-- 出力例
--    month    | revenue |  prev  | mom_pct
-- ------------+---------+--------+--------
--  2026-08-01 |  120000 |  NULL  |   NULL   ← 最初の月は前月がない
--  2026-09-01 |  150000 | 120000 |  125.0
--  2026-10-01 |  135000 | 150000 |   90.0
```

注意点が 3 つあります。

1. **`100.0 *` と小数を混ぜる**。`integer / integer` は整数除算になり、`135000 / 150000 = 0` になってしまいます。
2. **売上ゼロの月は行が存在しない**。注文がない月は GROUP BY の結果に出てこないので、lag は「前の行」＝前々月を見てしまいます。厳密には `generate_series` で月の一覧を作って LEFT JOIN します。
3. **前月が 0 だと 0 除算エラー**。`nullif(lag(...), 0)` で NULL にして避けます。

### 5.3 移動平均（フレーム指定）

```sql
-- 直近 3 か月の移動平均
avg(revenue) OVER (ORDER BY month ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
```

`ROWS` は「物理的な n 行」、`RANGE` は「値が同じ（または範囲内の）行」を単位にします。同じ値が並ぶ可能性があるときは、累計でも `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` と明示すると意図通りになります。

## 6. 再帰 CTE（軽く）

`WITH RECURSIVE` は、**自分自身の結果を参照して行を増やしていく** CTE です。「開始行（非再帰項）」と「1 段進める規則（再帰項）」を `UNION ALL` でつなぎ、新しい行が出なくなるまで繰り返します。

```sql
-- 2026 年の 12 か月を生成（売上ゼロの月を埋める土台に使える）
WITH RECURSIVE months(m) AS (
  SELECT date '2026-01-01'                       -- 開始行
  UNION ALL
  SELECT (m + interval '1 month')::date FROM months   -- 1 か月進める
  WHERE m < date '2026-12-01'                    -- 終了条件
)
SELECT m FROM months;
```

本領は **階層データ** の展開です。たとえばカテゴリに `parent_id` を持たせれば「家電 > PC周辺機器 > ケーブル」のような木構造を、根から葉まで 1 クエリでたどれます。終了条件を忘れたり、データが循環していると無限ループになるので、深さの上限を設けるのが定石です（PostgreSQL 14 以降は `CYCLE` 句で循環検出も可能）。なお連番の生成だけなら PostgreSQL の `generate_series()` の方が簡単です。

> [!note] MySQL との違い
> MySQL は 8.0 からウィンドウ関数・CTE（再帰含む）に対応しています。5.7 以前では使えないため、古い環境ではユーザー変数や自己結合で代用していました。

## よくある誤解・つまずき

- ❌ **`count(列)` は行数を数える** → ✅ NULL でない値の数です。行数は `count(*)`。
- ❌ **該当行がなければ `sum` は 0** → ✅ NULL になります。0 にしたいなら `coalesce(sum(x), 0)`。
- ❌ **ウィンドウ関数の結果を WHERE で絞れる** → ✅ ウィンドウ関数は WHERE より後に評価されるので書けません。サブクエリ / CTE で包んでから絞ります。
- ❌ **`sum(x) OVER (ORDER BY ...)` は全体合計** → ✅ ORDER BY を書くとデフォルトフレームが「先頭から現在行まで」になり累計になります。全体合計なら ORDER BY を外します。
- ❌ **前月比は `revenue / prev` で OK** → ✅ 整数どうしは整数除算。`100.0 *` を付け、0 除算と欠けた月にも注意します。

## まとめ

- 集約関数は複数行を 1 つの値にまとめる。`count(*)` は行数、`count(列)` は NULL 以外の数
- GROUP BY 後の SELECT にはグループ列と集約しか書けない。WHERE はグループ化前、HAVING は後を絞る
- ウィンドウ関数は行を減らさずに集計値を付け足す。PARTITION BY で区切り、ORDER BY で並べ、フレームで範囲を決める
- ランキングは ROW_NUMBER / RANK / DENSE_RANK、累計は SUM OVER、前月比は LAG
- 再帰 CTE は連番や階層の展開に使う。終了条件を必ず書く

## 確認クイズ

1. `SELECT count(*), count(category_id) FROM products;` の 2 つの値が違いました。何が分かりますか？
> [!tip]- 答え
> category_id が NULL の商品（カテゴリ未分類）があることが分かります。差がその件数です。count(*) は行を数え、count(列) は NULL でない値だけを数えます。

2. 「各ユーザーの最新の注文 1 件」を ROW_NUMBER で取り出す SQL を書いてください。
> [!tip]- 答え
> ```sql
> SELECT * FROM (
>   SELECT o.*, row_number() OVER (PARTITION BY user_id ORDER BY ordered_at DESC) AS rn
>   FROM orders o
> ) t
> WHERE rn = 1;
> ```
> ウィンドウ関数は WHERE で直接使えないのでサブクエリで包みます。

3. 月別売上に `sum(revenue) OVER (ORDER BY month)` を付けたら、全期間の合計ではなく少しずつ増える値になりました。なぜですか？
> [!tip]- 答え
> OVER に ORDER BY を書くと、デフォルトのフレームが「区切りの先頭から現在行まで」になるため累計になります。全期間合計を各行に付けたいなら `sum(revenue) OVER ()` と ORDER BY を外します。
