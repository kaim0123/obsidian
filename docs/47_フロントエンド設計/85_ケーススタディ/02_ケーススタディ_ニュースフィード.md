# ケーススタディ：ニュースフィード

## この章の目的

SNS のタイムラインのような **ニュースフィード** を、[[01_RADIOテンプレート]] に沿って設計する章です。無限スクロール・カーソルページネーション・仮想化・楽観的更新を、47 の各ノートの知識を組み合わせて使います。

---

## 1. R — 要件

| 種類 | 内容 |
|------|------|
| 機能 | 投稿の一覧を新しい順に表示 / 下までスクロールすると続きを読み込む / いいねできる |
| 非機能 | モバイル中心。数百件スクロールしてもカクつかない。初期表示が速い |
| a11y | キーボードで投稿間を移動でき、スクリーンリーダーで読める |
| 範囲外 | 投稿の作成・コメント・リアルタイム通知 |

---

## 2. A — 全体構成

```text
  FeedPage（ページ）
   └─ Feed（一覧・読み込み制御）          ← サーバー状態を購読
       ├─ FeedItem × N（1 件の表示）       ← Props だけで描画
       │    └─ LikeButton（いいね）        ← 楽観的更新
       └─ LoadMoreSentinel（末尾の目印）   ← 見えたら次ページを取得
```

- **サーバー状態**：投稿一覧（サーバー状態ライブラリでキャッシュ）
- **クライアント状態**：ほぼ無し（スクロール位置はブラウザ・ライブラリに任せる）
- **レンダリング**：最初のページは SSR、以降は CSR で追加取得

`Feed` はデータ取得と読み込み制御、`FeedItem` は表示だけ、と責務を分けます（[[01_コンポーネントの分割粒度と境界]]、[[10-2-Container-Presentational]]）。

---

## 3. D — データモデル

| エンティティ | 主なフィールド | 置き場所 |
|-------------|---------------|---------|
| Post | id, author, body, createdAt, likeCount, likedByMe | サーバー状態（ページ単位のキャッシュ） |
| User（作者） | id, name, avatarUrl | Post に埋め込み（表示専用） |
| FeedPage | items: Post[], nextCursor | サーバー状態 |

`likeCount` は **サーバーが真実の源** です。クライアントは楽観的に書き換えますが、最終的にはサーバーの値に合わせます（[[02_Single_Source_of_Truthと派生状態]]）。

---

## 4. I — インターフェース

### サーバー API

```text
GET  /feed?cursor=<opaque>&limit=20
  → { items: Post[], nextCursor: string | null }
POST /posts/:id/like     DELETE /posts/:id/like
```

**オフセット方式ではなくカーソル方式** にします。

| 方式 | 長所 | 短所 |
|------|------|------|
| オフセット（`?page=3`） | 任意のページに飛べる | 読んでいる間に新着が入ると、重複・抜けが起きる |
| カーソル（`?cursor=...`） | 新着が入っても重複しない | 任意ページへのジャンプはできない |

フィードは先頭に新着が増え続けるので、カーソル方式が向きます。

### コンポーネントの Props

```tsx
type FeedItemProps = {
  post: Post;
  onLikeToggle: (postId: string) => void;
};
```

`FeedItem` はデータ取得を知らず、Props だけで描画します（[[02_Propsはコンポーネントの公開API]]）。

---

## 5. O — 最適化と深掘り

### 無限スクロール

末尾の目印（sentinel）が画面に入ったら次ページを取得します。スクロールイベントを監視するより、`IntersectionObserver` のほうが軽量です。

```tsx
function LoadMoreSentinel({ onVisible }: { onVisible: () => void }) {
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => {
    const el = ref.current;
    if (!el) return;
    const io = new IntersectionObserver(([e]) => e.isIntersecting && onVisible());
    io.observe(el);
    return () => io.disconnect();
  }, [onVisible]);
  return <div ref={ref} aria-hidden="true" />;
}
```

### 仮想化

数百件を DOM に全部置くとメモリと描画が重くなります。**見えている範囲だけ DOM を作る仮想化**（TanStack Virtual など）を使います（[[03_パフォーマンスを設計で作り込む]]）。

| 仮想化する | 仮想化しない |
|-----------|-------------|
| 数百件以上になる | 数十件で止まる |
| 行の高さがおおむね計算できる | ブラウザの「ページ内検索」を必ず効かせたい |

### 楽観的更新（いいね）

押した瞬間に表示を変え、失敗したら元に戻します。

```text
  クリック → キャッシュの likedByMe / likeCount を即書き換え → POST
            成功: サーバーの値で上書き
            失敗: 書き換え前に戻してトースト表示
```

### アクセシビリティ

- 一覧は `role="feed"`、各投稿は `<article>` とし、`aria-setsize` / `aria-posinset` で位置を伝える（WAI-ARIA の feed パターン）
- 読み込み中は `aria-busy="true"` を付ける
- いいねボタンは `aria-pressed` で状態を伝える（[[02_アクセシビリティを部品設計に組み込む]]）

### エラー

次ページの取得失敗は一覧全体を壊さず、末尾に「再読み込み」ボタンを出します（[[04_エラー境界とフォールバックUI]]）。

---

## まとめ

- フィードは **サーバー状態が主役**。クライアント状態はほとんど持たない
- 新着が増え続けるデータには **カーソルページネーション**
- 無限スクロールは `IntersectionObserver`、大量件数は **仮想化**
- いいねは **楽観的更新 + 失敗時のロールバック**
- `role="feed"` と `aria-busy` で読み込み中の状態を伝える
