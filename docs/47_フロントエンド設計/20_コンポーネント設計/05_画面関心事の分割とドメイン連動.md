# 画面関心事の分割とドメイン連動

[[MOC_フロントエンド設計体系|📚 目次]] ｜ [[04_Atomic_Design|← 前へ]]

> [!abstract] この記事で分かること
> - 複雑な画面は異なる関心事の寄せ集めであること
> - 小さく分け・画面そのものを分ける・タスクベース UI が主流になりやすい理由
> - 項目の並び・グルーピングをソフトウェアの論理構造と揃える考え方（増田本）
>
> **前提**：部品の粒度は [[01_コンポーネントの分割粒度と境界]]。ドメイン連動の本論は [[09_画面とドメインオブジェクトの設計]]。アプリ層の分割は [[07_アプリケーション機能を組み立てる]]。

増田亨『現場で役立つシステム設計の原則』第7章のうち、**画面／UI 側**の要点を、既存のコンポーネント設計ノートとつなぐ形で整理します。

---

## 1. 複雑な画面は関心事が混ざっている

1つの画面に次が同居しがちです。

- 複数ロールの関心（登録・承認・照会）  
- 複数の業務かたまり（顧客・契約・請求）  
- 検索・一覧・詳細編集・副作用つき操作  

混ざったまま巨大コンポーネントや「何でもフォーム」にすると、変更理由が異なる改修が同じファイルに集まります（[[01_コンポーネントの分割粒度と境界]] の分割サインと同型）。

---

## 2. 小さな単位に分け、必要なら画面も分ける

| 方針 | 内容 |
|------|------|
| **関心事単位に考える** | 「この画面で利用者が一度にやりたいこと」は何か |
| **部品に分ける** | 変更理由・データのまとまりでコンポーネント境界を切る |
| **画面を分ける** | 1画面に載せきれない／役割が違うならルートやウィザードのステップに分ける |

アプリ層では参照／更新やシナリオに分ける（[[07_アプリケーション機能を組み立てる]]）。フロントでは **ルート・タブ・ステップ・独立パネル** として同じ分割を視覚に出す。

---

## 3. タスクベースのインターフェース

「1画面に全項目」から、「やりたいこと（タスク）ごとに画面／ダイアログ」へ寄る流れが増えています。

### 3.1 増えている2つの理由（増田本の整理）

1. **利用者の仕事が多様で、全部入り画面が認知負荷になる**  
2. **ソフトウェア側も関心事ごとに独立して変更・テストしたい**（画面分割＝変更単位の分割）

モバイルや権限の細分化も、タスク単位の画面と相性がよいです。

### 3.2 今後の主流としての位置づけ

タスクベースに分けると、画面の境界がドメインオブジェクト／ユースケースの境界に近づき、**画面とドメインの連動**（[[09_画面とドメインオブジェクトの設計]]）がしやすくなります。CRUD の「1リソース＝1巨大フォーム」は、関心事が単純なとき以外は見直し候補です。

---

## 4. 視覚表現と論理構造を揃える

| 画面（視覚） | ソフトウェア（論理） |
|--------------|----------------------|
| 項目の並び順 | フィールド・値オブジェクトの提示順、フォームスキーマの順 |
| 枠・見出しでのグルーピング | オブジェクトのまとまり、埋め込み VO、セクション用の型 |
| 画面／ステップの分割 | 関心事・シナリオ・集約の操作単位 |

デザインカンプとドメインモデルを別々に固めてから無理に合わせるより、**ずれを見つけたら両方を少しずつ直す**方が、用語と構造が安定します。デザインシステムの「いつ Dialog / Drawer を使うか」といった判断ルール（[[01_デザインシステムの構成要素]]）も、タスク単位の分割とセットで効きます。

### 4.1 表示判断はドメイン寄り、当て方は UI

状態に応じた強調（警告色・disabled）の **判定** はドメイン／共有の表示モデルへ寄せ、コンポーネントは class や variant を当てるだけ、という分担が安全です（詳細は [[09_画面とドメインオブジェクトの設計]]）。API の DTO を画面に直結しない話は [[02_APIレイヤと型の共有]]。

### 4.2 画面以外の利用者向け情報

帳票・メール・通知・空状態のコピーも、同じグルーピングと業務用語に揃えると、フロントだけのローカル用語が増えにくくなります（[[02_ユビキタス言語]]）。

---

## まとめ

- 複雑な画面＝関心事の混在。小さく分け、必要なら画面自体を分ける  
- タスクベース UI は利用者にも開発にも分割の単位を与える  
- 並び・グループ・画面分割をドメイン／シナリオと連動させ、ずれを改善の手がかりにする
