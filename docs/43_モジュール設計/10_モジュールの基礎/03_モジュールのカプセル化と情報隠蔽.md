# モジュールのカプセル化と情報隠蔽

## この章の目的

モジュールの **内部を隠し、必要な操作だけを公開する** — カプセル化と情報隠蔽 — をモジュール設計の視点で学びます。  
[[06_カプセル化と情報隠蔽]] の内容を、パッケージ・ディレクトリ単位に適用します。

---

## 1. カプセル化の目的

**カプセル化** とは、モジュールの **内部実装を隠し**、決めた **公開面（API）** だけを外に見せることです。

| 目的 | 効果 |
|------|------|
| 変更の自由 | 内部を書き換えても、公開 API が同じなら外は無傷 |
| 理解のしやすさ | 外から見る情報量が減る |
| 誤用の防止 | 触ってはいけない内部にアクセスできない |

```text
  ┌─────────────────────────┐
  │      Order Module       │
  │  ┌───────────────────┐  │
  │  │  公開 API         │  │ ← 外から見える
  │  │  createOrder()    │  │
  │  │  cancelOrder()    │  │
  │  └───────────────────┘  │
  │  ┌───────────────────┐  │
  │  │  内部（非公開）    │  │ ← 隠す
  │  │  SQL, 計算詳細    │  │
  │  └───────────────────┘  │
  └─────────────────────────┘
```

---

## 2. 公開すべきもの・隠すべきもの

| 公開する | 隠す |
|---------|------|
| ユースケースを表す関数・クラス | DB スキーマの詳細 |
| ドメインの型（必要な範囲） | 内部ヘルパー・ユーティリティ |
| エラー型・結果型 | フレームワーク固有の実装 |
| 設定の **インターフェース** | 接続文字列・認証情報の具体 |

**ルール**: 「外のモジュールが知る必要があるか？」で判断する。

---

## 3. 内部表現の変更を安全にする

内部表現が変わっても、公開 API が安定していれば **他モジュールへの影響はない** はずです。

### 例: 注文の永続化

```text
  内部変更前: CSV ファイルに保存
  内部変更後: PostgreSQL に保存

  公開 API: save(order), findById(id)  ← 変わらない
       │
       ▼
  呼び出し側モジュールは変更不要
```

これが情報隠蔽の力です。**内部表現の変更理由** をモジュール内に閉じ込めます。

---

## 4. 漏れ出す詳細（Leaky Abstraction）の危険性

**Leaky Abstraction（漏れ出す抽象化）** とは、隠すはずの詳細が公開 API や型を通じて外に漏れる状態です。

| 漏れの例 | 問題 |
|---------|------|
| ORM の Entity をそのまま公開 | DB 構造変更が全体に波及 |
| `SQLException` をそのまま throw | DB 依存が呼び出し側に伝播 |
| 内部用 DTO を export | 意図しない依存が生まれる |

```typescript
// 漏れている（悪い例）
export class OrderEntity {  // DB カラムと 1:1
  dbRow: RawDbRow;
}

// 隠蔽できている（良い例）
export class Order {  // ドメインの概念だけ
  readonly id: OrderId;
  cancel(): void;
}
```

## 5. カプセル化の実践例

### ディレクトリで表現

```text
order/
  index.ts          ← 公開 API のみ re-export
  domain/           ← 内部（export しない）
  infra/            ← 内部
  application/      ← ユースケース（公開する場合あり）
```

### 言語機能

| 言語 | 手段 |
|------|------|
| Java | `public` / package-private |
| TypeScript | `export` の有無、 barrel file |
| Python | `_` プレフィックス、`__all__` |
| Go | 小文字 = パッケージ外非公開 |

**package.json** の `"exports"` や **モジュール境界 linter**（依存方向チェック）も有効です。

---

## まとめ

- **カプセル化** = 内部を隠し、公開 API だけを見せる
- 公開は「外が知る必要があるもの」だけに絞る
- 内部表現の変更をモジュール内に閉じ込められる
- **Leaky Abstraction** — 内部詳細の漏れ — に注意する
