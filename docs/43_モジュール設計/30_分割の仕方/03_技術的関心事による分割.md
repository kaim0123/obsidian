# 技術的関心事による分割

## この章の目的

**技術的な関心**（UI、DB、ログなど）でモジュール・レイヤーを分ける方法を学びます。  
ドメイン分割との **バランス** が、この章の要点です。

---

## 1. 関心事の分離（Separation of Concerns）

**関心事の分離（SoC）** とは、**異なる関心を別の場所に置く** ことです。

| 関心 | 例 |
|------|-----|
| 業務ルール | 注文のキャンセル条件 |
| 表示 | HTML / JSON の組み立て |
| 永続化 | DB への保存 |
| 外部連携 | 決済 API |

[[04_関心の分離]] をモジュールレベルで適用します。

```text
  1 ファイルに全部          関心ごとに分離
  ──────────────          ──────────────
  order_controller.rb       order/domain/
  + SQL + メール            order/infra/
                            web/controllers/
```

---

## 2. プレゼンテーション層・ビジネス層・データ層

古典的な **3 層** 分割は、モジュール設計の基本パターンです。

| 層 | 責務 | モジュール例 |
|----|------|-------------|
| **プレゼンテーション** | HTTP、UI、入力検証 | `web`, `api` |
| **ビジネス（アプリケーション）** | ユースケースの orchestration | `order/application` |
| **データ（インフラ）** | DB、外部 API | `order/infra` |

```text
  [Presentation]  →  [Application]  →  [Infrastructure]
       │                  │                    │
    HTTP 受付          ユースケース           DB / 外部 API
```

詳細は [[02_レイヤードアーキテクチャのモジュール構成]] を参照。

---

## 3. 横断的関心事（ログ・認証・エラー処理）

**横断的関心事** とは、多くのモジュールにまたがる機能です。

| 関心事 | 分割の選択肢 |
|--------|-------------|
| ログ | 共通ライブラリ + 各モジュールから呼ぶ |
| 認証 | 専用 `auth` モジュール |
| エラー処理 | 共通の Error 型 + 各層で変換 |
| トランザクション | アプリケーション層で境界を張る |

```text
  悪い例: 各モジュールにコピペのログコード
  良い例: logging モジュールを薄く依存（インターフェース経由）
```

**注意**: 横断関心事を **1 つの巨大 common** にしない（[[01_凝集度]]）。

---

## 4. インフラとドメインの分離

**ドメイン**（業務ルール）と **インフラ**（技術詳細）を分離します。

| ドメイン側 | インフラ側 |
|-----------|-----------|
| Order エンティティ | PostgresOrderRepository |
| ビジネスルール | REST API クライアント |
| ポート（インターフェース） | アダプタ（実装） |

```text
  order/
    domain/       ← フレームワーク非依存
    application/
    infra/        ← DB, HTTP など
```

[[03_ヘキサゴナルアーキテクチャのモジュール構成]] がこの分離を体系化しています。

---

## 5. 技術分割とドメイン分割のバランス

| アプローチ | 強み | 弱み |
|-----------|------|------|
| **ドメイン分割** | 業務理解・チーム分担 | 層の混在リスク |
| **技術分割** | 技術の差し替え・統一 | 1 機能が複数フォルダに散らばる |

**推奨**: **ドメインを主軸** にし、**各ドメインモジュール内** で層を分ける。

```text
  推奨構造
  order/
    domain/
    application/
    infra/
  payment/
    domain/
    application/
    infra/

  非推奨（機能が散らばる）
  controllers/order_controller
  services/order_service
  repositories/order_repository
```

---

## まとめ

- **SoC** で UI・業務・永続化・外部連携を分ける
- **3 層** はモジュール内のサブ構造として使う
- **横断的関心事** は専用モジュール + 薄い依存で
- **ドメイン主軸 + モジュール内レイヤー** がバランスの取れた形
