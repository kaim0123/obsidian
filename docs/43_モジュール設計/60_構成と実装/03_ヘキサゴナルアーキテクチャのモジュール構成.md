# ヘキサゴナルアーキテクチャのモジュール構成（ポートとアダプタ）

> この章は「ポートとアダプタをモジュール・ディレクトリにどう落とし込むか」を扱います。スタイル自体の説明は 41 の [[ヘキサゴナルアーキテクチャ]]・[[クリーンアーキテクチャの概要]] を参照してください。

## この章の目的

**ヘキサゴナルアーキテクチャ**（ポートとアダプタ）で、ドメインを **中心** に置き、外部を **差し替え可能** にする構造を学びます。

---

## 1. コアと外部の分離

ヘキサゴナルでは、アプリケーションを **コア（ドメイン + アプリケーション）** と **外部（UI, DB, 外部サービス）** に分けます。

```text
              ┌──────────────┐
    HTTP ────→│   Adapter    │
              │      ↓       │
              │   [ Port ]   │  ← コアが定義
              │      ↓       │
              │    Domain    │  ← 中心
              │      ↑       │
              │   [ Port ]   │
    DB   ────→│   Adapter    │
              └──────────────┘
```

| 部分 | 内容 |
|------|------|
| **コア** | 業務ルール。外部技術に依存しない |
| **外部** | 入出力の詳細。コアの **ポート** を **実装** |

---

## 2. ポートの設計

**ポート** = コアが外部に要求する **インターフェース**（[[02_依存関係の管理]] の DIP）。

| 種類 | 方向 | 例 |
|------|------|-----|
| **Driving（Primary）** | 外 → コア | `PlaceOrderUseCase` の入口 |
| **Driven（Secondary）** | コア → 外 | `OrderRepository`, `PaymentGateway` |

```typescript
// Driven Port（コアが定義）
interface PaymentGateway {
  charge(amount: Money, customerId: CustomerId): Promise<PaymentId>;
}

// Driving Port（ユースケースそのもの）
interface PlaceOrderPort {
  placeOrder(cmd: PlaceOrderCommand): Promise<OrderId>;
}
```

---

## 3. アダプタの役割

**アダプタ** = ポートの **具体実装**。外部技術をコアの言語に **翻訳** します。

| アダプタ | 例 |
|---------|-----|
| Web Adapter | REST Controller → UseCase 呼び出し |
| DB Adapter | PostgresOrderRepository |
| External API Adapter | StripePaymentGateway |

```text
  REST Controller（Adapter）
       │ HTTP JSON → Command
       ▼
  PlaceOrderUseCase（Core）
       │
       ▼
  StripeGateway（Adapter）→ Stripe API
```

**新しい UI（CLI, gRPC）** を足すとき、コアはそのまま、アダプタだけ追加します。

---

## 4. テストしやすさとの関係

ヘキサゴナルは **テスト容易性** と相性が良いです。

| テスト | 方法 |
|--------|------|
| ドメイン単体 | ポートなし、純粋な Entity / DomainService |
| ユースケース | ポートを **Fake / Mock** で差し替え |
| アダプタ | 統合テストで DB / API と接続 |

```text
  UseCase テスト
  ┌─────────────────────────┐
  │ PlaceOrderUseCase       │
  │   + FakePaymentGateway  │
  │   + InMemoryOrderRepo   │
  └─────────────────────────┘
  → DB なしで実行可能
```

[[01_テストしやすいモジュール設計]] と合わせて読むと理解が深まります。

---

## まとめ

- **ヘキサゴナル** = コア（ドメイン）中心 + ポート/アダプタ
- **ポート** はコアが定義する契約（Driving / Driven）
- **アダプタ** が HTTP, DB, 外部 API を接続
- ポートの差し替えで **テスト・技術変更** がしやすい
