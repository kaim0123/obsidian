# 付録C　よくあるアンチパターン一覧

モジュール設計で避けるべき典型パターンです。

---

## 1. 大泥団（Big Ball of Mud）

| 症状 | 境界がなく、すべてが相互依存 |
| 対策 | ドメイン単位で段階的分割（[[04_モジュール設計の進化]]） |

---

## 2. 巨大 common / util モジュール

| 症状 | 無関係な処理が `common` に集まる |
| 対策 | 機能的凝集で本来のモジュールへ移す（[[01_凝集度]]） |

---

## 3. 共有データベース

| 症状 | 複数モジュールが同一テーブルに直接 SQL |
| 対策 | Repository 経由、Query API、スキーマ分離（[[03_データの受け渡しと共有]]） |

---

## 4. 循環依存

| 症状 | order ↔ payment の相互 import |
| 対策 | 第 3 モジュール抽出、DIP、イベント（[[02_依存関係の管理]]） |

---

## 5. レイヤー違反

| 症状 | Controller が SQL 直実行、Domain が ORM 依存 |
| 対策 | レイヤー依存ルール + CI（[[02_レイヤードアーキテクチャのモジュール構成]]） |

---

## 6. 漏れ出す抽象化（Leaky Abstraction）

| 症状 | ORM Entity、SQLException がモジュール境界を越える |
| 対策 | DTO / ドメイン型で変換、infra に閉じ込め（[[03_モジュールのカプセル化と情報隠蔽]]） |

---

## 7. 神サービス / 神モジュール

| 症状 | 1 モジュールが全ユースケースを担当 |
| 対策 | 責務分割、変化の理由で分ける（[[01_モジュール分割の基本プロセス]]） |

---

## 8. 過剰分割（Premature Microservices）

| 症状 | 小規模なのにサービスが乱立、Distributed Monolith |
| 対策 | まずモノリス内モジュール化（[[04_マイクロサービスとモノリスのモジュール設計]]） |

---

## 9. 技術名だけのトップ構造

| 症状 | `controllers/`, `services/`, `models/` だけでドメインが見えない |
| 対策 | ドメイン主軸 + モジュール内レイヤー（[[03_技術的関心事による分割]]） |

---

## 10. 巨大 integration モジュール

| 症状 | すべての外部連携が 1 モジュールに集中 |
| 対策 | 各ドメインの infra にアダプタを配置 |

---

## 対策の優先順位

```text
  1. 循環依存・共有 DB の解消（結合度）
  2. common 肥大化の分解（凝集度）
  3. レイヤー違反・Leaky Abstraction
  4. 命名・ディレクトリの整理
```
