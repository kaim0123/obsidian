# 凝集度（Cohesion）

## この章の目的

モジュールの **中身がどれだけ一つの目的にまとまっているか** — すなわち **凝集度** — を学びます。  
[[05_凝集度と結合度]] のモジュール版として、分割判断の物差しになります。

---

## 1. 凝集度とは何か

**凝集度（Cohesion）** とは、1 つのモジュール内の要素が **どれだけ関連した目的のために集まっているか** を表す指標です。

| 凝集度 | 状態 | モジュール例 |
|--------|------|-------------|
| **高い** | 1 つの関心・責務に集中 | `billing` — 請求関連だけ |
| **低い** | 無関係な処理が混在 | `misc` — 日付・メール・CSV が同居 |

```text
  高凝集                      低凝集
  ──────                      ──────
  [Order Module]              [Utils Module]
   ・注文作成                   ・日付フォーマット
   ・明細管理                   ・メール送信
   ・合計計算                   ・ファイルアップロード
```

**凝集度は高いほどよい** とされます（[[02_結合度]] とセットで覚える）。

---

## 2. 凝集度が低いときに起きる問題

| 問題 | 具体例 |
|------|--------|
| 変更範囲が読めない | メール仕様変更のつもりが、無関係な CSV 処理まで触る |
| 名前が意味を失う | `common` / `util` / `helper` が肥大化 |
| テストが難しい | 1 モジュールのテストに無関係な依存が必要 |
| 再利用しにくい | 必要な機能だけ取り出せない |

```text
  低凝集モジュール
       │
       ├─→ 変更のたびに「どこまで触る？」が不明
       ├─→ 新機能が「とりあえず common に」で追加される
       └─→ モジュールが肥大化 → さらに低凝集
```

---

## 3. 機能的凝集を目指す

凝集度にはいくつかのレベルがありますが、モジュール設計では **機能的凝集（Functional Cohesion）** を目指します。

**機能的凝集** = モジュール内のすべてが **1 つの明確な機能・責務** を実現するために存在する状態です。

| レベル（低→高） | 説明 |
|----------------|------|
| 偶発的 | 関連性なしでたまたま同じ場所 |
| 論理的 | カテゴリだけ共通（すべて「ユーティリティ」） |
| 時間的 | 同じタイミングで実行されるだけ |
| 手続き的 | 処理順序だけ共通 |
| 通信的 | 同じデータを扱う |
| 順次的 | 出力が次の入力になる |
| **機能的** | **1 つの機能を完結** |

---

## 4. 凝集度を高めるための分割の考え方

### 手順

1. モジュールの **1 文説明** を書く（「このモジュールは ○○ を担当する」）
2. 説明に **含まれない処理** をリストアップする
3. 含まれない処理を **別モジュールへ移す** か、新モジュールを作る

### 例: `order` モジュール

```text
  Before                          After
  ──────                          ─────
  order/                          order/     … 注文の業務ルール
   ・注文作成                      notification/ … 注文完了メール
   ・注文メール送信                payment/   … 決済連携
   ・決済 API 呼び出し
```

### 注意

- **分割しすぎ** も問題（[[01_モジュール分割の基本プロセス]] 参照）
- 2〜3 回の変更で一緒に触る処理は、**同じモジュールに残す** こともある

---

## 5. 凝集度のチェックリスト

- [ ] このモジュールを **1 文** で説明できるか
- [ ] モジュール内のファイルは **同じ変化の理由** を持つか
- [ ] `util` / `common` / `misc` に **無関係な機能** が溜まっていないか
- [ ] 新機能追加時、「ここに置く理由」を **言語化** できるか
- [ ] モジュール単体で **テストの意味** があるか

詳細チェックは [[010Programming/43_モジュール設計/90_付録/付録B_チェックリスト]] も参照。

---

## まとめ

- **凝集度** = モジュール内のまとまりの強さ（高いほどよい）
- 低凝集は変更範囲の不明瞭・肥大化・テスト困難を招く
- **機能的凝集** — 1 つの明確な責務 — を目指す
- 1 文説明と「含まれない処理」の洗い出しで分割を判断する
