# データの受け渡しと共有

## この章の目的

モジュール間で **何をどう渡すか**、**共有してはいけないもの** を学びます。  
密結合の典型である **共有 DB** や **巨大 DTO** の問題も扱います。

---

## 1. モジュール間で何を渡すべきか

| 渡すもの | 向いている場面 |
|---------|---------------|
| **プリミティブ + ID** | 参照だけ必要（`orderId: string`） |
| **DTO（データ転送オブジェクト）** | 読み取り専用のスナップショット |
| **コマンド / クエリオブジェクト** | 意図が明確な操作 |
| **ドメインオブジェクト** | 同一境界内、または慎重に設計した共有 |

```text
  避けたい: 相手モジュールの Entity をそのまま mutate
  推奨:     ID または読み取り専用 DTO
```

**原則**: 相手の **内部状態** を直接触らない。

---

## 2. DTO・値オブジェクト・エンティティの使い分け

| 種類 | 特徴 | モジュール間 |
|------|------|-------------|
| **DTO** | 平坦、シリアライズ向き | API 境界でよく使う |
| **値オブジェクト** | 不変、値で等価 | 共有可能（小さく安定） |
| **エンティティ** | ID で同一性、ライフサイクル | **原則モジュール内** |

```typescript
// モジュール境界での DTO
interface OrderSummaryDto {
  orderId: string;
  status: string;
  totalAmount: number;
}

// モジュール内部の Entity（export しない）
class Order {
  cancel(): void { /* 業務ルール */ }
}
```

詳細は [[010Programming/44_クラス設計・デザインパターン/00_全体像/目次]] で深掘りします。

## 3. 共有データベースの落とし穴

**複数モジュールが同じ DB テーブルを直接読み書き** するのは、アンチパターンです。

| 問題 | 説明 |
|------|------|
| スキーマ変更の連鎖 | 1 テーブル変更が全モジュールに波及 |
| 整合性の責任が不明 | 誰がトランザクションを張るか |
| 境界の消失 | モジュール分割の意味が薄れる |

```text
  アンチパターン
  [Order Module] ──→ orders テーブル ←── [Report Module]
                           ↑
                    直接 SQL で共有

  改善
  [Order Module] ──→ OrderRepository（唯一の書き込み）
  [Report Module] ──→ OrderQuery API または 読み取りレプリカ
```

---

## 4. イベントとメッセージによる連携

**同期呼び出し** の代わりに **イベント** で疎結合にできます。

```text
  Order Module                    Payment Module
       │                                │
       │  OrderPlacedEvent              │
       └──────── publish ──────────────→│ subscribe
                                        │ charge()
```

| 方式 | 向く場面 |
|------|---------|
| 同期 API | 即座の結果が必要（在庫確認など） |
| イベント | 副作用・通知・他コンテキスト連携 |
| メッセージキュー | 非同期・耐障害性が必要 |

[[01_イベント駆動を学ぶ理由|42 / 40_イベント駆動設計]] も参照。

---

## 5. 整合性とトランザクション境界

**1 トランザクション** で整合性を保てる範囲 = 通常 **1 集約・1 モジュール内** です。

| パターン | 説明 |
|---------|------|
| 単一モジュール内 TX | 注文作成 + 明細保存 |
| 分散 TX（2PC） | 複雑・避けがち |
| **結果整合性** | イベント +  eventual consistency |

```text
  Order モジュール内（強整合）
  ┌─────────────────────┐
  │ TX: Order + Lines   │
  └─────────────────────┘

  Order → Payment（結果整合）
  OrderPlaced → 非同期で決済 → PaymentCompleted
```

---

## まとめ

- モジュール間は **ID・DTO・コマンド** を渡し、内部 Entity を共有しない
- **共有 DB 直接アクセス** は密結合の温床
- **イベント** で疎結合連携（結果整合性を理解した上で）
- **トランザクション境界** = 集約・モジュール単位が基本
