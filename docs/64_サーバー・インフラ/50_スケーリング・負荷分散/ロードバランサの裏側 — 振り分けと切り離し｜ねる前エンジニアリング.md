## 詳しい要約

**テーマ：ロードバランサの振り分け方と、壊れた先・止める先の切り離し方**

ロードバランサ（負荷を振り分ける役）は入口を1つにまとめ、後ろのどのサーバーに渡すかを決める。前半は振り分けの決め方（順番に配る・空いている所へ・同じ人は同じ所へ）、後半はヘルスチェックで倒れたサーバーを切り離して戻す流れと、新しい版を出すときにエラーを出さずに入れ替える手順を扱う。

---

### よくある場面

- セール開始の瞬間にアクセスが一気に来て、1台では受け切れない
- 台数を増やしたのに、1台だけがやけに重い（振り分け方の問題）
- 新しい版を出すたびに数秒だけエラーが出る（「少しだけならいい」と放っておかないのが品質に責任を持つこと）

### 1台に全部が集まる → 入口に振り分け役を置く

- 1台のサーバーが同時にさばける数（例：6つ）を超えると、溢れた分は待たされるか間に合わずエラーになる。その1台が止まれば全員が使えない
- 1台に頼ると「遅い」と「止まる」の2つが困る → サーバーを複数台並べる
- 利用者に複数の住所を教えるのは大変なので、真ん中に**ロードバランサ**を置き、入口を1つにする。利用者からはサーバーが1台に見える
- 振り分け役は自分では処理せず、受付のように窓口へ案内するだけ

### 振り分けの決め方

| 決め方 | 名前 | 特徴・弱点 |
|---|---|---|
| 順番に配る | **ラウンドロビン** | 数は公平。依頼の重さが同じならうまくいくが、重い依頼が1台に続けて当たるとその1台だけ積み上がる（重さは見ていない）。性能の違うサーバーが混ざるときは強い所に多めに配る**重み**をつける |
| 空いている所へ | **最小接続数** | 各サーバーの処理中の数を覚えておき（渡したら+1、返事が来たら−1）、一番少ない所へ渡す。重い依頼で詰まった所を自然に避け、重さの違いに後から追いつく。多くの場面で良い選択だが、数える手間がかかる。また壊れてすぐエラーを返すサーバーは処理中の数が少なく見え、**早く失敗する所に依頼が集まる**危険がある |
| 同じ人は同じ所へ | （同じ利用者をいつも同じサーバーへ） | ログイン中の情報などをサーバーの記憶に置いている場合に使う。弱点は、偏りやすいことと、そのサーバーが止まると別のサーバーは利用者を知らず、ログインし直しやカートの中身が消えることがある。今は記憶を**共有の置き場**に出し、どのサーバーでも同じ記憶を読めるようにする作りが多い |

### 1台が倒れたとき → ヘルスチェックで切り離す

- 何もしなければ振り分け役は気づかず、倒れたサーバーにも渡し続ける。3台中1台が倒れると**3回に1回エラー**になり、利用者にはどのサーバーかは見えない
- **ヘルスチェック**：振り分け役が数秒ごとに各サーバーへ「元気？」と小さな依頼を送り、決まった時間内に返事があれば合格
- 1回失敗しただけでは外さない（たまたま遅れただけかもしれない）。決めた回数（例：3回）**続けて失敗**したら切り離し、以降は残りのサーバーにだけ配る
- 気づくまでの間はエラーが出ている。間隔5秒×3回ならおよそ15秒は気づけない（気づくまでの時間＝間隔×回数）
- 間隔を短く・回数を少なくすると、少し遅れただけで外してしまう。外しすぎると残りの台に依頼が集まってそこも倒れる。早すぎても遅すぎても困る

### 様子見の窓口と、浅い確認・深い確認

- サーバー側に様子見のための窓口を用意する。最短の形は呼ばれたら `200`（成功）で OK を返すだけ
- 浅い確認はプログラムが動いて返事ができることは分かるが、DBにつながらなくなっていても OK を返してしまう
- 深い確認はDBに一言聞いてみて、答えがあれば `200`、なければ `503`（使えない）を返す。DBの不調にも気づける
- ただしDBが全体で止まると、全サーバーが揃って「使えない」と答え、振り分け役が**全部を切り離して誰も使えなくなる**

| | 浅い確認 | 深い確認 |
|---|---|---|
| 見るもの | 返事ができるか | DBなども使えるか |
| 重さ | 軽い | 確かめる分重い |
| 弱点 | つながる先の不調を見落とす | 共通の先が止まると全部外れる |

- どちらが正解ということはなく、現場では使い分けたり組み合わせたりする。**外したら何が起きるか**を先に考えて何を確かめるか決める

### 戻すとき・入れ替えるとき

- 切り離した後も様子見の依頼は送り続けるので、直ったことにも気づける。決めた回数続けて成功したら戻す。外すのも戻すのも振り分け役が自動で行う
- 新しい版を出すときは1台ずつ止めて入れ替えるが、いきなり止めると処理中だった依頼が途中で切れる（**出すたびに数秒だけ出るエラーの正体**）
- 正しい順：まず新しい依頼を送るのをやめる → 手元の処理中の分だけ片付ける → 処理中が0になってから止めて入れ替える。これを1台ずつ繰り返せば止めずに入れ替えられる
- 外すのは壊れたときだけではない

### AIに設定を書かせたとき見るところ

1. 様子見の窓口が何を確かめているか（OK を返すだけか、DBまで見るか）
2. 続けて何回で外すか、間隔は何秒か
3. 止めるときに手元の依頼を待っているか（待つ時間がゼロだと出すたびにエラーが出る）
4. ログインなどの記憶をサーバーの中に置いていないか（止まったときに消える）
- AIは動く設定は書けるが、壊れたときの動きはこちらが聞かないと考えてくれないことが多い。「1台倒れたらどうなる？」と聞くのが大事

### まとめ

- 振り分け役は入口を1つにして、渡す先を決める
- 決め方は、順番に・空いている所へ・同じ人は同じ所へ。重さが違うなら空いている所へ
- 様子見が続けて失敗したら外し、続けて成功したら戻す。気づくまでの時間は間隔×回数
- 止めるときは、まず新しい依頼を止めて手元を片付ける
- 製品ごとの設定画面は知らなくてよい。名前や画面は違っても考え方は同じ
