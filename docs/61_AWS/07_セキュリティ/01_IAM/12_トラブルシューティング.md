# トラブルシューティング

## 概要

このドキュメントでは、IAMの設定や運用において発生する可能性のある問題とその解決方法を説明します。よくある問題から複雑な問題まで、段階的なアプローチで解決策を提供します。

## 認証関連の問題

### 1. ログインできない

#### 問題: パスワードが正しくない
```
エラーメッセージ: "Invalid password"
原因: パスワードが間違っている、または期限切れ
```

**解決方法:**
```bash
# パスワードのリセット
aws iam update-login-profile \
    --user-name john-doe \
    --password 'NewPassword123!' \
    --password-reset-required

# パスワードポリシーの確認
aws iam get-account-password-policy
```

#### 問題: MFAトークンが無効
```
エラーメッセージ: "Invalid MFA token"
原因: MFAデバイスの時刻同期問題、またはトークンの期限切れ
```

**解決方法:**
```bash
# MFAデバイスの再同期
aws iam resync-mfa-device \
    --user-name john-doe \
    --serial-number arn:aws:iam::123456789012:mfa/john-doe-mfa \
    --authentication-code1 123456 \
    --authentication-code2 789012

# MFAデバイスの状態確認
aws iam list-mfa-devices --user-name john-doe
```

#### 問題: アカウントがロックされている
```
エラーメッセージ: "Account is locked"
原因: 複数回のログイン失敗によるアカウントロック
```

**解決方法:**
```bash
# アカウントのアンロック（管理者権限が必要）
aws iam update-login-profile \
    --user-name john-doe \
    --password 'NewPassword123!' \
    --password-reset-required

# ログイン履歴の確認
aws cloudtrail lookup-events \
    --lookup-attributes AttributeKey=Username,AttributeValue=john-doe
```

### 2. アクセスキーの問題

#### 問題: アクセスキーが無効
```
エラー: "InvalidAccessKeyId: The AWS Access Key Id you provided does not exist"
原因: アクセスキーが削除されている、または無効化されている
```

**解決方法:**
```bash
# アクセスキーの状態確認
aws iam list-access-keys --user-name john-doe

# 新しいアクセスキーの作成
aws iam create-access-key --user-name john-doe

# 古いアクセスキーの削除
aws iam delete-access-key \
    --user-name john-doe \
    --access-key-id AKIAIOSFODNN7EXAMPLE
```

#### 問題: シークレットキーが無効
```
エラー: "SignatureDoesNotMatch: The request signature we calculated does not match"
原因: シークレットキーが間違っている、またはアクセスキーと一致しない
```

**解決方法:**
```bash
# アクセスキーの再作成
aws iam create-access-key --user-name john-doe

# 環境変数の更新
export AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
export AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

## 権限関連の問題

### 1. アクセス拒否エラー

#### 問題: 権限不足
```
エラー: "AccessDenied: User is not authorized to perform: s3:GetObject"
原因: 必要な権限が付与されていない
```

**解決方法:**
```bash
# 現在の権限の確認
aws iam list-attached-user-policies --user-name john-doe
aws iam list-user-policies --user-name john-doe
aws iam get-groups-for-user --user-name john-doe

# 必要なポリシーのアタッチ
aws iam attach-user-policy \
    --user-name john-doe \
    --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess

# ポリシーのシミュレーション
aws iam simulate-principal-policy \
    --policy-source-arn arn:aws:iam::123456789012:user/john-doe \
    --action-names s3:GetObject \
    --resource-arns arn:aws:s3:::my-bucket/object.txt
```

#### 問題: 明示的なDeny
```
エラー: "AccessDenied: Explicit deny in policy"
原因: ポリシーで明示的にアクセスが拒否されている
```

**解決方法:**
```bash
# ポリシーの確認
aws iam get-policy-version \
    --policy-arn arn:aws:iam::123456789012:policy/MyPolicy \
    --version-id v1

# Denyポリシーの特定と修正
# ポリシーを確認し、不要なDenyステートメントを削除
```

#### 問題: 条件が満たされていない
```
エラー: "AccessDenied: Not authorized to perform this action"
原因: ポリシーの条件が満たされていない
```

**解決方法:**
```bash
# 条件の確認
aws iam simulate-principal-policy \
    --policy-source-arn arn:aws:iam::123456789012:user/john-doe \
    --action-names s3:GetObject \
    --resource-arns arn:aws:s3:::my-bucket/object.txt \
    --context-entries ContextKeyName=aws:SourceIp,ContextKeyValues=203.0.113.12,ContextKeyType=string

# 条件の調整
# ポリシーの条件を確認し、適切な値を設定
```

### 2. ロールの引き受けエラー

#### 問題: 信頼ポリシーの問題
```
エラー: "AccessDenied: User is not authorized to perform: sts:AssumeRole"
原因: 信頼ポリシーが正しく設定されていない
```

**解決方法:**
```bash
# 信頼ポリシーの確認
aws iam get-role --role-name MyRole

# 信頼ポリシーの修正
aws iam update-assume-role-policy \
    --role-name MyRole \
    --policy-document file://trust-policy.json
```

#### 問題: 外部IDの不一致
```
エラー: "AccessDenied: Invalid external ID"
原因: 外部IDが正しくない
```

**解決方法:**
```bash
# 正しい外部IDでロールを引き受け
aws sts assume-role \
    --role-arn arn:aws:iam::123456789012:role/MyRole \
    --role-session-name MySession \
    --external-id correct-external-id
```

#### 問題: セッション時間の超過
```
エラー: "AccessDenied: Session duration exceeded"
原因: セッション時間が最大値を超えている
```

**解決方法:**
```bash
# セッション時間の確認
aws iam get-role --role-name MyRole

# セッション時間の調整
aws iam update-role \
    --role-name MyRole \
    --max-session-duration 3600
```

## 監視とログ関連の問題

### 1. CloudTrailの問題

#### 問題: CloudTrailログが記録されない
```
症状: IAMイベントがCloudTrailに記録されない
原因: CloudTrailの設定が正しくない
```

**解決方法:**
```bash
# CloudTrailの状態確認
aws cloudtrail describe-trails

# CloudTrailの有効化
aws cloudtrail start-logging --name MyTrail

# ログ配信の確認
aws cloudtrail get-trail-status --name MyTrail
```

#### 問題: ログファイルの検証失敗
```
エラー: "Log file validation failed"
原因: ログファイルが改ざんされている、または破損している
```

**解決方法:**
```bash
# ログファイルの検証
aws cloudtrail validate-logs \
    --trail-arn arn:aws:cloudtrail:us-east-1:123456789012:trail/MyTrail \
    --start-time 2024-01-01T00:00:00Z \
    --end-time 2024-01-02T00:00:00Z

# ログファイルの再配信
aws cloudtrail start-logging --name MyTrail
```

### 2. Access Analyzerの問題

```
症状: Access Analyzerで分析が実行されない

```

**解決方法:**
```bash

aws accessanalyzer start-resource-scan \
```

## 予防策

### 1. 定期的な監査

#### 月次監査
```bash

aws iam list-users

# 未使用アクセスキーの確認

aws accessanalyzer list-findings \
    --analyzer-arn arn:aws:access-analyzer:us-east-1:123456789012:analyzer/MyAnalyzer
```

#### 四半期監査
```bash
# ポリシーの見直し
aws iam list-policies

# ロールの見直し
aws iam list-roles

# グループの見直し
aws iam list-groups
```

### 2. 自動化された監視

#### CloudWatchアラーム
```bash
# 異常なアクセスのアラーム
aws cloudwatch put-metric-alarm \
    --alarm-name "SuspiciousIAMActivity" \
    --alarm-description "Detect suspicious IAM activity" \
    --metric-name "IAMEvents" \
    --namespace "AWS/IAM" \
    --statistic Sum \
    --period 300 \
    --threshold 10 \
    --comparison-operator GreaterThanThreshold
```

#### Lambda関数での監視
```python
import boto3
import json

def monitor_iam_activity(event, context):
    cloudtrail = boto3.client('cloudtrail')
    
    # 異常なアクティビティの検出
    response = cloudtrail.lookup_events(
        LookupAttributes=[
            {
                'AttributeKey': 'EventName',
                'AttributeValue': 'AssumeRole'
            }
        ],
        StartTime=datetime.now() - timedelta(hours=1),
        EndTime=datetime.now()
    )
    
    # 異常なイベントの処理
    for event in response['Events']:
        if is_suspicious_event(event):
            send_alert(event)
    
    return {
        'statusCode': 200,
        'body': json.dumps('Monitoring completed')
    }
```
