# 条件キーとセッションポリシー

## 概要

**条件キー**と**セッションポリシー**は、IAMポリシーでより詳細で動的なアクセス制御を実現するための機能です。条件キーを使用することで、時間、IPアドレス、ユーザー属性、リソース属性などに基づいた細かいアクセス制御が可能になります。

## 条件キーの種類

### 1. グローバル条件キー

#### 時間関連の条件キー
```json
{
  "Condition": {
    "DateGreaterThan": {
      "aws:CurrentTime": "2024-01-01T00:00:00Z"
    },
    "DateLessThan": {
      "aws:CurrentTime": "2024-12-31T23:59:59Z"
    }
  }
}
```

**利用可能な時間条件キー:**
- `aws:CurrentTime`: 現在の日時
- `aws:EpochTime`: Unixタイムスタンプ
- `aws:TokenIssueTime`: トークンの発行時刻

#### ネットワーク関連の条件キー
```json
{
  "Condition": {
    "IpAddress": {
      "aws:SourceIp": "203.0.113.0/24"
    },
    "StringEquals": {
      "aws:SourceVpc": "vpc-12345678"
    },
    "StringEquals": {
      "aws:SourceVpce": "vpce-12345678"
    }
  }
}
```

**利用可能なネットワーク条件キー:**
- `aws:SourceIp`: 送信元IPアドレス
- `aws:SourceVpc`: 送信元VPC
- `aws:SourceVpce`: 送信元VPCエンドポイント
- `aws:VpcSourceIp`: VPC内の送信元IP

#### 認証関連の条件キー
```json
{
  "Condition": {
    "Bool": {
      "aws:MultiFactorAuthPresent": "true"
    },
    "StringEquals": {
      "aws:MultiFactorAuthAge": "3600"
    }
  }
}
```

**利用可能な認証条件キー:**
- `aws:MultiFactorAuthPresent`: MFAの使用有無
- `aws:MultiFactorAuthAge`: MFA認証からの経過時間
- `aws:PrincipalType`: プリンシパルのタイプ

### 2. サービス固有の条件キー

#### S3関連の条件キー
```json
{
  "Condition": {
    "StringEquals": {
      "s3:ExistingObjectTag/Department": "Engineering"
    },
    "StringLike": {
      "s3:prefix": "documents/*"
    },
    "NumericLessThan": {
      "s3:max-keys": "100"
    }
  }
}
```

**利用可能なS3条件キー:**
- `s3:ExistingObjectTag/*`: 既存オブジェクトのタグ
- `s3:prefix`: オブジェクトのプレフィックス
- `s3:max-keys`: 最大キー数
- `s3:x-amz-acl`: ACL設定

#### EC2関連の条件キー
```json
{
  "Condition": {
    "StringEquals": {
      "ec2:ResourceTag/Environment": "Production"
    },
    "StringEquals": {
      "ec2:InstanceType": "t2.micro"
    },
    "StringEquals": {
      "ec2:Region": "us-east-1"
    }
  }
}
```

**利用可能なEC2条件キー:**
- `ec2:ResourceTag/*`: リソースのタグ
- `ec2:InstanceType`: インスタンスタイプ
- `ec2:Region`: リージョン
- `ec2:AvailabilityZone`: アベイラビリティゾーン

#### IAM関連の条件キー
```json
{
  "Condition": {
    "StringEquals": {
      "iam:PassedToService": "lambda.amazonaws.com"
    },
    "StringEquals": {
      "iam:AssociatedResourceArn": "arn:aws:lambda:us-east-1:123456789012:function:MyFunction"
    }
  }
}
```

**利用可能なIAM条件キー:**
- `iam:PassedToService`: 権限を渡すサービス
- `iam:AssociatedResourceArn`: 関連リソースのARN
- `iam:PermissionsBoundary`: 権限境界

### 3. プリンシパル条件キー

#### ユーザータグ条件キー
```json
{
  "Condition": {
    "StringEquals": {
      "aws:PrincipalTag/Department": "Engineering"
    },
    "StringEquals": {
      "aws:PrincipalTag/Project": "WebApp"
    }
  }
}
```

**利用可能なプリンシパル条件キー:**
- `aws:PrincipalTag/*`: プリンシパルのタグ
- `aws:PrincipalOrgID`: プリンシパルの組織ID
- `aws:PrincipalOrgPaths`: プリンシパルの組織パス

#### セッション条件キー
```json
{
  "Condition": {
    "StringEquals": {
      "aws:RequestedRegion": "us-east-1"
    },
    "StringEquals": {
      "aws:RequestTag/Environment": "Production"
    }
  }
}
```

**利用可能なセッション条件キー:**
- `aws:RequestedRegion`: リクエストされたリージョン
- `aws:RequestTag/*`: リクエストで指定されたタグ
- `aws:TagKeys`: リクエストで指定されたタグキー

## セッションポリシー

### 1. セッションポリシーとは

**セッションポリシー**は、一時的な認証情報（AssumeRole、AssumeRoleWithSAML等）を使用する際に、追加の権限制限を適用するポリシーです。既存のアイデンティティベースポリシーやリソースベースポリシーと組み合わせて使用されます。

### 2. セッションポリシーの特徴

#### 一時的な制限
- セッション期間中のみ有効
- セッション終了時に自動的に無効化
- 既存の権限をさらに制限

#### 動的な制限
- リクエスト時に動的に適用
- 条件に基づいた制限
- コンテキストに応じた制限

### 3. セッションポリシーの使用場面

#### AssumeRoleでの使用
```bash
# セッションポリシー付きでロールを引き受け
aws sts assume-role \
    --role-arn arn:aws:iam::123456789012:role/MyRole \
    --role-session-name MySession \
    --policy '{
        "Version": "2012-10-17",
        "Statement": [
            {
                "Effect": "Allow",
                "Action": "s3:GetObject",
                "Resource": "arn:aws:s3:::my-bucket/*"
            }
        ]
    }'
```

#### AssumeRoleWithSAMLでの使用
```bash
# SAMLアサーション付きでロールを引き受け
aws sts assume-role-with-saml \
    --role-arn arn:aws:iam::123456789012:role/MyRole \
    --principal-arn arn:aws:iam::123456789012:saml-provider/MyProvider \
    --saml-assertion file://assertion.xml \
    --policy '{
        "Version": "2012-10-17",
        "Statement": [
            {
                "Effect": "Allow",
                "Action": "s3:GetObject",
                "Resource": "arn:aws:s3:::my-bucket/*"
            }
        ]
    }'
```

## 実践的な使用例

### 1. 時間ベースのアクセス制御

#### 営業時間内のみアクセス許可
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:*",
      "Resource": "*",
      "Condition": {
        "DateGreaterThan": {
          "aws:CurrentTime": "2024-01-01T09:00:00Z"
        },
        "DateLessThan": {
          "aws:CurrentTime": "2024-12-31T18:00:00Z"
        },
        "StringEquals": {
          "aws:PrincipalTag/Department": "Engineering"
        }
      }
    }
  ]
}
```

#### 平日のみアクセス許可
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "ec2:StartInstances",
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:CurrentTime": "Saturday"
        },
        "StringNotEquals": {
          "aws:CurrentTime": "Sunday"
        }
      }
    }
  ]
}
```

### 2. ネットワークベースのアクセス制御

#### 特定IPからのみアクセス許可
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "*",
      "Resource": "*",
      "Condition": {
        "IpAddress": {
          "aws:SourceIp": "203.0.113.0/24"
        }
      }
    }
  ]
}
```

#### VPC内からのみアクセス許可
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket/*",
      "Condition": {
        "StringEquals": {
          "aws:SourceVpc": "vpc-12345678"
        }
      }
    }
  ]
}
```

### 3. 認証ベースのアクセス制御

#### MFA必須のアクセス制御
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:DeleteObject",
      "Resource": "*",
      "Condition": {
        "Bool": {
          "aws:MultiFactorAuthPresent": "true"
        }
      }
    }
  ]
}
```

#### MFA認証からの経過時間制限
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "iam:CreateUser",
      "Resource": "*",
      "Condition": {
        "NumericLessThan": {
          "aws:MultiFactorAuthAge": "3600"
        }
      }
    }
  ]
}
```

### 4. リソース属性ベースのアクセス制御

#### タグベースのアクセス制御
```json
{
  "Version": "2012-10-17",
  "Statement": [

      "Effect": "Allow",
      "Action": "s3:GetObject",
```

## 高度な条件の組み合わせ

### 1. 複数条件の論理演算

#### AND条件（すべての条件を満たす必要がある）
```json
{
  "Condition": {
    "StringEquals": {
      "aws:PrincipalTag/Department": "Engineering"
    },
    "Bool": {
      "aws:MultiFactorAuthPresent": "true"
    },
    "IpAddress": {
      "aws:SourceIp": "203.0.113.0/24"
    }
  }
}
```

#### OR条件（いずれかの条件を満たせばよい）
```json
{
  "Condition": {
    "ForAnyValue:StringEquals": {
      "aws:PrincipalTag/Department": ["Engineering", "Marketing", "Sales"]
    }
  }
}
```

#### NOT条件（条件を満たさない場合）
```json
{
  "Condition": {
    "StringNotEquals": {
      "aws:PrincipalTag/Environment": "Production"
    }
  }
}
```

### 2. ネストした条件

#### 複雑な条件の組み合わせ
```json
{
  "Condition": {
    "StringEquals": {
      "aws:PrincipalTag/Department": "Engineering"
    },
    "ForAnyValue:StringEquals": {
      "aws:PrincipalTag/Project": ["WebApp", "MobileApp"]
    },
    "Bool": {
      "aws:MultiFactorAuthPresent": "true"
    },
    "DateGreaterThan": {
      "aws:CurrentTime": "2024-01-01T09:00:00Z"
    },
    "DateLessThan": {
      "aws:CurrentTime": "2024-12-31T18:00:00Z"
    }
  }
}
```

### 3. 動的な条件

#### リソース属性の動的参照
```json
{
  "Condition": {
    "StringEquals": {
      "aws:PrincipalTag/Project": "${s3:ExistingObjectTag/Project}",
      "aws:PrincipalTag/Environment": "${s3:ExistingObjectTag/Environment}"
    }
  }
}
```

#### リクエスト属性の動的参照
```json
{
  "Condition": {
    "StringEquals": {
      "aws:RequestedRegion": "us-east-1"
    },
    "StringLike": {
      "aws:RequestTag/Name": "temp-*"
    }
  }
}
```

## 条件キーのテスト

### 1. IAM Policy Simulatorでのテスト

#### 基本的なテスト
```bash
# 条件付きポリシーのシミュレーション
aws iam simulate-principal-policy \
    --policy-source-arn arn:aws:iam::123456789012:user/john-doe \
    --action-names s3:GetObject \
    --resource-arns arn:aws:s3:::my-bucket/object.txt \
    --context-entries ContextKeyName=aws:SourceIp,ContextKeyValues=203.0.113.12,ContextKeyType=string
```

#### 複数条件のテスト
```bash
# 複数条件のシミュレーション
aws iam simulate-principal-policy \
    --policy-source-arn arn:aws:iam::123456789012:user/john-doe \
    --action-names s3:GetObject \
    --resource-arns arn:aws:s3:::my-bucket/object.txt \
    --context-entries \
        ContextKeyName=aws:SourceIp,ContextKeyValues=203.0.113.12,ContextKeyType=string \
        ContextKeyName=aws:MultiFactorAuthPresent,ContextKeyValues=true,ContextKeyType=boolean
```

### 2. 条件の検証

## トラブルシューティング

### 1. 条件が正しく動作しない

#### 条件の構文エラー
```
エラー: Invalid condition key
原因: 条件キーが正しくない
解決策: 正しい条件キーを確認
```

#### 条件の値の型エラー
```
エラー: Invalid condition value
原因: 条件の値の型が正しくない
解決策: 適切な型の値を指定
```

### 2. セッションポリシーの問題

#### セッションポリシーの構文エラー
```
エラー: Invalid session policy
原因: セッションポリシーの構文が正しくない
解決策: JSON構文を確認
```

#### 権限の競合
```
エラー: Access denied
原因: セッションポリシーが既存の権限を制限しすぎている
解決策: セッションポリシーを調整
```

### 3. デバッグの方法

#### 条件の段階的テスト
```bash
# 1. 条件なしでテスト
aws iam simulate-principal-policy \
    --policy-source-arn arn:aws:iam::123456789012:user/john-doe \
    --action-names s3:GetObject \
    --resource-arns arn:aws:s3:::my-bucket/object.txt

# 2. 条件を1つずつ追加してテスト
aws iam simulate-principal-policy \
    --policy-source-arn arn:aws:iam::123456789012:user/john-doe \
    --action-names s3:GetObject \
    --resource-arns arn:aws:s3:::my-bucket/object.txt \
    --context-entries ContextKeyName=aws:SourceIp,ContextKeyValues=203.0.113.12,ContextKeyType=string
```
