# VPCセキュリティ機能

## セキュリティグループのベストプラクティス
```bash
# 最小権限の原則
- 必要なポートのみ開放
- 特定のIPアドレスからのアクセスに制限
- 定期的なルールの見直し
```

## ネットワークACLの活用
```bash
# サブネットレベルでの追加セキュリティ
- デフォルトルールを拒否に変更
- 明示的に必要なトラフィックのみ許可
- セキュリティグループとの組み合わせ使用
```

## VPCフローログ
- VPC、サブネット、ENIレベルでのネットワークトラフィック監視
- CloudWatch LogsまたはS3に送信
- セキュリティ監査とトラブルシューティングに活用

## セキュリティの階層化

### 1. ネットワークレベル
- VPC: 論理的な分離
- サブネット: 機能別分離
- ルートテーブル: トラフィック制御

### 2. セキュリティグループレベル
- インスタンス単位での制御
- ステートフルファイアウォール
- インバウンド・アウトバウンドルール

### 3. ネットワークACLレベル
- サブネット単位での制御
- ステートレスファイアウォール
- 明示的な許可・拒否ルール

## セキュリティ設定例

### Webサーバー用セキュリティグループ
```yaml
インバウンド:
  - HTTP (80): 0.0.0.0/0
  - HTTPS (443): 0.0.0.0/0
  - SSH (22): 10.0.0.0/16

アウトバウンド:
  - All traffic: 0.0.0.0/0
```

### データベース用セキュリティグループ
```yaml
インバウンド:
  - MySQL (3306): 10.0.0.0/16
  - PostgreSQL (5432): 10.0.0.0/16

アウトバウンド:
  - All traffic: 0.0.0.0/0
```

### アプリケーションサーバー用セキュリティグループ
```yaml
インバウンド:
  - HTTP (80): 10.0.1.0/24
  - HTTPS (443): 10.0.1.0/24
  - SSH (22): 10.0.0.0/16

アウトバウンド:
  - HTTP (80): 0.0.0.0/0
  - HTTPS (443): 0.0.0.0/0
  - MySQL (3306): 10.0.3.0/24
```
