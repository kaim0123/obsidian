# ELB（Elastic Load Balancer）とは

## 概要

ELB（Elastic Load Balancer）は、**複数のサーバーにトラフィックを分散**させる AWS のサービスです。1 つのロードバランサーが複数の EC2 インスタンスやコンテナにリクエストを振り分けることで、アプリケーションの可用性とスケーラビリティを向上させます。

## なぜ ELB が必要なのか？

### 1. 高可用性の実現

- 1 台のサーバーが故障しても、他のサーバーでサービス継続
- 自動的にヘルスチェックを行い、異常なサーバーを除外

### 2. スケーラビリティの向上

- トラフィック増加時に新しいサーバーを追加
- 負荷に応じて自動的にスケールアウト

### 3. パフォーマンスの最適化

- 地理的に近いサーバーにリクエストを振り分け
- サーバーの負荷状況に応じて分散

## ELB の種類

### 1. Application Load Balancer（ALB）

**レイヤー 7（アプリケーション層）**で動作

#### 特徴

- HTTP/HTTPS トラフィックを処理
- パスベースルーティング（例：/api/_、/images/_）
- ホストベースルーティング（例：api.example.com、www.example.com）
- コンテナやサーバーレスアーキテクチャに対応

#### 使用例

```
example.com/api/* → バックエンドAPIサーバー
example.com/images/* → 画像サーバー
example.com/static/* → 静的ファイルサーバー
```

### 2. Network Load Balancer（NLB）

**レイヤー 4（トランスポート層）**で動作

#### 特徴

- TCP/UDP トラフィックを処理
- 超低レイテンシー（数マイクロ秒）
- 静的 IP アドレスを提供
- 数百万リクエスト/秒を処理可能

#### 使用例

- ゲームサーバー
- IoT アプリケーション
- リアルタイム通信

### 3. Classic Load Balancer（CLB）

**レガシーサービス**（新規利用は推奨されない）

#### 特徴

- レイヤー 4 とレイヤー 7 の両方に対応
- 基本的なロードバランシング機能
- ALB や NLB への移行が推奨

## ELB の主要機能

### 1. ヘルスチェック

```
設定例：
- プロトコル：HTTP
- パス：/health
- ポート：80
- 間隔：30秒
- 閾値：2回連続失敗で異常と判定
```

### 2. ターゲットグループ

- 複数の EC2 インスタンスをグループ化
- ヘルシーチェックの設定
- トラフィック分散の方法を指定

### 3. リスナー

- 特定のポートでトラフィックを受信
- プロトコル（HTTP/HTTPS/TCP/UDP）を指定
- ターゲットグループへの転送ルールを設定

### 4. スティッキーセッション

- 同一ユーザーのリクエストを同じサーバーに振り分け
- セッション情報を保持するアプリケーションで重要

## 実際の構成例

### Web アプリケーションの構成

```
インターネット
    ↓
ALB（Application Load Balancer）
    ↓
┌─────────────────┬─────────────────┐
│   Webサーバー1   │   Webサーバー2   │
│   (10.0.1.10)   │   (10.0.1.11)   │
└─────────────────┴─────────────────┘
```

### マイクロサービス構成

```
ALB
├── /api/users → ユーザーサービス
├── /api/orders → 注文サービス
└── /api/products → 商品サービス
```

## セキュリティ機能

### 1. SSL/TLS 終端

- HTTPS トラフィックを復号化
- バックエンドサーバーは HTTP で通信可能
- SSL 証明書の管理を簡素化

### 2. WAF（Web Application Firewall）連携

- SQL インジェクション攻撃の防御
- XSS 攻撃の防御
- DDoS 攻撃の軽減

### 3. セキュリティグループ

- 特定の IP アドレスからのアクセスのみ許可
- ポートレベルでのアクセス制御

- NLCU（Network Load Balancer Capacity Unit）料金：約$0.006/NLCU

## ベストプラクティス

### 1. 適切なロードバランサーの選択

- **ALB**：HTTP/HTTPS アプリケーション
- **NLB**：TCP/UDP アプリケーション、低レイテンシー要求

### 2. マルチ AZ 構成

- 複数のアベイラビリティゾーンに配置
- 単一障害点を排除

### 3. ヘルスチェックの最適化

- 軽量なヘルスチェックエンドポイントを作成
- 適切な間隔と閾値を設定

## まとめ

ELB は、高可用性とスケーラビリティを実現するための重要なサービスです。適切に設定することで、トラフィックの増加やサーバーの故障に対応できる堅牢なアプリケーションを構築できます。
