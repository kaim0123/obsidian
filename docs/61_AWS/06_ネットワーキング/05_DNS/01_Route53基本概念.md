# Route 53 とは

## 概要

Route 53 は、AWS の**DNS（Domain Name System）サービス**です。ドメイン名を IP アドレスに変換するだけでなく、**高可用性**と**スケーラビリティ**を備えた DNS サービスとして、世界中のユーザーに高速なドメイン解決を提供します。

## なぜ Route 53 が必要なのか？

### 1. ドメイン名の管理

- ドメインの登録・管理
- DNS レコードの設定
- ドメインの自動更新

### 2. 高可用性の実現

- 99.99%の可用性を保証
- 複数のデータセンターで冗長化
- 自動フェイルオーバー

### 3. トラフィックの最適化

- 地理的に近いサーバーへの誘導
- ヘルスチェックによる自動切り替え
- 負荷分散

## DNS の基本概念

### 1. ドメイン名と IP アドレス

```
例：
www.example.com → 203.0.113.1
api.example.com → 203.0.113.2
```

### 2. DNS 解決の流れ

```
1. ユーザーがwww.example.comにアクセス
2. ローカルDNSサーバーがRoute 53に問い合わせ
3. Route 53がIPアドレス（203.0.113.1）を返す
4. ユーザーがIPアドレスにアクセス
```

## レコードタイプ

### 1. A レコード

**IPv4 アドレス**を指定

```
例：
www.example.com → 203.0.113.1
api.example.com → 203.0.113.2
```

### 2. AAAA レコード

**IPv6 アドレス**を指定

```
例：
www.example.com → 2001:db8::1
api.example.com → 2001:db8::2
```

### 3. CNAME レコード

**別のドメイン名**を指定

```
例：
blog.example.com → www.example.com
shop.example.com → store.example.com
```

### 4. エイリアスレコード

**AWS リソース**を直接指定（推奨）

```
例：
www.example.com → my-load-balancer-1234567890.us-west-2.elb.amazonaws.com
api.example.com → my-cloudfront-distribution.cloudfront.net
```

### 5. MX レコード

**メールサーバー**を指定

```
例：
example.com → 10 mail.example.com
example.com → 20 backup-mail.example.com
```

### 6. TXT レコード

**テキスト情報**を指定

```
例：
example.com → "v=spf1 include:_spf.google.com ~all"
_dmarc.example.com → "v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com"
```

## ルーティングポリシー

### 1. シンプルルーティング

**単一のリソース**にトラフィックを送信

```
例：
www.example.com → 203.0.113.1
```

### 2. 重み付けルーティング

**複数のリソース**に重みを付けて分散

```
例：
www.example.com → 203.0.113.1（重み：70）
www.example.com → 203.0.113.2（重み：30）
```

### 3. レイテンシーベースルーティング

**最も低いレイテンシー**のリソースに送信

```
例：
www.example.com → 東京のサーバー（レイテンシー：50ms）
www.example.com → シンガポールのサーバー（レイテンシー：80ms）
→ 東京のサーバーが選択される
```

### 4. 地理的近接性ルーティング

**地理的な位置**に基づいて送信

```
例：
www.example.com → 日本からのアクセス → 東京のサーバー
www.example.com → 米国からのアクセス → バージニアのサーバー
```

### 5. 位置情報ルーティング

**大陸・国・州**に基づいて送信

```
例：
www.example.com → アジア → シンガポールのサーバー
www.example.com → 北米 → バージニアのサーバー
www.example.com → 欧州 → アイルランドのサーバー
```

### 6. 複数値回答ルーティング

**複数の健全なリソース**からランダムに選択

```
例：
www.example.com → 203.0.113.1（健全）
www.example.com → 203.0.113.2（健全）
www.example.com → 203.0.113.3（不健全）
→ 203.0.113.1または203.0.113.2がランダムに選択
```

### 7. フェイルオーバールーティング

**プライマリとセカンダリ**の設定

```
例：
www.example.com → プライマリサーバー（203.0.113.1）
www.example.com → セカンダリサーバー（203.0.113.2）
→ プライマリが不健全な場合、セカンダリに切り替え
```

## ヘルスチェック

### 1. 基本的な設定

```
例：
- プロトコル：HTTP
- パス：/health
- ポート：80
- 間隔：30秒
- 閾値：3回連続失敗で不健全と判定
```

### 2. ヘルスチェックの種類

- **HTTP/HTTPS**：ウェブサーバーのヘルスチェック
- **TCP**：データベースサーバーのヘルスチェック
- **CALCULATED**：複数のヘルスチェックの組み合わせ

## 実際の使用例

### 1. 基本的なウェブサイト

```
設定：
www.example.com → Aレコード → 203.0.113.1
example.com → Aレコード → 203.0.113.1
```

### 2. 高可用性構成

```
設定：
www.example.com → フェイルオーバー
├── プライマリ：203.0.113.1（東京）
└── セカンダリ：203.0.113.2（大阪）
```

### 3. グローバル配信

```
設定：
www.example.com → 地理的近接性
├── 日本 → 東京のサーバー
├── 米国 → バージニアのサーバー
└── 欧州 → アイルランドのサーバー
```

### 4. マイクロサービス

```
設定：
api.example.com → レイテンシーベース
├── 東京のAPIサーバー
├── シンガポールのAPIサーバー
└── バージニアのAPIサーバー
```

## ドメイン登録

### 1. 新規ドメインの登録

- Route 53 で直接ドメインを登録可能
- 自動更新の設定
- プライバシー保護の設定

### 2. 既存ドメインの移管

- 他のレジストラから Route 53 に移管
- ネームサーバーの変更
- DNS レコードの移行

## セキュリティ機能

### 1. DNSSEC

- DNS 応答の整合性を検証
- 偽装攻撃の防止
- 暗号化による認証

### 2. プライベートホストゾーン

- VPC 内でのみ利用可能な DNS
- 内部サービス間の通信
- 外部からのアクセス不可

## ベストプラクティス

### 1. エイリアスレコードの活用

- AWS リソースにはエイリアスレコードを使用
- 自動的な IP アドレス変更に対応
- コストの削減

### 2. 適切な TTL 設定

- 静的コンテンツ：長い TTL（3600 秒）
- 動的コンテンツ：短い TTL（300 秒）
- 変更頻度に応じて調整

### 3. ヘルスチェックの最適化

- 軽量なヘルスチェックエンドポイント
- 適切な間隔と閾値の設定
- 複数のヘルスチェックの組み合わせ

## まとめ

Route 53 は、高可用性とスケーラビリティを備えた DNS サービスです。適切に設定することで、グローバルなトラフィックの最適化、高可用性の実現、セキュリティの強化を同時に実現できます。
