# EC2 基本概念

## 概要

EC2（Elastic Compute Cloud）は、AWS が提供する仮想サーバーサービスです。クラウド上で仮想マシン（インスタンス）を作成・管理し、様々なアプリケーションを実行できます。

## 主な特徴

### 1. 仮想サーバーサービス

- 物理サーバーを購入する必要がなく、クラウド上で仮想マシンを利用
- 必要な時に作成し、不要になったら削除できる柔軟性

### 2. スケーラビリティ
- 必要に応じてサーバーの性能を変更可能
- 柔軟性: 様々なOSやアプリケーションを実行可能
- コスト効率: 使用した分だけの従量課金制
- 高可用性: 複数のデータセンターで冗長化可能

## 主要なコンポーネント

### 1. AMI (Amazon Machine Image)
- インスタンスのテンプレート
- OS、アプリケーション、設定が含まれる
- 例：Ubuntu、Windows Server、Amazon Linux
- 独自の AMI を作成することも可能

### 2. インスタンスタイプ
- CPU、メモリ、ストレージ、ネットワーク性能を定義
- 用途に応じて選択可能

### 3. セキュリティグループ
- 仮想ファイアウォールの役割
- インスタンスへのアクセス制御

### 4. キーペア
- SSH接続のための認証キー
- 公開鍵と秘密鍵のペア

## インスタンスファミリー

EC2 では用途に応じて様々なインスタンスファミリーが用意されています：

### General Purpose（汎用）: バランスの取れた性能
- **用途**: Webサーバー、アプリケーションサーバー
- **特徴**: CPUとメモリのバランスが良い
- **例**: t3.micro, t3.small, m5.large

### Compute Optimized（コンピューティング最適化）: CPU 集約的なワークロード
- **用途**: 高性能コンピューティング、ゲームサーバー
- **特徴**: CPU性能が高い
- **例**: c5.large, c5.xlarge

### Memory Optimized（メモリ最適化）: メモリ集約的なアプリケーション
- **用途**: データベース、メモリ集約型アプリケーション
- **特徴**: 大量のメモリを搭載
- **例**: r5.large, r5.xlarge

### Storage Optimized（ストレージ最適化）: 大量のデータ処理
- **用途**: データウェアハウス、NoSQLデータベース
- **特徴**: 高速ストレージアクセス
- **例**: i3.large, i3.xlarge

### Accelerated Computing（高速コンピューティング）: GPU や FPGA を活用

## インスタンスタイプの命名規則

```
t3.micro
│ │ │
│ │ └─ サイズ（micro, small, medium, large, xlarge, 2xlarge...）
│ └── 世代（3, 4, 5...）
└──── ファミリー（t=汎用, c=コンピューティング, r=メモリ, i=ストレージ）
```

## プレイスメントグループ

インスタンスの配置戦略を制御：

### 1. クラスター
- 同一 AZ 内の近い場所に配置
- 低レイテンシーが必要な場合

### 2. パーティション
- 論理的なパーティションに分散配置
- 障害の影響を限定

### 3. スプレッド
- 異なるハードウェアに分散配置
- 可用性を最大化

## オンデマンドキャパシティ予約

- 特定の AZ でインスタンスの容量を予約
- 重要なワークロードの確実な実行を保証

## 実際の使用例

- Web サーバーの構築
- データベースサーバーの運用
- 開発・テスト環境の構築
- バッチ処理の実行

## まとめ

EC2 は、クラウド上で仮想サーバーを柔軟に利用できるサービスです。様々なインスタンスタイプと購入方法を組み合わせることで、コスト効率と性能のバランスを取ることができます。
