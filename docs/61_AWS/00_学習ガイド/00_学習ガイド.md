## AWSの基本概念

### AWSとは
**Amazon Web Services (AWS)** は、Amazonが提供するクラウドコンピューティングプラットフォームです。インターネット経由でコンピューティングリソースを提供するサービスです。

### クラウドコンピューティングの3つのモデル

#### 1. IaaS (Infrastructure as a Service)
- **提供内容**: 仮想サーバー、ストレージ、ネットワーク
- **管理範囲**: OS、ミドルウェア、アプリケーションはユーザーが管理
- **例**: EC2、VPC、EBS

#### 2. PaaS (Platform as a Service)
- **提供内容**: 開発・実行環境
- **管理範囲**: アプリケーションのみユーザーが管理
- **例**: Elastic Beanstalk、Lambda

#### 3. SaaS (Software as a Service)
- **提供内容**: 完成されたアプリケーション
- **管理範囲**: ユーザーは使用のみ
- **例**: Amazon WorkMail、Amazon Chime

## AWSの基本用語集

### リージョンとアベイラビリティゾーン

#### リージョン (Region)
- **定義**: AWSがサービスを提供する地理的な場所
- **例**: アジアパシフィック（東京）、米国東部（バージニア北部）
- **特徴**: 独立したデータセンター群

#### アベイラビリティゾーン (AZ)
- **定義**: リージョン内の独立したデータセンター
- **特徴**: 障害時の冗長性を提供
- **例**: ap-northeast-1a, ap-northeast-1c, ap-northeast-1d

### ネットワーク関連用語

#### VPC (Virtual Private Cloud)
- **定義**: 論理的に分離された仮想ネットワーク環境
- **機能**: 独自のIPアドレス範囲、サブネット、ルートテーブルを設定

#### サブネット (Subnet)
- **定義**: VPC内のIPアドレス範囲
- **種類**: 
  - パブリックサブネット（インターネットアクセス可能）
  - プライベートサブネット（インターネットアクセス不可）

#### セキュリティグループ
- **定義**: 仮想ファイアウォール
- **機能**: インスタンスレベルでのトラフィック制御

#### ネットワークACL
- **定義**: サブネットレベルでのファイアウォール
- **特徴**: セキュリティグループよりも粗い制御

### コンピューティング関連用語

#### EC2インスタンス
- **定義**: 仮想サーバー
- **特徴**: オンデマンドで作成・削除可能

#### AMI (Amazon Machine Image)
- **定義**: インスタンスのテンプレート
- **内容**: OS、アプリケーション、設定

#### インスタンスタイプ
- **定義**: CPU、メモリ、ストレージ、ネットワーク性能の組み合わせ
- **例**: t3.micro, m5.large, r5.xlarge

### ストレージ関連用語

#### EBS (Elastic Block Store)
- **定義**: EC2インスタンス用の永続ブロックストレージ
- **特徴**: インスタンスにアタッチして使用

#### S3 (Simple Storage Service)
- **定義**: オブジェクトストレージサービス
- **特徴**: 99.999999999%の耐久性

#### EFS (Elastic File System)
- **定義**: マネージドNFS
- **特徴**: 複数のインスタンスから同時アクセス可能

## EC2とVPCの違いと関係性

### EC2とは
**Amazon Elastic Compute Cloud (EC2)** は、クラウド上の仮想サーバーサービスです。

#### EC2の特徴
- **仮想サーバー**: クラウド上で仮想マシンを実行
- **柔軟性**: 様々なOS、アプリケーションを実行可能
- **スケーラビリティ**: 必要に応じて性能を変更可能
- **従量課金**: 使用した分だけの料金

#### EC2の主要コンポーネント
```
EC2インスタンス
├── AMI (テンプレート)
├── インスタンスタイプ (性能)
├── セキュリティグループ (ファイアウォール)
├── キーペア (認証)
└── EBSボリューム (ストレージ)
```

### VPCとは
**Amazon Virtual Private Cloud (VPC)** は、AWSクラウド内の論理的に分離された仮想ネットワークです。

#### VPCの特徴
- **仮想ネットワーク**: 独自のネットワーク環境を構築
- **IPアドレス管理**: 独自のIPアドレス範囲を設定
- **ネットワーク制御**: ルートテーブル、セキュリティグループで制御
- **インターネット接続**: インターネットゲートウェイで制御

#### VPCの主要コンポーネント
```
VPC
├── CIDRブロック (IPアドレス範囲)
├── サブネット (ネットワーク分割)
│   ├── パブリックサブネット
│   └── プライベートサブネット
├── インターネットゲートウェイ (IGW)
├── ルートテーブル (ルーティング)
├── ネットワークACL (サブネットレベルファイアウォール)
└── セキュリティグループ (インスタンスレベルファイアウォール)
```

### EC2とVPCの関係性

#### 基本的な関係
```
VPC (ネットワーク環境)
└── サブネット (ネットワークセグメント)
    └── EC2インスタンス (仮想サーバー)
```

#### 詳細な関係図
```
┌─────────────────────────────────────────┐
│                 VPC                     │
│  ┌─────────────────┐ ┌─────────────────┐ │
│  │ パブリックサブネット │ │ プライベートサブネット │ │
│  │ ┌─────────────┐ │ │ ┌─────────────┐ │ │
│  │ │ EC2インスタンス │ │ │ EC2インスタンス │ │ │
│  │ │ (Web Server) │ │ │ (Database)   │ │ │
│  │ └─────────────┘ │ │ └─────────────┘ │ │
│  └─────────────────┘ └─────────────────┘ │
│           │                   │          │
│           └─────── IGW ────────┘          │
└─────────────────────────────────────────┘
```

### 主な違い

| 項目 | EC2 | VPC |
|------|-----|-----|
| **役割** | 仮想サーバー | 仮想ネットワーク |
| **提供機能** | コンピューティング | ネットワーキング |
| **管理レベル** | インスタンス | ネットワーク |
| **設定項目** | AMI、インスタンスタイプ | CIDR、サブネット、ルート |
| **料金** | インスタンス時間 | 使用したリソース |

### 実際の使用例

#### Webアプリケーションの構成
```
VPC: 10.0.0.0/16
├── パブリックサブネット: 10.0.1.0/24
│   └── EC2インスタンス (Web Server)
│       ├── AMI: Amazon Linux 2
│       ├── インスタンスタイプ: t3.micro
│       └── セキュリティグループ: HTTP(80), HTTPS(443), SSH(22)
└── プライベートサブネット: 10.0.2.0/24
    └── EC2インスタンス (Database)
        ├── AMI: Amazon Linux 2
        ├── インスタンスタイプ: t3.small
        └── セキュリティグループ: MySQL(3306)
```

## AWSサービスの分類

### コンピューティングサービス

#### EC2 (Elastic Compute Cloud)
- **用途**: 仮想サーバー
- **特徴**: オンデマンド、リザーブド、スポットインスタンス

#### Lambda
- **用途**: サーバーレスコンピューティング
- **特徴**: イベント駆動、従量課金

#### ECS (Elastic Container Service)
- **用途**: コンテナ管理
- **特徴**: Dockerコンテナの実行・管理

#### EKS (Elastic Kubernetes Service)
- **用途**: Kubernetes管理
- **特徴**: マネージドKubernetesクラスター

### ネットワーキングサービス

#### VPC (Virtual Private Cloud)
- **用途**: 仮想ネットワーク
- **特徴**: 論理的に分離されたネットワーク環境

#### CloudFront
- **用途**: CDN (Content Delivery Network)
- **特徴**: グローバルなコンテンツ配信

#### Route 53
- **用途**: DNSサービス
- **特徴**: ドメイン名の管理・解決

#### ELB (Elastic Load Balancer)
- **用途**: 負荷分散
- **特徴**: Application、Network、Classic Load Balancer

### ストレージサービス

#### S3 (Simple Storage Service)
- **用途**: オブジェクトストレージ
- **特徴**: 高い耐久性、スケーラビリティ

#### EBS (Elastic Block Store)
- **用途**: ブロックストレージ
- **特徴**: EC2インスタンス用の永続ストレージ

#### EFS (Elastic File System)
- **用途**: ファイルシステム
- **特徴**: 複数インスタンスからの同時アクセス

#### Glacier
- **用途**: アーカイブストレージ
- **特徴**: 長期保存、低コスト

### データベースサービス

#### RDS (Relational Database Service)
- **用途**: リレーショナルデータベース
- **対応DB**: MySQL、PostgreSQL、Oracle、SQL Server

#### DynamoDB
- **用途**: NoSQLデータベース
- **特徴**: サーバーレス、自動スケーリング

#### ElastiCache
- **用途**: インメモリキャッシュ
- **対応エンジン**: Redis、Memcached

#### Redshift
- **用途**: データウェアハウス
- **特徴**: 大規模データ分析

### セキュリティサービス

#### IAM (Identity and Access Management)
- **用途**: アクセス管理
- **特徴**: ユーザー、ロール、ポリシー管理

#### CloudTrail
- **用途**: 監査ログ
- **特徴**: API呼び出しの記録

#### GuardDuty
- **用途**: 脅威検出
- **特徴**: 機械学習による異常検知

#### WAF (Web Application Firewall)
- **用途**: Webアプリケーション保護
- **特徴**: SQLインジェクション、XSS攻撃の防御

### 監視・管理サービス

#### CloudWatch
- **用途**: 監視・ログ管理
- **特徴**: メトリクス、アラーム、ログ

#### CloudFormation
- **用途**: インフラのコード化
- **特徴**: Infrastructure as Code

#### Systems Manager
- **用途**: システム管理
- **特徴**: パッチ管理、設定管理

## 主要サービスの詳細解説

### コンピューティング層

#### EC2の詳細
```
EC2インスタンス
├── インスタンスファミリー
│   ├── T3/T4g: バースト可能汎用
│   ├── M5/M6i: 汎用
│   ├── C5/C6i: コンピューティング最適化
│   ├── R5/R6i: メモリ最適化
│   └── I3/I4i: ストレージ最適化
├── 料金モデル
│   ├── オンデマンド: 従量課金
│   ├── リザーブド: 長期契約で割引
│   └── スポット: 未使用容量を安価で利用
└── ストレージ
    ├── インスタンスストア: 一時的
    └── EBS: 永続的
```

#### Lambdaの詳細
```
Lambda関数
├── 実行環境
│   ├── Node.js, Python, Java, Go等
│   └── カスタムランタイム
├── トリガー
│   ├── API Gateway
│   ├── S3
│   ├── DynamoDB
│   └── CloudWatch Events
└── 料金
    ├── リクエスト数
    └── 実行時間（GB-秒）
```

### ネットワーキング層

#### VPCの詳細設定
```
VPC設計例
├── CIDRブロック: 10.0.0.0/16
├── パブリックサブネット
│   ├── AZ-a: 10.0.1.0/24
│   └── AZ-c: 10.0.2.0/24
├── プライベートサブネット
│   ├── AZ-a: 10.0.11.0/24
│   └── AZ-c: 10.0.12.0/24
├── データベースサブネット
│   ├── AZ-a: 10.0.21.0/24
│   └── AZ-c: 10.0.22.0/24
└── ルートテーブル
    ├── パブリック: 0.0.0.0/0 → IGW
    └── プライベート: 0.0.0.0/0 → NAT Gateway
```

#### セキュリティグループ設定例
```bash
# Webサーバー用セキュリティグループ
Inbound Rules:
- HTTP (80): 0.0.0.0/0
- HTTPS (443): 0.0.0.0/0
- SSH (22): 管理者IP/32

Outbound Rules:
- All traffic: 0.0.0.0/0

# データベース用セキュリティグループ
Inbound Rules:
- MySQL (3306): Webサーバーセキュリティグループ

Outbound Rules:
- All traffic: 0.0.0.0/0
```

### ストレージ層

#### S3ストレージクラス
```
S3ストレージクラス
├── Standard
│   ├── 用途: 頻繁にアクセスするデータ
│   └── 料金: 最も高い
├── Standard-IA (Infrequent Access)
│   ├── 用途: 月に1回程度のアクセス
│   └── 料金: Standardより安い
├── One Zone-IA
│   ├── 用途: 再構築可能なデータ
│   └── 料金: 最も安い（単一AZ）
└── Glacier
    ├── 用途: アーカイブデータ
    └── 料金: 最も安い（復元時間が長い）
```

#### EBSボリュームタイプ
```
EBSボリュームタイプ
├── gp3 (汎用SSD)
│   ├── 用途: 汎用的なワークロード
│   └── 性能: 最大16,000 IOPS
├── io2 (プロビジョンドIOPS SSD)
│   ├── 用途: 高性能が必要なデータベース
│   └── 性能: 最大64,000 IOPS
├── st1 (スループット最適化HDD)
│   ├── 用途: ビッグデータ、ログ処理
│   └── 性能: 最大500 MiB/s
└── sc1 (コールドHDD)
    ├── 用途: アクセス頻度の低いデータ
    └── 性能: 最大250 MiB/s
```

## よくある質問

### Q1: EC2とVPCはどちらを先に学ぶべきですか？

**A**: **VPCを先に学ぶことをお勧めします**。

理由：
- VPCはネットワーク基盤で、EC2はその上で動作する
- VPCの概念を理解してからEC2を学ぶと、ネットワーク設定が理解しやすい
- 実際の運用では、VPCを設計してからEC2インスタンスを配置する

学習順序：
1. VPCの基本概念（CIDR、サブネット、ルートテーブル）
2. セキュリティグループの理解
3. EC2インスタンスの作成
4. ネットワーク設定の実践

### Q2: 無料利用枠でどの程度学習できますか？

**A**: **十分に基礎学習が可能です**。

無料利用枠の内容：


### Q3: セキュリティグループとネットワークACLの使い分けは？

**A**: **レベルと粒度が異なります**。

| 項目 | セキュリティグループ | ネットワークACL |
|------|-------------------|----------------|
| **レベル** | インスタンスレベル | サブネットレベル |
| **粒度** | 細かい制御 | 粗い制御 |
| **状態** | ステートフル | ステートレス |
| **優先度** | 高い | 低い |

使い分けの例：
```
セキュリティグループ：
- Webサーバー: HTTP(80), HTTPS(443), SSH(22)
- データベース: MySQL(3306) from Webサーバー

ネットワークACL：
- サブネット全体: 特定IPからのアクセス制限
- 一時的なブロック: 攻撃IPの遮断
```
