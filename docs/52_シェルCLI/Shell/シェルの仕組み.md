## 詳しい要約

**テーマ：シェルの正体は「読む・展開する・PATH で探す・子プロセスで動かす」プログラム**

ターミナルは文字の表示を担当するだけで、入力された文字を解釈しているのはその中で動く「シェル」という別プログラムである。シェルは変数を展開し、`PATH` からコマンドを探し、子プロセスとして実行する。環境変数とシェル変数の違い、`PATH` の探索順を実演で示す。

---

### ターミナルとシェル

- ターミナルは文字・色・スクロールの表示だけを担当。入力を解釈するのは **シェル**。
- シェルはカーネルを外側から包む（shell = 殻）もので、入力をカーネルへの依頼に変換して渡す。
- シェルの実体はファイルで、起動するとプロセスになる。`echo $SHELL` で場所（例: `/bin/zsh`）が分かる。

### 変数と環境

- `echo` が動く前に、シェルが `$SHELL` を値に**置き換えて（展開して）**いる。
- シェルはメモリ上に変数名と値の表（**環境**）を持つ。値は数値も含めすべて文字列。
- `NAME=value` で作った変数は `echo $NAME` では表示されるが、`printenv NAME` では出ない。`printenv` はシェルが作る**子プロセス**で、子に渡るのは **`export`** の印がついた変数だけだから。
- 印つき＝**環境変数**、印なし＝**シェル変数**。
- 子プロセスは生まれた時点の環境の**コピー**を受け取る。C 言語では `main` の第 3 引数 `envp` で受け取れる。

### PATH によるコマンド探索

- コマンド名だけ打つと、シェルは環境変数 **`PATH`** のコロン区切りのディレクトリを**左から順に**探し、最初に見つかったものを実行する（`which` で確認できる）。
- `PATH` の先頭にカレントディレクトリを足すと自作の `printenv` が勝つ。既定で入れないのは、同名の怪しいプログラムを実行しないため。
- `PATH` を空にすると `which` すら見つからなくなる（`which` もシェルが `PATH` で探していたため）。ターミナルを開き直せば元に戻る。

### まとめ

- 入力を解釈するのはターミナルではなくシェル。
- 子プロセスに渡るのは `export` した環境変数だけ（環境はコピーで渡る）。
- コマンドは `PATH` を左から探して最初に見つかったものが実行される。
