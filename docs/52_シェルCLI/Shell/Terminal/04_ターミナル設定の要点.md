# ターミナル設定の要点 — フォント・カラー・透過

## この文書のねらい

ターミナル（Windows Terminal / WezTerm / iTerm2 …）を **どれを選んでも同じように悩む** 設定項目がある。

- フォントをどれにするか
- 何色のテーマにするか
- 透過はどこまでかけるか
- IME・絵文字・Nerd Font で詰まないか

この文書では、**ツールを問わず共通する設定の勘所** を整理する。個別の手順は各ツール別ドキュメント（`Windows_Terminal.md` 等）を参照。

---

## 1. 優先順位：どこから手を付けるか

ターミナルを自分用にするときは、**効果が大きい順** にこの流れが効率的：

1. **フォント** — 読みやすさ＝疲労度に直結
2. **カラースキーム** — 可読性＋気分
3. **サイズと行間** — 目への負担
4. **キーバインド** — 頻用操作の省力化
5. **透過・背景** — あくまで飾り（やりすぎ注意）
6. **プロンプト** — シェル側で作るので最後

---

## 2. フォント選び

### 2-1. 必須条件

- **等幅**（monospace）であること — プロポーショナルは桁がズレて使い物にならない
- **半角英数・日本語・記号** のバランスがとれていること
- **全角文字が厳密に 2 倍幅**（ambiguous width が期待通り）

### 2-2. 有力候補

| フォント                    | 特徴                                               |
|-----------------------------|----------------------------------------------------|
| **Cascadia Code**           | Microsoft 純正、合字対応、絵文字対応               |
| **Cascadia Mono**           | Cascadia から合字を抜いた派生                      |
| **JetBrains Mono**          | JetBrains 純正、合字対応                           |
| **Fira Code**               | 合字の先駆け。人気が根強い                         |
| **Iosevka**                 | 細身、省スペース、バリアント多い                   |
| **Hack**                    | クセがなく読みやすい                               |
| **SF Mono**                 | macOS 純正                                         |
| **Source Code Pro**         | Adobe、安定                                        |
| **Ubuntu Mono**             | Ubuntu 純正                                        |

日本語も混ざるなら **合成指定**（Windows Terminal / WezTerm が対応）：

```
"fontFace": "Cascadia Code, BIZ UDGothic"
```

- 先に書いたほうが優先、カバー外を次のフォントで補う
- 日本語向け：**BIZ UDGothic** / **UD デジタル 教科書体** / **MS Gothic**（古参）

### 2-3. Nerd Font（アイコン入りフォント）

Powerlevel10k / starship のようなモダンプロンプトは **アイコン（`` `` など）** を使う。これには **Nerd Font 化された派生** が必要：

- `CascadiaCode Nerd Font`
- `FiraCode Nerd Font`
- `JetBrainsMono Nerd Font`

Nerd Fonts 公式（[nerdfonts.com](https://www.nerdfonts.com/)）から落とす。インストール後、設定の `fontFace` を Nerd Font 版に差し替える。

### 2-4. 合字（ligature）は有効？無効？

`===` が 1 つの記号に見える、`=>` が矢印に見える — これが合字。

- **有効**：コードエディタで使うならデザイン的に読みやすい
- **無効**：ログや数値出力で **意図しない結合** が起きる場合あり

ターミナル用なら **無効 or Mono 版を使う** のが無難。

## 3. フォントサイズと行間

### 3-1. サイズ

| 画面               | 目安         |
|--------------------|--------------|
| ノート 13〜14 型   | 11〜13 pt    |
| デスクトップ WQHD  | 12〜14 pt    |
| 4K モニタ          | 14〜18 pt    |
| 遠くから見る（ウェビナー） | 16 pt 以上 |

- **小さすぎる** と目が痛む。`Ctrl+`=`/`-`` 相当でその場で変えられる
- **大きすぎる** と 1 画面に入る情報が減る

### 3-2. 行間（`lineHeight` / `line_height`）

1.0（詰めすぎ）〜1.2（広すぎず読みやすい）の範囲。日本語が多いなら **1.1〜1.2** が目に優しい。

---

## 4. カラースキーム

### 4-1. 基本方針

- **背景：濃色（ダーク）**、**文字：淡色** が主流
- 16 色のパレット（ANSI カラー）を意識する：
  - `black` `red` `green` `yellow` `blue` `magenta` `cyan` `white` × normal / bright
- テーマはその 16 色の組み合わせを決めたもの

### 4-2. 定番テーマ

| テーマ              | 特徴                                         |
|---------------------|----------------------------------------------|
| **One Half Dark**   | VS Code 定番テーマの派生                    |
| **Solarized Dark**  | 青みのある落ち着いた古参                     |
| **Solarized Light** | 明るい部屋向けの同じ調色                     |
| **Tokyo Night**     | 紫〜青系、コントラスト強め                   |
| **Dracula**         | 紫中心、視認性高い                           |
| **Gruvbox Dark**    | レトロなアースカラー                        |
| **Nord**            | 寒色の落ち着いた配色                        |
| **Monokai**         | 暖色寄り、コード用老舗                       |
| **Campbell**        | Windows Terminal 既定                        |

### 4-3. 選ぶときの観点

- **背景とプロンプト色のコントラスト** — 迷子にならないか
- **エラーの赤は目立つか** — 致命的な赤が沈まないこと
- **コメント色が薄すぎないか** — grep 結果の強調が見えるか
- **長時間見て疲れないか** — 彩度が高すぎないか

1 日 8 時間見るので **「映える」より「疲れない」** 基準で。

### 4-4. 配色は気分で変える

業務用と個人用、本番サーバー接続時と開発時で **色スキームを分ける** のが事故防止に効く：

- 本番 SSH タブは **赤っぽく**、ローカルは **青っぽく** など
- PowerShell の通常タブと管理者タブも色分けする

## 5. 透過・背景

### 5-1. 透過（opacity / acrylic）

- 完全不透明（`opacity: 1.0`）が視認性は最高
- 85〜95% くらいの **ほんのり透過** が雰囲気もよく実害も少ない
- 60% を切ると **文字が読みにくくなる**

Windows Terminal なら：

```jsonc
"useAcrylic": true,
"opacity": 90
```

### 5-2. 背景画像

- 気分は上がるが、**作業中は文字の邪魔** になりがち
- 設定するなら **暗めで低彩度** の画像 + 透過強め
- ターミナルは情報密度が高いので、原則「無し or ごく淡く」

### 5-3. カーソル

- 形：**bar**（縦線）・**underscore**・**block**
- 点滅：あると目で追いやすいが、疲れる人も
- IME 入力時に **下線がきれいに出るか** を要チェック

---

## 6. キーバインドの要点

ターミナルのキー設定で **まず見直す** べきもの：

- **コピー / 貼り付け**：`Ctrl+C` は「中断」なので、`Ctrl+Shift+C/V` が慣例
  - `copyOnSelect` を有効にすると、選択するだけでコピー（Linux 流）
- **タブ切替**：`Ctrl+Tab` / `Ctrl+PageUp/Down`
- **ペイン分割**：`Alt+Shift+D` など
- **コマンドパレット**：`Ctrl+Shift+P`
- **検索**：`Ctrl+F`（ターミナル自身で検索）

---

## 7. 日本語環境の罠

### 7-1. 文字コード

- Windows の古い cmd 系は **CP932** が既定 → UTF-8 で書かれたファイルを `type` すると化ける
- 対処：`chcp 65001` でコードページを UTF-8 に（プロファイルに追加可）
- PowerShell 7 や WSL はデフォルトで UTF-8 なので意識せず済む

### 7-2. IME（変換中の表示）

- 変換中の下線・確定前文字が **カーソル位置と合わない** ことがある
- ターミナルによって IME 対応度が違う。乗り換え前に実機で試す
- Windows Terminal は年々良くなっているが、完璧ではない

### 7-3. 曖昧幅文字（Ambiguous width）

- `★` や `→` のような文字は、環境によって **半角扱い** か **全角扱い** かが違う
- 設定項目：
  - Windows Terminal：（現状自動）
  - WezTerm：`treat_east_asian_ambiguous_width_as_wide`
  - iTerm2：`Treat ambiguous-width characters as double width`
- 日本語環境では **全角（wide）扱い** が合うことが多い

---

## 8. スクロールバック

### 8-1. 行数の設定

- 既定 9000〜10000 行くらいのことが多い
- ログを長時間追うなら **50000〜100000** に増やす
  - 例：Windows Terminal の `historySize: 50000`

### 8-2. 検索とコピー

- 検索：`Ctrl+F` で過去の出力から検索
- スクロール：`Ctrl+PageUp/Down`、`Shift+マウスホイール`

---

## 9. 絵文字・Unicode

- 絵文字（Emoji）は **カラー描画対応のターミナル** でないと白黒になる
- Windows Terminal / WezTerm / iTerm2 は対応
- フォント側（Emoji フォント）のフォールバックも関係

---

## 10. 設定を失わないために：Dotfiles 化

- Windows Terminal の `settings.json`
- WezTerm の `wezterm.lua`
- Alacritty の `alacritty.toml`
- iTerm2 の preferences は **シンボリックリンク** で `Preferences` フォルダに入れる方法が定番

**Git で管理** しておけば、新しい PC でも `git clone` + リンクで 1 分復元できる（→ `../../Dotfiles/`）。

## 11. チェックリスト：新しい環境でまずやる 10 個

- [ ] 等幅フォントを好みのものに（Nerd Font 化推奨）
- [ ] フォントサイズを画面に合わせて調整（11〜14pt 目安）
- [ ] カラースキームを選ぶ（1 日かけて疲れないもの）
- [ ] 透過を 85〜95% くらいに
- [ ] コピーを `copyOnSelect`、貼り付けを `Ctrl+Shift+V` に
- [ ] タブ・ペイン分割のショートカットを確認
- [ ] スクロールバック行数を増やす（50000 など）
- [ ] 日本語が混ざった文字列で桁ズレがないか確認
- [ ] 本番用タブに **別カラー** を割り当てる
- [ ] 設定ファイルを **Git に追加**（dotfiles）

---

## 12. まとめ

- 優先順位は **フォント → 色 → サイズ → キー → 透過**
- 見た目より **疲れにくさ** と **ミスを減らす工夫**（色分け）を重視
- Nerd Font + 日本語フォント合成 が現代の定番
- 設定は **ファイル 1 枚**に収めて **Git で育てる**

ターミナルは **1 日の大半を過ごす場所**。カスタマイズにかけた時間は高確率で回収できる。
