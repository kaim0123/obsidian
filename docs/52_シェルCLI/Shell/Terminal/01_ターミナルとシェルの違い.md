# ターミナルとシェルの違い — 混同しがちな概念の整理

## この文書のねらい

「ターミナル」と「シェル」は、**完全に別の概念** にもかかわらず、日常会話では混同されがち。

- 「PowerShell を開く」「Windows Terminal を開く」は何が違うのか
- 「bash」と「GNOME Terminal」は同じなのか
- VS Code の「統合ターミナル」とはどこに属する話なのか

ここをハッキリさせることが、後々の **カスタマイズ・トラブル対応** の迷いを減らす出発点になる。

> **初めての人** → 先に `00_ターミナルとシェル入門.md`（ターミナル一覧・シェル一覧・組み合わせ例）を読むと、この文書が理解しやすい。

---

## 1. 結論（一言で）

> **ターミナル = 文字を表示する「窓」（ウィンドウアプリ）。シェル = キーボード入力を解釈する「中の人」（プログラム）。**

```
[ ターミナル（Windows Terminal など） ]   ← ウィンドウ本体
        ↑ 文字を表示          ↓ キー入力を受け取る
[ シェル（bash, PowerShell, zsh など） ] ← コマンドを解釈・実行
        ↑ プログラム呼び出し
[ OS（Windows / Linux / macOS） ]
```

**1 つのターミナルアプリの中で、好きなシェルを起動できる**。両者は独立して選べる。

---

## 2. 歴史的な経緯（なぜ分かれているのか）

1960〜70 年代、コンピュータは 1 台を多人数で共有していた。
手元の **物理的な「端末（terminal）」= 画面＋キーボード** が本体（メインフレーム）に繋がっていた。

```
[端末 1] ─┐
[端末 2] ─┼─→ [メインフレーム（ここでシェルが動く）]
[端末 3] ─┘
```

- 端末 = 入出力装置
- シェル = プログラムを起動する仕組み

**いまは PC 1 台で完結しているが、この「別物」という分業はそのまま残っている**。
PC 上の「ターミナル（アプリ）」は、かつての物理端末を画面上に模した **仮想端末（Terminal Emulator）**。

## 3. 具体例で見る

### 3-1. Windows

| ターミナル（窓）             | 中で動くシェル例                                  |
|------------------------------|---------------------------------------------------|
| **Windows Terminal**         | PowerShell 7 / Windows PowerShell / cmd / WSL bash |
| **VS Code 統合ターミナル**   | 同上、好きなものを設定で選べる                    |
| 旧 **conhost**（cmd.exe の窓）| cmd / PowerShell                                 |
| **PowerShell.exe（単体）**   | PowerShell                                        |
| **Git Bash**                 | bash（Git for Windows 付属）                      |
| **WSL（`wsl`コマンド）**     | 各ディストリのログインシェル（既定は bash）       |

### 3-2. macOS

| ターミナル                  | 中で動くシェル例                      |
|-----------------------------|--------------------------------------|
| **Terminal.app**（標準）    | zsh（10.15〜既定）／ bash / fish 等 |
| **iTerm2**                  | 同上                                  |
| **Alacritty / WezTerm**     | 同上                                  |
| **Warp**                    | 同上（独自の AI 機能を持つ）          |

### 3-3. Linux

| ターミナル                  | 中で動くシェル例                      |
|-----------------------------|--------------------------------------|
| GNOME Terminal / Konsole    | bash / zsh / fish など                |
| Alacritty / Kitty / WezTerm | 同上                                  |
| TTY（Ctrl+Alt+F1 などのコンソール）| 同上                          |

## 4. 役割の分担

### 4-1. ターミナル（エミュレータ）の仕事

- ウィンドウの表示・タブ・分割
- **フォント・色・背景画像・透過**
- キーボードショートカット（コピー、検索、タブ切替）
- **スクロールバック**（過去の出力を遡れる）
- IME・マウス入力の受け渡し

### 4-2. シェルの仕事

- コマンドの解釈（`ls *.log | grep ERROR` を分解）
- **変数・関数・制御構文**
- パイプ・リダイレクト
- **プロンプト**（`user@host:~$` を作っているのはシェル）
- ヒストリ（シェルごとにファイルが分かれる：`.bash_history`, `.zsh_history`）
- 補完（シェルごとに機能差が大きい）

### 4-3. 境界にあるもの

- **色のエスケープシーケンス**：シェルが `\e[31m` を出す → ターミナルが「赤」と解釈して色を付ける
- **Ctrl+C**：ターミナルが受け取って SIGINT に変換 → シェルが実行中プロセスに伝える

---

## 5. なぜ区別が重要か

### 5-1. 「設定する場所」が違うから

| 設定したいもの                 | いじる場所                                  |
|--------------------------------|---------------------------------------------|
| **フォント・色・背景**         | **ターミナル側**（Windows Terminal の設定） |
| **プロンプト表示（`PS1` など）** | **シェル側**（`.bashrc` / `$PROFILE`）     |
| タブ切替ショートカット         | **ターミナル側**                            |
| `Ctrl+R` の履歴検索動作        | **シェル側**                                |
| エイリアス・補完               | **シェル側**                                |

「色を変えたい」のにシェル側をいじっても無駄、「`ll` エイリアスを作りたい」のにターミナル設定を開いても意味がない。

### 5-2. 「文字化け」の犯人探し

- **ターミナルが UTF-8 対応していない** → シェルが UTF-8 を出しても化ける
- **シェルのロケールが違う** → ターミナル側が UTF-8 でも化ける

どちらも確認しないと直せない典型例。

### 5-3. 「ここで動くか」の予測

- Windows Terminal を入れても、**中で動くシェルが bash** なら bash コマンドしか通らない
- **PowerShell のタブに切り替える** と同じウィンドウでもコマンドセットが変わる

## 6. よくある誤解

| 誤解                                           | 実際                                                         |
|------------------------------------------------|--------------------------------------------------------------|
| 「PowerShell = ターミナル」                   | PowerShell は **シェル**。窓は Windows Terminal や VS Code 統合 |
| 「Windows Terminal でしか PowerShell は動かない」| どのターミナルでも起動できる（`pwsh` を呼ぶだけ）          |
| 「bash は Linux のターミナル名」               | bash は **シェル**。Linux のターミナルは GNOME Terminal など |
| 「Git Bash はターミナル」                      | Git Bash は **「MinTTY ターミナル + bash シェル」のセット**  |
| 「VS Code 統合ターミナルは独自のシェル」       | **窓（エミュレータ）だけ**提供。中身は PowerShell / bash 等  |

---

## 7. 図解：VS Code を例に

VS Code の「ターミナル」という UI は、実際には：

```
[ VS Code の ターミナルペイン（= 窓） ]
        ↓
[ 設定で選んだシェル（PowerShell / bash / zsh など） ]
```

`settings.json` の `terminal.integrated.defaultProfile.windows`（OS 別）で **シェルを切り替えできる**。見た目は同じでも中身は別、の典型。

---

## 8. セッションの入れ子

シェルの中で別のシェルを起動することもある：

```
Windows Terminal（窓）
  └─ pwsh（PowerShell）
       └─ wsl（WSL ディストリへ）
            └─ bash
                 └─ python       # 対話 REPL（これはシェルではなくプログラム）
```

各層が「自分の親」に入力を渡す構造。`exit` で 1 つずつ戻る。

---

## 9. まとめ

- **ターミナル = 窓**（Windows Terminal, iTerm2, GNOME Terminal など）
- **シェル = 窓の中で動くプログラム**（bash, zsh, fish, PowerShell, cmd）
- **別物なので別々にカスタマイズ・トラブル対応する**
- 見た目（色・フォント）はターミナル、プロンプト・エイリアスはシェル
- Git Bash / WSL は **セット品**だが、中で何が動いているかは分解して考えるのがコツ

この区別ができるようになると、ネットの記事を読むときの **「何をどこに書くべきか」** がハッキリ見える。
