# シェルスクリプト入門

## この文書のねらい

コマンドラインで毎回同じ手順を打つなら、**シェルスクリプト** にまとめると一発で実行できる。
バックアップ、デプロイ、ログ解析、開発環境セットアップ — これらはほぼシェルスクリプトで片付く。

この文書では、**動くスクリプトを 1 ファイル書ける** ところから、**壊れにくいスクリプトを書ける** ところまで、最短で到達することを目標にする。

---

## 1. シェルスクリプトとは

> **コマンドをファイルに並べたもの。上から順に実行される。**

ファイルに `.sh` の拡張子を付け、先頭に **shebang（シバン）** を書く。

```bash
#!/usr/bin/env bash
echo "Hello, world"
```

- `#!` の行は **使うインタプリタの指定**。これが無いと何で動かすかがシステムに伝わらない
- `#!/usr/bin/env bash` が移植性の高い定番（`/bin/bash` より環境依存が少ない）

---

## 2. 最初のスクリプトを動かす

### 2-1. ファイルを作る

```bash
cat > hello.sh <<'EOF'
#!/usr/bin/env bash
echo "Hello, $USER"
echo "今日は $(date '+%Y-%m-%d')"
EOF
```

### 2-2. 実行権限を付ける

```bash
chmod +x hello.sh
```

### 2-3. 実行する

```bash
./hello.sh
```

- `./` を **付けるのが大事**（カレントディレクトリは `PATH` に含まれないのが普通）
- `bash hello.sh` という呼び方もある。この場合は shebang と実行権限が無くても動く

## 3. 変数と引数

### 3-1. 変数

```bash
name="Alice"
echo "Hello, $name"
```

（→ 詳しくは `環境変数とexport.md`）

### 3-2. 位置引数

スクリプトに渡された引数は `$1` `$2` ... で取り出す。

```bash
#!/usr/bin/env bash
echo "最初の引数: $1"
echo "2 番目: $2"
echo "全部: $@"
echo "個数: $#"
```

```bash
./script.sh foo bar
# 最初の引数: foo
# 2 番目: bar
# 全部: foo bar
# 個数: 2
```

| 記号  | 意味                                            |
|-------|-------------------------------------------------|
| `$0`  | スクリプト名                                    |
| `$1` .. `$9` | 個別の引数                               |
| `$#`  | 引数の個数                                      |
| `$@`  | 全引数（個別に展開：だいたいこっちを使う）      |
| `$*`  | 全引数（1 つの文字列として）                    |
| `$?`  | 直前コマンドの終了ステータス                    |
| `$$`  | 現在の PID                                       |

### 3-3. 読み取り時に `"..."` で囲む

```bash
rm "$1"      # "$1" のようにクォート。空白や空文字列の事故を防ぐ
```

## 4. 条件分岐 `if`

### 4-1. 基本形

```bash
if [ "$1" = "hello" ]; then
    echo "こんにちは"
elif [ "$1" = "bye" ]; then
    echo "さようなら"
else
    echo "よくわかりません"
fi
```

### 4-2. `[` と `[[` の違い

```bash
[ "$x" = "foo" ]          # POSIX 準拠。sh でも動く
[[ "$x" == "foo" ]]       # bash 拡張。より安全・多機能
```

- **bash を前提にするなら `[[ ... ]]`** がおすすめ
- パターンマッチや `&&` / `||` が内部で使える

### 4-3. よく使う比較

| 書き方              | 意味                         |
|---------------------|------------------------------|
| `[[ -z "$x" ]]`     | 空文字列か                   |
| `[[ -n "$x" ]]`     | 空でないか                   |
| `[[ "$a" == "$b" ]]` | 文字列が等しい              |
| `[[ "$a" != "$b" ]]` | 等しくない                  |
| `[[ "$a" == foo* ]]` | パターンマッチ（`[[` 専用） |
| `[[ "$a" =~ ^[0-9]+$ ]]` | 正規表現マッチ           |
| `(( a > b ))`       | 数値比較                     |
| `[[ -f file ]]`     | ファイルが存在              |
| `[[ -d dir ]]`      | ディレクトリが存在          |
| `[[ -e path ]]`     | 何らかが存在                |

## 5. 繰り返し

### 5-1. `for`

```bash
for f in *.log; do
    echo "処理中: $f"
done
```

### 5-2. 数値の繰り返し

```bash
for i in {1..5}; do
    echo $i
done

for ((i=0; i<10; i++)); do
    echo $i
done
```

### 5-3. `while`

```bash
count=0
while (( count < 5 )); do
    echo $count
    ((count++))
done
```

### 5-4. ファイルを 1 行ずつ読む

```bash
while IFS= read -r line; do
    echo "行: $line"
done < input.txt
```

- `IFS=` で前後の空白を保持
- `-r` でバックスラッシュをリテラル扱い
- このイディオムは丸暗記して OK

## 6. 関数

```bash
greet() {
    local name="$1"
    echo "Hello, $name"
}

greet "Alice"
```

- `local` で変数をその関数内に閉じ込める（忘れると外に漏れる）
- 返り値は `return N`（0〜255）、または `echo` で値を返してキャッチ

```bash
get_date() {
    date '+%Y-%m-%d'
}

today=$(get_date)
echo "$today"
```

## 7. 壊れにくいスクリプトの定型

スクリプトの先頭に **おまじない** を入れる：

```bash
#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'
```

### 7-1. `set -e`

- コマンドが 1 つでも失敗したら **即座に終了**
- 失敗を見逃して次に進まない

### 7-2. `set -u`

- **未定義の変数を使ったらエラー**
- `$UNDEFINED` を使ったタイポが即バレる

### 7-3. `set -o pipefail`

- パイプの途中で失敗しても **全体を失敗扱い** にする
- 普段 `|` の左が失敗しても右が成功すれば exit 0 になるのを防ぐ

### 7-4. `IFS=$'\n\t'`

- 単語分割の区切りを **改行とタブだけ** にする
- 空白を含むファイル名でも壊れにくくなる

## 8. エラーハンドリング

### 8-1. 失敗時のトラップ

```bash
trap 'echo "エラー: $LINENO 行目で失敗"; exit 1' ERR
```

- `ERR` トラップで、どこで失敗したか行番号が拾える

### 8-2. 後始末（クリーンアップ）

```bash
tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT

# ... tmp を使う処理 ...
```

- スクリプトが終了する（正常終了でも異常終了でも）と `rm` が走る
- 一時ファイルを残さない定番パターン

### 8-3. 失敗してもいい箇所

```bash
rm old.log || true
```

- `|| true` で終了ステータスを無理やり 0 に
- `set -e` 下でもここは止まらない

## 9. 引数のバリデーションとヘルプ

```bash
#!/usr/bin/env bash
set -euo pipefail

usage() {
    cat <<EOF
Usage: $(basename "$0") <input_file> <output_dir>

指定したファイルを圧縮して output_dir にコピーします。
EOF
    exit 1
}

if [[ $# -lt 2 ]]; then
    usage
fi

input="$1"
outdir="$2"

[[ -f "$input" ]] || { echo "入力ファイルがありません: $input" >&2; exit 1; }
[[ -d "$outdir" ]] || { echo "出力ディレクトリがありません: $outdir" >&2; exit 1; }

# ... 本処理 ...
```

**ポイント**：
- 先頭にヘルプ、次に引数チェック、最後に本処理、の並びに統一する
- エラーメッセージは `>&2` で stderr に

## 10. 実例：ミニバックアップスクリプト

```bash
#!/usr/bin/env bash
set -euo pipefail

SRC="$HOME/dev"
DST="$HOME/backup"
DATE=$(date '+%Y%m%d-%H%M%S')
ARCHIVE="$DST/dev-$DATE.tar.gz"

mkdir -p "$DST"

tar -czf "$ARCHIVE" -C "$(dirname "$SRC")" "$(basename "$SRC")"

echo "作成: $ARCHIVE"
echo "サイズ: $(du -h "$ARCHIVE" | cut -f1)"

# 古いバックアップを 10 個まで残す
ls -1t "$DST"/dev-*.tar.gz | tail -n +11 | xargs -r rm -v
```

## 11. スクリプトの品質を上げるツール

### 11-1. ShellCheck

```bash
shellcheck script.sh
```

- シェルスクリプト用の静的解析。**全スクリプトにかけるべき**
- `SC2086` `SC2046` などのよくあるバグを指摘してくれる
- VS Code 拡張もあり、保存時に自動チェック可

### 11-2. `shfmt`

- コードフォーマッタ
- インデント・改行を統一できる

## 12. bash で止めるべきか、Python / Go に移るべきか

シェルスクリプトは **数十〜数百行まで** が守備範囲。
これを超えて次のどれかを感じ始めたら **移植を検討**：

- 配列や辞書を本格的に使いたい
- 浮動小数点演算が必要
- テストが欲しい
- Windows でも動かしたい（bash は前提にしづらい）

移植先の候補：
- **Python** — 文字列処理・データ加工、テストも書きやすい
- **Go** — バイナリ 1 つで配布したい
- **PowerShell** — Windows 中心なら

**判断基準**：「このスクリプト、5 ヶ月後の自分が読んで直せるか？」で Yes なら bash 継続、怪しければ移植。

## 13. つまずきやすいポイント

| 症状                                       | 原因・対処                                             |
|--------------------------------------------|--------------------------------------------------------|
| `./script.sh` が「コマンドがない」        | shebang がおかしい or 実行権限がない or 改行コードが CRLF |
| 変数が空白で分割されて壊れる              | `"$var"` のように必ずクォート                          |
| `cd` してもスクリプト終了後に戻る          | スクリプトは子プロセス。移動は呼び出し元には及ばない   |
| 関数の外で変数が壊れている                | `local` を忘れている                                   |
| `set -e` が効かない箇所がある             | パイプ・サブシェル・`if` 条件部は例外。`set -o pipefail` も併用 |
| Windows で編集したら動かない              | 改行 CRLF → LF に変換（`dos2unix` or Git の autocrlf） |

---

## 14. まとめ

- まずは **3 行のスクリプト** から始める（shebang + 1 コマンド + 実行権限）
- 変数・条件・ループ・関数の **基本構文** を押さえれば 7 割書ける
- `set -euo pipefail` + `IFS=$'\n\t'` を定型で入れる
- **ShellCheck** を通せば品質が一段上がる
- 数百行を超えたら **別言語への移植** を検討

シェルスクリプトは「書き捨て」と思われがちだが、**Git で管理して育てる** と資産になる。dotfiles と一緒に運用するのが現代的（→ `../../Dotfiles/`）。
