# bash 基礎 — シェルの基本動作と起動モード

## この文書のねらい

**bash (Bourne-Again SHell)** は Linux / macOS の事実上の標準シェルで、Git Bash や WSL を通じて Windows でも使う。
PowerShell と違って **テキスト（文字列）を扱う** のが基本。

この文書では、bash が「どう動いているか」「どう起動するか」「最低限どう書くか」を、初心者が **自分の環境で何が起きているか説明できる** レベルまで整理する。

> **シェル全体の一覧・ターミナルとの違い** → 先に `../Terminal/00_ターミナルとシェル入門.md`

---

## 1. そもそも bash とは

### 1-1. 立ち位置

- Bourne Shell（`sh`）の後継。**GNU プロジェクト**による再実装
- Linux ディストリビューションの多くで **既定のログインシェル**
- macOS は 10.15 Catalina 以降、既定は `zsh`。ただし `bash` も入っている（古いバージョン）
- Windows では **Git Bash**（Git for Windows 付属の MINGW64）と **WSL** で使える

### 1-2. シェルとは何か

> キーボード入力（文字列）を解釈して OS のプログラムを起動する「仲介役」。

```
人間 → [bash] → カーネル → プログラム起動
```

- 対話モード：あなたがプロンプトで 1 行ずつ打つ
- 非対話モード：スクリプトファイルを頭から順に実行する

---

## 2. 起動モードの 4 分類 — 重要

bash は **起動のされ方** によって、どの設定ファイルを読むかが変わる。
これが **`.bashrc` / `.bash_profile` 問題** の根源。

### 2-1. 2 つの軸

| 軸                | 状態                                 |
|-------------------|--------------------------------------|
| 対話的 / 非対話的 | プロンプトを表示するか（人間と会話するか） |
| ログイン / 非ログイン | ログインセッションの最上位シェルか |

組み合わせで **4 象限**：

|                  | 対話的                        | 非対話的             |
|------------------|-------------------------------|----------------------|
| **ログイン**     | SSH ログイン直後 / macOS Terminal | 一部のスクリプト実行 |
| **非ログイン**   | Linux でターミナル起動後の子シェル | ほとんどのスクリプト |

### 2-2. 実例で見分ける

- **SSH でサーバに入った直後** → ログイン・対話
- **GUI のターミナルアプリを開いた** → OS によってログイン扱いだったり非ログインだったり
- **`bash` と打って子シェル** → 非ログイン・対話
- **`./script.sh` 実行** → 非ログイン・非対話
- **`bash --login script.sh`** → ログイン・非対話

### 2-3. 各モードで読まれるファイル

#### ログイン・シェル起動時（順番に読む）
1. `/etc/profile`
2. `~/.bash_profile` → あれば以降はスキップ
3. 無ければ `~/.bash_login`
4. さらに無ければ `~/.profile`

#### 対話・非ログイン・シェル起動時
- `/etc/bash.bashrc`（環境による）
- `~/.bashrc`

#### 非対話・非ログイン
- 原則、どのファイルも読まれない（`BASH_ENV` で明示すれば別）

**混乱を避ける定番パターン**：`~/.bash_profile` から `.bashrc` を呼び出しておく：

```bash
# ~/.bash_profile
[ -f ~/.bashrc ] && . ~/.bashrc
```

詳細は `bashrcとbash_profile.md`。

## 3. プロンプトの読み方

```
user@host:~/dev/project $
│   │   │         │   │
│   │   │         │   └ プロンプト末尾（一般ユーザは $、root は #）
│   │   │         └──── カレントディレクトリ（~ はホーム）
│   │   └─────────────── ホスト名
│   └───────────────────── 区切り
└──────────────────────── ユーザ名
```

環境変数 **`PS1`** で見た目をカスタマイズできる：

```bash
export PS1='\u@\h:\w\$ '      # よく見る標準形
export PS1='\W \$ '            # 最小限（basename だけ）
```

## 4. コマンドの基本構造

```bash
command  [options]  [arguments]

ls       -la        /var/log
└┬─┘     └┬─┘       └──┬──┘
コマンド  オプション     引数
```

- **コマンド**：実行するプログラム（`ls`, `grep`, `echo`）
- **オプション**：挙動を変えるスイッチ。短縮形 `-l` と長形式 `--long` がある
- **引数**：コマンドが対象にするもの

### 4-1. オプションの書き方バリエーション

```bash
ls -l -a /tmp         # 別々
ls -la /tmp           # まとめる
ls --all --long /tmp  # 長形式
ls -a --long /tmp     # 混在も可
```

### 4-2. `--` の意味

```bash
rm -- -file.txt
```

- `--` は「これ以降はオプションではなく引数」の合図
- 名前が `-` で始まるファイルを扱うときの定番

## 5. 変数と `$`

### 5-1. 代入と参照

```bash
name="Alice"
echo "Hello, $name"
echo "Hello, ${name}!"
```

- **代入時に `$` を付けない**、**参照時に `$` を付ける**
- **`=` の周りに空白を入れない**（`name = "Alice"` はエラー）

### 5-2. 引用符の違い（重要）

| 囲み方         | 中身の扱い                     |
|----------------|--------------------------------|
| `'...'` シングル | **何も展開しない**（完全リテラル） |
| `"..."` ダブル   | 変数 `$...` / バッククォートは展開 |
| `` `...` ``    | コマンド置換（`$(...)` 推奨）  |

```bash
echo '$HOME'     # → $HOME
echo "$HOME"     # → /home/alice
echo "$(date)"   # → 2026年 4月 22日 ...
```

### 5-3. よく使う環境変数

| 変数       | 意味                          |
|------------|-------------------------------|
| `$HOME`    | ホームディレクトリ            |
| `$USER`    | ログインユーザー名            |
| `$PATH`    | 実行ファイル検索パス          |
| `$PWD`     | カレントディレクトリ          |
| `$SHELL`   | ログインシェルのパス          |
| `$?`       | 直前コマンドの終了ステータス  |
| `$$`       | 現在のプロセス ID             |

→ 詳細は `環境変数とexport.md`

## 6. 終了ステータスと `$?`

UNIX のコマンドは **数値の終了ステータス** を返す：

- `0` = 成功
- `0 以外` = 失敗（意味はコマンドごと、よく使うのは 1, 2, 127 など）

```bash
ls /nonexistent
echo $?     # → 2（エラーだったことがわかる）
```

### 条件実行

```bash
make && ./run              # make 成功時のみ ./run
make || echo "失敗"         # make 失敗時のみ echo
make && ./run || echo "どこかで失敗"
```

- `&&` ：前が成功したら次を実行
- `||` ：前が失敗したら次を実行

## 7. コマンド置換・サブシェル・ブレース展開

### 7-1. コマンド置換 `$(...)`

```bash
today=$(date +%Y-%m-%d)
echo "今日は $today"
```

- コマンドの **出力を文字列として埋め込む**
- 古い書き方 `` `...` `` はネストしにくいので `$(...)` 推奨

### 7-2. サブシェル `(...)`

```bash
( cd /tmp && ls )     # 親のカレントディレクトリは変わらない
pwd                    # 元の場所のまま
```

- `( )` の中は **子プロセス** で実行される
- ディレクトリ移動や環境変数の変更が **外に影響しない**

### 7-3. ブレース展開 `{}`

```bash
echo file_{1,2,3}.txt      # → file_1.txt file_2.txt file_3.txt
echo {a..e}                 # → a b c d e
mkdir -p project/{src,test,docs}
```

## 8. ワイルドカード（グロブ）

```bash
ls *.txt          # 拡張子 .txt
ls *.{jpg,png}    # 複数パターン
ls ?.c            # 1 文字だけ
ls [abc]*         # a か b か c で始まる
```

- これは bash の機能。シェルがファイル名に展開してからコマンドに渡す
- マッチ対象がなければ、そのままの文字列として渡される（設定で変更可）

## 9. ヘルプの引き方

```bash
ls --help        # コマンド自身の簡易ヘルプ
man ls           # マニュアルページ（詳細）
help cd          # bash 組み込みコマンドのヘルプ
type ls          # ls は何か（エイリアス？実行ファイル？）
which ls         # 実行ファイルのパス
```

- `--help` と `man` は慣習。使えないコマンドもある
- `type` は最重要（「これはエイリアス？関数？ビルトイン？」がわかる）

## 11. つまずきやすいポイント

| 症状                                 | 原因・対処                                        |
|--------------------------------------|---------------------------------------------------|
| `$HOME`と書いたのに変数が展開されない | シングルクォートで囲っている                     |
| `name = "x"` がエラー                 | `=` の前後の空白は禁止                            |
| `.bashrc` を書いたのに反映されない    | ログインシェルでは読まれない（→ `.bash_profile`） |
| スクリプトが動かない                 | 先頭に `#!/usr/bin/env bash`、`chmod +x`          |
| 日本語が文字化け                     | ロケール（`LANG=ja_JP.UTF-8`）・ターミナル側の設定 |
| `sudo` の後でエイリアスが効かない    | `sudo` は別シェル。`alias sudo='sudo '` で対処可  |

## 12. まとめ

- bash は **テキスト志向のシェル**。PowerShell とは発想が違う
- 起動モード 4 種類 × 読み込むファイルの違いが **最初の壁**
- 引用符とワイルドカードは **すべての基礎**
- `$?` とパイプで **コマンドを繋げる**のが真骨頂（→ `リダイレクトとパイプ.md`）
- 「`type コマンド名`」で正体を確認する癖をつけると迷子にならない
