# zsh / fish との比較 — 乗り換え検討時の判断材料

## この文書のねらい

bash を使っていると、周りから **「zsh 速いよ」「fish 便利だよ」** という声が聞こえてくる。
実際どれくらい違うのか、乗り換えるならどういう基準で選ぶか、**何を捨てて何を取るか** を整理する。

結論を先に：

- **普段の対話操作だけ速くしたい** → **zsh** か **fish**
- **スクリプトの互換性を保ちたい** → **bash のまま**
- **学習コストを下げたい** → **fish**
- **最大限カスタマイズしたい** → **zsh**

---

## 1. 一言比較

| シェル  | 一言で                                                      |
|---------|-------------------------------------------------------------|
| **bash** | デファクト。どこにでもあり、スクリプトの事実上の標準         |
| **zsh**  | bash 互換 + 強化版。カスタマイズに底がない                   |
| **fish** | 「今の常識」で作り直した現代的シェル。bash 非互換だが即戦力 |

---

## 2. 立ち位置と歴史

```
sh (Bourne Shell, 1977)
   ├─ bash (1989) ─ GNU 版。事実上の標準
   ├─ ksh ─ 商用環境で多い
   └─ zsh (1990) ─ bash/ksh の長所と補完強化

別系統
└─ fish (2005) ─ POSIX 互換を捨てた代わりに UX を重視
```

- bash / zsh は **POSIX 系の子孫**。構文はだいたい共通
- fish は **別言語** と思うほうが近い

---

## 3. 採用状況

| 環境                       | 既定シェル                            |
|----------------------------|--------------------------------------|
| ほとんどの Linux           | bash                                 |
| macOS（〜10.14）           | bash (3.2 の古いもの)                |
| macOS（10.15 Catalina〜）  | **zsh**                              |
| Ubuntu デスクトップ      | bash（`sh` は dash）                 |
| Windows (Git Bash)         | bash                                 |
| Windows (WSL)              | 配布による（Ubuntu なら bash）       |

**macOS の既定が zsh になった** ことで zsh の存在感が一気に増した。

## 4. 機能比較表

| 機能                             | bash               | zsh                  | fish                |
|----------------------------------|--------------------|-----------------------|---------------------|
| POSIX 互換（sh スクリプト動く）  | ○                 | ○（ほぼ）             | ×                   |
| タブ補完                         | 基本               | **強力**（メニュー）  | **強力**（文脈認識） |
| 履歴からの予測入力（autosuggest） | なし（要拡張）    | あり（要設定 / プラグイン） | **既定**          |
| 構文ハイライト                   | なし               | あり（プラグイン）    | **既定**            |
| プロンプト                       | PS1 で自作         | テーマ豊富（p10k等） | テーマあり           |
| 配列・連想配列                   | あり（機能限定）  | **あり（強力）**      | あり（独自構文）     |
| スクリプト資産の流用             | ◎                 | ◎（ほぼそのまま）     | △（書き直し必要）    |
| 学習コスト                       | 低                 | 中                    | **低**              |
| カスタマイズの深さ               | 中                 | **深い**              | 中                  |
| フレームワーク                   | bash-it 等         | oh-my-zsh, prezto, p10k | fisher, omf     |
| 起動速度                         | 速い               | 設定次第で重くなる    | 速い                |

## 5. 対話 UX（実感できる差）

### 5-1. タブ補完

- **bash**：完全一致 or 部分一致で止まる。補完スクリプトを別途入れる必要あり
- **zsh**：メニュー式で矢印キー選択、`cd /u/l/b` → `/usr/local/bin` 補完など強力
- **fish**：**文脈を読んで**引数候補まで出す（`git checkout` でブランチ名が出る）

### 5-2. ヒストリ検索

- bash：`Ctrl+R` で履歴検索
- zsh：zsh-history-substring-search など、矢印で部分一致ジャンプ可
- fish：**既定で autosuggest**。打ち始めると薄い字で候補が見える、`→` で確定

### 5-3. プロンプト

- bash：`PS1` を書く。Git 情報を出すなら `__git_ps1` を組み込む
- zsh：**Powerlevel10k** が事実上の定番。速い・綺麗・設定ウィザード付き
- fish：テーマ機能内蔵

## 6. スクリプト言語としての違い

### 6-1. bash / zsh

```bash
# bash・zsh どちらでも動く
for f in *.log; do
    echo "$f"
done
```

- zsh は **ほぼ bash のスーパーセット**。既存の bash スクリプトはだいたい動く
- 配列・連想配列は zsh の方が強力

### 6-2. fish は構文が違う

```fish
# fish 専用
for f in *.log
    echo $f
end
```

- `then` / `fi` ではなく `end`
- 変数代入は `set x 1`（`x=1` ではない）
- **bash スクリプトはそのままでは動かない**

そのため、fish を対話シェルに使っていても **スクリプトは bash で書く** のが現実的。shebang を `#!/usr/bin/env bash` にすれば共存できる。

## 7. 乗り換えの判断基準

### 7-1. 「bash から動かない」と判断していい人

- **サーバー管理者** — 本番サーバーは bash だけ入っていることが多い。対話も bash でやって一貫させる
- **配布スクリプトを書く人** — POSIX / bash 前提で書けば誰でも動かせる
- **学習途中** — まずは bash で一通り覚える。乗り換えは後でよい

### 7-2. zsh を検討する人

- **macOS 既定で使っている** — せっかくなので活用
- **プロンプト・補完にこだわりたい** — p10k + oh-my-zsh で世界が変わる
- **bash のスクリプト資産を守りたい** — 互換性が高いので安心

### 7-3. fish を検討する人

- **細かい設定より「開けてすぐ快適」が欲しい** — 既定で補完・履歴予測・色が揃っている
- **POSIX 互換を気にしなくていい** — 対話シェルだけ切り替え、スクリプトは bash で書く
- **「$@ と $* の違い」みたいな歴史的負債を避けたい**

---

## 8. 段階的な乗り換え手順

### 8-1. 現在のシェルを確認

```bash
echo $SHELL
```

### 8-2. インストール（Linux / macOS）

```bash
# zsh
sudo apt install zsh        # Debian/Ubuntu
brew install zsh             # macOS

# fish
sudo apt install fish
brew install fish
```

### 8-3. 試しに起動（ログインシェルは変えない）

```bash
zsh       # 試し打ち、気に入らなければ exit
fish
```

- 既定シェルを変えないまま **一時起動**して試せる
- 既存の bash 環境は壊れない

### 8-4. 気に入ったら既定に

```bash
# 登録済みシェル一覧
cat /etc/shells

# 必要なら追加
which fish | sudo tee -a /etc/shells

# 既定シェル変更
chsh -s $(which zsh)        # または which fish
```

ログイン後に反映される。失敗しても `chsh -s /bin/bash` で戻せる。

### 8-5. 共通設定は `.profile` に

どのシェルでも読む `~/.profile` に **bash 非依存な環境変数**（PATH など）だけ書く。
シェル固有の設定は `~/.zshrc` や `~/.config/fish/config.fish` に。

## 9. フレームワーク・テーマ

### 9-1. zsh

- **oh-my-zsh** — プラグイン・テーマの集合体。敷居が低く始めやすい
- **prezto** — 軽量。oh-my-zsh より起動が速い
- **zinit** / **sheldon** — プラグインマネージャだけ使って自分で組み立てる
- **Powerlevel10k（p10k）** — テーマの定番。非同期描画で速い

### 9-2. fish

- **fisher** — 代表的なプラグインマネージャ
- **starship** — bash / zsh / fish どれでも使えるクロスシェルプロンプト（推奨度高）

### 9-3. bash

- **bash-it** — oh-my-zsh の bash 版
- **starship** — fish 同様こちらも使える
- **Nix / asdf** 等でバージョン管理するときは素の `.bashrc` のほうが楽

---

## 10. つまずきやすいポイント

| 症状                                                 | 原因・対処                                              |
|------------------------------------------------------|---------------------------------------------------------|
| zsh で `~/.bashrc` が効かない                        | zsh は読み込まない。`.zshrc` に転記 or 明示 `source`    |
| fish で `source` スクリプトが動かない                | 構文違い。bash で書くなら `bash script.sh` で実行       |
| プロンプトが遅くなった                               | oh-my-zsh の読み込み過多 / git 情報取得が重い。p10k へ  |
| 乗り換えたら PATH が変わった                         | 共通部分は `~/.profile` に集約                           |
| Cursor では `claude` が動くが bash では `command not found` | `.zshrc` だけに PATH を書いている。→ `PATHとprofile入門.md` |
| Homebrew の補完が効かない                            | `FPATH` / `fpath` の設定追加が必要                       |

---

## 11. まとめ

- **bash** は「どこでも動く」が最大の強み。スクリプトの既定はこのまま
- **zsh** は bash 互換を保ちつつ対話 UX を大幅強化。カスタマイズ好きなら天国
- **fish** は「使い始めて即便利」な現代シェル。互換性を捨てた代わりに軽い
- 対話シェルとスクリプトは **分けて考える** のが現代的：対話は好みで、スクリプトは bash で
- 迷ったら一度 **starship + zsh/fish** を試してみて、合わなければ戻せる
