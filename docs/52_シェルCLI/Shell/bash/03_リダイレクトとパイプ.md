# リダイレクトとパイプ — `>` `>>` `2>&1` `|`

## この文書のねらい

UNIX 系シェルの真価は **「小さなコマンドを組み合わせる」** ところにある。
その接続器が **パイプ `|`** と **リダイレクト `>` `>>` `<` `2>&1`**。

この記号たちを **読み書きできるようになる** のが、bash を「使えるようになる」ことと同義。

---

## 1. 前提：3 本の流れ（ストリーム）

どのコマンドも、起動すると必ずこの 3 つを持つ。

| 番号 | 名前                       | 用途                       | 既定の向き先         |
|------|----------------------------|----------------------------|----------------------|
| `0`  | 標準入力（stdin）         | データの入り口             | キーボード           |
| `1`  | 標準出力（stdout）        | 通常の結果                 | 画面                 |
| `2`  | 標準エラー出力（stderr）  | エラー・警告メッセージ     | 画面                 |

**鍵となる気づき**：`1` と `2` は別の流れ。画面に混じって見えるだけで、分けられる。

---

## 2. 出力リダイレクト `>` と `>>`

### 2-1. `>` — ファイルに書く（上書き）

```bash
ls > files.txt       # ls の結果を files.txt に保存（中身は上書き）
echo "hello" > a.txt # 上書き
```

- ファイルがなければ作られる
- ファイルがあれば **中身は消えて置き換わる**

### 2-2. `>>` — ファイルに追記

```bash
echo "new line" >> log.txt
date >> log.txt
```

- ファイルの末尾に足される
- ファイルがなければ作られる

### 2-3. `>` と `>>` の使い分け

| やりたいこと                      | 使う記号 |
|-----------------------------------|----------|
| 初回作成 / 毎回まっさらにしたい  | `>`      |
| 継続的にログを貯める             | `>>`     |
| 既存ファイルを絶対に壊したくない | **`>>` か `>|`（noclobber 回避）** |

### 2-4. 誤って上書きしない `noclobber`

```bash
set -o noclobber
echo "x" > existing.txt    # → エラー（上書き禁止）
echo "x" >| existing.txt   # 明示的に上書き
```

壊して困るファイルを扱うときの保険。

## 3. エラー出力のリダイレクト

### 3-1. `2>` — stderr だけ別ファイルへ

```bash
command 2> errors.log
```

- 通常の出力は画面、エラーだけ `errors.log` に。

### 3-2. `2>&1` — stderr を stdout に合流させる

```bash
command > all.log 2>&1
```

- まず stdout を `all.log` に向ける
- 続いて「stderr は stdout と同じ先に」と指示

**書く順序が重要**。`2>&1 > all.log` は意味が違う（エラーは画面、通常だけファイル）。

### 3-3. `&>` — 両方まとめて（bash 拡張）

```bash
command &> all.log         # stdout + stderr を all.log に
command &>> all.log        # 追記
```

- bash ならこちらの方が簡潔
- POSIX 準拠スクリプトが必要なら `> file 2>&1` を使う

### 3-4. エラーだけ捨てたい

```bash
command 2> /dev/null       # エラーメッセージを消す
command > /dev/null 2>&1   # 全出力を消す（バックグラウンド実行などで）
```

`/dev/null` は **書き込んだら消える** 特殊ファイル（ブラックホール）。

---

## 4. 入力リダイレクト `<`

### 4-1. `<` — ファイルを標準入力に流し込む

```bash
wc -l < access.log
```

- `wc -l access.log` でも同じ結果だが、意味が違う：
  - `wc -l < file` → **wc は「標準入力から読んでいる」**（ファイル名を知らない）
  - `wc -l file` → **wc にファイル名を教えた**

### 4-2. `<<` — ヒアドキュメント

```bash
cat <<EOF
Hello
$USER
EOF
```

- `EOF`（任意の印）まで **複数行を標準入力に流す**
- 変数は展開される
- 展開したくないなら `<<'EOF'` のようにクォート

### 4-3. `<<<` — ヒアストリング

```bash
grep 'foo' <<< "$variable"
```

- 文字列 1 つを標準入力にする簡略形

---

## 5. パイプ `|` — コマンドを繋ぐ

### 5-1. 基本

```bash
ls -la | less
```

- 左の stdout → 右の stdin に直結
- **ファイルを経由せず、メモリ上でストリーム**

### 5-2. よくある 3 段パイプ

```bash
grep ERROR app.log | awk '{print $1}' | sort | uniq -c | sort -rn
```

- ログから ERROR 行 → 1 列目（日付）を抽出 → 集計 → 件数順に並べる
- **「1 コマンド 1 責務 × パイプで結合」** が UNIX 流

### 5-3. パイプと stderr

**注意**：`|` は **stdout だけ** を次に渡す。stderr は素通りして画面に出たままになる。

```bash
command 2>&1 | grep error      # stderr も含めて grep したい場合
command |& grep error          # bash 拡張（= 2>&1 |）
```

---

## 6. `tee` — 分岐

```bash
command | tee output.log | grep ERROR
```

- `tee` はパイプを **T 字に分岐**：ファイルに書きつつ、次のコマンドにも流す
- 長時間コマンドのログを **見ながら記録** するのに便利

```bash
command | tee -a log.txt       # -a で追記
sudo ...   # パスワード権限でファイルに書く定番：
echo "content" | sudo tee /etc/config > /dev/null
```

---

## 7. 実用的な定番パターン

### 7-1. コマンドの出力を確認しつつ保存

```bash
make 2>&1 | tee build.log
```

### 7-2. 長時間実行してエラーだけ記録

```bash
long_task > output.log 2> errors.log
```

### 7-3. バックグラウンド実行・ログ記録

```bash
./server > server.log 2>&1 &
```

`&` は最後につけてバックグラウンド実行の合図。

### 7-4. 失敗を無視したい（スクリプト中）

```bash
rm tmp.txt 2>/dev/null || true
```

- `|| true` で終了ステータスを無理やり 0 に
- `set -e` 下でも止まらない

### 7-5. 「何も出力しない」テスト

```bash
diff a.txt b.txt > /dev/null && echo "same"
```

- 差分の出力はいらない、結果（終了ステータス）だけ見たい

## 8. 記号まとめ一覧

| 記号         | 意味                                      |
|--------------|-------------------------------------------|
| `cmd > f`    | stdout を f に（上書き）                  |
| `cmd >> f`   | stdout を f に追記                        |
| `cmd 2> f`   | stderr を f に                            |
| `cmd 2>> f`  | stderr を f に追記                        |
| `cmd 2>&1`   | stderr を stdout に合流                   |
| `cmd > f 2>&1` | stdout も stderr も f に                |
| `cmd &> f`   | 同上（bash 拡張、簡略版）                 |
| `cmd < f`    | f を stdin に                             |
| `cmd <<EOF`  | ヒアドキュメント                          |
| `cmd <<<"s"` | ヒアストリング                            |
| `a | b`      | a の stdout → b の stdin                  |
| `a |& b`     | a の stdout+stderr → b の stdin（bash）   |
| `a | tee f`  | a の stdout をファイル f にも書く         |
| `> /dev/null`| 捨てる                                    |

---

## 9. つまずきやすいポイント

| 症状                                         | 原因・対処                                       |
|----------------------------------------------|--------------------------------------------------|
| エラーがログファイルに入らない              | `2>&1` が抜けている                               |
| `2>&1 > file` と書いたら期待通りでない       | 順序が逆。`> file 2>&1` が正しい                 |
| 大事なファイルを `>` で吹き飛ばした         | 起動前に `set -o noclobber`、日常は `>>` を優先   |
| パイプの左側が終了しない                     | 左が長時間実行中。`| head` で打ち切り試す         |
| `sudo cmd > /root/file` が権限エラー         | リダイレクトはシェルが先に解釈する。`sudo tee` 経由へ |
| ヒアドキュメントで変数展開されすぎる         | `<<'EOF'` のようにクォート                        |

---

## 10. まとめ

- **3 つのストリーム**（stdin, stdout, stderr）を別々に扱えることが出発点
- **`>` は上書き、`>>` は追記**、事故防止には `>>` を優先
- **`2>&1`** でエラーも同じ行き先に。順序に注意
- **パイプ `|`** で小さなコマンドを繋ぐのが UNIX 流
- **`tee`** で「見ながら記録」、**`/dev/null`** で「捨てる」

この記号を使いこなせるようになると、ログ解析やデバッグの効率が一段上がる。
