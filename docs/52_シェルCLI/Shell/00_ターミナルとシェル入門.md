# ターミナルとシェル入門 — 一覧と違いから理解する

## この文書のねらい

「ターミナル」「シェル」「bash」「PowerShell」「Cursor のターミナル」—— 用語が多くて混乱しやすい。

ここでは **ゼロから** 次を整理する。

1. **ターミナル** と **シェル** の違い（最重要）
2. よく出会う **ターミナル一覧**（窓アプリ）
3. よく出会う **シェル一覧**（中身のプログラム）
4. **組み合わせ例**（Cursor / Obsidian / Terminal.app など）
5. このあと **何を読めばよいか**

> 用語の整理だけなら §1〜§3。具体例は §4。学習ルートは §6。

---

## 1. 結論 — 2 つの別物

### 1-1. 一言で

| 用語 | 何か | 例え |
|------|------|------|
| **ターミナル** | 文字を表示する **窓（アプリ）** | テレビの画面 |
| **シェル** | コマンドを解釈する **中身（プログラム）** | テレビで流れる番組 |

```
[ ターミナル（窓） ]  ← フォント・色・タブはここ
        ↕ 文字のやりとり
[ シェル（中身）   ]  ← コマンド・PATH・設定はここ
        ↕
[ OS（Windows / macOS / Linux） ]
```

**同じターミナルアプリの中で、シェルを切り替えられる。**  
逆に、同じシェル（bash など）を、別のターミナル（Cursor / iTerm2 など）から起動することもできる。

### 1-2. よくある混同

ネットの記事では「PowerShell ターミナル」「bash ターミナル」と書かれることがあるが、厳密には：

| 記事の言い方（曖昧） | 正確な分解 |
|----------------------|------------|
| PowerShell ターミナル | **Windows Terminal（窓）** + **PowerShell（シェル）** |
| bash ターミナル | **Terminal.app（窓）** + **bash（シェル）** |
| Git Bash | **MinTTY（窓）** + **bash（シェル）** の **セット品** |
| Cursor のターミナル | **Cursor 統合ターミナル（窓）** + **設定したシェル** |

**cmd / PowerShell / bash / zsh はすべて「シェル」** であり、ターミナルではない。

## 2. ターミナル一覧 — 「窓」アプリ

ターミナル = **Terminal Emulator（端末エミュレータ）**。黒い画面に文字を出す **アプリ本体**。

### 2-1. macOS でよく使う

| 名前 | ひとこと | 備考 |
|------|----------|------|
| **Terminal.app** | macOS 標準 | 最初から入っている |
| **iTerm2** | 高機能・macOS 定番 | タブ・分割・検索が充実 |
| **Alacritty** | 最速・最小 | タブなし。tmux 併用向き |
| **WezTerm** | 多機能・クロスプラットフォーム | Lua で設定 |
| **Warp** | AI 補助付きの新世代 UI | アカウント連携あり |
| **Cursor 統合ターミナル** | エディタ内のターミナル | VS Code 系と同じ考え方 |
| **VS Code 統合ターミナル** | エディタ内のターミナル | 設定でシェルを選べる |
| **Obsidian 統合ターミナル** | ノートアプリ内のターミナル | プラグイン依存 |

### 2-2. Windows でよく使う

| 名前 | ひとこと | 備考 |
|------|----------|------|
| **Windows Terminal** | Windows の現行標準 | タブ・WSL・PowerShell 統合 |
| **コマンドプロンプトの窓** | 旧来の cmd 用ウィンドウ | conhost ベース |
| **VS Code / Cursor 統合ターミナル** | エディタ内 | 中身は PowerShell / bash 等 |
| **Git Bash の窓（MinTTY）** | Git for Windows 付属 | bash が最初から入ったセット |
| **PowerShell.exe 単体** | シェル単体起動 | 窓もシェルも PowerShell 系 |

### 2-3. Linux でよく使う

| 名前 | ひとこと |
|------|----------|
| **GNOME Terminal** | Ubuntu 等のデスクトップ標準 |
| **Konsole** | KDE 向け |
| **Kitty / Alacritty / WezTerm** | 軽量・高機能系 |
| **TTY コンソール** | Ctrl+Alt+F1 などの全画面 |

### 2-4. ターミナルが担当すること

- ウィンドウ・タブ・画面分割
- **フォント・色・背景・透過**
- コピー / ペーストのショートカット
- スクロール（過去の出力を遡る）
- IME（日本語入力）の表示

→ 詳しくは `04_ターミナル設定の要点.md` / `03_その他のターミナル.md`

## 3. シェル一覧 — 「中身」のプログラム

シェル = あなたが打った **`ls` や `git` を解釈して OS に伝える** プログラム。

### 3-1. 主要シェル比較

| シェル | 主な環境 | 特徴 | 設定ファイル例 |
|--------|----------|------|----------------|
| **bash** | Linux, WSL, Git Bash, macOS（任意） | 事実上の標準。スクリプト資産が多い | `~/.bashrc`, `~/.bash_profile`, `~/.profile` |
| **zsh** | macOS 10.15〜 **既定** | bash に近い + 補完が強い | `~/.zshrc`, `~/.profile` |
| **fish** | 任意（全 OS） | 初心者向け UX。bash 非互換 | `~/.config/fish/config.fish` |
| **sh** | Unix 全般 | 最小限。スクリプト互換用 | — |
| **PowerShell** | Windows 標準, クロスプラットフォーム | オブジェクト指向。Windows 管理向き | `$PROFILE` |
| **cmd** | Windows 旧標準 | 古い・機能限定 | レジストリ / バッチ |
| **pwsh** | PowerShell 7+ | クロスプラットフォーム版 PowerShell | `$PROFILE` |

### 3-2. シェルが担当すること

- コマンドの解釈（`ls`, `cd`, パイプ `|` など）
- **PATH**（コマンドを探す場所）
- エイリアス（`ll` → `ls -la` など）
- **プロンプト**（`user@host:~$` の表示）
- 履歴（↑ キーで過去のコマンド）
- 補完（Tab キー）

→ bash 詳細: `../bash/bash基礎.md`  
→ zsh / fish: `../bash/zsh_fishとの比較.md`  
→ PowerShell: `../PowerShell/PowerShell基礎.md`  
→ PATH: `../bash/PATHとprofile入門.md`

### 3-3. シェルではないが混同されやすいもの

| 名前 | 正体 |
|------|------|
| **python**（対話モード） | Python 言語の REPL（プログラム） |
| **node** | JavaScript の REPL |
| **mysql** クライアント | データベース用プログラム |
| **Claude Code（`claude`）** | CLI ツール（シェルではない） |

プロンプトが `$` や `>` でも、**中身がシェルとは限らない**。

## 4. 組み合わせ例 — 「今どれが動いているか」

### 4-1. macOS の典型パターン

| あなたが開いたもの | ターミナル（窓） | 中のシェル（例） |
|--------------------|------------------|------------------|
| Terminal.app | Terminal.app | **zsh**（macOS 既定） |
| Cursor → ターミナル | Cursor 統合 | **zsh**（多い） |
| Obsidian → ターミナル | Obsidian 統合 | **bash**（環境による） |
| iTerm2 | iTerm2 | zsh / bash / fish（選べる） |

**同じ Mac でも、窓が違うと中のシェルも違う** → 読む設定ファイル（`.zshrc` / `.profile`）が変わる → PATH の設定が片方だけ効く、というトラブルが起きる。

### 4-2. Windows の典型パターン

| あなたが開いたもの | ターミナル（窓） | 中のシェル（例） |
|--------------------|------------------|------------------|
| Windows Terminal | Windows Terminal | **PowerShell 7** または **cmd** |
| Git Bash | MinTTY | **bash** |
| WSL | Windows Terminal 等 | **bash**（Ubuntu 等） |
| Cursor → ターミナル | Cursor 統合 | PowerShell / bash（設定次第） |

### 4-3. 図解：Cursor を例に

```
[ Cursor エディタ ]
    └─ [ 統合ターミナル（窓） ]
            └─ [ zsh または bash（シェル） ]
                    └─ [ claude, git, node など（コマンド） ]
```

- **Cursor を入れたから `claude` が使える** わけではない
- **シェルの PATH 設定** に `~/.local/bin` などが入っているかが効く

### 4-4. 今の環境を確認するコマンド

ターミナル（どれでも）を開いて打つ：

```bash
echo $SHELL          # ログインシェルのパス（例: /bin/zsh）
echo $0              # 今動いているシェル（-zsh ならログイン zsh）
ps -p $$             # プロセス名（zsh / bash 等）
which claude         # コマンドが PATH のどこから見つかるか
```

## 5. 設定は「窓」と「中身」で場所が違う

| 変えたいもの | いじる場所 | 例 |
|--------------|------------|-----|
| フォント・色・背景 | **ターミナル側** | Windows Terminal の settings.json |
| タブ・分割 | **ターミナル側** | iTerm2 の設定 |
| PATH（コマンドの検索場所） | **シェル側** | `~/.profile`, `~/.zshrc` |
| エイリアス・プロンプト | **シェル側** | `~/.bashrc`, `~/.zshrc` |
| 既定シェルの切替 | **ターミナル or OS 設定** | Cursor: `terminal.integrated.defaultProfile` |

**色を変えたいのに `.bashrc` を編集しても意味がない。**  
**`ll` エイリアスを作りたいのに Windows Terminal の色設定を触っても意味がない。**

---

## 7. 3 行まとめ

1. **ターミナル = 窓**、**シェル = 中身**。別物。
2. **cmd / PowerShell / bash / zsh はシェル**。Terminal.app / Cursor / Windows Terminal は **ターミナル**。
3. **窓が違うと中のシェルも違うことがある** → 設定（PATH など）が片方だけ効くことがある。

## 補足：GUI と CUI

ターミナルとシェルが提供する「文字で操作する画面（CUI）」を、マウスで操作する GUI と比べ、サーバー管理で CUI が中心になる理由を整理します。

### 概要

GUI（Graphical User Interface：グラフィカルユーザーインターフェース）と CUI（Character User Interface：キャラクタユーザーインターフェース）は、ユーザーがコンピュータと対話するための異なるインターフェース方式です。それぞれに特徴があり、用途に応じて使い分けられています。

### GUI（Graphical User Interface）

#### GUI の特徴

- **視覚的操作**: アイコン、ボタン、メニューなどの視覚的要素
- **マウス操作**: クリック、ドラッグ、右クリックなどの直感的操作
- **WYSIWYG**: 画面上の表示がそのまま結果となる
- **マルチウィンドウ**: 複数のアプリケーションを同時に表示

#### GUI の構成要素

- **ウィンドウ**: アプリケーションの表示領域
- **メニューバー**: 機能選択のためのメニュー
- **ツールバー**: よく使用する機能のボタン
- **アイコン**: ファイルやアプリケーションの視覚的表現
- **ダイアログボックス**: 設定や確認のための画面

#### GUI のメリット

- **直感性**: 初心者でも操作しやすい
- **視覚性**: 情報が分かりやすく表示される
- **効率性**: 複数の作業を同時に実行可能
- **学習コスト**: 操作の習得が容易

#### GUI のデメリット

- **リソース消費**: メモリや CPU を多く使用
- **操作速度**: 複雑な操作に時間がかかる
- **自動化困難**: スクリプト化が難しい
- **リモート操作**: ネットワーク経由での操作が重い

#### GUI の代表例

- **Windows**: デスクトップ、スタートメニュー、タスクバー
- **macOS**: Dock、メニューバー、Finder
- **Linux**: GNOME、KDE、XFCE
- **Web ブラウザ**: Chrome、Firefox、Safari

### CUI（Character User Interface）

#### CUI の特徴

- **テキストベース**: 文字による操作と表示
- **キーボード操作**: コマンド入力による操作
- **コマンドライン**: 命令文による制御
- **シンプル**: 最小限のリソースで動作

#### CUI の構成要素

- **プロンプト**: コマンド入力待ちの表示
- **コマンド**: 実行する命令文
- **オプション**: コマンドの動作を指定する引数
- **出力**: コマンド実行結果の表示
- **エラーメッセージ**: エラー発生時の通知

#### CUI のメリット

- **高速性**: 素早い操作が可能
- **自動化**: スクリプトによる自動実行
- **リソース効率**: 少ないメモリ・CPU で動作
- **リモート操作**: ネットワーク経由での軽快な操作
- **精密制御**: 細かい設定や制御が可能

#### CUI のデメリット

- **学習コスト**: コマンドの習得が必要
- **直感性**: 初心者には操作が難しい
- **視覚性**: 情報の理解に時間がかかる
- **エラー**: 間違ったコマンドでシステムに影響

#### CUI の代表例

- **Windows**: Command Prompt、PowerShell
- **macOS**: Terminal、zsh
- **Linux**: Bash、Zsh、Fish
- **サーバー管理**: SSH、リモート接続

### GUI と CUI の比較

#### 操作の違い

| 項目           | GUI            | CUI        |
| -------------- | -------------- | ---------- |
| 操作方式       | マウス・タッチ | キーボード |
| 学習難易度     | 簡単           | 難しい     |
| 操作速度       | 中程度         | 高速       |
| 自動化         | 困難           | 容易       |
| リソース使用量 | 多い           | 少ない     |

#### 用途の違い

| 用途           | GUI        | CUI        |
| -------------- | ---------- | ---------- |
| 一般ユーザー   | 適している | 不適切     |
| システム管理者 | 補助的     | 主要       |
| 開発者         | 併用       | 主要       |
| サーバー管理   | 不適切     | 適している |
| 自動化         | 困難       | 適している |

### サーバー環境での GUI と CUI

#### サーバーでの CUI の重要性

- **リモート管理**: SSH 経由での遠隔操作
- **自動化**: スクリプトによる自動処理
- **効率性**: 高速な操作と設定
- **安定性**: 軽量で安定した動作
- **セキュリティ**: 最小限の攻撃面

#### サーバーでの GUI の制限

- **リソース消費**: サーバーリソースの無駄遣い
- **セキュリティリスク**: 攻撃対象の拡大
- **ネットワーク負荷**: リモート接続時の重い通信
- **保守性**: 設定の複雑化

#### サーバー管理での CUI 活用

- **設定ファイル編集**: vi、nano、emacs
- **ログ確認**: tail、grep、less
- **プロセス管理**: ps、top、kill
- **ファイル操作**: ls、cp、mv、rm
- **ネットワーク設定**: ifconfig、netstat、ss

### 現代的なインターフェース

#### ハイブリッドアプローチ

- **GUI + CUI**: 両方の利点を活用
- **ターミナル統合**: GUI 内での CUI 操作
- **コマンドパレット**: GUI 内でのコマンド実行
- **自動化ツール**: GUI 操作のスクリプト化

#### クラウド時代のインターフェース

- **Web ベース GUI**: ブラウザ経由の管理画面
- **API**: プログラムによる制御
- **CLI**: クラウドサービスのコマンドラインツール
- **ダッシュボード**: 統合管理画面

#### 開発環境での活用

- **IDE**: 統合開発環境での GUI + CUI
- **ターミナル統合**: エディタ内でのコマンド実行
- **デバッグ**: GUI での視覚的デバッグ
- **バージョン管理**: GUI + CUI の併用

### 学習の進め方

#### CUI の習得方法

1. **基本コマンド**: ls、cd、pwd、mkdir、rm
2. **ファイル操作**: cp、mv、cat、grep、find
3. **プロセス管理**: ps、top、kill、jobs
4. **ネットワーク**: ping、ssh、scp、wget
5. **スクリプト**: Bash、Python、PowerShell

#### GUI の習得方法

1. **基本操作**: ウィンドウ操作、メニュー使用
2. **ファイル管理**: エクスプローラー、Finder
3. **アプリケーション**: 各種ソフトウェアの操作
4. **設定**: システム設定、アプリケーション設定
5. **ショートカット**: キーボードショートカット

#### 実践的な学習

- **仮想環境**: VirtualBox、VMware での練習
- **クラウド環境**: AWS、Azure での実践
- **プロジェクト**: 実際のシステム構築
- **コミュニティ**: フォーラム、勉強会への参加

### まとめ

GUI と CUI は、それぞれ異なる特徴と用途を持つユーザーインターフェースです。GUI は直感的で使いやすく、一般ユーザーに適しています。一方、CUI は高速で自動化が容易で、システム管理者や開発者に適しています。現代の IT 環境では、両方のインターフェースを適切に使い分けることが重要です。特にサーバー管理では、CUI の習得が不可欠であり、効率的なシステム運用の基盤となります。
