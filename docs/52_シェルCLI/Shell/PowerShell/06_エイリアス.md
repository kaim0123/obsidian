# エイリアス — bash 風コマンドとの対応（ls / cat / rm）

## この文書のねらい

PowerShell では `ls` や `cat` が **普通に動く** ように見える。
これは PowerShell が正式なコマンドレットに **別名（エイリアス）** を付けて、bash からの乗り換え組にも優しくしているから。

ただし：
- **見た目は同じでも中身は別物**。挙動が bash と完全一致するわけではない
- エイリアスは便利だが、**スクリプトには正式名を書くのが流儀**

この文書でその「見かけと実体」のズレを整理する。

---

## 1. エイリアスとは

> **PowerShell のコマンドやコマンドレットに付けた別名。**

例：`ls` は `Get-ChildItem` のエイリアス。`ls` と打っても、内部では `Get-ChildItem` が呼ばれている。

```powershell
Get-Alias ls
# CommandType  Name   Definition
# -----------  ----   ----------
# Alias        ls ->  Get-ChildItem
```

## 2. bash / コマンドプロンプト → PowerShell 対応表

### 2-1. ファイルとディレクトリ

| bash / cmd        | PowerShell エイリアス | 実体（コマンドレット） |
|-------------------|------------------------|------------------------|
| `ls`, `dir`       | `ls`, `dir`            | `Get-ChildItem`        |
| `cd`, `chdir`     | `cd`, `chdir`          | `Set-Location`         |
| `pwd`             | `pwd`                  | `Get-Location`         |
| `cp`, `copy`      | `cp`, `copy`           | `Copy-Item`            |
| `mv`, `move`      | `mv`, `move`           | `Move-Item`            |
| `rm`, `del`       | `rm`, `del`, `erase`   | `Remove-Item`          |
| `mkdir`, `md`     | `mkdir`, `md`          | `New-Item -Type Directory` （厳密には関数） |
| `cat`             | `cat`, `type`          | `Get-Content`          |
| `echo`            | `echo`                 | `Write-Output`         |
| `touch`           | （なし）               | `New-Item`             |

### 2-2. プロセス / 環境

| bash / cmd    | PowerShell エイリアス | 実体                   |
|---------------|------------------------|------------------------|
| `ps`          | `ps`                   | `Get-Process`          |

| `clear`, `cls`| `clear`, `cls`         | `Clear-Host`           |
| `history`     | `history`              | `Get-History`          |
| `which`       | （なし）               | `Get-Command`          |
| `man`         | `man`                  | `Get-Help`             |
| `env`         | （なし）               | `Get-ChildItem Env:`   |

### 2-3. 絞り込み・変換

| bash       | PowerShell          | 実体                                    |
|------------|---------------------|-----------------------------------------|
| `grep`     | **なし**（要注意）  | `Select-String`                         |

| `head`     | `select -First N`   | `Select-Object -First N`                |

| `sort`     | `sort`              | `Sort-Object`                           |
| `uniq`     | `select -Unique`    | `Select-Object -Unique`                 |
| `xargs`    | `foreach`, `%`      | `ForEach-Object`                        |

## 3. 「見た目は同じ、中身は別」の罠

### 3-1. `ls` は出力フォーマットが違う

```powershell
ls
# PowerShell は 4 列（Mode / LastWriteTime / Length / Name）を綺麗に整形
```

```bash
ls     # bash: ファイル名だけ並ぶ（-l しないと詳細は出ない）
```

**`ls -la` 相当がほしいとき** は `Get-ChildItem -Force`（隠しファイル含む）。

### 3-2. `cat file1 file2` は動くが…

PowerShell の `cat`（= `Get-Content`）は **オブジェクト（文字列の配列）** を返す。
`cat file1 file2 > out.txt` は bash と同じく結合できるが、**エンコーディングが UTF-16 LE (BOM 付き)** になることがある（5.1 の既定）。

UTF-8 で書きたいなら：

```powershell
Get-Content file1, file2 | Set-Content out.txt -Encoding UTF8
```

### 3-3. `rm -rf` はそのままでは通らない

```powershell
rm -rf dir   # ← -rf なんてパラメータは無い、とエラーになる
```

PowerShell 流儀では：

```powershell
Remove-Item -Recurse -Force dir
# または
rm -Recurse -Force dir    # エイリアス + 正式パラメータ
```

### 3-4. `grep` は標準で無い

```powershell
# ❌ grep は存在しない
# ✅ Select-String を使う
Get-Content app.log | Select-String 'ERROR'
Select-String -Path *.log -Pattern 'ERROR'
```

bash から来た人が最初にハマる定番。

### 3-5. `curl` / `wget` はエイリアス（PowerShell 5.1）だが中身は別物

5.1 では `curl` は **`Invoke-WebRequest` のエイリアス**。
「なんで `-L` や `-H` が効かないの？」となる。
本物の `curl.exe` を使いたいなら：

```powershell
curl.exe -L -H "Accept: application/json" https://example.com
```

**`.exe` を付ける** とエイリアスを回避できる。PowerShell 7 では既定でエイリアスが外されている。

## 4. エイリアスの操作

### 4-1. 一覧を見る

```powershell
Get-Alias                # 全部
Get-Alias ls             # 特定の 1 個
Get-Alias -Definition Get-ChildItem   # 指定コマンドの別名を逆引き
```

### 4-2. 新しいエイリアスを作る

```powershell
Set-Alias ll Get-ChildItem
Set-Alias g  git
```

**永続化したいなら `$PROFILE` に書く**（→ `PowerShellプロファイル.md`）。

### 4-3. エイリアスを消す

```powershell
Remove-Item Alias:ll
```

### 4-4. 複雑なものは関数にする

エイリアスは **引数の追加ができない**。`ls -la` のようにオプション付きで別名をつけたいときは **関数** を使う：

```powershell
function ll { Get-ChildItem -Force @args }
```

## 5. 使っていいエイリアス vs ダメなエイリアス

### 対話（コマンドライン入力） → 何でも OK

- 打鍵を減らせるので積極的に使ってよい
- `ls`, `cat`, `rm`, `?`（Where-Object）, `%`（ForEach-Object）など

### スクリプト（.ps1 ファイル）→ 正式名で書く

| 理由                        | 具体例                                       |
|-----------------------------|----------------------------------------------|
| 可読性                     | `?` より `Where-Object` のほうが明確         |
| 可搬性                     | エイリアスは上書きされていることがある       |
| 静的解析ツールが警告する    | `PSAvoidUsingCmdletAliases` ルール           |
| コードレビューしやすい      | 初心者が読める                               |

```powershell
# ❌ スクリプトでこれは避ける
gci | ? {$_.Length -gt 1MB} | % {$_.Name}

# ✅ こう書く
Get-ChildItem |
  Where-Object { $_.Length -gt 1MB } |
  ForEach-Object { $_.Name }
```

## 6. bash ライクなエイリアス集（プロファイル用）

`$PROFILE` に足しておくと bash 気分で使える定番：

```powershell
# 強化版 ls
function ll  { Get-ChildItem -Force @args }
function la  { Get-ChildItem -Force -Hidden @args }

# grep 風
function grep { param($Pattern); $input | Select-String $Pattern }

# which（コマンドのパス）
function which { param($Name); (Get-Command $Name).Source }

# touch
function touch { param($Path); New-Item -ItemType File -Path $Path -Force | Out-Null }

# mkcd
function mkcd { param($Path); New-Item -ItemType Directory -Path $Path | Out-Null; Set-Location $Path }
```

---

## 7. まとめ

- `ls` / `cat` / `rm` は **エイリアス**。実体は `Get-ChildItem` / `Get-Content` / `Remove-Item`
- **オプションは bash と違う**（`-rf` は効かない、`-Recurse -Force` を使う）
- `grep` は無い → `Select-String` で代用
- 5.1 の `curl` は偽物 → 本物を呼ぶなら `curl.exe`
- 対話ではエイリアス積極使用、**スクリプトは正式名**

「bash っぽく打てるから bash と同じ」**ではない** ことを意識すると、ハマりが激減する。
