# PowerShell基礎 — オブジェクトパイプラインの考え方

## この文書のねらい

PowerShell は Windows で標準的に使えるシェルだが、**見た目はコマンドラインでも中身は「.NET の対話実行環境」** である。
普通のシェル（bash / コマンドプロンプト）との最大の違いは、**コマンドがテキストではなくオブジェクトを受け渡しする**という点。

この文書では、まず「PowerShell とは何か」を押さえてから、PowerShell を PowerShell たらしめている **オブジェクトパイプライン** の感覚をつかむことをゴールにする。

---

## 1. PowerShell はどんなシェルか

### 1-1. 一言でいうと

> **.NET のオブジェクトを扱える、Microsoft 製の高機能シェル。**

- Windows 10 / 11 に標準搭載（「Windows PowerShell 5.1」）
- macOS / Linux でも動く（「PowerShell 7.x」、クロスプラットフォーム）
- 対話的に使う「シェル」としても、ファイルに書いて実行する「スクリプト言語」としても使える

### 1-2. 他のシェルとの位置づけ

| シェル           | 扱う単位        | 主な用途                       |
|------------------|-----------------|--------------------------------|
| コマンドプロンプト | テキスト        | Windows の基本操作             |
| bash / zsh       | テキスト        | Unix 系の標準的な操作          |
| **PowerShell**   | **オブジェクト** | **Windows 管理・自動化・開発** |

**ポイント**：他のシェルは「画面に出る文字列」を扱うが、PowerShell は「プロパティを持つオブジェクト」を扱う。

---

## 2. コマンドレット（cmdlet）という単位

PowerShell のコマンドは「コマンドレット（cmdlet）」と呼ばれ、次の命名規則で書かれる。

```
動詞-名詞
```

| 例                 | 意味                           |
|--------------------|--------------------------------|
| `Get-Process`      | プロセスを取得する             |
| `Get-ChildItem`    | 子要素（ファイル一覧）を取得   |
| `Set-Location`     | 場所（カレントディレクトリ）を設定 |
| `New-Item`         | 新しい項目（ファイル等）を作る |
| `Remove-Item`      | 項目を削除する                 |
| `Stop-Process`     | プロセスを止める               |

**「動詞-名詞」を読めば何をするコマンドか想像がつく** のが PowerShell の強み。
初めて見るコマンドでも `Get-` で始まれば「何かを取得する、読み取り専用で安全」と判断できる。

---

## 3. オブジェクトパイプライン — PowerShell の核心

### 3-1. まず bash の場合

bash では、パイプ `|` は **テキスト** を次のコマンドに渡す。

```bash
ps aux | grep chrome | awk '{print $2}'
```

各段階で **文字列を切り貼り** していく。列がズレたり、空白を含むと壊れたりする。

### 3-2. PowerShell の場合

PowerShell のパイプは **オブジェクト** を次のコマンドに渡す。

```powershell
Get-Process | Where-Object { $_.CPU -gt 100 } | Sort-Object CPU -Descending
```

- `Get-Process` は「プロセスオブジェクトの配列」を返す
- `Where-Object` はその配列の各要素（`$_`）から `.CPU` プロパティを見て絞り込む
- `Sort-Object` は `CPU` プロパティで並べる

**文字列ではなく「プロセス」そのものを渡している** ので、列のズレや空白問題が起きない。

### 3-3. なぜそれが嬉しいのか

- 「列」を数えなくていい（`awk '{print $2}'` のような脆いコードにならない）
- ロケールや表示形式に依存しない（日付の表示が変わっても壊れない）
- IDE のように **補完が効く**（`$_.` と打てば使えるプロパティ一覧が出る）

---

## 4. 自動変数 `$_` と `$PSItem`

パイプラインで流れてくる「いまの 1 件」を指す変数が **`$_`** （または同義の `$PSItem`）。

```powershell
Get-ChildItem | Where-Object { $_.Length -gt 1MB }
```

- `Get-ChildItem` が返したファイル情報の 1 件ずつが `$_` に入る
- `$_.Length` はファイルサイズのプロパティ

これは bash の `xargs` とも `for` ループとも違う、**PowerShell に慣れるうえで最初の山** になる。

---

## 5. オブジェクトの中身を覗く 3 つのコマンド

PowerShell の感覚をつかむために、この 3 つを呼吸のように使えるようにしておく。

### 5-1. `Get-Member` — 何が入っているかを調べる

```powershell
Get-Process | Get-Member
```

- オブジェクトの **プロパティとメソッドの一覧** が出る
- 「このオブジェクトに対して何ができるか」を知るための辞書

### 5-2. `Select-Object` — 必要な列だけ取り出す

```powershell
Get-Process | Select-Object Name, CPU, Id
```

- テーブル表示する列を絞る
- `-First 10` / `-Last 5` で件数も絞れる

### 5-3. `Format-Table` / `Format-List` — 表示形式を変える

```powershell
Get-Process | Format-List *
```

- `Format-List` は縦長（全プロパティを見たいとき）
- `Format-Table` は横長（ざっと眺めたいとき）

> **注意**：`Format-*` を通したあとはもうオブジェクトではなく「表示用の塊」になる。**パイプラインの最後にだけ使う** のが鉄則。

---

## 6. ヘルプの引き方

わからないコマンドに出会ったらこの 3 つ。

```powershell
Get-Help Get-Process              # 使い方の説明
Get-Help Get-Process -Examples    # 実例だけ見たいとき
Get-Help Get-Process -Full        # 全部見たい（長い）
```

初回だけ `Update-Help`（管理者権限）でヘルプ本体をダウンロードする必要がある。

**Tip**：コマンド名を忘れたら `Get-Command *process*` のようにワイルドカードで探せる。

## 7. 起動モードと実行ポリシー

### 7-1. 起動の種類

- **対話モード**：`powershell` や `pwsh` と打って起動、コマンドを 1 行ずつ実行
- **スクリプトモード**：`.ps1` ファイルを書いて実行（`.\script.ps1`）
- **コマンドモード**：`powershell -Command "Get-Date"` のように 1 発だけ実行

### 7-2. 実行ポリシーの壁

初めてスクリプトを実行しようとすると、たいてい次のエラーが出る。

```
このシステムではスクリプトの実行が無効になっているため...
```

これは **セキュリティのための実行ポリシー** が原因。対処は：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

- `RemoteSigned`：自分で書いたスクリプトは実行可、ネットから落としたものは署名必須（実用的な既定）
- `CurrentUser` スコープで設定すれば、システム全体には影響しない

詳しくは `Windows/権限/実行ポリシー.md` を参照。

## 8. この後の学習パス

1. **まずは対話で慣れる**
   - `Get-ChildItem` `Get-Process` `Get-Service` など `Get-*` 系で遊ぶ
   - `| Get-Member` で中身を確認する癖をつける
2. **パイプラインを使ってみる**
   - `Where-Object` / `Select-Object` / `Sort-Object` を組み合わせる
   - → `パイプラインとフィルタ.md`
3. **bash との対応を覚える**
   - `ls` `cat` `rm` は PowerShell ではエイリアス、中身は別物
   - → `エイリアス.md`
4. **設定を自分用にする**
   - プロンプト、関数、エイリアスを永続化
   - → `PowerShellプロファイル.md`
5. **スクリプトを書く**
   - `.ps1` を書いて自動化
   - → `主要コマンドパレット.md` / `bash/シェルスクリプト入門.md` と対比

## 9. つまずきやすいポイント

| 症状                                           | 原因・対処                                         |
|------------------------------------------------|----------------------------------------------------|
| `ls` の結果が bash と違う                      | PowerShell の `ls` は `Get-ChildItem` のエイリアス |
| `.ps1` が実行できない                          | 実行ポリシー（§7-2）                               |
| 日本語が文字化けする                           | `$OutputEncoding` / コンソールの `chcp 65001`      |
| `cat file.txt \| grep foo` が動かない          | `grep` は PowerShell には無い。`Select-String` を使う |
| パイプの途中で `Format-Table` を挟むと以降が壊れる | `Format-*` はパイプ末端専用                        |

---

## 10. まとめ

- PowerShell は **「.NET オブジェクトを扱える」** 特殊なシェル
- コマンドは **「動詞-名詞」** の形で命名されていて読みやすい
- パイプは **オブジェクトを運ぶ**。`$_` で各要素にアクセスする
- `Get-Member` / `Select-Object` / `Get-Help` の 3 種の神器で迷子にならない
- bash の知識はそのまま使えない。**bash 風のエイリアスは便利だが中身は別物** と覚えておく

「テキスト切り貼り」の発想を捨て、「オブジェクトを流す」発想に切り替わった瞬間に、PowerShell が急に楽しくなる。
