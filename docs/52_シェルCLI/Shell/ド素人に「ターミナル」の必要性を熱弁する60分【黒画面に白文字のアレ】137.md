## 詳しい要約

**テーマ：なぜ「黒い画面（ターミナル／UNIX）」は無骨なのか — コマンドをパイプでつなぐための不親切さ**

プログラミング未経験の水野さんに、堀元さんがターミナルを実際に触らせながら UNIX の基本コマンドとパイプを教える回（約 1 時間）。ターミナルは命令を覚えないと使えず、返答も素っ気ない「無骨で不親切」な道具に見えるが、その無骨さこそが **出力を次の命令の入力につなげる（パイプ）** ための設計であり、組み合わせれば強力になる、というのが結論。用語はターミナルと UNIX を意図的に混ぜた、厳密性なしのざっくり説明だと断っている。

---

### ターミナルと UNIX のざっくり整理

- 映画のハッカーが黒い画面に白い英字を打っているのが **ターミナル**。Mac には標準で入っている
- 多くの人は OS が壊れたときにだけ黒い画面を見るので「危険なもの」と思い込むが、普段使っても壊れない（前後即因果の誤謬のような認知バイアス）
- 名前は「端末」から。昔のコンピューターは GUI がなく、端末＝ターミナルで操作するしかなかった
- ハッカーが操作しているのはたいてい **UNIX**（OS）で、それを操作する黒い画面をターミナルと呼んでいる、という整理で進める（実演には Cygwin を「UNIX」として使用）
- Web サイトを HTML・CSS で作ってアップロードする程度ならターミナルは不要。本腰を入れてプログラミングする人が使い始める
- 上の世代にとってはむしろこれが普通で、「マニュアルで命令一覧を読みながら使うもの」という感覚

### 覚えたコマンド

| コマンド | 意味 | 実演 |
|---|---|---|
| `ls` | 今いる **ディレクトリ（＝フォルダ）** の中身を表示（エクスプローラーや Finder と同じ情報） | 池袋・渋谷・新宿・名簿.txt が表示される |
| `cd <移動先>` | ディレクトリを移動（change directory）。`cd ..` で一つ上、`cd` だけで最初の場所へ | 渋谷 → 宮坂 → ラーメン屋と移動。画像ファイルには入れず、ターミナルでは画像も見られない |
| `cat <ファイル>` | テキストファイルの中身を表示 | 名簿.txt に名前と年齢が並ぶ |
| `wc <ファイル>` | 行数・単語数・バイト数を数える（word count） | 名簿は 50 件 |
| `grep <文字列> <ファイル>` | 文字列で検索 | 「田」を含む人だけ抽出 |

- 便利機能: **Tab キー** で名前の続きを補完、**上矢印キー** で直前の命令を呼び出して編集
- エンジニアもコマンドの細かい使い方はよく忘れて毎回ググる
- 「エンジニアが黒い画面を開くとまず `ls` を打つのは、話す前の『えーと』と同じ **フィラー**」という話（映画『ソーシャル・ネットワーク』のザッカーバーグの画面にも ls）

### パイプ（|）で命令を組み合わせる

- 「田を含む人が何人いるか」を数えたい → `grep 田 名簿.txt | wc` のように、**直前の命令の出力を直後の命令の入力に流す** のがパイプ（縦棒）
- 命令名を先頭に書き、目的語（引数）は右に書くのが原則。パイプで流れ込んだものは「書かれていない仮の目的語」になるイメージ
- 水野さんは「パイプは動詞を名詞化する（nominalization）もの」と理解し、堀元さんもそう考えてもよいと認める
- `ls -R` で配下のディレクトリを **再帰的** に一覧できる
- 練習問題: 配下にある「ラーメン.jpeg」の枚数を数える → `ls -R | grep ラーメン.jpeg | wc`（答え 2 枚）。WC が何を受け取りたいか、その中に grep、さらにその中に ls という階層構造を考え、逆順に書いてパイプでつなぐ（分割統治）
- こうした考え方が染みついた人を「**UNIX 人**」と呼ぶらしい

### 無骨さこそが便利さ（冒頭の禅問答の答え）

- エクスプローラーのように画像のサムネイルや更新日時などを親切に表示すると、次の処理に渡すときに **余計な情報（ノイズ）** になる（「ふわちゃん」のたとえは不発に終わる）
- Word で開くと書式や太字などの情報が混ざり、プログラムで素直に処理しにくい
- 出力が素朴であるほど次のプログラムがシンプルに処理できる。**出力を入力につなげ続ける前提では、無骨で不親切であることが最も便利で親切**
- 覚えたコマンドが増えるほど組み合わせで加速的にできることが増え、「ファイルの中身に特定の文字列を含むメモを探す」ような処理も 1 行で書ける

### テキストファイル／Markdown で書こう、という脱線

- 過去の企画書を中身で探したいとき、UNIX 上にテキストファイルで置いておけば grep とパイプで確実に見つけられる（Word ファイルを cat すると文字化けする）
- 見た目と内容は分離すべきなので、内容は **Markdown** などのテキストで書き、必要なら変換して PDF で出す、という主張。SF 作家の円城塔氏らもテキストで書いているが、編集者に Word を求められるなど周囲に使わせるのは難しい
- Notion の `#` で見出しになる書き方も Markdown 記法

### まとめ

- ターミナル（UNIX）は命令を覚える必要があり返答も素っ気ないが、それは **命令をパイプでつなぐため** の設計
- `ls`・`cd`・`cat`・`wc`・`grep` とパイプだけでも多くの処理が組み合わせでできる
- UNIX は「最初はとっつきにくいが、付き合うほど好きになる頑固職人」。次回は「UNIX 哲学」（書籍『UNIX という考え方』）を深掘りする予告
