# パス区切り文字 — `\` と `/` の混在問題

## はじめに

Windows では、パスの区切り文字に **バックスラッシュ `\`** を使います。一方、Unix 系（Linux / macOS）では **スラッシュ `/`**。

この違いが、Windows 開発で一番混乱を招きます。

- Windows ネイティブ: `C:\Users\kai\file.txt`
- Unix 風: `/home/kai/file.txt`

さらに **円記号とバックスラッシュの問題** もあり、日本の Windows 環境ではより厄介になります。

---

## なぜ違うのか（歴史的経緯）

### Unix: `/` を選択

1970年代に Unix が生まれたとき、ディレクトリ区切りに `/` が選ばれた。

### DOS / Windows: `/` は既に占有されていた

DOS（Windowsの祖先）では **コマンドラインオプション** に `/` を使う慣習があった（`DIR /W` など）。

```cmd
DIR /W   ← ワイド表示オプション（/ で始まる）
```

そのため、パス区切りには **残っていたもう一つの候補「`\`」** が採用された。

### この判断が今まで尾を引く

現代では OS の相互運用が増えた結果、**「Unix は `/`、Windows は `\`」の違いがバグや混乱の温床** に。

---

## Windows API は実は `/` も受け入れる

意外にも、Windows の API（カーネル）は **両方の区切り文字を受け付けます**。

```powershell
# PowerShell でどちらも動く
cd C:\Users\kai
cd C:/Users/kai
```

```cmd
REM cmd でも両方動く（ただし一部コマンドは不可）
cd C:\Users\kai
cd C:/Users/kai
```

API レベルで正規化されているためです。ただし、**一部のコマンドや古いツールは `\` しか受け付けない** ので、見た目の標準は `\`。

---

## 円記号（¥）とバックスラッシュ

日本の Windows では、エディタやターミナルで **バックスラッシュが円記号（¥）に見える** ことがあります。

```
C:¥Users¥kai  ← フォントで円記号に見えている
C:\Users\kai  ← 実際の文字
```

### なぜ同じ文字に見えるのか

文字コード `0x5C`（92番）は、**US-ASCII では `\`、日本版 JIS では `¥`** に割り当てられていた。Shift_JIS もこれを引き継いだ。

現代は Unicode（UTF-8）が標準で、`\` (U+005C) と `¥` (U+00A5) は別文字だが、日本語フォントでは `0x5C` を `¥` の字形で表示するものがある（MS ゴシック等）。

### 実務上の対処

- **中身は `\` なので、実害はほぼない**
- 気になるなら英数字フォント（Consolas、Cascadia Code、Source Code Pro 等）を使う
- JavaScript / Python 等の文字列リテラルでも、`\` として扱われるので OK

```javascript
const path = "C:\\Users\\kai";  // \\はエスケープ。実体は C:\Users\kai
```

---

## シェル別の扱い

### cmd.exe: `\` 標準

```cmd
cd C:\Users\kai
dir C:\Users
```

`/` はオプション開始記号なので、パスには `\` を使う。

### PowerShell: どちらも OK

```powershell
cd C:\Users\kai
cd C:/Users/kai
cd "C:/Program Files"   # スペース含みはクォート
```

スクリプト可搬性を意識するなら `/` で書くのも一案。

### Git Bash / WSL: `/` 固定

```bash
cd /c/Users/kai       # Git Bash
cd /mnt/c/Users/kai   # WSL
```

`\` は **エスケープ文字** なので、パス区切りには使えない。

---

## エスケープとクォート

### bash での `\`

Unix シェルでは `\` は **エスケープ文字**。特殊文字を打ち消す意味。

```bash
# スペースを含むパス、2通りの書き方
cd "/mnt/c/Program Files"       # ダブルクォートで囲む
cd /mnt/c/Program\ Files        # \でスペースをエスケープ
```

だから Windows パスを bash にそのまま書くと崩壊:

```bash
cd C:\Users\kai
# → 「\U」「\k」 などがエスケープ解釈されて別の意味になる
```

### プログラム内の文字列リテラル

```javascript
// JavaScript
const p1 = "C:\\Users\\kai";           // \ をエスケープ
const p2 = String.raw`C:\Users\kai`;   // raw文字列ならエスケープ不要
const p3 = "C:/Users/kai";             // スラッシュなら普通に書ける
```

```python
# Python
p1 = "C:\\Users\\kai"        # エスケープ
p2 = r"C:\Users\kai"         # raw 文字列
p3 = "C:/Users/kai"          # スラッシュでも動く
```

Python / JavaScript とも、Windows 関数には `/` を渡しても内部で変換してくれるので、**raw 文字列 or スラッシュ** で書くのが現代的。

## 混在時のよくあるバグ

### 1. 文字列連結でやらかす

```javascript
// ❌ 危険: OSによって壊れる
const p = "C:\\Users\\kai" + "/" + "file.txt";
// → "C:\\Users\\kai/file.txt" （混在）

// ✅ 良い: path.join を使う
const path = require('path');
path.join("C:\\Users\\kai", "file.txt");
```

### 2. 正規表現で `\` をマッチさせるとき

```javascript
// Windows のパスを正規表現で分解
const re = /\\/g;  // バックスラッシュにマッチ（エスケープ必須）
"C:\\Users\\kai".split(re);
// → ["C:", "Users", "kai"]
```

### 3. JSON / YAML 内でパスを書くとき

```json
{
  "path": "C:\\Users\\kai"        // \\ が必須
  // または
  "path": "C:/Users/kai"          // スラッシュなら問題なし
}
```

### 4. シェルスクリプトを Windows で編集

エディタによっては改行コードや区切り文字を「勝手に変換」する。Git の autocrlf 等と合わさって事故を起こす。

## プログラミング言語での推奨

### JavaScript / TypeScript (Node.js)

```javascript
const path = require('path');

path.join('users', 'kai', 'file.txt');      // OS依存の区切り
path.posix.join('users', 'kai', 'file.txt'); // 常にスラッシュ
```

### Python

```python
from pathlib import Path

# OSに応じた区切り
p = Path('users') / 'kai' / 'file.txt'

# スラッシュに統一
p.as_posix()
```

### Java / Kotlin

```java
// File.separator で実行環境の区切りを取得
String p = "users" + File.separator + "kai";

// Path を使うほうが現代的
Path.of("users", "kai", "file.txt");
```

### C# / .NET

```csharp
// Path.Combine が推奨
Path.Combine("users", "kai", "file.txt");

// スラッシュでも受ける
var p = "C:/Users/kai";
```

### Go

```go
import "path/filepath"

// OS依存
filepath.Join("users", "kai", "file.txt")

// スラッシュ固定（URL等）
import "path"
path.Join("users", "kai", "file.txt")
```

**共通原則**: **手で連結しない**。必ず標準ライブラリの `join` 系関数を使う。

---

## URL と ファイルパス の違い

**URL は常にスラッシュ `/`**。これはファイルパスとは別物。

```
https://example.com/users/kai/profile
file:///C:/Users/kai/file.txt        ← file URL はスラッシュ
```

Windows 側でも `file:///C:/Users/...` と書く（バックスラッシュは URL エンコードが必要）。

---

## まとめ

- Windows: `\`、Unix: `/`。歴史的経緯で分かれたが、Windows API は両方受け入れる
- **bash / WSL では `\` は使えない**（エスケープ文字として解釈される）
- 日本語フォントで `\` が `¥` に見えるのは表示だけ、実体は同じ文字
- プログラミングでは **標準ライブラリの `path.join`** 等を使い、手で連結しない
- ポータブルな書き方を心がければ、OS 依存のバグが大幅に減る
