# コンソールの文字化け — `chcp 65001` の話

## はじめに

Windows のコマンドプロンプトや PowerShell で、日本語を含む出力が **「□□□」「???」「譁?」** のように化けることがあります。これは **コンソールのコードページ** と **出力の文字コード** が合っていないのが原因です。

典型的なシナリオ:

- Docker コマンドの日本語出力が化ける
- Python スクリプトの `print("こんにちは")` が化ける
- ログファイルを `type` で見ると化ける

本稿ではその原因と対処を解説します。

---

## 背景: コンソールの「コードページ」

Windows のコンソール（cmd / 旧 PowerShell）は、**「どの文字コードで文字を解釈するか」** をコードページ番号で指定します。

| コードページ | 意味 |
|-------------|-----|
| **932** | 日本語 Shift_JIS（CP932） |
| **65001** | UTF-8 |
| **1252** | 西欧（Windows-1252） |
| **437** | US 英語（DOS オリジナル） |

**日本語版 Windows のデフォルトは 932（CP932）**。しかし現代のツール（Git、Docker、Python、Node.js等）は **UTF-8 で出力** する。ここでミスマッチが起きて化けます。

---

## 現在のコードページを確認

```cmd
chcp
```

出力例:

```
現在のコード ページ: 932
```

`932` なら CP932、`65001` なら UTF-8。

---

## 一時的に UTF-8 に切り替える

```cmd
chcp 65001
```

以後、そのコンソール窓では UTF-8 が使われます。ウィンドウを閉じるとリセット。

---

## 永続化する方法

### 方法 1: レジストリで cmd のデフォルトを UTF-8 に

管理者 PowerShell で:

```powershell
# 現在のユーザーの Command Processor に AutoRun を設定
reg add "HKCU\Software\Microsoft\Command Processor" /v AutoRun /d "chcp 65001 > nul" /f
```

cmd.exe 起動時に毎回 `chcp 65001` が実行されるようになる。

### 方法 2: システムロケール全体を UTF-8 に

**設定 → 時刻と言語 → 言語と地域 → 管理用の言語の設定 → システムロケールの変更**

→ 「**ベータ: ワールドワイド言語サポートで Unicode UTF-8 を使用**」に✓ → 再起動

これで Windows 全体のデフォルト ANSI コードページが UTF-8 になります。

**メリット**: cmd、古いアプリ、すべてが一貫した扱いに
**デメリット**: 一部の古いソフトが誤動作する可能性

### 方法 3: Windows Terminal を使う

新しい **Windows Terminal** は、UTF-8 処理がデフォルトで優秀。cmd や PowerShell を Windows Terminal 上で開く運用にすれば、多くの化けが解消される。

---

## PowerShell 固有の事情

PowerShell は cmd より複雑で、**コードページだけでなく `$OutputEncoding` と `[Console]::OutputEncoding`** が絡みます。

### PowerShell 5.1

Windows 標準の 5.1 は **出力エンコーディングがややバラバラ**。

```powershell
# 現在のエンコーディングを確認
[Console]::OutputEncoding
$OutputEncoding

# UTF-8 に統一
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
```

これを `$PROFILE` に書けば、毎回適用。

### PowerShell 7

既定で UTF-8 なので、通常は何もしなくて OK。5.1 との互換性のために明示する場合:

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new()
```

### PowerShell 5.1 と 7 の併用

- cmd: `AutoRun` で `chcp 65001`
- PS 5.1: `$PROFILE` でエンコーディング設定
- PS 7: デフォルトで OK

## よくある化けパターンと原因

### 1. Docker コマンドの日本語が化ける

```cmd
docker ps
# コンテナ名が「???」になる
```

→ `chcp 65001` で解決。

### 2. Python の print が化ける

```python
print("こんにちは")
# 出力: ????
```

原因:
- Python の stdout エンコーディングが CP932
- コンソールが UTF-8 でも、Python 側が違うと化ける

対処（PowerShell 5.1 での例）:

```powershell
# PYTHONIOENCODING 環境変数で Python の stdout を UTF-8 に
$env:PYTHONIOENCODING = "utf-8"
chcp 65001
python script.py
```

永続化: 環境変数 `PYTHONIOENCODING=utf-8` を設定。

### 3. `type` でファイル内容が化ける

`type file.txt` は **コンソールのコードページで解釈** して表示する。ファイルが UTF-8、コンソールが CP932 なら化ける。

対処:
```cmd
chcp 65001
type file.txt
```

または PowerShell:
```powershell
Get-Content -Raw -Encoding UTF8 file.txt
```

### 4. Git の出力が化ける

Git for Windows は出力エンコーディング設定が複数ある。

```bash
# すべて UTF-8 に
git config --global core.quotepath false
git config --global i18n.commitencoding utf-8
git config --global i18n.logoutputencoding utf-8
git config --global core.pager "less -r"
```

### 5. 出力を書き出すと化ける（リダイレクト）

```cmd
python script.py > output.txt
```

- コンソールが UTF-8 でも、**リダイレクト時は別ルート**
- Python の PYTHONIOENCODING がリダイレクト時に CP932 に戻る等

対処:
```cmd
set PYTHONIOENCODING=utf-8
python script.py > output.txt
```

## Windows Terminal を使うことの優位性

**Windows Terminal** は、cmd / PowerShell / WSL をタブで統合する Microsoft の新しいターミナル。

### 利点

- **UTF-8 ネイティブ**（レンダリング、入力、出力）
- 絵文字や CJK フォント対応が優秀
- プロファイル切り替えが楽
- GPU 加速で高速描画

### 設定ファイルのキーポイント

```json
{
  "defaultProfile": "{PowerShell7 の GUID}",
  "profiles": {
    "defaults": {
      "fontFace": "Cascadia Code",
      "fontSize": 11
    }
  }
}
```

---

## 実践的推奨設定

### コンパクトな初期設定

1. **Windows Terminal** をインストール（Microsoft Store）
2. **PowerShell 7** をインストール（`winget install Microsoft.PowerShell`）
3. デフォルトプロファイルを PowerShell 7 に
4. cmd 使用時に備えて `reg add` で `AutoRun=chcp 65001 > nul`
5. 必要に応じてシステムロケール UTF-8 を ON

### フォント

UTF-8 対応だけでなく、**日本語フォント内蔵** のものが吉:

- **Cascadia Code**（Microsoft 公式）
- **UDEV Gothic**（等幅、合字対応）
- **Source Han Code JP**
- **HackGen**（Hack + Genshin）

## 別視点: 化けたときの調査手順

1. **どこで化けている？**
   - コンソール出力
   - ファイル書き出し
   - 別プロセスへのパイプ
2. **元の文字コードは何？**
   - ソースファイル → エディタで確認
   - HTTP レスポンス → `Content-Type` ヘッダ
   - DB → カラムエンコーディング
3. **経路のどこで変換されている？**
   - アプリ内エンコーディング
   - コンソールのコードページ
   - パイプやリダイレクト時の扱い
4. **全体を UTF-8 に揃える**

---

## まとめ

- コンソール文字化けの主因は **コードページとコンテンツのエンコーディングの不一致**
- 一時対処は **`chcp 65001`**、永続対処は **AutoRun 設定** か **システムロケール UTF-8**
- **PowerShell 7 + Windows Terminal** に移行するのが最も根本的な解決
- PowerShell 5.1 では `$OutputEncoding` も UTF-8 に設定
- Python / Git / Docker 等、ツール別の環境変数設定も併用
