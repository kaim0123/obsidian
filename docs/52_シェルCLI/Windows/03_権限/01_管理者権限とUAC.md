# 管理者権限と UAC — 何が昇格を要求するのか

## はじめに

Windows で作業していると、たびたび **「この変更をアプリに許可しますか？」** という青いダイアログが出ます。これが **UAC**（User Account Control / ユーザーアカウント制御）です。

UAC は「**管理者権限が必要な操作**」を実行する前に、**ユーザーに確認を求める仕組み** です。Vista で導入されて以来、Windows セキュリティの基本となっています。

この仕組みを理解していないと:

- 「なぜインストールが失敗するのか」
- 「なぜ `C:\Program Files` に書き込めないのか」
- 「PowerShell で管理者として実行」とは何なのか

…が分からずにハマります。

---

## UAC の背景

### Vista 以前の Windows の問題

Windows XP までは、ユーザーが通常使うアカウントが **デフォルトで管理者権限** を持っていました。その結果:

- マルウェアもフル権限で動く → 被害が深刻
- 一般ユーザーが誤操作でシステム破壊
- アプリ開発者が「管理者前提」でコードを書くクセ

### UAC の解決策

Vista で UAC が導入され:

- **普段は権限を絞って動作**
- **必要な時だけ昇格して管理者権限を与える**

ログインユーザーは管理者でも、**実行中のプロセスは通常権限** という2段構えになりました。

---

## 「管理者アカウント」と「管理者権限で実行」の違い

### 管理者アカウント

- Windows のユーザー種別。アカウント作成時に「管理者」か「標準ユーザー」かを選ぶ
- 管理者アカウントでも、**普段は標準ユーザー相当の権限** で動く

### 管理者権限で実行（昇格プロセス）

- UAC ダイアログを通過した後、プロセスが **管理者権限** で動く状態
- タスクマネージャで「昇格」列を見ると分かる

```
[管理者アカウントでログイン]
    ↓
[普段のアプリ: 通常権限]  ← 標準ユーザーと同じ
    ↓  UAC 昇格
[特定アプリ: 管理者権限]  ← この瞬間だけフル権限
```

---

## 何が UAC 昇格を要求するか

### システム領域への書き込み

- `C:\Windows\`、`C:\Program Files\`、`C:\Program Files (x86)\`
- `HKEY_LOCAL_MACHINE` レジストリ
- システムサービス（`services.msc`）

### システム設定の変更

- ドライバのインストール
- Windows 機能の有効化・無効化
- システム環境変数の変更
- ファイアウォール規則
- UAC 自身の設定

### 一部のコマンド

- `net user`、`net localgroup`
- `dism`、`sfc /scannow`
- `bcdedit`
- `Set-ExecutionPolicy -Scope LocalMachine`
- レジストリの HKLM 編集（`reg add HKLM\...`）

### 管理者必須のアプリ

- ハードウェアドライバ系
- ウイルス対策ソフト
- 一部のインストーラ

---

## UAC 昇格を要求しない操作

ユーザー領域の変更は **昇格不要**:

- `C:\Users\yourname\` 配下
- `HKEY_CURRENT_USER` レジストリ
- ユーザー環境変数
- 多くのモダンアプリのインストール（Chrome、Discord 等は自分の AppData に入るため）

---

## UAC 昇格の方法

### GUI: 右クリック → 「管理者として実行」

- 実行ファイル（.exe、.bat、.ps1 ショートカット）を右クリック
- 「管理者として実行」

### ショートカットで常に管理者実行

1. ショートカットのプロパティ → 互換性タブ
2. 「管理者としてこのプログラムを実行する」にチェック

または:

1. ショートカットのプロパティ → 詳細設定
2. 「管理者として実行」にチェック

### コマンドライン

**PowerShell から別プロセスを管理者で起動**:

```powershell
Start-Process powershell -Verb RunAs
Start-Process cmd -Verb RunAs
Start-Process notepad -Verb RunAs -ArgumentList "C:\Windows\hosts"
```

### タスクスケジューラ経由

「最上位の特権で実行」を指定したタスクを作ると、UAC プロンプトなしで管理者実行可能（スケジューラ起動分のみ）。

### Windows Terminal で管理者タブ

- Windows Terminal の設定で、プロファイルごとに「管理者権限で起動」を設定できる
- タイトルバーに「管理者」と表示されれば OK

---

## 昇格状態の確認

### PowerShell

```powershell
# 現在のプロセスが管理者かどうか
$identity = [System.Security.Principal.WindowsIdentity]::GetCurrent()
$principal = New-Object System.Security.Principal.WindowsPrincipal($identity)
$principal.IsInRole([System.Security.Principal.WindowsBuiltinRole]::Administrator)
# True = 管理者
```

### cmd

```cmd
net session >nul 2>&1
if %errorlevel%==0 (echo admin) else (echo not admin)
```

## UAC の設定レベル

**コントロール パネル → ユーザー アカウント → ユーザー アカウント制御設定の変更**

スライダーで4段階:

| レベル | 挙動 |
|-------|------|
| 常に通知（最上位） | すべての変更で画面が暗転して通知 |
| 変更時に通知（既定） | アプリが変更を加える時のみ |
| 通知するが暗転しない | 同上、画面は暗転しない |
| 通知しない（最下位） | **UAC 無効に近い。非推奨** |

既定（上から2番目）が普通。下げるのは非推奨。

## UAC の回避すべきアンチパターン

### 1. UAC を完全に無効化

セキュリティが大きく下がる。一部のモダンアプリ（Store アプリ）も動かなくなる。

### 2. 全アプリを「常に管理者として実行」

不要な昇格の機会を増やすだけ。**必要な時だけ昇格** が原則。

### 3. 「管理者コマンドプロンプトを開きっぱなし」

操作を間違えるとシステム破壊。昇格シェルは必要最小限に。

## よくあるハマりどころ

### 1. ドラッグ＆ドロップが昇格プロセスに効かない

管理者として開いたエクスプローラーや VSCode に、通常権限のエクスプローラーから D&D できない。**同じ権限レベル同士** のアプリ間でしか D&D できない（セキュリティ上の制限）。

### 2. ネットワークドライブが見えない

標準プロセスでマウントしたネットワークドライブは、**昇格プロセスからは見えない** ことがある。

解決:
- 昇格プロセスからも明示的にマウントする
- レジストリ設定で「EnableLinkedConnections」を有効にする

### 3. 管理者 PowerShell で `choco install` が動いた、一般 PowerShell だと動かない

Chocolatey は管理者権限必須のパッケージマネージャ。**起動時に管理者で開く**（またはショートカット設定）。

### 4. インストーラが「アクセスが拒否されました」

インストーラ自身は通常権限で動く。インストール先が `C:\Program Files` だと書き込み不可。インストーラを右クリック → 管理者として実行。

### 5. `npm install -g` が権限エラー

グローバルインストールは管理者権限が必要。

**対処**:
- nvm-windows、volta を使って権限なしでも入る構成に
- または PowerShell を管理者で開いて実行

## WSL と UAC

WSL 側（Linux）の `sudo` は UAC とは **完全に別物**。

- Windows 側の UAC: Windows の管理者権限
- WSL 内の sudo: Linux の root 権限

WSL の起動自体は UAC 昇格不要。WSL の中で何をしようが、Windows 側のシステム領域には触れない。

### Windows 側を WSL から操作する場合

WSL から `powershell.exe` を呼んで Windows 側を管理するなら、**PowerShell 側で昇格が必要**。

```bash
# WSL から管理者 PowerShell を起動
powershell.exe -Command "Start-Process powershell -Verb RunAs"
```

## トラブルシューティング

### 「管理者として実行」が出ない

- 右クリックメニューに項目がない → ショートカットなら対象が .exe であることを確認
- グループポリシーで無効化されている可能性（企業PC）

### UAC ダイアログが出ない、出ても応答できない

セカンダリログオンサービス（`seclogon`）が止まっていることがある:

```powershell
Start-Service seclogon
```

### 管理者で実行しているのに「アクセスが拒否されました」

- UAC ではなく **ファイル/フォルダの ACL** が原因の場合あり
- 詳しくは `ファイル権限.md`

---

## まとめ

- UAC は **必要な時だけ管理者権限に昇格** する仕組み
- 「管理者アカウント」と「昇格プロセス」は別物
- システム領域（Windows、Program Files、HKLM）への書き込みで昇格が要求される
- 昇格シェルは **必要最小限** に。常時使うと事故の元
- `Start-Process -Verb RunAs` でコマンドラインから昇格可能
- D&D やネットワークドライブで権限レベルの違いによる罠に注意
- WSL の sudo と Windows の UAC は別システム
