# 実行ポリシー — PowerShell の ExecutionPolicy

## はじめに

PowerShell スクリプトを実行しようとして:

```
.\script.ps1 : このシステムではスクリプトの実行が無効になっているため、
ファイル C:\path\script.ps1 を読み込むことができません。
```

というエラーに遭遇したことはありますか？これは PowerShell の **実行ポリシー**（ExecutionPolicy）による制限です。

実行ポリシーは「**どんなスクリプトなら実行していいか**」を決める、**セキュリティ機能（というより安全装置）** です。

---

## なぜ実行ポリシーがあるのか

PowerShell は非常に強力。`.ps1` ファイルにはシステム全体を破壊できるほどのコマンドが書けます。

もし実行ポリシーがなければ:

- メールに添付された `.ps1` をクリックすると、任意のコードが動く
- Web からダウンロードしたスクリプトがそのまま走る
- マルウェアが簡単に拡散する

これを防ぐため、**「うっかり実行」を止める** のが実行ポリシーの目的です。ただしセキュリティ **境界** ではなく、**意図せぬ実行を防ぐ安全装置** という位置づけ（Microsoft も公式にそう述べている）。

---

## 実行ポリシーの種類

| ポリシー | 動作 |
|---------|------|
| **Restricted** | スクリプト実行を **完全に禁止**（対話型コマンドのみ可） |
| **AllSigned** | 信頼された発行元による **署名付きスクリプトのみ** 実行可 |
| **RemoteSigned** | ローカルのスクリプトは OK、**ダウンロード元のスクリプトは署名必須** |
| **Unrestricted** | 署名不要で実行可。ダウンロード元は警告 |
| **Bypass** | 警告もなし、何でも実行 |
| **Undefined** | 設定なし（上位スコープに従う） |

### デフォルト値

- **Windows クライアント**: `Restricted`（Windows 10 以降）
- **Windows Server**: `RemoteSigned`

### 実用的には `RemoteSigned`

普通の開発者が使うには `RemoteSigned` がバランス良い:

- 自分で書いた .ps1 はすぐ動く
- ネットから落とした .ps1 は「ブロック解除」するまで動かない
- 署名は任意

---

## 現在のポリシーを確認

```powershell
# すべてのスコープを確認
Get-ExecutionPolicy -List

# 出力例:
#         Scope ExecutionPolicy
#         ----- ---------------
# MachinePolicy       Undefined
#    UserPolicy       Undefined
#       Process       Undefined
#   CurrentUser       Undefined
#  LocalMachine       Restricted
```

- **実効的なポリシー** は、優先度の高いスコープから決定される
- 優先度: `MachinePolicy > UserPolicy > Process > CurrentUser > LocalMachine`

---

## スコープ（適用範囲）

### 1. Process

現在の PowerShell プロセスのみ。閉じると消える。

### 2. CurrentUser

現在のユーザーのみ。レジストリの `HKCU` に保存。

### 3. LocalMachine

全ユーザー。管理者権限が必要。レジストリの `HKLM` に保存。

### 4. UserPolicy / MachinePolicy

グループポリシーで強制設定された内容。個人では変更不可。

---

## 変更方法

### 基本コマンド

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

- 管理者権限不要（CurrentUser なら）
- 全ユーザー向けは管理者権限で `-Scope LocalMachine`

### よく使うパターン

```powershell
# 個人で RemoteSigned にする
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

# 一時的に現プロセスだけ Bypass（その場だけ）
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process

# 設定を戻す
Set-ExecutionPolicy -ExecutionPolicy Restricted -Scope CurrentUser
```

---

## 一時的に回避する方法

ポリシーを変えずに一回だけ実行したい場合:

### Bypass 指定で起動

```powershell
# 別 PowerShell を起動して一発実行
powershell -ExecutionPolicy Bypass -File "C:\path\script.ps1"
```

### インラインで Bypass

```powershell
# 一時的に現セッションだけ Bypass
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\script.ps1
```

## ダウンロードファイルの「ブロック」

Windows はダウンロードしたファイルに **「Zone.Identifier」** という印を付けます。これがあると `RemoteSigned` では実行できない。

### ブロック解除

```powershell
# 1ファイル
Unblock-File -Path .\script.ps1

# フォルダ配下全部
Get-ChildItem -Path C:\scripts -Recurse |
    Unblock-File
```

### Zone.Identifier を確認

```powershell
Get-Item .\script.ps1 -Stream *
# :$DATA
# Zone.Identifier   ← これがあるとブロック対象
```

代替の実体: NTFS の **代替データストリーム (ADS)** に「このファイルはインターネット領域から来た」情報が付く。

## 署名とは何か

スクリプトの **改ざん検知** と **発行元の確認** のための仕組み。

### 署名付きスクリプトを作る

自己署名でもできる:

```powershell
# 証明書を作成
$cert = New-SelfSignedCertificate -Type CodeSigningCert `
                                   -Subject "CN=My Code Signing" `
                                   -CertStoreLocation "Cert:\CurrentUser\My"

# スクリプトに署名
Set-AuthenticodeSignature -FilePath .\script.ps1 -Certificate $cert

# 信頼できる発行元として登録
Move-Item -Path "Cert:\CurrentUser\My\$($cert.Thumbprint)" `
          -Destination "Cert:\CurrentUser\TrustedPublisher"
```

これで `AllSigned` や `RemoteSigned` でも実行できる。

### 商用利用

企業で配布するなら DigiCert などから **コード署名証明書** を購入し、それで署名する。

## ポリシーが効かないように感じるとき

### ケース1: `python script.py` が動いてしまう

実行ポリシーは **`.ps1` ファイルに対してのみ** 効きます。`.py` や `.js` の実行には関係ない。

### ケース2: `&` でシェル実行なら通る

```powershell
& "C:\path\script.ps1"    # ポリシー適用
& { Get-Process }          # これはポリシーに引っかからない
```

対話型コマンドや式展開はポリシー対象外。

### ケース3: グループポリシーが上書き

企業 PC では管理者が強制設定していることがある:

```powershell
Get-ExecutionPolicy -List
# MachinePolicy    AllSigned   ← これが最優先
# CurrentUser      RemoteSigned  ← 効かない
```

この場合、個人の `Set-ExecutionPolicy` は効きません。情シスに相談。

### ケース4: プロファイルが読み込まれない

`$PROFILE` の読み込みも実行ポリシーに従います。初回は `RemoteSigned` にしないとプロファイルが動かない。

---

## 推奨設定

### 個人 PC

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

- 自作スクリプトはそのまま動く
- ダウンロードしたものは明示的に Unblock しないと動かない → 安全

### 開発用共有サーバー

```powershell
Set-ExecutionPolicy -ExecutionPolicy AllSigned -Scope LocalMachine
```

- 署名必須。意図しないスクリプトが混入しても動かない

### CI/CD スクリプト実行

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy.ps1
```

- その実行だけ Bypass。ポリシー本体は変えない

---

## セキュリティ上の注意

### 実行ポリシーはセキュリティ境界ではない

Microsoft 公式が明言している通り、**実行ポリシーは「誤実行防止」** であって「悪意対策」ではない。以下で簡単に迂回される:

```powershell
# どのポリシーでも通る方法
Get-Content .\script.ps1 | Invoke-Expression
powershell -Command "iex (Get-Content .\script.ps1 -Raw)"
```

マルウェア対策には **AppLocker / WDAC / Microsoft Defender** など別の仕組みが必要。

---

## トラブルシューティング

### 1. 「スクリプトの読み込みが無効」

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### 2. 「このスクリプトは信頼されていない発行元」

```powershell
Unblock-File -Path .\script.ps1
# または
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
```

### 3. 「グループポリシーで設定が上書きされている」

企業 PC でよくある。情シスの承認なしには変更不可。`powershell -ExecutionPolicy Bypass -File ...` で回避できる場合あり（ポリシー次第）。

### 4. VSCode の統合ターミナルで `$PROFILE` が動かない

```powershell
# Profile を確認
$PROFILE
Test-Path $PROFILE

# 実行ポリシーが原因
Get-ExecutionPolicy
```

`Restricted` だと Profile は読み込まれない。`RemoteSigned` 以上に。

---

## まとめ

- 実行ポリシーは `.ps1` スクリプトの **誤実行防止** のための安全装置
- 個人開発なら **`RemoteSigned` を `CurrentUser` スコープ** で設定が推奨
- ダウンロードファイルは **`Unblock-File`** で解除
- 一時的な回避は **`-ExecutionPolicy Bypass -Scope Process`**
- セキュリティ **境界** ではない（迂回可能） → 本格的なマルウェア対策には別仕組みを
- 企業 PC ではグループポリシーが効いている場合あり、情シスに相談
