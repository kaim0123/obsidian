# ストア設計の基本

> **ひとことで言うと**：ストアとは「状態」と「その状態を変える関数（アクション）」をひとまとまりにした入れ物。コンポーネントは状態を直接いじらず、決められた関数だけを呼んで更新する。

## たとえ話で理解する

銀行の窓口を思い浮かべてください。

- 金庫（＝状態）の中身は、お客さんが直接触れない。
- お客さんは窓口で「預ける」「引き出す」（＝アクション）と頼むだけ。
- 窓口のルール（残高より多くは引き出せない、など）が1か所にまとまっているので、誰が頼んでも同じ結果になる。

金庫をロビーに置いて「ご自由にどうぞ」にすると、誰がいつ減らしたのか分からなくなります。

## なぜ必要？（困りごと）

カートの状態を各コンポーネントが好き勝手に書き換えると、

- 「同じ商品を2回入れたら数量を増やす」というルールを、ボタンごとに書くことになる（書き忘れ・書き間違いが起きる）。
- 合計金額がおかしいとき、どこで変わったのか探せない。
- 状態の形（型）を変えると、あちこちのコンポーネントを直すことになる。

更新ロジックをストアに集めれば、ルールは1か所、探す場所も1か所になります。

## 基本の仕組み

```
  ┌────────────── ストア ──────────────┐
  │  状態（state）   { items: [...] }   │
  │  アクション     addItem / removeItem │
  │  購読の仕組み   subscribe / 通知     │
  └───────▲───────────────┬────────────┘
    ① アクションを呼ぶ     │ ③ 変わったよ！と通知
          │               ▼
     コンポーネント ◀── ② 新しい状態を読んで再描画
```

ストアに必要な部品は3つだけです。

| 部品 | 役割 | 例 |
| --- | --- | --- |
| 状態 | 今のデータ | `{ items: [] }` |
| アクション（更新関数） | 状態を変える唯一の入口。ルールをここに書く | `addItem(product)` |
| 購読（subscribe） | 変更をコンポーネントに知らせる | `subscribe(listener)` |

設計のコツ：

- **状態は最小限に**：合計金額のように計算で出せる値は持たない（[[04_派生状態と単一の情報源]]）。
- **更新はイミュータブルに**：配列やオブジェクトは書き換えず、新しく作り直す（[[03_イミュータブルな更新]]）。
- **アクションは「何をしたいか」で名付ける**：`setItems` より `addItem` / `clearCart`。
- **ストアは関心ごとに分ける**：カート用・認証用など。1つの巨大ストアにしない。

## コード例

### 方法1：useSyncExternalStore で最小ストアを作る

`useSyncExternalStore` は、React の外にあるデータ（外部ストア）を安全に読むための React 標準フックです。

```ts
// createStore.ts：どんな状態にも使える最小ストア
type Listener = () => void;

export function createStore<T>(initial: T) {
  let state = initial;
  const listeners = new Set<Listener>();

  return {
    getState: () => state,
    setState: (updater: (prev: T) => T) => {
      state = updater(state); // 新しい状態に差し替える
      listeners.forEach((l) => l()); // 購読者に通知
    },
    subscribe: (l: Listener) => {
      listeners.add(l);
      return () => { listeners.delete(l); }; // 購読解除の関数を返す
    },
  };
}
```

```ts
// cartStore.ts：状態とアクションをひとまとめにする
import { useSyncExternalStore } from "react";
import { createStore } from "./createStore";

type Item = { id: string; name: string; price: number; qty: number };
type CartState = { items: Item[] };

const store = createStore<CartState>({ items: [] });

// アクション：更新のルールはここにだけ書く
export const cartActions = {
  addItem(p: Omit<Item, "qty">) {
    store.setState((s) => {
      const found = s.items.find((i) => i.id === p.id);
      if (found) {
        return { items: s.items.map((i) => (i.id === p.id ? { ...i, qty: i.qty + 1 } : i)) };
      }
      return { items: [...s.items, { ...p, qty: 1 }] };
    });
  },
  removeItem(id: string) {
    store.setState((s) => ({ items: s.items.filter((i) => i.id !== id) }));
  },
  clear() {
    store.setState(() => ({ items: [] }));
  },
};

// コンポーネント用のフック
export function useCart() {
  return useSyncExternalStore(store.subscribe, store.getState);
}
```

```tsx
// 使う側：状態を読んで、アクションを呼ぶだけ
function CartBadge() {
  const { items } = useCart();
  const count = items.reduce((sum, i) => sum + i.qty, 0); // 派生値はその場で計算
  return <span>カート {count}</span>;
}

function AddButton({ id, name, price }: { id: string; name: string; price: number }) {
  return <button onClick={() => cartActions.addItem({ id, name, price })}>カートに入れる</button>;
}
```

💡 Provider が要らず、どのコンポーネントからでも `useCart()` と `cartActions` を使えます。この形は Zustand の考え方とほぼ同じです（[[02_Zustand]]）。

### 方法2：Context + useReducer で作る

`useReducer` は「今の状態」と「アクション（何が起きたかを表すオブジェクト）」から次の状態を返す関数（reducer）で状態を管理するフックです（[[04_複雑なローカル状態をreducerで整理する]]）。

```tsx
type Action = { type: "add"; item: Omit<Item, "qty"> } | { type: "remove"; id: string };

function cartReducer(state: CartState, action: Action): CartState {
  switch (action.type) {
    case "add":
      return { items: [...state.items, { ...action.item, qty: 1 }] };
    case "remove":
      return { items: state.items.filter((i) => i.id !== action.id) };
  }
}

const CartContext = createContext<{ state: CartState; dispatch: React.Dispatch<Action> } | null>(null);

export function CartProvider({ children }: { children: React.ReactNode }) {
  const [state, dispatch] = useReducer(cartReducer, { items: [] });
  return <CartContext.Provider value={{ state, dispatch }}>{children}</CartContext.Provider>;
}
```

- 良い点：React 標準だけで書ける。更新ルールが reducer に集まる。
- 弱い点：Context なので、状態が変わると使う全員が再描画される（[[02_propsバケツリレーとContextの限界]]）。

### どちらを選ぶ？

| | useSyncExternalStore | Context + useReducer |
| --- | --- | --- |
| Provider | 不要 | 必要 |
| 一部だけ購読 | セレクタで可能（[[04_セレクタと再レンダー対策]]） | できない |
| 向いている規模 | 共有が多い・頻繁に変わる | 小〜中規模、変化が少ない |

Redux Toolkit の「slice（状態＋reducer＋アクションのまとまり）」も同じ発想です（[[01_Redux]]）。

## よくある失敗

- ❌ `store.getState().items.push(x)` のように直接書き換える → ⭕ 必ずアクション経由で、新しい配列を作る
- ❌ 合計金額や件数もストアに保存する → ⭕ 元データ（items）から計算する
- ❌ `setItems` だけ公開して、ルールを各コンポーネントに書く → ⭕ `addItem` のように意図を表すアクションを用意する
- ❌ アプリの全状態を1つのストアに入れる → ⭕ カート・認証など関心ごとに分ける
- ❌ `getState` が毎回新しいオブジェクトを返す → ⭕ 同じ状態なら同じ参照を返す（無限ループや無駄な再描画の原因になる）

## まとめ

- ストア＝状態＋アクション＋購読の仕組み。更新は必ずアクション経由。
- 素の React なら `useSyncExternalStore` で最小ストアが作れ、`Context + useReducer` でも同じ考え方を実現できる。
- 状態は最小限・イミュータブルに、アクションは意図で名付ける。
