# グローバル状態とは

> **ひとことで言うと**：アプリの離れた場所にある複数のコンポーネントが、同じデータを読んだり書き換えたりする必要があるときに、それらの外側（アプリ全体から見える場所）に置く状態のこと。

## たとえ話で理解する

家族のカレンダーを思い浮かべてください。

- 自分の手帳（＝ローカル状態）は自分だけが見て書く。
- 冷蔵庫に貼った家族カレンダー（＝グローバル状態）は、家族全員が見て、誰でも予定を書き込める。

「お父さんの出張」を全員が知る必要があるなら、各自の手帳に書き写すより冷蔵庫に1枚貼るほうが確実です。ただし、何でも冷蔵庫に貼ると散らかって誰も読まなくなります。

## なぜ必要？（困りごと）

たとえば EC サイトで、次の3か所が「ログイン中のユーザー」と「カートの中身」を使うとします。

- ヘッダー：ユーザー名とカートの件数バッジ
- 商品詳細ページ：「カートに入れる」ボタン
- 購入ページ：カートの一覧と合計金額

これらはコンポーネントの木（ツリー：親子関係の図）の中で**遠く離れている**ため、どこか1つの `useState` に入れると、

- 共通の親まで状態を持ち上げ（[[02_状態の持ち上げ]]）、
- そこから何階層も props（親から子へ渡す引数）で渡す

ことになります。これが「props バケツリレー」です（[[02_propsバケツリレーとContextの限界]]）。

## 基本の仕組み

```
         ┌──────────────────────┐
         │  グローバル状態（ストア） │  user / cart / theme
         └──────────┬───────────┘
        読む・書く   │   読む・書く
   ┌────────────────┼────────────────┐
   ▼                ▼                ▼
 Header        ProductPage       CheckoutPage
（件数表示）    （追加ボタン）      （一覧・合計）
```

- **ストア**：グローバル状態をしまっておく入れ物。コンポーネントの外、またはツリーの一番上に置く。
- **購読（subscribe）**：「この値が変わったら教えて」と登録すること。変わると登録したコンポーネントだけが再描画される。

### グローバルに置くもの・置かないもの

| 種類 | 例 | グローバル向き？ |
| --- | --- | --- |
| アプリ全体の設定 | テーマ（ダーク/ライト）、言語 | ⭕ 向いている |
| ログイン情報 | ユーザー名、権限 | ⭕ 向いている |
| 複数画面をまたぐ作業中データ | カート、下書き | ⭕ 向いている |
| 1つの部品だけのUI状態 | モーダルの開閉、入力中の文字 | ❌ ローカルで十分 |
| サーバーから取ってきたデータ | 商品一覧、ユーザー詳細 | △ 専用の仕組みが良い（[[01_サーバー状態とは]]） |
| URLで共有したいもの | 検索条件、ページ番号 | △ URLに置く（[[01_URL状態とは]]） |

💡 「グローバル状態」は最後の手段くらいに考えるのがコツです。まずは [[03_状態は使う場所の近くに置く]] を検討しましょう。

## コード例

### Before：props で何階層も渡している

```tsx
// App が user を持ち、使わない Layout や Sidebar も中継役になっている
function App() {
  const [user, setUser] = useState<{ name: string } | null>(null);
  return <Layout user={user} onLogout={() => setUser(null)} />;
}

function Layout({ user, onLogout }: { user: { name: string } | null; onLogout: () => void }) {
  return <Sidebar user={user} onLogout={onLogout} />; // 自分は使わない
}

function Sidebar({ user, onLogout }: { user: { name: string } | null; onLogout: () => void }) {
  return <UserMenu user={user} onLogout={onLogout} />; // ここも中継だけ
}
```

### After：Context でグローバルに置く（素の React）

```tsx
import { createContext, useContext, useState, type ReactNode } from "react";

type User = { name: string } | null;
type AuthValue = { user: User; logout: () => void };

const AuthContext = createContext<AuthValue | null>(null);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<User>({ name: "山田" });
  return (
    <AuthContext.Provider value={{ user, logout: () => setUser(null) }}>
      {children}
    </AuthContext.Provider>
  );
}

// どこからでも呼べるカスタムフック
export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("AuthProvider の中で使ってください");
  return ctx;
}

// 中継役は props を受け取らなくてよくなる
function UserMenu() {
  const { user, logout } = useAuth();
  return <button onClick={logout}>{user?.name} をログアウト</button>;
}
```

Context は「頻繁に変わらない値」には十分ですが、頻繁に変わる値を入れると再レンダーが増えます。詳しくは [[02_propsバケツリレーとContextの限界]] と [[04_セレクタと再レンダー対策]]。

### ライブラリを使うと

Zustand なら Provider 不要で、ストアを1つ作って `useStore(s => s.user)` のように必要な部分だけ読めます（[[02_Zustand]]）。選び方は [[05_状態管理ライブラリの選び方]]。

## よくある失敗

- ❌ とりあえず全部グローバルに入れる → ⭕ 「2か所以上の離れた場所で使うか？」を確認してから置く
- ❌ サーバーから取ったデータをグローバルストアに手でコピーして管理する → ⭕ キャッシュ付きの仕組み（[[05_TanStack Query]] など）に任せる
- ❌ モーダルの開閉やフォーム入力中の値までグローバルにする → ⭕ その部品の `useState` で持つ
- ❌ 誰でもどこからでも直接書き換えられるようにする → ⭕ 更新は決まった関数経由にする（[[03_ストア設計の基本]]）

## まとめ

- グローバル状態は「離れた複数のコンポーネントが共有するデータ」の置き場所。
- テーマ・ログイン情報・カートなどが典型。UI の一時状態やサーバーデータは別の置き場所が向く。
- 置きすぎると散らかるので、まずはローカルに置けないか考える。
