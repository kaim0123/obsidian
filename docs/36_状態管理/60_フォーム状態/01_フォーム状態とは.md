# フォーム状態とは

> **ひとことで言うと**：フォームには「入力値」だけでなく、「触ったか」「変更したか」「エラー」「送信中か」といった複数の状態がある。これらをまとめて管理するのがフォーム状態。

## たとえ話で理解する

役所の**申請書**を窓口で書く場面です。

- **入力値（values）**：申請書に書いた内容
- **触った（touched）**：その欄に一度でもペンを当てたか。まだ書いていない欄に「未記入です」と怒るのは早すぎる
- **変更した（dirty）**：最初の内容から書き換えたか。書き換えていないなら「保存しますか？」と聞く必要はない
- **エラー（errors）**：職員が付箋で「ここ漢字が違います」と指摘したもの
- **送信中（submitting）**：窓口に出して、審査を待っている最中。二重に出してはいけない

## なぜ必要？（困りごと）

入力値しか管理していないと……

- ページを開いた瞬間、まだ何も書いていないのに**全部の欄が赤いエラー**になる
- 何も変更していないのに、画面を離れるとき「**変更が保存されていません**」と警告が出る
- 送信ボタンを連打して、**同じ注文が2回**送られる
- エラーの表示・非表示の条件が欄ごとにバラバラで、**コードが if 文だらけ**になる

## 基本の仕組み

### フォーム状態の構成要素

| 状態 | 意味 | 使いどころ |
|---|---|---|
| values | 現在の入力値 | 送信するデータ |
| initialValues | 最初の値 | dirty の判定、リセット |
| touched | 一度フォーカスを外したか（欄ごと） | エラーを表示するタイミング |
| dirty | 初期値から変わったか | 「保存」ボタンの有効化、離脱警告 |
| errors | 検証エラー（欄ごと） | エラーメッセージ表示 |
| status | 送信の段階（idle / submitting / success / error） | ボタンの無効化、結果表示 |

- **フォーカス**：入力欄が選ばれてキーボード入力を受け付けている状態。フォーカスが外れることを **blur（ブラー）** と呼ぶ。

### 「持つ状態」と「計算で出す状態」

```
持つ（state）             計算で出す（派生）
─────────────             ─────────────────
values           ──┬──▶  errors  = validate(values)
initialValues    ──┼──▶  dirty   = values ≠ initialValues
touched          ──┘     表示するエラー = touched かつ errors
status                   送信できる？ = エラーなし かつ status ≠ submitting
```

errors や dirty は values から計算できるので、別の state に**コピーしない**のがコツです（[[04_派生状態と単一の情報源]]）。

### フォーム状態はどこに置く？

- 基本は**そのフォームのコンポーネント内**（ローカル状態）で十分
- 複数画面にまたがる場合（ウィザード）は [[02_ウィザード（多段階フォーム）]]
- 送信後にサーバーのデータを更新する部分は [[04_ミューテーションとキャッシュの無効化]]

## コード例

### Before：入力値だけを持つ

```tsx
import { useState } from "react";

export function SignupForm() {
  const [email, setEmail] = useState("");
  // エラーを常に表示 → 開いた瞬間に赤い
  const error = email.includes("@") ? "" : "メールアドレスを入力してください";

  return (
    <form>
      <input value={email} onChange={(e) => setEmail(e.target.value)} />
      <p>{error}</p>
      <button>登録</button> {/* 連打できる */}
    </form>
  );
}
```

### After：touched・dirty・status も扱う

```tsx
import { useState } from "react";

type Values = { email: string; name: string };
const initial: Values = { email: "", name: "" };

function validate(v: Values) {
  const e: Partial<Record<keyof Values, string>> = {};
  if (!v.email.includes("@")) e.email = "メールアドレスの形式で入力してください";
  if (!v.name) e.name = "名前は必須です";
  return e;
}

export function SignupForm() {
  const [values, setValues] = useState(initial);
  const [touched, setTouched] = useState<Partial<Record<keyof Values, boolean>>>({});
  const [status, setStatus] = useState<"idle" | "submitting">("idle");

  const errors = validate(values); // 派生
  const dirty = JSON.stringify(values) !== JSON.stringify(initial); // 派生

  const field = (name: keyof Values) => ({
    name,
    value: values[name],
    onChange: (e: React.ChangeEvent<HTMLInputElement>) =>
      setValues({ ...values, [name]: e.target.value }),
    onBlur: () => setTouched({ ...touched, [name]: true }),
  });
  // 続きは下
```

```tsx
  const onSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    setTouched({ email: true, name: true }); // 送信時は全エラーを見せる
    if (Object.keys(errors).length > 0) return;
    setStatus("submitting");
    await fetch("/api/signup", { method: "POST", body: JSON.stringify(values) });
    setStatus("idle");
  };

  return (
    <form onSubmit={onSubmit}>
      <input {...field("email")} />
      {touched.email && errors.email && <p>{errors.email}</p>}
      <input {...field("name")} />
      {touched.name && errors.name && <p>{errors.name}</p>}
      <button disabled={!dirty || status === "submitting"}>登録</button>
    </form>
  );
}
```

- エラーは「触った欄だけ」表示される
- 送信中はボタンが押せない
- 送信の失敗処理などは [[04_送信フローの状態]] で詳しく扱う

### ライブラリを使うと

このような管理を毎回書くのは大変なので、React Hook Form のようなフォームライブラリがよく使われます。`formState` に `errors`・`touchedFields`・`isDirty`・`isSubmitting` がまとめて用意されています。詳しくは [[08_React Hook Form]]。

## よくある失敗

- ❌ ページを開いた瞬間に全欄のエラーを表示 → ⭕ touched（blur 後）か送信後にだけ表示する
- ❌ errors を useState で持ち、values と別々に更新してズレる → ⭕ errors は values から計算する（派生状態）
- ❌ 送信中もボタンが押せて二重送信 → ⭕ status を持ち、送信中は disabled にする
- ❌ 欄ごとに useState を10個並べる → ⭕ values を1つのオブジェクトにまとめるか、[[04_複雑なローカル状態をreducerで整理する]]
- ❌ 小さなフォームなのにグローバルストアに入れる → ⭕ フォーム状態は基本ローカル。送信したらサーバー状態へ

## まとめ

- フォーム状態 ＝ values ＋ touched ＋ dirty ＋ errors ＋ 送信 status
- errors と dirty は values から計算し、コピーして持たない
- 数が増えたら reducer やフォームライブラリで整理する
