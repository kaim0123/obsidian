# イミュータブルな更新

> **ひとことで言うと**：状態のオブジェクトや配列は「直接書き換えず、変更後の新しいコピーを作って置き換える」。React は「中身」ではなく「別物になったか（参照が変わったか）」で変更を検知するからです。

## たとえ話で理解する

提出済みの書類を修正したいとき、ペンで上から書き足すと「いつ・どこが変わったか」が分かりにくくなります。そこで **新しい用紙に清書して差し替える** ルールにします。

受付の人は「用紙そのものが新しくなったか」だけを見れば、変更があったと一瞬で分かります。中身を1文字ずつ見比べる必要はありません。

- **ミュータブル（mutable）**：書き換え可能 → 元の用紙に書き足す
- **イミュータブル（immutable）**：書き換え不可 → 新しい用紙に清書する

## なぜ必要？（困りごと）

```tsx
const [user, setUser] = useState({ name: "たろう", age: 20 });

user.age = 21;      // 中身を書き換えた
setUser(user);      // 同じオブジェクトを渡した
// → React「前と同じもの（同じ参照）だ」→ 再描画されない！
```

- ボタンを押しても画面が変わらない
- `useEffect` や `React.memo` が変更に気づかない
- 過去の値が勝手に変わり、Undo（元に戻す）が作れない（[[03_Undo・Redo]]）

## 基本の仕組み

### 参照（リファレンス）とは

オブジェクトは「箱」で、変数が持っているのは箱の中身ではなく **箱の場所（参照）** です。

```
書き換え（ミュータブル）          コピー（イミュータブル）
before ─┐                         before ──> [箱A] {age:20}
        ├─> [箱A] {age:21}        after  ──> [箱B] {age:21}
after  ─┘
before === after → true           before === after → false
（React は変更に気づけない）       （React は変更に気づける）
```

React は `Object.is(前, 後)`（ほぼ `===` と同じ比較）で「変わったか」を判定します。

### よく使う書き方の早見表

| やりたいこと | ❌ 書き換え | ⭕ 新しく作る |
|---|---|---|
| プロパティ変更 | `obj.a = 1` | `{ ...obj, a: 1 }` |
| 配列に追加 | `arr.push(x)` | `[...arr, x]` |
| 配列から削除 | `arr.splice(i, 1)` | `arr.filter((_, j) => j !== i)` |
| 要素を変更 | `arr[i].done = true` | `arr.map(t => t.id === id ? { ...t, done: true } : t)` |
| 並び替え | `arr.sort()` | `arr.toSorted()` または `[...arr].sort()` |

- `...`（スプレッド構文）：中身を展開して新しいオブジェクト／配列にコピーする書き方
- `toSorted` / `toReversed` / `with` は元の配列を変えない新しいメソッド（ES2023）

## コード例

### ネストしたオブジェクトの更新

```tsx
import { useState } from "react";

type Profile = { name: string; address: { city: string; zip: string } };

export function AddressForm() {
  const [profile, setProfile] = useState<Profile>({
    name: "たろう",
    address: { city: "東京", zip: "100-0001" },
  });

  const changeCity = (city: string) => {
    // 変わる階層はすべてコピーする（外側も address も）
    setProfile((prev) => ({
      ...prev,
      address: { ...prev.address, city },
    }));
  };

  return <input value={profile.address.city} onChange={(e) => changeCity(e.target.value)} />;
}
```

### 配列（Todo リスト）の更新

```tsx
type Todo = { id: number; title: string; done: boolean };

function useTodos() {
  const [todos, setTodos] = useState<Todo[]>([]);

  const add = (title: string) =>
    setTodos((prev) => [...prev, { id: Date.now(), title, done: false }]);

  const toggle = (id: number) =>
    setTodos((prev) => prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));

  const remove = (id: number) =>
    setTodos((prev) => prev.filter((t) => t.id !== id));

  return { todos, add, toggle, remove };
}
```

💡 `setTodos((prev) => ...)` のように **関数で更新** すると、常に最新の値を元に計算できて安全です。

### ライブラリを使うと

ネストが深いとスプレッドが大変になります。Immer というライブラリを使うと「書き換えているように書いて、裏でコピーを作る」ことができます。Redux Toolkit は Immer を内蔵しています（[[01_Redux]]）。深いネスト自体を避けるには [[05_状態の正規化]] も有効です。

## よくある失敗

- ❌ `arr.push()` してから `setArr(arr)` → ⭕ `setArr([...arr, x])`
- ❌ 外側だけコピーして内側を書き換える（`const c = {...p}; c.address.city = "大阪"`）→ ⭕ 変わる階層はすべてスプレッドする
- ❌ `arr.sort()` を描画中に呼んで状態を壊す → ⭕ `toSorted()` かコピーしてからソート
- ❌ 連続更新で古い値を使う（`setCount(count + 1)` を2回）→ ⭕ `setCount(c => c + 1)` の関数形式
- ❌ 何もかも毎回ディープコピー（`structuredClone` 等）する → ⭕ 変わった部分だけコピー。変わらない部分は同じ参照のままで良い

## まとめ

- React は「参照が変わったか」で変更を検知する
- オブジェクトはスプレッド、配列は map / filter / スプレッドで新しく作る
- ネストが深いなら Immer や正規化で楽をする
