# ページングと無限スクロール

> **ひとことで言うと**：大量のデータは少しずつ（ページ単位で）取る。「ページ番号で切り替える」か「下までスクロールしたら次を足す」かの2通りがあり、どちらもページごとにキャッシュすると速く・正しく動く。

## たとえ話で理解する

- **ページング**：分厚い本を「〇ページを開く」と指定して読む。前のページに戻るのも自由
- **無限スクロール**：巻物をくるくる広げていく。読み進めるほど下に足されていく

どちらも「全部を一度に机に広げない」のがポイントです。一度読んだページにしおりを挟んでおけば（＝キャッシュ）、戻ったときにすぐ開けます。

## なぜ必要？（困りごと）

1万件を一度に取ると、通信も表示も重くなります。かといって素の fetch で分割取得すると、次の問題が出ます。

- ページを切り替えるたびに画面が空になり、ガタッとちらつく
- 2ページ → 3ページと素早く押すと、2ページ目の結果が後から届いて表示が狂う（競合）
- 無限スクロールで「次を読む」が2回同時に走り、同じページが重複して並ぶ
- 1ページ目に戻ると、また最初から取り直しになる
- 途中で新しい投稿が増え、次のページに **同じ項目がズレて再登場** する

## 基本の仕組み

### 2つの方式

| 方式 | 取り方 | 向いている場面 |
|---|---|---|
| ページング（ページ番号） | `?page=3&limit=20` | 管理画面の表、検索結果。「何ページ目」が大事 |
| 無限スクロール | 「次を読む」で後ろに足す | SNS のタイムライン、フィード |

### オフセット方式とカーソル方式

- **オフセット方式**：「先頭から40件飛ばして20件」と位置で指定。分かりやすいが、途中で件数が増えるとズレる
- **カーソル方式**：「このID（カーソル）の次から20件」と目印で指定。ズレにくく、無限スクロール向き
  - **カーソル**：「ここまで読んだ」を表す目印。サーバーがレスポンスに `nextCursor` として付けて返すことが多い

### キャッシュのしかた

```
ページング：       ["posts", { page: 1 }]  ["posts", { page: 2 }]  ... ページごとに別キャッシュ
無限スクロール：   ["feed"] = { pages: [1ページ目, 2ページ目, ...] }  1つのキャッシュに積み上げ
```

💡 ページ番号は URL に入れておくと、リロードや共有でも同じページが開けます（[[03_フィルタ・並び替え・ページネーション]]）。

## コード例

### Before：素の fetch でページング

```tsx
function PostTable() {
  const [page, setPage] = useState(1);
  const [posts, setPosts] = useState<Post[] | null>(null);

  useEffect(() => {
    const controller = new AbortController();
    setPosts(null); // ← 切り替えのたびに空になり、ちらつく
    fetch(`/api/posts?page=${page}`, { signal: controller.signal })
      .then((r) => r.json())
      .then(setPosts)
      .catch(() => {});
    return () => controller.abort(); // 素早い切り替えでの競合を防ぐ
  }, [page]);

  // 1ページ目に戻るとまた取り直し（キャッシュが無い）
  return <Table rows={posts} onPageChange={setPage} />;
}
```

### After：ページング（TanStack Query）

```tsx
import { useQuery, keepPreviousData } from "@tanstack/react-query";

function PostTable() {
  const [page, setPage] = useState(1);
  const { data, isPlaceholderData } = useQuery({
    queryKey: ["posts", { page }], // ページごとにキャッシュ
    queryFn: () => fetch(`/api/posts?page=${page}`).then((r) => r.json()),
    placeholderData: keepPreviousData, // 次が届くまで前のページを表示したまま
  });

  return (
    <>
      <Table rows={data?.items} dimmed={isPlaceholderData} />
      <button onClick={() => setPage((p) => p + 1)} disabled={isPlaceholderData || !data?.hasMore}>
        次へ
      </button>
    </>
  );
}
```

### After：無限スクロール（TanStack Query）

```tsx
import { useInfiniteQuery } from "@tanstack/react-query";

function Feed() {
  const { data, fetchNextPage, hasNextPage, isFetchingNextPage } = useInfiniteQuery({
    queryKey: ["feed"],
    queryFn: ({ pageParam }) =>
      fetch(`/api/feed?cursor=${pageParam}`).then((r) => r.json()),
    initialPageParam: "", // 最初のカーソル
    getNextPageParam: (lastPage) => lastPage.nextCursor ?? undefined, // undefined なら終わり
  });

  const items = data?.pages.flatMap((p) => p.items) ?? [];
  return (
    <>
      <ul>{items.map((i) => <li key={i.id}>{i.text}</li>)}</ul>
      <button onClick={() => fetchNextPage()} disabled={!hasNextPage || isFetchingNextPage}>
        {isFetchingNextPage ? "読み込み中…" : hasNextPage ? "もっと見る" : "これで全部です"}
      </button>
    </>
  );
}
```

- `fetchNextPage` は取得中に重ねて呼んでも二重に走らない
- 自動で読み込みたいときは、ボタンの代わりに **IntersectionObserver**（要素が画面に入ったことを知らせるブラウザの機能）で末尾を監視して `fetchNextPage()` を呼ぶ

SWR では `useSWRInfinite(getKey, fetcher)` を使い、`size` / `setSize(size + 1)` でページ数を増やします。詳しくは [[05_TanStack Query]] / [[06_SWR]]。

## よくある失敗

- ❌ ページ番号をキーに入れ忘れ、どのページも同じキャッシュになる → ⭕ `["posts", { page }]` のようにキーに含める
- ❌ 切り替えのたびに空にしてちらつく → ⭕ 次が届くまで前のページを表示したまま（`keepPreviousData`）
- ❌ 無限スクロールをオフセット方式で作り、項目が重複・欠落する → ⭕ 追加が多いデータはカーソル方式にする
- ❌ 「次を読む」の二重実行で同じページが並ぶ → ⭕ 取得中は呼ばない（`isFetchingNextPage` を確認）
- ❌ 追加・削除のあと無限リスト全体を放置する → ⭕ `["feed"]` を無効化して取り直す（[[04_ミューテーションとキャッシュの無効化]]）

## まとめ

- 大量データはページ単位で取り、ページごとにキャッシュする
- 表ならページング＋前ページ表示維持、フィードなら無限スクロール＋カーソル方式
- 競合・重複・ちらつきはライブラリの仕組み（キー・`keepPreviousData`・`useInfiniteQuery`）で防げる
