# 最初の5分で何をするか

アラートが鳴った直後は、慌てて手当たり次第にログを見たり、思いついた修正を入れたりしがちです。最初の数分でやるべきことは、**影響を把握し、人を集め、記録を始め、止血できるか判断する**ことです。この章では、オンコール担当やインシデントコマンダーが最初の 5 分で使うチェックリストをまとめます。

---

## 1. 最初の 5 分のチェックリスト

| 時間 | やること | 具体例 |
|------|----------|--------|
| 0〜1 分 | **アラートを受け取る（Ack）** | PagerDuty で Acknowledge、チャンネルに「見ています」 |
| 1〜2 分 | **影響を確認する** | ダッシュボードでエラー率・レイテンシ・リクエスト数を見る |
| 2〜3 分 | **宣言するか決める** | 重大度を付け、インシデントチャンネルを作る |
| 3〜4 分 | **人を集める** | IC・必要な専門家を呼ぶ。1 人で抱えない |
| 4〜5 分 | **止血策を検討する** | 直前の変更はあるか？ロールバックできるか？ |

この順番は Atlassian の Incident Handbook や PagerDuty の Incident Response ドキュメントの初動と同じ考え方です。

---

## 2. 影響を確認する：3 つの問い

1. **誰が困っているか**：全ユーザーか、一部か。特定の地域・端末・顧客か。
2. **何ができないか**：ログインできない、決済できない、表示が遅い。
3. **いつから、悪化しているか**：グラフで開始時刻を特定する。**増え続けているか横ばいか**で急ぐ度合いが変わる。

見るべきダッシュボードは事前に決めておきます。Google SRE 本 6章の**ゴールデンシグナル**（レイテンシ・トラフィック・エラー・飽和度）が基本です（66_可観測性/10_基礎）。

---

## 3. 「直前に何が変わったか」を最初に疑う

障害の多くは**変更**がきっかけです。まず次を確認します。

| 変更の種類 | 確認場所 |
|------------|----------|
| アプリのデプロイ | CI/CD の履歴、デプロイ通知チャンネル |
| 設定変更・Feature Flag | 設定管理ツール、Flag の変更ログ |
| インフラ変更 | IaC の適用履歴、クラウドの監査ログ |
| DB マイグレーション | マイグレーション履歴 |
| 外部サービス | 依存先のステータスページ |
| トラフィック | キャンペーン開始、ボット、メディア掲載 |

開始時刻と変更時刻が一致すれば、**原因の確証がなくてもロールバックする**のが基本です（[[01_デプロイ直後の異常]]）。

---

## 4. 最初に書くメッセージのテンプレート

インシデントチャンネルの最初の投稿は、後から来た人がすぐ状況をつかめる形にします。

```text
【SEV2 宣言】決済エラー増加
- 検知: 14:02 アラート（checkout API 5xx 率 8%）
- 影響: クレジットカード決済の一部が失敗。他の決済手段は正常
- 開始: 13:55 頃から
- 直前の変更: 13:50 payment-service v2.14.0 デプロイ
- IC: 山田 / Ops: 佐藤 / Comms: 未定
- 次の行動: v2.13.3 へのロールバックを検討中
```

---

## 5. やってはいけないこと

- **黙って調べ続ける**：15 分経っても 1 人なら、それ自体が問題。応援を呼ぶ。
- **記録せずに変更する**：何をしたか後でわからなくなる（[[06_インシデントタイムラインの記録]]）。
- **本番で試行錯誤する**：思いつきの設定変更を重ねない。1 つずつ、宣言してから。
- **原因がわかるまで止血しない**：ロールバックや機能 OFF は原因不明でも実行できる。
- **責任者探しをする**：「誰がデプロイした？」ではなく「何がデプロイされた？」と聞く。

---

## 6. 1 人でオンコールしているとき

- 最初の 5 分で**応援を呼ぶ基準**を決めておく。例：「SEV2 以上なら即 IC を呼ぶ」「10 分で原因の見当がつかなければ呼ぶ」。
- 呼ぶことをためらわない文化が大切です。呼ばれて何もなかったことを責めない（[[04_オンコール疲弊対策と引き継ぎ]]）。
- 手が回らないときは、記録は「時刻＋一言」だけでもチャンネルに残す。

---

## 7. ランブックとつなぐ

アラートごとに「最初に見るもの」「止血策」をランブックに書いておくと、最初の 5 分が短くなります（[[02_ランブックの書き方]]）。アラート通知にランブックの URL を含めておくのが効果的です。
