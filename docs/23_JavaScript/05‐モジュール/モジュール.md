# モジュール（ES Modules）

## モジュールとは

**モジュール（module）** とは、「コードをファイル単位で分割して、必要なものだけを他のファイルから読み込める仕組み」のことです。

1つのファイルに全部書くと、何千行にもなって読めなくなり、変数名が衝突し、どこで何をしているか分からなくなります。モジュールを使えば、機能ごとにファイルを分け、明示的に「これを公開する（export）」「これを取り込む（import）」と書けます。

JavaScript の標準モジュール機能は **ES Modules（ESM）** と呼ばれ、ES2015 で導入されました。現在のブラウザ・Node.js・ビルドツール（Vite、webpack、esbuildなど）で標準的に使われます。

## export（公開する）

他のファイルから使えるようにしたい関数・クラス・変数に `export` を付けます。

### 名前付きエクスポート（named export）

```js
// math.js
export const PI = 3.14159;

export function add(a, b) {
  return a + b;
}

export function multiply(a, b) {
  return a * b;
}
```

複数の値を個別の名前で公開できます。1つのファイルにいくつでも書けます。

まとめて書くこともできます。

```js
// math.js
const PI = 3.14159;
function add(a, b) { return a + b; }
function multiply(a, b) { return a * b; }

export { PI, add, multiply };
```

### デフォルトエクスポート（default export）

ファイルから「1つだけ代表となるもの」を公開したい場合に使います。

```js
// user.js
export default class User {
  constructor(name) {
    this.name = name;
  }
}
```

`default` は1ファイルに1つだけ。名前付きと共存もできます。

```js
// logger.js
export default function log(msg) { console.log(msg); }
export const LEVEL = { INFO: 1, ERROR: 2 };
```

## import（取り込む）

他のファイルから取り込むには `import` を使います。

### 名前付きインポート

```js
// app.js
import { add, multiply, PI } from "./math.js";

console.log(add(1, 2));     // 3
console.log(multiply(4, 5)); // 20
console.log(PI);            // 3.14159
```

波括弧 `{ }` の中の名前は、エクスポート側の名前と **一致** させる必要があります。

### 別名を付ける（as）

同じ名前のものが他にもあって被るとき、別名を付けられます。

```js
import { add as sum } from "./math.js";
console.log(sum(1, 2)); // 3
```

### デフォルトインポート

```js
import User from "./user.js";
const taro = new User("太郎");
```

デフォルトなので名前は好きに付けられます（`User` でも `Person` でも OK）。

### 名前付き＋デフォルトを同時に

```js
import log, { LEVEL } from "./logger.js";
```

### 全部まとめて

```js
import * as math from "./math.js";
console.log(math.add(1, 2));
console.log(math.PI);
```

名前空間のように使えます。

## ファイルパスの書き方

- `./foo.js` … 同じフォルダ
- `../foo.js` … 1つ上のフォルダ
- `./utils/foo.js` … サブフォルダ
- `foo` や `@scope/foo` … `node_modules` のパッケージ

ブラウザで直接動かすときは **拡張子（.js）が必須**。Node.js でも ESM として動かすなら拡張子を付けるのが安全です。TypeScript+バンドラ環境では省略できることもあります。

## ブラウザで使う

HTML で `<script>` に `type="module"` を付けます。

```html
<script type="module" src="./app.js"></script>
```

`type="module"` にすると:

- 自動で strict モードになる
- トップレベルの `var` がグローバルにならない
- `import` / `export` が使える
- 別オリジンからの読み込みは CORS が必要

## Node.js で使う

Node.js では伝統的に **CommonJS（CJS）** という別の仕組み（`require` / `module.exports`）が使われてきました。最近は ESM も使えます。

ESM として動かすには、次のいずれか。

1. `package.json` に `"type": "module"` を書く
2. ファイル拡張子を `.mjs` にする

```js
// package.json
{
  "type": "module"
}
```

```js
// greet.mjs
export function greet(name) { return `Hello, ${name}!`; }
```

CommonJS の書き方との違いは次のとおり。

| 目的 | CommonJS | ESM |
|---|---|---|
| 公開 | `module.exports = x` | `export default x` / `export { x }` |
| 取り込み | `const x = require("./foo")` | `import x from "./foo.js"` |
| 動的 | 同期 | 非同期（`import()`） |

## 動的 import

通常の `import` はファイルの先頭にしか書けませんが、条件によって読み込みたいときは **動的 import** を使います。

```js
async function loadHeavyModule() {
  const module = await import("./heavy.js");
  module.run();
}

// 「ボタンを押したときだけ読み込む」などに便利
button.addEventListener("click", loadHeavyModule);
```

戻り値は Promise なので `await` で取り出します。コード分割やレイジーロードの基本テクニックです。

## モジュールの特徴

### 1回だけ評価される

同じモジュールを何度 import しても、ファイルの中身は **1回しか実行されません**。

```js
// counter.js
console.log("counter.js ロード");
export let count = 0;
```

```js
import { count } from "./counter.js";
import { count } from "./counter.js";  // メッセージは出ない
```

### export されたものは「生きたリンク」

import した値は、エクスポート側が変わると反映されます（読み取り専用）。

```js
// counter.js
export let count = 0;
export function inc() { count++; }
```

```js
import { count, inc } from "./counter.js";
console.log(count); // 0
inc();
console.log(count); // 1（反映される）
count = 99; // TypeError（代入できない）
```

### strict モードが自動的に有効

`"use strict"` を書かなくても、モジュール内は厳格モードで動きます。

## よくある落とし穴

### 1. 拡張子を忘れる

ブラウザでは `.js` 省略不可。`import { x } from "./foo"` は 404 になります。

### 2. default と named を混同

```js
// NG
import { User } from "./user.js"; // user.js が default export の場合
// OK
import User from "./user.js";
```

### 3. 循環参照（A が B を、B が A を）

できてしまうとタイミングによって `undefined` が見えることがあります。設計で避けるのがベスト。

### 4. CommonJS と ESM の混在

Node.js プロジェクトで両方を混ぜると地獄を見ます。プロジェクト単位でどちらかに寄せましょう。新規なら ESM 推奨。

## まとめ

- モジュールはコードをファイル単位に分割する仕組み
- `export` で公開、`import` で取り込む
- 名前付き（複数）／デフォルト（1つ）の2種類
- ブラウザでは `<script type="module">`、Node.js では `"type": "module"`
- 動的 import でレイジーロードもできる
- モジュールは1回しか評価されない、strict が自動で効く

モジュールを使えないと、規模の大きな JavaScript は書けません。`import`/`export` は必ず手に馴染ませましょう。
