## 07-1. import / export（ES Modules）

### なぜファイルを分けるのか

1つのファイルに全部書くと：
- ファイルが長すぎて探しにくい
- 複数人で同時に編集しにくい
- 同じコードを別の場所で再利用できない

### export：外に公開する

```javascript
// math.js
// named export（名前付きエクスポート）
export function add(a, b) {
  return a + b;
}

export function subtract(a, b) {
  return a - b;
}

export const PI = 3.14159;
```

```javascript
// まとめてexportする書き方
function add(a, b) { return a + b; }
function subtract(a, b) { return a - b; }
const PI = 3.14159;

export { add, subtract, PI };
```

### import：外から取り込む

```javascript
// main.js
import { add, subtract, PI } from "./math.js";

console.log(add(2, 3));     // → 5
console.log(subtract(5, 3)); // → 2
console.log(PI);             // → 3.14159
```

### default export

1つのモジュールにつき1つだけ「デフォルト」として公開できます。

```javascript
// User.js
export default class User {
  constructor(name) {
    this.name = name;
  }
}

// main.js
import User from "./User.js";  // { } なしで好きな名前で受け取れる
const user = new User("太郎");
```

### named export vs default export

```
named export （推奨）：
  - export { add, subtract }
  - import { add } from "./math.js"
  - 名前が固定されるのでリファクタリングしやすい
  - 1つのファイルから複数エクスポートできる

default export：
  - export default function() {}
  - import anyName from "./module.js"
  - 好きな名前で受け取れる（一貫性が下がる）
  - 1ファイルにつき1つだけ
```

### HTMLでES Modulesを使う

```html
<!-- type="module" をつける -->
<script type="module" src="main.js"></script>
```

### Node.jsでES Modulesを使う

```json
// package.json に追加
{
  "type": "module"
}
```

または、ファイル拡張子を `.mjs` にする。

## 07-2. 依存関係の考え方（循環参照の回避）

### 循環参照とは

A が B を import し、B が A を import する状態。

```javascript
// ❌ 循環参照
// a.js
import { b } from "./b.js";
export const a = "A" + b;

// b.js
import { a } from "./a.js";
export const b = "B" + a;
```

これは「卵が先か鶏が先か」問題で、正しく動きません。

### 循環参照の回避

```javascript
// ✅ 共通部分を別ファイルに切り出す
// shared.js
export const BASE = "共通値";

// a.js
import { BASE } from "./shared.js";
export const a = "A" + BASE;

// b.js
import { BASE } from "./shared.js";
export const b = "B" + BASE;
```

**コツ**：依存関係は**一方向**（ツリー構造）にする。上流から下流へ流れるように設計する。

```
✅ 良い構造（ツリー型）
main.js → feature.js → utils.js

❌ 悪い構造（循環）
main.js → feature.js → utils.js → feature.js
```

## 07-3. 設計の最小ルール（責務、命名、フォルダ構成）

### 1ファイル1責務

```
✅ 良い例
math.js       → 数学的な計算関数
validation.js → バリデーション関数
api.js        → API通信関連

❌ 悪い例
utils.js      → 雑多な関数が100個入っている
```

### ファイル名の命名

```
- 機能を表す名前にする（何が入っているかわかるように）
- ケバブケース（kebab-case）が一般的：date-utils.js, user-service.js
- クラスを公開するファイルはパスカルケース：User.js, TodoItem.js
```

### フォルダ構成の例

```
src/
├── components/     ← UI部品
│   ├── Header.js
│   └── TodoItem.js
├── services/       ← API通信、外部連携
│   └── api.js
├── utils/          ← 汎用ユーティリティ
│   ├── date.js
│   └── format.js
├── constants.js    ← 定数
└── main.js         ← エントリーポイント
```

## 07-4. named import の作法（読みやすさと運用）

### import の書き方のコツ

```javascript
// ✅ 必要なものだけ import する
import { add, subtract } from "./math.js";

// ❌ すべてを import する（何を使っているか不明確）
import * as math from "./math.js";
math.add(1, 2);  // 便利だが、依存が見えにくい
```

### import の整理

```javascript
// ✅ 整理された import（グループ分け）
// 1. 外部ライブラリ
import React from "react";
import { useState } from "react";

// 2. 自分のプロジェクト内のモジュール
import { formatDate } from "./utils/date.js";
import { fetchUser } from "./services/api.js";

// 3. 定数・型
import { MAX_RETRIES } from "./constants.js";
```

### re-export（まとめて公開）

```javascript
// utils/index.js
export { formatDate } from "./date.js";
export { formatNumber } from "./number.js";
export { capitalize } from "./string.js";

// main.js（1つの場所から全部importできる）
import { formatDate, formatNumber, capitalize } from "./utils/index.js";
```

## よくある間違い

```javascript
// ❌ ファイルパスの ./ を忘れる
import { add } from "math.js";     // npm パッケージと解釈される
// ✅ 相対パスには ./ をつける
import { add } from "./math.js";

// ❌ default export を { } で import する
import { User } from "./User.js";  // named import になってしまう
// ✅ default export は { } なし
import User from "./User.js";

// ❌ 循環参照に気づかない → 実行時に undefined になる
```

---

## 重要ポイント

1. **`export`** で公開、**`import`** で取り込む
2. **named export** を基本にする（`export { add }`）
3. 相対パスには **`./`** を忘れずにつける
4. **循環参照を避ける**：依存関係は一方向に
5. **1ファイル1責務**：ファイル名で中身がわかるように
6. import は**必要なものだけ**取り込む
