# クロージャ（Closure）

## クロージャとは何か

**クロージャ（closure）** とは、「関数が定義された場所の変数を、その関数がずっと覚えている仕組み」のことです。関数と、その関数を作った時点の周囲の情報（スコープ）がセットになっているもの、と考えると分かりやすいです。

JavaScript では、関数は値として扱える「第一級オブジェクト」なので、別の関数から関数を返したり、変数に代入したり、引数として渡したりできます。このときに、返された関数が「元いた場所の変数」を覚えて使えるのがクロージャの特徴です。

言い換えると、クロージャは「自分が生まれた環境を持ち歩ける関数」です。

## 一番シンプルな例

まずは最小の例を見てみましょう。

```js
function makeCounter() {
  let count = 0;                // ← この count が「囲まれた変数」
  return function () {
    count += 1;
    return count;
  };
}

const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
```

`makeCounter` は関数の中で `count` という変数を定義し、`count` を参照する関数を返しています。`makeCounter()` の呼び出しは終わっているのに、返ってきた内側の関数は `count` を覚えています。これがクロージャです。

普通は、関数の実行が終わったら中で作った変数は消えます。しかしクロージャでは、「その変数を参照している関数」が残っている限り、変数はメモリ上に保たれ続けます。

## もう一つの例：プライベートな状態を持つ

クロージャを使うと、外からは直接触れない「プライベートな状態」を作ることができます。

```js
function createBankAccount(initialBalance) {
  let balance = initialBalance;  // 外から直接アクセスできない変数

  return {
    deposit(amount) {
      balance += amount;
      return balance;
    },
    withdraw(amount) {
      if (amount > balance) {
        throw new Error("残高不足");
      }
      balance -= amount;
      return balance;
    },
    getBalance() {
      return balance;
    },
  };
}

const account = createBankAccount(1000);
console.log(account.getBalance()); // 1000
account.deposit(500);
console.log(account.getBalance()); // 1500
// account.balance は undefined（直接アクセスできない）
```

`balance` は `createBankAccount` のローカル変数なので、外側からは `account.balance` のように直接読めません。でも `deposit`, `withdraw`, `getBalance` の3つのメソッドからは読み書きできます。これで「残高は関数経由でしか操作できない」という安全な仕組みができます。

オブジェクト指向でいう「プライベートフィールド」をクロージャで実現している、と考えると分かりやすいです。

## クロージャがよく使われる場面

### 1. イベントハンドラで情報を持ち運ぶ

```js
function setupButton(buttonId, message) {
  const button = document.getElementById(buttonId);
  button.addEventListener("click", function () {
    alert(message); // ← 外側の message を覚えている
  });
}

setupButton("btn1", "こんにちは");
setupButton("btn2", "さようなら");
```

ボタンごとに違うメッセージを出したいとき、クロージャのおかげで簡単に書けます。

### 2. 関数ファクトリ（関数を作る関数）

```js
function multiplyBy(factor) {
  return function (n) {
    return n * factor;
  };
}

const double = multiplyBy(2);
const triple = multiplyBy(3);

console.log(double(5)); // 10
console.log(triple(5)); // 15
```

`factor` の値が関数ごとに記憶されるので、「2倍する関数」と「3倍する関数」を別々に作れます。

### 3. デバウンスやスロットルなどのテクニック

入力中に何度もAPIを呼ばないようにする「デバウンス」という処理にもクロージャが使われます。

```js
function debounce(fn, delay) {
  let timerId;                   // ← クロージャで保持
  return function (...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delay);
  };
}
```

`timerId` は外からは見えない内部状態で、呼び出しのたびに保持されます。

## よくある落とし穴：ループの中でクロージャ

昔の JavaScript（`var` しかなかった頃）では、次のコードは期待通り動きませんでした。

```js
// NG例（var だと期待通りに動かない）
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i);            // 全部 3 になる
  }, 100);
}
```

`var` は関数スコープなので、3つの `setTimeout` はすべて同じ `i` を見ています。ループが終わったあと `i` は 3 になっているので、3回「3」が出ます。

`let` を使えば解決します。

```js
// OK例：let を使う
for (let i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i);            // 0, 1, 2 が順に出る
  }, 100);
}
```

`let` はブロックスコープなので、ループの回ごとに新しい `i` が作られ、各クロージャはそれぞれの `i` を覚えます。

**教訓**：現代の JavaScript では原則 `let`/`const` を使い、`var` は避けましょう。

## メモリの話（軽く）

クロージャは便利ですが、「参照し続けている変数は解放されない」という性質があります。大きなデータを抱えたままのクロージャを大量に作ると、メモリを食い続けてしまうことがあります。

普段はあまり気にしなくて大丈夫ですが、「イベントリスナを外し忘れて、そこから重いオブジェクトを参照し続けている」というケースはメモリリークの原因になります。必要なくなったハンドラは `removeEventListener` で外す、というのが基本です。

## まとめ

- クロージャ＝「関数」＋「関数が作られた時のスコープ」
- 関数の外に出しても、内側の変数を覚えたまま使える
- プライベートな状態を持たせる、関数ファクトリ、イベントハンドラなどで頻出
- ループと組み合わせるときは `let` を使う

クロージャは JavaScript のあらゆる場面で顔を出す概念です。「なぜこの関数は終わったはずの変数を覚えているんだろう？」と思ったら、ほぼクロージャだと思って間違いありません。
