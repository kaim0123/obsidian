# 環境判定

## 環境判定とは

JavaScript は **ブラウザ、Node.js、Deno、Bun、Web Worker、Cloudflare Workers、Electron** など、さまざまな環境で動きます。それぞれで使える API が違うため、「今どこで動いているか」を判定して分岐するコードが必要になることがあります。

ここでは代表的な判定方法と、その落とし穴を紹介します。

## ブラウザかどうか

```js
if (typeof window !== "undefined") {
  // ブラウザ環境
}
```

`window` が存在すればブラウザ（あるいはブラウザっぽい環境）。

あるいは `document`：

```js
if (typeof document !== "undefined") {
  // DOM が使える
}
```

### typeof を使う理由

宣言されていない変数を直接参照すると `ReferenceError` になります。`typeof` なら未宣言でも安全。

```js
console.log(window); // ReferenceError（Node.js）
typeof window;       // "undefined"（エラーにならない）
```

## Node.js かどうか

```js
if (typeof process !== "undefined" && process.versions?.node) {
  // Node.js 環境
}
```

`process.versions.node` は Node.js のバージョン文字列が入っていて、ブラウザには無い。

### process だけだと不十分？

Electron、Bun、一部のポリフィルでは `process` が存在する場合があります。より正確には `process.versions.node` を見る。

## Web Worker かどうか

```js
if (typeof self !== "undefined" && typeof window === "undefined") {
  // Worker（Web Worker / Service Worker）
}

if (typeof ServiceWorkerGlobalScope !== "undefined") {
  // Service Worker
}

if (typeof DedicatedWorkerGlobalScope !== "undefined") {
  // 専用 Worker
}
```

## Deno かどうか

```js
if (typeof Deno !== "undefined") {
  // Deno
}
```

## Bun かどうか

```js
if (typeof Bun !== "undefined") {
  // Bun
}
```

## Electron かどうか

```js
if (typeof process !== "undefined" && process.versions?.electron) {
  // Electron
}
```

## globalThis

環境を問わず「グローバルオブジェクト」を指す標準。ブラウザでは `window`、Node.js では `global`、Worker では `self` を指します。

```js
globalThis.foo = 1; // どの環境でも OK
```

環境依存のコードを書くときの統一窓口になります。

## SSR（サーバサイドレンダリング）対応

Next.js など SSR 環境では、同じコードが **サーバ側（Node.js）とクライアント側（ブラウザ）** の両方で動きます。ブラウザ API を使う処理は分岐が必要。

```js
// Next.js のコンポーネント内
if (typeof window !== "undefined") {
  // クライアント側でのみ実行
  const saved = localStorage.getItem("theme");
}
```

あるいは `useEffect` / `onMounted` の中だけに書く。

```jsx
useEffect(() => {
  const saved = localStorage.getItem("theme");
  // ...
}, []);
```

`useEffect` はクライアントでのみ実行されるので、分岐不要。

## ユーザーエージェント判定（非推奨）

```js
const ua = navigator.userAgent;
if (/Mobile/i.test(ua)) {
  // モバイル
}
if (/Chrome/i.test(ua)) {
  // Chrome 系
}
```

**注意**：ユーザエージェントは簡単に偽装できるし、新機能検出には向きません。「ブラウザ機能があるか」で判定するのが現代の主流（**機能検出**）。

```js
// UA より「機能があるか」で判定するのが◎
if ("IntersectionObserver" in window) {
  // IntersectionObserver が使える
}

if ("serviceWorker" in navigator) {
  // Service Worker が使える
}
```

## モバイル判定

厳密には困難ですが、近似的に：

```js
// タッチデバイスか
const isTouch = "ontouchstart" in window || navigator.maxTouchPoints > 0;

// 画面幅でモバイルか判定
const isMobile = window.matchMedia("(max-width: 640px)").matches;

// 現代的：User-Agent Client Hints（Chromium 系）
navigator.userAgentData?.mobile; // true / false
```

## OS 判定

```js
const platform = navigator.userAgentData?.platform ?? navigator.platform;
if (/Mac/i.test(platform)) {
  // macOS
}
if (/Win/i.test(platform)) {
  // Windows
}
```

## ブラウザの機能検出（Feature Detection）

特定の機能があるかを調べる。**これが最も安全で推奨される方法**。

```js
// CSS のサポート
if (CSS.supports("display", "grid")) { ... }

// API の存在
if ("fetch" in window) { ... }
if ("crypto" in window && crypto.subtle) { ... }

// DOM 機能
if ("dialog" in document.createElement("dialog")) { ... }
```

## 環境変数

Node.js では `process.env` で環境変数を読めます。

```js
if (process.env.NODE_ENV === "production") {
  // 本番環境
}
```

ブラウザ側では、ビルドツール（Vite/webpack）が `import.meta.env` や `process.env` をコード置換で提供します。

```js
// Vite
if (import.meta.env.PROD) { ... }
if (import.meta.env.DEV) { ... }
```

## まとめ（実装テンプレ）

```js
export const isBrowser = typeof window !== "undefined";
export const isNode = typeof process !== "undefined" && !!process.versions?.node;
export const isDeno = typeof Deno !== "undefined";
export const isBun = typeof Bun !== "undefined";
export const isWorker = typeof self !== "undefined" && typeof window === "undefined";
export const isServiceWorker = typeof ServiceWorkerGlobalScope !== "undefined";
```

## 落とし穴

### 1. 早い段階で判定するとバグる

モジュール読み込み時に判定するより、**使う直前に判定** のほうが安全。SSR 時に `window` 参照でクラッシュしがち。

### 2. typeof を忘れる

```js
if (window) { ... }         // Node では ReferenceError
if (typeof window !== "undefined") { ... } // 安全
```

### 3. process が「偽装」されている

ポリフィルで `process` を定義するブラウザ環境もある。厳密には `process.versions?.node` で確認。

### 4. UA 判定に頼らない

機能検出に移行するのが現代の定石。「IE なら〜」のような UA 分岐は寿命が短い。

## まとめ

- 基本は `typeof global変数 !== "undefined"` で判定
- どの環境にいるかよりも、**必要な機能があるか** を調べる方が健全
- SSR では「window は使う直前に判定」または useEffect の中で
- 「環境別コード」は抽象化して1カ所に集める（`isBrowser` などの定数）

環境依存のバグは「デバッグしづらい」種類の代表格なので、最初から環境判定のユーティリティを作っておくと開発が楽になります。
