# 日付フォーマット

## なぜ難しいか

日付は単に「年月日を並べる」だけなら簡単ですが、次の要素が絡むと一気に複雑になります。

- **ゼロ埋め**（`2026-4-3` ではなく `2026-04-03`）
- **タイムゾーン**（UTC か JST か）
- **ロケール**（日本語、英語、`4月22日` vs `April 22`）
- **祝日・曜日**（和風の「水曜日」）

ここでは代表的なパターンをまとめます。

## 方法1：自作（最小限）

シンプルな `YYYY-MM-DD` なら自前が速い。

```js
function formatDate(d) {
  const y = d.getFullYear();
  const m = String(d.getMonth() + 1).padStart(2, "0");
  const day = String(d.getDate()).padStart(2, "0");
  return `${y}-${m}-${day}`;
}

formatDate(new Date()); // "2026-04-22"
```

時刻込み：

```js
function formatDateTime(d) {
  const pad = (n) => String(n).padStart(2, "0");
  const y = d.getFullYear();
  const m = pad(d.getMonth() + 1);
  const day = pad(d.getDate());
  const h = pad(d.getHours());
  const min = pad(d.getMinutes());
  const s = pad(d.getSeconds());
  return `${y}-${m}-${day} ${h}:${min}:${s}`;
}
```

覚えることは `padStart("0")` と `getMonth() + 1` の2点。

## 方法2：toLocaleDateString / toLocaleString

ブラウザ・Node.js 標準の変換関数。ロケールを指定できます。

```js
const d = new Date();
d.toLocaleDateString("ja-JP"); // "2026/4/22"
d.toLocaleDateString("en-US"); // "4/22/2026"
d.toLocaleTimeString("ja-JP"); // "10:30:00"
d.toLocaleString("ja-JP");     // "2026/4/22 10:30:00"
```

シンプルですがカスタマイズの幅は限定的。

## 方法3：Intl.DateTimeFormat（推奨）

柔軟にフォーマットできる標準 API。

```js
const fmt = new Intl.DateTimeFormat("ja-JP", {
  year: "numeric",
  month: "2-digit",
  day: "2-digit",
  weekday: "short",
  hour: "2-digit",
  minute: "2-digit",
});

fmt.format(new Date()); // "2026/04/22(水) 10:30"
```

### 主なオプション

| オプション | 値の例 |
|---|---|
| year | "numeric", "2-digit" |
| month | "numeric", "2-digit", "long", "short", "narrow" |
| day | "numeric", "2-digit" |
| weekday | "long", "short", "narrow" |
| hour / minute / second | "numeric", "2-digit" |
| hour12 | true / false |
| timeZone | "Asia/Tokyo", "UTC" など |
| timeZoneName | "short", "long" |

### 例：和風

```js
new Intl.DateTimeFormat("ja-JP-u-ca-japanese", {
  era: "long",
  year: "numeric",
  month: "long",
  day: "numeric",
}).format(new Date());
// "令和8年4月22日"
```

### 例：相対時間（Intl.RelativeTimeFormat）

```js
const rtf = new Intl.RelativeTimeFormat("ja-JP", { numeric: "auto" });
rtf.format(-1, "day");  // "昨日"
rtf.format(3, "hour");  // "3時間後"
```

「5分前」などの表示に便利。

## 方法4：toISOString（API 通信向け）

サーバとのやり取りには ISO 8601 形式（UTC）。

```js
new Date().toISOString();
// "2026-04-22T01:30:00.000Z"
```

- 末尾の `Z` は UTC
- サーバ・DB にはこれを送るのが国際標準
- 表示には向かない（ユーザ向けには変換が必要）

## 方法5：ライブラリ

手軽に色々な書式を扱えるのはやはりライブラリ。

### dayjs（軽量・推奨）

```js
import dayjs from "dayjs";
dayjs().format("YYYY-MM-DD HH:mm:ss");      // "2026-04-22 10:30:00"
dayjs().format("YYYY年MM月DD日(dd)");        // "2026年04月22日(水)"
dayjs("2026-04-22").add(7, "day").format(); // 1週間後
```

約 2KB で moment.js 相当の書きやすさ。

### date-fns（関数ベース）

```js
import { format, addDays } from "date-fns";
format(new Date(), "yyyy-MM-dd"); // "2026-04-22"
format(new Date(), "yyyy/MM/dd (EEE)", { locale: ja }); // "2026/04/22 (水)"
```

必要な関数だけ import できるのでバンドルサイズに優しい。

### luxon

タイムゾーン操作が強力。

## フォーマット記号（ライブラリでよくあるパターン）

| 記号 | 意味 |
|---|---|
| YYYY / yyyy | 4桁の年 |
| MM | 月（01-12） |
| M | 月（1-12） |
| DD / dd | 日（01-31） |
| HH | 時（00-23、24時間制） |
| hh | 時（01-12、12時間制） |
| mm | 分 |
| ss | 秒 |
| dddd / EEEE | 曜日フル（"水曜日"） |
| ddd / EEE | 曜日短（"水"） |
| A / a | AM/PM |

**注意**：moment.js/dayjs では `YYYY`、date-fns では `yyyy` など、ライブラリによって記号が違います。ドキュメント確認必須。

## よくある落とし穴

### 1. 月は0始まり

```js
new Date(2026, 4, 1); // 5月1日（4月ではない）
```

`getMonth()` も0始まり。手動フォーマット時は `+1` を忘れずに。

### 2. タイムゾーンが違う表示

```js
new Date("2026-04-22").getHours();
// UTC 00:00 を JST で解釈 → 9（サーバと見え方が違うことがある）
```

サーバとブラウザで時差が出ることに注意。API では ISO 形式（UTC）で送受信、表示時にローカル変換が鉄則。

### 3. 曜日の配列を回す

`getDay()` は 0=日, 1=月, ..., 6=土 の数値。配列で対応表を作ると便利。

```js
const jpWeek = ["日", "月", "火", "水", "木", "金", "土"];
jpWeek[new Date().getDay()]; // "水"
```

### 4. フォーマット毎に Intl インスタンスを作らない

`Intl.DateTimeFormat` はインスタンス生成が重め。何度も使うなら変数に保持。

```js
const fmt = new Intl.DateTimeFormat("ja-JP", { ... });
for (const d of dates) {
  console.log(fmt.format(d));
}
```

## まとめ

- 簡単な `YYYY-MM-DD` は **自作** で十分
- ロケール対応の表示は **Intl.DateTimeFormat** が標準で強力
- API 通信は **toISOString**（UTC）
- 書式の多様性・計算が多いなら **dayjs / date-fns**
- 月0始まり・タイムゾーン・ロケール差に注意

日付フォーマットは「小さいが毎回迷う」テーマ。この記事のパターンさえ覚えれば、必要なときに引き出せるようになります。詳しい基礎は [[Date]] を参照。
