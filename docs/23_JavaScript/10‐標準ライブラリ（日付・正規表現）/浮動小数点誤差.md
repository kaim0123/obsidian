# 浮動小数点誤差

## 最も有名な例

```js
0.1 + 0.2;             // 0.30000000000000004
0.1 + 0.2 === 0.3;     // false !!
```

初めて見ると「JavaScript はおかしい」と思いますが、これは JavaScript だけの問題ではなく、多くの言語で発生する **IEEE 754 浮動小数点数** の仕様です。Python でも Java でも同様に起こります。

## なぜ起こるのか

コンピュータは数値を **2進数** で表現します。

- `0.5` は2進数で `0.1`（ぴったり）
- `0.25` は `0.01`
- `0.1` は2進数で **循環小数**（`0.0001100110011...` と無限に続く）

しかし、コンピュータは有限のビット数（64ビット）しか使えないため、どこかで **切り捨て** が発生します。その結果、僅かな誤差が生まれます。

これは10進数で「`1 ÷ 3 = 0.333…`」をどこかで打ち切らなきゃいけないのと同じ話です。

## 影響する演算

```js
0.1 + 0.2;              // 0.30000000000000004
0.3 - 0.1;              // 0.19999999999999998
1.005 * 100;            // 100.49999999999999
Math.round(1.005 * 100); // 100（101 にならない）
```

通貨計算、数学処理、合計の表示などで見慣れない端数が現れる原因です。

## 整数でも安全な範囲がある

整数は `Number.MAX_SAFE_INTEGER`（`2^53 - 1 = 9007199254740991`）までなら正確に表せます。

```js
Number.MAX_SAFE_INTEGER;         // 9007199254740991
9007199254740992 === 9007199254740993; // true！（区別できない）
```

巨大な ID などを扱うときは BigInt か文字列を使う必要があります。

## 対処パターン

### 1. toFixed で表示だけ整える

表示用ならこれで十分。

```js
(0.1 + 0.2).toFixed(2); // "0.30"（文字列）
Number((0.1 + 0.2).toFixed(2)); // 0.3（数値）
```

ただし `toFixed` は文字列を返すので、計算に使うときは再度 Number 変換が必要。

### 2. 整数に変換して計算

金額処理などで鉄則。「円単位ではなくサン単位で計算」するイメージ。

```js
// NG
const total = price * tax;

// OK（セント/サン単位）
const totalCents = Math.round(price * 100 * tax);
const totalYen = totalCents / 100;
```

通貨は「最小単位（1円 or 1銭）で持ち、表示時に割る」が定石。

### 3. 近似比較（Number.EPSILON）

「ほぼ同じ」を許容する比較。

```js
const nearlyEqual = (a, b, eps = Number.EPSILON) => Math.abs(a - b) < eps;
nearlyEqual(0.1 + 0.2, 0.3); // true
```

科学計算や位置計算などに。

### 4. 専用ライブラリ

- **decimal.js** … 任意精度の10進演算
- **big.js** … 軽量
- **bignumber.js** … 高機能

金融・会計システムで誤差が許されないなら、これらを使います。

```js
import Decimal from "decimal.js";
new Decimal(0.1).plus(0.2).toString(); // "0.3"
```

## 具体的な落とし穴

### 合計がズレる

```js
const items = [0.1, 0.2, 0.3];
const total = items.reduce((a, b) => a + b, 0); // 0.6000000000000001
```

### 配列のインデックス計算

```js
const idx = 0.1 * 10; // 1 になるはずが…
arr[idx]; // 常識的には arr[1] だが、厳密には 1.0000000000000002 の場合も
```

JavaScript では配列アクセスの際に整数化されるため、ほとんど問題になりませんが、正確性が必要なら `Math.round(idx)` を挟むのが安全。

### Math.round の罠

```js
Math.round(0.5);  // 1
Math.round(1.5);  // 2
Math.round(-0.5); // 0（-1 ではない）
Math.round(-1.5); // -1（-2 ではない）
```

銀行家丸め（偶数丸め）ではないので、用途によっては自前で書き直す。

## 比較の誤り

```js
if (price * tax === expected) { ... } // 誤差でfalseになるかも
```

必ず「許容誤差内で一致」を使う。

```js
if (Math.abs(price * tax - expected) < 0.001) { ... }
```

## まとめ

- JavaScript の数値は IEEE 754 倍精度浮動小数点 → **誤差が必ずある**
- `0.1 + 0.2 !== 0.3` は言語仕様としての正しい挙動
- 対処：
  - 表示は `toFixed`
  - 計算は整数化（セント/サン単位）
  - 比較は `Math.abs(a - b) < ε`
  - 正確性が必要なら decimal.js など
- 安全な整数は `Number.MAX_SAFE_INTEGER` まで

お金と数値を扱うときには、必ず意識するべきトピックです。「0.30000000000000004」を見て焦らなくなったら、JavaScript の初級は卒業したと言えるでしょう。
