# デバウンス（Debounce）とスロットル（Throttle）

## 何のために使うか

ユーザの操作（キー入力、スクロール、リサイズ、マウスムーブなど）は **短時間で大量にイベントを発火** します。例えば検索ボックスで「JavaScript」と打つと、10回くらい `input` イベントが飛ぶので、毎回サーバに問い合わせると負荷が大きすぎます。

これを抑えるテクニックが **デバウンス** と **スロットル** です。

## デバウンス（Debounce）とは

「一定時間入力が止まってから1回だけ実行する」

```
入力： ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁
     ▲▲▲▲     ▲    ▲▲
イベント発火  発火  発火

デバウンス（500ms）：
       ───500ms→実行
              ───500ms→実行
                      ───500ms→実行（最後のだけ）
```

連続入力中は待機し、静かになったら最後の状態で1回実行。

### 典型的な用途

- 検索サジェスト（打ち終わってから検索）
- フォームの自動保存
- リサイズ完了後のレイアウト再計算

## スロットル（Throttle）とは

「一定時間に最大1回だけ実行する」（間引く）

```
入力： ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁
     ▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲

スロットル（500ms）：
     ▲─────500ms─────▲─────500ms─────▲
     実行            実行            実行
```

定期的にコンスタントに実行。

### 典型的な用途

- スクロール連動の表示更新（無限スクロール、ヘッダの表示切替）
- マウスムーブによる位置更新
- ウィンドウリサイズで毎秒数回だけ計算したい

## 違いを一言で

- **デバウンス** = 「連続して呼ばれたら最後の1回だけ実行」
- **スロットル** = 「一定間隔で実行」

検索の確定を待つのはデバウンス、スクロール追従はスロットル、という使い分け。

## デバウンスの実装

```js
function debounce(fn, delay = 300) {
  let timerId;
  return function (...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn.apply(this, args), delay);
  };
}
```

### 使い方

```js
const handleSearch = debounce((keyword) => {
  console.log("検索:", keyword);
  fetch(`/api/search?q=${encodeURIComponent(keyword)}`);
}, 500);

input.addEventListener("input", (e) => handleSearch(e.target.value));
```

### キャンセル対応版

```js
function debounce(fn, delay = 300) {
  let timerId;

  const debounced = (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delay);
  };

  debounced.cancel = () => clearTimeout(timerId);
  return debounced;
}
```

ページ遷移時にキャンセルできます。

## スロットルの実装

```js
function throttle(fn, limit = 300) {
  let inThrottle = false;
  return function (...args) {
    if (inThrottle) return;
    fn.apply(this, args);
    inThrottle = true;
    setTimeout(() => (inThrottle = false), limit);
  };
}
```

### 使い方

```js
const handleScroll = throttle(() => {
  console.log("scrollY:", window.scrollY);
}, 200);

window.addEventListener("scroll", handleScroll);
```

### 末尾も実行する版（trailing）

上の実装だと最後の呼び出しが捨てられる場合がある。末尾も確実に拾いたいなら：

```js
function throttle(fn, limit = 300) {
  let last = 0;
  let timer;
  return function (...args) {
    const now = Date.now();
    const remaining = limit - (now - last);
    if (remaining <= 0) {
      last = now;
      fn.apply(this, args);
    } else {
      clearTimeout(timer);
      timer = setTimeout(() => {
        last = Date.now();
        fn.apply(this, args);
      }, remaining);
    }
  };
}
```

## requestAnimationFrame 版（スロットルの代替）

スクロール・アニメーション系には RAF を使うと滑らかで負荷が低い。

```js
function rafThrottle(fn) {
  let scheduled = false;
  return function (...args) {
    if (scheduled) return;
    scheduled = true;
    requestAnimationFrame(() => {
      fn(...args);
      scheduled = false;
    });
  };
}

window.addEventListener("scroll", rafThrottle(() => {
  // 60fps で実行される
}));
```

ブラウザの描画タイミングに合わせてくれます。

## ライブラリを使う

実戦では lodash などを使うことも多い。

```js
import debounce from "lodash.debounce";
import throttle from "lodash.throttle";

const onSearch = debounce(search, 300);
const onScroll = throttle(updatePosition, 100);
```

`leading` / `trailing` オプションで最初と最後の挙動を調整できます。

## React での注意点

関数コンポーネント内で `debounce` を直接呼ぶと、レンダリングごとに新しい関数が作られて効かなくなります。

```jsx
// NG
function SearchBox() {
  const handle = debounce((v) => fetch(`/q=${v}`), 300);
  // レンダリング毎に新しい debounce が作られる
  return <input onChange={(e) => handle(e.target.value)} />;
}

// OK（useMemo で固定）
function SearchBox() {
  const handle = useMemo(() => debounce((v) => fetch(`/q=${v}`), 300), []);
  useEffect(() => () => handle.cancel(), [handle]);
  return <input onChange={(e) => handle(e.target.value)} />;
}
```

`useMemo` や `useRef` で関数をメモ化し、アンマウント時にキャンセルします。

## 間違えやすい選び方

| 状況 | 選ぶべき |
|---|---|
| 入力が落ち着いたら処理したい | デバウンス |
| 入力中も定期的に反応したい | スロットル |
| アニメーション系（スクロール追従、ドラッグ） | rAF or スロットル |
| 「オートセーブ」 | デバウンス |
| 「位置の追従」「進捗表示」 | スロットル |

## まとめ

- **デバウンス**：最後の入力から一定時間待ってから実行
- **スロットル**：一定間隔ごとに最大1回だけ実行
- 検索・保存はデバウンス、スクロール・リサイズはスロットル
- `requestAnimationFrame` はアニメ系に最適
- React では `useMemo` / `useRef` で関数を固定し、アンマウントで cancel

これらは「性能を出す小技」ではなく、「ユーザ体験を整える基本」の1つ。使いこなせるとイベント周りの設計が楽になります。
