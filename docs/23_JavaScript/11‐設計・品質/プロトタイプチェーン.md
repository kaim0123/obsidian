# プロトタイプチェーン（Prototype Chain）

## プロトタイプチェーンとは

JavaScript のオブジェクトには、「親オブジェクト」を指す内部リンクがあります。このリンクを **プロトタイプ（prototype）** と呼びます。

オブジェクトのプロパティやメソッドを呼び出したとき、JavaScript は次の手順で探します。

1. まず自分自身のプロパティを見る
2. 見つからなければ親（プロトタイプ）を見る
3. それでも見つからなければ、親の親を見る
4. 最後まで見つからなければ `undefined` を返す

この「自分 → 親 → 親の親 → … → null」という連なりを **プロトタイプチェーン** といいます。

他の言語のクラス継承に似ていますが、JavaScript では「オブジェクトがオブジェクトを継承する」という形で動いています。

## 具体例でイメージする

```js
const animal = {
  eat() {
    console.log("食べる");
  },
};

const dog = {
  bark() {
    console.log("ワンワン");
  },
};

// dog の親（プロトタイプ）を animal にする
Object.setPrototypeOf(dog, animal);

dog.bark(); // "ワンワン"（dog 自身のメソッド）
dog.eat();  // "食べる"（親の animal から借りている）
```

`dog` 自身に `eat` はありませんが、親の `animal` をたどって見つかるので呼び出せます。これがプロトタイプチェーンの動作です。

## プロトタイプを確認する方法

- `Object.getPrototypeOf(obj)` … `obj` の親を取得
- `Object.setPrototypeOf(obj, proto)` … 親をセット（使いすぎると遅い）
- `obj.__proto__` … 非推奨だがよく見る書き方

```js
const arr = [1, 2, 3];
console.log(Object.getPrototypeOf(arr) === Array.prototype); // true
console.log(Object.getPrototypeOf(Array.prototype) === Object.prototype); // true
console.log(Object.getPrototypeOf(Object.prototype)); // null（チェーンの終点）
```

配列の `arr` の親は `Array.prototype`、その親は `Object.prototype`、その親は `null`。これで `arr.toString()` のようなメソッドが、`Array.prototype` や `Object.prototype` から借りられる仕組みが見えてきます。

## なぜ配列に map や push があるのか

普段書く `[1, 2, 3].map(x => x * 2)` の `map` はどこから来るのでしょうか。答えは `Array.prototype.map` です。

すべての配列は `Array.prototype` を親に持つので、`map`, `filter`, `push`, `forEach` などが自動的に使えるのです。自分で `map` を定義したわけではないのに使えるのは、プロトタイプチェーンのおかげです。

```js
const arr = [1, 2, 3];
console.log(arr.map === Array.prototype.map); // true
```

## コンストラクタ関数とプロトタイプ

従来の JavaScript では、プロトタイプチェーンはコンストラクタ関数で作られていました。

```js
function Person(name) {
  this.name = name;
}

Person.prototype.sayHello = function () {
  console.log(`こんにちは、${this.name}です`);
};

const taro = new Person("太郎");
taro.sayHello(); // "こんにちは、太郎です"
```

- `new Person("太郎")` で作られた `taro` の親は `Person.prototype`
- `Person.prototype` には `sayHello` が定義されている
- だから `taro.sayHello()` が呼べる

`class` 構文（ES2015〜）は内部的にはこの仕組みを使った「書きやすい皮」です。

```js
class Person {
  constructor(name) {
    this.name = name;
  }
  sayHello() {
    console.log(`こんにちは、${this.name}です`);
  }
}
```

こちらの書き方のほうがモダンで読みやすいですが、裏では同じプロトタイプチェーンが動いています。

## クラス継承もチェーンでできている

```js
class Animal {
  eat() { console.log("食べる"); }
}

class Dog extends Animal {
  bark() { console.log("ワンワン"); }
}

const pochi = new Dog();
pochi.bark(); // "ワンワン"
pochi.eat();  // "食べる"（Animal から継承）
```

ここでは `pochi → Dog.prototype → Animal.prototype → Object.prototype → null` というチェーンが作られています。`eat` を探すとき、`Dog.prototype` にはないので `Animal.prototype` まで登っていって見つけます。

## プロパティの「上書き」の動き

同じ名前のプロパティが自分と親の両方にある場合、**先に自分のものが優先** されます。これを「シャドーイング」と呼びます。

```js
const parent = { greet: "Hello" };
const child = Object.create(parent);
child.greet = "Hi";

console.log(child.greet);  // "Hi"（自身のもの）
console.log(parent.greet); // "Hello"（親は変わっていない）
```

`child.greet = "Hi"` は親の `greet` を書き換えているのではなく、「`child` 自身に `greet` を新しく作っている」のです。親はそのままです。

## hasOwnProperty：自分のものかチェックする

プロパティが「自分のもの」か「親から借りているもの」かを調べたいときに使います。

```js
const arr = [1, 2, 3];
console.log(arr.hasOwnProperty("length")); // true（自身のプロパティ）
console.log(arr.hasOwnProperty("map"));    // false（Array.prototype から）
```

モダンな書き方では `Object.hasOwn(arr, "map")` が推奨されます。

## よくある落とし穴

### 1. for...in はチェーンもなめる

```js
const parent = { a: 1 };
const child = Object.create(parent);
child.b = 2;

for (const key in child) {
  console.log(key); // "b", "a"（親の a も出てくる）
}
```

`for...in` はプロトタイプチェーン上のプロパティも列挙します。自分のものだけ見たいなら `Object.keys()` や `Object.hasOwn()` でフィルタします。

### 2. プロトタイプを書き換えるのは危険

`Array.prototype` に勝手にメソッドを追加する（いわゆる「モンキーパッチ」）と、全ての配列に影響が出ます。ライブラリ同士の衝突を起こすので、基本的にやめましょう。

### 3. Object.setPrototypeOf は遅い

実行中にプロトタイプを変えると、エンジンの最適化が壊れて性能が下がります。作成時に決めるのが原則です。

## まとめ

- プロトタイプ＝オブジェクトが持つ「親リンク」
- プロトタイプチェーン＝親をたどっていく連なり
- `map` や `toString` が自動で使えるのは、親が持っているから
- `class` も裏ではプロトタイプチェーンで動いている
- 普段は `class` で書けば OK。裏の仕組みを知っているとデバッグで役立つ

「なぜ配列に `.length` や `.map` があるんだろう？」という素朴な疑問の答えが、プロトタイプチェーンです。
