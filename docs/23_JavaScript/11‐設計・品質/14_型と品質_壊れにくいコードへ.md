## 14-1. Lint / Format（ESLint / Prettierの考え方）

### Lintとは

**コードの問題を自動で検出するツール**です。バグになりそうな書き方や、チームのルールに反する書き方を指摘してくれます。

### ESLint

JavaScriptの代表的なLintツール。

```bash
# インストール
npm install --save-dev eslint

# 設定ファイルを作成
npm init @eslint/config
```

```javascript
// eslint.config.js の例
import js from "@eslint/js";

export default [
  js.configs.recommended,
  {
    rules: {
      "no-unused-vars": "warn",     // 未使用の変数は警告
      "no-console": "off",          // console.logは許可
      "eqeqeq": "error",           // === を強制
      "no-var": "error",            // var を禁止
      "prefer-const": "warn",       // 再代入しないならconst
    },
  },
];
```

```bash
# 実行
npx eslint src/
npx eslint --fix src/  # 自動修正
```

### ESLint が検出する問題の例

```javascript
// ❌ 未使用の変数
let unused = "使われていない";  // warning: 'unused' is defined but never used

// ❌ == の使用
if (x == 0) { ... }  // error: Expected '===' and instead saw '=='

// ❌ 到達不能コード
function test() {
  return 1;
  console.log("ここには来ない");  // warning: Unreachable code
}
```

### Prettier

**コードの見た目を自動で統一するフォーマッター**です。インデント、改行、引用符などを統一してくれます。

```bash
npm install --save-dev prettier
```

```json
// .prettierrc
{
  "semi": true,
  "singleQuote": false,
  "tabWidth": 2,
  "trailingComma": "all",
  "printWidth": 80
}
```

```bash
npx prettier --write src/  # フォーマットを適用
```

### ESLint と Prettier の使い分け

```
ESLint    → コードの「品質」（バグ、ルール違反）
Prettier  → コードの「見た目」（インデント、改行）

両方使うのが一般的。
```

## 14-2. テスト入門（何をどうテストするか）

### なぜテストを書くのか

1. **バグを防ぐ**：コードを変更したとき、既存の機能が壊れていないか確認できる
2. **安心してリファクタリングできる**：テストがあれば、書き直しても動作を保証できる
3. **仕様書になる**：テストを読めば「何ができるか」がわかる

### テストの種類

```
ユニットテスト（単体テスト）
  → 関数1つ、クラス1つを個別にテスト
  → 最も基本的。まずはここから

インテグレーションテスト（結合テスト）
  → 複数のモジュールが正しく連携するかテスト
  → API + データベースの組み合わせなど

E2Eテスト（エンドツーエンド）
  → ユーザーの操作をシミュレートしてテスト
  → ブラウザを自動操作して画面を検証
```

### 何をテストすべきか

```
✅ テストすべきもの：
  - ビジネスロジック（計算、バリデーション、データ変換）
  - エッジケース（0、空文字、null、境界値）
  - エラーハンドリング（不正な入力に対する挙動）

❌ テストしなくていいもの：
  - 言語の機能そのもの（Array.map が動くかなど）
  - 外部ライブラリの内部動作
  - 定数の値
```

## 14-3. テストの書き方（関数テスト、DOMテストの入口）

### Node.js 組み込みテストランナー

Node.js 18以降は組み込みのテストランナーがあります。

```javascript
// math.js
export function add(a, b) {
  return a + b;
}

export function divide(a, b) {
  if (b === 0) throw new Error("0で割れません");
  return a / b;
}
```

```javascript
// math.test.js
import { describe, it } from "node:test";
import assert from "node:assert/strict";
import { add, divide } from "./math.js";

describe("add", () => {
  it("2つの正の数を足す", () => {
    assert.strictEqual(add(2, 3), 5);
  });

  it("負の数を足す", () => {
    assert.strictEqual(add(-1, 1), 0);
  });

  it("0を足す", () => {
    assert.strictEqual(add(5, 0), 5);
  });
});

describe("divide", () => {
  it("正常な割り算", () => {
    assert.strictEqual(divide(10, 2), 5);
  });

  it("0で割るとエラー", () => {
    assert.throws(
      () => divide(10, 0),
      { message: "0で割れません" }
    );
  });
});
```

```bash
node --test
```

### テストの構造：AAA パターン

```javascript
it("テストの説明", () => {
  // Arrange（準備）
  const input = [3, 1, 4, 1, 5];

  // Act（実行）
  const result = input.toSorted((a, b) => a - b);

  // Assert（検証）
  assert.deepStrictEqual(result, [1, 1, 3, 4, 5]);
});
```

### よく使うアサーション

```javascript
import assert from "node:assert/strict";

// 値が等しい
assert.strictEqual(result, expected);

// オブジェクト/配列の中身が等しい
assert.deepStrictEqual(result, expected);

// 真偽値
assert.ok(value);           // truthy であること
assert.ok(!value);          // falsy であること

// エラーが投げられる
assert.throws(() => dangerousFunction());
assert.throws(
  () => dangerousFunction(),
  { message: "期待するエラーメッセージ" }
);

// 非同期のエラー
await assert.rejects(
  async () => await fetchData("invalid"),
  { message: "Not Found" }
);
```

### テストのコツ

```javascript
// ✅ テスト名は「何をしたら、どうなるか」
it("空文字列を渡すとエラーになる", () => { ... });
it("ユーザーが存在しないときnullを返す", () => { ... });

// ✅ 1つのテストで1つのことだけ検証する
// ❌ 複数のことを1つのテストで検証
it("いろいろテスト", () => {
  assert.strictEqual(add(1, 2), 3);
  assert.strictEqual(subtract(5, 3), 2);
  assert.throws(() => divide(1, 0));
});

// ✅ それぞれ別のテストにする
it("add: 1+2=3", () => {
  assert.strictEqual(add(1, 2), 3);
});
it("subtract: 5-3=2", () => {
  assert.strictEqual(subtract(5, 3), 2);
});
```

## 14-4. 例外とエラー設計（エラーの型、メッセージ）

### エラーの種類を使い分ける

```javascript
// 組み込みエラー型
throw new Error("一般的なエラー");
throw new TypeError("型が不正です");
throw new RangeError("値が範囲外です");
throw new SyntaxError("構文が不正です");
```

### カスタムエラー

```javascript
class ValidationError extends Error {
  constructor(field, message) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

class NotFoundError extends Error {
  constructor(resource, id) {
    super(`${resource}（ID: ${id}）が見つかりません`);
    this.name = "NotFoundError";
    this.resource = resource;
    this.id = id;
  }
}

// 使い方
function findUser(id) {
  const user = database.get(id);
  if (!user) {
    throw new NotFoundError("User", id);
  }
  return user;
}

try {
  const user = findUser(999);
} catch (error) {
  if (error instanceof NotFoundError) {
    console.log(`${error.resource}が見つかりませんでした`);
  } else {
    throw error;  // 想定外のエラーは再throw
  }
}
```

### エラーメッセージの書き方

```javascript
// ❌ 曖昧なメッセージ
throw new Error("エラー");
throw new Error("失敗しました");

// ✅ 具体的なメッセージ
throw new Error("ユーザー名は1〜20文字で入力してください");
throw new Error(`APIリクエスト失敗: ${response.status} ${url}`);
throw new TypeError(`expected string, got ${typeof value}`);
```

### エラーハンドリングの設計原則

```javascript
// 1. 回復可能なエラーは catch して処理する
try {
  const data = await fetchData();
} catch (error) {
  showErrorMessage("データの取得に失敗しました");
  return defaultData;
}

// 2. 回復不能なエラーはそのまま投げる（握りつぶさない）
// ❌
try {
  criticalOperation();
} catch (error) {
  // 何もしない（エラーが握りつぶされる！）
}

// ✅
try {
  criticalOperation();
} catch (error) {
  logger.error(error);
  throw error;  // 再throw
}

// 3. catch したら必ず何かする（ログ、通知、デフォルト値）
```

## よくある間違い

```javascript
// ❌ catch で何もしない（サイレントエラー）
try {
  JSON.parse(invalidJson);
} catch (e) { }  // エラーが完全に無視される

// ❌ すべてのエラーを同じように処理する
try {
  await fetchAndProcess();
} catch (error) {
  console.log("エラー");  // ネットワークエラー？バグ？区別できない
}

// ❌ テストを書かずにリファクタリングする
// → 壊れたことに気づけない

// ❌ テストで実装の詳細をテストする
it("内部のcounterが3になる", () => {
  // 内部実装が変わると壊れる
});
// ✅ 振る舞いをテストする
it("3回呼ぶと結果が3になる", () => { ... });
```

---

## 重要ポイント

1. **ESLint** でコードの問題を自動検出、**Prettier** で見た目を統一
2. テストは **AAA パターン**（Arrange → Act → Assert）で書く
3. **1テスト1検証**。テスト名は「何をしたらどうなるか」
4. カスタムエラーで**エラーの種類を区別**できるようにする
5. エラーは**握りつぶさない**。catchしたら必ず何か対処する
6. テストは**振る舞い**をテストし、実装の詳細はテストしない

## ミニ課題

**「テスト付き文字列ユーティリティ」を作ろう**

以下の関数を実装し、それぞれにテストを書こう：

```javascript
// 1. 文字列を逆順にする
reverseString("hello")  // → "olleh"

// 2. パスカルケースに変換
toPascalCase("hello world")  // → "HelloWorld"
toPascalCase("foo-bar-baz")  // → "FooBarBaz"

// 3. 文字列が回文かどうか判定
isPalindrome("racecar")  // → true
isPalindrome("hello")    // → false
```
