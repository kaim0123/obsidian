# エラーハンドリング

## なぜ大事か

プログラムは必ず失敗します。ネットワークが切れる、ファイルが無い、ユーザが変な値を入れる、想定外のデータが返ってくる…これら全てを無視すると、アプリはユーザに謎のエラーを見せるか、サイレントに壊れます。

**良いエラーハンドリング**とは「想定外が起きたときに、適切な場所で検知し、適切なリカバリや通知を行う」ことです。ここでは JavaScript で使われる主要なテクニックをまとめます。

## try / catch / finally

同期コードのエラーを捕まえる基本。

```js
try {
  doSomething();
} catch (err) {
  console.error(err);
} finally {
  cleanup(); // 成功失敗関係なく実行
}
```

### Error オブジェクト

```js
throw new Error("何かがおかしい");
throw new TypeError("型が違う");
throw new RangeError("範囲外");
```

Error には `message`, `stack`, `name` が入っています。

```js
try {
  throw new Error("test");
} catch (e) {
  console.log(e.message); // "test"
  console.log(e.name);    // "Error"
  console.log(e.stack);   // スタックトレース
}
```

### カスタムエラー

```js
class AppError extends Error {
  constructor(message, code) {
    super(message);
    this.name = "AppError";
    this.code = code;
  }
}

throw new AppError("ユーザが見つかりません", "USER_NOT_FOUND");
```

業務エラーとシステムエラーを分けたいときに便利。

### catch の引数を省略できる（ES2019〜）

エラー内容を使わないなら省略可。

```js
try {
  JSON.parse(str);
} catch {
  return null;
}
```

## 非同期のエラーハンドリング

### async / await + try/catch

```js
async function run() {
  try {
    const data = await fetch("/api").then((r) => r.json());
    return data;
  } catch (err) {
    console.error(err);
    return null;
  }
}
```

### Promise チェーンの .catch

```js
fetchData()
  .then((data) => process(data))
  .catch((err) => console.error(err))
  .finally(() => hideLoader());
```

### Promise.all は1つでも失敗すると全部キャンセル

```js
try {
  const [a, b] = await Promise.all([fa(), fb()]);
} catch (err) {
  // どれか失敗
}
```

個別の成否が知りたいなら `allSettled`。

```js
const results = await Promise.allSettled([fa(), fb()]);
results.forEach((r) => {
  if (r.status === "fulfilled") console.log(r.value);
  else console.error(r.reason);
});
```

## fetch のエラーハンドリング（重要）

`fetch` は **HTTP エラー（404, 500）では reject しません**。ネットワーク失敗時のみ reject。

```js
async function getUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) {
    throw new Error(`HTTP ${res.status}`);
  }
  return res.json();
}
```

`res.ok` は 200〜299 のとき true。これを見ずに `res.json()` すると、エラー HTML をパースしようとしてバグります。

## イベント系のグローバルキャッチ

### ブラウザ

```js
window.addEventListener("error", (e) => {
  console.error("error:", e.error);
});

window.addEventListener("unhandledrejection", (e) => {
  console.error("promise rejection:", e.reason);
});
```

### Node.js

```js
process.on("uncaughtException", (err) => { ... });
process.on("unhandledRejection", (reason) => { ... });
```

最後の砦として、ログ送信や再起動などに使います。

## リトライ（再試行）

一時的な失敗は再挑戦で回復することがあります。

```js
async function retry(fn, times = 3, delay = 500) {
  for (let i = 0; i < times; i++) {
    try {
      return await fn();
    } catch (err) {
      if (i === times - 1) throw err;
      await new Promise((r) => setTimeout(r, delay * 2 ** i)); // 指数バックオフ
    }
  }
}

const user = await retry(() => fetchUser(1));
```

ただし「何度も失敗するなら諦める」こと、また「冪等（何度実行しても副作用が同じ）」な処理に限ること。

## タイムアウト

時間がかかりすぎたらキャンセル。

```js
async function withTimeout(promise, ms) {
  return Promise.race([
    promise,
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error("timeout")), ms)
    ),
  ]);
}

await withTimeout(fetch(url), 3000);
```

`fetch` 自体は `AbortController` を使うのが正攻法。

```js
const ctrl = new AbortController();
const id = setTimeout(() => ctrl.abort(), 3000);

try {
  const res = await fetch(url, { signal: ctrl.signal });
} catch (e) {
  if (e.name === "AbortError") console.log("キャンセル");
} finally {
  clearTimeout(id);
}
```

## 入力バリデーション（早めに fail）

```js
function divide(a, b) {
  if (typeof a !== "number" || typeof b !== "number") {
    throw new TypeError("数値で渡してください");
  }
  if (b === 0) {
    throw new RangeError("0で割れません");
  }
  return a / b;
}
```

「おかしなデータが深い処理に入る前に捕まえる」のが鉄則。

## エラーを適切なレベルで処理する

よくあるミスは、**浅いところで catch してログだけ出して握りつぶす** こと。

```js
// NG：エラーを握りつぶして呼び出し元には成功と見せかける
async function getUser(id) {
  try {
    return await fetch(`/api/users/${id}`);
  } catch (err) {
    console.error(err);
    // 戻り値なし（undefined）
  }
}
```

これは「失敗したのに成功したかのような戻り値」になり、呼び出し元で余計な判定が必要に。

**「自分で対処できないなら、throw してより上に任せる」** のが原則。

```js
async function getUser(id) {
  try {
    return await fetch(`/api/users/${id}`);
  } catch (err) {
    logger.error(err);
    throw err; // 呼び出し元に伝える
  }
}
```

## エラーは種類で分ける

全部の例外を同じ catch に押し込めると、ユーザには「謎のエラー」しか届きません。

```js
try {
  await save(data);
} catch (err) {
  if (err instanceof ValidationError) {
    showMessage("入力に誤りがあります");
  } else if (err instanceof NetworkError) {
    showMessage("通信に失敗しました");
  } else {
    showMessage("予期せぬエラーが発生しました");
    logger.error(err);
  }
}
```

## result オブジェクトパターン（例外を使わない選択肢）

例外が発生しない API 設計を好む場面もあります。

```js
async function safeFetch(url) {
  try {
    const res = await fetch(url);
    return { ok: true, value: await res.json() };
  } catch (err) {
    return { ok: false, error: err };
  }
}

const result = await safeFetch("/api");
if (result.ok) {
  use(result.value);
} else {
  handle(result.error);
}
```

関数型のエラーハンドリング（`Result<T, E>`）スタイル。TypeScript の discriminated union と相性が良い。

## まとめ

- 同期は `try/catch/finally`、非同期は `await` + `try/catch`
- `fetch` は HTTP エラーで reject しない → `res.ok` を確認
- Promise.all の代わりに `allSettled` を検討
- リトライ、タイムアウト、AbortController はセットで覚える
- エラーは「握りつぶさず、適切な場所で対処する」
- 種類で分岐してユーザへの表示を変える

エラーハンドリングはコードの成熟度を測る指標です。成功パスだけでなく失敗パスも丁寧に書けるようになると、そのプロダクトは一段階上のクオリティになります。
