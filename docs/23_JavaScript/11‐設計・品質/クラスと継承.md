# クラスと継承（Class & Inheritance）

## クラスとは

**クラス（class）** は、「同じような構造を持ったオブジェクトをたくさん作るための設計図」です。たとえば「ユーザー」「商品」「車」など、属性（プロパティ）と振る舞い（メソッド）をまとめて定義しておくと、同じ形のオブジェクトをいくつでも生み出せます。

JavaScript では ES2015（ES6）から `class` 構文が追加され、他のオブジェクト指向言語に近い書き方ができるようになりました。ただし、裏側では [[プロトタイプチェーン]] という仕組みで動いているだけで、まったく新しい機能ではありません。

## 一番シンプルなクラス

```js
class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    console.log(`こんにちは、${this.name}です（${this.age}歳）`);
  }
}

const taro = new User("太郎", 20);
taro.greet(); // "こんにちは、太郎です（20歳）"
```

### 各要素の役割

- `class User { ... }` … クラスを定義
- `constructor` … `new` で生成されたとき最初に呼ばれる特別なメソッド。初期化処理を書く
- `this` … 生成中のインスタンス自身を指す
- `new User(...)` … インスタンス（個々のオブジェクト）を作る

## プロパティとメソッド

クラスの中で `this.xxx = ...` と書いたものが **プロパティ（インスタンスごとに持つデータ）** になります。
`class` の本体に書いた関数は **メソッド（共通の振る舞い）** となり、全インスタンスで共有されます。

```js
class Counter {
  constructor() {
    this.count = 0;        // プロパティ
  }
  increment() {            // メソッド
    this.count += 1;
  }
}

const c = new Counter();
c.increment();
c.increment();
console.log(c.count); // 2
```

## クラスフィールド（新しい書き方）

最新の JavaScript では `constructor` を使わずにフィールドを直接書けます。

```js
class Counter {
  count = 0; // クラスフィールド

  increment() {
    this.count += 1;
  }
}
```

短く書けるのでおすすめです。

## プライベートフィールド（#）

フィールド名の頭に `#` を付けると、クラスの外からアクセスできない「真のプライベート」になります。

```js
class BankAccount {
  #balance = 0; // 外から触れない

  deposit(amount) {
    this.#balance += amount;
  }
  getBalance() {
    return this.#balance;
  }
}

const acc = new BankAccount();
acc.deposit(1000);
console.log(acc.getBalance()); // 1000
// console.log(acc.#balance); // SyntaxError
```

内部状態を隠蔽したいときに便利です。

## 静的メソッド・静的プロパティ

`static` を付けたものは、**インスタンスではなくクラス自身** に属します。

```js
class MathUtil {
  static PI = 3.14159;
  static square(n) {
    return n * n;
  }
}

console.log(MathUtil.PI);        // 3.14159
console.log(MathUtil.square(5)); // 25
// new MathUtil().square(5) は呼べない
```

ユーティリティ的な処理や、インスタンスに関係ない定数を置く場所として使います。

## getter / setter

プロパティのように見せながら、裏で処理を挟めます。

```js
class Temperature {
  constructor(celsius) {
    this._celsius = celsius;
  }
  get fahrenheit() {
    return this._celsius * 9 / 5 + 32;
  }
  set fahrenheit(value) {
    this._celsius = (value - 32) * 5 / 9;
  }
}

const t = new Temperature(25);
console.log(t.fahrenheit); // 77（関数呼び出しに見えない）
t.fahrenheit = 100;
console.log(t._celsius);   // 37.77...
```

## 継承（extends）

あるクラスを土台にして、新しいクラスを作ることを **継承** といいます。

```js
class Animal {
  constructor(name) {
    this.name = name;
  }
  eat() {
    console.log(`${this.name}は食事をする`);
  }
}

class Dog extends Animal {
  bark() {
    console.log(`${this.name}：ワンワン`);
  }
}

const pochi = new Dog("ポチ");
pochi.eat();  // "ポチは食事をする"（Animalから継承）
pochi.bark(); // "ポチ：ワンワン"
```

`extends` で親クラスを指定すると、親のメソッド・プロパティをそのまま使えます。

### super：親の機能を呼ぶ

子のコンストラクタでは、`this` を使う前に必ず `super(...)` を呼ぶ必要があります。

```js
class Cat extends Animal {
  constructor(name, color) {
    super(name);        // 親のコンストラクタを呼ぶ
    this.color = color;
  }
  describe() {
    super.eat();        // 親のメソッドを呼ぶ
    console.log(`色：${this.color}`);
  }
}

const tama = new Cat("タマ", "黒");
tama.describe();
// "タマは食事をする"
// "色：黒"
```

### メソッドのオーバーライド

親と同名のメソッドを子で書くと、子のほうが使われます。

```js
class Bird extends Animal {
  eat() {
    console.log(`${this.name}は空中で食事をする`);
  }
}

new Bird("すずめ").eat(); // "すずめは空中で食事をする"
```

親のを呼びたい場合は `super.eat()`。

## instanceof で判定

オブジェクトがどのクラスから作られたかを調べられます。

```js
console.log(pochi instanceof Dog);    // true
console.log(pochi instanceof Animal); // true（親も OK）
```

## クラスを使うべきか、関数で十分か

以下のような場合にクラスは便利です。

- 同じ構造のオブジェクトを繰り返し作る
- 状態とそれを操作するメソッドをまとめたい
- 継承・多態を使って差分だけ変えたバリアントを作りたい

一方で、単に値をまとめるだけなら **プレーンなオブジェクト** で十分ですし、
1回しか作らないなら関数クロージャ（[[クロージャ]]）のほうがシンプルな場合もあります。

React などのフレームワークでは「クラスより関数コンポーネント」が主流になっているため、必ずクラスを使う必要はありません。TPO に応じて使い分けましょう。

## よくある落とし穴

### 1. this の束縛

クラスのメソッドを「そのまま渡す」と `this` を失います。

```js
class Logger {
  constructor() {
    this.prefix = "[LOG]";
  }
  print(msg) {
    console.log(this.prefix, msg);
  }
}

const logger = new Logger();
const fn = logger.print;
fn("test"); // TypeError: Cannot read properties of undefined
```

対策は以下のいずれか。

```js
// (a) アロー関数プロパティ
class Logger {
  prefix = "[LOG]";
  print = (msg) => console.log(this.prefix, msg);
}

// (b) bind
const fn = logger.print.bind(logger);
```

### 2. class は巻き上げされない

`var` で定義した関数と違い、class は **定義より前に使えません**。

```js
const u = new User(); // ReferenceError
class User {}
```

### 3. 継承を深くしすぎない

継承は便利ですが、3〜4段以上重ねると修正が波及して大変になります。「継承より合成（composition）」という考え方が近年の主流です。

## まとめ

- `class` は同じ形のオブジェクトを量産するための設計図
- `constructor` で初期化、`this` で自身を参照
- `extends` と `super` で継承・親機能の呼び出し
- `#` プライベート、`static`、`get`/`set` などの機能もある
- 裏側は [[プロトタイプチェーン]] で動いている
- 継承は深くしすぎず、必要な場面で使う
