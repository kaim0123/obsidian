# オブジェクトのディープコピー

## 浅いコピーと深いコピー

- **浅いコピー（shallow copy）** … 1階層だけコピー。ネストしたオブジェクトは共有
- **深いコピー（deep copy）** … 全階層を新しく作る

```js
const original = { a: 1, nested: { b: 2 } };

// 浅いコピー
const shallow = { ...original };
shallow.nested.b = 99;
console.log(original.nested.b); // 99（影響を受ける！）

// 深いコピー
const deep = structuredClone(original);
deep.nested.b = 99;
console.log(original.nested.b); // 2（影響なし）
```

ネストしたオブジェクトまで完全に独立させたいときは深いコピーが必要。

## 方法1：structuredClone（推奨・モダン）

Node.js 17+、モダンブラウザ、Cloudflare Workers などで使える **標準のディープコピー API**。

```js
const original = {
  name: "太郎",
  birthday: new Date("2000-01-01"),
  hobbies: ["読書", "散歩"],
  tags: new Set(["A", "B"]),
  profile: { age: 25 },
};

const deep = structuredClone(original);
```

### 長所

- ビルトインなので追加ライブラリ不要
- **Date, Map, Set, Array, RegExp, TypedArray, ArrayBuffer, 循環参照** に対応
- 速い

### 短所

- **関数・DOMノード・Symbol・class のインスタンス** は扱えない

```js
structuredClone(() => 1); // DataCloneError
structuredClone(document.body); // DataCloneError
```

class のインスタンスは「プロパティだけがコピーされ、プロトタイプは失われる」。

```js
class User { constructor(n) { this.name = n; } greet() {} }
const u = new User("太郎");
const c = structuredClone(u);
c instanceof User; // false
c.greet;           // undefined
```

## 方法2：JSON.parse + JSON.stringify

昔から使われる簡易な手法。

```js
const deep = JSON.parse(JSON.stringify(original));
```

### 長所

- 短く書ける
- どんな古い環境でも動く

### 短所

- **Date は文字列化される**（ISO 文字列、Date オブジェクトに戻らない）
- **undefined, 関数, Symbol は消える**
- **Map, Set は空オブジェクトになる**
- **循環参照でエラー**
- **NaN, Infinity は null に変換**
- 遅い（シリアライズ＋パース）

```js
JSON.parse(JSON.stringify({ d: new Date() })); // { d: "2026-04-22T..." }
JSON.parse(JSON.stringify({ fn: () => 1 }));   // {}
JSON.parse(JSON.stringify({ m: new Map() }));  // { m: {} }
```

単純なデータ（プレーンオブジェクト＋プリミティブ＋配列）なら問題なし。それ以外は `structuredClone` を。

## 方法3：スプレッド構文を手動で再帰

簡易な関数を自作。

```js
function deepClone(v) {
  if (v === null || typeof v !== "object") return v;
  if (Array.isArray(v)) return v.map(deepClone);
  return Object.fromEntries(
    Object.entries(v).map(([k, val]) => [k, deepClone(val)])
  );
}
```

最低限ならこれで十分。Date や Map には対応しません。

## 方法4：ライブラリ

### lodash.cloneDeep

```js
import cloneDeep from "lodash.cloneDeep";
const copy = cloneDeep(original);
```

- 長所：古くから安定、幅広い型に対応
- 短所：ファイルサイズ（単体 import でも数 KB）

### rfdc（Really Fast Deep Clone）

非常に軽く速い。循環参照対応オプションあり。

```js
import rfdc from "rfdc";
const clone = rfdc();
const copy = clone(original);
```

## どれを使うべきか

```
 Date/Map/Set/循環参照を含む？
 ├─ Yes → structuredClone（環境が対応してるなら）
 │         ↓ 対応してないなら
 │         lodash.cloneDeep / rfdc
 └─ No  → プレーンなオブジェクト・配列・プリミティブだけ？
           ├─ Yes → JSON.parse(JSON.stringify()) で十分
           └─ No  → structuredClone か自作
```

## class のインスタンスをコピーしたいときは？

ディープコピーではプロトタイプまで引き継がないので、class の機能が失われます。対策：

### 1. コピー用メソッドを持たせる

```js
class User {
  constructor(name) { this.name = name; }
  clone() {
    return new User(this.name);
  }
}
```

### 2. Object.assign + Object.create

```js
const c = Object.assign(Object.create(Object.getPrototypeOf(u)), u);
```

単純な場合はこれでプロトタイプも保持できます（ただし深くはコピーされない）。

## イミュータブル更新（コピーの代わり）

React などでよくあるパターン：一部だけ変えた新オブジェクトを作る。

```js
const newUser = { ...user, name: "次郎" };
const newArr = arr.map((x) => (x.id === 1 ? { ...x, active: true } : x));
```

これは「ディープコピー」ではなく「変えた部分だけ新しく作る」。不変性を保ちつつ最小限の変更ができる、React・Redux 時代の定石。

深い構造を楽に扱うには **Immer** が便利。

```js
import { produce } from "immer";

const next = produce(state, (draft) => {
  draft.user.profile.age = 30;
});
```

## 落とし穴

### 浅いコピーを深いと勘違い

```js
const copy = { ...original };
copy.list.push("x"); // original.list にも影響！
```

`...` はあくまで浅い。ネストがあるなら全部新しく作る必要あり。

### Date が文字列になる

```js
const copy = JSON.parse(JSON.stringify({ d: new Date() }));
copy.d.getTime(); // TypeError（d は文字列）
```

`structuredClone` なら Date のまま。

### 循環参照の罠

```js
const a = {};
a.self = a;
JSON.stringify(a); // TypeError
structuredClone(a); // OK！
```

## まとめ

- 浅いコピーは `{ ...obj }`（ネストは共有）
- 深いコピーは **`structuredClone`** が第一候補
- シンプルなデータなら `JSON.parse(JSON.stringify())` でも OK（Date 等に注意）
- class のインスタンスや関数は特別扱い必要
- React など「一部だけ変更」用途はイミュータブル更新 or Immer

「コピーしたつもりなのに元が変わってしまった」という事故の大半は、この深いコピー/浅いコピーの混同から起きます。
