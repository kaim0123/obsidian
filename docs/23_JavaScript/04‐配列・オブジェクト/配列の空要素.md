# 配列の空要素（sparse array）

## 空要素とは

JavaScript の配列は、値が入っていない「穴（hole）」を持つことができます。これを **スパース配列（sparse array）** または **空要素のある配列** と呼びます。

例：

```js
const arr = new Array(3);      // [ , , ]（要素が3つ、全部穴）
const arr2 = [1, , 3];         // [1, , 3]（真ん中が穴）
const arr3 = [];
arr3[5] = "x";                 // [ , , , , , "x" ]（穴5個＋値）

console.log(arr.length);  // 3
console.log(arr2.length); // 3
console.log(arr3.length); // 6
```

長さはある（`length` が増える）のに、中身は入っていない状態です。

## `undefined` との違い

「値が `undefined`」と「値がない（穴）」は別物です。

```js
const a = [1, , 3];        // 真ん中は穴
const b = [1, undefined, 3]; // 真ん中は undefined

a.length; // 3
b.length; // 3

a[1]; // undefined
b[1]; // undefined

0 in a; // true
1 in a; // false（穴だから）
1 in b; // true
```

`in` 演算子や `hasOwnProperty` で「その位置に値があるか」を確認できます。

## メソッドごとの挙動

ここが一番混乱するポイント。メソッドによって **穴をスキップするもの/しないもの** があります。

### 穴をスキップする（無視する）

- `forEach`
- `map`
- `filter`
- `reduce`
- `every`
- `some`
- `find`, `findIndex`

```js
const a = [1, , 3];
a.forEach((v) => console.log(v));
// 1
// 3（2番目はスキップ）

a.map((v) => v * 2); // [2, empty, 6]（空はそのまま残る）
```

`map` の結果も元の穴を保持したままです！

### 穴を `undefined` として扱う

- `for...of`
- 分割代入
- スプレッド構文
- `Array.from`
- `fill`
- `includes`, `indexOf`（ただし `includes` は `undefined` を見つけてしまう）

```js
const a = [1, , 3];

for (const v of a) console.log(v);
// 1
// undefined
// 3

[...a]; // [1, undefined, 3]（穴が undefined に）

Array.from(a); // [1, undefined, 3]
```

### includes と indexOf の違い

```js
const a = [1, , 3];
a.includes(undefined); // true（穴も undefined と解釈）
a.indexOf(undefined);  // -1（見つからない）
```

## どうしてこんな仕様に？

JavaScript の配列は実態が **オブジェクト** です。キーが数値っぽい文字列のオブジェクト、という認識。

```js
const a = [1, , 3];
Object.keys(a); // ["0", "2"]（"1" が存在しない）
```

そのため「ある位置にプロパティが存在しない」という状態が発生し、メソッド側が `in` で確認してスキップする、という仕様ができました。

## 空要素を生むコード

### new Array(n)

```js
const a = new Array(3); // [ , , , ]
a.length; // 3
a[0]; // undefined
0 in a; // false
```

「長さ3で全部 undefined の配列」と思うかもしれませんが、穴だらけです。

### length を拡張

```js
const a = [1];
a.length = 5;
// a は [1, , , , ]
```

### インデックスを飛ばして代入

```js
const a = [];
a[10] = "x"; // 0〜9 は穴
```

### delete

```js
const a = [1, 2, 3];
delete a[1]; // [1, empty, 3]（length は 3 のまま）
```

`delete` は要素を減らさず穴にします。要素を消したいなら `splice` を使う。

```js
a.splice(1, 1); // [1, 3]
```

## 空要素を避ける／取り除く方法

### 新規作成時に値を入れる

```js
new Array(3).fill(0);        // [0, 0, 0]
Array.from({ length: 3 }, () => 0); // [0, 0, 0]
Array.from({ length: 5 }, (_, i) => i); // [0, 1, 2, 3, 4]
```

`fill` と `Array.from` はどちらもよく使われます。

### 穴を削除する

```js
const a = [1, , 3, , 5];
const clean = a.filter(() => true); // [1, 3, 5]
// または
const clean2 = Array.from(a).filter((v) => v !== undefined);
```

`filter` は穴をスキップするので、結果には穴が含まれません。

### undefined にしておく

ホールを避け、明示的に `undefined` を代入しておくのも手。挙動が統一されるので分かりやすい。

```js
const a = new Array(3);
for (let i = 0; i < 3; i++) a[i] = undefined;
```

## デバッグで気付くサイン

コンソールに出たとき、環境によって表示が違います。

- `[1, <2 empty items>, 4]`
- `[1, undefined × 2, 4]`
- `[1, , , 4]`

「empty」や「×」が出たら空要素の可能性が高いです。

## まとめ

- 空要素（ホール）は `undefined` とは別物。位置に「プロパティがない」状態
- メソッドによってスキップ or `undefined` として扱う
- `new Array(n)` や `delete` は穴を作る原因
- 安全に作るには `Array.from` や `fill` を使う
- 穴を取り除くには `filter(() => true)` または展開（`[...arr]`）

普段は気にしなくていい現象ですが、なぜか `map` で結果が飛び飛びに、`forEach` で思ったより反復が少ない、といったときに思い出してください。
