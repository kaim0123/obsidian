# 非同期処理（Asynchronous Programming）

## 非同期とは

JavaScript は基本的に **シングルスレッド**（一度に1つの処理しかしない）で動きます。しかし、ネットワーク通信やファイル読み書き、タイマーなど「結果が返るまで時間のかかる処理」を待つ間にUIが固まったら困ります。

そこで使われるのが **非同期処理（asynchronous processing）** です。時間のかかる処理を「バックグラウンドに投げ、終わったら教えてね」と任せる仕組みです。

非同期処理を扱うための主な3つの書き方があります。

1. **コールバック関数**（古典的）
2. **Promise**（ES2015〜）
3. **async / await**（ES2017〜、最も読みやすい）

## 同期と非同期の違い

```js
console.log("A");
console.log("B");
console.log("C");
// 出力: A, B, C（順番通り）
```

一方、非同期だと：

```js
console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
// 出力: A, C, B
```

`setTimeout` は0ミリ秒でも、いったん「後でね」キュー（タスクキュー）に回されるため、`C` のあとに `B` が出ます。

## 1. コールバック（古典）

時間のかかる関数に「終わったら呼んでね」と関数を渡します。

```js
setTimeout(() => {
  console.log("1秒経ったよ");
}, 1000);

// fs.readFile など（Node.js）
fs.readFile("data.txt", "utf-8", (err, data) => {
  if (err) return console.error(err);
  console.log(data);
});
```

### コールバック地獄

コールバックの中にまたコールバックを書くと、どんどんネストが深くなります。

```js
doA((resA) => {
  doB(resA, (resB) => {
    doC(resB, (resC) => {
      doD(resC, (resD) => {
        // ...
      });
    });
  });
});
```

これが「コールバック地獄」。読みづらく、エラー処理も面倒です。

## 2. Promise

Promise は「いつか値が入る箱」です。次の3つの状態を持ちます。

- **pending（保留中）** … まだ結果が出ていない
- **fulfilled（成功）** … 値が得られた
- **rejected（失敗）** … エラーが起きた

### Promise を作る

```js
const p = new Promise((resolve, reject) => {
  setTimeout(() => {
    const ok = Math.random() > 0.5;
    if (ok) resolve("成功！");
    else reject(new Error("失敗..."));
  }, 1000);
});
```

### Promise を使う

```js
p.then((value) => {
  console.log("結果:", value);
}).catch((err) => {
  console.error("エラー:", err);
}).finally(() => {
  console.log("終わり");
});
```

- `.then(fn)` … 成功したとき呼ばれる
- `.catch(fn)` … 失敗したとき呼ばれる
- `.finally(fn)` … 成功・失敗に関わらず最後に呼ばれる

### チェーン（連結）

Promise は **`.then` の戻り値がまた Promise** なので、連ねられます。

```js
fetchUser(1)
  .then((user) => fetchPosts(user.id))
  .then((posts) => console.log(posts))
  .catch((err) => console.error(err));
```

コールバック地獄を1段のチェーンに平らにできます。

## 3. async / await（推奨）

`async / await` は Promise をもっと読みやすく書くための糖衣構文です。**同期っぽい見た目** で非同期処理を書けます。

```js
async function run() {
  try {
    const user = await fetchUser(1);
    const posts = await fetchPosts(user.id);
    console.log(posts);
  } catch (err) {
    console.error(err);
  }
}

run();
```

### ルール

- `async` を付けた関数の中でだけ `await` が使える
- `await` は Promise の結果が出るまで待つ
- `async` 関数は **必ず Promise を返す**
- エラーは try/catch で捕まえる

### 例：fetch と組み合わせる

```js
async function getUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error("取得失敗");
  const data = await res.json();
  return data;
}

(async () => {
  const user = await getUser(1);
  console.log(user);
})();
```

## 並列と逐次

### 逐次（1つずつ待つ）

```js
const a = await fetchA(); // 1秒
const b = await fetchB(); // 1秒
// 合計 2秒
```

### 並列（同時に走らせる）

独立した処理なら `Promise.all` で同時に走らせましょう。

```js
const [a, b] = await Promise.all([fetchA(), fetchB()]);
// 合計 1秒
```

### その他の Promise 静的メソッド

- `Promise.all([...])` … 全部成功を待つ。1つでも失敗すると即 reject
- `Promise.allSettled([...])` … 全部の結果（成功/失敗混在OK）を返す
- `Promise.race([...])` … 最初に決着が付いたもので終わる
- `Promise.any([...])` … 最初に成功したもので終わる

## エラーハンドリング

`await` 中のエラーは `throw` として扱えます。

```js
async function safe() {
  try {
    const data = await fetchSomething();
    return data;
  } catch (err) {
    console.error("失敗:", err);
    return null;
  }
}
```

`.catch` でまとめて受け取ることもできます。

```js
const data = await fetchSomething().catch(() => null);
```

## イベントループの仕組み（ざっくり）

- JavaScript のメインスレッドは1つだけ
- 同期的なコードは全部片付けてから、非同期のタスクを処理する
- 非同期タスクには優先順位がある（Microtask: Promise、Macrotask: setTimeout）

```js
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// 出力: 1, 4, 3, 2
```

Promise の `.then` は **マイクロタスク** なので、`setTimeout` より先に実行されます。

## よくある落とし穴

### 1. await し忘れ

```js
async function bad() {
  const data = fetchData(); // Promise そのもの
  console.log(data);        // Promise { <pending> } が出る
}

async function good() {
  const data = await fetchData();
  console.log(data);
}
```

### 2. forEach の中で await

```js
// NG：await が効かない
[1, 2, 3].forEach(async (id) => {
  await fetch(`/api/${id}`);
});
// 先に forEach が終わる
```

`for...of` を使いましょう（逐次処理）。

```js
for (const id of [1, 2, 3]) {
  await fetch(`/api/${id}`);
}
```

並列でよければ `Promise.all(map)`。

```js
await Promise.all([1, 2, 3].map((id) => fetch(`/api/${id}`)));
```

### 3. エラーを握りつぶす

```js
// try/catch もなく、.catch もない
async function danger() {
  await mayFail(); // エラーが上に飛んでいく
}
```

Node.js では `unhandledRejection` になり、プロセスが落ちることもあります。呼び出し側で必ず受け止めましょう。

### 4. await を並列で使えるのに逐次にしてしまう

独立した処理を `await; await;` すると直列になって遅いです。`Promise.all` を思い出しましょう。

## まとめ

- 非同期＝時間のかかる処理を待たずに他を進める仕組み
- 書き方は：コールバック → Promise → async/await
- `async/await` が最も読みやすく、現代の主流
- エラーは try/catch、並列は Promise.all
- イベントループでマイクロタスク（Promise）がマクロタスク（setTimeout）より優先される

非同期処理は Web 開発のあらゆる場面で出てきます。「await を付け忘れていないか」「並列にできるところで逐次になっていないか」を習慣的にチェックできるようになると、コードの品質と速度が大きく変わります。
