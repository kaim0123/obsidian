# 02. 変数とスコープ

---

## この章で学ぶこと

- `let` と `const` の使い分け
- スコープ（変数が見える範囲）の仕組み
- プリミティブとオブジェクトの「参照」の違い
- イミュータブル（不変）に書くコツ

---

## 02-1. 変数宣言（let / const）と再代入

### 変数とは

変数は**値に名前をつけて保存する箱**です。

```javascript
let message = "こんにちは";
console.log(message);  // → こんにちは
```

### let：再代入できる変数

```javascript
let count = 0;
console.log(count);  // → 0

count = 1;           // 再代入OK
console.log(count);  // → 1

count = count + 1;   // 自分自身を使って更新もOK
console.log(count);  // → 2
```

### const：再代入できない変数（定数）

```javascript
const PI = 3.14159;
console.log(PI);  // → 3.14159

PI = 3;  // → TypeError: Assignment to constant variable.
         //   再代入しようとするとエラー！
```

### let と const の使い分け

```
基本ルール：まず const を使う。再代入が必要なときだけ let を使う。
```

```javascript
// ✅ 変わらない値は const
const TAX_RATE = 0.1;
const userName = "太郎";
const items = [1, 2, 3];  // 配列の中身は変えられる（後述）

// ✅ 変わる値は let
let total = 0;
let isLoggedIn = false;
let currentPage = 1;
```

> なぜ const を優先するのか？
> - 「この値は変わりません」という意思表示になる
> - うっかり上書きしてしまうバグを防げる
> - コードを読む人が「この変数は変わらない」と安心できる

### var は使わない

古いJavaScriptでは `var` を使っていましたが、現在は**使いません**。

```javascript
// ❌ var は使わない
var oldStyle = "古い書き方";

// ✅ let / const を使う
let newStyle = "新しい書き方";
const betterStyle = "もっと良い書き方";
```

`var` を使わない理由：
- スコープの挙動が直感的でない（関数スコープになる）
- 同じ名前で再宣言できてしまう（バグの温床）
- 巻き上げ（hoisting）の挙動がわかりにくい

## 02-2. スコープ（ブロック / 関数）と寿命

### スコープとは

スコープとは**変数が見える（使える）範囲**のことです。

### ブロックスコープ

`{ }` で囲まれた範囲がブロックです。`let` と `const` はブロックスコープを持ちます。

```javascript
{
  let x = 10;
  console.log(x);  // → 10（ブロックの中なのでOK）
}
console.log(x);  // → ReferenceError: x is not defined
                 //   ブロックの外からは見えない！
```

```javascript
// if文のブロック
if (true) {
  let secret = "秘密";
  console.log(secret);  // → "秘密"
}
console.log(secret);  // → ReferenceError（ブロックの外）

// for文のブロック
for (let i = 0; i < 3; i++) {
  console.log(i);  // → 0, 1, 2
}
console.log(i);  // → ReferenceError（forの外）
```

### スコープのネスト（入れ子）

内側のスコープから外側の変数は見えるが、逆はダメ。

```javascript
let outer = "外側";

{
  let inner = "内側";
  console.log(outer);  // → "外側"（外側は見える）
  console.log(inner);  // → "内側"
}

console.log(outer);  // → "外側"
console.log(inner);  // → ReferenceError（内側は見えない）
```

**イメージ：マジックミラー**
- 内側の部屋から外側は見える（覗ける）
- 外側の部屋から内側は見えない

### 関数スコープ

関数の中で宣言した変数は、関数の外からは見えません。

```javascript
function greet() {
  let greeting = "こんにちは";
  console.log(greeting);  // → "こんにちは"
}

greet();
console.log(greeting);  // → ReferenceError
```

### 変数の「寿命」

変数はスコープを抜けると消えます（ガベージコレクションで回収される）。

```javascript
function process() {
  let data = createHugeData();  // 大きなデータを作る
  // ... data を使った処理 ...
}  // ← ここで data は消える（メモリが解放される）
```

### TDZ（Temporal Dead Zone）

`let` と `const` は宣言前に使うとエラーになります。

```javascript
console.log(x);  // → ReferenceError: Cannot access 'x' before initialization
let x = 10;
```

これは**「一時的デッドゾーン（TDZ）」**と呼ばれます。スコープに入ってから宣言に到達するまでの間、変数にアクセスできません。

## 02-3. 参照とコピー（プリミティブ vs オブジェクト）

### プリミティブは「値」がコピーされる

```javascript
let a = 10;
let b = a;     // a の値（10）がコピーされる

b = 20;        // b を変えても...
console.log(a);  // → 10（a は変わらない！）
console.log(b);  // → 20
```

イメージ：メモ用紙に「10」と書いて渡す。相手が書き換えても自分のメモは変わらない。

### オブジェクト（配列含む）は「参照」がコピーされる

```javascript
let original = { name: "太郎", age: 20 };
let copy = original;  // 参照（住所）がコピーされる

copy.age = 30;            // copy を変えると...
console.log(original.age); // → 30（original も変わる！！）
```

イメージ：住所を渡す。同じ家を指しているので、一方が模様替えすると両方に影響する。

```javascript
// 配列でも同じ
let arr1 = [1, 2, 3];
let arr2 = arr1;       // 参照のコピー

arr2.push(4);
console.log(arr1);     // → [1, 2, 3, 4]（arr1も変わった！）
```

### 独立したコピーを作る

```javascript
// オブジェクトのコピー（スプレッド構文）
let original = { name: "太郎", age: 20 };
let copy = { ...original };  // 新しいオブジェクトを作る

copy.age = 30;
console.log(original.age);  // → 20（変わらない！）

// 配列のコピー
let arr1 = [1, 2, 3];
let arr2 = [...arr1];       // 新しい配列を作る

arr2.push(4);
console.log(arr1);          // → [1, 2, 3]（変わらない！）
```

> ⚠️ スプレッド構文は**浅いコピー（shallow copy）**です。ネストしたオブジェクトの中身は参照のままです。深いコピーについては06章で学びます。

## 02-4. イミュータブルに書くコツ（破壊的操作の罠）

### 破壊的操作とは

元のデータを直接変更する操作を「破壊的操作」と言います。

```javascript
// 破壊的操作の例
let fruits = ["りんご", "バナナ"];
fruits.push("みかん");  // 元の配列が変わる
console.log(fruits);    // → ["りんご", "バナナ", "みかん"]
```

### なぜ問題になるのか

```javascript
function addItem(list, item) {
  list.push(item);  // 元の配列を変えてしまう！
  return list;
}

let original = ["A", "B"];
let newList = addItem(original, "C");

console.log(newList);    // → ["A", "B", "C"]
console.log(original);   // → ["A", "B", "C"]  ← 元も変わった！
```

関数に渡した配列が知らないうちに変わるのは、バグの原因になります。

### イミュータブル（非破壊的）に書く

```javascript
function addItem(list, item) {
  return [...list, item];  // 新しい配列を作って返す
}

let original = ["A", "B"];
let newList = addItem(original, "C");

console.log(newList);    // → ["A", "B", "C"]
console.log(original);   // → ["A", "B"]  ← 元は変わらない！
```

### const でもオブジェクトの中身は変えられる

```javascript
const user = { name: "太郎", age: 20 };

// ✅ プロパティの変更はOK（const は「再代入」を禁止するだけ）
user.age = 21;
console.log(user);  // → { name: "太郎", age: 21 }

// ❌ 再代入はNG
user = { name: "花子" };  // → TypeError: Assignment to constant variable.
```

**イメージ**：`const` は「箱を別の箱に取り替えるのはダメ」だけど、「箱の中身を入れ替えるのはOK」。

## よくある間違い

```javascript
// ❌ constの値は絶対変わらないと思っている
const arr = [1, 2, 3];
arr.push(4);         // これはOK（配列の中身を変えている）
arr = [5, 6, 7];     // これはNG（再代入はできない）

// ❌ ブロックスコープを忘れる
if (true) {
  let x = 10;
}
console.log(x);  // ReferenceError

// ❌ 参照のコピーとは知らずにオブジェクトを渡す
let config = { debug: false };
let myConfig = config;
myConfig.debug = true;
// config.debug も true になっている！

// ❌ varを使ってforループの変数が漏れる
for (var i = 0; i < 3; i++) { }
console.log(i);  // → 3（varだとブロックスコープがない）
```

---

## 重要ポイント

1. **`const` を基本にする**。再代入が必要なときだけ `let`
2. **`var` は使わない**。常に `let` / `const` を使う
3. **スコープ** = 変数の見える範囲。`{ }` の中で宣言した変数は外から見えない
4. **プリミティブは値コピー**、**オブジェクト/配列は参照コピー**
5. 参照コピーの罠を避けるには**スプレッド構文 `{...obj}` / `[...arr]`** でコピーする
6. `const` は再代入を禁止するだけ。オブジェクトの中身は変えられる

## 練習問題

1. 以下のコードの出力を予想しよう：
   ```javascript
   let a = "hello";
   let b = a;
   b = "world";
   console.log(a);
   console.log(b);
   ```

2. 以下のコードの出力を予想しよう：
   ```javascript
   let obj1 = { x: 1 };
   let obj2 = obj1;
   obj2.x = 99;
   console.log(obj1.x);
   ```

3. 以下のコードにはバグがあります。原因を説明して修正しよう：
   ```javascript
   const items = ["A", "B", "C"];
   for (let i = 0; i < items.length; i++) {
     const item = items[i];
   }
   console.log(item);  // "C" を出力したい
   ```

## ミニ課題

**「安全な配列操作」を書こう**

以下の関数を、元の配列を変更しないように書き直そう：

```javascript
// この関数は元の配列を変えてしまう
function removeFirst(arr) {
  arr.shift();  // 先頭を削除（破壊的）
  return arr;
}

let numbers = [1, 2, 3, 4, 5];
let result = removeFirst(numbers);
console.log(result);   // → [2, 3, 4, 5]
console.log(numbers);  // → [2, 3, 4, 5] ← 元も変わっちゃう！
```

ヒント：`slice()` を使うと配列の一部を非破壊的に取り出せます。
