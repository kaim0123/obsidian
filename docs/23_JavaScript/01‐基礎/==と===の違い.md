# `==` と `===` の違い

## 結論から言うと

- **`==`（等価演算子）** … 型が違っても自動変換して比較する（ゆるい）
- **`===`（厳密等価演算子）** … 型も値も同じかを比較する（厳しい）

JavaScript では原則 **`===` を使う** のが推奨です。`==` は予想外の挙動を起こしやすく、コードレビューでもほぼ確実に指摘されます。

## 例で違いを見る

```js
1 == "1";    // true（"1" が 1 に変換される）
1 === "1";   // false（型が違うので false）

0 == false;  // true（false が 0 に変換）
0 === false; // false

null == undefined;  // true
null === undefined; // false

"" == 0;     // true
"" === 0;    // false
```

「見た目は似ているが型が違う」ペアで、`==` は true、`===` は false という結果になります。

## `==` の自動変換ルール（抜粋）

`==` は実は意外と複雑な変換規則で動きます。一部を紹介すると…

| 左 | 右 | 結果 |
|---|---|---|
| `null` | `undefined` | `true` |
| 数値 | 文字列 | 文字列を数値に変換して比較 |
| 真偽値 | 何か | 真偽値を数値に変換（true→1, false→0） |
| オブジェクト | プリミティブ | オブジェクトをプリミティブに変換 |
| NaN | 何か（NaN含む） | 常に `false` |

これを全部覚えるのは不可能に近く、毎回考えるくらいなら `===` を使った方が早いです。

## `==` の怖い具体例

```js
"" == "0";        // false
0 == "";          // true
0 == "0";         // true

false == "false"; // false
false == "0";     // true

null == 0;        // false（ここ特殊）
null < 1;         // true（でもこれは true）
```

「`0 == ""` は true、でも `"" == "0"` は false」のような混乱を招くケースが存在します。これを追いかける時間は人生の無駄です。

## `null` と `undefined` の例外ルール

`null` と `undefined` だけは特別に「お互いと等価」と定義されています。

```js
null == null;       // true
undefined == undefined; // true
null == undefined;  // true
null == 0;          // false
null == false;      // false
```

なので「値が null か undefined かを一緒に判定したい」ときだけは、次の形で `==` を使うケースもあります。

```js
if (value == null) { // null または undefined
  // ...
}
```

ただ、これも `value === null || value === undefined` か、`value ?? default`（Nullish Coalescing）の方が明確です。

## NaN は常に false

```js
NaN == NaN;  // false
NaN === NaN; // false
```

どちらでも NaN は自分自身と等しくありません。NaN の判定は `Number.isNaN(value)` を使います。

```js
Number.isNaN(NaN);      // true
Number.isNaN("abc");    // false
```

## オブジェクトの比較

オブジェクトは **参照比較** されます。

```js
{ a: 1 } == { a: 1 };  // false
{ a: 1 } === { a: 1 }; // false

const o = { a: 1 };
o === o; // true
```

中身が同じでも、別々に作った時点で異なるものとして扱われます。

## 0 と -0

```js
0 === -0;  // true（特例）
Object.is(0, -0); // false
```

ごく稀に `-0` と `0` を区別したいときは `Object.is` を使います。同じ理由で `NaN` も `Object.is(NaN, NaN)` は true を返します。

## Linter もほぼ必須で指摘する

ESLint の `eqeqeq` ルールは、多くのプロジェクトで有効化されています。`==` を書くと警告が出ます。理由は「一度でも混乱を招いたら、その後の調査コストのほうが高いから」。

## まとめ

- 基本は `===` と `!==` を使う
- `==` は型変換が発生して予測しにくい
- `null`/`undefined` まとめて判定したいときは `value == null` も便利（ただし代替もある）
- NaN の判定は `Number.isNaN` を使う
- オブジェクトは参照比較。中身を比べたいなら自作かライブラリ

「`==` を覚えなくて済むように、`===` を選ぶ」と考えれば OK です。
