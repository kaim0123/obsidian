 Critical (即修正推奨 — 機能が壊れている)

  C1. searchParams を同期アクセスしている

  - src/app/auth/login/page.tsx:1-12
  - Next.js 16 では searchParams は Promise なので、現在の実装では redirectTo が常に undefined
  になり「ログイン後に元のページに戻れない」が必ず発生する。
  - 修正: async function + await searchParams。

  C2. Proxy 内で getSession() を認可判定に使用

  - src/proxy.ts:37-49
  - 先ほどのセキュリティレビューでは「実害なし」としたが、別の実害がある: getSession()
  はリフレッシュをトリガしないケースがあり、cookie 同期と組み合わさってログアウトループの原因になる。@supabase/ssr の
  README でも middleware では getUser() を使えと明記。
  - 修正: await supabase.auth.getUser() に置き換える。

  C3. Proxy matcher が広すぎ — /api や _next/data を除外していない

  - src/proxy.ts:61-63
  - /api/* に Route Handler を増やした瞬間に、未認証時に JSON ではなく HTML リダイレクトが返り API
  クライアントが壊れる。RSC の _next/data フェッチも 302 でループ化する。
  - 修正:
  '/((?!api|_next/static|_next/image|_next/data|favicon.ico|.*\\.(?:png|jpg|jpeg|gif|webp|svg|ico|css|js|map)$).*)'

  C4. リダイレクト時に Supabase が更新した cookie を引き継いでいない

  - src/proxy.ts:19-21, 44-56
  - NextResponse.redirect() を新規生成しているため、getSession() が裏でリフレッシュした新 cookie が破棄される → refresh
  token 単回使用ルールでログアウト連鎖。
  - 修正: response.cookies.getAll() を redirect 用 response にコピーする。
