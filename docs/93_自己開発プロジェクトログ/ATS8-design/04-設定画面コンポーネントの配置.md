# 04. 設定画面コンポーネントの配置

## design.md の指摘（✅ 対応済み）

> **設定画面のコンポーネント配置が方針から外れている**
>
> `SourcesSettingsContent.tsx` / `StagesSettingsContent.tsx` を `features/settings/components/` に移動。`settings/stages`・`settings/sources` の page は共有コンポーネントを参照する薄いラッパーに統一。

---

## 基礎知識：app/ と features/ の役割分担

Next.js App Router では **`src/app/`** が URL とページの入口です。

```
src/app/(dashboard)/settings/sources/page.tsx
         ↑ URL: /settings/sources
```

一方 **`src/features/`** には **ビジネスロジックと UI の実体** を置く、というのが ATS8 の設計方針です。

| 場所 | 役割 |
|------|------|
| `app/.../page.tsx` | ルーティング。できるだけ **薄く** |
| `features/.../components/` | 実際の UI と操作ロジック |
| `features/.../hooks/` | データ取得・更新 |

---

## 何が間違っていたか

### 問題：UI の実体が app/ 側にあった

設定画面（反響元・選考段階）の **大きなコンポーネント** が `app/(dashboard)/settings/` 付近に置かれていました。

```
<!-- 以前（悪い例） -->
app/(dashboard)/settings/
├── sources/
│   └── page.tsx              ← ページ + 大量の UI ロジック
└── stages/
    └── page.tsx              ← 同上
```

### なぜ問題か

1. **方針と矛盾** — 他の機能（candidates, events）は `features/` に UI があるのに、settings だけ例外
2. **再利用できない** — 設定 UI を別の場所から使いたいとき、app/ から import できない（Next.js の慣習上 app/ はページ専用）
3. **テストしにくい** — page.tsx にロジックが混ざると、単体テストの対象にしづらい
4. **新メンバーが迷う** — 「設定のコードはどこ？」が分からない

---

## どう修正すべきか

### 1. UI を `features/settings/components/` に移す

```
features/settings/
├── components/
│   ├── SourcesSettingsContent.tsx   ← 反響元設定の UI 本体
│   └── StagesSettingsContent.tsx    ← 選考段階設定の UI 本体
├── hooks/
└── types.ts
```

### 2. page.tsx は「薄いラッパー」にする

```tsx
// app/(dashboard)/settings/sources/page.tsx（良い例）
import { SourcesSettingsContent } from '@/features/settings/components/SourcesSettingsContent'

export default function SourcesSettingsPage() {
  return <SourcesSettingsContent />
}
```

**page.tsx の仕事は「どのコンポーネントを表示するか」だけ。**

### 3. データ取得は hooks に

設定画面専用の fetch / mutation は `features/settings/hooks/` に置き、コンポーネントから呼び出します。

---

## 修正後のデータの流れ

```
ユーザーが /settings/sources にアクセス
    ↓
app/.../sources/page.tsx（ラッパー）
    ↓
SourcesSettingsContent（features/settings/components/）
    ↓
useSourcesSettings() など（features/settings/hooks/）
    ↓
/api/settings/sources（Route Handler）
```

---

## まとめ

| 間違い | 修正 |
|--------|------|
| 設定 UI が app/ に直書き | `features/settings/components/` へ移動 |
| page.tsx が太い | コンポーネント import だけの薄いラッパー |
| 機能ごとに配置ルールが違う | 全 feature で同じパターンを徹底 |

**学び**: `app/` は **「どの URL で何を見せるか」の表**、`features/` は **「中身」**。表に中身を書かない。
