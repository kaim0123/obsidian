## 1. layout.tsx の JSX インデント

### 基礎知識：JSX インデントとは？

React の JSX では、HTML のように **ネスト（入れ子）** で UI を書きます。

```tsx
<div>           {/* 親 */}
  <Header />    {/* 子 — インデントで親子関係が分かる */}
  <main>
    {children}
  </main>
</div>
```

**インデントが崩れている** = スペースの数が揃っておらず、どのタグがどの親の子か **目視で追いにくい** 状態です。

### 何が問題だったか

```tsx
// 以前（崩れている例）
<div className="flex min-h-screen">
<Sidebar />
  <div className="flex-1 flex flex-col">
<Header />
    <main>...</main>
  </div>
</div>
```

**動作には影響しません**（JavaScript としては正しい）が:

- コードレビューで構造を読み取りにくい
- 閉じタグ `</div>` の対応ミスに気づきにくい
- Prettier 等のフォーマッタを使っていれば自動で直る類の問題

### どう修正すべきか

Prettier / ESLint の auto-fix を実行するか、手動で揃える:

```tsx
// 修正後
<div className="flex min-h-screen bg-gray-50">
  <Sidebar />
  <div className="flex flex-1 flex-col">
    <Header />
    <main className="flex-1 bg-gray-50 p-6">{children}</main>
  </div>
</div>
```

### 現在の状態

**✅ 修正済み** — 現在の `(dashboard)/layout.tsx` はインデントが整っています。

## 2. 移行スクリプトの散在

### 基礎知識：移行スクリプトとは？

**旧システムから新システムへデータを移す** ための、一度きり（または稀に）実行するプログラムです。

ATS8 では `migrate_ats_ishome_to_ats8.cjs` のようなファイルが該当します。

### 何が問題だったか

```
<!-- 以前（悪い例） -->
ats8/
├── migrate_ats_ishome_to_ats8.cjs   ← ルート直下
├── supabase/
│   └── （別のスクリプト？）
└── src/
```

**スクリプトの居場所がバラバラ** だと:

- 新メンバーが「実行していいファイルはどれ？」と迷う
- `npm run xxx` で実行できるか分からない
- 本番アプリのコード（`src/`）と混ざって見える

### どう修正すべきか

#### 1. `scripts/` フォルダに集約

```
ats8/
├── scripts/
│   ├── migrate_ats_ishome_to_ats8.cjs
│   └── README.md          ← 各スクリプトの説明
└── src/
```

#### 2. 用途を README に書く

```markdown
# scripts/

## migrate_ats_ishome_to_ats8.cjs

旧 ATS（ishome）のデータを ATS8 の Supabase に投入する。

**前提**: `.env.local` に Supabase 接続情報が設定済みであること。

**実行**:
node scripts/migrate_ats_ishome_to_ats8.cjs

**注意**: 本番 DB では実行前にバックアップを取ること。
```

#### 3. package.json に npm script を追加（任意）

```json
"scripts": {
  "migrate:ishome": "node scripts/migrate_ats_ishome_to_ats8.cjs"
}
```
