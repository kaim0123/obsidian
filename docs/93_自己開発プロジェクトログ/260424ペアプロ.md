## この回のテーマと要約（初心者向け）

### テーマ：疎結合（そけつごう）

**疎結合**とは、プログラムの部品同士を「ゆるくつなぐ」設計のことです。ある1つのファイルやコンポーネントが、他の巨大な塊（この回だとコンタクトフォーム全体）に強く依存しないようにし、**小さな単位で入れ替え・テスト・再利用**しやすくします。

文字起こしの中では「素結合」と聞こえる箇所がありますが、文脈上 **疎結合**（結びつきを弱くする）を指していると読み取れます。

---

### 背景：何が課題だったか

リアルタイムバリデーションを、フォームコンポーネントの中に **手続き型** でまとめて書くと、次のようになりがちです。

- 1つの関数やコンポーネントを上から下まで読まないと、何が起きているか追いにくい
- **バリデーション**（ルール判定）と **ステート**（入力値・エラー表示の状態）と **イベント**（onChange / onBlur など）が同じ場所に混ざる
- 結果として「バリデーションだけ試したい」のにフォーム全体を読み込む必要が出て、**テストや再利用がしづらい**

疎結合の視点では、「バリデーションは本来、**渡された値を見て結果を返すだけ**」なので、フォームの JSX や React の state に直接くっついている必要はない、という整理になります。

---

### 今回の切り分け方（3層のイメージ）

| 置き場所 | 役割（ざっくり） | 典型の中身 |
|----------|------------------|------------|
| **フォーム（画面）のファイル** | 見た目と配線 | 入力欄の表示、`use〇〇` を呼んで返り値を渡す |
| **`lib` のユーティリティ** | ルール・変換（React と無関係が理想） | 値の正規化（半角化など）、バリデーション関数、エラーメッセージの判定 |
| **`use〇〇`（カスタムフック）** | React らしい「状態と振る舞い」のまとめ | `useState`、onChange / onBlur、lib の関数を呼んでエラーを更新する処理 |

- **`lib` に寄せる理由**  
  ここは **純粋関数**（同じ入力なら同じ出力、副作用がない）にしやすく、**フォームを動かさずにユニットテスト**できます。文字起こしでも「事実（値）だけ与えればよい」「フォームから何かを入れて評価する必要がない」と説明されています。

- **`use〇〇` に寄せる理由**  
  React では「ステートと、それを変える処理」を **フック** にまとめるのが一般的です。エラー表示・変更・フォーカス失敗など **フォームフィールド単位の関心** を1カ所に閉じ込めると、フォーム本体が薄くなります。

- **フォームファイルが薄くなる効果**  
  「このフィールドの値とエラーはどう作られるか」は **フックと lib を見れば追える**ようになり、画面ファイルは **表示と接続**に集中できます。

---

### 初心者が押さえるとよいポイント

1. **関心の分離** — 「表示」「状態・イベント」「ルール・変換」を分けると、変更箇所が見つけやすい。  
2. **疎結合とテスト** — lib を小さく切ると「この関数にこの文字列を入れたらどうなるか」だけで検証できる。  
3. **カプセル化とのつながり** — オブジェクト指向のカプセル化と同じく、「外から必要なことだけ見えればよい」単位にまとめると、コードが読みやすくなる。

このあとの文字起こしでは、上記の考え方に沿って **フォームエラー → フックへの移動 → 正規化・バリデーションの lib 切り出し → フォーム側のスリム化** が実演されています。
