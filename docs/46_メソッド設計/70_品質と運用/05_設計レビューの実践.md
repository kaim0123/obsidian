# 設計レビューの実践

## この章の目的

**メソッド設計レビュー** を総合演習として実践する章です。  
進め方、総合チェックリスト、Before/After の提示、リファクタリング PR の書き方を学びます。

---

## 1. メソッド設計レビューの進め方

1. **対象を決める** — 新規 PR / 複雑度 Top 10 / 変更頻度の高い関数
2. **オーケストレーションから読む** — エントリポイントの流れを把握
3. **チェックリストで点検** — [[付録B_メソッド設計チェックリスト]]
4. **優先度付きで指摘** — Critical 3 件以内
5. **フォロー** — リファクタ PR または次スプリントで対応

```text
  60 分レビューの例
  ─────────────────
  10 min  全体像・エントリポイント
  30 min  関数ごとにチェックリスト
  15 min  指摘の整理・優先度
  5 min   次アクション合意
```

---

## 2. レビュー用チェックリスト（総合版）

### 分割と責任

- [ ] 1 メソッド 1 関心（SoC / SRP）
- [ ] 50 行超・複雑度 10 超の関数がない
- [ ] オーケストレーションと詳細が分離

### 制御と読みやすさ

- [ ] Guard Clause で正常系が一直線
- [ ] ネスト 3 段以内
- [ ] 動詞 + 目的語の命名

### 契約と副作用

- [ ] CQS — getter に副作用なし
- [ ] 純粋にできる計算が Core にある
- [ ] 引数 3 個以下、または Parameter Object

### 品質

- [ ] 主要ロジックに単体テスト
- [ ] モックが 3 個以上 → 設計見直し

詳細: [[付録B_メソッド設計チェックリスト]]

## 3. Before / After の提示方法

レビューコメントでは **具体的な Before/After** を示します。

```javascript
// Before（L45-80）: 検証と計算が混在
function process(order) {
  if (!order.items.length) throw new Error('...');
  let total = 0;
  for (...) { total += ...; }
  db.save(order);
}

// After 提案
function process(order) {
  validateOrder(order);
  const total = calculateTotal(order.items);
  saveOrder({ ...order, total });
}
```

**diff 形式** または **疑似コード** で、変更の意図を伝えます。

---

## 4. リファクタリング PR の書き方

| 項目 | 内容 |
|------|------|
| **タイトル** | `refactor: extract validateOrder from handleRequest` |
| **説明** | 何を・なぜ・振る舞いは変えない |
| **スコープ** | 1 PR = 1 リファクタ主題（Extract Method のみ等） |
| **テスト** | 既存テスト通過 + 新規テスト（純粋関数） |

```markdown
## Summary
- handleRequest から validateOrder / calculateTotal を Extract Method
- 振る舞い変更なし（既存テスト 42 件通過）

## Why
- 単体テスト可能にするため
- 複雑度 18 → 6 に低減

## Test plan
- [x] npm test
- [x] 手動で注文 API を 1 回確認
```

---

## まとめ

- レビューはエントリポイント → チェックリスト → 優先度付き指摘
- 総合チェックリストで抜け漏れを防ぐ
- Before/After で改善意図を明確に
- リファクタ PR は小さく・振る舞い不変・テスト付き
