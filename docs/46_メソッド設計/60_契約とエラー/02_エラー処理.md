# エラー処理

## この章の目的

メソッド設計における **エラー処理** の書き方を学ぶ章です。  
例外の使い分け、try-catch の整理、Fail Fast、null の扱いを押さえます。

---

## 1. 例外を使う場面と使わない場面

| 例外を使う | 例外を使わない |
|-----------|---------------|
| 契約違反（前提条件の破れ） | 想定内の失敗（バリデーション） |
| 回復不能なエラー | 呼び出し側が分岐したい場合 |
| プログラムのバグ | パフォーマンスクリティカルなループ内 |

```javascript
// 想定内 → Result 型
function parsePort(input) {
  const n = Number(input);
  if (n < 1 || n > 65535) return { ok: false, error: 'invalid port' };
  return { ok: true, value: n };
}

// 契約違反 → 例外
function divide(a, b) {
  if (b === 0) throw new Error('division by zero');
  return a / b;
}
```

詳細は [[01_Design_by_Contract]] を参照。

## 2. try-catch だらけを避ける

**try-catch を各所に書く** と、正常系が読めなくなります。

```javascript
// 悪い例: try-catch だらけ
function process(order) {
  try {
    validate(order);
  } catch (e) { log(e); return; }
  try {
    save(order);
  } catch (e) { log(e); return; }
}

// 良い例: 境界でまとめる
function process(order) {
  validate(order);
  save(order);
}

// 呼び出し側（Shell）で 1 回 catch
try {
  process(order);
} catch (e) {
  handleError(e);
}
```

**エラー処理は境界（Shell）に集約** し、Core は例外をそのまま上げる（[[03_Functional_Core_Imperative_Shell]]）。

## 3. エラーメッセージと Fail Fast

**Fail Fast** — 不正を早く検出し、**分かりやすいメッセージ** で失敗させます。

```javascript
function withdraw(account, amount) {
  if (amount <= 0) {
    throw new Error(`amount must be positive, got ${amount}`);
  }
  if (amount > account.balance) {
    throw new Error(`insufficient funds: balance=${account.balance}, requested=${amount}`);
  }
  account.balance -= amount;
}
```

**何が・なぜ** 失敗したかが分かるメッセージを付けます。

## 4. null / undefined の扱い

**null 地獄** を避ける技法です。

| 手法 | 例 |
|------|-----|
| **Guard Clause** | `if (!user) return null;` |
| **Optional 型** | `Option<User>` で明示 |
| **デフォルト値** | `name ?? 'unknown'` |
| **早期 throw** | 必須なら `throw` |

```javascript
// 悪い例: null チェックが各所に
function getName(user) {
  if (user && user.profile && user.profile.name) {
    return user.profile.name;
  }
  return 'unknown';
}

// 良い例: 構造を保証するか、Guard で入口に集約
function getName(user) {
  if (!user?.profile?.name) return 'unknown';
  return user.profile.name;
}
```

## 5. エラー処理の Extract Method

複雑なエラー処理は **Extract Method** で名前を付けます。

```javascript
function handleRequest(req) {
  try {
    processRequest(req);
  } catch (e) {
    return buildErrorResponse(e);
  }
}

function buildErrorResponse(error) {
  if (error instanceof ValidationError) {
    return { status: 400, message: error.message };
  }
  if (error instanceof NotFoundError) {
    return { status: 404, message: error.message };
  }
  return { status: 500, message: 'Internal error' };
}
```

エラー種別ごとの分岐も、**1 関数 1 責任** で分割できます。

## まとめ

- 例外 = 契約違反。想定内は Result 型
- try-catch は境界に集約。Core はシンプルに
- Fail Fast + 分かりやすいメッセージ
- null は Guard・Optional・デフォルトで整理
