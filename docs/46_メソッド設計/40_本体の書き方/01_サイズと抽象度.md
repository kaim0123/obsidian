# サイズと抽象度

## この章の目的

**関数の長さ** と **抽象度の統一** を学ぶ章です。  
Clean Code の関数ルール、20 行の目安、コメントが構造を代弁するサインを押さえます。

---

## 1. Clean Code の関数ルール — 小さく書く

Robert C. Martin（*Clean Code*, 2008）は **関数は小さく** と述べます。

- **短い** — 1 画面に収まる
- **少ない行数** — 目安 20 行以下
- **少ない引数** — 0〜2 が理想
- **少ないインデント** — 1〜2 段

```javascript
// 目標: 読み手がスクロールせずに全体を把握できる
function registerUser(user) {
  validateUser(user);
  const hashed = hashPassword(user.password);
  persistUser({ ...user, password: hashed });
  notifyNewUser(user);
}
```

詳細は [[付録C_Clean_Code関数ルール早見表]] を参照。

---

## 2. 1 関数 = 1 抽象度

**1 関数の中のステップは、同じ抽象度** に揃えます。

```javascript
// 悪い例: 抽象度が混在
function processOrder(order) {
  validate(order);
  let total = 0;
  for (const i of order.items) {
    total += i.price * i.qty;  // 低レベル
  }
  db.query('INSERT ...');      // インフラ
}

// 良い例: 同じ抽象度
function processOrder(order) {
  validate(order);
  const total = calculateTotal(order);
  saveOrder(order, total);
}
```

高レベル = オーケストレーション、低レベル = 詳細関数 — **混在させない**。

---

## 3. 20 行の目安とその限界

**20 行** は **目安** であり、絶対ルールではありません。

| 20 行超でも許容 | 20 行以内にすべき |
|-----------------|-------------------|
| 宣言的な設定・マッピング | 分岐だらけの処理 |
| 生成されたコード | 手書きのビジネスロジック |
| 1 つの式の展開 | 複数の関心が混在 |

**複雑度**（[[03_複雑度と分岐]]）と **セット** で判断します。  
20 行でも分岐が 10 個あれば分割を検討。

---

## 4. コメントが構造を代弁しているサイン

次のコメントは **Extract Method の候補** です。

```javascript
function handleRequest(req) {
  // --- 認証 ---
  if (!req.token) { /* 15 行 */ }

  // --- バリデーション ---
  if (!req.body) { /* 20 行 */ }

  // --- 本処理 ---
  /* ... */
}
```

**良いコメント** = なぜ（Why）を説明。  
**構造のコメント** = 関数に切り出すべきサイン。

---

## 5. 読み手の視線で関数を読む練習

**読み方の練習**:

1. **関数名だけ** を上から読む — ストーリーになるか
2. **インデント** を数える — 3 段以上あれば Guard Clause を検討
3. **抽象度** を確認 — 同じレベルか
4. **1 分で説明** — 口頭で何をする関数か言えるか

```text
  registerUser()
    → validateUser()      「入力を検証」
    → hashPassword()      「パスワードをハッシュ」
    → persistUser()       「DB に保存」
    → notifyNewUser()     「通知を送る」
```

---

## まとめ

- Clean Code = 小さく・少引数・浅いインデント
- 1 関数 = 1 抽象度
- 20 行は目安。複雑度とセットで判断
- 構造のコメント = Extract Method のサイン
