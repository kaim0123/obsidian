# 関心の分離と単一責任（SoC / SRP）

## この章の目的

**1 メソッド 1 種類の仕事** を実現する原則を学ぶ章です。  
関心の分離、単一責任、オーケストレーションと詳細の役割分担を押さえます。

---

## 1. 関心の分離（SoC）— 1 関数 1 種類の仕事

**関心の分離（Separation of Concerns, SoC）** とは、目的の異なる処理を **別の関数** に分ける原則です（Dijkstra, 1974）。

```javascript
// 悪い例: 関心が混在
function saveUser(user) {
  if (!user.email) throw new Error('invalid');  // 検証
  db.insert(user);                               // 永続化
  sendWelcomeEmail(user);                        // 通知
  logger.info('saved');                          // ログ
}

// 良い例: 関心ごとに分離
function validateUser(user) { /* 検証だけ */ }
function persistUser(user) { /* 保存だけ */ }
function notifyNewUser(user) { /* 通知だけ */ }
```

ソフトウェア設計全体での SoC は [[04_関心の分離]] を参照。ここでは **関数レベル** に焦点を当てます。

## 2. 単一責任の原則 — メソッド版（1 メソッド 1 責任）

**単一責任の原則（SRP）** は、クラス版で広く知られていますが、**メソッドにも適用** できます。

> 1 メソッドは **1 つの変更理由** だけを持つべき

| 変更理由 | 分離先 |
|----------|--------|
| 入力形式の変更 | `validate()` |
| 計算ルールの変更 | `calculateTotal()` |
| 保存方式の変更 | `save()` |

クラス設計での SRP は [[MOC_クラス設計体系|44 クラス設計]] で詳述します。

---

## 3. オーケストレーション関数と詳細関数の役割分担

**オーケストレーション関数** は流れを組み立て、**詳細関数** は 1 つの仕事を実行します。

```javascript
// オーケストレーション: 流れの目次
function registerUser(user) {
  validateUser(user);
  const hashed = hashPassword(user.password);
  persistUser({ ...user, password: hashed });
  notifyNewUser(user);
}

// 詳細: 1 つの関心
function hashPassword(plain) { /* ... */ }
```

オーケストレーション関数は **短く・同じ抽象度** に保ち、詳細は下位関数に委譲します。

---

## 4. `process()` `handleData()` 問題 — 名前で責任を表す

**曖昧な名前** は、責任が不明確なサインです。

| 悪い例 | 良い例 |
|--------|--------|
| `process()` | `calculateInvoiceTotal()` |
| `handleData()` | `parseCsvRows()` |
| `doStuff()` | `sendOrderConfirmationEmail()` |

「この関数、何をする関数？」と **一言で説明できる** 名前を付けます（[[01_命名]]）。

## 5. メソッド設計のチェックリスト

- [ ] このメソッドは **1 種類の関心** だけを扱っているか

## 6. 演習 — 関心のラベル付け

次の関数の行に **関心ラベル**（検証 / 計算 / 保存 / 通知）を付けてください。

```javascript
function registerUser(user) {
  if (!user.email) throw new Error('email required');
  const hash = bcrypt.hash(user.password);
  db.insert({ ...user, password: hash });
  mailer.sendWelcome(user.email);
}
```

**期待する分割**:

```javascript
function registerUser(user) {
  validateUser(user);
  const hashed = hashPassword(user.password);
  persistUser({ ...user, password: hashed });
  notifyNewUser(user.email);
}
```

## まとめ

- SoC = 目的の異なる処理を別関数に分ける
- SRP（メソッド版）= 1 メソッド 1 変更理由
- オーケストレーションは流れ、詳細は下位関数
- `process()` 問題は名前で責任を明確にする
