# メソッドの分割 — 最初の一歩

## この章の目的

**メソッドをどう切るか** の第一歩を学ぶ章です。  
1 つの関数に全部書かない理由、段階的詳細化、抽象度、粒度の判断を押さえます。

---

## 1. なぜ 1 つの関数に全部書いてはいけないか

1 つの関数にすべてを書くと、次の問題が起きます。

| 問題 | 具体例 |
|------|--------|
| 読めない | 300 行で何をしているか把握できない |
| 直せない | 表示を変えると DB 処理まで触る必要がある |
| 試せない | 計算ロジックだけテストできない |
| 再利用できない | 同じ検証をコピペする |

```javascript
// 悪い例: 全部入り
function handleOrder(order) {
  // 検証 50 行
  // 計算 80 行
  // 保存 40 行
  // メール 30 行
}
```

**分割** は、これらの問題を同時に緩和する最も基本的な技法です。

---

## 2. 段階的詳細化（トップダウン）— 大きく書いて小さく割る

**段階的詳細化（Stepwise Refinement）** は、Niklaus Wirth が提唱した方法です。

1. まず **問題全体を 1 つの手続き** として書く（詳細は仮名でよい）
2. 各ステップを **さらに小さな手続き** に置き換える
3. **同じ抽象度のステップ** が並ぶレベルで止める

```javascript
// 第 1 段階: 流れだけ
function processOrder(order) {
  validate(order);
  const total = calculateTotal(order);
  save(order, total);
  notify(order);
}

// 第 2 段階: 各ステップを実装
function calculateTotal(order) {
  const subtotal = sumItems(order.items);
  const tax = calculateTax(subtotal);
  return subtotal + tax;
}
```

---

## 3. 同じ抽象度のステップを並べる

**1 関数 = 1 抽象度** が目標です。高レベルの流れの中に、ビット演算や SQL が直書きされていると読めません。

```javascript
// 悪い例: 抽象度が混在
function processOrder(order) {
  if (!order.items) return;
  let total = 0;
  for (const item of order.items) {
    total += item.price * item.qty;  // 低レベルの詳細
  }
  db.query('INSERT INTO ...');       // インフラの詳細
}

// 良い例: 同じ抽象度
function processOrder(order) {
  validate(order);
  const total = calculateTotal(order);
  saveOrder(order, total);
}
```

詳細は [[01_サイズと抽象度]] でも扱います。

---

## 4. 粒度の判断 — 短すぎ・長すぎの見分け方

| サイン | 状態 | 対処 |
|--------|------|------|
| **長すぎ** | 50 行超、スクロールが必要 | Extract Method（[[04_Extract_Method]]） |
| **短すぎ** | 1 行関数が大量、全体像が見えない | 統合または上位関数でまとめる |
| **名前が説明できない** | 「何をする関数？」と言えない | 責任を見直す（[[02_関心の分離と単一責任]]） |

**目安**: Clean Code では 20 行程度を推奨しますが、**行数だけ** で判断しない（[[01_サイズと抽象度]]）。

---

## 5. 最初の関数分割ワークショップ

次の手順で、既存コードを分割してみましょう。

1. **200 行以上の関数** を 1 つ選ぶ
2. **コメントで区切られた塊** を見つける（「// 検証」「// 計算」等）
3. 各塊に **動詞 + 目的語** の名前を付ける
4. Extract Method で切り出し、元関数は **オーケストレーション** だけにする
5. テストを 1 つ書き、分割後も動くことを確認する

```text
  Before: handleRequest() 200 行
  After:  handleRequest() 15 行
          ├─ validateRequest()
          ├─ processOrder()
          └─ sendResponse()
```

---

## まとめ

- 1 関数に全部書くと読めない・直せない・試せない
- 段階的詳細化 = 大きく書いて、同じ抽象度になるまで小さく割る
- 粒度は長すぎ・短すぎ・名前で判断する
- コメント頼みの塊から Extract Method へ
