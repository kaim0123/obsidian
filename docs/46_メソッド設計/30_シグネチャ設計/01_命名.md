# 命名

## この章の目的

**関数名・メソッド名** の付け方を学ぶ章です。  
Clean Code の関数ルール、boolean の命名、検索しやすさ、チームでの統一を押さえます。

---

## 1. 関数名は動詞 + 目的語

関数名は **何をするか** が伝わる **動詞 + 目的語** にします。

| 悪い例 | 良い例 |
|--------|--------|
| `data()` | `fetchUserData()` |
| `process()` | `calculateInvoiceTotal()` |
| `handle()` | `sendOrderConfirmation()` |

```javascript
function validateOrder(order) { /* ... */ }
function calculateTax(amount) { /* ... */ }
function persistOrder(order) { /* ... */ }
```

**1 関数 1 動詞** — 複数の動詞（`validateAndSave`）は分割のサインです。

---

## 2. boolean は `is` / `has` / `can` / `should`

真偽値を返す関数・メソッドは **プレフィックス** で統一します。

| プレフィックス | 用途 | 例 |
|---------------|------|-----|
| `is` | 状態 | `isActive()`, `isEmpty()` |
| `has` | 所持・包含 | `hasItems()`, `hasPermission()` |
| `can` | 能力・可否 | `canSubmit()`, `canEdit()` |
| `should` | 推奨・条件 | `shouldRetry()`, `shouldNotify()` |

```javascript
function isValidOrder(order) {
  return order && order.items.length > 0;
}
```

CQS の Query として **副作用なし** で返す（[[01_CQS]]）。

---

## 3. 意図が伝わる名前 vs 短い名前

| 方針 | 向く場面 |
|------|----------|
| **意図が伝わる長い名前** | 公開 API、ドメイン用語 |
| **短い名前** | スコープが狭いループ変数（`i`, `item`） |

```javascript
// スコープが広い → 長く
function calculateOrderTotalWithTaxAndShipping(order) { /* ... */ }

// スコープが 3 行 → 短くてよい
items.forEach(item => sum += item.price);
```

**略語は避ける** — `calc` より `calculate`、`usr` より `user`（チームで例外を決める場合を除く）。

### 3.1 変数名も業務の用語で書く

関数名だけでなく、**ローカル変数・フィールド** も略語や1文字を避け、業務で通じる語に揃えます（『現場で役立つシステム設計の原則』第1章）。

```typescript
// 悪い例
const up = 100;
const qty = 3;
const a = qty * up;

// 良い例
const unitPrice = 100;
const quantity = 3;
const basePrice = quantity * unitPrice;
```

名前が長くなりすぎるときは、形容詞の積み重ねではなく **業務用語そのもの** がないかを疑うとよいです。計算途中の意図を変数に落とす技法は [[05_段落と説明用の変数]] を参照してください。

## 4. 検索しやすい名前（`handleData` 問題）

**曖昧な名前** は grep でも見つけにくく、責任も不明確です。

```javascript
// 問題: プロジェクト内に handleData が 50 個
function handleData(data) { /* 何をする？ */ }

// 改善: 具体的な名前
function parseCsvRows(data) { /* ... */ }
function validateUserInput(data) { /* ... */ }
```

**検索テスト**: 関数名でプロジェクトを検索し、**1 つの意図** に絞れるか確認します。

---

## 5. 命名規則とチームでの統一

チームで **命名規約** を決め、[[010Programming/59_AI開発ツール・コーディング規約/コーディング規約/目次|コーディング規約]] と連携します。

| 項目 | 例 |
|------|-----|
| ケース | `camelCase`（JS）、`snake_case`（Python） |
| プライベート | `_prefix` または `#` |
| テスト | `should_X_when_Y` または `test_X` |
| 禁止名 | `data`, `info`, `process`, `handle`（単独） |

**リファクタリング時** — IDE の Rename で一括変更し、テストで確認。

---

## 6. 演習 — リネーム候補を挙げる

次の関数名を **具体的な名前** に直してください。

| Before | After（例） |
|--------|-------------|
| `process(data)` | `parseCsvRows(data)` |
| `handle(e)` | `logAndRethrow(e)` |
| `check(x)` | `isValidEmail(x)` |
| `getData()` | `fetchActiveUsers()` |

**ルール**: 検索したとき **1 つの意図** に絞れる名前にする。

---

## まとめ

- 関数名 = 動詞 + 目的語
- boolean = `is` / `has` / `can` / `should`
- 意図が伝わる名前を優先。略語は避ける
- `handleData` 問題 — 具体的で検索しやすい名前へ
