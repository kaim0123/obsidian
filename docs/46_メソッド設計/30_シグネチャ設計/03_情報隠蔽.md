# 情報隠蔽 — 関数レベル

## この章の目的

**情報隠蔽** をメソッド設計に適用する章です。  
公開操作と内部ヘルパーの線引き、戻り値・引数の設計、クラス設計との関係を学びます。

---

## 1. 情報隠蔽（Parnas）のメソッドへの適用

David Parnas（1972）が提唱した **情報隠蔽** は、**変更しやすい詳細を内部に閉じる** 設計原則です。

メソッドレベルでは次のように適用します。

- **呼び出し側** は「何をするか」だけ知ればよい
- **実装の詳細**（計算の途中式、データ構造）は関数の中に隠す
- 内部表現が変わっても **公開インターフェース** が同じなら呼び出し側は変更不要

```javascript
// 内部の詳細を隠す
function getOrderTotal(order) {
  return calculateSubtotal(order) + calculateTax(order);
}
// 呼び出し側は税計算の式を知らなくてよい
```

---

## 2. 公開する操作と内部ヘルパーの線引き

| 種類 | 役割 | 命名・配置 |
|------|------|-----------|
| **公開 API** | 他モジュール・他クラスから呼ばれる | 明確な名前、ドキュメント |
| **内部ヘルパー** | 同ファイル・同クラス内だけ | `_` プレフィックスや `private` |

```javascript
// 公開
export function processOrder(order) { /* ... */ }

// 内部ヘルパー（モジュール内のみ）
function calculateTax(amount) { /* ... */ }
```

Java では `private`、JavaScript ではモジュールスコープや `#` プライベートフィールドを使います。

---

## 3. 戻り値 — 内部データ構造をそのまま返さない

**内部表現の漏洩** は、呼び出し側が実装に依存する原因になります。

```javascript
// 悪い例: 内部 Map をそのまま返す
function getItems(order) {
  return order._itemMap;  // 呼び出し側が Map に依存
}

// 良い例: 必要な情報だけ返す
function getItems(order) {
  return [...order._itemMap.values()];
}
```

クラス設計でのカプセル化（[[MOC_クラス設計体系|44 クラス設計]]）と同じ考え方を、関数の戻り値にも適用します。

---

## 4. 引数 — 呼び出し側が内部を知りすぎない

引数に **内部表現** を渡させると、結合度が上がります。

```javascript
// 悪い例: DB の行オブジェクトを直接渡す
function calculateDiscount(dbRow) {
  return dbRow.price * dbRow.discount_rate;
}

// 良い例: ドメインの概念だけ渡す
function calculateDiscount(price, discountRate) {
  return price * discountRate;
}
```

Parameter Object を使う場合も、**ドメインの言葉** で組み立てます（[[02_引数の設計]]）。

---

## 5. クラス設計のカプセル化との関係

```text
  クラス設計（カプセル化）
    ├─ フィールドを private に
    └─ 公開メソッドで操作
         │
         ▼
  メソッド設計（情報隠蔽）
    ├─ ヘルパー関数を内部に
    └─ 引数・戻り値で詳細を隠す
```

クラスは **型の境界**、メソッドは **処理の境界** です。両方で情報隠蔽を意識すると、変更に強いコードになります。

---

## 6. 演習 — 漏れている詳細を見つける

次のコードで **情報隠蔽が破れている箇所** を指摘してください。

```javascript
function getUserDisplayName(user) {
  return user._internalName.toUpperCase();  // ①
}

function sortOrders(orders) {
  return orders.sort((a, b) => a._priority - b._priority);  // ②
}
```

| 箇所 | 問題 | 改善 |
|------|------|------|
| ① | `_internalName` に依存 | `getDisplayName()` を User に |
| ② | `_priority` と in-place sort | `getSortKey()` + 非破壊 sort |

---

## まとめ

- 情報隠蔽 = 詳細を内部に閉じ、公開操作だけを提供
- 公開 API と内部ヘルパーを線引きする
- 戻り値・引数で内部表現を漏らさない
- クラスのカプセル化とメソッドの情報隠蔽は連動する
