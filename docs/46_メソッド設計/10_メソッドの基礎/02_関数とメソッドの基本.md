# 関数とメソッドの基本

## この章の目的

メソッド設計の **用語と土台** を押さえる章です。  
関数とメソッドの違い、構造化プログラミング、入出力と副作用、呼び出し関係の読み方を学びます。

---

## 1. 関数（function）とメソッド（method）の違い

| 用語 | 文脈 | 例 |
|------|------|-----|
| **関数** | 手続き型・関数型 | `calculateTotal(items)` |
| **メソッド** | オブジェクト指向 | `order.calculateTotal()` |

設計上の論点（分割・命名・副作用）は **ほぼ同じ** です。本教材では **メソッド** を主語にしつつ、関数型の **純粋関数** も含めて扱います。

```javascript
// 関数
function calculateTotal(items) { /* ... */ }

// メソッド
class Order {
  calculateTotal() { /* ... */ }
}
```

---

## 2. 手続き（サブルーチン）— 名前付きの処理単位

**手続き（サブルーチン）** とは、名前を付けた **処理の塊** です。Fortran の SUBROUTINE から始まり、現代の関数・メソッドの原点です。

```javascript
function validateOrder(order) { /* 検証だけ */ }
function saveOrder(order) { /* 保存だけ */ }
function notifyCustomer(order) { /* 通知だけ */ }
```

「ここからここまでが検証」が **行番号とコメント** ではなく **関数名** で表現されます。これがメソッド設計の出発点です。

---

## 3. 構造化プログラミング — 順次・分岐・反復

Dijkstra が提唱した **構造化プログラミング** は、制御を次の 3 つだけで組み立てます。

- **順次** — 上から順に実行
- **分岐** — `if` / `switch`
- **反復** — `for` / `while`

`goto` を排除し、**制御フローを予測可能** にします。メソッド設計では、分岐の深さ（[[02_Guard_Clause]]）や複雑度（[[03_複雑度と分岐]]）が重要な論点になります。

---

## 4. 入力（引数）・出力（戻り値）・副作用

メソッドは **入出力** と **副作用** で理解できます。

| 要素 | 説明 | 例 |
|------|------|-----|
| **入力** | 引数 | `calculateTotal(items, taxRate)` |
| **出力** | 戻り値 | `return total` |
| **副作用** | 戻り値以外の影響 | DB 保存、ログ出力、グローバル変数の変更 |

```javascript
// 副作用あり: 戻り値に加えて DB を更新
function saveAndReturnTotal(order) {
  const total = calculateTotal(order);
  db.save(order, total);  // 副作用
  return total;
}
```

副作用の分離は [[02_純粋関数と副作用]]・[[03_Functional_Core_Imperative_Shell]] で詳しく扱います。

## 5. 関数の呼び出し関係を読む（入門）

メソッド設計では **誰が誰を呼ぶか** を読む力が必要です。

```text
handleRequest()
  ├─ validateRequest()
  ├─ processOrder()
  │    ├─ calculateTotal()
  │    └─ applyDiscount()
  └─ sendResponse()
```

**読み方のコツ**:

1. **上から下** — オーケストレーション関数は「流れの目次」
2. **深さを制限** — 3 段以上ネストしたら分割を検討
3. **名前で意図** — `process()` より `calculateTotal()` が具体的

クラス間の関係は [[MOC_クラス設計体系|44 クラス設計]]、モジュール間の関係は [[010Programming/43_モジュール設計/00_全体像/目次|43 モジュール設計 目次]] で扱います。

## 6. 練習 — 呼び出し関係を描く

次のコードの **呼び出し関係** を紙に描いてみましょう。

```javascript
function checkout(cart) {
  validateCart(cart);
  const total = calculateTotal(cart.items);
  applyCoupon(cart, total);
  chargePayment(cart.payment, total);
  return { orderId: cart.id, total };
}
```

```text
  checkout
    ├─ validateCart
    ├─ calculateTotal
    ├─ applyCoupon
    └─ chargePayment
```

**問い**: `calculateTotal` だけ単体テストしたいとき、他の関数を起動する必要があるか？  
→ ない。これが分割のメリットです。

---

## まとめ

- 関数とメソッドは文脈の違い。設計上の論点は共通
- 手続き = 名前付きの処理単位。分割の第一歩
- 構造化 = 順次・分岐・反復で制御を組み立てる
- 入出力と副作用を意識してメソッドを読む・書く
