# オブジェクトのメソッド

## この章の目的

**OOP におけるメソッド設計** を学ぶ章です。  
Tell, Don't Ask、貧血モデル、ドメインルールの配置、手続き型との使い分けを押さえます。

---

## 1. 状態に対する操作としてメソッドを定義する

OOP では、メソッドは **オブジェクトの状態に対する操作** として定義します。

```javascript
class Order {
  constructor(items) {
    this.items = items;
    this.status = 'draft';
  }

  calculateTotal() {
    return this.items.reduce((s, i) => s + i.price * i.qty, 0);
  }

  submit() {
    if (this.status !== 'draft') throw new Error('already submitted');
    this.status = 'submitted';
  }
}
```

データ（`items`, `status`）と振る舞い（`calculateTotal`, `submit`）が **同じクラス** にまとまります。

---

## 2. Tell, Don't Ask — データを取り出さずお願いする

**Tell, Don't Ask** = オブジェクトの内部を **取り出して判断せず**、**お願い（メッセージ）** する。

```javascript
// 悪い例: Ask（中身を取り出して判断）
if (order.status === 'draft' && order.items.length > 0) {
  order.status = 'submitted';
}

// 良い例: Tell（オブジェクトにお願い）
order.submit();
```

ロジックが **呼び出し側** に散らばると、変更時に複数箇所を直す必要があります。

---

## 3. 貧血モデル — ロジックがサービスに逃げる問題

**貧血モデル（Anemic Domain Model）** とは、エンティティが **データ入れ物** で、ロジックが **サービスクラス** に集中した状態です。

```javascript
// 貧血: Order はデータだけ
class Order {
  constructor(items, status) {
    this.items = items;
    this.status = status;
  }
}

// ロジックが OrderService に集中
class OrderService {
  submit(order) {
    if (order.status !== 'draft') throw new Error('...');
    order.status = 'submitted';
  }
}
```

**問題**: ドメインルールがサービスに散在し、**Order の不変条件** がクラス外に漏れる。  
**対策**: ルールを `Order.submit()` 等の **メソッドに移す**。

---

## 4. ドメインルールをメソッドに置く

**変更理由がドメイン** のルールは、ドメインオブジェクトのメソッドに置きます。

```javascript
class Order {
  submit() {
    if (this.status !== 'draft') {
      throw new Error('Order must be draft to submit');
    }
    if (this.items.length === 0) {
      throw new Error('Order must have items');
    }
    this.status = 'submitted';
  }

  isSubmittable() {
    return this.status === 'draft' && this.items.length > 0;
  }
}
```

`isSubmittable()` は Query（副作用なし）、`submit()` は Command（[[01_CQS]]）。

---

## 5. 手続き型関数 vs OOP メソッドの使い分け

| 向く場面 | 手続き型関数 | OOP メソッド |
|----------|-------------|-------------|
| 状態を持たない変換 | ◎ `formatDate()` | △ |
| 1 オブジェクトのルール | △ | ◎ `order.submit()` |
| 複数オブジェクトの協調 | ◎ オーケストレーション関数 | △ サービス |
| ユーティリティ | ◎ `clamp(value, min, max)` | △ |

**方針**: ドメインルールはオブジェクトに、**横断的・無状態** の処理は関数に。  
クラス設計の詳細は [[MOC_クラス設計体系|44 クラス設計]] を参照。

## まとめ

- メソッド = 状態に対する操作
- Tell, Don't Ask — 取り出さずお願いする
- 貧血モデルはロジックをサービスに逃がす問題
- ドメインルールはメソッドに。手続き型との使い分けを意識
