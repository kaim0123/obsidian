# 付録B　メソッド設計チェックリスト（総合版）

メソッド設計のレビューや自己点検に使えるチェックリストです。

---

## 1. 分割と責任

- [ ] 1 メソッド 1 種類の仕事（SoC）
- [ ] 1 メソッド 1 変更理由（SRP）
- [ ] オーケストレーション関数と詳細関数が分離されている
- [ ] `process()` `handleData()` 等の曖昧名がない
- [ ] 同じ抽象度のステップが並んでいる

---

## 2. サイズと複雑度

- [ ] 1 関数 50 行以内（目安 20 行）
- [ ] 循環的複雑度 10 以下
- [ ] ネスト 3 段以内
- [ ] 引数 3 個以下、または Parameter Object

---

## 3. 制御フロー

- [ ] Guard Clause で異常系を先に処理
- [ ] 正常系が一直線に読める
- [ ] フラグ引数で複数責任を切り替えていない

---

## 4. 契約と副作用

- [ ] CQS — getter / `is` / `has` に副作用なし
- [ ] 純粋にできる計算が I/O と分離されている
- [ ] Fail Fast — 前提条件を入口でチェック
- [ ] 内部データ構造をそのまま返していない

---

## 5. 命名と読みやすさ

- [ ] 関数名は動詞 + 目的語
- [ ] boolean は `is` / `has` / `can` / `should`
- [ ] コメントが構造を代弁していない（Extract Method 済み）

---

## 6. テストと品質

- [ ] 主要ロジックが単体テスト可能
- [ ] モックが 3 個以上必要な関数がない
- [ ] エラー処理が境界（Shell）に集約されている

---

## 使い方

| 場面 | 重点セクション |
|------|---------------|
| 新規関数作成 | 1〜5 |
| リファクタリング前 | 1〜4 と 6 |
| コードレビュー | 全体 |
| レガシー改善 | 2 と 4 を優先 |
