## 詳しい要約

**テーマ：GPU はなぜ「賢い CPU を多数並べる」方式に勝ったのか**

CPU と GPU の違いを「社長」と「経理部」にたとえて説明する回。CPU は判断（制御）・保存・演算を行うが、GPU は判断をせず保存と演算だけを大量の人数で一斉に行う。判断役を増やすと互いの調整コストが爆発する（船頭多くして船山に上る）ため、判断しない「指示待ちソルジャー」を大量に並べた GPU の方が、単純計算が大量に必要な画像処理やディープラーニングで効率がよい、というのが結論。

---

### よくある説明とその不可解な点

- 一般向けの説明：「CPU は賢いが少人数、GPU はアホだが大人数」。
- しかしそれなら「賢い CPU を大人数にすればよい」はず。実際 2013年ごろに CPU を大量に詰め込むアプローチ（Xeon Phi 系）もあったが、GPU に負けた。
- 専門家向けの説明（ハードウェア・マルチスレッディング、レイテンシよりスループット重視など）は難しすぎる。その中間の説明をするのが今回の狙い（厳密な用語運用は捨てると断っている）。

### CPU＝社長、GPU＝経理部

- **CPU（中央演算処理装置）** はどのコンピューターにも必ずある中心。会社法で必ず置かれる社長のようなもの。
- **GPU（画像処理装置）** は画像処理に特化した追加装置で、積んでいない PC もある。大企業にしかない経理部のようなもの。
- 「今は CPU より GPU の時代」というのは、市場での存在感・儲けの面では正しいが、コンピューターの構造上は CPU がないと動かないので CPU の方が重要。
- CPU が指示を出し、GPU が動く、という関係も社長と部署に対応する。

### 判断（制御）をするかどうかの違い

- CPU の仕事は大きく **判断・保存・演算** の3つ。GPU は **保存・演算** の2つで、判断はしない「指示待ち」。
- CPU の判断とは**制御**のこと。例：プログラム実行中にキーボード入力が来たら割り込んで先に処理する（**割り込み制御**）。ほかに分岐予測、投機実行、アウトオブオーダー実行など。
- OS も CPU と密接に連携して判断を担う（とっさの判断は CPU、猶予のある複雑な判断は OS という傾向で、「社長と前社長の院政」のようなイメージ）。OS には物理的実体はない。
- GPU は大量のレシートを全員で手分けして入力するように、**同じ単純作業を一斉に**こなす。

### なぜ CPU 多数ではダメなのか

- 判断役が複数いると、互いの判断を毎回うかがう手間が発生し、人数が増えるほど**加速度的に大変**になる（社長が2人いる会社、議員が多すぎる議会のイメージ）。
- 具体例：CPU A と B が同じメモリ番地（100番地）を別々に書き換えようとすると矛盾するため、毎回確認が必要になる。この一貫性を保つこと（**キャッシュコヒーレンシ**）のコストが CPU を多数にできない本質的な理由の一つ。
- 本来の演算より周囲とのコミュニケーションコストばかりが増えた。優秀な人だけを集めると権力闘争で仕事が進まない、という『知性の罠』の話とも重なる。
- 判断能力を持つ CPU は作るのが大変でコストも高い、という理由もある（ただしそれだけではつまらないので今回は構造面を強調）。

### 現代は単純作業の需要が爆増

- **ディープラーニング**の学習・推論は、単純な足し算などの計算の膨大な繰り返し。
- **画像処理**も単純計算の塊。写真を明るくするなら、何百万画素それぞれの赤・緑・青の値を2倍にする計算を一気に行う。コンピューターは絵全体を見ず画素ごとに論理的に処理する。
- こうした単純作業が大量に増えたため、判断しないソルジャーを大量に抱える GPU がありがたい時代になった。

### まとめ

- CPU は判断（制御）をする社長、GPU は言われた単純作業を大人数で一斉にこなす部署。
- 判断役を増やすと調整コスト（キャッシュコヒーレンシなど）が爆発するため、CPU の多数化は失敗し GPU が勝った。
- 画像処理や AI のような大量の単純計算の需要増が GPU の価値を押し上げた。コンピューターの中の構造は人間の組織とよく似ている。
