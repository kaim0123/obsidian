## 詳しい要約

メモリを増やしてもすぐ足りなくなる——この体感は **60 年以上前から繰り返されている構造** である。本動画は、パンチカードから **HBM（High Bandwidth Memory）** まで、コンピュータ記憶装置の進化を辿りながら、**なぜ「メモリ不足」は技術の問題ではなく人間の欲望の問題なのか** を霊夢と魔理沙の対話形式で解説する。核心メッセージは **「余裕ができる → 使い切る → 足りなくなる → 工夫する → また余裕ができる」** というループが一度も止まっていない、ということ。

### テーマと問い

- **メモリを増やしても重くなる**、**スマホはすぐアプリを落とす**、**AI は毎秒テラバイト級の帯域を要求する**——いずれも「足りない」という同じ感覚の現れ。
- メモリの歴史は **人間の欲望の歴史** でもある。より多く、より早く記憶したいという衝動は、パンチカードも DRAM も HBM も同じ根から生まれた。
- 結論：**メモリ不足はバグではなく人間の本質**。足りないという焦りが次の知恵（仮想メモリ、キャッシュ、HBM 等）を生んできた。

### 第 1 章——記憶装置の黎明期（物理現象で記憶する時代）

コンピュータ黎明期、**プログラムの保存** と **作業用メモリ（RAM）** は別物だった。

| 技術 | 仕組み | 特徴・問題 |
|------|--------|-----------|
| **パンチカード** | 紙の決まった位置に穴を開けて 1/0 を表現 | プログラムの読み込み用。修正は「紙を切り直す」物理作業。デバッグが文字通り格闘 |
| **水銀遅延線メモリ** | 缶の中の水銀に音波を流し、伝播の遅れで信号を一時保存 | 信号をループさせて維持。**温度で音が変わり**、冬と夏で挙動が変わる。有毒 |
| **ウィリアムズ管** | ブラウン管の画面に電子ビームで点を描き、電荷で 1/0 を記録 | 電源中は描き直し続ける必要あり（揮発性） |
| **磁気ドラム** | 回転する金属ドラム表面に磁気を記録 | ヘッドの前に来るまで待つ必要あり（**1 周 ≈ 16 ms**）。プログラマーは回転タイミングを計算してコードを配置 |

- 当時の容量は **KB 以下**。今のスマホ写真 1 枚の数万〜数十万倍の情報量差。
- 用途は **弾道計算・統計処理・暗号解読** など。コンピュータの黎明は **軍の要求** と切り離せない。

### 第 2 章——磁気コアメモリ（手編みの革命）

**1950 年代〜1970 年代** の主役。**フェライト（酸化鉄）の小さなリング**（直径 1〜2 mm）に磁化の向きで 0/1 を記録。

- **ランダムアクセス** が可能に——磁気テープの「順番読み」から脱却。プログラム設計の根本（サブルーチン、データ構造）が変わった。
- **非揮発性**——電源が切れても磁化の向きが残る。**アポロ計画の誘導コンピュータ** に搭載された「手編みのメモリ」。
- 製造は **職人が 1 ビットずつ針金を通す** 手作業。1 ビットあたり数百円相当のコスト。**1 ビットも無駄にしない** プログラミング文化が生まれた。
- 量産・小型化の限界 → **シリコン半導体** への移行が必然に。

### 第 3 章——640 KB の壁と DRAM 革命

#### 640 KB の壁

- IBM PC 設計時、1 MB のアドレス空間の **上位 384 KB を BIOS・ビデオカード等に予約**（メモリマップ I/O）。プログラムが使えるのは **640 KB のみ**。
- 「640 KB あれば誰にでも十分」は **ビル・ゲイツの発言として確認できる記録はない** 都市伝説——だが **640 KB という壁自体は本当** に存在した。
- 対策として **UMB・EMS・XMS** など、予約領域を無理やり使う **クソ技** が乱立。

#### DRAM（1970 年〜）

| 項目 | 内容 |
|------|------|
| **世界初の商用 DRAM** | 1970 年 **Intel 1103**（1 チップ 1024 ビット） |
| **仕組み** | トランジスタ 1 個 + コンデンサ 1 個で 1 ビット。電荷の有無で 0/1。**定期的なリフレッシュ** が必要（穴の開いたバケツに水を足し続けるイメージ） |
| **製造革命** | フォトリソグラフィで **ウェハから一括量産**。磁気コアの手編みから **10 年足らずで駆逐** |
| **2025 年現在も** | 材料・プロセスは進化したが、**電荷を貯めてリフレッシュする根本原理は 1970 年と同じ** |

- **1980 年代**：512 KB → 1 MB → 4 MB と数年単位で倍増。「4 MB あれば何でもできる」と本気で思われた時代があった。
- **シリコンサイクル**：工場建設費が数千億〜数兆円規模。赤字でも稼働を続ける → 供給過剰 → 価格暴落 → 工場閉鎖 → 供給不足 → 価格急騰、のループが **今も続く**。
- **1980 年代の日本**：NEC・東芝・日立が世界 DRAM 市場の **8 割近く** を掌握。クリーンルーム管理と歩留まりの高さが競争力の源泉。

### 第 4 章——仮想メモリ（「嘘」が世界を救った）

**1960 年代アトラスコンピュータ** に遡る発想。OS が **実際にはないメモリをあるように見せる** 仕組み。

| 概念 | 説明 |
|------|------|
| **ページ** | メモリを固定サイズ（現代では約 4 KB）の単位に分割 |
| **スワップ** | 使っていないページを HDD のスワップ領域に追い出し、必要時に取り出す（机の引き出しに書類をしまうイメージ） |
| **プロセス分離** | 各プログラムが独立した仮想アドレス空間を持つ → **マルチタスク・セキュリティの基盤** |
| **ページフォルト** | 必要なページが HDD に追い出されていた時に発生。頻発すると **スラッシング**（HDD ランプ点滅・フリーズ状態） |

- **Windows・Linux が成立した前提**。Photoshop の巨大画像、ブラウザの多数タブも、全部のデータが同時に RAM に乗っているわけではない。
- 副作用：**メモリが足りない恐怖が薄れた途端、ソフトウェアが肥大化**。「嘘が大家に火をつけた」——安いメモリが **最適化を後回しにする言い訳** になった。

### 第 5 章——ソフトウェア肥大化とヴィルトの法則

| 時期 | メモリ価格・容量 | ソフトウェアの変化 |
|------|-----------------|-------------------|
| **1990 年代前半** | 1 MB あたり **数万円**。16 MB PC はメモリだけで数十万円 | 制約の中で作られた |
| **1990 年代後半** | 1 MB が **数十円** まで暴落。16 MB → 256 MB → 512 MB → 1 GB | Windows 95/98/XP 普及で **初めてメモリを使い切らない** 状態を経験 |
| **Windows** | 95 の最低 4 MB → XP の 128 MB（**30 倍以上**） | |
| **Office** | 95 が数 10 MB → 2003 が 200〜400 MB | 機能追加以上に **「どうせメモリはある」前提** への設計変更 |
| **Chrome** | タブ 0 でも数百 MB 消費 | 2001 年頃の **タブブラウジング** が便利すぎてタブ乱開き → メモリ消費 |

- **ヴィルトの法則（Wirth's Law）**：**ハードウェアの速度が 2 倍になるより早く、ソフトウェアが重くなる**。
- 皮肉な補強：ムーアの法則（CPU が 18 ヶ月で 2 倍）に対し、ソフトは 18 ヶ月で **それ以上** 重くなる。
- 構造的原因：締め切り・競争・予算の制約下では **最適化は最後の優先順位**。「後で最適化しよう」が「今のハードで動くから」に変わる。
- **メモリを 2 倍にすれば、ソフトも 2 倍の容量を使い切る**——立ち往生のいちごっこ。

### 第 6 章——速さの壁（メモリ量からメモリ帯域へ）

#### CPU と DRAM の速度差

| 時代 | 状況 |
|------|------|
| **1990 年代** | CPU クロックが毎年 50〜60% 向上 |
| **2000 年代〜** | 熱・電力の壁で **4〜5 GHz 台で頭打ち** |
| **DRAM** | アクセス速度の向上は **年率 7% 程度** のみ |
| **2000 年代初頭** | CPU と DRAM の速度差が **100 倍以上** に。CPU 実行時間の **半分以上がメモリ待ち（ストール）** という研究も |

#### キャッシュ階層

| レベル | アクセス時間（目安） | 容量 |
|--------|---------------------|------|
| **L1** | ナノ秒オーダー | 数十〜数百 KB |
| **L2** | 数ナノ秒 | 数百 KB〜数 MB |
| **L3** | 数十ナノ秒 | 数 MB〜数十 MB |
| **DRAM** | 60〜100 ナノ秒 | GB 単位 |

- **倉庫（DRAM）と CPU の間に棚（キャッシュ）** を置く発想。**局所性**（同じデータへの繰り返しアクセス）が効果を発揮する前提。
- **キャッシュヒット率** が下がると一気に遅くなる。

#### WinFS の失敗（Longhorn）

- Windows Longhorn 開発中の **WinFS**——全ファイルをデータベース化し SQL で検索する壮大構想。
- 深刻な **メモリリークと性能問題**。有効化するだけでビルド全体が使い物に。**2004 年に Longhorn 開発リセット**、WinFS は製品化されず。
- **2006 年 Vista → 2009 年 Windows 7** へ。失敗の教訓が設計に折り込まれ、7 は Vista より確実に軽快になった。

### 第 7 章——スマホ・GPU・AI 時代

#### スマホ——PC と逆の哲学

| 項目 | PC | スマホ |
|------|-----|--------|
| **設計思想** | メモリを増やす方向 | **少ないメモリで快適に動かす** |
| **2007 年 iPhone** | — | RAM **128 MB** |
| **バックグラウンド** | アプリを生かし続ける | **使っていないアプリを容赦なく終了**（メモリ節約） |
| **ストレージ vs RAM** | 混同しにくい | **16 GB/32 GB 表示はストレージ**。実際の RAM は 4〜8 GB が普通 |

- **Apple Silicon の統合メモリ**：CPU と GPU が同じメモリ空間を共有 → **データコピーが不要** になり、速度・電力効率が向上。

#### GPU・VRAM・HBM

- **GPU** は昔の「画面を映す人」から **並列演算の巨大工場** へ。3D ゲーム・AI の行列計算に **大量データの高速出入り** が必要 → **VRAM（GPU 専用メモリ）**。
- **HBM（High Bandwidth Memory）**：
  - 従来 GDDR は基板に **横並び**、HBM は DRAM チップを **縦に多層積み**、**TSV（シリコン貫通電極）** で接続。
  - 配線経路が短い → 同じ面積に **何倍もの配線** → **帯域幅が桁違い**（HBM3E は **毎秒 1 TB 超**）。
  - 課題：熱・製造コスト・消費電力。
- **AI のボトルネック**：
  - 大規模 LLM はパラメータが **数百 GB**。推論のたびに重みを何度も読み返す → **計算より読み出し帯域がボトルネック**。
  - NVIDIA H100 は HBM 帯域 **毎秒 3.35 TB** でも、推論時のハードウェア活用率は **数 %** 程度——アクセスパターンが不規則で連続読み出しができないため。
  - **量の問題から帯域の問題へ** シフトしている。

### 結論——永遠に解決しないループ

```
余裕ができる → 使い切る → 足りなくなる → 工夫する（新技術） → また余裕ができる → …
```

- パンチカード → 水銀 → 磁気コア → DRAM → 仮想メモリ → キャッシュ → HBM。形は違えど **同じ欲求** から生まれた。
- メモリの壁を超えても **電力・冷却** が次の壁になる（大規模 AI 学習に原子力発電所 1 基分の電力という試算も）。
- **60 年前のプログラマーと、今日の AI エンジニアが同じことを言っている**——舞台も桁も変わったが、言っていることは変わらない。
- 失敗（WinFS 等）も **学習コストとして次に回収** される。メモリ不足は **進歩の燃料** でもある。
- 視聴者への実践的アドバイス：**タブを閉じる** のが 1 番の節約。

### 補足——要約に含めきれなかった技術・背景

#### 黎明期の「消去法」の選択

水銀遅延線が採用されたのは、当時の他手段に致命的な欠点があったため。

| 代替技術 | 却下理由 |
|----------|----------|
| **真空管メモリ** | 繊細すぎて実用に耐えない |
| **磁気テープ** | 順次アクセスのみで遅すぎる |
| **水銀遅延線** | 有毒・温度依存だが、大量生産可能な現実解だった |

磁気ドラム時代のプログラマーが **回転タイミングを計算して命令を配置** していたのは、現代の **キャッシュヒット率を意識する最適化** と本質的に同じ「泥臭い最適化」である——舞台が物理ドラムからシリコンキャッシュに変わっただけ、という動画の主張。

#### 投機的実行（Out-of-Order Execution）

キャッシュで誤魔化しても CPU–DRAM の速度差は本質的に残る。現代 CPU はこれに加え **投機的実行** で対処する。

- メモリ待ちの間、**次に何を計算するか予測** して先に処理を進める。
- 予測が当たれば待ち時間を有効活用できる。
- 外れるとやり直しが発生し、**むしろ遅くなる** こともある。
- 根っこは変わらない——「CPU は速いがデータが届かない」構造は今も続いている。

#### ブラウザ戦争とタブブラウジング（2001 年頃）

ソフトウェア肥大化の具体例として、ブラウザの歴史が詳しく語られる。

- **Internet Explorer・Netscape・Firefox** がシェアを争った時代。
- **2001 年前後にタブブラウジング登場**——新しいページを開くたびに別ウィンドウが増える問題を解決した革命。
- 便利すぎて **何十枚もタブを開く習慣** が定着。タブ 1 枚ごとにページ分のメモリを消費。
- 「タブを開きすぎて PC が重い」は **2000 年代前半からの古い悩み** であり、最近の話ではない。

#### WinFS 失敗の波及経路

| 年 | 出来事 |
|----|--------|
| **開発中** | WinFS 有効化だけで Longhorn ビルド全体が実用不能レベルに。XP より体感が遅い |
| **2004 年** | Microsoft が Longhorn 開発を **リセット**、コードを 1 から書き直し |
| **2006 年** | Longhorn から WinFS を切り離し、製品化は断念 |
| **2006 年 Vista → 2009 年 Windows 7** | 失敗の教訓が設計に折り込まれ、7 は Vista より確実に軽快に |

#### AI 推論のボトルネック（詳細）

- 大規模 LLM のパラメータは **数百 GB**。推論のたびに全重みをメモリに載せ、**何度も読み返す**。
- イメージ：**100 万人分の辞書を読み返しながら会話している** ような負荷。
- **NVIDIA H100**：HBM 帯域 **毎秒 3.35 TB** でも、推論時のハードウェア活用率は **数 %** 程度。
- 原因：行列演算なら連続読み出しで帯域をフル活用できるが、LLM 推論は **アクセスパターンが不規則** で、飛び飛びの読み出しになり帯域を使い切れない。
- **量の問題から帯域の問題へ**——「どれだけ早くデータを運べるか」が勝負の軸に移った。

#### 次の壁——電力と冷却

メモリの壁を超えても問題は消えず、形を変えて現れる。

- 大規模 AI 学習には **原子力発電所 1 基分に迫る電力** が必要という試算も紹介される。
- **60 年前のプログラマー** と **今日の AI エンジニア** が同じ「足りない」と言っている——舞台・道具・桁は変わっても言葉は同じ。

| 比喩 | 対応する概念 |
