#unix #歴史

## 要約

今日あたりまえに使う `ls` / `cd` / `grep`、その下で動く macOS・Linux、そして多くの言語の土台——その源流をたどると、しばしば **ケン・トンプソン（Ken Thompson）** に行き着く。動画は技術教科書ではなく、「自分が使いたい道具を追い求めた」一人のエンジニアの物語として、次の4つをほどく。

1. なぜ Unix はシンプルなのか  
2. なぜ C 言語は世界を制したのか  
3. grep はどこから来たのか  
4. Go が生まれた本当の理由  

### 少年時代：作る・二進数・合理性

1943年生まれ。海軍パイロットの父の転勤で米各地・東京・横浜・ナポリを転々とし、行く先でゼロから何か作り直す少年になる。日本ではフェンスの鉄線で友達宅までの電話線を自作。飛行機の廃材でラジオやロボットも作った。手回し計算機を手にし「なぜ10進数か？指が10本だから」と気づき、5進・4進・**2進**を試し、宿題を全部二進数で提出した逸話も残る——面倒を減らすために世界の見方自体を書き換える合理性が生涯を貫く。

UC Berkeley で電気工学。数学・物理一辺倒の最初の2年は乗り気でなく、3年で誰も使わない古いドラム式コンピュータに出会い、夜な夜な打ち込む（「火炎みたいな中」）。キャンパスのマシンの鍵・パスワードを握り、メインフレームを深夜に独占。コンピュータは勉強道具ではなく遊び道具。バイナリで根から考える力・欲しいものは自分で作る執着・面倒を徹底的に減らす合理性——これが後の Unix / C / Go の設計思想になる。

### ベル研究所と Multics からの撤退

1966年、ベル研究所入所（トランジスタも生んだ世界最高峰の研究所。締め切りも売る相手もない自由さが鍵）。採用理由は **Multics**（MIT・GE・ベルの次世代巨大OS、タイムシェアリングを究極まで）。何でもできる最高を目指し恐ろしく複雑化（ユーザーマニュアルだけで本棚約2.4m分とも）。トンプソン曰く「信じられないほど過剰に設計されていた。生まれる前から死んでいた」。主導権争いと遅延の末、ベルは撤退し「もうOS開発はするな」と通達。巨額マシンだけが残り、少年時代の衝動が蘇る——**自分が気持ちよく作業するためのOS**が欲しい。

### Unix：非力な PDP-7 と「複雑さのアンチ」

巨大マシンではなく、片隅の非力なミニコン **PDP-7** をあえて選ぶ。きっかけは自作ゲーム Space Travel を滑らかに動かすためマシンを隅々まで制御したかったこと。最初はディスク読み書きの高速化など地味な課題から始まり、一つ解くと次が生まれ、気づくとファイルシステムもプロセス管理も揃う——「知らないうちにそれはOSになっていた」。妻子が実家に帰った約3週間で、エディタ・アセンブラ・複数ユーザー機構を一人で書き上げ、Unix の原型になる。

名前の由来：**Multics** の反省から、単一・シンプルを超えて **Unix**（複雑さのアンチ）。設計思想は「1つのことだけをうまくやる小さな道具をたくさん作り、パイプでつなぐ」。研究所内で熱狂的に広がるが最初のユーザーIDは1桁（10人未満）。その輪にデニス・リッチーがいた。OS禁止のため「特許文書処理システム」と言い換えて予算を取り、秘書が特許を打つ裏で成長。ソースは誰でも読め書き直せ、「触ったらお前のもの」——後のオープンソース文化の遠い源流の一つとも。制約が Unix をシンプルに研ぎ澄ました。

### 正規表現と grep

Unix 以前、毎日使う最高の道具としてテキストエディタ **QED** を自分好みに改良。文字検索を **パターン検索（正規表現）** に進化させる（例: `a*`）。概念自体は有限オートマトンなど数学にあり、大学で学びソフトウェア検索に応用。きっかけは古典文学テキスト解析のバイト。エディタに `g`（全マッチ行に処理）を加え、代表的用法 `g/正規表現/p`（マッチ行を表示）＝ **Global Regular Expression Print** → **grep**。ベル研究所は当時ソフト特許不可の立場に対し、検索アルゴリズムをハードウェア回路として偽装して特許を取り、世界初級のソフト特許の一つに（本人はこれが最初で最後の特許だったと）。

### B言語から C言語へ、そして移植性

初期 Unix はアセンブリ。マシン依存で読み書きがつらいため、4KB制約下で **B言語** を自作。弱点は型がなく、文字も整数も同じワード扱い——メモリ無駄でハード制御にも弱い。リッチーがバイト扱い・型（char / int 等）・構造体を導入し、データに意味と大きさを与える。B の次なので **C**（1972年頃）。二人はアセンブリの Unix を C で丸ごと書き直す常識外れの挑戦に出て、失敗を経て3度目で成功（1973年）。

魔法は **移植性**——コンパイルし直せば別メーカーのマシンでも動く。特定ハードに縛られないOSが世界標準へ広がり、子孫が今の Mac / Linux に至る。長く生き残れた理由をトンプソンは「ベル研究所だったから」と——プレッシャーも待つユーザーもなく、売りの製品ですらなく、良いものを突き詰められる自由。

### チューリング賞・Plan 9・UTF-8

1983年、二人でチューリング賞。受賞講演は「コンパイラ自体に裏口を仕込むと、ソースに痕跡が残らず信頼できない」——「自分で完全に作っていないコードを本当に信頼することはできない」という今なお有効な警告。

Linux 成功の後、ロブ・パイクと次世代OS **Plan 9**。複数マシンをネットワークで1台のように扱う分散構想。「すべてがファイル」を極限まで（例: あるファイルに `9600` と書くだけで端末速度が変わる）。トンプソンは最高のOSと語るが、Webブラウザがなく商業的には Unix ほど振るわず。一方、食堂のナプキンでパイクと **UTF-8** を書き上げ——英語は少ないデータ量のまま、世界中の文字を表現でき、一晩で実装・標準化会議に提出、ウェブの文字表現の主流に。

### ベル研究所を去り、Google、そして Go

2000年頃、ベル分割で自由な空気が失われ「やってることをいちいち正当化」しなくてはならなくなり34年のベルを去る。Google に招かれ（赤いワゴンでグッズを送る熱烈な口説き）、最初は **Google Books**（世界の本のスキャン）。当時 Google の巨大系は主に C++ で、コンパイルが絶望的に遅い（10行でも依存追跡で数百万行・100台で15分待ちなど）うえ、言語自体が複雑化しすぎ、「改良は言語本体より大きく見えた」。

2007年、トンプソン・パイク・ロバート・グリーゼマーが「新しい言語を作ろう」→ **Go**。現場の問題（パイク）× 言語・コンパイラ経験（トンプソン）× 言語理論（グリーゼマー）。ルールは「3人全員が納得しない限り機能を入れない」。C++ への反発から機能を削ぎ落とす——Unix / B / C のミニマリズムの再来。解決したもの：圧倒的に速いコンパイル、簡潔な並行処理、自動メモリ管理、そして「誰でも1時間で覚えられる」シンプルさ。2009年オープンソース公開後、コミュニティが育てクラウド／コンテナ時代の主要言語へ。晩年のトンプソンは「ほとんど Go でしか書かない。標準ライブラリだけで大抵できる」。

### 二つの哲学

1. **自分のために作る** … Unix も C も Go も、誰かのためではなく自分が気持ちよくプログラミングするために。皮肉にもその個人的な道具が何億人に使われた。  
2. **徹底したミニマリズム** … 過剰な機能＝複雑さは悪。Multics ではなく Unix、C++ ではなく Go。機能を足すのは簡単で、本当に難しく価値があるのは削ること。

フェンスの鉄線で電話を作った少年は、半世紀を経て自分のための最高の道具にたどり着いた。一人の人生がそのまま現代コンピュータサイエンスの歴史になっている。
