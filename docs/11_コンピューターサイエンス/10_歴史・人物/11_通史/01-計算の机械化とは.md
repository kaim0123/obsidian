# 計算の机械化〜理論の確立（〜1940年代）

> **この章を読むと分かること**
> - なぜ人は「機械に計算させたい」と思ったのか
> - 電気を使わない「歯車のコンピュータ」が実在した話
> - 「計算とは何か」を世界で初めて定義した数学者の発想

---

## はじめに — 計算機の起源は「人命を救うこと」

いきなり驚く話から始めます。**プリンター（印刷機）は、もともと人命を救うために生まれた装置です。**

「画面を共有する技術がなかったから紙に印刷したんでしょ？」と思うかもしれません。ところが歴史を遡ると、コンピュータとプリンターの起源は同じ場所に行き着きます。それが今回の主役、**チャールズ・バベッジ（1791–1871）** という人物です。

---

## 1. 「コンピュータの父」たちを整理する

コンピュータの歴史の本を読んでいると、「コンピュータの父」と呼ばれる人物が何人も出てきます。これが混乱の元なので、まず番組内の整理に従って並べておきます。

| 人物 | 呼ばれ方 | 何をした人か |
|------|---------|------------|
| **チャールズ・バベッジ** | 機械式コンピュータの父 | 電気を一切使わず、歯車だけでコンピュータを作ろうとした |
| **アラン・チューリング** | コンピュータ**科学**の父 | 「計算とは何か」を数学として厳密に定義した |
| **ジョン・フォン・ノイマン** | 近代電子コンピュータの父 | 現代の PC・スマホの骨格となる設計図を書いた |

ほかにシャノン、ブールなども「父」と呼ばれることがあります。父が多すぎる、複雑な家庭事情のような分野です。

## 2. バベッジ — 歯車だけでコンピュータを作ろうとした男

### 2-1. 動機は「船乗りを救うこと」

18〜19世紀の船乗りは、海の上で自分の位置を知るために **航海暦（Nautical Almanac）** という分厚い本を持ち歩いていました。緯度・経度ごとに月や星の位置が数字でびっしり書かれた表です。

```
航海暦の使い方（イメージ）
 月がこの方角に見える → この緯度・経度にいる
 ↓
 船乗りは「計算済みの表」を見るだけでよい
```

問題は、その表が **人力で計算されていた** こと。たった1か所の計算ミスが連鎖し、表全体が狂います。位置を読み間違えた船は、バミューダトライアングルのような海域で遭難し、人が死んでいました。

若いバベッジはこの表の改訂作業を任されていました。最初は「2人で検算する」など人力での対策を試しましたが、ミスはゼロになりません。普通ならここで「チェック工程を増やそう」「フローを分けよう」とマネジメント的に解決しようとします。

**しかしバベッジは違いました。「人が介入する工程そのものを排除すればいい」と考えたのです。** これは当時としては常人の思考の外にある発想でした。

### 2-2. 「機械式コンピュータ」とは何か

ここで言う「機械」とは、電気を使わずに動く装置のことです。

- 蒸気機関 → 機械
- 手回しオルガン → 機械
- 歯車式の計算機 → 機械

バベッジが作ろうとしたのは **歯車と棒だけで動くコンピュータ** でした。表紙画像のような装置を想像してください — 大量の歯車と縦棒が連動し、左上のハンドルを回すと全体がギリギリと動き出す。1回転する歯車に対して別の歯車が 1/8 回転する、というような精密な歯比が組み合わされています。

> **耳で聞く人向けの例え（番組より）**
> ハンドルを回すと、麺を手で触らなくても自動でソバが動き出し、ソバの形を見れば数字が読み取れる「死ぬほど大掛かりな番台」。

当時の機械加工の水準では本来不可能な精度でした。バベッジは巨額の投資をつぎ込み、当時の精密機械としては **圧倒的世界一** の水準を実現します。

### 2-3. 歯車でもコンピュータは作れる、という事実

「電気を使わずにコンピュータって作れるの？」と思うかもしれません。

実は作れます。例えば **ドミノ倒し** でもコンピュータを作れます。ドミノが倒れる／倒れないを「1／0」と考え、「こことここが両方倒れた時だけ次が倒れる」という配置をすれば **AND ゲート** が作れます。YouTube には「3+9=12」を計算するためだけに **100万個のドミノ** を並べた動画もあります。

つまりコンピュータの本質は **論理回路の組み合わせ** であり、それが電子であろうと歯車であろうとドミノであろうと、**原理は同じ** なのです。

### 2-4. バベッジが先輩計算機と違ったところ

機械式の計算機自体はバベッジが最初ではありません。

- **アンティキテラ島の機械**（古代ギリシャ、紀元前）
- **パスカル**（17世紀、加減算ができる歯車計算機）
- **ライプニッツ**（17世紀、乗除算もできる改良版）

しかしこれらは「歯車5個程度で簡単な計算ができる」レベルでした。バベッジはこの精度と桁数を桁違いに引き上げ、さらに **解析機関（Analytical Engine）** という構想に至ります。これは「歯車の組み合わせだけで、現代のプログラミングでできる演算をすべて実行できる **汎用機械**」のアイデアでした。

```
パスカル・ライプニッツ：特定の計算ができる
        ↓ 大きな飛躍
バベッジ：原理的に「何でも計算できる」汎用機械の構想
```

この「汎用性」こそが、後の現代コンピュータに繋がる発想です。

### 2-5. ロマンチストかつリアリスト — 計算機＋印刷機の同時設計

バベッジは精度を1%上げて満足する人ではありませんでした。**100%の完璧を目指した** のです。

そこで彼の設計図には、計算機だけでなく **印刷機構** も最初から組み込まれていました。当時は活字印刷の時代 — 計算結果（345.136872 のような多桁の数）を人が紙に書き写すと、また書き間違える可能性があるからです。

歯車が回ると自動で活字を拾い、所定の位置にセットし、表に直接押す仕組み。これが **世界初のプリンター** に相当する発想でした。

> **発想の二面性**
> - **ロマンチスト**：完璧な夢を追う
> - **リアリスト**：人が少しでも介入すれば必ずミスると徹底する

さらに「活字を箱に入れる雑用係が 2 と 3 を取り違える」という残ったヒューマンエラーに対しても、**活字に物理的なくぼみと出っ張りを付けて、間違ったものは物理的に入らない** ようにしました。現代の USB コネクタが裏表で挿せないのと同じ発想です。

### 2-6. 悲しい結末 — 完成しなかった理由

これほどのビジョンと能力を持ちながら、**バベッジが生前に完成させた計算機はほぼ1つもありません**。原因は技術ではなく、凡庸な人間ドラマでした。

1. **報酬の相場がない問題**：世界初の精度を要求する加工に値段が付かず、職人と「高すぎる／妥当だ」で揉める
2. **工作機械の所有権問題**：バベッジは「金を出した工具は自分のもの」、職人は「難題を解く過程で得た道具は職人のもの」と主張し、決裂

政府から **7,500ポンド**（当時の蒸気船7.5隻分）の援助を受け、自費も合わせて合計 **17,000ポンド（蒸気船17隻分）** を投入しましたが、未完成のまま終わりました。

> **現代に通じる教訓**：書面で範囲を決めずに仕事を受けると揉める。フリーランスあるあるとして今でも繰り返されている失敗です。

200年後、ロンドン科学博物館がバベッジ生誕200年記念に **当時の技術のみで** 図面通りに再現したところ、図面の若干の誤記を直すだけで **完全に動きました**。あと一歩だったわけです。

> **よくある誤解**
> - 17,000ポンドを注いだのは「現代型コンピュータ」ではなく **第1差分機**（特化型の計算装置）
> - 「汎用機」の構想（解析機関）は **図面レベル** で完成していない
> - 計算機自体は **パスカル・ライプニッツが先**。バベッジの偉さは「汎用性のアイデア」と「圧倒的精度の機械式」の両面

## 3. チューリング — 「計算とは何か」を定義した男（1936年）

バベッジが「実装」に挑んだのに対し、約100年後、若き数学者 **アラン・チューリング** は **理論** から計算機の本質に迫ります。

### 3-1. なぜ「計算とは何か」を定義する必要があったのか

1930年代の数学界は **決定不能問題** — 「解けるか解けないかすら分からない問題」 — の扱いで混乱していました。「そもそも『解ける』とは何か？」を答えるには、「**計算とは何か**」を厳密に定義しなければなりませんでした。

> **チューリングの偉大さ**：実物を作ったことではなく、**世界で初めて計算を言語化・定義したこと**。当時はみんな「計算」を感覚では分かっていたが、誰も厳密には定義していなかった。「歩くとは何か」を定義した人がいなかったようなものです。

### 3-2. チューリングマシン — たった4つの部品

チューリングが論文で提案した理論上の機械は、たった **4つの要素** でできています（紙の上だけの機械で、物理的には作っていません）。

```
┌──────────────────────────────────────────────┐
│  チューリングマシンの4要素                     │
├──────────────────────────────────────────────┤
│  ① 無限に長いテープ                            │
│     マス目に記号（0と1だけでOK）を書く         │
│                                              │
│  ② 読み書きヘッド                              │
│     テープ上を動き、記号を読んだり書いたりする │
│                                              │
│  ③ 内部状態                                    │
│     「今どの局面にいるか」を表す（将棋の局面）  │
│                                              │
│  ④ 状態表（ルール表）                          │
│     「この状態でこの記号を読んだら、何を書いて │
│      どちらに動け」の命令一覧                  │
└──────────────────────────────────────────────┘
```

### 3-3. 主張：「あらゆる計算はこれに還元できる」

チューリングはこう主張しました。

> **どんな計算・どんなアルゴリズムも、突き詰めれば「記号を読む → 書き換える → 状態を変える」の繰り返しに還元できる。**

これは衝撃的な主張です。複雑な微分積分も、AI の推論も、3D ゲームの描画も、**この単純な操作の繰り返し** に分解できると言っているわけです。

そして実際、現代のすべてのコンピュータはこの「チューリングマシン」を **電子回路で実装した結果** にすぎません。1936年の紙の上の機械が、世界中のすべての PC・スマホの **理論的な土台** になっているのです。

## 4. ノイマン — 紙の上の機械を現実にした男（1945年）

### 4-1. ENIAC の問題 — 配線がプログラム

第二次世界大戦中の1946年、米国で **ENIAC** という世界初期の電子式汎用計算機が完成します。重さ30トン、部屋を丸ごと埋め尽くすサイズの巨大装置でした。

しかし致命的な欠点がありました。**プログラムがメモリにではなく、配線そのものに記述されていた** のです。

```
ENIAC の問題
 計算内容を変える = ケーブルを差し替え、スイッチを全部設定し直す
                ↓
 1回の変更に数時間〜数日かかる
                ↓
 約1000人のオペレーター（多くは女性の計算専門家）が常駐
```

理論上は汎用機なのに、実質的には専用機に近かったわけです。

### 4-2. 革命的な発想 — プログラムをメモリに入れる

設計者たちは現場で気づきました。

> **「プログラムをデータと同じ場所（メモリ）に入れればいいのでは？」**

これが **stored-program 方式**（プログラム内蔵方式）。一見地味ですが、これこそが現代の「ソフトウェア」を生んだ革命的な発想です。

```
配線を変える → メモリの中身を書き換えるだけ
   ↓
 ハードはそのままで、別のコンピュータに変身できる
   ↓
 これが「ソフトウェア」というものの誕生
```

足し算のプログラムがメモリにあれば、それを消して掛け算の命令列を書き込むだけで、同じハードが別の計算機になる。配線には一切触らない。**この発想がなければ、パソコンもスマホも、OS も、アプリも、AI も存在しません。**

### 4-3. ノイマン報告書と手柄争い

この設計思想は、1945年に **ジョン・フォン・ノイマン** 名義の報告書（First Draft of a Report on the EDVAC）として外部に出回りました。

しかし実際には、ENIAC 設計者の **エッカートとモークリー** らとの議論から生まれたアイデアでした。それが「ノイマン1人の手柄」のように広まったため、**チームは分裂** します。バベッジの「職人ともめた」話と同じく、ここでも凡庸な人間ドラマが歴史を動かしています。

> **ノイマンという人物**：ゲーム理論・量子力学・経済学など複数分野で同時に第一線にいた天才。会話の途中で暗算して答えを出すタイプで、周囲からも「頭の作りが違う」と言われた人物。トラブルメーカーでもあり、現代コンピュータの設計図を書いた人物でもある。

### 4-4. ノイマン型アーキテクチャ — 5つの部品

ノイマンが整理した現代コンピュータの骨格は、**5つの部品** からなります。

| 部品 | 役割 | 身近な例え |
|------|------|---------|
| **メモリ** | プログラム（命令）とデータの両方を格納 | 作業デスク |
| **演算装置（ALU）** | 実際の計算を担当 | 電卓 |
| **制御装置** | メモリから命令を読み取り、各部品に指示 | 司令塔 |
| **入出力装置** | キーボード・ディスプレイなど外界との窓口 | 目と口 |
| **バス** | 部品をつなぐデータの経路 | 廊下 |

動作の基本は、**フェッチ → デコード → 実行** の繰り返し：

```
① フェッチ（Fetch）：メモリから命令を取ってくる
② デコード（Decode）：命令の意味を解釈する
③ 実行（Execute）：実際に処理する
↓
電源が入っている間、毎秒「何十億回」繰り返す
```

### 4-5. チューリングマシンとの美しい対応

ここでチューリングマシンと比べてみましょう。

| チューリングマシン（1936年・紙） | ノイマン型（1945年・電子回路） |
|----------------------------|----------------------------|
| テープを読む | フェッチ |
| 状態表を参照する | デコード |
| 記号を書き換え、ヘッドを動かす | 実行 |

**ノイマン型は、チューリングマシンを電子回路で実装した答えそのもの** なのです。

驚くべきことに、この骨格は **80年経った今も変わっていません**。あなたが今これを読んでいる PC やスマホも、基本構造は1940年代の設計図と同じです。

## 5. この章のまとめ

| 時代 | 出来事 | 意味 |
|------|--------|------|
| 17世紀 | パスカル・ライプニッツの歯車計算機 | 小さな計算を機械化 |
| 1820〜1870年 | バベッジの差分機・解析機関 | 汎用機械の構想と挫折 |
| **1936年** | **チューリングマシン** | 「計算とは何か」の理論的定義 |
| **1946年** | **ENIAC** | 電子化したが配線がプログラム |

**1本の線でつなぐと**：

```
バベッジが「機械で計算する」夢を見た
        ↓
チューリングが「計算とは何か」を定義した
        ↓
ノイマンが「どう作るか」を設計した
        ↓
80年経っても、その骨格はまだ動いている
```
