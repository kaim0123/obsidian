## 要約

**テーマ：暗号技術の「死」と、ハッシュ関数の歴史**

暗号技術に「永遠に安全」なものはない。一度弱点が露わになると、軍艦の速度競争のように旧世代は一瞬で陳腐化し、世界は次の方式へ移行する。本回はその典型例として**暗号学的ハッシュ関数**を追い、2004年の衝撃的事件から現代の HTTPS・電子署名・ブロックチェーンまでをつなげて解説する（後半はコインチェックのタイアップあり）。

---

### 冒頭の事件：2004年、学会が起立した理由

カリフォルニア大学サンタバーバラ校で、中国人研究者**王小雲（ワン・シャオユン）**が学会発表を終えると、聴衆はスタンディングオベーションで見送った。表向きは「条件を満たす数の組を見つけた」という地味な成果に見えるが、暗号の専門家には意味が分かった。**広く使われていた MD5 で、意図的に同じハッシュ値（衝突）を作れる**ことを示したのだから、世界中のウェブの信頼の基盤が揺らいだ。発表を聞いた悪意ある者も理論上は成りすましが可能になるが、実用化までには数年かかることも多く、その間に業界は SHA-1 廃止やブラウザ警告などの対策を進める——**ゼロデイ攻撃**とは、この「発見から悪用までのタイムラグ」が極端に短いケースの呼び名でもある。

---

### ハッシュ関数とは何か

- **ハッシュ（hash）**＝「切り刻む」。任意長のデータを、固定長の値（ハッシュ値）に変換する。
- **一方向性**：元データには戻せない（逆算困難）。
- **決定性**：同じ入力なら必ず同じ出力。
- **雪崩効果（avalanche）**：入力が1ビットでも変わると、出力は一見ランダムに大きく変わる（35 と 36 を入れて出力が1だけ変わる関数では、総当たりで即破られる）。

**身近な用途**

| 用途 | 仕組みのイメージ |
|------|------------------|
| パスワード保存 | 平文ではなくハッシュだけ保存。漏洩しても元のパスワードは戻しにくい。ログイン時は入力をハッシュして照合 |
| 電子署名 | 巨大なファイル全体に署名するのは重い → まずハッシュを取り、その短い値に秘密鍵で署名 |
| HTTPS（TLS） | 配信サイトの内容が改ざんされていないか、ハッシュと証明書の組み合わせで検証 |

1日に数万回、スマホ・PCの裏でハッシュ計算が動いている。サイト1ページを開くだけでも、現代のウェブでは数十回はハッシュに依存している、という規模感。

**SHA-1 廃止とブラウザ警告**

かつて広く使われた **SHA-1** の危険性が知られても、まだ SHA-1 を使うサイトが残り、Chrome などが「安全ではありません」と警告した例がある（出版社サイトなど）。「閲覧するだけなら関係ない」という12年前の常識はもう古く、現代のサイトは広告・トラッキング・フォームなどで知らないうちにデータを送ることも多い。業界全体で **HTTPS（暗号化通信）をデフォルトにする**動きとセットで、弱いハッシュの排除が進んだ。

### デモ：「堀本法」で雪崩効果と衝突攻撃

説明用に**堀本法**という単純なハッシュを定義し、水野さんに手計算させる。

1. アルファベットを A=1 … Z=26 に変換
2. 初期値 1 から、1文字ごとに `現状の値 × 7 + 文字番号` を計算
3. 常に**下2桁だけ**を残す（100で割った余り＝MOD 100）

例：**cat** → 17、**bat**（c→b の1文字差）→ 68、**hat** → 62。入力は近くてもハッシュ値はバラバラ（雪崩）。逆に **bat** と **hat** は文字列としては遠いのに 68 と 62 で近い——「ランダムっぽい関数」を作るには、**増幅して捨てる**（桁を捨てて情報を落とす）のが基本、という直感。

**衝突攻撃のデモ**

ハッカー視点で「cat と同じハッシュ値 17 を出す別の文字列」を探す。式を `343 + 49×X₁ + 7×X₂ + X₃` のように展開すると、1文字目の係数 49 が大きく、下2桁は 100 の倍数付近を狙えば調整しやすい、という発想で **eat**（実演では e-a-v 系の変形）を導き、**cat と同じ 17** を再現。これが**衝突（collision）**であり、ハッシュ関数の致命的弱点になる。

- パスワード保存なら：他人のパスワード欄に「別の文字列」を入れてもログインできてしまう（同じハッシュなら通る）。
- 電子署名なら：1億円を A 社へ振込め、という指示書のハッシュと一致するよう、見えない位置に文字を足して**別内容の PDF でも同じハッシュ**を作れば、署名と内容の整合が取れなくなる——成りすまし・改ざんの理論的根拠になる（実際の SHA-2 系では現時点で衝突は知られていない、と番組内でも触れている）。

### 王小雲と MD5：Web 全体の信頼が揺れた瞬間

MD5 は MD4 の弱点を踏まえて改良されたが、それも王小雲らによって破られた。手法は堀本法デモと同型の**式の展開と係数の観察**だが、はるかに複雑で、論文は**400ページ規模の手計算**だった、というエピソード。悪用すれば証明書の偽装などが理論上可能——実例として **Stuxnet / Flame** では、ハッシュ衝突を使い **Microsoft 風の証明書を偽装**し、Windows 更新に見せかけたマルウェア配布が行われた、と紹介される（国家レベルのサイバー作戦）。

フィッシング対策として「ドメインをよく見ろ」は今も有効だが、**証明書まで本物そっくりに偽装される**攻撃では、URL 確認だけでは不十分になりうる。対策としてブックマークから開くなどが推奨される、という話にもつながる。

### 暗号の進化：破られる前提で次を用意する

| 世代 | 経緯 |
|------|------|
| MD4 | 弱点指摘 → 改良して MD5 へ |
| MD5 | 2004年 王小雲らにより衝突攻撃 → 廃止・警告 |
| SHA-1 | 同様に危険視され、順次淘汰 |
| SHA-2（SHA-256 など） | **現在の主流**。まだ実用的な衝突は知られず常用 |
| SHA-3 | **破られる前に**移行先として既に標準化・普及。コンペで選ばれた次世代方式（「SHA」はブランド名に近い） |

「破られない暗号を3社分散のように併用」という発想には、番組では「移行先を複数研究しておく」が近い——SHA-3 はすでに用意済み、という答え。暗号学界は**どうせ破られる**という歴史観のもと、乗り換え先を先に決めておく——人類の英知が集まった分野、という締めのトーン。

数学の「一方向性」などの理論研究が、数十年後にインターネット全体の基盤になった、という**好奇心駆動の研究が後から社会で必要になる**話題にも触れる。

### ビットコイン・ブロックチェーンとの接続

- **マイニング**：意味のないデータを付け足し、ハッシュの先頭に 0 が並ぶような値を**探索する作業**（王小雲の「狙ったハッシュを出す」と構造が似る）。
- **ブロックチェーン**：前ブロックの情報をまとめたハッシュを次ブロックに載せる鎖。過去の1ブロックを改ざんすると以降のハッシュがすべて変わり、改ざんコストが跳ね上がる——信頼性の技術的基盤。

暗号資産の価格や詐欺案件のイメージと、**技術そのものの美しさ**は分けて考えるべき、という主張。技術は株式のように優れた仕組みの上で悪用も起きうる、という比喩。

（後半）コインチェックの紹介、ビットコイン・イーサリアムから始めること、ポートフォリオの **1% 以内**、3分に1回アプリを開くような過剰監視は避ける、などの実務アドバイスと、5/31 までのキャンペーン（口座開設・購入で最大 2500 円分のビットコイン）の案内。
