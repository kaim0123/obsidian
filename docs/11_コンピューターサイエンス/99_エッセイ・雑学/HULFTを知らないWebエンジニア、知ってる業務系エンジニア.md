## 詳しい要約

**テーマ：日本の基幹系を支えるファイル転送ミドルウェア HULFT の 30 年**

国内ファイル転送ツールで金額シェア 21 年連続 1 位・導入 1 万 1725 社の HULFT（ハルフト）は、業務系エンジニアには日常の道具なのに Web 系エンジニアの多くは名前すら知らない。その誕生からシェア獲得、設計思想、最新版までをたどり、Web 系が S3 と Airflow で作っているパイプラインは HULFT が解いてきた問題の解き直しだと論じる。

---

### 知名度が割れる製品

- 2017 年の富士キメラ総研の調査で市場の約 **80%**。銀行・製造業・公共など基幹システムのある場所にはほぼ必ずある
- それでも Web 系が知らないのは、GitHub にも Stack Overflow にもほとんど出てこないから

### 第 1 章：百貨店の情報システム部門から誕生

- 作ったのは**セゾン情報システムズ**（西武百貨店と西友の電算部門が 1970 年に合同した西武情報センターが前身）
- 開発を率いたのは技術開発部の課長・西川氏。西武百貨店の売掛管理システムで苦労した経験から「多くの会社が使える製品を作りたい」と考えた
- 部下の「これからは分散システムが流行る」という一言がきっかけ。当初は汎用機 DB の複製をオープン系に作る野心的な構想だったが、当時のマシンでは難しく「ファイルを運んで DB に流し込む」現実路線に
- **5 人のチームで構想 6 か月・開発 6 か月**。メインフレーム → UNIX の一方向転送のみで **1993 年 1 月**に販売開始
- 名前は Host UNIX Link File Transfer の頭文字。西川氏が「ハル」という響き（季節の春、映画『2001 年宇宙の旅』の HAL 9000）を先に気に入っていた

### 第 2 章：シェアを作った泥臭い機種対応と門前払い

- 最初の数年は年 20 本程度しか売れず、価格で負けていた。機能限定の廉価版「HULFT-」は 1 本も売れなかった
- 転機は**対応機種の異常な広さ**。社内に IBM 機がないため、横河電機に「**ソースを公開するのでそちらで作りませんか**」と逆提案し、横河が最初の代理店に。日立にも同方式で依頼
- AS/400 版は 3 人を外部研修に 10 か月出し、富士通版は COBOL で書く必要があり外部に依頼、Tandem 版は Tandem 自身が体制を組んだ。開発体制 15 名未満で NEC・富士通・日立・IBM・Tandem 全機種に対応
- ファイル転送ツールは**送る側と受ける側の両方に必要** → 取引先が HULFT なら自分も買うしかない。FAX と同じく**相手が多いほど価値が上がる**構造でシェアが広がった
- 1995 年以降、企業間通信の BSC 手順ベースの全銀手順・JCA 手順を HULFT で置き換えようと流通業界団体に持ち込むが「勝手に作って」と**門前払い**
- 反発から業界を選ばない標準を目指し、**1996 年の HULFT4** でファイアウォール対応や EDI の CSV 変換を搭載。銀行にも入り始め、1998 年に累計 1 万本達成

### 第 3 章：Web 系が驚く中身

- 送ることを**配信**、受け取ることを**集信**と呼び、両側に相手ホストやファイル名を管理情報として登録
- 受信完了と同時に**転送後ジョブ**を自動起動できる → 「売上ファイルが届いたら集計、終わったら次のホストへ配信」という**夜間バッチの鎖**が日本の基幹システムの心臓部
- **コード変換**：メインフレームの EBCDIC・固定長レコードと、オープン系の Shift_JIS/UTF-8・可変長を転送しながら変換（漢字変換は 1994 年の HULFT3 で整備）
- **証跡**：いつ誰が何を送り、成功・失敗したかの履歴が残る。2008 年の HULFT7 で内部統制対応を強化（J-SOX の時代）
- 海外の同種製品は IBM の Sterling Connect:Direct（1983 年誕生）。Gartner はこの分野を **MFT（Managed File Transfer）** と呼ぶ
- Web 系に見えない理由：商用で OSS でない、両端にライセンスが必要で個人が触らない、動く場所が基幹系の夜間バッチで Web から最も遠い

### 第 4 章：コンテナ版と HULFT10

- 2023 年にクラウド型データ連携サービス **HULFT Square** を日米共同開発
- 2024 年 2 月、Amazon ECS 対応のコンテナ版を AWS Marketplace で販売開始（1 コンテナ 1 時間 2.3 ドルから）
- 2024 年 4 月に社名を**セゾンテクノロジー**に変更、同年 12 月に **HULFT10**（10 年ぶりのメジャーバージョンアップ、9 は欠番）
- 圧縮に **Zstandard** を採用し転送は HULFT8 の約 1.4 倍（z/OS では 5 倍）、CPU 使用率は半減。API ゲートウェイ機能とスマートプロキシで HTTP から呼べる入口ができ、UI も刷新
- 「オンプレ・クラウド、レガシーとモダンが混在する境界線を越える」— 30 年前に汎用機と UNIX の境界を越えた製品が、今度はメインフレームと ECS の境界を越えようとしている

### 最終章：S3 と Airflow は HULFT の再発明か

- データ基盤では S3 に Parquet ファイルを置き、置かれたら次の処理が動く → HULFT の配信・集信・転送後ジョブそのもの
- Airflow のセンサーがファイル到着を待つのは HULFT の集信起動と同じ発想
- 届いた保証、途中で切れたときの再送、二重処理の防止、誰が何を送ったかの記録 — データエンジニアの悩みは HULFT が 1990 年代に片付けてきた項目とほぼ一致
- 逆に業務系から見ると、転送後ジョブは Web 系の**イベント駆動**、管理情報の登録は **IaC** で書きたくなるもの。名前が違うだけで思想は共通
- 基幹システムのクラウド移行では、HULFT の鎖を読み解いて ECS やデータ基盤に翻訳できる人材が不足している

### まとめ

- HULFT のシェアは「両端に必要」という構造と、機種を選ばない泥臭い対応が作った
- 売り物は転送そのものではなく、**届いた後の連鎖と証跡**
- 終わりかけの製品ではなく、コンテナ・クラウド向けに作り直されている最中
- Web 系と業務系の両方の言葉が分かる人が、今いちばん求められている
