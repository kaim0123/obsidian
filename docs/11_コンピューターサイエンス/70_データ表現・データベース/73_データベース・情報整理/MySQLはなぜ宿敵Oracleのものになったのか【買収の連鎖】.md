## 詳しい要約

**テーマ：MySQL が Oracle の手に渡った「買収の連鎖」と MariaDB 分岐の 20 年史**

世界で最も使われる OSS データベース MySQL の持ち主は、長年のライバル Oracle である。2005 年の InnoDB 買収から Sun、Oracle へと続いた買収の連鎖と、生みの親モンティによる MariaDB のフォークをたどり、「オープンソースは買収できない」「ライセンスを読める人が最後に強い」という教訓を引き出す。

---

### 第1章 娘の名前がついた DB、Web 時代の標準に

- 1995 年、スウェーデンとフィンランドの 3 人が **MySQL AB** を設立。中心人物はフィンランド人プログラマの**ミカエル・“モンティ”・ワイデニウス**。
- 名前の由来はモンティの長女「My（ミュー）」。
- 2000 年代に **LAMP**（Linux・Apache・MySQL・PHP）で爆発的に普及。Facebook・YouTube・Wikipedia の初期データも MySQL 上にあった。
- ビジネスモデルは**デュアルライセンス**：OSS 版は GPL で無料、GPL の制約を避けたい企業には商用ライセンスを販売。無料で配りながら稼ぐ仕組みを発明した。

### 第2章 心臓部から始まった買収の連鎖

| 年 | 出来事 |
|---|---|
| 2005 年 10 月 | Oracle がフィンランドの **Innobase** を買収。MySQL で実際にデータを読み書きする中核ストレージエンジン **InnoDB** の開発元 |
| 2006 年 | Oracle が Berkeley DB を持つ Sleepycat を買収し、外堀を埋める |
| 2008 年 1 月 | **Sun Microsystems** が MySQL AB を **10 億ドル**で買収（OSS 企業として史上最高額、社員約 400 人）。創業メンバーは大金を得る |
| 2009 年 4 月 | リーマンショックで傾いた Sun を Oracle が **74 億ドル**で丸ごと買収。MySQL も狙いの 1 つとの見方が根強い |

- 心臓部の買収からわずか 4 年で、MySQL は丸ごと Oracle の手に落ちた。

### 第3章 生みの親の反乱と MariaDB 誕生

- モンティは 2009 年 2 月に Sun を退社し、Monty Program AB を設立して MySQL のソースを丸ごと複製した **MariaDB** を開発。名前は次女マリアから（息子マックスの名前は MaxDB に）。
- Oracle の Sun 買収発表はその 2 か月後。モンティは**先に避難所を作っていた**。
- 複製が許されるのは MySQL が **GPL** で公開されていたから。会社は買えても、公開済みのコードは買い占められない。
- モンティは「Save MySQL」署名運動で EU に買収阻止を訴え、欧州委員会が 2009 年 9 月から本格審査。Oracle は MySQL サポートを 5 年間続けるなどの公約を出し、**2010 年 1 月に承認**（発表から 9 か月、利用者は宙づり状態）。
- MariaDB は感情的な反発ではなく、GPL という**法的な土台の上で計画的に**生まれた。

### 第4章 分岐から 15 年、予想と逆の明暗

- 2013 年、Fedora や openSUSE などの Linux ディストリビューションが標準 DB を MariaDB に切り替え、RHEL 7 も続いた。Wikipedia も移行、Google も社内 MySQL を置き換えたと報じられた。
- しかし Oracle は予想に反して MySQL に投資を続け、2018 年の **MySQL 8.0** で性能・機能を大幅強化。DB-Engines ランキングで MySQL は今も全 DB 中 2 位の常連、MariaDB は大きく引き離されている。
- **MariaDB 社**は 2022 年 12 月に NYSE 上場（初値 11.55 ドル）したが、2024 年には 50 セント台まで下落し、投資会社 K1 に約 3,700 万ドルで買収・非公開化。
- ただし沈んだのは会社。OSS の MariaDB 本体は非営利の **MariaDB 財団**が守り、AWS が最上位スポンサーとして開発は続いている。

### 最終章 エンジニアが持ち帰るべき教訓

1. **オープンソースは買収できない**：Oracle が得たのは商標・開発チーム・商用ライセンス権で、公開済みコードとフォークする自由は買えなかった。EU の判断材料にもフォークの存在が入っていたとされる。**フォークは存在するだけで抑止力になる**。
2. **ライセンスを読める人が最後に強い**：モンティが数か月で MariaDB を立ち上げられたのは GPL が何を許すかを正確に理解していたから。DB 選定では性能表より先にライセンスを確認すべき（近年の Elasticsearch や Redis のライセンス変更騒動も同じ構図の再来）。
3. モンティは会社を売った金で同じ道具を作り直した。損得では説明できない、作り手の執念がある。

### まとめ

- MySQL は InnoDB → Sun → Oracle という買収の連鎖で、宿敵 Oracle のものになった。
- MariaDB は GPL に基づく計画的なフォークとして誕生したが、会社としては沈み、Oracle 傘下の MySQL が栄えるという予想と逆の結末に。
- OSS は買収できず、フォークの存在自体が抑止力になる。ライセンスの理解が最終的な武器になる。
