## 詳しい要約

**テーマ：「おもちゃ DB」SQLite がエッジ時代の主役へ**

「本番では使えない」と言われてきた SQLite は、実は 1 兆インスタンス以上が動く地球上で最も多く稼働する DB であり、航空機に載るほどの異常な品質管理に支えられている。2022 年以降 Cloudflare D1・Turso・Litestream・LiteFS などサーバー側で使う道具が揃い、SQLite が進化したのではなく時代が SQLite に追いついた。読み込み中心のアプリなら最初の柱として十分使える。

---

### 第1章 戦艦の画面エラーから始まった物語

- 2000 年、米メイン州の造船所の町で、38 歳の **Richard Hipp** が海軍駆逐艦の **ダメージコントロールシステム**（被弾時にどのバルブを閉めれば沈まないか判断する命に関わるシステム）を作っていた。
- 使っていた商用 DB **Informix** は性能は出るが、DB サーバーが落ちるたびに自分のアプリが「データベースサーバーに接続できません」と表示するのが恥ずかしかった。
- 「DB サーバー自体がいらない DB」、つまりファイルに直接読み書きする DB を構想。米議会の予算停止で政府契約が数か月止まった暇に書き始め、2000 年 8 月に SQLite 1.0 をリリース。
- 艦船の本番では採用されなかったが、ネットに公開すると「軽い・サーバー不要・ファイル 1 個で動く」の 3 点が開発者の心をつかんだ。

### 第2章 1 兆インスタンス、地球上で最も動いている DB

- iPhone・Android の OS 内部（連絡先、写真のメタデータ、設定、iMessage や WhatsApp の履歴）、Mac・Windows・Linux、Chrome・Firefox・Safari、Dropbox・iTunes・Adobe Lightroom、さらに **Airbus A350** の飛行ソフトウェアにも組み込まれている。
- スマホだけで 40 億台以上 × 1 台あたり数百ファイルで、インスタンス数は **1 兆（trillion）** を超える。公式サイトも「おそらく世界で最も広く導入された DB エンジン」と宣言し、ほぼ誰も否定しない。
- 人は気づかないうちに 1 日何百回も SQLite を使っている。

### 第3章 飛行機に載る DB を支える異常な品質管理

- 本体約 15 万行に対しテストコードは 1 億行以上、**約 700 倍**。
- 航空ソフトウェアの検証基準 **DO-178B** に準拠し、全分岐を真偽両方向でテストする **MC/DC** カバレッジ 100% を達成。リリースごとに何十億回のテストを回す耐久試験（soak test）も実施。
- Git ではなく Hipp 自作のバージョン管理 **Fossil** を使い、開発は Hipp と数人のコアメンバーのみ。コードはパブリックドメインだが、外部のプルリクエストは原則受け付けない。
- 2010 年頃 Android で利用が爆発し世界中からバグ報告や要求が殺到した際、品質を守るため外部 PR を断ると決めた。信頼性は偶然ではなく異常なテスト量と閉じた開発体制の産物。

### 第4章 SQLite ルネッサンス、エッジ時代の主役へ

| 道具 | 内容 |
|---|---|
| Cloudflare D1 | 2022 年 5 月発表、2024 年 4 月 GA。Cloudflare のエッジで SQLite を動かす |
| Turso | SQLite のフォーク libSQL を作り、世界中のエッジに複製 |
| Litestream | SQLite の WAL をリアルタイムで S3 に書き出して耐障害性を足す |
| LiteFS | Fly.io 製。SQLite ファイルを複数ノードに同期 |

- 一気に来た理由は **レイテンシ**。従来は 1 か所の PostgreSQL に世界中から接続するため、遠い地域では 1 リクエストごとに数十ミリ秒の往復が積み重なる。SQLite はアプリと同じサーバー内のファイルを読むだけ。D1 のエッジレプリカからの読み取りは 10 ミリ秒以下で、クラウド 1 リージョンの PostgreSQL に比べ P95 で 3〜10 倍速いという。
- マネージド PostgreSQL は待機だけで課金されるが、SQLite はファイルなので **待機コストがない**。
- エッジ・サーバーレス・低レイテンシという 3 つの流れが、古くて小さな道具に追いついた。

### 第5章 今の SQLite との付き合い方

- 苦手なのは **同時書き込みが多いワークロード**（書き込みは 1 つずつしかできない）。1 万人が同時にコメントする SNS のメイン DB には向かない。
- しかし多くのアプリは読み込みが 9 割以上。ブログ、管理画面、社内ツール、ダッシュボード、多くの SaaS なら速く・安く・運用が楽。
- 「最初から PostgreSQL」は将来スケールするかもという保険だったが、ほとんどのアプリはそこまで育たない。SQLite と PostgreSQL は SQL の方言が近く、スケールしたら移行もそれほど難しくない。捨て駒ではなく **最初の柱** になれる。
- 常識の逆転：「おもちゃだから本番で使えない」→「小さいから本番でも強い」、「スケールしないから避けろ」→「多くのアプリはそもそもそんなにスケールしない」。

### まとめ

- SQLite は地球上で最も多く動く DB で、航空機レベルのテストと閉じた開発で信頼性が守られている。
- エッジ・サーバーレス時代の道具が揃い、低レイテンシと待機コストゼロでサーバー側の選択肢になった。
- 書き込み集中には不向きだが、読み込み中心のアプリなら最初の DB として十分。
