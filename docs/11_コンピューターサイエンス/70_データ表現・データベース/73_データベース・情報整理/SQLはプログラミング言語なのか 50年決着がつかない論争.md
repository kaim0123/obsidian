## 詳しい要約

**テーマ：「SQL はプログラミング言語か」論争と、その問いを追い越した SQL の現在**

SQL は 1974 年に「プログラマー以外でも書ける言語」として意図的に言語らしくなく設計された。宣言型であることが「言語じゃない」論の根拠だが、SQL:1999 でチューリング完全になっても論争は終わらなかった。現実には使用率 3 位の現役言語であり、AI が最も大量に書く言語になった今、問うべきは分類ではなく「AI が書いた SQL を検証できるか」だと結論づける。

---

### オープニング

- 「SQL はプログラミング言語か」は英語圏の掲示板でも日本の SNS でも定期的に燃える話題（履歴書に書いてよいか悩む人も多い）。
- Stack Overflow 2025 年調査で SQL の使用率は 59%。JavaScript、HTML/CSS に次ぐ 3 位で、Python や Java より上。

### 第1章 プログラマー以外のために生まれた言語

- 1970 年、IBM の **E. F. Codd** がリレーショナルモデルの論文を発表。データを表で持ち集合演算で扱う設計図だが、関係代数のギリシャ文字と記号だらけで普通の人には読めなかった。
- IBM サンノゼ研究所の若手 **Donald Chamberlin** と **Raymond Boyce**（ボイス・コッド正規形に名を残す）が、記号だらけの SQUARE を経て英語の文のように書ける言語へ設計し直し、1974 年に **SEQUEL（Structured English Query Language）** を発表。
- 狙いは経理や事務担当者が自分でデータを引き出せること。心理学者 Phyllis Reisner の実験で、プログラミング経験ゼロの学生が数時間の講習でクエリを書けた。
- 英国の航空機メーカー Hawker Siddeley が SEQUEL の商標を持っていたため母音を抜いて SQL に。「シークエル」の発音はその名残。
- 1974 年 5 月の発表の数週間後、Boyce は脳動脈瘤で倒れ 27 歳で亡くなった。

### 第2章 「言語じゃない」派の理屈

- 根拠は **宣言型** であること。命令型は手順（読む順・分岐・繰り返し）を書くが、SQL は欲しい結果だけを書き、取り方は DB のオプティマイザが決める。
- 古典的 SQL には変数・ループ・条件分岐がなく、「制御構造のないものは HTML や CSS と同じ記述言語」という整理になる。
- 反論：HTML は見た目を記述するだけだが、SQL は結合・集計・並べ替えで入力から正しいデータを **計算** しており、裏には関係代数という数学がある。

### 第3章 チューリング完全の証明と、その軽さ

- **SQL:1999** で再帰クエリ（組織図やフォルダ階層をたどるための機能）が入り、実質ループを獲得。
- 後年、PostgreSQL 界隈の開発者が再帰クエリとウィンドウ関数で **サイクリックタグシステム**（チューリング完全が証明済みの最小級の計算モデル）を実装し、SQL はチューリング完全だと示された。
- それでも決着しなかったのは、チューリング完全のハードルが驚くほど低いから（2019 年の論文でカードゲーム「マジック：ザ・ギャザリング」もチューリング完全と証明、PowerPoint のアニメーションでも計算機が作れる）。

### 第4章 50 年選手が使用率 3 位である現実

- 2025 年調査：JavaScript 66%、HTML/CSS 62%、SQL 59%。1974 年生まれの言語が 51 年後もトップ 3 にいる例は他にない。
- 2009 年頃の **NoSQL ムーブメント**（MongoDB、Cassandra）で一度本気で「SQL の終わり」が語られたが、Hadoop・Spark・Kafka は後から SQL の窓口を付け、BigQuery や Snowflake も操作の中心は SQL、MongoDB まで SQL 互換の接続を用意した。
- 理由は SQL を読み書きできる人口が桁違いに多いから（分析者・経理・営業企画も書ける）。これは「英語のように書ける」設計の直接の成果。

### 第5章 AI が最も大量に書く言語

- **Text-to-SQL**：「先月の地域別売上を出して」と日本語で頼むと AI が SQL を生成・実行する分野が急成長。
- 専門家でなくても自然言語で問い合わせるという 50 年前の SQL の夢を LLM が実現しつつあり、SQL は役目を終えるどころか **AI が最も大量に書く言語** になった。
- ただし人間の仕事は残る。結合条件が 1 つ抜けただけで売上が 2 倍に膨らむような、見た目はもっともらしい誤りが平気で出る。書く力より **読んで間違いに気づく力**（クエリレビュー）が要る。

### まとめ

- SQL は非プログラマーのために意図的に宣言型で設計された言語で、それが「言語じゃない」論と 50 年の生存力の両方の源。
- チューリング完全の証明は論争の決め手にならなかった。
- これからのエンジニアの価値は、SQL の分類より AI が書いた SQL を検証できるかどうかで分かれる。
