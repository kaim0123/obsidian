## 詳しい要約

**テーマ：NoSQL の登場で RDB は置き換わったのか（2026 年の数字で検証）**

結論は「置き換わっていない。でも世界は広がった」。NoSQL は RDB を倒すためではなく RDB だけでは解けない問題のために生まれ、新しい市場を作って成長している。今は RDB が NoSQL の機能を取り込み、NoSQL が SQL に歩み寄る「融合」の時代で、エンジニアに求められるのはデータに応じた保存・検索方法を判断する力だ。

---

### 第1章 「NoSQL が来た！RDB は終わり！」騒動の正体

- 2010 年頃、SNS とスマホの爆発でデータ量が急増し、Twitter・Facebook・Google は従来の RDB では処理しきれない**スケールの問題**に直面。
- MongoDB・Cassandra・Redis などが「スケーラビリティ最強」「スキーマフリーで開発爆速」と盛り上がり、「RDB は遺物」と言う人も現れた。
- 名前の意味は当初の「No SQL（SQL は不要）」から「**Not Only SQL（SQL だけじゃない）**」へ変化。この変化が騒動の結末を象徴している。

### 第2章 RDB と NoSQL は何が違うのか

- 図書館のたとえ：**RDB は図書館の書棚**（分類番号順に整理、入れるのは手間だが探すのは速い）、**NoSQL は倉庫のコンテナ**（形がバラバラでも詰め込める、運び込みは速いが特定の箱を探すのは大変）。
- NoSQL の 4 種類：

| 種類 | 代表 | 特徴 |
|---|---|---|
| ドキュメント型 | MongoDB | JSON のような形式で保存 |
| キーバリュー型 | Redis | キーと値のペアをメモリに置き超高速アクセス |
| カラム型 | Cassandra | 列ごとに管理し大量書き込みに強い |
| グラフ型 | Neo4j | データ同士のつながりを高速にたどる（SNS の友達関係、不正検知） |

- 最も重要な違いは **ACID と BASE**：
  - **ACID**（Atomicity・Consistency・Isolation・Durability）：データを絶対に壊さない約束。銀行送金で「A から引いたのに B に足されない」を防ぐ。
  - **BASE**（Basically Available・Soft state・Eventually consistent）：最終的には揃うが一瞬ずれることを許容。SNS のいいね数なら困らない。
- どちらが優れているかではなく、**どちらが適しているか**の問題。

### 第3章 2026 年の数字が語る「置き換わっていない」現実

- DB-Engines ランキング（2026 年 3 月）：1 位 Oracle、2 位 MySQL、3 位 SQL Server、4 位 PostgreSQL、5 位 MongoDB。**トップ 5 のうち 4 つが RDB**。MongoDB のスコア約 384 に対し Oracle は約 1182。
- RDB 側で最も勢いがあるのは **PostgreSQL**：Stack Overflow 2024 年調査でプロ開発者の 49% が使用し全 DB 中 1 位、2023 年の DB-Engines 年間最優秀 DB。
- Mordor Intelligence の調査で 2025 年の DB 市場における **RDB シェアは 57.3%**。
- NoSQL 市場は年率 22% で成長（2026 年に約 104 億ドル、2034 年に 930 億ドル予測）。ただし RDB を奪っているのではなく、データ増加で**新しい市場（パイ）を作っている**。

### 第4章 NoSQL が勝った場所・勝てなかった場所

- **勝った場所**：
  - SNS（投稿、画像メタデータ、視聴履歴）など「大量に書いて緩く読む」データ
  - IoT（工場センサー、車のテレメトリ、スマート家電のログ）で水平スケーリングが活きる
  - Redis などインメモリの**キャッシュ**で Web アプリの応答を劇的に高速化
- **勝てなかった場所**：金融（送金・証券取引・保険契約）、在庫管理、会計、医療記録など**整合性が命**の領域。企業の基幹システムの大半は今も RDB。

### 第5章 「置き換わる」ではなく「住み分け」、そして融合へ

- RDB が NoSQL の機能を取り込んでいる：PostgreSQL は JSON のネイティブ処理、全文検索、ベクトル検索まで対応。PostgreSQL だけで RDB＋ドキュメント DB＋全文検索＋ベクトル DB＋時系列 DB の 5 つを統合したという報告も。
- NoSQL も SQL に寄ってきている：Couchbase は SQL 風の **N1QL** を搭載、MongoDB の集約パイプラインも SQL に近づく。
- 業界レポートは SQL と NoSQL の境界が曖昧になり「**コンバージド・データベース**」へ向かうと指摘。

### まとめ

- NoSQL は RDB の代替ではなく、RDB だけでは解けないスケールの問題のための追加の選択肢。
- 2026 年も RDB は市場の過半数を占め、PostgreSQL を筆頭にむしろ元気。
- 整合性が必要な領域は RDB、大量書き込み・キャッシュ・IoT は NoSQL が強い。
- 両者は融合しつつあり、重要なのは「このデータにはどんな保存と検索が最適か」を判断する力。
