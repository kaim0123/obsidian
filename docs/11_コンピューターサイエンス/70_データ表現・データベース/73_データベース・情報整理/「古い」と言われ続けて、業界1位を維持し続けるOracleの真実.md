## 詳しい要約

**テーマ：「古い・高い」と言われるOracleが、なぜ今も業界1位であり続けるのか**

「Oracleは古い」という評判とは裏腹に、2026年もDB-Enginesランキング世界1位、2024年にはERP市場でSAPを抜いて1位となった。強さの源泉は、RAC・Exadata・PL/SQL・ACIDの実証・Autonomous DBといった技術的優位、障害時の単一責任窓口と長期サポート、そしてクラウド／AI時代の戦略転換、何より47年の実証と社会インフラへの根の深さにある。

---

### 序章：3つの数字

- 2026年1月のDB-Enginesランキング：**1位 Oracle**、2位 MySQL、3位 SQL Server、4位 PostgreSQL
- 2024年、1980年代からSAPが守ってきた **ERP市場の世界1位** をOracleが奪取
- 2026年4月時点の未消化契約残高（今後売上になる予定の金額）は **4,550億ドル**。テック業界史上最大級

### 第1章 「Oracleは古い」業界認識と実態のずれ

- 1977年ラリー・エリソンらがSDLを起業、1979年 **Oracle V2** をリリース（世界初の商用RDB）。2026年も Oracle Database 23ai が現役
- 2010年代はMySQL・PostgreSQL・MongoDBなどのOSS DB、2020年代はSnowflake・ClickHouseなどのクラウドDBが台頭し、新規プロジェクトの95%以上は新しいDBを選ぶ
- **パラドックス**：新規採用は少ないが、既存利用は減らない。世界の主要銀行のほぼ100%、航空会社の予約システム、電力・保険・通信・証券取引の基幹がOracle。日本のメガバンクや大企業の基幹業務も同様
- ポイント：表面的な評判と実際のシェアが極端にずれた特殊な存在

### 第2章 Oracleの5つの技術的優位

| 技術 | 内容 |
|---|---|
| **RAC**（Real Application Clusters） | 複数サーバーで1つのDBを共有。1台止まっても処理継続、最大100台までスケール。**アプリを1行も変えずに実現**。PostgreSQLのレプリケーションやMySQLのクラスタリングはアプリ側にマスター／スレーブの意識が必要 |
| **Exadata** | ハードとDBソフトを統合したDB専用マシン。**Smart Scan** でストレージ層でSQLを実行し、データの99%をストレージから動かさない。Gartner調査でクエリ性能平均10倍、応答時間最大90%短縮。AT&T・Accentureが基幹DWHに利用 |
| **PL/SQL** | 1992年に登場したDB内で動く独自言語（ストアドプロシージャ、トリガー）。世界中で累計数十億行の業務ロジックがDB内に書かれ、書き換えは実質不可能 → 強力なロックイン |
| **ACIDの実証** | 全DBがACIDを謳うが実装の質はばらつく。Oracleは47年間、電源停止・ハード故障・ネットワーク切断などでデータを失わない仕組みを実証。金融・医療・政府で選ばれ続ける最大の理由。「47年の実証は3年では作れない」 |
| **Autonomous Database** | 2018年投入の自律型DB。プロビジョニング・チューニング・パッチ適用などを自動化しDBA不要を目指す。2024年に **AIベクトル検索** を内蔵し、専用ベクターDBなしでRAGアプリを構築可能 |

### 第3章 Single throat to choke：業界が払い続ける本当の理由

- **Single throat to choke（単一責任窓口）**：大規模障害時、DB・サーバー・ネットワーク・ストレージのどこが原因か分からない間にベンダー同士の責任のなすり合いが起きる
- Exadata、Oracle Linux、DB、仮想化、ストレージ、ネットワークまでOracle製なら、Oracle1社に電話すれば済む
- ある銀行のITマネージャー：「選ぶ理由は性能でもコストでもない。深夜2時に本番が止まったとき誰に電話するか、その答えが決まっていることが最大の価値」
- サポートは24時間365日、重大障害時はエリソン本人が出ることもあると言われる
- **Lifetime Support**：2003年リリースのOracle 10gも2026年に有償サポート継続。PostgreSQLのメジャーバージョンサポートは5年で、以降は自分でアップグレードが必要 → エンタープライズでは大きなリスク

### 第4章 2024年SAP超えとクラウド／AI時代の逆襲

- 2010年代は「クラウドに乗り遅れた」と評された。2017年に **OCI**（Oracle Cloud Infrastructure）を正式に立ち上げたが当初シェアは小さかった
- 2024年、AWS・Azure・Google Cloudの3大クラウドすべてで **Oracle Database@AWS／@Azure／@Google Cloud** を提供開始。競合クラウドの中に自社DBを置き、ロックインを保ったまま顧客がクラウドを選べるようにした
- 2025年にAMDと **5万GPU規模のAIスーパークラスター** 契約（2026年稼働予定）、NVIDIAとも深く連携
- クラウドインフラ売上は2026年に70%成長予測

### 第5章 47年の実証と業界深層への根の深さ

- 業界がOracleに戻る3つの理由：
  1. **AI時代の信頼性要求**：AIが業務判断に関わると、データ破損はAIが嘘を学ぶことにつながる。信頼できるDBの上に信頼できるAIが乗る
  2. **新興技術の限界の認識**：専用ベクターDBは汎用DBに敗北、NoSQLはSQLに統合、マイクロサービスは運用の難しさで揺り戻し
  3. **47年の実証の絶対的な価値**：20〜30年動く基幹システムに必要なのは新機能ではなく「止まらない・データを失わない」保証
- 業界のパターン：表層の流行（JSフレームワーク、AIの話題）は移り変わるが、実務の中核（銀行のメインフレームのCOBOL、基幹のOracle）はほとんど動かない
- 新規プロジェクトならコスト・開発速度・コミュニティの観点で **PostgreSQLを選ぶのが正しい**。しかし銀行・政府・保険・エネルギー・通信などの社会インフラ層ではOracleは消えない

### まとめ

- Oracleは評判と実シェアが極端にずれており、社会インフラの基幹を今も支えている
- RAC・Exadata・PL/SQL・ACIDの実証・Autonomous DBが新興DBの追いつけない技術的優位
- 単一責任窓口と長期サポートこそ、企業が高額を払い続ける本当の理由
- クラウド各社への進出とAIインフラで復活し、強さの本質は「47年の実証」と「業界深層への根の深さ」
