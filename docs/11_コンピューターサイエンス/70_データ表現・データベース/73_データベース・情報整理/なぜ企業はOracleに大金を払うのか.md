## 詳しい要約

**テーマ：無料 DB があるのに企業が Oracle に高額を払う理由**

MySQL や PostgreSQL は無料で優秀だが、止まれば大損害が出るミッションクリティカルなシステムでは足りない部分がある。Oracle が選ばれる理由は「サポートと保証」「40 年の信頼と実績」「RAC・Data Guard など大規模向け機能」の 3 つ。一方でコストやクラウド DB の台頭から Oracle を選ばない選択肢もあり、要件で選ぶことが大事、という解説。

---

### 導入

- Oracle のライセンス費用は年間数千万円、大規模だと億単位になることも。それでも **Fortune 500 企業のほとんど** が Oracle を使っている

### 第1章 Oracle とは何か

- **1977 年創業**、世界初の商用リレーショナルデータベースを作った。創業者は **ラリー・エリソン**
- IBM の研究者がリレーショナル DB の論文を発表したが、IBM 自身は製品化に消極的 → エリソンが先に製品化して市場を取った
- 40 年以上エンタープライズ DB のトップ。銀行・保険・通信・大手メーカーの基幹システム（銀行振込、携帯料金計算など）で使われる **デファクトスタンダード**

### 第2章 無料の DB では何がダメなのか

- MySQL・PostgreSQL は優秀で技術的にも成熟しており、多くの Web サービスやスタートアップでは十分
- ただし **ミッションクリティカル**（銀行の勘定系、航空予約、証券取引所など、1 時間止まるだけで数億円の損失が出るシステム）では不安が残る。使えないわけではないがリスクを負う覚悟が必要

### 第3章 理由①：サポートと保証

- 深夜 3 時に障害が起きたとき、無料 DB では自分で調べるかコミュニティ頼み
- Oracle は **24 時間 365 日のサポート**、専門エンジニアが対応し現地に駆けつけることも（ある金融機関では 2 時間で原因特定した例）
- **時間を金で買う**：障害が長引くほど損失は膨らむので、数時間早く復旧できればサポート費用は回収できる
- **保証**：製品に責任を持ち、原因調査と修正パッチを提供。無料 DB は自己責任

### 第4章 理由②：信頼性と実績

- 保守的な銀行の勘定系で **40 年使われてきた実績** は簡単には積み上げられない
- DB の乗り換えは数年がかりでリスクが大きい → 動いている Oracle を使い続ける＝ **ベンダーロックイン**。批判もあるが、安定重視の企業には合理的な選択でもある

### 第5章 理由③：機能の差

- **RAC（Real Application Clusters）**：複数サーバーで 1 つの DB を動かし、1 台壊れても別サーバーが引き継ぐ。負荷分散で大量アクセスにも耐える
- **Data Guard**：災害対策。東京のデータセンターが被災しても大阪で即座に復旧
- 無料 DB でも近いことはできるが自前構築が必要（PostgreSQL で RAC 相当の冗長化・自動フェイルオーバーを組むと設計から構築まで数ヶ月、問題も自分で解決）
- ライセンス費だけ見ると高いが、**運用コスト・人件費まで含めると逆転する** こともある。機能の有無だけでなく「誰が面倒を見てくれるか」が重要

### 第6章 それでも Oracle を選ばない選択肢

- スタートアップや中小企業には年間数千万円は非現実的 → MySQL・PostgreSQL で十分なことが多い
- **クラウド DB**（AWS Aurora、Google Cloud Spanner、Azure Cosmos DB）：初期費用が少なく従量課金、サーバー管理不要、スケーラビリティも高い
- 新規システムではクラウド DB が増えているが、Oracle 独自機能を使った既存システムの移行は大改修が必要 → **「新規はクラウド DB、既存は Oracle」** と使い分ける企業も多い

### まとめ

- ミッションクリティカル・予算あり・長期運用なら Oracle は有力、コスト重視ならクラウド DB や無料 DB
- Oracle の価値は「24 時間サポートと保証」「40 年の実績」「RAC・Data Guard などの機能と運用負担の軽減」
- 流行で選ばず、自分たちの要件に合った DB を選ぶことが大事
