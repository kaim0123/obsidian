#文字コード #ゆるコンピュータ科学ラジオ\_文字コード

## 要約

**文字コードシリーズ第2回の位置づけ**

前回の「文字コードとは何か」「64文字縛り」から、今回は歴史に踏み込む。1960年代の混沌からASCII、ビット拡張、切り替え方式（ISO/IEC 2022）、可変長2バイト方式まで、文字数不足をどう解決してきたかを追う。堀本が「左脳・右脳」「脳の取り替え」「サウナ」などの例えを多用する回で、リスナーが例え本体を覚えてしまう可能性も自覚している。

**文字コード制定前の地獄（1960〜70年代）**

文字コードという統一規格がない時代、開発者ごとに「あ＝30番」「い＝31番」など割り当てがバラバラだった。同じメールクライアントでも送受信側のソフトが違えば全文文字化け——実質的に暗号状態。1960年代は文字化けまみれでソフトがまともに使えなかった。現在は文字コード自動判定が進み文字化けは減ったが、当時は「万人対万人の闘争」に近い状態だった。

**ASCII：最初の本格的文字コード（1963年）**

**ASCII**（American Standard Code for Information Interchange＝情報交換のためのアメリカ標準コード）が1963年頃に制定され、実質最初の文字コードとして普及した。

- **7ビット＝128文字**：1ビットは0か1。7ビット並べると2⁷＝128通り。
- **収録内容**：大文字・小文字アルファベット（52文字）、数字0〜9（10文字）、記号（! ? $ など）、**制御文字**（約30文字：改行、タブ、ページ区切りなど「文字」ではなく機械への指示）。
- **128文字ですぐ埋まる**：アルファベットと制御文字だけで80文字超。日本語（ひらがな・カタカナ・漢字）は一切入らない。
- **6ビット派閥も存在**：1バイト＝8ビットが主流になる前、6ビットを1単位とする派閥もあった（2の累乗にこだわる必然性はなく、人間が恣意的に決めた）。

**なぜ7ビット？8ビット目の1ビット**

1バイトは8ビットなのにASCIIは7ビットしか使わない。残り1ビットは**誤り検出用（パリティビット）**に使っていた——通信途中で0と1が反転しても検出できるようにするため。QRコードの冗長性と同じ発想。後にこの8ビット目を文字用に開放して256文字に拡張する動きも起きる。

**ISO/IEC 646：国際版ASCIIと10文字の自由枠**

ASCIIを下敷きに国際的に使えるよう改めたのが**ISO/IEC 646**（前回登場した国際通貨記号を収録した規格）。各国ごとに**約10文字だけ自由に設定できる領域**が解放された。ドイツ語のウムラウト、アクサン記号、オングストローム記号など各国が割り当て——しかし10文字では日本語どころかひらがな50音すら入らない。ユニコードにはフェニキア文字や線文字Bなど古代文字まで収録されているが、ASCII時代の国際規格には到底足りなかった。

**解決策の第一歩：ビットを増やす**

7ビット＋誤り検出用1ビットを文字用に回すと8ビット＝256文字（2⁸）。アルファベット圏ならこれでかなり足りるが、日本人・中国人には依然として無理。ひらがな・カタカナだけでも約100文字。検討された案として、アルファベットを捨てる、日本独自規格を作る、カタカナを諦める、画像（デコメ）で代用する（通信速度の問題で非現実的）などが挙がるが、いずれも限界がある。

**ISO/IEC 2022：切り替え方式（1970年頃）＝「脳取り替え企画」**

256文字の枠を固定せず、**途中で文字セットを切り替える**方式が**ISO/IEC 2022**。堀本はこれを「脳取り替え企画」と呼ぶ。

- **GL領域とGR領域**：コード空間を左（GL）と右（GR）に分ける。GLは固定（アルファベット・基本記号）、GRは好きな文字セットを載せ替え可能——左脳・右脳のたとえに例える。
- **カートリッジ方式**：同じ番号129に、モードによって「ひ」または「ア」を割り当てる。文中に「ここからひらがなモードです」という**制御文字**を埋め込み、機械が切り替える。
- **ラブレター例え**：堀本がひらがな、水野がカタカナを担当し、書けない字は相手の「脳（う）」を借りて付け替える——分かりにくい例えとして番組の名物に。
- **漢字対応**：常用漢字1000字超を使うには、小1担当の山田君、小2担当の斎藤君……と多数の「脳」を用意し、頻繁に切り替える必要がある。2136文字なら21人分。
- **欠点**：切り替え指示が多すぎて文章自体が長くなる、制御文字を間違えると別の場所で読んでしまう、多数の文字セットをストックする負担。

**第二の解決策：全体を2バイトにする**

切り替えの限界を超え、**1文字あたり2バイト（16ビット）**を使う方式。2¹⁶＝65,536文字なら常用漢字はほぼ収まる。

- **不経済性**：英語だけ送る人もA一文字が2バイトになり、通信量が2倍になる——脳全体を2倍にすると消費カロリーも2倍、という例え。
- **可変長の問題**：1バイト文字と2バイト文字が混在すると、「先頭50バイト取る」といった処理で文字の途中で切れ、別の文字として解釈される（ファイル分割時の文字化け）。

**第三の解決策：切り替え先（右側）だけ2バイトにする**

GL（左・固定）は1バイトのまま、アルファベット圏の通信は無駄を抑え、GR（右・切り替え先）だけ2バイトの広大な領域にする——「右側だけ頭がでかい人」という例え。必要なときだけ大きい「脳」を装着する思想で、英語話者と日本語話者の両方に配慮する。

**Unicodeと4バイト時代**

2バイト（65,536文字）でも世界中の文字は足りない。3バイト、4バイト（UTF-8など）へと拡張し、Unicodeでは1200万文字超を1文字ずつマッピングする方針。1文字に4バイト使う不経済さと、文字数の膨張——このループが文字コード史の苦悩として繰り返される。

**なぜ文字コードは複数存在するのか**

「1個に統一すればいいのでは？」という疑問への答え：**用途によって便利な方式が違うから**。

- **1バイト固定（ASCII系）**：英語のみの通信向き。日本語は不可。
- **切り替え方式（ISO 2022）**：256文字以内で多言語を扱えるが、切り替えが煩雑。
- **全体2バイト**：漢字圏向きだが、英語のみの通信が非効率。
- **可変長（左1バイト・右2バイト）**：両方に配慮するが、処理が複雑。

実際の仕様はさらに複雑で、GL/GRの両方を切り替える規格もある（堀本の左脳・右脳例えは便宜上の単純化）。

**例えサウナ：理解のための混乱**

堀本は例えを多用し、水野を混乱させてから「例えなしで言うと……」と整理する「サウナ方式」を採用。例えている間は制御文字の話など本体が伝わらないが、例えを外すとスッと理解できる——逆説的に例えが理解の助けになる、という番組の自己言及。

**次回予告**

次回は文字コードと**技術的負債**、**幽霊文字（幽霊漢字）**など雑学要素多めの回。堀本が「キレている」幽霊漢字の話を予告。
