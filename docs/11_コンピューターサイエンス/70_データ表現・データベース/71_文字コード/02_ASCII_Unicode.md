# ASCIIとUnicode

## ASCIIとは
**American Standard Code for Information Interchange**の略。アメリカで1960年代に制定された、英数字と基本記号を**7ビット（128文字）**で表す規格です。

## ASCIIの内容

```
0x00〜0x1F  制御文字（NUL, TAB, LF, CR 等）
0x20        空白
0x21〜0x2F  !"#$%&'()*+,-./
0x30〜0x39  0〜9
0x3A〜0x40  :;<=>?@
0x41〜0x5A  A〜Z
0x5B〜0x60  [\]^_`
0x61〜0x7A  a〜z
0x7B〜0x7E  {|}~
0x7F        DEL
```

### 例
- `'A'` = 65 = 0x41
- `'0'` = 48 = 0x30
- `' '` = 32 = 0x20
- `'\n'` = 10 = 0x0A

## ASCIIの特徴

### 長所
- 7ビットで128文字、1バイトで十分
- シンプルで普及度が高い
- 現代のほぼ全ての文字コード互換性の基礎

### 限界
- **英語しか扱えない**
- 日本語、中国語、アラビア語などに非対応
- 特殊記号・絵文字も扱えない

## ASCII拡張
8ビット目を使い256文字に拡張した各種規格。
- **ISO-8859-1（Latin-1）**: 西欧
- **ISO-8859-2**: 中欧
- **ISO-8859-5**: キリル文字
- **Windows-1252**: Windowsの西欧

同じバイトが規格ごとに違う文字を表すため、**混在不可・文字化けが頻発**しました。

## 日本語で使われた拡張
- **Shift_JIS**（Microsoftが普及）
- **EUC-JP**（Unix系）
- **ISO-2022-JP**（メール）

## なぜUnicodeが必要だったか
異なる言語を同じ文書で扱えない、データ交換で壊れる、という問題を解決するため。

- 日本語と中国語を同じ文書に書きたい
- Webで世界中の言語を扱いたい
- グローバルなシステムで一貫した文字表現が欲しい

## Unicodeとは
**世界中のすべての文字を1つの符号空間に収める**試み。1991年〜現在も継続的に更新されています。

### コードポイントの範囲
```
U+0000 〜 U+10FFFF  （約111万個の位置）
```

### 収録数
2024年時点で約15万文字超を収録。絵文字・古代文字・記号なども含む。

## ASCIIとUnicodeの関係
UnicodeはASCIIを**そのまま包含**しています。
```
'A' = U+0041 = 65
```
ASCIIの範囲では「ASCIIコード = Unicodeコードポイント」。これが互換性の鍵。

## Unicodeの構造: 面（Plane）
コードポイントは17の「面」に分かれます。

| 面 | 範囲 | 主な内容 |
|---|---|---|
| 0 BMP | U+0000〜U+FFFF | ASCII、ラテン、日本語、中国語等 |
| 1 SMP | U+10000〜U+1FFFF | 絵文字、歴史的文字、数学記号 |
| 2 SIP | U+20000〜U+2FFFF | 拡張漢字 |
| 3 TIP | U+30000〜U+3FFFF | 拡張漢字B |
| 14 SSP | U+E0000〜U+EFFFF | タグ文字 |
| 15-16 PUA | U+F0000〜U+10FFFF | 私用領域 |

日常で使う文字はほぼBMPに収まります。絵文字・拡張漢字は面1以降。

## Unicodeの主要ブロック例

| 範囲 | ブロック名 |
|---|---|
| U+0000〜007F | ASCII |
| U+0080〜00FF | Latin-1補助 |
| U+3040〜309F | ひらがな |
| U+30A0〜30FF | カタカナ |
| U+4E00〜9FFF | CJK統合漢字 |
| U+1F000〜1F9FF | 絵文字 |

## 符号化（Encoding）との違い
Unicodeはあくまで**文字に番号を振っただけ**。実際にバイト列として保存・送信するには符号化方式が必要:
- **UTF-8**: ASCIIと互換、可変長
- **UTF-16**: 2または4バイト
- **UTF-32**: 4バイト固定

## 文字の識別: ユニコード正規表記
`U+XXXX` の形式で表す。Xは16進数。
```
U+0041  → 'A'
U+3042  → 'あ'
U+1F363 → '🍣'
```

## Unicodeの拡張

### サロゲートペア
UTF-16で **U+10000 以上** を表すための仕組み。2つの16bit値の組。
- 高位サロゲート: U+D800〜DBFF
- 低位サロゲート: U+DC00〜DFFF

### 結合文字 / 合成文字
1つの表示文字が複数のコードポイントで成り立つ場合。
```
"é" = U+00E9（単一）
"é" = U+0065 + U+0301（e + 合成アクセント）
```
外見は同じでもバイト列が違う → 正規化が必要（別章）。

### ゼロ幅結合子（ZWJ）
```
👨‍👩‍👧 = 👨 + ZWJ + 👩 + ZWJ + 👧
```
1つの絵文字に見えて、内部は複数コードポイント。

### 異体字セレクタ
同じ字の字形違い（旧字・新字など）を指定。
```
"葛" + U+E0101  → 葛の異体字
```

## プログラミングでの扱い

### Python 3
文字列は抽象的なUnicode文字列（コードポイント列）。
```python
s = "あA🍣"
len(s)  # 3
```

### JavaScript
内部はUTF-16。`length` は16bit単位の数。
```javascript
"🍣".length        // 2（サロゲートペア）
[..."🍣"].length    // 1
```

### Rust
`String` / `&str` はUTF-8バイト列。`.chars()` でコードポイント。
```rust
let s = "あA🍣";
s.len();                  // 7（UTF-8バイト数）
s.chars().count();        // 3
```

### Go
`string` はUTF-8バイト列。`rune` がコードポイント。

### Java
`String` はUTF-16。`char` は16bit。サロゲートペアの扱いが必要。

## 絵文字のバージョン
Unicodeは毎年拡張される。
- Unicode 6.0（2010）: 絵文字の本格導入
- Unicode 9.0: 肌色修飾
- Unicode 13.0: 人物絵文字の多様化
- Unicode 15.1（2023）: 最新

端末・フォントが絵文字を描画できるかは別問題。表示できない = "□" や tofu になる。

## Unicode vs 多国語対応（i18n）
Unicodeは**文字コードの統一**。
i18n（国際化）は**アプリがどう多言語対応するか**で、文字コード以外にも
- 翻訳（メッセージカタログ）
- 日付・通貨・数値形式
- 書字方向（右→左言語）
- 複数形の扱い

などを含みます。

## まとめ
- **ASCII** = 英数字+記号の7ビット規格、Unicodeの土台
- **Unicode** = 世界の文字を1つの符号空間に統合
- Unicodeは「番号のつけ方」、**符号化はUTF-8/16/32**で別
- ASCII範囲はUnicodeとコードが一致 → 互換性の鍵
- 現代はほぼ **Unicode（UTF-8）** 一択と考えてよい
