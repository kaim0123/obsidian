#浮動小数点 #プログラミング #JavaScript #Python #エンジニア

## 詳しい要約

**テーマ：0.1 + 0.2 = 0.30000000000000004 になる理由を 1 ビットずつ追う**

コンピューターに 0.1 + 0.2 を計算させると 0.3 と等しくならず、末尾に「4」がつく。JavaScript・Python・Ruby などどの言語でも同じ結果になる。原因は、0.1 が 2 進数で書き切れずに 64 ビットへ丸めて保存されること、そして足した答えがさらに「偶数への丸め」で隣のメモリへ寄せられることにある。コンピューターが計算を間違えたのではなく、決まり通りに丸めた結果である。

---

### 書き切れない数を切ると元に戻らない

- 10 進数では 1/3 を最後まで書き切れない。小数点以下 3 桁で切って 0.333 にし、3 倍しても 0.999 で 1 に戻らない。
- コンピューターの中でも同じことが起きる。0.1 は 10 進数では書き切れるが、コンピューターは小数を **2 進数** で持つ。

### 0.1 を 2 進数にする

- 2 進数の小数の桁は右へ 1/2、1/4…と小さくなる。0.5 や 0.75 は途中で桁が終わる。
- 小数を 2 倍して 1 の位に出た数字を取り出していくと、0.1 は 0.2 → 0.4 → 0.8 → 1.6 → 1.2 → 0.4… と 0.4 に戻ってきて、**「0011」が無限に繰り返す**。
- 理由：0.1 = 1/10、10 = 2 × 5。約分した分母が 2 の累乗だけなら書き切れるが、**5 が残ると書き切れない**。10 進数にとっての 3 が、2 進数にとっての 5 にあたる。

### 64 個の箱に詰める（浮動小数点数）

- JavaScript や Python の小数は 64 ビットで持つ。内訳は **符号 1 ビット・指数 11 ビット・仮数 52 ビット**。
- 0.00123 = 1.23 × 10⁻³ のように「数字の並び」と「小数点の位置」に分ける考え方。0.1 は 1.1001… × 2⁻⁴。指数はマイナスも表せるよう **1023 を足して** 格納する。通常の数では先頭が必ず 1 なので、小数点より右の 52 桁だけを入れる。
- 52 桁目で無限の並びを切るとき、切り捨てではなく近い方へ寄せる。0.1 ははみ出しが半分より大きいので繰り上がり、**本当の 0.1 よりわずかに大きく** 入る（ずれは小数点以下 18 桁目）。
- 0.2 は 0.1 の仮数そのままで指数が 1 大きいだけなので、やはり少し大きい。一方 0.3 は丸めの結果 **少し小さく** 入る。

### 丸めの正体（偶数への丸め）

- 64 ビットで表せる数は数直線上に「目盛り」のように飛び飛びに並ぶ。0.3 付近の間隔は小数点以下 17 桁目でやっと見える幅。答えが目盛りの間に落ちたら最も近い目盛りへ寄せる。これが **丸め**。
- 0.1 と 0.2 の中身を正確に足すと、「0.3 と書いたときの目盛り」と「そのすぐ上の目盛り」の **ちょうど真ん中** に落ちる（0.1 の並びの末尾が「10」で、3 倍するとはみ出しがちょうど半分になるため）。
- 真ん中のときは **仮数の最後の桁が 0（偶数）になる方** へ寄せる決まり。0.3 の目盛りは末尾 1、上の目盛りは 0 なので上が選ばれる。毎回同じ向きに寄せると答えが偏るのを防ぐためのルール。
- この上の目盛りを 10 進数で書くと 0.30000000000000004。つまり「0.3 と書いた数」と「足し算の答え」は **隣り合う別の目盛り** で、比較すると false になる。

### 表示のしくみ

- 画面の数字は中身そのものではない。JavaScript や Python は **その目盛りに戻ってこられる最短の 10 進数** を表示する。0.1 と書いた数は 0.1 の目盛りに戻るので「0.1」と表示される。
- 足し算の答えは「0.3」と書くと隣の 0.3 の目盛りに戻ってしまうため、区別するには 17 桁必要。桁数を指定して表示すると 0.1 の正体が見える。
- 人に見せる数は、桁数を決めて丸めてから表示する。

### IEEE 754

- どの言語も同じ答えになるのは、**IEEE 754** という規格に沿って小数を持っているから。1985 年に、機械ごとにバラバラだった小数の持ち方と丸め方を揃えるために決まった。

### 実務で気をつける 3 つのこと

1. **小数同士を == で比べない**。差が十分小さいかで判定する（Python なら `math.isclose`）。
2. **小さなずれは足し続けると積もる**。0.1 を 10 回足しても 1 にならない（Python の `sum` は 3.12 からずれを抑える足し方になり 1.0 を返す）。1991 年の湾岸戦争では、パトリオットミサイルのシステムが 2 進数で切り捨てた 0.1 秒を使って時間を計算し、100 時間稼働でずれが約 1/3 秒になり迎撃失敗の一因となって 28 人の米兵が亡くなった（24 ビットの古い持ち方だが、0.1 を書き切れない点は同じ）。
3. **お金を小数で持たない**（最も重要）。方法は 2 つ：最小単位の **整数** で持つ（0.1 ドル → 10 セント。ある決済 API は 1 ドルを 100 セントの整数で受け取る）、または **10 進数のまま計算する型** を使う（Python の `Decimal`、Java の `BigDecimal`。文字列で "0.1" を渡せば正確に入る）。

### まとめ

- 0.1 は分母に 5 を含むため 2 進数で書き切れず、64 ビットに丸めて少し大きく保存される。
- 0.1 + 0.2 の正確な和は 2 つの目盛りのちょうど真ん中に落ち、偶数への丸めで上側の目盛り（…04）が選ばれる。
- 表示は「目盛りに戻れる最短の 10 進数」なので、0.1 は 0.1 と見えるが中身は近似値。
- 実務では等値比較を避け、誤差の蓄積に注意し、お金は整数か Decimal 型で扱う。
