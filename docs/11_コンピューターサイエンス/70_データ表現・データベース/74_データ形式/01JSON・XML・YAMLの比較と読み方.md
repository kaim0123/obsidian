# JSON・XML・YAMLの比較と読み方

> [!abstract] この記事で分かること
> - API やツールで使う 3 つのデータ形式（JSON・XML・YAML）の違いと使い分け
> - JSON の文法ルールと 6 つのデータ型、正しい JSON・誤った JSON の見分け方
> - 入れ子（ネスト）になった JSON をプログラムからたどる方法

## 1. データ形式の比較：JSON・XML・YAML

### 1.1 データ形式（エンコード方式）とは

API やツールでデータをやり取りするには、「データをどういう文字の並びで表すか」を決める必要があります。これを **データ形式（データのエンコード方式）** といいます。主なものは **JSON・XML・YAML** です。

**同じデータでも JSON・XML・YAML のどれでも表せます。** 形式が違っても、表している中身（どの項目にどの値が入るか）は同じです。

#### 同じインターフェース情報を3形式で表す

**JSON**（`{ }` と `[ ]` で階層を表す。REST API で主流）

```json
{
  "interface": {
    "name": "GigabitEthernet0/1",
    "enabled": true,
    "vlans": [10, 20]
  }
}
```

**XML**（開始タグと終了タグでデータを囲む。NETCONF で使用）

```xml
<interface>
  <name>GigabitEthernet0/1</name>
  <enabled>true</enabled>
  <vlans>10</vlans>
  <vlans>20</vlans>
</interface>
```

**YAML**（インデントで階層を表す。Ansible のプレイブックで使用）

```yaml
interface:
  name: GigabitEthernet0/1
  enabled: true
  vlans:
    - 10
    - 20
```

### 1.2 比較表

| 項目 | JSON | XML | YAML |
| --- | --- | --- | --- |
| 階層の表し方 | `{ }`（オブジェクト）と `[ ]`（配列） | `<タグ>...</タグ>` の入れ子 | **インデント（字下げ）の深さ** |
| インデントの意味 | 見やすさのためだけ。**文法上の意味はない** | 見やすさのためだけ | **文法上の意味がある**（ずれると意味が変わる／エラー） |
| 主な用途 | **REST API**（最も一般的）、RESTCONF | **NETCONF**、RESTCONF | **Ansible** のプレイブック、設定ファイル |
| 特徴 | 人にも読みやすく、プログラムでも扱いやすい | 冗長だが厳密 | 括弧・クォートが少なく人が読み書きしやすい |
| HTTP の Content-Type | `application/json` | `application/xml` | （API ではあまり使わない） |

### 1.3 YAML の基本

```yaml
---                      # 文書の開始（省略可）
- name: VLANを作成        # 「- 」はリスト（配列）の要素
  hosts: switches        # 「キー: 値」で辞書（マッピング）
  gather_facts: false
  tasks:
    - name: VLAN 10
      cisco.ios.ios_vlans:
        config:
          - vlan_id: 10
            name: Sales
```

- **インデントの深さで階層が決まる**（タブではなく **スペース** を使う）。スペースの数がずれると意味が変わったりエラーになったりします。
- `-` はリストの要素、`キー: 値` は辞書。
- `#` 以降はコメント（JSON にはコメントがない）。

### 1.4 XML の基本

```xml
<?xml version="1.0" encoding="UTF-8"?>
<interface>                          <!-- 開始タグ -->
  <name>GigabitEthernet0/1</name>    <!-- 要素：<タグ>値</タグ> -->
  <enabled>true</enabled>
</interface>                         <!-- 終了タグ（/ が付く） -->
```

- 開始タグ `<name>` と終了タグ `</name>` で値を囲む。
- 入れ子で階層を表す。

### 1.5 データ形式と間違えやすいもの

| 用語 | 正体 |
| --- | --- |
| **MIB** | SNMP で管理する情報の定義（データベース）。REST API のデータ形式ではない |
| **Syslog** | ログメッセージを送るためのプロトコル。データ形式ではない |
| **CSV** | 値をカンマで区切って並べる表形式。**階層構造は表せない** |
| **HCL** | Terraform で使われる設定言語（[[03_Terraform入門]]） |
| **YANG** | データの「構造を定義する」言語（データモデル）。データ形式そのものではない（[[06_ネットワーク自動化とSDN]]） |

### ひっかけポイント・よくある誤解

- REST API でよく使うデータ形式は **JSON と XML**。MIB（SNMP の定義）や Syslog（ログのプロトコル）は違う。
- 「インデントで階層を表す・Ansible」＝ **YAML**。JSON のインデントには文法上の意味はない。
- 「開始タグと終了タグで囲む」＝ **XML**。CSV は階層を表せない。
- HCL は Terraform の言語。

### 押さえておくポイント

- **JSON：`{}` `[]`、REST API の主流** ／ **XML：タグ、NETCONF** ／ **YAML：インデント、Ansible**。
- 同じデータはどの形式でも表現可能。中身は同じ。

## 2. JSONの文法とデータ型を読み解く

「JSON を読んで値やデータ型を答える」「正しい JSON を選ぶ」はよく問われます。ここでは JSON を確実に読めるようにします。

### 2.1 JSON の基本ルール

**JSON（JavaScript Object Notation）** の文法は次のルールだけで成り立っています。

| ルール | 内容 |
| --- | --- |
| オブジェクト | `{ }` で囲み、中身は **「キー: 値」の組** |
| 配列 | `[ ]` で囲み、中身は **値の並び**（順番に意味がある） |
| キーと値の区切り | **`:`（コロン）**。`=` ではない |
| 要素どうしの区切り | **`,`（カンマ）** |
| キー | **必ずダブルクォート `"` で囲む** |
| 文字列の値 | **必ずダブルクォート `"` で囲む**。**シングルクォート `'` は使えない** |
| 数値・true/false・null | **クォートで囲まない** |
| 最上位 | オブジェクトでも配列でもよい（例：`[10, 20, 30]` も正しい JSON） |
| 空 | 空のオブジェクト `{}`、空の配列 `[]` も正しい |

### 2.2 JSON の6つのデータ型

| データ型 | 例 | 見分け方 |
| --- | --- | --- |
| **文字列**（string） | `"Sales"`、`"10.1.1.1"`、`"true"` | **ダブルクォートで囲まれている** |
| **数値**（number） | `10`、`3.14`、`-1` | クォートなしの数字 |
| **ブール値（真偽値）**（boolean） | `true`、`false` | クォートなし・**小文字** |
| **null** | `null` | クォートなし・小文字。「値が存在しない（空である）」 |
| **オブジェクト**（object） | `{"hostname": "R1"}` | `{ }` |
| **配列**（array） | `["Gi0/1", "Gi0/2"]` | `[ ]` |

**クォートの有無で、文字列かそれ以外かが決まる** のが最重要ポイントです。

```json
{
  "vlan": 10,            ← 数値
  "vlan_str": "10",      ← 文字列（クォートあり）
  "name": "Sales",       ← 文字列
  "enabled": true,       ← ブール値
  "enabled_str": "true", ← 文字列（クォートあり）
  "ip": "10.1.1.1",      ← 文字列（IPアドレスは数値ではない）
  "description": null,   ← null（値なし）
  "comment": "",         ← 空文字列（「空の文字列という値」がある）
  "count": 0,            ← 数値のゼロ（「0という値」がある）
  "ports": [],           ← 空の配列
  "device": {}           ← 空のオブジェクト
}
```

> 注意：上の `←` の注釈は説明用で、JSON にはコメントを書けません。

#### null・""・0・None の違い

| 書き方 | 意味 |
| --- | --- |
| `null` | **値が存在しない**。JSON の正しい書き方 |
| `""` | 長さ0の文字列。「値がない」のではなく「空の文字列という値がある」 |
| `0` | 数値のゼロという値がある |
| `None` | **Python** のキーワード。JSON では使えない（JSON では `null`） |

#### JSON と Python の対応

Python で JSON を読み込む（`json.loads()` や `requests` の `r.json()`）と次のように変換されます。

| JSON | Python |
| --- | --- |
| オブジェクト `{}` | 辞書 `dict` |
| 配列 `[]` | リスト `list` |
| 文字列 `"..."` | `str` |
| 数値 | `int` / `float` |
| `true` / `false` | `True` / `False` |
| `null` | `None` |

Python ではシングルクォートで文字列を書けますが、**JSON ではダブルクォートのみ** です。`{'hostname': 'R1'}` は Python の辞書としては正しくても JSON としては誤りです。

### 2.3 正しい JSON・誤った JSON

| 例 | 判定 | 理由 |
| --- | --- | --- |
| `{"hostname": "R1", "vlan": 10}` | 正しい | キーと文字列はダブルクォート、数値はクォートなし |
| `{hostname: R1, vlan: 10}` | 誤り | キーも文字列の値もクォートで囲まれていない |
| `{'hostname': 'R1', 'vlan': 10}` | 誤り | **シングルクォートは使えない**（Python や JavaScript では使える） |
| `["hostname" = "R1", "vlan" = 10]` | 誤り | 区切りは `=` ではなく `:`。キーと値の組は `[ ]` ではなく `{ }` |
| `{"vlan": 10 "name": "Sales"}` | 誤り | **要素の間の `,` が抜けている** |
| `{"vlan": 10, "name": "Sales",}` | 誤り | **最後の要素の後ろに余分な `,`**（末尾カンマ） |
| `{"vlan": 10, "name": "Sales"}` | 正しい | `,` で区切られている |
| `{"ports": []}` | 正しい | 値が空の配列 |
| `[10, 20, 30]` | 正しい | 最上位が配列でもよい |

**JSON でよくある誤り**：
1. 要素の間の `,` の抜け
2. 最後の要素の後ろの余分な `,`
3. シングルクォートの使用
4. キーをクォートで囲み忘れる

文法誤りのある JSON を API に送ると **400 Bad Request** が返されます（[[13HTTPステータスコード]]）。

### 2.4 入れ子（ネスト）構造の読み方

JSON は **`{ }` と `[ ]` の対応を見て階層を読みます**。インデントして書き直すと読みやすくなります。

#### 例1：配列

```json
{"hostname": "SW1", "interfaces": ["Gi0/1", "Gi0/2", "Gi0/3"]}
```

- `interfaces` の値は `[ ]` で囲まれているので **配列**。
- 配列の各要素（`"Gi0/1"` など）は文字列だが、**`interfaces` の値全体は配列**。
- 配列は同じ種類のデータを複数並べるときに使い、要素は `,` で区切り、**順番に意味がある**。

#### 例2：オブジェクトの中のオブジェクト

```json
{"device": {"hostname": "R1", "ip": "10.1.1.1"}, "site": "Tokyo"}
```

整形すると：

```json
{
  "device": {                 ← device の値はオブジェクト
    "hostname": "R1",         ← device の内側のキー
    "ip": "10.1.1.1"          ← クォートあり → 文字列
  },
  "site": "Tokyo"
}
```

```
 最上位オブジェクト
 ├── device : オブジェクト
 │     ├── hostname : "R1"
 │     └── ip       : "10.1.1.1"（文字列）
 └── site   : "Tokyo"
```

- **最上位のキーは `device` と `site` の2つ**。`hostname` は `device` の内側のキー。
- プログラムでは `data["device"]["hostname"]` のようにたどって `"R1"` を取り出します。

#### 例3：配列の中のオブジェクト（API 応答で頻出）

```json
{"devices": [{"name": "R1"}, {"name": "R2"}, {"name": "SW1"}]}
```

```
 data
 └── "devices" : 配列
        [0] → {"name": "R1"}
        [1] → {"name": "R2"}
        [2] → {"name": "SW1"}
```

- `data["devices"]` → 配列
- `data["devices"][2]` → 配列の **2番目（0から数えるので3つ目）** の要素 `{"name": "SW1"}`
- `data["devices"][2]["name"]` → **`"SW1"`**

**配列の番号（インデックス）は 0 から数えます。** 1 から数えると `"R2"` と誤答します。要素は3つ（0〜2番目）あるので `[2]` は存在し、エラーにはなりません（`[3]` ならエラー）。

Python での例：

```python
data = {"devices": [{"name": "R1"}, {"name": "R2"}, {"name": "SW1"}]}
print(data["devices"][2]["name"])   # SW1
print(len(data["devices"]))         # 3
for d in data["devices"]:
    print(d["name"])                # R1, R2, SW1
```

### ひっかけポイント・よくある誤解

- シングルクォート、クォートなしのキー、`=` 区切り、`[ ]` でキーと値の組 → いずれも誤り。
- `true`（クォートなし）は **ブール値**。`"true"` なら文字列。`10` が数値。
- `["Gi0/1", ...]` の値全体は **配列**。要素が文字列だからといって「文字列」と答えない。
- `{ }` はオブジェクト、`[ ]` は配列。
- 入れ子の内側のキー（hostname）を最上位と誤認しない。
- `"10.1.1.1"` はクォートがあるので **文字列**。IP アドレスだから数値、ではない。
- 配列は **0 から数える**。`[2]` は3つ目。
- 値がないのは `null`。`""` は空文字列、`0` は数値、`None` は Python。
- カンマ抜けは文法エラー。空配列や最上位の配列は正しい。

### 押さえておくポイント

- JSON の6つの型：**文字列・数値・ブール値・null・オブジェクト・配列**。
- **キーと文字列はダブルクォート**、数値・true/false・null はクォートなし。
- `:` で区切り、`,` で並べる。末尾カンマ不可。
- 入れ子は `data["a"]["b"]`、配列は `[0]` から。
