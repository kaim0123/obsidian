## 詳しい要約

**テーマ：名刺 1 枚の文法 JSON が XML を倒し、AI 時代の共通語になるまでの 25 年**

2001 年にダグラス・クロックフォードが JavaScript の既存文法から「発見」した JSON は、小ささと「変わらないこと」を武器に巨大な XML の仕様群を静かに打ち倒し、通信・DB・設定ファイル、そして AI とツールの間の共通語にまで広がった。

---

### 第 1 章：発明ではなく発見（2001 年）

- JSON の文法は**名刺 1 枚**に印刷できる大きさで、クロックフォードは名刺の裏に刷って配っていた
- 舞台は 2001 年、シリコンバレーのスタートアップ **State Software**（クロックフォードや仮想世界 Habitat のチップ・モーニングスターらが設立）。ブラウザとサーバーを常時つなぎ双方向にやり取りする（今でいう WebSocket の先取り）ためのデータ形式が必要だった
- 当時は XML が普通の選択だったが、JavaScript のオブジェクトの書き方をそのまま流用。2001 年 4 月に最初の JSON メッセージが送られた
- 本人の言葉：「**私は JSON を発明していない。発見した**」（1999 年の JavaScript 仕様にすでに存在していた）
- 逸話：初期はキーを引用符で囲まなくてよかったが、`do` というキーで予約語と衝突して動かなくなった → 「**キーは常に引用符で囲む**」と決め、言語中立の形式に近づいた

### 第 2 章：王者 XML と「WS-デススター」

- 2000 年代前半の企業システムでは XML がほぼ宗教。IBM・Microsoft などが **SOAP** を XML 上に築き、WS-Security や WSDL などの仕様が林立して「**WS-デススター**」と呼ばれる数千ページの塔になった
- XML は終了タグで同じタグ名を 2 回書くため冗長で、データ量が倍近くに膨らむ
- 対する JSON は 2002 年に json.org で仕様を公開しただけ。バージョン番号も企業の後ろ盾も標準化団体もなし
- クロックフォードは「**JSON に次のバージョンはない。完成している**」と仕様を凍結。変わらないことこそデータ形式の価値と考えた

### 第 3 章：Ajax の皮肉 — 名前は XML、中身は JSON

- 2005 年 2 月、ジェシー・ジェームズ・ギャレットが記事で **Ajax** と命名（Gmail や Google マップのページ再読み込みなしの通信）
- Ajax は Asynchronous JavaScript and XML、ブラウザの機能も XMLHttpRequest と「XML」を冠していたが、開発者が実際に送り始めたのは JSON（受け取ってそのままオブジェクトとして使え、パーサーで木構造を歩く手間がない）
- 標準化：2006 年 **RFC 4627** → 2013 年 **ECMA-404** → 2017 年 **RFC 8259**
- Twitter や Google の API は 2010 年代前半に相次いで XML を打ち切り JSON に一本化
- 逸話：参照実装のライセンスに「**善のために使い、悪のために使ってはならない**」と書いたところ IBM の弁護士から連絡があり、「IBM とその顧客に限り悪への使用を許可する」と返答した

### 第 4 章：通信から DB へ — 侵食と弱点

- 2009 年に **MongoDB** が登場し、JSON に近いドキュメントをそのまま保存できる手軽さがスタートアップに刺さった（NoSQL ブーム）
- リレーショナル側の反撃として、2014 年の **PostgreSQL 9.4 が JSONB 型**を搭載（バイナリ格納で中身に索引も張れる）。専用 DB を入れずに済むようになった
- 設定ファイルでも Node.js の `package.json`、ログ処理の JSON Lines、OpenAPI 周辺などエコシステムが育った
- 弱点（設計思想の裏返し）
  - **コメントが書けない**：コメントに解析用の指示を書き込む人が現れ互換性を壊し始めたため、意図的に削除
  - **日付型がなく、数値の精度も規定していない**：Twitter はツイート ID が 2^53 を超えて JavaScript 側で桁が壊れ、文字列版の `id_str` を追加する羽目になった

### 第 5 章：AI 時代の共通語

- LLM の**関数呼び出し（Function Calling）**の引数は JSON で設計され、OpenAI・Anthropic・Google は構造化出力に JSON を選んだ。**MCP** も土台は JSON
- 自然言語は曖昧すぎ、機械語は人間が読めない。その中間に JSON がちょうど収まり、人間・機械・AI の交差点にいる
- LLM は Web 上の大量の JSON を読んで育ったため JSON を上手に書ける。過去の普及が次の時代への適性まで作った
- 「発明品は作者の都合で変わるが、発見された法則は変わらない」— 25 年バージョン 1 のままだったことが AI の教材としての安定にもつながった

### まとめ

- JSON は新発明ではなく既存文法からの「発見」で、小ささと不変性で巨大な XML 仕様群に勝った
- Ajax の追い風の中、看板は XML・中身は JSON という形で静かに逆転が完了した
- コメント不可・数値精度未規定などの弱点は設計思想の裏返し
- 次の 10 年、JSON を最も多く書くのは人間ではなく AI になる
