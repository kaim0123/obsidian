## 詳しい要約

**テーマ：仕様書のない CSV が 50 年間世界標準であり続けた理由**

CSV は 1972 年に誰にも設計されずに生まれ、33 年間仕様書がないまま銀行・行政・研究機関のデータを運び続けてきた。仕様がないことで方言や事故も生んだが、「最小であること」を武器に XML・JSON・Parquet にも置き換えられず、AI 時代には方言の吸収を機械が担い始めている、という話を 5 章で追う。

---

### 第1章：発明されなかった形式（1972 年の FORTRAN）

- JSON にはダグラス・クロックフォードという作者がいるが、**CSV には作者がいない**
- 記録に残る最古の実装は **1972 年の IBM の FORTRAN コンパイラ**。数値をカンマ区切りで入力できる機能がひっそり追加された。設計も提案も委員会もない
- パンチカードの時代から、値をカンマで並べるのは人間にとって最も自然な書き方だった（仕様より先に習慣があった）
- 1980 年代に VisiCalc・Lotus 1-2-3・Excel などの表計算ソフトが乱立し、ソフト間のデータ交換で「全員が読み書きできる最小公倍数」としてカンマ区切りテキストが生き残った
- **2005 年 10 月の RFC 4180**（ヤコブ・シャフラノビッチが執筆）で初めて文書化。本人も「非常に一般的なのに一度も正式に文書化されたことがない」と認め、分類は標準ではなく**参考情報（Informational）**
- CSV は設計されたのではなく、**観察されて記録された形式**

### 第2章：組織と機械の境界に立つ関所

- 会計ソフト・EC の受注管理・広告レポート・勤怠など、あらゆる管理画面に「**CSV エクスポート**」ボタンがあり、新サービスで最初に要望される機能でもある
- 2009 年に米国政府が Data.gov を開設、日本も e-Stat や自治体のオープンデータで続き、配布ファイルの主役は CSV
- ティム・バーナーズ＝リーのオープンデータ 5 つ星評価：PDF＝1 つ星、Excel＝2 つ星、**CSV＝3 つ星**（機械可読の最初の段階）
- Python の pandas で最初に打つ命令は CSV の読み込み、Kaggle の配布データも CSV が定番
- CSV は組織と組織、人間と機械の境界に立つ「関所」になっている

### 第3章：仕様がないことの代償

- **カンマを含む値の問題**：住所や会社名にカンマがあると区切りと区別できない。引用符で囲む慣習が生まれたが、囲み方や引用符自体の扱いが実装ごとに違い、各言語の CSV ライブラリに「方言（dialect）」オプションがある
- **欧州**：ドイツやフランスは小数点にカンマを使うため、同じ拡張子でも**セミコロン区切り**
- **日本**：Shift_JIS、UTF-8 の **BOM**、Excel での文字化けという文字コードの地雷
- CSV は 1 つの形式ではなく「多方言の一族」
- **遺伝子改名事件（2020 年 8 月）**：Excel が MARCH1 や SEPT1 を日付に自動変換。2016 年の調査では遺伝子リストを含む論文の約 2 割でデータ破損。国際命名委員会は根絶は無理と判断し、MARCH1→MARCHF1、SEPT1→SEPTIN1 など**計 27 個の遺伝子名を改名**
- **英国コロナ集計事件（2020 年）**：検査機関は陽性者データを CSV で送っていたが、集計側が古い **XLS 形式（上限 65,536 行）**に変換していたため、上限を超えた **15,841 人分**がエラーも警告もなく消え、約 48,000 人の濃厚接触者への連絡が遅れた
- 事故の多くは CSV そのものではなく、**周辺の解釈・変換**で起きている

### 第4章：なぜ置き換えられないのか

- XML はスキーマで型を保証できたが重すぎた。JSON は階層を表現できるが表形式には冗長。**Parquet**（列指向）は分析基盤の主流だがバイナリで人が読めない
- W3C が 2015 年に型を持たせる「CSV on the Web」を作ったが、ほとんど普及しなかった。強い仕様を与えると CSV らしさが消える
- CSV の 3 つの強み：
  1. 誰の所有物でもなく、ライセンスや政治が絡まない
  2. テキストなのでメモ帳で目視できる
  3. 仕様が緩いので、どんな貧弱な環境でも数十行で読み書きを実装できる
- フォーマットの寿命は機能の多さでは決まらず、「読める環境が多い→選ばれる→対応が増える」の循環で決まる

### 最終章：AI 時代の CSV

- Hugging Face や Kaggle には CSV のデータセットが大量にある
- これまで区切り文字の判定や文字コードの推定は人間がコードを書いて対処してきたが、**AI は崩れた CSV を文脈で読み**、セミコロン区切りや列ずれも解釈し直せる
- ただし遺伝子改名や英国の事件は「機械が黙って解釈を変えた」ことが原因。AI はそれを桁違いの規模で行うため、**読めることと正しく読めていることは別**であり、検証の責任は人間に残る
- JSON がプログラム同士の共通語なら、CSV はその下の層にある、組織・人間・機械の間で手渡すときの「最も低く最も広い共通語」

### まとめ

- CSV は設計されず、習慣が 33 年後に参考情報として記録された形式
- 仕様の緩さは方言や事故を生んだが、事故の多くは周辺の変換・解釈で起きた
- 最小であることが参入障壁の低さとなり、機能で勝る後継にも置き換えられなかった
- AI が方言を吸収しても、結果を検証する責任は人間に残る
