### 1. みちょぱが建築する——Web 界隈のあるある

| 現実世界 | Web の世界 |
|----------|------------|
| お店の**内装**はみちょぱさんでもよい | **見た目**（CSS）の仕事 |
| **建築・構造**はプロの建築士に任せる | **論理構造**（HTML）の仕事 |
| 素人が耐震設計まで手を出すのは不安 | なのに **「みちょぱが建築しちゃう」** ケースが多い |

- みちょぱさん本人が店舗の**建築**まで手がける——シュバル理想郷的な不安（堀本さんの例え）。
- 現実なら「プロに任せよう」と思うのに、Web では**見た目の都合で論理構造までいじる**ことが日常化している、という問題提起。

### 2. 核心——論理と見た目の分離

**前回のおさらい**

- `<h1>` で囲んだ「大きい文字」と、`<div style="font-size:…">` で大きくした文字は**見た目は同じ**だが、**内部構造が違う**。
- 前者は「見出しである」という**論理情報**、後者は「でかく太くしろ」という**装飾指示**だけ。

**HTML と CSS の分担**

| | HTML | CSS |
|--|------|-----|
| **書くもの** | 論理・構造（見出し、強調、関連性…） | 見た目・装飾だけ |
| **正式名称** | HyperText Markup Language | **C**ascading **S**tyle **S**heets |
| **水野さんの反応** | 前回習った | 初耳（RSA 暗号と混同、SSD 330 CSS 等の空耳ネタ） |

- **HTML には見た目を一切書かない**——「ここ見出し」「ここ強調」と論理だけ書く。
- **CSS** で「見出しを派手に」「地味に」など、後から好き勝手装飾できる。
- 同じ HTML を、CSS 一つ変えるだけで**別デザイン**にできる。

### 3. James Webb 宇宙望遠鏡——最強の比喩

**写真の正体**

- James Webb が届ける美しい星雲写真（例：カリーナ星雲）は、**可視光線の写真ではない**。
- 赤外線・電波望遠鏡で取得したデータを、**人間が見やすいよう波長ごとに色を割り当てて着色**したもの。
- 「きれいに見えるように塗られている」——ただし望遠鏡側には**波長と色の対応ルール**がある（Web ほど自由ではない）。

**HTML / CSS との対応**

```
取得データ（赤外線の生情報）  ≒  HTML（論理・構造）
着色・見せ方のルール          ≒  CSS（見た目）
```

- **ブログのデザイン変更**が決定的な実例：テーマを変えると**過去記事も一斉に**新デザインになる。
- 中身の HTML は「ここ見出し」のまま、**CSS だけ差し替え**て見た目が変わる。
- 堀本さんの結論：**HTML ＝ CSS ＝ James Webb 宇宙望遠鏡**（覚えて帰ってほしい）。

---

### 4. 分離のメリット——マルチユースとメンテナンス

**Word で100本書いた場合**

- 各記事にデザインが**埋め込まれている** → デザイン変更＝100本すべて手作業。
- 堀本さんの体感：**Word で書く人が多い**から、デザイン変更が地獄になりがち。

**論理と見た目を分離した場合**

- 書くときは**論理だけ**（HTML）、見た目は**別ファイル**（CSS）。
- **文書のマルチユース**：同じ原稿から、雑誌用・Web 用・別媒体用に、それぞれ CSS（デザイン）を通せば使い回せる。
- 第1回の「Word でホームページを作るな」問題提起とも接続——**明確な論理構造で書ける**のが HTML の大きなポイント。

---

### 5. note の「見出し乱用」——みちょぱ建築の具体例

**プラットフォームの設計**

- note 等では見出し・太字ボタンで、**HTML タグを意識せず**使える。
- プラットフォームが裏で `<h1>` 相当を付与——**秘匿されている**からユーザーは構造を気にしない。

**副作用**

- 見出しの**意味**がわからない人が、見出しを使い始める。
- 「でかい太字にしたい」「強調したい」→ **見出しボタンを押す**（昔のライブドアブログでも同様）。
- 例：「山田太郎とは誰か？」のような**本文の一部**を見出しにする——**章立てではないのに見出しタグ**。

**なぜダメか**

| 問題 | 説明 |
|------|------|
| **論理の犠牲** | HTML は論理構造を書くためのものなのに、**見た目に引っ張られて**誤用 |
| **無駄遣い** | せっかくの「論理と見た目の分離」の恩恵を、見た目目的で台無しに |
| **みちょぱ建築** | 内装（見た目）の都合で、**建築（構造）まで手を出す**状態 |

- 堀本さんも Notion 台本で「見出しで大きくしよう」と**やりかねない**と自白。
- 正しくは：**`<strong>`（強調）** と **`<h2>`（見出し）** は別物。建築と内装は**別工程**。

### 6. Google も HTML の構造を読む

- Google はページを**漠然と文字列として**ではなく、**見出しを拾って**内容を把握している。
- 見出しを**重めにインデックス** → 検索精度・ランキングに影響。
- **速読派**も見出しに時間を割く——Google も同じことをしている。
- 見出しを「ドカーン」と**見た目目的で乱用** → Google から**ゴミコンテンツ**と判断されるリスク。
- 「ドカーン」で検索したら出てくるかも、という悲痛なジョーク。

### 7. クイズ——他にマークアップ言語を使っているものは？

**不正解・惜しい答え**

| 回答 | コメント |
|------|----------|
| **メルマガ** | ブログのタグに近すぎる |
| **クラフトビールのレシピ** | XML の Wikipedia 例にレシピあり——**汎用性が高いから間違いではない**が、今回の答えではない |

**正解：Oxford English Dictionary（OED）電子版**

- 辞書の各項目（発音、語源、用法、例文…）を**タグでマークアップ**して記述。
- **デザインが決まっていなくても**、中身の論理構造だけ先に書ける → ボランティア作業も可能。
- 「こういうデザインで見せたい」は**後から** CSS 等で決めればよい。
- 日本の国語辞典デジタル版も、同様の可能性が高い（堀本さん調査：OED については Wikipedia で確認、国語辞典は定かでない）。
- **「みちょぱがいなくても建築はできる」**＝見た目が決まっていなくても論理だけ書ける、の実例。

### 8. まとめと次回予告

**この回のメッセージ**

1. マークアップ言語最大のメリット：**論理と見た目を分離して書ける**。

3. 見出しは**見た目のため**ではなく**文書構造のため**——note 乱用は「みちょぱ建築」。
4. Google も構造を読む。**正しいマークアップ**は検索・機械処理の基盤。

**次回（第3回）**
