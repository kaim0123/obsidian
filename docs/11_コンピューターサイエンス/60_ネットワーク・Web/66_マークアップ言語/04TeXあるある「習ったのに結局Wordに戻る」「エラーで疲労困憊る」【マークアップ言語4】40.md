## 詳しい要約

**テーマ：TeX（テフ）あるあると、TeX が数式を美しく書ける理由**

マークアップ言語シリーズ第4回。理系の卒論でおなじみのマークアップ言語 **TeX** について、「授業で習っても結局 Word に戻る」「卒論時期に習得していないことを後悔する」「日本語パッケージでつまずく」といったあるあるを語り、Word の数式ツールと比べて TeX が数式を綺麗に書ける理由（WYSIWYG でないこと、全体を見てからコンパイルすること）を説明する。最後に「論理を記述するはずのマークアップ言語なのに、TeX は見た目のためのツール」という矛盾を提示し、次回の「マークアップ言語の悲劇の歴史」への伏線とする。

---

### TeX とは

- 文書に書きたい情報以外に、タグのような命令を付加して文書を作るツール（Word と同じ文書作成用途）。理系学生は卒論を TeX で書くことが多い。
- 系統に TeX、plain TeX、LaTeX、pLaTeX などがある。
- 読み方：英語圏では「テック」で開発者もそう読んでいたが、日本では「テフ」と読み、「テック」と言うと素人扱いされがち（理由は不明）。LaTeX の名前がゴムのラテックスに由来するという俗説も話題に。

### TeX あるある

- 大学2年ごろに授業で TeX を習い課題レポートも書くが、`\begin{equation}` などの命令を覚えるのが面倒で、**結局 Word に戻る**。
- 卒論で「TeX でないと受理しない」と言われ、ただでさえタスクが多い卒論時期に TeX の習得が加わって苦労する。
- 調べて書いてもエラーが出る。特に**日本語環境**は、日本語用パッケージと TeX のバージョンの相性問題などでつまずきやすい（漢字などが多く独自の工夫が必要なため）。
- 教訓：**必要なスキルの習得を後回しにするほど後で苦しむ**（アリとキリギリスのような話）。水野さんの Excel（SUM・AVERAGE は使えるが VLOOKUP は使えない）も同様。

### Word の数式ツールの苦しみ

- 例としてゼータ関数の式 ζ(2)=Σ1/n²=π²/6 を提示。
- Word の数式ツールは見たままを入力する方式（分数を挿入すると横棒が出て、上下にカーソルを入れる）。
- しかし複雑な式になるとカーソル位置が多すぎて狙った場所に入らない。log の底のような小さい文字を編集しようとすると真数の方が変わってしまう、分数が多重になったり log の中に log が入ったりすると編集不能になる、など。

### TeX が綺麗に書ける理由

- TeX なら log₂x は `\log_2 x` と書くだけ。底を小さく書く作業は不要で、「こう書いたらこう表示する」という取り決めだけでよい。
- マークアップ言語は **WYSIWYG ではない**（書いている途中のものと最終的な印刷物が一致しない）。そのため最後に翻訳・加工する**コンパイル**が必要。
- コンパイル時にエラーが出るとどこが悪いかわかりにくく、TeX のエラーメッセージは出来があまりよくない（「疲労コンパイル」というダジャレが生まれるほど）。
- 一方、Word の数式ツールは入力中ずっと数式を表示し続けなければならないが、TeX は**全体像がわかった状態で最後に一気に出力**するので、ベストなレイアウトで綺麗な数式を出せる（「明日」なのか「明日は運動会」なのかを知ってから書道をするようなもの）。
- 論文を書く段階では数式はすでに完成しているので、全体を書いてからコンパイルする方式で問題ない。

### 最終回への伏線：マークアップ言語の矛盾

- これまで「マークアップ言語は**論理と見た目を分離**し、論理を記述するもの」（HTML の見出し・強調、ブログのデザイン変更など）と説明してきた。
- ところが TeX は「数式を綺麗に書ける」という**見た目のためのツール**として紹介した（構造化はされているがわかりにくい）。
- この矛盾は誰の説明が悪いのでもなく、「マークアップ言語」という**言葉の定義そのもの**に矛盾が潜んでおり、その背景に「悲劇の歴史」がある。次回（最終回）で解説し、「マークアップ言語はパンダの親指である」という結論を導くと予告。

### まとめ

- TeX は理系の卒論に欠かせないマークアップ言語だが、習得の面倒さや日本語環境のエラーで苦しむのがあるある。スキル習得は早めに。
- WYSIWYG でなく全体を見てからコンパイルするため、複雑な数式でも綺麗に確実に書ける。
- 「論理を記述するはずのマークアップ言語」と「見た目のための TeX」の矛盾は、マークアップ言語の歴史によって解ける（次回）。
