## 要約

前回（ARPANET〜Web 誕生）の続編。**ネットスケープ**が市場を切り開き、**Microsoft** が **Embrace-Extend-Extinguish（抱きしめて拡張して消す）** で逆転し、**IE** が一時 **95%** のシェアを握った——その後 **Firefox・Safari・Chrome** により滅びた **30年のブラウザ戦争** を、技術・ビジネス・法廷の三層で解説する動画。ブラウザは「画面を表示するだけのソフト」ではなく、**Web の窓口＝プラットフォーム** であり、戦争の副産物として **JavaScript・AJAX・Node.js** など現代 Web の基盤技術が生まれた。

### テーマと位置づけ

- 前回まで：Web（1991）→ モザイク（1993）→ ネットスケープ（1994）
- 本動画：ネットスケープ登場以降、インターネットの歴史が「**お金の色**」に変わる——市場最大規模の技術戦争。
- 単なる技術史ではない：**アメリカ司法省の独占禁止訴訟**、**ビル・ゲイツの議会証言**、**判事自身による和解批判** まで及ぶ。
- 結論：歴史は単純化できない——ネットスケープは**被害者であり自滅者でもある**。そして **Chrome の65%シェア** は IE 全盛期への回帰懸念も生む。

### 第1次ブラウザ戦争：ネットスケープの時代（1994〜1998）

#### ネットスケープの台頭

- **1994年**、モザイク作者の **マーク・アンドリーセン** が **ネットスケープ・コミュニケーションズ** を共同設立。
- **1995年8月9日 IPO**（株式公開）：
  - 公募価格28ドル → 日中高値75ドル近く、終値58ドル台、時価総額約**30億ドル**。
  - 設立から1年半、**一度も黒字なし**の赤字会社——「利益がなくても将来性があれば価値がある」という **.com バブル** の起点の一つ。
- **ネットスケープ・ナビゲーター** が Web の窓口——「インターネット＝ネットスケープ」と思われるほど。
- **1995年末**、市場シェア約 **75%**。
- ビジネスモデルの弱点：**ブラウザを売って稼ぐ**（個人向け無料・企業向け有料）＋ **Web サーバー**（Netscape Commerce Server 等）をセットで収益化する計画。

#### Microsoft の参戦

- 当初 Microsoft は Web を軽視——**ビル・ゲイツ** の1994年社内文書にインターネットへの言及はほぼなし（PC 向けソフトが本命）。
- 転機はネットスケープの衝撃的 IPO——「Web が本物のビジネス」と示され、**1995年5月** に「インターネット・トゥルー」メモで全面参戦宣言。
- 参戦の仕方：
  - 自前開発ではなく **Spyglass** から **モザイクの商用ライセンス** を取得（当初200万ドル＋ロイヤルティ）。
  - **1995年8月**、**Internet Explorer 1.0** リリース。
  - **Windows 95** に IE を**最初から組み込み**——OS のファイルシステム・シェルと統合。IE は「ブラウザ」ではなく **OS の一部** と主張（独占禁止法回避の意図、裁判では却下）。
- IE 1.0 はネットスケープに遠く及ばない（遅く・機能貧弱）が、**最強の武器は Windows 95**——世界中の PC に最初から入っている無料ブラウザ vs 有料のネットスケープ。

#### Embrace-Extend-Extinguish（E-E-E）

- Microsoft 社内の公式用語ではないが、後世の研究者が行動パターンとして命名：
  1. **Embrace**：標準仕様に対応して業界に溶け込む
  2. **Extend**：独自機能を追加して標準を拡張
  3. **Extinguish**：独自機能への依存で競合を追いつけなくする
- IE は HTML に **Microsoft 独自タグ**（`<marquee>` 等）を追加——IE だけで動くサイトを大量生産。
- 公平に言えば **ネットスケープも独自拡張**（`<blink>` 点滅タグ等）を実施——**標準化機関 W3C も独自拡張の競争に加担**していた。ただし IE の市場支配力が圧倒的で影響も桁違い。
- シェア推移：IE **1995年 約5%** → **1999年 75%超**（ネットスケープが4年で築いた道を4年で逆向きに）。

### 戦争が生んだ技術：JavaScript（1995）

- **ブレンダン・アイヒ**（ネットスケープ）が **1995年5月**、わずか **10日間** で JavaScript のプロトタイプを作成。
- 経営陣の「Web ページを動かすスクリプト言語が必要、すぐに作れ」という指示——C や Java は数年かかる開発に対し異次元の速さ。
- アイヒ本人：「時間があれば全然違う設計にした」——**等号（`==`）の型変換** など欠点と個性が同時に生まれた。
- 名前の変遷：**Mocha** → **LiveScript** → **JavaScript**（Sun の Java が話題だったためマーケティング連携で命名——技術的には無関係）。
- 設計の影響：**Lisp**（関数を第一級オブジェクト）・**Self**（プロトタイプベース継承）・**Java**（見た目）の3言語。
- Microsoft は **JScript** という独自実装を作成——「**このページは Internet Explorer で最適化されています**」時代の元凶。
- **1996年**、**ECMA International** で標準化（**ECMAScript**）——今も ES2023/ES2024 と毎年更新。10日間の設計が今もコアに残る。
- **ES2015** で `class` キーワード追加も、内部は相変わらずプロトタイプベース（シンタックスシュガー）。

### CSS・DOM と「クロスブラウザ対応」の地獄

- **CSS**（1994年、ハーコン・ウィウム・リー提案）：コンテンツと見た目の分離——当時の HTML に `<font color="red">` 等が混在。
- **1996年**、**W3C**（ティム・バーナーズ＝リー設立、1994年）で CSS 標準化。
- しかし IE とネットスケープがそれぞれ **独自 CSS 拡張** を実装——「IE で崩れる」「ネットスケープでレイアウトが壊れる」が日常に。
- **DOM**（Document Object Model）もブラウザごとに実装が異なる——JavaScript・CSS・DOM 全部でバラバラ。
- 開発者は **クロスブラウザ対応** の地獄——ブラウザごとに別コード。今も残る言葉は「あの時代のトラウマ」。
- Microsoft の戦略：標準より **Windows 環境への最適化** を優先——「Windows なら IE で全部動く」。
- 標準化の遅れ：CSS 2.1 勧告（1998年）に対し、IE が比較的まともに対応したのは **IE 8（2009年）** まで待つ必要——**仕様と実装の乖離** が2000年代の Web に深い傷を残した。

### ネットスケープの致命的ミス：全面書き直し（1998〜2001）

- **1998年初頭**、ナビゲーター 4.0 以降のコードを **完全にゼロから書き直す** 決断。
- ジョエル・スポルスキー：「プログラマーが絶対にやってはいけないただ一つのこと」——既存コードには長年のバグ修正・改善が蓄積され、書き直しで全部リセット。
- 書き直しに **約3年**（1998〜2001）——この間ネットスケープは事実上まともなブラウザをリリースできず。
- その間 IE は **IE 5（1999年）** で安定性・速度が大幅改善——**1999年末 IE シェア75%超**。
- ネットスケープ没落の原因論争：
  - **Microsoft の抱き合わせ攻撃** が主因という見方
  - **自らの開発停滞（書き直し）** が主因という見方
  - 実際は両方——「被害者であり自滅者でもある」。因果を **Microsoft の無償配布 → 焦って書き直し** と重視する研究者も多い。

#### Mozilla プロジェクトと Firefox

- **1998年1月22日**、ネットスケープが **ブラウザのソースコードを無償公開**——「どうせ Microsoft に勝てないならオープンにして世界中と一緒に作る」逆転発想。
- プロジェクト名 **Mozilla**（Mosaic + Godzilla＝「モザイクをゴジラのようにやっつける」社内あだ名由来）。
- **2002年** Mozilla 1.0 リリース（3年以上かかった）。
- **2000年** Netscape 6.0 もリリースしたが完成度低く酷評——市場の空白を埋めるため出すしかなかった事情。
- **2004年11月**、**Firefox 1.0** 公開——一気に話題化。ネットスケープの死と引き換えにオープンソース Firefox が生まれた。

### 独占禁止訴訟：United States v. Microsoft（1998〜2001）

- **1998年**、アメリカ司法省と20州の司法長官が Microsoft を提訴——国家規模の訴訟。
- 争点：**Windows と IE の抱き合わせ**——OS の独占的地位でブラウザ市場も不当に独占した。
- 社内メールが証拠として開示——「ネットスケープのエアサプライ（空気の供給）を断ち切る」「プラットフォームとしてのネットスケープを壊滅させる」等。
- **ビル・ゲイツ** の証言ビデオも法廷上映——競合への質問にかわすような答えが続く（今もネットで視聴可能）。
- **2000年6月** 地裁判決：反トラスト法違反認定、**会社分割**（Windows と Office を別会社に）を命じる。
- **2001年** 控訴審で分割命令は**撤廃**——和解成立。Microsoft はライバルへの情報開示義務を負うが、**分割は免れた**。
- 判決を下した **ジャクソン判事** 自身が「Microsoft に有利すぎる和解」と公開批判——和解条件の実行性が薄いという批判は今も続く（「裁判に勝って和解で負けた」）。
- 訴訟の影響：
  - 訴訟中 Microsoft はライバルへの露骨な妨害に慎重に——**競争のブレーキ** として機能した面
  - 同時に開発リソースを大量消耗——「勝っても傷ついた」
- ネットスケープ倒後、**IE シェアは2002〜2004年頃に約95%** に到達——第2次ブラウザ戦争の幕開け。

### 第2次ブラウザ戦争：3方向からの挑戦

#### Firefox（2004年）——オープンソースコミュニティ

- **2004年11月** Firefox 1.0——**速さ**と**拡張性**（アドオンで機能追加）が武器。
- リリース後1ヶ月余りで **1000万ダウンロード**——IE への不満の大きさを示す。
- 資金集めのため **ニューヨーク・タイムズに全面広告**（クラウドファンディングで広告費を集めたコミュニティ）。
- **2005年**、Firefox シェア **10%超**——IE の牙に初めて本当の穴。

#### Safari / WebKit（2003年）——Apple

- **2003年** Apple が **Safari** 発表——内部でオープンソース **KHTML** レンダリングエンジンを採用。
- Apple が改良した **WebKit** をオープンソース公開——**2007年 iPhone** の Safari エンジンとなり、**スマートフォン時代の Web 基盤**に。
- レンダリングエンジン：HTML 解析 → DOM ツリー → スタイル計算 → レイアウト → 描画 → コンポジット。エンジンごとに解釈が異なり、**IE のボックスモデルバグ**（padding を幅に含めるか等）が開発者を苦しめた代表例。

#### Chrome / V8（2008年）——Google

- **2008年** Google が **Chrome** 登場——**V8** JavaScript エンジンが革命。
- **JIT（Just-In-Time）コンパイル**：実行しながら頻繁に呼ばれる部分だけ機械語に最適化——JavaScript 実行速度が **10倍以上** 向上と言われる。
- 現在は **TurboFan** 最適化コンパイラが中核（初期は Crankshaft 等、段階的進化）。
- エンジン競争激化：Mozilla は **SpiderMonkey** 高速化、Microsoft は **Chakra** 開発。
- **2013年**、Google が WebKit から **Blink** をフォーク——現在の Chrome と **Edge（2020年以降）** が Blink を使用。
- **2020年**、Microsoft は独自 **EdgeHTML** を諦め **Chromium**（Google のオープンソース）に乗り換え——「**IE を終わらせたのは Microsoft 自身**」という見方。第1次でネットスケープを倒した IE が、第2次で Google に倒された歴史の皮肉。

### 戦争の副産物：ブラウザが OS になった

#### AJAX と XMLHttpRequest

- **V8 の高速化** ＋ **AJAX**（Asynchronous JavaScript and XML）が、ブラウザをアプリ実行環境に変えた。
- AJAX：ページ全体を再読み込みせず、必要なデータだけサーバーと通信して更新（X/Twitter の新着追加等）。
- 皮肉な起源：**XMLHttpRequest を最初に実装したのは Microsoft**（**1999年**、Outlook Web Access 用——Web メールをリロードなしで表示するため）。AJAX 専用ではなかった。
- 後に W3C 標準化 → 現代の **Fetch API** への延長。
- **2005年2月**、Google が **Google マップ** リリース（地図ドラッグでリロードなし）——同月ジェシー・ジェームズ・ギャレットが **AJAX** という名前をつけ、概念が広まった。
- 「IE のために Microsoft が作った機能が、後に Google の革命に使われる」——技術は作った人の意図を超えて使われ方を見つける。

#### Node.js（2009年）

- **ライアン・ダール** が **Node.js** 作成——**V8 エンジンをブラウザの外**に取り出し、サーバーサイドで JavaScript を実行。
- 10日で作られたブラウザ用言語が、サーバー・スマホアプリ・IoT まで動かすインフラに——ブラウザ戦争の副産物が技術世界を根本から変えた。

### 現代：Chrome 独占と第3次戦争の予兆

- **2023年時点**、Chrome デスクトップシェア約 **65%**、全デバイス合計約 **60%**——IE 全盛期に近いレベル。
- **Blink エンジンへの集中** が新たな独占懸念——**EU 当局** も Google のブラウザ市場行動を監視。
- ただし Firefox・Safari（Blink 非使用）が存在し **Web 標準の多様性** を守っているという見方も。
- **iOS のブラウザエンジン制限**：契約上すべてのブラウザが **WebKit** 強制——Chrome も Firefox も実質 Safari と同じエンジン。**2024年以降**、EU の **DMA（デジタル市場法）** で緩和。
- 「Google の Chrome 独占を批判しつつ Apple の Safari 独占を見過ごしがち」——どのプレイヤーも市場支配力を持てば同じ枠にさらされる。
- **ブラウザ戦争は終わらない**——形を変えながら続き、第3次が始まるかもしれない。

### 動画のまとめ

ネットスケープが**市場を作り**、Microsoft が **E-E-E 戦略で潰し**、ネットスケープは**コードを書き直して自滅**もした。法廷で Microsoft が裁かれ、**Firefox・Safari・Chrome** が現れて今の状況に至った。戦争の副産物として **JavaScript・AJAX・Node.js** が生まれ、**戦争が技術を産み、技術がさらに戦争を作る**サイクルが続いている。
