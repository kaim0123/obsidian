## 詳しい要約

**テーマ：HTML が画面になるまで（クリティカルレンダリングパス）と display: none の正体**

ブラウザは HTML から DOM、CSS から CSSOM を作り、2 つを合わせて「描くものだけ」の Render Tree を作ったあと、Layout → Paint → Composite を経て画面を表示する。`display: none` で要素が消えるのは、**DOM には残るが Render Tree に入らないから**。何を変更したかによって、ブラウザがやり直す工程が変わる。

---

### HTML は文字列 → DOM（木構造）

- ブラウザに届く HTML は**ただの文字の並び**。画面は色のついた点の集まり。その間で何が起きているかが本題
- 要素の親子関係を毎回タグを数えて探すわけにはいかないので、ブラウザは HTML を先頭から読みながら**親子関係を持つ木＝DOM（Document Object Model）** を組み立てる
- HTML（ファイルの文字）と DOM（ブラウザが組み立てた木）は別物。JavaScript が要素を探す先も、開発者ツールの Elements に出ているのも DOM
- 書いた通りの木になるとは限らない：`table` の中に `tr` を直接書くと、ソースにない **`tbody` をブラウザが補う**
- DOM だけでは、要素の色や大きさは分からない

### CSSOM（見た目の規則の木）

- CSS は HTML と別ファイルで届くことが多く、中身は「どの要素に何を」という規則の並び。ブラウザはこれも木にまとめる → **CSSOM**
- 木を分けている理由：HTML と CSS は別々に届き、1 つの規則が多くの要素にかかるため。規則は規則でまとめておき、要素ごとの見た目は後で合わせるときに決める

### Render Tree（2 つの木を合わせる）

- DOM を上からたどり、要素ごとに CSSOM の規則を当てはめる
  - 例：1 つの `p` に「自分で書いた文字色」「親の body から継承した文字サイズ」「ブラウザ既定の余白」が同時にかかる
  - どの規則が勝つか・何を継承するかを計算して最終的な見た目を決める → **Computed Style**（開発者ツールの Computed）
- 見た目の決まった要素を集めた、描画用の木が **Render Tree**（実際のブラウザ内部はもっと細かく分かれているが、動画ではまとめて扱う）
- DOM と数が合わない：
  - `head` や `script` など通常表示されない要素は入らない
  - **`display: none` の要素も入らない**（DOM には残り、JavaScript からも取得できる）。Render Tree に入らないものは以降の工程に進まず、**場所も取らず描かれもしない**
  - 逆に、DOM にないのに CSS で出てくるもの（`::before` で足した飾りなど）もある

### display: none と visibility: hidden の違い

| | display: none | visibility: hidden |
|---|---|---|
| Render Tree | 入らない | 残る |
| 場所 | 取らない（下の要素が詰まる） | 取ったまま空白になる |
| 子要素に `visibility: visible` | 見えない | その子だけ見えるようになる |

### Layout → Paint → Composite

- **Layout**：Render Tree の時点では「何を描くか」だけで、位置や幅はまだない。幅は指定がなければ親の幅いっぱい → 親の親 → 最後はウィンドウ幅で決まる（PC とスマホで折り返しが変わる理由）。ウィンドウ幅から出発して箱ごとの位置と大きさを計算する
  - 例：見出しが 0px、その下にバナーがあるのでおすすめ商品は 120px から。バナーが Render Tree になければ見出しのすぐ下から始まる → **消したら下が詰まる理由**
- **Paint**：数字の並びから描く順番（背景 → 枠線 → 文字。後から描いたものが上に重なる）を決め、その順に色を置く
- **Composite**：ページの一部を別々の層に描いておき、最後に重ね合わせる。一部が動いたときにページ全体を塗り直さずに済む（例：スクロールは層をずらすだけで済む場合がある）

### 一度で終わらない：Reflow / Repaint

ページを開いた後も変更があるたびに、**変えたものに関係する工程から**やり直す。

| 変更 | やり直す工程 |
|---|---|
| `display: none` を付ける | 下の位置がずれるので Layout から（**リフロー**）→ Paint → Composite |
| 背景色だけ変える | 位置・大きさは変わらないので Paint から（**リペイント**） |
| `transform` で動かす | 条件が揃えば Composite だけで済む場合がある |

- アニメーションのように 1 秒に 60 回変わる場合、この差がそのまま滑らかさの差になる（`top` を毎回書き換えてスマホでカクカクになった経験談あり）
- **冒頭クイズの答え**：バナーを下へ動かすとき、やり直す工程が少ないのは **transform**。`top` は位置が変わるので Layout からやり直す
- ただし transform なら必ず Composite だけになるとは限らず、ブラウザの最適化次第

### まとめ

- 流れは **HTML→DOM／CSS→CSSOM → Render Tree → Layout → Paint → Composite**
- `display: none` は **Render Tree に入らない**から消えて場所も取らない。`visibility: hidden` は木に残り、場所を取ったまま見えないだけ
- 消したら下が詰まるのは **Layout が再計算された**から
- 表示がおかしいときは「HTML は合っている」で止まらず、その先の工程で何が起きているかを追う
