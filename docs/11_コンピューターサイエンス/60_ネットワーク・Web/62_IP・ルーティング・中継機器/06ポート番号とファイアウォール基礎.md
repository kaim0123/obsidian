# ポート番号とファイアウォール基礎

## ポート番号とは
同じコンピュータ上で動いている**複数のアプリを区別する番号**です。IPアドレスが「マンションの住所」なら、ポート番号は「部屋番号」にあたります。

```
[192.168.1.10]
 ├─ ポート80  → Webサーバー
 ├─ ポート22  → SSHサーバー
 └─ ポート3306→ MySQL
```

## 範囲と分類

| 範囲 | 区分 | 用途 |
|---|---|---|
| 0〜1023 | ウェルノウンポート | HTTP, SSH など標準サービス |
| 1024〜49151 | 登録済みポート | 特定ソフト用に登録されたもの |
| 49152〜65535 | 動的/プライベートポート | クライアント側の一時利用 |

## 代表的なポート番号

| ポート | プロトコル | 用途 |
|---|---|---|
| 20/21 | FTP | ファイル転送 |
| 22 | SSH | 暗号化リモート接続 |
| 25 | SMTP | メール送信 |
| 53 | DNS | 名前解決 |
| 80 | HTTP | Web（平文） |
| 110 | POP3 | メール受信 |
| 143 | IMAP | メール管理 |
| 443 | HTTPS | Web（暗号化） |
| 3306 | MySQL | データベース |
| 3389 | RDP | Windowsリモートデスクトップ |
| 5432 | PostgreSQL | データベース |
| 6379 | Redis | インメモリDB |
| 8080 | HTTP代替 | 開発サーバーなど |

## ポートの動き

### 例: Webアクセス
```
クライアント            サーバー
192.168.1.10:54321  →  203.0.113.5:443
    （動的ポート）        （ウェルノウン）
```
- クライアント側はOSが自動で空きポートを割り当てる
- サーバー側はサービスごとに決まったポートで待ち受け（LISTEN）

### ソケット
**IP + ポート番号**の組を「ソケット」と呼び、通信の端点を一意に識別します。

## よく使うコマンド
- `netstat -an` / `ss -tuln` : 開いているポートを確認
- `lsof -i :80` : ポート80を使っているプロセス
- Windowsの `netstat -ano` + `tasklist /FI "PID eq xxx"`

## ファイアウォールとは
ネットワークの通信を**許可・拒否**するルールに従ってフィルタリングする仕組みです。外部からの攻撃や意図しない通信を防ぐ役割を担います。

### 動作イメージ
```
[外部]
  │
  ▼
[ファイアウォール]  ← ルールで許可/拒否
  │
  ▼
[内部ネットワーク]
```

## ファイアウォールの種類

### パケットフィルタ型
- ヘッダ情報（IP・ポート・プロトコル）で判断
- 高速だがアプリ内容までは見ない

### ステートフルインスペクション型
- 通信の状態（接続中か否か）も記憶して判断
- 戻りの通信を自動で許可できる

### アプリケーションゲートウェイ（WAF等）
- HTTPなどアプリ層の中身まで検査
- SQLインジェクションなどを防ぐ

## ルール設計の基本

### 基本方針
- **デフォルト拒否**: 明示的に許可したもの以外は通さない
- **最小権限**: 必要最小限のポートだけ開ける
- **内向き/外向き**を別々に設計

### 例: Webサーバーの場合
```
許可:
  TCP 22   ← 管理用SSH（特定IPのみ）
  TCP 80   ← HTTP
  TCP 443  ← HTTPS
拒否:
  上記以外すべて
```

## セキュリティグループ（クラウド）
AWSなどクラウドではインスタンスごとに「セキュリティグループ」でファイアウォールを設定します。**インバウンド（入）/ アウトバウンド（出）**それぞれのルールを定義します。

## よくあるトラブル
- **繋がらない**: ポートが閉じている／ファイアウォールで遮断
- **遅い**: 想定外のポートで通信している
- **不要ポート開放**: 攻撃の入口になる

まずは `telnet ホスト ポート` や `nc -zv ホスト ポート` で疎通確認するのが定番です。

## 発展：IPサービスの全体像とポート番号

DHCP・DNS・NTP・SNMP などのIPサービスが使うTCP/UDPとポート番号を、一覧で整理します。

### なぜポート番号を覚える必要があるのか

IPアドレスは「どの機器か」を表し、ポート番号は「その機器の中のどのアプリケーション（サービス）か」を表します。ACLやファイアウォールで通信を許可・拒否するとき、パケットキャプチャを読むとき、障害の切り分けをするときには、「このサービスはTCPかUDPか、何番か」を即答できる必要があります。

「プロトコルとポート番号の組み合わせ」はよく問われ、**不正解の選択肢は、たいてい“別のプロトコルの正しいポート番号”** になっています（例：「Telnet ― 25」の25はSMTP）。そのため、1つずつ単独で覚えるのではなく、一覧で整理して「この番号はこのプロトコル」と双方向に言えるようにしておくのが効果的です。

### TCPとUDPの使い分け

| 項目 | TCP | UDP |
|---|---|---|
| 接続 | コネクション型（3ウェイハンドシェイクで接続を確立） | コネクションレス型（いきなり送る） |
| 信頼性 | 再送・順序制御・フロー制御あり | なし（必要ならアプリ側で対処） |
| オーバーヘッド | 大きい | 小さい（軽い） |
| 向いている用途 | 確実に届けたいもの（SSH、FTP、HTTP） | 軽さ・速さ優先、少量の問い合わせ、ブロードキャスト（DHCP、DNS問い合わせ、NTP、SNMP、Syslog、TFTP） |

IPサービスの多くがUDPを使うのは、次の理由からです。

- **DHCP**: クライアントはまだIPアドレスを持たず、サーバの場所も知らないため、TCPの接続（3ウェイハンドシェイク）を確立できない。ブロードキャストで送る必要もある（TCPはブロードキャストを扱えない）。
- **DNS**: 1回の問い合わせと応答で済む小さなやり取りなので、接続を張るコストが無駄になる。（応答が大きい場合やゾーン転送ではTCP 53も使う。）
- **SNMP**: 多数の機器を定期的に監視するため、軽いUDPが向いている。
- **NTP / Syslog**: 小さなメッセージを頻繁に送るため。
- **TFTP**: 実装を極力シンプルにするため（機器の起動時やROMモニタからでも使える）。

### よく出るポート番号一覧

| ポート | TCP/UDP | プロトコル | 用途・覚え方 |
|---|---|---|---|
| 20 | TCP | FTP（データ） | アクティブモードのデータ転送用 |
| 21 | TCP | FTP（制御） | ログイン・コマンド用。常に21番に接続 |
| 22 | TCP | SSH / SCP / SFTP | 暗号化されたリモートログイン・ファイル転送 |
| 23 | TCP | Telnet | 平文のリモートログイン（非推奨） |
| 25 | TCP | SMTP | メール送信 |
| 53 | UDP（主）/ TCP | DNS | 名前解決。通常の問い合わせはUDP |
| 67 | UDP | DHCP（サーバ） | サーバが待ち受け |
| 68 | UDP | DHCP（クライアント） | クライアントが待ち受け |
| 69 | UDP | TFTP | 認証なしの簡易ファイル転送 |
| 80 | TCP | HTTP | Web |
| 123 | UDP | NTP | 時刻同期 |
| 161 | UDP | SNMP（Get/Set） | エージェントが待ち受け |
| 162 | UDP | SNMP（Trap/Inform） | マネージャが待ち受け |
| 443 | TCP | HTTPS | 暗号化されたWeb |
| 514 | UDP | Syslog | ログの送信 |

**語呂・関連づけのコツ**

- 20/21/22/23 は「FTP・FTP・SSH・Telnet」と連番で覚える。SSHはTelnet（23）の安全版で、その1つ手前の22。
- DHCPは67/68と **2つの番号**（サーバ67、クライアント68）。DNS（53）やTFTP（69）と数字が近く、混同を狙われる。
- SNMPは161/162と **2つの番号**。小さいほう（161）が「エージェントへの問い合わせ」、大きいほう（162）が「Trap」。
- NTP 123 は「1・2・3と時を刻む」。
- Syslog 514。SNMPの161/162やNTPの123と取り違えさせる選択肢に注意。

### ひっかけポイント・よくある誤解

- 「Telnet ― 25」→ 25はSMTP（メール送信）。TelnetはTCP 23。
- 「DNS ― 69」→ 69はTFTP。DNSは53。
- 「NTP ― 161」→ 161はSNMP。NTPはUDP 123。
- 「DHCP ― UDP 53」「DHCP ― UDP 69」→ それぞれDNS、TFTPのポート。DHCPは67/68。
- 「SNMP ― 514」→ 514はSyslog。
- 「FTPの制御 ― TCP 20」→ 20はデータ用（アクティブモード）。制御は21。
- 「TFTP ― TCP」→ TFTPはUDP 69。TCP 20/21はFTP。

### 押さえておくポイント

- ポート番号の問題は、誤答が「他のプロトコルの正しい番号」になっている。一覧表を双方向（番号→プロトコル、プロトコル→番号）で言えるようにする。
- DHCP（67/68）とSNMP（161/162）は2つの番号を使う。どちらがどちら側かまで問われる。
- IPサービスの多くはUDP。TCPなのはSSH（22）、Telnet（23）、FTP（20/21）、HTTP/HTTPSなど。

## まとめ
- ポート番号はアプリを識別する**部屋番号**
- 有名サービスにはウェルノウンポートが決まっている
- ファイアウォールは通信を**許可/拒否**する関所
- 「**デフォルト拒否＋最小許可**」がセキュリティの基本
