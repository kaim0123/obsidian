# プロキシとリバースプロキシ

## プロキシとは
クライアントとサーバーの間に入り、**通信を中継する代理サーバー**のことです。「プロキシ（proxy）」は「代理」の意味。

```
[クライアント] ──→ [プロキシ] ──→ [サーバー]
                 代理で接続
```

プロキシは**どちら側の代理をするか**で大きく2種類に分かれます。
- **フォワードプロキシ**: クライアント側の代理
- **リバースプロキシ**: サーバー側の代理

## フォワードプロキシ

### 概要
「クライアント→サーバー」への通信を、クライアントに代わって中継します。一般に「プロキシ」というとこちらを指すことが多い。

```
[社内PC] ──→ [フォワードプロキシ] ──→ [インターネット]
```

### 主な用途
- **社内からのアクセス制御**（閲覧禁止サイトのブロック）
- **アクセスログ収集**
- **キャッシュによる高速化**
- **匿名化**（クライアントのIPを隠す）
- **地域制限の迂回**

### 代表的なソフト
- Squid
- (プライバシー用) Tor

### 設定のイメージ
ブラウザやOSに「このプロキシ経由で通信してね」と明示的に設定します。

## リバースプロキシ

### 概要
「外部→サーバー」への通信を、サーバー側で受けて中継します。クライアントからは**プロキシが本物のサーバーに見えます**。

```
[外部ユーザー] ──→ [リバースプロキシ] ──→ [Webサーバー1]
                                    ─→ [Webサーバー2]
                                    ─→ [Webサーバー3]
```

### 主な用途
1. **負荷分散（ロードバランシング）**
2. **SSL終端**: HTTPS処理をプロキシで行い、内部は平文HTTP
3. **キャッシュ**（CDN、静的ファイル）
4. **セキュリティ**（WAF、DDoS対策）
5. **URLルーティング**（パスごとに別サーバーへ振り分け）
6. **圧縮・最適化**（gzip, brotli）
7. **認証の統一**（Basic認証、OAuthゲートウェイ）

### 代表的なソフト
- **Nginx**（最も一般的）
- **HAProxy**
- **Traefik**
- **Envoy**
- クラウド: AWS ALB/CloudFront, Cloudflare

## フォワード vs リバース

| 項目 | フォワード | リバース |
|---|---|---|
| 代理する側 | クライアント | サーバー |
| 隠すIP | クライアント | サーバー |
| 設定する場所 | クライアント | サーバー |
| 主な目的 | 制御・匿名化 | 負荷分散・防御 |
| 例 | 社内Webフィルタ | Nginx, CDN |

## リバースプロキシの動作例（Nginx）

```nginx
http {
    upstream backend {
        server 10.0.0.1:3000;
        server 10.0.0.2:3000;
        server 10.0.0.3:3000;
    }

    server {
        listen 443 ssl;
        server_name example.com;

        ssl_certificate     /etc/ssl/fullchain.pem;
        ssl_certificate_key /etc/ssl/privkey.pem;

        location / {
            proxy_pass         http://backend;
            proxy_set_header   Host              $host;
            proxy_set_header   X-Real-IP         $remote_addr;
            proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
            proxy_set_header   X-Forwarded-Proto $scheme;
        }
    }
}
```

### ポイント
- `upstream` で振り分け先を定義
- SSLはリバースプロキシで終端
- `X-Forwarded-*` ヘッダで元の情報をバックエンドに伝える

## 代表的な負荷分散アルゴリズム
- **ラウンドロビン**: 順番に割り当て
- **最小コネクション**: 接続数が少ないサーバーへ
- **IPハッシュ**: 同じIPは同じサーバーへ（セッション維持）
- **重み付け**: サーバー性能に応じて配分

## CDN（Content Delivery Network）
リバースプロキシを**世界中に分散**配置したサービス。ユーザーに近いエッジから配信することで高速化します。
- 静的アセット（JS/CSS/画像）のキャッシュ
- エッジでのWAF、DDoS緩和
- 例: Cloudflare, CloudFront, Akamai, Fastly

## APIゲートウェイとの関係
リバースプロキシの進化系で、APIに特化した機能を持つ。
- 認証・認可
- レートリミット
- リクエスト/レスポンス変換
- マイクロサービスへのルーティング
- 例: Kong, AWS API Gateway, Traefik

## プロキシを通すときの注意点

### IPの見え方
- バックエンドサーバーから見える送信元IPはプロキシになる
- 本物のクライアントIPは `X-Forwarded-For` ヘッダなどで伝える必要あり

### ヘッダの扱い
- `Host`、`X-Real-IP`、`X-Forwarded-Proto` などを適切に設定
- 信頼できるプロキシからのヘッダのみ受け入れる（偽装対策）

### タイムアウト
- クライアント側・プロキシ側・バックエンド側で階層的にタイムアウトが発生する

## 透過型プロキシ
クライアントに設定させず、ネットワーク経路上で自動的に中継するプロキシ。ISP、企業ネットワークでよく使われる。

## SOCKSプロキシ
HTTPだけでなく**任意のTCP/UDP**を中継できる汎用プロキシ（SSHトンネルでよく使う）。
```bash
ssh -D 1080 user@example.com   # ローカル1080をSOCKS5として使う
```

## まとめ
- **フォワードプロキシ = クライアント側の代理**（制御・匿名化）
- **リバースプロキシ = サーバー側の代理**（負荷分散・防御・SSL終端）
- 実務ではNginxなどをリバースプロキシとして置くのが定番
- CDNやAPIゲートウェイもリバースプロキシの応用
