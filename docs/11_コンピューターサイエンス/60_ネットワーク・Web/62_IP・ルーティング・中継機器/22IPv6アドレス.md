# IPv6アドレス

## この章で扱うこと
IPv6アドレスの表記と省略ルール、プレフィックスとインターフェースID、アドレスの種類（リンクローカル・ユニークローカル・エニーキャスト・マルチキャスト）、修正EUI-64を扱います。

## IPv6アドレス

### IPv6アドレスの表記

IPv6アドレスは**128ビット**で、16ビットずつ8つの**ブロック（フィールド）**に区切り、各ブロックを4桁の16進数で表し、コロン（`:`）でつなぎます。

```
2001:0db8:0000:0000:0000:0000:0000:0001
└16bit┘ × 8ブロック ＝ 128ビット
```

#### 省略ルール（2つ）

| ルール | 内容 | 例 |
| --- | --- | --- |
| ① 先頭の0の省略 | 各ブロックの**先頭（左側）の0**は省略できる | `0db8` → `db8`、`0000` → `0`、`0001` → `1` |
| ② 連続する0ブロックの省略 | **0だけのブロックが連続する部分**は `::` にまとめられる。**1つのアドレスで1回だけ** | `:0:0:0:0:0:` → `::` |

**例**: `2001:0db8:0000:0000:0000:0000:0000:0001` を省略する。

1. 先頭の0を省略: `2001:db8:0:0:0:0:0:1`
2. 連続する0ブロック（6個）を `::` に: **`2001:db8::1`**

```
2001 : 0db8 : 0000 : 0000 : 0000 : 0000 : 0000 : 0001
2001 :  db8 :    0 :    0 :    0 :    0 :    0 :    1    ← ルール①
2001 :  db8 :             ::                     :    1    ← ルール②
= 2001:db8::1
```

**なぜ `::` は1回だけなのか**: `::` は「足りないブロックを0で埋める」という意味です。8ブロックに戻すとき、`::` が1つなら「8 − 書かれているブロック数」個の0を入れればよいので一意に決まりますが、2つあると、それぞれにいくつ0が入るのか決まりません。

```
2001:db8::0::1 の場合（書かれているブロックは 2001, db8, 0, 1 の4つ → 0を4個補う）
  2001:db8:0:0:0:0:0:1 ?  ← 左の::に3個、右の::に1個？
  2001:db8:0:0:0:0:0:1 ?  ← 左に1個、右に3個？ …どちらとも決められない → 不正
```

| 誤りの例 | 問題点 |
| --- | --- |
| `2001:db8:0:1` | ブロックが4つしかない。`::` を使わずに0のブロックを消すことはできない |
| `2001:db8::0::1` | `::` を2回使っている |
| `2001:db8:1` | ブロックが3つしかなく、0のブロックを `::` なしで消している |

補足: 0の省略は**先頭（左側）だけ**です。`0db0` を `db` にすることはできません（末尾の0は省略不可）。また、RFC 5952 の推奨表記では、16進数は小文字、`::` は最も長い0の連続部分に使い、0ブロックが1つだけの場合は `::` にしません。

### プレフィックスとインターフェースID

IPv6でもアドレスは「ネットワークを表す部分（**プレフィックス**）」と「機器を表す部分（**インターフェースID**）」に分かれ、プレフィックス長を `/64` のように表します。

**1ブロックは16ビット**なので、プレフィックス長をブロック数に換算すると簡単です。

| プレフィックス長 | ブロック数 | 典型的な用途 |
| --- | --- | --- |
| /32 | 先頭2ブロック | ISPへの割り当て |
| /48 | 先頭3ブロック | **組織（サイト）への割り当て**の単位としてよく使われる |
| /56 | 3.5ブロック | 小規模サイト・家庭 |
| **/64** | **先頭4ブロック** | **LANのサブネット**（一般的。SLAACには /64 が必要） |
| /127 | — | ルータ間のポイントツーポイントリンク |
| /128 | 全8ブロック | 1つのアドレス（ループバックなど） |

**例**: `2001:db8:acad:1::10/64` のプレフィックスは？

1. まず省略を戻して8ブロックにする
   `2001:0db8:acad:0001:0000:0000:0000:0010`
2. /64 = 先頭4ブロック → `2001:0db8:acad:0001`
3. 残り4ブロック（`0000:0000:0000:0010` = `::10`）がインターフェースID
4. プレフィックスは インターフェースID を0にしたもの → **`2001:db8:acad:1::/64`**

```
2001:db8:acad:1 : 0:0:0:10
└─ プレフィックス(64) ┘ └─ インターフェースID(64) ┘
```

| 誤りの選択肢 | 問題点 |
| --- | --- |
| `2001:db8::/64` | 3〜4ブロック目の `acad:1` が抜けている |
| `2001:db8:acad::/48` | プレフィックス長が違う。/48 は組織に割り当てる単位 |
| `::10/64` | インターフェースIDの部分だけを取り出している |

一般的な割り当ての階層:

```
2001:db8:acad::/48          ← 組織に割り当て（/48）
  2001:db8:acad:1::/64      ← サブネット1（4ブロック目でサブネットを区別：65,536個作れる）
  2001:db8:acad:2::/64      ← サブネット2
```

### IPv6アドレスの種類

IPv6の通信方式は**ユニキャスト・マルチキャスト・エニーキャスト**の3種類です。**ブロードキャストは存在しません**。

| 種類 | 範囲 | 説明 | IPv4で相当するもの |
| --- | --- | --- | --- |
| **グローバルユニキャスト（GUA）** | **2000::/3**（2000〜3FFF で始まる） | インターネットで使える、世界で一意のアドレス | グローバルアドレス |
| **ユニークローカル（ULA）** | **FC00::/7**（実際は **FD00::/8** を使う） | 組織内で自由に使え、組織内の複数のネットワークにはルーティングできるが、インターネットへはルーティングされない | **プライベートアドレス**（RFC 1918） |
| **リンクローカル** | **FE80::/10** | 同じリンク（セグメント）内でのみ有効。**ルータを越えて転送されない**。IPv6を有効にしたインターフェースに**自動で付与** | 169.254.0.0/16（APIPA） |
| **マルチキャスト** | **FF00::/8** | グループに参加しているすべての機器に届く | 224.0.0.0/4 |
| ループバック | **::1/128** | 自分自身 | 127.0.0.1 |
| 未指定 | ::/128 | アドレス未設定（送信元として一時的に使う） | 0.0.0.0 |
| エニーキャスト | （専用の範囲なし） | ユニキャストアドレスを複数の機器に設定し、最寄りの1台に届ける | — |

先頭の16進数で見分けるコツ:

```
2xxx, 3xxx  → グローバルユニキャスト（2000::/3）
FCxx, FDxx  → ユニークローカル（FC00::/7）
FE80〜FEBF  → リンクローカル（FE80::/10）
FFxx        → マルチキャスト（FF00::/8）
::1         → ループバック
```

#### リンクローカルアドレス

リンクローカルアドレスは、IPv6を有効にしたインターフェースに**自動で付与**されます（グローバルアドレスがなくても存在する）。同じリンク内だけで有効で、ルータを越えて転送されません。用途は、

- ルータ同士のやり取り（**OSPFv3のHello**など）
- **隣接ノードの検出（NDP）**、ルータ広告（RA）
- **IPv6ルーティングテーブルのネクストホップ**（ネクストホップがリンクローカルで表示されることが多い）

```
Router# show ipv6 interface brief
GigabitEthernet0/0     [up/up]
    FE80::21A:2BFF:FE3C:4D5E
    2001:DB8:ACAD:1::1

Router# show ipv6 route
O   2001:DB8:ACAD:2::/64 [110/2]
     via FE80::2, GigabitEthernet0/1        ← ネクストホップがリンクローカル
```

#### ユニークローカルアドレス

**リンクローカルとユニークローカルの違いは「使える範囲」**です。

```
       ┌──────────────── 組織内 ─────────────────┐
       │  [LAN-A] ── Router ── [LAN-B]           │ ── インターネット
       │   ↑ リンクローカル    ↑ リンクローカル     │
       │   （このリンクだけ）  （このリンクだけ）   │
       │   ←─── ユニークローカルは組織内でルーティング可 ──→│   ✕ インターネットへは出ない
       └─────────────────────────────────────────┘
```

| | リンクローカル | ユニークローカル | グローバルユニキャスト |
| --- | --- | --- | --- |
| 範囲 | FE80::/10 | FC00::/7（FD00::/8） | 2000::/3 |
| 有効範囲 | 1つのリンクの中だけ | 組織内（複数ネットワーク） | インターネット全体 |
| ルータを越えるか | 越えない | 組織内なら越える | 越える |
| インターネット | ✕ | ✕ | ○ |

FC00::/7 のうち、8ビット目が1の FD00::/8 がローカルに生成するアドレス（ランダムな40ビットのグローバルIDを含む）として使われます。

#### エニーキャスト

**同じユニキャストアドレスを複数の機器に設定**し、送信元から**ルーティング上最も近い（コストが最小の）1台**に届くようにする方式です。**エニーキャスト専用のアドレス範囲はありません**。DNSサーバ（ルートDNSサーバなど）の負荷分散や冗長化に使われます。

```
          ┌─ 経路コスト 10 ─ DNSサーバA（2001:db8::53）
 クライアント
          └─ 経路コスト 30 ─ DNSサーバB（2001:db8::53）   ← 同じアドレス
 → 2001:db8::53 宛ての通信は、コストが小さいサーバAに届く
```

```
Router(config-if)# ipv6 address 2001:db8::53/64 anycast
```

| 方式 | 届く相手 |
| --- | --- |
| ユニキャスト | 1対1（1台の機器だけに割り当てたアドレス） |
| マルチキャスト | 1対グループ（参加しているすべての機器） |
| エニーキャスト | 1対最寄りの1台 |
| ブロードキャスト | （**IPv6には存在しない**） |

#### ブロードキャストがない理由とマルチキャスト

ブロードキャストは、ネットワーク内の**すべての機器の処理を中断させる**（関係のない機器も受け取ってCPUで処理しなければならない）ため、IPv6では廃止されました。代わりに、**必要な機器だけが受け取るマルチキャスト**を使います。IPv6ではマルチキャストはIPv4以上に重要な役割を持ちます。

| マルチキャストアドレス | 意味 |
| --- | --- |
| FF02::1 | 全ノード（リンク内のすべてのIPv6機器）。ブロードキャストの代わりに近い |
| FF02::2 | 全ルータ |
| FF02::5 / FF02::6 | OSPFv3（全OSPFルータ / DR・BDR） |
| FF02::1:FFxx:xxxx | 要請ノードマルチキャスト（NDPのアドレス解決に使う） |

例えば、IPv4の**ARP**（ブロードキャストで「このIPアドレスのMACアドレスは？」と全員に聞く）の役割は、IPv6では **NDP（Neighbor Discovery Protocol）** が担います。NDPは **ICMPv6** のメッセージ（NS/NA、RS/RA）を使い、宛先を要請ノードマルチキャストにすることで、関係する機器だけが処理すればよいようにしています。

| IPv4 | IPv6 |
| --- | --- |
| ARP（ブロードキャスト） | NDP の NS/NA（ICMPv6＋要請ノードマルチキャスト） |
| ブロードキャスト | マルチキャスト（FF02::1 など） |
| DHCP | SLAAC（RS/RA）、DHCPv6 |

### 修正EUI-64

**修正EUI-64**は、48ビットのMACアドレスから64ビットのインターフェースIDを自動生成する方式です。SLAACやリンクローカルアドレスの生成に使われます。

**手順（MACアドレス 00:1A:2B:3C:4D:5E の例）**

**ステップ1: MACアドレスを前半と後半（24ビットずつ）に分ける**

```
00:1A:2B  |  3C:4D:5E
 前半(OUI)    後半
```

**ステップ2: 間に `FFFE` を挿入して64ビットにする**

```
00 1A 2B  FF FE  3C 4D 5E
→ 001A:2BFF:FE3C:4D5E
```

**ステップ3: 先頭から7ビット目（U/Lビット）を反転する**

```
先頭のバイト 00 = 0000 0000
                       ↑ 7ビット目（左から数えて7番目）
反転後            0000 0010 = 02
```

**結果: `021A:2BFF:FE3C:4D5E`**

7ビット目の反転は、先頭バイトの16進数に「2を足す/引く」と覚えると速いです（7ビット目の重みが2のため）。

| 先頭バイト | 2進数 | 反転後 | 結果 |
| --- | --- | --- | --- |
| 00 | 0000 0000 | 0000 0010 | **02** |
| 02 | 0000 0010 | 0000 0000 | 00 |
| 0C | 0000 1100 | 0000 1110 | 0E |
| A4 | 1010 0100 | 1010 0110 | A6 |
| 1A | 0001 1010 | 0001 1000 | 18 |

このインターフェースIDを使ったアドレスの例:

- リンクローカル: `FE80::21A:2BFF:FE3C:4D5E`（先頭の0は省略）
- グローバル（プレフィックス 2001:db8:acad:1::/64 の場合）: `2001:db8:acad:1:21a:2bff:fe3c:4d5e`

```
Router(config)# interface gigabitethernet0/0
Router(config-if)# ipv6 address 2001:db8:acad:1::/64 eui-64
Router(config-if)# exit
Router(config)# ipv6 unicast-routing          ! ルータとしてIPv6をルーティングする場合

Router# show ipv6 interface gigabitethernet0/0
GigabitEthernet0/0 is up, line protocol is up
  IPv6 is enabled, link-local address is FE80::21A:2BFF:FE3C:4D5E
  Global unicast address(es):
    2001:DB8:ACAD:1:21A:2BFF:FE3C:4D5E, subnet is 2001:DB8:ACAD:1::/64 [EUI]
  Joined group address(es):
    FF02::1
    FF02::2
    FF02::1:FF3C:4D5E
```

| 誤りの例 | 問題点 |
| --- | --- |
| `001A:2BFF:FE3C:4D5E` | FFFE の挿入はできているが、7ビット目の反転を忘れている |
| `021A:2BFE:FF3C:4D5E` | 挿入する値が FEFF になっている（正しくは **FFFE**） |
| `001A:2B3C:4D5E:FFFE` | FFFE を末尾に付けている。FFFE は前半と後半の**間**に挿入する |

### IPv6アドレスの設定方法（参考）

| 方法 | 内容 |
| --- | --- |
| 手動（静的） | `ipv6 address 2001:db8:acad:1::1/64` |
| 修正EUI-64 | `ipv6 address 2001:db8:acad:1::/64 eui-64` |
| SLAAC | ルータのRA（ルータ広告）でプレフィックスを受け取り、インターフェースIDは自分で生成（EUI-64またはランダム） |
| DHCPv6 | ステートフル（アドレスも配布）／ステートレス（DNSなどの情報だけ配布、アドレスはSLAAC） |
| リンクローカル | IPv6を有効にすると自動生成（`ipv6 enable`） |

### ひっかけポイント・よくある誤解

- **`::` を2回使う。** 1つのアドレスで `::` は1回だけ。
- **`::` を使わずに0ブロックを消す。** ブロック数が8に満たない表記は不正。
- **末尾の0を省略する。** 省略できるのは各ブロックの先頭の0だけ。
- **/64 のプレフィックスでブロックを落とす。** /64 は先頭4ブロック。`2001:db8:acad:1::10/64` のプレフィックスは `2001:db8:acad:1::/64`。
- **/48 を LANのサブネットと考える誤り。** /48 は組織への割り当て単位、LANは /64。
- **リンクローカル（FE80::/10）とユニークローカル（FC00::/7）の取り違え。** IPv4のプライベートアドレスに相当するのはユニークローカル。リンクローカルは同じリンク内だけで、組織内の別のネットワークへもルーティングされない。
- **2000::/3 を組織内専用と考える誤り。** 2000::/3 はインターネットで使うグローバルユニキャスト。
- **FF00::/8 をリンクローカルと考える誤り。** FF00::/8 はマルチキャスト。
- **::1 をユニークローカルと考える誤り。** ::1 はループバック（IPv4の127.0.0.1）。
- **EUI-64 で7ビット目の反転を忘れる、FFFE を FEFF にする、FFFE を末尾に付ける。**
- **エニーキャストとマルチキャストの混同。** マルチキャストはグループの全員、エニーキャストは最寄りの1台。
- **「IPv6にもブロードキャストがある」は誤り。** IPv6にあるのはユニキャスト・マルチキャスト・エニーキャスト。
- **エニーキャスト専用のアドレス範囲がある、は誤り。** ユニキャストアドレスを複数の機器に設定して使う。

### 押さえておくポイント

- 128ビット、16ビット×8ブロック、16進数
- 省略: 先頭の0を省略、連続する0ブロックは `::`（1回だけ）
- /64 ＝ 先頭4ブロック（LANの標準）、/48 ＝ 組織への割り当て単位
- GUA 2000::/3、ULA FC00::/7（FD00::/8）、リンクローカル FE80::/10、マルチキャスト FF00::/8、ループバック ::1
- リンクローカル: 自動付与、ルータを越えない、OSPFv3・NDP・ネクストホップに使う
- ULA ＝ IPv4のプライベートアドレス相当
- エニーキャスト: 同じアドレスを複数機器に設定 → 最寄りの1台に届く（専用範囲なし）
- IPv6にブロードキャストはない（マルチキャストで代用、ARPの役割はNDP）
- 修正EUI-64: MACを半分に分けて FFFE を挿入、先頭から7ビット目を反転
