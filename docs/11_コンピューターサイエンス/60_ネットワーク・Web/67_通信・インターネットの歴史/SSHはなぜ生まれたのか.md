## 詳しい要約

**テーマ：盗聴被害者の自衛ツールだったSSHが、世界中のサーバーの「玄関」かつ「配管」になるまで**

SSHはセキュリティ専門家が設計したものではなく、1995年に盗聴被害に遭ったフィンランドの研究者タトゥ・ユロネンが自分を守るために5ヶ月で書いた道具だった。自由な条件で配られた最後の版がOpenSSHとして生き残り、SSH-2で汎用の通信路へと性格を変えた。現在は発明者自身が鍵管理に警鐘を鳴らし、業界は「鍵を配らない」方向へ動いている。

---

### 第1章 起点になった盗聴事件

- 1995年、ヘルシンキ工科大学のネットワークで**スニッファー**が見つかり、数千人分の利用者名とパスワードが**平文**のまま抜かれていた
- 被害者の一人だったユロネン（27歳、専門は**データベース**で暗号は素人）が独自に対策ツールを作り始める
- 暗号方式を自作せず、既存方式を組み合わせる側に徹した
- 1995年7月にソースコード付きの無償ソフトとして公開 → 年末までに約50カ国・2万人に普及、サポートメールは1日150通
- 同年12月に **SSH Communications Security** 社を設立

### 第2章 なぜ世界は平文のままだったのか

- 1980年代までのインターネットは大学・研究機関だけの閉じた世界で、「鍵をかける」発想がなかった
- BSD UNIXの **rlogin / rsh / rcp（rコマンド）** は、接続元のマシン名と利用者名が許可リストにあればパスワードすら省略する「自己申告を信じる」仕組み
- 1990年代の商用化で悪意ある利用者が流入。当時のイーサネットは共有線で、隣の通信がそのまま見えた
- 1995年はWindows 95の年であり、一般利用者が流れ込んだ時期に事件とSSH誕生が重なった
- ポート番号の逸話：IANAに申請した結果、FTP(21)とTelnet(23)に挟まれた **22番** が空いており、翌日には割り当てられた
- ポイント：平文の時代は怠慢ではなく、悪意のない閉じた世界の名残だった

### 第3章 最後の自由な1本とOpenSSH

- 会社設立後、SSHのライセンスは版を重ねるごとに厳しくなり、商用利用が有料化
- 制限前に自由な条件で配られた **バージョン1.2.12** は回収できなかった
- 1998年、スウェーデンのビョルン・グレンバルがこれを拾い「OSSH」として再配布（ライセンス通りの利用で横取りではない）
- 1999年9月、**OpenBSD** チームが取り込み、12月1日のOpenBSD 2.6リリースまで約2ヶ月で作り直し（古いコードの整理、特許の残る暗号処理を外部部品に差し替え、プロトコル部分の書き直し）→ **OpenSSH** が誕生し、他OSにも移植されLinuxにも標準搭載
- 2001年、ユロネン側が「SSHは自社商標」と改名を求めたが、OpenBSD側は「すでにプロトコルを指す一般名詞」として拒否
- ポイント：SSHを世界標準にしたのは発明そのものではなく、自由な条件で残った最後の1本だった

### 第4章 玄関から配管へ（SSH-2）

- 初期SSH（SSH-1）は改ざん検知に **CRC32**（誤り検出用で、意図的な書き換えを防ぐ設計ではない）を使っていた
- 1998年、暗号化された通信の中身を読まずに任意データを差し込める攻撃手法が公表され、互換性を保ったままでは防げない構造的欠陥と判明
- 全面改訂版 **SSH-2** がIETFで標準化され、RFCとして確定したのは2006年（提案から約9年）
- SSH-2は **通信路の暗号化／利用者認証／チャネルの多重化** の3層構造。多重化により1本の接続内に独立した通信を何本も通せる
- ポート転送、ファイル転送、Git over SSH、rsync、踏み台の多段接続などはすべてこの設計の上に乗っている
- ポイント：SSHの寿命を伸ばしたのは暗号の強さではなく、何でも通せる汎用設計だった

### 最終章 合鍵の時代の終わり

- 鍵管理に最も強く警鐘を鳴らしているのは発明者本人。NISTが2015年に出した鍵管理の指針（内部報告 **NISTIR 7966**）の著者に名を連ねる
- 問題：鍵は配れるが回収できない。大組織ではサーバー1台に数十の公開鍵が溜まり、誰の鍵か分からなくなり、退職者の鍵が生きたまま残ることも多い
- 業界は鍵を配らない方向へ：
  - **AWS Session Manager**：22番ポートを開けず、サーバー側から迎えに行く形で接続
  - **Teleport** や **Tailscale SSH**：数時間で失効する使い捨て証明書を接続のたびに発行
- プロトコル側も現役で戦っている：2023年の **Terrapin攻撃**（接続冒頭のやり取りを削って機能の取り決めを弱い側へ誘導）。OpenSSHはその後、認証処理を本体から別プログラムに切り離した
- 利用者から見える使い方（宛先を打って入る）は1995年から変わらず、内部だけを作り替え続けたため、30年間誰も学び直さずに済んでいる

### まとめ

- SSHは製品開発ではなく、盗聴被害者の応急処置から生まれた
- 世界標準になったのは、自由なライセンスで残った最後の版をOpenBSDが拾ったから
- SSH-2のチャネル多重化によって「安全なログイン」から「何でも運ぶ配管」になった
- 今は「鍵を渡す」方式から「その都度身分を証明する（短命証明書・鍵を配らない接続）」方式へ移行しつつある
