# OSI参照モデルとカプセル化

## OSI参照モデルとは
ネットワーク通信の役割を**7つの階層**に分けて整理した国際標準モデルです。TCP/IPの4階層モデルより細かく、ネットワークの動作を理解・説明するための「共通言語」として使われます。

## 7階層の構成

```
┌───────────────────────────────┐
│ 7. アプリケーション層          │ HTTP, SMTP, FTP, DNS
├───────────────────────────────┤
│ 6. プレゼンテーション層        │ 文字コード、暗号化、圧縮
├───────────────────────────────┤
│ 5. セッション層                │ 接続の開始・維持・終了
├───────────────────────────────┤
│ 4. トランスポート層            │ TCP, UDP
├───────────────────────────────┤
│ 3. ネットワーク層              │ IP, ICMP
├───────────────────────────────┤
│ 2. データリンク層              │ イーサネット, MACアドレス
├───────────────────────────────┤
│ 1. 物理層                      │ ケーブル、電気信号、電波
└───────────────────────────────┘
```

### 各層の役割
| 層 | 役割 | 代表的な技術 |
|---|---|---|
| 7 アプリケーション | ユーザーが使うサービス | HTTP, DNS, SMTP |
| 6 プレゼンテーション | データ形式の変換 | JPEG, TLS, UTF-8 |
| 5 セッション | 通信の開始/終了管理 | RPC, NetBIOS |
| 4 トランスポート | 信頼性確保、ポート識別 | TCP, UDP |
| 3 ネットワーク | 宛先までの経路選択 | IP, ルーター |
| 2 データリンク | 隣接機器との通信 | イーサネット, スイッチ |
| 1 物理 | 物理的な信号の伝送 | ケーブル, Wi-Fi電波 |

## TCP/IPモデルとの対応

```
OSI 7層                    TCP/IP 4層
─────────────────────────────────────────
7 アプリケーション ─┐
6 プレゼンテーション├─→ アプリケーション層
5 セッション       ─┘
4 トランスポート    ─→ トランスポート層
3 ネットワーク      ─→ インターネット層
2 データリンク     ─┐
1 物理             ─┴→ ネットワークI/F層
```

## カプセル化とは
上の層から受け取ったデータに、各層で**ヘッダ（必要な制御情報）を追加して包む**処理のことです。受信側では逆に、下の層からヘッダを剥がしていきます（非カプセル化）。

### 送信時のカプセル化
```
[アプリデータ]                         ← 7層
  ↓
[TCPヘッダ | データ]                   ← 4層（セグメント）
  ↓
[IPヘッダ | TCPヘッダ | データ]        ← 3層（パケット）
  ↓
[イーサヘッダ | IP | TCP | データ | FCS] ← 2層（フレーム）
  ↓
 0101010101...                          ← 1層（ビット列）
```

### 受信時の非カプセル化
物理信号 → フレーム → パケット → セグメント → アプリデータ、と上へ渡しながら不要なヘッダを外していきます。

## 各層の単位（PDU）の呼び名
- アプリケーション層: **データ / メッセージ**
- トランスポート層: **セグメント（TCP）/ データグラム（UDP）**
- ネットワーク層: **パケット**
- データリンク層: **フレーム**
- 物理層: **ビット**

## なぜ階層に分けるのか

### メリット
1. **独立性**: ある層の実装を変えても他の層に影響が出にくい
2. **標準化**: 異なるメーカー同士でも通信できる
3. **分業**: 専門家が各層に集中して開発できる
4. **トラブル切り分け**: どの層で問題が起きているか特定しやすい

### 例: Wi-Fi→有線への切り替え
物理層（1層）とデータリンク層（2層）の技術が変わるだけで、上位のHTTPやTCPはそのまま動き続けます。

## 実務での使い方
トラブル対応では「**何層の問題か**」を意識するのが基本です。
- ping（3層）が通るか
- ポート（4層）が開いているか
- HTTPS（7層）が応答するか

## 発展：OSI参照モデルとTCP/UDP

OSI参照モデルの各層で動く機器・データの単位と、TCPとUDPの違い（3ウェイハンドシェイクなど）をもう一段詳しく整理します。

### なぜ「層」に分けるのか

ネットワーク通信は、「電気信号をどう送るか」から「どのアプリケーションにデータを渡すか」まで、多くの仕事の組み合わせです。これを1つの仕組みで全部やろうとすると複雑すぎるため、**役割ごとに層（レイヤ）に分けて**考えます。層に分けると、

- ある層の技術を入れ替えても（例: 銅線 → 光ファイバ）、上の層は影響を受けない
- 機器やプロトコルが「どの層で動くか」で役割を整理できる
- トラブル時に「どの層の問題か」で切り分けられる

という利点があります。この「層の地図」が **OSI参照モデル**（7層）と、実際のインターネットで使われる **TCP/IPモデル**（4層）です。

### OSI参照モデルの7層

| 層 | 名称 | 主な役割 | データの単位 | 代表的なアドレス・プロトコル | 代表的な機器 |
| --- | --- | --- | --- | --- | --- |
| L7 | アプリケーション層 | アプリケーションにサービスを提供 | データ | HTTP, DNS, SMTP, SSH | — |
| L6 | プレゼンテーション層 | データの表現形式（文字コード・暗号化など） | データ | JPEG, ASCII | — |
| L5 | セッション層 | 通信の開始・維持・終了の管理 | データ | — | — |
| L4 | トランスポート層 | アプリケーション間の通信、信頼性 | セグメント（TCP）/ データグラム（UDP） | TCP, UDP、**ポート番号** | — |
| L3 | ネットワーク層 | 異なるネットワーク間の経路選択（ルーティング） | パケット | IP, ICMP、**IPアドレス** | **ルータ**、L3スイッチ |
| L2 | データリンク層 | 同じネットワーク内での転送 | フレーム | Ethernet, **MACアドレス** | **L2スイッチ**、ブリッジ |
| L1 | 物理層 | 電気・光・電波の信号として送る | ビット | ケーブル、コネクタ、電圧 | **ハブ、リピータ**、ケーブル |

覚え方の基本は、**L1〜L4の層と代表的な機器をセットで覚える**ことです。

```
L4 トランスポート  … TCP/UDP        … ポート番号でアプリを区別
L3 ネットワーク    … IP             … ルータ（IPアドレスで経路選択）
L2 データリンク    … Ethernet       … L2スイッチ（MACアドレスで転送）
L1 物理            … 信号・ケーブル … ハブ・リピータ（信号を流すだけ）
```

#### ルータがL3で動作する理由

ルータの仕事は「受け取ったパケットの**宛先IPアドレス**を見て、ルーティングテーブルから次に送るべき方向（ネクストホップ・出力インターフェース）を決める」ことです。IPアドレスはL3のアドレスなので、ルータは**ネットワーク層（L3）**の機器です。

- L2スイッチはMACアドレス（L2）しか見ません。同じネットワーク（同じVLAN）内でしか転送できません。
- ハブやリピータは、信号の中身（アドレス）を一切見ずに、電気信号をそのまま流す/増幅するだけなのでL1です。
- L4はTCP/UDPが動く層で、**ポート番号**で通信相手のアプリケーションを区別します（例: HTTPS = TCP 443、DNS = UDP/TCP 53）。

### TCP/IPモデルとの対応

| OSI参照モデル | TCP/IPモデル（4層） | 例 |
| --- | --- | --- |
| L7 アプリケーション / L6 / L5 | アプリケーション層 | HTTP, DNS, DHCP, SSH |
| L4 トランスポート | トランスポート層 | TCP, UDP |
| L3 ネットワーク | インターネット層 | IPv4, IPv6, ICMP |
| L2 データリンク / L1 物理 | ネットワークアクセス層（リンク層） | Ethernet, Wi-Fi |

ネットワークの現場では「L2」「L3」のようにOSIの層番号で会話するのが一般的です。

### カプセル化

送信側では上の層から順にヘッダを付けていき（カプセル化）、受信側では下の層から順にヘッダを外します（非カプセル化）。

```
アプリケーションデータ
        ↓ L4: TCP/UDPヘッダを付ける（送信元/宛先ポート）      → セグメント
[TCPヘッダ][データ]
        ↓ L3: IPヘッダを付ける（送信元/宛先IPアドレス）        → パケット
[IPヘッダ][TCPヘッダ][データ]
        ↓ L2: Ethernetヘッダ＋FCSを付ける（送信元/宛先MAC）    → フレーム
[Ethernetヘッダ][IPヘッダ][TCPヘッダ][データ][FCS]
        ↓ L1: ビット列（電気・光・電波の信号）として送出
```

フレームの末尾の **FCS（Frame Check Sequence）** は、[[20物理層とケーブル・インターフェースの状態]] で扱うCRCエラーの話につながります。

### TCPとUDPの違い

L4の2大プロトコルがTCPとUDPです。

| 項目 | TCP | UDP |
| --- | --- | --- |
| 接続 | **コネクション型**（3ウェイハンドシェイクで接続を確立） | **コネクションレス型**（いきなり送る） |
| 信頼性 | 確認応答（ACK）・**再送**・順序制御・フロー制御（ウィンドウ）あり | なし（失われても再送しない） |
| ヘッダ長 | **最低20バイト** | **8バイト** |
| 速度・オーバーヘッド | 重い | 軽い・速い |
| 通信形態 | **1対1（ユニキャスト）専用** | 1対1のほか、ブロードキャスト・マルチキャストも可 |
| 主な用途 | HTTP/HTTPS, SSH, Telnet, FTP, SMTP | DNS（通常の問い合わせ）, DHCP, TFTP, SNMP, Syslog, 音声・動画（RTP） |

#### 3ウェイハンドシェイク

```
クライアント                      サーバ
    |  ---- SYN ------------------> |   ①接続したい
    |  <--- SYN/ACK --------------- |   ②了解。こちらからも接続したい
    |  ---- ACK ------------------> |   ③了解
    |  ==== データ送受信 ========== |
```

TCPは送ったデータに対して受信側から ACK（確認応答）が返ってこなければ、そのデータを**再送**します。これにより「確実に届く」ことを保証します。その代わり、接続確立・ACK・再送のための処理とヘッダが必要で、オーバーヘッドが大きくなります。

UDPは接続確立も再送もしないので、ヘッダはわずか8バイト（送信元ポート・宛先ポート・長さ・チェックサム）です。

- **音声・動画**: 遅れて再送されたデータは役に立たないので、多少欠けても速さを優先 → UDP
- **DNS**: 小さな問い合わせ1往復で済み、失敗したらアプリ側で問い合わせ直せばよい → UDP（大きな応答やゾーン転送はTCP）
- **DHCP**: 端末はまだIPアドレスを持っておらず、サーバの場所も知らないので**ブロードキャスト**で探す → 1対1専用のTCPは使えず UDP（67/68）

### ひっかけポイント・よくある誤解

- **「UDPも3ウェイハンドシェイクで接続を確立する」は誤り。** 3ウェイハンドシェイクはTCPの接続手順。UDPは接続を確立せずにいきなりデータを送る。
- **「TCPはブロードキャスト通信でよく使われる」は誤り。** TCPは1対1の通信専用。ブロードキャストはUDPで行う（例: DHCP）。
- **ルータの層をL2やL4と答える誤り。** MACアドレスで転送するのはL2スイッチ、ポート番号で区別するのはL4（TCP/UDP）。ルータはIPアドレスで経路を選ぶL3。
- **ハブをL2と答える誤り。** ハブ・リピータは信号を流す/増幅するだけのL1機器。

### 押さえておくポイント

- L1 物理（ハブ・リピータ）→ L2 データリンク（L2スイッチ・MAC）→ L3 ネットワーク（ルータ・IP）→ L4 トランスポート（TCP/UDP・ポート番号）
- データ単位: ビット（L1）、フレーム（L2）、パケット（L3）、セグメント/データグラム（L4）
- TCP: コネクション型、3ウェイハンドシェイク（SYN → SYN/ACK → ACK）、ACKと再送で信頼性、ヘッダ最低20バイト、1対1のみ
- UDP: コネクションレス、再送なし、ヘッダ8バイト、軽量・高速、ブロードキャスト/マルチキャストにも使える
- UDPの代表: DNS、DHCP、TFTP、SNMP、Syslog、音声・動画

## まとめ
- OSI参照モデルは通信を**7階層**に分けた整理モデル
- カプセル化は各層で**ヘッダを追加して包む**仕組み
- 階層化により**独立性・標準化・切り分け**がしやすくなる
- TCP/IPの4層と対応付けて理解すると実務で役立つ
