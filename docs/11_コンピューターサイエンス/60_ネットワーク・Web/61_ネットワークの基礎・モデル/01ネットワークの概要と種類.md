# ネットワークの概要と種類

## ネットワークとは
複数のコンピュータやデバイスをケーブルや電波でつなぎ、データをやり取りできるようにした仕組みです。メール送信、Web閲覧、動画視聴など、現代のIT活動はすべてネットワーク上で動いています。

## 基本モデル
```
[端末A] ──── ネットワーク ──── [端末B]
 送信 →                       ← 受信
```
送信側と受信側がルール（プロトコル）に従ってデータを送受信します。

## ネットワークの種類（規模による分類）

### LAN（Local Area Network）
- 家庭、オフィス、学校など**狭い範囲**のネットワーク
- 速度が速く、管理者が自分たちで構築できる
- 例: 自宅のWi-Fi、会社内のイーサネット

### WAN（Wide Area Network）
- 都市や国をまたぐような**広域ネットワーク**
- 通信事業者（キャリア）の回線を使う
- 例: 本社と支社を結ぶ専用線、インターネット全体

### MAN / CAN / PAN
- **MAN**: 都市規模（Metropolitan）
- **CAN**: 大学のキャンパス内
- **PAN**: Bluetoothなど、身の回りの機器同士

## 構成の種類（関係性による分類）

### クライアント・サーバー型
```
[クライアント] → リクエスト → [サーバー]
                ← レスポンス ←
```
役割が明確に分かれている。Webサイトやメールは基本この形式。

### P2P（Peer to Peer）型
各端末が対等にデータをやり取りする。BitTorrent、一部のビデオ会議などで利用。

## 接続方式

### 有線
- **イーサネット（LANケーブル）**: 安定して高速
- **光ファイバー**: 長距離・超高速

### 無線
- **Wi-Fi**: 一般的な無線LAN
- **Bluetooth**: 近距離、低消費電力
- **モバイル通信（4G/5G）**: 屋外でも使える

## インターネットの位置づけ
世界中のネットワーク同士を接続した「ネットワークのネットワーク」です。TCP/IPという共通プロトコルで動いているため、異なるメーカー・OSの機器でも通信できます。

## 基本用語のミニ辞典
- **ノード**: ネットワークに接続されている機器
- **ホスト**: データを送受信する端末
- **帯域**: 単位時間に送れるデータ量（bps）
- **遅延（レイテンシ）**: データが届くまでの時間

## 発展：ネットワークトポロジとクラウド

企業やデータセンターのネットワークの構成（キャンパスの3層構造・スパインリーフなど）と、クラウドのサービスモデルを整理します。

### キャンパスネットワークの3層構造

企業の建物（キャンパス）内のネットワークは、役割ごとに3つの層に分けて設計するのが基本です。

```
                    [Core1]══════[Core2]                 コア層
                     │  ╲        ╱  │                    … 高速転送に専念
                     │    ╲    ╱    │
                     │      ╳       │
                     │    ╱   ╲     │
                    [Dist1]═════[Dist2]                  ディストリビューション層
                     │  ╲        ╱  │                    … 集約・VLAN間ルーティング・
                     │    ╲    ╱    │                       ポリシー適用
                     │      ╳       │
                     │    ╱   ╲     │
                    [Acc1]       [Acc2]                  アクセス層
                    │  │  │      │  │                    … 端末を直接接続
                   PC  AP IP電話 PC  AP
```

| 層（端末に近い順） | 役割 | 典型的な機能 |
| --- | --- | --- |
| ① **アクセス層** | PC、AP、IP電話などの**端末を直接接続** | PoE、ポートセキュリティ、VLANの割り当て、QoSのマーキング |
| ② **ディストリビューション層** | 複数のアクセス層スイッチを**束ねる** | **VLAN間ルーティング**、ポリシー（ACLなど）の適用、ルートの集約、FHRP |
| ③ **コア層** | ディストリビューション層同士をつなぐ**中心** | 大量の通信を**高速に転送することに専念**（複雑な処理はしない） |

各層の機器は**2台ずつ用意して冗長化**し、どこか1か所が故障しても通信を続けられるように設計します。

#### 2層構造（コラプストコア）

小〜中規模のネットワークでは、コア層とディストリビューション層を1つにまとめた**2層構造（コラプストコア：collapsed core）**がよく使われます。機器の台数とコストを減らせます。

```
  コア/ディストリビューション層   [CoreDist1]═══[CoreDist2]
                                    │   ╲       ╱   │
  アクセス層                       [Acc1]   [Acc2]   [Acc3]
```

### スパインリーフ（データセンター）

データセンターでは、サーバ同士の通信（**東西トラフィック**：East-West）が非常に多くなります。3層構造では、離れたサーバ間の通信が多くの機器を経由し、経路によって遅延がばらつきます。そこで使われるのが**スパインリーフ**構造です。

```
  スパイン      [Spine1]                 [Spine2]
               ╱  │   ╲  ╲            ╱  ╱   │   ╲
              ╱   │    ╲   ╲        ╱   ╱    │    ╲
             ╱    │     ╲    ╲    ╱    ╱     │     ╲
  リーフ   [Leaf1]  [Leaf2]   [Leaf3]  [Leaf4]   ← 各リーフは全スパインに接続
             │        │          │       │
           サーバ    サーバ      サーバ   サーバ
```

（図では線が省略されていますが、Leaf1〜Leaf4 のそれぞれが Spine1・Spine2 の両方に接続されます）

ルール:

- サーバ（エンドポイント）は**リーフ**に接続する
- **すべてのリーフがすべてのスパインに接続**する
- **リーフ同士、スパイン同士は接続しない**（リーフ同士の通信は必ずスパインを経由）
- したがって、どのサーバ間の通信も「リーフ → スパイン → リーフ」で、**経由する機器の数が常に同じ**（遅延が予測しやすい）
- 容量が足りなくなったら**スパインやリーフを追加するだけ**で拡張できる（スケールアウト）
- 複数のスパインに等コストで負荷分散できる（ECMP）

Ciscoでは ACI（Application Centric Infrastructure）がスパインリーフを基盤にしたSDNソリューションです。

| トラフィックの種類 | 意味 | 向いている構成 |
| --- | --- | --- |
| 南北（North-South） | データセンター外部（ユーザー・インターネット）とサーバの間 | 従来の3層構造 |
| 東西（East-West） | データセンター内のサーバ同士 | **スパインリーフ** |

### その他のトポロジ

| トポロジ | 特徴 |
| --- | --- |
| **SOHO**（Small Office/Home Office） | 小規模オフィスや家庭。**1台のルータにスイッチ・無線AP・ファイアウォール・DHCPなどの機能がまとめられている**ことが多い |
| WAN | 拠点間を通信事業者の回線（専用線、MPLS、インターネットVPNなど）でつなぐ |
| オンプレミス | 自社の設備にサーバなどを置いて運用する |
| クラウド | 事業者の設備をネットワーク経由で利用する |

### クラウドのサービスモデル

クラウドサービスは「事業者がどこまで管理し、利用者がどこから管理するか」で分類されます。

```
                     オンプレミス   IaaS      PaaS      SaaS
アプリケーション       利用者        利用者    利用者    事業者
データ                 利用者        利用者    利用者    事業者
ミドルウェア/実行環境  利用者        利用者    事業者    事業者
OS                     利用者        利用者    事業者    事業者
仮想化                 利用者        事業者    事業者    事業者
サーバ/ストレージ      利用者        事業者    事業者    事業者
ネットワーク           利用者        事業者    事業者    事業者
```

| 形態 | 借りるもの | 利用者が管理する範囲 | 例 |
| --- | --- | --- | --- |
| オンプレミス | （借りない） | **すべて** | 自社サーバルーム |
| **IaaS** | 仮想マシン・ストレージ・ネットワークなどの**インフラ** | **OSから上** | AWS EC2、Azure Virtual Machines |
| PaaS | OS・実行環境（プラットフォーム）まで | **アプリケーション（とデータ）のみ** | Google App Engine、Azure App Service |
| SaaS | 完成したアプリケーション | **ほぼなし**（設定・データ程度） | Webメール、Microsoft 365、Webex |

管理範囲の大きさ: **オンプレミス（すべて自社）＞ IaaS（OSから上）＞ PaaS（アプリケーションのみ）＞ SaaS（ほぼなし）**

クラウドへの接続方法には、インターネット経由、インターネットVPN、専用線（クラウド事業者の専用接続サービスを含む）などがあります。展開モデル（参考）には、パブリック、プライベート、ハイブリッド、コミュニティがあります。

### ひっかけポイント・よくある誤解

- **3層構造の順番。** 端末に近い順に「アクセス → ディストリビューション → コア」。コアは端末から最も遠い中心。
- **コア層で複雑なポリシー処理をする、は誤り。** ポリシーの適用やVLAN間ルーティングはディストリビューション層。コアは高速転送に専念。
- **スパインリーフで「リーフ同士をつなぐ」「スパイン同士をつなぐ」は誤り。** リーフ同士・スパイン同士は接続しない。
- **スパインリーフと3層構造・コラプストコア・SOHOの混同。** データセンター＝スパインリーフ、キャンパス＝3層構造、小〜中規模キャンパス＝2層（コラプストコア）、家庭・小規模オフィス＝SOHO。
- **IaaS と PaaS の混同。** OSを自分で管理する＝IaaS。OSや実行環境まで事業者が管理し、アプリケーションの開発・実行に専念＝PaaS。完成したアプリをそのまま使う＝SaaS。クラウドを使わない＝オンプレミス。

### 押さえておくポイント

- 3層構造: アクセス（端末接続）→ ディストリビューション（集約・VLAN間ルーティング・ポリシー）→ コア（高速転送）
- コラプストコア＝コア＋ディストリビューションを統合した2層構造
- スパインリーフ: 全リーフ⇔全スパインを接続、リーフ同士/スパイン同士は接続しない、経由機器数が一定、東西トラフィック向き、追加するだけで拡張
- IaaS＝インフラを借り、OSから上を利用者が管理／PaaS＝アプリのみ管理／SaaS＝完成アプリを利用

## まとめ
- ネットワーク = 機器をつないでデータをやり取りする仕組み
- 規模で**LAN / WAN**などに分類される
- 構成で**クライアント・サーバー / P2P**に分かれる
- インターネットは世界規模のネットワークの集合体
