# ネットワークの全体像・通信フローとセキュリティ基礎

## この章の位置づけ
これまで学んできた要素（IP、TCP、DNS、HTTP、TLS、ルーター、プロキシなど）を**1本の流れとして結び付けて**、Webアクセスが裏で何をしているのか全体像を掴みます。あわせて、ネットワーク関連の**セキュリティの基本**も整理します。

## Webアクセスの全体フロー

ブラウザで `https://example.com/blog/post-1` を開いた時に何が起きるか。

```
① URL解析
   スキーム: https / ホスト: example.com / パス: /blog/post-1

② DNS名前解決
   example.com → 203.0.113.5（キャッシュ→リゾルバ→ルート→TLD→権威DNS）

③ TCP接続（3ウェイハンドシェイク）
   クライアント:54321 ⇄ 203.0.113.5:443

④ TLSハンドシェイク
   サーバー証明書検証、共通鍵の共有（ここから暗号化）

⑤ HTTPリクエスト送信
   GET /blog/post-1 HTTP/2
   Host: example.com

⑥ リバースプロキシ/ロードバランサで振り分け

⑦ アプリサーバーがDB等と連携して応答生成

⑧ HTTPレスポンス
   200 OK + HTML

⑨ 関連アセット（CSS, JS, 画像）取得
   HTTP/2多重化、キャッシュ活用

⑩ ブラウザがレンダリング
```

## データが通る機器の旅

```
[PC]
  │ Wi-Fi
  ▼
[家庭用ルーター(NAT)]
  │ 光回線
  ▼
[ISPのネットワーク]
  │
  ▼
[インターネット上の経路(複数ルーター)]
  │
  ▼
[CDNエッジ] → ヒットすれば即レスポンス
  │ ミス
  ▼
[データセンターのロードバランサ]
  │
  ▼
[リバースプロキシ(Nginx)]
  │
  ▼
[Webアプリサーバー] ⇄ [DB, キャッシュ]
```

## 各層で起きていることの一覧

| 層 | 主な処理 |
|---|---|
| アプリ層 | HTTP, TLS終端, Cookie, キャッシュ |
| トランスポート層 | TCP 3ハンド, ウィンドウ制御, 輻輳制御 |
| ネット層 | IPルーティング, NAT変換 |
| データリンク層 | MACアドレス, フレーム転送 |
| 物理層 | 電気/光/電波の信号伝送 |

## セキュリティ基礎

ネットワークセキュリティは「**CIA**」の3本柱で整理されます。
- **Confidentiality（機密性）**: 盗聴されない
- **Integrity（完全性）**: 改ざんされない
- **Availability（可用性）**: 止まらない

## 代表的な脅威と対策

| 脅威 | 何が起きる | 対策 |
|---|---|---|
| 盗聴 | 通信内容が読まれる | HTTPS / VPN |
| 改ざん | データが書き換えられる | TLS / 署名 / ハッシュ検証 |
| なりすまし | 偽サーバー/ユーザー | 証明書 / 認証 / MFA |
| DoS / DDoS | サービス停止 | CDN / WAF / レート制限 |
| 中間者攻撃(MITM) | 経路で傍受・改変 | HTTPS / HSTS / 証明書ピンニング |
| ポートスキャン | 開いているポート調査 | 最小許可 / IDS |
| SQLインジェクション | DBからデータ漏洩 | プレースホルダ / 入力検証 |
| XSS | ブラウザで不正スクリプト | 出力エスケープ / CSP |
| CSRF | 認証済みユーザーを悪用 | SameSite Cookie / CSRFトークン |
| フィッシング | 偽サイトで情報詐取 | ドメイン確認 / MFA / DMARC |
| ブルートフォース | 総当たり攻撃 | パスワードポリシー / ロック / MFA |

## 多層防御（Defense in Depth）
単一の対策に依存せず、**複数層で守る**のが鉄則です。

```
[DDoS対策/CDN] ← 境界で吸収
   │
[ファイアウォール/WAF] ← L3/L7で遮断
   │
[リバースプロキシ/認証ゲートウェイ]
   │
[アプリ層セキュリティ(入力検証・認可)]
   │
[DB/ファイルシステム権限]
   │
[監査ログ・監視]
```

## ゼロトラスト
「社内なら安全」ではなく、**あらゆる通信を検証する**考え方。
- ネットワーク境界に頼らない
- 強力な認証（MFA, デバイス証明書）
- 細かい認可（リソース単位）
- 暗号化（どこでもHTTPS/mTLS）

## 暗号と署名の使い分け

| 目的 | 使う技術 | 例 |
|---|---|---|
| 盗聴防止 | 対称鍵暗号（AES） | HTTPSの本文 |
| 鍵交換・認証 | 公開鍵暗号（RSA, ECDSA） | TLSハンドシェイク |
| 完全性検証 | ハッシュ（SHA-256） | 署名、整合性確認 |
| 認証情報 | 署名付きトークン（JWT） | API認可 |

## 運用で必須のセキュリティ設定

### サーバー側
- OS・ミドルウェアの**定期的なパッチ適用**
- 不要ポート・不要サービスを閉じる
- sshは鍵認証のみ、rootログイン禁止
- ログを集約し、異常を検知（SIEM）

### Web側
- HTTPS強制 + HSTS
- セキュリティヘッダー（CSP, X-Frame-Options, etc.）
- Cookieに HttpOnly / Secure / SameSite
- 認証失敗の回数制限、MFA導入

### アプリ側
- すべての入力を信用しない
- SQLはプレースホルダ、出力はエスケープ
- 機密情報はログに残さない
- 依存ライブラリの脆弱性スキャン

## VPNの位置づけ
離れた拠点や自宅から会社ネットワークに**暗号化トンネル**で接続する仕組み。盗聴防止と、本来アクセスできないリソースへの到達性確保が目的。ゼロトラスト時代には役割が変わりつつある。

## 切り分けの基本フレーム
トラブル時はOSI下層から上位へ順に確認するのが定石です。

```
物理/データリンク   → ケーブル・Wi-Fiは繋がっているか
ネットワーク        → ping でIP疎通
トランスポート      → telnet/nc でポート疎通
アプリ              → curl でHTTP応答
DNS                → dig で名前解決
TLS                → openssl s_client で証明書確認
```

## まとめ
- Webアクセスは **DNS→TCP→TLS→HTTP→DB** と多くの層が連携して動く
- セキュリティは**CIA（機密性・完全性・可用性）**を軸に考える
- 単一の対策ではなく**多層防御**とゼロトラストが基本
- トラブル時は**下の層から順に切り分け**するのが鉄則
