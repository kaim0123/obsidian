# プロトコルの階層と主要プロトコル

## プロトコルとは
ネットワーク上でデータをやり取りする際の**共通ルール**です。言語や方言のように、同じルールに従わないと相手と会話が成立しません。

### 身近な例
- 郵便: 封筒に住所と切手を貼る「ルール」
- 電話: 「もしもし」から始める「ルール」
- ネットワーク: HTTP、TCP、IPなどの技術的な「ルール」

## 階層ごとの代表的なプロトコル

```
┌─────────────────────────────────────────┐
│ アプリケーション層                      │
│ HTTP, HTTPS, SMTP, POP3, IMAP, FTP,     │
│ SSH, DNS, DHCP, Telnet                  │
├─────────────────────────────────────────┤
│ トランスポート層                        │
│ TCP, UDP                                │
├─────────────────────────────────────────┤
│ インターネット層                        │
│ IP (IPv4/IPv6), ICMP, ARP               │
├─────────────────────────────────────────┤
│ ネットワークインターフェース層          │
│ Ethernet, Wi-Fi(IEEE 802.11), PPP       │
└─────────────────────────────────────────┘
```

## アプリケーション層のプロトコル

### Web関連
- **HTTP (80)**: Webページを取得する
- **HTTPS (443)**: 暗号化されたHTTP

### メール関連
- **SMTP (25/587)**: メールを送信する
- **POP3 (110)**: メールをサーバーから取得（ダウンロード型）
- **IMAP (143)**: メールをサーバー上で管理する

### ファイル転送・リモート操作
- **FTP (21)**: ファイル転送（暗号化なし）
- **SFTP / SCP**: SSHを通じた安全なファイル転送
- **SSH (22)**: 安全にリモート接続する

### 名前解決・設定
- **DNS (53)**: ドメイン名をIPアドレスに変換
- **DHCP (67/68)**: IPアドレスを自動割当する

## トランスポート層のプロトコル

### TCP
- 信頼性重視。順序保証・再送あり
- HTTP、SSH、メールなどで使用

### UDP
- 速度重視。軽量で確認なし
- DNS、動画、ゲームなどで使用

## インターネット層のプロトコル

### IP (Internet Protocol)
- 宛先IPアドレスを元に**ルーティング**（経路決定）
- **IPv4**: 約43億個 / **IPv6**: 事実上無限

### ICMP (Internet Control Message Protocol)
- 通信のエラー通知・診断用
- `ping` や `traceroute` コマンドで利用

### ARP (Address Resolution Protocol)
- IPアドレスからMACアドレスを調べる
- 同じLAN内での通信に必須

## ネットワークインターフェース層

### Ethernet
- 有線LANの標準規格
- **MACアドレス**で同じLAN内の機器を識別

### Wi-Fi（IEEE 802.11）
- 無線LANの規格
- SSIDとパスワードで接続

## プロトコルの組み合わせ例

### Webページを開く時
```
HTTP (アプリ) → TCP (トランスポート) → IP (ネット) → Ethernet (物理)
```
さらに事前にDNSで名前解決、HTTPSならTLSで暗号化が加わります。

### メール送信時
```
SMTP → TCP → IP → Ethernet
```

## まとめ
- プロトコルはネットワーク上の**共通ルール**
- 階層ごとに役割の異なるプロトコルが存在
- アプリによって使うプロトコルの組み合わせが変わる
- よく使われるポート番号を覚えておくと実務で役立つ
