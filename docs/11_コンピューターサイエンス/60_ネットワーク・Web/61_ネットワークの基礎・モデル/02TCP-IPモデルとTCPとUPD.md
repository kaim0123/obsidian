# TCP/IPモデルとTCPとUDP

## TCP/IPとは
インターネットで使われる**通信プロトコルの集合**です。データの送受信を階層的に分担して処理することで、異なる機器やOS同士でも通信できるようにしています。

## TCP/IPの4階層モデル

```
┌─────────────────────────────┐
│ アプリケーション層           │ HTTP, DNS, SMTP, FTP
├─────────────────────────────┤
│ トランスポート層             │ TCP, UDP
├─────────────────────────────┤
│ インターネット層             │ IP, ICMP
├─────────────────────────────┤
│ ネットワークインターフェース │ イーサネット, Wi-Fi
└─────────────────────────────┘
```

### 各層の役割
| 層 | 役割 | 例 |
|---|---|---|
| アプリケーション | アプリが利用するデータ形式・手順を決める | HTTPでWebを表示 |
| トランスポート | 信頼性のあるデータ転送や宛先のアプリ識別 | ポート番号で振り分け |
| インターネット | 異なるネットワーク間でデータを運ぶ | IPアドレスでルーティング |
| ネットワークI/F | 物理的にデータを電気信号に変える | LANケーブル、Wi-Fi |

送信側は上から下へ、受信側は下から上へデータを流します。

## TCP（Transmission Control Protocol）

### 特徴
- **信頼性が高い**: 届いたかどうか確認しながら送る
- **順序保証**: データが送った順番通りに届く
- **コネクション型**: 通信前に「握手」をする

### 3ウェイハンドシェイク
```
クライアント              サーバー
    │ ── SYN ─────────→   │  「接続したい」
    │ ← SYN/ACK ────────  │  「OK」
    │ ── ACK ─────────→   │  「了解」
    │    （通信開始）     │
```

### 向いている用途
- Web（HTTP/HTTPS）
- メール（SMTP, IMAP）
- ファイル転送（FTP）

## UDP（User Datagram Protocol）

### 特徴
- **速い・軽い**: 確認なしで送りっぱなし
- **信頼性は低い**: パケット欠落や順序の乱れがある
- **コネクションレス**: 握手なしにいきなり送る

### 向いている用途
- 動画/音声ストリーミング
- オンラインゲーム
- DNSクエリ
- VoIP（IP電話）

## TCPとUDPの比較表

| 項目 | TCP | UDP |
|---|---|---|
| 信頼性 | 高い | 低い |
| 速度 | 遅め | 速い |
| 順序保証 | あり | なし |
| 接続確立 | 3ウェイハンドシェイク | なし |
| ヘッダサイズ | 20バイト以上 | 8バイト |
| 用途 | Web、メール | 動画、ゲーム、DNS |

## 使い分けの考え方
- **データが欠けると困る** → TCP（例: 銀行取引、ファイル転送）
- **多少欠けても速さ優先** → UDP（例: 動画配信、音声通話）

## まとめ
- TCP/IPはインターネットの基盤となる4階層プロトコル
- 各層が責任を分担することで複雑な通信を実現
- **TCP = 正確性重視**、**UDP = 速度重視**
- アプリケーションの特性に合わせて使い分ける
