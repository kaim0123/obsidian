# ネットワークエラーと切り分け

## この章の目的
「**サイトにつながらない / 遅い / 途中で切れる**」といった症状に遭遇したとき、どの層が原因かを**体系的に切り分ける**ための手順とツールを身につけます。

## 切り分けの基本原則

### ① 下位層から順に確認する
OSIの下から上に向かって確認すると、原因を絞り込みやすい。
```
物理 → データリンク → ネットワーク → トランスポート → アプリ
```

### ② 症状を分解する
- **誰が**: 自分だけ？ 全員？ 特定地域？
- **何が**: このサイトだけ？ すべて？
- **いつから**: 今だけ？ さっきまで動いていた？
- **どうなる**: タイムアウト？ 画面真っ白？ エラー画面？

### ③ 変更点を疑う
直前の作業（設定変更、デプロイ、更新）を確認。

## レイヤー別チェックリスト

### 1. 物理/データリンク層
- LANケーブルは繋がっているか
- Wi-Fiに接続できているか（SSID、パスワード）
- ルーターのランプ状態
- 他の端末はつながるか

### 2. ネットワーク層（IP/ルーティング）
```bash
# IP疎通確認
ping 8.8.8.8               # インターネット（ゲートウェイ越え）
ping 192.168.1.1           # 家庭内ルーター
ping example.com           # 名前解決もセットで確認

# ルート確認
traceroute example.com     # Linux/macOS
tracert example.com        # Windows

# IP設定確認
ipconfig                   # Windows
ip a / ifconfig            # Linux/macOS
ip route                   # ルーティングテーブル
```

### 3. トランスポート層（TCP/UDP/ポート）
```bash
# ポートの疎通確認
nc -vz example.com 443
telnet example.com 443

# 自端末の開放ポート
netstat -an
ss -tuln                   # Linux
```

### 4. DNS
```bash
dig example.com            # Aレコード
dig example.com @8.8.8.8   # Googleに直接
nslookup example.com       # Windowsでも
```

### 5. TLS/証明書
```bash
openssl s_client -connect example.com:443 -servername example.com </dev/null
# 有効期限・発行者・チェーンを確認
```

### 6. アプリケーション層（HTTP）
```bash
curl -v https://example.com
curl -I https://example.com     # ヘッダだけ
curl -w "%{time_total}\n" -o /dev/null -s https://example.com  # 時間計測
```

## よくあるエラーと原因

### 「このサイトにアクセスできません」「ERR_CONNECTION_REFUSED」
- サーバー側のサービスが落ちている
- ポートが閉じている（ファイアウォール）
- 間違ったポート/URL

### 「ERR_NAME_NOT_RESOLVED」「Name or service not known」
- DNSが引けない
- タイポ、ドメイン期限切れ

### 「Timeout」「接続がタイムアウトしました」
- サーバーまで届いているがレスポンスが遅すぎる
- 経路上で遮断されている
- ファイアウォール/セキュリティグループ

### 「SSL handshake failed」「NET::ERR_CERT_*」
- 証明書の期限切れ、信頼不能
- ドメイン名不一致
- TLSバージョンの不一致

### 502 Bad Gateway / 504 Gateway Timeout
- プロキシの先のサーバーが応答不能
- バックエンドが遅い

### 503 Service Unavailable
- メンテナンス、過負荷

### 429 Too Many Requests
- レートリミット超過。`Retry-After` を見る

### 403 Forbidden / 401 Unauthorized
- 権限/認証問題。トークン切れ、IPブロックなど

## 症状別トラブルシューティング

### A. 特定サイトだけ繋がらない
```
1. pingは通るか → 通らなければ経路問題
2. dig で正しいIPが返るか → 違うIPなら乗っ取り/DNSキャッシュ
3. 他の端末/ネットワークからはどうか
4. openssl で証明書は有効か
5. curl でHTTPステータスコードを確認
```

### B. すべてのサイトが遅い
```
1. ルーター再起動
2. Wi-Fi → 有線に切替テスト
3. speedtest で帯域測定
4. traceroute で遅延の発生地点特定
5. ISP障害情報を確認
```

### C. 途中で切れる
```
1. 無線強度、干渉
2. プロキシ/ロードバランサのアイドルタイムアウト
3. Keep-Alive 設定
4. パケットロス（mtrで確認）
```

### D. サーバー側で「つながらない」と言われる
```
1. サーバーのsystemctl status
2. netstat でポートLISTEN確認
3. ファイアウォール/セキュリティグループのルール
4. ログ（/var/log/nginx, journalctl）
```

## 便利なツールまとめ

| ツール | 用途 |
|---|---|
| ping | IP疎通 |
| traceroute / tracert / mtr | 経路・遅延 |
| dig / nslookup | DNS |
| nc / telnet | ポート疎通 |
| curl / wget | HTTP |
| openssl s_client | TLS |
| netstat / ss | 接続状況 |
| tcpdump / Wireshark | パケット解析 |
| nmap | ポートスキャン（自分の環境で） |
| DevTools (Network) | ブラウザ側の通信 |

## パケットキャプチャ入門
詳細に追いたい時は**tcpdump**や**Wireshark**でパケットを直接見る。
```bash
# 80/443だけキャプチャ
sudo tcpdump -i any -n 'port 80 or port 443'

# ファイルに保存（Wiresharkで解析）
sudo tcpdump -i any -w capture.pcap 'host example.com'
```

## ログの重要性
原因究明の主役はログ。あらかじめ
- サーバーログ（アクセス/エラー）
- アプリログ（例外、スロークエリ）
- インフラログ（LB、WAF、CDN）
を集約しておくと切り分けが速い。

## フローチャートの例

```
 サイトが見れない
   │
   ├─ DNSが引けない   → digで確認 → DNS変更/修正
   ├─ pingが通らない  → ネットワーク経路問題
   ├─ pingは通るがHTTPがダメ
   │      ├─ ncでポート → 閉じていればFW/サービス停止
   │      ├─ opensslで証明書 → 期限切れ等
   │      └─ curlでステータス → 4xx/5xxに応じて対応
   └─ レスポンスが遅い
          ├─ traceroute → 経路上の遅延
          └─ DevTools → サーバー or フロント
```

## 予防とモニタリング
- ヘルスチェック（/healthz などのエンドポイント）
- 証明書の期限監視
- レイテンシ・エラー率のダッシュボード（Grafana等）
- アラート（PagerDuty, Slack通知）

## 発展：端末のIP設定確認と切り分け

端末に必要なIP設定と、OSごとの確認コマンド、DNSの問題の切り分け方を整理します。

### 端末に必要な4つの設定

端末がネットワークで通信するには、次の4つが正しく設定されている必要があります。

| 設定 | 役割 | 誤っているとどうなるか |
| --- | --- | --- |
| IPアドレス | 自分の住所 | 通信できない、重複でエラー |
| サブネットマスク | どこまでが同じネットワークかの判定 | 同じネットワークの相手を別ネットワークと誤認する（またはその逆） |
| デフォルトゲートウェイ | 別のネットワーク宛ての通信を渡すルータ | **同じネットワーク内とは通信できるが、他のネットワークとは通信できない** |
| DNSサーバ | 名前（www.example.com）をIPアドレスに変換 | **IPアドレスなら通信できるが、名前では通信できない** |

### OSごとの確認コマンド

| OS | IPアドレス・マスク | デフォルトゲートウェイ | DNSサーバ | MACアドレス |
| --- | --- | --- | --- | --- |
| **Windows** | `ipconfig` | `ipconfig` | **`ipconfig /all`** | **`ipconfig /all`** |
| macOS | `ifconfig` | `netstat -rn` | `scutil --dns` など | `ifconfig` |
| Linux | `ip address`（`ip addr`）、古い環境では `ifconfig` | `ip route` | `/etc/resolv.conf`（`resolvectl status`） | `ip link` / `ip address` |
| Cisco IOS | `show ip interface brief` | `show ip route` / `show ip default-gateway`（L2スイッチ） | `show hosts` | `show interfaces` |

Windowsの `ipconfig` は、`/all` を付けないとDNSサーバやMACアドレス（物理アドレス）が表示されません。

### DNSの問題の切り分け

> IPアドレスとデフォルトゲートウェイは正しいが、www.example.com にアクセスできない。WebサーバのIPアドレスを直接指定するとアクセスできる。

**「IPアドレスなら通信できるが、名前では通信できない」はDNSの問題の典型的な症状**です。

推論の流れ:

1. IPアドレスを直接指定して外部のWebサーバに届く → **L1〜L3（ケーブル、IPアドレス、マスク、ゲートウェイ）は正常**
   - ケーブルが抜けていれば、IPアドレス指定でも通信できない
   - ゲートウェイが誤っていれば、外部のサーバには届かない
   - マスクが誤っていれば、IPアドレス指定の通信にも影響が出るはず
2. 名前を使ったときだけ失敗 → **名前解決（DNS）だけが失敗**している
3. 原因: DNSサーバの設定の誤り、またはDNSサーバに到達できない（DNSサーバの停止、UDP/TCP 53 がフィルタされている など）

切り分けの手順（下の層から順に）:

```
C:\> ping 192.168.1.1            ← ①ゲートウェイに届くか（L3、同一ネットワーク）
C:\> ping 203.0.113.80           ← ②外部サーバのIPアドレスに届くか（ルーティング）
C:\> nslookup www.example.com    ← ③名前解決ができるか（DNS）
サーバー:  UnKnown
Address:  192.168.1.10

*** UnKnown が www.example.com を見つけられません: Server failed
                                 ← DNSで失敗している
C:\> ipconfig /all               ← DNSサーバの設定を確認
```

| 症状 | 疑う箇所 |
| --- | --- |
| 何にもつながらない、リンクランプが消えている | ケーブル・NIC（L1） |
| 同じネットワーク内はOK、外部はNG | デフォルトゲートウェイ、ルーティング |
| 一部の同じネットワークの相手とだけ通信できない | サブネットマスク、IPアドレスの重複 |
| IPアドレスならOK、名前だとNG | **DNS** |
| 169.254.x.x が付いている | DHCPサーバから取得できていない |

### ひっかけポイント・よくある誤解

- **`ipconfig` だけでDNSやMACが見られると考える誤り。** Windowsでは `/all` が必要。
- **OSごとのコマンドの混同。** `ip address show` はLinux、`ifconfig` はmacOSや古いLinux（Windowsでは使えない）、`show ip interface brief` はCisco機器。
- **名前解決の失敗をゲートウェイ・ケーブル・マスクの問題と考える誤り。** それらが原因ならIPアドレス指定の通信も失敗する。

### 押さえておくポイント

- Windows＝`ipconfig /all`（DNSサーバ、MACアドレスまで表示）、macOS＝`ifconfig`、Linux＝`ip address`／`ip route`
- 端末の確認は「IPアドレス・マスク・ゲートウェイ・DNS」の4点
- 「IPならOK、名前だとNG」→ DNS
- 切り分けは下の層から: ping（IP到達性）→ nslookup（名前解決）

## まとめ
- ネットワークのトラブルは**下位層から順に切り分ける**
- 基本ツール `ping / dig / traceroute / nc / openssl / curl` を使いこなす
- エラーメッセージやステータスコードが**最大のヒント**
- ログと監視で**事前に気づく仕組み**を作るのが実務の鍵

この章でネットワーク編は終わりです。**DNS→TCP→TLS→HTTP** の全体像を押さえたうえで、実際に手を動かして通信を観察してみるのが上達の近道です。
