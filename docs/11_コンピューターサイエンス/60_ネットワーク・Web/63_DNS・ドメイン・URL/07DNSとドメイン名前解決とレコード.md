# DNSとドメイン名前解決とレコード

## DNSとは
**Domain Name System**の略で、人間にわかりやすい「ドメイン名」と、コンピュータが使う「IPアドレス」を**変換する仕組み**です。インターネットの「電話帳」に例えられます。

```
google.com  ⇄  142.250.196.142
（ドメイン名）  （IPアドレス）
```

## ドメイン名の構造

```
www.example.co.jp
│    │       │  │
│    │       │  └─ トップレベルドメイン（TLD）
│    │       └──── セカンドレベルドメイン
│    └──────────── サブドメイン
└───────────────── ホスト名
```

### 右から読むのがポイント
階層構造は右側ほど上位です。末尾に省略されたドット（`.`）がルートを表します。

### 代表的なTLD
- **gTLD**: `.com`, `.org`, `.net`, `.dev`
- **ccTLD**: `.jp`, `.us`, `.uk`（国別）

## 名前解決の流れ（再帰問い合わせ）

```
① [ブラウザ] → [フルサービスリゾルバ]「example.comのIPは?」
② リゾルバ → ルートDNS「知らない、.comに聞いて」
③ リゾルバ → .com DNS「example.comの担当サーバを教えて」
④ リゾルバ → example.comの権威DNS「203.0.113.5」
⑤ リゾルバ → ブラウザ「203.0.113.5です」
```

### 登場人物
- **スタブリゾルバ**: OSやブラウザ側のDNSクライアント
- **フルサービスリゾルバ（キャッシュDNS）**: 問い合わせを代行する（ISPやGoogleの `8.8.8.8` など）
- **ルートDNS / TLD DNS / 権威DNS**: 階層的に情報を管理

## キャッシュとTTL
問い合わせ結果は一定時間**キャッシュ**されます。その有効期限が**TTL (Time To Live)**です。
- TTLが短い: 変更がすぐ反映される / 問い合わせが増える
- TTLが長い: 問い合わせが減る / 変更反映に時間がかかる

DNSレコードを切り替える前はTTLを短くしておくのが定番です。

## 主要なDNSレコード

| レコード | 役割 | 例 |
|---|---|---|
| A | ドメイン → IPv4 | example.com → 203.0.113.5 |
| AAAA | ドメイン → IPv6 | example.com → 2001:db8::1 |
| CNAME | 別名（エイリアス） | www.example.com → example.com |
| MX | メールサーバー指定 | example.com → mail.example.com |
| NS | 権威DNSサーバー | example.com → ns1.example.net |
| TXT | 任意の文字列 | SPF, DKIM, 所有権証明 |
| SOA | ゾーンの管理情報 | 管理者、シリアル番号 |
| PTR | IP → ドメイン（逆引き） | 5.113.0.203.in-addr.arpa |
| SRV | サービス指定 | SIP, Microsoft系など |

### TXTレコードの使い道
- **SPF**: メール送信元の認証
- **DKIM**: メールの電子署名
- **DMARC**: SPF/DKIMの運用ポリシー
- ドメイン所有権の証明（Google Search Consoleなど）

## 確認コマンド

### dig / nslookup
```bash
# Aレコードを引く
dig example.com A

# 特定のDNSサーバーに問い合わせる
dig @8.8.8.8 example.com

# すべてのレコードタイプ
dig example.com ANY

# Windowsでは
nslookup example.com
```

## DNSとセキュリティ

### 主な脅威
- **DNSキャッシュポイズニング**: 偽の情報を注入される
- **DNSスプーフィング**: 応答を偽装される
- **DDoS**: DNSサーバー自体への攻撃

### 対策
- **DNSSEC**: 応答に電子署名を付けて改ざんを防ぐ
- **DoH / DoT**: DNS通信自体をHTTPS/TLSで暗号化

## 身近な例

### ブラウザで `https://example.com` を開くまで
```
1. ブラウザが「example.com」をDNSに問い合わせ
2. IPアドレス 203.0.113.5 を取得
3. 203.0.113.5:443 にTCP/TLS接続
4. HTTPリクエストを送信
5. レスポンスを受けて描画
```

## まとめ
- DNSは**名前をIPに変換する電話帳**
- ドメインは右から階層的に読む
- レコードには **A / AAAA / CNAME / MX / TXT / NS** など種類がある
- キャッシュとTTLで効率化、DNSSECで改ざん対策
