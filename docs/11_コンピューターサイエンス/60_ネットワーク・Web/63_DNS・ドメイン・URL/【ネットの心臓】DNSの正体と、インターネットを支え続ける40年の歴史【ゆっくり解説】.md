## 詳しい要約

2021 年秋、Facebook・Instagram・WhatsApp が一斉に約 6 時間ダウンした事件を入口に、インターネットの「電話帳」である **DNS（Domain Name System）** の正体と、誕生から約 40 年の歴史を解説する動画。原因はハッキングでもサーバー爆発でもなく、**名前を番号へ変換する仕組み（とその到達経路）が世界から一時的に消えた** ことだった。本動画は、DNS 以前の単一ファイル管理、1983 年ポール・モカペトリスによる分散・階層設計、名前解決の仕組み、ルート権限をめぐるガバナンス危機、カミンスキー攻撃、Dyn・Facebook の大規模障害、そして日常で使えるパブリック DNS までを一気に辿る。核心メッセージは **「普段は空気だが、止まった瞬間その上のすべてが道連れになる」**——良い設計は長く持ち、見えない土台ほど倒れたときの衝撃が大きい、ということ。

### テーマと問い

- 人間は **YouTube・Google** など名前でサイトを覚えるが、機械が使うのは **IP アドレス**（数字の住所）だけ。
- DNS は名前と番号を対応づけて変換する仕組み——いわば **インターネットの電話帳**。Web・メール・アプリ起動のたびに裏で動く。
- 変換が止まると、サーバーは生きていても **住所が引けず誰もたどり着けない**。Facebook が消えた日の正体がこれ。
- 動画の問い：**なぜたった一つの仕組みがネット全体を麻痺させる力を持つのか**。そして 40 年、危機をどう乗り越えてきたのか。

### 第 1 章——DNS とは何か（名前解決とレコード）

| 概念 | 説明 |
|------|------|
| **名前解決（レゾリューション）** | ドメイン名を機械が分かる番号へ翻訳する。DNS の第一の仕事 |
| **A レコード** | IPv4 の番号 |
| **AAAA レコード** | IPv6 の番号 |
| **MX レコード** | メールの宛て先 |
| **CNAME** | ある名前を別の名前へ転送 |
| **TXT レコード** | 自由な情報（送信者認証・ドメイン所有者確認など） |

- 1 ページを開くだけで、広告・画像・外部部品まで含め **何十回も** 変換が裏で起きることがある。
- DNS は単なる番号案内を超え、**その名前にまつわる道しるべの集合体**。乗っ取られたり止まると、接続だけでなくメールや本人確認まで崩れる恐れがある。

### 第 2 章——DNS 以前（HOSTS.TXT と単一障害）

1970 年代の ARPANET では、全ホストの名前と番号の対応を **世界にたった 1 つのテキストファイル（HOSTS.TXT）** で管理していた。

- 更新は **SRI** の **エリザベス・ファインラー** らのチームが手作業。更新版を世界中のホストがダウンロードしてコピーする方式。
- 台数が数百のうちは回ったが、増えるほどファイルが膨らみ、更新が追いつかず、配布だけで回線がパンクしかけた。
- 名前のかぶりも人手で裁定が必要。管理組織が倒れれば新規登録も更新も全部止まる——典型的な **単一障害点（SPOF）**。
- ファインラーたちは運用の現場から、所属・種類で区切る **ドメインにつながる命名方針** にも深く関与。設計は後のモカペトリスやポステル、運用と命名はファインラーたち、という分担が生まれる。

### 第 3 章——1983 年、分散と階層への転換

| 年・文書 | 内容 |
|----------|------|
| **1983** | 南カリフォルニア大学の **ポール・モカペトリス** が DNS の設計を提案 |
| **RFC 882 / 883** | その設計を記した文書 |

発想の転換は明確だった。**全部を 1 箇所で管理しようとするから破綻するなら、管理を世界中に分けて任せる**。

- **分散**：`.com` の担当、`.jp` の担当……各自が自分の範囲だけ責任を持つ。
- **階層（ツリー）**：根から枝・葉へ降りていく。`.com` の下で各社が自分のサーバー名を自分で登録。中央は 1 行ずつ書き足す必要がない。
- **委任（デリゲーション）**：上の階層が下に管理を任せる。責任のバトンを下へ渡していく。
- TLD は 2 系統——**gTLD**（`.com`・`.org` など分野別）と **ccTLD**（`.jp`・`.uk` など国別）。
- 当時はまだ数百台だが、無数の機械がつながる前提で **最初から無限に拡張できる形** を選んだ。人手の住所録係を、機械同士が勝手に名前を引き合える仕組みで置き換えた。だから 40 年持った。

### 第 4 章——名前解決の仕組み（リゾルバ・キャッシュ・エニーキャスト）

利用者が名前を入れると、まず **フルサービスリゾルバ（再帰問い合わせ）**——プロバイダー等が用意する代理人——が動く。

| 段階 | 役割 |
|------|------|
| **ルートサーバー** | 世界の住所録の入り口。番号自体は知らないが「`.com` ならあっち」と案内 |
| **TLD サーバー** | その会社の最終的な権威サーバーはここだと教える |
| **権威サーバー** | 本物の番号を返す |

- 利用者側は代理人に丸投げ（**再帰**）。代理人はルート → TLD → 権威と自分で 1 段ずつ聞く（**反復**）。
- **キャッシュ**：一度引いた番号をしばらく手元に覚える。同じ名前は辿らず即答。覚えておく時間を **TTL（生存時間）** と呼び、サイト側が指定する。
- 「ルートサーバーは 13 個」は誤解。住所としては **13 系統** だが、各系統が **エニーキャスト** で世界中に同じ顔のコピーをばらまいている。同じ IP を名乗って広告し、問い合わせはネットワーク的に最寄りの 1 台へ自動で届く。
- 通信は普段 **UDP・53 番**（速さ優先・1 往復）。答えが大きすぎるときだけ **TCP** に切替。存在しない名前の空振り結果も覚え、無駄な問い合わせを防ぐ。
- 体感：初めて開くサイトが一瞬もたつくのは名前解決。2 度目が早いのはキャッシュ。

### 第 5 章——ガバナンスの危機（ポステルと ICANN）

技術としての DNS は分散していたが、**ルートを誰が握るか** は長い間ほぼ 1 人に委ねられていた。

- **ジョン・ポステル**——番号やドメインの割り当てを一手に引き受け、「神に最も近い男」と呼ばれた人物。
- **1998 年 1 月 28 日**：当時 13 あったルートサーバーの運用者にメールを送り、**8 つの参照先を自分の大学のマシンへ切り替え**させた。事実上、インターネットの根を 1 人で掌握して見せた。本人は「いざという時のテスト」と説明したが、アメリカ政府は強く反発し即時の現状回復を迫った。
- 数日で元に戻したが、問いが残った——**世界のインフラの根が 1 人の善意と判断に委ねられていてよいのか**。
- この一件などが引きとなり、根の管理を国際的な組織へ移す流れが生まれる——**ICANN** の設立。皮肉にもポステル自身はその技術トップにつく予定だったが、同年秋、心臓の手術中に亡くなる。
- 教訓：**技術の分散と権力の分散は別問題**。後者は人間と政治の問題として戦わなければならなかった。

### 第 6 章——技術の危機（カミンスキー攻撃と DNSSEC）

| 年 | 出来事 |
|----|--------|
| **2008** | セキュリティ研究者 **ダン・カミンスキー** が DNS の致命的な穴を発見 |
| **2008 年 7 月 8 日** | 世界中で一斉にパッチ公開 |

- **キャッシュポイズニング**：攻撃者が本物の権威サーバーより先に偽の答えをリゾルバに食わせて覚え込ませる。
- 当時の弱点：問い合わせの **16 ビット識別番号** が一致すれば相手を本物と信じてしまった。当てられる範囲が狭い。
- カミンスキーの手口：存在しない名前を次々に問い合わせ、当たるまで偽答えを打ち込む。正しい答えが入るとしばらく上書きできないが、毎回新しい名前ならキャッシュは空のまま勝負を繰り返せる。当たりの瞬間、ドメイン全体の権威サーバー情報まで忍び込ませると、**そのドメインが丸ごと攻撃者の手に落ちる**。
- いきなり公表せず、Microsoft や主要 DNS ソフト開発者を秘密裏に集め、協調パッチを準備。公表前に詳細が一部漏れ、攻撃者と管理者の時間競争になったが、大きな被害が広がる前に大半がパッチを当てきった。
- 応急処置の肝：識別番号に加え **ソースポートもランダム化** し、当てる組み合わせを桁違いに増やす。根本治療は答えに電子署名を付ける **DNSSEC**——だが全員が足並みを揃えないと信頼の鎖が切れ、普及は今も途上。現実は **DNSSEC とランダム化の多重防御**。

### 第 7 章——現実に世界が止まった日

#### 2016 年 Dyn 攻撃

- Twitter・Netflix・Spotify・Reddit などが米東海岸で一斉につながらなくなった。
- 狙われたのは大手 DNS 事業者 **Dyn**。多くの有名サービスの名前解決を引き受けていたところへ、史上最大級の **DDoS**。
- 攻撃部隊の正体は、乗っ取られた監視カメラ・家庭用ルーター・ウェブカメラなど——**Mirai** ボットネット。弱いパスワードのまま放置された機器が軍隊のように殺到した。
- 教訓：多くの企業が DNS を **たった一社に任せきり** だった。今は複数事業者の併用が広がる。

#### 2021 年 Facebook 障害

- 設定変更のミスで、自分の居場所を世界に知らせる **BGP 経路広告** ごと丸ごと引っ込めてしまった。
- DNS サーバー自体は壊れていない。だがそこへ向かう道が消えただけで、世界中から名前が引けなくなった。社内の人間まで建物に入れなくなり、インフラが連鎖して倒れた。
- 外からの攻撃でも、たった一つの設定ミスでも、**名前が引けなくなった瞬間、巨人ですら沈黙する**。

### 第 8 章——今日から使える話（パブリック DNS・プライバシー・検閲）

- ネットが急に重い・つながらないとき、DNS を変えると治ることがある。例：**Google の 8.8.8.8**、**Cloudflare の 1.1.1.1**——プロバイダーの代理人を、別の優秀な代理人に変える操作。
- 背景：かつて一部プロバイダーは存在しない名前を引くとエラーではなく自社広告ページへ誘導していた。その反発として、余計なことをしない中立な DNS という旗印でパブリック DNS が広まった。
- 皮肉：みんなが巨大テックの DNS に集まれば、分散させた名前解決がまた一握りに集中する——**再中央集権化**。
- 最初の数秒真っ白で固まる体感は、多くの場合 DNS の応答待ち。ただし原因は常に DNS とは限らない。
- **プライバシー**：どの DNS を使うかは、誰に閲覧履歴を預けるかの問題。近年は問い合わせ自体を暗号化する動き（**DNS over HTTPS** など）が進む。
- DNS は検閲・フィルタにも使われる。学校や会社が「そんな住所はありません」と嘘の答えを返しアクセスをブロックする。逆に信頼できる DNS に変えると急に見られるようになるのもこのため。変える先は信頼できるところに限る——怪しい DNS は汚染の温床になる。

### 現在地とまとめ

- 今この瞬間も、Web・メール・アプリ・動画・ゲームのほぼ全ての通信が、最初の一歩で DNS を踏む。役割は住所変換にとどまらず、メール送信者認証・証明書発行制御・ドメイン所有確認などへ広がっている。
- 規模は桁外れ——世界では毎日膨大な問い合わせが飛び、平均すればミリ秒単位で捌かれる、人類屈指の巨大分散システム。うまくいっている限り完全に透明で、存在に気づくのは壊れて世界が止まったときだけ。
- 本質は **1983 年から変わらない**——一局集中をやめ、世界中で分担し、覚えて辿る。この単純で強い設計が 40 年間インターネットを支え続けている。
- 次にネットが急につながらなくなったら：**サーバーが死んだのではなく、電話帳が一瞬迷子になっただけかもしれない**。
