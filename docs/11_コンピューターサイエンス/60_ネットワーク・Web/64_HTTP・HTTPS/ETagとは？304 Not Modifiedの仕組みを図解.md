## 詳しい要約

**テーマ：ETag と 304 Not Modified による条件付きリクエスト**

ETag は、ブラウザのキャッシュが前回と同じデータかどうかを確かめるための識別値。変わったかどうかだけを先に聞き、同じなら 304 で本文を送らずに済ませることで通信を軽くする。

---

### 基本の流れ

1. 最初に画像を取得すると、サーバーは画像と一緒に **ETag** を返す。ブラウザはデータと ETag を保存する。
2. 次に同じ画像を開くとき、ブラウザは **`If-None-Match`** に前回の ETag を付けて問い合わせる。
3. サーバーは今の中身の ETag と比べる。
   - 同じなら **304 Not Modified**。本文は返さず、ブラウザは手元のデータを使う（例: 1.2MB の画像が数百バイトのやり取りで済む）。
   - 変わっていれば **200** と新しいデータ・新しい ETag を返す。
- ETag がなければ、同じ画像でも開くたびに丸ごと受け取ることになる。

### ETag は誰がどう作るか

- 作り方は決まっておらず、**中身のハッシュや更新情報からサーバーが決める**。
- 圧縮や CDN を挟むと、同じ中身でも ETag が変わることがある。

### 弱い ETag

- 先頭に **`W/`** が付くのが**弱い ETag**。バイト単位で違っても、中身が同じなら一致とみなす。
- キャッシュの確認には使えるが、**`If-Range` による部分取得の検証には使えない**。

### まとめ

- ETag は「前と同じか」を確かめる印。
- `If-None-Match` で聞き、同じなら 304 で本文を省略できる。
- 弱い ETag は意味的な一致を表し、部分取得の検証には使えない。
