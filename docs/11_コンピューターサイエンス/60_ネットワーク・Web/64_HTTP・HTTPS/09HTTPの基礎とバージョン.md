# HTTPの基礎とバージョン

## HTTPとは
**HyperText Transfer Protocol**の略で、Webブラウザとサーバーがやり取りする際の**通信ルール**です。Webページ、画像、API呼び出しなど、私たちがブラウザで見るほぼすべてはHTTPで動いています。

## 基本的な特徴

### 1. リクエスト / レスポンス型
```
[クライアント] ── リクエスト ──→ [サーバー]
                ←── レスポンス ──
```
クライアントが要求し、サーバーが応答する1対1のやり取りです。

### 2. ステートレス
サーバーは**前回の通信を覚えていない**。1回のやり取りが独立しています。状態管理は CookieやセッションID、トークンで別途行います。

### 3. テキストベース（HTTP/1.x）
人間が読める文字列で構成されています（HTTP/2以降はバイナリ）。

## HTTPメッセージの基本構造

### リクエスト例
```
GET /users/42 HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: application/json
```

### レスポンス例
```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 42

{"id": 42, "name": "Alice"}
```

### 構成要素
- **スタートライン**: メソッド+パス+バージョン / バージョン+ステータス
- **ヘッダ**: 付加情報（Host、Content-Typeなど）
- **空行**: ヘッダとボディの区切り
- **ボディ**: 送受信するデータ本体

## HTTPのバージョン比較

| バージョン | 年 | 主な特徴 |
|---|---|---|
| HTTP/0.9 | 1991 | GETのみ、HTML返すだけ |
| HTTP/1.0 | 1996 | ヘッダ追加、ステータスコード導入 |
| HTTP/1.1 | 1997 | 持続接続、Hostヘッダ、チャンク転送 |
| HTTP/2 | 2015 | バイナリ、多重化、ヘッダ圧縮 |
| HTTP/3 | 2022 | UDP+QUICベース、TCPの欠点を解消 |

## HTTP/1.1の特徴

### Keep-Alive（持続接続）
1つのTCP接続で複数のリクエスト/レスポンスをやり取り可能。接続確立のコストが減ります。

### パイプライン（実質不採用）
リクエストをまとめて送れるが、順序保証の問題で実用上はあまり使われません。

### Hostヘッダ
同じIPで複数ドメインを運用（バーチャルホスト）できるようになりました。

### 課題
- **Head-of-Lineブロッキング**: 1つのレスポンスが詰まると後続も待たされる
- ヘッダが毎回送られる
- 複数リクエストの効率が悪い

## HTTP/2の進化

### バイナリフレーミング
テキストでなくバイナリで送信。パースが高速・正確に。

### ストリーム多重化
1本のTCP接続で**複数のリクエストを並行**して処理できます。
```
1本のTCP接続上
  Stream 1: リクエストA ←→ レスポンスA
  Stream 3: リクエストB ←→ レスポンスB
  Stream 5: ...
```

### ヘッダ圧縮（HPACK）
繰り返されるヘッダを圧縮して転送量を削減。

### サーバープッシュ
クライアントの要求前にリソースを先行送信（実際はあまり使われなくなった）。

## HTTP/3の進化

### QUICの採用
TCPではなく**UDP上で動く独自プロトコル（QUIC）**を使用。
- TCPの3ウェイハンドシェイクが不要
- TLSハンドシェイクも統合し、**接続確立が高速**
- パケットロスがあってもストリームごとに独立（HoLブロッキング解消）

### 接続マイグレーション
Wi-Fi → モバイル回線などネットワークが切り替わっても接続を維持しやすい。

## ステートレス性と状態管理

### HTTPが覚えてくれないので…
- **Cookie**: ブラウザが保存して毎回送る
- **セッションID**: サーバー側の状態キー
- **トークン（JWTなど）**: 認可情報を持ち運ぶ
- **LocalStorage / SessionStorage**: クライアント側で永続保存

## よく使うHTTPコマンド

```bash
# curlでGET
curl https://example.com

# ヘッダ付きで
curl -H "Accept: application/json" https://example.com/api

# POSTリクエスト
curl -X POST https://example.com/api -d '{"name":"Alice"}' -H "Content-Type: application/json"

# バージョン指定
curl --http2 https://example.com
curl --http3 https://example.com
```

## まとめ
- HTTPはWebの通信ルール。**リクエスト/レスポンス型**で**ステートレス**
- バージョンは **1.1 → 2 → 3** と進化してきた
- **HTTP/2 = 多重化**、**HTTP/3 = QUIC/UDP**で高速化
- ステートレスなため Cookie やトークンで状態管理
