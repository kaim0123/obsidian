## 詳しい要約

**テーマ：HTTP ステータスコードを「サーバーが返す処理結果の番号」として整理する**

面接で「200番台・400番台・500番台は何を表すか」「404 は何か」と聞かれたのをきっかけに書かれた Zenn の記事。ステータスコードは百の位で意味が分かれ、特に **200番台＝成功、400番台＝クライアント側の問題、500番台＝サーバー側の問題** という責任の切り分けが重要だと、Next.js の API コード例とレストランのたとえで解説する。

---

### ステータスコードとは

- クライアント（ブラウザやフロントエンド）のリクエストに対し、サーバーが返す**結果番号**。`fetch` のレスポンスの `res.status` で取得できる。
- レストランにたとえると店員の返事：200「料理できました」、400「注文内容がおかしいです」、404「そのメニューはありません」、500「厨房でトラブルが起きました」。

### 全体像

| 番号帯 | 意味 |
|---|---|
| 100番台 | 情報（処理を続けて） |
| 200番台 | 成功 |
| 300番台 | リダイレクト（別の場所を見て） |
| 400番台 | クライアントエラー |
| 500番台 | サーバーエラー |

### 200番台：成功

- **200 OK**：正常に処理できた（データ取得・更新の成功）。
- **201 Created**：新規作成に成功。
- **204 No Content**：成功したが返す内容がない（削除成功など）。
- `res.ok` は 200〜299 で `true` になるので、201・204 も成功扱い。全部 200 でも動くが、意味に合わせて返すと API が読みやすくなる。

### 400番台：クライアント側のエラー

- サーバーは動いているが、リクエストの内容やアクセス先に問題がある状態（パラメータ不足、形式誤り、未ログイン、権限なし、存在しない URL など）。
- **400 Bad Request**：必須の `name` が空など、送られたデータがルールを満たさない（フォームのバリデーションエラーに近い）。
- **404 Not Found**：リクエストされたリソースが見つからない。ページがないだけでなく、API で指定したユーザー・記事・企業（例 `/companies/999999`）が存在しない場合にも使う。
- **401 Unauthorized**：名前に反して実際は「**認証されていない**」（未ログイン）。
- **403 Forbidden**：ログイン済みだが**権限がない**（管理者でないユーザーが管理画面へアクセス）。
- 覚え方：401「あなた誰ですか」、403「あなたなのは分かったけど入れません」、404「その場所・データが見つかりません」。

### 500番台：サーバー側のエラー

- **500 Internal Server Error**：リクエストは届いたがサーバー内部で処理に失敗（DB 接続失敗、コードの例外、外部 API の失敗、想定外のバグ）。try/catch で例外を捕まえて 500 を返す例を掲載。
- 400番台との違いは**責任の場所**（リクエスト側かサーバー側か）。

### フロントエンドでの扱い

- ステータスコードで表示を分ける。404 なら「指定された企業は見つかりませんでした」、500 なら「時間をおいてもう一度お試しください」のように、同じエラーでもユーザーへの説明が変わる。

### まとめ（面接での答え方）

- 「ステータスコードはサーバーがリクエスト結果を表すために返す番号。200番台は成功、400番台はクライアント側のリクエストに問題があるエラー、500番台はサーバー側で処理に失敗したエラー。404 は Not Found で、ページやリソースが見つからないこと」。
- 具体例として「存在しない企業 ID なら 404、DB 接続失敗なら 500」まで言えると伝わりやすい。
- API を書くときは、成功→200番台、リクエスト側の問題→400番台、サーバー側の問題→500番台という切り分けを意識する。

## はじめに

こんにちは、YSです。  
今回は **HTTPステータスコード** について整理します。

きっかけは、面接でこんな感じの質問をされたことです。

> 200番台、400番台、500番台はそれぞれ何を表していますか？  
> 404 は何を意味しますか？

普段 Next.js や API を触っていると、 `404` や `500` という数字はよく見ます。  
ただ、いざ面接で聞かれると、

- 200 は成功
- 404 はページがない
- 500 はサーバーエラー

くらいは出てきても、400番台と500番台の違いをきれいに説明するのは意外と難しいです。

この記事では、HTTPステータスコードを **「サーバーから返ってくる処理結果の番号」** として整理してみます。

---

## HTTPステータスコードとは

HTTPステータスコードは、クライアントからのリクエストに対して、サーバーが返す **結果番号** です。

たとえば、ブラウザやフロントエンドから API にリクエストを送ります。

```
const res = await fetch("/api/companies");
```

このとき、サーバーはレスポンスの中で、

```
res.status
```

としてステータスコードを返します。

```
const res = await fetch("/api/companies");

console.log(res.status); // 200, 404, 500 など
```

つまり HTTPステータスコードは、

> そのリクエストがどうなったのかを、サーバーが数字で教えてくれる仕組み

です。

レストランで例えるなら、注文したあとに店員さんが返してくる返事に近いです。

- 200: 料理できました
- 400: 注文内容がおかしいです
- 404: そのメニューはありません
- 500: 厨房側でトラブルが起きました

数字だけ見ると無機質ですが、要するに **リクエストに対する返答の種類** です。

---

## ざっくり全体像

HTTPステータスコードは、百の位で大きな意味が分かれます。

| 番号帯 | 意味 | ざっくり |
| --- | --- | --- |
| 100番台 | 情報 | 処理を続けてください |
| 200番台 | 成功 | リクエストは成功しました |
| 300番台 | リダイレクト | 別の場所を見に行ってください |
| 400番台 | クライアントエラー | リクエスト側に問題があります |
| 500番台 | サーバーエラー | サーバー側に問題があります |

面接でまず押さえるなら、特に大事なのはこの3つです。

- **200番台**: 成功
- **400番台**: クライアント側のエラー
- **500番台**: サーバー側のエラー

この分類が分かっていれば、個別の番号もかなり理解しやすくなります。

---

## 200番台: 成功

200番台は、リクエストが成功したことを表します。

一番よく見るのが `200 OK` です。

```
return Response.json(
  { message: "取得に成功しました" },
  { status: 200 },
);
```

`200` は、

> リクエストを受け取り、正常に処理できました

という意味です。

APIでデータ取得に成功したときなどによく使われます。

```
const res = await fetch("/api/companies");

if (res.ok) {
  const data = await res.json();
  console.log(data);
}
```

`res.ok` は、ステータスコードが 200〜299 のとき `true` になります。  
つまり `200` だけでなく、201 や 204 なども成功扱いです。

---

## 201 と 204 もよく見る

200番台の中で、個人的によく見るのはこのあたりです。

| ステータスコード | 意味 | よくある場面 |
| --- | --- | --- |
| 200 OK | 成功 | データ取得・更新成功 |
| 201 Created | 作成成功 | 新規作成に成功 |
| 204 No Content | 成功したが返す内容はない | 削除成功など |

たとえば、企業情報を新規作成するAPIなら `201` が自然です。

```
return Response.json(
  { id: "company_1", name: "Example Inc." },
  { status: 201 },
);
```

削除APIで、削除できたけど返すデータがない場合は `204` が使われることがあります。

```
return new Response(null, { status: 204 });
```

最初は全部 `200` でも動きます。  
ただ、処理の意味に合わせてステータスコードを返せると、APIとして少し読みやすくなります。

---

## 400番台: クライアント側のエラー

400番台は、クライアント側のリクエストに問題があるときに返ります。

ここでいうクライアントは、ブラウザやフロントエンド、APIを叩く側です。

たとえば、

- 必要なパラメータが足りない
- 入力形式が間違っている
- ログインしていない
- 権限がない
- 存在しないURLにアクセスした

といったケースです。

ざっくり言うと、

> サーバーは動いているけど、リクエストの内容やアクセス先に問題がある

という状態です。

---

## 400 Bad Request: リクエスト内容がおかしい

`400 Bad Request` は、リクエストの内容が不正なときに返ります。

たとえば、企業作成APIで `name` が必須なのに空だった場合。

```
export async function POST(req: Request) {
  const body = await req.json();

  if (!body.name) {
    return Response.json(
      { error: "企業名は必須です" },
      { status: 400 },
    );
  }

  return Response.json(
    { id: "company_1", name: body.name },
    { status: 201 },
  );
}
```

これはサーバーが壊れているわけではありません。  
「送られてきたデータがルールを満たしていない」ので、400番台になります。

フォームのバリデーションエラーに近い感覚です。

---

## 404 Not Found: 見つからない

面接で特に聞かれた `404` です。

`404 Not Found` は、

> リクエストされたリソースが見つからない

という意味です。

一番分かりやすいのは、存在しないページにアクセスしたときです。

```
/companies/999999
```

この `999999` の企業が存在しない場合、サーバーは `404` を返します。

```
export async function GET(
  _req: Request,
  { params }: { params: { id: string } },
) {
  const company = await findCompany(params.id);

  if (!company) {
    return Response.json(
      { error: "企業が見つかりません" },
      { status: 404 },
    );
  }

  return Response.json(company, { status: 200 });
}
```

ここで大事なのは、 `404` は単に「ページがない」だけではないことです。

APIでも、

- 指定したユーザーが存在しない
- 指定した記事が存在しない
- 指定した企業が存在しない
- URLのパス自体が存在しない

といったときに `404` になります。

つまり、404 は **「探しに行ったものが見つからなかった」** という返事です。

レストランで言うと、

> そのメニューはありません

です。

注文の文法自体は伝わっている。  
でも、注文されたメニューが存在しない。  
だから `404 Not Found` です。

---

## 401 と 403: 認証と認可

400番台で `404` と一緒に覚えておきたいのが、 `401` と `403` です。

| ステータスコード | 意味 | ざっくり |
| --- | --- | --- |
| 401 Unauthorized | 認証されていない | ログインしていない |
| 403 Forbidden | 権限がない | ログイン済みだがアクセス不可 |

この2つは名前がややこしいです。  
特に `401 Unauthorized` は「認可されていない」と訳したくなりますが、実際の使い方としては **認証されていない** に近いです。

たとえば、ログインしていないユーザーがマイページにアクセスしたら `401` 。

```
if (!session) {
  return Response.json(
    { error: "ログインが必要です" },
    { status: 401 },
  );
}
```

ログインはしているけど、管理者権限がないユーザーが管理画面にアクセスしたら `403` 。

```
if (session.user.role !== "admin") {
  return Response.json(
    { error: "権限がありません" },
    { status: 403 },
  );
}
```

面接で聞かれたら、

- 401: あなた誰ですか
- 403: あなたなのは分かったけど、ここには入れません
- 404: そもそもその場所・データが見つかりません

くらいの理解で答えられるとよさそうです。

---

## 500番台: サーバー側のエラー

500番台は、サーバー側に問題があるときに返ります。

代表は `500 Internal Server Error` です。

これは、

> リクエスト自体は来たが、サーバー内部で処理に失敗した

という意味です。

たとえば、

- DB接続に失敗した
- サーバー側のコードで例外が起きた
- 外部APIの呼び出しに失敗した
- 想定外のバグで処理が落ちた

といったケースです。

```
export async function GET() {
  try {
    const companies = await fetchCompaniesFromDb();
    return Response.json(companies, { status: 200 });
  } catch (error) {
    console.error(error);

    return Response.json(
      { error: "サーバー内部でエラーが発生しました" },
      { status: 500 },
    );
  }
}
```

400番台との違いは、責任の場所です。

| 番号帯 | 問題がある場所 | 例 |
| --- | --- | --- |
| 400番台 | リクエスト側 | 入力ミス、権限なし、存在しないURL |
| 500番台 | サーバー側 | DBエラー、コードの例外、外部API失敗 |

ここは面接でもかなり聞かれやすいポイントだと思います。

---

## フロントエンドではどう扱うか

フロントエンドでは、ステータスコードを見て表示を分けます。

```
const res = await fetch("/api/companies/999999");

if (res.status === 404) {
  throw new Error("企業が見つかりません");
}

if (!res.ok) {
  throw new Error("取得に失敗しました");
}

const company = await res.json();
```

React で書くなら、ざっくりこういう分岐になります。

```
if (status === 404) {
  return <p>指定された企業は見つかりませんでした</p>;
}

if (status === 500) {
  return <p>時間をおいてもう一度お試しください</p>;
}
```

`404` なら「見つからない」とユーザーに伝える。  
`500` なら「サーバー側の問題なので、時間をおいて再試行してほしい」と伝える。

同じエラーでも、ステータスコードによってユーザーへの説明が変わります。

---

## 面接で答えるなら

面接で短く答えるなら、こんな感じで良さそうです。

> HTTPステータスコードは、サーバーがリクエスト結果を表すために返す番号です。  
> 200番台は成功、400番台はクライアント側のリクエストに問題があるエラー、500番台はサーバー側で処理に失敗したエラーです。  
> 404 は Not Found で、指定されたページやリソースが見つからないことを表します。

もう少し具体例を足すなら、

> たとえば、存在しない企業IDで `/companies/999` にアクセスした場合、URLの形式は正しくても対象の企業が存在しないので 404 を返します。  
> 一方、DB接続失敗などサーバー内部の問題なら 500 になります。

まで言えると、かなり伝わりやすいと思います。

---

## 自分なりの理解

ここまでをまとめると、こうです。

| コード | 意味 | 自分なりの例え |
| --- | --- | --- |
| 200 | 成功 | 注文した料理が出てきた |
| 201 | 作成成功 | 新しい注文が登録された |
| 204 | 成功、返す内容なし | 処理は終わったので返事だけ |
| 400 | リクエスト不正 | 注文内容が足りない |
| 401 | 未認証 | まずログインしてください |
| 403 | 権限なし | あなたは入れません |
| 404 | 見つからない | そのメニューはありません |
| 500 | サーバー内部エラー | 厨房側でトラブルが起きた |

特に大事なのは、

- 400番台は **クライアント側**
- 500番台は **サーバー側**
- 404 は **見つからない**

という切り分けです。

---

## おわりに

HTTPステータスコードは、普段なんとなく見ている数字ですが、面接で聞かれると意外と説明力が試されるところでした。

特に `404` は「ページがない」だけでなく、APIで指定したデータが見つからない場合にも使われます。

今後 API を書くときは、

- 成功したなら 200番台
- リクエスト側の問題なら 400番台
- サーバー側の問題なら 500番台

という責任の切り分けを意識して、ステータスコードを選んでいきたいです。
