## 詳しい要約

**テーマ：HTTPS（TLS）は鍵を送らずに同じ鍵を共有する**

ブラウザの鍵マークは通信が暗号化されている印だが、その暗号化に使う鍵は一度も経路を流れていない。TLS のハンドシェイクでは「公開してよい値」だけを交換し、双方が手元の秘密の値と組み合わせて同じ共有秘密にたどり着く。

---

### なぜ鍵を送れないのか

- ブラウザとサーバーは最初、同じ鍵を持っていない
- 鍵をそのまま送ると、同じ経路で鍵ごと盗まれてしまう

### ハンドシェイクでの鍵共有

1. ブラウザが **自分だけの秘密の値** を作り、手元に置いたまま **公開してよい値** だけを送る
2. サーバーも同様に秘密の値を作り、公開してよい値を返す
3. 双方が「受け取った値 ＋ 自分の秘密の値」を組み合わせる。材料は左右で違うのに、**出てくる答え（共有秘密）は同じ**
4. この共有秘密から、両側がそれぞれ暗号化の鍵を作る

- 途中で盗聴している第三者が見るのは交換された 2 つの値だけで、**現実的な時間では同じ秘密にたどり着けない**

### まとめ

- 秘密そのものは一度も経路を流れずに、双方が同じ鍵を持てる
- ただしこの段階では **相手が本物かはまだ確かめていない**。ここまでが HTTPS の入り口
