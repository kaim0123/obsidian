## 詳しい要約

URLを入力してからブラウザにページが表示されるまでの流れを、Twitterのプロフィール画面を例に解説した動画。表面的な「リクエスト → レスポンス」のイメージの裏側にある仕組みを、たとえ話を交えて順に追う。

### この動画を見るメリット

1. **Webブラウザの基礎が分かる** — ページがどう表示されるかの仕組みを理解できる
2. **HTTP通信がWebの土台である** — サイトやアプリ開発の土壌を固める知識になる
3. **IPアドレス・DNSなどの用語が整理できる**
4. **サイトやアプリの動きを頭の中でイメージできる** — バグ調査やパフォーマンス改善の切り分けに役立つ

### 全体の流れ（結論）

1. URLを解析する
2. キャッシュにIPアドレスがないか確認する
3. なければDNSでIPアドレスを取得する
4. IPアドレスでWebサーバーにリクエストする
5. ポート番号を割り当てる
6. HTTPリクエストを送信する
7. ロードバランサでアクセスを調整する
8. HTTPレスポンスを送信する
9. レンダリングする

### 各ステップの要点

#### 1. URLを解析する

URL（Uniform Resource Locator）は「リソース（HTML・CSS・画像などの資産）の場所を一意に決める住所」。次のように分割できる。

| 要素 | 例 | 意味 |
| --- | --- | --- |
| プロトコル | `https` | 通信のルール。`S`はSecure（安全な通信） |
| ドメイン | `twitter.com` | アクセス先の住所名 |
| パス | `/shin_engineer` など | ドメイン内のより詳細な位置 |

#### 2. キャッシュにIPアドレスがないか確認する

ブラウザには一時保存領域（キャッシュ）がある。過去にアクセスしたサイトのIPアドレスが残っていれば、それを再利用する。初めてのページならキャッシュにはない。

**IPアドレス**はサーバーの住所（例: `104.244.x.x`）。住所が分からないとリクエスト（手紙）すら送れない。

#### 3. DNSでIPアドレスを取得する

**DNS（Domain Name System）**は電話帳のような仕組み。ドメイン名とIPアドレスの対応表を持つ。

- 人は覚えやすいドメイン名（`twitter.com`）を使う
- パソコンは数字（IPアドレス）しか理解できない
- その対応をDNSサーバーが管理する
- 世界中の対応表は膨大なため、DNSサーバーは複数存在する（負荷分散）

#### 4〜5. Webサーバーへリクエストし、ポート番号を割り当てる

IPアドレスが分かったら、サーバーへ「プロフィール画面をください」とリクエストできる。

**ポート番号**はマンションの部屋番号のようなもの。プロトコルに応じて自動で割り当てられる。

- HTTPS → **443**
- HTTP → **80**

開発者ツールのネットワークタブで、リモートアドレスに `:443` が付いていることを確認できる。

#### 6. HTTPリクエストを送信する

リクエストには決まったフォーマットがある。

1. **リクエストライン**（例: `GET /path HTTP/2`）
2. **ヘッダー**（Host、User-Agent、Accept など）
3. **空行**（ヘッダーとボディの区切り）
4. **メッセージボディ**（GETでページ取得するだけなら不要。POSTや更新時などに使う）

`curl -v` などで実際のリクエスト内容を確認できる。

#### 7. ロードバランサでアクセスを調整する

大規模サービスではサーバーが複数ある。ロードバランサはコンビニの複数レジのように、リクエストを空いているサーバーへ振り分け、負荷分散する。

#### 8. HTTPレスポンスを送信する

レスポンスにもフォーマットがある。

1. **ステータスライン**（ステータスコードを含む）
2. **ヘッダー**
3. **空行**
4. **メッセージボディ**（HTMLなど）

主なステータスコードの意味:

| コード帯 | 意味 | 例 |
| --- | --- | --- |
| 200番台 | 成功 | 200 OK |
| 300番台 | リダイレクト | — |
| 400番台 | クライアント側の問題 | 404 Not Found（存在しないURLなど） |
| 500番台 | サーバー側の問題 | サーバーダウンなど |

メッセージボディにはHTML（および後続で読み込むCSS・JSへの参照）が含まれる。

#### 9. レンダリングする

レスポンス受信後の表示処理の流れ:

1. **ローディング** — まずHTMLをダウンロード。HTML内の参照に従いCSSなども追加リクエスト
2. **スクリプティング** — JavaScriptを実行（ReactやVueなどもここで動く）
3. **レンダリング** — DOM構築・レイアウトなど（詳細は別動画の範囲）
4. **ペインティング** — 画面に描画

HTMLが最初なのは、CSSやJSの読み込み指示がHTML内に書かれているため。

### HTTP通信とは何か

上記1〜9の流れ全体が、広い意味でのHTTP通信の物語。狭く言えば、クライアントとサーバー間の**リクエストとレスポンスのやり取り**。

**HTTP** = HyperText Transfer Protocol

- **HyperText** … HTMLのようなタグ付き文書
- **Transfer** … 送受信（リクエスト／レスポンス）
- **Protocol** … 決まりごと・ルール

つまり「ハイパーテキストを運ぶための決まりごと」がHTTPであり、Webの基礎となる。
