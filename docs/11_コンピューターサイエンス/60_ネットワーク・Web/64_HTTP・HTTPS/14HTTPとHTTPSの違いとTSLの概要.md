# HTTPとHTTPSの違いとTLSの概要

## HTTPとHTTPSの違い
**HTTPS = HTTP + TLS（暗号化層）**。通信経路が暗号化されるかどうかが最大の違いです。

| 項目 | HTTP | HTTPS |
|---|---|---|
| 暗号化 | なし（平文） | あり |
| ポート | 80 | 443 |
| URLスキーム | `http://` | `https://` |
| 盗聴 | 可能 | 不可 |
| 改ざん | 検出不可 | 検出可能 |
| なりすまし | 防げない | サーバー証明書で防止 |
| 速度 | 軽い | ハンドシェイクで少し重い |
| SEO | 不利 | 優遇 |

現代ではHTTPSが事実上の標準です。HTTPは開発・テストや内部通信など限定用途のみ。

## なぜHTTPはダメなのか

HTTPは誰でも読める平文。Wi-Fiや中継経路で傍受されると
- ログイン情報が漏れる
- セッションIDを盗まれる
- 中身を書き換えられる（広告挿入、マルウェア埋め込み）
- ユーザーになりすまされる

といった脅威に直結します。

## HTTPSが提供する3つの保証

### 1. 機密性（暗号化）
経路で覗かれても読めない。

### 2. 完全性
途中で改ざんされたら気づける。

### 3. 真正性（認証）
相手が本当にそのドメインの持ち主か、証明書で確認できる。

## TLSとは
**Transport Layer Security**。HTTPSの実体を担う暗号化プロトコル。前身はSSL。

```
アプリケーション層   HTTP
      ↓
      ↓ TLS（暗号化）
      ↓
トランスポート層     TCP
```

### SSL / TLSのバージョン
| バージョン | 年 | 状態 |
|---|---|---|
| SSL 2.0 | 1995 | 廃止 |
| SSL 3.0 | 1996 | 廃止 |
| TLS 1.0 | 1999 | 廃止推奨 |
| TLS 1.1 | 2006 | 廃止推奨 |
| TLS 1.2 | 2008 | 現役 |
| TLS 1.3 | 2018 | 最新・推奨 |

現在は **TLS 1.2 / 1.3** のみ使うのが標準。

## TLSハンドシェイクの概要（TLS 1.3）

```
クライアント                       サーバー
    │ ─── ClientHello ───────→      │  対応暗号方式・鍵候補送信
    │ ←── ServerHello, 証明書 ──    │  方式選択・証明書送信
    │     + 鍵共有パラメータ        │
    │ 鍵確定 + Finished             │
    │ ───────────→                  │
    │ ←───────── Finished           │
    │ ====== 暗号化通信開始 ======= │
```

TLS 1.3では**1往復（1-RTT）** で開始可能。過去のセッションを再利用すれば**0-RTT**も可能。

## 暗号の仕組み（ざっくり）

### 公開鍵暗号
- 公開鍵で暗号化、秘密鍵で復号（またはその逆で署名検証）
- 鍵交換・認証に使う

### 共通鍵暗号
- 同じ鍵で暗号化/復号
- 本文の暗号化に使う（高速）

### 両者の使い分け
1. **公開鍵暗号**で安全に共通鍵を交換
2. 以降の通信は**共通鍵暗号**で高速にやり取り

これがTLSのハイブリッド暗号方式です。

## サーバー証明書
サーバーの身元を保証する電子証明書。**認証局（CA）**が署名している。

### 含まれる情報
- ドメイン名（CN/SAN）
- サーバーの公開鍵
- 発行者・有効期限
- CAの電子署名

### 種類
| 種類 | 検証の厳しさ | 用途 |
|---|---|---|
| DV | ドメイン所有のみ | 個人・一般サイト |
| OV | 組織の存在も確認 | 企業サイト |
| EV | 法的実体まで厳格確認 | 金融・大企業 |

## 信頼の連鎖（チェーン）

```
[ルートCA]  ← ブラウザ/OSに組み込み済み
    │ 署名
    ▼
[中間CA]
    │ 署名
    ▼
[サーバー証明書]
```
ブラウザはサーバー証明書の署名をたどってルートCAに到達できれば信頼します。

## HTTPS化によるメリット（実務）
- **SEO**: Googleは検索順位でHTTPSを優遇
- **ブラウザ警告**: HTTPは「保護されていません」と表示される
- **新機能要件**: Service Worker、HTTP/2、位置情報などはHTTPS必須
- **ユーザー信頼**: 鍵アイコンで安心感

## HSTS（HTTPS強制）
一度HTTPSで訪問したら、ブラウザ側で**次回からHTTPを使わない**よう強制する仕組み。
```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

## よくある誤解

### 「HTTPSなら安全」ではない
HTTPSは**経路の安全**を保証するだけ。
- サーバー自体の脆弱性（SQLインジェクションなど）
- フィッシング（似た名前のドメイン）
- クライアント端末のマルウェア

は別問題です。

## まとめ
- **HTTPS = HTTP + TLS**。暗号化・完全性・真正性を保証
- TLSは**公開鍵と共通鍵のハイブリッド**暗号
- **サーバー証明書＋認証局**で「本物のサーバー」を確認
- 現在はHTTPSが事実上の標準、**TLS 1.2/1.3**を使う

次章では、証明書の取得・更新など**HTTPS運用の実務**を学びます。
