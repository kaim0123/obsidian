# 実践的な計算量分析

## 🎯 このページのゴール

- 与えられたコードを見て、**自力で計算量を判定** できるようになる
- ループ・再帰のパターン別の分析方法を知る
- 実務でよくあるアンチパターンと改善策を学ぶ

> 前提: [01_計算量の基礎](01_計算量の基礎.md) / [02_時間計算量](02_時間計算量.md) を読んでいること。

---

## 1. 分析の基本3ステップ

どんなコードでも、次の順で見ていけば計算量がわかります。

### ステップ1️⃣ : 入力サイズを決める
まず「**何が n なのか**」をはっきりさせる。

- 配列 `arr` の長さ？
- 文字列 `s` の長さ？
- 2つある場合は `n` と `m` を分ける

### ステップ2️⃣ : 各部分のコストを数える
ループごとに **何回回るか** を数える。

### ステップ3️⃣ : 一番大きい項を残す
ざっくり **支配的な項** だけを取り出して Big-O で表現。

## 2. ループの分析

### 🔹 単純な1重ループ → O(n)

```python
for i in range(n):
    print(i)        # 定数時間の処理
# O(n)
```

### 🔹 独立した2つのループ → O(n)（足し算）

```python
for i in range(n):      # n回
    ...
for j in range(n):      # n回
    ...
# 合計 2n → O(n)
```

**順番に並んだループは足し算** → 大きい方で決まる。

### 🔹 ネストした2重ループ → O(n²)（掛け算）

```python
for i in range(n):          # n回
    for j in range(n):      # n回
        ...
# n × n = O(n²)
```

**入れ子のループは掛け算**。

### 🔹 内側が nに依存しない → O(n)

```python
for i in range(n):
    for j in range(100):    # 常に100回（定数）
        ...
# n × 100 = O(n)
```

### 🔹 三角ループ → 実は O(n²)

```python
for i in range(n):
    for j in range(i, n):   # i回目はn-i回
        ...
# n + (n-1) + (n-2) + ... + 1 = n(n+1)/2 ≒ n²/2
# → O(n²)
```

定数倍（1/2）は無視するので結局 **O(n²)**。

### 🔹 毎回半分になるループ → O(log n)

```python
i = n
while i > 1:
    i //= 2             # 毎回半分
# log₂ n 回 → O(log n)
```

### 🔹 外がn、内が毎回半分 → O(n log n)

```python
for i in range(n):      # n回
    j = n
    while j > 1:
        j //= 2         # log n回
# n × log n → O(n log n)
```

## 3. 再帰の分析

再帰は **呼び出しツリー** を描くとわかりやすい。

### 🔹 パターンA: 1回の呼び出しで1回呼ぶ → O(n)

```python
def f(n):
    if n == 0:
        return
    f(n - 1)        # 自分を1回だけ呼ぶ
```

呼び出し深さ: n回 → **O(n)**

### 🔹 パターンB: 1回の呼び出しで2回呼ぶ → O(2ⁿ)

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)    # 2回呼ぶ
```

呼び出しツリーが **二分木** になる → 葉の数 ≒ 2ⁿ → **O(2ⁿ)**

### 🔹 パターンC: 毎回半分で分ける → O(log n)

```python
def binary_search(arr, target, left, right):
    if left > right:
        return -1
    mid = (left + right) // 2
    ...
    return binary_search(arr, target, mid+1, right)  # 片側だけ呼ぶ
```

半分にして片方だけ → **O(log n)**

### 🔹 パターンD: 毎回半分で分けて両方処理 → O(n log n)

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])     # 半分を再帰
    right = merge_sort(arr[mid:])    # もう半分も再帰
    return merge(left, right)        # マージにO(n)
```

- 深さ: log n
- 各階層で合計 O(n) の処理
- 全体: **O(n log n)**

### マスター定理（参考）

「分割統治法」の計算量を式で出せる定理。詳細は応用トピックですが、形だけ紹介：

```
T(n) = a·T(n/b) + f(n)
```

- a: 再帰呼び出しの数
- b: 入力を何等分するか
- f(n): 分割・合体のコスト

深く覚える必要はありません。**ツリーを描く方が直感的** です。

## 4. 組み込み関数の計算量を知っておく

自分のコードだけでなく、**使っている関数の計算量** も合算する必要があります。

### Python主要操作の計算量（代表例）

| 操作 | 計算量 | メモ |
|------|-------|------|
| `list[i]` | O(1) | インデックスアクセス |
| `list.append(x)` | 償却O(1) | [04_償却計算量](04_償却計算量.md) |
| `list.insert(0, x)` | **O(n)** | 先頭挿入は全要素ずらす |
| `x in list` | **O(n)** | 線形探索 |
| `list.sort()` | O(n log n) | Timsort |
| `list[a:b]` | O(b-a) | スライスはコピー |
| `dict[k]` | O(1) | ハッシュ（平均） |
| `k in dict` | O(1) | 同上 |
| `k in set` | O(1) | 同上 |
| `str + str` | O(n+m) | 新しい文字列を作る |
| `"".join(list)` | O(n) | 文字列結合の正攻法 |

### よくある落とし穴

```python
for x in arr:
    if x in other_list:     # ← ここが O(m)
        ...
# 全体: O(n × m)

# ↓ セットにすれば O(1) で検索できる
other_set = set(other_list)
for x in arr:
    if x in other_set:      # O(1)
        ...
# 全体: O(n + m)
```

## 5. 実際に分析してみる（例題）

### 例題1: 重複チェック

```python
def has_duplicate(arr):
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] == arr[j]:
                return True
    return False
```

- 外ループ: n回
- 内ループ: 平均 n/2 回
- → **O(n²)**

**改善版**:
```python
def has_duplicate(arr):
    return len(set(arr)) != len(arr)
# O(n)
```

### 例題2: 2つのリストの共通要素を探す

```python
def intersection(a, b):
    result = []
    for x in a:
        if x in b:         # ← O(len(b))
            result.append(x)
    return result
```

- 外ループ: n回
- `in b`: 各回 m回
- → **O(n × m)**

**改善版**:
```python
def intersection(a, b):
    b_set = set(b)         # O(m)
    return [x for x in a if x in b_set]  # O(n)
# O(n + m)
```

### 例題3: 文字列を逆順にする

```python
def reverse(s):
    result = ""
    for c in s:
        result = c + result     # ← 毎回新しい文字列を作る
    return result
```

- ループ: n回
- 各回の文字列連結: **O(n)**（新しい文字列を作るため）
- → **O(n²)**（よくある罠！）

**改善版**:
```python
def reverse(s):
    return s[::-1]          # O(n)
```

## 6. 計算量を減らす常套手段

| テクニック | ビフォー | アフター | 仕組み |
|-----------|---------|---------|--------|
| **ハッシュセット化** | O(n²) | O(n) | 検索をO(1)に |
| **ソート前処理** | O(n²) | O(n log n) | 順序を使って重複を削る |
| **メモ化** | O(2ⁿ) | O(n) | 計算済みをキャッシュ |
| **動的計画法** | O(2ⁿ) | O(n²) | 部分解を順番に埋める |
| **スライディングウィンドウ** | O(n²) | O(n) | 範囲を差分更新 |
| **二分探索** | O(n) | O(log n) | ソート済みデータで |
| **累積和** | O(n)×クエリ数 | O(1)×クエリ数 | 事前計算 |

「O(n²) を見たら O(n log n) か O(n) にできないか疑う」が基本姿勢。

## 7. 実務での判断基準

### いつ最適化すべき？

1. **計測してから** 判断する（早すぎる最適化は諸悪の根源）
2. **nが大きくなる予想** があるか確認する（将来含めて）
3. **ホットパス**（頻繁に呼ばれる場所）を優先

### コードレビューでのチェックポイント

- ネストしたループの内側で **線形検索** していないか？
- ループ内で **文字列連結** していないか？
- **同じ計算を何度もしていない** か？
- 配列の **先頭への挿入** を繰り返していないか？

### ざっくりした目安

| 入力サイズ | 許容される計算量 |
|----------|----------------|
| n ≤ 10 | O(n!) まで |
| n ≤ 20 | O(2ⁿ) まで |
| n ≤ 500 | O(n³) まで |
| n ≤ 5,000 | O(n²) まで |
| n ≤ 10⁶ | O(n log n) まで |
| n ≤ 10⁸ | O(n) まで |
| n > 10⁸ | O(log n) 〜 O(1) |

## 8. 分析のチェックリスト

コードを見て計算量を判定する際の自己確認:

- [ ] `n` が何を指すか明確か？
- [ ] 全ループの回る回数を数えたか？
- [ ] ネストは掛け算、並列は足し算で計算したか？
- [ ] 使っている組み込み関数の計算量を考慮したか？
- [ ] 文字列連結・リスト先頭挿入などの罠を見落としてないか？
- [ ] 再帰は呼び出しツリーの形で考えたか？
- [ ] 支配項だけ残して Big-O にしたか？
- [ ] 空間計算量も必要に応じて見たか？

---

## 9. まとめ

- **ループは足し算と掛け算で分析**、定数倍は無視
- **再帰は呼び出しツリー** で考える
- **組み込み関数の計算量** も必ず考慮する
- **O(n²) を見たらまず改善を疑う**
- ハッシュ・ソート・メモ化は **万能の3大テクニック**
- 最適化は **計測してから**、ホットパスから
