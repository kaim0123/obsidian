# 時間計算量

## 🎯 このページのゴール

- よく出てくる計算量オーダーを **コードの実例と一緒に** イメージできる
- 自分のコードを見て「これは何オーダー？」と言えるようになる
- 計算量によって処理時間がどれくらい違うか体感する

> 前提: [01_計算量の基礎](01_計算量の基礎.md) を読んでから読むと理解が早いです。

---

## 1. 典型的なオーダー 早見表

速い順に並べています。**まずは太字の5つ** を覚えれば実務の8割をカバーできます。

| オーダー | 名前 | 例 | 感覚 |
|---------|------|-----|------|
| **O(1)** | 定数 | 配列の n番目を取る | 一瞬 |
| **O(log n)** | 対数 | 二分探索 | めちゃ速い |
| **O(n)** | 線形 | 配列を1周見る | 普通 |
| **O(n log n)** | 準線形 | 効率的なソート | 普通〜やや重い |
| **O(n²)** | 二乗 | 二重ループ | nが大きいと危険 |
| O(n³) | 三乗 | 三重ループ | 危険 |
| O(2ⁿ) | 指数 | 全探索 | ほぼ使えない |
| O(n!) | 階乗 | 順列全列挙 | 絶望 |

---

## 2. それぞれ詳しく見る

### 🟢 O(1) — 定数時間

**データ量に関係なく、いつも同じ時間で終わる** 処理。

```python
def get_first(arr):
    return arr[0]           # 配列が何万要素でも一瞬

def add(a, b):
    return a + b            # 単純な計算
```

- 配列のインデックスアクセス（`arr[i]`）
- 辞書/ハッシュテーブルの検索（`dict[key]`）※平均
- 数式1回の計算

**理想形**。これで済むなら常にこれを目指す。

---

### 🟢 O(log n) — 対数時間

**データが2倍になっても、手間は1増えるだけ**。超高速。

代表例：**二分探索（binary search）**

```python
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1       # 右半分だけ見る
        else:
            right = mid - 1      # 左半分だけ見る
    return -1
```

**毎回、残りの半分を捨てる** ので、nを何回2で割れば1になるか = `log₂ n` 回で終わる。

| n | log₂ n |
|---|--------|
| 1,000 | 約10 |
| 100万 | 約20 |
| 10億 | 約30 |

10億件でも30回の比較で見つかる！

---

### 🟡 O(n) — 線形時間

**データ量に比例** して時間が増える。最も素直な形。

```python
def sum_all(arr):
    total = 0
    for x in arr:           # n回ループ
        total += x
    return total

def find(arr, target):
    for x in arr:           # 最悪n回
        if x == target:
            return True
    return False
```

- 全要素を1回ずつ見る処理全般
- 文字列の長さチェック、1重ループ

n件を普通に処理するなら、これが最低限必要なコスト。

---

### 🟡 O(n log n) — 準線形時間

**効率的なソート** の計算量。多くの場面で「これ以上速くできない限界」。

代表例：マージソート、クイックソート（平均）、Pythonの `sorted()`

```python
sorted_arr = sorted(arr)    # O(n log n)
```

仕組みのイメージ：
- データを半分に分ける（log n回）
- 各階層で全要素を並べ直す（n回）
- → `n × log n` 回の操作

```
    [8,3,5,1,7,2,6,4]       ← n = 8
    ├─[8,3,5,1] [7,2,6,4]   ← 分割（log n 階層）
    ├─[8,3][5,1] [7,2][6,4]
    └─[8][3][5][1][7][2][6][4]
    各階層で n 個の要素を処理
```

---

### 🔴 O(n²) — 二乗時間

**二重ループ** の典型。nが小さいときは問題ないが、大きくなると一気に重くなる。

```python
def has_duplicate(arr):
    for i in range(len(arr)):           # n回
        for j in range(i + 1, len(arr)): # n回（平均n/2）
            if arr[i] == arr[j]:
                return True
    return False
```

- バブルソート、選択ソート、挿入ソート
- 全ペアを調べる処理
- 行列の要素を全部見る（n×nの場合）

n=10,000 で **1億回** のループ。数秒かかる規模。

**改善のヒント**：
- ハッシュセットを使って O(n) にできる場合が多い
- 上記の重複チェックも `len(set(arr)) != len(arr)` で O(n) に

---

### 🔴 O(2ⁿ) — 指数時間

**データが1増えると、時間が2倍** になる。ほぼ使い物にならない領域。

代表例：素朴なフィボナッチ数列（メモ化なし）

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)   # 1回の呼び出しが2回呼び出す
```

呼び出しツリー：
```
              fib(5)
           /         \
        fib(4)       fib(3)
       /      \      /     \
     fib(3) fib(2) fib(2) fib(1)
     ... （爆発的に増える）
```

| n | 呼び出し回数 |
|---|-----------|
| 10 | 約1,000 |
| 30 | 約10億 |
| 50 | 約1,000兆 ← 実質終わらない |

**メモ化（memoization）** で O(n) にできるのが定番テク。

---

### ⚫ O(n!) — 階乗時間

**全ての順列を試す** ような処理。最悪のオーダー。

```python
from itertools import permutations
for p in permutations(arr):    # n! 通り
    ...
```

- 巡回セールスマン問題の全探索
- n=10 で 約360万通り
- n=15 で 約1兆通り

実務では **絶対に避ける**。近似アルゴリズムや動的計画法で回避する。

---

## 3. オーダーの伸び方を体感する

1秒に1億回の処理ができるとして、n件にかかる時間：

| n | O(log n) | O(n) | O(n log n) | O(n²) | O(2ⁿ) |
|---|---------|------|-----------|-------|-------|
| 10 | 一瞬 | 一瞬 | 一瞬 | 一瞬 | 一瞬 |
| 100 | 一瞬 | 一瞬 | 一瞬 | 一瞬 | 宇宙の年齢 |
| 10,000 | 一瞬 | 一瞬 | 一瞬 | **1秒** | ∞ |
| 1,000,000 | 一瞬 | 0.01秒 | 0.2秒 | **2.8時間** | ∞ |
| 100,000,000 | 一瞬 | 1秒 | 27秒 | **31年** | ∞ |

**覚えておくべき目安**:
- n = 10⁶（100万）で **O(n²)は厳しい** → O(n log n)以下を目指す
- n = 10⁸（1億）で **O(n)も遅め** → O(log n)やアルゴリズム工夫が必要
- n = 10¹²（1兆）なら **O(log n)** 一択

---

## 4. よくある混同ポイント

### 「2重ループ = 必ずO(n²)」ではない

```python
for i in range(n):
    for j in range(10):     # 内側は常に10回（定数）
        ...
# → O(n × 10) = O(n)
```

内側のループが **nに依存しない** なら、全体はO(n)のまま。

### 「ループが1つ = 必ずO(n)」でもない

```python
i = 1
while i < n:
    i *= 2                 # 毎回2倍 → log n 回で終わる
# → O(log n)
```

---

## 5. まとめ

- **O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)** の順に遅くなる
- 実務では **O(n log n) 以下** に収めるのが目標
- O(n²) は **nが数千を超えると危険**
- O(2ⁿ) や O(n!) は **基本的に避ける**
- ループの数 = オーダーではない。**実際に何回回るか** を数える
