# 計算量の基礎

## 🎯 このページのゴール

- 「計算量」とは何か、なぜ必要なのかを理解する
- `O(n)` のような記号（Big-O記法）の読み方がわかる
- 似た記号（Ω・Θ）との違いを区別できる

---

## 1. 計算量って何？

**計算量（computational complexity）** とは、
**「データが増えたとき、プログラムがどれくらい遅くなるか／メモリを使うか」** をざっくり表したもの。

### なぜ必要？

同じ問題を解くプログラムでも、書き方によって速さが全然違います。

例：1〜100の合計を求める
```python
# パターンA：1つずつ足す（100回の足し算）
total = 0
for i in range(1, 101):
    total += i

# パターンB：公式を使う（1回の計算）
total = 100 * (100 + 1) // 2
```

データが100個なら両方とも一瞬。
でも **100万個・1億個** になると？

| 件数 | パターンA（ループ） | パターンB（公式） |
|------|-------------------|-----------------|
| 100 | 0.00001秒 | 0.000001秒 |
| 100万 | 0.1秒 | 0.000001秒 |
| 1億 | 10秒 | 0.000001秒 |

**件数が増えたときの差** を予測できる道具、それが計算量です。

---

## 2. Big-O記法の読み方

計算量を表す一番よく使われる記号が **Big-O記法（ビッグ・オー）**。

```
O(n)   ← 「オーダー エヌ」と読む
O(n²)  ← 「オーダー エヌ の 2乗」
O(1)   ← 「オーダー 1」（データ量に関係なく一定）
```

### 意味

> **データ量を `n` としたとき、最悪でもこれくらいのオーダー（規模）で時間がかかる**

ポイントは **「最悪ケースの上限」** を表していること。

### 具体例

```python
def find_first(arr, target):
    for x in arr:          # n回ループする可能性あり
        if x == target:
            return True
    return False
```

- 配列の先頭にあれば1回で終わる（ベスト）
- 末尾にあれば n回ループする（ワースト）
- Big-Oは **ワースト** を表すので → **O(n)**

---

## 3. なぜ「ざっくり」なのか

Big-Oは細かい定数や低次の項を **無視** します。

例えば、ある処理が `3n² + 5n + 100` ステップかかるとき：

- `n` が大きくなると `n²` の項が支配的になる
- `5n` や `100` は誤差レベル
- 係数 `3` も本質ではない（CPUや言語で変わる）

→ **O(n²)** とだけ書く

### イメージ

```
n = 10      → 3·100 + 5·10 + 100 = 450
n = 100     → 3·10000 + 5·100 + 100 = 30600
n = 1000    → 3·1000000 + 5·1000 + 100 = 3005100
                ↑ ほぼこれだけで決まる
```

**「nが十分大きいときの振る舞い」** だけを見ているのです。

---

## 4. Big-O・Ω・Θ の違い

計算量の記号は3種類あり、それぞれ意味が違います。

| 記号 | 名前 | 意味 | ざっくり |
|------|------|------|---------|
| `O(f)` | ビッグ・オー | **上限**（最悪でもこれ以下） | 「遅くてもこれくらい」 |
| `Ω(f)` | ビッグ・オメガ | **下限**（少なくともこれ以上） | 「早くてもこれくらい」 |
| `Θ(f)` | ビッグ・シータ | **ぴったり**（上下とも一致） | 「だいたいこれ」 |

### 例：線形探索 `find_first`

- 最悪：n回 → **O(n)**
- 最良：1回 → **Ω(1)**
- 平均的な上下限は一致しないので Θ では書けない

### 例：全要素を1回ずつ見る処理（合計を求めるなど）

```python
total = 0
for x in arr:
    total += x
```

- 最悪もn回、最良もn回 → 上下とも n
- → **Θ(n)**（ぴったりn）

### 実務での使い分け

日常会話では **ほぼ Big-O しか使わない** ので、まずはBig-Oだけ覚えればOK。
ΩとΘは「こういう違いもある」と知っておく程度で十分です。

## 5. よく見る計算量オーダー（プレビュー）

早い順に並べるとこうなります。詳細は `時間計算量.md` で解説。

```
O(1)  <  O(log n)  <  O(n)  <  O(n log n)  <  O(n²)  <  O(2ⁿ)  <  O(n!)
 速い ←――――――――――――――――――――――――――――――――――――――→ 遅い
```

| オーダー | n=100 で | n=10000 で |
|---------|---------|-----------|
| O(1) | 1 | 1 |
| O(log n) | 7 | 13 |
| O(n) | 100 | 10,000 |
| O(n log n) | 664 | 132,877 |
| O(n²) | 10,000 | 100,000,000 |
| O(2ⁿ) | 天文学的 | 宇宙が終わる |

---

## 6. まとめ

- 計算量 = **データが増えたときの「遅さ」の伸び方**
- Big-O記法 `O(n)` は **最悪ケースの上限** をざっくり表す
- 定数倍や低次の項は無視する（本質ではない）
- `O` / `Ω` / `Θ` は上限・下限・ぴったり、の違い
- 実務では **Big-O** を読めれば十分スタートできる
