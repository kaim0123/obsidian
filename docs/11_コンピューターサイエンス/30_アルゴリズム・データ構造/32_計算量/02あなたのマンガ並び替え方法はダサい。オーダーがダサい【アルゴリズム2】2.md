## 要約

**選択ソートというアルゴリズム**

マンガがバラバラに並んだ本棚を、1巻を探して左に置き、2巻を探して左に置き…と繰り返して並べる方法。アルゴリズムの世界では**選択ソート（セレクションソート）**と呼ぶ。普通の人間が思いつくやり方であり、コンピュータに指示するのも簡単で、実装も分かりやすい。つまり**立派なアルゴリズム**である——問題を解く手順を考えて提示しているという意味で、前回の「アルゴリズムの本質」に照らしても正しい。ただし、この回の主題は「**どう間違っているか**」を痛感すること。より良いオーダーのアルゴリズムが存在するので、選択ソートでは「O(n²)のアルゴリズムだ」と煽られる、という話になる。

**アルゴリズムの評価＝計算の回数（計算量）**

アルゴリズムの良し悪しをどう評価するか。専門的には「同じ機械・同じ条件で、どれだけ早く終わるか」を考えるが、ざっくり言うと**計算の回数**で決まる。ここでいう「計算」には**比較**（「この巻は1巻か？」「どっちが大きいか？」の判定）も1回の計算として数える。コンピュータは「パッと見て全部分かる」ことができないので、1冊ずつ取り出して「1巻か？」と判定する作業を、最悪なら全冊分行う必要がある。

**選択ソートの計算回数を概算する**

例として1巻から1000巻までバラバラに並んだマンガを選択ソートで並べるとする。1巻を探すのに、平均すると n/2 回（1000冊なら約500回）の比較が必要。2巻を探すときも同様に約500回、と繰り返す。これを n 回（1巻、2巻、…、n巻と順に取り出すので）繰り返すと、全体の計算回数は **(n/2) × n ＝ n²/2** のオーダーになる。つまり **O(n²)**（オーダーは n の2乗）。1000冊ならおおよそ50万回程度の計算になる。データ数 n が増えると、計算回数が n の2乗で増えていくのが本質で、係数（1/2 など）は「オーダー」を考えるときには省略する。

**オーダーとは**

コンピュータ科学でいう**オーダー**は「注文」ではなく**桁（オーダー）**の意味。データの個数を n としたとき、「計算回数は n² ぐらいになる」と表す。オミクロン（O）を使って **O(n²)** と書く。宇宙の寿命から言えば10年なんて誤差、というような「桁でざっくり言う」感覚に近い。良いアルゴリズムは、このオーダーが**小さい**ほどよい。n² は n や n log n に比べて大きいので、選択ソートは「効率が悪い」とされる。

**O(n log n) のアルゴリズムの存在**

整列（ソート）に関しては、**O(n log n)** のアルゴリズムが存在することが知られている。log n は n に比べて増え方がゆるやか（例：n が1000でも log n は10程度）なので、n × log n は n² よりずっと小さい。つまり「1巻から順に探して並べる」より、**「2個ずつ取り出して大小を比べ、勝ち抜いたもの同士をまた比べる」ようなやり方**（トーナメントのような考え方）をうまく組み合わせると、もっと少ない計算回数で並び替えができる。水野さんが「ちっちゃいのを比べ続けて勝ち抜かせる」と発言した部分は、その巧妙なトリックへの伏線。詳細は次回のクイックソートで扱う。

**教科書の構成：バブルソートから選択ソートへ**

岩波の教科書では、整列の説明が**もっと効率の悪い方法**から始まる。**バブルソート**——隣同士を比べて入れ替え、また隣同士を比べて入れ替え、を繰り返す方法。子供の頃、ぐちゃぐちゃになったトランプを「ここ直したら綺麗になる」と局所的に並べ替えようとした経験に近い。そこから選択ソート（最小値を見つけて左に置く）が出てきて、「これが一番効率いいよね」と思いきや、**最善ではない。もっと良い O(n log n) のアルゴリズムがある**、という流れで次回へつなぐ。

**実用でのソート**

Google検索でも、検索結果をユーザーの属性（例：30代主婦向けの順）で並び替える処理が行われている。並び替えは日常的に使われる技術であり、だからこそ「どのアルゴリズムで何回計算しているか」を意識すると、普段使うサービスの中身が少し見えてくる。
