# 空間計算量

## 🎯 このページのゴール

- 「空間計算量」と「時間計算量」の違いを理解する
- 自分のコードがどれくらいメモリを使うか見積もれる
- 時間とメモリのトレードオフの考え方を知る

> 前提: [01_計算量の基礎](01_計算量の基礎.md) の Big-O記法を理解していること。

---

## 1. 空間計算量って何？

**空間計算量（space complexity）** とは、
**プログラムが動くときに使う「メモリの量」** が、データ量に対してどう増えるかを表したもの。

時間計算量が「**時間**の伸び方」なら、
空間計算量は「**メモリ**の伸び方」。記法は同じ Big-O を使います。

```
時間計算量: O(n)  → データ2倍で時間2倍
空間計算量: O(n)  → データ2倍でメモリ2倍
```

---

## 2. なぜ気にするのか

メモリは **有限の資源** です。使いすぎると：

- **遅くなる**（スワップが発生する）
- **落ちる**（OutOfMemoryError / メモリ不足で強制終了）
- **他のプロセスに影響する**（サーバーなら致命的）

特にモバイル・組み込み・大規模データ処理では時間以上に重要な指標。

---

## 3. 何をカウントする？

空間計算量で数えるのは **「追加で使うメモリ」** です。

入力データそのもの（例: 引数で渡された配列）のサイズは、
**アルゴリズムの性能とは別** なので、多くの場合カウントしません。

```python
def sum_all(arr):        # arrのサイズはカウントしない
    total = 0            # 変数1個 → O(1)
    for x in arr:
        total += x
    return total
# 空間計算量: O(1)
```

> 「入力も含める／含めない」 は文脈で変わります。
> 「**追加領域（auxiliary space）**」 = 入力を除いた使用量、と呼び分けることもあります。

---

## 4. よくある空間計算量の例

### 🟢 O(1) — 追加メモリがほぼゼロ

**変数を数個使うだけ** の処理。データ量に関係なく一定。

```python
def find_max(arr):
    max_val = arr[0]       # 変数1個だけ
    for x in arr:
        if x > max_val:
            max_val = x
    return max_val
# 空間計算量: O(1)
```

一番理想的。**その場で処理する（in-place）** とも言います。

---

### 🟡 O(n) — 入力に比例した追加メモリ

**新しいリスト・辞書などを作る** とよくこうなる。

```python
def double_all(arr):
    result = []            # 新しいリスト
    for x in arr:
        result.append(x * 2)
    return result
# 空間計算量: O(n)  ← 入力と同じサイズの配列を作る
```

```python
def count_chars(s):
    counter = {}           # 文字種の数だけ辞書が増える
    for c in s:
        counter[c] = counter.get(c, 0) + 1
    return counter
# 空間計算量: O(n)  ← 最悪、全文字が異なれば n個のキー
```

---

### 🔴 O(n²) — 二次元の追加メモリ

**n×n の表や配列** を作る処理。

```python
def make_matrix(n):
    return [[0] * n for _ in range(n)]
# 空間計算量: O(n²)
```

n=10,000 なら 1億要素。整数1個8バイトとして **800MB**。危険。

---

### 🟣 O(log n) — 再帰の深さ分だけ使う

**再帰呼び出しはスタックにメモリを積む** ので、再帰の深さ分の空間を使います。

```python
def binary_search(arr, target, left, right):
    if left > right:
        return -1
    mid = (left + right) // 2
    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search(arr, target, mid + 1, right)
    else:
        return binary_search(arr, target, left, mid - 1)
# 時間: O(log n)、空間: O(log n)  ← 再帰の深さがlog n
```

同じ二分探索でも、**ループで書けば空間は O(1)** になります。

## 5. 時間 vs 空間 のトレードオフ

多くの場合、**時間を縮めるとメモリを使う**／**メモリを節約すると時間がかかる** というトレードオフがあります。

### 例1: フィボナッチ数列

```python
# パターンA: 再帰（メモリ節約、時間は最悪）
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)
# 時間: O(2ⁿ)、空間: O(n)

# パターンB: メモ化（時間短縮、メモリ犠牲）
memo = {}
def fib_memo(n):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n-1) + fib_memo(n-2)
    return memo[n]
# 時間: O(n)、空間: O(n)  ← 結果を全部保存

# パターンC: ループ（両方効率的）
def fib_loop(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
# 時間: O(n)、空間: O(1)  ← 最強
```

パターンB は「**時間のために空間を払う**」典型例。

### 例2: ハッシュを使った検索

- 毎回配列を線形探索: 時間 O(n)、空間 O(1)
- ハッシュセットを作って検索: 時間 O(1)、空間 O(n)

**「キャッシュ」「メモ化」「事前計算」** は全てこのトレードオフを使ったテクニック。

---

## 6. 空間計算量の数え方のコツ

### ステップ1: 新しく確保するものを探す
- 配列・リスト・辞書・セットの生成
- 再帰呼び出し（スタック）
- 大きな文字列の連結

### ステップ2: そのサイズが n にどう依存するか考える
- 入力と同じサイズ? → O(n)
- 固定サイズ? → O(1)
- n×n? → O(n²)

### ステップ3: 一番大きいものを採用
時間計算量と同じで、**支配的な項** だけで判断する。

### 例

```python
def example(arr):
    n = len(arr)
    total = 0                  # O(1)
    seen = set()               # 最終的に O(n)
    matrix = [[0]*10 for _ in range(n)]  # O(n × 10) = O(n)
    for x in arr:
        seen.add(x)
    return total, seen
# 最大は O(n) → 全体: O(n)
```

## 7. 隠れたメモリ消費に注意

### スライス・コピー
```python
arr2 = arr[:]           # 配列を丸ごと複製 → O(n) の追加メモリ
sub = arr[1000:2000]    # 1000要素分のコピー
```

### 文字列の連結
```python
# 毎回新しい文字列を作る → O(n²) 空間になりうる
result = ""
for s in strings:
    result += s
# → join を使えば O(n)
result = "".join(strings)
```

### デフォルト引数にリストを使う罠
```python
def f(arr=[]):          # 呼び出しのたびに同じリストを使い回す
    arr.append(1)
    return arr
# メモリリークの原因になることも
```

---

## 8. まとめ

- 空間計算量 = **データが増えたときのメモリ使用量の伸び方**
- 基本は時間計算量と同じBig-O記法
- 数えるのは **追加で使うメモリ** （入力そのものは除くことが多い）
- **O(1) < O(log n) < O(n) < O(n²)** の順に消費が大きくなる
- 再帰は **深さ分のスタック** を使うことを忘れない
- **時間と空間はトレードオフ** になることが多い（メモ化・キャッシュ）
