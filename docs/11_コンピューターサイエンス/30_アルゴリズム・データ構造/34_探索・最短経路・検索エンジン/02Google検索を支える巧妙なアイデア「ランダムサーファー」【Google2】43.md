## 要約

**シリーズの位置づけ**

ゆるコンピュータ科学ラジオ「Googleのアルゴリズム」第2回（[[01Googleの根幹になった論文を読む。検索エンジンの解剖。【Google1】42]] の続編）。前回までの **PageRank**（被リンク数＝論文の被引用数）の欠陥——特に **循環参照**——を、論文 *The Anatomy of a Large-Scale Hypertextual Web Search Engine* に登場する **ランダムサーファー**（Random Surfer）模型でどう解決するかを、直感的な比喩を中心に解説する回。数式はほぼ1本だけで、交通網・観光地の人気といった日常のイメージで理解できるのが特徴。

### 前回の復習：PageRank と循環参照の問題

- **PageRank** の根幹アイデア：ページが **どれだけリンク（引用）されているか** で「いいページ」をランク付けする。
- 第1回で残した問題：**循環参照**。A→B→A のように互いにリンクし合うと、お互いを「正しい」と言い合い、ランクが **ぐるぐる上がり続ける**。
- リンクスパムやスコアの無限増大も同系統の問題。被リンク元の PageRank を加味しても、循環参照そのものは解けない。
- 本回のテーマ：**架空の存在「ランダムサーファー」を1つ想定するだけで、これらを一撃で解決する** という巧妙なトリック。

### ランダムサーファーとは

- **架空の Web 閲覧者**。Wikipedia のリンクを次々と飛び続ける人、といったイメージ。
- 実在する人物ではなく、**シミュレーション上の仮想存在**（マックスウェルの悪魔的な「召喚」比喩）。
- 行動ルールは2つだけ：
  1. **85%の確率**で、今いるページから **ランダムに1本選んだリンク** を辿って次のページへ移動する。
  2. **15%の確率**で **飽きてやめる**（teleport）——Web 上の **どこかランダムなページ** に再び「生まれ落ちる」。
- この召喚→サーフィン→飽きる、を **何億回も** 繰り返す。

### 何億回シミュレーションすると何がわかるか

- ページは **「めちゃくちゃよく訪問された」** ものと **「あまり訪問されなかった」** ものに分かれる。
- **よく訪問されるページ** ＝ 重要なページ、とみなせる。
- ここで **リンク数** だけでなく **リンクの強さ** も自然に加味される：
  - 100サイトからリンクされている **新宿駅** のようなページは、サーファーが頻繁に訪れる。
  - 新宿から **渋谷への1本だけ** のリンクがあっても、新宿を通るサーファーは **ほぼ確実に渋谷も訪れる** → 渋谷は被リンク1本でも **強いリンク** として評価される。
  - 逆に、Yahoo! トップから Yahoo! ニュースへの1本リンクも同型——人気サイトからの1本は価値が高い。

### 循環参照の解決：離島と東京駅の比喩

- **A と B が互いにだけリンク** し、他サイトからはリンクされていない **離島** を想像する。
- サーファーがたまたま A か B に落ちると、85%の確率で **A↔B を行き来** する。
- しかし **15%で飽きて消える** → また別の場所にランダム再配置される。
- 離島全体への訪問回数は **全体の中では微々たるもの**——A と B の間を何度行き来しても、人口（訪問数）はそこに **定住しない**。
- **東京駅・新宿駅** の比喩：循環リンクにはなっていなくても、全国から人が **1回ずつ通過** するだけで **圧倒的にカウントされる**。
- つまりランダムサーファー模型は、**リンクの循環** と **ネットワーク全体でのハブ性** を同時に測れる。交通網と **本質的に同型** のモデル。

### なぜ「巧妙なトリック」なのか

- 論文では数式は **ほぼ1本**（PageRank の漸化式）。残りは **直感的理解**（Intuitive Justification）で説明されている。
- 複雑なグラフ理論を正面から解くのではなく、**「ネットサーフィンする人を大量に召喚して観察する」** という身近な発想から PageRank 相当のスコアが得られる。
- 着想の系譜：**論文の被引用数** → **被リンク数** → **ネットサーフィンする人の動きをシミュレーション** と、日常の観察から到達している。
- 「アルゴリズムの良さ＝巧妙なトリックに **心よい驚き** を感じること」（第1回で引用した著者の言葉）が、本回の核心でもある。

### 交通・ネットワーク・バイオミメティクス（余談）

- **交通網** と Web のリンク構造は構造的に似ている——ランダムサーファーは **人流モデル** そのもの。
- **粘菌（スライムモールド）** が餌に向かって菌糸を伸ばすと、北海道の鉄道網に似たネットワークになる（中垣俊之氏ら、イグノーベル賞）——ネットワーク最適化の **バイオミミクリー** の例。
- **渋滞学**（西成活裕氏）：セルオートマトンで「車間距離を空けた車を投入すると渋滞が緩和される」→ **インターネットの輻輳制御**（データが集まりすぎてパニックになる状態の回避）への応用も研究されている。
- 話は脱線するが、**「ネットワークは交通と同じ数学」** という本質は本編と通じる。

### 現代の Google への注意（補足）

- 本回扱ったのは **1998年の初期論文のアイデア** の **大幅な単純化**。
- 現代の Google 検索は PageRank だけでなく、**数十〜数百種** のシグナルを組み合わせており、1アイデアでは説明できない。
- 論文には他にも例えば **近接性（proximity）** の原則がある：「**かわいい 猫**」で検索したとき、「かわいい」と「猫」が **近い位置** にあるページほど relevant——「かわいい犬の写真」記事の末尾に「猫アレルギー」とだけ書いてあるページは下げたい、といった話。

### まとめのテーマ：「正しいアイデア」

- レイ・カーツワイル『シンギュラリティは近い』前書きより、児童文学 **トム・スウィフト・ジュニア** シリーズの教訓を引用：
  - **「正しいアイデアには、一見手も足も出ないような難題を解決する力がある」**
- PageRank の流れに当てはめると：
  1. 「いいページをランク付けしたい」→ 被リンク数でいいのでは？
  2. 循環参照で破綻 → どうしよう？
  3. **ランダムサーファーを想定すればよい** —— 1つの正しいアイデアで **全問題が解決**。
- 「世界はアルゴリズムに溢れている」——日常の問題をコンピュータに同じように計算させる **着想の源泉** が、Google 創業者たちの思考そのもの。
