## 要約

Google が数兆ページの中から **0.5秒程度** で答えを返す——その「当たり前」の裏には **60年のコンピュータ科学の知恵** がある。前回（ソート）の続編として、「**探す**」側の歴史を解説する動画。**線形探索** → **二分探索** → **ハッシュ** → **B木** → **転置インデックス（全文検索）** → **PageRank（Google）** までをたどり、「**どう早く探すか**」と「**どう良い順に出すか**」の両方が磨かれてきたことを示す。

### テーマと前回との関係

- 総当たり（線形探索）では一生かかる——Google が扱う数兆ページには**全件スキャンは不可能**。
- 前回のソート：**並べ替えは早く探すための前処理**——今回はその「探す」側。
- ソートと同様、**絶対の正解は1つではなく**、状況によって最適な手法が異なる。
- 結論：検索の1回1回は、60年分の天才たちの工夫の積み重ね——魔法ではなく**理屈の積み重ね**。

### 第1章：線形探索（Linear Search）——全部見る

- 先頭から1個ずつ順番に見ていく——トランプの束を上からめくる、冷蔵庫の調味料を奥から探す。
- **O(n)**：データ n 個なら最悪 n 回。10億件なら10億回（秒間1億回でも約10秒）。
- 人間の基本動作だが、コンピュータが扱うデータは桁が違う——**全部見ないための工夫**が必要。

### 第2章：二分探索（Binary Search）——半分に捨てる

- **前提：データが並んでいる**（前回のソートが前提）。
- 真ん中を見て、大きい/小さいで**半分を捨てる**を繰り返す——辞書を真ん中から開く発想。
- **O(log n)**：100個→約7回、1,000個→約10回、**10億件→約30回**（2³⁰ ≈ 10億）。線形探索の10億回から別次元へ。
- ぴったりの値だけでなく「この値以上で1番小さいもの」等の応用も広い——検索の基礎として今も多用。
- **弱点**：
  - 並んでいることが絶対条件——頻繁な追加があると並べ直しコストが重い
  - **整数オーバーフローのバグ**：`(left + right) / 2` で巨大データの足し算が上限超過——**20年近く教科書の「正しいコード」に潜んでいた**。Google 技術者が **2006年** に指摘するまで多くの実装に残存。理屈が正しくても**機械の数の上限**が牙を向く典型例。

### 第3章：ハッシュ（Hash）——計算で場所を当てる

- 並べ替え不要——鍵（名前等）を**計算で別の値（置き場所）に変換**し、探すのではなく**最初から場所を計算**。
- 図書館の請求番号の比喩——棚を順に見るのではなく「この棚のこの位置」と分かる。
- **理想的には O(1)**：10億件でも計算1回で場所が分かる（二分探索の30回すら上回る）。
- **身近な用途**：
  - **パスワード保存**——元の文字列ではなくハッシュ値のみ保管（漏れても元に戻せない）
  - **辞書型・連想配列**——名前を入れたら値が一発で出る
- **衝突（Collision）**：異なる鍵が同じ場所に割り当てられる
  - 対策：**チェイン法**（同じ場所にリストをぶら下げる）、**オープンアドレス法**（隣の空きを探す）
  - 衝突が増えると O(1) が O(n) に逆戻り——**わざと余裕を持たせた空き**を確保
  - **ハッシュ DoS 攻撃**（前回ソートの DoS と同様）：同じ場所に集中するデータを送り付けて遅くする → 本番では**計算方法をランダム化**して防御
- **苦手分野：範囲検索**——データがバラバラに散るため「30〜50の売上を全部」等が困難。ハッシュは**一発で当てるのは得意、まとめて取るのは苦手**。

### 第4章：B木（B-tree）——ディスク向けの巨人

- **1970年代**、**バイヤー**と**マクレイト**が考案（「B」の由来は諸説あり——Balance / Bayer / Boeing 等、本人も明言を避けた）。
- **ハードディスクの性質**に特化：1点ずつ読むより**まとめてどさっと読む**方が効率良い（メモリより桁違いに遅いディスクへのアクセス回数が勝負）。
- 普通の木（2分岐）ではなく**1ノードに何十の子**——**太くて低い木**にしてディスク読み込み回数を削減。数百万件でも数回の読み込みで到達。
- **二分探索をディスク向けに改造**した発想。
- **現代での用途**：
  - ほぼ**全てのデータベース**
  - **ファイルシステム**（NTFS 等）
  - データベースの**インデックス**の正体が B木——インデックスなしは線形探索に逆戻り（100万件で体感「一瞬」vs「数十秒」の差）
- **ハッシュとの使い分け**：一発で当てるならハッシュ、**範囲で取るなら B木**——得意分野が違う。

### 第5章：全文検索と転置インデックス（Inverted Index）

- Google の検索は番号や鍵ではなく**普通の言葉**で探す——従来の「値を探す」とは根本的に異なる。
- 素朴な方法：全文章を開いて単語があるか調べる → 再び線形探索の地獄。
- **天才的な発想の転換：逆引き（転置インデックス）**
  - 通常：「この文章にどんな単語があるか」
  - 逆：「**この単語はどの文章に出てくるか**」の一覧を**先に作っておく**
  - 例：「猫」→ 文書3番・7番・12番。検索時はリストを引くだけ——文章を全部開く必要なし。
  - 本の末の索引（「この用語はこのページ」）と同じ発想。
- **検索エンジンの裏側**：
  - **クローラー**がリンクを辿って世界中のページを自動巡回・収集
  - 集めたページを単語ごとに分解し転置インデックスを構築・更新（寝ている間も継続）
- **複数キーワード**：「白い」と「猫」→ 両方の単語リストの**共通部分（積集合）**を取る。

### 第6章：PageRank と Google の誕生

#### 1990年代の検索エンジン

- 軍拡時代：**AltaVista**（最大手）、**Yahoo**、Excite 等がしのぎを削る。
- 当時の順位決定：**キーワードの出現回数**（TF）——多く出てくるページほど上位。
- **致命的な穴（キーワードスタッフィング）**：
  - ページ内に検索ワードを大量に詰め込めば上位に出せる
  - 背景と同じ色で見えない文字を埋め込む手口も
  - 検索結果が**スパムだらけ**——「ページの自己申告」を信じる限界

#### PageRank（1996年〜）

- **スタンフォード大学**の大学院生 **ラリー・ペイジ** と **セルゲイ・ブリン** の研究プロジェクト（当初は **BackRub**——ページ同士のリンクの「後ろからの繋がり」を分析）。
- 核心の発想：**良いページからリンクされるページは良いページ**——リンクを「推薦の票」と見なす。
- 単純な多数決ではない：
  - **重要なページからの1票**は無名ページの1票より重い
  - **たくさんリンクを出しているページ**の票の価値は薄まる（誰にでも推薦状を書く人の推薦は軽い）
- **鶏が先か卵が先か問題**：重要なページの重要度を決めるには重要度が必要 → **再帰的に仮の点数を繰り返し計算**し、収束させる（クイックソートの再帰と同じ構造）。
- **ランダムサーファーの比喩**：Web をランダムにリンクを辿り続ける人がよくたどり着くページほど重要。
- **PageRank** 命名：ページの順位＋Larry **Page** の名前をかけたちゃっかり。
- キーワード詰め込みスパムには通用しない——中身のないページは誰からもリンクされない。

#### Google の成立

- 当初は作った検索エンジンを**既存企業に売ろうとした**が、どこも本気で買わなかった（検索の価値が理解されていなかった）。
- **1998年**、ガレージで2人が起業——**Google**。
- 社名：**googol**（10の100乗）が元——膨大な情報を扱う意気込み。綴り **Google** はスペルミスがそのまま定着したという話。
- 口コミで「欲しい答えが一発で出る」と広がり、AltaVista・Yahoo の人力分類にも抗えなかった——**高発の小さなチームが王者をひっくり返す**典型例（クイックソートのホアと同様）。
- **現代の Google**：PageRank だけではなく**何百もの判断材料**を組み合わせ——PageRank は出発点。リンク購入等の不正対策も継続。探す側と騙す側の戦いは今も続く。

### 60年の流れの整理

| 段階 | 手法 | 計算量 | 得意なこと |
|---|---|---|---|
| 全部見る | 線形探索 | O(n) | シンプル・小規模 |
| 半分に捨てる | 二分探索 | O(log n) | 整列済みデータの値検索 |
| 計算で当てる | ハッシュ | O(1) 理想 | 鍵による一発検索 |
| ディスク向け | B木 | 数回のディスク読み込み | 範囲検索・DBインデックス |
| 言葉で探す | 転置インデックス | リスト参照 | 全文検索 |
| 良い順に出す | PageRank | 反復計算で収束 | 検索結果のランキング |

- **前半（速さの工夫）**：線形探索 → 二分探索 → ハッシュ → B木
- **後半（質の工夫）**：転置インデックス → PageRank——「見つける」から「**良いものを上に出す**」へステージが上がった。

### 動画のまとめ

- Google の一瞬の答えは、**クローラーによる索引構築**（寝ている間の地道な作業）と、**転置インデックス・B木・ハッシュ** 等の「全部見ない」技術、そして **PageRank** による「良い順に並べる」知恵の結晶。
- 単なるアルゴリズムが**世界の入り口（何を知るかの見え方）** そのものを決めている。
- 次回予告：圧縮の話、ハッシュの別の使い道（データを守り証明する用途）へ。
