## 要約

**クイックソートの考え方**

前回は選択ソート（1巻を探して左に置き、2巻を…）が O(n²) で効率が悪いこと、O(n log n) の巧妙なアルゴリズムがあるという話で終わった。今回は**クイックソート**を扱う。手順はこうだ。例えば1巻から30巻のマンガなら、**真ん中ぐらい（15巻）を基準値**にする。全冊を「15巻より小さい」「15巻より大きい」の2グループに分ける。大小比較だけして、それぞれのグループの中身の順序は気にしない（ぐちゃぐちゃでよい）。分け終わると、左側と右側に分かれる。次は**左側だけ**を同じやり方で（左側の真ん中を基準にまた分ける）、**右側だけ**も同じやり方で分ける。これを、グループが1個になるまで繰り返す。**1個の場所を確定させるのではなく、「左と右に分けただけ」を繰り返す**のに、最終的に全体が並んだ状態になる——ここが直感に反していて、最初は「効率悪そう」と思う人が多いが、計算すると O(n log n) になる。

**なぜ O(n log n) になるか**

1回目の分割：n 個のデータを基準と比較して左右に分けるので、だいたい n 回の計算。2回目の分割では、左と右でそれぞれ約 n/2 個ずつになるので、左に n/2、右に n/2 で合計 n 回。3回目も同様に合計 n 回…と、**1回の「分割のラウンド」ごとに、全体で約 n 回の計算**がかかる。問題は**何回ラウンドを繰り返すと1個になるか**。2分割が繰り返されると、1回で2つ、2回で4つ、3回で8つ…と**指数的に**増える。逆に言うと、n 個を1個になるまで半分ずつにし続けるには **log₂ n 回**程度でよい。2の10乗が1024なので、1000冊なら約10回の分割でよい。つまり**分割の回数が log n 程度**で、1回の分割に O(n) かかるので、全体で **O(n log n)**。選択ソートの O(n²) と比べると、n が1万・100万と増えたときに圧倒的に計算回数が少ない。折り紙を半分に折り続けると30回で月に届く、という指数の話と同様に、「半分ずつにしていく」ことの強力さが説明される。

**「何も決まってない」のに早い——巧妙なトリック**

選択ソートは「1回やると1個場所が決まる」が、クイックソートは1回の分割では「15巻がだいたい真ん中に来そう」という程度で、どの巻が何番目かは決まっていない。それでも、**次からは左と右の狭い範囲だけを相手にすればよい**ので、全体としての計算回数が少なくなる。教科書（アルゴリズムとデータ構造）の「良いアルゴリズムとは、巧妙なトリックが隠されていて快い驚きを感ずるものだ」という言葉が引用され、**直感では効率悪そうに見えるやり方のほうが、実は効率がいい**という逆説が強調される。アルゴリズムの楽しさは、こうした「トリックに隠された快い喜び」にある。

**分割統治（Divide and Conquer）とデカルト**

「大きな問題を分割して、それぞれを解き、統治する」という考え方は、コンピュータ科学では**Divide and Conquer（分割統治）**という名前で定着している。デカルトの「困難は分割せよ」（コギト・エルゴ・スムと並ぶ有名な方針）に通じる。**コンピュータ科学は「デカルトみ」を味わえる学問**だ、と結論づける。コンピュータに携わる人は、Divide & Conquer を当たり前のように口にし、問題を「自分が扱える大きさに切り分ける」ことを常に考えている。

**プログラマーの仕事と「どこで分割するか」**

プログラマーの仕事の多くは**「どこで divide するか」**である。プログラム全体でエラーが起きていても、**自分の知っている範囲までで切って**考えたり、再利用できる単位に**ライブラリとして分割**してまとめたりする。ビーフシチュー用・クリームシチュー用に「野菜を切って煮込む」ところまでをひとくくりにしておけば、ルーを変えるだけで別の料理になる——これも分割のセンス。逆に「同じ処理をあちこちにコピペしている」「まとめようとしたらエラーで動かなくて諦めた」は、divide できていない状態。実社会でも、クリエイティブな仕事や、つまらない業務の外注範囲を切り出すことなど、**いかにして divide するか**は広く問われるが、**特にコンピュータに携わる人は、その頻度が桁違いに高い**。デカルトみを感じたいならコンピュータ科学がおすすめ、という主張につながる。ソフトウェア工学の**カプセル化**も、「いかに divide して conquer するか」を表した概念として言及される。

**アルゴリズムは「高速化」だけではない**

アルゴリズムを「ただ速くするためのもの」と捉えるのは誤解。**解けなかった問題を解けるようにする**例として**ディープラーニング**が挙げられる。2012年、「誰にも教わっていないのに猫の画像を識別できるようになった」という話。それまでは教師データで「これは猫、これは猫じゃない」と与える必要があったが、ニューラルネットワーク（小さな脳細胞のような単位をたくさんつなげたモデル）というアルゴリズムの工夫で、新しい問題が解けるようになった。ニューラルネットワークそのものも、大きな問題を小さな単位に**分割**して扱う考え方で支えられている。アルゴリズムは、高速化だけでなく、**新しい問題解決**を可能にする。

**シリーズのまとめ**

コンピュータは**単純な計算しかできない**が、その速度と量が異常なまでに大きい。その「使い道」を整備したのがコンピュータ科学であり、**道筋（アルゴリズム）を示す**ことが本質である——第1回の藤代先生の言葉に戻る。アルゴリズムとデータ構造の教科書にはデータ構造の話もあり、アルゴリズムとセットで学ぶと本来は全18回くらいになるが、今回はアルゴリズムに焦点を当てた3回完結として締めくくる。
