# 木構造（二分木・BST・AVL・赤黒木）

## 概要

**木構造（Tree）** は、データを **階層的（親子関係）** に組織化するデータ構造です。現実世界の「家系図」「組織図」「ファイルシステム」を思い浮かべれば、木構造はすぐ理解できます。

> **リストが「1列の行列」なら、木は「枝分かれした系図」**

木構造は、

- **親子関係がある** データ（階層の表現）
- **ソート済みで素早く探したい** データ（検索木）
- **優先度に応じて取り出したい** データ（ヒープ）
- **文字列のプレフィックス検索** （トライ木）

など、幅広い用途で使われる柔軟な骨格です。

---

## なぜ重要なのか

木構造を理解すると、**O(log N) という魔法のような計算量** が手に入ります。

- 配列での線形探索は O(N) — 100万件なら最悪100万回比較
- 平衡二分探索木なら O(log N) — 100万件でも20回程度の比較で到達

これは、ソート済みデータの **二分探索** と同じ原理を「動的に挿入・削除できる」構造で実現したものです。データベースのインデックス（B木・B+木）、関連配列（TreeMap）、構文木、ファイルシステムなど、至るところで木が使われています。

---

## 用語と基本構造

### 基本用語

```
           [A]              ← 根（ルート）
          /   \
        [B]   [C]           ← 内部ノード
       /  \     \
     [D] [E]    [F]         ← 葉（リーフ）
```

| 用語 | 意味 |
|---|---|
| ノード（node） | 木の要素（丸い部分） |
| 根（root） | 木の最上部のノード |
| 葉（leaf） | 子を持たないノード |
| 親／子 | 直接つながっているノードの上下関係 |
| 兄弟（sibling） | 同じ親を持つノード同士 |
| 深さ（depth） | 根からそのノードまでの距離 |
| 高さ（height） | そのノードから葉までの最長距離 |
| 部分木（subtree） | あるノードを根とする木 |

### 表現方法

```javascript
class TreeNode {
  constructor(value) {
    this.value = value;
    this.children = []; // 任意個の子
  }
}

// 二分木なら子は left / right の2つ
class BinaryTreeNode {
  constructor(value) {
    this.value = value;
    this.left = null;
    this.right = null;
  }
}
```

## 二分木（Binary Tree）

### 定義

**各ノードが最大2つの子（left, right）** を持つ木。木のすべての発展形は二分木が基本です。

```
       [1]
      /   \
    [2]   [3]
    / \
  [4] [5]
```

### 走査（Traversal）

木をすべて辿るには主に4つの順序があります。

```
     [A]
    /   \
  [B]   [C]
  / \
[D] [E]
```

- **前順（Pre-order）**: 自分 → 左 → 右 — A, B, D, E, C
- **中順（In-order）**: 左 → 自分 → 右 — D, B, E, A, C
- **後順（Post-order）**: 左 → 右 → 自分 — D, E, B, C, A
- **層順（Level-order / BFS）**: 上から順、左から右 — A, B, C, D, E

```javascript
function inOrder(node) {
  if (node === null) return;
  inOrder(node.left);
  console.log(node.value);
  inOrder(node.right);
}
```

再帰で書けば自然ですが、内部的にはスタックを使っているのと同じ（コールスタック）。明示的なスタックを使えば非再帰でも書けます。

---

## 二分探索木（BST: Binary Search Tree）

### 定義

二分木にさらに **順序の制約** を加えたもの。

> **「各ノードについて、左の部分木は自分より小さい値のみ、右の部分木は自分より大きい値のみ」**

```
       [8]
      /   \
    [3]   [10]
    / \      \
  [1] [6]   [14]
      / \    /
    [4] [7][13]
```

この性質から、**中順走査するとソート済みで出てくる**（1, 3, 4, 6, 7, 8, 10, 13, 14）という美しい性質があります。

### 検索・挿入・削除

**検索**: 根から始めて、目的値と比較 → 小さければ左へ、大きければ右へ。毎回半分に絞り込める。

```javascript
function search(node, target) {
  if (node === null) return null;
  if (target === node.value) return node;
  if (target < node.value) return search(node.left, target);
  return search(node.right, target);
}
```

**挿入**: 検索と同じように降りていき、空いた場所（null）に新ノードを置く。

**削除**: 少し複雑。
- 葉なら単に切り離す
- 子が1つなら、その子を親に直接つなぐ
- 子が2つなら、**後継ノード**（右部分木の最小値）を持ってきて置き換える

### 計算量の罠

BSTの計算量は **木の高さ** に依存します。

| 木の形 | 高さ | 計算量 |
|---|---|---|
| バランスの取れた木 | O(log N) | O(log N) |
| 一直線に偏った木（片側にしか枝分かれしない） | O(N) | O(N) |

```
すでにソート済みの [1, 2, 3, 4, 5] を順に挿入すると:

[1]
  \
  [2]
    \
    [3]
      \
      [4]
        \
        [5]    ← 実質ただの連結リスト！
```

**この問題を解決するのが「自己平衡二分探索木」** です。

## AVL 木（自己平衡二分探索木）

### 概要

1962 年に Adelson-Velsky と Landis が考案した最初の **自己平衡二分探索木**。挿入・削除のたびに、木の形が **崩れすぎないように自動で回転（rotation）** で整える仕組みを持ちます。

### 平衡条件

> **すべてのノードについて、左部分木と右部分木の高さの差が ±1 以内**

```
OK:
    [5]              [5]
   /   \           /   \
  [3]  [8]       [3]  [8]
                 /
                [1]     ← 差1, OK

NG:
    [5]
   /   \
  [3]  [8]
  /
 [1]
 /
[0]      ← [3]の左右高さ差が2、不均衡
```

この条件が崩れた瞬間に、**回転操作** で形を調整します。

### 回転のイメージ

```
単一右回転（左に偏った木を整える）:

     [3]              [2]
     /                / \
    [2]    →       [1] [3]
    /
   [1]
```

実装は少し手間ですが、どのような挿入・削除の組み合わせでも **4種類の回転パターン**（左・右・左右・右左）で対応できます。

### 計算量

- 検索・挿入・削除: **常に O(log N)**
- 回転コスト自体は O(1)（ポインタの付け替えだけ）

### 用途

- データベースの一部のインデックス
- 標準ライブラリの一部（ただし後述の赤黒木が多い）

## 赤黒木（Red-Black Tree）

### 概要

AVL 木より **ゆるい平衡条件** を採用した自己平衡二分探索木。AVL より少し木が高くなる代わりに、**挿入・削除で必要な回転回数が少なく済む** のが利点です。実務では AVL よりよく使われます。

### ルール

各ノードに「赤」か「黒」の色がつき、次のルールを満たします。

1. ルートは黒
2. 赤ノードの子は必ず黒（赤が連続しない）
3. 任意のノードから葉までのパスにある **黒ノードの数は等しい**

このルールから、**最長パスは最短パスの高々2倍** に抑えられ、結果として高さは O(log N) になります。

```
         [10,B]
        /      \
     [5,R]   [15,B]
     /   \
   [3,B] [8,B]
```

（B: 黒, R: 赤）

### 計算量

- 検索・挿入・削除: **O(log N)**
- 挿入時の回転は最大2回
- 削除時の回転は最大3回

### 採用例

- Java の `TreeMap`, `TreeSet`
- C++ の `std::map`, `std::set`
- Linux カーネルのスケジューラ、ファイルシステム
- Python の `sortedcontainers`

---

## AVL と赤黒木の比較

| 特徴 | AVL木 | 赤黒木 |
|---|---|---|
| 平衡条件 | 厳しい（高さ差±1） | ゆるい（色ルール） |
| 木の高さ | より低い | 少し高い |
| 検索速度 | わずかに速い | わずかに遅い |
| 挿入・削除 | 回転が多め | 回転が少なめ |
| 実装の複雑さ | やや単純 | やや複雑 |
| 向いている用途 | 検索が多い場面 | 書き込みが多い場面、汎用 |

**一般的には赤黒木の方がバランス良好** で、標準ライブラリではこちらが多く採用されます。

## その他の重要な木

### B木・B+木（データベース用）

1ノードに **大量の子** を持てる多分木。ディスクから1ブロック読む単位と合わせることで、ディスクI/Oを最小化できる。**データベースのインデックスやファイルシステム（NTFS, ext4 など）** で広く使われる。

### セグメント木・Binary Indexed Tree

区間和や区間更新を高速に扱うための特殊な木。競プロで頻出。

### トライ木

文字列のプレフィックス検索に特化した木（別ファイルで解説）。

### ヒープ

優先度付きキュー用の特殊な二分木（別ファイルで解説）。

## よくある間違い

### 1. 木 ≠ 二分木

「木」は子が何個あってもよい一般的な構造。子が最大2個のものが「二分木」。ファイルシステムは一般的な木、構文解析では二分木が多い、と使い分けを意識しましょう。

### 2. BSTで平衡を取らずに運用

ソート済みデータを素直に挿入すると、BSTは **連結リストに退化** します。実務では **自己平衡木** を使うか、言語標準のソート済みマップ（`TreeMap` 等）を使うのが安全です。

### 3. 再帰の深さで例外

深い木（特にアンバランスな木）を再帰で走査すると、スタックオーバーフローが起きることがあります。反復＋スタックでの実装が必要な場合もあります。

### 4. 削除の実装ミス

BSTの削除は、子が2つの場合に「後継ノードの値で置き換えて、後継ノードを削除」するやや複雑な処理が必要。ここを手抜きするとツリーが壊れます。

---

## まとめ

### 重要なポイント

1. **木は階層データの基本構造**
2. **二分探索木（BST）は検索・挿入・削除を O(log N) で実現 — ただし平衡が取れていれば**
3. **AVL 木・赤黒木は自己平衡で常に O(log N) を保証**
4. **実務では標準ライブラリの `TreeMap` / `std::map` などが赤黒木ベース**
5. **ソート順や範囲検索が必要ならハッシュテーブルではなく木を選ぶ**

### チェックリスト

- [ ] キーの順序が必要か？ 必要なら木、不要ならハッシュテーブル
- [ ] 範囲検索（◯◯以上◯◯以下）が必要か？ 必要なら木が有利
- [ ] 自分で BST を実装するときは、平衡を取れるか？ 取れないなら言語標準を使う
- [ ] 再帰の深さは許容範囲に収まるか？
