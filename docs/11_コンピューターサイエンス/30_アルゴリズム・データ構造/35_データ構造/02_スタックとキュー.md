# スタックとキュー（LIFO / FIFO / 両端キュー）

## 概要

**スタック（Stack）** と **キュー（Queue）** は、データの出し入れに **順序のルール** を課した、最も基本的なコンテナです。配列や連結リストが「順番に並んだデータの集まり」そのものだとすれば、スタックとキューは「どの順で取り出すか」を制約した **使い方のルール** を定めたものと言えます。

> **スタックは「積み上げた皿」、キューは「レジに並ぶ人の列」**

- **スタック**: 後に入れたものが先に出る（**LIFO**: Last In, First Out）
- **キュー**: 先に入れたものが先に出る（**FIFO**: First In, First Out）
- **両端キュー（Deque）**: 両端から入れる・出せる

---

## なぜ重要なのか

スタックとキューは、コンピュータサイエンス全般に登場する **「処理の順序」を管理する仕組み** の基盤です。

- 関数呼び出しは内部的にスタックで管理されている（コールスタック）
- ブラウザの「戻る」ボタンはスタック
- プリンタの印刷待ち行列はキュー
- BFS（幅優先探索）はキュー、DFS（深さ優先探索）はスタックを使う
- タスクスケジューラ、メッセージキュー、非同期処理の裏側でもキューが活躍

つまり、スタック／キューは特定のアルゴリズムの道具であるだけでなく、**「順序を持った処理フロー」を表現する思考のフレームワーク** でもあります。

## スタック（Stack）

### イメージ

食堂の皿を思い浮かべてください。皿を積み上げるとき、新しい皿は必ず **一番上** に乗ります。取るときも **一番上** から取ります。真ん中や底にある皿を直接は取れません。

```
操作の様子:

push(1):   [1]

push(2):   [2]       ← 上に積む
           [1]

push(3):   [3]
           [2]
           [1]

pop():     [2]       ← 3 が取り出される
           [1]
```

### 基本操作

| 操作 | 意味 | 計算量 |
|---|---|---|
| `push(x)` | 一番上に x を積む | O(1) |
| `pop()` | 一番上を取り除いて返す | O(1) |
| `peek()` / `top()` | 一番上を見るだけ（取り除かない） | O(1) |
| `isEmpty()` | 空かどうかを調べる | O(1) |

### 実装例（JavaScript）

```javascript
class Stack {
  constructor() {
    this.items = [];
  }

  push(item) {
    this.items.push(item); // 配列の末尾を「上」として使う
  }

  pop() {
    if (this.isEmpty()) return undefined;
    return this.items.pop();
  }

  peek() {
    return this.items[this.items.length - 1];
  }

  isEmpty() {
    return this.items.length === 0;
  }

  size() {
    return this.items.length;
  }
}

const stack = new Stack();
stack.push(1);
stack.push(2);
stack.push(3);
console.log(stack.pop());  // 3
console.log(stack.peek()); // 2
```

配列の末尾を「上」として扱うと、`push`/`pop` はどちらも配列の末尾操作になり O(1) になります。

### 典型的な使用例

#### 1. 関数呼び出し（コールスタック）

```javascript
function a() { b(); }
function b() { c(); }
function c() { console.log("hi"); }
a();
```

実行時にメモリ上では次の順で積まれます：

```
[c の呼び出し情報]  ← 実行中
[b の呼び出し情報]
[a の呼び出し情報]
```

`c` が終われば pop され、`b` に戻り、`b` が終われば pop され `a` に戻る。**LIFO がそのまま呼び出し履歴の意味** になっています。

#### 2. 括弧の対応チェック

```javascript
function isBalanced(str) {
  const stack = [];
  const pairs = { ')': '(', ']': '[', '}': '{' };

  for (const ch of str) {
    if ('([{'.includes(ch)) {
      stack.push(ch);
    } else if (')]}'.includes(ch)) {
      if (stack.pop() !== pairs[ch]) return false;
    }
  }
  return stack.length === 0;
}

isBalanced("({[]})"); // true
isBalanced("({[})");  // false
```

開き括弧を push、閉じ括弧が来たら pop して対応を確認します。

#### 3. 「戻る」機能（アンドゥ）

操作履歴をスタックに積み、`Ctrl+Z` で pop して直前の状態に戻す。

## キュー（Queue）

### イメージ

レジの列を想像してください。新しい人は **最後尾** に並び、レジの人は **先頭** から順に処理します。割り込みはなし。

```
enqueue(1): [1]

enqueue(2): [1, 2]     ← 末尾に追加

enqueue(3): [1, 2, 3]

dequeue():  [2, 3]     ← 先頭の 1 が取り出される
```

### 基本操作

| 操作 | 意味 | 計算量 |
|---|---|---|
| `enqueue(x)` | 末尾に x を追加 | O(1) |
| `dequeue()` | 先頭を取り除いて返す | O(1) |
| `front()` / `peek()` | 先頭を見るだけ | O(1) |
| `isEmpty()` | 空かどうか | O(1) |

### 実装上の注意

単純に JavaScript の配列で `arr.shift()` を使うと、先頭削除のたびに **残り全要素をずらす** ため O(N) かかってしまいます。本格的に使うなら以下のいずれかを検討します。

- **連結リスト**: 先頭と末尾のポインタを持てば O(1)
- **循環バッファ（リングバッファ）**: 固定長配列を環状に使う
- **2つのスタックで実装**: 理論的な演習としてよく出題される

### 実装例（連結リスト版）

```javascript
class Node {
  constructor(value) {
    this.value = value;
    this.next = null;
  }
}

class Queue {
  constructor() {
    this.head = null; // 先頭（取り出し側）
    this.tail = null; // 末尾（追加側）
    this.length = 0;
  }

  enqueue(value) {
    const node = new Node(value);
    if (this.tail === null) {
      this.head = this.tail = node;
    } else {
      this.tail.next = node;
      this.tail = node;
    }
    this.length++;
  }

  dequeue() {
    if (this.head === null) return undefined;
    const value = this.head.value;
    this.head = this.head.next;
    if (this.head === null) this.tail = null;
    this.length--;
    return value;
  }
}

const q = new Queue();
q.enqueue("A");
q.enqueue("B");
q.enqueue("C");
console.log(q.dequeue()); // A
console.log(q.dequeue()); // B
```

### 典型的な使用例

#### 1. 幅優先探索（BFS）

「現在地から距離1のノード → 距離2のノード → …」と **層ごとに** 広げていく探索。

```javascript
function bfs(start, graph) {
  const queue = [start];
  const visited = new Set([start]);

  while (queue.length > 0) {
    const node = queue.shift(); // ※実用では効率的なキューを使う
    console.log(node);
    for (const next of graph[node]) {
      if (!visited.has(next)) {
        visited.add(next);
        queue.push(next);
      }
    }
  }
}
```

迷路の最短経路や、SNSの「2ステップ先の友達」などを見つけるのに使います。

#### 2. タスクの順次処理

印刷ジョブ、メッセージ処理、Webサーバーのリクエスト処理など、「到着順に処理する」場面で多用されます。

```
リクエスト到着: [req1, req2, req3]
                     ↓
ワーカーが先頭から取り出して処理
                     ↓
到着順に応答が返る（公平性）
```

#### 3. ストリーム処理のバッファ

動画配信・音声処理・データ取り込みなど、流れてくるデータを一時的に貯めて処理する用途。

## 両端キュー（Deque: Double-Ended Queue）

### 概要

**両端キュー（Deque、「デック」と読む）** は、**両端で追加・削除ができる** キューです。スタックとキューの両方の機能を兼ね備えています。

```
   先頭 ←→ [A, B, C, D] ←→ 末尾

両端に対して追加・削除が可能:
  addFront(x) / removeFront()
  addBack(x)  / removeBack()
```

### 基本操作

| 操作 | 意味 |
|---|---|
| `addFront(x)` | 先頭に追加 |
| `addBack(x)` | 末尾に追加 |
| `removeFront()` | 先頭から削除 |
| `removeBack()` | 末尾から削除 |

すべて O(1) で実装可能です（双方向連結リストか循環バッファで実装）。

### 典型的な使用例

#### 1. スライディングウィンドウの最大値

固定長の窓を配列上でスライドさせ、各位置での最大値を効率的に求める問題。Deque を使うと O(N) で解けます。

#### 2. ブラウザの閲覧履歴

「戻る」と「進む」があるシステムでは、両端からの操作が自然に表現できます。

#### 3. ワークスチールアルゴリズム

並列計算でタスクを分散するとき、自分のタスクキューの片端から、他のワーカーのキューの逆端から盗む、という設計があります。

### 言語ごとの実装

- Java: `ArrayDeque`, `LinkedList`（両方とも Deque インターフェース実装）
- Python: `collections.deque`
- C++: `std::deque`
- JavaScript: 標準にはないが、配列を使って簡易実装可能

---

## スタック・キュー・両端キューの比較

| 特徴 | スタック | キュー | 両端キュー |
|---|---|---|---|
| 入れる場所 | 一端（上） | 一端（末尾） | 両端 |
| 取り出す場所 | 同じ一端（上） | 反対端（先頭） | 両端 |
| 順序ルール | LIFO | FIFO | 自由 |
| 代表的用途 | 再帰・履歴・構文解析 | BFS・ジョブ処理 | スライディングウィンドウ |

## よくある間違い

### 1. JavaScript の `Array.shift()` をキューとして使う

```javascript
// ❌ 先頭削除が O(N)
const queue = [];
queue.push(x);
queue.shift(); // これが遅い！
```

要素数が数万以上になると急激に遅くなります。大量データを扱うなら専用のキュー実装（連結リストベース等）を使いましょう。

### 2. スタックオーバーフロー

深すぎる再帰呼び出しはコールスタックを使い切り、クラッシュします（**スタックオーバーフロー**）。

```javascript
function infinite() { infinite(); } // RangeError: Maximum call stack size exceeded
```

解決策:
- 再帰を **明示的なスタック** を使ったループに書き直す
- 言語によっては **末尾再帰最適化** が利く
- データサイズが大きいならそもそもアルゴリズムを再設計する

### 3. スタックとキューを混同した結果、BFSがDFSになる

BFSでは **キュー** を使います。うっかりスタックを使うと **DFS** になり、求める答え（最短経路など）が得られません。

```javascript
// ❌ BFSのつもりで実装した DFS
const stack = [start];
while (stack.length > 0) {
  const node = stack.pop(); // ← これだとDFS！
  ...
}

// ✅ 正しい BFS
const queue = [start];
while (queue.length > 0) {
  const node = queue.shift(); // 先頭から取る
  ...
}
```

「`pop` vs `shift`」の違いだけで挙動が大きく変わります。

## まとめ

### 重要なポイント

1. **スタックは LIFO、キューは FIFO**
2. **スタックは後入れ先出し（皿積み）、キューは先入れ先出し（レジの列）**
3. **Deque は両端から操作可能で、スタックとキューを包含する**
4. **実装上、キューを配列で素朴に書くと O(N) になるので注意**
5. **BFS はキュー、DFS はスタック（または再帰＝暗黙のスタック）**
