# ヒープと優先度付きキュー（二分ヒープ・ヒープソート）

## 概要

**優先度付きキュー（Priority Queue）** は、「**一番偉いもの**（最大 or 最小）**を素早く取り出したい**」というニーズに応えるデータ構造です。その代表的な実装が **二分ヒープ（Binary Heap）** です。

> **普通のキューは「並んだ順に出す」、優先度付きキューは「偉い順に出す」**

- 普通のキュー: FIFO（並んだ順）
- 優先度付きキュー: 優先度の高い順（例: 最小値優先、締切が早い順）

「全データをソートせずに、毎回 **最大（最小）だけを素早く** 取りたい」というユースケースに最適です。

---

## なぜ重要なのか

「最大／最小を O(log N) で取り出せる」という性質は、多くの実用アルゴリズムの基盤です。

- **ダイクストラ法**（最短経路）: 未訪問で最もコストの低いノードを取り出す
- **プリム法**（最小全域木）: 最も軽い辺から加える
- **ヒープソート**: 全ソートを O(N log N) で達成
- **イベントシミュレーション**: 次に発生するイベントを時刻順で取り出す
- **Top K 問題**: 巨大データから上位 K 件を効率よく選ぶ
- **タスクスケジューラ**: 締切順・優先度順にタスクを実行

「毎回ソートすればいい」と思いたくなりますが、ソートは O(N log N)、ヒープなら挿入 O(log N)・最大取り出し O(log N) と **動的な挿入と取り出しを効率よく両立** できるのが強みです。

---

## 二分ヒープ（Binary Heap）とは

### 定義

二分ヒープは、次の2つの条件を満たす **二分木** です。

1. **ヒープ条件**: 親の値は、その子の値より常に大きい（最大ヒープ）／小さい（最小ヒープ）
2. **完全二分木**: 葉の最下段以外は完全に埋まっていて、最下段も左から詰まっている

### 図で理解する

**最大ヒープ**:

```
         [50]          ← 根が最大値
        /    \
     [30]    [40]      ← 親 ≥ 子
     / \     /  \
   [20][10][35][25]
```

- 根は必ず最大値（最大ヒープの場合）
- 親と子の間には順序関係があるが、**兄弟同士には順序関係がない**（[30] と [40] の大小は自由）

**最小ヒープ**:

```
         [1]
        /   \
      [3]    [5]
      / \    / \
    [8][4] [9][6]
```

### 完全二分木の意味

「完全二分木」とは、**左から順番にぎっしり詰まっている** 状態。

```
完全二分木（OK）:
    [A]
   /   \
  [B]  [C]
  / \   /
[D][E][F]

完全でない（NG）:
    [A]
   /   \
  [B]  [C]
     \    \
    [E]   [F]  ← 左が空いているのに右が埋まっている
```

**なぜこの制約が必要か**: 配列で効率的に表現するため。

---

## 配列表現の魔法

完全二分木は、**配列として隙間なく** 表現できます。木構造を作らなくても配列だけでヒープが実装できるのです。

```
木の図:
             [50]
           index=0
         /         \
      [30]         [40]
    index=1      index=2
     /   \        /   \
   [20] [10]   [35] [25]
  index=3 4    5     6

配列表現:
index:  0    1    2    3    4    5    6
       [50] [30] [40] [20] [10] [35] [25]
```

親子のインデックス関係は単純な式で表せます（0始まりの場合）:

- **親** of index `i` = `(i - 1) / 2`（整数除算）
- **左の子** of index `i` = `2i + 1`
- **右の子** of index `i` = `2i + 2`

```
index=1 (値30) の親: (1-1)/2 = 0 (値50) ✓
index=1 (値30) の左子: 2×1+1 = 3 (値20) ✓
index=1 (値30) の右子: 2×1+2 = 4 (値10) ✓
```

**配列だけで木構造を完全に表現できる** ので、ポインタ不要でメモリ効率も良く、キャッシュ効率にも優れます。

## 基本操作

### 挿入（push）: O(log N)

手順:
1. 新要素を **配列末尾** に追加（完全二分木の右下の空き位置）
2. その要素を親と比較し、ヒープ条件を破っていたら **親と交換**（これを **up-heap / sift up** と呼ぶ）
3. ヒープ条件を満たすまで繰り返す

```
最大ヒープに 45 を挿入:

Step 1: 末尾に追加
         [50]
        /    \
     [30]    [40]
     / \     /  \
   [20][10][35][25]
                  \
                  [45]  ← 末尾

Step 2: 親(25)と比較 → 45 > 25 なので交換
         [50]
        /    \
     [30]    [40]
     / \     /  \
   [20][10][35][45]
                  
Step 3: 親(40)と比較 → 45 > 40 なので交換
         [50]
        /    \
     [30]    [45]
     / \     /  \
   [20][10][35][40]

Step 4: 親(50)と比較 → 45 < 50 なので終了
```

根まで達しても最大 log N 回の交換で済みます。

### 最大の取り出し（pop / extract max）: O(log N)

手順:
1. 根の値を取り出す（これが結果）
2. **末尾の要素を根に持ってくる**（配列の末尾を削除）
3. 新しい根を子と比較し、ヒープ条件を破っていたら **大きい方の子と交換**（**down-heap / sift down**）
4. ヒープ条件を満たすまで繰り返す

```
最大取り出し（50を取る）:

Step 1 & 2: 根を取り出し、末尾(25)を根に
         [25]
        /    \
     [30]    [40]
     / \     /
   [20][10][35]

Step 3: 子(30, 40)のうち大きい方(40)と比較 → 25 < 40 なので交換
         [40]
        /    \
     [30]    [25]
     / \     /
   [20][10][35]

Step 4: 子(35)と比較 → 25 < 35 なので交換
         [40]
        /    \
     [30]    [35]
     / \     /
   [20][10][25]

以下、子がないので終了。
```

### ヒープ化（heapify）: O(N)

既存の配列をヒープに変換する操作。意外なことに **O(N log N) ではなく O(N) で可能** です。

手順: **下から順に sift down する**（葉は既に単独ヒープとみなせるので、内部ノードから処理）。

```javascript
function heapify(arr) {
  const n = arr.length;
  // 最後の内部ノードから根まで
  for (let i = Math.floor(n / 2) - 1; i >= 0; i--) {
    siftDown(arr, i, n);
  }
}
```

### 実装例

```javascript
class MinHeap {
  constructor() {
    this.data = [];
  }

  push(value) {
    this.data.push(value);
    this._siftUp(this.data.length - 1);
  }

  pop() {
    if (this.data.length === 0) return undefined;
    const top = this.data[0];
    const last = this.data.pop();
    if (this.data.length > 0) {
      this.data[0] = last;
      this._siftDown(0);
    }
    return top;
  }

  peek() { return this.data[0]; }

  _siftUp(i) {
    while (i > 0) {
      const parent = Math.floor((i - 1) / 2);
      if (this.data[i] >= this.data[parent]) break;
      [this.data[i], this.data[parent]] = [this.data[parent], this.data[i]];
      i = parent;
    }
  }

  _siftDown(i) {
    const n = this.data.length;
    while (true) {
      const l = 2 * i + 1;
      const r = 2 * i + 2;
      let smallest = i;
      if (l < n && this.data[l] < this.data[smallest]) smallest = l;
      if (r < n && this.data[r] < this.data[smallest]) smallest = r;
      if (smallest === i) break;
      [this.data[i], this.data[smallest]] = [this.data[smallest], this.data[i]];
      i = smallest;
    }
  }
}

const heap = new MinHeap();
heap.push(5);
heap.push(3);
heap.push(8);
heap.push(1);
console.log(heap.pop()); // 1
console.log(heap.pop()); // 3
```

## ヒープソート（Heapsort）

ヒープを使ったソート手法。

### 手順

1. 配列全体をヒープ化（O(N)）
2. 根（最大値）を配列末尾と交換 → ヒープサイズを1減らす
3. 新しい根を sift down
4. サイズが1になるまで繰り返す

### 計算量

- 全体: **O(N log N)**
- **追加メモリ不要（in-place）**
- 最悪・平均・最良すべて O(N log N) で安定

### 他のソートとの比較

| アルゴリズム | 平均 | 最悪 | 追加メモリ | 安定性 |
|---|---|---|---|---|
| クイックソート | O(N log N) | O(N²) | O(log N) | 不安定 |
| マージソート | O(N log N) | O(N log N) | O(N) | 安定 |
| ヒープソート | O(N log N) | **O(N log N)** | **O(1)** | 不安定 |

ヒープソートは最悪ケース保証と省メモリが強み。ただし実際のマシンでは、定数倍が大きくキャッシュ効率も悪いため、クイックソートより遅いことが多い。

## 言語標準の優先度付きキュー

| 言語 | API |
|---|---|
| Python | `heapq`（最小ヒープのみ） |
| Java | `PriorityQueue`（デフォルト最小） |
| C++ | `std::priority_queue`（デフォルト最大） |
| JavaScript | 標準なし（ライブラリを使うか自作） |
| Go | `container/heap` |
| C# | `PriorityQueue<TElement, TPriority>`（.NET 6+） |

### Python の例

```python
import heapq

h = []
heapq.heappush(h, 5)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
print(heapq.heappop(h))  # 1
print(heapq.heappop(h))  # 3
```

最大ヒープが欲しければ値を負にして入れるのが常套手段。

## 典型的な応用

### 1. ダイクストラ法（最短経路）

```javascript
function dijkstra(graph, start) {
  const dist = { [start]: 0 };
  const heap = new MinHeap();
  heap.push([0, start]);

  while (!heap.isEmpty()) {
    const [d, u] = heap.pop();
    if (d > dist[u]) continue;
    for (const [v, w] of graph[u]) {
      const nd = d + w;
      if (nd < (dist[v] ?? Infinity)) {
        dist[v] = nd;
        heap.push([nd, v]);
      }
    }
  }
  return dist;
}
```

「未訪問ノードの中で最もコストの低いものを選ぶ」部分にヒープを使うと、全体を O((N+E) log N) で解けます。

### 2. Top K 問題

「100万件から最大10件を選ぶ」

```javascript
function topK(arr, k) {
  const heap = new MinHeap();
  for (const v of arr) {
    heap.push(v);
    if (heap.size() > k) heap.pop();
  }
  return heap.toArray();
}
```

全ソート O(N log N) より、**O(N log K)** で済む。K が小さいほど得。

### 3. スケジューラ・イベントシミュレーション

「次に発生するイベント（時刻が最小）を取り出す」という処理にぴったり。

### 4. 中央値のストリーム計算

最大ヒープと最小ヒープの2つを使うと、ストリームで中央値を O(log N) ずつ更新できます。

## よくある間違い

### 1. 兄弟同士の順序を期待する

ヒープは親子の順序しか保証しません。中順走査してもソート順にはなりません。**ソートされた順に見たいなら `pop` を繰り返す** のが正しい使い方です。

### 2. 最大ヒープと最小ヒープの取り違え

多くのライブラリは最小ヒープがデフォルト（Python, Java）、一方 C++ は最大ヒープがデフォルト。**仕様を確認せず実装すると逆の結果** になります。

### 3. 要素の更新を軽視

「あるノードの優先度だけ変えたい」は、単純なヒープでは効率的にできません（O(N) で探してから O(log N) で更新）。必要なら **インデックス付きヒープ** や **フィボナッチヒープ** を検討します。実用上は「古い値を無視し、新しい値を再 push する」という遅延削除でしのぐことが多い。

### 4. 「ヒープ」と「ヒープメモリ」の混同

プログラミングで言う「ヒープ」には2つの意味があります。

- データ構造としての **ヒープ**（このページの主題）
- メモリ管理における **ヒープ領域**（動的割り当て用のメモリ）

両者は無関係なので、文脈で判断してください。

## まとめ

### 重要なポイント

1. **ヒープ = 「最大（最小）を素早く取り出せる」特殊な完全二分木**
2. **配列で木を表現でき、実装もシンプル**
3. **挿入・最大取り出しは O(log N)、ヒープ化は O(N)**
4. **優先度付きキューの実装としてデファクト**
5. **ダイクストラ・Top K・スケジューラなど応用範囲が広い**
