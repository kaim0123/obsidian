## 詳しい要約

**テーマ：大規模言語モデルを支えるデータ集め・データ掃除・子守り・教育という泥臭い努力**

大規模言語モデルシリーズ第3回（ゲスト：コトラボの李さん）。巧妙なアイデアの裏で、大規模言語モデルは Web 全体のデータの収集と粗悪な文章の除去、学習中の24時間体制の監視（子守り）、人手で作った指示と回答による教育（ファインチューニング）といった地道な作業に支えられている。結論は「一見本質的でない地道な努力こそ本質的」ということ。

---

### データ王「Common Crawl」

- 学習データの候補として Wikipedia（日本語版全体で約30GB）、Yahoo!知恵袋、X などが挙がるが、量が足りなかったり品質が低かったりする
- 答えは「**Web上の文章すべて**」。非営利団体 **Common Crawl** が Web 全体をクロールしてデータ化し、公式サイトから配布している
- 目的はイノベーションの加速で、研究者・開発者はみなお世話になっている。データ集めで挫折する人がいなくなった（ワンピースのゴール・D・ロジャーより親切）

### 粗悪な文章の混入と除去

- 自動生成ブログなどによる、一見意味がありそうで意味のない文章（「カフェめぐりや観光地の食べ歩き…」）が混入しており、学習の敵になる。粗悪な AI が作った文章が次の AI 作りを邪魔するという皮肉
- 李さんの研究仲間内ではこの種の文章を「ランボー怒りのプロパンガス」と呼んでいる
- よく使われる手法は、数単語の範囲での文章の自然さを判定するもの。この種の文章は局所的には自然なので**弾けない**ことが多い（言語処理学会の論文でも指摘）
- 他の粗悪データは**人がルールを書いて**除く。例：SEO 対策で名詞を羅列したページは「名詞が9割以上なら除外」、広告文まみれのページ、スパムに多い「バイアグラ」の出現回数で判定するなど
- データを観察してはルールを何十種類も作るのが泥臭い。データサイエンス全般でも**前処理が9割**（企業の Excel データは日付の書式や年齢の単位がバラバラ）

### 学習中の「子守り」

- 大量の GPU を同時に動かすため、どこかが突然壊れるなどのトラブルが起き、学習を24時間体制で見守って対処する必要がある
- 実際に「**ベビーシッティング**」という用語があり、Meta は80日間見守ったログを公開している
- 確定的なはずのコンピュータでも、ハードウェアの故障や通信障害などで失敗が起こる

### 教育（ファインチューニング）

- Web の文章を学習しただけでは、それらしい文章を続けられるだけで、質問に対して望ましい形で答えるとは限らない（「格差はなぜ縮まらないのか」に対して怒りの投稿のような続きを出しうる）。反社会的な発言も困る
- 「こう聞かれたらこう答える」という指示と回答のペアを**約1万件、人手で作成**して学習させる（例：「1匹を『いっぴき』と数えるのに2匹を『にぴき』と数えない理由」に対する模範解答）
- 作成は、丁寧なマニュアルを整備したうえで、主婦の方などにお願いすることもあった
- 周りの言葉を浴びる赤ちゃん期（子守り）の後に学校教育を受けるようで、堀元は「かわいい」と感じたが、水野と李さんは「数値の組にすぎない」と一蹴

### 泥臭い努力こそ本質

- 日本語コーパスを作った丸山岳彦先生の、文字をひたすら数える作業（アルバイトも動員）を思い出させる
- 東浩紀『ゲンロン戦記』：「一見本質的でないことこそ本質的で、本質的なことばかり追求すると新しいことは実現できなくなる」。社員の使い込みを何度も経験した末に「人間はやはり地道に生きねばならん」と気づき、自ら領収書を打ち込んだ話
- 単語ベクトルのようなアイデアだけでなく、1万件の指示を人手で書くような努力がなければ ChatGPT の精度は出ない

### まとめ

- 学習データは Common Crawl が提供する Web 全体だが、粗悪な文章の除去には人手のルール作りが欠かせず、完全には除けない
- 学習中は24時間の「子守り」、学習後は人手で作った約1万件の指示・回答による「教育」が必要
- 大規模言語モデルは巧妙なアイデアと、泥臭い地道な努力の両方の上に成り立っている
