## 要約

Python は **特別に速いわけでも、特別に強力なわけでもない** のに、AI・機械学習の世界で **研究コミュニティの共通語** になった。本動画は、1989 年の誕生から 2020 年代の AI ブームまで **30 年の歴史** をたどり、技術力だけでなく **タイミング・コミュニティ・設計思想** が噛み合った結果として Python が頂点に立った理由を解説する。

### テーマ：なぜ Python なのか

- 世界中の AI 研究者が国籍に関係なく **Python で論文のコードを書き、GitHub で公開** している——英語が学術の共通語であるのと同様のイメージ。
- C や Java のような歴史ある言語もあったが、Python が選ばれたのは **単純な性能比較だけでは説明できない**。
- 実力がゼロなら話にならないが、**同程度の実力を持つ選択肢の中で、先に生態系を築いた方が勝つ** という構図が決定的だった。

### 誕生とグイド・ヴァン・ロッサム

- **1989 年のクリスマス休暇**、オランダ人プログラマー **グイド・ヴァン・ロッサム** が暇つぶしで開発を開始。企業プロジェクトではなく **完全な個人の趣味** から始まった。
- 前身は教育用言語 **ABC**。ABC の **読みやすさ重視** の思想を継ぎつつ、制限を取り除いた言語を目指した。
- **1991 年** に最初のバージョンが公開。
- グイドの哲学：**「コードを書く時間より読む時間の方が長い」** → **読みやすさを最優先**。
- **インデント（字下げ）の強制**：中括弧 `{}` の代わりにスペースでブロックを表現。最初は不便に感じるが、全員が同じルールで書くため **スタイルが統一され、結果的に読みやすくなる**。
- 名前の由来：蛇ではなくイギリスのコメディ **「モンティ・パイソン」**。
- グイドは **BDFL（Benevolent Dictator For Life＝慈悲深き終身独裁者）** としてコミュニティの最終決定権を長年保持。**2018 年** にその座を退き、Python は **コミュニティによるガバナンス** に移行した。

### 「バッテリー付属」と科学計算エコシステム

- Python のスローガン **「Batteries Included（バッテリー付属）」**＝最初から使える標準ライブラリが揃っている。
- 科学計算で本当に革命が起きたのは **2000 年代の外部ライブラリの充実**：
  - **1995 年**：Jim Hugunin が **Numeric**（数値計算）を作成 → 後に Travis Oliphant らが **NumPy** として統合整備。
  - **2001 年**：**SciPy**（科学技術計算）、**IPython**。
  - **2003 年**：**Matplotlib**（グラフ描画）。
  - **2010 年**：**scikit-learn**（機械学習）v0.1 リリース。
- **NumPy の核心**：裏側は **C で書かれた高速コード**、表向きは **Python の簡潔な書き方** で操作——「外見は Python、中身は C」。
- **2011 年**：**IPython Notebook** 登場 → **2014 年** に **Jupyter** として独立。コードを書いてすぐ実行し、結果・メモを同じ画面に残せる **対話的な実験環境** が研究者に刺さった。
- 計算・可視化・機械学習が **すべて Python で完結** する環境が 2010 年代前半に整い、**Python から離れる理由がなくなった**。

### Python 2 → 3 の大混乱（黒歴史）

- **2008 年**：**Python 3.0** リリース。**Python 2 との後方互換性を意図的に切り捨て**。
- Python 2 には設計上の欠陥があり、直すには過去を切り捨てるしかなかった（グイドの言い分）。
- 現場は混乱：大量のライブラリ・企業システムが Python 2 のまま。**依存関係の鎖** により個別移行が困難。
- 移行完了まで **約 10 年**。Python 2 のサポート終了は **2020 年 1 月 1 日**。
- 混乱の大きさ自体が **Python が社会に深く組み込まれていた証拠**。
- それでも R や MATLAB への完全な乗り換えには踏み切れなかった——**汎用的な科学計算の生態系** として Python が頭一つ抜けていた。

### 2012 年：深層学習の爆発と AlexNet

- **2012 年**、画像認識コンテスト **ImageNet** で **AlexNet** が従来手法を圧倒的な差で打ち破った → **ディープラーニングが実用になる** と証明された瞬間。
- 世界中の AI 研究者がこの分野に殺到。**急いでモデルを作って試したい** 研究者にとって、**ライブラリが最も揃っていたのが Python** だった（先行者利益）。
- 当時の AI 研究者の多くは **コンピュータサイエンスより数学・統計** が専門。**数学の記法に近い書き方** でコードが短く読みやすい Python が、**プログラマー向け言語ではなく「何かを実現するためのツール」** として選ばれた。

### グルー言語としての Python

- Python は **グルー言語（glue language＝接着剤言語）** とも呼ばれる——**いろんな部品をつなぎ合わせる** のが得意。
- 重い計算は **C など高速なコードに任せ**、全体の流れを Python が束ねる。
- **2015 年 11 月**：Google が **TensorFlow** をオープンソース公開。自社の DistBelief 経験を活かした再設計。**Python 向けインターフェイスを全面に** 出してリリース → Python と AI の結びつきがさらに深化。
- **2017 年 1 月**：Facebook AI 研究チームが **PyTorch** を公開。
  - TensorFlow：計算グラフを **事前定義してから実行** → デバッグがしにくい不満。
  - PyTorch：**実行しながらグラフが構築される** 方式 → Python らしいインタラクティブな使い方で研究者に好評。
- どちらを選んでも **自動的に Python を選ぶ** ことになり、**Python を経由しないと AI の最先端が使えない** 状態が固定化した。

### GPU 革命——影の立役者

- 深層学習を爆発させた **影の立役者は GPU**（もともとゲームのグラフィックス用）。
- GPU は **大量の計算を並列処理** できる特性がニューラルネットワークの学習に完璧にはまった。
- **2007 年**：NVIDIA が **CUDA** を公開し、GPU を **汎用計算（GPGPU）** に使える道を開いた。
- 深層学習モデルは **行列演算の塊** で、GPU は行列演算が得意。**CPU だけなら数週間かかる訓練が数時間** に短縮されるレベル。
- NumPy・TensorFlow・PyTorch も **GPU 上で動く計算の指示を Python から出せる**。
- 比喩：**Python は現場監督**——自分は速く動けないが、GPU 何千個の「作業員」に的確な命令を飛ばす司令官。実際の計算は **C や CUDA** が担当。

### AI の民主化とネットワーク効果

- **2010 年代後半** から **「AI の民主化」**——専門知識がなくても使えるツールが増加。その窓口のほとんどが Python。
- **Google Colab**：ブラウザだけで Python を書き、**無料で GPU** が使える。
- **Hugging Face**：NLP 分野の学習済みモデルを簡単に利用可能。
- **Kaggle**：データサイエンスのコンテストを Python で楽しめる場。
- 大学の **データサイエンス入門** も Python が世界標準に。理系だけでなく文系の学生も触るようになった。
- **ネットワーク効果**：使う人が多い → ライブラリ・教材が増える → さらに使いやすくなる（雪だるま）。
- **2020 年代**：GitHub の AI 関連コードの大半が Python。論文の実装も基本的に Python → **後から入る人が選択の余地なく Python を学ぶ** 状態。

### 「Python は遅い」のに許される理由

- 単純な処理では C などと比べ **10〜100 倍遅い** ことがある——それでも最先端 AI 開発に使われている。
- **何が遅いのかが重要**：
  - AI 学習で時間がかかる **行列演算・微分計算** は NumPy・TensorFlow 等が担い、実際には **C や CUDA** が動いている。
  - Python が書いているのは **「何をするか指示する部分」** の大半。重い計算は別言語に委譲 → **遅さがボトルネックにならない設計**。
- **開発速度**：C や Java より **大幅に短いコード量** で同じことが書ける。研究者にとって **プログラムの実行速度より、アイデアを早く試せる速度** が命（試行錯誤の繰り返し）。
- **GIL（Global Interpreter Lock）**：Python インタプリタが **同時に 1 スレッドしか実行できない** 制約 → マルチコア CPU をうまく使えない弱点。
  - ただし **GPU 利用時は GPU 側で並列処理** するため GIL がボトルネックになりにくい——弱点を GPU が補っている。
- 結論：**「Python は遅いけれど、うまく使えば（全体としては）速い」**——批判されながらも勝ち続ける技術的理由。

### 30 年の積み重ね——まとめ

| 要因 | 内容 |
|------|------|
| **設計思想** | 読みやすさ重視。研究コードは「書くより読んで理解・改良する」作業が多く、Python が向いていた |
| **科学計算ライブラリ** | NumPy → SciPy → scikit-learn と、深層学習ブーム **前に** 生態系が整っていた |
| **グルー言語** | C/CUDA/GPU など高速な部品を Python が束ねる柔軟性 |
| **先行者利益** | 2012 年の深層学習爆発時、すでに道具が揃っていた |
| **論文→コード→学習の連鎖** | 研究者が Python で公開 → 他者が再現のため Python を学ぶ → さらに増える |
| **TensorFlow / PyTorch** | 両方とも Python 前提 → 乗り換えコストが天文学的に |
| **オープンソースコミュニティ** | 30 年かけて積み重なった必然 |

- **1 番優れたものが勝つとは限らない**——偶然と必然が混ざり合った物語。
- 1989 年の **1 人の男のクリスマスの暇つぶし** から始まり、コミュニティが育て、ライブラリが揃い、ブームが来て、ようやく頂点に立った。
- **挑戦者**（Julia など）も存在するが、Python の覇権が崩れるかは今後の話として次回予告。
