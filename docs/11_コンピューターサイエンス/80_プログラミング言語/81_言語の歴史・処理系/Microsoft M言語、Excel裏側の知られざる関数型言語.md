不変性（イミュータブル）：let SourceData = ... と一度宣言したら変更不可。  
遅延評価（lazy evaluation）：必要になるまでコードを実行しない。  
テーブルがファーストクラス：表が数値や文字列と同じく第一級の値。  
純粋関数主義：副作用なし、同じ入力→同じ出力。

## 詳しい要約

**テーマ：Excel／Power BI の裏で 2 億人が無意識に動かす関数型言語「M 言語」**

世界で最も使われている関数型言語は Haskell や F# ではなく、Excel と Power BI の Power Query の裏で動く **M 言語（Power Query M Formula Language）** だ。Microsoft は「言語の存在を隠す」逆張り戦略で関数型を業務の世界に浸透させた。業界の知名度と実際の普及は大きくずれており、本物の革命は目立たない場所で起きる、というのが結論。

---

### 序章・第1章 M 言語とは何か

- 利用規模：Microsoft 365 の Excel 法人有料ユーザーは世界で **2 億人以上**、Power BI Desktop は数百万人。全員が毎日 M を実行しているが、多くの人はそれを「Excel」と呼んでいる。
- 一方で関数型コミュニティではほぼ無名。Haskell や Scala の本は山ほどあるが、M の本は世界で数冊。
- 2010 年に Power Query と一緒に発表。当時の Excel は外部データの取り込み・整形が弱く、VBA マクロか SQL との併用しかなかった。
- 「業務担当者にコードを書かせない」＝ **GUI の裏で自動生成される言語**として設計。
- 「データの取得と変換（Get & Transform）」→ Power Query エディタで列の分割・行の削除・型変更をクリックすると、1 操作ごとに M コードが生成され、最後に **Mashup エンジン**（M の実行エンジン）がデータソースから取得・変換して結果を返す。

### 第2章 F# から生まれた関数型言語

- 設計ベースは **F#**（Microsoft が 2005 年に公開、OCaml に着想を得て CLR 上で動く）。M は F# のデータ処理特化の派生で、本家の数千倍の規模で普及した。
- 4 つの特徴：

| 特徴 | 内容 |
|---|---|
| 不変性（immutable） | `let` で一度宣言した変数は変更不可。変えたければ新しい変数を作る |
| 遅延評価（lazy evaluation） | 結果が必要になった瞬間に、必要な部分だけ評価（Haskell や Spark に近い） |
| テーブルがファーストクラス | 表が数値や文字列と同じ第一級の値。代入・返り値・入れ子が自由 |
| 純粋関数 | 副作用なし、同じ入力に同じ出力。グローバル変数の変更や外部状態の読み取りを言語で禁止 |

- 見た目は業務ツールだが、中身は**教科書通りの関数型言語**。

### 第3章 言語を隠して普及させた 3 つの逆張り戦略

1. **言語の存在を隠す**：M をプログラミング言語としてではなく、Excel のデータ準備用 GUI ツールとして売った。学ばなくても使える。
2. **必要な人にだけ深いレベルを開放**：数式バーと詳細エディタで生成済み M コードを直接編集できる。業務担当者とエンジニアが同じツールで共存し、段階的にレベルアップできる。
3. **関数型の利点を体験として提供**：10 ステップの整形手順でステップ 5 を直すと、6〜10 が自動で再実行される。各ステップが前の結果だけに依存する**純粋性**があるから、安全に途中から差し替えられる。
- 「最高の言語は、ユーザーが言語を使っていることを忘れる言語」。

### 第4章 Query Folding：M が自動で SQL に翻訳する仕組み

- 書かれた M コードを、データソース側の SQL や独自クエリ言語に**自動翻訳**する機能。
- 例：SQL Server の 100 万行の売上から「10 万円以上・日本のみ」を抽出する場合、素朴な実装では全件をダウンロードしてメモリ上で絞るので遅い。Query Folding ではフィルタを **WHERE 句**に変換してサーバー側で実行し、必要な数行だけが届く。
- コンパイラがソース側で実行できるかを自動判定し、SQL Server・Oracle・PostgreSQL など各方言に変換。できなければ Mashup エンジン内で実行。
- 効くかどうかは M の書き方に依存（特定の関数で効かなくなる、順序を変えると効く）。ここに**エンジニアの専門領域**がある。

### 第5章 知名度と実態のずれ、隠れた革命

- **知名度は技術の本質と関係ない**：ユーザー数で M は Haskell の数千倍。業界の話題と実際の使用は極端にずれうる。
- **関数型は適切なパッケージングで業務に浸透できる**：「関数型は難しく業務人材には無理」という常識への反証。
- **本物の革命は目立たない場所で起きる**：2010〜2026 年、M は静かに業務界の関数型化を進めてきた。
- 2026 年の AI エージェント時代：Copilot for Excel は自然言語の指示を M コードに変換して実行する。ユーザーは言語の存在をさらに意識しなくなる。
- 「SQL は業界で最も書かれているコード、M は最も実行されている関数型コード」。

### まとめ

- M 言語は F# 派生の純粋・遅延評価・不変な関数型言語で、Excel／Power BI の裏で 2 億人規模で動いている。
- 普及の鍵は「言語を隠す」「段階的に開放する」「関数型の利点を体験で渡す」という逆張り戦略。
- Query Folding により GUI 操作が自動でデータソース側の SQL に翻訳され、高速に実行される。
- 最も影響力のある言語が、最も話題になる言語とは限らない。
