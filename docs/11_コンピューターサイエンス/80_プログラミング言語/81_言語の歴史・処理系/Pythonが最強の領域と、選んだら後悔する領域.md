## 詳しい要約

**テーマ：Python の適材適所 ―「できる」と「適している」は違う**

Python は万能ではなく、データ分析・機械学習・自動化では最強だが、実行速度・モバイル・フロントエンド・大規模開発では別の言語を選ぶべき。大事なのは「Python でできるか」ではなく「Python が適しているか」で判断し、目的に合わせて次の言語を学ぶことだと説く。

---

### 第1章 Python が得意な領域

- **データ分析・機械学習**：NumPy、pandas、scikit-learn、TensorFlow、PyTorch などエコシステムが圧倒的。論文のサンプルコードも Python が多く、デファクトスタンダード。
- **スクリプト・自動化**：ファイル一括処理、Excel 操作、定期バッチなど。シンプルな構文で数行で動く。
- **プロトタイピング**：コンパイル不要、型宣言不要でコード量が少なく、アイデア検証が速い。
- **教育・入門**：構文がシンプルで環境構築も比較的楽。

### 第2章 Python が苦手な領域

- **実行速度**：インタプリタ言語のため C や Rust より 10〜100 倍遅いこともある。リアルタイム処理・ゲームエンジン・組み込みには C/C++/Rust。
- **モバイルアプリ**：Kivy や BeeWare はあるが成熟しておらず、iOS は Swift、Android は Kotlin が素直。
- **フロントエンド**：ブラウザは JavaScript/TypeScript の世界（React・Vue・Angular）。PyScript は実用段階ではない。
- **大規模開発**：動的型付けのため、数万〜数十万行になると変数の中身や引数が分からなくなり、リファクタリングで壊れた箇所を見つけにくい。型ヒント（3.5 以降）は強制ではなく、チームで徹底しないと混在する。

### 第3章 Python が微妙な領域

- **Web バックエンド**：Django・FastAPI で小規模なら十分だが、大量リクエストでは Go や Node.js の方が性能が出やすく、スケール時にサーバー台数が増えがち。
- **ゲーム**：Pygame で簡単なものは作れるが、商用なら Unity や Unreal Engine。学習用にはあり。
- **デスクトップアプリ**：Tkinter などはあるが見た目が今ひとつ。モダンなものは Electron や各 OS のネイティブ言語。

### 第4章 なぜ「何でもできる」と思われるのか

- ライブラリが豊富で、入れればたいていのことは「できる」。
- 入門者が最初に触る言語なので「プログラミング＝Python」という感覚になり、他言語と比較できず弱点に気づけない。

### 第5章 Python の次に学ぶべき言語（目的別）

| 目的 | 言語 |
|---|---|
| 実行速度・安全性 | Rust（C++ の代替として注目） |
| バックエンド・インフラツール | Go（Google 製、シンプルで速い） |
| フロントエンド | TypeScript 一択 |
| モバイル | Swift（iOS）/ Kotlin（Android）、両方なら Flutter・React Native |

### まとめ

- Python は得意領域では最強、苦手領域では遠回り。
- 「できる」ではなく「適している」で言語を選ぶ。
- 1 つの言語に固執せず、Python で機械学習＋TypeScript でフロントのように組み合わせる。
