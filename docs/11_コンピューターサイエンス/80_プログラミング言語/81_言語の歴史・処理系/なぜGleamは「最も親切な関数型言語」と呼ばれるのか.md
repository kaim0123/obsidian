## 詳しい要約

**テーマ：関数型言語Gleamの設計哲学「親切さ」とその背景**

Gleamは2024年に1.0が出たばかりの関数型言語だが、2025年Stack Overflow調査の「最も称賛される言語」で初登場2位となった。作者ルイス・ピルフォールドの「エンジニアのストレスを減らしたい」という哲学が、親切なエラーメッセージ・小さな言語仕様・一体化したツールチェーンとして実装され、BEAMの信頼性とML系の型安全性を両立している。言語設計の判断軸が「実装のしやすさ」から「使う人への親切さ」へ移りつつあることを象徴する言語、という話。

---

### 第1章 ルイス・ピルフォールドの人生

- ロンドンで生物学を学んでいたが中退し、プログラミング本を1冊買って独学。C言語で挫折後、MITのオンラインコースで学び、Ruby で職業エンジニアに、Haskell で関数型を知る
- 11歳のとき母親に演劇クラスに入れられ、「人前で話すこと」「人の気持ちを考えること」を学んだ経験が、後の設計思想に影響
- Elixir 1.0（2014年）後、Erlang仮想マシン **BEAM** のコミュニティに深く関わり、ツール（ドキュメント生成・フォーマッタ関連）にも貢献
- しかし Elixir は **動的型付け** で、大規模コードでは本番デプロイ後に型の不一致によるクラッシュが頻発 → 「BEAMのランタイムにML言語の型システムを組み合わせられないか」
- 2016年、カンファレンス発表用のプロトタイプがGleamの起源

### 第2章 「親切さ」を3つの設計選択で実装

1. **人間に話しかけるエラーメッセージ**：Haskellの専門用語だらけのメッセージと違い、何が間違っていてどう直せばいいかを人間の言葉で書く。優しいエラーメッセージで知られる **Elm** の哲学を継承
2. **言語の表面積を極小に**：「午後1日で全部学べる」が設計目標。キーワードは数十個、主要構文はほぼ1ページに収まる。それでも代数的データ型・パターンマッチング・関数などは揃っている
3. **ツールチェーンの一体化**：コンパイル・フォーマット・テスト・依存解決・LSP起動がすべて `gleam` コマンド1つに入り、バイナリを1つダウンロードするだけで書き始められる（JSならnpm・ESLint・Prettier・Jest…と別々）
- コンパイラは **Rust** で実装。本人いわく「RustはMLとCを足したような言語で、MLとシンプルさが好きな自分には最高の道具」

### 第3章 WhatsAppを支えるBEAMという土台

- BEAM は1986年、Erlang とともにスウェーデンの **エリクソン** が電話交換機用に開発。「止まらないこと」が設計の中心
- 強み：
  1. **軽量プロセス**：1台で数百万プロセスを同時に動かせる
  2. **アクターモデル**：プロセス同士はメモリを共有せずメッセージで通信し、共有メモリの競合を根本から消す
  3. **Let it crash 哲学**：致命的エラーのプロセスは潔く終了させ、監督（スーパーバイザー）プロセスが再起動してシステム全体は動き続ける
- 代表例 **WhatsApp**：2009年時点で社員55人で4億5000万ユーザー（数字は動画内の発言どおり）
- Erlang・Elixir は動的型付けだが、Gleam は **コンパイル時に型チェック** し、Erlangソースに変換してBEAMで実行。さらに **JavaScriptにもコンパイル** でき、フロントもバックも1言語で書ける

### 第4章 Stack Overflow初登場2位、業界を超えた広がり

- 2024年3月 v1.0 リリース（本番対応宣言）
- 2025年4月、ThoughtWorks の Technology Radar で「Assess」に選出
- 2025年 Stack Overflow 調査「最も称賛される言語」で初登場2位、ユーザーの70%が使い続けたいと回答
- Gleam 開発者の大半は Erlang/Elixir 出身ではなく、**TypeScript・Python・Rust・Go** から来ている → BEAM コミュニティ内ではなく業界全体の関数型ファンを引き寄せている
- 作者は「関数型言語に挫折した人にこそもう一度試してほしい」と語る

### 第5章 言語設計の判断軸が「親切さ」に移る時代

- 2026年の日本では業務利用・求人・書籍・コミュニティはほぼない。それでも触る価値は大きい：
  1. **関数型の最高の入り口**：Haskell や OCaml で挫折した人でも半日で動かせ、パターンマッチングや変数不変性などのエッセンスを体験できる
  2. **言語設計の最前線を学べる**：設計者の哲学が明確で、「なぜその選択か」が読み取れる教科書
  3. **早期に触れる経験** が数年後の差別化になりうる
- 1965年、トニー・ホーアは「実装が楽だから」と null を入れ「10億ドルの過ち」となった。60年を経て判断軸は「使う人への親切さ」へ
- Rust・Kotlin・Swift・TypeScript も、エラーメッセージの親切さやツールチェーン一体化の方向に進化している

### まとめ

- Gleamは「BEAMの信頼性 × ML系の型安全性」を1つにした関数型言語で、JSにもコンパイルできる
- 親切さは、エラーメッセージ・言語の小ささ・ツールチェーン一体化という具体的な設計に表れている
- 業務利用はまだ少ないが、関数型の入門や言語設計を学ぶ題材として価値が高く、「親切さ」は今後の言語設計全体の潮流
