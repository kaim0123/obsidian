## 要約

**JavaScript** は 1995 年に **たった 10 日間** で生まれた言語が、ブラウザ戦争・標準化・ライブラリ革命・サーバー進出を経て、今や **Web 開発の中心言語** になった軌跡を解説する。Java との混同、設計上の歴史的経緯、そして Node.js 以降の「どこでも動く言語」への変貌が主題。

### テーマ：10 日の奇跡から世界基盤へ

- JavaScript と Java は **名前が似ているだけで全く別物**（カレーとカレーパンの関係）。
- 1995 年当時の Web は **静的な HTML 文書** しかなく、ページを「見るだけ」で動かせなかった。
- ネットスケープが Web に動きをつける言語を求め、**ブレンダン・エイヒ** に開発を依頼。
- 最初のプロトタイプを **10 日間** で完成——この急造が後の **設計上の不統一**（型変換、スコープなど）の遠因にもなった。

### 誕生と名前の変遷（1995 年）

- **1995 年**：インターネット普及初期。Netscape Communications が **ブラウザ内で動くスクリプト言語** の開発を開始。
- 開発者：**ブレンダン・エイヒ（Brendan Eich）**。
- 言語名の変遷：**Mocha** → **LiveScript** → **JavaScript**。
- 最終名称は当時大人気だった **Sun Microsystems の Java** の人気に便乗するマーケティング戦略——**Java とは無関係** だが名前だけ借りた。
- 当初の目的は **Web ページの簡単な装飾・動的処理** に留まっていた。

### ブラウザ戦争と標準化（1990 年代後半）

- **Netscape Navigator** と **Microsoft Internet Explorer** がシェア争い——いわゆる **ブラウザ戦争**。
- Microsoft は IE を Windows に **標準搭載** し、Netscape の JavaScript を模倣した **JScript** を独自実装。
- ブラウザごとに **微妙に動作が異なる** 地獄——「Netscape では動くが IE では動かない」が日常化。
- **1997 年**：**ECMA International** により **ECMAScript** として標準化——「JavaScript はこう動くべき」というルールブック。
- 標準化だけでは解決せず、特に **IE6（2001 年リリース）** が長期間（約 6 年）アップデートされず、**高シェアの古い実装** に開発者が合わせざるを得ない **クロスブラウザ対応地獄** が続いた。

### jQuery と Ajax——リッチ Web アプリの時代（2000 年代）

- **2006 年**：**jQuery**（ジョン・レシグ作）登場——**「Write Less, Do More（少ないコードで多くを実現）」**。
- ブラウザ差異を吸収し、`$()` 記法で **1 行のコード** がどのブラウザでも動くように。
- **2010 年代初頭** には世界中の Web サイトの **半数以上** が jQuery を使用。
- **Ajax**（Asynchronous JavaScript and XML）：**ページ全体をリロードせず** サーバーと通信する技術。
  - 技術自体は 1999 年頃から存在。
  - **2005 年** に Google が **Gmail・Google Maps** で本格採用し一気に普及。
- **Web 2.0** 時代：Web が「見る場所」から「ユーザーが参加して情報を作る場所」へ——YouTube、Twitter、Facebook などが登場。
- JavaScript は装飾用から **本格的な Web アプリケーション開発言語** へと地位を確立。

### Node.js 革命——ブラウザの外へ（2009 年）

- **2009 年**：**Node.js**（ライアン・ダール作）登場——JavaScript 史上最も革命的な出来事の一つ。
- それまで JavaScript は **ブラウザ内でのみ** 実行可能だった。
- Node.js により **サーバーサイド（バックエンド）** でも JavaScript が動くように——**フルスタック JavaScript** が可能に。
  - フロントエンド（ブラウザ側）とバックエンド（サーバー側）を **同じ言語** で書ける。
- **非同期 I/O・イベント駆動** モデル：大量のリクエストを効率的に処理——チャットアプリやリアルタイム通信に最適。
- **npm**（Node Package Manager）：JavaScript パッケージ管理ツール。現在 **200 万超** のパッケージ——世界最大のレジストリ。
- Netflix、PayPal、LinkedIn、Uber など大企業もサーバーサイドに JavaScript を採用。
- 用途は Web を超え **モバイル（React Native）・デスクトップ（Electron）・IoT** まで拡大。

### モダン JavaScript——ES6 以降（2010 年代〜）

- **2015 年**：**ES6（ECMAScript 2015）** 大型アップデート——言語を劇的に書きやすく。
  - `let` / `const`、アロー関数、クラス構文、`import` / `export` など。
- 以降 **毎年アップデート** される **Evergreen（常緑）** モデルへ。
- **フレームワーク戦国時代**：
  - **React**（2013 年、Facebook）：コンポーネントベース UI。現在最も人気。
  - **Angular**（2010 年、Google）：フル機能の大規模向けフレームワーク。企業アプリで多用。
  - **Vue.js**（2014 年、エヴァン・ユー個人開発）：シンプルで学びやすい。中国を中心に人気。
- **SPA**（Single Page Application）：技術的には 1 ページだが、リロードなしでコンテンツ切り替え——YouTube、Gmail などが代表例。
- **TypeScript**（2012 年、Microsoft）：JavaScript に **型システム** を追加。大規模開発では事実上の標準に。
- 新ツール・フレームワークの乱立により **JavaScript Fatigue（JavaScript 疲れ）** という言葉も生まれた。

### 現在と未来

- GitHub で **最も使われているプログラミング言語** の一つ。Stack Overflow 調査でも上位。
- **Next.js** など **メタフレームワーク** の登場で開発効率がさらに向上。
- **WebAssembly** との連携も進み、可能性は拡大中。
- **わずか 10 日で生まれた言語** が、30 年近く経った今も **世界中の Web を支える基盤技術** として進化を続けている。
