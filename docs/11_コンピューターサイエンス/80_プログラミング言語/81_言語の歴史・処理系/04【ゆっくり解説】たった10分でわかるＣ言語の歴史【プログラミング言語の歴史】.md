## 詳しい要約

**1972 年** にベル研究所の **デニス・リッチー** が誕生させた C 言語は、名前の通り **A 言語 → B 言語** の系譜を受け継ぎ、**Unix** 開発の実用ニーズから生まれた。**データ型とポインタ** による効率的なメモリ制御、**K&R C** による事実上の標準化、**ANSI C / ISO C** による公式標準化を経て、**50 年以上** にわたり OS・組み込み・DB・ゲームエンジンなどの基盤として現役を続けている。本動画は、誕生の背景から標準の変遷、後続言語への影響、現代の用途と Rust などの挑戦者までを **約 10 分** で俯瞰する。

### テーマ：なぜ C なのか

- プログラミング入門では Python や JavaScript から始める人も多いが、**コンピュータの仕組みを深く理解する** なら C は依然として重要。
- C の名前は成績の「C」ではなく、本当に存在した **A 言語・B 言語** の続き——プログラミング言語史の中核を担う **「すべての言語の母」** 的存在。
- **D 言語** も実在するが、本編の焦点は C の **壮大な歴史**。

### 誕生の背景：1960〜70 年代のコンピュータ

- **1960 年代〜70 年代初頭**：コンピュータは **メインフレーム**（部屋全体を占める大型機）が主流で、非常に高価。
- 当時のプログラミングは **アセンブリ言語や機械語** が中心——**低レベル**（ハードウェアに近い）な作業で、内部構造を詳しく知らないとコードが書けなかった。
- **1970 年頃**、AT&T **ベル研究所**（ノーベル賞級の最先端研究機関）で、**デニス・リッチー** と **ケン・トンプソン** が **Unix オペレーティングシステム** の開発に着手。
- Unix 開発では当初 **B 言語**（BCPL の改良版）を使用していたが、**型の概念が弱く文字しか扱えない** など限界があった——数字も文字として扱うしかなく **計算が非効率**。

### 1972 年：C 言語の誕生と革新

- **1972 年**、リッチーが B 言語を改良して **C 言語** を設計。
- **最大の革新：データ型の導入** —— `int`（整数）、`char`（文字）、`float`（浮動小数）などを **明確に区別** し、効率的な計算を可能にした。
- **ポインタ** の導入——データが **メモリのどこにあるか** を示す概念。メモリを **直接操作** でき、高速なプログラムが書けるようになった。
- C は **高レベルな表現力** と **低レベルなハードウェア制御** の両立を目指した言語として設計された。

### K&R C と 1980 年代の爆発的普及

- **1978 年**、リッチーと **ブライアン・カーニハン** が著書 **『The C Programming Language』** を出版——通称 **K&R C**。
- 事実上の **C 言語の仕様書** となり、多くのプログラマーの **バイブル** に。わずか **32 個のキーワード** で学習しやすい **シンプルかつ強力** な言語だった。
- **1980 年代** に C は爆発的に普及。理由は主に **3 つ**：
  1. **移植性（ポータビリティ）** —— 異なるコンピュータでも動かしやすい（当時は機種ごとに言語が違うことが多かった）。
  2. **効率性** —— アセンブリに近い **高速なコード** を生成。組み込み・システムプログラミングに最適。
  3. **表現力** —— 高レベル記述と低レベル制御の **両立**。

### 標準化：ごちゃ混ぜから世界標準へ

- 1980 年代後半、各メーカーが **独自拡張** を追加し **ごちゃ混ぜ（方言だらけ）** の問題が発生。
- **1989 年**：**ANSI**（米国国家規格協会）が **ANSI C（C89）** を制定。
  - 主な改良：**関数プロトタイプ**、新ライブラリ関数、**`const` 修飾子**、構造化された **プリプロセッサ** の改良。
- **1990 年**：**ISO**（国際標準化機構）が **ISO C90** として採用し **世界標準** に。
- 標準化により C は真の意味で **ポータブルな言語** となった。

### 標準の進化：C99・C11・C23

| 標準 | 時期 | 主な新機能 |
|------|------|------------|
| **C99** | 1999 年 | インライン関数、可変長配列（VLA）、`//` 一行コメント、`_Bool`、**複素数型**（科学技術計算・信号処理向け） |
| **C11** | 2011 年 | **マルチスレッド** サポート、構造体の匿名メンバ、`_Generic` 総称マクロ、境界チェック付き関数 |
| **C23** | 2023 年 | ビット演算の標準ライブラリ追加など。**C++ との互換性** 向上も進行中 |

- プログラミング言語は **生き物のように進化し続ける**——「もう完成」と思われがちでも標準は更新される。

### 後続言語への影響

- C の設計思想（特に **中括弧 `{}` によるブロック構造**）は多くの言語が継承：
  - **C++** —— C に **オブジェクト指向** を追加。
  - **Java** —— C / C++ の **文法** を参考に設計。
  - **C#** —— Java の影響を受けつつ、Microsoft が開発。**C 風の文法** を採用。
  - **JavaScript** —— ブラウザ向けスクリプトだが、C 言語の文法を一部採用。
- 「真似」というより、C の **構造化という優れた設計思想** の継承と言える。

### 現代でも使われ続ける理由

- **50 年以上** 経っても現役の主な用途：
  - **Linux カーネル**、**組み込みシステム**、**デバイスドライバー**
  - **データベース管理システム**、**ゲームエンジン**（C / C++）
  - **高性能計算（HPC）**、**ネットワークプログラミング**
- 今も使われる **4 つの理由**：
  1. **パフォーマンス** —— 最高クラスの実行速度。システム・組み込みでは必須。
  2. **移植性** —— ほぼ全アーキテクチャに C コンパイラが存在（OS を動かすためにまず必要）。
  3. **安定性** —— **30 年以上前** のコードでもそのまま動くことがある（商用システムで重要）。
  4. **相互運用性** —— Python・Ruby など多くの言語が **C とのインターフェイス** を提供（高速ライブラリの基盤）。
- **2023 年 C23** 制定時点でも、標準化は **活発に継続** している。

### 挑戦者：Rust・Zig など

- 近年 **Rust**（メモリ安全性重視のシステムプログラミング言語）や **Zig** など、C の **代替** を名乗る言語が登場。
- それでも C は **すべてのプログラミング言語の母** として、今後も重要な位置を占め続けると見られる。

### まとめ

- C 言語の最大の功績：**効率的で移植性の高いシステムプログラミング言語の基礎** を築き、多くの現代言語に影響を与え、重要なシステムの **基盤として今も活躍** し続けていること。
- 初心者は Python や JavaScript から始めてよいが、**コンピュータの奥深さ** を知るには C も学ぶ価値がある——まずは **Hello, World** から。
