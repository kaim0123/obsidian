## 詳しい要約

サン・マイクロシステムズ（現オラクル）の **Java** が、1991年の「スマート家電」試みから **Web・アプレット・企業システム・携帯・Android・ビッグデータ** まで30年近く使われ続けるまでを、技術面とビジネス面から辿る。**Write Once, Run Anywhere（WORA）**——バイトコードと **JVM** によるポータビリティ——が一貫した軸。オラクル買収・Google 訴訟・有料化の危機を **OpenJDK** エコシステムが受け止め、2017年以降は **6ヶ月リリース** と **LTS** で再加速している。

### 名前と誕生のきっかけ

- 開発チームがカフェで名前を検討し、コーヒー産地 **Java** 島にちなんで命名。当初は **Oak** だったが商標問題で変更。
- **1991年頃・グリーンプロジェクト**（サン）：テレビ・レンジ等をネットワークで繋ぐ **未来の家電** 向け言語。中心は **ジェームズ・ゴスリング**。
- 当時の課題：家電メーカーごとに **CPU が異なり**、C ではターゲットごとに **再コンパイル** が必要で家電向きでない。
- 解：**どんな機械でも動く言語** → **WORA**。ソースは **バイトコード** にコンパイルし、各 OS の **JVM** が実行（C は OS 別に機械語へ直接コンパイルするのと対比）。

### 1995年——家電は失敗、インターネットが救う

- **1995年** 公式発表（アルファ版）時点で **家電業界は関心薄くプロジェクトは頓挫**。
- 同時期の **インターネットブーム** と **Netscape Navigator** の Java サポートにより、ブラウザ上の **アプレット**（アニメ・ゲーム）が話題に——**運とタイミング** が大ブレイクを後押し。

### コア技術（当時として先進的な標準機能）

| 領域 | 内容 |
|------|------|
| **OOP** | クラス・継承・カプセル化（例：動物→犬・猫）。コード再利用 |
| **ガベージコレクション（GC）** | 不要メモリの自動回収。C/C++ の手動解放・メモリリーク回避。ただし **Stop-the-world** は後のバージョンで改善 |
| **例外処理** | `try` / `catch` / `finally`。**検査例外**で処理漏れをコンパイル時検出 |
| **マルチスレッド** | 標準サポート（描画・音・通信の並行など） |
| **リフレクション** | 実行時に自身の構造を調査・変更。**Spring** の DI コンテナ等の基盤 |

### 黄金時代（1996〜2000年代初頭）

- **1996 JDK 1.0**（Java Development Kit＝開発用道具箱）。
- **1997 JDK 1.1・JDBC**：DB 接続の標準 API。Oracle・MySQL・PostgreSQL 等を **同様の書き方** で扱える。
- **1998 Java 2**：**Swing**（高機能 GUI）。プラットフォーム分割——**J2SE**（標準）・**J2EE**（企業）・**J2ME**（組込・携帯）。
  - **J2EE**：**Servlet**（サーバ上の動的生成）、**JSP**（HTML 内に Java）、**EJB**（トランザクション・セキュリティ等の企業向けロジック）。
  - **J2ME**：ガラケー時代のゲーム・アプリ・着メロ・待受等で **大量採用**。

### Java 5 以降の言語進化の波

- **2004 Java 5**：**ジェネリクス**（型安全、`List<String>` 等）、**アノテーション**（`@Override` 等→フレームワーク発展）、拡張 `for`、可変長引数など **一大転換点**。

### オラクル時代の試練とコミュニティの反応

- **2010年** サンが **オラクルに買収**。商標・ライセンス管理が厳格化。
- **Oracle v. Google**：Android が **Java API の構造を利用** したとして提訴。**2021年まで約11年**、最終的に **Google 勝訴**——業界に大きな影響。
- **2019年頃・Java 8 商用サポートの有料化**：個人・開発は無料でも、商用で **継続アップデート** には **Oracle JDK サブスクリプション** が必要に——企業に衝撃。
- 対抗と分岐：**OpenJDK** が活性化。**Amazon Corretto**、**AdoptOpenJDK**（のち **Eclipse Temurin**）、**Azul Zulu** 等、**無料ディストリビューション** が増加——**ピンチをチャンス** に。

### モダン Java（Java 9〜）

- **2017 Java 9〜**：**6ヶ月ごとのリリース**（従来は数年に一度）。小さな改善の積み上げで **再び進化のペースを取り戻した** との評価。
- 主な変化の例：
  - **モジュールシステム（Project Jigsaw）**：大規模アプリの分割。**JRE と JDK の統合**、必要モジュールのみの軽量ランタイム。
  - **Java 10**：`var` による型推論。
  - **Java 11（LTS）**：標準 **HTTP Client**、単一ファイルの **直接実行** など。
  - **Java 14**：**switch 式**（値を返せる・簡潔な記法）。
  - **Java 16**：**record**（データ保持クラスを短く記述）。
  - **Java 17（LTS）**：**sealed class**（継承の制限→安全な設計）。
  - **Java 21**：**仮想スレッド（Virtual Threads）**——従来スレッドは数千が限界だったが、**数万〜数十万** を軽量に。既存の同期的コードのまま非同期の恩恵（**Project Loom**）。コード変更は最小限。

### 現在の主な利用分野（動画時点・2025年前後）

| 分野 | 例・補足 |
|------|----------|
| **金融・基幹** | 銀行・保険・証券。三菱UFJ・みずほ・野村等。**安定性・セキュリティ** |
| **Android** | **Kotlin** が主流だが JVM 上で動き **Java 資産・ライブラリを活用** |
| **Web バックエンド** | **Spring Boot**（DI・AOP 等を簡略化）。Netflix・X・Airbnb・Spotify・LinkedIn 等 |
| **ビッグデータ** | **Hadoop**・**Spark**・**Kafka**（LinkedIn 発、高スループットメッセージング）等は Java 実装が多い |
| **人気指標** | **TIOBE** 等で長年 **上位常連**（動画内ではトップ4言及） |

### 進行中のプロジェクト（未来）

- **Project Valhalla**：プリミティブクラス・**値型**でパフォーマンス向上。
- **Project Panama**：C/C++ ネイティブ連携の改善。**Foreign Function & Memory API**（JNI より安全・簡便）。
- **Project Amber**：パターンマッチング、レコードパターン等——**モダン言語の良いとこ取り** と **後方互換** の両立。

### Java が長く愛される理由（動画の結論）

1. **後方互換性**：20年前のコードが今も動く——企業の **書き直しコスト** を抑える。
2. **安定性と進化のバランス**：新機能を取り入れつつ既存システムを守る。
3. **巨大なエコシステム**：**Maven Central**・GitHub 上の膨大なライブラリ、問題解決の情報量。
4. **一貫した理念**：**WORA** と JVM による **ポータビリティ** が、家電失敗から Web・企業・モバイル・クラウドまで形を変えて支え続けた。

**一言で**：家電向けの「一度書けばどこでも動く」実験が、インターネットと企業 IT の標準語になり、オラクル時代の揺れを OpenJDK と6ヶ月リリースで乗り越え、仮想スレッドと Valhalla/Panama/Amber で **まだ進化中** の言語である。
