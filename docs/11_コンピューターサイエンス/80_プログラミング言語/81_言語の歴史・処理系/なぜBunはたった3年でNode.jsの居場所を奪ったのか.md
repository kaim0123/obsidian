## 詳しい要約

**テーマ：新興ランタイムBunが短期間でNode.jsを揺さぶった経緯と理由**

Node.jsの15年の「帝国」にはツール乱立や遅さという歪みが溜まっていた。ジャレッド・サムナーが個人的な不満から作ったオールインワンのランタイムBunは、Zig・JavaScriptCore・オールインワン設計という3つの選択で圧倒的な速さを実現し、2025年12月にAnthropicに買収されてClaude Codeの基盤になった。Node.jsは消えないが、新規プロジェクトでは本気の候補になった、という話。

---

### 第1章 Node.js帝国と、積もっていた歪み

- 2009年、**ライアン・ダール**（当時27歳）がRuby製Webサーバーの遅さに悩み、Google の **V8** エンジンをサーバーに持ち込んで Node.js を作った。JSConf EU でのデモ（JSだけで動くIRCサーバー）が衝撃を与えた
- 以後、Express・Next.js・React・Svelte など現代Web開発の土台に
- 一方で **ツールが多すぎる** 歪み：パッケージ管理は npm、バンドラーは webpack や esbuild、テストは Jest、型は TypeScript、リンターは ESLint、フォーマッタは Prettier…。新規プロジェクトの最初の30分は設定で消え、node_modules は巨大、ビルドは数分待ち
- ライアン・ダール自身が2018年の講演で「Node.jsの10の後悔」を認め、**Deno** を作ったが、npm資産との互換性を切り捨てたため多くの開発者は移行しなかった

### 第2章 ゲーム開発の不満から生まれた、1人の決断

- 2021年、元Stripeのフロントエンドエンジニア **ジャレッド・サムナー** が Next.js で個人ゲームを作っていて、ビルドとホットリロードの遅さに苛立つ
- esbuild で高速化を試みるも Next.js との組み合わせで納得できず、バンドラー・トランスパイラを自作 → 「ランタイム自体を作り直さないと本当の速さは出ない」と気づく
- ランタイム・バンドラー・トランスパイラ・パッケージマネージャー・テストランナーを **1つの実行ファイルに統合** する決断
- 名前の由来は友人が飼っていたウサギ（Bunny）
- 2022年7月5日、Xで発表しバズ。同年8月に Kleiner Perkins リードで700万ドルのシード調達。会社名は「Bun（パン）を焼く」から **Oven**

### 第3章 Bunを支える3つの大胆な選択

1. **Zigで書く**：2016年生まれのCの代替を目指す低レベル言語。Go（esbuild の言語）はGCがあり最速ではなく、Rust は所有権モデルが大規模ランタイム開発には複雑と判断。Zig は手動メモリ管理だがCより強力なコンパイラを持ち、Cコードを直接呼べる
2. **JavaScriptCoreを採用**：V8ではなくApple（Safari）のエンジン。V8はJIT性能は最強だが起動時の初期化コストが重い。JSCは起動が速くJITもそこそこで、CLIや短命なワーカー向き
3. **オールイン哲学**：全部入りの1バイナリ
- 数字：`bun install` は npm install の6〜9倍速、起動は Node.js の約1/4（約15ms）、TypeScript をコンパイル不要で実行、HTTPスループット2〜3倍、APIサーバーのメモリ使用量25〜40%減。しかも既存npmパッケージとほぼ互換
- 速さは魔法ではなく、地味な選択の積み重ね

### 第4章 1.0リリースとAnthropic買収

- 2023年9月8日、**Bun 1.0** 正式リリース（本番対応宣言）。「node を bun に書き換えるだけで速くなる」デモが世界中で話題に
- 2024年以降 Next.js が公式サポート、Claude Code・OpenAIの内部ツール・Cloudflare の一部サービスなど大企業インフラが採用
- **2025年12月2日、AnthropicがBunの買収を発表**。同日、Claude Code の年間換算売上が10億ドルに到達（GitHub Copilot が2年かかった規模を6か月で）と発表。Claude Code は Bun で作られた実行ファイルとして配布されている
- Claude Code チームリードのボリスとサムナーがサンフランシスコを4時間散歩して合流が決まった。サムナーは「VC出資スタートアップの収益化の苦しみを飛ばせる、最高のJSツールを作り続ければいい」と書いた

### 第5章 Node.jsは消えない。でも未来は別にある

- Node.js は15年の資産・知識・エコシステムがあり当分現役。ただし新規プロジェクトではBunが本気の候補に昇格
- 採用時の注意点：
  1. **互換性は約98%**。残り2%で本番でつまずくことがある
  2. オープンIssueはNode.jsの約3倍で、まだ成長途中。リスク管理が必要
  3. **ローカル開発はBun、本番はNode.js** というハイブリッド運用が現時点で最も実用的（`bun install` で依存解決するだけでも開発速度が変わる）
- 個人の不満が帝国を揺るがす法則：Linus のバージョン管理への不満が Git を、Apache の遅さが Nginx を、DBのスケール問題が Redis を生んだように、サムナーの「Next.jsのビルドが遅い」がBunを生んだ

### まとめ

- Node.jsの歪み（ツール乱立・遅さ）に対し、Bunはランタイム〜テストまでを1バイナリに統合して解決を図った
- 速さの源泉は Zig・JavaScriptCore・オールイン設計の3つの技術選択
- Anthropic 買収で AI 時代の開発インフラの中核に。導入はまずローカル開発から部分的に
