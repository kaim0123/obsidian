## 要約

**「Java のパクリ」** と嘲笑されて誕生した C#（C Sharp）は、訴訟・独占・Windows 依存という **10 年の屈辱** を経て、オープンソース化とクラウド転換のあと **世界トップクラスの言語** へと逆転した。本動画は、1990 年代後半の Java 覇権、Microsoft の Visual J++ 事件、伝説の設計者 **アンダース・ヘルスバーグ** の執念、LINQ・Async/Await などの革新、バルマー時代の「Linux は癌」からナデラ CEO による **「Microsoft loves Linux」** までをたどり、**制約の中で最高を目指した設計** がいかに時代を超える言語を生んだかを解説する。

### テーマ：パクリから最強へ

- GitHub 調査や Stack Overflow 開発者アンケートで **常にトップ 5 入り** する C# だが、登場当初は業界から **「Java のパクリ 2 番戦」** と散々馬にされていた。
- そのギャップの裏には、Sun Microsystems（サン・マイクロシステムズ）との **IT 史に残る泥沼訴訟** と、言語設計者の **敗北から学んだ執念** がある。
- 最初は **Java への復讐** として生まれたが、今や C# は対抗意識ではなく **それ自体の強み** で評価されている。

### 1990 年代：Java の覇権と Write Once, Run Anywhere

- **1995 年**、Sun が公開した Java は **Write Once, Run Anywhere（1 度書けばどこでも動く）** という革命的概念で IT 界の寵児に。
- 当時は OS ごと（Windows / Unix 各社方言）に **別コードを書き直す** のが当たり前だった。
- **JVM（Java Virtual Machine）** がバイトコードを各 OS 上で解釈実行し、プラットフォーム差を吸収——OS 固有の違いを意識せず 1 つのコードで済む。
- **J2EE（現 Jakarta EE）** などエンタープライズ向けフレームワークが続々登場し、2000 年代頭には **バックエンド開発＝Java** という地位を確立。
- この王者に Microsoft が **「取り込もう」** と動いた——それが後の大問題の始まり。

### Microsoft の Visual J++ と Embrace-Extend-Extinguish

- 当時 Microsoft は Windows 最強だが、言語面では **C/C++ は難しく、Visual Basic は本格システム向きでない** など 5 手に回っていた。
- **1996 年**、Java ライセンスを受けて **Visual J++** をリリース。見た目は Java だが **J/Direct** で Windows 固有 API を直接呼び出せる独自拡張を追加。
- 結果、Visual J++ で書いたコードは **Windows でしか動かない** —— Java の最大の強みである移植性を破壊。
- これは Microsoft の伝統的戦略 **Embrace-Extend-Extinguish（取り込む→拡張する→消し去る）** の典型：
  1. 競合技術を取り込んで互換を示す
  2. 独自拡張で自社エコシステムへの依存を作る
  3. 互換性がなくなった状態で競合を排除する

### 訴訟劇：2 回の法廷闘争と 16 億ドル

| 訴訟 | 時期 | 内容 | 結果 |
|------|------|------|------|
| **第 1 次** | 1997 年提訴 → 2001 年 1 月和解 | Java ライセンス契約違反（互換性テスト未適合） | 報道では約 **2,000 万ドル**。**Java 商標を使った製品の製造禁止** —— Visual J++ 事実上終了 |
| **第 2 次** | 2002 年 3 月提訴 → 2004 年 4 月最終和解 | 反トラスト法違反（市場支配力の悪用で Java 妨害） | 反トラスト関連 **7 億ドル** + 特許関連 **9 億ドル** = 合計 **16 億ドル**（当時約 1,700 億円） |

- 第 1 次和解で Java 商標が使えなくなった Microsoft は、**Java を超える言語を 1 から作る** ことを決断。
- **2002 年 2 月**、**.NET Framework と C#** が公開——コードネームは **Cool（C-like Object Oriented Language）** だが商標問題で **C#（C シャープ）** に。音楽記号のシャープ＝C++ を 1 段上げたというメッセージも込められている。

### アンダース・ヘルスバーグ：言語設計の伝説

- Microsoft が **1996 年** に Borland から引き抜いた **アンダース・ヘルスバーグ**（デンマーク出身）が C# 設計を主導。
- 彼の業績：**Turbo Pascal**（単一パスコンパイラでコンパイルを数秒に短縮）、**Delphi**（VCL による GUI 開発革命）、後に **TypeScript** も設計——**1 人で 3 つの言語** を生んだ伝説的人物。
- 引き抜き競争では Borland への対抗金が **50 万ドルから 100 万ドル超** まで引き上げられたとされる（業界報道ベース）。
- **知られにくい事実**：ヘルスバーグは C# 設計以前、**Visual J++ のアーキテクト** だった——訴訟の原因となった製品を設計した本人が、その後 C# を作った。
- 彼自身の証言：Visual J++ 開発中の Sun との争いと裁判所の制限命令から、**「他者からライセンスを受けた技術の上に将来のプラットフォームは作れない」** と悟り、自社の言語と実行環境を 1 から作る決断へ。

### C# の設計方針：Java の良いところを取り、欠点を根本修正

- **文法は Java に似ている**（クラス、インターフェース、例外処理など）が、**設計思想は大きく異なる**。

#### プロパティ（Property）

- Java：フィールドアクセスに `getName()` / `setName()` など **メソッドを手動で書く** のが慣例。
- C#：**言語レベルでプロパティをサポート** —— 呼び出し側はフィールドと同じ書き方で読み書きでき、ボイラープレートが大幅に減る。

#### ジェネリクス：型消去 vs 具体化（Reified Generics）

- Java：**型消去（Type Erasure）** —— コンパイル時は型チェックに使うが **実行時に型情報が消える**。後から追加したため後方互換性を優先した妥協。
  - プリミティブ型をジェネリクスに直接渡せず **ラッピングのオーバーヘッド** が発生。
  - 実行時に `instanceof List<String>` のような **型の問い合わせができない**。
- C#：**最初から設計に組み込んだ具体化ジェネリクス** —— 実行時にも型情報が存在。`List<int>` は int 専用の効率的なメモリレイアウトで扱われ、JIT コンパイラが最適化したネイティブコードを生成。
- 比喩：Java は「昔の服をみんなが着られるように決めわたす」、C# は「その人専用のスーツをその場で仕立てる」。

#### LINQ（Language Integrated Query）

- **2007 年 C# 3.0** で導入。データの検索・絞り込み・並び替えを **SQL ライクな構文** で直接コードに書ける。
- コレクションだけでなく **データベース、XML、JSON** など多様なデータソースに同じ構文で操作可能。
- Entity Framework など ORM と組み合わせると LINQ が **SQL に自動変換** —— 型安全なデータベース操作（コンパイル時にエラー検出）。
- Java 相当の **Stream API** は **2014 年 Java 8** —— **7 年遅れ**。

#### Async/Await（非同期プログラミング）

- 時間のかかる処理（HTTP リクエスト、ファイル I/O、DB クエリ）を待つ間、**コールバック地獄** やスレッド大量生成を避ける仕組み。
- `await` で処理を一時停止しスレッドを解放、完了後に自動再開——**同期処理のように読める非同期コード**。
- **2012 年 C# 5.0** で導入。Java は **2023 年 Java 21** の Project Loom（仮想スレッド）で一応対応——**11 年差**（ただし Loom は Async/Await とは **別アプローチ**）。Python 3.5（2015 年）、Rust の Future も同概念。

### Windows の牢獄：バルマー時代の封闭

- C# は技術的に優れていたが、**.NET Framework は実質 Windows のみ** —— Linux / macOS への公式対応なし。
- **Mono** プロジェクト（Xamarin 創業者ミゲル・デ・イカザ等）や **Unity** ゲームエンジンが非公式に Linux 対応を試みたが、最新機能への追従が遅れ完全性も保証されなかった。
- **2001 年**、CEO スティーブ・バルマーが Chicago Sun-Times で **「Linux は癌（cancer）」** と発言——厳密には **GPL ライセンス**（OSS コードを組み合わせると自社コード公開義務が生じうる）への批判だったが、短縮引用で **「Linux は癌」** として業界の語り草に。
- .NET は Windows / Windows Server に最適化され続け、2000 年代の Web 主流（Linux + PHP / Ruby on Rails / Node.js）の中で **二番手** に。C# の主用途は **Windows エンタープライズ社内システム**（ASP.NET、WinForms、WPF）に限定され、「Windows 専用言語」のイメージが固定化。

### ナデラ時代：Microsoft loves Linux と .NET のオープン化

- **2014 年**、**サティア・ナデラ** が CEO に就任——Azure クラウド部門出身。Microsoft を **Windows 会社からクラウド会社** へ転換。
- **2015 年** Azure 開発者イベントで **「Microsoft loves Linux」** と宣言——バルマーの「癌」発言からの劇的転換。会場は凍りついたとされる。
- 論理：クラウド利用者は Linux・Docker を使う。**壁を作り続けたら Azure は選ばれない** —— オープン化はビジネス上の必然。
- **2014 年 11 月**：.NET Core ランタイムを **オープンソース化** と発表。
- **2016 年**：**.NET Core 1.0** 正式リリース——**Linux / macOS / Windows 全対応**。
- **2018 年**：Microsoft が **GitHub を 75 億ドルで買収**。GitHub Actions（2018 年発表、2019 年正式）など機能強化に投資し、反発より実績で信頼を獲得。
- **2020 年 .NET 5** で .NET Framework と .NET Core が **ブランド統一**（ただし WPF / WinForms 等デスクトップ機能は Windows 限定のまま）。現在 .NET 8 / 9 まで進化。

### 現代の C#：性能・普及・用途

- **ASP.NET Core** は TechEmpower ベンチマーク等で **Java Spring Boot と比べスループット優位** のケースが多い——マネージド言語＝遅いという常識が覆りつつある。
- **`Span<T>`** や **`Memory<T>`** などメモリコピーを極限まで減らす低レベル最適化——場合によっては **C++ に迫る性能**。
- **Unity** が C# をスクリプト言語に採用——スマホゲーム開発で圧倒的シェア。**IL2CPP** で中間言語→C++→ネイティブコード変換も可能（iOS ビルドでは事実上必須）。
- 用途：**Unity ゲーム**、**ASP.NET Core バックエンド**、**WPF / MAUI デスクトップ・モバイル** —— マルチプラットフォーム言語へ。

### 立場の逆転：C# が Java を先行するケース

| 機能 | C# | Java | 差 |
|------|-----|------|-----|
| LINQ / Stream | 2007（C# 3.0） | 2014（Java 8） | **7 年** |
| Async/Await / 仮想スレッド | 2012（C# 5.0） | 2023（Java 21, Project Loom） | **11 年**（モデルは異なる） |
| レコード型 | 2020（C# 9.0） | 2021（Java 16） | ほぼ同時期 |
| パターンマッチング | 2017（C# 7.0）〜段階強化 | 2021 年以降本格整備 | C# が先行 |

- Java は **後方互換性** を非常に重視——20 年前のコードも動く安心感は大企業に不可欠だが、**革新的機能追加を遅らせる** 面もある。
- Stack Overflow 調査：C# は **最も愛されている言語** の上位常連。Java は広く使われているが **「次も使いたいか」** では下がる傾向——若い世代は冗長な記法を嫌い **Kotlin** へ移行（Android 公式推奨言語化で加速）。
- **Kotlin** は JVM 上で Java 互換を保ちつつモダン化——LINQ 相当、null 安全、データクラス等、**C# で先行した機能の多くを JVM 上で実現**。ある意味 **Java 内のアンダース・ヘルスバーグ的改革者** で、C# に対する Java 陣営の別働隊とも言える。
- Java 側も **Project Loom**、**GraalVM**（ネイティブバイナリ化）、シールドクラス等で確実に進化——**競争が両方を育てた**。

### まとめ：制約の中で最高を目指す

1. Java に喧嘩を売り **訴訟で叩かれた** → 自社言語を作るしかなかった（**Visual J++ 問題がなければ C# は生まれなかった** 可能性）。
2. ヘルスバーグらが **Java の欠点を直しながら C# を設計** した。
3. しかし **Windows の牢獄** に閉じ込められ普及しなかった。
4. **ナデラ CEO** がオープン化し、ようやく実力を発揮——**制約の中でどう最高を目指すか** が時代を超えるものを生む。
5. 訴訟・引き抜き・思想転換——すべてが今日書かれる **1 行のコード** に影響している。
