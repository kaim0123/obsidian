## 詳しい要約

プログラミング言語の歴史シリーズ第1回。**人類が最初に「プログラミングの地獄」から解放された言語**は Python でも Java でもなく、**数文字のニーモニック記号**（アセンブリ言語）である——という問いから始まり、**配線プログラミング → 機械語の地獄 → アセンブリによる救済 → 現代でも生き残る理由 → 次回への橋（コンパイラ）** までを一気通貫で解説する。

### 導入：二段階の「地獄」

- クイズの答えは **アセンブリ言語のニーモニック**（`MOV` `ADD` など）。高級言語よりずっと昔、たった数文字の記号が人類を救った。
- **第1の地獄：配線プログラミング** —— 1940年代の **ENIAC** はスイッチとケーブルの物理接続でプログラムした。計算内容を変えるたびに **数時間の電気工事** に相当する作業が必要だった。
- **第2の地獄：機械語（0と1）** —— 配線から脱出しても、プログラムは **ビット列を手書き** する世界が待っていた。一般のプログラマーは一生目にしないが、現代のソフトウェアの土台には不可欠だった。

### 機械語が「地獄」だった理由

- コンピュータは **トランジスタのオン/オフ（1/0）** しか扱えない。現代 CPU には数十億個のスイッチがあり、その組み合わせで全演算が成り立つ。
- 例：`AL` レジスタに `61` を入れる命令は機械語で **`10110011001`**（11ビット）。プログラム全体がこの羅列の連続。
- **命令ごとにバイト長・ビット構造が異なる**（ISA 依存）。CPU は先頭バイトを見て「この命令は何バイトか」を判断しながら実行する——人間も同様に **オフセット計算** を手で行っていた。
- **デバッグ**：数百行のバイト列を目視確認。1ビットの誤りで別命令実行・暴走・クラッシュ。
- **パンチカード／紙テープ**：穴を開けたら消せない。間違えれば **最初から作り直し**。
- **マシンごとに命令セットが違う** —— あるマシンで `ADD` が `0011` でも、別マシンでは別コード。**標準化前** は転職のたびに命令を覚え直すレベル。
- **エンディアン**：複数バイト数値のメモリ並び順（ビッグ／リトル）もマシン依存。混在すると計算が全滅する。

### 歴史的人物と出来事

- **ENIAC の女性プログラマー**（ジーン・ジェニングス・バートリク、フランシス・ビルズほか）：カイロスを読みパッチパネルを設定。貢献が広く知られるまで **50年以上** かかった。
- **フォン・ノイマン型（プログラム内蔵方式）**（1945年論文、1949年 **EDSAC** 実用化）：命令とデータを **同じメモリ** に置く。**ソフトウェア** という概念の誕生。書き換えは楽になったが、打ち込む **0と1の量** は爆増した。
- **モーリス・ウィルクス**（ケンブリッジ）：**サブルーチン**（関数の先祖）を実用化・ライブラリ化。1951年の本はコンピュータプログラミング最初期の教科書の一つ。「想像よりはるかに難しかった」——組織的デバッグの必要性を訴えた。
- **バグの伝説**（1947年、グレース・ホッパー周辺）：実際の **蛾** がリレーに挟まり、ログに *First actual case of bug being found*。語源自体はエジソン（1878年）以前から存在。
- **アセンブラの誕生**（1951年頃）：「自分で翻訳するのは無理」→ コンピュータに翻訳させる。**IBM** のナサー・ロチェスターらが実用化。**複数拠点でほぼ同時多発**（電話のベル／グレイ特許争いと同型）——切実な需要の証。

### アセンブリ言語がもたらしたもの

| 仕組み | 内容 | 現代へのつながり |
|--------|------|------------------|
| **ニーモニック** | `MOV` `ADD` `SUB` `CMP` など英語略語で命令表現 | 覚えやすい記号（ギリシャ語 *mnemonikos*＝記憶） |
| **レジスタ名** | `AX`（アキュムレータ）`BX` `CX`（カウンタ）`DX` など役割付き | ISA 設計思想の可視化 |
| **スタック** | `PUSH`/`POP`、関数呼び出し時に戻りアドレスを積む | ネスト呼び出し・再帰の基盤（`CALL`/`RET`） |
| **ラベル** | `loop_start:` のように **場所に名前** | 変数名・関数名の思想的先祖。1行追加でアドレスがずれる問題を解消 |
| **ディレクティブ** | `.data` `.text` でコードとデータを分離 | 誤実行防止（コードインジェクションの概念的先祖） |
| **マクロ** | アセンブル時にテキスト展開（実行時ではない） | 繰り返しの抽象化（関数とは別フェーズ） |

- 生産性は **数倍**、アドレス計算ミスも大幅減少——機械語手書きがボトルネックだった証拠。

### アセンブラの内部（翻訳の仕組み）

1. **字句解析（トークン化）** —— `MOV AL, 61` を `MOV` / `AL` / `,` / `61` に分解。
2. **構文解析** —— トークン列が文法的に正しいか（`MOV 61` のような順序はエラー＝**コンパイルエラーの原型**）。
3. **ニーモニック → オペコード変換** —— 辞書引きでバイト列生成。
4. **2パスアセンブル** —— **前方参照問題**（先に `jmp loop`、後で `loop:` 定義）を解くため、1パス目で **シンボルテーブル**（ラベルとアドレス対応表）を作り、2パス目でアドレスを埋める。
5. **オブジェクトファイル**（`.o` / `.obj`）—— まだ実行不可の中間成果物。
6. **リンカ** —— 複数オブジェクトを結合し、**外部ライブラリ参照**（`printf` など）を解決して実行ファイルに。
   - **静的リンク**：ライブラリコードを実行ファイルに埋め込む。
   - **動的リンク**：実行時に DLL（Windows）/ `.so`（Linux）を読み込む。欠落時は「DLLが見つかりません」エラー。
7. Linux では最終形式が **ELF**（Executable and Linkable Format）。高度なアセンブラは **ピープホール最適化** も実施。

### 高級言語との違い・RISC と CISC

- **抽象化の有無**が本質。Python の `for` ループはレジスタを意識しないが、アセンブリは **ISA をそのまま書く**（隠蔽ゼロ）。
- `A = B + C` は C なら1行、アセンブリでは **最低3行以上**（ロード・加算・ストア。アドレス計算が絡めば5〜6行も）。
- **メリット**：レジスタ割当・命令順序を完全制御。**パイプライン／キャッシュ** を熟知した人間の手書きが、コンパイラより速い場合もある。
- **デメリット**：**ポータビリティゼロ**（x86 と ARM は別物）。Apple の Intel→Apple Silicon 移行の苦労の一端。
- **CISC**（Complex ISA、例：x86）：命令種類が豊富、1命令で複合操作。回路が複雑・遅い・高消費電力。
- **RISC**（Reduced ISA、例：ARM）：単純命令を高速実行し組み合わせ。モバイル・組み込み向き。現代 CPU は内部で **アウトオブオーダー実行** など複雑化し、RISC/CISC の境界は曖昧に。

### 現代でもアセンブリが必要な場面

- **BIOS / UEFI**：電源ON直後。スタックも未初期化で **C は使えない**。「OSが声を上げる前の声」。
- **Linux カーネル**：`start_kernel` 前の初期化コード。
- **割り込みハンドラ**：キーボード・タイマー等。**マイクロ秒単位**でコンパイラ生成コードの無駄も許されない。
- **組み込み**（ARM Cortex-M0 等、RAM 数KB）：ランタイムオーバーヘッドすら重い。冷蔵庫・自動車・**エアバッグ制御** など命に関わる領域。
- **SIMD / AVX**：画像・音声・AI のホットパス。FFmpeg・x264 等。
- **コンテキストスイッチ**（Linux カーネル）：プロセス切替を秒間数千回。
- **マルウェア解析・CTF**：逆アセンブルは必須スキル。「アセンブリが読める」はセキュリティ研究者の名刺代わり。

### 限界と次の進化への橋

- **高級言語にないもの**：型付き変数・スコープ・自動メモリ管理。アドレスは番号かラベルで、大規模化すると **4002番地は何だっけ？** が日常化。
- レジスタは 8086 で8個、x86-64 でも16個——複雑処理ではスタックへ退避の管理が延々続く。
- **UNIX 初期**はかなりアセンブリ（Thompson & Ritchie）——限界を感じ **C 言語** を自作（移植性・書きやすさ）。C コンパイラは **B** 経由で実装され、B は **アセンブリ** で書かれた。
- **ブートストラップ問題**：新言語のコンパイラをその言語だけで書けない最初の一歩は、必ずアセンブリか機械語から始まる（靴紐で自分を持ち上げる比喩）。
- **全高級言語のピラミッド最下層**がアセンブリ。Python・Java・Rust も最終的には機械語に落ちる。

### まとめのメッセージ

- **機械語は地獄、アセンブリはその地獄に秩序をもたらした橋**。CPU に近い側と人間に近い側の間の **最初の橋**。
- 功績者の多く（ENIAC の女性たち、初期アセンブラ開発者）は教科書に載らない。**グレース・ホッパー** は例外——「コンピュータは英語を理解できない」と言われながら、**動くものを見せた**ことで説得した。
- **次回（第2回）**：アセンブリの限界（10万行規模）から **コンパイラと高級言語の夜明け** へ——「ニーモニックで CPU と話す」から「人間の言葉でコンピュータと話す」への距離短縮。
