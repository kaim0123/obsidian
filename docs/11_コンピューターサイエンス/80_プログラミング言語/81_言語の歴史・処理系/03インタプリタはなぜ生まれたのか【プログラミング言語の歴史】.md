## 詳しい要約

プログラミング言語の歴史シリーズ第3回。前回のコンパイラは「全部翻訳してから実行」——**速さ** を追求した道だった。インタープリタは **書いたその場で動く** 体験で、コンピュータを専門家の道具から **万人の相棒** に変えた。**BASIC → Unix シェル／AWK → Perl → Python → Ruby／JavaScript → 型の後付け（TypeScript 等）** まで、速度より対話を選んだ歴史と、JIT で境界が曖昧になった現代までを追う。

### なぜインタープリタが必要だったか

| 動機 | コンパイラの壁 | インタープリタの強み |
|------|----------------|----------------------|
| **教育** | コンパイルの関門が「動く感動」を遅らせる | 書いてすぐ実行、即フィードバック |
| **プロトタイピング** | 試行錯誤のサイクルが重い | 試して失敗してまた試すが速い |
| **対話的計算** | 計画してから一括実行 | 計算しながら考え、結果を見てまた考える |

- 大型機時代：**バッチ処理**（カード提出→翌朝結果）。タイプミス1つで1日無駄。IBM 7094 級は数億円、**コンピュータ時間はお金**——「すぐ動く」体験自体が革命。
- **REPL**（Read-Eval-Print Loop）：読んで・評価して・出力して繰り返す。**1958年頃の Lisp**（マッカーシー）が自然に REPL を実装——**同相性（ホモイコニシティ）**：コードとデータが同じ S 式。`(+ 1 2)` はデータでも式でもあり、**マクロ**でコードを動的生成。
- **CTSS**（1961, MIT）：Compatible Time-Sharing System。1台を複数人で共有、各ユーザーに仮想端末——**みんなが REPL を使える**環境の起点の一つ。
- 現代の **Jupyter Notebook** は「コード＋説明＋結果」を記録する科学者向け REPL。APL・FORTH など他の対話系もあったが、Lisp は学術的影響が大きい。

### BASIC：誰でも書ける夢の最初の形（1964）

- **ダートマス大学**のジョン・ケメニー & トーマス・カーツ。**G.E. 225** 上で1964年5月初動作。
- **BASIC**＝Beginner's All-purpose Symbolic Instruction Code。FORTRAN は一般学生には壁が高すぎた。
- **行番号10刻み**：後から行を挿入できる（`11` `15` など）。`GOTO` で飛ぶ——メモリ貴重時代の実用策（のちに構造化批判の的にも）。
- インタープリタは行番号リストを順に実行、`GOTO` でジャンプ先を探す単純構造。**4KB** で動く **Altair BASIC**（ゲイツ & アレン、1975）→ **Microsoft の最初の製品**。Apple II・TRS-80 等に搭載、**電源ON→BASIC 画面→`RUN`** が80年代子供の体験。雑誌の打ち込み文化。
- **ダイクストラ**（1975）：「BASIC に慣れた精神的損傷は回復不可能」——`GOTO` 多用が構造化学習の妨げ、という批判。普及の功績と「悪習慣」批判は両立する複雑な言語。

### Unix 文化：小さな道具と「のり」

- **哲学**：「1つのプログラムは1つのことをうまくやれ」。`ls` `grep` `sort` `wc` 等を **パイプ**（`|`）で接続。
- **シェルスクリプト**＝**グルーコード**（接着剤）。`sh` → **bash**（Bourne Again Shell）。
- **sed**（1974）、**awk**（1977, Aho・Weinberger・Kernighan）：テキスト処理専用インタープリタ。awk はレコード／フィールド（`$1` `$2`…）でログ解析。Unix の「**すべてはテキスト**」——JSON・CSV・Markdown・Web API レスポンスまで現代も継続。**マイクロサービス**・DevOps にも思想が受け継がれる。
- 限界：条件分岐・複雑なデータ構造で手に負えない → より強い **スクリプト言語** へ。

### Perl（1987）：Unix ツールの統合と Web 黎明期

- **ラリー・ウォール**（言語学出身）。**Perl**＝Practical Extraction and Report Language（後に *Pathologically Eclectic Rubbish Lister* など自虐的別名も）。
- **TMTOWTDI**（There's More Than One Way To Do It）——パールへの「何でもあり」と対になる哲学。
- **sed + awk + sh + C** の「全部入り」。**1990年代 CGI** の主力、動的 Web ページ生成。
- **正規表現**を言語レベルで直接サポート（`=~` 等）——**PCRE** がデファクト標準。JavaScript・Python の正規表現文法はほぼ Perl 由来。
- **CPAN**（1995）：世界初規模のオープンソースライブラリ集——**npm・PyPI の先祖**。
- プログラマー三美徳：**怠惰・短気・傲慢**（Lazy, Impatient, Hubris）——自動化・改善・品質への動機。読みにくさは「書き捨てスクリプト文化」も要因。
- 現状：Python・Ruby にユーザー奪われつつ、**システム管理・テキスト処理**では現役。CPAN は22万超モジュール。

### Python（1991）：読みやすさと「慈悲深き独裁者」

- **グイド・ヴァン・ロッサム**（オランダ）。**ABC**（1980年代教育言語）から **インデントで構造** を継承。
- **Zen of Python**（`import this`）：「美しいは醜いより良い、明示は暗示より良い、シンプルは複雑より…」「やり方は1つであるべき」——**Perl へのアンチテーゼ**。
- **BDFL**（Benevolent Dictator For Life）：グイドが最終決定。2018年辞任→**委員会ガバナンス**へ。
- 実装：**CPython** はソース→**バイトコード**→VM が解釈（完全な一行ずつインタープリタではない）。**GIL** で Python スレッド同時実行は1本——重い計算は **NumPy** 等（C/C++）に任せ、Python は API の「司令塔」。TensorFlow・PyTorch も同型。
- **PyPy**（JIT）が速度問題への回答の一つ。哲学は **「早くなくても、正しく読みやすい方が価値」**。
- **Python 2→3**：後方互換切断で10年以上の移行。**pip**（CPAN モデル）に50万超パッケージ。入門定番言語として **BASIC の夢を現代に継承**。

### 1995年双子：Ruby と JavaScript

**Ruby**（松本行弘・マッツ、1993設計／1995公開）

- 目標：**プログラマーを幸せにする**。ほぼ全てがオブジェクト（`3.times` 等）。
- **最小驚きの法則**（POLS）：直感通りに動く。
- **Ruby on Rails**（2004, DHH）：**Convention over Configuration**。MVC 普及。数日で Web アプリ骨格——世界展開のきっかけ。

**JavaScript**（ブレンダン・アイク、ネットスケープ、**10日間**プロトタイプ）

- 当初 **Mocha** → **LiveScript** → **JavaScript**（Java とは**技術的無関係**、マーケティング上の名前——最大の誤解の一つ）。
- 急ぎの設計ゆえ `typeof null === "object"` 等の奇妙な挙動——`===`・厳格モード等で改善。
- **ブラウザ唯一の言語**という独占が普及を加速。**Ajax**（2005頃, Google Maps/Gmail）で本格アプリ言語へ。
- **Node.js**（2009, Ryan Dahl）：サーバー側 JS、イベント駆動・ノンブロッキング I/O。
- **V8**（Chrome）：JIT＋**隠しクラス**でオブジェクト構造を静的解析、C++ に近い速度。フロント・バック同一言語時代。
- 標準：**ECMAScript（ES）**、毎年仕様更新。

### 動的型付け vs 静的型付け・段階的型付け

- 本編言語は多く **動的型付け**（変数に型宣言不要）——楽だが **実行時まで型ミスが潜む**（本番で稀な入力だけエラー、等）。
- **静的型付け**：コンパイル（または解析）時に型ミスを潰す。大規模チーム向き。
- **用途で使い分け**が正解——対立ではなく補完。
- **既存コードベースを捨てられない** → 動的言語に **型を後付け**：
  - **TypeScript**（2012, Microsoft, アンダース・ヘイルスバーグ＝C# 設計者）：JS のスーパーセット、`.ts`→`.js` 変換。**構造的部分型**（プロパティが揃えばクラス名不要）——JS のプロトタイプモデルと相性良し。段階的に型注釈を追加可能。
  - **Python 型ヒント**（PEP 484, 2015）：ヒントのみ、ランタイムは強制しない。**mypy / pyright** が静的解析。
  - Ruby **Sorbet**、PHP **PHPStan** 等、同方向。
- **JIT**・最適化で「インタープリタ＝遅い」固定観念は崩壊。**コンパイラとインタープリタの境界は曖昧**（前回の続き）。**段階的型付け（gradual typing）** で静的・動的の間を緩やかに移行。

### 言語間の影響と現代

| 流れ | 内容 |
|------|------|
| エコシステム | Perl **CPAN** → Python **pip** → JavaScript **npm** |
| 型 | Haskell / ML 研究 → TypeScript・Python 型ヒント |
| 体験 | BASIC「誰でも」→ Python 入門定番 → **AI 時代の「誰でも AI」** の言語として Python の役割拡大 |

- インタープリタの哲学：**機械の都合に人間が合わせるのではなく、人間がコンピュータと自然に対話する**——速さより **人間らしさ** を優先した歴史。ただし **JIT・TypeScript** で速さも諦めきれなかった。
- コンパイラとインタープリタは **対立ではなく補い合い**。ベーシック→Python/JavaScript が「誰でもプログラム」を世界規模で完成させた流れ。
- **プログラミング言語の歴史**＝抽象化・速度・安全性・体験の **トレードオフとの格闘**。最初の「動いた」瞬間の感動が技術を押し上げてきた。
