## 詳しい要約

**テーマ：使われない Haskell が主流言語の源流になっている理由**

Haskell を業務で書く人は少数（TIOBE で 30〜50 位圏、シェア 0.5% 以下）だが、Rust・TypeScript・Swift など主流言語の中核機能の多くは Haskell 由来であり、業界の大多数は知らずに Haskell の思想を使っている。難しさの正体（モナド・高階型・遅延評価・純粋性）、主流言語への影響、本番採用企業、短期生産性と長期信頼性の議論を 5 章で解説する。

---

### 序章

- 「関数型言語は難しいだけ」「学術界の自己満足」という声がある一方、表面と現実には大きなずれがある
- Rust の所有権モデル・Option/Result・トレイト・async/await、TypeScript の型システム・ADT・パターンマッチング、Swift・Scala・F#・OCaml・Elm・PureScript などが Haskell の影響を強く受けている

### 第1章 Haskell の正体、純粋関数型言語の設計思想

- 1990 年、**完全に純粋な関数型プログラミング言語** を作る目的で誕生。名前は論理学者 **ハスケル・カリー** に由来
- 他の関数型言語は「関数型でも書ける」言語で副作用もあるが、Haskell は **副作用をすべて型で管理** する
- 他の言語では関数を見ても副作用（DB 書き込みなど）の有無が中身を読まないと分からない
- Haskell では副作用のある関数の型に必ず **IO**（外部世界に影響する印）が付き、純粋な計算か外界を変える関数かが型で一目で分かる
- バグの多くは予想外の副作用から生まれる → **言語設計レベルで解決**

### 第2章 4つの難しさの正体

1. **モナド**：文脈付きの値を扱う仕組み。JavaScript の Promise（「将来の値」という文脈）はその一例。Haskell では入出力・失敗の可能性・エラー・状態管理をすべてモナドで統一的に扱う
2. **高階型（Higher-Kinded Types）**：Java・C#・Rust の型システムは具体的な型を扱うが、Haskell は「リスト」という箱そのものを引数として渡せる **型の型** を扱える
3. **遅延評価（Lazy Evaluation）**：必要になるまで評価しない。**無限リスト** も定義できる
4. **純粋性**：同じ入力に必ず同じ出力。グローバル変数の変更や乱数などは言語仕様で禁止。Python なら普通に書ける「現在時刻の取得」も、Haskell では型に外部世界の印を付けないとコンパイラに拒否される
- 他言語の常識を捨てる必要があり、学び直しコストが大きい
- 人材は JavaScript エンジニアの数十分の一以下、社員教育に **1〜2 ヶ月** の追加コスト、ライブラリ生態系も小さく Stripe・Twilio・SendGrid などの主要 SDK が提供されないことが多い

### 第3章 Rust、TypeScript、Swift、主流言語の隠れた源流

1. **Rust の Option と Result**：Haskell の **Maybe と Either** の直接の移植（Rust に null がないのは Haskell の仕組み）
2. **Rust のトレイト**：Haskell の **型クラス** のほぼ直接の移植。2024 年の論文で Swift のプロトコル、Scala の implicit、Rust のトレイトは型クラスの 3 つの方言と分析された
3. **async/await**（JavaScript、Python、C# など）：モナドを非同期処理だけに絞り、シンタックスシュガーを付けた形
4. **TypeScript の Union Types・Discriminated Unions・Type Narrowing**：Haskell の **代数的データ型（ADT）** から派生。「成功ならユーザーデータ、失敗ならエラーメッセージのどちらか」という型は、Haskell が 1990 年から持っていたものを TypeScript が 2017 年に取り入れた（27 年遅れ）
- 格言「Haskell で 20 年前にできたことが、主流言語で 5 年前にやっとできるようになった」→ 業界全体が技術的に Haskell に追いついている状態

### 第4章 Mercury、Cardano など重要領域での本番採用

- 2026 年 4 月時点の本番大規模採用：**Mercury**（フィンテック・銀行業務）、**Hasura**（GraphQL エンジン）、**Cardano**（ブロックチェーン、時価総額数十兆円）、**Foxhound Systems**（Haskell を第一候補と公言するコンサル）
- Mercury（2026 年 3 月の現役エンジニアのブログ）：数百万行の Haskell を本番運用、100 人以上が毎日 Haskell を書き、新卒の半数が 6 ヶ月以内に本番コードを書く
- 採用企業の共通点：①**絶対に間違いが許されない領域**（フィンテック・医療・ブロックチェーン）②**長期保守性** が重要（5〜10 年動かす）③**複雑なドメインロジック**
- 証言「Haskell のコンパイラは 99% のバグをコードが動く前に検出する」：JS の実行時バグ、Python の型不整合、Java の NullPointerException がコンパイル時に止まる
- Foxhound Systems「開発生産性・保守性・信頼性・性能の組み合わせで最高。学習コストは高いが長期的なバグ削減と保守性向上で回収できる」→ 短期コスト vs 長期リターンの経営判断

### 第5章 使われない言語が業界に深く影響するパラドックス

- **短期生産性 vs 長期信頼性**：JS・Python は 30 分で動くプロトタイプが書けるが、Haskell は 30 分でやっと環境構築が終わる
- 3 年後には逆転：型がなく副作用が制御されない JS プロジェクトは保守困難になり、Haskell プロジェクトは新規エンジニアもコンパイラの助けで安全に変更できる
- **AI コーディングエージェント時代**：AI に JS で書かせると平均的で 3 年後に保守困難なコード、Haskell で書かせると型システムに守られ最初から保守可能なコードが出てくる → Haskell の強みが再評価
- 「最も使われない言語が最も深く影響する」：直接の利用者は 0.5% 未満でも、Rust の Option、TypeScript の Union Types、Swift の Optional など、業界は知らずに Haskell 生まれの概念を毎日書いている

### まとめ

- Haskell は副作用を型で管理する純粋関数型言語で、モナド・高階型・遅延評価・純粋性が難しさの正体
- Option/Result、トレイト、async/await、Union Types など主流言語の中核機能は Haskell の子孫
- 間違いが許されない・長期保守・複雑なドメインの領域では本番採用が進み、AI 時代に強みが再評価されている
