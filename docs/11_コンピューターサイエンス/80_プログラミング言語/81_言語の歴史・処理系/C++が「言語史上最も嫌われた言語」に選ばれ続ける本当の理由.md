## 詳しい要約

**テーマ：C++ が最も嫌われながら最も使われ続ける理由**

C++ は開発者調査で「使い続けたくない言語」の常連で、巨匠たちや米政府機関からも批判されている。その原因は未定義動作・テンプレート・ヘッダー・ビルド時間・肥大化という言語設計に根ざす構造問題にある。一方で膨大なコード資産と代替困難な強みがあるため消えない。「嫌われること」と「消えないこと」は別の話であり、既存の C++ を読める力はむしろ価値が上がる、というのが結論。

---

### 第1章 嫌われている客観的な証拠

- 2024 年 5 月の **Stack Overflow 開発者調査**（6 万 5000 人以上）で「来年も使い続けたい」割合は Rust 81%、C# 70%、Go 64%、Python 67% に対し **C++ は 46%**。つまり C++ ユーザーの 54% は乗り換えたいと答えた。2025 年も傾向は同じ。
- それでも **TIOBE** 指数では 2025 年に世界 4 位。Photoshop、Office、Chrome、Unreal Engine、PyTorch の中核は C++。
- 作者 **Bjarne Stroustrup** 自身：「言語には 2 種類ある。皆が文句を言う言語と、誰も使っていない言語だ」。
- 2024 年 9 月、米国 **CISA** が「2026 年 1 月 1 日までに製造業者はメモリ安全戦略を持つべき」と声明。C++ はメモリ安全でない言語に含まれる。NASA・Microsoft・Google なども C/C++ から離れるよう発言し、Stroustrup はこれを「前例のない深刻な攻撃」と表現した。
- 感情論ではなく、**業界調査・巨匠の発言・政府機関の声明が一致**した客観的現象である。

### 第2章 嫌われる 5 つの構造問題

1. **未定義動作（UB）**：配列の範囲外アクセスやオーバーフローなどは未定義とされ、コンパイラは「UB は起きない」と仮定して最適化する。その結果、書いたはずの**防御的な条件チェックが最適化で消え**、本番でクラッシュや脆弱性になる。
2. **テンプレートメタプログラミング（TMP）**：本来はジェネリックプログラミング用だったが、1994 年にテンプレートがコンパイル時に**チューリング完全**だと偶然発見され、コンパイル時計算の文化が根付いた。エラーメッセージが画面 10 ページに及ぶこともあり「コードではなく呪文」と呼ばれる。
3. **ヘッダーファイル**：1972 年、メモリが少なかった時代の C から継承した仕組み。`#include` が再帰的に展開され、Chrome のフルビルドは通常マシンで 4 時間以上。C++20 で **Modules** が標準化されたが、コンパイラ・ビルドシステム・業界の対応が進まず、実用はほぼゼロ。
4. **ビルド時間**：ヘッダー問題の直接の結果。Go の生みの親ロブ・パイクは、Go は巨大な C++ のコンパイル待ちの間に構想されたと語っている。
5. **機能の肥大化**：C++98 から C++26 まで 3 年ごとに新標準。C++23 の規格書は約 2000 ページ、キーワードは 97 個（Go 25 個、Python 35 個）。人間 1 人が頭に保てる量を超えている。

### 第3章 巨匠たちの本音

| 人物 | 発言 |
|---|---|
| **Linus Torvalds**（Linux） | 2007 年「C++ は恐ろしい言語だ。レベルの低いプログラマーが多く使うことでさらに恐ろしくなる」、2022 年「C++ は私が持っていない問題を解決する言語だ」。Linux カーネルが C++ で書かれていないのは彼の強い意思による |
| **Ken Thompson**（C・UNIX） | 「C++ は本当に愚かな言語だ。C を引きずっていったから」 |

- 別々の言語・文化・アプローチを持つ人々が共通して批判している点が、**文化の違いでは解決できない構造問題**である証拠とされる。

### 第4章 それでも消えない理由

- 用途：OS（Linux・Windows・macOS・Android・iOS の中核）、Photoshop、Office、Chrome、Firefox、Unreal Engine、大作ゲーム、証券取引所の高頻度取引、ボーイング・エアバス・テスラ・トヨタの組み込み、PyTorch・TensorFlow の計算カーネル。
- 推定で数兆行規模の C++ 資産があり、**全部を書き換えるのは現実的に不可能**。
- 他言語が真似しにくい強み：①**ハードウェアレベルの制御**、②**GC なしの予測可能な動作**、③**巨大なエコシステム**（Boost、Qt、CMake など）。
- Microsoft は 2030 年までの Windows の Rust 移行を発表したが、全面移行には数十年かかる見込み。
- C++ を嫌いながら毎日書いて給料をもらう状態を、業界では「**C++ ストックホルム症候群**」と呼ぶ。

### 第5章 エンジニアの取るべき道

1. **否定で終わらせない**：嫌われる理由は正当だが、C++ を捨てれば世界の半分のソフトが動かなくなる。批判しつつ敬意を持って付き合う。
2. **新規プロジェクトでは他の選択肢を真剣に検討**：Rust・Zig・Go などが代替候補。新規で C++ を選ぶには明確な理由が必要。
3. **既存の C++ を理解する力は武器になる**：新しく学ぶ人が減る一方、巨大なコードベースは 20〜30 年動き続けるため、読み書きできる人材の希少価値は上がる。

- 学ぶ目的は「C++ を愛するため」ではなく「C++ とうまく別れる方法を知るため」かもしれない。

### まとめ

- C++ の嫌われ方は調査・巨匠・政府が一致する客観的事実で、原因は言語設計に根ざす 5 つの構造問題。
- 巨大な既存資産と代替困難な強みがあるため、嫌われても消えない。
- 新規では代替を検討しつつ、既存 C++ を読める力は希少価値として持っておく。
