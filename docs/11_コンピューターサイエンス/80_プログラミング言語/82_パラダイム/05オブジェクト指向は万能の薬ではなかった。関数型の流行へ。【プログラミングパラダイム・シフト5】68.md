## 要約

**シリーズの位置づけ**

「プログラミングパラダイム・シフト」**第5回・最終回**（当初4回予定が前回の膨らみで延長）。OOの**限界と「神話からの脱却」**を述べ、**関数型プログラミング**を第3の潮流として概観する。関数型の理論は堀本も大学4年から「挫折し続け」今回入門書を読んだ程度——**中身は深掘りせず**、参照透過性・副作用・噂話レベルに留め、専門家監修での別回を予告。

**前回までの復習と「神話」**

- OOは2000年代に**GUI（Windows 95 など）と相性が良く**爆発的に流行。現実の写実（ルネサンス比喩）、カプセル化・継承・ポリモーフィズム。
- その結果、**何でもOOにすればよい魔法の薬**のように一人歩き。堀本も大学で「極地に達した」「やっときゃええや」と思っていた。
- **Web+DBプレス（2022年12月号）** メインタイトル「**オブジェクト指向神話からの脱却**」——今も使われるが、**何にでもOOは過剰**。適切な付き合い方・使うシーンの見極めが課題。

**OOの核心問題：参照透過性がない**

**参照透過性（referential transparency）**：同じ入力なら**常に同じ出力**が返る性質。

- OOは**データと命令をセット**で持つ。カプセル化された「水野」に「魔法を使え」と指示すると、**MPが満タンか空か**で結果が変わる——**同じ入力（命令）なのに出力が違う**。
- テスト担当者は「今ちゃんと動いてるのか／MP切れなのか／内部の複合状態のせいか」が分かりにくい。**投薬して治ったか判断する**ような難しさ。カプセル化は利用者には便利でも、**テストする人には害**になりうる。
- これはOOの**3原則の一つ（カプセル化）を捨てない限り**根本解決しにくい、というトレードオフ。

**関数型：純粋関数と副作用**

- **関数型**（Haskell、Scala、Rust など）はOOとは別パラダイム。構造化プログラミングの「関数」とは別で、ここでいうのは**純粋関数**。
- **純粋関数**：**副作用のない**関数。`f(x) = x²` は入力だけで決まるが、`f(x) = x² + 堀本のMP` のように**外部の変数状態に依存**すると、同じ `x=3` でも答えが9だったり18だったりする——参照透過性が壊れる。
- **副作用（side effect）**：堀本のMPのように、**計算のたびに世界の状態が変わる**処理。関数型はこれを**極力避け**、変数を「ぎゅっと」整理し、**入力と出力だけをつなぐ**記述を目指す。ユーザー入力などは**特殊な一箇所に寄せ**、残りはテストしやすくする。

**カプセル化への関数型からの批判（引用）**

関数型の本より：情報隠蔽（カプセル化）は本質ではなく、**副作用を抑えて再利用するための「臭いものに蓋」**にすぎない——ストップウォッチは使うだけなら中身不要でも、**修理屋・テスト担当は内部が要る**。堀本は「悲しくなった」と語る。

**関数型の「噂」と現実**

堀本は理論を完マスしていないが、よく言われる話として：

| 話題 | 内容 |
|------|------|
| テスト | 参照透過性で検証しやすい |
| 並列処理 | 副作用が少ないと一斉処理（Twitter的負荷）に強い、とされる |
| バグ | 副作用がバグの温床 → 取り除くと減る、とされる |
| Scala | **Twitter採用**で2010年代に「落ちにくい」「ロバスト」騒ぎ。大学生が入門書を買い勉強する**プレッシャー**——**ピークはそこまで**で、採用＝業界支配ではなかった |
| Rust | 近年ホット。Google・Gmail周りなどでの採用ニュース。堀本は「ラスト島民」気分 |

宿題ジョーク：Rust／Scalaで堀本のホームページを——阿部寛レベルなら**HTML（マークアップ）で足りる**。

**シリーズ総括：パラダイムシフト＝しばしば「ダウングレード」**

- プログラミング言語の変化は**半導体容量だけ**ではなく、**思想・パラダイムの転換**（非エンジニア向けメッセージ）。
- 3つのシフトはいずれも**技術的にはできることをあえて制限**した面がある：
  1. **構造化**：`goto` 自由をやめる  
  2. **OO**：カプセル化で外から内部をいじらせない  
  3. **関数型**（潮流）：副作用を抑える  
- 「表現の幅を狭めたが読みやすく／テストしやすくなった」——堀本の**官能小説・検閲**たとえは水野が「違うかも」と突っ込み、コメント欄で決めることに。
- 「関数型やっとかないと」も含め、**人間臭い**流行と不安。一般向けにこの手の史観本は少なく、ラジオは「面白説明おじさん」枠で続ける所存。

**今後の企画・募集**

- 『プログラミング言語大全』を読みながら**言語対戦／読み会**（Whitespace＝スペース・タブ・改行だけの真っ白ソースなど）。
- 関数型は監修付きでいつか本格回。
- コメント募集：**あなたの分野のパラダイムシフト**（例：水野／堀本——1973年猪木 vs アリ、権威から強さへ、寝技 vs 立ち技の「猪木状態」が総合格闘技の源流、など）。

**3パラダイムの一覧（シリーズ通し）**

1. **構造化プログラミング** — 宗教改革／ダイクストラ、`goto` 禁止、順次・選択・反復  
2. **オブジェクト指向** — ルネサンス／写実、データ＋処理の一体化、GUIと共鳴  
3. **関数型**（進行中の潮流） — 純粋関数、副作用排除、参照透過性、OO神話への反動
