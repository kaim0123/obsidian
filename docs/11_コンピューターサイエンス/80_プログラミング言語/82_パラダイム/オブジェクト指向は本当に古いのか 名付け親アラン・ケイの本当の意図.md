## 詳しい要約

**テーマ：オブジェクト指向の功罪 ― 業界が広めた「分類学」と名付け親の「メッセージング」**

オブジェクト指向には、Simula 由来の「現実の分類を写す」考え方と、アラン・ケイの「中身を隠してメッセージだけでやり取りする」考え方の 2 つがある。業界が持ち帰ったのは前者で、その罪は継承に集中した。2010 年代の Go・Rust・Java 8・React フックは継承による分類を切除し、カプセル化とインターフェースが残った。AI 時代には「境界」の価値が上がり、LLM こそケイの定義に最も近いオブジェクトだ、という結論。

---

### オープニング

- 仕事で触る言語（Java・C#・Python・TypeScript）はほぼ OOP なのに、Go には継承がなく Rust にはクラスがない。
- 名付け親アラン・ケイは 1997 年の OOPSLA 基調講演で「私がその言葉を作ったが、**C++ のことは念頭になかった**」と発言。

### 第1章 1967年ノルウェーで完成していた骨格

- 1960 年代ノルウェー計算センターの **クリステン・ニガードとオーレ＝ヨハン・ダール** が、港の混雑や原子炉の挙動を模擬するために **Simula 67** を作った。
- **クラス・オブジェクト・継承・仮想メソッド**という今の OOP の骨格はほぼすべて 1967 年に揃っていた。
- Simula にとってクラスは**現実の分類**（船 → タンカー）。生物の分類学のようなもので、これが後に功にも罪にもなる。
- 2 人は 2001 年にチューリング賞を受賞し、翌 2002 年に相次いで亡くなった。

### 第2章 名付け親アラン・ケイの本当の意図

- 分子生物学を学んだケイが見ていたのは**細胞**。細胞は中身を見せず、分子を送り合うことでだけやり取りする。
- 1972 年、ゼロックス・パロアルト研究所で Smalltalk を作ったケイにとって、オブジェクトは**互いにメッセージを送る小さな計算機**で、受け取った側がどう応じるかを自分で決める。最初の Smalltalk-72 には継承がなかった。
- ケイは後年「オブジェクトという言葉を作ったことを後悔している。**大きな考えはメッセージング**だ」と書いた。
- 1979 年、ベル研のビャーネ・ストラウストラップが C に Simula のクラスを足し、1985 年に C++ として公開。1995 年の Java が「すべてはオブジェクト」を掲げ企業標準に。どちらも継承したのはクラスで、**メッセージングと遅延束縛は落とした**。
- 業界の OOP はケイの思想ではなく、**Simula の分類学を継いだもの**。

### 第3章 功はカプセル化と共通語、罪は継承

- **功**：1990 年代の GUI（ウィンドウ・ボタンなどの部品）と OOP は相性が良かった。1994 年のデザインパターン本（GoF）が 23 の定石に名前を付け、設計の**共通語**ができた。
- その本の 20 ページ目には「**クラス継承よりオブジェクト合成を優先せよ**」と既に書かれていたが、読まれなかった。
- 継承が罪になる 3 つの理由：
  1. **脆い基底クラス問題**：親を 1 行直すと子クラス全部の挙動が変わる。
  2. **継承ツリーの肥大化**：分類学でコードを組むと 5〜6 段の継承ができ、どこで定義されたか追えなくなる。
  3. **名詞の王国**（2006 年、スティーブ・イェギのエッセイ）：動詞が許されず、「ゴミを捨てる」ためにマネージャークラスやストラテジーを作る。Spring には AbstractSingletonProxyFactoryBean という実在のクラス名がある。
- Erlang の作者ジョー・アームストロング（2009 年）：「バナナが欲しかっただけなのに、バナナを持ったゴリラとジャングル全体がついてきた」。
- 功は**カプセル化と共通語**、罪は**現実の分類を継承で写したこと**に集中している。

### 第4章 GoとRustが切除したもの

- 2009 年の Go（ロブ・パイク、ケン・トンプソンら）：クラスも継承もなく、構造体とインターフェースのみ。インターフェースは宣言不要で、メソッドが揃えば満たしたことになる。
- 2015 年 1.0 の Rust も同様で、トレイトで「できること」を後から足す。
- 2014 年 Java 8 にラムダ式、2019 年 React がフックを導入しクラスコンポーネントから関数コンポーネントへ。
- ゲーム業界では 2014 年、Insomniac のマイク・アクトンが CppCon で **データ指向設計**を掲げ、CPU キャッシュのために同じデータをまとめて並べろと主張。Unity は **ECS（Entity Component System）** として標準化。
- 捨てられたのは**継承による再利用**、残ったのは**カプセル化とインターフェース**。2010 年代の清算は OOP の否定ではなく、分類学の切除だった。

### 最終章 AI時代に「境界」の価値が上がる

- 実務面：深い継承階層では意味が複数ファイルに散り、一度に読める量に限りがある AI には不利。入出力で閉じた関数や**明確な境界（カプセル化）**は「この中だけ直せ」と指示でき、AI の味方になる。
- 思想面：LLM は中身を誰も読めず、こちらは言葉を送るだけで、受け取った側が応じ方を決める。**ケイが 1972 年に描いたオブジェクトそのもの**が、言語の外側から現れた。
- 功は**境界を引くことを教えたこと**、罪は**分類することを強いたこと**。分類は現実が変わると崩れるが、境界は残る。

### まとめ

- 業界の OOP（Simula の分類学）と名付け親の OOP（メッセージング）は別物。
- 継承による分類が罪の中心で、Go・Rust などはそこを切除した。
- クラス設計時は「これは現実の分類か、変更を閉じ込める境界か」を問う。
- AI 時代に境界（カプセル化）の価値はむしろ上がる。
