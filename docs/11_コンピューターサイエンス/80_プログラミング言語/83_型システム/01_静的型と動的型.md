# 静的型と動的型

## 型とは
値の**種類**を表す情報です。「数値」「文字列」「配列」などのカテゴリ分けで、そのデータに対して何ができるかを決めます。

## 静的型付けと動的型付けの違い
型チェックが**いつ行われるか**による分類です。

| 項目 | 静的型付け | 動的型付け |
|---|---|---|
| 型チェック | コンパイル時 | 実行時 |
| 型注釈 | 必要（推論も） | 不要 |
| エラー発見 | 実行前 | 実行後 |
| 柔軟性 | 低い | 高い |
| 実行速度 | 速い傾向 | 遅い傾向 |
| 代表言語 | Java, Go, Rust, TS | Python, JS, Ruby |

## 静的型の例（TypeScript）
```typescript
function add(a: number, b: number): number {
  return a + b;
}

add(1, 2);          // OK
add(1, "hello");    // コンパイルエラー（実行前に判明）
```

## 動的型の例（Python）
```python
def add(a, b):
    return a + b

add(1, 2)          # 3
add("a", "b")      # "ab"
add(1, "a")        # TypeError（実行してはじめて分かる）
```

## 静的型のメリット

### ① 実行前にバグを発見
```typescript
const user: { name: string } = { name: "Alice" };
user.age;  // エラー: プロパティがない
```

### ② エディタ支援が強力
- 自動補完
- リファクタリング（名前変更の安全な置換）
- 定義ジャンプ

### ③ ドキュメントになる
シグネチャを読むだけで関数の使い方がわかる。
```typescript
function getUser(id: number): Promise<User | null>
```

### ④ 実行速度の最適化
型がわかっているとコンパイラが効率的なコードを生成できる。

## 動的型のメリット

### ① 書き始めが速い
型定義を考えずに書ける。プロトタイピングや探索的作業に向く。
```python
data = [{"name": "A"}, {"name": "B"}]
for d in data: print(d["name"])
```

### ② 柔軟性
同じ関数が様々な型を受け付けられる（ダックタイピング）。

### ③ メタプログラミングしやすい
実行時に型を決める、動的に属性を追加する、などが容易。

## ダックタイピング
動的型言語の特徴。「**アヒルのように鳴けばアヒル**」＝型名でなく、持っているメソッドで判断。
```python
class Duck:
    def quack(self): print("ガー")
class Person:
    def quack(self): print("ガーっぽく")

def make_it_quack(x):
    x.quack()   # x の型は何でもいい、quack があれば動く
```

## 静的型と動的型の中間

### 型ヒント（Python, Ruby）
動的型に後付けで型注釈。実行時には影響しないがツールが使える。
```python
def greet(name: str) -> str:
    return f"Hello, {name}"
```

### 段階的型付け（Gradual Typing）
一部だけ型を付けられる。TypeScript、Python + mypy、Flow など。
```typescript
function process(x: any) {  // 部分的に any で緩和
  return x.toString();
}
```

### 動的＋JIT最適化
JavaScriptのV8、PyPyなど実行時に型を推論して高速化。

## 型チェックの強度と独立
「静的/動的」と「強い/弱い」は別の軸です。

| 言語 | 静的/動的 | 強い/弱い |
|---|---|---|
| Java | 静的 | 強い |
| C | 静的 | 弱い（暗黙変換多い） |
| Python | 動的 | 強い |
| JavaScript | 動的 | 弱い |
| Haskell | 静的 | 非常に強い |

## 使い分けの指針

### 静的型が向く場面
- 大規模開発、長期保守
- チーム開発
- パフォーマンスが重要
- ミスが許されない（金融・インフラ）

### 動的型が向く場面
- プロトタイピング
- スクリプト、自動化
- データ分析、研究コード
- 小規模・短命コード

## 実務での現状
多くの現場で「**段階的に型を付ける**」アプローチが主流。
- Node.js → TypeScriptへ移行
- Python + mypy / pyright
- Ruby + RBS / Sorbet
- Clojure + spec

## まとめ
- **静的型 = 実行前に型チェック**、**動的型 = 実行時に型チェック**
- 静的型: 安全・速い・大規模向き
- 動的型: 柔軟・書き始めが速い・小規模〜探索向き
- 現代は**段階的型付け**で両者の長所を取り入れるのが主流
