# 代数的データ型（ADT）

## 代数的データ型とは
複数の型を**組み合わせて作る型**のことです。主に
- **直積型（Product Type）**: 複数の値を同時に持つ（AND）
- **直和型（Sum Type / Tagged Union）**: 複数の選択肢のうち1つを持つ（OR）

の2種類を組み合わせて構成します。Haskell、ML、Rust、Swift、TypeScriptなどで強力に使えます。

## 直積型（Product Type）

### 概念
「A **かつ** B」を持つ型。レコード、タプル、構造体、オブジェクトなど。

### 例
```typescript
type User = {
  name: string;
  age: number;
};
// User は name AND age を両方持つ
```

```rust
struct Point { x: f64, y: f64 }
```

### タプル
```typescript
type Coord = [number, number];
const p: Coord = [10, 20];
```

```python
from typing import Tuple
p: Tuple[int, int] = (10, 20)
```

## 直和型（Sum Type / Tagged Union）

### 概念
「A **または** B **または** C」、どれか1つの型を取る。状態や結果の表現に強力。

### TypeScriptの判別可能なUnion
```typescript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number }
  | { kind: "rect"; w: number; h: number };

function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.radius ** 2;
    case "square": return s.side ** 2;
    case "rect":   return s.w * s.h;
  }
}
```

### Rustのenum
```rust
enum Shape {
    Circle(f64),
    Square(f64),
    Rect { w: f64, h: f64 },
}

fn area(s: Shape) -> f64 {
    match s {
        Shape::Circle(r)    => std::f64::consts::PI * r * r,
        Shape::Square(a)    => a * a,
        Shape::Rect { w, h } => w * h,
    }
}
```

### Haskell
```haskell
data Shape = Circle Double | Square Double | Rect Double Double

area :: Shape -> Double
area (Circle r)   = pi * r * r
area (Square a)   = a * a
area (Rect w h)   = w * h
```

### Swift
```swift
enum Shape {
    case circle(radius: Double)
    case square(side: Double)
    case rect(w: Double, h: Double)
}
```

## なぜ「代数的」なのか
- 直積型: 型の**積**（AとBの組み合わせ）
- 直和型: 型の**和**（AまたはB）

組み合わせ論理と同じ代数的な計算ができるからです。
- `A × B` は `A × B` 通りの値を取る
- `A + B` は `A + B` 通りの値を取る

## よく使うADTの例

### Option / Maybe
値があるかないか。nullの代わり。
```rust
enum Option<T> {
    Some(T),
    None,
}
```

```typescript
type Option<T> = { kind: "some"; value: T } | { kind: "none" };
```

使用例:
```rust
fn find(id: u32) -> Option<User> { ... }

match find(42) {
    Some(user) => println!("{}", user.name),
    None       => println!("not found"),
}
```

### Result / Either
成功または失敗を型で表現。
```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}

fn parse(s: &str) -> Result<i32, String> { ... }
```

```typescript
type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E };
```

### リスト
```haskell
data List a = Nil | Cons a (List a)
```
再帰的な直和型。

### 木構造
```rust
enum Tree<T> {
    Leaf,
    Node(T, Box<Tree<T>>, Box<Tree<T>>),
}
```

## パターンマッチングとの相性
ADTはパターンマッチングと組み合わせて本領発揮。**すべてのケースを網羅**しないとコンパイルエラーになるので、漏れを防げます。

### 網羅性チェック
```rust
enum Status { Loading, Success, Error }

fn show(s: Status) -> &'static str {
    match s {
        Status::Loading => "…",
        Status::Success => "OK",
        // Error を忘れるとコンパイルエラー
    }
}
```

### TypeScriptの網羅性
```typescript
function assertNever(x: never): never { throw new Error("unreachable"); }

function area(s: Shape) {
  switch (s.kind) {
    case "circle": return ...;
    case "square": return ...;
    case "rect":   return ...;
    default: return assertNever(s);   // 追加忘れでエラー
  }
}
```

## 従来のオブジェクト指向との比較

### オブジェクト指向（サブクラス）
```java
abstract class Shape { abstract double area(); }
class Circle extends Shape { ... }
class Square extends Shape { ... }
```
振る舞いを各クラスに分散。新しい**型**追加は楽だが、新しい**操作**追加は大変。

### ADT（パターンマッチ）
```rust
enum Shape { Circle(f64), Square(f64) }
fn area(s: Shape) -> f64 { match s { ... } }
fn perimeter(s: Shape) -> f64 { match s { ... } }
```
振る舞いを中央集約。新しい**操作**追加は楽だが、新しい**型**追加は全ての関数を修正する必要。

### どちらが良いか
- 変化の軸が**型を追加**: OOPが向く
- 変化の軸が**操作を追加**: ADTが向く

これは「Expression Problem」として知られています。

## ADTの利点

### ① 「不可能な状態」を型で禁止できる
例: 「ロード中なのにエラーも表示する」のような矛盾状態を型レベルで排除。
```typescript
type State =
  | { kind: "loading" }
  | { kind: "error"; message: string }
  | { kind: "loaded"; data: User };
// loading と error の両方を同時には持てない
```

### ② 網羅性チェックで漏れを防ぐ
新しいケースを追加すると、使っている全ての `match` が壊れて教えてくれる。

### ③ ドメインモデルが明確
ビジネスロジックをそのまま型に写し取れる。

## 実用例: API結果
```typescript
type ApiResult<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; message: string };

function render(r: ApiResult<User>) {
  switch (r.status) {
    case "idle":    return "待機中";
    case "loading": return "読み込み中...";
    case "success": return `ようこそ ${r.data.name}`;
    case "error":   return `エラー: ${r.message}`;
  }
}
```

## 各言語でのサポート状況

| 言語 | ADT | パターンマッチ |
|---|---|---|
| Haskell | 強力 | 非常に強力 |
| Rust | 強力 | 強力 |
| Swift | 強力 | 強力 |
| TypeScript | 判別可能Union | switch + never |
| Scala | sealed trait | match |
| Python (3.10+) | Union型 | match-case |
| Java (17+) | sealed class | pattern matching |

## まとめ
- ADTは**直積（AND）と直和（OR）**を組み合わせて作る型
- 直和型 + パターンマッチで**網羅性チェック**が効く
- 「不可能な状態を表せない」ようにドメインを設計できる
- `Option`, `Result`, 状態モデリングで威力を発揮
- OOPとは得意分野が異なるので、場面で使い分ける
