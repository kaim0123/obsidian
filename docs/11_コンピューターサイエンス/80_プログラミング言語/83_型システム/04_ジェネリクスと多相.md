# ジェネリクスと多相

## 多相（ポリモーフィズム）とは
**1つのコード・関数・型が複数の型に対して動く**性質のことです。「多くの形に適応する」というギリシャ語由来の言葉。

## 多相の種類

### 1. パラメトリック多相（ジェネリクス）
型をパラメータ化して、どんな型でも動く関数・データ構造を作る。

### 2. サブタイプ多相（継承・インターフェース）
サブクラスが親クラスとして振る舞える。

### 3. アドホック多相（オーバーロード・トレイト）
同じ名前でも型ごとに別実装を持つ。

### 4. 強制多相
暗黙変換による多相（弱い型付けで見られる）。

## ジェネリクス（パラメトリック多相）

### 基本のイメージ
型を「引数」として受け取る関数・クラス。
```typescript
function identity<T>(x: T): T {
  return x;
}

identity<number>(42);      // T = number
identity<string>("hi");    // T = string
identity(true);            // T = boolean（推論）
```

### ジェネリクスがないと
```typescript
function identityNumber(x: number): number { return x; }
function identityString(x: string): string { return x; }
// 型ごとに書く羽目になる
```

## ジェネリックなデータ構造

### 汎用リスト
```typescript
class Stack<T> {
  private items: T[] = [];
  push(x: T): void { this.items.push(x); }
  pop(): T | undefined { return this.items.pop(); }
}

const s1 = new Stack<number>();
const s2 = new Stack<string>();
```

### 複数のパラメータ
```typescript
class Pair<K, V> {
  constructor(public key: K, public value: V) {}
}
```

## 各言語でのジェネリクス

### Java
```java
class Box<T> {
    private T value;
    public T get() { return value; }
    public void set(T v) { this.value = v; }
}

Box<String> b = new Box<>();
```

### C#
```csharp
class Box<T> {
    public T Value { get; set; }
}
```

### Rust
```rust
struct Pair<K, V> { key: K, value: V }

fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list { if item > largest { largest = item; } }
    largest
}
```

### Go（1.18〜）
```go
func Max[T constraints.Ordered](a, b T) T {
    if a > b { return a }
    return b
}
```

### Python（typing）
```python
from typing import TypeVar, List
T = TypeVar("T")

def first(xs: List[T]) -> T:
    return xs[0]
```

## 型制約（バウンド）

ジェネリクスに「こういう型じゃないとダメ」の制約を付ける。

```typescript
interface HasLength { length: number; }

function log<T extends HasLength>(x: T): void {
  console.log(x.length);
}

log("hello");       // OK（string は length を持つ）
log([1, 2, 3]);     // OK
log(42);            // エラー
```

```java
<T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}
```

## 変位（Variance）
ジェネリック型における**親子関係の伝わり方**。詳細は別章「型安全性と共変反変」へ。

## サブタイプ多相
継承またはインターフェース実装による多相。
```typescript
interface Animal { sound(): string; }

class Dog implements Animal { sound() { return "Woof"; } }
class Cat implements Animal { sound() { return "Meow"; } }

function describe(a: Animal) {
  console.log(a.sound());
}
describe(new Dog());   // "Woof"
describe(new Cat());   // "Meow"
```

## アドホック多相

### メソッドオーバーロード（Java等）
```java
int add(int a, int b)       { return a + b; }
double add(double a, double b) { return a + b; }
String add(String a, String b) { return a + b; }
```

### 演算子オーバーロード（Python, C++）
```python
class Vec:
    def __init__(self, x, y): self.x, self.y = x, y
    def __add__(self, other): return Vec(self.x+other.x, self.y+other.y)

Vec(1,2) + Vec(3,4)  # Vec(4,6)
```

### 型クラス / トレイト
Haskellの型クラス、Rustのトレイトは**型ごとに別実装**を提供する仕組み。
```rust
trait Greet { fn greet(&self) -> String; }

impl Greet for String { fn greet(&self) -> String { format!("Hi {}", self) } }
impl Greet for i32    { fn greet(&self) -> String { format!("#{}", self) } }
```

## ジェネリクスのメリット

### ① 型安全性を保ったまま再利用
- 配列、キュー、マップなどを汎用化
- 型チェックが効くため、誤用が減る

### ② コード重複の削減
同じロジックを型ごとに書き直す必要がない。

### ③ 抽象度の向上
アルゴリズム自体（ソートなど）を型に依存しない形で表現できる。

## ジェネリクスの落とし穴

### 過剰なジェネリクス
必要以上に型パラメータを増やすとコードが難解に。
```typescript
// 複雑すぎる例
function f<A, B extends A, C extends B, D extends C>(...) { ... }
```
「本当に複数型で使うのか？」を自問する。

### 型消去（Java）
Javaのジェネリクスは実行時には消える（`List<String>` と `List<Integer>` は同じ `List`）。リフレクション時に注意。

### 制約の組み合わせ
境界を複数付けると読みにくい。インターフェースに切り出すと整理される。

## 実用例

### Result型（Rust）
```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```
成功と失敗を型で表現する代表的なジェネリクス。

### Promise / Future
```typescript
function fetchUser(id: number): Promise<User> { ... }
```
非同期結果をジェネリクスで型付け。

### コレクションAPI
- `Array<T>`, `Map<K, V>`, `Set<T>`
- `Stream<T>`, `Optional<T>`

## まとめ
- 多相 = **1つのコードが複数の型で動く**性質
- **ジェネリクス（パラメトリック多相）**が最も重要
- 型制約（バウンド）で制限をかけられる
- **サブタイプ多相**（継承）、**アドホック多相**（オーバーロード・トレイト）も覚えておく
- 過剰なジェネリクスは可読性を損なう。**必要な時にだけ**使う
