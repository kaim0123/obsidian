# 強い型付けと弱い型付け

## 型付けの「強い/弱い」とは
言語が**型の違いをどれだけ厳密に扱うか**の度合いです。異なる型を混ぜた時に
- **拒否する** → 強い型付け
- **暗黙に変換して通す** → 弱い型付け

なお、静的/動的とは**独立した軸**です。

## 弱い型付けの例（JavaScript）
```javascript
1 + "2";       // "12"   数値→文字列に暗黙変換
"5" - 3;       // 2      文字列→数値に暗黙変換
[] + {};       // "[object Object]"
"5" == 5;      // true   型が違っても等しい
```
これは柔軟な反面、**予期せぬ変換**でバグの温床になります。

## 強い型付けの例（Python）
```python
1 + "2"        # TypeError: unsupported operand type(s)
"5" - 3        # TypeError
```
暗黙変換しないので、意図しない挙動は起きにくい。

## 強さの段階
現実には「強い/弱い」は程度問題。以下のように並べられます。

```
強い ←──────────────────────────→ 弱い
Haskell > Rust > Python > Java > JavaScript > PHP > C
```

## 各言語の性質

### JavaScript（弱い型付け）
- 暗黙の型変換が非常に多い
- `==` と `===`（厳密等価）の使い分けが必要
- `parseInt`, `Number()` など明示変換でバグ回避

### Python（強い型付け・動的）
- `1 + "a"` は即エラー
- 変換は `int()`, `str()` など**明示**

### Java（強い型付け・静的）
- 型が合わないとコンパイルエラー
- 明示的なキャスト `(int) d` が必要
- ただし数値同士の `int → long` などは自動で昇格

### C / C++（弱めの型付け）
- ポインタ ⇄ 整数などの暗黙変換が可能
- `void*` へ/からの変換も緩い
- 古いCほど緩く、C++は強化されている

### Haskell / Rust（非常に強い型付け）
- 整数と浮動小数点ですら自動変換しない
```haskell
1 + 2.0  -- エラー（明示的なfromIntegralが必要）
```

## 強い型付けのメリット

### ① 予期せぬ挙動が起きにくい
```javascript
// 弱い型付けでよくあるバグ
const price = "100";
const tax = 10;
price + tax;  // "10010"（文字列結合）
```

### ② リファクタリング時に安心
型が合わないと即エラーになるので検知しやすい。

### ③ 仕様をコードで強制できる
「この値は必ず整数」といった制約を型で担保。

## 弱い型付けのメリット

### ① コードが短く書ける
型変換を意識せずに書ける場合がある。

### ② 動的型と組み合わせると柔軟
テンプレート処理や設定読み込みで便利。

### ③ 文字列と数値を自然に連結
```javascript
const msg = "Age: " + age;  // 直感的
```

## よくある暗黙変換（JS）

| 式 | 結果 | 理由 |
|---|---|---|
| `"1" + 1` | "11" | + は文字列優先 |
| `"1" - 1` | 0 | - は数値演算 |
| `true + 1` | 2 | true → 1 |
| `[] == false` | true | 複雑な変換ルール |
| `null == undefined` | true | 特殊ルール |
| `NaN === NaN` | false | 仕様 |

これらはバグの温床。**`===` / `Number()` / `String()` を使って明示**するのが鉄則。

## 型強制（Coercion）と型変換（Conversion）

### 暗黙的型強制（Coercion）
言語が勝手に行う（弱い型付けの特徴）。
```javascript
"5" * 2  // 10
```

### 明示的型変換（Conversion / Cast）
プログラマが指定する。
```javascript
Number("5") + 2;         // 7
parseInt("10px", 10);    // 10
String(42);              // "42"
```

```java
int i = (int) 3.7;       // Javaのキャスト
```

## 「等価性」の比較

### `==`（ゆるい比較、JS）
型が違えば変換を試みる → 驚きの挙動
```javascript
"0" == false;  // true
"" == 0;       // true
```

### `===`（厳密比較、JS）
型も値も同じかを判定
```javascript
"0" === false;  // false
"0" === 0;      // false
```

### Pythonの `==`
値を比較、暗黙変換はほぼしない
```python
"5" == 5  # False
```

## バグを避けるためのルール

### 1. `==` ではなく `===` を使う（JS）
### 2. 明示変換を習慣に
```javascript
const total = Number(input) + 100;
```
### 3. TypeScript 等で型を明示
### 4. バリデーションを境界で行う
外部入力（フォーム、API、DB）が入る時点で正しい型に変換しておく。

## 実例: ユーザー入力の処理
```javascript
// ❌ 暗黙変換任せ
const age = req.body.age + 1;  // "25" + 1 → "251"

// ✅ 明示変換
const age = Number(req.body.age) + 1;
if (Number.isNaN(age)) throw new Error("不正な年齢");
```

## まとめ
- **強い型付け = 暗黙変換をしない**、**弱い型付け = 暗黙変換する**
- 静的/動的とは独立した概念
- JavaScriptは弱い、Python / Rust / Haskellは強い
- **暗黙変換はバグの温床**、明示変換と厳密等価（`===`）を徹底するのが安全
