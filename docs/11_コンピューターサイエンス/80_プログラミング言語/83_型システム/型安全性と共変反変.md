# 型安全性と共変反変

## 型安全性とは
型に関する**ルール違反が起きないこと**を保証する性質です。型安全な言語では、
- 数値を文字列として使えない
- 存在しないプロパティを参照できない
- 不正なキャストを実行時に防ぐ

といった保護があります。

## 「どの段階で守るか」

### コンパイル時の型安全
静的型言語が提供。実行前にエラーになる。
```typescript
const n: number = "hello";  // エラー
```

### 実行時の型安全
動的型言語でも、変な操作をすると例外になる。
```python
"abc".append(1)  # AttributeError
```

### 完全に型安全でない例
Cの未初期化ポインタ、型の弱い暗黙変換などは**未定義動作**を引き起こすことがある。

## 型安全性が崩れる操作

### any型（TypeScript）
```typescript
const x: any = "str";
x.nonExistent();  // コンパイル通るが実行時エラー
```

### 強制キャスト
```typescript
const x = "10" as unknown as number;  // 危険
```
```java
Object o = "hello";
Integer i = (Integer) o;  // ClassCastException
```

### 生ポインタ（C/C++）
メモリを直接操作できる反面、型を無視して読み書きできてしまう。

## 型安全性を保つ言語機能

### ヌル許容/非許容の区別
```typescript
let a: string = "hi";
let b: string | null = "hi";  // null を許す
```

### 網羅性チェック（Exhaustiveness）
```typescript
type Shape = "circle" | "square";

function area(s: Shape) {
  switch (s) {
    case "circle": return ...;
    case "square": return ...;
    // 新しい値 "triangle" を追加 → コンパイルエラーで検出
  }
}
```

### 所有権システム（Rust）
メモリ安全と型安全を同時に保証。

## 変位（Variance）とは
**ジェネリック型における親子関係の扱い方**です。`Animal` を継承した `Dog` があるとき、`List<Dog>` は `List<Animal>` のサブタイプなのか？ という問題。

```
Animal
  └─ Dog
```

## 4つの変位

### 共変（Covariant）
`Dog ≦ Animal` ならば `G<Dog> ≦ G<Animal>`。

例: 読み取り専用のリスト
```typescript
type ReadonlyList<out T> = { get(i: number): T };
// ReadonlyList<Dog> を ReadonlyList<Animal> として使える
```
**出力（戻り値）方向に使う型**は共変にできる。

### 反変（Contravariant）
`Dog ≦ Animal` ならば `G<Animal> ≦ G<Dog>`。

例: 関数の引数
```typescript
type Handler<in T> = (value: T) => void;
// Handler<Animal> を Handler<Dog> として使える
// （Animal を処理できる関数は Dog も処理できる）
```
**入力（引数）方向に使う型**は反変にできる。

### 不変（Invariant）
親子関係がまったく伝わらない。読み書き両方に使うケース。
```typescript
type Box<T> = { value: T };
// Box<Dog> と Box<Animal> は互換性なし
```

### 双変（Bivariant）
共変・反変のどちらとしても扱える。安全性は低い。
- TypeScriptの関数パラメータはデフォルト双変（`strictFunctionTypes` でオフ）

## 直感的な覚え方

```
出力（read）→ 共変（Covariant、親方向OK）
入力（write/arg）→ 反変（Contravariant、子方向OK）
両方（read/write）→ 不変（Invariant）
```

「**PECS原則**（Producer Extends, Consumer Super）」で覚えるのが一般的。

## 具体例: 関数の型

```typescript
type AnimalHandler = (a: Animal) => void;
type DogHandler    = (d: Dog) => void;
```

### 引数は反変
```typescript
let f: DogHandler = (d: Dog) => {};
let g: AnimalHandler = (a: Animal) => {};

// 安全:
f = g;  // AnimalHandler を DogHandler として使える（Animalを受けられる関数は Dog を受けられる）

// 危険:
g = f;  // Dog 専用関数を Animal 引数として使うと Cat が来た時に壊れる
```

### 戻り値は共変
```typescript
type GetAnimal = () => Animal;
type GetDog    = () => Dog;

let gA: GetAnimal = () => new Dog();  // OK（Dog は Animal）
```

## Java / C#での変位注釈

### Java（ワイルドカード）
```java
List<? extends Animal>  // 共変（読み取り専用）
List<? super Dog>       // 反変（書き込み専用）
```

### C#（in / out）
```csharp
interface IReader<out T> { T Read(); }          // 共変
interface IWriter<in T>  { void Write(T v); }   // 反変
```

### Kotlin
```kotlin
interface Source<out T> { fun next(): T }   // 共変
interface Sink<in T>    { fun put(v: T) }   // 反変
```

### TypeScript 4.7〜
```typescript
interface Consumer<in T> { accept(v: T): void; }
interface Producer<out T> { produce(): T; }
```

## 配列の変位の罠

### Javaの配列は共変（危険）
```java
Number[] nums = new Integer[3];
nums[0] = 1.5;   // ArrayStoreException（実行時エラー）
```
型安全のため、**ジェネリクス**を使った方が良いとされる。

### TypeScriptの配列
```typescript
const dogs: Dog[] = [new Dog()];
const animals: Animal[] = dogs;  // OK（共変）
animals.push(new Cat());          // 実は危険
dogs[1]; // Cat が入っている…
```
TypeScriptも配列は実質共変で、同じような穴がある。

## 実務での指針

### 読み取り用途は `readonly` / 共変
```typescript
function printAll(items: readonly Animal[]) {
  items.forEach(a => console.log(a));
}
```

### 書き込み用途は不変か反変
```typescript
function stuff(box: { value: Dog }) {
  box.value = new Dog();  // Animal ではダメ
}
```

### 関数型は引数反変・戻り値共変
設計時にこれを意識するとしっくりくる。

## まとめ
- **型安全性**は「型ルール違反を防ぐ保証」、崩れると未定義動作や実行時エラーに
- 共変/反変/不変は**ジェネリクスと親子関係**の話
- **読み取り（出力）は共変**、**書き込み（入力）は反変**、**両方使うなら不変**
- Javaのワイルドカード、C#の`in/out`、TSの`in/out`、Kotlinの`in/out`で指定
- 配列は歴史的に共変だが穴があり、現代では `readonly` の使用が推奨
