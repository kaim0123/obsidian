# 型推論

## 型推論とは
プログラマが型注釈を書かなくても、**コンパイラ/インタプリタが自動的に型を決めてくれる**仕組みです。静的型言語でも、ある程度までは型を省略できるようになります。

```typescript
let x = 10;        // number と推論される
let s = "hello";   // string と推論
```

## 型注釈 vs 型推論

### 型注釈（明示）
```typescript
let age: number = 20;
```

### 型推論（暗黙）
```typescript
let age = 20;      // number と推論
```

どちらも結果は同じ。読み手に意図を伝えたい/境界を明確にしたい場面では注釈、それ以外は推論に任せると簡潔。

## 推論の仕組み（ざっくり）

### 初期化式から
```typescript
let n = 42;           // リテラル 42 → number
let arr = [1, 2, 3];  // number[]
```

### 関数の戻り値
```typescript
function add(a: number, b: number) {
  return a + b;   // 戻り値は number と推論
}
```

### 文脈から（Contextual Typing）
```typescript
const nums: number[] = [];
nums.map(n => n * 2);   // n は number と推論（配列要素の型から）
```

## 言語ごとの推論力

### Haskell / ML系（最強クラス）
Hindley-Milner型推論により、ほぼ注釈なしで動く。
```haskell
add x y = x + y
-- (Num a) => a -> a -> a と推論
```

### Rust
関数引数と戻り値は**必ず型注釈**、関数内のローカルは強力に推論。
```rust
fn add(a: i32, b: i32) -> i32 {
    let sum = a + b;       // i32 と推論
    sum
}
```

### TypeScript
ローカル変数・配列・関数戻り値などを推論。関数パラメータは原則注釈が必要。
```typescript
const user = { name: "Alice", age: 20 };
// { name: string; age: number } と推論
```

### Go
`:=` で型推論。
```go
x := 10           // int
s := "hello"      // string
```

### Kotlin / Swift / C# `var`
ローカル変数で強力に推論。
```kotlin
val x = 10        // Int
val s = "hello"   // String
```

## 推論の限界

### 関数パラメータ
文脈がないと型が決まらない。
```typescript
function add(a, b) { return a + b; }  // エラー（暗黙anyで危険）
```

### 空配列
```typescript
const arr = [];   // never[] または any[] に推論される場合
```
何を入れる配列か分からないため、明示が安全。

### ジェネリクスの初期化
```typescript
const map = new Map();  // Map<any, any>
// 明示するなら
const map = new Map<string, number>();
```

## リテラル型の推論

### `let` は広く、`const` は狭く
```typescript
let x = "hello";   // string
const y = "hello"; // "hello"（リテラル型）
```

### 絞り込み（Narrowing）
```typescript
function f(x: string | number) {
  if (typeof x === "string") {
    x.toUpperCase();  // この中では x は string
  }
}
```

## 推論に頼るコツ

### ① 境界（API・公開関数）は明示
使う側・読み手のために書く。
```typescript
export function fetchUser(id: number): Promise<User> { ... }
```

### ② 内部ローカルは推論
短い関数内では省略しても読みやすい。
```typescript
const total = items.reduce((sum, i) => sum + i.price, 0);
```

### ③ 意図を伝えたい場合は注釈
「この変数は絶対に `string` として扱う」など。

## 推論で起きがちな落とし穴

### 過剰な汎化
```typescript
const arr = [1, "a"];   // (string | number)[]
```
想定より広い型になっていないか注意。

### 逆に狭すぎる
```typescript
const state = "loading";  // "loading" 型（const）
// これを後で state = "idle" にしたいならエラー
let state: "loading" | "idle" = "loading";
```

### 暗黙のany
```typescript
function f(x) { ... }  // TS の noImplicitAny が無効だと any に
```

## 型推論とツール支援
IDEがホバーで推論結果を表示してくれる。
- VS Code: 変数にマウスオーバーで型が出る
- `// ^?` ツールチップ（TypeScript Twoslash）

## 関連テクニック

### satisfies（TypeScript）
値の型を保ちつつ、ある型を満たすか検査。
```typescript
const config = {
  host: "localhost",
  port: 8080,
} satisfies Config;
config.port.toFixed();  // number と推論されたまま使える
```

### as const
リテラル型として固定。
```typescript
const colors = ["red", "green", "blue"] as const;
// readonly ["red", "green", "blue"]
```

### typeof / ReturnType
値や関数から型を引き出す。
```typescript
const defaults = { lang: "ja", dark: true };
type Settings = typeof defaults;
type Result = ReturnType<typeof fetchUser>;
```

## まとめ
- 型推論は**書かなくても型を決めてくれる**仕組み
- ローカルは推論に任せ、**境界（API・公開関数）は明示**
- 言語ごとに推論の強さが違う（Haskell > Rust > TS > Go）
- `let` と `const`、リテラル型、`satisfies` など TS の特徴的機能も理解しておく
- 過剰な汎化・狭すぎる推論に注意
