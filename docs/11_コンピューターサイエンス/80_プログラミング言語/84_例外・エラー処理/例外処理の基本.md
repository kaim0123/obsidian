# 例外処理の基本

## 例外とは
プログラム実行中に発生する**想定外の事態**を表す仕組みです。ファイルが見つからない、ネットワークが切れた、0で割った、などを通常の戻り値ではなく「例外」としてプログラムの流れから分離します。

```javascript
try {
  JSON.parse("invalid");
} catch (e) {
  console.log("パースに失敗: " + e.message);
}
```

## try / catch / finally

### 基本構造
```javascript
try {
  // 例外が起きるかもしれない処理
} catch (e) {
  // 例外が起きたときの処理
} finally {
  // 成功/失敗に関わらず最後に実行される処理
}
```

### 各言語の構文
| 言語 | 構文 |
|---|---|
| Java/C#/JS | `try/catch/finally` |
| Python | `try/except/else/finally` |
| Ruby | `begin/rescue/ensure` |
| Rust | 例外なし。`Result<T, E>` |
| Go | 例外なし。戻り値でエラー |

## 例外の発生

### throw / raise
```javascript
if (age < 0) throw new Error("年齢は0以上");
```

```python
if age < 0:
    raise ValueError("年齢は0以上")
```

```java
throw new IllegalArgumentException("年齢は0以上");
```

## 例外の伝播
例外は`throw`した地点から**呼び出し元へ連鎖的に伝わり**、`catch`されるまで遡ります。

```
[main] → [service] → [dao] ←┐
                             │ 例外発生
[main] ←─ [service] ←─ [dao] ┘ 上へ伝わる
  catch
```

どこでも捕捉されないと、プログラムはクラッシュします。

## スタックトレース
例外が発生した時の**呼び出し履歴**。バグの原因特定に役立つ。
```
Error: 年齢は0以上
    at validate (src/user.js:10)
    at createUser (src/user.js:20)
    at main (src/main.js:5)
```

## 例外の種類（階層）
多くの言語で例外はクラス階層を持ちます。
```
Error (Throwable)
  ├─ RuntimeException
  │    ├─ NullPointerException
  │    ├─ IllegalArgumentException
  │    └─ IndexOutOfBoundsException
  ├─ IOException
  │    ├─ FileNotFoundException
  │    └─ ...
  └─ ...
```

## 複数の例外を捕まえる

### Python
```python
try:
    risky()
except FileNotFoundError as e:
    print("ファイル無し")
except PermissionError as e:
    print("権限無し")
except Exception as e:
    print("その他:", e)
```

### JavaScript（型で分岐）
```javascript
try {
  risky();
} catch (e) {
  if (e instanceof RangeError) { ... }
  else if (e instanceof TypeError) { ... }
  else throw e;  // 予想外は再送出
}
```

### Java（マルチキャッチ）
```java
try { ... }
catch (IOException | SQLException e) { ... }
```

## 例外の再送出
処理できない例外は**そのまま上に投げる**のが鉄則。
```javascript
try { ... }
catch (e) {
  log(e);
  throw e;   // または throw new WrapError("context", e);
}
```

## カスタム例外
業務ロジックに合った例外型を作ると、呼び出し元で適切に処理できる。
```typescript
class NotFoundError extends Error {
  constructor(public id: string) {
    super(`id=${id} not found`);
  }
}

throw new NotFoundError("user-42");
```

## 例外とエラー戻り値の違い

### 例外
- コードの正常系から切り離せる
- 呼び出し元で受けないと落ちる
- スタックトレースで追跡しやすい

### エラー戻り値（Go, Rust）
```go
user, err := getUser(id)
if err != nil { return err }
```
- 明示的なエラー処理が必要
- 型レベルで見落としを防げる
- コードが冗長になりやすい

両方のアプローチに長所短所があります。

## 例外の使いどころ
- **例外的・異常な状態**: ファイル読み取り失敗、ネットワーク切断
- **プログラムのバグ**: 想定外のnull、配列外アクセス
- **外部システム連携の失敗**: DB接続、API呼び出し

### 例外で表現すべきでないもの
- 正常な分岐（例: 検索結果が0件 → 例外ではなく空リストで返す）
- ループ制御（例外で抜けるのは遅い・読みづらい）
- バリデーション失敗（設計次第、戻り値で返す方が扱いやすい場合も）

## よくあるアンチパターン

### 1. 空catch（例外を握り潰す）
```javascript
try { risky(); }
catch (e) { /* 何もしない */ }
```
バグの温床。最低でもログを残すこと。

### 2. `catch (Exception)` で全部掴む
粒度が粗すぎ。想定外まで飲み込んでしまう。

### 3. メッセージを失う
```java
catch (IOException e) {
    throw new RuntimeException("failed");  // 元のeが消える
}
```
→ 原因例外を保持：
```java
throw new RuntimeException("failed", e);
```

### 4. 例外で正常処理を表す
例外はコストが高く、デバッグも難しい。通常の制御フローに使わない。

## finallyの使い方
リソース解放などの後処理に使う。
```javascript
let conn;
try {
  conn = await db.connect();
  await conn.query(...);
} finally {
  conn?.close();   // 成功・失敗どちらでも実行
}
```

## 例外安全性（Exception Safety）
例外が起きても**状態が壊れない**ように設計する考え方。C++等では特に重要。
- **基本保証**: 例外後もオブジェクトは破壊されない
- **強い保証**: 例外前の状態に戻る（トランザクション的）
- **nothrow保証**: 絶対に例外を投げない

## まとめ
- 例外は**想定外の状況**を正常系から切り離す仕組み
- `try / catch / finally` が基本、必要なら再送出
- **空catch・握り潰し**は重大なアンチパターン
- 例外とエラー戻り値は設計選択。Rust/Goは戻り値、Javaは例外中心
- 通常の制御フローには使わない
