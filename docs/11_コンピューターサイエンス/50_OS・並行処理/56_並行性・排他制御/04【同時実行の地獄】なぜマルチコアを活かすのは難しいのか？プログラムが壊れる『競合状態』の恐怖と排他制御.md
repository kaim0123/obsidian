## 要約

前回（マルチコア編）の続き。**コアを増やしても、プログラムの書き方を変えなければ速くならないどころかバグの温床になる**——その正体が **競合状態（レースコンディション）** と **排他制御** だ。本動画は、賽銭箱の比喩から x86 のアトミック命令、ミューテックス／セマフォ、デッドロック、Rust／Go の設計思想、Therac-25 事故、ロックフリーとアムダールの法則まで、**マルチコア時代のソフトウェア地獄** を体系的に解説する。

### マルチコアの甘い夢と「消える1円」

- 前回：クロック周波数の壁 → **コア数を増やす** マルチコア戦略が主流に。
- 直感では「2コアなら2倍、4コアなら4倍」だが、**ハードが2倍になってもソフトを書き換えなければ性能は上がらない**。
- 導入の比喩：賽銭箱で100回音がしたのに98円しかない → **2人の巫女が同時にカウント**すると、両者が同じ値（100）を読んでそれぞれ +1 し、結果は101のまま。**2回の更新のうち1回が消える（ロストアップデート）**。

### 競合状態とクリティカルセクション

- **競合状態（race condition）**：複数の実行体（スレッド／コア）が同じデータに同時アクセスし、**実行のタイミング次第で結果が変わる**状態。
- 「今書いてるから待って」は人間には簡単だが、CPU では **読む → 計算する → 書く** が複数命令に分割され、**その途中のどこでも** OS のスケジューリングにより別スレッドに切り替わる。
- x86 の例（カウンター `X`）：
  1. `MOV EAX, [X]` … メモリから読み込み（例：100）
  2. `INC EAX` … レジスタで +1（101）
  3. `MOV [X], EAX` … メモリへ書き戻し
- スレッド A が 1 の直後に B に切り替わると、両方が 100 を読み、両方が 101 を書く → **2回インクリメントしたのに結果は101**。
- この **途中で割り込まれてはいけない一連の処理** を **クリティカルセクション** と呼ぶ。保護しないとデータ破壊につながる。

### 原子性とハードウェアの LOCK

- **原子性（atomicity）**：「読む・計算する・書く」を **分割不可能な1つの操作** として扱うこと（爆弾解除とタイマー停止をセットで行う比喩）。
- 3命令のままでは不十分なため **ハードウェアの力** を借りる。
- x86 の **LOCK プレフィックス**：命令の前に付けるとその命令をアトミックに。**`LOCK INC [mem]`** はメモリ上の値を直接 +1。
- 実装の変遷：
  - **バスロック**：メモリバス全体を一時占有（道路封鎖）——古い方式。
  - **キャッシュロック**：**キャッシュライン** 単位だけを占有（1車線だけ封鎖）——現代の主流。
- **MESI プロトコル** で対象キャッシュラインを **Exclusive（独占）** や **Modified（書き換え済み）** 状態にし、「使用中」の札を立てる。他コアは待つ。

### ミューテックスとセマフォ

- LOCK は **1命令** しか守れない。**残高確認 → 引き落とし** のような複数ステップはソフトウェアの同期機構が必要。
- **ミューテックス（mutex）**＝ **Mutual Exclusion（相互排除）**
  - 比喩：**トイレの個室**——鍵は1つ、鍵を持った人だけが入れる。
  - **所有権あり**：鍵をかけた本人だけが開けられる（他人は勝手に開けない）。
  - `lock()` → 処理 → `unlock()`。鍵が取れなければ **ブロック（待機）**。
- **セマフォ（semaphore）**
  - 比喩：**3人まで入れるラウンジ**、駐車場の空き枠——**カウンター** で同時利用数を管理。
  - 鉄道の腕木式信号機（セマフォ）に由来（ダイクストラ）。
  - **所有権なし**：誰が減らしても誰でも増やせる（駐車場で A が出ても B が入れる）。
  - データの書き換え保護には通常 **鍵1つのミューテックス** を使う。セマフォは **リソース数の制限** に向く。

### デッドロック

- ロックの副作用：**デッドロック（deadlock）**＝循環待ちによる **完全停止**（プログラムは生きたまま凍る）。
- **食事する哲学者の問題**：5人が円卓に座り、隣の2本のフォークが必要。全員が同時に左のフォークだけ取ると、全員が右のフォークを待ち、**誰も手放さない** → 永遠に食べられない。
- 発生の **4条件**（いずれか1つでも崩せば防げる）：
  1. **相互排除**（資源は独占）
  2. **保持と待機**（手に持ったまま次を待つ）
  3. **奪取禁止**（他人から奪えない）
  4. **循環待ち**（全員が輪になって待つ）
- 回避策の例：**リソースに順序をつけ、番号の小さい方から取る**（一方通行）、**タイムアウト** で一旦すべて手放す。

### 言語・設計による「地獄からの解放」

プログラマがすべて手で設計するのは大変なため、言語・パラダイムが対策を提供する。

| 手法 | 考え方 |
|------|--------|
| **不変性（immutability）** | データを書き換えなければ競合は起きない。変更時は新データを作る（Haskell、Clojure 等） |
| **スレッドローカルストレージ** | 各スレッド専用のメモリ領域なら共有しない＝鍵不要 |
| **Go のチャンネル** | 共有メモリに書かず **メッセージで通信**（郵便の比喩） |
| **Rust の所有権** | 各データに **常に1つの所有者**。コンパイル時に複数スレッドからの同時アクセスを拒否 → **メモリ安全性**（データ競合によるメモリ破壊はコンパイル時検出）。ただし **論理的な競合**（処理順序の勘違い）は別問題 |

- Go の格言：**「メモリを共有して通信するな。通信してメモリを共有しろ。」**（Don't communicate by sharing memory; share memory by communicating.）

### Therac-25：競合状態が命を奪った

- 1980年代の放射線治療装置 **Therac-25**。競合状態のバグで **通常の100倍以上の放射線** を照射。
- データ入力タスクとハードウェア制御タスクが同じ変数を共有。技術者が8秒以内に素早く設定変更すると両タスクが同時アクセスし、**画面は低出力モード表示なのに実際は高出力** のまま照射。
- 1985〜1987年に少なくとも6件の事故、**3人死亡**。コードは **1人のプログラマが約2万行**、レビューなし。前機種 Therac-20 はハードの安全装置が守っていたが、Therac-25 は **ソフトのみで安全** としたためバグが直撃。
- きっかけに **医療機器ソフトウェア規制が大幅強化**。競合状態は「ただのバグ」ではなく **命に関わる** 問題。

### スピンロック・メモリバリア・TSO

- 高水準のミューテックスは最終的に **CMPXCHG（compare-and-exchange）** 等のハードウェア命令に落ちる。値が一致すればアトミックに書き換え。
- **スピンロック**：待つときにスリープせず **高速ループ** で待つ（`while (CAS(lock, 0, 1) == fail) spin;`）。
- **アウトオブオーダー実行**：CPU が最適化のため命令順を入れ替える → 並列処理では **旗を立てる前にお弁当が届かない** ような事故が起きうる。
- **メモリフェンス（`MFENCE` 等）**：「ここまでの作業は終わらせろ」と **命令の並び替えをブロック** する柵。
- x86 のメモリモデル **TSO（Total Store Order）** は比較的親切だが、**Store → Load の順序だけは保証されない** 例外あり。ただし **LOCK 付き命令は暗黙にメモリバリア効果** も持つ。
- LOCK の **代償**：キャッシュライン独占・パイプラインリセット等で通常命令より重い。**闇雲にロックするとマルチコアの意味がなくなる**（**スケーラビリティの欠如**）。

### ロックフリーとアムダールの法則

- **ロックフリーアルゴリズム**：CAS 等のアトミック命令だけで、ミューテックスなしに同期。設計難度は高い。
- 保証の強さ：**ウェイトフリー**（全員が有限手で進む）＞ **ロックフリー**（誰か1人は必ず進む）＞ **オブストラクションフリー**。
- **アムダールの法則**：並列化できない部分が全体の10%なら、コアをいくら増やしても **最大10倍** までしか速くならない。8コアで並列しても **最後の結果集約で順番待ち** が発生する。
- 現代のソフト設計は **並列化できる部分を増やす** かの戦い。

### 次回予告

- 並列処理とハードの管理をすべてプログラマが担うのは無理 → **OS（オペレーティングシステム）** がスケジューリング・仮想メモリ・リソース管理を担う「神様」。
- 次回：**OS の正体**（スケジューリング、仮想メモリ、時空の切り取り術）。
