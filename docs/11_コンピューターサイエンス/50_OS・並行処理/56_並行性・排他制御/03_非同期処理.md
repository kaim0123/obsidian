# 非同期処理

## 非同期処理とは
重い処理や**I/O待ち**の間に他の処理を進められる仕組みです。「終わったら知らせて」と言って次に進むイメージ。

### 同期 vs 非同期
```
同期:    [処理A][処理B][処理C]
         順番に待つ

非同期:  [処理A開始]
         [処理B実行]
         [Aが完了したら通知]
```

## なぜ非同期が必要か
- **UIが固まらない**: 重い処理中も画面操作ができる
- **I/Oで待たない**: ネットワーク・DB・ファイルの完了を待つ間に他を進める
- **リソース効率**: 少ないスレッドで多数のリクエスト処理

## 非同期処理の実現方法

### 1. コールバック
完了時に呼ばれる関数を渡す。
```javascript
fs.readFile("a.txt", (err, data) => {
  if (err) return handle(err);
  console.log(data);
});
```
ネストが深くなる「コールバック地獄」が有名。

### 2. Promise / Future
将来の結果を表すオブジェクト。
```javascript
fetch("/api")
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.error(err));
```

### 3. async / await
Promiseを同期っぽく書ける構文。現代のデファクト。
```javascript
async function load() {
  try {
    const res = await fetch("/api");
    const data = await res.json();
    console.log(data);
  } catch (e) {
    console.error(e);
  }
}
```

### 4. イベント / Observer
データが発生したら通知を受け取る。
```javascript
emitter.on("data", chunk => process(chunk));
```

### 5. ストリーム / Observable
データを連続的に扱う。RxJSなど。

## イベントループの仕組み（JavaScript例）

```
┌────────────────────────────────┐
│   コールスタック                │
│     実行中のコード               │
└───────────────┬────────────────┘
                │完了/イベント
                ▼
┌────────────────────────────────┐
│   タスクキュー（マクロ/マイクロ）│
└───────────────┬────────────────┘
                │
                ▼
      イベントループが拾う
```

ブラウザもNode.jsもこの「1スレッド + イベントループ + 非同期I/O」モデル。

## Promiseの状態
- **pending（保留）**: まだ完了していない
- **fulfilled（成功）**: 値を持つ
- **rejected（失敗）**: 理由を持つ

一度決まった状態は変わらない（イミュータブル）。

## async/awaitのポイント

### awaitは「一時停止」
```javascript
async function f() {
  console.log("1");
  const x = await somePromise();   // ここで待つ
  console.log("2", x);
}
```
関数は一時停止するが、**他のコード（イベントループ）は動き続ける**。

### エラーは try/catch
```javascript
try {
  const data = await fetchData();
} catch (e) {
  console.error(e);
}
```

### 並行に走らせる
```javascript
// 直列
const a = await f1();
const b = await f2();

// 並行（f1とf2が同時に走る）
const [a, b] = await Promise.all([f1(), f2()]);
```

## Promise.all / allSettled / race / any

| 関数 | 動作 |
|---|---|
| all | 全部成功で resolve、1つでも失敗で reject |
| allSettled | 全部の結果（成功/失敗）を返す |
| race | 最初に決着したもの |
| any | 最初に成功したもの（全部失敗で reject） |

## 他言語の非同期

### Python (asyncio)
```python
import asyncio

async def fetch(url):
    await asyncio.sleep(1)
    return url

async def main():
    results = await asyncio.gather(fetch("a"), fetch("b"))

asyncio.run(main())
```

### C# (async/await)
```csharp
async Task<string> LoadAsync() {
    var res = await httpClient.GetStringAsync("...");
    return res;
}
```

### Rust (async/await + ランタイム)
```rust
#[tokio::main]
async fn main() {
    let res = reqwest::get("https://example.com").await.unwrap();
}
```

### Go（軽量スレッドで同期風）
```go
ch := make(chan string)
go func() { ch <- fetch() }()
result := <-ch
```

## CPUバウンドと非同期
非同期は**I/O待ち**を効率化するためのもの。CPU処理には効果なし。
- 重い計算 → Worker Thread / マルチプロセス / GPU
- I/O待ち → async/await / Promise

## 非同期の落とし穴

### 1. await忘れ
```javascript
async function save() {
  db.insert(data);      // ← awaitなし、処理完了前に関数が終わる
}
```

### 2. Promiseを返し忘れ
```javascript
async function a() {
  doAsync().then(...);   // ← returnなし、上位で完了を待てない
}
```

### 3. 逐次化してしまう
```javascript
// ❌ 順番に実行（遅い）
for (const id of ids) {
  const user = await fetchUser(id);
  users.push(user);
}

// ✅ 並行実行
const users = await Promise.all(ids.map(fetchUser));
```

### 4. 例外の握りつぶし
Promiseでcatchしないと、「Unhandled Promise Rejection」になる。

### 5. 無限のPromise生成
`Promise.all` に数万件渡すと全部同時に走って相手を潰す。同時実行数を制限する。
```javascript
// p-limit などで同時実行数を制御
const limit = pLimit(10);
const tasks = ids.map(id => limit(() => fetchUser(id)));
```

## タイムアウトとキャンセル
長時間待たない設計。
```javascript
const controller = new AbortController();
setTimeout(() => controller.abort(), 5000);
await fetch(url, { signal: controller.signal });
```

## 非同期処理のベストプラクティス

### 1. I/Oには積極的に非同期を使う
### 2. エラー処理を忘れない
`try/catch` または `.catch`
### 3. 同時実行数を制限する
外部APIや重い処理
### 4. タイムアウトを設ける
### 5. ブロッキング処理を混ぜない
同期的に重い計算を実行するとイベントループが止まる
### 6. キャンセル可能に設計する
AbortSignal、Context、CancellationToken

## まとめ
- 非同期処理は**I/O待ち**の間に他のタスクを進める仕組み
- コールバック → Promise → **async/await** と進化
- `Promise.all` で並行化、逐次化のアンチパターンに注意
- CPUバウンドには効果なし、**スレッド/プロセス/GPU**を併用
- タイムアウト・キャンセル・同時実行制限を忘れない
