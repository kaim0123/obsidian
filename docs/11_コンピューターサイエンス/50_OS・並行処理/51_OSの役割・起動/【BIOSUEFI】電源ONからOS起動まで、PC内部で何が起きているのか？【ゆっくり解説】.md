## 詳しい要約

**テーマ：電源 ON から OS 起動までのバトンリレー（BIOS/UEFI → ブートローダー → カーネル）**

PC の電源を入れてから Windows が起動するまでには、最低3回のバトンタッチ（UEFI/BIOS → ブートローダー → OS カーネル）がある。BIOS とブートローダーの役割分担、BIOS の限界と後継の UEFI の強み、そして電源投入から起動完了までの流れを時系列で解説する。

---

### BIOS の役割

- BIOS（Basic Input/Output System、基本入出力システム）は、電源投入直後に**最初に動く**プログラム。
- 仕事は3つ。
  1. **POST**（Power-On Self Test）：CPU・メモリ・キーボードなどが正常か確認。起動時の「ピッ」が完了の合図で、異常時はビープ音の回数で故障箇所を知らせる。
  2. **ハードウェアの初期化**：各デバイスを使える状態にする。
  3. **ブートデバイスの選択とブートローダーの呼び出し**：OS が入った記憶装置（HDD/SSD）からブートローダーを読み込む。

### なぜブートローダーが必要か

- BIOS は1970年代の設計を引き継いだ原始的なプログラムで、**16ビットモード・1MB のメモリ**しか扱えず、現代の巨大な OS を直接起動するには力不足。
- **ブートローダー**が32/64ビットモードに切り替え、OS に必要な環境を整えてから OS にバトンを渡す。例：Windows ブートマネージャー、Linux の GRUB。
- BIOS はハードウェア寄り、ブートローダーはソフトウェア寄りの担当。

### BIOS の問題点

| 問題 | 内容 |
|---|---|
| **2.2TB の壁** | パーティション方式 MBR（Master Boot Record）が32ビットのアドレッシングのため、2.2TB を超えるストレージから起動できない |
| 起動が遅い | デバイスを1つずつ順番にチェックする |
| セキュリティが弱い | ブートローダーが本物か確認できず、マルウェアに乗っ取られやすい |
| 拡張性が低い | 新しいハードウェアへの対応が難しく、GUI もなくマウス操作不可 |

### UEFI の強み

- UEFI（Unified Extensible Firmware Interface）は BIOS の後継として1990年代に Intel（HP と共同）が開発を始めたファームウェア（ハードウェアとソフトウェアの中間にある、ハードウェアを制御する基本プログラム）。
- **GPT**（GUID パーティションテーブル）対応で、理論上約8ZB（約80億TB）まで扱える（Windows ではパーティションあたり18EB が上限）。
- **セキュアブート**：起動時にブートローダーのデジタル署名を確認し、マルウェアの起動を防ぐ。
- **高速起動**：複数デバイスを並列にチェックできる。
- **モダンな UI**：マウス操作・高解像度のグラフィカル画面。
- 普及は2011年ごろから（Intel 6シリーズ世代で2TB 超の HDD 対応のため）。Windows 8 以降は UEFI が標準。互換性のため多くは**レガシー BIOS モード**も備える。
- UEFI は FAT32 でフォーマットされた **EFI システムパーティション**にブートローダーやドライバーを保存しており、削除すると起動しなくなる。

### 起動の流れ（時系列）

1. 電源投入 → CPU がリセット解除され、**リセットベクター**（x86 で決められたアドレス）へジャンプ。そこに BIOS/UEFI のコードがある。
2. **POST**：CPU レジスタのチェック、BIOS ROM のチェックサム検証、タイマー・DMA コントローラー・メモリコントローラーの初期化、メモリテスト。クイックブート設定で簡易化できる。
3. **ブート順序**（例：USB → SSD → ネットワーク）に従ってブートデバイスを検索。
   - BIOS：先頭セクター（LBA0）の最後の2バイトが **0x55AA**（ブートシグネチャ）なら起動可能とみなし、MBR のコードを実行。
   - UEFI：GPT を読み、EFI システムパーティション内の `EFI/BOOT/BOOTX64.EFI` を実行。
4. ブートローダーが**カーネル**（Windows は ntoskrnl、Linux は vmlinuz）をメモリに読み込み、実行を渡す。
5. カーネルがデバイスドライバーの読み込み、システムサービスの起動、セッションの開始を行い、起動完了。全体で約10秒。

### 補足

- デュアルブートの OS 選択画面は GRUB などのブートローダーが表示している。
- 「No bootable device」「Operating System not found」はブートデバイスが見つからないかブートローダーの破損。ブート順序確認 → 接続確認 → インストールメディアからスタートアップ修復、の順で対処。
- Linux の **initramfs/initrd**（初期 RAM ディスク）は、ドライバー未読み込みで本物のファイルシステムにアクセスできないカーネルのために、メモリ上に一時的なファイルシステムを作って必要なドライバーを読み込む仕組み。

### まとめ

- BIOS はハードウェアのチェック・初期化とブートローダーの呼び出し、ブートローダーは OS の読み込みと起動、という役割分担。
- BIOS は2.2TB の壁・低速・低セキュリティが課題で、UEFI が大容量対応・高速起動・セキュアブート・モダン UI で置き換えた。
- 電源ボタン1つの裏で、複数のプログラムによるバトンリレーが走っている。
