## 詳しい要約

**テーマ：コンテナの正体と、それが理解されにくい理由**

Linux カーネルのどこにも「コンテナ」という機能は存在せず、あるのは名前空間・cgroups・オーバーレイファイルシステムなどのバラバラの部品だけ。コンテナはその組み合わせに後からついた「あだ名」にすぎない。理解より先に標準化が完成したため中身を知らなくても使えるが、セキュリティや AI エージェントの隔離の文脈で、中身を理解する価値が再び高まっている。

---

### オープニング コンテナは存在しない

- 面接で「コンテナと仮想マシンの違いは」と聞くと、答えは「軽い仮想マシン」「プロセスの隔離」「毎日使っている道具」に分かれる。
- カーネルのソースを検索しても「コンテナ」という機能は出てこない。あるのは **名前空間（namespace）**、**cgroups**、**オーバーレイファイルシステム**などの部品だけ。実体がないから説明できない。

### 第1章 監獄から始まった部品の歴史

| 年 | 出来事 |
|---|---|
| 1979 | UNIX V7 に **chroot**。プロセスから見えるファイルシステムのルートを特定のディレクトリに付け替える（牢屋に入れる発想） |
| 2000 | FreeBSD **Jails**（直訳は「監獄」）。Poul-Henning Kamp が主導。ホスティング業者が 1 台のサーバーを複数顧客に安全に貸すための機能 |
| 2002〜 | Linux で**名前空間**の実装開始。マウント・プロセス番号・ネットワークなどをプロセスごとに別世界にする |
| 2006 | Google が社内クラスターでプロセス集団ごとに CPU・メモリを制限する機能を開発。名前は「**プロセスコンテナ**」 |
| 2008/1 | 「コンテナ」は意味が広すぎて混乱するとして **cgroups** に改名され、Linux 2.6.24 に統合 |

- 開発者自身が「このコードはコンテナの重要な部品だが、全体からはほど遠い」と説明していた。**コンテナは発明されたのではなく、部品が静かに揃っていっただけ**。

### 第2章 5 分のトークと規格の発明

- 2013 年 3 月、PaaS 企業 dotCloud を率いる **Solomon Hykes** が PyCon で 5 分のライトニングトーク。奥の小部屋で 30 人程度に話すつもりが、実際はメインステージで数百人の前だった。
- 反響は想定外で、Hacker News には「オープンソースでないなら絵に描いた餅」との書き込みも。チームは 2 週間で突貫のオープンソース化を決め、翌年社名を Docker に変えた。
- Docker が発明した部品は 1 つもない（名前空間も cgroups も既存、**LXC** という先行ツールもあった）。発明したのは**イメージという配布形式**と**Dockerfile という書き方**、つまり技術ではなく**体験**。
- 海運のコンテナと同じ構造：1956 年に **マルコム・マクリーン**が規格化された鉄の箱を実用化したとき、船も港もトラックもすでにあった。箱の規格が揃っただけで物流費が桁違いに下がった。

### 第3章 理解を阻む 3 枚の壁

1. **実体がない**：仮想マシンにはハイパーバイザーという実体があるが、コンテナは 8 種類の名前空間・cgroups・オーバーレイ FS などの部品の束に輪ゴムをかけた状態。
2. **比喩の事故**：「コンテナは軽量な仮想マシン」という比喩は入口としては便利だが出口を塞ぐ。中に OS を探し始めるが、**中に OS はなく、カーネルはホストと共有、動いているのは隔離されたただのプロセス**。だからホスト側で `ps` を打つとコンテナ内のプロセスが見える。
3. **Mac と Windows のねじれ**：名前空間も cgroups も Linux カーネルの機能なので、Mac では本来動かない。**Docker Desktop は裏で Linux の仮想マシンを起動し、その中でコンテナを動かしている**。最も普及した開発環境が最も例外的な構成という皮肉。

### 第4章 理解より先に標準化が完成した

- 理解しなくても動くよう、産業全体が作り込んだ：2014 年 Google が **Kubernetes** を公開（社内システム Borg の 10 年近い知見）、2015 年 **OCI** でイメージ形式と実行の仕様が固まった。
- Docker 自身も分解され、実行部分は **containerd** と **runc** に切り出された。**Kubernetes は今 Docker なしでコンテナを動かしている**。
- 「Docker」という 1 語が会社名・コマンド・常駐プロセス・イメージ形式をすべて指すため、「Docker は終わった」と「Docker は標準になった」という記事が同時に正しいという状況が生まれた。
- コンテナは**理解の普及より先に利用の標準化が完成した**珍しい技術。

### 最終章 輪ゴムの中身を知る価値

- **セキュリティ**：コンテナは VM より壁が薄く、カーネルを共有するので**カーネルの穴は全コンテナの穴**になる。AWS は軽量 VM **Firecracker** を作って Lambda の裏で使い、Google は **gVisor** を作った。「コンテナか VM か」の二択ではなく「**隔離の強さをどこに設定するか**」という設計問題に変わっており、判断には壁が何でできているかの知識が要る。
- **AI エージェント**：AI が書いたコードを安全に実行する使い捨てサンドボックスの需要が増え、その実装の主役がコンテナと軽量 VM。四半世紀前に貸しサーバーのために作られた隔離技術が再登板している。

### まとめ

- コンテナは単一の機能ではなく、chroot から続く名前空間・cgroups などの部品の組み合わせにつけられた名前。
- Docker の功績は部品ではなく、イメージ形式と Dockerfile による規格と体験の発明。
- 「軽量 VM」という比喩と Mac/Windows での VM 経由の実行が理解を妨げている。
- 名前が実体より先に広まり、理解されないまま勝った技術だからこそ、中身を説明できる人の価値が上がっている。
