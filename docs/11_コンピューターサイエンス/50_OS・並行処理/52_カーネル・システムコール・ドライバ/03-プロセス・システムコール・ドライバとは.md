# プロセス・システムコール・ドライバ

> **この章を読むと分かること**
> - 「プロセス」と「スレッド」って何が違うの？
> - なぜ Chrome は1つのアプリで32個もプロセスを立ち上げるのか
> - アプリがハードを動かすときの「お願い」 = システムコール
> - 2024年に世界の Windows をブルースクリーンにした **CrowdStrike事件** の正体
> - ファイルシステムが「パンチカード時代」からどう進化したか
> - 黒い画面（ターミナル）が、実は便利な理由

## はじめに — OSの「裏側」を覗く

[[01-OSの役割と起動とは|第1節]] で「OSは資源管理者」「カーネルは社長室」と説明しました。この章ではその **裏側で何が起きているか** を見ていきます。

```
あなたが「Chromeを開く」とクリックする
        ↓
裏では：
  ・OSが新しいプロセスを作る
  ・メモリを割り当てる
  ・ハードディスクからファイルを読む（システムコール）
  ・ディスプレイドライバがピクセルを描画
  ・キーボードドライバが入力を待つ
        ↓
画面に Chrome が表示される
```

これらすべてを支えているのが、**プロセス、システムコール、ドライバ、ファイルシステム**。普段意識しないけれど、すべての操作を支えています。

## 1. プロセスとは何か — 「設計図と建物」の関係

### 1-1. プログラムとプロセスの違い

```
プログラム ＝ 設計図（ハードディスクに保存されたファイル）
プロセス   ＝ その設計図から建てられた、実際に動いている建物
```

例：

```
Excelのプログラムファイル（1つ）
        ↓ 3回起動
プロセス1（Excel #1）  ← 別々のメモリ空間
プロセス2（Excel #2）  ← 互いに影響しない
プロセス3（Excel #3）
```

同じ Excel を3つ開けば、**プロセスが3つできる**。それぞれが独立して動きます。

### 1-2. PID — プロセスの背番号

各プロセスには **PID（Process ID）** という番号が振られます。タスクマネージャーを見るとずらっと並んでいるあれです。

```
PID    名前          メモリ使用量
─────────────────────────────────
1234   chrome.exe    500 MB
5678   notepad.exe   10 MB
9012   spotify.exe   200 MB
...
```

### 1-3. 仮想アドレス空間 — ホテルの部屋

各プロセスは **自分専用のメモリ空間** を持っているように見えます。これを **仮想アドレス空間** といいます。

```
比喩：ホテルの部屋
   各部屋（プロセス）は独立しているように見える
        ↓
でも実際の建物（物理メモリ）は共有
        ↓
OSが「あなたの部屋はここ」と割り振っている
```

[[01-OSの役割と起動とは|第1節]] で扱った「コンタミ防止」が、この仕組みで実現されています。

## 2. なぜ Chrome は32個もプロセスを立ち上げるのか

### 2-1. マルチプロセスアーキテクチャ

Chromeでタスクマネージャーを開くと、たった1つのChromeブラウザなのに **大量のプロセス** が立ち上がっています。

```
Chromeアプリ
   ├─ メインプロセス
   ├─ タブ1 プロセス
   ├─ タブ2 プロセス
   ├─ タブ3 プロセス
   ├─ 拡張機能A プロセス
   ├─ 拡張機能B プロセス
   └─ ... 32個など
```

### 2-2. なぜわざわざ分けるのか

理由は **セキュリティと安定性**：

```
1つのタブがクラッシュ
        ↓
そのタブのプロセスだけが落ちる
        ↓
他のタブは無事に動き続ける
```

> **教訓**：プロセスを分けると、リソースは余計に使うが、**1つの障害が全体に波及しない**。
> Chromeは「メモリを食う」と言われがちですが、これはセキュリティとのトレードオフです。

## 3. スレッド — プロセスの中の小さな働き手

### 3-1. プロセスの中の複数の流れ

1つのプロセスの中に、**複数の処理の流れ** を作れます。これが **スレッド**。

```
1プロセス（例：動画編集ソフト）
   ├─ スレッド1：UI（ボタンクリックの監視）
   ├─ スレッド2：動画のエンコード処理
   └─ スレッド3：プレビュー再生
```

すべて並行して動くので、エンコード中もUIが固まりません。

### 3-2. プロセスとスレッドの違い

| | プロセス | スレッド |
|---|--------|--------|
| メモリ空間 | 独立（別々） | 共有（同じプロセス内で） |
| 作るコスト | 高い | 低い |
| 切替コスト | 高い | 低い |
| 通信 | 面倒（プロセス間通信） | 簡単（同じメモリだから） |
| 影響範囲 | 1つ落ちても他は安全 | 1つ落ちるとプロセス全体が落ちる |

### 3-3. なぜ両方使い分けるのか

- **プロセスを分ける**：安全性が大事なとき（タブごとに分けるChrome）
- **スレッドを分ける**：効率が大事なとき（同じアプリ内の並行処理）

## 4. OSはタスク管理のプロ — 300個のタスクを同時にこなす

### 4-1. 「即レス必須のブラック企業」

人間が同時にこなせる仕事はせいぜい数個。一方、OSはあなたのPC上で **約300プロセス** を同時にさばいています。

> **CPU の労働環境（OS が課す）**
> - 17秒も休ませない（アイドル状態は負け）
> - 8時間労働でも休憩なし
> - プライベートなし
> - フル活用しないと資源を逃す
> 
> 一方ユーザーには **即レス必須**：
> - 文字入力の遅延、マウスのもたつきは許されない
> - 120Hz ディスプレイなら 1/60秒の遅れも許容しない

### 4-2. エイジングとスターベーション

OSのタスク管理には人間のToDo管理にも応用できる概念があります。

| 用語 | 意味 |
|-----|------|
| **エイジング（aging）** | 優先度が低くて後回しになり続けたタスクの優先度を、時間とともに少しずつ上げる |
| **スターベーション（starvation）** | いつまでも着手されず、CPU時間が与えられず枯れる状態 |
| **無限延期（infinite postponement）** | 永遠に後回しにされる |

> 人間の例：「ゲーミングチェアの肘掛けが吹き飛んだまま1年半」「靴磨きを2年放置」 — これがスターベーション。
> 締切のある原稿は「エイジング」されて優先度が上がっていく（編集者が嫌味にならない形で存在感を出して、エイジングを早める）。

### 4-3. タスクマネージャーで何が見える

Windowsならタスクバー右クリック、Macなら「アクティビティモニタ」。

```
見える部分      ── Chrome, Notion など
       ↓
見えない裏側 ── LINE通知（未起動でも待機中）
              IME（日本語入力）
              マウスドライバ
              バックグラウンドサービス
              ...
```

実は1アプリの裏に **複数プロセス** が動いていることが多い（Discordなど）。

## 5. システムコール — アプリがカーネルに「お願い」する仕組み

### 5-1. なぜ「お願い」が必要なのか

[[01-OSの役割と起動とは|第1節]] で説明したように、**カーネルだけがハードウェアに直接アクセスできる特権** を持っています。

```
[アプリ]         ← ファイルを開きたい
  ↓
  │ 直接ディスクには触れない（特権なし）
  ↓
[システムコール] ← カーネルへの正式な「お願い」
  ↓
[カーネル]       ← ハードウェアに直接アクセス
  ↓
[ディスク]
```

### 5-2. アプリは「執事」を通す

> **比喩**：アプリは王様の私室、ハードウェアは外の庭。
> 王様は庭に出られない（特権がない）から、執事（カーネル）に「庭の花を取ってきて」とお願いする。
> 
> その「お願い」の正式な様式が **システムコール**。

### 5-3. システムコールの代表例

| カテゴリ | 例 | 何をするか |
|--------|-----|--------|
| ファイル操作 | `open`, `read`, `write`, `close` | ファイルを読み書きする |
| プロセス | `fork`, `exec`, `wait` | プロセスを作る・実行する |
| メモリ | `mmap`, `brk` | メモリを確保する |
| 通信 | `socket`, `send`, `recv` | ネットワーク通信 |
| デバイス | `ioctl` | デバイス制御 |

### 5-4. なぜこの仕組みが必要なのか

仮にアプリが直接ハードを触れたら：

- 悪意あるアプリがファイルを勝手に削除
- バグのあるアプリがハードに異常な命令を送って物理的破壊
- 複数アプリが同じハードを取り合って大混乱

> **カーネルが間に入ることで、安全と秩序を保っている**。

### 5-5. アプリの裏で常に動いている

あなたがガチャを引く瞬間にも、システムコールが何百回も呼ばれています。

```
1. ガチャアプリ「乱数を取得したい」→ システムコール
2. アプリ「画像を表示したい」→ システムコール
3. アプリ「サーバーと通信したい」→ システムコール
4. アプリ「結果を保存したい」→ システムコール
   ...
```

## 6. ドライバ — OSの「特権階級」とCrowdStrike事件

### 6-1. ドライバとは何か

**ドライバ**（デバイスドライバ）は、**OSとハードウェアの間を橋渡しするソフトウェア**。

```
マウスを右に3cm動かす
   ↓
マウスのハードウェアが「電気信号」を出す
   ↓
[マウスドライバ] ← OSが理解できる形式に翻訳
   ↓
OS「ああ、カーソルを右に3cm動かしたいのね」
   ↓
画面のカーソルが動く
```

各ハードウェア（マウス、キーボード、プリンタ、GPU、ネットワークカード…）には専用のドライバが存在します。

### 6-2. ドライバの「特権」

ドライバは **カーネルと同じ Ring 0** という **最高特権レベル** で動きます。

```
リングプロテクション（Intel CPU）
┌─────────────────────────┐
│  Ring 3  ← 普通のアプリ  │
│  Ring 2                  │
│  Ring 1                  │
│  Ring 0  ← カーネル＋ドライバ │ ← 何でもできる最強特権
└─────────────────────────┘
```

つまり、**ドライバにバグがあるとカーネル諸共お亡くなり**になります。

### 6-3. CrowdStrike事件（2024年7月19日）

2024年7月19日、世界中の Windows PCが **一斉にブルースクリーン** になる事件が起きました。

```
発生規模：約850万台のWindowsが同時クラッシュ
影響：
  - 空港の搭乗手続きシステム停止
  - 銀行のATM停止
  - 病院のシステム停止
  - テレビ局の放送停止
  - 全世界で大混乱
```

原因は **CrowdStrike** というセキュリティ会社のドライバ更新ファイルにバグがあったこと。

```
CrowdStrikeのドライバが
最高特権（Ring 0）でWindowsに組み込まれていた
        ↓
更新ファイルにバグ
        ↓
ドライバがクラッシュ
        ↓
カーネルごとブルースクリーン
        ↓
世界中の業務が停止
```

> **教訓**：ドライバは「最強の特権を持つ」がゆえに、バグの影響も最大級。たった1つの会社のドライバが、世界経済を止めうる。

### 6-4. Rust への移行

最近、安全性を高めるために **Linux カーネル** に **Rust** という新しい言語でドライバを書く動きが始まっています。Cで書いたドライバの脆弱性を減らすため。

## 7. ファイルシステム — パンチカードから現代まで

### 7-1. 1950年代 — パンチカード時代

最古のデータ保存はなんと **紙にプスプス穴を開ける** 方式でした。

```
パンチカード：横長の厚紙
   ├─ 穴あり = 1
   └─ 穴なし = 0

1枚あたり最大80文字
"Hello World"のプログラム = 1枚使用
複雑なプログラム = 数百枚〜数千枚
```

問題：**カードの束を床に落としたら地獄**。順番をバラバラに並べ直すしかありません。

### 7-2. 磁気テープ時代

そこに登場したのが磁気テープ。録音テープと同じ原理でデータを記録。

しかし問題：**順番にしか読めない**（テープを巻き戻すしかない）。100MBのデータの最後を見るのに、最初から100MB全部を再生する必要がある。

### 7-3. ハードディスクの登場（1956年、IBM）

```
ハードディスク：磁気を使った円盤
       ↓
ランダムアクセス（どこでも直接読める）
       ↓
これが「ファイルシステム」のスタート
```

### 7-4. 階層ファイルシステム（UNIX）

[[02-UNIX-Linux-Windowsとは|UNIX]] で導入された **ディレクトリ階層**。これで初めてファイル管理が現代的になりました。

```
/
├── home/
│   ├── alice/
│   │   ├── photos/
│   │   └── docs/
│   └── bob/
└── etc/
```

### 7-5. 現代の主要ファイルシステム

| ファイルシステム | 使用OS | 特徴 |
|------|-----|------|
| **NTFS** | Windows | アクセス制御、ジャーナリング |
| **APFS** | macOS | SSD最適化、スナップショット |
| **ext4** | Linux | 安定、Linux標準 |
| **Btrfs / ZFS** | サーバー | スナップショット、冗長性 |
| **exFAT / FAT32** | USB等 | OS間互換性 |

> **ジャーナリング**：書き込み前に「これからこれを書きます」と記録しておくことで、停電してもデータ破損を防ぐ仕組み。

## 8. ターミナル — 黒い画面の正体

### 8-1. なぜ「黒い画面」なのか

ハッカー映画でおなじみの **黒画面に白文字** のあれ。**ターミナル**（terminal、端末）と呼びます。

なぜ「端末」？ — 昔のコンピュータには **GUI がなく**、ターミナルからしか操作できませんでした。当時は「コンピュータ = ターミナル」だったので、その名残です。

### 8-2. 多くの人が誤解する理由

> **誤解パターン**：「ターミナルを開く = パソコンが壊れる」
> 
> 真相：黒い画面を見るのは、OSが破損したエラー時が多い。だから「黒い画面 = やばい」という認知バイアスが生じる。
> **平常時に開くなら、何も危なくない**。

### 8-3. 「対話拒否」が実は便利

ターミナルは **覚えたコマンドを打ち込む** スタイル。覚える量が多くて不便そうに見えます。

しかし慣れると圧倒的に便利：

```
ファイル名一覧をテキストファイルに保存したい
   ↓
GUIだと：
   1. エクスプローラを開く
   2. ファイルを選ぶ
   3. 名前を1つずつ コピー
   4. テキストファイルに貼り付け
   ↓ 数分かかる
   
ターミナルだと：
   ls > filenames.txt
   ↓ 一瞬で完了
```

### 8-4. 基本コマンド（5つだけ）

| コマンド | 略 | 意味 |
|--------|-----|------|
| **ls** | LiSt | 今いるディレクトリの中身を表示 |
| **cd** | Change Directory | ディレクトリを移動 |
| **cat** | conCATenate | ファイルの中身を表示 |
| **wc** | Word Count | 行数・単語数を数える |
| **grep** | Global Regular Expression Print | 検索 |

### 8-5. パイプ（`|`）の魔法

UNIX 最大の発明：**コマンドを `|` でつなぐ**。

```
名簿から「田」がつく人を数える：

grep "田" namelist.txt | wc -l
       ↓                      ↓
  田が含まれる行を出力 → 行数を数える
       
（パイプ「|」で結果を次に流す）
```

複雑なことが、**小さなコマンドの組み合わせ** で実現できます。これが [[02-UNIX-Linux-Windowsとは|UNIX哲学]] の真髄。

### 8-6. エンジニア豆知識：「ls」はフィラー

エンジニアはターミナルを開くと **条件反射で `ls`** を入力する習性があります。

> 「えーと…」と話し始める前に間を埋めるフィラー（えーと、あの、など）のように、
> エンジニアは特に用がなくても `ls` を打ってしまう。
> 
> 映画『ソーシャル・ネットワーク』のザッカーバーグも、考え事をしているシーンで画面に **`ls`** と打っている、という小ネタ。

## 9. この章のまとめ

### 全体の構造

```
[アプリケーション（ユーザー空間）]
   ├─ プロセス（独立したメモリ空間）
   └─ スレッド（プロセス内の流れ）
        ↓ システムコール
[カーネル空間]
   ├─ プロセス管理
   ├─ メモリ管理
   ├─ ファイルシステム
   └─ ドライバ（特権で動く）
        ↓
[ハードウェア]
   CPU、メモリ、ディスク、入出力装置
```

### 大切なポイント

1. **プロセスは「設計図 → 建物」**
   プログラムは設計図、プロセスはその実体。Chromeのタブごとに分けるのはセキュリティのため。

2. **スレッドはプロセス内の並行作業者**
   メモリを共有するので速いが、1つ落ちると全体が落ちる。

3. **アプリは「お願い」してハードを動かす**
   その仕組みがシステムコール。

4. **ドライバは特権を持つ翻訳係**
   バグると世界が止まる（CrowdStrike事件）。

5. **ファイルシステムはパンチカードから70年の進化**
   ジャーナリングなど、データを守る工夫の積み重ね。

6. **ターミナルは「対話拒否」が便利の源**
   慣れるとGUIより圧倒的に速い。エンジニア文化の中心。
