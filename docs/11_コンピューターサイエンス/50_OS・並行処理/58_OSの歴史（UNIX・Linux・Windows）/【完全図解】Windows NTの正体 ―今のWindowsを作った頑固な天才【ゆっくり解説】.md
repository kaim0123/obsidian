## 詳しい要約

**テーマ：今の Windows の本当の祖先「Windows NT」と設計者デイヴ・カトラーの物語**

今の Windows は 95/98/Me の子孫ではなく、別系統の **Windows NT** の子孫である。DEC で計画を潰されたデイヴ・カトラーが Microsoft に移り、移植性と堅牢性を最優先に設計した NT の誕生の経緯、アーキテクチャ（HAL、カーネルとエグゼクティブ、環境サブシステム、オブジェクトマネージャー、メモリ保護、プリエンプティブマルチタスク、ハイブリッドカーネル、NTFS、ACL）、そして NT 3.1 から 2000 までの歩みを解説する。

---

### カトラーと DEC での挫折

- カトラーは名門 **DEC**（ミニコンピューターで躍進し、1980年代に業界2位の規模）で、銀行や工場で長年止まらずに動いた OS **VMS** を設計した実力者。品質に妥協せず、見込んだ部下にしか怒鳴らないと言われた。
- 次世代コンピューター「Prism」と OS「Mica」を一から作る計画を任されたが、1988年、社内で似た計画が乱立し予算を食い合った結果、真っ先に中止された（技術評価は高かったとも）。
- 失望したカトラーは17年勤めた DEC を去る。

### Microsoft へ

- 噂でカトラーの実力を知っていた**ビル・ゲイツ**がすかさず声をかけた。当時の Microsoft は大型機の技術者から見れば格下の小さなパソコン向けソフト屋だった。
- カトラーは **DEC 時代の仲間約20人を連れて行く**ことを条件に受諾し、1988年秋にレドモンドへ。
- 当初の任務は IBM と共同で育てていた次世代 **OS/2** の開発。しかし1990年の **Windows 3.0** が大ヒットし、会社は Windows に舵を切る。新 OS も1〜2年かけて OS/2 流から Windows 流へ切り替わり、これが IBM との決別のきっかけに。IBM は単独で OS/2 を続けたが、最終的に市場から撤退した。

### 設計の柱：移植性

- 目標は「**頑丈で移植性の高い OS**」。x86、MIPS、後の Alpha など命令セットの異なる機械で同じ OS を動かす。
- 大半を **C 言語**で書き、ハードウェア依存コードを最小限に。当時は速さのためアセンブリで書くのが定石だったが、カトラーは移植性を優先した。
- 依存部分は **HAL（Hardware Abstraction Layer）** に集約し、割り込み・タイマー・DMA・APIC などのプラットフォーム差を吸収（個々のデバイス I/O は I/O マネージャーとドライバー層が担当）。
- カーネルモードは、スケジューラや割り込み処理を担う小さな**カーネル**と、その上の**エグゼクティブ**（メモリ・プロセス・I/O マネージャー、セキュリティ参照モニターなど）の2階層。移植時に書き換えるのは HAL とごく一部だけで済む。
- 意図的に x86 を後回しにし、Intel i860 で設計を検証、MIPS を主役に開発した。その結果 NT 3.1 は x86 と MIPS に対応して発売され、後に PowerPC や DEC の Alpha にも対応。DEC 自身が Alpha 向けに NT を売る側になった。

### 設計の柱：互換性と堅牢性

- **環境サブシステム**：Win32、OS/2 1.x のテキストアプリ向け OS/2 サブシステム、POSIX.1 最小実装の POSIX サブシステム。POSIX 対応は米政府調達の入札条件だったため（実質は名ばかりの対応）。
- **オブジェクトマネージャー**：ファイル・デバイス・プロセスなどあらゆるリソースをオブジェクトとして統一管理し、セキュリティ参照モニターで一元的に権限照合。
- **プロセスごとに独立した仮想アドレス空間**：ページングで広大な空間に見せ、あるプロセスが暴走しても他プロセスのメモリに到達できない（メモリ保護）。
- **プリエンプティブマルチタスク**：OS が強制的にタイムスライスで実行権を回収。9x 系は古い16ビットアプリで協調的マルチタスクを引きずり、1つが固まると道連れになりやすかった。
- ほかに複数 CPU の**SMP 対応**（9x は非対応）、複数 PC をまとめて管理する**ドメイン**。
- **ハイブリッドカーネル**：純粋なマイクロカーネル（Mach など）は安全だが切り替えコストで遅く性能面で苦戦。NT は安全と速さの中間を取った。
- 「NT は VMS の焼き直し」は言い過ぎだが、設計思想の影響は濃い。VMS の各文字を1つずつ進めると WNT になるという言葉遊びも。

### 開発の苦闘と NT 3.1 の発売

- 開発の壮絶さは G・パスカル・ザカリーの本『**Showstopper!**』に描かれた。200人超が何年も格闘し、出荷前は「死の行軍」。家庭を顧みず没頭した人もいた。カトラーは管理職になっても最も難しい部分を自ら握った。コードは数百万行、社内全体で日常業務に使わせる大規模検証を行った。
- **1993年7月27日、Windows NT 3.1** 発売（既存の Windows 3.1 に番号を合わせた）。
- 「NT」の由来は公式には **New Technology**。現場の噂では開発時のターゲット i860 のコード名 **N10** が本当の由来という説も。NT は Northern Telecom の商標でもあり表記義務があった。Windows 2000 で NT の名が消えたのは家庭向けと企業向けの名称整理のためのマーケティング判断。
- 発表時は UNIX 陣営から懐疑的な声が多く、価格も基本版約500ドル、サーバー版は1000ドル台以上と企業向け。
- **NTFS**：それまでの FAT は誰でもファイルに触れ、壊れたら復旧困難だった。NTFS は書き込み前に予定を記録する**ジャーナリング**でファイル管理情報の整合性を守る（中身そのものの保護は別の話）。
- **ACL**（アクセス制御リスト）とアクセストークンの照合で細かい権限管理。後の版で米政府の **C2 評価**を条件付きで取得。
- 弱点：高性能で高価な PC が必要。古い DOS/16ビットアプリは NTVDM や WOW という仮想マシンに隔離して動かしたため、一部の古いゲームやハードを直接叩くソフトは動作が怪しかった。家庭には広まらなかったが、安定性を求める開発者やパワーユーザーに熱烈に支持された。

### NT 3.5 から 2000 へ

- **NT 3.5（コード名 Daytona）**：軽量化し、TCP/IP を自前実装に刷新してネットワークを強化（「Network Technology の略」と誤解されたほど）。ファイル・プリンター共有に強い Novell の **NetWare** の隙間を突き、業務を動かすサーバーとしての需要を取った。
- **IIS** は 3.51 の無償追加部品として登場し、NT 4.0 サーバー版で標準同梱。サーバーで様々なサービスを動かすクラウドの原型的な発想。
- 金融機関の基幹システムや政府機関など「止まったら困る現場」で採用が進んだ（VMS と同じ客層）。
- **NT 4.0（1996年）**：見た目を Windows 95 そっくりにして移行しやすくした。さらに速度のため画面描画処理をユーザーモードから**カーネルモードへ移す**という、安全を少し妥協する決断をした。
- **Windows 2000**：ドメインが **Active Directory** に進化し、数万台規模の一元管理が可能に。企業向けの完成形となり、次の Windows XP で家庭向けにも一本化される（次回予告）。

### まとめ

- 今の Windows の本流は 9x 系ではなく、カトラーが設計した NT 系。
- 移植性（C 言語・HAL）、堅牢性（メモリ保護・プリエンプティブ・オブジェクト管理・NTFS・ACL）、現実的な速さ（ハイブリッドカーネル）を両立させた設計が、企業・サーバー市場での信頼を築いた。
- 計画を潰された天才が格下と見ていた会社で作った OS が世界中の PC とサーバーの土台になった、という逆転劇。カトラーはその後も Microsoft のクラウドやゲーム機の土台に関わったと言われる。
