## 詳しい要約

### シリーズの位置づけ

UNIXシリーズ前回の続き。**『UNIXという考え方』**を種本に、UNIXの設計思想（哲学）を語る回。前回扱った**ターミナル**（黒い画面でコマンド操作する前提のOS）の延長線上にある。LinuxもUNIX系であり、哲学の部分はLinuxと共通と考えてよい（今回はLinuxの話は一旦脇に置く）。**「対話拒否」**回——本筋から大きく脱線する雑談が多い。

### 普通のOS vs UNIX：ユーザーインターフェースの思想

現代のOS（Windows、macOSなど）のUI思想は**「ユーザーに分かりやすく・使いやすく」**。電源を切りたければスタートメニューから直感的に選べる。昔はパソコンを買ってもセットアップできず5年間箱のまま、という話もあったが、今のOSは初心者を困らせない方向に進化している。

一方、UNIXの始まりに据えられた思想（本書1ページより）：

> **何をしているのかわからないのなら、ここにいるべきではない**

他のOS設計者が初心者から専門家まで幅広く受け入れようと苦労している中、UNIX設計者はこの**不適切極まりないアプローチ**を選んだ。自己責任・事前学習を前提とする**逆張り**の設計。

### ラーメン二郎との共通点（1）：「勉強してから来い」

UNIXの厳しさは**ラーメン二郎**に酷似する。

- **コール**：麺提供直前に野菜・ニンニク・背脂の量を宣言する。店主の「ニンニク入れますか？」に「はい」と答えるのは不正解。「ニンニク」「ニンニク入れますか」が正解——自然言語として成立しないやり取りが当たり前。
- **落とし穴**：軽い気持ちで頼むと終わる、シラーメンが普通サイズ相当、など。ルールを知らないと入るな。
- **通販・自販機の二郎**＝**macOS / Windows**（食べやすい形）。**実店舗**＝**UNIX**（本番の厳しさ）。

尖ったプロダクトは最初は受け入れにくくても、誰かの心に深く刻まれ離れない——**傑作を生む**という共通点。

### 脱線エピソード：尖ったプロダクトの記憶

- **ロックマンエグゼ3 究極攻略スペシャル**：シナリオ攻略は一切載せず、クリア後の対人戦で強くなる方法だけ。表紙に「シナリオ攻略の情報は一切出てこない」と明記。HPメモリは全部取った前提。受験ドリル・難関校入試問題集のような尖り。チップ（カード）の**フォルダ**（厳密にはディレクトリ）構成まで載る。
- **ポケモンルビー・サファイア時代の大会**（愛知ベスト16）：伝説ポケモンで固めて行ったが、全員**大爆発**するチームに敗北。本格的プレイヤーは**守る**を覚えさせ、わけわからないポケモンを使う。攻略本がなく、現地で初めて知る悔しさ。

### ラーメン二郎との共通点（2）：対話型ではない

二郎の「ニンニク入れますか？」は一見対話型だが、実際は**コマンド入力のプロンプト**（`$` マークと同じ——「ここからコマンドを入れてください」という合図）。「固め」「野菜絡め」などは覚えたコマンドを打つ操作。

**対話型インターフェース**の問題：

- 麺の硬さ・味の濃さ・野菜・ニンニク・油など**変数が多い**と、1つずつ聞いていくと**時間がかかる**。
- **非対話型**（一方的にコマンドを一括指定）なら、システムを理解した人は「固め・濃いめ」と一発で済む。
- 対話型は相手の前に**拘束される**（話している間は他のことができない）——UNIX哲学はこれを嫌う。

身近な「対話型＝拘束」の例：

- Windowsアプリの「何をしたいですか？」メニュー
- タクシーの「ルートどうしますか？」
- カスタマーサポートの「1を押してください…」
- 営業電話の「説明してもよろしいでしょうか？」

**パイプ**（Aの出力をBが受け取り、次々つなぐ）の良さは、途中で対話が入ると**止まってしまう**こと。プログラム連携の観点でも対話型はマイナス。

### 負担の所在と「信頼」

整理すると、**どちらが作業負担を持つか／主導権を誰に渡すか**の話。

| | 対話型（一般的なOS） | UNIX |
|---|---|---|
| 前提 | わからない人向けにシステムが案内 | ユーザーが要件を定義してから来る |
| 主導権 | OS・システム側 | ユーザー側 |
| 信頼 | ユーザーを怖がっている | **ユーザーを信頼している** |

**進撃の巨人**の比喩：リヴァイがエルヴィンに「分かった、お前の判断を信じよう」と言って口答えせず従う——UNIXがユーザーに主導権を渡すのと同じ構図。他のOS開発者は「ユーザーはコンピューターを怖がっている」と考えがち。

プログラミング言語でも同様：**C言語**（ポインタなど前提知識が必要）vs **Python**（比較的緩い）。**力會**（厳しい塾）のように、入る条件が高く尖っているものほど話題に残る。

### 本回まとめた2つのUNIX哲学

1. **初心者向けではない**——「何をしているかわからないならここにいるべきではない」という厳しさ。それゆえに熱狂的なファンを生む。
2. **対話型（拘束的）インターフェースを嫌う**——一撃で意図を伝えられる非対話型を好む。

※UNIXの主要哲学は本によると**9つ**あり、今回はそのうち**2つ分**程度。残り（Small is beautiful、Do one thing well、テキストファイルで保存、フィルタとして設計、など）もラーメン二郎に無理やり当てはめるところで締め——次回以降に本格的なUNIX哲学の話を予定。
