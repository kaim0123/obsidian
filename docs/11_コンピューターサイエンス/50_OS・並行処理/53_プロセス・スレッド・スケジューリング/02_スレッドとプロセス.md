# スレッドとプロセス

## プロセスとは
OSから見た**実行中のプログラム**。独立したメモリ空間、ファイルハンドル、権限を持ちます。

```
[プロセスA]       [プロセスB]
 コード           コード
 メモリ(独立)    メモリ(独立)
 ファイル         ファイル
```

## スレッドとは
プロセス内の**実行の流れ**。同じプロセス内のスレッドは**メモリを共有**します。

```
[プロセスA]
  ├─ スレッド1 (スタック・レジスタは独立)
  ├─ スレッド2
  └─ スレッド3
     ↑ メモリ・ファイルは共有
```

## プロセスとスレッドの比較

| 項目 | プロセス | スレッド |
|---|---|---|
| メモリ空間 | 独立 | 共有 |
| 生成コスト | 大 | 小 |
| 切替コスト | 大 | 小 |
| 通信 | IPCが必要 | 共有変数で可 |
| 障害の影響 | 他プロセスに波及しない | プロセス全体が落ちる |
| 排他制御 | 基本不要（独立） | 必要 |

## プロセスの構成要素
- 実行コード
- 変数、ヒープ、スタック
- プロセスID（PID）
- ファイルディスクリプタ
- 環境変数
- 実行権限（UID/GID）

## スレッドの構成要素
- スレッドID
- プログラムカウンタ（どこを実行中か）
- スタック
- レジスタの値

コード・ヒープ・ファイル等はプロセス内で共有。

## プロセスの生成

### Unix: fork + exec
```c
pid_t pid = fork();
if (pid == 0) {
    execvp("ls", args);   // 子プロセスで別プログラム起動
}
```

### 高水準API
- Python: `subprocess.run(...)` / `multiprocessing.Process`
- Node.js: `child_process.spawn(...)`
- Java: `ProcessBuilder`

## スレッドの生成

### Java
```java
Thread t = new Thread(() -> {
    System.out.println("別スレッド");
});
t.start();
t.join();
```

### Python
```python
import threading
t = threading.Thread(target=lambda: print("hi"))
t.start()
t.join()
```

### C++（std::thread）
```cpp
#include <thread>
std::thread t([]{ std::cout << "hi"; });
t.join();
```

### Go（goroutine = 軽量スレッド）
```go
go func() { fmt.Println("hi") }()
```

## IPC（プロセス間通信）
プロセスはメモリを共有しないので、専用の手段が必要です。

| 方法 | 特徴 |
|---|---|
| パイプ | 親子間で簡単、単方向 |
| 名前付きパイプ（FIFO） | 任意プロセス間、ファイル経由 |
| 共有メモリ | 高速だが同期が必要 |
| メッセージキュー | 非同期通信 |
| ソケット | ネットワーク越しもOK |
| シグナル | 簡易な通知（SIGTERM等） |
| ファイル | 単純だが遅い |

## スレッドの通信
共有変数で直接やり取りできるが、排他制御が必須。
```java
synchronized (lock) {
    counter++;
}
```

## スレッドモデル

### 1:1モデル（ネイティブスレッド）
ユーザースレッド1つにつきカーネルスレッド1つ。Java、.NET、Linux pthreadなど。

### N:1モデル（全部ユーザーレベル）
1つのカーネルスレッドで複数の軽量スレッドを実行。切替高速だが、1つがブロックすると全員止まる。

### M:Nモデル（混合）
Go の goroutine、Erlangプロセス、Kotlinコルーチン。多数の軽量スレッドを少数のカーネルスレッドで効率的に回す。

## 軽量スレッド（コルーチン）
OSスレッドよりさらに軽く、数十万〜数百万同時に走らせられる。
- Go: goroutine（約2KBスタックから始まる）
- Kotlin: Coroutine
- Erlang: process
- Java 21: 仮想スレッド（Virtual Thread）

## CPU割り当てとスケジューリング

### プリエンプティブ（横取り）
OSがタイムスライスで強制的に切替。Linux・Windowsなど一般的OS。

### 協調的（協調マルチタスク）
タスク自身が「譲る」を明示。Node.jsのイベントループや古い協調OSなど。

## プロセス vs スレッド vs 非同期: いつ何を使う？

### プロセス
- 隔離が必要（サンドボックス、セキュリティ）
- Pythonで真の並列化（GIL回避）
- クラッシュ耐性が重要

### スレッド
- CPU並列化
- 細かい粒度の並行処理
- 共有データが多い

### 非同期
- I/Oバウンド
- 多数の並行接続（Webサーバー、チャット）
- メモリ効率重視

## 共有メモリのリスク
スレッドは便利だが、データ競合やデッドロックの危険がある。対策:
- ミューテックス / ロック
- イミュータブルデータ
- メッセージパッシング

詳しくは「排他制御」「デッドロックと競合状態」の章へ。

## 実例: Webサーバー

### プロセスベース
- Apache Prefork、古い設定
- 独立性高いがメモリ食う

### スレッドベース
- Tomcat、Spring Boot
- 1リクエスト1スレッド

### 非同期ベース
- Node.js、nginx
- 1スレッドで多数の接続

### 軽量スレッド
- Go + net/http
- Rust + Tokio

## プロセスツリーの確認
```bash
# Linux
ps -ef
ps -eLf           # スレッドも見る
pstree -p

# Windows
Get-Process
```

## まとめ
- **プロセス**: 独立したメモリ・堅牢だが重い
- **スレッド**: メモリ共有・軽量だが排他制御必須
- **軽量スレッド（goroutine等）**: スレッドより圧倒的に軽い
- プロセス間はIPC、スレッド間は共有メモリで通信
- 用途に応じて**プロセス・スレッド・非同期・コルーチン**を使い分ける
