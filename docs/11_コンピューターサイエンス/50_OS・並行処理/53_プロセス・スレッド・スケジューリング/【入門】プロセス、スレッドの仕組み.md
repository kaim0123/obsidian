#オペレーティングシステム #プロセス #スレッド

## 要約

面接の定番「プロセスとスレッドの違い」を、**プログラム → プロセス → スレッド** の順で積み上げて説明する入門。結論の一言は「**プロセスは隔離の単位、スレッドは実行の単位**」。

### 第1章：プログラムとは何か

プログラム＝命令の列とデータ＝**ディスク上の実行可能ファイル**。クリックされるまで何もしない静的な存在。Cのソースはテキスト → コンパイルで実行可能ファイル（CPU向け命令）になるが、まだディスク上で動いていない。動かすには **メモリに載せる**必要がある。

### 第2章：プロセスの正体

実行時、OSがファイルをメモリに読み込む（CPUはメモリからしか命令を取れない）。典型レイアウト:

| 領域 | 内容 |
| --- | --- |
| テキスト | 機械語コード（サイズ・中身は変わらない） |
| データ | グローバル／定数など起動時に決まっているもの（サイズ固定、値は変わり得る） |
| スタック | ローカル変数・関数呼び出し（積みすぎ＝スタックオーバーフロー） |
| ヒープ | 動的確保（必要時に必要なだけ。伸び縮みする） |

この「実行中の状態」がプロセス。ただしレイアウト図＝プロセスそのものではない。OSが管理する情報（レジスタ、PC、SP、メモリページ、開いているファイルなど）も付き、入れ物が **PCB（Process Control Block）**。識別は `ps` の **PID**。

同じプログラムを2回起動＝**別プロセス**（コードは同じでもデータは別。大きいファイルを開いた方がメモリ多い）。物理上のコードは共有されることもあるが、プロセスとしては別物。最重要性質は **各プロセスが自分だけのアドレス空間を持つ**こと——あるプロセスが別プロセスのメモリを壊せず、1つが落ちても他は動き続ける。Chromeがタブごとにプロセスを立てるのはこのため（クラッシュ／悪意のあるページの被害をタブ内に閉じ込める）。厳密には「壊せない」ではなく「普通は壊せない」——共有メモリやデバッガなど正規手続きの通り道はある。OSが守るのは主に事故による破壊。

### 第3章：インタプリタ言語のとき

C/Rust はコンパイル結果がプログラム。Python では登場ファイルが2つ——**インタプリタ**と `.py`。`.py` はプログラムではなくテキスト。起動されるプログラムはインタプリタ側。テキストセクションに入るのはインタプリタの機械語で、あなたのソースはヒープに読み込まれた**データ**として解釈実行される。現代の JS は JIT など複雑だが、「起動されるプログラムがエンジン」という点は同じ。

### 第4章：スレッド

スレッド＝**プロセスの中の実行単位**。実際にCPUで命令を実行しているのはスレッド。プロセスは必ず1本以上（最初がメイン）。0本のプロセスは存在しない。

会社の比喩: プロセス＝会社、スレッド＝社員。

- **スレッド専用**: スタック、レジスタ、プログラムカウンタ（※レジスタは正確にはスレッドの持ち物）
- **共有**: コード・データ・ヒープ＝アドレス空間そのもの

1本だけなら一人で全部やる状態。増やせば手分けでき、同じメモリを見るので通信は速い（変数に書けば伝わる）が、**1本の暴走でプロセス全体が落ちる**。共有カウンタを2スレッドから加算すると結果がずれる（加算＝読む・足す・書き戻しの途中で割り込まれ片方の結果が消える）→ ロックで順番を守る必要。プロセスならメモリが別なので起きない。**速さと引き換えに正しさを自分で守る**のがスレッド。Webサーバが接続ごとにスレッドを作るのは、接続ごとにプロセスを作るより軽いから。

### 第5章：並列・並行・スケジューラ

- **並列（parallelism）**: 本当に同時（コア数に物理上限。4コアなら理論上同時は4本）
- **並行（concurrency）**: OSが時間を細かく刻んで順番に走らせ、同時に見える

100本スレッドを作っても同時に動けるのはコア数分、残りは待ち。共有資源があると待たされ、並列のつもりが並行に落ちる。**スケジューラ**がCPU時間を配り優先度も付ける。Chromeで見ていないタブが遅くなるのは、非表示ウィンドウの優先度を下げている例。

### 第6章：コンテキストスイッチ

動いているプロセスをCPUから下ろし、別プロセスを載せる。下ろす前に状態を **PCB に保存**し、次のPCBを読み出して再開。コストが高い——レジスタだけでなく **アドレス空間（ページテーブル）の入れ替え**があり、キャッシュも冷えしばらく遅い。

スレッド同士の切替もコンテキストスイッチだが、**同じアドレス空間なので安い**（ページテーブル入れ替え不要、保存状態も少ない）——「スレッドが軽い」はこの差。さらに安いのが **ファイバー／コルーチン**——OSではなくアプリ自身が切替え、自分から **yield（譲る）** する約束。譲るまで他に切り替わらないので長い処理では注意。切替の安さと引き換えに複雑さを引き受ける（非同期の裏側）。

### 第7章：まとめ

| | プログラム | プロセス | スレッド |
| --- | --- | --- | --- |
| 何か | ディスク上の命令とデータ | メモリに載せて実行しているもの | その中で実際に命令を実行する単位 |
| メモリ | — | **独立**（隔離・安全だが重い） | **共有**（速いが危ない） |

Chromeがタブごとにプロセスを立てるのは、メモリ増を承知のうえで**安全を選んだ**設計。面接では「プロセスは隔離の単位、スレッドは実行の単位」と答えられる状態を目指す。
