# プロセスとスレッド

OS の最も基本的な仕事のひとつが **「プログラムを動かすこと」** である。
ここでは「プロセス」と「スレッド」という 2 つの実行単位を、初心者でもイメージできるように解説する。

---

## 1. プロセスとは

### 一言でいうと
> **プロセス ＝ 実行中のプログラム**

ディスク上にある `.exe` や バイナリファイルはただのデータ。
OS がそれをメモリに読み込み、CPU に命令を実行させた瞬間から「プロセス」になる。

### プロセスが持つもの

| リソース | 内容 |
|---|---|
| **メモリ空間** | コード・データ・ヒープ・スタックを含む独立したアドレス空間 |
| **プログラムカウンタ** | 次に実行する命令の位置 |
| **レジスタ** | CPU 内部の作業領域のスナップショット |
| **ファイルディスクリプタ** | 開いているファイル・ソケットなどの一覧 |
| **プロセスID (PID)** | OS が管理に使う一意な番号 |

### 身近な例
- ブラウザを開く → 1 つのプロセスが起動
- ターミナルで `node app.js` を実行 → Node.js のプロセスが起動
- タスクマネージャー（Windows）や `ps` コマンド（Linux/Mac）で一覧を確認できる

---

## 2. スレッドとは

### 一言でいうと
> **スレッド ＝ プロセスの中にある "実行の流れ"**

1 つのプロセスの中に複数のスレッドを持てる。
スレッドはプロセスのメモリ空間を**共有**しながら、それぞれ独立に命令を実行する。

### スレッドが持つもの（独自に持つ部分）

| リソース | 説明 |
|---|---|
| **スタック** | ローカル変数や関数呼び出し履歴（スレッドごとに別） |
| **プログラムカウンタ** | 今どの命令を実行しているか（スレッドごとに別） |
| **レジスタ** | CPU の作業領域（スレッドごとに別） |

**ヒープ・コード領域・ファイルディスクリプタ** などはプロセス内の全スレッドで共有する。

---

## 3. プロセスとスレッドの違い

```
┌─── プロセスA ────────────────┐   ┌─── プロセスB ────────────┐
│                              │   │                          │
│  メモリ空間（独立）           │   │  メモリ空間（独立）       │
│  ┌────────┐  ┌────────┐     │   │  ┌────────┐              │
│  │スレッド1│  │スレッド2│     │   │  │スレッド1│              │
│  │(スタック)│  │(スタック)│     │   │  │(スタック)│              │
│  └────────┘  └────────┘     │   │  └────────┘              │
│                              │   │                          │
│  ヒープ（共有）               │   │  ヒープ（共有）           │
└──────────────────────────────┘   └──────────────────────────┘
        ↑ 壁がある（直接アクセス不可）  ↑
```

| 観点 | プロセス | スレッド |
|---|---|---|
| **メモリ** | 独立（他プロセスとは隔離） | プロセス内で共有 |
| **生成コスト** | 高い（メモリ空間の確保が必要） | 低い（共有メモリを使い回す） |
| **通信** | IPC（パイプ・ソケット等）が必要 | メモリ共有で直接やり取り可能 |
| **安全性** | 1 つ落ちても他に影響しにくい | 1 つが異常だとプロセス全体が巻き添え |
| **切り替えコスト** | 大きい（コンテキストスイッチ重い） | 小さい（メモリ空間の切り替え不要） |

## 4. プロセスの生成

### fork（UNIX系）
親プロセスのコピーを作って子プロセスを生成する。

```
親プロセス
    │
    ├── fork() ──→ 子プロセス（親のコピー）
    │                  │
    │                  └── exec() で別プログラムに置き換え可能
    │
    └── 親は続行
```

- `fork()` の直後、親と子はほぼ同じ状態
- 子プロセスで `exec()` を呼ぶと、別のプログラムに差し替えられる
- この「fork + exec」パターンが UNIX の基本

### Windows の場合
`CreateProcess()` という API で一発でプロセスを作る（fork の概念はない）。

---

## 5. 生成コストの違い

なぜプロセスの生成はスレッドより重いのか？

1. **メモリ空間の確保**: プロセスには独立したアドレス空間が必要 → ページテーブルの作成等が発生
2. **OS リソースの割り当て**: ファイルディスクリプタ表、シグナルハンドラなどの初期化
3. **コピー**: fork の場合は親プロセスの状態をコピー（Copy-on-Write で最適化はされる）

スレッドはこれらの大半をスキップして、スタック領域の確保程度で済む。

## 6. プロセスの状態遷移

プロセスは常に以下のいずれかの状態にある。

```
                      ┌─────────┐
         生成 ──────→ │  Ready  │ ←────── タイムアウト/割り込み
                      │ (実行可能)│
                      └────┬────┘
                           │ ディスパッチ（CPU割り当て）
                           ▼
                      ┌─────────┐
                      │ Running │
                      │ (実行中) │
                      └──┬───┬──┘
               I/O待ち   │   │   終了
                  ┌──────┘   └──────┐
                  ▼                 ▼
            ┌──────────┐      ┌──────────┐
            │ Waiting  │      │Terminated│
            │ (待機中)  │      │ (終了)    │
            └──────────┘      └──────────┘
```

- **Ready（実行可能）**: CPU の割り当てを待っている
- **Running（実行中）**: CPU で命令を実行中
- **Waiting（待機中）**: I/O 完了やイベントを待っている
- **Terminated（終了）**: 実行完了。リソースが解放される

## 7. 用途の使い分け

### プロセスを使うケース
- **安全性・隔離が重要なとき**: Web ブラウザのタブ（Chrome は各タブが別プロセス）
- **異なるプログラムを実行するとき**: シェルからコマンドを実行
- **クラッシュの影響を限定したいとき**: ワーカープロセス（Nginx, Gunicorn）

### スレッドを使うケース
- **同じプログラム内で並行処理したいとき**: GUI の描画と裏でのデータ処理
- **データ共有が頻繁なとき**: メモリ共有の方がIPCより高速
- **軽量に並行処理を増やしたいとき**: Web サーバーのリクエスト処理

### どちらでもない新しい選択肢
- **コルーチン / グリーンスレッド**: OS スレッドより更に軽量（Go の goroutine、Python の asyncio）
- **イベントループ**: シングルスレッドで非同期 I/O（Node.js）

---

## 8. 開発者として知っておくべきこと

1. **プロセスの隔離はセキュリティの基本**: あるプロセスが別プロセスのメモリを直接読み書きできない（サンドボックスの原理）
2. **マルチスレッドはバグの温床になりやすい**: メモリ共有 → 排他制御が必要 → デッドロックや競合状態のリスク（→ `同期と排他制御.md` で詳述）
3. **「並行」と「並列」は違う**: 並行（concurrent）は "交互に進める"、並列（parallel）は "同時に進める"。シングルコアでも並行は可能
4. **Node.js はシングルスレッド?**: メインの JavaScript 実行はシングルスレッドだが、I/O は裏で別スレッドが処理している（libuv）
