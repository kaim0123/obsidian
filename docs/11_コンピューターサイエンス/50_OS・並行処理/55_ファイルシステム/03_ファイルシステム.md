# ファイルシステム

コンピュータのデータは最終的にディスク（SSD/HDD）に保存される。
ファイルシステムは、このディスク上のデータを **「ファイル」と「ディレクトリ」** という形で整理し、効率的に読み書きするための仕組みである。

---

## 1. ファイルシステムとは何か

### 一言でいうと
> **ディスク上の 0 と 1 の羅列を、人間が扱える「ファイル名」「フォルダ」として見せる仕組み**

ディスクはただのバイト列の塊。ファイルシステムがなければ「どこからどこまでが 1 つのファイルか」すら分からない。

### ファイルシステムの役割
1. **データの配置管理**: どのデータがディスクのどの位置にあるか追跡
2. **名前の管理**: ファイル名・ディレクトリ構造を維持
3. **メタデータの管理**: サイズ、作成日時、権限などの付帯情報
4. **空き領域の管理**: どのブロックが未使用か把握
5. **アクセス制御**: 誰が読み書きできるか

---

## 2. 代表的なファイルシステム

| ファイルシステム | OS | 特徴 |
|---|---|---|
| **NTFS** | Windows | ジャーナリング対応、ACL による細かい権限管理 |
| **ext4** | Linux | 広く使われる Linux 標準。ジャーナリング対応 |
| **APFS** | macOS/iOS | Apple デバイス向け。スナップショット対応 |
| **FAT32** | 汎用 | シンプルで互換性が高い。USB メモリなどに利用。4GB制限 |
| **exFAT** | 汎用 | FAT32 の 4GB制限を解消。SD カードなどに利用 |

## 3. inode（アイノード）

UNIX 系 OS（Linux, macOS）のファイルシステムの核心となるデータ構造。

### inode とは
> **ファイルの「メタデータ」と「データブロックの位置」を記録する構造体**

重要なポイント: **inode にファイル名は含まれない**。

### inode に含まれる情報

| 情報 | 説明 |
|---|---|
| ファイル種別 | 通常ファイル / ディレクトリ / シンボリックリンク 等 |
| 所有者・グループ | `uid`, `gid` |
| パーミッション | `rwxr-xr-x` のようなアクセス権限 |
| サイズ | ファイルのバイト数 |
| タイムスタンプ | 作成日時・更新日時・アクセス日時 |
| データブロックへのポインタ | 実際のデータがディスクのどこにあるか |
| リンク数 | このinodeを指すディレクトリエントリの数 |

### ファイル名はどこにあるか？
**ディレクトリ** が「ファイル名 → inode 番号」の対応表を持っている。

```
ディレクトリ "documents/"
┌───────────────────────────┐
│ ファイル名    │ inode番号  │
├───────────────┼───────────┤
│ report.txt   │   42      │
│ memo.md      │   87      │
│ data.csv     │   103     │
└───────────────┴───────────┘

inode #42
┌──────────────────────┐
│ サイズ: 1024 bytes    │
│ 権限: rw-r--r--      │
│ データブロック: [5, 8] │ → ディスクのブロック5, 8に実データ
└──────────────────────┘
```

### ハードリンクとシンボリックリンク

```
ハードリンク:
  fileA.txt  ──→  inode #42  ──→ データブロック
  fileB.txt  ──→  inode #42  ──→ （同じデータ）
  ※ 同じ inode を複数の名前が指す。片方を消してもデータは残る

シンボリックリンク (symlink):
  shortcut.txt  ──→  "documents/report.txt"（パス文字列）
  ※ 別ファイルへの「ショートカット」。元ファイルを消すとリンク切れになる
```

## 4. ファイルディスクリプタ

### 一言でいうと
> **プログラムが開いているファイルを識別するための整数番号**

ファイルを `open()` すると、OS がファイルディスクリプタ（fd）を返す。以降はこの番号を使って読み書きする。

### 標準のファイルディスクリプタ

| fd | 名前 | 用途 |
|---|---|---|
| **0** | stdin（標準入力） | キーボード入力 |
| **1** | stdout（標準出力） | 画面出力 |
| **2** | stderr（標準エラー） | エラー出力 |

```bash
# リダイレクトの仕組みはファイルディスクリプタの差し替え
echo "hello" > output.txt   # fd 1 を output.txt に向ける
./app 2> error.log          # fd 2 を error.log に向ける
./app > /dev/null 2>&1      # fd 1 と fd 2 をどちらも捨てる
```

### 開いたら閉じる
ファイルディスクリプタは有限のリソース。`open()` したら `close()` する。
閉じ忘れるとリソースリークになり、やがて「Too many open files」エラーになる。

## 5. ジャーナリング

### 問題: 書き込み途中でクラッシュしたらどうなる？

ファイルの保存中に停電やクラッシュが起きると、中途半端な状態がディスクに残る可能性がある。

### ジャーナリングの仕組み
> **書き込みの「予定」を先にログ（ジャーナル）に記録してから、実際の書き込みを行う**

```
1. ジャーナルに「これからブロック5にデータAを書く」と記録
2. 実際にブロック5にデータAを書き込む
3. 書き込み完了 → ジャーナルの記録を消す

もし 2 の途中でクラッシュしたら？
→ 再起動時にジャーナルを読み、未完了の操作をやり直す（リプレイ）
```

### ジャーナリングの種類

| 種類 | 内容 | 速度 | 安全性 |
|---|---|---|---|
| **メタデータのみ** | ファイルサイズや場所の変更だけ記録 | 速い | データ内容は保護されない |
| **フルジャーナリング** | データ本体も含めて記録 | 遅い | 最も安全 |

ext4 はデフォルトでメタデータのみジャーナリング。

## 6. ディスクの構造とブロック

### ブロック（Block）
ファイルシステムがデータを読み書きする最小単位。一般的に **4KB**。

```
ディスク全体
┌──────┬──────┬──────┬──────┬──────┬──────┬───┐
│ block│ block│ block│ block│ block│ block│...│
│  0   │  1   │  2   │  3   │  4   │  5   │   │
└──────┴──────┴──────┴──────┴──────┴──────┴───┘
```

- 1 バイトのファイルでも最低 1 ブロック（4KB）を占有する
- 小さいファイルがたくさんあると、ブロックの無駄（内部断片化）が発生する

### パーティション
1 つの物理ディスクを論理的に分割したもの。

```
物理ディスク (512GB SSD)
┌─────────────┬─────────────┬───────────────┐
│ パーティション1│ パーティション2│ パーティション3 │
│ (Windows C:) │ (Linux /)    │ (swap)        │
│ NTFS        │ ext4         │               │
└─────────────┴─────────────┴───────────────┘
```

## 7. VFS（Virtual File System）

Linux では、異なるファイルシステム（ext4, NTFS, FAT32...）を **統一的なインターフェース** で扱えるようになっている。これが VFS。

```
アプリケーション
      │
      │  open(), read(), write(), close()
      ▼
┌──────────────┐
│     VFS      │ ← 統一インターフェース
└──┬───┬───┬───┘
   │   │   │
   ▼   ▼   ▼
 ext4 NTFS FAT32    ← 各ファイルシステムドライバ
```

「すべてはファイル」という UNIX の哲学:
- `/dev/sda` → ディスクデバイスもファイル
- `/proc/cpuinfo` → CPU 情報もファイルとして読める
- ソケットやパイプもファイルディスクリプタで操作

## 8. 開発者として知っておくべきこと

1. **パスの区切り文字**: Windows は `\`、UNIX系は `/`。クロスプラットフォームでは注意（Node.js の `path.join()` など）
2. **ファイル名の制限**: OS やファイルシステムによって使えない文字・長さの制限が異なる
3. **アトミックな書き込み**: `rename()` はアトミック（途中状態がない）。安全なファイル更新は「一時ファイルに書いて rename」が定石
4. **パーミッション**: `chmod 755` の意味 — 所有者(rwx) / グループ(r-x) / その他(r-x)
5. **fd リーク**: ファイルを開いたら必ず閉じる。`try-finally` や `with` 文、`using` を活用
