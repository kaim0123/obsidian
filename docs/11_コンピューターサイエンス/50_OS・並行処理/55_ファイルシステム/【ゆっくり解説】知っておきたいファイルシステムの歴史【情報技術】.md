## 詳しい要約

本動画は、**1950 年代のパンチカード** から **SSD 時代の最新ファイルシステム** まで、**ファイルシステム（File System）** の歴史を時系列で解説する。ファイルシステムとは、コンピュータ内で **「どこに何のデータがあるか」** を管理する仕組みであり、これがなければ PC は **ただの鉄塊** に過ぎない。神社の賽銭箱の整理に例えながら、**記憶装置の進化** と **ファイルシステムの進化** が常に連動してきたことを描く。

### ファイルシステムとは

- **ファイルシステム**＝ディスク上のデータの **配置・名前・権限・整合性** を管理する OS の中核機能。
- ユーザーがフォルダやファイル名で操作している裏側で、**クラスタ・ブロック・メタデータ** を通じて物理的な記録位置を抽象化している。
- 普段は意識しないが、**コピー・削除・起動・バックアップ** のすべてがファイルシステムに依存する **不可欠な基盤技術**。

---

### ファイルシステムの進化年表

| 年代 | 記憶装置 / FS | 特徴 |
|------|---------------|------|
| **1950 年代** | **パンチカード** | ファイルシステムなし。1 枚 80 文字程度。物理的な順序管理 |
| **1950 年代後半〜** | **磁気テープ** | **順次アクセス** のみ。テープ先頭にファイル一覧。2000 年代までバックアップ用途 |
| **1960 年代〜** | **HDD（RAMAC 等）** | **ランダムアクセス** が可能に。本格的な FS 設計の始まり |
| **1977〜** | **FAT12 → FAT16 → FAT32** | フロッピー向け。**クラスタ + FAT 表** で管理。USB/SD で現役 |
| **1993** | **NTFS** | Windows NT と同時登場。**ジャーナリング・権限・暗号化** |
| **1992〜2008** | **ext → ext2 → ext3 → ext4** | Linux 系。**ジャーナリング・エクステント・遅延割り当て** |
| **2010 年代〜** | **SSD 向け FS** | **ReFS / Btrfs / F2FS / APFS** など。スナップショット・SSD 最適化 |

---

### 第 1 期：ファイルシステム以前——パンチカードと磁気テープ（1950 年代）

#### パンチカード時代

- **1950 年代** のコンピュータには **ファイルシステムという概念自体が存在しなかった**。
- **パンチカード** に穴を開けて 0/1 を記録。1 枚あたり **約 80 文字** しか入らず、「Hello World」程度のプログラムでも 1 枚を消費。
- 数百枚のカードを **正しい順序** で通す必要があり、落として順番が狂うと **地獄の再整理** が発生——これが **物理的なファイル管理の原点**。

#### 磁気テープ時代

- **1950 年代後半** から **磁気テープ** が普及。カセットテープと同様の原理で **大量データの記録** が可能に。
- しかし **順次アクセス（Sequential Access）** しかできない——テープの 10 曲目を聴くには最初から早送りするのと同じで、**途中のファイルに直接アクセスできない**。
- テープ先頭に **ファイル一覧** を書く程度の単純な管理だったが、パンチカードよりはるかにマシ。**バックアップ用途では 2000 年代まで現役**。

---

### 第 2 期：HDD の登場と FAT 系列（1960〜1990 年代）

#### ハードディスクとランダムアクセス

- **1960 年代**、**HDD（Hard Disk Drive）** が登場。IBM の **RAMAC** は冷蔵庫 2 台分のサイズで **容量わずか 5 MB** だったが、当時は革命的。
- 円盤上を読み取りヘッドが **好きな位置に直接移動** できる **ランダムアクセス** が可能に——CD で好きな曲を選ぶのと同じ原理。
- これにより **データの配置・管理を真剣に設計する必要** が生じ、**1960〜70 年代** に UNIX の UFS など各種 FS が開発された。

#### FAT（File Allocation Table）

- **1977 年**、Microsoft が **FAT（File Allocation Table）** を開発。**フロッピーディスク向け** のシンプルな FS。
- ディスクを **クラスタ** という小さな区画に分割し、**どのクラスタがどのファイルに使われているか** を表（FAT）で管理——神社の境内を区画分けしてノートに記録するイメージ。
- **FAT12 → FAT16 → FAT32（1996）**：数字はアドレス指定の **ビット数**。管理できる **ファイル数・サイズ・ディスク容量** が段階的に拡大。
- **FAT32** は **2 TB まで** のディスクに対応し、**USB メモリ・SD カード** で今も広く使われる。**シンプルさと互換性** が強み。

#### FAT の欠点

- **断片化（Fragmentation）**：書き込み・削除を繰り返すとファイルがディスク上に **バラバラに散在** し、読み込みが遅くなる。
- **デフラグ（Defrag）** が定期的に必要——散らばったファイルを **まとめて整理** する作業。
- **FAT32 の 4 GB ファイルサイズ制限**——現代の大容量ファイル（動画・ISO イメージ等）には不向き。

---

### 第 3 期：NTFS——Windows の次世代 FS（1993〜）

- **1993 年**、Microsoft が **NTFS（New Technology File System）** を **Windows NT** と共に発表。**Windows 11 でも現役** の標準 FS。

#### 主な機能

| 機能 | 内容 |
|------|------|
| **大容量対応** | 理論上 **16 EB（エクサバイト）** までのファイルサイズ |
| **ジャーナリング** | ファイル操作の **変更履歴を記録**。停電・クラッシュ時に **途中から修復** 可能 |
| **アクセス権限（ACL）** | ユーザー・グループごとに **読み取り・書き込み** を細かく制御 |
| **圧縮・暗号化** | FS レベルで **自動圧縮** や **EFS 暗号化** をサポート |
| **ハードリンク / シンボリックリンク** | 1 つのファイルを **複数のパスから参照** 可能 |

- FAT 時代は停電で **ファイルシステム全体が破損** することもあったが、NTFS のジャーナリングにより **データ整合性が大幅に向上**。
- **30 年以上** 使われ続けているが、内部は **何度もアップデート** されており、基本設計の優秀さが長寿命の理由。

---

### 第 4 期：Linux の ext 系列（1992〜2008）

#### ext / ext2

- **1992 年**、Linux 向けに **ext（Extended File System）** が登場するが、すぐに問題が判明。
- **1993 年** の **ext2** が Linux の **事実上の標準** になった。ただし **ジャーナリング機能がなく**、異常終了時は **fsck（ファイルシステムチェック）** でディスク全体をスキャン——大容量ディスクでは **数時間** かかることも。

#### ext3——ジャーナリングの導入

- **2001 年**、**ext3** が登場。ext2 に **ジャーナリング** を追加したバージョン。
- **後方互換性** あり——ext2 フォーマットのディスクを **そのまま ext3 としてマウント** 可能。
- **2000 年代の Linux** で広く使われ、安定性が評価された。

#### ext4——現代 Linux の標準

- **2008 年**、**ext4** が登場。主な改良点：
  - **ボリュームサイズ**：ext3 の最大 16 TB → ext4 は **1 EB（エクサバイト）**
  - **エクステント（Extents）**：ブロックを 1 個ずつではなく **連続範囲（例：ブロック 100〜200）** で管理し、**大ファイルの性能向上・断片化抑制**
  - **遅延割り当て（Delayed Allocation）**：書き込みをバッファに溜めてから **効率的にディスクへ書き込み**
- 現時点でも **多くの Linux ディストリビューションのデフォルト FS**。
- 動画では **XFS・Btrfs・ZFS** なども言及されるが、詳細は別動画へ。

---

### 第 5 期：SSD 時代の最新ファイルシステム（2010 年代〜）

#### SSD 時代の課題

- **2010 年代** から **SSD（Solid State Drive）** が普及。機械部品がなく **フラッシュメモリ** で記録するため **高速**。
- しかし HDD とは特性が異なり、**同じ場所への書き込み回数に上限** がある——特定セルばかり使うと **劣化（ウェアアウト）** する。
- **ウェアレベリング** により書き込みを **均等に分散** させる必要があり、FS 側も **SSD 向けの最適化** が求められる。

#### 各 OS の最新 FS

| FS | 開発元 | 主な特徴 |
|----|--------|----------|
| **ReFS** | Microsoft（2012） | **Resilient File System**。**自動修復・CoW・スナップショット**。主にサーバー用途 |
| **Btrfs** | Linux コミュニティ | **スナップショット・サブボリューム・圧縮・重複排除（dedup）** |
| **F2FS** | Samsung | **Flash-Friendly File System**。**SSD 専用** 最適化。スマートフォン等で採用 |
| **APFS** | Apple（2017） | **Apple File System**。**暗号化・スナップショット・クローン**。iPhone / Mac の SSD 向け |

#### 共通する現代 FS の機能

- **ジャーナリング** —— 異常終了からの **高速復旧**
- **スナップショット** —— ある時点の FS 状態を **丸ごと保存・一瞬で復元**（タイムマシン的）
- **コピーオンライト（CoW）** —— 上書きせず **新しい場所に書いてから古いデータを削除**。書き込み中のエラーでも **元データを保護**
- **暗号化・SSD 最適化** —— セキュリティと **フラッシュメモリの寿命延長**

---

### まとめと今後

- ファイルシステムの歴史は **記憶装置の進化と不可分** —— パンチカード → テープ → HDD → SSD と、媒体が変わるたびに **新しい FS が生まれる**。
- 現代の FS は **ジャーナリング・スナップショット・暗号化・SSD 最適化** など **似た機能を標準装備** し、技術が **成熟・収束** してきた。
- 今後、**3D XPoint・MRAM** など **次世代不揮発性メモリ** が普及すれば、再び **新しいファイルシステム** が必要になる可能性がある——**進化はまだ続いている**。
