#プログラミング #エンジニア

## 要約

「プログラミングとはメモリのシンタックスシュガーである」——malloc / free / スタックオーバーフローなどを、暗記ではなく**メモリの図**でつなげる入門。観察用の顕微鏡として C 言語を使い（普段使いの言語である必要はない）、ゴールは次の3つ。

1. スタックとヒープの決定的な違い  
2. メモリリークとスタックオーバーフローがなぜ・どう起きるか  
3. 物理的なイメージで掴むこと  

### メモリの基本：番地とセル

メモリは同じ大きさの区画が1列に並び、各区画に **アドレス（住所）** が振られている。データを置く＝番号付き区画に値を書くこと。変数名は人間用のラベルで、CPUが見ているのはアドレス。**名前・アドレス・値**をいつもセットで見る習慣が大事。

### スタック：LIFO と自動片付け

役割の違う2領域のうち、まずスタック。ルールは **LIFO（後入れ先出し）** だけ。

- 関数呼び出しごとに **スタックフレーム** が上に積まれる（ローカル変数はその中）  
- CPUが実行しているのは常に一番上のフレーム  
- 関数が終わるとフレームが丸ごと外れ、中のローカルも消える——**誰も命令しなくても自動で片付く**（最大の長所）  

弱点は2つ。

1. 関数終了で中身が消える → データを長生きさせられない  
2. 確保サイズをコンパイル時に決める必要がある → 「実行してから100個欲しい」が基本できない  

### ヒープ：malloc・ポインタ・長生き

ヒープは好きな場所・好きな大きさで自由に確保できる広い領域。**勝手には消えない**——解放するまで残り続けるのがスタックとの決定的な違い。

- **`malloc`** … ヒープに領域を用意し、**先頭の住所を返す**  
- 今日いちばん大事な図: **ポインタ `ptr` はスタック上**にあり、その**値はヒープ領域の住所**。データ本体は遠くのヒープ、手元には住所だけ  
- `*ptr = 100` … アスタリスク＝矢印を辿った先へ書き込む  

関数が終わるとスタック上の `ptr` は消えるが、ヒープの100は残る。住所を return すれば関数を超えて使い続けられる。実行時に `n` を受け取ってから `n` 個分 malloc するなど、**サイズも自由**。スタックの2弱点を埋める一方、片付けは自分の責任。

### free・ダングリング・GC

C には GC がない。**`malloc` したら必ず `free`**（ペアで考える）。`free` 後も `ptr` の値（住所）は残り、解放済みを指し続ける＝**ダングリングポインタ**。定石は解放後に `NULL` を入れる。

普段の言語で `free` を書かないのは消えたのではなく、**GC＝自動化された free**（誰も指していないヒープを回収）。スタック／ヒープの根本は言語が変わっても同じ。

### 2つの有名バグ

| | スタックオーバーフロー | メモリリーク |
| --- | --- | --- |
| 起き方 | 止まらない再帰などでフレームが積まれ続け、有限の天井を突き破る → **即クラッシュ** | `malloc` したが `free` 忘れ。関数終了でポインタは消えるがヒープは残り、**到達不能な迷子メモリ**が溜まる → **じわじわ枯渇** |
| 対策の感覚 | 停止条件／巨大ローカル配列を積みすぎない | 確保と解放のペア。GC言語でも参照が残り続ければリークは起きる |

### 「変数は箱」をやめて表を手書きする

箱の比喩はポインタ／参照で破綻する。慣れないうちは**住所と値の両方**をメモリ表に書く。ポインタの値は住所そのもの、ポインタのポインタも表上では「値が住所」。型サイズ（例: int 4バイト、64bitポインタ8バイト）も意識。値渡し／参照渡しは曖昧語より**スタック表で何がコピーされ、住所か値が渡るかを見る**。Java などではプリミティブ以外は多くヒープにあり、スタックには住所だけ——**スタック表とヒープ表を両方書く**のが最強の理解法。

### 持ち帰る3点

1. **スタック**は自動で積んで自動で消える（高速・固定サイズ）  
2. **ヒープ**は自分で借りて自分で返す（手動／低速・サイズ自由）。両者をつぐのがポインタ  
3. **積みすぎ**→スタックオーバーフロー、**返し忘れ**→メモリリーク  

普段の高水準言語でも、裏ではスタックが積まれ、ヒープが確保され、GCが片付ける。メモリの使い方を意識できれば、言語を問わずパフォーマンスやバグの原因を論理的に推測できる。
