## 詳しい要約

### シリーズの位置づけ

「プリンシプルオブライフ」第3回。今回の柱は **リファクタリング**、**コードの臭い（code smell）**、**命名の重要性**、そしてラリー・ウォールの **プログラマの三大美徳**（怠惰・短気・傲慢）。冒頭から「編集者とプログラマはほぼ同じ仕事（相手は才能ある人、見出し・命名にこだわる）」という抽象化で始まる。

### リファクタリングとは

- **リファクタリング**：外から見た振る舞いは変えず、ソースを**きれいに書き直す**作業（rewrite に近い）。コンピューター界隈でしか使わない専門語、という自虐比喩（官能小説の「海」レベル）。
- **具体例**：重複処理の統合、インデント整理。編集の**推敲・リライト**、自分の数ヶ月前の原稿を見て恥ずかしくなる感覚と同型。
- **共有コードの羞恥**：サポーターサイトをフロントエンド担当と分担し、自分のバックエンドが丸見えになる「苦行」。フロントでやるべき処理をサーバ側でごまかしている部分など。
- **Excel 比喩**：`#NAME?`、とりあえず全部 `SUM`、家に仕事持ち帰り——非エンジニアにも伝わるレベルで説明。

**賛否**：動いているものに手を入れると壊れるリスクもあるが、『達人プログラマー』は **少しずつ書き直せ**（次の担当の負荷が爆増するから）と繰り返し述べる。

### 引き継ぎ・コードを直す難しさ

- 前任者のコードは「深い理由がある」のか「その場しのぎ」か判別不能。
- **不要に見える分岐を消す**→動かなくなる、というあるある（数学の因数分解・場合分けのたとえ）。
- 直すときの手がかりはフィーリングではなく、経験則として **「臭い（くさい）ところ」**。

### コードの臭い（Code Smell）

調香師の比喩——物理的な臭いではなく、**このままだと失敗しがち**という経験則。

| 用語（おしゃれな例） | ざっくり意味 |
|---|---|
| 重複コード | 同じことを繰り返している |
| 長すぎるメソッド | クリック4回分を1行にまとめるべきではない |
| 消費税8%と10%で別関数 | まとめられる処理の重複 |
| 昨日の横恋慕 | 他クラスのメソッドを過度に呼ぶ |
| 不適切な親密さ | 他クラスの実装詳細に依存 |
| 相続拒否 | （用語として紹介） |

現場では「臭い」とより **「関数が長いので分割しましょう」** と言うことが多い、というメタ談。

### その場しのぎ（Quick and Dirty）と TypeScript

- **その場しのぎ**：Excel で全部足す、`any` で型エラーを黙らせる（TypeScript の `any` 乱用）など。動くが後から読めない＝**腐臭するコード**。
- TypeScript は型で安全にする言語だが、エラーを消すために `any` を書くのは **愚かさの自覚** ネタとして自己開示。

### 命名は最重要課題

『達人プログラマー』で何度も繰り返される原則。

- 関数・ファイル名は **穴埋めパン（半導体のゲート記号）** のように、見ただけで役割が分かるべき。
- **悪い例**：`registerCustomerInformation` と名付けたが、中身の大半が入力検証 → 実態は `validateCustomerInformation`。名前と中身がずれたまま残ると、リファクタリングが必要になる。
- **編集者との共通点**：雑誌の特集タイトル、大トリの見出しが軸になる。「〇〇の未来」「〇〇入門」は角度が弱い——命名と同型の失敗。

### プログラマの三大美徳（Three Virtues）

ラリー・ウォール（Perl）由来。**怠惰・短気・傲慢**（Laziness, Impatience, Hubris）。

| 美徳 | 意味（番組での解釈） |
|---|---|
| **怠惰** | 同じ面倒を繰り返さない。自動化・再利用 |
| **短気** | 遅い・待たされる部分を早くしたがる原動力 |
| **傲慢** | 「俺が書いたコードがこんなに汚いはずがない」——許せず書き直す。**作品への矜持** |

傲慢はプログラマに限らず **ものづくりする人全般** に広げられる、という主張。

### 傲慢の具体例（クリエイター）

- **東村アキコ**（NHK『まんべん』）：アシスタント仕上げの完成原稿を見て「違う」と書き直す。多連載・育児の狭間でも品質の一線を譲らない。
- **浦沢直樹**：漫画家は100人100通りの仕事——比較・解説の面白さ。
- **ラジオ制作への応用**：ボツ素材だらけで更新が遅いのは **傲慢が足りない** のでは（「公開順を推測し間違えていけない」気持ち）。悪用はせず、プロ意識として持つ。

### まとめ

- リファクタリング・臭い・命名は、編集の推敲・タイトル・リライトと **同じ構造**。
- 三大美徳のうち **傲慢** を特に推し——「これでいいはずがない」感覚を持って、コードも番組も磨き続ける、という締め。
- 水野さんのダメコードを酒飲みながら実況レビューする企画案（コードレビュー文化のエンタメ化）もネタとして出る。
