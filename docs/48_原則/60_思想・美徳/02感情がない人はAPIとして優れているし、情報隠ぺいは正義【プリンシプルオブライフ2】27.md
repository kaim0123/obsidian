## 詳しい要約

### シリーズの位置づけ

「プリンシプルオブライフ」第2回。前回に続き『**The Pragmatic Programmer**』由来の原則を人生訓に読み替える。今回のテーマは **情報隠蔽（information hiding）**。「隠す＝悪」という一般印象（公文書改ざん、強権国家など）とは逆に、エンジニアリングの文脈では **正義** だ、という主張。

### オープニング：本心が見えない人＝REST API

にこやかに振る舞うが腹の内が読めない人——ポーカーフェイス、お調子者、ふられたのに笑っているように見える人など——を、**内部構造が見えず情報隠蔽が完璧**な存在として称賛する導入。

- **パルナスの規則**を満たしている  
- **ステートレス**で、ある程度 **冪等性** がある  
- アーキテクチャとして **REST API** に近い  

→「付き合いづらい」のではなく **設計として優れている**、という逆張り。

### 半導体回とのつながり（ブラックボックス）

未公開の半導体まとめ回では **モジュール化・ブラックボックス**（全加算器など「入力がこう入ればこう出る、中身は気にしない」）を雑に語ったが、より正確なソフトウェア工学用語が **情報隠蔽**。

| 半導体回で触れたこと | 今回の emphasis |
|---|---|
| 中身を**気にしなくていい**（利用者の負荷軽減） | 中身を**公開しない**（境界の設計） |

「オープンソース＝正義」とは別レイヤの話（規模が違う）として切り分ける。

### 情報隠蔽の2つのメリット（経費精算の例）

水野さんは経理・会計・確定申告を理解していないが、**経費精算はできる**。

- 領収書を決まった手続きで渡す → 「受け取りました」→ しばらくして払い戻し  
- 経理部は内部フロー（どこを回るか、決裁、銀行処理など）を**一切説明しない**  

これが情報隠蔽の具体例。

1. **知る必要のないことを知らなくてよい** — 経費精算のために会計を学ばなくてよい。決算・貸借対照表まで追うと本業に戻れない。  
2. **安全である** — 素人が PL/BS を触ると粉飾・誤記のリスク。行政文書も、訓練を受けた有資格者が書くのと同型。

大企業の社員や、税理士に決算を丸投げする中小経営者も、**専門の内側を隠蔽されたモジュール**として機能を使っている、という話。

### パルナスの規則（Parnas's Law）

オブジェクト指向などで **情報隠蔽のための規則** として語られる。

> モジュールの利用者には、その利用に**必要な情報だけ**を与え、それ以外は**一切見せない**。

- 「ブラックボックス＝悪」ではなく、**必要な情報だけ出ている**のが良い設計。  
- 経理部は領収書という決まった入力でお金が返る → **パルナスの規則を満たしている**。  
- 大企業の分業・「歯車の一つ」批判の裏返しとして、**知らなくていいことを知らないままにできる**のは合理的、という視点。

（半導体回の振り返り：リスナーには「ブラックボックス」印象だけ残り、本題が消えた——というメタ談あり。）

### API・Stripe・REST の例

ゆるコンピューター科学ラジオのサポーター決済 **Stripe** を例に **API** を説明。

- **API**（Application Programming Interface）：巨大な内部実装を隠し、「こうリクエストを送ればこう返る」という**窓口**だけ公開。  
- 顧客情報の取得など、マニュアル通りにサーバーへ送ればデータが返る。**中で何が起きているかは分からない**＝情報隠蔽。  
- **REST API**：決まった URL・フォーマットで送ると、成功レスポンスかエラーが返る。経理部の「領収書を渡すとお金かエラー」に相当。

### 人間を REST API と呼ぶ（本題の抽象化）

冒頭の「本心が見えない人」を再定義。

- 内部の感情・本音は隠蔽されているが、**決まった振る舞い（リクエスト）に対して適切な応答**を返す。  
- **ステートレス**：その場の気分で急に切れない（飲み会でも同じように返してくれる安心感）。  
- **冪等性**：同じリクエストを何度送っても同じ種類の正しい応答（外さない）。  
- **パルナスの規則**：余計な本音を見せず、付き合いに必要な情報だけ出す → **付き合いやすい**側面もある。

「REST API だから褒めるべき」「サイコパスではなく REST API と呼んでほしい」など、エンジニア用語での人物評ジョーク。人間を手段にするのは行き過ぎ、という自己ツッコミもあり。

### このラジオ自身も情報隠蔽

- リスナーに**楽しむために必要な話だけ**を喋り、収録準備・台本の厚意など**余計な情報は出さない** → 番組設計もパルナスの規則に沿っている、というメタ。  
- 水野さんは聞かれたことだけ的確に返し、余計なことをしない → **優れたラジオパーソナリティ API**、というネタ。

### まとめ・用語の言い換え

- **情報隠蔽** ＝ 悪い響きだが、実態は **「提供情報の最小化」** に近い（認知負荷の低下・安全性の向上）。  
- モジュール化の本質は情報隠蔽。不要な情報を与えないことが、パルナスの規則を守る設計。  
- 締めでは「情報開示こそ正義」との水掛け論は避け、**隠蔽は正義** として回を閉じる。サポーター向け **REST API 名** などのネタも触れる。
