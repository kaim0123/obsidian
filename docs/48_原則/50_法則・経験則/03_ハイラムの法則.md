# ハイラムの法則（Hyrum's Law）

## はじめに

ライブラリのバグを直したら、「バグ修正のせいで動かなくなった」と苦情が来た——こんな経験はないでしょうか。ドキュメントには一言も書いていない挙動なのに、**誰かがそれを当てにしていた** のです。

API を使う人が増えるほど、この現象は避けられなくなります。これを **ハイラムの法則（Hyrum's Law）** と呼びます。

---

## 一言でいうと

**「使う人が十分に多ければ、仕様に書いていない挙動まで、必ず誰かが依存する」**

原文はおおむね次のとおりです。

> API の利用者が十分に多ければ、契約（仕様）で何を約束したかは関係なくなる。システムの観測可能なふるまいはすべて、誰かに依存される。

---

## 出典・背景

- Google のソフトウェアエンジニア **Hyrum Wright** の観察が元になっている
- Google 社内の大規模な共通ライブラリを変更する中で、何度もこの問題にぶつかったことから生まれた
- 書籍『Software Engineering at Google』（2020）で取り上げられ、広く知られるようになった

これを皮肉った有名な漫画が xkcd の「Workflow」（#1172）です。「キーボードを押し続けると CPU が熱くなるバグ」を直したら、「その熱でスペースキーを温めていたのに！」と苦情が来る、という話です。

---

## 現場で起きる例

### 例1: 並び順

```javascript
// 仕様: 「ユーザーの一覧を返す」（順序は保証しない）
function getUsers() {
  return db.query('SELECT * FROM users'); // たまたま ID 順で返っていた
}

// 利用者のコード
const users = getUsers();
const oldest = users[0]; // 「先頭が一番古いユーザー」だと思い込んでいる
```

DB のインデックスを変えたら並び順が変わり、利用者側が壊れます。仕様上は「順序は保証しない」のに、です。

### 例2: エラーメッセージの文字列

```javascript
try {
  api.createUser(data);
} catch (e) {
  if (e.message.includes('already exists')) { // メッセージ文言に依存
    // ...
  }
}
```

API 提供側が「エラーメッセージを分かりやすく直した」だけで、利用者の分岐が動かなくなります。

### 例3: 他にもよく依存されるもの

- レスポンスの **処理時間**（タイムアウト値を合わせている）
- JSON の **キーの順序**、**余分なフィールド** の有無
- ハッシュマップの **反復順序**
- 乱数の **シード値による結果**

---

## どう付き合うか

### 提供する側

- **見せるものを減らす**: 公開する情報・型・フィールドを最小限にする（情報隠蔽）。見えないものには依存できない
- **保証しない挙動は、あえて揺らす**: たとえば Go の `map` は反復順序を意図的にランダムにしており、順序への依存がそもそも生まれないようにしている
- **エラーは文字列ではなくコードで返す**: 利用者が依存してよいのは機械的なコードだけ、と明示する
- **変更前に利用状況を調べる**: 利用者が多い API では、「仕様の範囲内の変更」でも影響調査とバージョニングが必要 → [[02_後方互換性]]・[[01_バージョニング]]

### 使う側

- **ドキュメントに書いてあることだけに依存する**
- 「たまたまそう動いている」ものを使うなら、**その前提をテストに書いておく**（壊れたときにすぐ気づける）

---

## よくある誤解

| 誤解 | 実際 |
|---|---|
| 「仕様に書いていないから変えても問題ない」 | 契約上は正しいが、**現実には壊れる人がいる**。利用者が多いほど確実に |
| 「依存する側が悪いだけ」 | 責任論としてはそうでも、壊れたシステムは直さなければならない。提供側も **依存されにくい設計** で備えるべき |
| 「大企業だけの話」 | 社内の共通モジュールでも、利用箇所が増えれば同じことが起きる |

---

## まとめ

- **使う人が多ければ、観測できる挙動はすべて誰かに依存される**
- 「仕様の範囲内の変更」でも壊れることがある
- 提供側は **見せるものを減らし、保証しないものは揺らす**
- 利用側は **仕様に書いてあることだけに依存する**
