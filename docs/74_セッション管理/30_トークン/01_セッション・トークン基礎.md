## セッションとは

### 簡単に言うと

**セッション**は、ユーザーがログインしてからログアウトするまでの「会話の続き」を管理する仕組みです。

### 具体例で理解する

レストランで食事をする場面を想像してください：

1. **入店**（ログイン）
   - 店員があなたを認識して、テーブルに案内します
   - これが「セッション開始」です

2. **食事中**（ログイン状態）
   - 店員はあなたがどのテーブルにいるか覚えています
   - 注文を取ったり、料理を運んだりします
   - これが「セッション継続中」です

3. **退店**（ログアウト）
   - 会計を済ませて店を出ます
   - これが「セッション終了」です

### 技術的な説明

- サーバー側でセッションIDを管理し、ユーザーの状態を保持します
- クライアント（ブラウザ）にはセッションIDが保存されます（通常はCookie）
- サーバーはセッションIDを見て、どのユーザーかを識別します

### セッションの特徴

- ✅ **サーバー側で状態を管理**するため、セキュア
- ✅ サーバー側で**セッションを無効化**できる
- ❌ サーバーに**メモリやストレージが必要**
- ❌ **スケーラビリティ**に課題がある場合がある

## トークンとは

### 簡単に言うと

**トークン**は、ユーザーの認証情報を表す「証明書」のようなものです。紙のチケットやクーポン券をイメージすると分かりやすいです。

### 具体例で理解する

遊園地の入場チケットを想像してください：

1. **チケット購入**（ログイン）
   - 入場チケットを受け取ります
   - これが「トークン発行」です

2. **アトラクション利用**（API呼び出し）
   - チケットを見せてアトラクションに乗ります
   - 係員はチケットを見て、あなたが入場権を持っていることを確認します
   - これが「トークン検証」です

3. **チケット期限切れ**（トークン期限切れ）
   - チケットに有効期限があり、期限が切れると使えなくなります
   - 新しいチケットが必要になります

### 技術的な説明

- トークンは**文字列**で、ユーザー情報や権限情報が含まれています
- 通常は**JWT（JSON Web Token）**という形式が使われます
- トークンには**署名**が含まれており、改ざんを防げます

### トークンの特徴

- ✅ **サーバー側で状態を保持しない**（ステートレス）
- ✅ **スケーラビリティ**が高い
- ✅ 複数のサービス間で**共有**しやすい
- ❌ トークンが漏洩すると**悪用されるリスク**がある
- ❌ 一度発行すると、**期限まで無効化しにくい**

## アクセストークン

### 簡単に言うと

**アクセストークン**は、APIやリソースにアクセスするための「通行証」です。

### 具体例で理解する

会社の入館証を想像してください：

- 入館証を持っていれば、オフィスに入れます
- 会議室や特定のフロアに入る権限も入館証に含まれています
- 有効期限があり、期限が切れると使えなくなります

### 技術的な説明

- **用途**: APIリクエストの認証に使用
- **有効期限**: 通常は**短い**（15分〜1時間程度）
- **含まれる情報**: ユーザーID、権限（スコープ）、有効期限など
- **保存場所**: クライアント側（メモリ、ローカルストレージなど）

### アクセストークンの特徴

- ✅ **短い有効期限**でセキュリティが高い
- ✅ 漏洩しても**被害を最小限**に抑えられる
- ❌ 頻繁に**更新が必要**

### 使用例

```javascript
// APIリクエスト時にアクセストークンを使用
fetch('https://api.example.com/user/profile', {
  headers: {
    'Authorization': 'Bearer ' + accessToken
  }
})
```

## リフレッシュトークン

### 簡単に言うと

**リフレッシュトークン**は、アクセストークンの期限が切れたときに、新しいアクセストークンを取得するための「交換券」です。

### 具体例で理解する

図書館の貸出カードを想像してください：

1. **初回ログイン**
   - 図書館で貸出カード（リフレッシュトークン）を受け取ります
   - このカードは長期間有効です

2. **本を借りる**（APIアクセス）
   - 貸出カードを見せて、本を借ります
   - このとき、一時的な利用券（アクセストークン）を受け取ります

3. **利用券の期限切れ**
   - 利用券の期限が切れました
   - 貸出カードを見せて、新しい利用券（新しいアクセストークン）を受け取ります

4. **貸出カードの期限切れ**
   - 貸出カードも期限が切れました
   - もう一度図書館に行って、新しい貸出カード（再ログイン）が必要です

### 技術的な説明

- **用途**: 新しいアクセストークンを取得するために使用
- **有効期限**: 通常は**長い**（数日〜数週間、場合によっては数ヶ月）
- **含まれる情報**: ユーザーID、トークンIDなど
- **保存場所**: クライアント側の**安全な場所**（HttpOnly Cookie推奨）

### リフレッシュトークンの特徴

- ✅ **長い有効期限**で、ユーザーは頻繁にログインしなくて良い
- ✅ 漏洩した場合、**無効化**できる
- ❌ 漏洩すると**大きなリスク**（長期間有効なため）
- ❌ **安全に保存**する必要がある

### 使用例

```javascript
// アクセストークンが期限切れの場合
if (isAccessTokenExpired()) {
  // リフレッシュトークンを使って新しいアクセストークンを取得
  const newAccessToken = await refreshAccessToken(refreshToken);
  // 新しいアクセストークンでAPIリクエストを再試行
}
```

## IDトークン

### 簡単に言うと

**IDトークン**は、ユーザーが「誰であるか」を証明する「身分証明書」です。

### 具体例で理解する

運転免許証を想像してください：

- 運転免許証には、あなたの名前、生年月日、住所などが書かれています
- これを見れば、あなたが誰であるかが分かります
- ただし、運転免許証だけでは車を運転できるわけではありません（アクセストークンが必要）

### 技術的な説明

- **用途**: ユーザーの**身元確認**に使用
- **有効期限**: 通常は**短い**（アクセストークンと同程度）
- **含まれる情報**: ユーザーID、名前、メールアドレス、認証時刻など
- **使用場面**: OAuth2.0やOpenID Connectで使用

### IDトークンの特徴

- ✅ ユーザーの**身元情報**を含む
- ✅ **署名**されているため、改ざんを検出できる
- ✅ 複数のサービス間で**ユーザー情報を共有**しやすい
- ❌ アクセストークンとは**別物**なので混同しやすい

### 使用例

```javascript
// IDトークンからユーザー情報を取得
const userInfo = decodeIdToken(idToken);
console.log(userInfo.name);      // ユーザー名
console.log(userInfo.email);     // メールアドレス
console.log(userInfo.sub);       // ユーザーID
```

## 3つのトークンの関係

### 全体像

```
┌─────────────────────────────────────────┐
│           ユーザーがログイン             │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  3つのトークンが発行される               │
│  - アクセストークン（短期限）            │
│  - リフレッシュトークン（長期限）        │
│  - IDトークン（短期限）                  │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  アクセストークンでAPIにアクセス         │
│  （IDトークンでユーザー情報を取得）      │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  アクセストークンの期限が切れる          │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  リフレッシュトークンで                 │
│  新しいアクセストークンを取得            │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  リフレッシュトークンの期限が切れる      │
│  → 再ログインが必要                      │
└─────────────────────────────────────────┘
```

### 比較表

| 項目 | アクセストークン | リフレッシュトークン | IDトークン |
|------|-----------------|---------------------|-----------|
| **用途** | APIアクセス | アクセストークン更新 | ユーザー識別 |
| **有効期限** | 短い（15分〜1時間） | 長い（数日〜数週間） | 短い（15分〜1時間） |
| **含まれる情報** | ユーザーID、権限 | ユーザーID、トークンID | ユーザー情報 |
| **使用頻度** | 高い（毎回のAPI呼び出し） | 低い（期限切れ時のみ） | 中（ログイン時、ユーザー情報取得時） |
| **保存場所** | メモリ、ローカルストレージ | HttpOnly Cookie推奨 | メモリ、ローカルストレージ |

## 実際の使用例

### ログインフロー

```javascript
// 1. ユーザーがログイン
async function login(username, password) {
  const response = await fetch('/api/auth/login', {
    method: 'POST',
    body: JSON.stringify({ username, password })
  });
  
  const data = await response.json();
  
  // 3つのトークンを受け取る
  const accessToken = data.accessToken;    // アクセストークン
  const refreshToken = data.refreshToken;  // リフレッシュトークン
  const idToken = data.idToken;            // IDトークン
  
  // 安全に保存
  localStorage.setItem('accessToken', accessToken);
  // リフレッシュトークンはHttpOnly Cookieに保存（サーバー側で設定）
  
  return { accessToken, refreshToken, idToken };
}
```

### APIアクセス

```javascript
// 2. アクセストークンを使ってAPIにアクセス
async function getUserProfile() {
  const accessToken = localStorage.getItem('accessToken');
  
  const response = await fetch('/api/user/profile', {
    headers: {
      'Authorization': `Bearer ${accessToken}`
    }
  });
  
  if (response.status === 401) {
    // アクセストークンが期限切れ
    await refreshTokens();
    // 再試行
    return getUserProfile();
  }
  
  return await response.json();
}
```

### トークンリフレッシュ

```javascript
// 3. リフレッシュトークンで新しいアクセストークンを取得
async function refreshTokens() {
  const response = await fetch('/api/auth/refresh', {
    method: 'POST',
    credentials: 'include' // Cookieにリフレッシュトークンが含まれる
  });
  
  const data = await response.json();
  
  // 新しいアクセストークンを保存
  localStorage.setItem('accessToken', data.accessToken);
  
  return data.accessToken;
}
```

### ユーザー情報の取得

```javascript
// 4. IDトークンからユーザー情報を取得
function getUserInfo(idToken) {
  // JWTをデコード（実際の実装ではライブラリを使用）
  const payload = JSON.parse(atob(idToken.split('.')[1]));
  
  return {
    userId: payload.sub,
    name: payload.name,
    email: payload.email
  };
}
```

## まとめ

### 覚えておくべきポイント

1. **セッション**: サーバー側で状態を管理する仕組み
2. **アクセストークン**: APIにアクセスするための通行証（短期限）
3. **リフレッシュトークン**: アクセストークンを更新するための交換券（長期限）
4. **IDトークン**: ユーザーが誰であるかを証明する身分証明書

### セキュリティのベストプラクティス

- ✅ アクセストークンは**短い有効期限**にする
- ✅ リフレッシュトークンは**HttpOnly Cookie**に保存する
- ✅ トークンは**HTTPS**で送信する
- ✅ トークンが漏洩した場合は**即座に無効化**する
- ✅ **定期的にログアウト**してトークンを無効化する

### よくある質問

**Q: アクセストークンとIDトークンの違いは？**
A: アクセストークンは「APIにアクセスする権利」、IDトークンは「ユーザーが誰であるか」を示します。

**Q: リフレッシュトークンはなぜ必要？**
A: アクセストークンの有効期限を短くしてセキュリティを高めつつ、ユーザーに頻繁なログインを強制しないためです。

**Q: セッションとトークンの違いは？**
A: セッションはサーバー側で状態を管理しますが、トークンはステートレスでサーバー側に状態を保持しません。
