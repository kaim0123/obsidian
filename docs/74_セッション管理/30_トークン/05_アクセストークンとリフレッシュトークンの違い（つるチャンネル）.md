アクセストークンとリフレッシュトークン。名前は聞くけれど、なぜわざわざ2種類に分けるのでしょうか？長い期限のアクセストークンだけで済ませると、盗まれたときの危険が長く続きます。かといって期限を短くすると、切れるたびにログインが必要になります。その両方を成り立たせるのが「リフレッシュトークン」です。この動画では、・...

## 詳しい要約

**テーマ：トークンをアクセス用とリフレッシュ用の 2 種類に分ける理由**

ログイン後のトークンは 1 種類でも動くが、期限を長くすると盗まれたときの危険が長く続き、短くすると頻繁に再ログインが必要になる。この両立のためにアクセストークンとリフレッシュトークンに分ける、という解説（ショート動画）。

---

### アクセストークンだけの問題

- ログイン時にサーバーが発行し、アプリは **API を呼ぶたびに送る**。サーバーはそれで許可されたアクセスか確認する
- 期限を長くすると、**盗まれてもサーバーからは正しいトークン** に見え、期限切れまで使われ続ける恐れ
- 期限を短くすると被害時間は減るが、**切れるたびにログインが必要** で不便

### 2 種類に分ける仕組み

- ログイン時に **アクセストークン** と **リフレッシュトークン** の 2 つを受け取る
- 普段の API アクセスにはアクセストークンだけを使う
- 期限が切れたら、リフレッシュトークンを **トークン更新の窓口** に送る → サーバーが検証して問題なければ新しいアクセストークンを発行 → **ログインし直さずに** 利用を続けられる

### リフレッシュトークンが盗まれたら？

- 盗まれると新しいアクセストークンを発行される恐れがあるので、**厳重に扱う**
- 普段の API には送らず、**更新するときだけ** 使う
- 一度使ったリフレッシュトークンを無効にして新しいものに交換する仕組み（ローテーション）もある

### まとめ

- アクセストークンは **短命** にして漏れたときの被害を抑える
- リフレッシュトークンは **使う場所を限定** しながらログイン状態を続ける
- この役割分担が 2 種類に分ける理由
