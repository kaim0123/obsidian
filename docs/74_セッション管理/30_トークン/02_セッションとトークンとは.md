# セッションとトークンとは

セッションとトークンは、Webアプリケーションでユーザーの認証状態を管理するための重要な仕組みです。この章では、これらの概念と使い分けについて初心者向けに詳しく解説します。

## 📖 セッションとトークンとは何か

**セッション（Session）**は、サーバー側で管理される一時的なデータです。  
**トークン（Token）**は、認証情報を含む文字列で、クライアント側で管理されます。

### 日常生活での例え

- **セッション**: レストランの「テーブル番号」のようなもの
  - サーバーが「テーブル5番」と記録
  - お客様は「テーブル5番」という番号だけを受け取る
  - 実際の情報（注文内容など）はサーバー側に保存される

- **トークン**: 「会員証」のようなもの
  - 会員証には名前や会員番号が書かれている
  - 会員証を見れば、誰であるかが分かる
  - 会員証自体に情報が含まれている

## 🔐 セッション（Session）

### セッションとは

セッションは、サーバー側で管理される一時的なデータです。ユーザーがログインすると、サーバーはセッションIDを生成し、そのIDとユーザー情報をサーバー側に保存します。

### セッションの仕組み

```
1. ユーザーがログイン
   ↓
2. サーバーがセッションIDを生成（例: "abc123"）
   ↓
3. サーバー側に保存: { "abc123": { userId: 1, username: "yamada" } }
   ↓
4. セッションIDをクッキーでクライアントに送信
   ↓
5. 次回のリクエストでセッションIDを送信
   ↓
6. サーバーがセッションIDからユーザー情報を取得
```

### セッションの特徴

- **サーバー側で管理**: データはサーバーに保存される
- **セッションIDで識別**: クライアントにはIDだけが送られる
- **セキュリティが高い**: 機密情報がクライアントに送られない
- **サーバーのリソースを使用**: メモリやデータベースに保存

### セッションの実装例

```javascript
const express = require('express');
const session = require('express-session');
const app = express();

// セッションの設定
app.use(session({
  secret: 'your-secret-key', // セッションIDの署名に使用
  resave: false, // セッションが変更されていなくても再保存しない
  saveUninitialized: false, // 初期化されていないセッションを保存しない
  cookie: {
    secure: true, // HTTPSのみ
    httpOnly: true, // JavaScriptからアクセス不可
    maxAge: 24 * 60 * 60 * 1000, // 24時間
    sameSite: 'strict' // CSRF攻撃対策
  },
  // セッションストア（デフォルトはメモリ、本番環境ではRedisなどを使う）
  store: new MemoryStore()
}));

// ログイン処理
app.post('/api/login', async (req, res) => {
  const { username, password } = req.body;
  
  // 認証処理
  const user = await authenticateUser(username, password);
  
  if (user) {
    // セッションにユーザー情報を保存
    req.session.userId = user.id;
    req.session.username = user.username;
    req.session.email = user.email;
    
    res.json({ message: 'ログイン成功' });
  } else {
    res.status(401).json({ error: '認証に失敗しました' });
  }
});

// 認証が必要なエンドポイント
app.get('/api/profile', (req, res) => {
  // セッションからユーザー情報を取得
  if (!req.session.userId) {
    return res.status(401).json({ error: 'ログインが必要です' });
  }
  
  res.json({
    userId: req.session.userId,
    username: req.session.username,
    email: req.session.email
  });
});

// ログアウト処理
app.post('/api/logout', (req, res) => {
  req.session.destroy((err) => {
    if (err) {
      return res.status(500).json({ error: 'ログアウトに失敗しました' });
    }
    res.json({ message: 'ログアウトしました' });
  });
});
```

### セッションストア

セッションを保存する場所です。本番環境では、メモリではなくデータベースやRedisを使います。

```javascript
// Redisを使ったセッションストア
const RedisStore = require('connect-redis')(session);
const redis = require('redis');
const client = redis.createClient();

app.use(session({
  store: new RedisStore({ client }),
  secret: 'your-secret-key',
  resave: false,
  saveUninitialized: false,
  cookie: {
    secure: true,
    httpOnly: true,
    maxAge: 24 * 60 * 60 * 1000
  }
}));
```

## 🎫 トークン（Token）

### トークンとは

トークンは、認証情報を含む文字列です。最も一般的なのは**JWT（JSON Web Token）**です。

### JWTトークンの構造

JWTは、3つの部分で構成されます：

```
header.payload.signature
```

#### 1. Header（ヘッダー）

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

#### 2. Payload（ペイロード）

```json
{
  "userId": 1,
  "username": "yamada",
  "email": "yamada@example.com",
  "iat": 1234567890,
  "exp": 1234654290
}
```

#### 3. Signature（署名）

```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```

### トークンの仕組み

```
1. ユーザーがログイン
   ↓
2. サーバーがJWTトークンを生成（ユーザー情報を含む）
   ↓
3. トークンをクライアントに送信
   ↓
4. クライアントがトークンを保存（localStorage、sessionStorageなど）
   ↓
5. 次回のリクエストでトークンを送信
   ↓
6. サーバーがトークンを検証し、ユーザー情報を取得
```

### トークンの実装例

```javascript
const express = require('express');
const jwt = require('jsonwebtoken');
const app = express();

const JWT_SECRET = process.env.JWT_SECRET || 'your-secret-key';

// ログイン処理
app.post('/api/login', async (req, res) => {
  const { username, password } = req.body;
  
  // 認証処理
  const user = await authenticateUser(username, password);
  
  if (user) {
    // JWTトークンを生成
    const token = jwt.sign(
      {
        userId: user.id,
        username: user.username,
        email: user.email
      },
      JWT_SECRET,
      {
        expiresIn: '24h' // 24時間で有効期限切れ
      }
    );
    
    res.json({ token, user: { id: user.id, username: user.username } });
  } else {
    res.status(401).json({ error: '認証に失敗しました' });
  }
});

// トークンを検証するミドルウェア
function authenticateToken(req, res, next) {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1]; // "Bearer TOKEN"
  
  if (!token) {
    return res.status(401).json({ error: 'トークンが必要です' });
  }
  
  jwt.verify(token, JWT_SECRET, (err, user) => {
    if (err) {
      return res.status(403).json({ error: '無効なトークンです' });
    }
    
    req.user = user; // ユーザー情報をリクエストオブジェクトに追加
    next();
  });
}

// 認証が必要なエンドポイント
app.get('/api/profile', authenticateToken, (req, res) => {
  // req.userにユーザー情報が含まれている
  res.json({
    userId: req.user.userId,
    username: req.user.username,
    email: req.user.email
  });
});
```

### クライアント側でのトークン使用

```javascript
// ログイン
async function login(username, password) {
  const response = await fetch('/api/login', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ username, password }),
  });
  
  const { token } = await response.json();
  
  // トークンを保存
  localStorage.setItem('token', token);
  
  return token;
}

// トークンを使ってAPIを呼び出す
async function fetchProfile() {
  const token = localStorage.getItem('token');
  
  const response = await fetch('/api/profile', {
    headers: {
      'Authorization': `Bearer ${token}`,
    },
  });
  
  if (response.status === 401) {
    // トークンが無効な場合、再ログイン
    localStorage.removeItem('token');
    window.location.href = '/login';
    return;
  }
  
  const profile = await response.json();
  return profile;
}
```

## 🔄 セッションとトークンの違い

| 項目 | セッション | トークン（JWT） |
|------|-----------|----------------|
| **保存場所** | サーバー側 | クライアント側 |
| **データの場所** | サーバー側 | トークン内（エンコードされている） |
| **ステートレス** | ステートフル（サーバーに状態を保存） | ステートレス（サーバーに状態を保存しない） |
| **スケーラビリティ** | 低い（サーバー間で共有が必要） | 高い（サーバー間で共有不要） |
| **セキュリティ** | 高い（機密情報がクライアントに送られない） | 中程度（トークンが盗まれるリスク） |
| **ログアウト** | 簡単（サーバー側で削除） | 難しい（トークンを無効化する仕組みが必要） |
| **有効期限の管理** | サーバー側で管理 | トークン内に含まれる |

## 💡 セッションとトークンの使い分け

### セッションが適している場合

1. **従来のWebアプリケーション**
   - サーバーサイドレンダリング（SSR）
   - セッション管理が簡単

2. **セキュリティが最優先**
   - 機密情報を扱う
   - トークンの盗難リスクを避けたい

3. **ログアウトの即時反映が必要**
   - トークンの無効化が不要

### トークンが適している場合

1. **モバイルアプリ**
   - クライアント側で管理しやすい

2. **マイクロサービスアーキテクチャ**
   - 複数のサーバー間で認証情報を共有
   - ステートレスな設計

3. **SPA（Single Page Application）**
   - クライアント側で状態管理
   - API中心の設計

4. **スケーラビリティが重要**
   - サーバー間でセッションを共有する必要がない

## 🔐 トークンの種類

### 1. アクセストークン（Access Token）

リソースにアクセスするために使用するトークン。有効期限が短い。

```javascript
// アクセストークンの生成
const accessToken = jwt.sign(
  { userId: user.id },
  JWT_SECRET,
  { expiresIn: '15m' } // 15分で有効期限切れ
);
```

### 2. リフレッシュトークン（Refresh Token）

アクセストークンを更新するために使用するトークン。有効期限が長い。

```javascript
// リフレッシュトークンの生成
const refreshToken = jwt.sign(
  { userId: user.id, type: 'refresh' },
  JWT_SECRET,
  { expiresIn: '7d' } // 7日間で有効期限切れ
);

// アクセストークンの更新
app.post('/api/refresh', (req, res) => {
  const { refreshToken } = req.body;
  
  jwt.verify(refreshToken, JWT_SECRET, (err, decoded) => {
    if (err || decoded.type !== 'refresh') {
      return res.status(403).json({ error: '無効なリフレッシュトークンです' });
    }
    
    // 新しいアクセストークンを発行
    const newAccessToken = jwt.sign(
      { userId: decoded.userId },
      JWT_SECRET,
      { expiresIn: '15m' }
    );
    
    res.json({ accessToken: newAccessToken });
  });
});
```

## 💻 実践例：完全な実装

### セッションを使った実装

```javascript
const express = require('express');
const session = require('express-session');
const RedisStore = require('connect-redis')(session);
const redis = require('redis');
const app = express();

const client = redis.createClient();

app.use(express.json());
app.use(session({
  store: new RedisStore({ client }),
  secret: process.env.SESSION_SECRET,
  resave: false,
  saveUninitialized: false,
  cookie: {
    secure: process.env.NODE_ENV === 'production',
    httpOnly: true,
    maxAge: 24 * 60 * 60 * 1000,
    sameSite: 'strict'
  }
}));

// ログイン
app.post('/api/login', async (req, res) => {
  const { username, password } = req.body;
  const user = await authenticateUser(username, password);
  
  if (user) {
    req.session.userId = user.id;
    req.session.username = user.username;
    res.json({ message: 'ログイン成功' });
  } else {
    res.status(401).json({ error: '認証に失敗しました' });
  }
});

// 認証ミドルウェア
function requireAuth(req, res, next) {
  if (!req.session.userId) {
    return res.status(401).json({ error: 'ログインが必要です' });
  }
  next();
}

// プロフィール取得
app.get('/api/profile', requireAuth, async (req, res) => {
  const user = await getUserById(req.session.userId);
  res.json(user);

app.post('/api/logout', (req, res) => {

```

### トークンを使った実装

```javascript
const express = require('express');
const jwt = require('jsonwebtoken');
const app = express();

const JWT_SECRET = process.env.JWT_SECRET;
const JWT_REFRESH_SECRET = process.env.JWT_REFRESH_SECRET;

app.use(express.json());

// ログイン
app.post('/api/login', async (req, res) => {
  const { username, password } = req.body;
  const user = await authenticateUser(username, password);
  
  if (user) {
    // アクセストークンとリフレッシュトークンを生成
    const accessToken = jwt.sign(
      { userId: user.id, username: user.username },
      JWT_SECRET,
      { expiresIn: '15m' }
    );
    
    const refreshToken = jwt.sign(
      { userId: user.id, type: 'refresh' },
      JWT_REFRESH_SECRET,
      { expiresIn: '7d' }
    );
    
    // リフレッシュトークンはデータベースに保存（ログアウト時に無効化するため）
    await saveRefreshToken(user.id, refreshToken);
    
    res.json({
      accessToken,
      refreshToken,
      user: { id: user.id, username: user.username }
    });
  } else {
    res.status(401).json({ error: '認証に失敗しました' });
  }
});

// トークン検証ミドルウェア
function authenticateToken(req, res, next) {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1];
  
  if (!token) {
    return res.status(401).json({ error: 'トークンが必要です' });
  }
  
  jwt.verify(token, JWT_SECRET, (err, user) => {
    if (err) {
      return res.status(403).json({ error: '無効なトークンです' });
    }
    req.user = user;
    next();
  });
}

// プロフィール取得
app.get('/api/profile', authenticateToken, async (req, res) => {
  const user = await getUserById(req.user.userId);
  res.json(user);
});

// アクセストークンの更新
app.post('/api/refresh', async (req, res) => {
  const { refreshToken } = req.body;
  
  if (!refreshToken) {
    return res.status(401).json({ error: 'リフレッシュトークンが必要です' });
  }
  
  // データベースでリフレッシュトークンを検証
  const isValid = await validateRefreshToken(refreshToken);
  if (!isValid) {
    return res.status(403).json({ error: '無効なリフレッシュトークンです' });
  }
  
  jwt.verify(refreshToken, JWT_REFRESH_SECRET, (err, decoded) => {
    if (err) {
      return res.status(403).json({ error: '無効なリフレッシュトークンです' });
    }
    
    // 新しいアクセストークンを発行
    const newAccessToken = jwt.sign(
      { userId: decoded.userId, username: decoded.username },
      JWT_SECRET,
      { expiresIn: '15m' }
    );
    
    res.json({ accessToken: newAccessToken });
  });
});

// ログアウト
app.post('/api/logout', async (req, res) => {
  const { refreshToken } = req.body;
  
  // リフレッシュトークンを無効化
  await invalidateRefreshToken(refreshToken);
  
  res.json({ message: 'ログアウトしました' });
});
```

## ⚠️ セキュリティの注意点

### セッションのセキュリティ

```javascript
// ✅ 推奨設定
app.use(session({
  secret: process.env.SESSION_SECRET, // 環境変数から取得
  cookie: {
    secure: true, // HTTPSのみ
    httpOnly: true, // JavaScriptからアクセス不可
    sameSite: 'strict' // CSRF攻撃対策
  },
  // 本番環境ではRedisなどの外部ストアを使用
  store: new RedisStore({ client })
}));
```

### トークンのセキュリティ

```javascript
// ✅ 推奨設定
const token = jwt.sign(
  payload,
  process.env.JWT_SECRET, // 強力なシークレットキー
  {
    expiresIn: '15m', // 短い有効期限
    issuer: 'myapp.com', // 発行者
    audience: 'myapp.com' // 受信者
  }
);

// トークンの検証
jwt.verify(token, process.env.JWT_SECRET, {
  issuer: 'myapp.com',
  audience: 'myapp.com'
}, (err, decoded) => {
  // 検証処理
});
```

### トークンの保存方法

```javascript
// ❌ 間違い（localStorageはXSS攻撃のリスク）
localStorage.setItem('token', token);

// ✅ 推奨（httpOnlyクッキーに保存）
res.cookie('token', token, {
  httpOnly: true,
  secure: true,
  sameSite: 'strict'
});

// または、メモリに保存（ページを閉じると消える）
let token = null; // グローバル変数に保存
```

## 🔄 ハイブリッドアプローチ

セッションとトークンを組み合わせることもできます。

```javascript
// セッションにトークンを保存
app.post('/api/login', async (req, res) => {
  const user = await authenticateUser(username, password);
  
  if (user) {
    // JWTトークンを生成
    const token = jwt.sign(
      { userId: user.id },
      JWT_SECRET,
      { expiresIn: '24h' }
    );
    
    // セッションにトークンを保存
    req.session.token = token;
    req.session.userId = user.id;
    
    res.json({ message: 'ログイン成功' });
  }
});

// トークンとセッションの両方を検証
function authenticate(req, res, next) {
  // セッションを確認
  if (!req.session.userId) {
    return res.status(401).json({ error: 'ログインが必要です' });
  }
  
  // トークンを検証
  const token = req.session.token;
  jwt.verify(token, JWT_SECRET, (err, decoded) => {
    if (err) {
      return res.status(403).json({ error: '無効なトークンです' });
    }
    req.user = decoded;
    next();
  });
}
```

## 🎯 まとめ

### セッション

- **サーバー側で管理**される認証状態
- **セキュリティが高い**（機密情報がクライアントに送られない）
- **ログアウトが簡単**（サーバー側で削除）
- **スケーラビリティが低い**（サーバー間で共有が必要）

### トークン（JWT）

- **クライアント側で管理**される認証情報
- **ステートレス**（サーバーに状態を保存しない）
- **スケーラビリティが高い**（サーバー間で共有不要）
- **ログアウトが難しい**（トークンの無効化が必要）

### 使い分け

- **セッション**: 従来のWebアプリ、セキュリティ最優先
- **トークン**: モバイルアプリ、マイクロサービス、SPA
