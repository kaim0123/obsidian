Cookieとは何か、ログイン状態が保たれる仕組みを図解で解説します。HTTPは、前の通信を覚えていません。それなのに、Webサイトでは一度ログインすると、別のページを開いてもログイン状態が保たれます。なぜでしょうか？この動画では、Cookieを使ってユーザーを識別する基本的な仕組みを、ログインを例に解説します。...

## 詳しい要約

**テーマ：Cookie がログイン状態を保てる仕組み**

HTTP はリクエストごとに独立していて前の通信を覚えていない（ステートレス）。その問題を解決する仕組みの 1 つが Cookie で、「値を運ぶのが Cookie、意味を決めて覚えているのはサーバー」というのが結論。

---

### HTTP はステートレス

- ログインに成功しても、次に「マイページを見せて」と頼むとサーバーは相手が誰か分からない。
- HTTP は**リクエストごとに独立**しており、前の通信を覚えていない。これを**ステートレス**という。

### セッション ID を Cookie で運ぶ流れ

1. ログイン成功時、サーバーはレスポンスヘッダーの **`Set-Cookie`** でセッション ID（例: `ABC123`）を返す。
2. ブラウザはその値を**サイトごとに分けて保存**する。
3. 次にそのサイトへリクエストするとき、**`Cookie` ヘッダー**に入れて自動で送る。
4. サーバーは `ABC123` を「鶴田さんのログイン済みセッション」として覚えているので、本人だと分かる。

- Cookie 自体が判断しているわけではない。**Cookie は値を運ぶだけで、意味を決めるのはサーバー**。
- Cookie はログイン専用ではなく、ユーザー設定・カート・アクセス解析などにも使われる。

### セキュリティ上の属性

- **HttpOnly**：JavaScript から読み取れないようにする。
- **Secure**：HTTPS のときだけ送る。
- **SameSite**：別サイトからのリクエストで Cookie を送る条件を制御する。

### まとめ

- HTTP は覚えていない → Cookie を保存して次の通信で送る → サーバーが識別する。
- 覚えているのはサーバー、運んでいるのが Cookie。
- 扱いを誤るとセキュリティ問題になるため、HttpOnly・Secure・SameSite を適切に使う。
