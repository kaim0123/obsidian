# クッキーとログイン

[[旧トピック目次|← 目次に戻る]]

---

## 1. クッキーとは
- Webブラウザがサーバーから受け取って保存する小さなデータ（key-value形式）
- サーバーへのリクエスト時に自動で送信される
- 主な用途：セッション管理、認証情報の保持、ユーザー設定の保存、トラッキング

---

## 2. ログイン処理の全体像
- ユーザーがID/パスワードを送信
- サーバー側で認証（DB照合、ハッシュ化パスワードの検証）
- 認証成功時に「セッションID」や「JWT」などを発行
- セッションIDやトークンをクッキーやローカルストレージに保存
- 以降のリクエストでクッキーを使い、認証状態を維持

---

## 3. クッキーとログインの関係
- クッキーは「セッションID」や「認証トークン」を保存するために使われる
- サーバーはクッキーの値でユーザーを識別し、認証済みかどうかを判定
- セッション管理の主な方式：
  - サーバーサイドセッション（セッションIDをクッキーに保存、サーバーで状態管理）
  - JWT認証（トークンをクッキーやヘッダーに保存、サーバーレスな認証）

---

## 4. セキュリティとベストプラクティス
- HttpOnly属性：JavaScriptからアクセス不可にし、XSS対策
- Secure属性：HTTPS通信時のみ送信
- SameSite属性：CSRF対策（Strict/Lax/None）
- 有効期限（Expires/Max-Age）やドメイン/パスの制限
- セッション固定攻撃・ハイジャック対策

---

## 5. 実装例
### サーバーサイド（Node.js/Express）
```js
// ログイン時
res.cookie('session_id', sessionId, { httpOnly: true, secure: true, sameSite: 'lax' });
```
### クライアントサイド（fetchでクッキー送信）
```js
fetch('/api/user', { credentials: 'include' });
```
