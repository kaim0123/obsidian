# クッキーとセッション管理

[[MOC_サーバー・インフラ体系|← サーバー・インフラ目次]]

---

## 1. クッキーとは（サーバー観点）
- WebサーバーがHTTPレスポンスでSet-Cookieヘッダーを返すことで、ブラウザに小さなデータ（key-value形式）を保存させる仕組み
- 次回以降のリクエスト時、ブラウザは自動でCookieを送信
- 主な用途：セッション管理、認証情報の保持、ユーザー設定、トラッキング

---

## 2. セッション管理の仕組み
- **セッション**：クライアントとサーバー間の一時的な状態管理
- サーバーは「セッションID」を発行し、クッキーに保存
- サーバー側でセッション情報（ユーザーID、認証状態など）を管理
- クライアントはセッションID付きクッキーを送信し、サーバーはそれを元に状態を復元

---

## 3. クッキーとログインの関係
- ログイン成功時、サーバーはセッションIDや認証トークン（JWT等）をクッキーにセット
- 以降のリクエストでクッキーを使い、認証状態を維持
- サーバーサイドセッション（状態はサーバー管理）とJWT認証（状態はトークン内に埋め込み）の違い

---

## 4. セキュリティとベストプラクティス
- HttpOnly属性：JavaScriptからアクセス不可（XSS対策）
- Secure属性：HTTPS通信時のみ送信
- SameSite属性：CSRF対策（Strict/Lax/None）
- 有効期限（Expires/Max-Age）、ドメイン/パスの制限
- セッション固定攻撃・ハイジャック対策
- サーバー側でのセッションストア（メモリ、DB、Redis等）

---

## 5. Webサーバー・インフラとの関係
- Nginx/ApacheなどのWebサーバーはリバースプロキシとしてCookieを中継
- HTTPS終端やロードバランサー配下でのセッション維持（Sticky Session、分散セッションストア）
- サーバーレス環境やマイクロサービスでのセッション管理の工夫

---

## 6. 実装例
### Node.js/Expressでのセッション管理
```js
// express-sessionミドルウェア利用例
const session = require('express-session');
app.use(session({
  secret: 'your-secret',
  resave: false,
  saveUninitialized: false,
  cookie: { httpOnly: true, secure: true, sameSite: 'lax' }
}));
```
