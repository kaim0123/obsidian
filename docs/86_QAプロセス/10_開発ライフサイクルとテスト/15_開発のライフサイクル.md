# 開発のライフサイクル

## はじめに

プログラムを開発する時、計画から完成まで、いくつかの段階があります。この一連の流れを**開発のライフサイクル**といいます。

この章では、開発のライフサイクルの基本的な考え方を学びます。

## 開発のライフサイクルとは

**開発のライフサイクル**とは、プログラムを開発する際の一連の流れのことです。

### 基本的な流れ

1. **計画（Planning）**
2. **設計（Design）**
3. **実装（Implementation）**
4. **テスト（Testing）**
5. **デプロイ（Deployment）**
6. **保守（Maintenance）**

## 各段階の詳細

### 1. 計画（Planning）

何を作るかを決めます。

**やること**：
- 要件を整理する（[[14_非機能要件|非機能要件]]も含めて定義）
- 機能をリストアップする
- 優先順位を決める
- スケジュールを立てる

**例**：
```
プロジェクト：家計簿アプリ

要件：
- 収入と支出を記録できる
- 月ごとの集計ができる
- データを保存できる

優先順位：
1. 収入・支出の記録（必須）
2. データの保存（必須）
3. 月ごとの集計（重要）
4. グラフ表示（あれば良い）
```

### 2. 設計（Design）

どのように作るかを決めます。

**やること**：
- データ構造を設計する
- 関数やクラスを設計する
- ユーザーインターフェースを設計する

**例**：
```python
# データ構造の設計
transaction = {
    "date": "2024-01-01",
    "type": "支出",  # または "収入"
    "category": "食費",
    "amount": 1000,
    "memo": "昼食"
}

# 関数の設計
def add_transaction(date, type, category, amount, memo):
    """取引を追加する"""
    pass

def calculate_monthly_total(year, month):
    """月ごとの合計を計算する"""
    pass
```

### 3. 実装（Implementation）

実際にコードを書きます。

**やること**：
- 設計に基づいてコードを書く
- 小さな単位で実装する
- 動作確認しながら進める

**例**：
```python
# まずは基本的な機能から
def add_transaction(date, type, category, amount, memo):
    transaction = {
        "date": date,
        "type": type,
        "category": category,
        "amount": amount,
        "memo": memo
    }
    return transaction

# 動作確認
transaction = add_transaction("2024-01-01", "支出", "食費", 1000, "昼食")
print(transaction)
```

### 4. テスト（Testing）

プログラムが正しく動くかを確認します。

**やること**：
- 単体テストを書く
- 動作を確認する
- バグを見つけて修正する

**例**：
```python
def test_add_transaction():
    transaction = add_transaction("2024-01-01", "支出", "食費", 1000, "昼食")
    assert transaction["amount"] == 1000
    assert transaction["type"] == "支出"

test_add_transaction()
print("テスト成功！")
```

### 5. デプロイ（Deployment）

プログラムを実際に使えるようにします。

**やること**：
- プログラムを実行できる状態にする
- 必要に応じてサーバーに配置する
- ユーザーに提供する

**例**：
- ローカルで実行できるようにする
- クラウドにアップロードする
- アプリストアに公開する

### 6. 保守（Maintenance）

プログラムを継続的に改善します。

**やること**：
- バグを修正する
- 新機能を追加する
- パフォーマンスを改善する
- ドキュメントを更新する

## 開発手法

### 1. ウォーターフォールモデル

各段階を順番に進める方法です。

```
計画 → 設計 → 実装 → テスト → デプロイ → 保守
```

**特徴**：
- 計画が立てやすい
- 後戻りがしにくい
- 変更に対応しにくい

### 2. アジャイル開発

小さな単位で繰り返し開発する方法です。

```
計画 → 設計 → 実装 → テスト
  ↑                              ↓
  └────────── 繰り返し ──────────┘
```

**特徴**：
- 変更に対応しやすい
- 早期に動作するものができる
- 計画が変わりやすい

### 初心者におすすめ

初心者は、**小さな単位で繰り返す**方法がおすすめです。

1. 小さな機能を1つ実装する
2. 動作確認する
3. 次の機能を実装する

## 実践例

### 例：簡単なタスク管理アプリ

#### 1. 計画

```
機能：
- タスクを追加できる
- タスクの一覧を表示できる
- タスクを完了にできる
```

#### 2. 設計

```python
# データ構造
task = {
    "id": 1,
    "title": "買い物",
    "completed": False
}

# 関数
def add_task(title):
    """タスクを追加"""
    pass

def list_tasks():
    """タスクの一覧を表示"""
    pass

def complete_task(task_id):
    """タスクを完了にする"""
    pass
```

#### 3. 実装（段階的に）

**ステップ1：タスクを追加できるようにする**
```python
tasks = []

def add_task(title):
    task = {
        "id": len(tasks) + 1,
        "title": title,
        "completed": False
    }
    tasks.append(task)
    return task

# 動作確認
add_task("買い物")
print(tasks)
```

**ステップ2：一覧を表示できるようにする**
```python
def list_tasks():
    for task in tasks:
        status = "✓" if task["completed"] else " "
        print(f"{status} {task['id']}: {task['title']}")

# 動作確認
list_tasks()
```

**ステップ3：完了にできるようにする**
```python
def complete_task(task_id):
    for task in tasks:
        if task["id"] == task_id:
            task["completed"] = True
            return True
    return False

# 動作確認
complete_task(1)
list_tasks()
```

#### 4. テスト

```python
def test_add_task():
    tasks.clear()
    add_task("テスト")
    assert len(tasks) == 1
    assert tasks[0]["title"] == "テスト"

def test_complete_task():
    tasks.clear()
    add_task("テスト")
    complete_task(1)
    assert tasks[0]["completed"] == True

test_add_task()
test_complete_task()
print("テスト成功！")
```

## 開発のベストプラクティス

### 1. 小さく始める

最初から完璧を目指さず、小さく始めます。

### 2. 動作確認しながら進める

コードを書いたら、すぐに動作確認します。

### 3. バージョン管理を使う

Gitなどのバージョン管理システムを使います。

### 4. ドキュメントを書く

コードの説明や使い方を書きます。

### 5. テストを書く

動作を確認するテストを書きます。

## まとめ

- 開発のライフサイクル：計画 → 設計 → 実装 → テスト → デプロイ → 保守
- 小さな単位で繰り返し開発する
- 動作確認しながら進める
- バージョン管理、ドキュメント、テストを活用する

開発のライフサイクルを理解すると、効率的にプログラムを開発できるようになります。小さく始めて、段階的に機能を追加していきましょう！
