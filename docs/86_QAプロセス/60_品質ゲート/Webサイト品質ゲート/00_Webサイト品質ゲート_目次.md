# 08_QA（QAエンジニアリング：テストと分ける）目次

QAは **テスト技術だけではない**。
「自動テストを書く技術」 = `07_Testing/`、
「品質を担保するプロセス・観点・運用」 = ここ、と住み分ける。

| カテゴリ | 何を書く？ |
|---------|----------|
| **Fundamentals** | 品質特性・欠陥の性質・レビュー観点など **QAの土台** |
| **TestDesign** | 同値分割・境界値・デシジョンテーブル等の **設計技法** |
| **Process** | 不具合管理・リリース判定・メトリクスなど **運用プロセス** |
| **Templates** | テストケース/バグ票/チェックリストの **雛形** |
| **Training** | 教材本体（学ぶ順序・演習） |

---

## 🧩 07_Testing との使い分け

| 観点 | 07_Testing | 08_QA |
|------|-----------|-------|
| 主体 | **開発者** が書くテスト | **QA視点** の品質保証 |
| 中身 | Vitest / Playwright / モック技法 | 観点表 / バグ票 / プロセス |
| 形 | コード中心 | ドキュメント・表・チェックリスト中心 |
| 例 | 「この関数をVitestでテスト」 | 「この機能のリリース判定基準は何か」 |

**両者が混ざりそうな時**:
- 「**どう書くか**」→ 07_Testing
- 「**何を・なぜ・どれだけやるか**」→ 08_QA

## 📝 この領域の運用ルール

### 「テスト設計技法」と「教材」を分ける

- **TestDesign/** → その技法を **使いたいとき** に開く（リファレンス）
- **Training/** → **学びたいとき** に開く（チュートリアル）

同じ「境界値分析」でも、
- TestDesign/境界値/ = 実務用の一次資料
- Training/07_境界値分析.md = 体系的な学習

### 99_QAエンジニア向け教材/ の扱い

段階的に Training/ へ移行する想定。
**移行前は両方にあっても構わない**（リンク切れ防止）。

### JSTQB との関係

- `99_JSTQB_FL/` = 資格試験のシラバスと用語
- `08_QA/` = 実務で使う知識
- 両者のリンクを張り、「資格勉強 → 実務知識」の橋渡しを作る
