## 詳しい要約

**テーマ：Google の秘密兵器 Borg からインフラの共通言語になった Kubernetes の 10 年**

Kubernetes は Google が社内で 10 年磨いた大規模運用のノウハウ（Borg）をオープンソース化したもので、2014 年の公開からわずか 10 年でコンテナ利用組織の 82% が本番運用するインフラ標準になった。手動デプロイとベンダーロックインを終わらせ、今は「AI の OS」になりつつある。

---

### 第 1 章：Google の秘密兵器 Borg

- 2003 年頃、Google は検索の急成長で何千台ものサーバーに何百ものサービスを配置する必要があり、手動管理は限界だった
- そこで社内開発したクラスタ管理システムが **Borg**（名前はスタートレックの集合意識を持つ種族から）。検索・Gmail・YouTube・マップがすべてその上で動き、毎週 20 億以上のコンテナが起動していたとされる
- 画期的だったのは**自己修復**：ジョブが落ちると自動で別マシンで再起動
- Borg は社内システムに強く依存し公開できなかったため、10 年の知見をオープンソースとして出すプロジェクトが始まった。コードネームは **Project Seven**（元 Borg のキャラクター Seven of Nine に由来、ロゴの 7 本の舵輪もここから）
- Kubernetes はギリシャ語で「操舵手」の意味。登場時点で 10 年分の実践経験が詰まっていた

### 第 2 章：Docker が「箱」を作り、Kubernetes が「港」を作った

- **Docker**（2013 年）は段ボール箱：アプリと動作環境を 1 つの箱にまとめ、どこでも同じように動かす（「自分の PC では動くのに」問題＝works on my machine を解決）
- しかし箱が 1 万個に増えると、どのトラックに載せるか、壊れた箱の入れ替え、不足時の追加を人間が管理するのは無理
- **Kubernetes** は港の管理者：コンテナの配置、故障時の自動交換、スケールをすべて自動化
- 真骨頂は**自己修復**と**宣言的管理**（「こうあるべき」という望ましい状態を定義すれば、その状態を維持し続ける）。深夜のアラート対応も大幅に減る

### 第 3 章：数字で見る変化

| 指標 | 数値 |
|---|---|
| コンテナ利用組織の本番運用率（CNCF） | **82%**（2023 年は 66%） |
| 評価した組織の最終採用率 | 96% |
| マネージドサービスの内訳 | EKS 約 42%、GKE 約 27%、AKS 約 23% |
| マルチクラウドで運用する企業 | 64% |
| 企業あたりの平均クラスタ数 | 6.3 |
| 生成 AI モデルをホストする組織で推論管理に使う割合 | 66% |

- 開発者は世界で 560 万人以上、Fortune 100 企業の 77% が本番運用
- どのクラウドでも動くため、AWS ⇔ Google Cloud の移行もしやすく**ベンダーロックイン**を避けられる

### 第 4 章：Kubernetes が「殺した」もの

- **手動デプロイ**：SSH で入ってファイルを置き、設定を変えて再起動する作業を、YAML ファイルを書いて適用するだけに変えた
- **ベンダーロックインの常識**：3 大クラウドは「逃げられないようにする」のではなく「うちのマネージド Kubernetes が一番便利」で競争するようになり、競争が健全化
- **コンテナオーケストレーション戦争**に勝利：2015 年頃は Docker Swarm や Apache Mesos が競合していたが、2017 年に AWS と Azure がネイティブサポートを発表して事実上決着。シェアは **92%**
- 勝因は Google だけの力ではない：2015 年に Google が Kubernetes を中立の **CNCF** に寄贈し、競合クラウドも安心して参加できた。コントリビューターは 8000 人以上に

### 第 5 章：Kubernetes の「次」

1. **AI ワークロードの基盤**：GPU クラスタ管理、モデルのスケーリング、推論パイプラインの自動化の土台に
2. **プラットフォームエンジニアリング**の台頭：Kubernetes は複雑すぎるため、その上に使いやすい層を作る専門チームが生まれている。例：Spotify は 200 以上のクラスタを運用するが、開発者は **Backstage** 経由で YAML を直接書かない
3. **Kubernetes を意識しない方向**への進化：サーバーレスや CaaS は裏で Kubernetes が動くがユーザーは意識しない。電気のように「見えなくなる」ほど当たり前に

### まとめ

- Kubernetes は Google が 10 年磨いた Borg の知見をオープンソース化したもの
- Docker が梱包を、Kubernetes が大規模運用を解決した
- 最大の変化は思想：**インフラはコードで定義する／障害は起きる前提で自動復旧する／特定ベンダーに依存しない**
- 一社の秘密兵器が世界のインフラの共通言語になり、AI の OS になろうとしている
