## 詳しい要約

**テーマ：Docker の誕生から普及、Docker 社の栄枯盛衰、そして Docker が変えたもの**

Docker は、アプリとその動作に必要なものを「コンテナ」という箱に詰めてどこでも同じように動かす技術。dotCloud の内部ツールとして生まれ、2013 年の 5 分のデモから数年で開発のやり方を根本から変えた。Docker 社自体はビジネスで苦しんだが、技術は空気のように当たり前になり、DevOps・マイクロサービス・Infrastructure as Code の起点になった。

---

### 第1章 「サーバーへの出荷は大変だ」

- 2010 年、パリで **Solomon Hykes** が PaaS の **dotCloud** を創業。開発者がアプリを簡単にクラウドにデプロイできるサービスだった。
- 手元では動くのにサーバーでは動かない「**It works on my machine**」問題を解決するため、アプリと必要なもの全部を 1 つの箱に詰めて箱ごと運ぶ内部ツールを作った。これが Docker の原型。
- 2013 年 3 月、**PyCon** の 5 分のライトニングトークで披露。数日後にオープンソース化され、GitHub のスターは 1 年で 1 万超。
- 本業より内部ツールが注目されたため、社名を Docker に変え、PaaS 事業は売却して Docker に全振りした。
- 名前の由来は港の荷役作業員（docker）。標準化されたコンテナの積み下ろしから着想。
- Docker は「**自分たちの困りごとを解決したら、世界中が同じ困りごとを抱えていた**」製品だった。

### 第2章 Docker が解決した「俺のマシンでは動く」問題

- Docker 以前は OS・ライブラリのバージョン、設定ファイル、環境変数をすべて揃える必要があり、**環境構築に 3 日**かかることも珍しくなかった。
- **仮想マシン**（VMware、VirtualBox）は OS ごと丸ごと抱えるため、数 GB のディスク・数百 MB のメモリを使い、起動に数分かかる（家ごと運ぶイメージ）。
- **コンテナ**は OS のカーネルをホストと共有し、アプリに必要なライブラリと設定だけを詰める（部屋だけ運ぶイメージ）。サイズは数十 MB、起動は数秒。
- **Dockerfile** というテキスト 1 つで環境構築手順をコードとして書け、共有すれば誰でも同じ環境を再現できる。
- **Docker Hub** には世界中の開発者が作ったイメージがあり、コマンド 1 つで数秒後には MySQL が動く。以前は依存確認・リポジトリ追加・インストール・設定・権限付与で何十分もかかっていた。

### 第3章 爆発的普及

| 時期 | 出来事 |
|---|---|
| 2013 年 11 月 | Docker 0.7、すべての Linux ディストリビューションに対応 |
| 2014 年 6 月 9 日 | Docker 1.0 リリース。「コンテナエンジンからプラットフォームへ」 |
| 2014 年 6 月 10 日 | **Google が Kubernetes をオープンソース公開**（社内の Borg で 10 年以上コンテナを運用してきた知見。偶然ではない可能性が高い） |
| 2014 年中 | Docker Hub のダウンロード 1 億回突破。VMware、Microsoft、IBM が提携を発表 |
| 2015 年 | **OCI（Open Container Initiative）** 設立。コンテナの業界標準仕様を策定し、ベンダーロックインを防ぐ |

- 「Docker が箱を標準化し、Kubernetes が箱の管理を標準化した」ことでコンテナ時代の基盤が一気に整った。
- Microsoft が Windows Server での Docker 採用を発表したのは、当時考えられない展開だった。普及は口コミではなく**業界全体が一斉に動いたレベル**。

### 第4章 Docker 社の栄光と苦難

- Docker はオープンソースで誰でも無料。**AWS・Google・Azure** が自社クラウドに組み込んで収益を上げたが、Docker 社は直接収益を得られなかった。
- エンタープライズ製品で収益化を狙ったが、Kubernetes が標準になり独自のオーケストレーション **Docker Swarm は敗北**。
- 2018 年に創業者 Hykes が退社、2019 年に Docker Enterprise を **Mirantis** に売却し、開発者向けツールに集中。
- **Docker Desktop** 中心の戦略が成功し、2022 年には月 3500 万回のエンジンダウンロード、登録開発者 1000 万人。「技術の覇者から開発者体験の覇者へ」と立ち位置を変えて再起。
- Stack Overflow 2025 年調査では使用率が前年比 17 ポイント増で、全技術中最大の伸び。
- 教訓：**技術を作った会社がその技術で勝てるとは限らない**というオープンソースの残酷さ。

### 第5章 Docker が本当に変えたもの

1. **DevOps の実現**：開発と運用の間の環境の壁を消し、開発から本番デプロイまでを一貫して自動化可能に。CI/CD パイプラインの普及は Docker なしに語れない。
2. **マイクロサービスの実用化**：考え方は以前からあったが、各サービスを独立した箱に入れる手段を Docker が提供して初めて現実的になった。
3. **Infrastructure as Code**：Dockerfile で環境をコード定義する発想が、Terraform・Ansible・Kubernetes マニフェストなどインフラ全体をコードで管理する文化につながった。

### まとめ

- Docker は dotCloud の内部ツールから生まれ、5 分のデモで世界に広がった。
- VM と違いカーネルを共有するため軽く速く、Dockerfile と Docker Hub で環境構築を数秒にした。
- Docker 社はビジネスで苦しみつつ開発者体験に舵を切って再起し、技術自体は DevOps・マイクロサービス・IaC の土台になった。
