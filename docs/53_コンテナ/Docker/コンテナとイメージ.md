# コンテナとイメージ

## イメージとコンテナの違い

### イメージ
- アプリケーションの**設計図・テンプレート**
- 読み取り専用
- 複数のコンテナを作成できる
- Docker Hubなどで共有可能

### コンテナ
- イメージから作成された**実行環境**
- 書き込み可能
- 起動・停止・削除が可能
- 各コンテナは独立している

## 関係性の例え

```
イメージ = クラス（設計図）
コンテナ = インスタンス（実体）
```

## イメージのレイヤー構造

Dockerイメージは複数のレイヤーが重なって構成されています。

```
┌─────────────────┐
│  アプリコード    │ ← 最上層
├─────────────────┤
│  依存パッケージ  │
├─────────────────┤
│  ランタイム      │
├─────────────────┤
│  OS基盤         │ ← 最下層
└─────────────────┘
```

### レイヤーのメリット
- 変更のあったレイヤーのみ再ビルド
- 共通レイヤーはキャッシュされる
- ストレージ効率が良い

## ライフサイクル

### イメージの作成
```bash
# Dockerfileからビルド
docker build -t my-image:1.0 .

# または既存イメージを取得
docker pull nginx:latest
```

### コンテナの作成と起動
```bash
# 新規作成して起動
docker run -d --name my-container my-image:1.0

# 既存コンテナの起動
docker start my-container
```

### コンテナの停止と削除
```bash
# 停止
docker stop my-container

# 削除
docker rm my-container
```

### イメージの削除
```bash
docker rmi my-image:1.0
```

## タグとバージョン管理

### タグの命名規則
```bash
docker build -t myapp:1.0 .
docker build -t myapp:1.0-alpine .
docker build -t myapp:latest .
```

### よく使われるタグ
- `latest`: 最新版（デフォルト）
- `1.0`, `2.0`: バージョン番号
- `alpine`: 軽量版
- `dev`, `prod`: 環境別

## コンテナの状態確認

### イメージ一覧
```bash
docker images
```

### コンテナ一覧
```bash
docker ps      # 実行中
docker ps -a   # 全て
```

### 詳細情報の確認
```bash
docker inspect <コンテナID>
docker inspect <イメージID>
```

## ベストプラクティス

1. **イメージは小さく保つ**
   - alpine版を使用
   - 不要なファイルを含めない

2. **タグを明示的に指定**
   - `latest`に依存しない
   - バージョンを明確に

3. **レイヤーを最適化**
   - 変更頻度の低いものを下層に
   - RUNコマンドをまとめる

4. **セキュリティ**
   - 公式イメージを使用
   - 定期的に更新
