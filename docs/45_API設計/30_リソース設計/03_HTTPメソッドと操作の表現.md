# HTTPメソッドと操作の表現

## この章の目的

**GET / POST / PUT / PATCH / DELETE** の役割と、冪等性・安全性を理解する章です。

---

## 1. GET・POST・PUT・PATCH・DELETE の役割

| メソッド | 意味 | 典型用途 |
|----------|------|----------|
| **GET** | 取得 | 一覧・詳細の参照 |
| **POST** | 作成 | 新規リソース作成、非冪等な処理 |
| **PUT** | 置換 | リソース全体の更新（存在しなければ作成も可） |
| **PATCH** | 部分更新 | 一部フィールドだけ変更 |
| **DELETE** | 削除 | リソース削除 |

```text
  GET    /users          … 一覧
  POST   /users          … 新規作成
  GET    /users/123      … 詳細
  PATCH  /users/123      … 名前だけ変更
  DELETE /users/123      … 削除
```

---

## 2. 冪等性と安全性

| 性質 | 意味 | メソッド |
|------|------|----------|
| **安全（Safe）** | サーバー状態を変えない | GET |
| **冪等（Idempotent）** | 同じリクエストを何度送っても結果が同じ | GET, PUT, DELETE（PATCH は △） |
| 非冪等 | 送るたびに新リソースができる等 | POST |

```text
  DELETE /users/123  を 2 回  →  2 回目も「削除済み」で同じ結果（冪等）
  POST   /users      を 2 回  →  ユーザーが 2 人できる（非冪等）
```

決済など POST の二重送信対策は[[03_レート制限と冪等性]]（Idempotency-Key）で扱います。

---

## 3. 作成・取得・更新・削除の典型パターン

| 操作 | リクエスト | 成功レスポンス |
|------|-----------|---------------|
| 一覧取得 | `GET /users` | `200` + 配列（または `data` ラップ） |
| 詳細取得 | `GET /users/{id}` | `200` + オブジェクト |
| 作成 | `POST /users` + JSON ボディ | `201` + `Location` ヘッダ |
| 部分更新 | `PATCH /users/{id}` + 変更フィールド | `200` または `204` |
| 削除 | `DELETE /users/{id}` | `204` |

```http
POST /v1/users HTTP/1.1
Content-Type: application/json

{"name": "田中太郎", "email": "taro@example.com"}

→ 201 Created
  Location: /v1/users/usr_01HXYZ
```

---

## 4. GET に副作用を持たせない理由

**GET は安全** でなければなりません。サーバーの状態を **変えてはいけません**。

| 理由 | 説明 |
|------|------|
| キャッシュ | GET は CDN・ブラウザがキャッシュする |
| Prefetch | ブラウザがリンク先を先読みすることがある |
| ブックマーク・共有 | URL が実行操作になっていると危険 |

```text
  ❌  GET /users/123/delete     … リンクを踏んだだけで削除
  ❌  GET /orders/456/approve   … 承認が意図せず実行される
  ✅  POST /orders/456/approve  … 副作用は POST 等で（[[03_検索と複合操作]]）
```

削除・更新・作成は **POST / PUT / PATCH / DELETE** を使います。

---

## 5. メソッドとステータスコードの組み合わせ

| 操作 | 成功時 | よくある失敗 |
|------|--------|-------------|
| GET 一覧 | `200 OK` | — |
| GET 詳細 | `200 OK` | `404 Not Found` |
| POST 作成 | `201 Created` | `400`, `409`, `422` |
| PUT / PATCH 更新 | `200 OK` または `204` | `404`, `409`, `422` |
| DELETE 削除 | `204 No Content` | `404` |

```text
  POST で作成成功 → 201（200 だけ返す API もあるが 201 がより明確）
  DELETE 成功     → 204（ボディなし）が一般的
```

[[03_ステータスコード]]・[[01_エラー設計]]と合わせて、**成功・失敗の両方** を設計します。
