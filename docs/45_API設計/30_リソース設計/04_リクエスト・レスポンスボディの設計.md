# リクエスト・レスポンスボディの設計

## この章の目的

JSON ボディの **命名・型・ラップ形式** を揃え、クライアントが扱いやすい形にする章です。

---

## 1. JSON を基本とする理由

Web API では **JSON（JavaScript Object Notation）** が事実上の標準です。

| 理由 | 説明 |
|------|------|
| 可読性 | 人間にも読みやすい |
| 言語非依存 | Python, Java, Go, JavaScript など広くサポート |
| ツール | OpenAPI、Postman、各種 SDK と相性が良い |
| 軽量 | XML より compact |

```http
Content-Type: application/json
Accept: application/json
```

特殊なケース（ファイルアップロード等）以外は JSON を前提に設計します。

---

## 2. 成功レスポンスのラップ形式（`data` / `meta`）

一覧 API などでは **`data` と `meta`** でラップすると一貫性が保てます。

```json
{
  "data": [
    { "id": "usr_01", "name": "田中" },
    { "id": "usr_02", "name": "佐藤" }
  ],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 150
  }
}
```

| 形式 | 用途 |
|------|------|
| `{ "data": ... }` | 単一・一覧どちらも同じ構造 |
| `meta` | ページネーション、集計情報 |
| 配列直返し | シンプルだが、メタ情報を付けにくい |

チームで **ラップするかどうか** を決め、全体で統一します（[[04_一貫性]]）。

---

## 3. フィールド命名（`snake_case` と `camelCase` の統一）

| 規則 | 例 | 向いている場面 |
|------|-----|---------------|
| `snake_case` | `created_at`, `user_id` | Python/Ruby API、DB カラムに近い |
| `camelCase` | `createdAt`, `userId` | JavaScript/TypeScript フロント向け |

```json
// snake_case の例
{
  "user_id": "usr_01",
  "created_at": "2026-06-19T10:00:00Z"
}
```

**どちらでもよいが、API 全体で 1 つに固定** することが重要です。  
変換レイヤー（DB は snake、JSON は camel）を挟むチームもあります。

---

## 4. 日時・ID・金額などの型と形式

| 種類 | 推奨形式 | 避けたい例 |
|------|----------|-----------|
| 日時 | ISO 8601 UTC `2026-06-19T10:00:00Z` | `"2026/06/19"`, Unix 秒の混在 |
| ID | 文字列（UUID や `usr_01HXYZ`） | 数値と文字列の混在 |
| 金額 | 整数（最小単位）または decimal 文字列 | 浮動小数点 `19.99`（誤差） |
| 真偽値 | `true` / `false` | `1`/`0`, `"yes"`/`"no"` |
| 列挙 | 文字列定数 `"pending"`, `"shipped"` | マジックナンバー |

```json
{
  "id": "ord_01HXYZ",
  "total_amount": 3000,
  "currency": "JPY",
  "ordered_at": "2026-06-19T10:00:00Z",
  "status": "pending"
}
```

## 5. 作成・更新リクエストの設計（必須・任意・部分更新）

### 作成（POST）

```json
{
  "name": "田中太郎",
  "email": "taro@example.com",
  "nickname": "taro"
}
```

- 必須・任意フィールドをドキュメントで明示
- サーバー生成項目（`id`, `created_at`）は **リクエストに含めない**

### 部分更新（PATCH）

```json
{
  "name": "田中花子"
}
```

- 送ったフィールド **だけ** 更新
- PUT は **全体置換**（送らなかったフィールドは null 扱い等、仕様を明確に）

| メソッド | 意味 | 送る内容 |
|----------|------|----------|
| PUT | 全体置換 | リソースの全フィールド |
| PATCH | 部分更新 | 変更したいフィールドのみ |
