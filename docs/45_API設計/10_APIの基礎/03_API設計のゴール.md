# API設計のゴール

## この章の目的

良い API 設計が目指す状態と、本教材全体の8テーマの地図を示す章です。

---

## 1. 「誰が使っても迷わない窓口」を目指す

> **API設計を一言で言うと、「誰が使っても迷わない窓口」を、長く使える形で決めること。**

良い API は、名前・形式・エラー・権限が揃っていて、ドキュメントを読まなくても「だいたい当たりがつく」状態を目指します。

---

## 2. 使いやすさ・予測可能性・一貫性

| 原則 | 意味 |
|------|------|
| 使いやすさ | クライアント開発者の手間が少ない |
| 予測可能性 | 1 つ学べば他も同じルール |
| 一貫性 | 命名・形式・エラーが全体で統一 |

一貫性は [[04_一貫性]] で詳しく扱います。

---

## 3. 長く使える形（バージョニング・後方互換性）

API は公開すると **クライアントが依存** し始めます。

- **バージョニング** — `/v1/` で変更の世代を分ける
- **後方互換性** — 追加は OK、削除・改名は慎重に

50_互換性と進化で詳しく学びます。

---

## 4. 安全な窓口（認証・認可・HTTPS）

| 要素 | 役割 |
|------|------|
| HTTPS | 通信の暗号化 |
| 認証 | あなたは誰か（401） |
| 認可 | 何ができるか（403） |

60_セキュリティと信頼性で詳しく学びます。

---
