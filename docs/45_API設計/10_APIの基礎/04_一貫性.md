# 一貫性

## この章の目的

**同じ種類の操作は同じルールで表現する** — API 設計の第一歩である一貫性を学ぶ章です。

---

## 1. 一貫性とは何か

**一貫性（Consistency）** とは、API 全体で **命名・形式・エラー・レスポンス構造** などのルールが揃っている状態です。

```text
  一貫性がある API
    GET /users     → { "data": [...] }
    GET /orders    → { "data": [...] }   ← 同じ形

  一貫性がない API
    GET /users     → { "data": [...] }
    GET /orders    → [ {...}, {...} ]    ← 配列を直返し（混乱）
```

[[00_API設計の概要]] の 8 テーマの第 1 項目。他のテーマ（REST・エラーなど）も、一貫性の上に成り立ちます。

---

## 2. 一貫性がないときに起きる問題

| 問題 | 具体例 |
|------|--------|
| 共通処理が書けない | エンドポイントごとにパース方法が違う |
| ドキュメント依存 | 「この API だけ例外」が増える |
| レビュー基準がない | 各自バラバラに設計する |
| SDK・クライアント lib が複雑化 | if 分岐だらけになる |

```text
  一貫性なし
       │
       ├─→ クライアントのバグ増加
       ├─→ 新メンバーの学習コスト増
       └─→ レガシー API の固定化
```

---

## 3. 揃えるべき項目（命名・日時・ID・レスポンス形式・真偽値）

| 項目 | 良い例（統一） | 悪い例（バラバラ） |
|------|----------------|-------------------|
| 命名 | `snake_case` または `camelCase` を全体で固定 | `/getUser` と `/orders/list` が混在 |
| 日時 | ISO 8601（`2026-06-19T10:00:00Z`） | `2026/06/19` と Unix 秒が混在 |
| ID | 文字列 UUID またはプレフィックス付き ID | 数値 ID と UUID が混在 |
| レスポンス | 常に `{ "data": ... }` でラップ | 配列直返しとオブジェクト返しが混在 |
| 真偽値 | `true` / `false` | `1` / `0` や `"yes"` / `"no"` |

```json
{
  "data": {
    "id": "usr_01HXYZ",
    "name": "田中太郎",
    "created_at": "2026-06-19T10:00:00Z",
    "is_active": true
  }
}
```

---

## 4. API 設計ガイドラインを1枚にまとめる

チーム開発では、**1 枚のガイドライン** にルールを書いておくと効果的です。

### ガイドラインに含める項目（例）

| カテゴリ | 決めること |
|----------|-----------|
| URL | 複数形、小文字、ハイフン、ネストの深さ |
| JSON | フィールド命名規則、日時形式、ID 形式 |
| レスポンス | 成功時のラップ形式、エラー形式 |
| ステータス | 401/403/404/422 の使い分け |
| バージョン | `/v1/` 方式など |

```text
  ガイドライン 1 枚
       │
       ├─→ 設計レビューの基準になる
       ├─→ OpenAPI スキーマと整合させやすい
       └─→ 新規エンドポイント追加が速くなる
```

[[03_チームでAPI設計を守る]]でチーム運用の視点も扱います。

---

## 5. 一貫性のチェックリスト

- [ ] フィールド命名（`snake_case` / `camelCase`）が API 全体で統一されているか
- [ ] 日時は ISO 8601 + UTC（またはタイムゾーン明示）か
- [ ] ID の型・形式がリソース間で揃っているか
- [ ] 成功レスポンスの構造（`data` / `meta`）が統一されているか
- [ ] エラーレスポンスの構造（`error.code` など）が統一されているか
- [ ] 真偽値・列挙値の表現が統一されているか
- [ ] 新規 API がガイドラインから外れていないか（レビューで確認）
