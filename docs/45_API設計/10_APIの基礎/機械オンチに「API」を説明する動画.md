## 詳しい要約

**API の正体は「窓口」**。楽天銀行が窓口（API）を用意し、freee が「明細ちょうだい」と決まった形式で依頼すると、内部の仕組みを知らなくても情報が返ってくる。大企業の受付で「営業部の山田部長と 15 時からアポある」と言えば案内してもらえるのと同じで、**利用者側は内部を気にせず、決まった情報を渡せば望む結果が得られる**。

**ユーザーインターフェースのプログラム版**。人間がサイトでログイン → 明細表示するのを、プログラム同士が決まったメッセージのやり取りで自動で行う。LINE のように「定型文を送ると定型文が返る」イメージで、1 日平均 1 万回以上、天気表示・X の埋め込み動画・タクシーアプリの地図など、多くの情報取得が API 経由。

**システム統合と API 連携は別物**。みずほ銀行のように「中身まで統合する」と失敗しやすいが、API 連携は**内部に干渉しない**。楽天銀行と freee はお互いの内部を触らず、窓口で「明細ちょうだい」→「はい」とやり取りするだけ。**素結合**（疎い結合）が API の本質で、責任範囲が分かれるので変更しやすく、開発の心理的安全性も上がる。逆に**密結合**だと一箇所変えると全体を探し回る地獄になる。

**情報隠蔽**（内部を隠すこと）のメリット：外から余計な操作をされない、実装の詳細を理解しなくても使える、**イノベーションを加速する**。API エコノミーの理由は、(1)他サービスと組み合わせやすく組み合わせ爆発が起きる（例：タクシーアプリ ×Google Map API）、(2)開発者も内部を API で区切っておけば気楽に変更・改善できる。

**社会学の「弱い紐帯」との共通点**。マーク・グラノベッターの「弱い紐帯の強み」は、親しい人より「たまに会う人」からの情報で就職することが多いという話。強い紐帯は情報が似通っていて新しさがなく、弱い紐帯からこそ新しい情報が入る。API による素結合も「つながりはあるが中身には踏み込まない」ことで、変更・イノベーションがしやすくなる。人間関係でも「API 的な深い共有」より、**適度に弱くつながっておく**方が新しい動きが生まれやすい。ゆる言語ラジオのサポーターコミュニティも弱い紐帯の例として、結婚や副業などの「イノベーション」が起きている。
