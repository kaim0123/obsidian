# APIの種類と全体像

## この章の目的

API の種類と、Web API が設計階層のどこに位置するかを整理する章です。

---

## 1. ライブラリ API・OS API・Web API の違い

| 種類 | 通信の相手 | 特徴 |
|------|-----------|------|
| ライブラリ API | 同じプロセス内 | 関数呼び出し、型で契約 |
| OS API | OS カーネル | システムコール |
| Web API | ネットワーク越し | HTTP + JSON が主流 |

Web API は **別のマシン・別のチーム** が使うことが多く、**契約の明確さ** が特に重要です。

---

## 2. 内部 API と外部公開 API

| 種類 | 利用者 | 設計の厳しさ |
|------|--------|-------------|
| 内部 API | 自社フロント・自社サービス | 同時デプロイなら緩めも可 |
| 外部公開 API | パートナー・一般開発者 | 後方互換・ドキュメント必須 |

外部公開 API は **変更の影響が読めない** ため、バージョニングとドキュメントが必須になります。

---

## 3. クライアント（ブラウザ・モバイル・サーバー）の視点

API は **サーバー側の都合** だけで決めると使いにくくなります。  
設計するときは、次のクライアントを想像してください。

- **ブラウザ（SPA）** — CORS、トークン管理
- **モバイルアプリ** — 古いバージョンが長期間残る
- **他サーバー** — 安定性、レート制限、冪等性

> API 設計は「サーバーを書く人」と「クライアントを書く人」の **橋渡し** です。

---

## 4. API 設計が設計階層のどこに位置するか

```text
アーキテクチャ → ソフトウェア設計 → モジュール設計
                                        ↓
                                   API設計（本教材）
                                        ↓
                              クラス設計 → メソッド設計
```

API 設計は **プログラムの外側に向けた契約** の層です。[[MOC_モジュール設計体系]] で決めたモジュール境界のうち、外部に公開する部分を具体化します。

---

## 5. 本書で扱う範囲

本教材の中心は **REST ベースの Web API** です。

- HTTP メソッド + リソース URL
- JSON ボディ
- 認証（Bearer Token など）

80_APIスタイルで GraphQL・RPC・Webhook など **他スタイル** も触れますが、まず REST の基本を固めることが先です。
