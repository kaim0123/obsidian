---

## 1. APIドキュメントの重要性
- 利用者・開発者・運用者の共通言語
- 仕様の誤解・バグ・運用トラブルを防ぐ
- APIファースト開発（仕様→実装→テスト）の基盤

---

## 2. ドキュメント作成ツール
- **OpenAPI（Swagger）**：YAML/JSONでAPI仕様を記述。Swagger UI/Redocで可視化
- **API Blueprint**：Markdownライクな記法。Aglio等でHTML化
- **Postman**：API設計・テスト・ドキュメント一体型ツール

---

## 3. テスト自動化
- ユニットテスト（個々のAPI関数のテスト）
- 統合テスト（APIエンドポイント全体のテスト）
- E2Eテスト（システム全体の動作確認）
- モックサーバーで外部依存を排除
- CI/CDパイプラインで自動テスト

---

## 4. ドキュメントの継続的更新
- 実装・仕様変更時は必ずドキュメントも更新
- サンプルリクエスト/レスポンス、エラー例も充実させる
- ドキュメントとテストの自動連携（例：OpenAPIからテストコード生成）

---

APIの品質は「ドキュメントとテストの充実度」で決まります。
