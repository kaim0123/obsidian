## 1. HTTPの基礎

- **HTTP（HyperText Transfer Protocol）**はWebの通信規約（プロトコル）
- クライアント（例：ブラウザ、スマホアプリ）とサーバーが「リクエスト」と「レスポンス」でやりとり
- 主なメソッド：
  - GET（取得）
  - POST（作成）
  - PUT（更新・全置換）
  - PATCH（部分更新）
  - DELETE（削除）
- 主なヘッダー：
  - Content-Type（データ形式）
  - Authorization（認証情報）
  - Accept（受け入れ可能なデータ形式）
- ステータスコード：200, 201, 400, 401, 404, 500など

---

## 2. RESTの設計原則

- **REST（Representational State Transfer）**はWeb API設計の代表的なスタイル
- 「リソース（資源）」をURLで表現し、HTTPメソッドで操作
- **原則**：
  - リソース指向（エンティティを一意なURLで表現）
  - ステートレス（各リクエストは独立して完結）
  - 統一インターフェース（HTTPの標準メソッド・ステータスコードを活用）
  - 階層構造（URLのパスでリソースの階層を表現）
- **RESTful設計のメリット**：
  - シンプルで分かりやすい
  - キャッシュや認証、バージョン管理がしやすい
  - クライアント/サーバーの独立性が高い
- **デメリット**：
  - 複雑な操作や多対多のリレーション表現がやや苦手
  - 過度なREST原則の厳守は現実的でない場合も

---

## 3. REST以外のAPI設計との比較

- **GraphQL**：クライアントが必要なデータだけを柔軟に取得できる。型安全・スキーマ駆動
- **gRPC**：バイナリ通信・高速・多言語対応。マイクロサービス間通信で利用
- RESTは「シンプルなCRUD API」に最適、複雑な要件にはGraphQLやgRPCも検討
