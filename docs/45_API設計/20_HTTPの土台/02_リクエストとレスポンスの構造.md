# リクエストとレスポンスの構造

## この章の目的

HTTP メッセージの **中身** — リクエストライン、ヘッダー、ボディ — を読めるようになる章です。

---

## 1. リクエストライン・メソッド・パス

HTTP リクエストの **1 行目** がリクエストラインです。

```http
GET /v1/users/123 HTTP/1.1
│   │             │
│   │             └─ プロトコルバージョン
│   └─ パス（リソースの場所）
└─ HTTP メソッド（何をしたいか）
```

| 要素 | 例 | 意味 |
|------|-----|------|
| メソッド | `GET` | 取得（[[03_HTTPメソッドと操作の表現]]で詳述） |
| パス | `/v1/users/123` | ユーザー ID 123 |
| バージョン | `HTTP/1.1` | プロトコル |

メソッドとパスの組み合わせが「どの操作を、どのリソースに対して行うか」を表します。

---

## 2. ヘッダーの役割（Content-Type、Accept など）

**ヘッダー** はリクエスト・レスポンスの **メタ情報** です。キーと値のペアで送ります。

```http
GET /v1/users HTTP/1.1
Host: api.example.com
Accept: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

| ヘッダー | 方向 | 役割 |
|----------|------|------|
| `Host` | リクエスト | 接続先サーバー |
| `Content-Type` | 両方 | ボディの形式（例: `application/json`） |
| `Accept` | リクエスト | クライアントが欲しい形式 |
| `Authorization` | リクエスト | 認証情報（[[01_認証]]） |
| `Location` | レスポンス | 作成したリソースの URL（201 など） |

JSON API では `Content-Type: application/json` を POST・PUT・PATCH のリクエストに付けるのが基本です。

---

## 3. ボディと JSON の基本

**ボディ（Body）** は、メッセージの **本文** です。GET には通常ボディがありません。

```http
POST /v1/users HTTP/1.1
Content-Type: application/json

{
  "name": "田中太郎",
  "email": "taro@example.com"
}
```

| 形式 | 用途 | API での位置づけ |
|------|------|-----------------|
| JSON | データのやり取り | **Web API の主流** |
| フォーム | HTML フォーム | 従来型 Web |
| バイナリ | ファイル | アップロード（[[03_検索と複合操作]]） |

JSON は人間にも読みやすく、多くの言語で扱えるため、本教材でも JSON を前提にします。

---

## 4. レスポンスの読み方（ステータス・ヘッダ・ボディ）

レスポンスも **ステータス行 + ヘッダ + ボディ** の構造です。

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /v1/users/usr_01HXYZ

{
  "data": {
    "id": "usr_01HXYZ",
    "name": "田中太郎",
    "email": "taro@example.com"
  }
}
```

| 部分 | 読み方 |
|------|--------|
| `201 Created` | 成功（作成完了）。[[03_ステータスコード]]でコード一覧 |
| ヘッダ | `Location` で新リソースの URL を確認 |
| ボディ | 作成されたリソースの内容 |

クライアントは **まずステータスコード** を見て、成功か失敗かを判断します。

## 5. curl やブラウザ開発者ツールで API を観察する

設計を学ぶうえで、**実際の HTTP を見る** 習慣が大切です。

### curl の例

```bash
# GET — 一覧取得
curl -i https://api.example.com/v1/users

# POST — 作成（JSON ボディ付き）
curl -i -X POST https://api.example.com/v1/users \
  -H "Content-Type: application/json" \
  -d '{"name":"田中太郎","email":"taro@example.com"}'
```

`-i` オプションで **レスポンスヘッダ** も表示されます。

### ブラウザ開発者ツール

1. F12 → **Network（ネットワーク）** タブを開く
2. ページ操作や API 呼び出しを行う
3. リクエストを選び、Headers / Payload / Response を確認

> ドキュメントだけでなく、**生の HTTP** を見ると「設計のずれ」に気づきやすくなります。
