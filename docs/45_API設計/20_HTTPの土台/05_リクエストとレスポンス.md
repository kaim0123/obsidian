## 1. リクエストの構造
- クライアントがサーバーに送る「お願い」
- 主な要素：
  - URL（エンドポイント）
  - HTTPメソッド（GET, POST, PUT, DELETE, ...）
  - ヘッダー（Content-Type, Authorization, Accept など）
  - ボディ（POST/PUT/PATCH時のデータ本体、JSONやFormなど）
- 例：curlコマンド
```bash
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name": "Taro", "email": "taro@example.com"}'
```

---

## 2. レスポンスの構造
- サーバーがクライアントに返す「答え」
- 主な要素：
  - ステータスコード（200, 201, 400, 401, 404, 500 など）
  - ヘッダー（Content-Type, Set-Cookie, ...）
  - ボディ（JSON, HTML, バイナリデータなど）
- 例：JSONレスポンス
```json
{
  "id": 1,
  "name": "Taro",
  "email": "taro@example.com"
}
```

---

## 3. ステータスコードとエラーハンドリング
- 200 OK：成功
- 201 Created：新規作成成功
- 204 No Content：成功だが返すデータなし
- 400 Bad Request：リクエスト不正
- 401 Unauthorized：認証エラー
- 403 Forbidden：権限なし
- 404 Not Found：リソースなし
- 422 Unprocessable Entity：バリデーションエラー
- 500 Internal Server Error：サーバーエラー
- エラー時はエラー内容をJSONで返すのが一般的

---

## 4. 実践Tips
- API設計時は「一貫したレスポンス形式」「適切なエラーコード」「詳細なエラーメッセージ」を意識
- fetchやaxiosなどのクライアントライブラリでのリクエスト例も学ぶと良い
