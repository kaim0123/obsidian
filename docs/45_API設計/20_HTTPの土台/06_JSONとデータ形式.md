## 1. JSONとは
- JavaScript Object Notationの略
- 軽量で人間にも読みやすいテキスト形式
- オブジェクト（連想配列）、配列、数値、文字列、真偽値、null などの型をサポート
- ネスト（入れ子）構造も表現可能
- ほぼ全てのプログラミング言語で扱える

### 例：JSONデータ
```json
{
  "id": 1,
  "name": "Taro",
  "email": "taro@example.com",
  "tags": ["api", "json"],
  "profile": { "age": 20, "city": "Tokyo" }
}
```

---

## 2. 他のデータ形式との比較
- **XML**：階層構造・属性・スキーマ定義が可能。冗長で人間には読みにくい。SOAPなどで利用
- **CSV**：表形式データのやりとりに最適。構造が単純で高速だが、階層構造や型情報は持てない
- **YAML**：設定ファイルやCI/CDで利用。可読性が高いが厳密なパースが必要

---

## 3. バリデーションとスキーマ定義
- JSON Schemaなどでデータ構造・型・必須項目・制約を定義
- APIのリクエスト/レスポンスの品質担保や自動ドキュメント生成に活用
- バリデーションエラー時は422 Unprocessable Entityなどを返す

---

## 4. API設計でのデータ形式選択のポイント
- ほとんどのWeb APIはJSONが主流
- 外部システム連携やレガシーシステムではXML/CSVも利用
- データ量・構造・可読性・パース速度・互換性を考慮して選択
