## 1. GraphQLの特徴
- Facebookが開発したAPIクエリ言語・ランタイム
- クライアントが必要なデータだけを柔軟に取得
- スキーマ駆動・型安全・自己記述的
- 1エンドポイントで複数リソースを横断的に取得可能

### GraphQLクエリ例
```graphql
query {
  user(id: 1) {
    name
    posts {
      title
      createdAt
    }
  }
}
```

---

## 2. RESTとの違い
- RESTは「リソースごとにエンドポイント」、GraphQLは「1エンドポイントで柔軟なクエリ」
- 過不足ないデータ取得（N+1問題やオーバーフェッチ/アンダーフェッチの解消）
- スキーマで型・構造・バリデーションを明示

---

## 3. gRPC・WebSocketなど他のAPI設計
- **gRPC**：Google開発。バイナリ通信・高速・多言語対応。マイクロサービス間通信で利用
- **WebSocket**：双方向通信・リアルタイム性が必要な場合（チャット、ゲーム等）
- **用途ごとの選択指針**：
  - REST：シンプルなCRUD、広範な互換性
  - GraphQL：柔軟なデータ取得、型安全、API統合
  - gRPC：高速・多言語・マイクロサービス
  - WebSocket：リアルタイム通信

---

## 4. 実務での注意点
- GraphQLはキャッシュ・認可・N+1問題対策が必要
- gRPCはHTTP/2やバイナリ通信の知識が必要
- 新しいAPI設計手法も「要件・運用・エコシステム」に合わせて選択
