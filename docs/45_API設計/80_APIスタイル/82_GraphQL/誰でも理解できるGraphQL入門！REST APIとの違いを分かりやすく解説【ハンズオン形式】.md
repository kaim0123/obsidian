## 詳しい要約

**テーマ：GraphQL とは何か（REST との違い）と、Node.js × React でのハンズオン**

GraphQL は一言でいうと **「API のクエリ言語」**。前半では「クエリ」と「API」をたとえで説明したうえで、REST API と比べたときの GraphQL のメリット（単一エンドポイント・オーバーフェッチの回避・型指定）を解説する。後半は Apollo Server で本のデータを返す GraphQL サーバーを作り、React（Vite）と Apollo Client から叩いて画面に表示するまでを実演する。厳密さより「イメージを頭に残す」ことを優先した説明だと断っている。

---

### GraphQL＝API のクエリ言語

- **クエリ** は「問い合わせ」。Google の検索欄に「YouTube」と打ち込んで情報をもらうのが、問い合わせるための言語のイメージ
- **API** は **クライアントとサーバーをつなぐ仲介役**。レストランでいえばお客さん＝クライアント、厨房＝サーバー、ウェイター＝API（インターフェース＝何かと何かをつなぐもの）
- よって GraphQL は「**ウェイター（API）に問い合わせ・指示をするための言語**」
- この図の流れは従来の REST API で、GraphQL はこれから使われていく新しい API の規格

### REST API との違いと GraphQL のメリット

| 観点 | REST API | GraphQL |
|---|---|---|
| エンドポイント | `/students`、`/courses`、`/instructors` とデータごとに別々にアクセス | **`/graphql` の 1 つ** で学生・授業・先生を取得できる |
| 取得データ | `GET /users/:id` で id だけ欲しくても name・住所・誕生日まで返る＝**オーバーフェッチ** | クエリで欲しい属性（name、posts の title、followers の name など）を自分で指定し、それだけが返る |
| メソッド | GET・POST・PUT・DELETE を使い分ける | `query` を書いて問い合わせる |

- メリットのまとめ
  1. **1 つのエンドポイントで複数のデータ** を取得できる
  2. **余計なデータを取得しない**
  3. **型指定** ができるので扱うデータが明確になり、TypeScript などと同様に型の段階でエラーを捕まえられる（堅牢性）

### ハンズオン①: バックエンド（Node.js + Apollo Server）

1. `backend` フォルダで `npm init -y`、`graphql` と `apollo-server` をインストール
2. `server.js` で `new ApolloServer({ typeDefs, resolvers })` を作り、`server.listen()` で起動（引数がないと typeDefs が必要というエラーになる）
3. **typeDefs（型定義）**: `gql` で `Book` 型（title・author はいずれも String）と、`Book` のリストを返すクエリ `test` を定義
4. **resolvers（リゾルバー）**: クエリ `test` が実行されたときに返す値を決めるもの。擬似データ（『吾輩は猫である』夏目漱石、『走れメロス』太宰治）の配列 `books` を返す
5. `localhost:4000` で Apollo のブラウザ画面を開き、`query { test { title author } }` を実行すると 2 冊分のデータが返る

### ハンズオン②: フロントエンド（React + Apollo Client）

1. `create-react-app` より高速な **Vite** で React の雛形を作成（`npm install` を忘れずに）
2. `@apollo/client`・`@apollo/react-hooks`・`graphql`・`apollo-boost` をインストール
3. `main.jsx` で `new ApolloClient({ uri: "http://localhost:4000", cache: new InMemoryCache() })` を作成（cache プロパティがないとエラー）し、`ApolloProvider` で `App` を包んで全コンポーネントから使えるようにする
4. `App.jsx` で `gql` を使ってクエリを定義。そのまま console.log すると構造が深くてわかりにくい
5. **`useQuery` フック** を使うと `loading`・`error`・`data` を取り出せる。ロード中・エラー時の表示を分け、`data.test.map()` で著者とタイトルを画面に表示

### まとめ

- GraphQL は「API に問い合わせるための言語」とまず押さえる
- REST と違い、単一エンドポイントで必要なデータだけを取得でき、型で堅牢にできる
- サーバー側は typeDefs（型とクエリ）＋ resolvers（返す値）、クライアント側は ApolloClient ＋ ApolloProvider ＋ useQuery が基本の流れ
