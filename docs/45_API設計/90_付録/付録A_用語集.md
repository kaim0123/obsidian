# 付録A　用語集

本教材で登場する API 設計の主要用語です。五十音順（見出し）で整理しています。

---

## あ行

| 用語 | 説明 |
|------|------|
| **API** | Application Programming Interface。プログラム同士の約束された入口 |
| **API Key** | クライアントを識別するための文字列。シンプルだが漏洩に注意 |
| **アンチパターン** | よく見るが避けるべき設計の型 |
| **Accept** | クライアントが受け取れるレスポンス形式を示す HTTP ヘッダー |
| **Authorization** | 認証情報（Bearer Token など）を載せる HTTP ヘッダー |

## か行

| 用語 | 説明 |
|------|------|
| **クエリパラメータ** | URL の `?` 以降。フィルタ・ページネーションなどに使う |
| **クライアント** | API を呼び出す側（ブラウザ、モバイル、他サーバー） |
| **Content-Type** | リクエスト／レスポンスボディの形式（例: `application/json`） |
| **CORS** | ブラウザが別オリジン API を呼ぶ際の制約と許可の仕組み |
| **CRUD** | Create / Read / Update / Delete。リソース操作の基本 4 種 |

## さ行

| 用語 | 説明 |
|------|------|
| **サーバー** | API を提供し、リクエストを処理してレスポンスを返す側 |
| **ステータスコード** | HTTP レスポンスの結果を 3 桁数字で表す（200, 404 など） |
| **ステートレス** | サーバーがリクエスト間でクライアント状態を保持しない性質 |
| **スキーマ** | リクエスト／レスポンスのフィールド構造の定義（OpenAPI など） |
| **冪等性（Idempotency）** | 同じ操作を何度実行しても結果が変わらない性質 |

## た行

| 用語 | 説明 |
|------|------|
| **DTO** | Data Transfer Object。API 越しに渡すデータ構造 |
| **Breaking Change** | 既存クライアントを壊す変更（フィールド削除・型変更など） |
| **Deprecation** | 機能を「非推奨」と告知し、将来削除する移行期間を設けること |
| **トークン** | 認証済みであることを示す文字列（JWT など） |

## な行

| 用語 | 説明 |
|------|------|
| **内部 API** | 自社サービス内だけで使う API |
| **外部公開 API** | パートナーや一般開発者向けに公開する API |
| **ネストリソース** | `/users/{id}/orders` のように親子関係を URL で表現する方式 |
| **422 Unprocessable Entity** | 形式は正しいがビジネスルール違反などで処理できないときのステータス |

## は行

| 用語 | 説明 |
|------|------|
| **バージョニング** | API の世代を `/v1/` などで分け、変更の影響を管理すること |
| **Bearer Token** | `Authorization: Bearer <token>` 形式で送るアクセス用トークン |
| **Pagination** | 大量データを page / cursor などで分割して返す仕組み |
| **PATCH** | リソースの一部だけを更新する HTTP メソッド |
| **PUT** | リソース全体を置き換える HTTP メソッド |
| **POST** | 新規作成や非 CRUD 操作に使う HTTP メソッド |
| **HATEOAS** | レスポンスに関連リンクを含め、クライアントの発見可能性を高める REST の考え方 |

## ま行

| 用語 | 説明 |
|------|------|
| **メソッド（HTTP）** | GET / POST / PUT / PATCH / DELETE など、操作の意味を表す動詞 |
| **ミドルウェア** | 認証・ログなど、ハンドラの前後で共通処理を行う層 |

## や行

| 用語 | 説明 |
|------|------|
| **OAuth 2.0** | 第三者アプリに限定的なアクセス権を委譲する認可フレームワーク |
| **OpenAPI** | REST API の仕様を YAML/JSON で記述する標準（旧 Swagger） |
| **429 Too Many Requests** | レート制限超過を示すステータスコード |
| **YAML** | OpenAPI などでよく使う、人間が読みやすい設定記述形式 |

## ら行

| 用語 | 説明 |
|------|------|
| **REST** | リソースを URL で表し、HTTP メソッドで操作する API 設計スタイル |
| **RPC スタイル** | `/createUser` のように「動詞＋操作」を URL に載せるスタイル |
| **リソース** | API が扱う「もの」（ユーザー、注文、TODO など） |
| **レート制限** | 一定時間あたりのリクエスト数を制限し、乱用を防ぐ仕組み |
| **後方互換性** | 古いクライアントが新 API でも動き続けること |

## わ行・英語

| 用語 | 説明 |
|------|------|
| **Webhook** | イベント発生時にサーバーからクライアント URL へ POST する仕組み |
| **GraphQL** | 1 エンドポイントで必要なフィールドだけ取得するクエリ言語 |
| **HTTPS** | HTTP を TLS で暗号化した通信。API では必須 |
| **JSON** | Web API で最もよく使うデータ形式 |
| **JWT** | JSON Web Token。署名付きトークンで認証・認可に使う |
| **URL / URI** | API の住所。パス・クエリ・フラグメントを含む |
