# 付録B　API 設計チェックリスト（総合版）

新規 API 設計・変更レビュー・リリース前に使えるチェックリストです。

---

## 1. 全体・一貫性

- [ ] 命名規則（複数形・ケース・プレフィックス）が **プロジェクト全体で統一** されている
- [ ] 同じ概念に **同じ用語** を使っている（user / member の混在がない）
- [ ] 日時・金額・ID の **形式が統一** されている（ISO 8601、通貨コードなど）
- [ ] 成功・エラー・ページネーションの **レスポンス構造が揃っている**
- [ ] 内部 API と外部 API で **ルールの差** が意図的である

---

## 2. URL・リソース設計

- [ ] URL に **動詞を載せていない**（`/getUser` ではなく `/users/{id}`）
- [ ] リソース名は **名詞・複数形**（`/users`, `/orders`）
- [ ] ネストは **浅く**、深い階層は別リソース or クエリで表現
- [ ] ID は **パス** に、フィルタ・ソートは **クエリ** に置いている
- [ ] 同じリソースへの **別名 URL** が乱立していない

---

## 3. HTTP メソッド・ステータス

- [ ] GET は **副作用なし**、POST/PUT/PATCH/DELETE の意味が REST 的に妥当
- [ ] 201 + `Location` で **作成リソース** を示している（該当時）
- [ ] 204 は **ボディなし** の成功（削除・更新など）に使っている
- [ ] 400 / 401 / 403 / 404 / 409 / 422 / 429 / 500 を **意味に沿って** 使い分けている
- [ ] 500 以外の 4xx で **クライアントが対処可能** な情報を返している

---

## 4. リクエスト・レスポンスボディ

- [ ] フィールド名は **snake_case または camelCase** で統一
- [ ] 不要な内部フィールド（パスワードハッシュなど）を **返していない**
- [ ] 作成・更新で **必要最小限** の入力だけ受け付けている
- [ ] null と「フィールド省略」の **意味の差** がドキュメント化されている
- [ ] リスト API は **ラッパー**（`items`, `data`, `meta`）の形が統一されている

---

## 5. エラー設計

- [ ] エラーボディに **機械可読な code** がある
- [ ] **人間向け message** と **開発者向け detail** を分けている
- [ ] バリデーションエラーは **フィールド単位** で返せる（422 など）
- [ ] スタックトレース等の **内部情報を漏らしていない**
- [ ] エラー形式が **全エンドポイントで同じ**

---

## 6. ページネーション・検索

- [ ] 一覧 API に **ページネーション** がある（大量データ想定時）
- [ ] page/limit または cursor 方式が **一貫** している
- [ ] ソート・フィルタの **パラメータ名** が他 API と揃っている
- [ ] デフォルト limit に **上限** がある
- [ ] 空結果は **200 + 空配列**（404 ではない）

---

## 7. バージョニング・互換性

- [ ] 破壊的変更の **方針** が決まっている（新バージョン / deprecation）
- [ ] フィールド **追加** は後方互換として許容されている
- [ ] 削除・改名・型変更は **移行期間** またはバージョン分離がある
- [ ] 非推奨 API に **Sunset / Deprecation ヘッダー** またはドキュメント記載がある
- [ ] クライアント影響を **リリースノート** で共有している

---

## 8. 認証・認可・セキュリティ

- [ ] **HTTPS のみ** で提供している
- [ ] 401（未認証）と 403（権限不足）を **区別** している
- [ ] トークン・API Key を **URL クエリに載せていない**
- [ ] レート制限があり、429 と **Retry-After** を返せる
- [ ] 入力値の **バリデーション・サニタイズ** がある
- [ ] CORS 設定が **必要最小限** のオリジンのみ許可

---

## 9. 信頼性・運用

- [ ] 重要な POST に **冪等性キー** または設計上の冪等性がある
- [ ] タイムアウト・リトライ方針が **ドキュメント化** されている
- [ ] ヘルスチェック（`/health` など）がある（該当サービス）
- [ ] リクエスト ID（`X-Request-Id`）で **トレース** できる
- [ ] 変更前に **契約テスト / OpenAPI 検証** がある

---

## 10. ドキュメント

- [ ] OpenAPI（または同等）で **全公開エンドポイント** が記述されている
- [ ] 認証方法・例示 curl・エラーコード一覧がある
- [ ] サンプルリクエスト／レスポンスが **実際と一致** している
- [ ] 変更履歴（Changelog）が **更新** されている
