---

## 1. 認証方式
- **APIキー**：シンプルな認証。クエリやヘッダーで送信。漏洩リスクに注意
- **Basic認証**：ユーザー名・パスワードをBase64で送信。HTTPS必須
- **OAuth2**：外部サービス連携やユーザー認可に最適。アクセストークン発行
- **JWT（JSON Web Token）**：署名付きトークンで認証・認可を実現。分散システムで有用

---

## 2. 認可（アクセス制御）
- **RBAC（ロールベースアクセス制御）**：ユーザーの役割ごとに権限を設定
- **ABAC（属性ベースアクセス制御）**：ユーザー属性やリソース属性で柔軟に制御

---

## 3. 通信の安全性
- **HTTPS**：通信内容の暗号化。APIは必ずHTTPSで公開
- **CORS（クロスオリジンリソースシェアリング）**：WebブラウザからのAPI利用時の制御
- **セキュリティヘッダー**：CSP, HSTS, X-Frame-Options, X-Content-Type-Options など

---

## 4. レートリミット・監査
- 一定時間内のリクエスト数制限（DoS/DDoS対策）
- IP制限やAPIキーごとのリミット
- 監査ログで不正アクセスや障害調査

---

## 5. 入力値バリデーションと脅威対策
- サニタイズ・エスケープでSQLインジェクション/XSS/コマンドインジェクション対策
- CSRF（クロスサイトリクエストフォージェリ）対策（トークン、SameSite Cookie）
- バリデーションエラー時は適切なエラーコード・メッセージを返す

---

APIのセキュリティは「多層防御」と「最小権限の原則」が重要です。
