# ページネーション・フィルタ・ソート

## この章の目的

一覧 API の **分割取得・絞り込み・並び替え** を設計する章です。

---

## 1. 一覧 API が必要になる場面

`GET /users` や `GET /orders` のように **複数件を返す API** は、データが増えるとそのままでは扱えません。

| 問題 | 原因 |
|------|------|
| レスポンスが巨大 | 数万件を一度に JSON 化 |
| 遅い | DB・ネットワーク・パースの負荷 |
| タイムアウト | モバイル回線・サーバー制限 |

```text
  GET /orders  →  10 万件全部返す  ❌
  GET /orders?page=1&limit=20  →  20 件ずつ  ✅
```

**一覧 API には最初からページネーションを設計** しておくのが定石です。

---

## 2. オフセット方式（`page` / `limit`）

```text
GET /users?page=2&limit=20
```

| 項目 | 内容 |
|------|------|
| リクエスト | `page`（何ページ目）, `limit`（1 ページ件数） |
| レスポンス例 | `{ "data": [...], "meta": { "page": 2, "limit": 20, "total": 150 } }` |
| メリット | 実装・理解が簡単、「N ページ目へジャンプ」しやすい |
| デメリット | データ追加・削除で **重複や取りこぼし** が起きやすい |

管理画面の表など、**任意ページへジャンプ** したい場面向きです。

---

## 3. カーソル方式（`cursor` / `has_more`）

```text
GET /users?limit=20&cursor=eyJpZCI6MTIzfQ
```

| 項目 | 内容 |
|------|------|
| リクエスト | `limit`, `cursor`（前回の続き位置） |
| レスポンス例 | `{ "data": [...], "meta": { "next_cursor": "...", "has_more": true } }` |
| メリット | リアルタイム更新に強い、大量データ・無限スクロール向き |
| デメリット | 任意ページへのジャンプが難しい |

SNS タイムライン、ログ、フィードなど **順次読み進める UI** に向いています。

---

## 4. フィルタとソートのクエリパラメータ設計

一覧 API では **クエリパラメータ** で絞り込み・並び替えを表現します。

```text
GET /products?category=book&status=active&sort=-price,created_at
```

| パラメータ | 例 | 意味 |
|-----------|-----|------|
| フィルタ | `category=book` | カテゴリが book |
| フィルタ | `status=active` | 有効なものだけ |
| ソート | `sort=price` | 価格昇順 |
| ソート | `sort=-price` | 価格降順（`-` プレフィックス） |
| 複合 | `sort=-price,created_at` | 価格降順 → 同値は作成日昇順 |

- パラメータ名は **一貫した命名**（[[04_一貫性]]）
- 許容するフィルタ・ソート列を **ドキュメント化**

---

## 5. 方式の選び方と `limit` 上限

| 用途 | おすすめ |
|------|----------|
| 管理画面、件数少〜中、ページジャンプ | オフセット |
| タイムライン、ログ、無限スクロール | カーソル |

### 共通のベストプラクティス

- **`limit` に上限** を設ける（例：最大 100）
- **`total`（総件数）** は DB コストが高い場合、省略または概算を検討
- ソート順を **固定** する（例：`created_at desc, id desc`）
- `has_more` や `next_cursor` を含め、クライアント実装を単純に

```json
{
  "data": [...],
  "meta": {
    "limit": 20,
    "next_cursor": "eyJpZCI6MTIzfQ",
    "has_more": true
  }
}
```
