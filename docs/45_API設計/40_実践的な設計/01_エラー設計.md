# エラー設計

## この章の目的

API は **失敗も予測可能な形** で返す。ステータス + 機械可読 code + 人間向け message を学ぶ章です。

---

## 1. エラー設計の目的

クライアントはエラー内容を見て、**再試行・ユーザー表示・ログ送信** を判断します。

| 目的 | 説明 |
|------|------|
| 機械可読 | プログラムが `code` で分岐できる |
| 人間可読 | 開発者・ユーザーに原因が伝わる |
| 一貫性 | 全エンドポイントで同じ JSON 構造 |
| 調査可能 | `request_id` でログと紐づく |

```text
  500 だけ返す API  →  クライアントは「再試行すべきか」も分からない
  設計されたエラー  →  UI・リトライ・サポートがしやすい
```

---

## 2. ステータスコード + 機械可読な `code`

**2 段階** でエラーを表現します。

| 層 | 役割 | 例 |
|----|------|-----|
| HTTP ステータス | 大分類 | `422 Unprocessable Entity` |
| `error.code` | 細かい種類（固定文字列） | `VALIDATION_ERROR`, `INSUFFICIENT_STOCK` |

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "入力内容に誤りがあります"
  }
}
```

- `code` は **大文字スネークケース** の固定文字列
- クライアントは `code` で switch する（message 文字列比較は避ける）

---

## 3. 人間向け `message` とフィールド単位の `details`

バリデーションエラーは **フィールド単位** で返すとフォーム UI と相性が良いです。

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "入力内容に誤りがあります",
    "details": [
      {
        "field": "email",
        "code": "INVALID_FORMAT",
        "message": "メールアドレスの形式が正しくありません"
      },
      {
        "field": "password",
        "code": "TOO_SHORT",
        "message": "8文字以上で入力してください"
      }
    ]
  }
}
```

| フィールド | 向き | 用途 |
|-----------|------|------|
| `message` | 人間 | 画面表示、ログ |
| `details[].field` | 機械 + 人間 | フォームの該当欄にエラー表示 |
| `details[].code` | 機械 | クライアント側の細かい分岐 |

---

## 4. `request_id` とログ調査

**`request_id`** をエラーレスポンスに含めると、サポート・障害調査が楽になります。

```json
{
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "サーバーでエラーが発生しました",
    "request_id": "req_abc123xyz"
  }
}
```

```text
  ユーザー「エラーが出ました」
       │
       ▼
  request_id: req_abc123xyz  をサポートに伝える
       │
       ▼
  サーバーログで同じ ID を検索 → 原因特定
```

- 本番レスポンスに **スタックトレースを含めない**
- `request_id` はレスポンスヘッダ `X-Request-Id` に付ける方式もある

---

## 5. エラーレスポンスのチェックリスト

- [ ] 4xx / 5xx を原因に応じて使い分けているか
- [ ] すべてのエラーで **同じ JSON 構造**（`error.code` 等）か
- [ ] `code` は固定文字列で、ドキュメントに一覧があるか
- [ ] バリデーションは **フィールド単位** の `details` があるか
- [ ] `request_id` を付けてログと紐づけられるか
- [ ] 5xx の詳細（内部情報）を本番レスポンスに漏らしていないか
- [ ] 401 と 403 を正しく区別しているか（第18〜19章）
