# 認証とセッションのパターン

「ログイン」と「ログイン状態の保持」は Web アプリで避けられないテーマです。
Next.js では複数のアプローチがあるので、それぞれの仕組みと向き不向きを押さえましょう。

---

## 1. 認証の主要パターン

| 方式 | 概要 | 向き |
|------|------|------|
| **メール + パスワード** | 自前で管理 | 古典的、フル制御したい |
| **OAuth（Google / GitHub 等）** | 外部 ID プロバイダ | 楽、ユーザーが既にアカウントを持っている |
| **マジックリンク** | メールに送るリンクでログイン | パスワード管理を避けたい |
| **パスキー（Passkey）** | 生体認証 + デバイス | 最新、セキュア |
| **JWT** | サーバーステートレス | API 中心、SPA |
| **セッションクッキー** | サーバー側でセッション管理 | Web アプリの定番 |

---

## 2. 推奨ライブラリ：Auth.js（旧 NextAuth）

[Auth.js](https://authjs.dev/) は Next.js でデファクトスタンダードな認証ライブラリです。

- OAuth、メール、Credentials など多数の Provider に対応
- セッション管理（クッキー or DB）を勝手にやってくれる
- App Router に対応（v5 系）

### 最小セットアップ

```bash
npm install next-auth@beta
```

```ts
// auth.ts（プロジェクトルート）
import NextAuth from "next-auth";
import GitHub from "next-auth/providers/github";

export const { handlers, signIn, signOut, auth } = NextAuth({
  providers: [GitHub],
});
```

```ts
// app/api/auth/[...nextauth]/route.ts
export { GET, POST } from "@/auth";
```

```ts
// .env.local
AUTH_SECRET=任意のランダム文字列
AUTH_GITHUB_ID=xxx
AUTH_GITHUB_SECRET=xxx
```

これだけで `/api/auth/signin` などが動きます。

### サーバーで認証情報を取得

```tsx
// app/dashboard/page.tsx（Server Component）
import { auth } from "@/auth";
import { redirect } from "next/navigation";

export default async function Dashboard() {
  const session = await auth();
  if (!session) redirect("/login");
  return <p>ようこそ {session.user?.name}</p>;
}
```

### クライアントで認証情報を取得

```tsx
"use client";
import { useSession } from "next-auth/react";

export function Avatar() {
  const { data: session } = useSession();
  return <img src={session?.user?.image ?? "/anon.png"} />;
}
```

## 3. 自前でセッションを実装する場合

外部ライブラリに頼らず、最小限のセッションを実装するパターンも知っておきましょう。

### A. ログイン時にクッキーを発行

```ts
// app/login/actions.ts
"use server";
import { cookies } from "next/headers";
import { redirect } from "next/navigation";
import { SignJWT } from "jose";

const secret = new TextEncoder().encode(process.env.AUTH_SECRET);

export async function login(formData: FormData) {
  const email = formData.get("email") as string;
  const password = formData.get("password") as string;

  const user = await db.users.findUnique({ where: { email } });
  if (!user || !(await verifyPassword(password, user.passwordHash))) {
    throw new Error("メールまたはパスワードが違います");
  }

  // JWT を作ってクッキーに入れる
  const token = await new SignJWT({ sub: user.id })
    .setProtectedHeader({ alg: "HS256" })
    .setExpirationTime("7d")
    .sign(secret);

  (await cookies()).set("session", token, {
    httpOnly: true,
    secure: process.env.NODE_ENV === "production",
    sameSite: "lax",
    path: "/",
    maxAge: 60 * 60 * 24 * 7,
  });

  redirect("/dashboard");
}
```

### B. セッション読み出し用のヘルパ

```ts
// lib/session.ts
import { cookies } from "next/headers";
import { jwtVerify } from "jose";

const secret = new TextEncoder().encode(process.env.AUTH_SECRET);

export async function getSession() {
  const token = (await cookies()).get("session")?.value;
  if (!token) return null;
  try {
    const { payload } = await jwtVerify(token, secret);
    return payload as { sub: string };
  } catch {
    return null;
  }
}
```

### C. Server Component で利用

```tsx
import { getSession } from "@/lib/session";
import { redirect } from "next/navigation";

export default async function Dashboard() {
  const session = await getSession();
  if (!session) redirect("/login");
  return <p>ユーザー ID: {session.sub}</p>;
}
```

## 4. クッキー設定の鉄則

| オプション | 値 | 意味 |
|-----------|-----|------|
| `httpOnly` | `true` | JS からアクセス不可（XSS 対策） |
| `secure` | `true`（本番） | HTTPS でのみ送信 |
| `sameSite` | `"lax"` または `"strict"` | CSRF 対策。lax が推奨 |
| `path` | `"/"` | 全パスで送信 |
| `maxAge` | 秒数 | 有効期限 |

これらを**必ず指定**しましょう。指定漏れは典型的脆弱性。

## 5. パスワードのハッシュ化

絶対に**平文で保存しない**こと。`bcrypt` か `argon2`、`scrypt`（Node 標準）を使います。

```ts
import { hash, compare } from "bcryptjs";

const passwordHash = await hash(password, 10);
const ok = await compare(input, passwordHash);
```

## 6. ログアウト

```ts
// app/logout/actions.ts
"use server";
import { cookies } from "next/headers";
import { redirect } from "next/navigation";

export async function logout() {
  (await cookies()).delete("session");
  redirect("/");
}
```

## 7. ミドルウェアでの保護

```ts
// middleware.ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function middleware(request: NextRequest) {
  const token = request.cookies.get("session");
  if (!token) {
    const url = new URL("/login", request.url);
    url.searchParams.set("from", request.nextUrl.pathname);
    return NextResponse.redirect(url);
  }
  return NextResponse.next();
}

export const config = {
  matcher: ["/dashboard/:path*", "/settings/:path*"],
};
```

⚠ Middleware は Edge Runtime なので、JWT 検証など軽いものは OK ですが、DB 問い合わせは避けましょう。
**「軽いゲート + 各ページで本格チェック」**が定石です。

## 8. RBAC（権限管理）

ユーザーの役割（admin / member など）に応じてアクセス制御。

```ts
// lib/auth-guard.ts
import { getSession } from "@/lib/session";
import { redirect } from "next/navigation";

export async function requireAdmin() {
  const session = await getSession();
  const user = await db.users.findUnique({ where: { id: session?.sub } });
  if (user?.role !== "admin") redirect("/forbidden");
  return user;
}
```

```tsx
// app/admin/page.tsx
import { requireAdmin } from "@/lib/auth-guard";

export default async function AdminPage() {
  const admin = await requireAdmin();
  return <h1>{admin.name}（管理者）</h1>;
}
```

## 9. CSRF 対策

- Server Actions は Next.js が自動的に CSRF トークンを処理してくれる
- 自前 Route Handler の場合は、`SameSite=Lax`/`Strict` クッキー + CSRF トークン または **Origin ヘッダ確認**

```ts
export async function POST(request: Request) {
  const origin = request.headers.get("origin");
  if (origin !== process.env.NEXT_PUBLIC_SITE_URL) {
    return NextResponse.json({ error: "forbidden" }, { status: 403 });
  }
  // ...
}
```

## 10. 「ログインしているかどうかでレイアウトを変える」

詳しくは [[01認証付きレイアウト分岐]] で扱いますが、よくあるパターン：

```tsx
// app/(authed)/layout.tsx
import { getSession } from "@/lib/session";
import { redirect } from "next/navigation";

export default async function AuthedLayout({ children }: { children: React.ReactNode }) {
  const session = await getSession();
  if (!session) redirect("/login");
  return <div className="authed-layout">{children}</div>;
}
```

ルートグループ `(authed)` 配下のすべてのページで、自動的に認証チェックが走ります。

## 11. つまずきポイント

### Q. クッキーをセットしたのに次のリクエストで読めない

→ `path: "/"` を指定しているか確認。デフォルトは現在のパスに限定されます。

### Q. 本番でだけクッキーが消える

→ `secure: true` の場合は HTTPS 必須。HTTP だと送信されません。

### Q. Auth.js の `auth()` が undefined

→ プロバイダ設定や環境変数を確認。`AUTH_SECRET` を必ず設定。

### Q. ミドルウェアでセッション検証したい

→ JWT 検証ならミドルウェアでも可（jose ライブラリ等）。DB 検証はミドルウェアでは避ける。

### Q. CSRF が心配

→ Server Actions を使うか、`SameSite` を必ず設定。

---

## まとめ

- 推奨は **Auth.js（NextAuth）** か、シンプル要件なら**自前 + JWT クッキー**
- クッキーは必ず **`httpOnly` + `secure` + `sameSite`** をセット
- パスワードは **bcrypt/argon2** でハッシュ化
- 認可は **Server Component / Route Handler / Server Action でも個別にチェック**
- ミドルウェアは「軽い振り分け」だけに使い、DB 検証は本処理側で
