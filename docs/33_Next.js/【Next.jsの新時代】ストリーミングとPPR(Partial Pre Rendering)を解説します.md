## 動画の要約（詳しめ）

### 全体像

この動画は、**データ取得に時間がかかるときでも「準備できたところから順に見せる」**ための仕組みとしての **ストリーミング** と、ページ内で **静的に先に確定させる領域** と **その後ストリームで埋める領域** を分ける発想につながる **PPR（Partial Pre-Rendering）** を、ダッシュボードのデモコードを使って順に説明している。

---

### ストリーミングが解決すること

デフォルトでは、複数の **動的サーバーコンポーネント** が並列でフェッチしている場合でも、**一番遅いフェッチが終わるまでページ全体がブロックされる**ことがある（例として、複数カードが 1〜4 秒の疑似遅延を持ち、全体が約 4 秒後に一度に描画される挙動）。ユーザーから見ると、**サイドバーやヘッダーのような静的にも描ける UI まで空白のまま**になりがちである。

ストリーミングは、この「全体を最遅コンポーネントの完了に合わせる」モデルをやめて、**すでに描画できる部分を先に送り、その後コンテンツを段階的に足していく**考え方。UX としてはローディングの体感時間が短くなり、「何かが動いている」ことが分かりやすくなる。

---

### Suspense と境界（バウンダリー）の考え方

React の **`Suspense`** で **動的なサーバーコンポーネント** をラップすると、その内側がストリーミングの単位になり、**準備できるまでは `fallback`（文字列でも静的コンポーネントでも可）を表示**できる。

実装上の注意点として、**動的な部分が複数あるときに Suspense を一部だけ付けると、期待どおりに段階表示にならない**ことがある。デモでは **各カードごとに Suspense を張る**と、約 1 秒ごとに順に中身が埋まっていく。逆に **動的サーバーコンポーネント群をひとつの大きな Suspense でまとめて包む**と、**最も遅いデータが揃うまで中身が一緒に待たされる**ため、細かく区切った方が体感は良くなるという比較が示される。

Suspense が決めているのは実質 **`fallback` と「本体」の境界**。境界の外側（例: 「ダッシュボード」という見出しやヘッダーなど）は静的に早期表示し、境界の内側だけがストリームで後から現れる——という説明になっており、この **静的シェル／動的内側の分離** のイメージは後半の **PPR** の説明とつなげて理解できる。

---

### `loading.js`（ルートセグメントの規約）

Next.js では、**同じルートセグメントに `loading.tsx` / `loading.js` を置く**と、そのセグメントのページが **自動的に Suspense でラップされたのと同様のストリーミング**が有効になる（フォールバックは `loading` ファイルの内容）。**ページ単位でまとめてストリーミングしたい**とき向き。

一方、**セグメント内の個々のコンポーネントを細かく段階表示したい**ときは、**コンポーネント側で Suspense を使う**方が適する。

**`loading.js` と手書きの Suspense を同時に使うと、Suspense 側が優先**される、という整理も登場する。

---

### フォールバックとスケルトン

`fallback` はプレースホルダー文字列でもよいが、実務では **スケルトン UI やスピナー** の方が UX が良い。デモでは shadcn/ui の **Skeleton** を使ったカード用スケルトンを `fallback` に載せている。

---

### PPR（Partial Pre-Rendering）とは何か

**ページの一部を静的に事前レンダリングし、残りを動的にストリーミングで埋める**というモデル。動画内では **「Suspense で切った内側が動的、外側が静的」** という今回のストリーミングの議論が、**静的シェル＋動的島** のイメージとほぼ同じである、と説明されている。

※当時は **実験的機能** であり、設定は **`next.config` の `experimental`（インクリメンタルな PPR 有効化）** と **対象ルートのセグメント設定オプション** の組み合わせだった（バージョンは動画収録時点の Next に依存。**Canary 環境でのみ使える設定**への言及や、ビルド・ESLint 周りのトラブル回避の一例も含まれる）。

本番での効果体感や、開発時は静的プリレンダの影響でスケルトンが目立ちにくい、といった運用上のニュアンスにも触れ、**実 API フェッチと組み合わせた実装を想定することが推奨**されている。

動画末尾では、このストリーミング／Suspense／`loading.js` は **ダッシュボードに限らず、データフェッチして表示するアプリ一般**に使える、とまとめている。
