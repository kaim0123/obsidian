# ストリーミングと PPR（Partial Prerendering）

データ取得や動的処理に時間がかかるときでも、**準備できた部分から順にユーザーに見せる**ために使うのが **ストリーミング** です。その延長線上で、「ページの静的な外枠だけ先に出し、遅い部分はあとから流す」モデルが **PPR（パーシャルプリレンダー Partial Prerendering）** と呼ばれる考え方に近い、と捉えるとわかりやすいです。

---

## 1. ストリーミングが解決すること

複数の **動的な Server Components** が並んでいても、**最も遅い処理が終わるまでレイアウトごと空白のまま**に見えることがあります。

ストリーミングは、この「全体ブロック」をやめて、**すでに描画できる部分を先に送り、コンテンツを段ごとに足す**方式です。

- UX 上：待ち体感が短くなり、`fallback` で「読み込み中」が伝わりやすい。
- 実装上：**境界（boundary）単位**でチャンクを流すというイメージ。

---

## 2. Suspense と境界の切り方

React の **`Suspense`** で **動的サーバーコンポーネント** を包むと、その内側がストリーミング単位になり、準備できるまで **`fallback`** を表示できます。

実務でのコツです。

| 張り方 | 挙動のイメージ |
|--------|----------------|
| **遅い塊ごとに** Suspense を分ける | 1 つずつ中身が埋まり、体感がよくなりやすい |
| **大きく 1 つの** Suspense にまとめる | **一番遅い処理が終わるまで内側一式がまとめて待つ** |

外側に置いた見出し・ナビなどは先に確定させ、境界の内側だけがあとから流れる、という構成にすると読みやすいです。この **静的シェル／動的内側の分離** は、後述の **PPR** と同じ図で理解できます。

`fallback` は文字列でもよいですが、**スケルトンやインジケータ**のほうが一般的に UX が良いです。

---

## 3. `loading.tsx`（ルートセグメントの規約）

同じルートセグメントに **`loading.js` / `loading.tsx`** を置くと、そのセグメントのページが **自動的に Suspense 相当のストリーミング**になります。**フォールバックはそのファイルの内容**です。

| ユースケース | おすすめ |
|--------------|----------|
| **ページ単位**でまとめてストリーミングしたい | `loading.tsx` |
| **細かく**コンポーネント単位で段階表示したい | コンポーネント側で `Suspense` を書く |

**`loading.tsx` と手書きの `Suspense` を両方置いた場合、`Suspense` 側が優先**されます（細かく区切ったときに `loading.tsx` の効果だけが体感できないことがあるので注意）。

---

## 4. PPR（パーシャルプリレンダー）とは

**ページの一部を事前に静的に確定させ、残りを動的（ストリーミングなど）で埋める**モデルです。動画上の説明どおり、`Suspense` で切った「内側＝動的」「外側＝静的」のイメージとほぼ同じですが、**設定・安定版フラグ・ルート単位の有効化**は Next.js のバージョンで変わります。**最新のフラグ名と推奨手順は [Next.js 公式ドキュメント](https://nextjs.org/docs) を確認**してください（実験段階だった時期には `experimental` とルート単位オプションの組み合わせでした）。

運用上も、開発時は静的側が強く効いて **スケルトンが目立ちにくい**ことがあるため、体感は **`next build` 後や本番環境**で確認することが推奨されます。
