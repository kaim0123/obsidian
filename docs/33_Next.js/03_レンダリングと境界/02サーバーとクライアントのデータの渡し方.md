# サーバーとクライアントのデータの渡し方

Server Components と Client Components が混在する App Router では、
**「どっちからどっちへ、どうやってデータを渡すのか」**を整理しておく必要があります。

---

## 1. 4 つの方向

| 方向 | 主な手段 |
|------|----------|
| ① Server → Client | **props で渡す** |
| ② Client → Server | **Server Actions** / **Route Handlers** |
| ③ Server → Server | 関数を直接呼ぶ（普通の関数呼び出し） |
| ④ Client → Client | React の Context、Zustand などの状態管理 |

---

## 2. ① Server → Client：props 経由

最も基本のパターン。Server Component で取得したデータを、子の Client Component に props として渡します。

```tsx
// app/page.tsx（Server Component）
import Counter from "./Counter";

export default async function Page() {
  const data = await fetch("https://api.example.com/init").then(r => r.json());
  return <Counter initial={data.count} />;
}
```

```tsx
// app/Counter.tsx
"use client";
import { useState } from "react";

export default function Counter({ initial }: { initial: number }) {
  const [n, setN] = useState(initial);
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}
```

### 渡せる値

**シリアライズ可能な値だけ**渡せます。

| 渡せる | 渡せない |
|-------|---------|
| string / number / boolean | function（普通の関数） |
| Array / 普通のオブジェクト | class インスタンス |
| Date | Symbol |
| null / undefined | Map / Set（一部 OK） |
| Promise（React が解決してくれる） | DOM ノード |

### 関数を渡したいときは Server Actions

Server Component から「**サーバー側で動く関数**」を Client に渡すには **Server Actions** を使います。

```tsx
// app/page.tsx
import LikeButton from "./LikeButton";

export default function Page() {
  async function like() {
    "use server";
    // ここはサーバー側で実行される
    await db.likes.create({ ... });
  }
  return <LikeButton onLike={like} />;
}
```

```tsx
// app/LikeButton.tsx
"use client";

export default function LikeButton({ onLike }: { onLike: () => Promise<void> }) {
  return <button onClick={() => onLike()}>いいね</button>;
}
```

`onLike` は普通の関数のように見えますが、**裏で HTTP リクエストとしてサーバーに送信**されます。詳細は [[03Server-Actions（フォーム・ミューテーション）]] で。

## 3. ② Client → Server：Server Actions

Client から「サーバー側の処理」を呼ぶ方法は主に 2 つ。

### A. Server Actions（推奨）

サーバー側に書いた `"use server"` 関数を、フォームやイベントから直接呼べます。

```ts
// app/actions.ts
"use server";

export async function addTodo(formData: FormData) {
  const title = formData.get("title");
  await db.todos.create({ title });
}
```

```tsx
// app/AddTodoForm.tsx
"use client";
import { addTodo } from "./actions";

export default function AddTodoForm() {
  return (
    <form action={addTodo}>
      <input name="title" />
      <button type="submit">追加</button>
    </form>
  );
}
```

### B. Route Handlers（API 経由）

`fetch("/api/...")` で叩く伝統的な方法。

```ts
// app/api/todos/route.ts
import { NextResponse } from "next/server";

export async function POST(request: Request) {
  const body = await request.json();
  await db.todos.create(body);
  return NextResponse.json({ ok: true });
}
```

```tsx
"use client";

export function AddTodo() {
  async function handle() {
    await fetch("/api/todos", {
      method: "POST",
      body: JSON.stringify({ title: "shopping" }),
    });
  }
  return <button onClick={handle}>追加</button>;
}
```

### どちらを使う？

- **アプリ内部の処理**：Server Actions（型安全、簡潔）
- **外部からも叩かれる API**：Route Handlers（モバイル、外部サービス連携）

## 4. ③ Server → Server：普通の関数呼び出し

Server Component 同士は**ただの async 関数**としてデータをやり取りできます。

```ts
// lib/posts.ts
export async function getPosts() {
  return await db.posts.findMany();
}
```

```tsx
// app/posts/page.tsx
import { getPosts } from "@/lib/posts";

export default async function Page() {
  const posts = await getPosts();
  return <ul>...</ul>;
}
```

`fetch` を使うと、Next.js が**同じリクエスト内で自動的に重複排除**してくれるので、複数コンポーネントで同じ `fetch` を呼んでもネットワークアクセスは 1 回で済みます。

```ts
// 同じ URL の fetch は 1 回しか走らない
const a = await fetch("/api/user");
const b = await fetch("/api/user"); // ネットワーク呼ばれない
```

## 5. ④ Client → Client：Context / 状態管理

Client コンポーネント間で値を共有したいときは React の `Context` などを使います。

```tsx
// app/providers.tsx
"use client";
import { createContext, useState, useContext } from "react";

const ThemeContext = createContext<{ theme: string; setTheme: (s: string) => void } | null>(null);

export function ThemeProvider({ children }: { children: React.ReactNode }) {
  const [theme, setTheme] = useState("light");
  return <ThemeContext.Provider value={{ theme, setTheme }}>{children}</ThemeContext.Provider>;
}

export function useTheme() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("ThemeProvider 必須");
  return ctx;
}
```

```tsx
// app/layout.tsx（Server Component のまま）
import { ThemeProvider } from "./providers";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <ThemeProvider>{children}</ThemeProvider>
      </body>
    </html>
  );
}
```

ポイント：**`ThemeProvider` は Client Component**ですが、その `children`（=各ページ）は **Server Component のまま**にできる、というのが App Router の良いところ。

## 6. URL を介した状態共有（`useSearchParams`）

UI の状態（フィルタ、ページ番号など）は **URL に持たせる**のがベストプラクティス。

- リロードしても状態が消えない
- 共有可能（URL を渡せば同じ画面が再現できる）
- ブラウザの戻る/進むが効く

```tsx
// Server Component 側
export default async function Page({
  searchParams,
}: {
  searchParams: Promise<{ q?: string }>;
}) {
  const { q } = await searchParams;
  const results = await search(q);
  return <Results data={results} />;
}
```

```tsx
// Client Component 側
"use client";
import { useSearchParams, useRouter } from "next/navigation";

export function SearchBox() {
  const router = useRouter();
  const params = useSearchParams();
  return (
    <input
      defaultValue={params.get("q") ?? ""}
      onChange={(e) => router.push(`?q=${e.target.value}`)}
    />
  );
}
```

## 7. クッキーとヘッダで「リクエスト固有のデータ」を渡す

ログイン中ユーザーや言語設定などを **どのコンポーネントからも参照したい**場合、Context を使うより `cookies()` / `headers()` が便利です。

```tsx
// 任意の Server Component
import { cookies, headers } from "next/headers";

export default async function Page() {
  const cookieStore = await cookies();
  const session = cookieStore.get("session_token");

  const headerList = await headers();
  const ua = headerList.get("user-agent");

  // ...
}
```

> Next.js 15 以降、`cookies()` / `headers()` は async 化されました（`await` 必須）。

## 8. つまずきポイント

### Q. Server Component から普通の関数を Client にそのまま渡したい

→ シリアライズできないので不可。**Server Actions（`"use server"`）**にしてください。

### Q. Client Component で `cookies()` を使ったらエラー

→ `cookies()` は Server 専用。Client では `document.cookie` を使うか、Route Handler 経由で取得します。

### Q. Server Component で `useState` を使いたい

→ それは Client Component の役目。状態が必要な部分だけ Client に切り出して。

### Q. Provider を Layout に入れたい

→ Provider 自体は Client Component（`"use client"`）。それを Server の Layout で `<Provider>{children}</Provider>` のように囲めば OK。

---

## まとめ

| 方向 | 手段 |
|------|------|
| Server → Client | **props**（シリアライズ可能な値のみ） |
| Client → Server | **Server Actions**（推奨） or **Route Handlers** |
| Server → Server | 普通の async 関数呼び出し（`fetch` は自動 dedupe） |
| Client → Client | **Context** や 状態管理ライブラリ |

URL を使った状態共有 (`searchParams`) は、共有・リロードに強いのでおすすめです。
