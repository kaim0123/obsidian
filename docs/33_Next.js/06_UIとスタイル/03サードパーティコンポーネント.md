# サードパーティコンポーネント

UI を 0 から作るのは大変。多くのプロジェクトでは**外部の UI コンポーネントライブラリ**を導入します。
Next.js（特に App Router）でうまく付き合うコツを押さえましょう。

---

## 1. 主要な UI ライブラリの選択肢

### A. shadcn/ui（**現在最も人気**）

- Tailwind ベース
- ライブラリではなく**コードを自分のリポジトリにコピー**するスタイル
- カスタマイズしやすい
- App Router 完全対応

```bash
npx shadcn@latest init
npx shadcn@latest add button input dialog
```

→ 自分の `components/ui/` 配下に Button などのファイルが**直接配置**される。

```tsx
import { Button } from "@/components/ui/button";

<Button variant="outline" size="sm">クリック</Button>
```

### B. Radix UI

- アクセシビリティ重視の**ヘッドレス**コンポーネント（見た目なし）
- スタイリングは自由
- shadcn/ui の中身も Radix を使っている

### C. MUI（Material UI）

- マテリアルデザイン
- リッチで多機能、ただしバンドルサイズが大きい
- App Router の Server Components で使うには設定が必要

### D. Mantine

- 機能豊富、ドキュメント充実
- 最近 App Router 対応が進んだ

### E. Chakra UI

- シンプルで使いやすい
- 過去人気だが App Router との相性に難あり

### F. Ant Design

- ビジネス向け、フル装備
- 中国系プロダクトでよく使われる

## 2. App Router で UI ライブラリを使うときの注意

多くのライブラリは **`useState` などのフックを内部で使う**ため、**Client Component** として動作する必要があります。

そのため、

- import するファイル冒頭に **`"use client"`** が必要なケースが多い
- ライブラリ提供のラッパーコンポーネント（Provider）を Client 側に配置

### 典型的な配置パターン

```tsx
// app/providers.tsx
"use client";

import { ThemeProvider } from "some-ui-lib";

export function Providers({ children }: { children: React.ReactNode }) {
  return <ThemeProvider>{children}</ThemeProvider>;
}
```

```tsx
// app/layout.tsx（Server Component のまま）
import { Providers } from "./providers";

export default function RootLayout({ children }: any) {
  return (
    <html lang="ja">
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

これで **ルートレイアウトは Server**、Providers の中の children は **Server のまま**でいける、という美しい構造に。

## 3. shadcn/ui 詳しく

shadcn/ui は「**npm install するライブラリ」ではなく「コードを生成する CLI」**です。

### メリット

- 中身が**自分のコード**になるので、自由にカスタマイズできる
- 不要なコンポーネントは入らない（バンドルサイズ最小）
- アップデートで破壊変更を被らない（自分のリポジトリで管理）

### デメリット

- アップグレードは手動（差分を取り込む）
- 「ライブラリのドキュメントを読む」感覚ではない

### 初期セットアップ

```bash
npx shadcn@latest init
```

- Tailwind の設定
- `components.json`（shadcn の設定ファイル）が作られる
- `lib/utils.ts` に `cn` ユーティリティが置かれる

### コンポーネントを追加

```bash
npx shadcn@latest add button card dialog form input
```

### 使う

```tsx
import { Button } from "@/components/ui/button";
import { Card, CardHeader, CardContent } from "@/components/ui/card";

export default function Page() {
  return (
    <Card>
      <CardHeader>タイトル</CardHeader>
      <CardContent>
        <Button>OK</Button>
      </CardContent>
    </Card>
  );
}
```

## 4. 状態管理ライブラリ

UI 以外でも、グローバル状態が必要になることがあります。

| ライブラリ | 特徴 |
|-----------|------|
| **Zustand** | シンプル、軽量、人気 |
| **Jotai** | アトム単位、細かい制御 |
| **Redux Toolkit** | 大規模アプリ向け、複雑 |
| **TanStack Query** | サーバーステート（API レスポンス）専用、超強力 |

### TanStack Query（Server Components の時代でも有用）

サーバーから取った**クライアント側のキャッシュ**として使うと便利。

```bash
npm install @tanstack/react-query
```

```tsx
// app/providers.tsx
"use client";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { useState } from "react";

export function Providers({ children }: { children: React.ReactNode }) {
  const [client] = useState(() => new QueryClient());
  return <QueryClientProvider client={client}>{children}</QueryClientProvider>;
}
```

## 6. フォーム

### React Hook Form + Zod

```bash
npm install react-hook-form zod @hookform/resolvers
```

```tsx
"use client";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";

const schema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

type FormData = z.infer<typeof schema>;

export function LoginForm() {
  const { register, handleSubmit, formState: { errors } } = useForm<FormData>({
    resolver: zodResolver(schema),
  });
  return (
    <form onSubmit={handleSubmit(data => console.log(data))}>
      <input {...register("email")} />
      {errors.email && <p>{errors.email.message}</p>}
      <input type="password" {...register("password")} />
      <button>送信</button>
    </form>
  );
}
```

### Server Actions と組み合わせ

```tsx
const onSubmit = handleSubmit(async (data) => {
  await createUser(data); // Server Action
});
```

## 8. Server Component で使えるかチェック

サードパーティライブラリを入れる前に、**Server Component で使えるか** を見ましょう。

- `useState`、`useEffect` を内部で使っている → **Client 専用**
- `'use client'` が無いコンポーネントだけ → **Server でも OK**

公式ドキュメントに「App Router compatible」「Client Components」などの記載があるはず。

## 9. バンドルサイズに注意

サードパーティをたくさん入れると **JS バンドルが膨らむ**ので注意。

### 対策

- **動的 import**（コード分割）

```tsx
import dynamic from "next/dynamic";

const HeavyComponent = dynamic(() => import("./HeavyComponent"), {
  ssr: false, // クライアントでのみ読み込む
  loading: () => <p>読み込み中...</p>,
});
```

- **必要な関数だけ import**（tree shake が効くライブラリを選ぶ）

```ts
// ❌ ライブラリ全体を import
import _ from "lodash";

// ✅ 必要な関数だけ
import debounce from "lodash/debounce";
```

## 10. つまずきポイント

### Q. ライブラリを入れたら「`useState` is not a function」エラー

→ そのコンポーネント（または import 元のファイル）に `"use client"` を追加。

### Q. ハイドレーションエラー（`hydration mismatch`）

→ サーバーとクライアントで描画結果がズレている可能性。日付・乱数・`window` 依存のコードに注意。

### Q. SSR でだけ動かないコンポーネント

→ `dynamic` の `ssr: false` でクライアントのみに。

### Q. shadcn/ui のテーマが効かない

→ `globals.css` に Tailwind の theme 変数が入っているか確認。

### Q. Tailwind を使ったライブラリが動かない

→ そのライブラリのソースファイルが Tailwind の `content` に含まれているか確認。

## まとめ

- **shadcn/ui + Tailwind** が 2026 年現在の鉄板
- ライブラリは多くが Client Component 前提。**Provider を Client、children を Server** の構造で
- 状態管理は **Zustand** か **TanStack Query** から
- フォームは **React Hook Form + Zod**、Server Actions と組み合わせも◎
- バンドルサイズに注意、不要に重いライブラリは避ける
