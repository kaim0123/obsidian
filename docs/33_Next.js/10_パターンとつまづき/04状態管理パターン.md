# 状態管理パターン（旧教科書・統合）

直下の教科書調ノート [[08-state-management|状態管理（旧・直下）]] のテーマを、**App Router 前提**で整理し直したものです。
「どこで状態を持つか」を Server / Client / サーバー外のソースに分解すると、迷いどころが減ります。

関連: [[03_レンダリングと境界/01Server-ComponentsとClient-Components]]／[[04_データ取得とキャッシュ/01fetchとキャッシュ境界]]／[[02クエリと検索パラメータ]]

---

## 1. まず分類する：3 種類の「状態」

| 種類 | 典型例 | 置き場所の目安 |
|------|--------|----------------|
| **サーバー由来のデータ** | API・DB の一覧・詳細、ユーザー権限など | Server Component で `fetch`／キャッシュ。クライアントで購読が必要なら SWR／TanStack Query |
| **UI・クライアント専用** | モーダルの開閉、フォーム入力中、ドラッグ中 | `"use client"` 内の `useState`／リデューサ／小型ストア |
| **アプリ全体で共有するクライアント状態** | テーマ、カート、クライアント側セッション表示 | Context／Zustand／Redux 等（Provider は Client 側） |

ポイント: **サーバー状態を無理にグローバルストアに載せない**。
Next.js は RSC と `fetch` のキャッシュでサーバー状態の大部分を単純化できます。

---

## 2. App Router と Client 境界

- **`useState`／`useContext`／Zustand／Redux** はブラウザ上の対話モデルです。**Client Component でのみ**意味があります。
- **Provider を置くコンポーネント**自体が `children` に RSC を含むため、その Provider を包むファイルは **`"use client"` が必要**です。

```tsx
// app/providers.tsx
"use client";

import type { ReactNode } from "react";
import { ThemeProvider } from "./theme-context";

export function AppProviders({ children }: { children: ReactNode }) {
  return <ThemeProvider>{children}</ThemeProvider>;
}
```

```tsx
// app/layout.tsx（Server Component のままで OK）
import { AppProviders } from "./providers";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ja">
      <body>
        <AppProviders>{children}</AppProviders>
      </body>
    </html>
  );
}
```

Pages Router 時代の `pages/_app.tsx` で包んでいた処理は、**`app/layout.tsx` + Client の `providers.tsx`** に相当します。

---

## 3. ローカル状態（`useState`）

単一コンポーネントや小さな木の範囲なら **`useState` が第一候補**です。

```tsx
"use client";

import { useState } from "react";

export function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button type="button" onClick={() => setCount((c) => c + 1)}>
      count: {count}
    </button>
  );
}
```

フォームは制御コンポーネント＋1 オブジェクトにまとめる、`useReducer` で複雑化に対応する、というのは Next に限らず React 共通です。

---

## 4. Context（テーマ・軽い共有）

ツリー内で **`useContext` が足りる規模**（テーマ、アクセシビリティ設定など）では Context で十分です。

- Provider を **`"use client"` モジュール**に置く。
- 値が頻繁に変わり下位が広いと再レンダリングコストが乗るため、分割や `useMemo` で安定化する。

認証そのものの設計は [[05_バックエンド統合/02認証とセッションのパターン]]、レイアウト分岐は [[01認証付きレイアウト分岐]] を参照してください。

---

## 5. グローバルストア：Zustand と Redux（RTK）

| | Zustand | Redux Toolkit |
|--|---------|----------------|
| 特徴 | ボイラープレート少なめ・小〜中規模に向く | 大規模・タイムトラベル・厳密なイベントの流れ |
| Provider | 必須ではない（単一ストアの `create`）が、`React.useSyncExternalStore` 利用時も通常は問題なし | `<Provider store={store}>` が必要 |

**どちらも「クライアント上の状態」**です。
サーバーから初期データを渡す場合は、RSC から props で渡すか、`useEffect` でハイド後に読み込むかを用途で選びます（SEO・初回表示が重要なら RSC で渡す）。

Redux の基礎解説は React 側ノート [[../../02_React/【Redux入門】初学者でも理解できるReduxの仕組みを解説します！(Redux Toolkitを使用)|Redux 入門（Redux Toolkit）]] も参照できます。

## 6. サーバー状態：SWR・TanStack Query・RSC の使い分け

- **一覧が RSC で十分**（ユーザー操作で再フェッチしない・URL で表現できる）→ `async` の Server Component で `fetch`。キャッシュ戦略は [[04_データ取得とキャッシュ/01fetchとキャッシュ境界]]。
- **クライアントでインタラクティブに再取得／楽観的更新／ミューテーション後の無効化**が主役 → **TanStack Query** または **SWR** を Client で使う。

```tsx
"use client";

import useSWR from "swr";

const fetcher = (url: string) => fetch(url).then((r) => r.json());

export function useUsers() {
  return useSWR("/api/users", fetcher);
}
```

Route Handler や Server Actions と組み合わせる場合は [[05_バックエンド統合/01Route-Handlers]]、[[04_データ取得とキャッシュ/03Server-Actions（フォーム・ミューテーション）]] を参照してください。

## 7. URL と「状態」

フィルター・ページ番号・タブを URL に載せられるなら **真実のソースを URL にする** と共有可能で SSR とも相性が良いです。
詳しくは [[02クエリと検索パラメータ]]。

---

## 8. よくあるつまずき

1. **`useState` を Server Component で使いたい**
   → 対話が必要な部分だけ Client に切り出す（[[03_レンダリングと境界/01Server-ComponentsとClient-Components]]）。

2. **`localStorage` を初期レンダーで読むとハイド不整合**
   → マウント後にだけ読む、またはサーバー側ではデフォルト固定＋クライアントで上書きなど、ハイド齟齬を設計する。

3. **ストアにサーバー状態を丸ごとコピーして二重管理**
   → 「キャッシュの唯一のソース」が分散しバグりやすい。RSC／Query のキャッシュ戦略側に寄せる。

4. **Provider をサーバーコンポーネントのファイル直下に書いてしまう**
   → Context は Client。`providers.tsx` のように **`"use client"` レイヤを 1 枚挟む**。

## 9. 旧ノートとの対応

[[08-state-management]] の章立て（`useState` → Context → Redux → Zustand → SWR／React Query → カスタムフック・練習問題）は、このノートの構成に読み替え可能です。
コードサンプルのうち **`pages/_app.js` のみの記述**は、このノートの **`app/layout.tsx` + `providers.tsx`** と対応させてください。

---

## まとめ

- **サーバー状態**は RSC＋`fetch`／必要なら Query 系。**クライアント状態**は Client で `useState`〜ストアまで。
- **Provider／Context／Redux／Zustand は Client 境界の設計**が App Router の鍵。
- **URL で表現できる状態は URL に寄せる**と運用が楽。
