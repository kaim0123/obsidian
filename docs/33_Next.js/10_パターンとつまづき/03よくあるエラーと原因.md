# よくあるエラーと原因

開発中に**何度も遭遇する典型エラー**と、その原因・対処をまとめました。
エラーメッセージで Ctrl+F すると素早く該当箇所が見つかります。

---

## 1. ハイドレーションエラー（Hydration mismatch）

### エラー例

```
Hydration failed because the initial UI does not match what was rendered on the server.
```

### 原因

**サーバーで生成した HTML と、クライアントで描画した結果が違う**ときに起こる。

### よくある原因と対処

| 原因 | 対処 |
|------|------|
| `Date.now()`、`Math.random()` を直接使用 | `useEffect` でクライアント側だけで生成 |
| `typeof window !== 'undefined'` で分岐 | `useEffect` で代用 |
| サーバーとクライアントで違う `localStorage` 値 | `useEffect` で初期化 |
| `<p>` の中に `<div>` を入れた | HTML として不正なネスト。修正 |
| 拡張機能（Grammarly 等）が DOM をいじる | `<body>` に `suppressHydrationWarning` |

```tsx
// 例：時刻表示はクライアント側で
"use client";
import { useState, useEffect } from "react";

function Clock() {
  const [time, setTime] = useState<string | null>(null);
  useEffect(() => {
    setTime(new Date().toLocaleTimeString());
  }, []);
  if (!time) return null;
  return <p>{time}</p>;
}
```

## 2. `Error: Event handlers cannot be passed to Client Component props.`

### 原因

**Server Component から Client Component に関数を直接渡そうとした**。

### 対処

- 関数を Server Action にする：

```tsx
// app/page.tsx（Server）
async function handleClick() {
  "use server";
  // サーバーで処理
}
return <ClientButton onClick={handleClick} />;
```

- またはコンポーネント全体を `'use client'` 化

---

## 3. `useState`/`useEffect` is not a function

### 原因

**Server Component で React フックを使った**。

### 対処

ファイルの一番上に `"use client"` を追加。

```tsx
"use client";
import { useState } from "react";
// ...
```

---

## 4. `cookies()` was called outside a request scope

### 原因

`cookies()` / `headers()` を **Server Component / Route Handler / Server Action 以外**で呼んだ。

### 対処

- これらは Server 専用。Client Components や普通の関数の中では使えません。
- もし Client で必要なら、**Server から props で渡す**。

---

## 5. `useSearchParams() should be wrapped in a suspense boundary`

### 原因

`useSearchParams` を使う Client Component が `<Suspense>` で囲まれていない。

### 対処

```tsx
import { Suspense } from "react";

export default function Page() {
  return (
    <Suspense fallback={<p>Loading...</p>}>
      <ClientComponentUsingSearchParams />
    </Suspense>
  );
}
```

## 6. ECONNREFUSED / fetch failed

### 原因

- 外部 API のサーバーが落ちている
- ホスト名 / ポート / プロトコルが間違っている
- 開発時、自分の `localhost` を SSR から fetch しようとして失敗

### 対処

- URL を確認
- ローカル開発時：相対パスではなくフルパス（`http://localhost:3000/...`）にする
- もしくは `await fetch` ではなく内部関数を直接呼ぶ（同じプロセスなら不要）

---

## 7. `Image` の width / height 関連

### エラー

```
Image with src "/foo.jpg" is missing required "width" property.
```

### 対処

- リモート画像は `width`/`height` 必須
- ローカル画像は `import` すれば自動取得
- `fill` を使う場合は親に `position: relative`

---

## 8. リモート画像が表示されない

### エラー

```
Invalid src prop on `next/image`, hostname "..." is not configured under images in your `next.config.js`
```

### 対処

`next.config.ts` の `images.remotePatterns` に追加：

```ts
images: {
  remotePatterns: [
    { protocol: "https", hostname: "example.com" },
  ],
}
```

設定後に **dev サーバーの再起動**が必要。

---

## 9. `Module not found: Can't resolve '...'`

### 原因

- 依存パッケージ未インストール
- import パスの typo
- `tsconfig.json` の `paths` 設定不足
- 大文字小文字違い（Linux 本番でだけ起こりがち）

### 対処

- `npm install <名前>` を確認
- VSCode で「Go to definition」が動くか確認
- 大文字小文字も含めて完全一致しているか

---

## 10. `Element type is invalid` / `default export missing`

### 原因

- コンポーネントを `export default` し忘れ
- `import` でデフォルトと名前付きを混同

### 対処

```ts
// ✅ デフォルト export
export default function MyComp() { ... }
import MyComp from "./MyComp";

// ✅ 名前付き export
export function MyComp() { ... }
import { MyComp } from "./MyComp";
```

---

## 11. ハイドレーションミスマッチ：日付フォーマット

### 原因

`new Date().toLocaleString()` は**ロケールによって違う**ため、サーバーとクライアントで違う結果になる。

### 対処

- フォーマットを固定する（`date-fns` 等）
- または `useEffect` でクライアント側だけ表示

---

## 12. `next.config` の設定が反映されない

### 原因

- 設定ファイルの拡張子（`.ts`/`.js`/`.mjs`）が間違っている
- 開発サーバーを再起動していない
- 構文エラーがあって読み込めていない

### 対処

- 1 個だけにする（重複してると上書き合戦）
- `npm run dev` を完全に止めて再起動

---

## 13. 環境変数が undefined

### 原因

- `.env.local` に書いたが、開発サーバー再起動してない
- `NEXT_PUBLIC_` を付け忘れ（クライアントで使いたい場合）
- Vercel 上に環境変数を登録していない

### 対処

- 開発：再起動
- 本番：Vercel ダッシュボードで設定 → 再デプロイ
- 機密値に `NEXT_PUBLIC_` は付けないこと（漏れる）

---

## 14. ビルドで `Static generation failed`

### 原因

- `generateStaticParams` 内で外部 API がエラー
- 静的生成しようとしたページで `cookies()` を呼んだ
- `dynamic = "force-static"` のページでクライアント情報を読んでいる

### 対処

- API 側のエラーを確認
- 動的扱いにすべきページなら `dynamic = "force-dynamic"` に
- `generateStaticParams` の戻り値を `[]` にすればビルド時生成をスキップ可能

---

## 15. `Error: dynamic server usage`

### 原因

静的にしたいページで `cookies()` / `headers()` / `searchParams` を使った。

### 対処

- 動的にしてもよいなら：`export const dynamic = "force-dynamic"`
- 静的のままにしたいなら：その関数を呼んでいる Client Component に分離する

---

## 16. CORS エラー

### エラー

```
Access to fetch at '...' from origin '...' has been blocked by CORS policy
```

### 原因

外部 API がクロスオリジンを許可していない。

### 対処

- **Server Component / Route Handler から呼ぶ**（CORS は適用されない）
- 自分で API を中継する：`/api/proxy/...` を作って、そこ経由で呼ぶ
- 相手側に CORS 設定を依頼

---

## 17. `Request body is too large`

### 原因

Vercel のデフォルト制限（4.5MB）を超えた。

### 対処

- 小さな chunk に分割してアップロード
- 大ファイルは S3 等の Pre-signed URL を使い、クライアントから直接アップ
- Vercel Blob などの専用サービスを使う

---

## 18. 開発時：HMR が効かない

### 原因

- `node_modules` の中のファイルを直接編集
- ファイルが Next.js の監視対象外（`pages/api` の外で API 風）
- `next dev` の Webpack/Turbopack が壊れた

### 対処

- `.next/` を削除して再起動
- `npm run dev -- --turbo` で Turbopack を試す（または逆に外す）
- ファイル監視数を増やす（Linux で `inotify` の上限に引っかかるケース）

---

## 19. `Functions Reached Maximum Duration`

### 原因（Vercel）

Hobby は **10 秒**、Pro は **60 秒**でタイムアウト。

### 対処

- 重い処理を非同期 / 分割
- バッチ処理は Vercel Cron や Queue サービス（Inngest, Trigger.dev 等）に逃がす
- ストリーミングで部分応答を返す

---

## 20. App Router の `params` でエラー

### エラー

```
Route "/[slug]" used `params.slug`. `params` should be awaited before using its properties.
```

### 原因

Next.js 15 以降、`params` は Promise になった。

### 対処

```tsx
// ❌ 古い書き方
export default function Page({ params }: { params: { slug: string } }) {
  const { slug } = params;
}

// ✅ 新しい書き方
export default async function Page({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
}
```

## 21. `revalidate` してもキャッシュが古いまま

### 原因

- 該当 `fetch` にタグを付けていない
- アクセスが無くて再生成が起きていない
- CDN（Vercel Edge）側のキャッシュも別途存在

### 対処

- `fetch(..., { next: { tags: [...] } })` でタグ付け
- `revalidateTag` でなく `revalidatePath` で広めに無効化してみる
- CDN キャッシュは `revalidateTag` 連動するが、自前ホストなら別途対応

---

## 22. Edge Runtime での Node API エラー

### エラー

```
Module not found: Can't resolve 'fs' / 'crypto' / 'path' / ...
```

### 原因

`middleware.ts` や Edge Runtime の Route Handler で Node 専用 API を使った。

### 対処

- Middleware では Node API を使わない
- 必要なら Runtime を Node に：

```ts
export const runtime = "nodejs"; // route.ts の冒頭
```

---

## 23. `Invariant: attempted to hard navigate to the same URL`

### 原因

`router.push` などで現在のページに遷移しようとして競合。

### 対処

- 同じ URL なら `router.refresh()` を使う
- 条件分岐で「URL が変わるときだけ push」にする

---

## 24. 大きい `_next/static` のキャッシュが消えない

### 原因

ブラウザに長期キャッシュされている（Next の静的アセットは immutable で 1 年キャッシュ）。

### 対処

- 通常はビルドのたびにファイル名にハッシュが付くので**自動で別ファイル扱い**になり、特に問題は起きない
- 開発中なら DevTools で「Disable cache」を ON

---

## 25. PostCSS / Tailwind 関連

| エラー | 原因 / 対処 |
|--------|------------|
| `cannot find module @tailwindcss/postcss` | Tailwind v4 系。`npm install -D @tailwindcss/postcss` |
| Tailwind クラスが効かない | `content` に対象パスが含まれていない |
| `@tailwind base;` が動かない | v4 では `@import "tailwindcss";` に変更 |

## 26. 「とりあえず試す」トラブルシュート手順

### Step 1：シンプルに

```bash
rm -rf .next
npm run dev
```

### Step 2：依存をクリーン

```bash
rm -rf node_modules package-lock.json
npm install
```

### Step 3：バージョンを固定 / 更新

```bash
npm install next@latest react@latest react-dom@latest
```

### Step 4：エラーをそのまま検索

エラーメッセージを Google にコピペすると、だいたい同じ問題が出てきます。

### Step 5：再現最小コードを作る

別プロジェクトで再現すれば、自分のコード起因か Next.js のバグかが判別できる。

---

## まとめ

- ハイドレーションエラーは **Server と Client で結果が違う**ことが原因
- Server / Client の境界違反（`useState` を Server で使う、`cookies()` を Client で）は頻出
- v15+ の `params` / `searchParams` / `cookies()` は **Promise / async** 化された
- 困ったら **`.next` 削除 → 依存再インストール → エラー検索**
- 本番でしか出ないエラーには **大文字小文字** や **環境変数漏れ**が多い
