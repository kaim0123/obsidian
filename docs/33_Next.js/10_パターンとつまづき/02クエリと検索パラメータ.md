# クエリと検索パラメータ

URL の `?key=value` 部分を **クエリ文字列**（または検索パラメータ）と呼びます。
Next.js では、Server / Client それぞれで取り方が違うので、整理しておきましょう。

---

## 1. URL の構造

```
https://example.com/blog?page=2&category=react#section-1
                    ↑     ↑                    ↑
                 pathname  searchParams      hash
```

| 部位 | 用語 | 例 |
|------|------|-----|
| `https://example.com` | origin | |
| `/blog` | pathname | |
| `?page=2&category=react` | search / searchParams | `page=2`, `category=react` |
| `#section-1` | hash | アンカー |

---

## 2. Server Component で取る

`page.tsx` の引数として `searchParams` を受け取れます（**Promise**！）。

```tsx
// app/search/page.tsx
export default async function Search({
  searchParams,
}: {
  searchParams: Promise<{ q?: string; page?: string }>;
}) {
  const { q, page } = await searchParams;
  const pageNum = Number(page ?? 1);
  const results = await searchPosts(q, pageNum);

  return (
    <div>
      <p>キーワード: {q}</p>
      <p>ページ: {pageNum}</p>
      <ul>{results.map(...)}</ul>
    </div>
  );
}
```

### 重要：`searchParams` を使うと**動的レンダリング**になる

`searchParams` を読んだ時点で、そのページは静的生成できなくなり、毎リクエストで動的に処理されます。
つまり、**「検索条件で結果が変わるページ」は自然に動的扱い**になります。

### 配列の値（同じキーが複数）

```
?tag=a&tag=b
```

```ts
const { tag } = await searchParams; // string | string[] | undefined
```

複数値の可能性があるので、型注釈は `string | string[]` にするか、`Array.isArray` で分岐。

## 3. Client Component で取る

`useSearchParams` フックを使います。

```tsx
"use client";
import { useSearchParams } from "next/navigation";

export default function FilterUI() {
  const searchParams = useSearchParams();
  const q = searchParams.get("q");
  const page = searchParams.get("page") ?? "1";

  return <p>{q} / {page}</p>;
}
```

### 値の取り方

```ts
searchParams.get("q");          // string | null
searchParams.getAll("tag");     // string[]
searchParams.has("foo");        // boolean
searchParams.entries();         // [key, value][]
```

## 4. クエリを書き換える（Client Component）

`useRouter` と組み合わせて、クエリを更新しつつ URL を変更します。

```tsx
"use client";
import { useRouter, useSearchParams, usePathname } from "next/navigation";

export function PageNav() {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();

  function setPage(n: number) {
    const params = new URLSearchParams(searchParams);
    params.set("page", String(n));
    router.push(`${pathname}?${params}`);
  }

  return (
    <>
      <button onClick={() => setPage(1)}>1</button>
      <button onClick={() => setPage(2)}>2</button>
    </>
  );
}
```

### `router.push` vs `router.replace`

| メソッド | 履歴への追加 |
|---------|-------------|
| `push` | 追加（戻るで前ページへ） |
| `replace` | 上書き（戻るで前ページへ飛ばない） |

検索条件の変更は `replace` が UX 的に親切なことが多い。

## 5. フォーム + クエリの典型

検索フォームから URL のクエリを更新するパターン。

```tsx
"use client";
import { useRouter, usePathname } from "next/navigation";

export function SearchForm({ defaultValue }: { defaultValue: string }) {
  const router = useRouter();
  const pathname = usePathname();

  function action(formData: FormData) {
    const q = formData.get("q") as string;
    const params = new URLSearchParams();
    if (q) params.set("q", q);
    router.push(`${pathname}?${params}`);
  }

  return (
    <form action={action}>
      <input name="q" defaultValue={defaultValue} />
      <button>検索</button>
    </form>
  );
}
```

## 6. デバウンス（入力中の連続更新を抑制）

```tsx
"use client";
import { useEffect, useState } from "react";
import { useRouter, usePathname } from "next/navigation";

export function LiveSearch({ defaultValue }: { defaultValue: string }) {
  const [value, setValue] = useState(defaultValue);
  const router = useRouter();
  const pathname = usePathname();

  useEffect(() => {
    const id = setTimeout(() => {
      const params = new URLSearchParams();
      if (value) params.set("q", value);
      router.replace(`${pathname}?${params}`);
    }, 300);
    return () => clearTimeout(id);
  }, [value, router, pathname]);

  return <input value={value} onChange={e => setValue(e.target.value)} />;
}
```

## 7. 動的セグメント（`params`）と検索パラメータ（`searchParams`）の違い

```
/blog/hello?page=2
       ↑       ↑
     params  searchParams
```

| 種別 | 取り方（Server） | 取り方（Client） |
|------|----------------|------------------|
| `params`（動的セグメント） | `await params` | `useParams()` |
| `searchParams`（クエリ文字列） | `await searchParams` | `useSearchParams()` |

---

## 8. クエリで状態管理するメリット

UI の状態（フィルタ、ソート、ページ番号、開いているタブなど）を**URL に持たせる**と：

- ✅ リロードしても状態が消えない
- ✅ 共有できる（URL を渡せば同じ画面）
- ✅ ブラウザの戻る/進むが効く
- ✅ サーバー側で初期状態を取れる（Server Component に渡る）

`useState` だけで管理するより、ずっと UX が良くなることが多い。

---

## 9. `<Link>` でクエリ付きリンク

```tsx
<Link href={`/search?q=${encodeURIComponent(q)}`}>検索</Link>
<Link href={{ pathname: "/search", query: { q, page: 2 } }}>...</Link>
```

オブジェクト記法だとエンコードが自動的に行われて安全。

## 10. 検索条件の永続化（URL + LocalStorage）

両方使うパターン：

- 共有や戻るは URL
- 「次回開いたとき自動復元」は LocalStorage

```tsx
"use client";
import { useEffect } from "react";
import { useSearchParams, useRouter, usePathname } from "next/navigation";

const KEY = "lastSearch";

export function FilterPersist() {
  const router = useRouter();
  const pathname = usePathname();
  const params = useSearchParams();

  // 1. URL に何もなければ LocalStorage から復元
  useEffect(() => {
    if (params.size === 0) {
      const saved = localStorage.getItem(KEY);
      if (saved) router.replace(`${pathname}?${saved}`);
    }
  }, []);

  // 2. URL が変わったら LocalStorage に保存
  useEffect(() => {
    localStorage.setItem(KEY, params.toString());
  }, [params]);

  return null;
}
```

## 11. つまずきポイント

### Q. `searchParams.q` で undefined になる

→ `await searchParams` していますか？v15+ は Promise です。

### Q. `useSearchParams()` の戻り値で `set` ができない

→ `URLSearchParams` を新しく作って書き換える必要あります（`new URLSearchParams(searchParams)`）。

### Q. クエリを変えても画面が更新されない

→ `router.refresh()` を呼ぶ、または `Link` を使うと自動更新。

### Q. Server Component で `searchParams` を使ったらビルドが遅い

→ `searchParams` を使うと動的になる＝静的生成不可。これは仕様。
キャッシュ可能なら Client 側で `useSearchParams` を使う構成に。

### Q. クエリが文字化け

→ `encodeURIComponent` を使う、または `URLSearchParams` 経由で。

### Q. `useSearchParams()` が `<Suspense>` 必要と警告される

→ Next.js 14 以降、`useSearchParams` を使う Client Component は `<Suspense>` で囲む必要あります。

```tsx
import { Suspense } from "react";

export default function Page() {
  return (
    <Suspense>
      <FilterUI />
    </Suspense>
  );
}
```

## まとめ

- Server Component：**`await searchParams`**、自動で動的レンダリング
- Client Component：**`useSearchParams()`** + **`useRouter()`** で書き換え
- 動的セグメント `params` とは別物
- 状態を **URL に持たせる**と UX 大幅向上
- `useSearchParams` を使う Client は **`<Suspense>`** 必須
