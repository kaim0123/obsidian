# 認証付きレイアウト分岐

「ログインページはサイドバーなし、ダッシュボードはサイドバーあり」のように、
**URL によって全体レイアウトを切り替えたい**ケースは超頻出です。

App Router では **ルートグループ（`(name)`）** を使うのが定石です。

---

## 1. 一般的な要件

```text
/                 ← トップ（共通レイアウト）
/about            ← 共通レイアウト
/login            ← ログインページ（ヘッダー・フッター無し）
/signup           ← 同上
/dashboard        ← サイドバーあり
/dashboard/posts  ← サイドバーあり
/settings         ← サイドバーあり
```

これを 1 つのルートレイアウトで分岐させようとすると、URL を見て条件分岐するハメに…。
ルートグループを使えば**フォルダを分けるだけ**でレイアウトが変わります。

---

## 2. 解決策：ルートグループでレイアウトを分ける

### フォルダ構造

```text
app/
├── layout.tsx                  ← 最低限の <html>/<body> だけ
├── (marketing)/
│   ├── layout.tsx              ← ヘッダー + フッター
│   ├── page.tsx                → "/"
│   ├── about/page.tsx          → "/about"
│   └── pricing/page.tsx        → "/pricing"
├── (auth)/
│   ├── layout.tsx              ← 中央寄せの authシンプルレイアウト
│   ├── login/page.tsx          → "/login"
│   └── signup/page.tsx         → "/signup"
└── (dashboard)/
    ├── layout.tsx              ← サイドバー + 認証チェック
    ├── dashboard/page.tsx      → "/dashboard"
    └── settings/page.tsx       → "/settings"
```

### ルートレイアウト

```tsx
// app/layout.tsx
import "./globals.css";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ja">
      <body>{children}</body>
    </html>
  );
}
```

### 公開ページ用

```tsx
// app/(marketing)/layout.tsx
import Link from "next/link";

export default function MarketingLayout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <header className="border-b p-4">
        <nav className="flex gap-4">
          <Link href="/">Home</Link>
          <Link href="/about">About</Link>
          <Link href="/pricing">Pricing</Link>
          <Link href="/login" className="ml-auto">Login</Link>
        </nav>
      </header>
      <main className="mx-auto max-w-5xl p-8">{children}</main>
      <footer className="border-t p-4 text-center text-sm">© 2026 My Site</footer>
    </>
  );
}
```

### 認証ページ用

```tsx
// app/(auth)/layout.tsx
export default function AuthLayout({ children }: { children: React.ReactNode }) {
  return (
    <main className="flex min-h-screen items-center justify-center bg-gray-50">
      <div className="w-full max-w-md rounded-lg bg-white p-8 shadow">
        {children}
      </div>
    </main>
  );
}
```

### ダッシュボード用（認証チェック付き）

```tsx
// app/(dashboard)/layout.tsx
import { redirect } from "next/navigation";
import { auth } from "@/lib/auth";
import Sidebar from "./_components/Sidebar";

export default async function DashboardLayout({ children }: { children: React.ReactNode }) {
  const session = await auth();
  if (!session) redirect("/login");

  return (
    <div className="flex min-h-screen">
      <Sidebar user={session.user} />
      <main className="flex-1 p-8">{children}</main>
    </div>
  );
}
```

これで **配下のすべてのページに自動で認証チェック**がかかります。
ページ側で個別にチェックする必要はありません（ただし重要な操作は念のため二重チェック推奨）。

## 3. 共通の認証ヘルパ

ルートグループ + Layout だけでも実用できますが、ヘルパを作っておくと安心。

```ts
// lib/auth.ts
import { cookies } from "next/headers";
import { redirect } from "next/navigation";
import { jwtVerify } from "jose";

const secret = new TextEncoder().encode(process.env.AUTH_SECRET);

export async function auth() {
  const token = (await cookies()).get("session")?.value;
  if (!token) return null;
  try {
    const { payload } = await jwtVerify(token, secret);
    return { user: { id: payload.sub as string } };
  } catch {
    return null;
  }
}

export async function requireAuth() {
  const session = await auth();
  if (!session) redirect("/login");
  return session;
}
```

## 4. 「ログイン後に元のページに戻したい」

```tsx
// app/(dashboard)/layout.tsx
import { redirect } from "next/navigation";
import { headers } from "next/headers";

export default async function DashboardLayout({ children }: any) {
  const session = await auth();
  if (!session) {
    const path = (await headers()).get("x-pathname") ?? "/dashboard";
    redirect(`/login?from=${encodeURIComponent(path)}`);
  }
  return <>...</>;
}
```

`x-pathname` を Middleware で付与しておくと、現在のパスを取れる：

```ts
// middleware.ts
import { NextResponse } from "next/server";

export function middleware(request) {
  const res = NextResponse.next();
  res.headers.set("x-pathname", request.nextUrl.pathname);
  return res;
}
```

## 5. ロールごとに分岐

「admin だけ /admin が見れる」など。

```text
app/
└── (dashboard)/
    ├── (member)/
    │   └── dashboard/page.tsx       → /dashboard
    └── (admin)/
        ├── layout.tsx               ← admin チェック
        └── admin/page.tsx           → /admin
```

```tsx
// app/(dashboard)/(admin)/layout.tsx
import { auth } from "@/lib/auth";
import { redirect } from "next/navigation";

export default async function AdminLayout({ children }: any) {
  const session = await auth();
  const user = await db.users.findUnique({ where: { id: session?.user.id } });
  if (user?.role !== "admin") redirect("/dashboard");
  return <>{children}</>;
}
```

ルートグループは**入れ子にできる**ので、より細かい権限分岐が可能です。

## 6. ヘッダーをページごとに少し変えたい

「同じ `(marketing)` でも、`/pricing` だけ CTA ボタンを表示したい」など、
ページ側から Layout のヘッダーを微調整したい場合。

### A. Slot（並列ルート）を使う

```text
app/
└── (marketing)/
    ├── layout.tsx        ← children と @cta を受ける
    ├── page.tsx          → "/"
    ├── @cta/
    │   ├── default.tsx   ← 通常は何も表示しない
    │   └── pricing/page.tsx ← /pricing 時に表示
    └── pricing/page.tsx  → "/pricing"
```

### B. シンプルに Conditional rendering

子コンポーネントから親に状態を伝える設計は複雑になりがちなので、
**「ヘッダーを Client Component にして `usePathname()` で分岐」**が手っ取り早い。

```tsx
// app/(marketing)/_components/Header.tsx
"use client";
import { usePathname } from "next/navigation";

export default function Header() {
  const pathname = usePathname();
  return (
    <header>
      ...
      {pathname === "/pricing" && <button>無料トライアル</button>}
    </header>
  );
}
```

## 7. アンチパターン

### ❌ ルートレイアウトで全部分岐

```tsx
// app/layout.tsx
export default function RootLayout({ children }: any) {
  // pathname が /login かどうかで…（このやり方は破綻する）
  return <>{children}</>;
}
```

`layout.tsx` は Server Component。`usePathname()` は使えませんし、URL ごとに分岐するロジックを 1 か所に集めるとすぐ崩壊します。

### ❌ Middleware だけで認証

```ts
// middleware.ts で認証チェック → 通すだけ
```

Middleware は Edge Runtime で軽量なゲートにすぎません。**実データのアクセス制御は Layout や Server Component で**やりましょう。

### ❌ クライアント側で認証分岐

```tsx
"use client";
const { data: session } = useSession();
if (!session) router.push("/login");
```

これだと **ページ表示後にリダイレクト**されるので、ちらつきます。
Server Component の Layout で `redirect()` を呼べば、HTML が返る前に遷移完了します。

## 8. つまずきポイント

### Q. ルートグループのフォルダ名が URL に出てしまった

→ `(name)` ではなく `（name）`（全角括弧）になっていませんか？

### Q. ネストしたグループでレイアウトが二重に入る

→ それが正しい挙動です。`(dashboard)/layout.tsx` の中に `(admin)/layout.tsx` が入ります。

### Q. Middleware と Layout どっちで認証する？

→ **両方**やるのが安全。Middleware は軽い振り分け、Layout で本格チェック。

### Q. クライアント側で「ログイン中ならボタン非表示」にしたい

→ Server Component で session を取って prop として Client に渡すのが一番シンプル。

### Q. `redirect` でリダイレクトしたら React の例外が出た

→ try/catch で囲んでいませんか？`redirect` は内部で例外を投げる仕組みなので、catch すると無効化されます。

---

## まとめ

- 認証要 / 不要を **ルートグループ `(name)`** で分ける
- それぞれの `layout.tsx` で**サイドバー有無・認証チェック**を切り替え
- 認証チェックは Server Component の Layout で **`redirect`** が王道
- **Middleware は補助、Layout で本格チェック**の二段構え
- Client 側でリダイレクトはチラつきの原因
