# `use cache`（Next.js 16 前後・統合ノート）

Next.js でのキャッシュ指定は、`fetch` のオプション（`cache` / `revalidate` / `tags` など）で細かく扱える一方、コード上 **`"use cache"` ディレクティブ**で「キャッシュ単位」を明示できる流れがあります（資料上は Next.js 16 入門コンテンツをベース）。

---

## 1. "use cache" が担うこと

- **主にデータ取得の関数など**、`"use cache"` を付けるとそのスコープの結果が **サーバー側データキャッシュ**の対象になりやすくなる。
- **`async` 関数内**での利用が前提となる説明があります（ディレクティブの詳細・制約はバージョンのドキュメントに従ってください）。
- **ファイル全体**に付けると「ファイル全体がキャッシュ対象」の単位にもできるが、資料では **関数単位**の利用が主とされています。
- 「キャッシュ」とは取得結果をサーバー側に置き、繰り返しのコストを下げる、という単純化でよいです（ISR に近い挙動の説明とセットで説明されています）。

---

## 2. 設定：キャッシュコンポーネント（Cache Components）

`"use cache"` を実際に使うには、`next.config` 側で **キャッシュコンポーネント（撮影資料では Cache Components）** を有効化する必要があります。**オフのままでは従来寄りの挙動**で、`"use cache"` を試しても期待どおりにならない、という整理です。具体的なキー名は **`next.config` の現在版**を確認してください。

---

## 3. Suspense と PPR 前提になる「エラー」（重要）

キャッシュコンポーネント有効時は、資料・デモによれば次のような制約があります。

**キャッシュされていないデータ取得が `Suspense` の外から呼ばれる**とエラーになり、コンパイル結果や実行時ガイダンスで是正を促されます。意図は **PPR（静的と動的部分の分離）を設計として強める**ためです。

対処は主にどちらかです。

| 対処 | 説明 |
|------|------|
| **`"use cache"` でフェッチ関数をキャッシュ対象にする** | 一覧 ISR 気味・更新頻度に合わせやすい |
| **キャッシュしないなら、その部分だけ `Suspense` で包む** | 「常に最新」寄り。**`fallback`** でスケルトン等を出せる |

従来（v14/v15 寄り）は、ページに SSR が混ざっても **ページ全体が動的側に寄る**説明がありましたが、このモデルでは **同一ページ内で静的／動的分離** がビルド出力（例：**Partial Prerender** 表記など）にも現れる形で説明されます。

---

## 4. キャッシュの寿命：`cacheLife()`

単に `"use cache"` だけの場合でも、資料では「デフォルトで **約 15 分間隔の再検証**」「有効期限のような概念」など ISR 様の時間軸があります。細かく指定するために **`cacheLife()`** が出てくる説明があります（`'days'` 等のプリセット例）。具体的な名前と値は **公式ドキュメントの一覧** を正とすること。

資料上のニュアンスとして、「完全に不変の SSG」の捉え方は長期 TTL でも **再検証前提**に読み替えられつつある、とも述べられています。**常に最新が必須**なら、`Suspense` 内での SSR／ストリーミング側へ寄せる、という結論にもつながります。

---

## 5. タグと無効化・更新：`cacheTag()` / `revalidateTag()` / `updateTag()`

ミューテーション後に一覧が古いまま、というときの典型的な運用です。

| API | メモ（資料ベース） |
|-----|-------------------|
| **`revalidatePath`** | 経路単位の再検証。タグ必須ではないケースもある。**投稿直後すぐ一覧を新鮮に**したい用途で有効、という説明があります。 |
| **`cacheTag()`** | キャッシュにラベルを付ける。一覧・詳細など **複数エントリを一括で追跡したいとき** に同じタグを貼る。 |
| **`revalidateTag()`** | **ISR に近く**、いったん古い結果を見せ、その裏で再検証、という側面の説明がある。**即時反映より「追いつくだけ」の時**との対比があります。 |
| **`updateTag()`** | **即時に関連キャッシュを更新したいとき** に選ぶ、という対比があります。 |

---

## 6. `refresh()` について

資料では **サーバーアクション向けに `refresh()`** が触れられます。**「キャッシュされていないデータ」を最新状態に反映したい**文脈（通知バッジ、リアルタイム統計など）で紹介され、**キャッシュ済みコンテンツを即無効化する代替にはならない**点にも注意されています。**SSR（`Suspense` 側）ならミューテーション直後に自然に反映される**、という対比にもつながります。

---

## 7. 開発ヒント：`next dev` と本番への近さ

ルーターキャッシュなど **本番に近い挙動は `next build` 後に `npm run start`** で確認する、という整理もありました。

また **next-devtools-mcp** は、アップグレード補助・設定・ドキュメント検索などの支援ツールとして紹介されています。**キャッシュヒット率そのものは別途（ブラウザのパフォーマンスツールなど）**で確認する話題もありました。
