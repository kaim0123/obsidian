# `lib/` と `app/` の置き方の補足

Next.js の App Router では **`app/` は「ルートとレイアウトの規約」**、**`lib/` は慣習としての共有コード置き場**です。名前は変更可能ですが、公式ドキュメントや `create-next-app` の説明でも `lib/` がよく登場します。

---

## `app/` に置くもの

`app/` 以下は **フォルダーとファイル名がそのまま URL やレイアウトの振る舞いにつながる**「規約フォルダー」です。

| 種類 | 役割 |
|------|------|
| `page.tsx` / `route.ts` | ページと Route Handler（API） |
| `layout.tsx` / `template.tsx` | 共通枠や再マウント用のテンプレート |
| `loading.tsx` / `error.tsx` / `not-found.tsx` | UI の特殊ファイル |
| ルートグループ `(name)`、`[param]` | URL の整理・動的セグメント |

つまり **「この URL で何が起きるか」を決めるもの** は `app/` に置く、と考えると整理しやすいです。

---

## `lib/` に置くもの

`lib/` は **フレームワークのルーティング規約とは無関係な、再利用コード** をまとめる場所です。典型例は次のようなものです。

| 例 | メモ |
|----|------|
| 日付フォーマット、配列処理などの純関数 | テストと置き換えがしやすい |
| DB クライアントのシングルトン（例: Prisma） | 「複数インポートで接続が増えすぎない」構成と相性が良い |
| バリデーションスキーマ、定数、`fetch` の薄いラッパー | サーバー／クライアントの両方から使うかは別途注意（後述） |

**`lib/` は必須ではありません。** チームが `utils/`、`helpers/` にまとめるなら、その名前で問題ありません。重要なのは **共有ロジックを `page.tsx` と同じファイルに増殖させないこと** と、サーバー専用のコードを Client Component から誤って引っ張らないことです。

---

## `src/` があるときの関係

`create-next-app` で **`Use src/ directory`** を選ぶと、アプリ一式は **`src/` 配下** に寄せられます。このときのイメージは次のとおりです。

```text
my-app/
├── src/
│   ├── app/          ← App Router（規約そのまま）
│   ├── lib/          ← 共有ユーティリティ等（よく並べる）
│   └── …
├── public/
└── package.json
```

- **`src/app`** … ルーティングの本体。
- **`src/lib`** … ルーティングと無関係な共有コード。`@/lib/...` のようにインポートしやすい。

**直下に `lib/` と `src/lib/` を二重につくらない**よう、プロジェクトのどちらか一方に統一するのがおすすめです。

---

## インポートエイリアス `@/` と `lib`

`create-next-app` のデフォルトでは、 **`@/*` がプロジェクトルート側のソースにマップされる**構成が多く、

- **`src/` あり** → 多くは `@/` → `./src/*`
- **`src/` なし** → `@/` → プロジェクトルート（その直下に `app/`, `lib/`）

になります（実際は `tsconfig.json` の `paths` を確認すると確実です）。

例:

```tsx
import { formatDate } from "@/lib/format";
```

`app/` の深い階層からでも、`../../../lib/...` のような相対パスより **`@/` の方が壊れにくく**読みやすいです。

---

## `components` は `app/` と `components/` のどちら？

**どちらでもよく、両方組み合わせる構成もあります。**

| 置き場所 | 向いているとき |
|---------|----------------|
| **`app/` 直下のサブフォルダー**（例: `app/(dashboard)/_components/`） | そのルート専用。ファイルをページのそばに置きたい（コロケーション） |
| **プロジェクトルートまたは `src` 直下の `components/`** | 複数ルートや Storybook などから共通利用 |

UI を「ルート専用」か「共通」かで分けると、後から移動するときも迷いません。

---

## サーバー専用のコードを置くときの注意

`lib/` に **データベース呼び出し・シークレット・サーバーだけで動くライブラリー** を置いた場合でも、 **`"use client"` 付きのコンポーネントから `import` すると、そのモジュールはクライアントバンドルに載る可能性があります**。

避け方の考え方:

- サーバー専用ファイルは名前やコメントで意図を明確にする（例: `lib/server/...`）
- Client 側からは **`props` で渡されたデータだけ** を使う
- Server Actions は別ファイルに切り、`"use server"` の境界で整理する

詳細は [[03_レンダリングと境界/01Server-ComponentsとClient-Components]] や、アプリ内のサーバー構成ノートとあわせて読むと安全です。

---

## ひとことのまとめ

- **`app/`** … URL・レイアウトなど **Next が解釈する規約**。ここだけで「サイトの地図」が決まる。
- **`lib/`（または類似名前）** … **規約と無関係な共有コード**を置く定番ポジション。
- **`src/` を使うなら `src/app` と `src/lib` を並べ、`@/` で安定したインポートにする。**

関連: [[01_前提と環境/03create-next-appと設定ファイル]]（初期フォルダー構成）、[[02_AppRouter/01ファイル規約とURL]]（App Router のファイル規約）。
