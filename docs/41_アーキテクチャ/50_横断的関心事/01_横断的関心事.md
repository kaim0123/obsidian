# 横断的関心事 — 第6部の入口

## この教材の目的

第2〜5部では、**機能をどう分けるか**（層、ドメイン、サービス境界）を中心に学んできました。

第6部では、**どの機能にも関わるが、1つのビジネス機能だけに属さない**設計論題——**横断的関心事 (Cross-Cutting Concerns)**——を扱います。

- 認証・認可の置き方（境界、アイデンティティ）
- 観測性（ログ、メトリクス、トレース）とアーキテクチャ上の接点
- 設定とシークレット、フィーチャーフラグ（概要）

「横断的」とは、**注文・在庫・会計のどの機能にもまたがる**という意味です。  
置き方を間違えると、各所に同じロジックが増えたり、障害時に原因が追えなくなったりします。

この第6部は**概要レベル**です。セキュリティや SRE の専門書の代わりではなく、「アーキテクチャ図を描くときにどこに書くか」を押さえることを目的にしています。

前提として [[レイヤードアーキテクチャ]]、[[05BFFとAPIゲートウェイとグレースフルデグレーデーション]]、[[01品質属性]] を読んでおくとつながりやすくなります。

---

## 1. 横断的関心事とは

**横断的関心事**とは、システムの**複数の部分に共通して必要**な関心事のことです。

| 例 | なぜ「横断的」か |
|----|------------------|
| 認証 | Web API、バッチ、管理画面、すべて「誰が操作しているか」が必要 |
| ログ | どの層・どのサービスでも、障害調査のために記録が必要 |
| 設定 | DB 接続先、外部 API の URL など、多くの部品が参照する |

```
  ┌─────────────────────────────────────────┐
  │  横断的関心事（認証・ログ・設定 …）        │
  ├──────────┬──────────┬──────────┬────────┤
  │  注文     │  在庫     │  会計     │  通知    │
  │  機能     │  機能     │  機能     │  機能    │
  └──────────┴──────────┴──────────┴────────┘
       ↑ すべてに関わるが、どれか1つだけの「業務」ではない
```

[[03アーキテクチャに効く原則]] で学んだ**関心の分離**は、横断的関心事にも当てはまります。  
「各機能にベタ書き」ではなく、**境界を決めて一箇所（または少数の箇所）に集約**するのが基本です。

---

## 2. なぜ第6部を学ぶのか

横断的関心事は、機能要件の一覧には**目立たない**ことが多いです。  
しかし設計を後回しにすると、次のような問題が起きやすくなります。

| 問題 | 典型例 |
|------|--------|
| 重複 | 各 API が独自に JWT を検証し、ルールがバラバラ |
| 漏れ | 新しいエンドポイントだけ認可チェックを忘れる |
| 追跡不能 | ログ形式がサービスごとに違い、障害時にリクエストを辿れない |
| 設定の散乱 | 本番 URL がコードに直書き、環境ごとにビルドし直し |

アーキテクチャの仕事は、「**どこで**」「**誰が**」「**どのルールで**」横断処理を行うかを決めることです。

---

## 3. この第6部の読み方

```
  01_横断的関心事（このノート）
       │
       ├─→ 02 認証・認可 … 誰か・何ができるか、境界の置き方
       │
       ├─→ 03 観測性 … ログ・メトリクス・トレースと設計の接点
       │
       └─→ 04 設定・シークレット・フィーチャーフラグ … 環境と振る舞いの制御
```

**02 → 03 → 04** の順がおすすめです。  
すでに本番運用をしている場合は、03（観測性）から入っても構いません。

---

## 4. 初心者が覚えておきたい3つのこと

1. **認証と認可は別物** — 「誰か」を確かめるのと、「その人が何をしてよいか」は分けて設計する（[[02認可と認証の置き方と境界とアイデンティティ]]）
2. **観測性は後付けより最初から** — ログ形式・トレース ID・メトリクスの置き場所を、図の段階で決めておく（[[03観測性とログとメトリクスとトレースとアーキテクチャ上の接点]]）
3. **シークレットはコードに入れない** — 設定と秘密情報は環境・専用ストアで管理し、機能の ON/OFF はフィーチャーフラグで（[[04設定とシークレットとフィーチャーフラグ]]）
