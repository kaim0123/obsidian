## 詳しい要約

**テーマ：CSR / SSR / SSG / ISR の仕組み・メリットとデメリット・使いどころ**

4つのレンダリングパターンを図解で比較し、どんなプロジェクトにどれを選ぶべきかを解説する動画。インタラクションが多いアプリは CSR、SEO とコンテンツ重視なら SSR、更新がほぼない静的ページは SSG、ときどき更新するブログなどは ISR が向く。Next.js ならページごとに使い分けられるのが強み、というのが結論。

---

### CSR（クライアントサイドレンダリング）

- サーバーは `<div id="app">` だけの **ほぼ空の HTML** を返し、ブラウザが CSS・JavaScript をダウンロードして、`ReactDOM.render` で App コンポーネントを空の div に挿入する。
- **デメリット**：最初に必要な JS をすべて読み込むため **初回読み込みが遅い**。コンポーネントが増えるほど JS も増える。空の HTML なので SEO にも不利。
- **メリット**：2回目以降はサーバーにリクエストせず DOM を差し替えるだけなので **最も高速**。これが **SPA（シングルページアプリケーション）**。
- **向いているもの**：Google マップ、座席予約、ダッシュボードなど、動的でインタラクションが多いアプリ。React は CSR のみ。

### SSR（サーバーサイドレンダリング）

- リクエストのたびにサーバー側で HTML を生成する（**プリレンダリング**）。Next.js 12 以前は `getServerSideProps`、現在は `fetch` に `cache: 'no-store'` を指定。
- **メリット**：構築済みの HTML を返すので **初回読み込みが速い**、端末のスペックに依存しない、クローラーが HTML を巡回しやすく **SEO に強い**。
- **デメリット**：ページ遷移のたびにサーバーでレンダリングするため、2回目以降は CSR より遅くなりやすい。
- **向いているもの**：ブログ、EC サイト、コーポレートサイトなど、コンテンツ重視で SEO 対策が必要なサイト。デジタル庁サイトが当初 Next.js を採用していた（後に PHP に置き換わった）話にも触れている。

### SSG（静的サイト生成）

- **ビルド時** に HTML を生成しておく。Next.js 12 以前は `getStaticProps`、現在は `fetch` に `cache: 'force-cache'`。
- **メリット**：非常に高速で、端末スペックにも依存しない。
- **デメリット**：内容を更新するには再ビルドが必要。
- **向いているもの**：ドキュメント、ヘルプページ、ポートフォリオなど、更新頻度が月1回程度以下のページ。1日1投稿のブログなら SSR か ISR の方がよい。

### ISR（インクリメンタル静的再生成）

- **SSG と SSR のいいとこ取り**。ビルド時にプリレンダリングし、返した HTML をキャッシュして2回目以降はそれを表示する。
- `revalidate`（例：3600 秒）を設定すると、期限切れ後のリクエストをきっかけに裏で再ビルドされる。Next.js 12 は `getStaticProps` の `revalidate`、13 以降は `fetch` の `next: { revalidate }`。
- 時系列の例（revalidate 3600 秒）：
  1. 1800 秒時点のアクセス → キャッシュ（古いデータ）を返す
  2. 3800 秒時点のアクセス → **一度は古いデータを返し**、裏で再ビルド
  3. 次のアクセス → 再生成された最新の HTML を返し、再びキャッシュ
- **デメリット**：期限切れ直後も一度は古いデータが返るため常に最新とは限らない。簡単に使えるのは Vercel でホスティングした場合（他のサービスは仕組みづくりが必要かもしれない、と補足）。
- **向いているもの**：1〜2日に1回投稿するブログ・記事サイト、SNS のプロフィール欄のように、SSR ほど頻繁でないがときどき更新されるページ。

### まとめ

| パターン | 生成タイミング | 強み | 向いている例 |
| --- | --- | --- | --- |
| CSR | ブラウザで実行時 | 2回目以降の操作が最速 | マップ、予約、ダッシュボード |
| SSR | リクエストごとにサーバーで | 初回が速い・SEO に強い | ブログ、EC、コーポレート |
| SSG | ビルド時 | 非常に高速 | ドキュメント、ヘルプ、ポートフォリオ |
| ISR | ビルド時＋定期再生成 | 高速かつ定期的に更新 | 適度に更新するブログ |

- Next.js ではページ単位でレンダリングパターンを使い分けられる（React 単体は CSR のみ）。
- 仕組みを理解すれば、プロジェクトの更新頻度やインタラクションの量に応じて選べるようになる。
