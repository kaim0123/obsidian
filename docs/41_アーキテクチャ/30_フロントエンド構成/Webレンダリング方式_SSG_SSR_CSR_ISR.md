## Webのレンダリング方式（SSG / SSR / CSR / ISR）

フロントエンドの文脈でよく並べられるのは次の4つです。

| 略称 | 正式名（英語） | 一言 |
|------|----------------|------|
| **SSG** | Static Site Generation | ビルド時にHTMLを作る |
| **SSR** | Server-Side Rendering | リクエストのたびにサーバーでHTMLを組み立てる |
| **CSR** | Client-Side Rendering | ブラウザでJavaScriptがHTMLを描画する |
| **ISR** | Incremental Static Regeneration | 静的ページを「後から部分的に更新」する（主にNext.js） |

---

## SSG（Static Site Generation）静的サイト生成

- **いつ** HTMLができるか: **ビルド時**（`npm run build` など）。
- **配信**: できあがったファイルをCDNや静的ホスティングで配る。
- **長所**: 表示が速い、サーバー負荷が小さい、キャッシュしやすい。
- **短所**: データが頻繁に変わるページには不向き（毎回ビルドが必要になりがち）。
- **向く例**: ブログ、ドキュメント、LP、ポートフォリオの固定ページ。

---

## SSR（Server-Side Rendering）サーバーサイドレンダリング

- **いつ** HTMLができるか: **ユーザーのリクエストのたび**（サーバー上）。
- **配信**: サーバー（またはEdge）が毎回（またはキャッシュ戦略付きで）HTMLを返す。
- **長所**: リクエスト時点のデータを反映しやすい、SEOや初回表示の制御がしやすい。
- **短所**: サーバー負荷・レイテンシが増えやすい、実行環境が必要。
- **向く例**: ログイン後の画面、在庫・価格が変わる商品ページ、個人別のダッシュボード。

---

## CSR（Client-Side Rendering）クライアントサイドレンダリング

- **いつ** HTMLが「中身つき」になるか: **ブラウザがJavaScriptを実行したあと**。
- **配信**: 最初は薄いHTML＋大きなJSバンドル。描画はクライアント任せ。
- **長所**: 遷移後のインタラクションが豊かにしやすい、従来のSPAと相性がよい。
- **短所**: 初回表示までにJS読み込みが必要、SEOや低速端末では不利になりやすい。
- **向く例**: 管理画面、チャット、地図アプリなど「アプリ」に近いUI。

※ **ハイドレーション**（サーバーが出したHTMLにクライアントJSが「イベントを付ける」）は、SSR/SSGと組み合わせて語られることが多いです。

---

## ISR（Incremental Static Regeneration）増分静的再生成

- **前提**: まず **SSG と同様に静的ページ** として配る。
- **追加の考え方**: 「このページはビルド時だけでなく、**一定時間ごと**や **再生成のトリガー**で、バックグラウンドで静的ファイルを更新できる」というモデル（代表的には **Next.js** の機能として知られる）。
- **長所**: SSGの速さを保ちつつ、ある程度の更新頻度に対応しやすい。
- **短所**: フレームワーク・ホスティングの対応に依存する。全員が同じ「ISR」という標準仕様があるわけではない。
- **向く例**: 更新はあるが「毎リクエストDB」までは要らない一覧ページ、ニュース一覧など。

---

## ざっくり比較（覚え方）

| 観点 | SSG | SSR | CSR | ISR |
|------|-----|-----|-----|-----|
| HTMLの主な生成タイミング | ビルド時 | リクエスト時 | ブラウザ実行後 | ビルド＋（後から）再生成 |
| 最新データとの相性 | ビルドのたびに反映 | 強い | API次第 | 中〜強（設計による） |
| 本番で常時サーバー処理 | 不要（静的配信可） | 必要 | API次第 | 静的＋再生成基盤 |

---

## Astroとの対応（ざっくり）

- Astroの **デフォルト寄り** は **SSG**（静的にHTMLを出す）。
- **SSR** や **サーバーAPI** はオプションで利用可能。
- **CSR** に近い挙動は、`client:*` で島としてReact/Vue等を動かす部分で起きる。
- **ISR** は Next.js の名前として有名で、Astro単体の「ISRという同名機能」とは別物として理解すると混乱が減ります（似た運用は「再ビルド」「Webhookでデプロイ」などで代替することが多い）。

---

## まとめ

- **SSG** と **SSR** に加え、よくセットで出るのが **CSR** と **ISR** です。
- 迷ったら「**HTMLはいつ・どこで完成するか**」と「**データはどのくらいの頻度で変わるか**」の2軸で選ぶと整理しやすいです。
