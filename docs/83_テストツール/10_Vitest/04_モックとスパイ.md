# 04 — モックとスパイ

この章では、Vitest のモック機能を使って **外部依存（API、DB、時刻、ファイル I/O、他モジュール）** を切り離し、テスト対象のロジックだけに集中する方法を解説します。

---

## なぜモックが必要か

実際のコードでは、関数の中で他の関数を呼んだり、API を叩いたり、ファイルを読んだりします。そのまま単体テストすると：

- **遅い**（ネットワーク、DB への接続）
- **不安定**（外部 API が落ちているとテストも落ちる）
- **再現不能**（「現在時刻」や「乱数」に依存する）
- **副作用が残る**（本番 DB に書き込んでしまう可能性）

これらを避けるため、**依存を偽物（モック）に差し替えて**、テスト対象のロジックだけを検証します。

> **モック (mock)** と **スパイ (spy)** は混同されがちですが、使い分けは次のとおりです。
> - **モック**：呼ばれたときの**返り値や挙動を差し替える**。
> - **スパイ**：元の実装は変えず、**呼ばれた回数や引数を記録**する。
>
> Vitest の `vi.fn()` はどちらとしても使える汎用ツールです。

---

## `vi.fn()` — モック関数を作る

もっとも基本の API です。呼び出し履歴を持つ「記録する関数」を生成します。

```ts
import { it, expect, vi } from 'vitest';

it('vi.fn の基本', () => {
  const fn = vi.fn();

  fn('hello');
  fn('world', 42);

  expect(fn).toHaveBeenCalled();            // 呼ばれたか
  expect(fn).toHaveBeenCalledTimes(2);      // 何回呼ばれたか
  expect(fn).toHaveBeenCalledWith('hello'); // 引数で呼ばれたか
  expect(fn).toHaveBeenLastCalledWith('world', 42);
  expect(fn).toHaveBeenNthCalledWith(1, 'hello'); // 1 回目の呼び出し
});
```

### 返り値を設定する

```ts
const fn = vi.fn();

fn.mockReturnValue(42);                 // 常に 42 を返す
fn.mockReturnValueOnce('first');        // 1 回目だけ 'first'
fn.mockReturnValueOnce('second');       // 2 回目だけ 'second'

fn.mockResolvedValue({ ok: true });     // Promise で解決（非同期）
fn.mockRejectedValue(new Error('ng')); // Promise を reject

fn.mockImplementation((a, b) => a + b); // 任意の実装に差し替え
fn.mockImplementationOnce(() => 'one'); // 1 回限りの実装
```

### 初期実装を渡す

```ts
const add = vi.fn((a: number, b: number) => a + b);
expect(add(1, 2)).toBe(3);
expect(add).toHaveBeenCalledWith(1, 2);
```

「記録もしたいけど実装もほしい」ときに使う書き方です。

## `vi.spyOn()` — 既存メソッドをスパイする

「元の実装は残したまま、呼び出し履歴だけ取りたい」場合。

```ts
it('console.log が呼ばれることを確認', () => {
  const spy = vi.spyOn(console, 'log');

  doSomething();

  expect(spy).toHaveBeenCalledWith('done');
  spy.mockRestore();    // 元の実装に戻す（重要！）
});
```

**`mockRestore()` を呼ばないと他のテストに影響**します。`afterEach(() => vi.restoreAllMocks())` をまとめて登録するのが安全策です（07 章で詳解）。

返り値だけ差し替えることもできます。

```ts
const spy = vi.spyOn(Math, 'random').mockReturnValue(0.5);
expect(randomPick(['a', 'b'])).toBe('a');
spy.mockRestore();
```

## モジュール単位のモック — `vi.mock()`

個別の関数だけでなく、**モジュール全体を差し替える**こともできます。`fetch` や自作ユーティリティの置き換えでよく使います。

### 基本形

対象コード：

```ts
// src/api.ts
export async function fetchUser(id: number) {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}

// src/greet.ts
import { fetchUser } from './api';

export async function greet(id: number) {
  const user = await fetchUser(id);
  return `Hello, ${user.name}!`;
}
```

テスト：

```ts
// src/greet.test.ts
import { describe, it, expect, vi } from 'vitest';
import { greet } from './greet';
import { fetchUser } from './api';

vi.mock('./api');   // ← モジュール全体をモック化（上部に書くのが安全）

describe('greet', () => {
  it('ユーザー名を使って挨拶する', async () => {
    // fetchUser の返り値を設定
    vi.mocked(fetchUser).mockResolvedValue({ id: 1, name: 'Alice' });

    const result = await greet(1);

    expect(result).toBe('Hello, Alice!');
    expect(fetchUser).toHaveBeenCalledWith(1);
  });
});
```

### ポイント

1. **`vi.mock(path)` はファイル先頭に書く**。Vitest が自動で**巻き上げて**（import より前に実行して）くれるので、実体が読まれる前にモックが適用される。
2. `vi.mock('./api')` とだけ書くと、そのモジュールの全 export が **`vi.fn()` に置き換わる**。
3. 型を保ったまま `.mockResolvedValue` などを呼びたいので、**`vi.mocked(fn)`** で型キャストするのが定番。

### 一部だけ差し替える（部分モック）

「`fetchUser` だけ差し替えたいが、他の export はそのまま使いたい」場合：

```ts
vi.mock('./api', async () => {
  const actual = await vi.importActual<typeof import('./api')>('./api');
  return {
    ...actual,
    fetchUser: vi.fn(),
  };
});
```

`vi.importActual` で元のモジュールを読み込み、上書きしたい部分だけ差し替えます。

### ファクトリー関数でモックを作る

```ts
vi.mock('./api', () => ({
  fetchUser: vi.fn().mockResolvedValue({ id: 1, name: 'Alice' }),
  fetchPosts: vi.fn().mockResolvedValue([]),
}));
```

- テストごとに違う返り値にしたい場合は、`it` 内で `vi.mocked(fetchUser).mockResolvedValue(...)` で上書きする。

## `__mocks__` フォルダによる永続的なモック

同じモックを複数のテストで使い回すなら、`__mocks__` フォルダに書いておけます。

```
src/
├── api.ts
└── __mocks__/
    └── api.ts      ← ここにモック実装
```

```ts
// src/__mocks__/api.ts
import { vi } from 'vitest';
export const fetchUser = vi.fn();
export const fetchPosts = vi.fn();
```

テストファイルで：

```ts
vi.mock('./api');       // 自動的に __mocks__/api.ts が使われる
```

プロジェクト規模が大きくなってきたときの整理に便利です。

## `fetch` / `axios` など HTTP のモック

### fetch（グローバル）

```ts
import { beforeEach, it, expect, vi } from 'vitest';

beforeEach(() => {
  vi.stubGlobal('fetch', vi.fn());
});

it('ユーザー取得成功', async () => {
  vi.mocked(fetch).mockResolvedValue({
    ok: true,
    json: async () => ({ id: 1, name: 'Alice' }),
  } as Response);

  const user = await fetchUser(1);
  expect(user.name).toBe('Alice');
  expect(fetch).toHaveBeenCalledWith('/api/users/1');
});
```

### axios

```ts
vi.mock('axios');
import axios from 'axios';

vi.mocked(axios.get).mockResolvedValue({ data: { id: 1, name: 'Alice' } });
```

### より本格的には MSW を推奨

**Mock Service Worker (MSW)** は「HTTP 層をネットワーク境界で横取りする」ライブラリで、`fetch` / `axios` どちらからも透明に見えます。実務では MSW を入れておくと、単体テストと E2E テストで同じモックサーバーを使い回せて効率的です。

```ts
import { setupServer } from 'msw/node';
import { http, HttpResponse } from 'msw';

const server = setupServer(
  http.get('/api/users/:id', ({ params }) =>
    HttpResponse.json({ id: Number(params.id), name: 'Alice' })
  ),
);

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
```

## グローバルや環境変数をモックする

### `vi.stubGlobal` / `vi.unstubAllGlobals`

```ts
beforeEach(() => {
  vi.stubGlobal('crypto', { randomUUID: () => 'test-uuid' });
});

afterEach(() => {
  vi.unstubAllGlobals();
});
```

### `vi.stubEnv` / `vi.unstubAllEnvs`

```ts
vi.stubEnv('NODE_ENV', 'production');
```

`import.meta.env` / `process.env` の値をテスト時だけ差し替えるのに使えます。

## モックのリセット — よく混乱する 3 つの API

| API | 何をするか |
|-----|-----------|
| `mockClear()` / `vi.clearAllMocks()` | **呼び出し履歴**だけクリア（実装と返り値は残す） |
| `mockReset()` / `vi.resetAllMocks()` | 呼び出し履歴 **＋ 実装・返り値**をリセット（空の `vi.fn()` に戻す） |
| `mockRestore()` / `vi.restoreAllMocks()` | `spyOn` で作ったスパイを**元の実装に戻す** |

**推奨の運用**：

```ts
// vitest.config.ts
export default defineConfig({
  test: {
    clearMocks: true,     // 各テストの前に clearMocks 相当を実行
    restoreMocks: true,   // spyOn を自動で復元
  },
});
```

この 2 つを true にしておくと、`beforeEach` で毎回書かなくて済みます。

## 呼び出し履歴の詳細を見る

```ts
const fn = vi.fn();
fn('a', 1);
fn('b', 2);

// 全呼び出しの引数配列
console.log(fn.mock.calls);
// => [['a', 1], ['b', 2]]

// 全呼び出しの返り値
console.log(fn.mock.results);
// => [{ type: 'return', value: undefined }, ...]

// 最後の呼び出しの引数
console.log(fn.mock.lastCall);
// => ['b', 2]
```

`expect` で表現しきれない複雑な検証は、`fn.mock.calls` を直接調べるのも手です。

## モックしすぎアンチパターン

モックは強力な反面、**使いすぎると「モックだけが通るテスト」になって実装の保証にならない**という罠があります。

### 避けたいパターン

- **ほぼすべての関数をモックしてしまい、実質何もテストしていない**。
- **実装の内部呼び出し順までアサーションしてしまう**（リファクタのたびに壊れる）。
- **「xxx が呼ばれたこと」だけ検証**して、結果（返り値や副作用）を検証しない。

### 指針

- **純粋な関数はモック不要**。そのままテストできるように設計する。
- **モックするのは「外の世界」**（HTTP、DB、時刻、乱数、ファイル）。
- 「呼ばれたこと」より、**「結果がどうなったか」**を検証する方が壊れにくい。
- 自分のコード同士は**できるだけ実物で**組み合わせる（モックは境界で）。

## ミニ演習：ロジック ＋ 外部依存 の例

注文に消費税を乗せる関数をテストします。

```ts
// src/order.ts
import { fetchTaxRate } from './tax-api';

export async function calculateTotal(price: number, countryCode: string) {
  const rate = await fetchTaxRate(countryCode);
  return Math.round(price * (1 + rate));
}
```

テスト：

```ts
// src/order.test.ts
import { describe, it, expect, vi } from 'vitest';
import { calculateTotal } from './order';
import { fetchTaxRate } from './tax-api';

vi.mock('./tax-api');

describe('calculateTotal', () => {
  it('税率 10% なら税込価格を整数で返す', async () => {
    vi.mocked(fetchTaxRate).mockResolvedValue(0.1);
    expect(await calculateTotal(1000, 'JP')).toBe(1100);
  });

  it('税率が 0 のとき元の価格のまま', async () => {
    vi.mocked(fetchTaxRate).mockResolvedValue(0);
    expect(await calculateTotal(500, 'US')).toBe(500);
  });

  it('fetchTaxRate にはカントリーコードが渡される', async () => {
    vi.mocked(fetchTaxRate).mockResolvedValue(0.1);
    await calculateTotal(1000, 'JP');
    expect(fetchTaxRate).toHaveBeenCalledWith('JP');
  });

  it('API がエラーを返すと例外が伝播する', async () => {
    vi.mocked(fetchTaxRate).mockRejectedValue(new Error('timeout'));
    await expect(calculateTotal(1000, 'JP')).rejects.toThrow('timeout');
  });
});
```

このテストは、

- **`fetchTaxRate` という外部依存をモック**して、
- **`calculateTotal` 側のロジック**（掛け算 + 四捨五入 + エラー伝播）だけを検証

する、というモック活用の典型です。

---

## この章のまとめ

- **`vi.fn()`** で「記録する関数」を作る。`mockReturnValue` / `mockResolvedValue` などで挙動を制御。
- **`vi.spyOn()`** は元の実装を残しつつ履歴を取る。使ったら `mockRestore()`。
- **モジュール全体**を差し替えるなら `vi.mock()`。一部だけ差し替えるときは `vi.importActual` と組み合わせる。
- HTTP は `fetch` を stub してもよいが、実務では **MSW** が便利。
- `clearMocks` / `restoreMocks` を `vitest.config.ts` で有効にすると、テスト間の汚染が減る。
- モックは**外の世界の境界でだけ**使う。自分のコードの中まではできるだけ実物を通す。
