# 01 — Playwrightとはと環境構築

この章では、Playwright が何であるか、なぜ E2E テストに使われるのかを説明したうえで、あなたの PC に Playwright をインストールして「動かせる状態」までを解説します。

---

## Playwright とは

**Playwright** は、Microsoft が中心となって開発している **E2E（End-to-End）テスト** 用のオープンソースライブラリです。ブラウザをプログラムから操作し、実際のユーザーと同じようにページを開いたり、ボタンを押したり、フォームに入力したりする動作を自動化できます。

### E2E テストとは

- **単体テスト**：関数やクラスなど、小さな単位が正しく動くかを検証するテストです。
- **E2E テスト**：ブラウザから Web アプリにアクセスし、「ログイン → 一覧表示 → 詳細表示」のように、**一連の流れ**が期待どおりに動くかを検証するテストです。

Playwright は後者「E2E テスト」を自動化するためのツールです。QA エンジニアや開発者が、リリース前やデプロイ後に「画面が壊れていないか」「主要な操作ができるか」を自動で確認するために使います。

### Playwright の主な特徴

| 特徴 | 説明 |
|------|------|
| **複数ブラウザ対応** | Chromium（Chrome 系）、Firefox、WebKit（Safari 系）を同じ API で扱えます。 |
| **安定しやすい** | 要素が表示されるまで自動で待つなど、**自動待機**によりフレキーなテストを書きやすくなっています。 |
| **高速** | ブラウザとテストコードの通信が効率化されており、多くのテストを短時間で回せます。 |
| **多言語対応** | JavaScript/TypeScript のほか、Python、Java、C#、.NET などで利用可能です。本教材では **JavaScript/TypeScript（Node.js）** を前提にします。 |
| **強力なツール** | コード生成（Record）、トレース、スクリーンショット、動画録画など、デバッグやレポートに役立つ機能が標準で用意されています。 |

### 他の E2E ツールとの違い（イメージ）

- **Selenium**：長年使われている標準的なツール。Playwright はそれより新しく、自動待機や API の設計がモダンです。
- **Cypress**：開発者体験が良いツール。Playwright は複数ブラウザ・複数タブ・並列実行などに強く、CI での大規模実行に向いています。
- **Puppeteer**：主に Chrome/Chromium 向け。Playwright は同じチームの流れを汲みつつ、クロスブラウザとテスト向け機能を強化したイメージです。

「モダンな E2E テストを始めたい」「複数ブラウザを同じコードでテストしたい」という場合に、Playwright は非常に向いています。

---

## 環境構築の流れ

Playwright を動かすには、次の 2 つが必要です。

1. **Node.js**（JavaScript を実行する環境）
2. **Playwright のパッケージとブラウザ**

まず Node.js の有無を確認し、必要ならインストールします。そのあとで Playwright 用のプロジェクトを作り、ブラウザをインストールします。

---

## Node.js の確認とインストール

### 1. Node.js が入っているか確認する

ターミナル（PowerShell やコマンドプロンプト）を開き、次のコマンドを実行します。

```bash
node -v
```

例として、`v20.10.0` のようにバージョン番号が表示されれば、Node.js はインストール済みです。**18 以上**（できれば 20 以上）を推奨します。

「コマンドが見つかりません」などと出る場合は、Node.js をインストールする必要があります。

### 2. Node.js をインストールする（必要な人向け）

1. 公式サイト [https://nodejs.org/](https://nodejs.org/) にアクセスします。
2. **LTS（Long Term Support）** と書かれた方をダウンロードしてインストールします。
3. インストール後、ターミナルを**一度閉じて開き直し**、もう一度 `node -v` を実行してバージョンが表示されることを確認します。

あわせて、パッケージ管理用の `npm` も入ります。次で確認できます。

```bash
npm -v
```

こちらもバージョンが表示されれば問題ありません。

---

## Playwright のインストール

Playwright は「プロジェクトごと」にインストールするのが一般的です。これから使うフォルダ（例：`playwright-tutorial`）を作成し、その中で初期化とインストールを行います。

### 方法 A：公式の初期化コマンドで一括セットアップ（推奨）

次のコマンドを実行すると、Playwright 用のプロジェクトが自動で作成されます。

```bash
npm init playwright@latest
```

実行すると、次のような質問が順番に表示されます。

1. **Where to put your end-to-end tests?**  
   テストファイルを置くフォルダ名です。初期値の `e2e` のまま Enter で問題ありません。

2. **Add a GitHub Actions workflow?**  
   GitHub にプッシュしたときにテストを実行するワークフローを追加するかどうかです。後から追加できるので、初心者は `No` でも構いません。

3. **Install Playwright browsers?**  
   Chromium、Firefox、WebKit をインストールするかです。**Yes** を選ぶと、その場でブラウザがダウンロードされます（時間がかかることがあります）。

4. **Install system dependencies?**  
   Linux でブラウザを動かすために必要なシステムライブラリを入れるかです。Windows の場合は関係ないので、表示に従って選べば大丈夫です。

すべて終わると、プロジェクトフォルダに次のようなものができます。

- `package.json` — プロジェクト名や依存パッケージの定義
- `playwright.config.ts`（または `.js`）— Playwright の設定ファイル
- `e2e/`（または指定した名前）— テストファイルを置くフォルダ
- サンプルのテストファイル（例：`e2e/example.spec.ts`）

この時点で、すでに「最初のテスト」を実行できる状態になっています。実行方法は **02 章** で説明します。

### 方法 B：既存のフォルダに手動で追加する

すでに存在する Node.js プロジェクトに Playwright を追加する場合は、そのフォルダで次を実行します。

```bash
npm init -y
npm install -D @playwright/test
npx playwright install
```

- `npm init -y`：`package.json` を自動作成（既にある場合は省略可）
- `npm install -D @playwright/test`：Playwright のテストランナーを開発用の依存関係としてインストール
- `npx playwright install`：Chromium、Firefox、WebKit のバイナリをダウンロード

手動で追加した場合は、設定ファイル（`playwright.config.ts`）やテスト用フォルダ（`e2e/`）は自分で作成する必要があります。02 章の「プロジェクト構成」を参考に、同じような形で用意するとよいです。

---

## ブラウザのインストール先とサイズ

`npx playwright install` を実行すると、Playwright 専用のブラウザが次のような場所にダウンロードされます。

- **Windows**：`%USERPROFILE%\AppData\Local\ms-playwright\`
- **macOS**：`~/Library/Caches/ms-playwright/`
- **Linux**：`~/.cache/ms-playwright/`

これらは通常の Chrome や Firefox とは別の「テスト用」のバイナリです。合計で数百 MB 程度になることがあるため、初回の `install` には数分かかることがあります。

特定のブラウザだけ使う場合は、次のように指定できます。

```bash
npx playwright install chromium
```

Chromium だけなら、ダウンロード時間と容量を抑えられます。学習時は Chromium のみでも十分です。

---

## インストールがうまくいかないとき

- **ネットワークエラー**：プロキシやファイアウォールの影響でダウンロードに失敗することがあります。環境に合わせてプロキシ設定を確認してください。
- **権限エラー**：インストール先フォルダに書き込み権限があるか確認し、必要なら「管理者として実行」やフォルダの権限変更を検討します。
- **Node.js のバージョン**：古い Node.js だと動かない場合があります。`node -v` で 18 以上であることを確認し、必要なら LTS 版に更新してください。

公式ドキュメントの「Installation」や「Troubleshooting」も参照すると、エラーメッセージに応じた対処法が載っています。

---

## この章のまとめ

- **Playwright** は、ブラウザ操作を自動化する E2E テスト用のライブラリで、複数ブラウザ・自動待機・高速実行が特徴です。
- 実行環境として **Node.js**（18 以上推奨）が必要です。
- プロジェクトで `npm init playwright@latest` を実行するか、`npm install -D @playwright/test` のあと `npx playwright install` で、Playwright とブラウザをインストールできます。
- インストールが終わったら、次章で「最初のテスト」を実行し、画面の動きとテスト結果の関係を確認しましょう。
