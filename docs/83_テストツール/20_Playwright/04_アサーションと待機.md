# 04 — アサーションと待機

E2E テストでは、「このボタンを押したあと、画面に『完了』と表示される」「この入力欄の値が期待どおりである」のように、**期待する状態になっているか**を検証する必要があります。この検証のことを**アサーション（assertion）**といいます。また、非同期で動く Web アプリでは「要素が表示されるまで待つ」ことが重要で、Playwright は**自動待機**によってそれをサポートしています。この章では、**expect** を使ったアサーションの書き方と、待機・タイムアウトの考え方を解説します。

---

## アサーションとは

**アサーション**は、「ある条件が成り立っていることを断言する」処理です。テスト中にアサーションが失敗すると、その時点でテストは「失敗」となり、期待値と実際の値の差分などがレポートに出力されます。Playwright では、**expect** という API を使ってアサーションを書きます。この **expect** は Jest などでおなじみのスタイルに近く、`.toHaveTitle()` や `.toBeVisible()` のように「読みやすい英文」で期待内容を表現できます。

---

## expect の基本形

Playwright の expect は、**expect(値).to〇〇(...)** の形で書きます。日本語で読み下すと「**〇〇であることを期待する**」という意味です。

- **expect(値)**：検証したい対象（ページ全体、Locator、値など）を渡します。
- **.to〇〇(...)**：マッチャーと呼ばれ、「〜であること」を表します。

例：

```typescript
// 「ページのタイトルに "ログイン" が含まれること」を期待する
await expect(page).toHaveTitle(/ログイン/);

// 「"完了" という見出しが画面に見えていること」を期待する
await expect(page.getByRole('heading', { name: '完了' })).toBeVisible();

// 「メール入力欄の値が 'test@example.com' であること」を期待する
await expect(page.getByLabel('メール').inputValue()).resolves.toBe('test@example.com');
```

**await** を付けることで、アサーションが「条件を満たすか、タイムアウトするまで」待ってから結果を出します。これが、後述する「自動待機」と組み合わさって、安定したテストを書く土台になります。

> **読み方のコツ**: `expect(〇〇).toBeVisible()` は「〇〇が Visible（見える）であること（toBe）を expect（期待）する」と読めます。英語が苦手でも、`toHave〜`（〜を持つ）、`toBe〜`（〜である）の 2 パターンを知っていれば、ほとんどのマッチャーの意味が推測できます。

---

## ページに対するアサーション

**ページ全体**の状態を検証する代表的なマッチャーです。

### toHaveTitle — タイトル

現在のページの `<title>` が、指定した文字列または正規表現にマッチすることを確認します。

```typescript
await expect(page).toHaveTitle('ダッシュボード');
await expect(page).toHaveTitle(/ログイン|Login/);
```

### toHaveURL — URL

現在の URL が期待どおりかどうかを確認します。

```typescript
await expect(page).toHaveURL('https://example.com/dashboard');
await expect(page).toHaveURL(/\/dashboard/);
```

### toHaveScreenshot — スクリーンショット比較（スナップショットテスト）

現在の画面と、事前に保存したスクリーンショットを比較します。見た目のリグレッション検知に使います。初回実行時は基準画像が作られ、2 回目以降はその画像と比較されます。

```typescript
await expect(page).toHaveScreenshot('dashboard.png');
```

---

## 要素（Locator）に対するアサーション

**Locator**（`page.getByRole(...)` などで得たもの）に対してよく使うマッチャーです。

### toBeVisible / toBeHidden

要素が**表示されているか**（visible）、**非表示か**（hidden）を検証します。表示状態は、CSS の `display`、`visibility`、`opacity` などに依存します。

```typescript
await expect(page.getByText('保存しました')).toBeVisible();
await expect(page.getByTestId('loading')).toBeHidden();
```

### toBeEnabled / toBeDisabled

ボタンや入力欄が**有効か**、**無効か**（disabled）を検証します。

```typescript
await expect(page.getByRole('button', { name: '送信' })).toBeEnabled();
await expect(page.getByRole('button', { name: '送信' })).toBeDisabled();
```

### toBeChecked

チェックボックスやラジオボタンが**オンになっているか**を検証します。

```typescript
await expect(page.getByRole('checkbox', { name: '同意する' })).toBeChecked();
await expect(page.getByRole('checkbox', { name: '同意する' })).not.toBeChecked();
```

### toHaveText — 要素内のテキスト

要素のテキスト（子孫要素のテキストを含む）が、指定した文字列または正規表現にマッチすることを確認します。

```typescript
await expect(page.getByTestId('message')).toHaveText('保存しました');
await expect(page.getByTestId('message')).toHaveText(/保存|完了/);
```

複数行や配列で指定することもできます。

```typescript
await expect(page.getByRole('list')).toHaveText(['項目1', '項目2']);
```

### toHaveValue — input の値

`<input>` や `<textarea>` の **value** を検証します。

```typescript
await expect(page.getByLabel('メール')).toHaveValue('test@example.com');
await expect(page.getByLabel('メール')).toHaveValue('');
```

### toHaveCount — マッチする要素の数

同じ Locator にマッチする要素が**何個あるか**を検証します。

```typescript
await expect(page.getByRole('listitem')).toHaveCount(5);
```

### toHaveAttribute — 属性の有無・値

要素が特定の属性を持ち、その値が期待どおりであることを確認します。

```typescript
await expect(page.getByRole('link', { name: '詳細' })).toHaveAttribute('href', /\/items\/\d+/);
```

### not — 否定

**.not** を挟むと、「〜でないこと」を検証できます。

```typescript
await expect(page.getByText('エラー')).not.toBeVisible();
await expect(page).not.toHaveURL(/error/);
```

---

## 値の取得とアサーション — inputValue()、textContent() など

Locator から**値を取得**して、それを expect で検証するパターンもあります。

```typescript
await expect(page.getByLabel('メール').inputValue()).resolves.toBe('test@example.com');
const text = await page.getByTestId('message').textContent();
expect(text).toContain('完了');
```

- **inputValue()**：入力欄の value を取得します。Promise を返すので、**resolves** でアサーションするか、**await** で取得してから **expect(値)** で検証します。
- **textContent()**：要素のテキストを取得します。

**resolves** は「この Promise が解決した値に対して toBe(...) を適用する」という意味で、非同期の値をその場で検証するときに便利です。

---

## 自動待機の考え方

Web アプリでは、ボタンを押してから結果が表示されるまでに**時間差**があることがよくあります。そのため、「クリックした直後に『完了』の要素を expect する」と、まだ DOM にない段階でアサーションが走り、**フレーク（不安定な失敗）**の原因になります。Playwright では、多くの操作とアサーションに**自動待機**が組み込まれており、「条件が満たされるまで一定時間待ってから、満たされれば成功、満たされなければタイムアウトで失敗」という動きをします。

### 何が「待って」くれるか

- **click / fill / check など**：対象要素が **visible** かつ **stable**（動いていない）などになってから操作します。つまり「押せる状態になるまで」待ちます。
- **expect(locator).toBeVisible()**：その要素が表示されるまで、タイムアウトいっぱいまで繰り返しチェックします。
- **expect(locator).toHaveText(...)**：要素が存在し、かつテキストが一致するまで待ちます。

そのため、**「操作 → すぐ expect」** と書いても、expect の側で「表示されるまで待つ」ため、多くの場合は追加の **sleep** を書かずに済みます。**sleep（固定秒待ち）はなるべく使わず、要素の状態やアサーションに任せる**のがベストプラクティスです。

```
自動待機のイメージ:

  await page.getByRole('button', { name: '保存' }).click();
  await expect(page.getByText('保存しました')).toBeVisible();

  click の裏側:        ボタンが見える？ → まだ → まだ → 見えた！→ クリック実行
  expect の裏側:       テキストが見える？ → まだ → まだ → 見えた！→ 成功
                       テキストが見える？ → まだ → まだ → ... → タイムアウト → 失敗
```

> **初心者向けポイント**: `page.waitForTimeout(3000)` のような「とりあえず 3 秒待つ」コードは、最初は安心感がありますが、環境によっては足りなかったり無駄に長かったりします。Playwright の自動待機に任せるのが、安定したテストへの近道です。

### タイムアウト

「いつまで待つか」は**タイムアウト**で決まります。デフォルトでは、例えば次のような値が使われます（バージョンや設定により異なります）。

- **action timeout**（click や fill など）：例えば 30 秒。その時間内に「操作可能な状態」にならなければ失敗します。
- **expect timeout**（expect の待機）：例えば 5 秒。その時間内に条件が満たされなければアサーション失敗になります。

これらは **playwright.config.ts** の **use** や **expect** で変更できます。

```typescript
// playwright.config.ts
export default defineConfig({
  use: {
    // click や fill の操作が「要素が操作可能になるまで」待つ最大時間
    // 15_000 = 15,000ミリ秒 = 15秒
    actionTimeout: 15_000,
  },
  expect: {
    // expect(...).toBeVisible() などが「条件を満たすまで」待つ最大時間
    // 10_000 = 10,000ミリ秒 = 10秒
    timeout: 10_000,
  },
});
```

個別の操作やアサーションで上書きすることもできます。

```typescript
await page.getByRole('button', { name: '送信' }).click({ timeout: 20_000 });
await expect(page.getByText('完了')).toBeVisible({ timeout: 15_000 });
```

---

## 明示的に「待つ」 — waitFor

「この要素が表示されるまで待ちたいが、expect はしたくない」という場合は、**waitFor** で状態を待つだけにできます。

```typescript
await page.getByText('読み込み完了').waitFor({ state: 'visible' });
```

**state** には `'visible'`、`'hidden'`、`'attached'`（DOM に存在）、`'detached'`（DOM から削除）などが指定できます。waitFor もタイムアウトまで自動で待ちます。

---

## ソフトアサーション（optional）

通常、1 つのアサーションが失敗すると、その時点でテストは失敗して終了します。**ソフトアサーション**を使うと、失敗してもテストを続行し、最後に「失敗したアサーション」をまとめてレポートできます。複数の項目を一度に検証したいときに便利です。

```typescript
await expect.soft(page).toHaveTitle(/期待タイトル/);
await expect.soft(page.getByText('メッセージ1')).toBeVisible();
await expect.soft(page.getByText('メッセージ2')).toBeVisible();
```

すべての soft が終わったあと、どれかが失敗していればテストは failed として扱われます。

---

## この章のまとめ

- **アサーション**は **expect(対象).to〇〇(...)** で書き、**await** することで「条件が満たされるまで待ってから検証」できます。
- ページには **toHaveTitle** / **toHaveURL**、要素には **toBeVisible** / **toHaveText** / **toHaveValue** / **toHaveCount** など、用途に応じたマッチャーがあります。
- **.not** で否定、「〜でないこと」を検証できます。
- Playwright の**自動待機**により、多くの操作と expect は「条件が満たされるまで待つ」ため、**sleep は極力使わず、要素の状態とアサーションに任せる**と安定します。
- タイムアウトは設定や個別の **timeout** オプションで調整できます。**waitFor** で「表示されるまで待つだけ」の処理も書けます。
