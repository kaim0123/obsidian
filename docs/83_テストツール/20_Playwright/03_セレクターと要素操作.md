# 03 — セレクターと要素操作

E2E テストでは「このボタンを押す」「この入力欄に文字を入れる」のように、画面上の**要素**を指定して操作します。この章では、Playwright で要素を指定する方法（**セレクター**）と、よく使う**操作**（クリック、入力、選択、ドラッグなど）を、初心者向けに詳しく解説します。

---

## なぜセレクターが重要か

テストは「正しい要素」に対してだけ操作する必要があります。間違った要素を指定すると、意図しないリンクがクリックされたり、別の入力欄に文字が入ったりして、テストが不安定になったり、誤った結果を出したりします。また、デザイン変更で class 名や id が変わると、そのセレクターに依存したテストは一斉に壊れます。**どのように要素を指定するか**は、保守性と安定性に直結するため、Playwright では「ユーザーに近い見つけ方」を推奨しています。

---

## Playwright で推奨される「見つけ方」の優先順位

Playwright のドキュメントでは、要素の指定方法を次の順で推奨しています。

1. **getByRole** — 役割（ボタン、リンク、テキストボックスなど）とアクセシブルな名前で探す。
2. **getByLabel** — ラベル（`<label>` や aria-label）でフォーム要素を探す。
3. **getByPlaceholder** — プレースホルダーで入力欄を探す（補助的に）。
4. **getByText** — 表示テキストで探す。
5. **getByTestId** — テスト用の data-testid で探す（実装詳細に依存しないようにするため）。

最後の手段として、**CSS セレクター**（`locator('css=...')`）や **XPath** を使う方法もあります。まずは 1〜5 を覚え、それで表現しづらい場合だけ CSS/XPath を検討すると、読みやすく壊れにくいテストになります。

---

## getByRole — 役割と名前で探す

**getByRole** は、アクセシビリティの「ロール」（ボタン、リンク、見出し、テキストボックスなど）と、**アクセシブルな名前**（画面に表示されているテキストや aria-label など）で要素を指定する方法です。ユーザーが「送信ボタン」「ログインリンク」と認識するのと同じ考え方で書けるため、推奨されます。

### 基本的な書き方

```typescript
// 「送信」というテキストのボタンをクリックする
await page.getByRole('button', { name: '送信' }).click();

// 「利用規約」というテキストのリンクをクリックする
await page.getByRole('link', { name: '利用規約' }).click();

// 「メールアドレス」という名前のテキスト入力欄に文字を入れる
await page.getByRole('textbox', { name: 'メールアドレス' }).fill('test@example.com');

// 「会員登録」という見出し（h1〜h6）を取得する
await page.getByRole('heading', { name: '会員登録' });
```

> **読み方のコツ**: `getByRole('button', { name: '送信' })` は、日本語に直すと「ロールが button（ボタン）で、名前が『送信』の要素を取得する」です。ユーザーが「送信ボタンを押す」と言うのと同じ感覚で書けます。

- **第 1 引数**：ロール名（`'button'`, `'link'`, `'textbox'`, `'heading'`, `'checkbox'`, `'radio'` など）。
- **第 2 引数（省略可）**：`name` に、その要素のアクセシブルな名前を指定します。省略すると、そのロールの要素が複数ある場合は「どれか 1 つ」を指すことになり、意図が伝わりにくくなるので、できるだけ `name` を付けるとよいです。

### ロールの例

| ロール | 主な対象 |
|--------|----------|
| **button** | `<button>`、`type="submit"` の input、role="button" の要素 |
| **link** | `<a href="...">` |
| **textbox** | `<input type="text">`、`<textarea>` |
| **heading** | `<h1>`〜`<h6>` |
| **checkbox** | `<input type="checkbox">` |
| **radio** | `<input type="radio">` |
| **combobox** | `<select>` やカスタムのドロップダウン |
| **img** | `<img>`（alt が名前になる） |

名前は「完全一致」でなく、部分一致にもできます。正規表現も使えます。

```typescript
await page.getByRole('button', { name: /送信|Submit/i }).click();
```

---

## getByLabel — ラベルでフォーム要素を探す

入力欄や選択肢に `<label>` が紐づいている場合、**getByLabel** で「ラベルのテキスト」を指定して要素を取得できます。フォームのテストでは非常に便利です。

```html
<label for="email">メールアドレス</label>
<input id="email" type="email" />
```

```typescript
await page.getByLabel('メールアドレス').fill('test@example.com');
```

ラベルが input を包んでいる形でも使えます。

```html
<label>
  パスワード
  <input type="password" />
</label>
```

```typescript
await page.getByLabel('パスワード').fill('secret');
```

`aria-label` が付いている要素も、getByLabel で名前を指定して探せます。

---

## getByPlaceholder — プレースホルダーで探す

入力欄に `placeholder` があるとき、その文字列で探す方法です。**ラベルがないフォーム**で補助的に使います。プレースホルダーは仕様変更で変わりやすいので、getByRole や getByLabel を優先し、どうしても必要なときだけ getByPlaceholder を使うのがおすすめです。

```typescript
await page.getByPlaceholder('メールアドレスを入力').fill('test@example.com');
```

---

## getByText — 表示テキストで探す

画面上に表示されている**テキスト**で要素を探します。リンク、ボタン、見出し、段落など、どんな要素でも「この文字が含まれる要素」として指定できます。

```typescript
await page.getByText('ログイン').click();
await page.getByText('利用規約', { exact: true }).click();
await page.getByText(/ようこそ、.+/).click();
```

- **部分一致**：デフォルトでは、指定した文字列を**含む**要素が対象になります。複数ある場合は最初にマッチした 1 つです。
- **完全一致**：`{ exact: true }` を付けると、そのテキストと完全に一致する要素だけを探します。
- **正規表現**：`/パターン/` を渡すと、そのパターンにマッチするテキストを持つ要素を探します。

注意点として、同じテキストがページ内に複数あると「どれがクリックされるか」が曖昧になります。その場合は、より範囲を絞った locator（親要素で絞る、getByRole でロールを指定するなど）と組み合わせると安全です。

---

## getByTestId — テスト用 ID で探す

**data-testid** 属性を付けた要素を、テスト専用の識別子として使う方法です。デザインや class 名が変わっても、テスト用 ID だけ維持すればテストは動き続けます。開発チームと「テスト用には testid を使う」と決めておくと、保守しやすくなります。

```html
<button data-testid="submit-login">ログイン</button>
```

```typescript
await page.getByTestId('submit-login').click();
```

属性名はデフォルトで `data-testid` です。`playwright.config.ts` で `use.getByTestId` を変更すれば、別の属性名（例：`data-qa`）にもできます。

---

## locator とチェーン — 範囲を絞る

上記の `getByRole` などは、すべて **Locator** というオブジェクトを返します。Locator は「その時点ではまだ要素を探していない」遅延評価のオブジェクトで、`.click()` や `.fill()` を呼んだタイミングで初めて要素を探して操作します。

**親要素で範囲を絞り、その中から子を探す**ことができます。

```typescript
// ページ全体 → main エリア → その中の「送信」ボタン、と絞り込む
await page.getByRole('main').getByRole('button', { name: '送信' }).click();
```

これは「main ロールの要素の内側にある『送信』ボタン」をクリックします。ページに複数の「送信」ボタンがある場合に、特定のブロック内の 1 つだけを指定するのに便利です。

```typescript
// login-form の中にある「メール」入力欄に絞り込む
await page.getByTestId('login-form').getByLabel('メール').fill('a@b.com');
```

「login-form という testid を持つ要素の内側にある『メール』ラベルの入力欄」にフォーカスできます。

> **初心者のよくある疑問**：「ページに同じ名前のボタンが 2 つあってテストが動かない」という場合は、このチェーン（つなげて書く方法）で親要素を先に指定すると解決することが多いです。

---

## 要素の操作 — クリック、入力、選択

Locator を取得したあと、代表的な操作は次のとおりです。

### click — クリック

```typescript
await page.getByRole('button', { name: '送信' }).click();
```

オプションで、**修飾キー**（Ctrl、Shift など）を押したままクリックしたり、**ダブルクリック**や**右クリック**も指定できます。

```typescript
await page.getByRole('link', { name: '別タブで開く' }).click({ modifiers: ['Control'] });
await page.getByRole('button', { name: 'アイテム' }).click({ button: 'right' });
await page.getByRole('button', { name: '編集' }).dblclick();
```

### fill — 入力欄に文字を入れる

**fill** は、入力欄の既存の内容を**いったん消してから**指定した文字列を入力します。1 つの入力欄にまとめて入れるときに使います。

```typescript
await page.getByLabel('ユーザー名').fill('yamada');
await page.getByPlaceholder('検索').fill('Playwright');
```

**type** は、キーを 1 つずつ打つように入力します。遅い代わりに、オートコンプリートやキーイベントに反応する UI をテストするときに使います。

```typescript
await page.getByLabel('検索').type('Playwright', { delay: 100 });
```

### check / uncheck — チェックボックス・ラジオ

```typescript
await page.getByRole('checkbox', { name: '同意する' }).check();
await page.getByRole('checkbox', { name: '同意する' }).uncheck();
await page.getByRole('radio', { name: '男性' }).check();
```

### selectOption — セレクトボックス（ドロップダウン）

`<select>` では、**selectOption** で選択します。値（value）か、表示ラベルで指定できます。

```typescript
await page.getByLabel('都道府県').selectOption('tokyo');
await page.getByLabel('都道府県').selectOption({ label: '東京都' });
await page.getByLabel('都道府県').selectOption([{ label: '東京都' }, { label: '大阪府' }]); // 複数選択
```

### キーボード入力 — press

特定のキーを押す操作です。Enter、Tab、Esc など。

```typescript
await page.getByLabel('検索').press('Enter');
await page.getByLabel('メール').press('Tab');
await page.keyboard.press('Escape');
```

### ホバー、ドラッグ

```typescript
await page.getByRole('menuitem', { name: 'ファイル' }).hover();
await page.getByText('ドラッグ元').dragTo(page.getByText('ドロップ先'));
```

---

## 複数要素と n 番目 — first, last, nth

同じセレクターに複数マッチする場合、**first** / **last** / **nth** で「1 番目」「最後」「n 番目」を指定できます。

```typescript
await page.getByRole('listitem').first().click();
await page.getByRole('listitem').last().click();
await page.getByRole('listitem').nth(2).click(); // 0 始まりで 3 番目
```

---

## ページ遷移 — goto、戻る・進む

- **goto**：指定した URL に遷移します。デフォルトで「ロードが完了する」まで待ちます。

```typescript
await page.goto('https://example.com/');
await page.goto('/login'); // baseURL が設定されていれば相対パス可
```

- **goBack** / **goForward**：ブラウザの戻る・進む。

```typescript
await page.goBack();
await page.goForward();
```

---

## この章のまとめ

- 要素の指定は **getByRole → getByLabel → getByPlaceholder → getByText → getByTestId** の順で考えると、読みやすく壊れにくいテストになります。
- **getByRole** は「役割＋名前」で、ユーザーの見え方に近い形で指定できます。
- **getByLabel** はフォームで特に便利です。**getByTestId** は実装変更に強く、チームで testid を決めておくと保守しやすいです。
- Locator は **`.click()`**、**`.fill()`**、**`.check()`**、**`.selectOption()`**、**`.press()`** などで操作し、**親 locator の内側**で絞り込むと、複数候補がある場合でも安全に指定できます。
