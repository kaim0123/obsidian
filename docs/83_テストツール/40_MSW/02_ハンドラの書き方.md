# ハンドラの書き方

MSW の**ハンドラ**は「どのリクエストに、どんな応答を返すか」の定義です。この章では、MSW v2 の `http` / `graphql` / `HttpResponse` を使った書き方を、よく使うパターンごとにまとめます。

---

## 1. 基本形

```ts
import { http, HttpResponse } from 'msw';

http.get('/api/users/:id', ({ request, params, cookies }) => {
  return HttpResponse.json({ id: params.id, name: '山田' });
});
```

| 部品 | 意味 |
|------|------|
| `http.get` / `post` / `put` / `patch` / `delete` / `all` | メソッド（`all` は全メソッド） |
| 第1引数 | URL のパターン。`:id` はパスパラメータ、`*` はワイルドカード、正規表現も可 |
| `request` | 標準の Fetch API の `Request`。ヘッダー・ボディ・URL を読める |
| `params` | パスパラメータ（`{ id: '1' }`、値は文字列） |
| `cookies` | リクエストの Cookie |
| 戻り値 | 標準の `Response`（`HttpResponse` はその便利版） |

- v1 の `rest.get(url, (req, res, ctx) => res(ctx.json(...)))` から書き方が変わりました。古い記事を読むときは注意。

## 2. リクエストを読む

### クエリパラメータ

```ts
http.get('/api/products', ({ request }) => {
  const url = new URL(request.url);
  const page = Number(url.searchParams.get('page') ?? 1);
  return HttpResponse.json({ page, items: products.slice((page - 1) * 10, page * 10) });
});
```

- URL パターンにはクエリを書かない（`/api/products?page=1` ではなく `/api/products`）。クエリはハンドラの中で読みます。

### ボディ

```ts
http.post('/api/login', async ({ request }) => {
  const { email, password } = (await request.json()) as { email: string; password: string };
  if (password !== 'correct') {
    return HttpResponse.json({ message: 'パスワードが違います' }, { status: 401 });
  }
  return HttpResponse.json({ token: 'dummy-token' });
});
```

`request.formData()`・`request.text()` も使えます。

### ヘッダー

```ts
http.get('/api/me', ({ request }) => {
  if (!request.headers.get('Authorization')) {
    return new HttpResponse(null, { status: 401 });
  }
  return HttpResponse.json({ name: '山田' });
});
```

## 3. 応答を作る

```ts
HttpResponse.json({ ok: true });                         // JSON
HttpResponse.json({ ok: true }, { status: 201 });        // ステータス
HttpResponse.text('OK');                                 // テキスト
HttpResponse.xml('<ok/>');
new HttpResponse(null, { status: 204 });                 // ボディなし
HttpResponse.json(data, { headers: { 'X-Total-Count': '42' } });
```

### エラー

```ts
// サーバーエラー（応答は返る）
http.get('/api/users', () => new HttpResponse(null, { status: 500 }));

// ネットワークエラー（応答が返らない：オフライン・CORS 失敗など）
http.get('/api/users', () => HttpResponse.error());
```

- 500 とネットワークエラーでは、アプリ側で起きることが違います（`fetch` は 500 では reject しないが、ネットワークエラーでは reject する）。**両方テストする**のがおすすめです。

### 遅延

```ts
import { delay } from 'msw';

http.get('/api/users', async () => {
  await delay(500);        // 500ms 待つ（ローディング表示の確認）
  return HttpResponse.json([]);
});
// delay() だけなら本物らしいランダムな遅延、delay('infinite') で永遠に返さない
```

- テストで `delay` を使うとテストが遅くなります。ローディング表示の確認には `delay('infinite')` で止めるのが確実です。

## 4. テストごとに上書きする：server.use

共通のハンドラは正常系にしておき、異常系はそのテストの中だけで上書きします。

```ts
test('サーバーエラーのときはエラーメッセージを表示する', async () => {
  server.use(
    http.get('/api/users', () => new HttpResponse(null, { status: 500 })),
  );
  render(<UserList />);
  expect(await screen.findByRole('alert')).toHaveTextContent('読み込みに失敗しました');
});
```

- `server.use` で足したハンドラは**先に評価される**ので、共通のハンドラより優先されます。
- `afterEach(() => server.resetHandlers())` で元に戻す（[[01_MSWの仕組みとセットアップ]]）。

### 1回だけ上書きする

```ts
server.use(
  http.get('/api/users', () => new HttpResponse(null, { status: 500 }), { once: true }),
);
// 1回目は 500、2回目以降は共通のハンドラ → 「再試行ボタンで復旧する」テストに使える
```

## 5. 状態を持つハンドラ

作成→一覧のように、前のリクエストの結果が次に影響するシナリオでは、ハンドラの外に簡易的なデータを持ちます。

```ts
let todos = [{ id: 1, title: '買い物' }];

export const handlers = [
  http.get('/api/todos', () => HttpResponse.json(todos)),
  http.post('/api/todos', async ({ request }) => {
    const { title } = (await request.json()) as { title: string };
    const todo = { id: todos.length + 1, title };
    todos = [...todos, todo];
    return HttpResponse.json(todo, { status: 201 });
  }),
];

export const resetDb = () => { todos = [{ id: 1, title: '買い物' }]; };
```

- 状態は**テストごとにリセット**する（`afterEach(resetDb)`）。
- 本格的には `@mswjs/data` のような、モック用のデータベースライブラリも使えます。

## 6. 本物に通す：passthrough と bypass

```ts
import { passthrough, bypass } from 'msw';

// このリクエストはモックせず本物に流す
http.get('/api/health', () => passthrough());

// 本物の応答を取ってきて、一部だけ書き換える
http.get('/api/user', async ({ request }) => {
  const real = await fetch(bypass(request)).then((r) => r.json());
  return HttpResponse.json({ ...real, name: 'テスト用の名前' });
});
```

## 7. GraphQL

```ts
import { graphql, HttpResponse } from 'msw';

graphql.query('GetUser', ({ variables }) => {
  return HttpResponse.json({ data: { user: { id: variables.id, name: '山田' } } });
});

graphql.mutation('CreatePost', () => {
  return HttpResponse.json({ errors: [{ message: '権限がありません' }] });
});
```

- 操作名（`query GetUser { … }` の `GetUser`）で振り分けます。エンドポイントを分けたいときは `graphql.link('https://api.example.com/graphql')`。

## 8. ハンドラの整理

| 方針 | やり方 |
|------|--------|
| **リソースごとにファイルを分ける** | `handlers/users.ts`・`handlers/orders.ts` を `handlers/index.ts` でまとめる |
| **正常系を共通に、異常系はテストで上書き** | 共通ハンドラには「一番よくある成功応答」だけを置く |
| **データはファクトリで作る** | 応答データを [[05_テストデータの用意]] のファクトリで作ると、テストと共有しやすい |
| **型を付ける** | `http.get<Params, RequestBody, ResponseBody>(…)` で応答の型を API の型とそろえる。OpenAPI から生成する方法もある（37/50_型安全・コード生成） |
