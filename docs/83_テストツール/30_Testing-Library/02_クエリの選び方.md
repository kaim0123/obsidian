# クエリの選び方

Testing Library のテストの大半は「要素を探す」ことです。探し方（クエリ）の選び方で、テストの読みやすさ・壊れにくさ・アクセシビリティへの効き目が大きく変わります。この章では、クエリの種類と優先順位、特に一番使う `getByRole` の使いこなしをまとめます。

---

## 1. クエリの形：get / query / find

クエリ名は「**種類** + **By** + **何で探すか**」でできています。

| 種類 | 見つからないとき | 複数見つかったとき | 非同期 | 使いどころ |
|------|------------------|--------------------|--------|------------|
| `getBy…` | エラー | エラー | × | **ある**はずの要素を探す（基本はこれ） |
| `queryBy…` | `null` を返す | エラー | × | **ない**ことを確かめる |
| `findBy…` | エラー（タイムアウト） | エラー | ○（Promise） | **これから現れる**要素を待つ |
| `getAllBy…` / `queryAllBy…` / `findAllBy…` | 上と同じ（配列を返す） | 配列で返す | — | 複数の要素を扱う |

```ts
expect(screen.getByRole('heading', { name: '注文履歴' })).toBeInTheDocument();
expect(screen.queryByText('読み込み中')).not.toBeInTheDocument();
expect(await screen.findByRole('list')).toBeInTheDocument();
```

- 「ない」ことを `getBy` で確かめようとすると、見つからない時点でエラーになってしまう。**否定には `queryBy`**。
- 「現れるのを待つ」なら `waitFor(() => getBy…)` より `findBy…` が短く書けます（[[04_非同期UIとよくある間違い]]）。

---

## 2. 優先順位

公式ドキュメントが推奨する順番です。上ほどユーザーの体験に近く、下ほど実装に近くなります。

| 優先 | クエリ | 何で探すか | 例 |
|------|--------|------------|----|
| 1 | **`ByRole`** | アクセシビリティツリーのロールとアクセシブルネーム | ボタン・リンク・見出し・入力欄 |
| 2 | `ByLabelText` | `<label>` や `aria-label` | フォームの入力欄 |
| 3 | `ByPlaceholderText` | placeholder | ラベルのない入力欄（本来はラベルを付けるべき） |
| 4 | `ByText` | 表示テキスト | 段落・メッセージ（ロールのない要素） |
| 5 | `ByDisplayValue` | 入力欄の現在値 | 値が入った状態のフォーム |
| 6 | `ByAltText` | 画像の alt | `<img>` |
| 7 | `ByTitle` | title 属性 | ツールチップ（スクリーンリーダーで一貫しない） |
| 8 | `ByTestId` | `data-testid` | 他の方法で探せない場合の最終手段 |

- **迷ったら `ByRole`**。ほとんどの要素はこれで探せます。
- `ByTestId` を使いたくなったら、まず「この要素はユーザーからどう見えるか」を考える。ラベルやロールが足りないなら、マークアップを直すほうが先です。

## 3. getByRole を使いこなす

### よく使うロール

| 要素 | ロール |
|------|--------|
| `<button>` | `button` |
| `<a href>` | `link` |
| `<h1>`〜`<h6>` | `heading`（`level` で絞れる） |
| `<input type="text">`・`<textarea>` | `textbox` |
| `<input type="checkbox">` | `checkbox` |
| `<input type="radio">` | `radio` |
| `<select>` | `combobox`（`multiple` なら `listbox`） |
| `<ul>` / `<li>` | `list` / `listitem` |
| `<table>` / `<tr>` / `<td>` | `table` / `row` / `cell` |
| `<nav>` / `<main>` / `<dialog>` | `navigation` / `main` / `dialog` |
| `role="alert"` | `alert` |

### オプション

```ts
screen.getByRole('button', { name: '保存' });            // アクセシブルネームで絞る
screen.getByRole('button', { name: /保存/ });            // 正規表現（部分一致）
screen.getByRole('heading', { level: 2, name: '設定' }); // 見出しのレベル
screen.getByRole('checkbox', { checked: true });         // 状態で絞る
screen.getByRole('tab', { selected: true });
screen.getByRole('button', { pressed: true });           // aria-pressed
screen.getByRole('dialog', { hidden: true });            // 非表示の要素も含める
```

- **アクセシブルネーム**は、ボタンならテキスト、入力欄なら関連づいたラベル、`aria-label` などから計算される名前です。スクリーンリーダーが読み上げる名前と同じなので、`name` で絞ると「読み上げで区別できるか」も同時に確かめられます。

### 範囲を絞る：within

同じボタンが複数ある一覧では、行を先に探してからその中を探します。

```ts
import { within } from '@testing-library/react';

const row = screen.getByRole('row', { name: /田中/ });
await user.click(within(row).getByRole('button', { name: '削除' }));
```

## 4. テキストのマッチ

```ts
screen.getByText('送信しました');                  // 完全一致（前後の空白は正規化）
screen.getByText(/送信しました/);                  // 部分一致
screen.getByText('送信', { exact: false });        // 部分一致・大文字小文字を無視
screen.getByText((content, el) => el?.tagName === 'SPAN' && content.startsWith('合計'));
```

- テキストが複数の要素に分かれている（`<p>合計 <strong>1,000</strong> 円</p>`）と、`getByText('合計 1,000 円')` では見つかりません。関数マッチャーを使うか、`toHaveTextContent` で親要素を確かめます。

---

## 5. 探せないときのデバッグ

| 方法 | 何が分かるか |
|------|--------------|
| `screen.debug()` | 現在の DOM を出力する（長いときは `screen.debug(undefined, 30000)`） |
| `screen.logTestingPlaygroundURL()` | Testing Playground の URL を出力。ブラウザで開くと推奨クエリを教えてくれる |
| `logRoles(container)` | 画面上の要素とロール・名前の一覧 |
| エラーメッセージ | `getByRole` が失敗すると、見つかったロールの一覧が表示される |

```ts
import { logRoles } from '@testing-library/dom';
const { container } = render(<Menu />);
logRoles(container);
```
