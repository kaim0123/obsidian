# テストツールの全体像と選び方

JavaScript / TypeScript のテストツールは種類が多く、「Vitest と Testing Library と MSW は何が違うのか」「Playwright があれば Vitest はいらないのか」と迷いがちです。この章では、ツールを**役割（レイヤー）ごと**に並べ、何をどの組み合わせで使うかを整理します。個々のツールの使い方は各フォルダの教材へ。

---

## 1. ツールの役割

テストツールは、1つで全部をやるのではなく、役割の違う部品を組み合わせて使います。

| 役割 | 何をするか | 代表的なツール | このフォルダ |
|------|------------|----------------|--------------|
| **テストランナー** | テストファイルを探して実行し、結果を報告する | Vitest、Jest、Node.js test runner | 10_Vitest |
| **アサーション** | 期待値と比べて成否を判定する | Vitest / Jest の `expect`、jest-dom | 10_Vitest |
| **DOM 環境** | Node.js 上でブラウザの DOM を再現する | jsdom、happy-dom、Vitest Browser Mode | 10_Vitest（06章） |
| **UI テストユーティリティ** | コンポーネントを描画し、ユーザーのように探して操作する | Testing Library、user-event | 30_Testing-Library |
| **ネットワークのモック** | HTTP / GraphQL のリクエストを横取りして偽の応答を返す | MSW、nock | 40_MSW |
| **E2E ランナー** | 本物のブラウザを自動操作する | Playwright、Cypress、WebdriverIO | 20_Playwright |
| **ビジュアル回帰** | スクリーンショットの差分を検知する | Playwright の `toHaveScreenshot`、Chromatic | 86/60_品質ゲート |
| **アクセシビリティ** | WCAG 違反を自動検出する | axe-core（@axe-core/playwright、vitest-axe） | 86/60_品質ゲート |
| **カバレッジ** | 実行された行・分岐を計測する | v8、istanbul | 10_Vitest（06章） |
| **性能** | 表示速度・負荷を計測する | Lighthouse CI、k6 | 86/60_品質ゲート |

## 2. テストレベルとツールの組み合わせ

```
【Unit】        Vitest ─────────────────────────── 関数・フックのロジック
【Integration】 Vitest + jsdom + Testing Library + MSW ─ 画面単位の振る舞い
【E2E】         Playwright（+ 必要なら MSW / page.route）── 本物のブラウザで主要フロー
【静的】        TypeScript + ESLint / Biome ────────── 実行前に防ぐ
```

- **Vitest と Playwright はどちらか一方ではなく、役割が違う**。Vitest は速いフィードバック、Playwright は本物のブラウザでの確認。
- Testing Library と MSW は Vitest の「上に乗せる」道具。Integration テスト（Testing Trophy で一番厚い層）の中心になります（[[02_テストの形（ピラミッド・Trophy・Honeycomb）]]）。

## 3. よくある比較

### Vitest と Jest

| | Vitest | Jest |
|---|--------|------|
| 設定 | Vite の設定をそのまま使える。ESM・TypeScript がそのまま動く | ESM・TS には Babel / ts-jest などの設定が必要なことが多い |
| 速度 | 速い（Vite の変換と並列実行） | 大規模では遅くなりやすい |
| API | Jest とほぼ互換（`vi.fn` ↔ `jest.fn`） | 事実上の標準で、情報が多い |
| 向いている場面 | 新規プロジェクト、Vite / Next.js 以外も含む最近の構成 | 既存の Jest 資産が大きいプロジェクト、React Native |

移行の差分は [[01_Vitestとはと環境構築]] を参照。

### Playwright と Cypress

| | Playwright | Cypress |
|---|------------|---------|
| ブラウザ | Chromium・Firefox・WebKit | Chromium 系・Firefox（WebKit は実験的） |
| 動き方 | ブラウザの外からプロトコルで操作。複数タブ・複数オリジンに強い | ブラウザの中で動く。デバッグ UI が分かりやすい |
| 並列実行 | 標準で無料 | 無料版は制限あり（Cloud で並列化） |
| 待機 | 自動待機（auto-wait） | 自動リトライ |
| 向いている場面 | クロスブラウザ、CI での大量実行 | 対話的に書きながら確かめたいチーム |

詳しくは [[00_Playwright_目次]]。

### jsdom と happy-dom と Browser Mode

| | jsdom | happy-dom | Vitest Browser Mode |
|---|-------|-----------|---------------------|
| 正体 | Node.js 上の DOM 実装 | より軽量な DOM 実装 | 本物のブラウザ（Playwright などで起動） |
| 速さ | 普通 | 速い | 遅め |
| 再現度 | 高いが、レイアウト・CSS は計算しない | jsdom よりやや低い | 本物 |
| 選び方 | 迷ったらこれ | 速さを優先したいとき | レイアウト・フォーカス・Canvas などに依存するとき |

## 4. 構成例

### Vite + React の SPA

```bash
npm i -D vitest jsdom @testing-library/react @testing-library/dom \
  @testing-library/user-event @testing-library/jest-dom msw @playwright/test
```

- Unit / Integration：Vitest + jsdom + Testing Library + MSW
- E2E：Playwright（ログイン → 主要操作 の数本）

### Next.js（App Router）

- Client Component と純粋関数：Vitest + Testing Library
- **async な Server Component は Vitest で描画しにくい**ので、E2E（Playwright）で確かめる
- API Route / Server Action のロジックは、関数として切り出して Vitest で単体テスト

### Node.js の API サーバー

- Vitest（または Node.js test runner）で単体テスト
- DB を含む統合テストは Testcontainers で本物の DB を立てる
- 外部 API は MSW（Node）か nock でモック
