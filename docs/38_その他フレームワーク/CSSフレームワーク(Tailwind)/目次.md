# Tailwind CSS 目次（学習ルート）

このフォルダのTailwind解説を「迷いにくい順」「実務で困らない順」に並べた目次です。  
迷ったら上から順に進めれば、導入 → 書き方 → レイアウト/レスポンシブ → 設計/運用まで一通り繋がる構成になっています。

---

## 0. まず最初に（読み方）

- **ゴール**: Tailwindで“意図した見た目を、壊れにくく、後から直しやすく”実装できるようになる
- **前提**: CSSの基礎（ボックスモデル / Flex / Grid / 優先順位）がうっすら分かると早い
- **学び方**: 章ごとに「概念 → 手を動かす → よくある事故 → チェック」で固める

---

## 1. Tailwindの全体像（何が嬉しいか）

- **Tailwindとは / ユーティリティファースト**
  - Tailwindの立ち位置（CSSを捨てる道具ではなく“設計を加速する道具”）
- [[11-tailwind-basics|11 Tailwind CSS基礎]]

---

## 2. セットアップ（まず動く状態を作る）

- **CDN（学習用）とnpm（推奨）**
- **ビルドの基本**
  - `tailwind.config.*` の `content` が最重要（効かない原因No.1）
  - `@tailwind base/components/utilities`
- **開発体験**
  - watch、ホットリロード、整形（Prettier / class順序）

---

## 3. “書き方の規則”を先に覚える（ここで詰まりが減る）

- **クラスの読み方**
  - `-{size}` / `/{opacity}` / `[]`（任意値）などのパターン
- **状態とバリアント**
  - `hover:` `focus:` `active:` `disabled:` `group-hover:` `peer-*`
- **レスポンシブ**
  - `sm:` `md:` `lg:` `xl:`（ブレークポイントの考え方）
- **ダークモード**
  - `dark:` と運用方針（クラス方式/メディア方式）
- **優先順位**
  - 「後勝ち」と同系統ユーティリティの衝突（例: `text-sm` と `text-lg`）

---

## 4. よく使う基本ユーティリティ（実務で即使う）

- **レイアウト土台**
  - `container` `mx-auto` `p-*` `space-*` `gap-*`
- **サイズ**
  - `w-*` `h-*` `min-w-*` `max-w-*` `aspect-*`
- **余白**
  - `m-*` `p-*` `px-*` `py-*`
- **色**
  - `bg-*` `text-*` `border-*` `ring-*` `opacity-*`
- **タイポ**
  - `text-*` `font-*` `leading-*` `tracking-*` `truncate/line-clamp`
- **枠と影**
  - `border` `rounded-*` `shadow-*`

---

## 5. レイアウト（Flex / Grid / 溢れ / メディア）

- **Flex**
  - `flex` `flex-col` `items-*` `justify-*` `flex-wrap` `basis-*` `grow/shrink`
- **Grid**
  - `grid` `grid-cols-*` `col-span-*` `grid-rows-*` `place-*`
- **position / z-index**
  - `relative/absolute/fixed/sticky` `inset-*` `z-*`
- **overflow / スクロール**
  - `overflow-*` `overscroll-*` `scroll-*`

---

## 6. コンポーネントっぽく組む（“長いclass”を破綻させない）

- **再利用の単位**
  - まずはコピペでOK → 似たものが増えたら抽象化
- **抽象化の選択肢**
  - 文字列変数（定数）/ 関数 / コンポーネント
  - `clsx` / `classnames` / `cva`（クラス組み立て）
- **@apply（使いどころを限定）**
  - “共通の塊”だけに寄せる（肥大化防止）

---

## 7. 実務の定番UIパターン（だいたいこれ、が分かる）

- [[13-tailwind-recipes|13 Tailwind 実務レシピ集（UIパターン）]]
- **カード（基本の素体）**
  - 外枠: `rounded-*` `border` `shadow-*`
  - 余白: `p-*`（中身の呼吸）
  - 背景: `bg-white`（ダークなら `dark:bg-*`）
  - レイアウト: `flex`/`grid` + `gap-*`
- **他によくあるもの**
  - モーダル / ドロップダウン / トースト
  - タブ / アコーディオン / ツールチップ
  - ナビゲーション（ヘッダ/サイドバー）/ テーブル / フォーム

---

## 8. テーマと設計（チームで運用できる状態にする）

- **デザインのスケール**
  - spacing / color / typography の方針
- **カスタマイズ**
  - `theme.extend` の基本（上書きより“追加”中心）
  - 独自トークンの置き場
- **プラグイン**
  - `@tailwindcss/forms` `typography` `aspect-ratio`（必要な時だけ）

---

## 9. まず覚えるデバッグ手順（効かない/崩れるの最短ルート）

- **効かない**
  - `content` パス → クラス名のスペル → 同系統の衝突（後勝ち）→ バリアントの書き方
- **崩れる**
  - 親のサイズ制約（`max-w` / `min-w`）→ overflow → flex/gridの設定 → 画像/テキストの最小幅
- **レスポンシブで壊れる**
  - どのブレークポイントで何が上書きされるかをまず確認

---

## 10. 応用（必要になってからでOK）

- [[12-tailwind-advanced|12 Tailwind CSS応用]]
- **アニメーション**
  - `transition-*` `duration-*` `ease-*` `animate-*`（意味のある動きだけ）
- **パフォーマンス**
  - 生成CSSの把握、不要クラスの減らし方

---

## 11. 逆引き（困ったらここ）

- **“効かない”**: `content` → スペル → バリアント（`md:`や`hover:`の`:`）→ 競合（後勝ち）
- **“長すぎてつらい”**: まずは分割（コンポーネント化）→ その後に `cva` や `@apply` を検討
- **“レスポンシブが破綻する”**: 文字/画像/最小幅/overflow を先に疑う
