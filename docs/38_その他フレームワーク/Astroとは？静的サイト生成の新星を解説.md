## 詳しい要約

**テーマ：静的サイトジェネレーター Astro の特徴と使いどころ**

Astro は 2021 年に登場した、コンテンツ重視のサイトに特化したフレームワーク。デフォルトで JavaScript を出力せず、必要な部分だけ読み込む「Islands Architecture」で軽さを実現する。万能ではなく、「コンテンツ中心かどうか」で選ぶべきツールだというのが結論。

---

### 第1章 静的サイトジェネレーターの歴史

- HTML 手書き → 面倒になり **WordPress** などの CMS が流行（世界のサイトの 4 割以上という統計も）。
- WordPress はサーバーで PHP が動き DB からデータを取る**動的生成**のため、遅くセキュリティリスクもある。
- そこで**静的サイトジェネレーター**が登場。あらかじめ HTML を生成して配信するだけなので、サーバー負荷が軽く表示が速い。
- **Jekyll**（GitHub 創業者作、GitHub Pages で使われた）→ **Hugo**、**Gatsby**。ただし機能が増えるにつれてどれも複雑になった。

### 第2章 Astro とは何か

- 2021 年登場。ブログ・ポートフォリオ・ドキュメントサイトなど**コンテンツ重視のサイト**に最適化。
- 最大の特徴は **デフォルトで JavaScript を出力しない**こと。HTML と CSS だけを出力する。
- インタラクティブな機能が必要な部分だけ JS を読み込む。これを **Islands Architecture**（静的 HTML の海にインタラクティブな島が浮かぶイメージ）と呼ぶ。

### 第3章 なぜ注目されているのか

- 背景は**Web サイトが重くなりすぎている問題**。フロントエンドフレームワーク製のサイトは大量の JS を読み込み、スマホや遅い回線で表示が遅くなる。
- Google は表示速度を重視し、**Core Web Vitals** が検索順位に関係する。
- 例：ブログなら記事本文は静的 HTML で十分。コメント欄だけ React や Vue で作れば、そこだけ JS が読み込まれる。従来は小さなボタン 1 つのために大きなバンドルを読み込んでいた。

### 第4章 他のフレームワークとの違い

| 比較対象 | 特徴 |
|---|---|
| **Next.js** | SSG・SSR・API ルートなど多機能なフルスタック FW。シンプルなブログにはオーバースペック |
| **Gatsby** | React ベースの SSG。一時は人気だったが、ビルドが重く設定が複雑で開発も停滞気味。新規で選ぶ理由は少ない |
| **Hugo** | ビルドが非常に速いが、Go 言語製でテンプレートの書き方に癖がある |
| **Astro** | React・Vue・Svelte など好きな UI ライブラリを使え、**同じプロジェクト内で混在**もできる |

### 第5章 選ぶべき場面・選ばない場面

- **向いている**：ブログ、ポートフォリオ、ドキュメントサイト、コーポレートサイト、マーケティングサイト（表示が速く SEO にも強い）。
- **向いていない**：ログインがありユーザーごとにデータが違い、リアルタイム更新がある複雑なアプリ（SNS、チャット、ダッシュボード、管理画面）→ Next.js などが適する。
- **EC サイト**は規模次第。商品紹介中心で決済は外部サービス程度なら Astro でもいけるが、カートや在庫管理が複雑なら別の FW。

### まとめ

- Astro は「デフォルト 0 JS・必要なところだけ JS」の Islands Architecture で軽さを実現する。
- 判断基準は**コンテンツを見せるのが主か、ユーザーとのインタラクションが主か**。
- フレームワークは道具であり、目的に合ったものを選ぶことが大事。
