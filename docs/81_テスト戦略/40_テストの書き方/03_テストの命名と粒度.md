# テストの命名と粒度

テストが落ちたとき、最初に目に入るのは**テスト名**です。名前だけで「何が壊れたか」が分かれば、コードを開く前に原因の見当がつきます。この章では、テスト名の付け方と、1つのテストで何をどこまで確かめるか（粒度）を扱います。

---

## 1. テスト名は「仕様の一文」にする

| 悪い例 | 何が問題か | 良い例 |
|--------|------------|--------|
| `test('calcTotal')` | 何を確かめているか分からない | `会員は合計から10%割引される` |
| `test('正常系1')` | 番号では中身が分からない | `商品が1つのとき、合計は単価×数量になる` |
| `test('applyDiscountが呼ばれる')` | 実装の詳細を名前にしている | `割引期間中は割引後の価格を表示する` |
| `test('エラーになること')` | どんな条件で、どんなエラーか | `数量が0のとき、「数量を入力してください」を返す` |

### 名前の型

- **「〜のとき、〜になる」**（条件 + 期待結果）が基本。
- メソッド名を入れる型（`add_在庫0_エラーを返す`）もあるが、メソッド名を変えると名前も変える必要がある。**振る舞いの言葉で書く**ほうが長持ちする。
- 日本語のテスト名で問題ない。チームの言葉（ユビキタス言語）に合わせる。

### describe で文脈をまとめる

```ts
describe('calcShipping（送料計算）', () => {
  describe('合計が5000円以上のとき', () => {
    test('送料は無料になる', () => { /* … */ });
  });
  describe('合計が5000円未満のとき', () => {
    test('送料は500円になる', () => { /* … */ });
    test('離島は送料に1000円が加算される', () => { /* … */ });
  });
});
```

- 出力は「calcShipping（送料計算） › 合計が5000円未満のとき › 送料は500円になる」となり、一文の仕様として読めます。
- Given-When-Then を describe に割り当てる書き方は [[02_テストの構造（AAA・Given-When-Then）]] を参照。

## 2. 1テストで何を確かめるか

### 「1テスト1アサーション」の是非

- 厳密に `expect` を1つにする必要はありません。**1テスト1振る舞い（1つの理由で落ちる）** が本来の意図です。
- 1つの振る舞いを確かめるのに `expect` が2〜3個あるのは自然です（結果の値と、状態が変わっていないこと、など）。

```ts
// ○ 1つの振る舞い（在庫切れは追加できない）を2つの観点で確かめる
expect(result.ok).toBe(false);
expect(cart.items).toHaveLength(0);

// ✗ 複数の振る舞いを1つのテストに詰め込む
cart.add(item1); expect(cart.total).toBe(100);
cart.remove(item1); expect(cart.total).toBe(0);
cart.add(outOfStock); expect(cart.items).toHaveLength(0);
```

- 下の例は、最初の `expect` で落ちると後ろの確認が実行されず、何が壊れているのかの全体が見えません。

### 似たケースはパラメータ化する

境界値・同値クラスのように、同じ手順で入力だけ違うケースは表にまとめます。

```ts
test.each([
  { subtotal: 4999, expected: 500 },
  { subtotal: 5000, expected: 0 },   // 境界
  { subtotal: 5001, expected: 0 },
])('合計 $subtotal 円の送料は $expected 円', ({ subtotal, expected }) => {
  expect(calcShipping(subtotal)).toBe(expected);
});
```

- 境界値の選び方は [[07_境界値分析]]、同値クラスは [[06_同値分割法]] を参照。

## 3. テストファイルの置き方

| 置き方 | 例 | 向いている場面 |
|--------|----|----------------|
| **本番コードの隣** | `cart.ts` と `cart.test.ts` | 単体・統合テスト。テストがあるかがすぐ分かる |
| **tests フォルダに分ける** | `tests/e2e/checkout.spec.ts` | E2E テスト。ビルドから外しやすい |

- ファイル名の規則（`.test.ts` / `.spec.ts`）はチームで1つにそろえる。
