# テストの種類（機能・非機能）

[[01_テストレベル]] が「どの大きさをテストするか」だったのに対し、**テストタイプ**は「何の性質を確かめるか」の分類です。レベルとタイプは直交していて、「単体レベルの機能テスト」「システムレベルの性能テスト」のように組み合わせて使います。

---

## 1. JSTQB の4つのテストタイプ

| タイプ | 問い | 例 |
|--------|------|----|
| **機能テスト** | 何ができるか（What） | 検索すると該当商品が出る、合計金額が正しい |
| **非機能テスト** | どのくらいうまくできるか（How well） | 1秒以内に表示される、スクリーンリーダーで読める |
| **ブラックボックステスト** | 仕様どおりか（中身を見ない） | 仕様書から作ったテストケース |
| **ホワイトボックステスト** | 内部構造を通っているか（中身を見る） | 全ての分岐を1回は通す |

- ブラックボックス／ホワイトボックスは「テストケースの作り方」の区別でもあります。具体的な技法は 87_テスト設計技法（[[MOC_テスト設計技法]]）へ。

---

## 2. 機能テスト

仕様・要件・ユーザーストーリーに書かれた**機能が正しく動くか**を確かめます。

- **観点**：機能の完全性（必要な機能が全部あるか）、正確性（結果が正しいか）、適切性（目的に合っているか）。
- **テストケースの作り方**：同値分割・境界値・デシジョンテーブル・状態遷移など（[[06_同値分割法]] 〜 [[10_状態推移テスト]]）。
- 自動化しやすく、単体〜E2E のどのレベルでも行います。

---

## 3. 非機能テスト

ISO/IEC 25010 の品質特性にそって分類されることが多いです。

| 品質特性 | テストの例 |
|----------|------------|
| 性能効率性 | 負荷テスト、ストレステスト、応答時間の計測 |
| 互換性 | ブラウザ・OS・端末ごとの表示確認 |
| 使用性 | ユーザビリティテスト、アクセシビリティテスト |
| 信頼性 | 長時間稼働テスト、障害からの復旧テスト |
| セキュリティ | 脆弱性診断、ペネトレーションテスト |
| 保守性 | 静的解析、コードメトリクス |
| 移植性 | インストール・移行テスト |

詳しくは [[03_非機能テスト概要]] で扱います。

---

## 4. 変更に関係するテスト

JSTQB v3 までは「変更関連のテスト」として独立したタイプでした。v4 では次の2つが SDLC の中の活動として扱われます。

| テスト | 目的 | いつ |
|--------|------|------|
| **確認テスト（再テスト）** | 直したはずの欠陥が本当に直ったか | バグ修正の後 |
| **回帰テスト** | 変更が他の場所を壊していないか | あらゆる変更の後 |

- 回帰テストは**毎回同じものを流す**ので、自動化の効果が一番大きい領域です（[[03_テスト自動化の考え方]]）。
- 変更の影響範囲を見て、全部流すか一部に絞るかを決める（影響分析）。

---

## 5. 現場でよく聞くその他のテスト

| 名前 | 意味 | 位置づけ |
|------|------|----------|
| **スモークテスト** | ビルドやデプロイ直後に、主要機能が最低限動くかをざっと確かめる | 回帰テストの最小セット |
| **サニティテスト** | 特定の修正・機能について、深く入る前に筋が通っているかを軽く確かめる | 確認テストの前段 |
| **探索的テスト** | テスト設計と実行を同時に行う | テストの「やり方」（[[04_探索的テストとリスクベーステスト]]） |
| **ビジュアル回帰テスト** | スクリーンショットの差分で見た目の変化を検知する | 非機能（互換性・使用性）× 回帰 |
| **契約テスト** | API の提供側と利用側で決めた形が守られているか | 統合レベルの機能テスト |
| **メンテナンステスト** | 本番稼働中のシステムの修正・移行・廃止に伴うテスト | JSTQB 2.4 |

名前が違っても、**レベル（どの大きさ）× タイプ（何の性質）× やり方（スクリプト／探索）** に分解すると整理できます。

---

## 6. 組み合わせの例

| | 機能 | 非機能 |
|---|------|--------|
| **Unit** | 価格計算関数のテスト | 関数の実行時間のベンチマーク |
| **Integration** | フォーム送信の流れ | コンポーネントのアクセシビリティ（axe） |
| **E2E** | ログイン→購入の流れ | Lighthouse による表示速度の計測 |
| **受け入れ** | 業務シナリオの確認 | 実ユーザーによる使いやすさ評価 |
