# スクロール率・滞在時間の計測

## 🎯 このページのゴール

- LPのスクロール到達率（25/50/75/100%）を計測できる
- 「特定セクションの表示」を要素表示トリガーで計測できる
- 滞在時間・エンゲージメント時間の考え方を理解する

---

## 1. なぜスクロール計測が重要か

LPは **縦長1ページ** で構成され、ユーザーは上から順に読みます。
どこまで読まれたかが分かれば、**離脱ポイント = コンテンツ改善ポイント** になります。

```
Hero          100%読まれる (当然)
  ↓
特徴紹介       85%
  ↓
料金          60% ← この手前で離脱が多い
  ↓
お客様の声     40%
  ↓
FAQ          30%
  ↓
フォーム      25% ← ここまで来た人だけCV候補
```

---

## 2. 方法A: GA4の拡張計測（自動）

GA4のデータストリーム設定で **拡張計測機能** をONにすれば、**90%スクロール** は自動計測されます。

```
GA4 → 管理 → データストリーム → 該当ストリーム選択
  → 「拡張計測機能」> スクロール数 がON
```

- 発火: 縦90%到達で1回のみ
- イベント名: `scroll`
- パラメータ: `percent_scrolled = 90`

### デメリット

- **90%1点しか取れない**
- 25/50/75% のきめ細かい分析はできない

---

## 3. 方法B: GTMでスクロール距離トリガー（推奨）

25/50/75/90% など **任意の％** で発火できる。

### Step1: 組み込み変数の有効化

```
変数 > 組み込み変数 > 次をチェック:
  ☑ Scroll Depth Threshold
  ☑ Scroll Depth Units
  ☑ Scroll Direction
```

### Step2: トリガー作成

```
トリガー > 新規
  タイプ: スクロール距離
  縦方向のスクロール深度: 割合
  値: 25, 50, 75, 90    (カンマ区切り)
  このトリガーの発火場所: 一部のページ
  条件: Page Path equals "/" (LPのURLに限定する場合)
  名前: Scroll - LP 25/50/75/90
```

### Step3: タグ作成

```
タグ > 新規
  タイプ: GA4 イベント
  イベント名: scroll_depth
  パラメータ:
    percent_scrolled = {{Scroll Depth Threshold}}
    page_path        = {{Page Path}}
  トリガー: Scroll - LP 25/50/75/90
```

### 命名の注意

- GA4の自動計測 `scroll` と **同じ名前を避ける**（`scroll_depth` など別名に）
- 自動計測（90%のみ）と併用すると **90%のみ二重発火** するので、どちらか片方に統一

### 拡張計測を無効化してGTMに一本化するのがおすすめ

```
データストリーム > 拡張計測機能 > スクロール数 をOFF
  → GTMだけで25/50/75/90%を計測
```

## 4. 方法C: 要素の表示トリガー（特定セクションの到達率）

「料金セクションが画面に入った」「フォームが表示された」など **具体的な要素の表示** を計測する方法。

### HTML例

```html
<section id="pricing">料金...</section>
<section id="contact-form">お問い合わせ...</section>
```

### トリガー（料金セクション到達）

```
トリガー > 新規
  タイプ: 要素の表示
  選択方法: ID
  要素ID: pricing
  表示されるタイミング: 1ページにつき1度
  最低表示比率: 50% (要素の50%が見えたら発火)
  最低表示時間: 1000ms
  名前: Visibility - Section Pricing
```

### タグ

```
タグ > 新規
  タイプ: GA4 イベント
  イベント名: section_view
  パラメータ:
    section_name = pricing
  トリガー: Visibility - Section Pricing
```

### 活用例

```
section_view (pricing)    → 料金到達率
section_view (testimonial) → お客様の声到達率
section_view (contact-form) → フォーム到達率  ← フォームCVの母数として重要
```

→ **探索レポート** で「セッション数 vs section_view (contact-form) 数」を比較すれば、**コンテンツ改善の効果** を数値化できます。

## 5. 滞在時間の計測

### GA4の標準指標「エンゲージメント時間」

GA4では **「平均エンゲージメント時間」** が滞在時間の主要指標。

- ページが **フォアグラウンドにある時間** を計測
- タブを切り替えたり他ウィンドウをアクティブにした時間は **除外**
- UA時代の「平均セッション時間」より **実態に近い**

標準レポートで自動的に見られます:

```
レポート → エンゲージメント → ページとスクリーン
  → 表の列に「平均エンゲージメント時間」
```

### タイマートリガーで「X秒以上滞在」を計測

特定時間を超えたユーザーを別イベント化したい場合:

```
トリガー > 新規
  タイプ: タイマー
  イベント名: gtm.timer
  間隔: 30000 ms (30秒)
  上限: 1
  条件: Page Path equals "/"
  名前: Timer - 30s on LP
```

```
タグ:
  イベント名: time_on_page_30s
  トリガー: Timer - 30s on LP
```

GA4でキーイベント化すれば「30秒以上滞在したユーザー」をCV扱いにもできる（**マイクロコンバージョン** と呼ぶ）。

## 6. スクロール計測の落とし穴

### 短いLPでは50%まで一瞬で発火

- スマホでファーストビューが画面の80%を占めると、**ページロード直後に50%スクロール済み** になる
- 対策: **25%は除外**、50/75/90%で運用
- または **スクロール距離をピクセル単位** で指定

### 無限スクロール・遅延ロード

- 記事ページなどで画像が遅延ロードされると、**ページの総高さが変動** → 計測が不安定
- 対策: 要素表示トリガーで「特定セクションの表示」を代用

### SPAの経路変更

- Next.js等のクライアントルーティングでは「新しいページに来た」扱いが曖昧
- 対策: `history.pushState` フックで `gtm.historyChange` をトリガー、**各遷移ごとにスクロール計測をリセット**

## 7. 分析に使う軸の例

探索レポートで組み合わせると効果的な分析軸:

| 縦軸（ディメンション） | 横軸（指標） | 何が分かる？ |
|---------------------|-------------|-------------|
| 流入元 × percent_scrolled | ユーザー数 | どの流入が深く読む？ |
| デバイス × percent_scrolled | エンゲージ率 | モバイル/デスクトップで読み方が違う？ |
| セクション名（`section_view`） | 到達ユーザー数 | どこで離脱している？ |
| ページタイプ × 平均エンゲージメント時間 | — | LP別の熱量 |

## 8. Microsoft Clarity との併用（無料・推奨）

GA4単体では分からない「**実際の動き**」を補完する無料ツール:

- **ヒートマップ**: クリック位置・スクロール到達ヒートマップ
- **セッション録画**: ユーザーのマウス/タップを録画再生
- **AI分析**: 異常なユーザー行動の自動ハイライト

LP改善の実務では **GA4 + Clarity の組み合わせが定番**。両方GTMで入れられます。
