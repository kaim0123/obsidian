# LP計測の全体像

## 🎯 このページのゴール

- LP（ランディングページ）で **測るべきKPIを俯瞰** する
- 「何を・いつ・どう」測るかを **パターンで覚える**
- 後続ノート（ボタンクリック・フォーム送信等）の **読む順序** を把握する

---

## 1. LP運用で測りたいこと

LPの目的は明確で、**コンバージョン（問い合わせ/購入/登録）を増やすこと**。
そのために、最低でも次のデータを取ります:

| 指標 | 何が分かる？ |
|------|-------------|
| 流入数・流入元 | どこから何人来たか（広告 / 検索 / SNS / 直接） |
| 主要CTAのクリック数 | ボタン設置位置の良し悪し |
| スクロール率（25/50/75/100%） | 最後まで読まれているか・どこで離脱するか |
| フォーム表示率 | 問い合わせフォーム部分まで到達した人数 |
| **フォーム送信完了数（CV）** | 最重要指標 |
| フォーム離脱率 | どの項目で入力を諦めたか |
| 電話番号タップ数 | モバイルで電話CVを測る |
| 滞在時間 | 興味の深さの代替指標 |

## 2. 計測の全体フロー（定番パターン）

```
[1] HTMLに GTM スニペット設置
[2] GA4 の Googleタグを GTM 経由で設置
[3] 組み込み変数を有効化 (Click系・Form系)
[4] 個別イベントのトリガー・タグを作成
    ├ CTAクリック          → [[01_CTAボタンのクリック計測]]
    ├ フォーム送信完了      → [[02_フォーム送信完了の計測]]
    ├ 電話/メールリンク     → [[03_電話番号タップ・メールリンクの計測]]
    ├ スクロール            → [[04_スクロール率・滞在時間の計測]]
    └ 外部リンク/DL         → [[05_外部リンク・ファイルダウンロードの計測]]
[5] GA4でキーイベント化 (CV指定)
[6] 広告(Google Ads / Meta) と連携
[7] 定期モニタリング・改善
```

## 3. 各イベントをGA4イベントとしてどう名付けるか

**表記ゆれを防ぐため、最初にイベント名設計書を作る** こと。

### 推奨命名表

| 目的 | GA4 イベント名 | 必須パラメータ |
|------|--------------|--------------|
| CTAボタンクリック | `cta_click` | `button_name`, `cta_position` |
| 電話番号タップ | `tel_tap` | `phone_number`, `tap_position` |
| メールリンククリック | `mail_click` | `mail_to`, `position` |
| フォーム表示（フォーカス開始） | `form_start` | `form_id` |
| **フォーム送信完了** | `generate_lead` or `contact_form_submit` | `form_id`, `form_type` |
| スクロール | `scroll`（自動）or `scroll_depth` | `percent_scrolled` |
| 外部リンククリック | `click`（自動）or `outbound_click` | `link_url`, `link_domain` |
| ファイルダウンロード | `file_download` | `file_url`, `file_extension` |
| 動画再生 | `video_start` / `video_complete` | `video_title` |

> 💡 **「業種推奨イベント名」** をできるだけ使う。例えばリード獲得系は `generate_lead` を推奨。広告側の最適化機能とも連動する。

## 4. LP構成とCV計測ポイントの対応図

```
┌────────────────────────┐
│ ヒーローエリア          │
│  [お問い合わせはこちら] │ ← cta_click (position: hero)
├────────────────────────┤
│ 特徴紹介                │ ← scroll 25%
├────────────────────────┤
│ お客様の声              │ ← scroll 50%
├────────────────────────┤
│ 料金プラン              │ ← scroll 75%
│  [無料相談する]         │ ← cta_click (position: pricing)
├────────────────────────┤
│ FAQ                    │ ← scroll 90%
├────────────────────────┤
│ お問い合わせフォーム    │ ← form_start
│  ...                   │
│  [送信する]             │ ← generate_lead (on success)
└────────────────────────┘
   電話ボタン (fixed)     ← tel_tap
```

## 5. 測定の優先順位（最初にやるべき順）

### 優先度：★★★（必須）

1. **GA4 PV計測** — 最低限の流入把握
2. **フォーム送信完了計測** — 売上/リードに直結
3. **CTAボタンクリック** — 改善の最大効果ポイント

### 優先度：★★（強く推奨）

4. 電話番号タップ（モバイル主戦場のLPでは必須級）
5. スクロール率（コンテンツ改善用）
6. フォーム離脱ポイント（CVR改善用）

### 優先度：★（余裕があれば）

7. ボタンのヒートマップ（GA4単体では不可 → Microsoft Clarity等と併用）
8. 動画再生率
9. チャット起動数

## 6. 広告との連携（効果測定の仕上げ）

CV計測だけで終わらせず、必ず **広告プラットフォーム側** にCVをインポートします。

| 広告 | 連携方法 |
|------|---------|
| Google Ads | GA4 → Admin → プロダクトリンク → Google Ads リンク → キーイベントをインポート |
| Meta（Facebook/Instagram） | GTMで Meta Pixel + Conversions API を設置 |
| LINE広告 | GTMで LINE Tag を設置 |
| Yahoo!広告 | コンバージョンタグ(CVタグ)をGTMで設置 |
| TikTok広告 | GTMで TikTok Pixel |

**広告側CV = GA4側CV ではない** ことに注意:
- 広告はクリック→CVまでの経路を自前のアトリビューションで追う
- GA4は広告クリック後に来た人の行動を中心に見る
- **双方でCV数に差が出る** のは仕様

## 7. 2026年の運用の肝

### サーバーサイドGTM検討ライン

- 月間PV **10万超** / 広告でCV最適化している LP は検討開始
- クライアント側だけでは **20〜40%のデータを取り逃がす**

### Consent Mode v2 対応

- EUユーザーが1人でも来る可能性があるなら必須レベル
- CMP（CookieHub等）と GTM を連携

### AI活用

- Analytics Advisor で「今週CVが減った理由」を即要約
- Microsoft Clarity（無料）のAIサマリーと併用すると、**行動録画+AI分析** が揃う

## 8. 運用モニタリングのサンプル頻度

| 頻度 | 確認項目 |
|------|---------|
| 毎日 | CV数・流入数・広告費対効果 |
| 週次 | 流入元別CVR、スクロール到達率、曜日傾向 |
| 月次 | キーイベントの定義見直し、フォーム離脱ポイント分析、A/B施策の検証 |
