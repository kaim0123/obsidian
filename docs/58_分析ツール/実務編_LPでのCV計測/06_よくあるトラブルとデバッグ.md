# よくあるトラブルとデバッグ

## 🎯 このページのゴール

- LP計測で **実際に起きがちなトラブル** の典型を知る
- 原因の **切り分け順序** を身につける
- 即チェックできる **デバッグチェックリスト** を手元に持つ

---

## 1. トラブル対応の基本フロー

```
[問題発生]
   ↓
[①再現確認] 自分のブラウザで同じ現象が起きるか？
   ↓
[②スコープ特定] どのイベント？どのタグ？どの条件？
   ↓
[③発火側確認] GTMプレビューで「Fired」になっているか？
   ↓
[④受信側確認] GA4リアルタイム / DebugViewに届いているか？
   ↓
[⑤集計側確認] 24h待っても定型レポートに反映されているか？
```

**多くの場合、③の時点で犯人がわかります。** 「発火していない」のか「発火しているがGA4に届かない」のかで、調査の方向が変わります。

## 2. 症例別トラブル集

### 症例1: 「GA4 リアルタイムに何も出ない」

#### 考えられる原因

| 原因 | 確認 |
|------|------|
| GTMの公開を忘れている | GTM右上の「変更」数を確認 |
| 計測ID（G-...）が違う | タグ設定のID欄を再確認 |
| gtag.js と GTM が二重設置 → 片方止まっている | ソースコード検索 `gtag('config'` |
| ブラウザに広告ブロッカー | シークレットモード + 拡張無効で試す |
| 自社IPでデータ除外 | 管理 → データフィルタ確認 |
| Consent Modeで analytics_storage=denied | プレビューの Consent タブ |
| GTMスニペット設置位置が間違い | `<head>` に正しく入っているか |

### 症例2: 「CTAクリックが発火しない」

#### 考えられる原因

| 原因 | 確認 |
|------|------|
| 組み込み変数 `Click Classes` 未有効化 | 変数 > 組み込み変数を確認 |
| トリガー条件の文字列ミス（スペース・大文字） | 実際のclass属性と比較 |
| ボタンが `<button>` でクリック時に `preventDefault()` | JSで遷移していないか |
| 動的生成ボタン（React/Vue） | `DOM Ready` トリガーにしてみる |
| `Click Classes contains "btn"` のような曖昧条件で **他ボタンまで発火** | プレビューで誤発火確認 |

#### 切り分け手順

1. **素の `クリック - すべての要素 / すべてのクリック`** トリガーを仮で作り、とにかく発火するか
2. 発火する → 条件式の書き方が悪い
3. 発火しない → トリガー自体の設定か変数の問題

### 症例3: 「フォーム送信の GTM自動トリガーが動かない」

#### 考えられる原因

| 原因 | 対策 |
|------|------|
| Ajax送信 (e.preventDefault) | dataLayer方式に切り替え |
| reCAPTCHA v3 導入済み | dataLayer方式 |
| iframe埋め込みフォーム | 親ウィンドウからメッセージ経由 or サンクスページ遷移 |
| 仮想フォーム（`<form>`タグなし） | dataLayer方式 |
| SPA（Next.js/React） | dataLayer方式が確実 |

→ **9割は dataLayer.push への切り替えで解決**

### 症例4: 「PVが2倍にカウントされる」

#### 考えられる原因

| 原因 | 対策 |
|------|------|
| gtag.js と GTM併設 | gtag.jsを削除 |
| GA4プロパティに Googleタグが2つ | 1つだけに統合 |
| SPAで pushState とページ遷移の両方でPVイベント | どちらか片方 |
| プレビューモード状態のまま | プレビューを終了 |
| Chrome拡張 `Google Analytics Debugger` が2重計測している | 無効化 |

### 症例5: 「DebugViewには出るが、リアルタイムに出ない」

- 普通ありえない（両方とも直近の計測）
- 考えられる原因: **計測IDが違う** or **プロパティを見間違えている**
- GA4の左上プロパティ名を再確認

### 症例6: 「リアルタイムに出るが、翌日の定型レポートに反映されない」

- **集計遅延は24〜48時間** なので、まず待つ
- 数日経っても出ない:
  - **データ保持期間が短い**（2か月のまま）
  - **サンプリングでフィルタされている**
- まれなケース: **Googleの集計障害**（Google公式ステータスで確認）

### 症例7: 「キーイベント化したのに、CV数がゼロ」

- キーイベント化は **未来のイベントにしか効かない**（過去データは対象外）
- 設定から **24〜48時間後** のデータから反映
- それでも0なら **イベント名のtypo** を疑う（GTM側とGA4側の名前が一致しているか）

### 症例8: 「Google Adsと GA4で CV数が違う」

- これは **仕様**。誤差5〜20%は正常範囲
- 主要な原因:
  - 広告: **クリックベース**（広告クリック→CVまで90日アトリビューション）
  - GA4: **セッションベース**（CV時のセッションの参照元）
- 広告のCVが多すぎる → **二重発火疑い**（GTMのタグを点検）
- GA4のCVが多すぎる → **非広告からのCVも含まれている**（当然）

### 症例9: 「モバイルだけ計測されない」

- iOS Safari の **ITP**（Intelligent Tracking Prevention）
- 自社ドメインでない `.googletagmanager.com` / `analytics.google.com` が **広告トラッカー扱い** で遮断される可能性
- 抜本対策: **サーバーサイドGTM** で自社ドメイン経由にする

### 症例10: 「ページ遷移時に計測イベントが送られない」

- 別ページへのリンククリック → イベント発火 → **送信完了前にページ離脱**
- 対策1: トリガーで **「タグの発火を待機」** をON（最大2000ms）
- 対策2: `navigator.sendBeacon` を使うGA4の標準動作を信頼（通常はこれでOK）

## 3. デバッグ即実行リスト（5分チェック）

### A. ブラウザ側で確認

1. シークレットウィンドウで対象ページを開く
2. F12 → Network タブ → フィルタに `collect` を入力
3. 計測イベントを起こす（クリック等）
4. `collect?v=2&tid=G-XXXXXXXXXX&...` が **200** で返っているか
5. そのリクエストの **Payload** を開いて `en=xxx` にイベント名があるか

### B. GTMプレビューで確認

1. GTM 右上「プレビュー」
2. 対象サイトを操作
3. Tag Assistant の該当イベントをクリック
4. **Tags Fired** に出ているか
5. 出ていなければ **Tags Not Fired** で理由を見る
6. **Variables** タブで条件に使う変数の値を確認

### C. GA4側で確認

1. リアルタイム → イベント（届いているか）
2. DebugView → 自分のセッションでパラメータまで確認
3. 管理 → イベント → 該当イベントが表示されるか（表示は数時間遅延あり）

## 4. 「原因がわからない」時の最終手段

### カスタムHTMLでconsole.logを仕込む

```html
<script>
  window.dataLayer = window.dataLayer || [];
  var _origPush = window.dataLayer.push;
  window.dataLayer.push = function() {
    console.log('[DL PUSH]', arguments[0]);
    return _origPush.apply(window.dataLayer, arguments);
  };
</script>
```

→ GTMの前に設置すると、**pushされる全内容がコンソールに出る**

### トリガーを一時的に「素のクリック」にして発火確認

条件付きトリガーがダメなら「クリック = すべての要素 / すべてのクリック」で **必ず発火する** 状態を作って、タグ側を疑う

### 別プロパティ・別コンテナで切り分け

- 新しい計測IDを作って、**そっちに送信** してみる
- 送れる → 元のプロパティの設定問題
- 送れない → GTM側の問題

## 5. 予防策（この運用で大半のトラブルを避けられる）

### 🛡 予防1: 命名規則を文書化

- イベント名・パラメータ名・変数名のルールを **最初に決める**
- 表記ゆれで別イベント扱いになる事故を予防

### 🛡 予防2: ワークスペースを分ける

- 検証用・本番用 で GTMワークスペースを分離
- **未検証の変更** が本番に混入することを防ぐ

### 🛡 予防3: バージョン名を必ず書く

- 「公開」時に **変更内容** を残す
- 「何がおかしくなった？」を追跡可能に

### 🛡 予防4: 月次モニタリング

- 毎月1日: 主要CV数・PV数の前月比グラフを確認
- 50%以上の急変は **計測不具合** の疑いあり

### 🛡 予防5: 外部モニタリングツール連携

- **Google Search Console** で検索流入を二重チェック
- **Microsoft Clarity** で実ユーザー行動と照合
