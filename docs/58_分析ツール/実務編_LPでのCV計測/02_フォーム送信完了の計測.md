# フォーム送信完了の計測

## 🎯 このページのゴール

- LPで **最重要CV** である「問い合わせフォーム送信完了」を計測できる
- 4つのパターン（サンクスページ / 要素表示 / dataLayer / 送信ボタンクリック）から **自分のサイトに合った方法** を選べる
- それぞれの **落とし穴と対策** を理解する

---

## 1. 4つの計測パターン（決定ガイド）

| パターン | 精度 | 実装難度 | サイト側の条件 |
|---------|------|---------|--------------|
| **A: サンクスページPV** | ★★★★★ | ★ | 送信後に `/thanks` 等に遷移する |
| **B: 要素の表示（Element Visibility）** | ★★★★ | ★★ | 送信後に同ページ内で「ありがとうございました」等が表示される |
| **C: dataLayer.push（推奨）** | ★★★★★ | ★★★ | 開発側にJS実装を依頼できる |
| **D: 送信ボタンクリック** | ★★ | ★ | 他のパターンが使えない時の妥協案 |

→ **理想は C（dataLayer）**、**一番楽は A（サンクスページ）**。実務ではこの2つがほとんど。

---

## 2. パターンA: サンクスページのPVでCV判定

**LPが `/contact.html` → 送信後 `/thanks.html` に遷移** するケース。

### GTM設定

#### トリガー

```
トリガー > 新規
  タイプ: ページビュー
  このトリガーの発火場所: 一部のページビュー
  条件: Page Path  equals  "/thanks.html"
  名前: PV - Thanks Page
```

#### タグ

```
タグ > 新規
  タイプ: GA4 イベント
  イベント名: generate_lead
  パラメータ:
    form_id    = contact
    form_type  = inquiry
    value      = 3000        (リード1件の想定価値)
    currency   = JPY
  トリガー: PV - Thanks Page
```

### GA4でCV化

1. 上記イベントが GA4 リアルタイムに届くのを確認
2. 管理 → イベント → `generate_lead` を **キーイベントとしてマーク**

### この方式の強み

- **最もシンプル**で、JSの知識が不要
- 送信完了 = サンクスページ到達 = 100%本物のCV
- **誤発火がほぼ無い**

### 注意点

- 直接 `/thanks.html` をURLで開いた人もCVカウントされる
  - 対策: サンクスページに **noindex + robots.txt** を設定。検索流入も防ぐ
  - 対策: サンクスページに **リダイレクト防止チェック**（sessionStorageで送信成功フラグ）を実装
- トラフィックが少ないとCVまでのセッションが途切れて、**参照元が(direct)になる** 場合がある
  - 対策: **URLにクエリパラメータを付けない**、**サブドメインを跨がない**

## 3. パターンB: 要素の表示（Element Visibility）

**送信後に同じページで「送信完了しました」が表示** されるケース。

### HTML例

```html
<form id="contact-form">
  <!-- ... -->
  <button type="submit">送信する</button>
</form>

<div id="thanks-message" style="display:none">
  送信ありがとうございました！
</div>

<script>
// 送信成功時にサンクスメッセージを表示
document.querySelector('#contact-form').addEventListener('submit', async function(e) {
  e.preventDefault();
  const res = await fetch('/api/contact', { method: 'POST', body: new FormData(this) });
  if (res.ok) {
    document.querySelector('#thanks-message').style.display = 'block';
  }
});
</script>
```

### GTM設定

#### トリガー

```
トリガー > 新規
  タイプ: 要素の表示
  選択方法: CSSセレクタ
  要素セレクタ: #thanks-message
  このトリガーを発火させるタイミング: 1ページにつき1度
  最低表示時間 (ミリ秒): 1000
  名前: Visibility - Thanks Message
```

#### タグ

```
タグ > 新規
  タイプ: GA4 イベント
  イベント名: generate_lead
  パラメータ:
    form_id   = contact
    form_type = inquiry
  トリガー: Visibility - Thanks Message
```

### 注意点

- `display:none` → `display:block` の切り替えだけでなく、**DOM変更検知** も必要な場合は「DOM変更」オプションをON
- **スクロールで下に隠れていた要素** が見えるようになっただけでも発火するので、**display切り替えパターン** で設計するのが無難

## 4. パターンC: dataLayer.push（推奨・最も堅牢）

**開発側で送信成功時に `dataLayer.push`** してもらう方式。

### HTML/JS側

```html
<form id="contact-form">
  <input name="email" type="email" required>
  <!-- ... -->
  <button type="submit">送信する</button>
</form>

<script>
document.querySelector('#contact-form').addEventListener('submit', async function(e) {
  e.preventDefault();
  try {
    const res = await fetch('/api/contact', {
      method: 'POST',
      body: new FormData(this)
    });
    if (!res.ok) throw new Error('Send failed');

    // ✅ サーバーが成功を返した時だけpush
    window.dataLayer = window.dataLayer || [];
    window.dataLayer.push({
      event: 'contact_form_submit_success',
      form_id: 'contact',
      form_type: 'inquiry'
    });

    // サンクス表示
    location.href = '/thanks.html';
    // または同ページでメッセージ表示
  } catch (err) {
    alert('送信に失敗しました。もう一度お試しください。');
  }
});
</script>
```

### GTM設定

#### トリガー

```
トリガー > 新規
  タイプ: カスタム イベント
  イベント名: contact_form_submit_success
  名前: Custom - Contact Submit Success
```

#### データレイヤー変数

```
変数 > 新規
  タイプ: データレイヤー変数
  変数名: form_id
  バージョン: 2
  名前: DLV - form_id
```

同様に `DLV - form_type` も作成

#### タグ

```
タグ > 新規
  タイプ: GA4 イベント
  イベント名: generate_lead
  パラメータ:
    form_id   = {{DLV - form_id}}
    form_type = {{DLV - form_type}}
  トリガー: Custom - Contact Submit Success
```

### この方式の強み

- **送信が本当に成功した時だけ** 発火（サーバー200を確認してからpushするため）
- **バリデーションエラー** や **ネットワークエラー** でCVが膨らまない
- **フォームの種類ごとに form_id を切り替え** て使いまわせる
- **SPA（Next.js / Nuxt / React等）** で一番綺麗に動く

### 開発者への依頼文テンプレ

```
フォーム送信成功時に、以下のコードを追加してください:

window.dataLayer = window.dataLayer || [];
window.dataLayer.push({
  event: 'contact_form_submit_success',
  form_id: 'contact',          // フォームを識別するID
  form_type: 'inquiry'          // 問い合わせ種別 (inquiry / estimate / ...)
});

※ サーバーから200が返った直後に追加してください。
※ バリデーションエラーやサーバーエラー時はpushしないでください。
```

## 5. パターンD: 送信ボタンクリック（最終手段）

他の方法が取れない時の **暫定・精度低め**。

### トリガー

```
タイプ: クリック - すべての要素
条件:
  Click Element  matches CSS selector  button[type="submit"]
  AND Form ID equals "contact-form"
```

### タグ

```
GA4 イベント
イベント名: form_submit_click
  (generate_leadは使わない方が安全。別名で送って切り分ける)
```

### 重大な注意

- **バリデーションエラー時もクリックは発生する** → CVが膨らむ
- **ユーザーが複数回ボタンを押す** → 重複計測
- **送信完了との数字の乖離** が常に付きまとう

→ 本格運用ではA/B/Cのいずれかに **必ず切り替えるべき**

## 6. フォーム離脱ポイントの計測（応用）

どの入力欄で離脱しているかを調べるには、**フォーカス/ブラーイベント** を計測する。

```js
// 各入力欄の最初のフォーカスで form_start を送る
document.querySelectorAll('#contact-form input, #contact-form textarea').forEach(el => {
  el.addEventListener('focus', function once() {
    window.dataLayer.push({
      event: 'form_field_focus',
      field_name: this.name
    });
    this.removeEventListener('focus', once);
  }, { once: true });
});
```

GA4側で入力欄別の開始率を探索レポートで可視化できる。

## 7. サードパーティフォームの計測

### reCAPTCHA が入っているフォーム

- GTMの「フォーム送信」自動検知トリガーは **reCAPTCHA v2/v3 で動かない** ことが多い
- 必ず **dataLayer方式（パターンC）** を使う

### Googleフォーム埋め込み

- iframe内のため **GTMから送信イベントを取れない**
- 対策: Googleフォームのリダイレクト先ページを自前の `/thanks` にする → パターンAへ

### HubSpot / Salesforce / Pardot フォーム

- それぞれ公式で **submit完了コールバック** がある
  - HubSpot: `onFormSubmitted` コールバック
  - Pardot: `successUrl` へのリダイレクト
- それを使って dataLayer.push

### Wix / STUDIO / Webflow

- 管理画面から **サンクスページ遷移の設定** が可能 → パターンAで対応

## 8. 送信後の確認フロー

1. プレビューモードON
2. 実際にフォームを入力して送信
3. Tag Assistant で **`generate_lead` タグが Fired**
4. `Data Layer` タブで **push されたオブジェクト** が期待通り
5. GA4 → リアルタイム → イベント に **`generate_lead`** が表示
6. 24時間後、GA4 → 管理 → イベントで **`generate_lead` をキーイベント化**

---

## 9. 広告との連携

### Google Ads

1. GA4でキーイベント化
2. Google Adsとのアカウント連携
3. Ads → コンバージョン → インポート → GA4 → `generate_lead` を選択

### Meta広告（Lead広告との整合）

```
GTMで Meta Pixel - Lead タグを追加
  標準イベント: Lead
  value: 3000
  currency: JPY
同じ Custom - Contact Submit Success トリガーで発火
```

### Conversions API（2026年推奨）

- **iOS 14+ のATT（App Tracking Transparency）** 以降、Pixelだけでは精度が落ちる
- 対策: **サーバーサイドGTM 経由で Conversions API** に送る
- Meta側では「Pixel + CAPI」両方で計測して重複排除（event_idを付与）

## 10. よくあるトラブル

### トラブル1: サンクスページでGAタグが2回発火

- HTMLに残った **古いgtag.js** とGTMが両方生きている
- 対策: 古いコードを削除

### トラブル2: サンクスページのリファラが(direct)

- フォームが別ドメインに送信 → リダイレクトで戻ってくると参照元が失われる
- 対策: フォーム送信先を同ドメイン/サブドメインに統一

### トラブル3: dataLayer.push が発火しない

- pushのタイミングが **GTM読み込み前**
- 対策: JSでGTM読み込み後（DOMContentLoaded以降）に実行

### トラブル4: カスタムイベントトリガーが反応しない

- イベント名の **大文字小文字・typo**
- 対策: Data Layer タブでイベント名を **コピペ** で一致させる

### トラブル5: 広告側CVと GA4側CV の数字が合わない

- **これは仕様**。広告はクリックIDベース、GA4はセッションベース
- 誤差5〜20%は許容範囲。大きくずれる場合はタグ二重発火を疑う
