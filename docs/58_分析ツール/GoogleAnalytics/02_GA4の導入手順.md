# GA4の導入手順

## 🎯 このページのゴール

- GA4 のアカウント → プロパティ → データストリームを **実際に作れる** ようになる
- **計測ID（G-XXXXXXXXXX）** を取得する
- 計測タグの **3つの設置方法** を理解し、現場では「GTM経由」を選ぶ理由を知る

---

## 1. 手順の全体像

```
Step1. Googleアカウントを用意
   ↓
Step2. GA4アカウント作成 (https://analytics.google.com)
   ↓
Step3. プロパティ作成 (サイト名/タイムゾーン/通貨 設定)
   ↓
Step4. ビジネス情報の入力 (業種・規模・利用目的)
   ↓
Step5. データストリーム作成 → 計測ID(G-XXXXXXXXXX)が発行される
   ↓
Step6. 計測タグをサイトに設置 ← ここで3択(後述)
   ↓
Step7. リアルタイムレポートで計測されているか確認
```

---

## 2. Step1〜5: 管理画面での作業

### アカウント・プロパティ作成

1. https://analytics.google.com にアクセス
2. 「測定を開始」→ アカウント名を入力（通常は **会社名**）
3. 「次へ」→ プロパティ名を入力（通常は **サイト名**）
4. **タイムゾーン**: `日本`、**通貨**: `日本円(JPY)` を選択
5. 業種・ビジネス規模・利用目的を選択

> 💡 タイムゾーンと通貨は **後から変更可能だが、過去データは遡って変換されない**。最初に正しく設定するのが鉄則。

### データストリーム作成 → 計測ID取得

1. 「プラットフォームを選択」で **ウェブ** を選ぶ
2. ウェブサイトURLとストリーム名を入力
3. 「ストリームを作成」をクリック
4. 表示された **測定ID（Measurement ID）** をコピー
   - 形式: `G-` で始まる10文字前後（例: `G-ABC12D3E4F`）
   - `AW-` で始まる場合は **Google広告のID** なので混同しないこと

**計測IDの場所**:
```
管理 (左下の歯車アイコン)
  └ データストリーム
      └ 該当のウェブストリームをクリック
          └ 画面右上の「測定ID」
```

## 3. Step6: 計測タグを設置する3つの方法

### 方法A: HTMLに直接貼る（gtag.js）

GA4が自動生成するスニペットを、**全ページの `</head>` の直前** にコピペします。

```html
<!-- Google tag (gtag.js) -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-ABC12D3E4F"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'G-ABC12D3E4F');
</script>
```

- 👍 **一番シンプル**。HTMLがわかれば誰でも設置可能
- 👎 ボタン追加やイベント送信のたびに **HTML/JSの改修が必要**
- 使いどころ: 静的サイト・小規模LP・計測がPVだけで十分な場合

### 方法B: GTM経由（推奨）

1. GTMでコンテナを作成（[[02_GTMの導入手順]] で詳述）
2. GTMスニペットをHTMLの `<head>` と `<body>` 直後に設置
3. GTM管理画面で **「Googleタグ」** または **「GA4イベント」タグ** を作り、計測IDを指定

- 👍 **一度HTMLに貼れば以降はGTM画面だけで完結**
- 👍 ボタンクリック・フォーム送信など複雑な計測も画面操作で追加可能
- 👍 Meta Pixel / LINE Tag / 広告タグも **同じコンテナで一元管理**
- 👎 GTMを学ぶコストが少しかかる
- 使いどころ: **実務ではほぼ一択**（本ノート群の前提もこれ）

### 方法C: プラグイン・連携（WordPress等）

- WordPressなら `Site Kit by Google` プラグインで計測IDを入れるだけ
- Shopify / Wix / STUDIO などは管理画面に計測IDを貼る欄が用意されている
- 👍 最速で導入できる
- 👎 高度な計測（ボタン・フォームCV）はプラグインの範囲で制約される

## 4. ⚠️ よくある事故

### 事故1: gtag.js と GTM経由のGA4タグを **同時に設置** してしまう

- **PVが2倍に膨らむ**（計測IDがどちらからも発火するため）
- GTMへ移行したら、**HTML直書きのgtag.jsは必ず削除** すること

### 事故2: 本番とステージングで同じ計測IDを使う

- 開発環境のテストPVが本番のデータを汚す
- 対策:
  - GA4プロパティを **本番用・検証用で別に作る**
  - または GTMの **「Lookup Table 変数」** でホスト名に応じて計測IDを切替

### 事故3: タイムゾーンを誤ってUTCで作成

- レポートが9時間ずれて見え、毎回換算が必要になる
- 対策: 最初に `日本` を設定

---

## 5. Step7: 動作確認

### リアルタイムレポートで確認

1. 別タブでサイトを開く
2. GA4 → レポート → **リアルタイム**
3. 「過去30分間のユーザー」に自分のアクセスが反映されれば成功（数秒〜1分遅延）

### Google Tag Assistant で詳細確認

- Chrome拡張 [Tag Assistant Companion](https://chromewebstore.google.com/) をインストール
- タグが発火しているか、計測IDが正しいかを **リクエスト単位で確認**

---

## 6. 設置直後にやっておくべき初期設定

| 設定項目 | 何のため？ |
|---------|-----------|
| データ保持期間を「14か月」に変更 | デフォルト2か月では探索レポートが使えない |
| 内部トラフィック除外（自社IPをフィルタ） | 社員アクセスで数字が膨らむのを防ぐ |
| Google Search Consoleと連携 | 検索クエリも見られるようになる |
| Google Adsと連携（広告を使う場合） | オーディエンス共有・コンバージョン連携 |
| タイムゾーン・通貨の再確認 | 後から直すと過去データが歪む |
