# イベント・パラメータ・ユーザープロパティ

## 🎯 このページのゴール

- GA4の心臓部である **イベント・パラメータ・ユーザープロパティ** の関係を理解する
- 4種類のイベント（自動収集・拡張計測・推奨・カスタム）の **違いと使い分け** を知る
- 「どんな名前で送ればいいか」の **命名ガイド** を身につける

---

## 1. 3つの概念の関係図

```
[イベント]            ← ユーザーが起こした"行動"
  └─ [パラメータ]      ← その行動の"詳細情報"
      └─ 値
[ユーザープロパティ]   ← そのユーザー自身の"属性" (横断的に付与)
```

### 具体例で見る

ユーザーが「資料ダウンロード」ボタンを押した瞬間:

```json
イベント: "file_download"
パラメータ:
  file_name:      "料金表2026.pdf"
  file_extension: "pdf"
  link_url:       "https://example.com/download/price.pdf"
  page_location:  "https://example.com/pricing"

ユーザープロパティ (そのユーザーに紐づく):
  membership_level: "free"
  signup_date:      "2026-03-10"
```

## 2. イベントの4つの種類

GA4のイベントは **性質によって4分類** されます。

### ① 自動収集イベント

**GA4を設置するだけで勝手に送られる** イベント。無効化不可。

| イベント | いつ発火？ |
|---------|-----------|
| `first_visit` | そのブラウザで初回訪問時 |
| `session_start` | セッション開始時 |
| `user_engagement` | ページを10秒以上閲覧 or 何か操作 |

### ② 拡張計測イベント（設定ONで自動）

データストリームの **「拡張計測機能」をONにすると自動** で送られる。ONで十分なケースが多い。

| イベント | 何を測る？ | 自動パラメータ |
|---------|-----------|---------------|
| `page_view` | ページ閲覧 | `page_location`, `page_title`, `page_referrer` |
| `scroll` | 90%スクロール | `percent_scrolled`(90) |
| `click` | **外部リンク**クリック | `link_url`, `link_domain`, `outbound` |
| `view_search_results` | サイト内検索 | `search_term` |
| `video_start/progress/complete` | YouTube埋め込み動画 | `video_title`, `video_url` |
| `file_download` | ファイルDL（pdf等） | `file_name`, `file_extension` |
| `form_start / form_submit` | フォーム操作 | `form_id`, `form_name` |

⚠️ `click` は **外部ドメインへのリンクのみ**。サイト内ボタンは対象外。

### ③ 推奨イベント（名前が決まっている）

**自分で送る必要があるが、名前とパラメータが推奨仕様として決まっている** イベント。業種に合わせて使う。

| 業種 | 代表的な推奨イベント |
|------|---------------------|
| EC | `add_to_cart`, `begin_checkout`, `purchase`, `refund` |
| リード獲得 | `generate_lead`, `sign_up`, `login` |
| メディア/ブログ | `share`, `select_content` |

- 📘 一覧: https://support.google.com/analytics/answer/9267735

### ④ カスタムイベント

**完全に自分で命名・設計する** イベント。推奨イベントにないものはこれ。

- 例: `cta_click` / `tel_tap` / `contact_form_submit` / `faq_open`
- 命名ルールは **任意だがチーム内で統一する** のが重要

## 3. パラメータの基礎

イベントに付けられる **詳細情報**。1イベントあたり **最大25個のカスタムパラメータ** まで。

### 自動で付く主なパラメータ

| パラメータ | 意味 |
|-----------|------|
| `page_location` | 閲覧中のフルURL |
| `page_title` | ページのtitle要素 |
| `page_referrer` | 直前のページURL |
| `session_id` | セッション一意ID |
| `engagement_time_msec` | エンゲージ時間（ミリ秒） |

### カスタムパラメータは「登録」が必要

送信しただけでは **レポートに列として出てこない** ので、**カスタムディメンション/カスタム指標** として登録する必要があります。

```
管理 → カスタム定義 → カスタムディメンションを作成
  ├ ディメンション名: "ボタン名"
  ├ スコープ: イベント
  └ イベントパラメータ: "button_name"  ← 送信時の名前と一致させる
```

> ⚠️ スコープには **「イベント」「ユーザー」「項目（EC）」** の3つ。ユーザープロパティに紐づけるなら「ユーザー」。

---

## 4. ユーザープロパティとは

**そのユーザーに"横断的"に紐づく属性**。会員ランクや登録日などに使う。

- イベントごとに毎回送る必要はない（ログイン時に1回setすればOK）
- **個人情報（氏名・メールアドレス等）は禁止**（規約違反）

### 送り方の例（gtag.js）

```js
gtag('set', 'user_properties', {
  membership_level: 'premium',
  signup_year: '2026'
});
```

### 送り方の例（GTM）

GA4イベントタグまたはGA4設定タグの **「ユーザープロパティ」** 欄で設定。

## 5. 命名ガイド（命名規則）

- **すべて小文字 + スネークケース** にする → `file_download`, `cta_click`
- **表記ゆれは大敵**: `form_submit` と `formSubmit` は **別イベント扱い** になる
- イベント名は **40文字以内**、パラメータ名は **40文字以内**、値は **100文字以内** が上限
- **動詞 + 対象** の順で書くとわかりやすい: `submit_contact_form`, `click_hero_cta`

### 命名の悪い例 / 良い例

| ❌ 悪い例 | ✅ 良い例 | 理由 |
|----------|----------|------|
| `Button1Click` | `cta_click` | キャメルケース混在を防ぐ |
| `お問い合わせ送信` | `contact_form_submit` | 日本語は避ける（文字化け・予約語衝突リスク） |
| `form-submit` | `form_submit` | ハイフンは不可 |
| `click` | `cta_click` | 自動収集と衝突するので避ける |

## 6. 実際のデータ送信コード例

### gtag.js で送る

```js
// カスタムイベント: CTAボタンクリック
gtag('event', 'cta_click', {
  button_name: 'hero_contact',
  page_location: window.location.href,
  cta_position: 'above_fold'
});
```

### dataLayer.push で送る（GTM経由）

```js
window.dataLayer = window.dataLayer || [];
window.dataLayer.push({
  event: 'cta_click',
  button_name: 'hero_contact',
  cta_position: 'above_fold'
});
```

> 📘 dataLayer の仕組みは [[06_データレイヤー(dataLayer)]] で詳説

## 7. 2026年の実務観点

- **客観的指標を優先**: `engagement_rate`（エンゲージメント率）が UA時代の「直帰率」の代替として主流
- **AIインサイト活用**: Analytics Advisor に「今週、form_submit が減った理由は？」と聞けば要約してくれる
- **プライバシー対応**: 同意を得ていないユーザーのイベントは Consent Mode で **自動的に匿名化** される設計が標準
