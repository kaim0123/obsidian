# キーイベント（コンバージョン）設定

## 🎯 このページのゴール

- GA4 で **重要な行動をCV（キーイベント）としてマーク** できるようになる
- 旧「コンバージョン」と **キーイベント** の呼び方の違いを理解する
- LP運用で **最も需要の高い**「フォーム送信をCV化する」 を設定できる

---

## 1. 「キーイベント」とは（用語の整理）

2024年、Googleは用語を更新しました。

| 旧名称 | 新名称 |
|-------|-------|
| コンバージョン（Conversions） | **キーイベント（Key Events）** |

- GA4でビジネス上 **重要な行動** にマークをつける機能
- マークされたイベントは **専用レポートで集計**・**広告プラットフォームへ送信** できる
- 技術的には「あるイベントに『これはキーイベントです』というフラグを立てるだけ」

### 代表的なキーイベント例

| 業種 | 典型的なキーイベント名 |
|------|----------------------|
| LP/リード獲得 | `generate_lead`, `contact_form_submit` |
| EC | `purchase`, `begin_checkout`, `add_to_cart` |
| SaaS | `sign_up`, `start_trial`, `login` |
| メディア | `newsletter_signup`, `share` |

## 2. 設定の基本フロー

```
Step1. GTM(または直接送信)でイベントを先に発火させる
   ↓ (GA4で計測される)
Step2. GA4の「管理 > イベント」で発火を確認
   ↓
Step3. 該当イベントの「キーイベントとしてマーク」をON
   ↓ (24〜48h)
Step4. キーイベントレポートに反映される
```

> ⚠️ 重要: **イベントが最低1回 GA4 で観測されていないと、キーイベント化の操作ができない** → 先にテスト送信しておくこと

---

## 3. 設定手順（3つの方法）

### 方法A: 既存イベントをキーイベント化（最も簡単）

1. GA4 → 管理 → **イベント** を開く
2. 一覧から対象イベント（例: `contact_form_submit`）を探す
3. **「キーイベントとしてマーク」列のトグルをON**
4. 完了

💡 最初の発火から **イベント一覧に現れるまで最大24時間** かかる場合あり。

### 方法B: キーイベントを "先に" 作成

本番で発火する前に枠だけ作っておきたい時。

1. GA4 → 管理 → **キーイベント**
2. 右上「**新しいキーイベント**」
3. イベント名を正確に入力（例: `contact_form_submit`）
4. 保存 → 以降そのイベント名で送られたら自動でCV扱い

### 方法C: 「イベントを作成」で既存イベントを加工してCV化

例: 「フォーム送信 かつ URLが /contact のとき」だけCVにしたい場合。

1. 管理 → **イベント** → 「イベントを作成」
2. 新規イベントの **条件**:
   - `event_name` equals `form_submit`
   - `page_location` contains `/contact`
3. 新イベント名: `contact_form_submit`
4. 作成後、このイベントをキーイベント化

> 💡 GTM側で設定してもほぼ同等のことができる。**シンプルに運用するならGTMで分岐、GA4を汚したくないならこの方法** を選ぶ。

## 4. 金額付きキーイベントの設定

リード獲得やECで **1件あたりの金額** を持たせたいとき。

### パラメータに `value` と `currency` を追加して送る

```js
// フォーム送信時にLTV換算で5000円の価値を付ける例
gtag('event', 'generate_lead', {
  value: 5000,
  currency: 'JPY',
  form_name: 'contact'
});
```

- `value`: 金額（数値）
- `currency`: ISO4217の通貨コード（JPY/USD/EUR）※両方必須
- GA4のキーイベントレポートに **「キーイベントの値」列** が表示される
- 広告に送る際は **入札最適化の対象** になる

## 5. LPで「問い合わせフォーム送信」をCV化する実例

LP運用で最も典型的なパターンです。**後続の `実務編_LPでのCV計測/` フォルダに具体手順** があります。ここでは設計の全体像だけ。

### パターンA: サンクスページがある場合（最簡単）

```
[フォーム送信]
     ↓
[/thanks に遷移]
     ↓
[page_view イベントが発火]
     ↓
GA4で「page_location が /thanks を含む」をCVとして作成
```

### パターンB: 同じページで送信完了（SPA/Ajax送信）

```
[フォーム送信]
     ↓
[JSでサンクスメッセージを表示]
     ↓
[dataLayer.push({ event: 'form_submit_success' })] ← 開発側で仕込む
     ↓
GTMの「カスタムイベント」トリガーで拾ってGA4へ送信
     ↓
GA4側でキーイベント化
```

### パターンC: 送信ボタンのクリックをCV化（妥協案）

```
[送信ボタンがクリックされた時点] でイベント発火
     ↓
⚠️ バリデーションエラーで送信失敗したケースも含まれる
```

- 👍 実装が最も簡単
- 👎 **実際の送信成功と一致しない** ため数字が膨らむ
- 使いどころ: 検証フェーズの暫定計測

## 6. CV設定後のチェックリスト

- [ ] イベントが **GA4リアルタイム** に表示されるか
- [ ] イベントの **パラメータ** が意図通り付与されているか
- [ ] キーイベントとしてマークされているか（緑のチェック）
- [ ] 24〜48h後、**キーイベントレポート** に集計されているか
- [ ] Google Ads連携している場合、**Ads側の「コンバージョン」にインポート** されているか
- [ ] 同じイベントが **GTMとGA4両方** からCV化されていないか（二重カウント防止）

---

## 7. 2026年の注意点

- **自動的に重要と判定されるキーイベント**（`purchase`など）は、設定しなくてもCV扱いになる
- 広告との連携では **ad_storage の同意** が必須。同意モード v2 を導入していないと広告側にコンバージョン数が送られない
- **2026年6月15日以降**: Google Signals と ad_storage の同意扱いが変更予定
