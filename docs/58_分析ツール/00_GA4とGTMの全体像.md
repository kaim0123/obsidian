# GA4とGTMの全体像

## 🎯 このページのゴール

- GA4（Googleアナリティクス4）と GTM（Googleタグマネージャー）が **何のための道具で、どう役割分担しているか** を理解する
- 2026年現在の最新の使われ方（AI連携・サーバーサイド計測・同意モード）の大枠をつかむ
- これから読むノートの全体像を掴み、迷わず必要な章に飛べるようにする

---

## 1. ざっくり、何ができるの？

| ツール | 一言でいうと | 例えるなら |
|--------|-------------|-----------|
| **GA4**（Googleアナリティクス4） | サイト訪問者の行動を **記録・集計・分析** する「計測器」 | Webサイト専用の健康診断・カルテ |
| **GTM**（Googleタグマネージャー） | 計測用タグを **エンジニアなしでWebサイトに追加・管理** する「司令塔」 | 家電のリモコン（タグのON/OFFを切替） |

- **GA4だけ** でも計測は可能（HTMLに計測タグを直接貼る）
- **GTMを挟む** ことで、ブログの公開ボタンを押すようにノーコードで計測設定を追加・変更できる
- 実務では **GTM経由でGA4にデータを送る** 構成がほぼ標準

---

## 2. データが流れる順序（イメージ図）

```
[ユーザーがLPを閲覧]
        ↓  ブラウザがHTML/JSを実行
[HTMLに埋め込まれた GTMスニペット] ← 1回だけ貼り付けておく
        ↓  GTMの管理画面で設定した「タグ」を発火
[GTMの "GA4 設定タグ"] ─── 計測ID(G-XXXXXX)を指定
        ↓
[Googleのサーバー（GA4）]
        ↓  集計・レポート化
[GA4の管理画面でグラフ・表として閲覧]
```

ポイント:
- HTMLに貼るのは **GTMのスニペットだけ** で済む（これ1回）
- 以降は「ボタンクリックも測りたい」「フォーム送信も測りたい」が **GTMの画面だけで完結**

---

## 3. GA4とGTMの役割分担

### GA4がやること

- イベント（pageview / click / form_submit など）の **受け取りと保存**
- ユーザー属性・流入経路・コンバージョン（キーイベント）の **集計**
- 探索レポート・経路探索・ファネル分析などの **可視化**

### GTMがやること

- 「いつ」「どのタグを」「どんなデータと一緒に」発火するかを制御
  - いつ = **トリガー**（例: このボタンがクリックされたとき）
  - どのタグを = **タグ**（例: GA4にform_submitイベントを送る）
  - どんなデータ = **変数**（例: クリックされた要素のテキスト、URL など）
- 計測用タグ以外にも Google広告・LINE Tag・Meta Pixel など **各種マーケタグを一元管理**

## 4. 2026年時点のトピック（最低限おさえたい）

| トピック | 何が起きているか |
|---------|-----------------|
| **キーイベント** | かつての「コンバージョン」が GA4では **キーイベント（Key Events）** という呼び方に統一された |
| **AIアシスタント** | 2025年末に **Analytics Advisor** が登場。自然言語で質問すると傾向や異常値を要約してくれる |
| **同意モード v2** | Cookie同意の扱いが厳しくなり、EU圏では **Consent Mode v2 が事実上必須**。日本でもCMP連携が推奨されつつある |
| **サーバーサイドGTM** | 広告ブロッカー・ブラウザ制限で **クライアント計測だけだと 20〜40% のデータを取り逃がす** 時代に。サーバーサイドへの移行が進行中 |
| **Google Signals と Ads の連携変更** | 2026年6月15日以降、GA4のGoogle SignalsとGoogle広告のad_storage同意の扱いが変更される |

> 💡 本ノート群では **クライアント側のGTM + GA4** を中心に解説し、サーバーサイドGTMは概念紹介に留める（導入難度が一段上がるため）
