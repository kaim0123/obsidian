# 命名規則・運用ルール

## 🎯 このページのゴール

- **タグ・トリガー・変数・GA4イベント** の命名規則を1つの場所で参照できる
- チーム運用で揉めない **推奨フォーマット** を知る
- GTMコンテナを **壊さずに育てる** ための運用ルールを押さえる

---

## 1. なぜ命名規則が重要か

- GTMは **半年で100個以上** のタグ・トリガー・変数になりうる
- **命名がバラバラだと「どれが何か」が分からなくなり**、重複・事故・無駄な工数が発生
- **検索で絞り込めるか** が最大の品質指標: `GA4 - ` で検索して全GA4タグが出るか？
- チームで作業する場合、**ルールがなければ他人の設定を壊す** リスクが跳ね上がる

---

## 2. 共通原則（すべてのアセットに適用）

### 2-1. 書式

| 原則 | 例 |
|------|-----|
| **半角スペース区切り** で分ける（`- ` がセパレータ） | `GA4 - Event - cta_click` |
| **先頭は "何のツール/種別か"** のプレフィックス | `GA4` / `GTM` / `Meta` / `Ads` / `LINE` |
| 英語・英数字中心（日本語は **値** でのみ許容） | ✓ `Thanks Page` ✗ `サンクスページ` |
| タグ/トリガー/変数の **名前に揺れを残さない** | `thank you` / `thanks` / `thx` を統一 |

### 2-2. 大文字・小文字の使い分け

| 要素 | 書き方 |
|------|-------|
| GA4 イベント名・パラメータ名 | **全て小文字 + snake_case** （`cta_click`） |
| GTMタグ・トリガー・変数の名前 | **Title Case** OK（`GA4 - Config - All Pages`） |
| dataLayer のキー | **snake_case** 推奨（開発側との整合性のため） |

## 3. タグの命名規則

### 推奨フォーマット

```
{プラットフォーム} - {目的} - {対象・条件}
```

### 具体例

| タグ名 | 解説 |
|-------|------|
| `GA4 - Config - All Pages` | GA4基本の Google タグ |
| `GA4 - Event - page_view` | PV計測の補助タグ |
| `GA4 - Event - cta_click` | CTAクリックのイベント |
| `GA4 - Event - generate_lead` | フォーム送信完了のCV |
| `GA4 - Event - file_download` | PDF/資料ダウンロード |
| `GA4 - Event - scroll_depth` | スクロール率 |
| `Meta - PageView - All Pages` | Meta Pixel の PageView |
| `Meta - Lead - Thanks Page` | Meta Pixel の Lead |
| `Ads - Conversion - Form Submit` | Google広告のCVタグ |
| `LINE - Conversion - Lead` | LINE広告のCVタグ |
| `Custom HTML - User ID Init` | カスタムHTMLは `Custom HTML - ` を先頭に |

### タグ命名のルール表

| ルール | 理由 |
|--------|------|
| プラットフォームプレフィックスを必ず付ける | 検索で絞り込める |
| イベント名はタグ名の末尾に **そのまま含める** | GA4側と対応が取れる |
| "Config" は **1コンテナに1つだけ** | 複数あれば誤設置の疑い |
| 日付やバージョン番号は **含めない** | バージョン機能で管理する |
| 「new」「test」「tmp」は公開時に必ず削除 | ゴミが残る原因 |

---

## 4. トリガーの命名規則

### 推奨フォーマット

```
{トリガー種別} - {条件の要約}
```

種別の略語:

| 種別 | 略語 |
|------|-----|
| Page View | `PV` |
| Click - All Elements | `Click` |
| Click - Just Links | `Link Click` |
| Form Submission | `Form` |
| Element Visibility | `Visibility` |
| Scroll Depth | `Scroll` |
| Custom Event | `Custom` |
| Timer | `Timer` |
| History Change | `History` |
| JavaScript Error | `JS Error` |

### 具体例

| トリガー名 | 何のトリガー？ |
|-----------|-------------|
| `PV - All Pages` | 全ページ（デフォルト） |
| `PV - LP Top` | LPトップページのみ |
| `PV - Thanks Page` | サンクスページのみ |
| `Click - CTA Hero` | ヒーローエリアCTA |
| `Click - CTA Pricing` | 料金セクションCTA |
| `Link Click - Tel` | 電話リンク（tel:） |
| `Link Click - Mail` | メールリンク（mailto:） |
| `Link Click - PDF` | PDFダウンロードリンク |
| `Link Click - Outbound` | 外部リンク |
| `Form - Contact Submit` | お問い合わせフォーム送信 |
| `Custom - form_submit_success` | dataLayer経由の送信成功 |
| `Visibility - Thanks Message` | サンクスメッセージ表示 |
| `Visibility - Section Pricing` | 料金セクション到達 |
| `Scroll - LP 25/50/75/90` | LPスクロール率 |
| `Timer - 30s on LP` | LP滞在30秒タイマー |

### トリガー命名のルール表

| ルール | 理由 |
|--------|------|
| 先頭に **種別略語**（PV/Click/Link Click等） | 一覧画面で型がすぐわかる |
| Customトリガーは **dataLayerのイベント名をそのまま** 末尾に | 開発との連携で追跡しやすい |
| 複数条件なら **最も特徴的な条件** を名前に | 全条件を入れると長すぎる |
| ページ限定トリガーは **ページ名** を入れる | `PV - Thanks Page` |
| 「あらゆる場所」を意味する `All Pages` を例外なく使う | `All` `ALL` 等の揺れを防ぐ |

## 5. 変数の命名規則

### 推奨フォーマット

```
{変数タイプ略語} - {用途の説明}
```

### 変数タイプの略語

| 変数タイプ | 略語 |
|----------|-----|
| データレイヤー変数 | `DLV` |
| 定数 | `Const` |
| ルックアップテーブル | `LT` |
| 正規表現テーブル | `RT` |
| カスタムJavaScript | `JS` |
| JavaScript変数（グローバル参照） | `GJS` |
| DOM要素 | `DOM` |
| 自動イベント変数 | `AEV` |
| 1st Party Cookie | `Cookie` |
| URL（カスタム構成）| `URL` |

### 具体例

| 変数名 | 役割 |
|-------|------|
| `DLV - order_id` | dataLayerのorder_idを取得 |
| `DLV - user_id` | ログインユーザーID |
| `DLV - form_id` | フォーム識別子 |
| `Const - GA4 Measurement ID` | `G-XXXXXXXXXX` |
| `Const - Conversion Value` | リード1件の仮定金額 |
| `LT - GA4 ID by Environment` | 本番/検証でIDを切替 |
| `JS - Clean Hostname` | `www.` 除去済みホスト名 |
| `JS - Click Data-CTA` | クリック要素の data-cta 取得 |
| `JS - File Extension` | Click URL から拡張子抽出 |
| `DOM - User Name` | `.user-name` 要素のテキスト |
| `AEV - Click data-position` | クリック要素の data-position |
| `Cookie - _ga` | GAのクライアントID Cookie |

### 変数命名のルール表

| ルール | 理由 |
|--------|------|
| 先頭に **タイプ略語** を必ず付ける | 同名で型違いを区別 |
| DLV は **データレイヤー側のキー名そのまま** | 開発との整合 |
| 定数は「何の定数か」を明記 | `Const - Value` だけだと意味不明 |
| カスタムJSは **戻り値の意味** を名前に | `JS - Get Something` より `JS - Clean Hostname` |

## 6. GA4 イベント名・パラメータ名の命名規則

### Google公式ルール（2026年現在）

GA4イベントは **Google公式の厳しいルール** があります:

| ルール | 詳細 |
|-------|------|
| 文字種 | **英数字 + アンダースコア** のみ（ハイフン・スペース不可） |
| 先頭文字 | **文字（a-z, A-Z）** で始まること（`1st_step` ✗） |
| 大文字小文字 | **区別される** → `form_submit` と `Form_Submit` は別イベント |
| 長さ | イベント名 **最大40文字**、パラメータ名 **最大40文字**、値 **最大100文字** |
| 予約語禁止 | `ga_`, `google_`, `gtag_`, `firebase_` で始まる名前は不可 |
| 絵文字 | 使用禁止（通っても使わないこと） |

### 推奨フォーマット

**すべて小文字 + snake_case + `動詞_対象` または `対象_動作`**

### 良いイベント名の例

| イベント名 | 意図 |
|-----------|------|
| `cta_click` | CTAクリック |
| `form_submit` | フォーム送信 |
| `generate_lead` | リード獲得（推奨イベント） |
| `file_download` | ファイルDL（推奨イベント） |
| `scroll_depth` | スクロール率 |
| `tel_tap` | 電話タップ |
| `mail_click` | メールリンククリック |
| `video_complete` | 動画完了 |
| `section_view` | セクション表示 |
| `outbound_click` | 外部リンククリック |

### 避けるべき例

| ❌ 悪い例 | ✓ 正しい例 | 理由 |
|----------|------------|------|
| `CTAClick` | `cta_click` | キャメルケースNG |
| `cta-click` | `cta_click` | ハイフンNG |
| `click` | `cta_click` | GA4自動イベント名と衝突 |
| `お問合せ送信` | `contact_form_submit` | 日本語は避ける |
| `1st_click` | `first_click` | 数字始まりNG |
| `ga_event` | `custom_event` | 予約プレフィックス |
| `form submit` | `form_submit` | スペースNG |
| `clicked_button_multiple_times_today` | `cta_click` | 40文字以内に収める |

### パラメータ名の命名

同じく **小文字 + snake_case**。以下のような共通パラメータを定義しておくと混乱しない:

| パラメータ名 | 用途 |
|-------------|------|
| `button_name` | ボタンの識別名 |
| `button_text` | ボタンの表示テキスト |
| `button_position` | ボタンの設置位置（hero/pricing等） |
| `form_id` | フォーム識別子 |
| `form_type` | フォーム種別 |
| `file_name` / `file_extension` | ファイル情報 |
| `link_url` / `link_domain` / `link_text` | リンク情報 |
| `percent_scrolled` | スクロール率 |
| `value` / `currency` | CV金額（GA4推奨） |
| `page_path` / `page_location` / `page_title` | ページ情報（自動付与もあるが明示可） |

### 推奨イベント名を優先的に使う

GA4には **業種別の推奨イベント名** が定義されています。**カスタム名を自由に付ける前に、推奨名で代用できないか確認**。

例えばリード獲得系は `generate_lead` を使うと、Google広告の入札最適化と連動しやすくなります。

📘 [GA4推奨イベント一覧](https://developers.google.com/analytics/devguides/collection/ga4/reference/events)

## 7. dataLayer イベント名の命名

`dataLayer.push({event: '...'})` の `event` の名前。

### 原則

| 原則 | 理由 |
|------|------|
| **小文字 + snake_case** | GA4と揃える |
| GA4イベント名と **同じ名前でもよい** | `event: 'purchase'` などそのまま転送 |
| サイト内の **独自シグナル** は名前を区別 | `event: 'form_submit_success'` など |

### 推奨パターン

- **GA4にそのまま転送する場合**: GA4の推奨名に合わせる（`purchase`, `sign_up` 等）
- **中間シグナルとして使う場合**: サフィックスで明示（`form_submit_success`, `form_submit_error`）
- **操作の成否を区別する場合**: `_success` / `_failed` / `_error`

## 8. フォルダ分けと workspace 運用

### フォルダで整理

GTMにはタグ/トリガー/変数を **フォルダ分け** する機能があります。10個を超えたら必須。

推奨フォルダ:

```
📁 GA4/
    ├ 🏷 GA4 - Config - All Pages
    ├ 🏷 GA4 - Event - cta_click
    ├ ⏰ Click - CTA Hero
    └ 📦 DLV - form_id

📁 Meta/
    ├ 🏷 Meta - PageView - All Pages
    └ 🏷 Meta - Lead - Thanks Page

📁 Google Ads/
    └ 🏷 Ads - Conversion - Form Submit

📁 Utility/
    ├ 📦 Const - GA4 Measurement ID
    ├ 📦 JS - Clean Hostname
    └ 📦 LT - GA4 ID by Environment

📁 _Archive/            ← 使わなくなったが消せないもの
```

### workspace（作業スペース）の運用

- **本番用ワークスペース**: ここで公開（Publish）
- **検証用ワークスペース**: 新規タグの動作確認
- **修正用ワークスペース**: 緊急修正専用

→ 複数人で同時作業しても競合しない

## 9. バージョン管理の命名

GTMの「公開」時に残す **バージョン名と説明** の書き方。

### 推奨フォーマット

```
{セマンティックバージョン} - {変更概要}
```

### 具体例

| バージョン名 | 説明 |
|------------|------|
| `v1.0.0 - 初期リリース` | GA4 Config + PV計測のみ |
| `v1.1.0 - CTA計測追加` | ヒーロー/料金セクションのCTA計測 |
| `v1.1.1 - CTA発火条件修正` | Click Classes の正規表現修正 |
| `v1.2.0 - Meta Pixel導入` | Meta広告連携 |
| `v2.0.0 - Consent Mode v2対応` | 同意モード対応 |

### バージョン命名のルール

- **メジャー（X.0.0）**: 大きな構造変更・計測ID変更
- **マイナー（1.X.0）**: 新規タグ追加・新機能
- **パッチ（1.1.X）**: バグ修正・条件微調整
- **説明は日本語可**（自分たちがわかるように）
- 「一旦公開」「とりあえず」等は残さない

## 10. アンチパターン集（やってはいけない）

### アンチパターン1: 「テスト」「tmp」「new」が本番に残る

```
❌ New Tag (6)
❌ test - facebook
❌ tmp - scroll
```

→ 定期的に **整理タイム** を設けて削除する

### アンチパターン2: 内容がわからない名前

```
❌ Tag 1
❌ 送信
❌ うごく
```

→ **他人が初見で理解できる名前** に

### アンチパターン3: 命名規則がチーム内で不統一

```
Aさん作: GA4 - Event - cta_click
Bさん作: CTA_click_event
Cさん作: click_cta_button_v2
```

→ **最初にドキュメントで合意** + **コードレビュー的なチェック運用**

### アンチパターン4: バージョン名を書かない

```
❌ (名前なし)
❌ Version 12
❌ fix
```

→ 1ヶ月後の自分がわかる情報を残す

### アンチパターン5: 日本語と英語が混在

```
❌ GA4 - Event - 問い合わせ送信
```

→ どちらかに **統一**。イベント名部分は英語(snake_case)が必須

### アンチパターン6: 同じ目的のタグが重複

```
❌ GA4 - Event - cta_click
❌ GA4 - Event - Click CTA
❌ GA4 click tracking
```

→ 公開前に **必ず一覧を確認**。月次でクリーンアップ

## 11. 命名規則チェックリスト（公開前）

タグを作ったら公開前に:

- [ ] タグ名は **`{ツール} - {目的} - {対象}`** 形式か
- [ ] トリガー名は **`{種別略語} - {条件}`** 形式か
- [ ] 変数名は **`{タイプ略語} - {用途}`** 形式か
- [ ] イベント名は **小文字 + snake_case** か
- [ ] 似た目的の **重複タグがない** か
- [ ] **テスト用・一時的な名前** が残っていないか
- [ ] バージョン名と **変更概要の説明** が書かれているか
- [ ] フォルダに **分類済み** か

## 12. 📋 命名テンプレート（コピペ用）

チームで共有する命名ガイド表のたたき:

```markdown
## GTM命名規則（このプロジェクトの版）

### タグ
形式: `{プラットフォーム} - {目的} - {対象}`
例:
  GA4 - Config - All Pages
  GA4 - Event - {event_name}
  Meta - {StandardEvent} - {発火場所}
  Ads - Conversion - {CV名}

### トリガー
形式: `{種別略語} - {条件}`
略語: PV / Click / Link Click / Form / Visibility / Scroll / Custom / Timer
例:
  PV - Thanks Page
  Click - CTA Hero
  Link Click - PDF
  Custom - form_submit_success

### 変数
形式: `{タイプ略語} - {用途}`
略語: DLV / Const / LT / JS / DOM / AEV / Cookie
例:
  DLV - order_id
  Const - GA4 Measurement ID
  JS - Clean Hostname

### GA4 イベント名
書式: 小文字 + snake_case、40文字以内、英数字＋アンダースコアのみ
推奨名を優先: purchase / sign_up / generate_lead / file_download / etc.

### バージョン名
形式: `vX.Y.Z - {変更概要}`
例: v1.1.0 - CTA計測追加
```
