# トリガー（Triggers）の基礎

## 🎯 このページのゴール

- トリガーが「**タグを発火させるタイミング条件**」であることを理解する
- **代表的なトリガータイプ** と、それぞれの使いどころを覚える
- 「クリック」「フォーム送信」「カスタムイベント」の違いを具体例で理解する

---

## 1. トリガーとは

タグに対して **「いつ発火させるか」** を定義する条件。

- タグは **最低1つのトリガー** が付いていないと発火しない
- 1つのタグに **複数のトリガー** を付けられる（どれかが満たされれば発火）
- トリガーは **複数のタグから参照** できる（使い回しOK）

---

## 2. トリガーのタイプ一覧（2026年現在）

### ページビュー系

| タイプ | いつ発火？ |
|--------|-----------|
| **ページビュー（Page View）** | HTMLパース直後（最も早い） |
| **DOM Ready** | DOMの構築完了時 |
| **ウィンドウ ロード済み** | すべての画像・CSS・JSの読み込み完了後 |

→ タイミングの差: `Page View < DOM Ready < Window Loaded`

### インタラクション系

| タイプ | いつ発火？ |
|--------|-----------|
| **クリック - すべての要素** | 何らかの要素がクリックされたとき |
| **クリック - リンクのみ** | `<a>`タグがクリックされたとき（遷移前に発火） |
| **フォーム送信** | フォームが送信されたとき（自動検知） |
| **スクロール距離** | 指定した%まで縦/横スクロールされたとき |
| **要素の表示 (Element Visibility)** | 指定要素が画面に入ったとき |
| **YouTube 動画** | 動画の再生/一時停止/完了 |

### 独自シグナル系

| タイプ | いつ発火？ |
|--------|-----------|
| **カスタム イベント** | `dataLayer.push({event: '...'})` された瞬間 |
| **履歴の変更 (History Change)** | SPAのURL変更（pushState等）を検知 |
| **JavaScript エラー** | 未処理の例外が発生したとき |
| **タイマー** | ページ滞在時間が一定経過したとき |

---

## 3. 超重要: クリック系トリガーの2種類

### 「クリック - すべての要素」 vs 「クリック - リンクのみ」

| タイプ | 対象 | 備考 |
|--------|------|------|
| **すべての要素** | `<button>`, `<div>`, `<span>` など何でも | ボタンや任意要素向け |
| **リンクのみ** | `<a>` タグに限定 | `{{Click URL}}` が使える・**遷移前に発火** 可能 |

### リンクのみトリガーの特徴

- **「タグの発火を待機」** オプションがあり、リンク遷移を **数百ミリ秒遅らせて** 計測を完了させられる
- 外部リンクのクリック計測でよく使う

```
[外部リンククリック]
      ↓ 遷移を一瞬ブロック
[GA4タグが発火し送信完了]
      ↓
[本来の遷移へ進む]
```

## 4. トリガーの発火条件（フィルタ）

トリガーには **「このトリガーの発火条件」** というフィルタ欄があります。

### 代表的な条件設定

```
条件1: Click Classes  includes  "cta-btn"
条件2: Click URL      contains  "/contact"
条件3: Page Path      matches RegEx  "^/thanks"
```

- **AND条件のみ**（複数並べるとすべて満たしたとき発火）
- OR条件は **別トリガーを作って** 同じタグに付ける

### 使える演算子

- `equals` / `does not equal`
- `contains` / `does not contain`
- `starts with` / `ends with`
- `matches RegEx` / `does not match RegEx`
- `less than` / `greater than`

## 5. 実例で覚えるトリガー設計

### 例1: 全ページでGA4設定タグを発火

```
トリガータイプ: ページビュー
条件: すべてのページビュー
→ "All Pages" (組み込み) でOK
```

### 例2: LPのCTAボタンクリック

```
トリガータイプ: クリック - すべての要素
条件: Click Classes contains "hero-cta"
```

→ 事前に組み込み変数 `{{Click Classes}}` を有効化する必要あり（[[05_変数(Variables)の基礎]] 参照）

### 例3: サンクスページ到達

```
トリガータイプ: ページビュー
条件: Page Path equals "/thanks"
```

### 例4: 資料PDFのダウンロードリンク

```
トリガータイプ: クリック - リンクのみ
条件: Click URL ends with ".pdf"
発火を待機: 2000ms (外部遷移を少し遅延)
```

### 例5: フォーム送信成功を dataLayer から受ける

```
トリガータイプ: カスタム イベント
イベント名: form_submit_success
```

→ 開発側で `dataLayer.push({event: 'form_submit_success'})` を送ってもらう想定

### 例6: スクロール75%

```
トリガータイプ: スクロール距離
縦方向の割合: 75%
発火タイミング: ページビュー直後から
```

## 6. 「Check Validation」オプション（フォーム送信で超重要）

フォーム送信トリガーには **「入力検証を確認」** というチェックボックスがあります。

| チェック | 挙動 |
|---------|------|
| **OFF**（デフォルト） | フォーム送信の **試み** で発火 → 必須漏れエラーでも発火してしまう |
| **ON** | フォームが **実際に正しく送信** された時だけ発火 |

### なぜ重要？

- OFFのままだと、**送信エラーもCVとしてカウント** され、数字が膨らむ
- 対策: **常にONにする**（フォームがGTMの自動検知対象の場合）

⚠️ ただし、多くのLPは **送信時にJSで独自バリデーション** → GTMのフォーム送信トリガーが効かないことが多い。
→ その場合は **「カスタムイベント」トリガー + dataLayer.push** 方式が確実（[[02_フォーム送信完了の計測]] で詳細）。

## 7. トリガーの例外（Exceptions）

「通常は発火させたいが、特定条件のときは発火させたくない」ケース。

```
タグの設定画面 > トリガーの追加 >
  「このタグを発火しない: 例外」を設定
```

### 例: 内部IPのアクセスは除外

- トリガー本体: All Pages
- 例外: `{{User IP}} equals 192.168.x.x` のとき発火させない

## 8. カスタムイベントトリガーと dataLayer

**GTM最強の組み合わせ** がこれです。開発側と連携する際の標準パターン。

```js
// 開発側（アプリのJS）
window.dataLayer = window.dataLayer || [];
window.dataLayer.push({
  event: 'purchase_complete',
  order_id: 'A12345',
  revenue: 5000
});
```

```
GTM側:
  トリガー: カスタム イベント
    イベント名: purchase_complete
  タグ: GA4 イベント
    イベント名: purchase
    パラメータ:
      transaction_id = {{DLV - order_id}}
      value          = {{DLV - revenue}}
      currency       = JPY
```

## 9. トリガーの命名規則

```
{タイプ} - {条件の要約}

例:
PV - All Pages
PV - Thanks Page
Click - CTA Hero
Click - PDF Download
Custom - form_submit_success
Scroll - 75%
```
