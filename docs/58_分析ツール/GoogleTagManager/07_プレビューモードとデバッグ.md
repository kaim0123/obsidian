# プレビューモードとデバッグ

## 🎯 このページのゴール

- GTMプレビューモード（Tag Assistant）で **発火状況を確認** できる
- GA4リアルタイムレポートと組み合わせた **ダブルチェック** ができる
- 計測が動かない時の **トラブルシュート手順** を身に付ける

---

## 1. プレビューモードとは

GTMの管理画面で **「プレビュー」** をクリックすると、**Tag Assistant** という別タブが開き、変更を公開せずにサイトで計測テストができる機能。

- 本番環境のユーザーには影響しない
- 自分のブラウザだけが **プレビュー版のGTMコンテナ** を読み込む
- 変更を加えた未公開のタグもここで動作検証できる

---

## 2. プレビューモードの起動

```
GTM管理画面 右上の「プレビュー」ボタン
   ↓
Tag Assistant が新しいタブで開く
   ↓
対象サイトのURLを入力 → "Connect"
   ↓
別タブでサイトが開き、ページ右下に「Tag Assistant Connected」と表示
   ↓
サイトを操作するたび Tag Assistant 側で発火が可視化される
```

### 「Connect」できない時

- CookieブロッカーでGTMドメインが遮断されている → 一時的に無効化
- HTTPSとHTTPが混在している → URLを正しいものに
- 企業プロキシで `googletagmanager.com` が遮断されている → 別ネットワークで試す

---

## 3. Tag Assistant の画面構成

Tag Assistant 側の画面:

```
[左] Summary / イベント時系列
  └ Page Load
  └ DOM Ready
  └ Window Loaded
  └ Click (Click Text: "お問い合わせ")
  └ Form Submit
  └ (カスタムイベント: form_submit_success)
  └ ...

[右] 選択中のイベントの詳細
  ├ Tags Fired:       発火したタグ
  ├ Tags Not Fired:   発火しなかったタグ（条件不一致）
  ├ Variables:        その瞬間の変数値
  ├ Data Layer:       現在のdataLayer配列
  └ Consent:          Consent Modeの状態
```

### 各タブで見るべきポイント

| タブ | 何を見る？ |
|------|-----------|
| **Tags** | 期待のタグが発火したか・発火しないタグの理由 |
| **Variables** | 変数の **現在値** が期待通りか |
| **Data Layer** | `dataLayer.push` された内容と順序 |
| **Consent** | 同意ステータス（Consent Mode利用時） |
| **Errors** | タグで発生したJSエラー |

## 4. 実際のデバッグフロー

### シナリオ: 「CTAボタンクリックでGA4にcta_click が送られない」

#### Step1: Tag Assistant で該当イベントを選択

左側の時系列から **Click** イベントをクリック

#### Step2: タグが発火しているか確認

- ✅ **Tags Fired** にタグ名が出ている → GTMの設定は正常。GA4側を確認へ
- ❌ **Tags Not Fired** にタグ名 → GTM設定に問題あり。次のStep3へ

#### Step3: 変数を確認

Variables タブで:

- `Click Classes` / `Click URL` / `Click Text` の値が期待通りか
- 空（undefined）なら組み込み変数の有効化忘れ

#### Step4: トリガーの条件を再確認

- `Click Classes contains "cta"` 等の条件と、実際の値（`hero-cta-btn mt-4` 等）がマッチしているか
- スペース区切りの複数classに引っかかっていないか

#### Step5: GA4リアルタイムで受信確認

- GTMでFireしていても、GA4に届いていなければ意味がない
- GA4 → レポート → リアルタイム → **イベント** に `cta_click` が出ていれば成功

---

## 5. Google Tag Assistant Companion（Chrome拡張）

プレビューを使わずに **本番環境のタグ挙動を確認** できるChrome拡張。

- [Chrome Web Store](https://chromewebstore.google.com/) で "Tag Assistant Companion" を検索
- インストールすると **他人のサイト** でも発火状況を覗ける
- 実装完了後の **本番モニタリング** にも有用

---

## 6. GA4 DebugView（GA4側のデバッグ機能）

GTMのプレビューモードと連動して、**GA4側に届いたイベントをリアルタイム表示** する機能。

### 有効化方法

- GTMのプレビューモードに入れば自動で `debug_mode=true` が付く
- または Chrome拡張 **「Google Analytics Debugger」** をインストール

### 見方

```
GA4 → 管理 → DebugView
  └ ユーザー単位でイベントタイムラインが表示
  └ 各イベントのパラメータ・ユーザープロパティも一覧で確認
```

> 💡 **DebugViewとリアルタイムレポートの違い**
> - リアルタイム: 全ユーザーの集計（直近30分）
> - DebugView: 自分のデバッグセッションだけを抽出（詳細）

## 7. よくあるトラブル事例

### ケース1: タグが「Not Fired」で理由が表示される

- 「Conditions Not Met」と出ている → トリガー条件不一致
- 「Blocking Trigger」と出ている → 例外トリガーに引っかかった
- 「Consent Not Granted」と出ている → Consent Mode で必要な同意が得られていない

### ケース2: 変数が undefined

- **組み込み変数の有効化忘れ**: 変数 > 組み込み変数 > 該当のチェックを入れる
- **発火タイミングが早すぎる**: Page View → DOM Ready → Window Loaded へトリガーを後ろに
- **dataLayer.push より先に評価されている**: カスタムイベントトリガーに変更

### ケース3: イベントがGA4に届かない

- **広告ブロッカー**が動いている（uBlock, AdGuard）
- **Consent Mode で拒否** されている（analytics_storage が denied）
- **計測IDが間違っている**（G-XXXXXXXXXX を再確認）
- **ネットワークタブ**を F12 で開き `collect?v=2&tid=G-...` リクエストの有無を確認

### ケース4: プレビューと本番で挙動が違う

- **未公開の変更** がプレビューだけで動いている
- プレビューで確認後は **必ず公開** を忘れずに

### ケース5: 自分のアクセスだけ計測されない

- **内部IPフィルタ** で除外されている
- **ブラウザ拡張** でGAを無効化している

## 8. ネットワークタブを使った最終確認

F12 → Network タブで以下をフィルタリング:

| フィルタキーワード | 意味 |
|------------------|------|
| `collect` | GA4 Measurement Protocolのリクエスト |
| `gtm.js` | GTMコンテナ本体の読み込み |
| `gtag/js` | Googleタグ(gtag.js)の読み込み |
| `google-analytics.com` | 旧GA系通信（UA時代） |
| `analytics.google.com` | GA管理画面 |

発火後、`collect?v=2&tid=G-XXXXXXXXXX&...` のようなリクエストが200で返っていれば計測成功です。

## 9. 公開前チェックリスト

本番公開（Publish）前にこれだけ確認:

- [ ] プレビューで **対象イベントが Fired** になる
- [ ] タグに渡される **パラメータが期待値** になっている
- [ ] GA4 DebugView で **イベントが受信** されている
- [ ] DebugView で **パラメータ値が期待通り** になっている
- [ ] **誤発火**（他ページで意図せず発火）がない
- [ ] 既存タグの発火回数に変化がないか（壊れていないか）
- [ ] 2〜3端末/ブラウザで再現確認

## 10. 2026年のデバッグ機能強化

- **AI駆動のエラー解説**: Tag Assistant が発火失敗時に **自然言語で原因を説明** してくれるようになった
- **リアルタイム イベントストリーム**: より低遅延で発火情報を表示
- **Consent 状態の可視化強化**: どのタグがどの同意要件でブロックされたか一目でわかる
