# コンバージョン設定とGA4連携

## 🎯 このページのゴール

- Google広告のCV計測の **3つの選択肢** を理解する
- GA4キーイベントを **Google広告にインポート** できる
- **拡張コンバージョン（Enhanced Conversions）** で計測精度を上げる
- **同じCVを二重カウント** する事故を防ぐ

---

## 1. CV計測は「広告運用の心臓」

Google広告のAI（スマート入札）は、**CVデータを元に最適化** を学習します。

- **CV計測が正確** → AIが正しく学習 → CPAが下がる
- **CV計測が壊れている** → AIが誤学習 → 広告費が無駄に

2026年現在、**CV計測の精度こそが広告運用の成否を決める** と言われる理由です。

---

## 2. CV計測の3つの選択肢

| 方法 | 概要 | 精度 | 運用難度 |
|------|-----|------|---------|
| **A. Google広告ネイティブCVタグ** | Google広告側で直接タグを生成・設置 | 中 | 中 |
| **B. GA4キーイベントのインポート**（推奨） | GA4で計測 → Google広告にCVとしてインポート | 高 | 低 |
| **C. 拡張コンバージョン** | A/Bに追加で設定する精度向上オプション | **最高** | 中 |

→ 2026年の標準は **B + C の組み合わせ**: GA4のキーイベントを広告にインポート + 拡張コンバージョンで精度向上

---

## 3. 方法B: GA4キーイベントのインポート（推奨）

### 事前準備

1. GA4で計測できていること
2. GA4でキーイベント化が済んでいること（[[05_キーイベント(コンバージョン)設定]] 参照）
3. Google広告アカウントと **GA4プロパティがリンク済み** であること

### GA4プロパティとGoogle広告のリンク

```
GA4 管理 → プロダクトリンク → Google 広告のリンク → リンク
  ↓
Google広告アカウントを選択
  ↓
有効な設定: [自動タグ設定 有効化] [パーソナライズド広告] [CVのエクスポート]
```

### インポート手順

```
Google広告 → ツールと設定 → 測定 → コンバージョン → 新しいコンバージョン アクション
  → インポート
  → Google アナリティクス 4 プロパティ → ウェブ
  → GA4プロパティを選択
  → インポートするキーイベントをチェック
  → インポート
```

### インポート後の扱い

- インポートされたCVは **Google広告内の「コンバージョン」一覧** に表示される
- データ反映は **12〜24時間** の遅延あり
- GA4側で新しいキーイベントを追加しても **自動では同期されない**（手動で再インポートが必要）

---

## 4. 方法A: Google広告ネイティブ CVタグ

GA4 と連携せず、Google広告で直接タグを発行して設置する方法。

### 手順

```
Google広告 → ツールと設定 → 測定 → コンバージョン → 新しいコンバージョン アクション
  → ウェブサイト
  → 「コードを手動でインストールする」or「GTMを使用する」
```

### タグの2種類

- **Global Site Tag (gtag.js)**: 全ページに設置（もはや不要、Googleタグで代替）
- **イベントスニペット**: CV発生ページに設置

### GTMで設置する場合

GTMには **公式テンプレート** があります:

```
GTM → 新しいタグ → Google 広告 コンバージョン トラッキング
  設定:
    コンバージョン ID: AW-XXXXXXXXX
    コンバージョン ラベル: ABCdefGHIj
    コンバージョン値: (任意)
    通貨コード: JPY
    注文 ID: (重複排除用)
  トリガー: サンクスページのPV or カスタムイベント
```

### いつこの方法を選ぶ？

- GA4を使わない場合（レア）
- **GA4インポートが使えない特殊なケース**（オフラインCV等）

### 注意点

- 同じCVを **ネイティブタグとGA4インポートの両方で設定してはいけない**（二重カウント）
- どちらか片方を **「セカンダリ」** に設定して集計から除外するのが定石

---

## 5. 方法C: 拡張コンバージョン（Enhanced Conversions）

**2026年現在、最も重要なCV精度改善機能**。

### 何をしているか？

CV発生時に **ユーザーの個人情報をハッシュ化** してGoogleに送信し、**Googleのログインユーザーデータと突合** して「Cookie削除・クロスデバイスで逃したCV」を取り戻す技術。

### 送る情報（ハッシュ化済み）

- メールアドレス（ハッシュ化）
- 電話番号（ハッシュ化）
- 氏名・住所（ハッシュ化・任意）

→ **ハッシュ化されるので生データはGoogleに届かない**

### 期待できる効果

- 2026年の実測値で **5〜15% のCV数回復**
- iOS Safari・広告ブロッカー・クロスデバイス等で失われるCVを取り戻せる
- **スマート入札の精度向上** により広告効率UP

### 実装方法

#### パターン1: GA4インポートCVの場合

GA4側で拡張コンバージョンを有効化すれば、**広告側に自動共有** される。

```
GA4 管理 → データ収集と変更 → ユーザー指定データの収集
  → 拡張コンバージョンを有効化
```

GTMの **Googleタグ** で、ユーザーデータを読み取る設定を追加:

```
Googleタグ の詳細設定
  → ユーザー指定データの収集
  → フィールドのマッピング:
    email: {{DLV - user_email}}
    phone_number: {{DLV - user_phone}}
    address: {{DLV - user_address}}  (任意)
```

#### パターン2: Google広告ネイティブCVの場合

GTMの **Google広告 コンバージョン タグ** で個別に設定:

```
Google 広告 コンバージョン タグ
  → 拡張コンバージョンを有効化
  → ユーザー情報の取得方法:
      ・ダイレクト入力 (dataLayerやDOMから取得)
      ・コード (JavaScript)
      ・既存のタグ (Googleタグで指定済みのもの)
```

### ⚠️ 注意: GA4 Goalsインポートでは拡張CV使えない

2026年時点の制約:
- **GA4のキーイベント** からインポートしたCV → 拡張CV **使える**
- 旧UAから移行した「GA Goalインポート」 → 拡張CV **使えない**

→ 新規で組むなら **キーイベント ベースのインポート** を選ぶこと

## 6. CVの「プライマリ」と「セカンダリ」

2026年のGoogle広告CVは2種類に分類されます。

| 分類 | 挙動 |
|------|-----|
| **プライマリ** | スマート入札の **最適化対象**。コンバージョン数列に計上 |
| **セカンダリ** | レポート観察用。入札最適化には **使われない** |

### 使い分けの基本

```
Primary:   フォーム送信完了 (最重要の"本CV")
Secondary: CTAクリック・電話タップ・マイクロCV (参考指標)
```

### 二重カウント防止の決定打

GA4インポートとネイティブタグの **両方で同じCVを設定** してしまった場合:

```
片方を「セカンダリ」に変更する
  → プライマリは1つだけにする
  → スマート入札の学習が一貫する
```

## 7. CVの設定項目（詳細）

### アクションの種類（カテゴリ）

| カテゴリ | 例 |
|---------|-----|
| 購入 | EC決済完了 |
| リード | 問い合わせ送信・資料DL |
| ページビュー | 特定ページ到達 |
| サインアップ | 会員登録 |
| お問い合わせ | 電話タップ |
| その他 |  |

→ **P-MAXなどのAI配信** では、カテゴリが配信最適化のヒントになる

### カウント方法

| 方法 | いつ使う？ |
|------|---------|
| **毎回** | EC購入（同じユーザーが複数回買ったら毎回CV） |
| **1回のみ** | リード獲得（同じユーザーが何度送信しても1CV扱い） |

### アトリビューションモデル

2026年現在、以下のモデルが選択可能:

| モデル | 配分方法 |
|-------|---------|
| **データドリブン**（推奨） | AIが実データに基づき配分 |
| ラストクリック | 最後のクリックに100% |
| ファーストクリック | 最初のクリックに100% |
| 線形 | 全クリックに均等配分 |
| 減衰 | 直近ほど配分大きい |
| 位置ベース | 最初と最後に40%ずつ、中間に20% |

**データドリブン** がデフォルト推奨。Google広告のAI学習精度が最も高い。

### コンバージョン値

CV1件あたりの **価値（円）** を指定できます。

- 固定値: 3000円（リード1件の想定価値）
- 動的値: GA4で送られたparameter `value` を使用
- 使わない: 空欄（タグの設定で値を渡さない）

ROAS最適化を使う場合は **必ず値を設定** すること。

## 8. CVの検証（テストフロー）

CV設定が正しく動いているか確認:

### Step1: Tag Assistant で発火確認

GTMプレビューモード → サイトでCV発生 → タグ発火を見る

### Step2: Google広告の診断ツール

```
Google広告 → ツールと設定 → 測定 → コンバージョン
  → 該当CVを選択
  → ステータス欄を確認
```

| ステータス | 意味 |
|----------|------|
| 未確認 | まだCVが検出されていない |
| 記録中 | 正常に受信中 ✓ |
| タグが見つかりません | タグ設置ミス |
| アクションなし | タグは動いているがCVが発生していない |

### Step3: 実際のCV数値確認

- 広告 → コンバージョン列（反映に12〜24h）
- GA4側のキーイベント数と照合

### CV数が一致しない場合

| 事象 | 理由 |
|------|------|
| GA4 > 広告 | 広告経由でないCVも含まれる（普通） |
| 広告 > GA4 | 広告のアトリビューション範囲が広い（普通） |
| 異常に一方が大きい | **二重カウント疑い**・要調査 |

## 9. オフラインコンバージョン（CRM連携）

**電話でのCV・店舗来店・営業成約** など、Webで完結しないCV:

### Google広告の仕組み

- 広告クリック時に **GCLID（クリックID）** をCookieに保存
- フォーム送信時にGCLIDも送る
- 後日、**成約時にCRMからGoogle広告へCSVアップロード** することで「このクリックは成約した」と教える

### 運用

```
[ユーザー広告クリック] → GCLID保存
       ↓
[フォーム送信] → GCLIDも一緒に自社DBへ
       ↓
[営業が成約]  → CSVにGCLID + 金額を記載
       ↓
[Google広告にアップロード] → CV認識
```

### 2026年の推奨

- **CRM連携 API**（Google Ads API経由）で自動化
- HubSpot / Salesforce / Zoho 等は公式インテグレーションあり

## 10. 同意モード（Consent Mode v2）との関連

### 2026年6月15日の変更

- **Google広告のCV計測** は **`ad_storage` 同意のみ** で制御されるようになる
- GA4の同意設定からは **切り離される**

### 実装すべきこと

- CMP（Cookiebot / CookieHub / OneTrust 等）導入

- 拒否時も **匿名ping送信** で統計的補完（Advanced mode）

## 11. よくあるトラブル

### トラブル1: 「タグが見つかりません」

- GTMで公開漏れ
- CVラベルのコピーミス
- CVタグのトリガー条件ミス

### トラブル2: CV数が0のまま

- CV発生ページに **タグが設置されていない**
- 自動タグ設定がOFF（URLに `gclid` が付かない）
- LPが別ドメイン（リダイレクトで gclid が消える）

### トラブル3: CV数が異常に多い

- **二重カウント**（ネイティブ + GA4インポート両方でプライマリ）
- トリガー誤設定（全PVで発火している）
- テスト送信を本番CVに加算している

### トラブル4: 拡張CV送信がエラー

- ハッシュ化の方法が間違っている
- 送る前に個人情報が空文字のまま
- 対策: GTMの **「ダイレクト入力」** を使えば自動でハッシュ化

### トラブル5: GA4とGoogle広告のCV数が大きく違う

- **アトリビューション期間** が違う（広告のデフォルト30日 vs GA4の設定次第）
- 広告は **クリック後の行動** を、GA4は **セッション起点** を見ている
- 誤差10〜20%は仕様
