# リマーケティングとオーディエンス

## 🎯 このページのゴール

- 「リマーケティング」と「オーディエンス」の違いを理解する
- GA4のオーディエンスを **Google広告で再利用** できる
- 2026年の同意ルールで **リマケが効かなくなる条件** を知る

---

## 1. リマーケティング とは

**一度サイトを訪れたユーザーに、再度広告を見せる仕組み**。

### 典型シナリオ

```
[初回訪問] LP来訪 → 未CV → 離脱
     ↓
[数日後] 別のサイトを見る
     ↓
[広告表示] 再訪を促す広告がバナーで表示される
     ↓
[再訪] LPに戻る → CV達成
```

### なぜ効くのか？

- 一度興味を持ったユーザーは **CVR が初回訪問の2〜5倍**
- ブランド・商品への認知コストが **すでに支払い済み**
- 広告費の **費用対効果が最高クラス**

---

## 2. 「オーディエンス」の正体

リマケに使う **ユーザーの集合** を「オーディエンス」と呼びます。

### オーディエンスの種類

| 種類 | 何？ |
|------|------|
| **ウェブサイト訪問者** | サイトに来たことがある人 |
| **エンゲージメントユーザー** | 一定時間以上閲覧・複数ページ見た人 |
| **CV未達成者** | 訪問したがCVしていない人 |
| **既存CV者** | CVしたことがある人 |
| **カスタムセグメント** | 特定URL・キーワード・興味で定義 |
| **類似オーディエンス** | 既存CV者に似たユーザー |
| **カスタマー マッチ** | 自社が持つ顧客リスト（メールアドレス等） |

### 2026年の変化

- 従来の「類似オーディエンス（Similar Audiences）」は **段階的に廃止**
- 代わりに **P-MAX のオーディエンスシグナル** や **最適化されたターゲティング** へ移行
- **ファーストパーティデータ（顧客リスト）の重要性がかつてなく上昇**

---

## 3. オーディエンスを作る方法

### 方法A: Google広告側で直接作成

```
Google広告 → ツールと設定 → 共有ライブラリ → オーディエンス マネージャー
  → オーディエンスリスト → 「+」→ ウェブサイト訪問者
  → ルールを設定:
     URL contains "/contact"
     AND NOT URL contains "/thanks"
  → 有効期間: 最大540日
```

### 方法B: GA4でオーディエンス作成 → 広告にインポート

GA4の豊富な条件式でオーディエンスを作り、広告で使う **2026年の推奨パターン**。

```
GA4 → 管理 → オーディエンス → 新しいオーディエンス
  → 条件:
     イベント "cta_click" を発火
     AND NOT イベント "generate_lead" を発火
  → 名前: "CTA押下CV未達成"
  → 保存
```

**Google広告とリンクしていれば自動的に共有** されるので、広告側で使えます。

### 方法C: カスタマー マッチ（顧客リスト）

自社DB・CRMの **顧客メール・電話** をハッシュ化してアップロード:

```
Google広告 → ツールと設定 → オーディエンス マネージャー
  → 「+」→ カスタマー マッチ
  → CSVアップロード (email/phone)
  → Googleが自動でハッシュ化 → ログインユーザーとマッチ
```

**2026年の最強手法**: Cookie規制の影響を受けにくい・既存顧客への訴求に最適

---

## 4. オーディエンスの有効期間

リストに含まれる **「過去どこまで」のユーザーか** を指定。

| 期間 | 用途 |
|------|-----|
| 1〜7日 | カート離脱・直近離脱ユーザー |
| 30日 | 標準的なリマケ |
| 90日 | 長期検討型商材・BtoB |
| 180〜540日 | 既存CV者の再活性化 |

- 広告効果は **30日以内** が一番高い
- **540日（最大）** を設定しておくとリスト母数は確保されるが、古いユーザーは反応が低い

---

## 5. リマケ戦略のパターン

### パターン1: CV未達成者への再訴求（基本）

```
オーディエンス:
  条件: サイト訪問済 AND NOT サンクスページ到達
  期間: 30日
広告メッセージ:
  「まだ間に合います」「限定特典」等
配信先:
  ディスプレイ or Demand Gen
```

### パターン2: 検討段階別のセグメント

```
セグメント1: LP訪問のみ → 軽い再認知広告
セグメント2: CTAクリックあり → 具体的オファー
セグメント3: フォーム開始したが未送信 → 離脱防止メッセージ
```

→ GA4で各セグメントをオーディエンス化。**段階ごとにクリエイティブを変える**

### パターン3: 既存CV者のクロスセル/リピート

```
オーディエンス: generate_lead 発火 AND 30日経過
広告: 関連商品 or アップセル
```

### パターン4: カスタマー マッチでLP回避

```
オーディエンス: 既存顧客リスト（メール）
キャンペーン: リピート購入促進・会員特典
```

## 6. 類似オーディエンス（2026年は廃止方向）

かつて主力だった「類似オーディエンス（Similar Audiences）」:

- 既存CV者に似た **"新しいユーザー"** を自動生成
- 新規獲得に強力だった

### 2026年の扱い

- **独立機能としては廃止**、警告通知あり
- 代わりに **P-MAX の「オーディエンスシグナル」** として活用
- または **最適化されたターゲティング**（Googleが自動で類似ユーザーを検索面から選ぶ）に移行

### 既存のリストはどうなる？

- リマーケティングリストとしての利用は継続
- 「類似生成」機能だけが停止
- 新規運用では **シグナル付きP-MAX** を設計することが推奨

---

## 7. Consent Mode との関係（2026年の肝）

### リマケは `ad_personalization` 同意が必須

2026年のConsent Mode v2 仕様:

| パラメータ | リマケへの影響 |
|-----------|-------------|
| `ad_storage` | **Denied**ならCookie保存できず、リマケ母数ゼロ |
| `ad_user_data` | **Denied**ならGoogle広告にデータ送信不可 |
| `ad_personalization` | **Denied**なら個別ユーザーを追跡した配信不可 |

→ **3つすべてが Granted** の時だけ完全なリマケが機能

### 2026年6月15日以降の変更

- GA4の「Google Signals」設定が **リマケを直接制御しなくなる**
- 代わりに **`ad_storage` 同意のみ** で広告データの流れを制御
- **同意を取れない = リマケリスト母数の激減**

### 対策

- **Consent Mode Advanced** 実装（匿名ping補完）
- **カスタマー マッチ**（既存顧客リスト）への投資拡大
- **ファーストパーティデータの蓄積**

## 8. プライバシーポリシーの必須記載

リマーケティングを使う場合、**LPにプライバシーポリシーの記載義務** があります（Google広告ポリシー）。

### 記載すべき項目

- サードパーティ（Googleを含む）がCookie・ウェブビーコンを使用することの告知
- **データの使用目的**（広告配信・計測）
- ユーザーが **オプトアウトする方法** の案内
- **Cookie ポリシー** のリンクまたは詳細

### テンプレート例

```
【サードパーティCookieについて】
当サイトでは、Googleをはじめとする第三者配信事業者の Cookie を利用し、
ユーザーが当サイトへ過去にアクセスした情報に基づいて広告を配信しています。

ユーザーは Google アカウントの広告設定ページ (https://www.google.com/settings/ads)
でパーソナライズド広告を無効にできます。
詳細は当社のCookieポリシーをご確認ください。
```

→ **この記載がないと広告停止リスク** あり

## 9. リマケ配信のチャネル別特徴

| チャネル | 特徴 |
|---------|------|
| **ディスプレイ** | 一番オーソドックス・安価・バナー |
| **Demand Gen** | YouTube/Gmail/Discover・ビジュアル強い |
| **YouTube** | 動画リマケ・印象強め |
| **検索（RLSA）** | リマケリストに該当する人の検索結果で上位表示・入札増 |
| **ショッピング** | EC商品の再表示 |
| **Gmail** | プロモーションタブに表示 |

### RLSA（Remarketing List for Search Ads）

**過去訪問ユーザーが検索した時だけ** 入札を強化する機能:

```
通常の検索キャンペーン
  + オーディエンス: 過去訪問者 (リマケリスト)
  → 訪問者が検索した時だけ入札 +30%
```

再検索してきたユーザーは購入意欲が高いため、RLSAは **CVR と単価の両方** を改善できます。

## 10. ダイナミック リマーケティング（EC特化）

**ユーザーが見た "その商品" を再表示** する高度なリマケ:

### 必要な準備

1. **Google Merchant Center** で商品フィード登録
2. **GTM** で商品ページ・カート・購入のdataLayer送信
3. **Google 広告 リマーケティングタグ** に商品IDを含めて発火

### dataLayerの例

```js
// 商品ページ
window.dataLayer.push({
  event: 'view_item',
  ecomm_pagetype: 'product',
  ecomm_prodid: 'SKU-01',
  ecomm_totalvalue: 3000
});

// カート
window.dataLayer.push({
  event: 'view_cart',
  ecomm_pagetype: 'cart',
  ecomm_prodid: ['SKU-01', 'SKU-02'],
  ecomm_totalvalue: 5000
});
```

→ 離脱後、Gmailプロモーションやディスプレイで **同じ商品の広告** が表示される

## 11. オーディエンス設計のチェックリスト

- [ ] Google広告とGA4がリンク済み
- [ ] GA4でオーディエンスを作成
- [ ] GA4 Signals の状態を確認（2026-06-15以降の変更も要注意）
- [ ] Consent Mode v2 を実装済み
- [ ] **プライバシーポリシー** にリマケ記載あり
- [ ] **カスタマー マッチ** を検討した
- [ ] **有効期間** が適切
- [ ] **類似オーディエンス** に頼らない構成に移行した
- [ ] セグメントごとの **クリエイティブを分けている**
- [ ] RLSAを検索キャンペーンに適用した

## 12. よくあるトラブル

### トラブル1: リマケ配信されない

- **リストサイズ不足**（ディスプレイ: 100人、検索: 1000人以上必要）
- Consent Mode の `ad_personalization` が denied
- プライバシーポリシー未設置での配信停止

### トラブル2: リストサイズが急減した

- **2026-06-15 の同意仕様変更** 前後で一度チェック
- CMPを入れ替えた直後（同意再取得の影響）
- GA4/広告のオーディエンス有効期限切れ

### トラブル3: CVが増えない

- リマケはあくまで「刈り取り」。**新規獲得は別キャンペーン** が必要
- **頻度制御（フリーケンシー キャップ）** で配信しすぎを抑える

### トラブル4: 拒否ユーザーにも配信してしまう

- GTMのConsent設定ミス
- タグが **同意前に発火** する実装になっている
- 対策: Consent Mode v2 + Advanced mode
