# LP運用での広告実務

## 🎯 このページのゴール

- LPで広告を回す **最短の実装フロー** を把握する
- 「計測 → 広告配信 → 改善」の **PDCAサイクル** を身につける
- 月次モニタリングで **見るべき指標** と **よくある改善ポイント** を知る

---

## 1. LP広告運用の全体フロー

```
【フェーズ1: 計測の土台作り】
  ├ GA4プロパティ作成
  ├ GTM設置
  ├ キーイベント設定 (CTAクリック・フォーム送信)
  └ Consent Mode v2 対応

【フェーズ2: Google広告の準備】
  ├ アカウント作成 (エキスパートモード)
  ├ GA4とリンク
  ├ コンバージョンのインポート
  ├ 拡張コンバージョン有効化
  └ 初期キャンペーン作成

【フェーズ3: 配信開始】
  ├ 検索キャンペーン (ブランド保護 + 顕在層)
  ├ P-MAX (予算の大半)
  └ リマーケティング (CV未達成者)

【フェーズ4: モニタリング・改善】
  ├ 日次: CV数・予算消化
  ├ 週次: チャネル別効率・検索語
  ├ 月次: キャンペーン構成見直し・素材入れ替え
  └ 四半期: 予算配分の大規模見直し
```

## 2. ゴールデンルール: 「計測→広告」の順番を守る

❌ **やってはいけない**:
```
いきなり広告出稿
  ↓
計測してないのでCPA不明
  ↓
なんとなく止める
  ↓
何が悪かったか分からない
```

✅ **正しい順番**:
```
GA4 でCV計測を1週間テスト運用
  ↓
キーイベント・拡張CV が動いていることを確認
  ↓
広告出稿 (最初は小予算から)
  ↓
2週間でAI学習 → スケール
```

**計測の土台が無いまま広告予算を使うのは、盲目運転**。

## 3. 初回キャンペーン設計（推奨テンプレート）

### ケース: リフォーム会社のLP（月予算20万円）

```
キャンペーン1: 検索 - ブランド
  予算: 3万/月
  キーワード: 自社ブランド名 + 関連ワード
  目的: 競合にブランド名を取られない保護
  入札: 手動CPC or tCPA

キャンペーン2: 検索 - サービス
  予算: 5万/月
  キーワード: "リフォーム 東京" "キッチン 交換" 等
  入札: tCPA (目標8,000円)

キャンペーン3: P-MAX - 全方位
  予算: 10万/月
  素材: LPから抽出した画像15枚 + 動画1本 + 見出し15個
  シグナル: 既存顧客リスト + カスタムセグメント
  目的: CVの50%を狙う

キャンペーン4: リマーケティング
  予算: 2万/月
  オーディエンス: サイト訪問者 - CV除外
  配信: ディスプレイ + Demand Gen
```

### BtoBの場合

P-MAX比率を下げて **検索広告・AI Max主軸** に変更:

```
検索 (ブランド):   20%
検索 (顕在):       40%
AI Max for Search: 20%
P-MAX:             10%
リマーケティング:  10%
```

## 4. CV計測と広告配信の統合チェックリスト

配信開始前の **最後の確認**:

### GA4側
- [ ] 計測タグがGTM経由で動いている
- [ ] CTAクリック・フォーム送信がイベント化
- [ ] キーイベントとしてマーク済み
- [ ] 探索レポートでCV数が見える
- [ ] リアルタイム・DebugViewで発火確認

### GTM側
- [ ] Googleタグ (GA4 + 広告ID) 配置済み
- [ ] コンバージョン リンカー配置済み
- [ ] Google 広告 コンバージョンタグ or GA4インポート済み
- [ ] リマーケティングタグ配置済み
- [ ] Consent Mode v2 対応
- [ ] 命名規則に従って整理

### Google広告側
- [ ] エキスパートモード
- [ ] GA4とリンク済み
- [ ] コンバージョン「記録中」ステータス
- [ ] 拡張コンバージョン有効
- [ ] 自動タグ設定ON
- [ ] プライマリ/セカンダリを明確に分離
- [ ] 請求先設定済み
- [ ] 予算上限 (キャンペーン・アカウント)

### LP側
- [ ] モバイル表示確認
- [ ] 電話タップリンク (tel:)
- [ ] メールリンク (mailto:)
- [ ] フォーム送信テスト
- [ ] サンクスページ or サンクスメッセージ動作確認
- [ ] **プライバシーポリシー** 設置済み
- [ ] **運営者情報** 設置済み
- [ ] Cookieポリシー or 同意バナー

## 5. 日次モニタリング項目

朝10分で確認すべき指標:

| 指標 | 見るべき変化 |
|------|-----------|
| CV数 | 前日と比較して急減していないか |
| 広告費 | 想定通りに消化されているか |
| 検索語（検索キャンペーン） | 意図しない語で配信されていないか |
| 表示回数・クリック率 | 急落していないか |
| 警告 | Google広告の通知・アラート |

### 異常値の基準

- **前日比 ±50%** の急変 → 何かが壊れている可能性
- **CTR が突然 0%** → 広告が不承認になっている
- **CV数が3日連続ゼロ** → 計測か配信が壊れている

## 6. 週次モニタリング項目

週1回・30分の深掘り:

### 週次チェック

| 項目 | 確認 |
|------|-----|
| キャンペーン別 CPA | 目標CPAを超えていないか |
| チャネル別 ROAS | 赤字キャンペーンはないか |
| 検索語レポート | ネガティブキーワード追加候補 |
| P-MAX アセット評価 | "低" 評価の素材を差し替え |
| オーディエンス別効率 | セグメント別のCVR |
| デバイス別パフォーマンス | モバイル/PCの偏り |
| 曜日・時間帯別 | 効率の悪い時間帯を検討 |

### P-MAXの週次アクション

- **低評価アセット** の差し替え
- **検索語レポート** の確認（2026年新機能）
- **配信先レポート** で怪しいプレースメントを除外

## 7. 月次モニタリング項目

月1回・数時間の本格レビュー:

### 月次レビュー

```
1. 先月のCV数・CPA・ROAS サマリー
2. キャンペーン別・チャネル別のROIランキング
3. 赤字キャンペーンの原因分析
4. 新しい素材・訴求軸の検討
5. 予算配分の再設計
6. 競合の広告動向チェック (手動検索)
7. LP側の改善ポイント洗い出し
8. 次月の目標設定
```

### A/Bテストの設計

| 要素 | テスト例 |
|------|---------|
| LP | ヒーロー画像・CTAコピー・フォーム位置 |
| 広告文 | 訴求軸・オファー内容・CTAテキスト |
| 画像 | 人物有無・商品写真・抽象イラスト |
| キャンペーン構造 | 細分化 vs 統合 |

## 8. 指標の読み解き方

### CPA（獲得単価）

```
CPA = 広告費 ÷ CV数
```

| 判定 | 状況 |
|------|-----|
| CPA < 目標 | 拡大余地あり → 予算増 |
| CPA = 目標 | 現状維持 |
| CPA > 目標 × 1.5 | 要改善 → 素材・オーディエンスを見直し |

### ROAS（広告費用対効果）

```
ROAS = CV金額 ÷ 広告費 × 100%
```

| ROAS | 状況 |
|------|-----|
| ROAS 500%超 | 非常に好調 |
| ROAS 200-500% | 健全 |
| ROAS 100-200% | 粗利次第では要改善 |
| ROAS 100%未満 | 赤字 |

### CTR（クリック率）

```
CTR = クリック数 ÷ 表示回数 × 100%
```

- 検索広告: **5〜10%** が目安
- ディスプレイ: **0.1〜0.5%** が目安
- 低すぎるなら広告文・画像を改善

### CVR（コンバージョン率）

```
CVR = CV数 ÷ クリック数 × 100%
```

- BtoB/リード獲得: **2〜5%** が目安
- EC: **1〜3%** が目安
- 低すぎるなら **LP改善** が先決（広告以前）

## 9. 典型的な改善フロー

### パターン1: CPAが高い

```
診断:
  ├ CTRは良い? → No → 広告文・画像改善
  │            → Yes ↓
  ├ CVRは良い? → No → LP改善
  │            → Yes ↓
  └ 表示回数が少ない → 入札単価上げ or キーワード拡張
```

### パターン2: CVが増えない

```
1. CV計測が壊れていないか最優先で確認
2. 予算不足で表示回数が少ない
3. 競合激化で入札が弱い
4. LPが改善されておらずCVRが頭打ち
5. オーディエンスが疲弊している → 新規シグナル追加
```

### パターン3: 急にCPAが悪化

```
チェック順序:
  1. 計測不具合 (GA4で見えるか?)
  2. 広告の不承認 (広告タブで確認)
  3. 自動入札の学習リセット (最近設定変更した?)
  4. 季節要因 (前年同月比)
  5. 競合の新規参入
```

## 10. LP改善の観点（広告と連携する）

広告だけでは限界があります。LP改善も重要:

### 広告とLPの整合性

- **広告文のメッセージ** と **LPヒーローのメッセージ** を一致させる
- 広告で「無料相談」と謳ったら、LPでも最初に「無料相談」を見せる

### CTAの配置

- **ファーストビュー** にCTA必須
- **料金・特徴・お客様の声** の各セクション後にも
- モバイルでは **画面下固定CTA**

### フォームの最適化

- 入力項目は **最低限** に
- **プログレスバー** で長いフォームの途中離脱を抑える
- **エラー表示** を即時に

### 計測との連携

- スクロール率を計測して「読まれていないセクション」を把握
- フォーム離脱ポイントを `form_field_focus` で計測
- 週次でこれらの変化を見る

## 11. チーム運用のポイント

### 役割分担の推奨

| 役割 | 担当 |
|------|-----|
| 戦略立案 | マーケ責任者 |
| 広告運用 | 運用担当 or 代理店 |
| CV計測 | アナリティクス担当 |
| LP改善 | デザイナー + エンジニア |
| データ分析 | アナリスト |

### 情報共有の仕組み

- **週次レポート** を Slack や スプレッドシートで共有
- **KPI ダッシュボード** を Looker Studio で作成
- **広告 × LP × 計測** の三者で月1ミーティング

### 緊急対応のルール

- **広告費が急に激増**: アカウント凍結・停止
- **CV数が急にゼロ**: 計測チェックを最優先
- **不承認の広告**: 24時間以内に代替広告投入

## 13. まとめ: LP広告の成功 = 3つの掛け算

```
計測精度 × 広告設計 × LP品質 = 成果
```

どれか1つが弱いと全体の効果が大きく落ちます。

- **計測精度** → GA4 + GTM + 拡張CV (本ノート群の主題)
- **広告設計** → P-MAX + AI Max + リマケ (本フォルダの主題)
- **LP品質** → UIUX・訴求・フォーム最適化

**"広告運用を始める前に計測を整える"** これが2026年でも変わらない鉄則です。
