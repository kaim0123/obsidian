## エディタ・開発環境関連

### **エディタ（Editor）**
- **意味**: コードを書くためのソフトウェア
- **例**: VSCode、メモ帳、Sublime Text
- **補足**: プログラマーがコードを書くための専用ツール。通常のテキストエディタより高機能

### **IDE（統合開発環境）**
- **意味**: Integrated Development Environmentの略。コードを書く、実行する、デバッグするなどの機能が統合されたソフトウェア
- **例**: Visual Studio、IntelliJ IDEA、Eclipse
- **補足**: VSCodeは軽量なエディタだが、拡張機能でIDE並みの機能を実現できる

### **ワークスペース（Workspace）**
- **意味**: プロジェクトのフォルダやファイルをまとめて管理する単位
- **例**: 1つのプロジェクトフォルダを開いた状態
- **補足**: 複数のフォルダを1つのワークスペースにまとめることも可能

### **エクスプローラー（Explorer）**
- **意味**: ファイルやフォルダを表示・管理するパネル
- **例**: Windowsのエクスプローラーと同じような機能
- **補足**: VSCodeの左側に表示されるファイル一覧

### **ターミナル（Terminal）**
- **意味**: コマンドを入力して実行する画面（黒い画面）
- **例**: PowerShell、コマンドプロンプト、bash
- **補足**: マウスを使わず、キーボードだけで操作する画面。プログラマーがよく使う

### **コマンドパレット（Command Palette）**
- **意味**: VSCodeの機能を検索して実行できるメニュー
- **使い方**: `Ctrl + Shift + P`で開く
- **補足**: メニューを覚えなくても、機能名を検索して実行できる

### **拡張機能（Extension）**
- **意味**: VSCodeに機能を追加するプラグイン
- **例**: 日本語化、コード補完、Git連携
- **補足**: 無料でインストールでき、VSCodeを自分好みにカスタマイズできる

### **スニペット（Snippet）**
- **意味**: よく使うコードの断片を登録しておく機能
- **例**: 「clog」と入力すると`console.log()`が自動入力される
- **補足**: 同じコードを何度も書く手間を省ける

## ファイル・フォルダ関連

### **プロジェクト（Project）**
- **意味**: 1つのアプリやプログラムを作るためのファイル群
- **例**: Webサイト、ゲーム、アプリ
- **補足**: 通常は1つのフォルダにまとめられる

### **ソースコード（Source Code）**
- **意味**: プログラマーが書いたコード（人間が読める形式）
- **例**: `.js`、`.py`、`.html`ファイル
- **補足**: コンピューターが実行する前に、人間が書くコードのこと

### **ファイル拡張子（File Extension）**
- **意味**: ファイル名の最後にある「.」以降の部分
- **例**: `.js`（JavaScript）、`.py`（Python）、`.html`（HTML）
- **補足**: ファイルの種類を表す。VSCodeは拡張子で言語を自動認識する

### **フォルダ構造（Folder Structure）**
- **意味**: ファイルやフォルダの階層的な配置
- **例**: `project/src/index.js`
- **補足**: 整理された構造にすることで、コードが見つけやすくなる

### **ルートフォルダ（Root Folder）**
- **意味**: プロジェクトの最上位のフォルダ
- **例**: プロジェクトを開いた時に表示される一番上のフォルダ
- **補足**: すべてのファイルの親となるフォルダ

## コード関連

### **変数（Variable）**
- **意味**: データを保存する箱のようなもの
- **例**: `let name = "太郎"` の`name`が変数
- **補足**: 値を後から変更できる

### **関数（Function）**
- **意味**: 特定の処理をまとめたもの
- **例**: `function greet() { console.log("こんにちは"); }`
- **補足**: 何度も使う処理を関数にまとめることで、コードを再利用できる

### **クラス（Class）**
- **意味**: オブジェクトを作るための設計図
- **例**: `class Person { }`
- **補足**: オブジェクト指向プログラミングの基本概念

### **インポート（Import）**
- **意味**: 他のファイルのコードを使えるようにすること
- **例**: `import { useState } from 'react'`
- **補足**: 既存のコードを再利用するために使う

### **エクスポート（Export）**
- **意味**: 他のファイルで使えるようにコードを公開すること
- **例**: `export function myFunction() { }`
- **補足**: インポートと対になる概念

### **コメント（Comment）**
- **意味**: コードに書くメモ。プログラムの実行には影響しない
- **例**: `// これはコメントです`
- **補足**: コードの説明や注意事項を書くために使う

### **シンボル（Symbol）**
- **意味**: 関数名、変数名、クラス名などの識別子
- **例**: `function myFunction()`の`myFunction`がシンボル
- **補足**: VSCodeでシンボル検索を使うと、関数や変数に素早く移動できる

### **インデント（Indent）**
- **意味**: コードの行頭に付ける空白（字下げ）
- **例**: タブやスペースでコードを階層的に見やすくする
- **補足**: コードの構造を視覚的に表現するために重要

### **フォーマット（Format）**
- **意味**: コードの見た目を整えること
- **例**: インデントを統一、改行を調整
- **補足**: 読みやすいコードにするために自動で整形する機能

### **リント（Lint）**
- **意味**: コードの品質をチェックすること
- **例**: 未使用の変数、エラーの可能性を指摘
- **補足**: バグを防ぐために使う

### **補完（Autocomplete / IntelliSense）**
- **意味**: コードを入力する際に、候補を自動で表示する機能
- **例**: `con`と入力すると`console`が候補として表示される
- **補足**: タイピングの手間を省き、スペルミスを防げる

### **構文エラー（Syntax Error）**
- **意味**: コードの書き方（構文）が間違っているエラー
- **例**: 括弧が閉じていない、セミコロンが抜けている
- **補足**: プログラムが実行できない状態

### **ランタイムエラー（Runtime Error）**
- **意味**: プログラム実行中に発生するエラー
- **例**: 存在しない変数にアクセスしようとした
- **補足**: 構文は正しいが、実行時に問題が発生する

## Git・バージョン管理関連

### **Git（ギット）**
- **意味**: ファイルの変更履歴を管理するシステム
- **例**: コードのバージョン管理に使う
- **補足**: プログラマーが必ず使うツールの一つ

### **リポジトリ（Repository / Repo）**
- **意味**: プロジェクトのファイルと変更履歴を保存する場所
- **例**: ローカルリポジトリ（自分のPC）、リモートリポジトリ（GitHub等）
- **補足**: プロジェクトの「倉庫」のようなもの

### **コミット（Commit）**
- **意味**: 変更を記録すること
- **例**: 「ログイン機能を追加」というメッセージと共に変更を保存
- **補足**: スナップショットを撮るようなイメージ

### **プッシュ（Push）**
- **意味**: ローカルの変更をリモートリポジトリに送ること
- **例**: GitHubにコードをアップロードする
- **補足**: 他の人とコードを共有するために使う

### **プル（Pull）**
- **意味**: リモートリポジトリの変更をローカルに取得すること
- **例**: GitHubから最新のコードをダウンロードする
- **補足**: 他の人の変更を取り込むために使う

### **ブランチ（Branch）**
- **意味**: コードの分岐。メインのコードから分かれた作業用のコピー
- **例**: 「新機能開発」用のブランチを作成
- **補足**: 複数の人が同時に作業するために使う

### **マージ（Merge）**
- **意味**: ブランチの変更を統合すること
- **例**: 新機能ブランチをメインブランチに統合
- **補足**: 分岐したコードを1つにまとめる

### **コンフリクト（Conflict）**
- **意味**: マージ時に同じ箇所が異なる変更で競合すること
- **例**: 同じ行を2人が別々に変更した場合
- **補足**: 手動で解決する必要がある

### **ステージング（Staging）**
- **意味**: コミットする前に変更を選択すること
- **例**: 複数のファイルを変更したが、一部だけコミットしたい場合
- **補足**: コミット前に「この変更を含める」と指定する作業

### **差分（Diff）**
- **意味**: 変更前と変更後の違い
- **例**: 追加された行（+）、削除された行（-）を表示
- **補足**: 何が変更されたか一目でわかる

## デバッグ関連

### **デバッグ（Debug）**
- **意味**: プログラムのバグ（エラー）を見つけて修正すること
- **例**: プログラムが正しく動かない原因を調べる
- **補足**: プログラマーの重要な作業の一つ

### **ブレークポイント（Breakpoint）**
- **意味**: プログラムの実行を一時停止する地点
- **例**: 行番号の左をクリックして設定
- **補足**: その時点での変数の値を確認できる

### **ステップ実行（Step Execution）**
- **意味**: プログラムを1行ずつ実行すること
- **例**: `F10`でステップオーバー、`F11`でステップイン
- **補足**: バグの原因を特定するために使う

### **変数パネル（Variables Panel）**
- **意味**: デバッグ中に現在の変数の値を表示するパネル
- **例**: `name = "太郎"`、`age = 25`などが表示される
- **補足**: プログラムの状態を確認できる

### **コールスタック（Call Stack）**
- **意味**: 関数の呼び出し履歴
- **例**: `main()` → `functionA()` → `functionB()`の順に呼ばれた
- **補足**: どの関数から呼ばれたかがわかる

### **ログ（Log）**
- **意味**: プログラムの実行記録
- **例**: `console.log("処理開始")`でログを出力
- **補足**: プログラムの動作を確認するために使う

## その他

### **API（Application Programming Interface）**
- **意味**: プログラム同士が通信するための仕組み
- **例**: Web API、ライブラリの関数
- **補足**: 他のプログラムの機能を使うためのインターフェース

### **フレームワーク（Framework）**
- **意味**: アプリ開発を効率化するための骨組み
- **例**: React、Vue.js、Django
- **補足**: よく使う機能が最初から用意されている

### **ライブラリ（Library）**
- **意味**: よく使う機能をまとめたコードの集まり
- **例**: jQuery、Lodash
- **補足**: 自分で書かなくても使える便利な機能集

### **パッケージ（Package）**
- **意味**: ライブラリやツールを配布する単位
- **例**: npmパッケージ、Pythonパッケージ
- **補足**: 他の人が作ったコードを簡単に使える

### **依存関係（Dependency）**
- **意味**: プロジェクトが動作するために必要な他のパッケージ
- **例**: Reactを使うには、いくつかのパッケージが必要
- **補足**: プロジェクトが他のコードに依存している状態

### **ビルド（Build）**
- **意味**: ソースコードを実行可能な形式に変換すること
- **例**: TypeScriptをJavaScriptに変換、複数ファイルを1つにまとめる
- **補足**: 開発用のコードを本番用に変換する作業

### **コンパイル（Compile）**
- **意味**: ソースコードを機械語に変換すること
- **例**: C++のコードを実行ファイルに変換
- **補足**: 人間が読めるコードをコンピューターが実行できる形式に変換

### **正規表現（Regular Expression / Regex）**
- **意味**: 文字列のパターンを表現する記法
- **例**: `\d+`は「1つ以上の数字」を表す
- **補足**: 検索・置換で複雑なパターンを指定できる

### **マルチカーソル（Multi-cursor）**
- **意味**: 複数の場所に同時にカーソルを置く機能
- **例**: 同じ文字列を複数箇所で同時に編集
- **補足**: 効率的にコードを編集できる

### **ワークフロー（Workflow）**
- **意味**: 作業の流れ、手順
- **例**: コードを書く → テストする → コミットする → プッシュする
- **補足**: 効率的な作業手順を確立すること

## まとめ

これらの用語は、プログラミングを学ぶ上で頻繁に登場します。最初は覚えるのが大変ですが、実際に使いながら覚えていくのが一番です。わからない用語が出てきたら、この用語集を参照してください。

**覚え方のコツ**:
1. 実際に使ってみる（手を動かす）
2. エラーが出たら、その用語を調べる
3. 同じ用語を何度も見るうちに自然と覚える

無理に全部覚えようとせず、必要になった時に調べる習慣をつけましょう。
