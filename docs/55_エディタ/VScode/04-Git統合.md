## Gitとは

**Git（ギット）**は、ファイルの変更履歴を管理するシステムです。プログラマーが必ず使うツールの一つで、以下のようなことができます。

### Gitでできること

- **変更履歴の記録**: いつ、誰が、何を変更したかを記録
- **バージョン管理**: 過去の状態に戻れる
- **共同作業**: 複数人で同じプロジェクトを編集
- **バックアップ**: コードのバックアップとしても機能

### 用語解説

- **リポジトリ（Repository / Repo）**: プロジェクトのファイルと変更履歴を保存する場所
  - **ローカルリポジトリ**: 自分のPC上にあるリポジトリ
  - **リモートリポジトリ**: GitHub等のサーバー上にあるリポジトリ
- **コミット（Commit）**: 変更を記録すること。スナップショットを撮るようなイメージ
- **プッシュ（Push）**: ローカルの変更をリモートリポジトリに送ること
- **プル（Pull）**: リモートリポジトリの変更をローカルに取得すること
- **ブランチ（Branch）**: コードの分岐。メインのコードから分かれた作業用のコピー
- **マージ（Merge）**: ブランチの変更を統合すること
- **ステージング（Staging）**: コミットする前に変更を選択すること

## 基本的な使い方

### 1. ソース管理パネルを開く

- **ショートカット**: `Ctrl + Shift + G`
- **場所**: 左側のアクティビティバーから「ソース管理」アイコンをクリック

### 2. リポジトリを初期化（初回のみ）

初めてGitを使うプロジェクトの場合：

1. ソース管理パネルを開く
2. 「リポジトリを初期化する」をクリック
3. これでGitリポジトリが作成される

### 3. 変更をステージング

ファイルを変更すると、ソース管理パネルに変更されたファイルが表示されます。

- **方法1**: ファイルの横の「+」をクリック
- **方法2**: ファイルを右クリック → 「ステージの変更」
- **方法3**: すべての変更をステージング: 「変更」の横の「+」をクリック

**用語解説**:
- **ステージング**: コミットする前に「この変更を含める」と指定する作業。複数のファイルを変更したが、一部だけコミットしたい場合に便利です。

### 4. コミット

変更を記録します。

1. ステージングしたファイルの上にコミットメッセージを入力
2. 「✓」をクリック、または `Ctrl + Enter`
3. 変更が記録される

**コミットメッセージの書き方**:
- 簡潔に変更内容を書く
- 例: 「ログイン機能を追加」「バグを修正」「READMEを更新」

### 5. プッシュ（リモートリポジトリがある場合）

ローカルの変更をリモートリポジトリ（GitHub等）に送ります。

1. ソース管理パネルの「...」メニューをクリック
2. 「プッシュ」を選択
3. 初回の場合は、リモートリポジトリのURLを入力

## 実務でよく使う機能

### 変更の確認

#### 差分表示

ファイルをクリックすると、変更内容が表示されます。

- **緑色（+）**: 追加された行
- **赤色（-）**: 削除された行
- **黄色**: 変更された行

**用語解説**:
- **差分（Diff）**: 変更前と変更後の違い。何が変更されたか一目でわかります。

#### インライン表示

エディタでファイルを開くと、変更行の横に「+」「-」が表示されます。

- 変更を確認しながら編集できる
- 変更を元に戻すことも可能（右クリック → 「変更を元に戻す」）

### 変更を元に戻す

誤って変更してしまった場合：

1. ファイルを右クリック
2. 「変更を元に戻す」を選択
3. 変更が取り消される

### コミット履歴の確認

1. ソース管理パネルの「...」メニューをクリック
2. 「表示」→「コミット履歴を表示」
3. 過去のコミットを確認できる

## ブランチ操作

ブランチは、メインのコードから分かれた作業用のコピーです。複数の人が同時に作業するために使います。

### ブランチの作成

1. 左下のブランチ名をクリック（通常は「main」や「master」）
2. 「新しいブランチを作成...」を選択
3. ブランチ名を入力（例: `feature/login`）
4. Enterキーを押す

**ブランチ名の付け方**:
- `feature/機能名`: 新機能開発用
- `fix/修正内容`: バグ修正用
- `hotfix/緊急修正`: 緊急の修正用

### ブランチの切り替え

1. 左下のブランチ名をクリック
2. 切り替えたいブランチを選択
3. 自動でブランチが切り替わる

### ブランチのマージ

ブランチの変更をメインブランチに統合します。

1. メインブランチ（main等）に切り替え
2. ソース管理パネルの「...」メニューをクリック
3. 「ブランチ」→「ブランチをマージ...」
4. マージしたいブランチを選択

## マージコンフリクトの解決

**コンフリクト（Conflict）**は、マージ時に同じ箇所が異なる変更で競合することです。

### コンフリクトが発生した場合

1. コンフリクトが発生したファイルを開く
2. 以下のような表示がされる：
   ```
   <<<<<<< HEAD
   現在の変更（自分の変更）
   =======
   受信した変更（他の人の変更）
   >>>>>>> ブランチ名
   ```

### コンフリクトの解決方法

#### 方法1: 現在の変更を承諾

自分の変更を採用する場合：

1. コンフリクト部分をクリック
2. 「現在の変更を承諾」を選択

#### 方法2: 受信した変更を承諾

他の人の変更を採用する場合：

1. コンフリクト部分をクリック
2. 「受信した変更を承諾」を選択

#### 方法3: 両方を承諾

両方の変更を採用する場合：

1. コンフリクト部分をクリック
2. 「両方を承諾」を選択

#### 方法4: 手動で編集

自分で編集する場合：

1. `<<<<<<<`、`=======`、`>>>>>>>`の行を削除
2. 必要なコードだけを残す
3. ファイルを保存

### コンフリクト解決後の手順

1. ファイルを保存
2. 変更をステージング
3. コミット（通常は自動でメッセージが入る）
4. 必要に応じてプッシュ

## よくある操作の流れ

### 日常的な作業の流れ

1. **コードを編集**
2. **変更を確認**: ソース管理パネルで変更内容を確認
3. **ステージング**: コミットしたいファイルを選択
4. **コミット**: メッセージを書いてコミット
5. **プッシュ**: リモートリポジトリに送信

### 新機能開発の流れ

1. **ブランチを作成**: `feature/新機能名`
2. **コードを編集**: 新機能を実装
3. **コミット**: 定期的にコミット
4. **プッシュ**: リモートにプッシュ
5. **マージ**: メインブランチにマージ
6. **ブランチを削除**: 不要になったブランチを削除

### 他の人の変更を取り込む流れ

1. **プル**: リモートの最新変更を取得
2. **コンフリクト確認**: コンフリクトがあれば解決
3. **テスト**: 動作確認
4. **コミット**: 必要に応じてコミット

## トラブルシューティング

### Gitが認識されない

- **確認**: ターミナルで `git --version` を実行
- **解決**: Gitがインストールされていない場合は、[Git公式サイト](https://git-scm.com/)からインストール

### プッシュできない

- **確認**: リモートリポジトリのURLが正しいか
- **確認**: 認証情報（ユーザー名・パスワード）が正しいか
- **解決**: 「...」メニュー → 「リモート」→「リモートを追加/変更」で確認

### 変更が消えた

- **確認**: コミット履歴を確認
- **解決**: コミットしていれば、履歴から復元可能
