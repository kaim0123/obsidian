# 付録B　ソフトウェア設計チェックリスト（総合版）

設計レビューや自己点検に使えるチェックリストです。

---

## 1. 基本原則

- [ ] 異なる関心は分離されている（SoC）
- [ ] 各部品は 1 つの目的にまとまっている（高凝集）
- [ ] 部品間の依存は最小限（低結合）
- [ ] 内部実装は隠蔽されている（カプセル化）
- [ ] 依存の方向は内側（ドメイン）向き

---

## 2. 構造と境界

- [ ] モジュール・レイヤーの境界が明確
- [ ] 循環依存がない
- [ ] 公開 API の表面積は最小限
- [ ] 命名が意図を表している
- [ ] ディレクトリ構成が設計意図を反映している

---

## 3. ドメインと DDD

- [ ] ユビキタス言語がコードに反映されている
- [ ] 業務ルールはドメイン層にある
- [ ] 神クラス・神サービスがない
- [ ] 貧血ドメインモデルになっていない
- [ ] 集約の境界が整合性と一致している

---

## 4. 変化と拡張

- [ ] 変わりやすい箇所が隔離されている
- [ ] 拡張は既存コードの変更なしで可能か（OCP）
- [ ] 過剰な抽象化・パターン乱用がない（YAGNI）
- [ ] 技術的負債が可視化されている

---

## 5. 連携とイベント

- [ ] 同期/非同期の選択に理由がある
- [ ] イベントは過去形の事実として設計されている
- [ ] 冪等性が考慮されている
- [ ] 結果整合性が UI・業務と合意されている

---

## 6. テストと品質

- [ ] 主要な振る舞いが単体テスト可能
- [ ] 副作用は境界に押し出されている
- [ ] テストが書きにくい箇所に設計改善の候補がないか確認した

---

## 7. チームと文書

- [ ] 重要な設計判断が記録されている（ADR 等）
- [ ] 設計ルールがチームで共有されている
- [ ] 新人が全体像を把握できる説明がある

---

## 使い方

- **新機能前**: 1〜4 を中心に確認
- **リファクタリング前**: 1〜3 と 6
- **分散化検討時**: 5 を重点的に
- **定期レビュー**: 全体を通しで
