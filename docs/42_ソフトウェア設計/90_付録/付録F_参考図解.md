# 付録F　参考図解

本教材で使う概念の参考図解です。Obsidian やドキュメントにコピーして使えます。

---

## 1. 設計の階層

```text
アーキテクチャ    … 建物全体（システム・サービス・非機能）
    ↓
ソフトウェア設計  … 設計思想とパラダイム（本教材）
    ↓
モジュール設計    … 部屋の役割分担（パッケージ・レイヤー）
    ↓
クラス設計        … 家具の配置とつなぎ方
    ↓
メソッド設計      … 家具の細部（関数・メソッドの中身）
```

---

## 2. 関心の分離（レイヤー）

```text
  ┌─────────────────────────────────┐
  │  プレゼンテーション層（UI）        │
  ├─────────────────────────────────┤
  │  アプリケーション層（ユースケース）  │
  ├─────────────────────────────────┤
  │  ドメイン層（業務ルール）           │
  ├─────────────────────────────────┤
  │  インフラ層（DB・外部 API）        │
  └─────────────────────────────────┘
         依存の向き: 上 → 下（内側へ）
```

---

## 3. 三大パラダイムの組み合わせ

```text
  [イベント駆動]  サービス間は OrderPlaced 等で非同期連携
        │
  [DDD]           各サービス内部は境界づけられたコンテキスト
        │
  [OOP + FP]      集約はオブジェクト、計算部分は純粋関数
        │
  [手続き]        ユースケースのオーケストレーション
```

---

## 4. 境界づけられたコンテキスト

```text
  ┌──────────────┐    OrderPlaced    ┌──────────────┐
  │ 注文コンテキスト  │ ──────────────→ │ 在庫コンテキスト  │
  │ 用語: 注文・確定  │                  │ 用語: 引当・出庫  │
  │ 集約: Order     │                  │ 集約: StockItem │
  └──────────────┘                  └──────────────┘
```

---

## 5. イベント駆動の連携

```text
  注文サービス（Publisher）
       │
       │  OrderPlaced
       ▼
  イベントバス / メッセージブローカー
       │
       ├──→ 在庫サービス（引当）
       ├──→ 決済サービス（与信）
       └──→ 通知サービス（メール）
```

---

## 6. 集約の構造

```text
  Order（集約ルート）← 外部はここ経由でのみ操作
    ├── OrderLine
    └── OrderLine
```

---

## 7. 依存の方向（クリーンアーキテクチャ）

```text
        [UI]  [DB]  [外部 API]
          \    |    /
           \   |   /
            [インフラ]
                │
            [アプリケーション]
                │
             [ドメイン]  ← 中心。外に依存しない
```
