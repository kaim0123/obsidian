# 設計の基本用語

## この章の目的

以降の章で何度も登場する **設計の基本用語** を、ここで一度整理します。  
正確な定義より **イメージを掴む** ことを優先します。

---

## 1. 責務（Responsibility）と関心（Concern）

### 責務（Responsibility）

**責務** とは、その部品（モジュール・クラス・関数）が **担当すべき仕事** のことです。

- `Order` クラスの責務: 注文の状態管理、合計金額の計算
- `EmailSender` の責務: メールの送信

責務が曖昧だと、「この処理はどこに書くべきか」が毎回議論になります。

### 関心（Concern）

**関心** とは、ソフトウェアが扱う **目的の異なる関心事** です。

- 表示の関心（UI）
- 業務ルールの関心（ドメイン）
- データ保存の関心（永続化）

**関心の分離（Separation of Concerns）** は、異なる関心を別の場所に分ける原則です。[[04_関心の分離]] で詳しく扱います。

```text
  関心（Concern）  … 何について考えるか（UI・業務・DB）
  責務（Responsibility） … 誰がその仕事をするか
```

---

## 2. 境界（Boundary）と抽象化

### 境界（Boundary）

**境界** とは、部品の **内側と外側を分ける線** です。

- モジュールの境界: パッケージ・ディレクトリ
- クラスの境界: public / private
- サービスの境界: API・コンテキスト

境界があると、「内側の変更が外側に波及しにくい」構造を作れます。

### 抽象化（Abstraction）

**抽象化** とは、**本質的な部分だけを残し、詳細を隠す** ことです。

- 「ファイルに保存する」→ `Repository.save(order)` に抽象化
- 「HTTP で送る」→ `NotificationService.send()` に抽象化

抽象化は境界とセットで機能します。境界の向こう側には、抽象化されたインターフェースだけを見せます。

---

## 3. インターフェースと実装

| 用語 | 意味 |
|------|------|
| **インターフェース** | 外から見える **契約**（何ができるか、入力・出力） |
| **実装** | その契約を **満たす具体的な中身** |

```text
  利用者 ──→ [インターフェース] ──→ 実装A
                              └──→ 実装B（差し替え可能）
```

利用者は **インターフェースだけ** に依存すれば、実装を差し替えやすくなります。  
これが **依存性逆転** の基礎になります（詳細は [[010Programming/43_モジュール設計/00_全体像/目次|モジュール設計 目次]] や [[010Programming/44_クラス設計・デザインパターン/00_全体像/目次|クラス設計 目次]]）。

---

## 4. 依存関係のイメージ

**依存（Dependency）** とは、A が B を **使う・知る・呼ぶ** 関係です。

```text
  OrderService ──依存──→ OrderRepository
       │
       └── OrderService は OrderRepository がないと動かない
```

依存の方向が重要です。

- **望ましい**: 業務ロジック → 抽象 → 技術詳細
- **望ましくない**: 業務ロジック → 具体的な DB 実装に直結

依存が多い・循環していると、変更の影響が広がります（[[05_凝集度と結合度]]）。

## 5. 設計用語の地図

以降の章で出てくる用語の関係を、ざっくり地図にまとめます。

```text
                    設計の判断基準
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
   関心の分離        凝集度・結合度      カプセル化
        │                │                │
        └────────────────┼────────────────┘
                         ▼
                    境界・責務・抽象化
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
   手続き指向        オブジェクト指向     関数型
        │                │                │
        └────────────────┼────────────────┘
                         ▼
              DDD（業務中心）・イベント駆動（連携）
```

| 用語 | 一言で |
|------|--------|
| 責務 | 誰が何をするか |
| 関心 | 何について考えるか |
| 境界 | 内と外の線 |
| 抽象化 | 詳細を隠して本質だけ見せる |
| インターフェース | 外から見える契約 |
| 依存 | A が B を使う関係 |
| 凝集度 | まとまりの強さ（高いほどよい） |
| 結合度 | つながりの強さ（低いほどよい） |

詳細な用語集は [[010Programming/42_ソフトウェア設計/90_付録/付録A_用語集|付録A_用語集]] を参照してください。

---

## まとめ

- **責務** は担当する仕事、**関心** は目的の異なる領域
- **境界** と **抽象化** で変更の影響を抑える
- **インターフェース** と **実装** を分けると差し替えやすい
- **依存の方向** を意識する
