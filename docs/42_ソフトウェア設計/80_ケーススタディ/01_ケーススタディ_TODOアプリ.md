# ケーススタディ：TODO アプリの設計

## この章の目的

小規模な **TODO アプリ** を題材に、第1〜7部までの考え方を統合する演習です。

---

## 1. 要件の整理

### 機能要件

- タスクを追加・完了・削除できる
- タスク一覧を表示できる
- （任意）期限を設定できる

### 非機能要件

- 個人利用・小規模
- ブラウザで動作

### 用語

| 用語 | 意味 |
|------|------|
| タスク | やるべきこと 1 件 |
| 完了 | タスクを終了状態にする |

---

## 2. パラダイムと構造の選択

小規模 CRUD なので、**過剰設計は不要** です。

| 選択 | 理由 |
|------|------|
| 手続き的なユースケース流れ | 追加・完了・削除の流れが明確 |
| シンプルな OOP | Task をオブジェクトとして表現 |
| 関数型の要素 | フィルタ・ソートは純粋関数で |

```text
  DDD・イベント駆動は不要（1 コンテキスト・単純ドメイン）
```

---

## 3. モジュール候補の洗い出し

```text
  todo-app/
    ├── ui/          … 表示・入力（関心: プレゼンテーション）
    ├── application/ … ユースケースの流れ（追加・完了・削除）
    ├── domain/      … Task のルール
    └── storage/     … 永続化（localStorage 等）
```

**関心の分離** を意識した分割です。詳細は [[010Programming/43_モジュール設計/00_全体像/目次|モジュール設計 目次]] へつなげます。

---

## 4. クラス・関数の大まかな設計

```text
  Task（エンティティ）
    - id, title, completed, dueDate?
    - complete(), isOverdue()

  TaskRepository（インターフェース）
    - save(task), findAll(), delete(id)

  AddTaskUseCase / CompleteTaskUseCase（アプリケーション）
    - 手続き的なオーケストレーション
```

```javascript
// 純粋関数の例
function filterActive(tasks) {
  return tasks.filter(t => !t.completed);
}
```

---

## 5. 実装と振り返り

### 振り返りの問い

- [ ] UI に永続化の詳細が漏れていないか
- [ ] Task に完了ルールが閉じているか
- [ ] テストは Task と filterActive だけで書けるか
- [ ] モジュール間の依存方向は一方向か

### 改善の余地

- 期限機能を足すとき、Task に `isOverdue()` を置くか
- 複数ユーザーになったら、コンテキスト分割を検討

```text
  小規模でも「関心の分離」「高凝集・低結合」は練習になる
```
