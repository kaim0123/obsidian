# ケーススタディ：注文管理システム

## この章の目的

業務ルールがある **注文管理システム** で、DDD・パラダイム・イベントの考え方を統合します。

---

## 1. 業務ルールの整理とユビキタス言語

### 業務ルール（例）

- 注文は **確定** するとキャンセルできない（配送前まで）
- 確定時に **在庫を引当** する
- 合計金額は **明細の合計 − 割引**
- 5,000 円以上で **送料無料**

### ユビキタス言語

| 用語 | 意味 |
|------|------|
| 注文 | 顧客の購入依頼 |
| 明細 | 注文に含まれる商品 1 件 |
| 確定 | 注文を受け付け、在庫引当を行う |
| 引当 | 在庫を一時的に確保する |

---

## 2. コンテキストと集約の設計

```text
  ┌─────────────────┐         ┌─────────────────┐
  │ 注文コンテキスト   │         │ 在庫コンテキスト   │
  │ 用語: 注文・確定   │ ──────→ │ 用語: 引当・在庫数 │
  │ 集約: Order       │ イベント │ 集約: StockItem  │
  └─────────────────┘         └─────────────────┘
```

**Order 集約**（集約ルート）:

```text
  Order
    ├── OrderLine（明細）
    └── OrderLine
```

- 外部は `order.confirm()` 経由でのみ確定
- 在庫は Order 集約の外。イベントで連携

---

## 3. オブジェクトと関数の使い分け

| 置き場所 | 例 |
|---------|-----|
| エンティティ（OOP） | `Order.confirm()` — 状態遷移とルール |
| 値オブジェクト | `Money`, `Discount` — 不変の計算 |
| 純粋関数 | `calculateShipping(total)` — 送料ルール |
| アプリケーションサービス | `PlaceOrderUseCase` — 流れの制御 |

```javascript
// 値オブジェクト
class Money {
  constructor(amount) { this.amount = amount; }
  subtract(other) { return new Money(this.amount - other.amount); }
}

// エンティティ
class Order {
  confirm() {
    if (this.status !== 'draft') throw new Error('確定できません');
    this.status = 'confirmed';
    this.addDomainEvent(new OrderPlaced(this.id));
  }
}
```

---

## 4. ドメインイベントの設計

```text
  order.confirm()
       │
       └── OrderPlaced { orderId, lines, occurredAt }
                │
                ├──→ 在庫: StockReserved
                ├──→ 通知: 確認メール
                └──→ 分析: 売上記録
```

小規模モノリスなら **プロセス内イベント** から始め、成長したらメッセージングへ。

---

## 5. よくある設計ミスと修正

| ミス | 修正 |
|------|------|
| 確定ロジックが Controller に全部 | `Order.confirm()` に移す |
| 在庫を Order が直接更新 | OrderPlaced イベントで在庫コンテキストが反応 |
| 割引が SQL と画面に分散 | `Discount` 値オブジェクトに集約 |
| 貧血 Order（getter のみ） | 確定・キャンセルを Order のメソッドに |

```text
  業務の言葉 → 型とメソッド名 → 境界とイベント
```
