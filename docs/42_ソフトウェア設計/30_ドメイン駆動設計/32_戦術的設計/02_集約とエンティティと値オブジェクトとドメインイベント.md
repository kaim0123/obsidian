# 集約・エンティティ・値オブジェクト・ドメインイベント

## この教材の目的

ドメイン層を構成する**4つの基本部品**を、導入レベルで説明します。

- **エンティティ** … ID で識別される「もの」
- **値オブジェクト** … 値で意味が決まる「性質」
- **集約** … ルールを守るまとまりの単位
- **ドメインイベント** … 起きた「事実」の記録

[[03アーキテクチャに効く原則]] でも集約は不変条件の境界として触れています。ここでは DDD としての使い方を具体例付きで押さえます。

前提: [[02_DDDとは]]、[[06_ドメイン層とユースケースとアプリサービス]]

---

## 1. まず全体の関係

```
        ┌──────────────── 集約 ────────────────┐
        │                                      │
        │   Order（集約ルート・エンティティ）    │
        │      │                                 │
        │      ├── OrderLine（エンティティ）      │
        │      ├── Money（値オブジェクト）       │
        │      └── Address（値オブジェクト）     │
        │                                      │
        └──────────────────────────────────────┘
                         │
            状態が変わったとき
                         ▼
              OrderPlaced（ドメインイベント）
```

- **集約**は「まとめて一貫性を守る単位」
- その中に **エンティティ** と **値オブジェクト** が入る
- 重要な変化は **ドメインイベント** として表現する

---

## 2. エンティティ（Entity）

**エンティティ**は、**同一性（ID）** で識別されるオブジェクトです。

- 属性の値が同じでも、ID が違えば**別物**
- 時間とともに**状態が変わる**

```typescript
class Order {
  constructor(
    readonly id: OrderId,        // ← これで「どの注文か」が決まる
    private status: OrderStatus,
  ) {}

  ship() {
    if (this.status !== OrderStatus.Paid) {
      throw new Error('支払い前に発送できません');
    }
    this.status = OrderStatus.Shipped;
  }
}
```

### エンティティのポイント

| ポイント | 説明 |
|----------|------|
| ID がある | `OrderId`, `UserId` など、型で区別すると安全 |
| 振る舞いを持つ | `cancel()`, `ship()` のようにルールをメソッドに |
| ライフサイクルがある | 作成 → 変更 → （論理）削除 |

[[クリーンアーキテクチャの概要]] の **Entities** は、DDD では主にここ（ドメイン層のエンティティ・集約ルート）に対応します。

## 3. 値オブジェクト（Value Object）

**値オブジェクト**は、**属性の値の組み合わせ**で意味が決まり、**交換可能**なオブジェクトです。

- ID がない（または持たない）
- **不変（immutable）** にすることが多い
- 2つの値オブジェクトは、中身が同じなら**等しい**

```typescript
class Money {
  constructor(
    readonly amount: number,
    readonly currency: string,
  ) {
    if (amount < 0) throw new Error('金額は0以上');
    if (!currency) throw new Error('通貨は必須');
  }

  add(other: Money): Money {
    if (this.currency !== other.currency) {
      throw new Error('通貨が違います');
    }
    return new Money(this.amount + other.amount, this.currency);
  }
}
```

### 値オブジェクトに向いているもの

- 金額、住所、メールアドレス、日付範囲
- 「マイナスの金額はありえない」などの**小さな不変条件**
- どこにでもコピーして渡してよいデータ

### エンティティとの見分け方

| 質問 | エンティティ寄り | 値オブジェクト寄り |
|------|------------------|---------------------|
| 同じ内容でも別物になりうる？ | はい（別 ID） | いいえ（値が同じなら同じ） |
| 状態を変える？ | する | 変えず新しいインスタンスを作る |
| 例 | 注文、ユーザー | 金額、郵便番号 |

## 4. 集約（Aggregate）

**集約**は、**一貫性（不変条件）を守るためのまとまり**です。  
[[03アーキテクチャに効く原則]] にある「不変条件の境界」と同じ発想です。

### 集約ルート

集約には **1つだけ入り口** となる **集約ルート（Aggregate Root）** があります。

- 外からは **集約ルート経由だけ** で中身を変更する
- リポジトリが保存・読み込みするのも **集約ルート単位**

```
  外部 ──→ Order（集約ルート）──→ OrderLine
              │
              └── 合計金額・行数などの不変条件をここで守る
```

```typescript
class Order {  // 集約ルート
  private lines: OrderLine[] = [];

  addLine(productId: ProductId, quantity: number, unitPrice: Money) {
    if (quantity <= 0) throw new Error('数量は1以上');
    this.lines.push(new OrderLine(productId, quantity, unitPrice));
    // 合計が上限を超えないか、などもここで検証
  }

  total(): Money {
    return this.lines.reduce(
      (sum, line) => sum.add(line.subtotal()),
      Money.zero('JPY'),
    );
  }
}
```

### なぜ集約でまとめるのか

- **注文全体の合計**と**各行の小計**が矛盾しないようにする
- **同時更新**の単位をはっきりさせる（在庫と注文をいつ一緒にロックするか、など）
- トランザクションの境界の目安になる

### 集約設計の初心者向けルール

1. **小さく始める** — 最初から巨大な集約にしない
2. **参照は ID で** — 別集約のオブジェクトを直接持たず、`ProductId` のように ID のみ
3. **1トランザクションで変更する集約は1つ** が目安（厳密なルールではないが安全）

## 5. ドメインイベント（Domain Event）

**ドメインイベント**は、**ドメインの中で起きた、もう戻せない事実**を表すオブジェクトです。

- 過形（〜した）の名前: `OrderPlaced`, `PaymentCompleted`
- **いつ・誰の・何が** 起きたかの情報を持つ
- 集約の状態変更と一緒に発生する

```typescript
class OrderPlaced {
  constructor(
    readonly orderId: OrderId,
    readonly occurredAt: Date,
    readonly customerId: CustomerId,
    readonly total: Money,
  ) {}
}

class Order {
  private events: DomainEvent[] = [];

  confirm() {
    // ... 状態変更 ...
    this.events.push(
      new OrderPlaced(this.id, new Date(), this.customerId, this.total()),
    );
  }

  pullEvents(): DomainEvent[] {
    const e = [...this.events];
    this.events = [];
    return e;
  }
}
```

### ドメインイベントの用途（入門）

| 用途 | 例 |
|------|-----|
| 同じ BC 内の別処理を起こす | 注文確定 → 在庫引当 |
| 監査・履歴 | 「いつ誰が何をしたか」の記録 |
| 後から他システムへ連携 | メール送信、分析、別 BC への通知 |

**インフラの「メッセージキュー」と混同しない**こと。  
ドメインイベントはまず**ドメインの言葉での事実**であり、Kafka などはその**配信の仕組み**（インフラ）です。

---

## 6. 4つを使い分けるクイックガイド

| やりたいこと | 使うもの |
|--------------|----------|
| 「この注文」と「あの注文」を区別したい | エンティティ（ID） |
| 金額や住所にルールを持たせたい | 値オブジェクト |
| 注文と明細行を一緒に一貫させたい | 集約（集約ルート＋内部） |
| 「注文が確定した」という事実を残したい | ドメインイベント |

## 7. ミニ例 — EC の注文

```typescript
// 値オブジェクト
class OrderId {
  constructor(readonly value: string) {}
}

// 集約ルート（エンティティ）
class Order {
  private lines: OrderLine[] = [];
  private events: DomainEvent[] = [];

  static create(customerId: CustomerId): Order {
    return new Order(OrderId.generate(), customerId, OrderStatus.Draft);
  }

  addItem(productId: ProductId, qty: number, price: Money) {
    this.lines.push(new OrderLine(productId, qty, price));
  }

  place() {
    if (this.lines.length === 0) throw new Error('明細がありません');
    this.status = OrderStatus.Placed;
    this.events.push(new OrderPlaced(this.id, new Date(), this.total()));
  }

  total(): Money { /* ... */ }
}

// ユースケース側
class PlaceOrderUseCase {
  async execute(orderId: OrderId) {
    const order = await this.repo.findById(orderId);
    order.place();
    await this.repo.save(order);
  }
}
```

## 8. よくある誤解

| 誤解 | 実際 |
|------|------|
| 全部エンティティにする | 金額・住所は値オブジェクトの方が自然なことが多い |
| 集約は大きいほどよい | 小さく、必要性が出たら広げる |
| イベントは非同期のこと | まずはドメイン内の「起きた事実」。配信方法は別問題 |
| anemic な DTO ＋ 巨大サービスでよい | ルールはドメインオブジェクトと集約に寄せる |
