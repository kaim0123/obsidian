# リファクタリングの考え方

## はじめに

プログラムを書いていると、後から見直すと改善できる部分が見つかることがあります。**リファクタリング**とは、コードの動作を変えずに、コードの構造を改善することです。

この章では、リファクタリングの基本的な考え方を学びます。

## リファクタリングとは

**リファクタリング**とは、コードの動作を変えずに、コードの構造を改善することです。

### リファクタリングの目的

- **読みやすくする**：コードを理解しやすくする
- **保守しやすくする**：将来の変更を容易にする
- **バグを減らす**：コードの構造を改善してバグを減らす
- **パフォーマンスを改善する**：効率的なコードにする

### 重要な原則

**動作を変えない**：リファクタリングは、コードの動作を変えてはいけません。

## リファクタリングのタイミング

### 1. コードを書いた直後

コードを書いた直後に見直して、改善できる部分をリファクタリングします。

### 2. 機能を追加する前

新しい機能を追加する前に、既存のコードをリファクタリングして、追加しやすくします。

### 3. バグを修正した後

バグを修正した後、同じようなバグが起きないようにリファクタリングします。

### 4. コードレビューの後

コードレビューで指摘された点を改善するためにリファクタリングします。

## よくあるリファクタリングパターン

### 1. 関数の抽出（Extract Function）

長い関数を、小さな関数に分割します。

**リファクタリング前**：
```python
def process_order(order):
    # 注文の検証
    if not order:
        return False
    if order["total"] <= 0:
        return False
    
    # 在庫の確認
    for item in order["items"]:
        if item["stock"] < item["quantity"]:
            return False
    
    # 支払いの処理
    if order["payment_method"] == "credit":
        process_credit_payment(order)
    elif order["payment_method"] == "cash":
        process_cash_payment(order)
    
    return True
```

**リファクタリング後**：
```python
def validate_order(order):
    """注文を検証する"""
    if not order:
        return False
    if order["total"] <= 0:
        return False
    return True

def check_inventory(order):
    """在庫を確認する"""
    for item in order["items"]:
        if item["stock"] < item["quantity"]:
            return False
    return True

def process_payment(order):
    """支払いを処理する"""
    if order["payment_method"] == "credit":
        process_credit_payment(order)
    elif order["payment_method"] == "cash":
        process_cash_payment(order)

def process_order(order):
    """注文を処理する"""
    if not validate_order(order):
        return False
    
    if not check_inventory(order):
        return False
    
    process_payment(order)
    return True
```

### 2. 変数名の改善（Rename Variable）

変数名を、より明確な名前に変更します。

**リファクタリング前**：
```python
def calc(x, y):
    z = x * y * 1.1
    return z
```

**リファクタリング後**：
```python
def calculate_total_price(price, tax_rate):
    total = price * (1 + tax_rate)
    return total
```

### 3. マジックナンバーの削除（Replace Magic Number）

数値に意味を持たせます。

**リファクタリング前**：
```python
def is_adult(age):
    return age >= 18
```

**リファクタリング後**：
```python
ADULT_AGE = 18

def is_adult(age):
    return age >= ADULT_AGE
```

### 4. 重複コードの削除（Remove Duplication）

同じコードが複数箇所にある場合、関数にまとめます。

**リファクタリング前**：
```python
def process_user_a(user):
    if user["age"] >= 18:
        user["status"] = "adult"
    else:
        user["status"] = "minor"

def process_user_b(user):
    if user["age"] >= 18:
        user["status"] = "adult"
    else:
        user["status"] = "minor"
```

**リファクタリング後**：
```python
def set_user_status(user):
    user["status"] = "adult" if user["age"] >= 18 else "minor"

def process_user_a(user):
    set_user_status(user)

def process_user_b(user):
    set_user_status(user)
```

### 5. 早期リターン（Early Return）

ネストを減らすために、早期にリターンします。

**リファクタリング前**：
```python
def process_data(data):
    if data:
        if len(data) > 0:
            if all(isinstance(x, int) for x in data):
                return sum(data) / len(data)
            else:
                return None
        else:
            return None
    else:
        return None
```

**リファクタリング後**：
```python
def process_data(data):
    if not data:
        return None
    
    if len(data) == 0:
        return None
    
    if not all(isinstance(x, int) for x in data):
        return None
    
    return sum(data) / len(data)
```

## リファクタリングの手順

### 1. テストを書く（または確認する）

リファクタリング前の動作を確認するテストを書きます。

```python
def test_process_data():
    assert process_data([1, 2, 3]) == 2.0
    assert process_data([]) == None
    assert process_data(None) == None
```

### 2. 小さな変更を繰り返す

一度に大きな変更をするのではなく、小さな変更を繰り返します。

### 3. テストを実行する

変更のたびにテストを実行して、動作が変わっていないことを確認します。

### 4. コミットする

動作が確認できたら、変更をコミットします。

## 実践例

### 例：コードの改善

**リファクタリング前**：
```python
def calc(x, y, z):
    if x > 0:
        if y > 0:
            if z > 0:
                a = x * y
                b = a * z
                c = b / 2
                return c
            else:
                return 0
        else:
            return 0
    else:
        return 0
```

**リファクタリング後**：
```python
def calculate_volume(length, width, height):
    """
    直方体の体積を計算する
    
    Args:
        length: 長さ
        width: 幅
        height: 高さ
    
    Returns:
        体積（すべて正の値の場合）、それ以外は0
    """
    if not (length > 0 and width > 0 and height > 0):
        return 0
    
    volume = length * width * height
    return volume / 2
```

**改善点**：
- 変数名が明確になった
- 早期リターンでネストが減った
- ドキュメントが追加された
- ロジックが理解しやすくなった

## リファクタリングの注意点

### 1. 動作を変えない

リファクタリングは、コードの動作を変えてはいけません。

### 2. テストを書く

リファクタリング前の動作を確認するテストを書きます。

### 3. 小さく進める

一度に大きな変更をするのではなく、小さな変更を繰り返します。

### 4. バージョン管理を使う

Gitなどのバージョン管理システムを使い、変更を追跡します。

## まとめ

- リファクタリングは、コードの動作を変えずに構造を改善すること
- 関数の抽出、変数名の改善、重複コードの削除など、よくあるパターンがある
- テストを書いてからリファクタリングする
- 小さな変更を繰り返す
- 動作が変わっていないことを確認する

リファクタリングを習慣化すると、コードの品質が継続的に向上します。定期的に見直して改善しましょう！
