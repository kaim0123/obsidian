# 関数型指向の考え方

## この章の目的

**関数型** の考え方 — 純粋関数・副作用・不変性 — を設計の視点で学びます。  
専用言語がなくても、JavaScript・Python・Java 等で実践できます。

> 歴史的背景は [[00_ソフトウェア設計の変遷]] の「関数型指向」章を参照。

---

## 1. 関数型とは何か（第一級関数・純粋関数）

**関数型** とは、**関数を第一級オブジェクト** として扱い、**副作用を最小化** する設計を重視する考え方です。

| 概念 | 意味 |
|------|------|
| **第一級関数** | 関数を変数に代入・引数に渡す・戻り値にできる |
| **純粋関数** | 同じ入力 → 同じ出力。外部状態を変えない |

```javascript
// 純粋関数
function addTax(price, rate) {
  return price * (1 + rate);
}

// 非純粋（副作用あり）
let total = 0;
function addToTotal(price) {
  total += price;  // 外部の total を変更
}
```

---

## 2. 副作用（Side Effect）とその管理

**副作用** とは、関数が **戻り値以外に外部に影響を与える** ことです。

- グローバル変数の変更
- DB への書き込み
- コンソール出力・メール送信
- 引数のオブジェクトの変更

```text
  設計のコツ: 副作用を「境界」に押し出す

  [純粋な計算・変換]  … テストしやすい中心
         │
         ▼
  [I/O・DB・HTTP]     … 副作用の境界（アダプタ層）
```

すべてを純粋にする必要はありません。**副作用の場所を限定する** のが現実的です。

---

## 3. 不変性（Immutability）の設計的意味

**不変性** とは、データを **書き換えず、新しい値を作る** ことです。

```javascript
// 命令型: 元の配列を変更
items.push(newItem);

// 関数型: 新しい配列を返す
const newItems = [...items, newItem];
```

| メリット | 説明 |
|---------|------|
| 共有によるバグ防止 | 誰かが書き換えても元データは安全 |
| 推論しやすい | 「いつ何が変わったか」が明確 |
| 並行処理に有利 | ロックが不要になりやすい |

OOP の値オブジェクト（[[03_エンティティと値オブジェクト]]）とも相性がよいです。

---

## 4. データ変換パイプラインの読みやすさ

関数型では、データを **変換の連鎖** として表現します。

```javascript
const result = orders
  .filter(o => o.isActive)
  .map(o => o.total)
  .reduce((sum, t) => sum + t, 0);
```

- 各ステップが **小さな純粋関数**
- データの流れが **左から右に読める**
- 中間状態が **明示的**

メソッド設計の [[010Programming/46_メソッド設計/00_全体像/目次|メソッド設計 目次]] でも、関数分割の考え方として関連します。

---

## 5. 関数型の考え方が向く場面と限界

### 向く場面

- データの **検証・変換・集計**
- 並行・並列処理
- テスト容易性を重視する計算ロジック
- パイプライン型の処理

### 限界

- **状態を持つドメイン**（注文ステータスの遷移など）の表現が不自然になりうる
- I/O は結局副作用 — **境界の設計** が必要
- モナド等の抽象は学習コストが高い
- チームが命令型に慣れていると読みにくいことも

```text
  関数型は「全部関数で書く」ではなく、
  副作用を減らし、変換を読みやすくする「考え方」として使う
```

---

## まとめ

- 関数型は第一級関数と純粋関数を重視
- 副作用は境界に押し出し、中心は純粋に保つ
- 不変性で共有バグを防ぎ、推論しやすくする
- パイプラインでデータ変換を表現。向く場面と限界を知る
