## 詳しい要約

**テーマ：SQLのNULLが「気持ち悪い」のは、三値論理が数学の土台を壊しているから**

SQLは真・偽・不明（UNKNOWN）の三値論理で動いており、WHERE句は真の行しか通さないため、NULLを含む行は静かに消える。この気持ち悪さは排中律や反射律の崩壊として理論的に立証されたもので、NOT INやDBごとの方言など実務の事故につながる。欠損は現実の反映なので消せず、NOT NULLを基本にしてNULLの扱いを明示するのが落としどころ。

---

### 第1章 NULLの誕生：コッドと「知らない」の発明

- 1970年、IBMの **エドガー・F・コッド** がリレーショナルモデルの論文を発表（表だけでデータを扱う、今のRDBの土台）
- NULLが理論として本格的に登場するのは1979年の、欠けている情報の表し方に取り組んだ論文
- 例：新入社員の田中さんの電話番号をまだ聞いていない。0や空文字を入れると嘘のデータになり、集計にも混ざる → 「値がない」ことを示す印として **NULL** を導入
- 不明を含む比較の結果は「不明」とする、真でも偽でもない **第3の真理値**
- 三値論理自体は1920年、ポーランドの論理学者 **ウカシェヴィチ** が、未来の出来事のように今は真とも偽とも言えない命題を扱うために作った体系
- ポイント：NULLは手抜きではなく、「知らないことを知らないまま保存する」ための理論的装置

### 第2章 三値論理の仕組み：WHEREは真しか通さない

- SQLの条件式は **真・偽・不明** の3通りを返し、**WHERE句は真の行だけを通す**（偽も不明も捨てる）
- NULLと何かを比較すると結果は常に不明 → NULLを含む行は条件をどう書いても引っかからずに消える
- **NULL = NULL も不明**：知らない値同士が同じである保証はないため
- **否定しても不明のまま**：条件を否定形に書き直してもNULLの行は出てこない
- 集計関数（合計・平均など）はNULLを黙って無視する。`COUNT(*)` と `COUNT(列)` で件数が食い違うのも同じ理由
- ポイント：「条件は三値で評価される」「WHEREは真しか通さない」の2原則

### 第3章 数学者が怒る理由：排中律の崩壊

- 古典論理の **排中律**（どんな命題も「AまたはAでない」は必ず真）が壊れる
  - 例：給料がNULLの社員は「給料が100万以上 OR 100万以上でない」と書いても結果に現れない
- **反射律**（どんな値も自分自身と等しい）もNULLでは成り立たない
- **クリス・デイトとヒュー・ダーウェン** は「NULLはリレーショナルモデルを根底から破壊する」と批判し、NULLを使わないDB理論を提唱
- コッド自身も1990年の著書で、NULLを「まだ知らない」と「そもそも該当しない」（例：独身社員の配偶者名）の2種類に分ける **四値論理** を主張したが、どのDBも採用しなかった
- ポイント：NULLの気持ち悪さは気のせいではなく、数学の土台を壊している理論的に立証済みのもの

### 第4章 実務の事故簿：NOT INとDB方言

| 事故 | 内容 |
|---|---|
| **NOT INの穴** | 「この一覧に含まれない」条件で、一覧側にNULLが1つでも混ざると結果が0件になる |
| **ユニーク制約** | NULL同士は等しくないため、PostgreSQLやMySQLではユニーク制約の列にNULLを何行でも入れられるが、SQL Serverは1行しか許さない（標準の曖昧さを各社が別々に解釈） |
| **Oracleの空文字** | 長さ0の文字列をNULLとして扱う。移植のたびにエンジニアを苦しめる方言 |
| **外部結合** | 結合相手がいない行には、入れた覚えのないNULLが自動で生まれる |

- ポイント：理論のほころびがそのまま実務に漏れ出し、DBごとの方言で被害が倍増している

### 第5章 10億ドルの過ちとSQLに残ったNULL

- 1965年、英国の計算機科学者 **トニー・ホーア** がALGOL WにNULL参照を実装。2009年の講演で「**10億ドルの過ち**」と謝罪
- モダン言語はNULL安全へ：Kotlin・SwiftはNULLになり得る型を明示させ、RustはNULL参照そのものを言語から消した
- ただしSQLのNULLは事情が違う：言語のNULLは「参照先がない」という実装の都合、SQLのNULLは「情報が欠けている」という現実の反映で、欠損は型では消せない
- 実務の落としどころ：
  1. 設計では **NOT NULL制約を基本** にし、NULLを許す列を例外扱いにする
  2. クエリではNULLかどうかを専用の構文で必ず明示する。NULL同士を等しいとみなして比較できる構文も1999年からSQL標準に用意されている

### まとめ

- SQLは三値論理で動き、WHEREは真しか通さないため、NULLを含む行は静かに消える
- NULLは排中律・反射律を壊しており、理論家（デイト、ダーウェン、コッド自身）からも批判されてきた
- NOT IN、ユニーク制約、Oracleの空文字、外部結合など、実務の事故とDB方言に注意
- 欠損は現実の反映で消せないので、NOT NULLを基本にし、NULLの扱いをクエリで明示する
