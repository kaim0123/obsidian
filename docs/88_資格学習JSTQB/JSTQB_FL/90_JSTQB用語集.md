# JSTQB FL 重要用語集

試験で頻出の用語をアルファベット・五十音順に整理しています。

---

## あ行

| 用語 | 英語 | 意味 |
|------|------|------|
| アルファテスト | Alpha Testing | 開発元のサイトでユーザーが行うテスト |
| インスペクション | Inspection | 最も形式的なレビュー。モデレータが進行 |
| ウォークスルー | Walkthrough | 作成者が主導するレビュー |
| エラー | Error | 人間の間違い。欠陥の原因 |
| エラー推測 | Error Guessing | 経験に基づいてバグが潜む箇所を推測する技法 |

## か行

| 用語 | 英語 | 意味 |
|------|------|------|
| 回帰テスト | Regression Testing | 変更による副作用がないか確認するテスト |
| 確認テスト | Confirmation Testing | 修正した欠陥が本当に直ったか確認するテスト |
| 確認バイアス | Confirmation Bias | 自分の期待に合う情報ばかり注目する認知的偏り |
| 境界値分析 | Boundary Value Analysis | 同値パーティションの境界値でテストする技法 |
| 欠陥 | Defect / Bug / Fault | コードやドキュメントの誤り |
| 結合テスト | Integration Testing | モジュール間の連携を確認するテスト |
| 故障 | Failure | システムが期待通りに動作しないこと |
| 構成管理 | Configuration Management | 成果物のバージョンや変更を管理すること |
| 根本原因 | Root Cause | 問題の最も根本的な原因 |

## さ行

| 用語 | 英語 | 意味 |
|------|------|------|
| 殺虫剤のパラドックス | Pesticide Paradox | 同じテストを繰り返すと新しい欠陥が見つからなくなること |
| 重大度 | Severity | 欠陥がシステムに与える影響の大きさ |
| 受入テスト | Acceptance Testing | ユーザーが受け入れ可能か判断するテスト |
| 状態遷移テスト | State Transition Testing | 状態と遷移に基づくテスト技法 |
| 静的テスト | Static Testing | ソフトウェアを実行せずに行う検証 |
| 静的解析 | Static Analysis | ツールによるコードの自動分析 |
| スタブ | Stub | テスト対象が呼び出す下位モジュールの代替 |

## た行

| 用語 | 英語 | 意味 |
|------|------|------|
| 探索的テスト | Exploratory Testing | テスト設計と実行を同時に行うテスト |
| 単体テスト | Component / Unit Testing | 個々のモジュールのテスト |
| デシジョンカバレッジ | Decision Coverage | 全判定のtrue/falseを網羅する基準（C1） |
| デシジョンテーブル | Decision Table | 条件の組み合わせとアクションの表 |
| テストベース | Test Basis | テスト設計の根拠となる資料 |
| テストケース | Test Case | テスト条件・入力値・期待結果のセット |
| テストオラクル | Test Oracle | 期待結果を導き出す情報源 |
| ドライバ | Driver | テスト対象を呼び出す上位モジュールの代替 |
| 動的テスト | Dynamic Testing | ソフトウェアを実行して行うテスト |

## は行

| 用語 | 英語 | 意味 |
|------|------|------|
| ベータテスト | Beta Testing | ユーザーのサイトでユーザーが行うテスト |
| 非機能テスト | Non-functional Testing | 性能・セキュリティ等の品質特性のテスト |

## ま行

| 用語 | 英語 | 意味 |
|------|------|------|
| モデレータ | Moderator / Facilitator | レビュー会議の進行役。最重要な役割 |

## や行

| 用語 | 英語 | 意味 |
|------|------|------|
| 優先度 | Priority | 欠陥を修正する緊急度 |

## ら行

| 用語 | 英語 | 意味 |
|------|------|------|
| リスクベースドテスト | Risk-based Testing | リスクの高い部分を優先的にテストするアプローチ |

## わ行・その他

| 用語 | 英語 | 意味 |
|------|------|------|
| V字モデル | V-model | 開発工程とテスト工程を対応させた開発モデル |

---

## 紛らわしい用語の対比

| 対比 | 用語A | 用語B |
|------|-------|-------|
| 人のミス vs コードの誤り | エラー（人間のミス） | 欠陥（コードのバグ） |
| バグ発見 vs バグ修正 | テスト（発見する） | デバッグ（修正する） |
| 修正確認 vs 影響確認 | 確認テスト（直ったか確認） | 回帰テスト（他に影響ないか確認） |
| 影響の大きさ vs 修正の急ぎ | 重大度（技術的影響） | 優先度（ビジネス的緊急度） |
| 作成者主導 vs 進行役主導 | ウォークスルー（作成者） | インスペクション（モデレータ） |
| 上位の代役 vs 下位の代役 | ドライバ（上位） | スタブ（下位） |
| 命令網羅 vs 判定網羅 | ステートメントカバレッジ（C0） | デシジョンカバレッジ（C1） |
| 開発元でテスト vs ユーザー元でテスト | アルファテスト（開発元） | ベータテスト（ユーザー元） |
