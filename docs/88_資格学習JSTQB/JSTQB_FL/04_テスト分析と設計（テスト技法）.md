### 4.2 ブラックボックステスト技法

#### 同値分割法（Equivalence Partitioning）
- 入力データを**同じ振る舞いをするグループ（同値クラス）**に分割する
- 各同値クラスから**1つの代表値**をテストすれば十分
- **有効同値クラス**（正常系）と**無効同値クラス**（異常系）がある

##### 例: 年齢入力（1〜120が有効）
| 同値クラス | 範囲 | 有効/無効 | 代表値 |
|-----------|------|----------|--------|
| クラス1 | 0以下 | 無効 | -5 |
| クラス2 | 1〜120 | 有効 | 50 |
| クラス3 | 121以上 | 無効 | 200 |

**最小テストケース数 = 同値クラスの数 = 3**

---

#### 境界値分析（Boundary Value Analysis）
- 同値クラスの**境界にある値**でテストする
- 欠陥は境界付近に集中する傾向がある
- 2値境界値テスト: 各境界につき**2つの値**（境界値とその隣）
- 3値境界値テスト: 各境界につき**3つの値**（境界値とその前後）

##### 例: 年齢入力（1〜120が有効）- 2値の場合
| 境界 | テスト値 |
|------|---------|
| 下限の境界 | 0, 1 |
| 上限の境界 | 120, 121 |

**2値境界値テストのテストケース数 = 4**（0, 1, 120, 121）

##### 3値の場合
| 境界 | テスト値 |
|------|---------|
| 下限の境界 | 0, 1, 2 |
| 上限の境界 | 119, 120, 121 |

**3値境界値テストのテストケース数 = 6**（0, 1, 2, 119, 120, 121）

---

#### デシジョンテーブルテスト（Decision Table Testing）
- 複数の条件の**組み合わせ**に対する動作を表形式で整理する
- 条件の組み合わせを漏れなく網羅できる

##### 例: 会員割引の適用
| | ルール1 | ルール2 | ルール3 | ルール4 |
|---|---|---|---|---|
| **条件** | | | | |
| 会員である | Y | Y | N | N |
| 購入額5000円以上 | Y | N | Y | N |
| **アクション** | | | | |
| 10%割引 | X | - | - | - |
| 5%割引 | - | X | - | - |
| 割引なし | - | - | X | X |

**テストケース数 = ルール数（列数）**

---

#### 状態遷移テスト（State Transition Testing）
- システムの**状態（state）**と**イベント**による遷移をテストする
- **状態遷移図**: 状態、遷移、イベント、アクションを図示
- **状態遷移表**: すべての状態×イベントの組み合わせを表で整理

##### 例: ログインシステム
```
[ロック解除] --正しいPW--> [ログイン済み]
[ロック解除] --誤ったPW(1回目)--> [1回失敗]
[1回失敗]   --誤ったPW(2回目)--> [2回失敗]
[2回失敗]   --誤ったPW(3回目)--> [アカウントロック]
```

- **0スイッチカバレッジ**: すべての有効な遷移を1回はテストする
- **1スイッチカバレッジ**: 連続する2つの遷移の組み合わせをテストする

---

### 4.3 ホワイトボックステスト技法

#### ステートメントテスト（Statement Testing）
- コードの各**文（ステートメント）**が少なくとも1回実行されるようにテストする
- **ステートメントカバレッジ** = 実行された文の数 / 全文の数 × 100%

#### ブランチテスト（Branch Testing / Decision Testing）
- コードの各**分岐（ブランチ）**を少なくとも1回は通るようにテストする
- if文のtrue/false両方を通る
- **ブランチカバレッジ** = 実行されたブランチ数 / 全ブランチ数 × 100%
- **100%ブランチカバレッジは100%ステートメントカバレッジを包含する**（逆は成り立たない）

##### カバレッジの計算例
```python
def check(x, y):         #
    if x > 0:            # 分岐A
        print("正")      # S1
    if y > 0:            # 分岐B
        print("陽")      # S2
    print("完了")         # S3
```

- テストケース1: x=1, y=1 → S1, S2, S3 実行、分岐A=True, B=True
- テストケース2: x=-1, y=-1 → S3のみ実行、分岐A=False, B=False
- この2ケースで**ステートメントカバレッジ100%、ブランチカバレッジ100%**

---

### 4.4 経験ベースのテスト技法

#### エラー推測（Error Guessing）
- テスト担当者の**経験・知識・直感**に基づいて欠陥が潜みそうな箇所を推測
- 過去の欠陥データ、一般的な間違いのリストを活用
- 例: ゼロ除算、null入力、空文字列、最大値超え

#### 探索的テスト（Exploratory Testing）
- テスト設計・実行・学習を**同時に**行うアプローチ
- **セッションベーステスト**: タイムボックス（例: 90分）を設けて集中的に実施
- **チャーター（テスト指針）**: 探索の方向性を示すガイド
- 形式的なテストケースを事前に作成しない
- 経験豊富なテスト担当者に特に有効

### 4.1 テスト技法の分類

テスト技法は大きく3つに分類されます。

```
テスト技法
├── ブラックボックス技法 ← 仕様に基づく（中身を見ない）
├── ホワイトボックス技法 ← 構造に基づく（中身を見る）
└── 経験ベースの技法   ← テスト担当者の経験に基づく
```

| 分類 | 別名 | 基づくもの |
|------|------|-----------|
| **ブラックボックス** | 仕様ベース | 仕様書・要件定義書 |
| **ホワイトボックス** | 構造ベース | ソースコード・内部構造 |
| **経験ベース** | — | テスト担当者の知識・経験 |

```
ブラックボックス: 箱の中身を見ないで、入力と出力だけで判断
  [入力] → [■■■] → [出力]

ホワイトボックス: 箱の中身を見て、内部のロジックをテスト
  [入力] → [if → else → for] → [出力]
```

### 4.2 ブラックボックステスト技法

#### 4.2.1 同値分割法（Equivalence Partitioning）

入力値を「**同じ結果になるグループ（同値クラス / 同値パーティション）**」に分けて、各グループから**代表値を1つ**選んでテストする技法です。

##### 基本的な考え方

```
仕様: 年齢が18歳以上なら「成人」、18歳未満なら「未成年」と表示

同値パーティション:
  有効同値クラス① : 18以上（例: 25）→「成人」
  有効同値クラス② : 0〜17  （例: 10）→「未成年」
  無効同値クラス① : 負の数  （例: -5）→ エラー
```

| 用語 | 意味 |
|------|------|
| **有効同値クラス** | 仕様で受け入れられる入力のグループ |
| **無効同値クラス** | 仕様で受け入れられない入力のグループ |

##### 具体例：割引率の計算

```
仕様:
  購入金額 1〜999円     → 割引なし
  購入金額 1000〜4999円 → 5%割引
  購入金額 5000円以上   → 10%割引
  購入金額 0円以下      → エラー

同値パーティション:
  無効: 0以下    → 代表値: -100 → エラー
  有効: 1〜999   → 代表値: 500  → 割引なし
  有効: 1000〜4999 → 代表値: 3000 → 5%割引
  有効: 5000以上  → 代表値: 8000 → 10%割引

必要なテストケース数: 4つ（各パーティションから1つ）
```

> **ポイント**: 同値パーティション内のどの値を選んでも同じ結果になるはずなので、代表値を1つ選べばよい。

---

#### 4.2.2 境界値分析（Boundary Value Analysis）

同値パーティションの**境界（端の値）**に注目してテストする技法です。バグは境界付近に集中しやすいためです。

##### 基本的な考え方

```
仕様: 18歳以上なら成人

境界値:
  17 → 未成年（境界のすぐ内側）
  18 → 成人  （境界値そのもの）

  ※ 2値の境界値分析（最小限のテスト）
```

##### 2値と3値の境界値分析

| 方式 | テストする値 | 例（境界が18） |
|------|-------------|---------------|
| **2値** | 境界値とその隣 | 17, 18 |
| **3値** | 境界値とその両隣 | 17, 18, 19 |

##### 具体例：割引率の計算

```
仕様:
  1〜999円     → 割引なし
  1000〜4999円 → 5%割引
  5000円以上   → 10%割引

境界値（2値の場合）:
  0, 1      ← 無効/有効の境界
  999, 1000 ← 割引なし/5%の境界
  4999, 5000 ← 5%/10%の境界

テストケース: 0, 1, 999, 1000, 4999, 5000 の6つ
```

> **同値分割と境界値分析の関係**: 同値分割で「どのグループがあるか」を把握し、境界値分析で「境界付近を重点的にテスト」します。セットで使うことが多いです。

---

#### 4.2.3 デシジョンテーブルテスト（Decision Table Testing）

複数の条件の**組み合わせ**とそれに対する**動作（アクション）**を表にまとめてテストする技法です。

##### 基本的な考え方

```
仕様:
  - 会員で、かつ購入金額3000円以上 → 送料無料
  - 会員で、かつ購入金額3000円未満 → 送料300円
  - 非会員 → 購入金額に関係なく送料500円
```

##### デシジョンテーブル

| | ルール1 | ルール2 | ルール3 | ルール4 |
|--|---------|---------|---------|---------|
| **条件** | | | | |
| 会員か？ | Y | Y | N | N |
| 3000円以上か？ | Y | N | Y | N |
| **アクション** | | | | |
| 送料無料 | X | | | |
| 送料300円 | | X | | |
| 送料500円 | | | X | X |

ルール3とルール4はアクションが同じなので、**統合（集約）**できます：

| | ルール1 | ルール2 | ルール3 |
|--|---------|---------|---------|
| 会員か？ | Y | Y | N |
| 3000円以上か？ | Y | N | —（どちらでも同じ） |
| 送料無料 | X | | |
| 送料300円 | | X | |
| 送料500円 | | | X |

> **ポイント**: 条件がN個ある場合、最大 **2のN乗** のルールが存在します。ただし、結果が同じルールは統合できます。

##### もう一つの例：ログイン判定

```
条件:
  C1: ユーザーIDが正しいか？
  C2: パスワードが正しいか？
  C3: アカウントがロックされていないか？
```

| | R1 | R2 | R3 | R4 | R5 | R6 | R7 | R8 |
|--|----|----|----|----|----|----|----|----|
| C1: ID正しい | Y | Y | Y | Y | N | N | N | N |
| C2: PW正しい | Y | Y | N | N | Y | Y | N | N |
| C3: ロックなし | Y | N | Y | N | Y | N | Y | N |
| ログイン成功 | X | | | | | | | |
| ロック中エラー | | X | | X | | X | | X |
| 認証エラー | | | X | | X | | X | |

---

#### 4.2.4 状態遷移テスト（State Transition Testing）

システムの**状態**と、イベントによる**状態の変化（遷移）**に着目してテストする技法です。

##### 状態遷移図

```
仕様: 簡易ログインシステム
  - 初期状態: ログアウト状態
  - 正しい認証情報 → ログイン状態
  - ログアウト操作 → ログアウト状態
  - 3回連続で認証失敗 → アカウントロック状態
```

```
                  正しい認証情報
  [ログアウト] ──────────────────→ [ログイン]
       ↑                              │
       │        ログアウト操作         │
       └──────────────────────────────┘

       │ 認証失敗3回
       ↓
  [アカウントロック]
```

##### 状態遷移表

状態遷移を表形式で整理したものです。

| 現在の状態 | イベント | 次の状態 |
|-----------|---------|---------|
| ログアウト | 正しい認証 | ログイン |
| ログアウト | 認証失敗（1〜2回目） | ログアウト |
| ログアウト | 認証失敗（3回目） | アカウントロック |
| ログイン | ログアウト操作 | ログアウト |
| アカウントロック | 管理者が解除 | ログアウト |

> **テストのポイント**:
> - **有効な遷移**をすべてテストする（正常系）
> - **無効な遷移**もテストする（異常系：その状態では発生しないはずのイベント）

### 4.3 ホワイトボックステスト技法

コードの内部構造に基づいてテストケースを設計します。

#### 4.3.1 ステートメントカバレッジ（命令網羅 / C0）

コード中の**すべてのステートメント（命令文）**を少なくとも1回実行することを目指します。

```python
def check(x, y):        # 行1
    if x > 0:            # 行2
        print("正の数")  # 行3
    if y > 0:            # 行4
        print("yも正")   # 行5
    print("終了")        # 行6
```

**ステートメントカバレッジ100%を達成するテストケース：**

```
テストケース: x=1, y=1
  行1 ✓ → 行2 ✓（true）→ 行3 ✓ → 行4 ✓（true）→ 行5 ✓ → 行6 ✓
  → 全ステートメントを実行 → カバレッジ100%

最小テストケース数: 1つ
```

##### カバレッジの計算式

```
ステートメントカバレッジ = 実行されたステートメント数 / 全ステートメント数 × 100%
```

#### 4.3.2 デシジョンカバレッジ（判定条件網羅 / ブランチカバレッジ / C1）

すべての**判定（分岐）**の **true と false の両方**を少なくとも1回実行することを目指します。

```python
def check(x, y):        # 行1
    if x > 0:            # 行2: 判定①
        print("正の数")  # 行3
    if y > 0:            # 行4: 判定②
        print("yも正")   # 行5
    print("終了")        # 行6
```

**デシジョンカバレッジ100%を達成するテストケース：**

```
テストケース1: x=1, y=1
  判定① true ✓、判定② true ✓

テストケース2: x=-1, y=-1
  判定① false ✓、判定② false ✓

→ すべての判定のtrue/falseを網羅 → カバレッジ100%

最小テストケース数: 2つ
```

##### カバレッジの計算式

```
デシジョンカバレッジ = 実行された判定結果数 / 全判定結果数 × 100%
```

#### 2つのカバレッジの関係

```
デシジョンカバレッジ100% → ステートメントカバレッジ100%（必ず成り立つ）
ステートメントカバレッジ100% → デシジョンカバレッジ100%（成り立たない場合がある）
```

**デシジョンカバレッジの方が厳しい基準**です。

##### なぜステートメント100%でもデシジョン100%にならないのか

```python
def check(x):
    if x > 0:           # 判定
        print("正の数")
    print("終了")
```

```
テスト: x=1 → if文がtrue → 「正の数」「終了」が実行される
→ ステートメントカバレッジ: 100%（全行を実行した）
→ デシジョンカバレッジ: 50%（trueだけ。falseの分岐を通っていない）
```

### 4.4 経験ベースのテスト技法

テスト担当者の**知識や経験**に基づいてテストケースを設計する技法です。

#### 4.4.1 エラー推測（Error Guessing）

テスト担当者の**経験に基づいて**、バグが発生しやすい箇所を推測してテストします。

```
よくあるバグのパターン:
  - ゼロで割り算する
  - 空文字列を入力する
  - nullを渡す
  - 上限値を超える入力
  - 日付の境界（月末、うるう年）
  - 全角/半角の混在
```

#### 4.4.2 探索的テスト（Exploratory Testing）

**テスト設計と実行を同時に**行うテスト手法です。事前にテストケースを作り込まず、テストしながら学び、次のテストを考えます。

```
従来のテスト:
  設計（テストケース作成）→ 実行 → 結果記録

探索的テスト:
  テスト実行しながら → 気づきを得て → 次のテストを決める → 実行...
```

##### チャーターベースのテスト

探索的テストを構造化するために、**チャーター（テストの方向性）**を決めてテストします。

```
チャーター例:
  「ログイン機能に対して、不正な入力パターンで30分間テストする」
```

##### タイムボックス

探索的テストは**時間を区切って**（タイムボックス）実施します。通常60〜120分程度のセッションで行います。

#### 4.4.3 チェックリストベースドテスト

過去の経験や一般的な品質チェック項目をまとめた**チェックリスト**に基づいてテストします。

```
チェックリスト例（入力フォーム）:
  □ 必須項目が空の場合にエラーが出るか
  □ 最大文字数を超えた場合にエラーが出るか
  □ 特殊文字（<, >, &, "）を入力した場合の動作
  □ 数値項目に文字を入力した場合の動作
  □ コピー&ペーストでの入力は正しく処理されるか
```

### 4.5 テスト技法の選択

どの技法を使うかは状況に応じて判断します。

| 状況 | 適した技法 |
|------|-----------|
| 仕様に範囲が明確に定義されている | 同値分割、境界値分析 |
| 複数条件の組み合わせがある | デシジョンテーブル |
| 状態の変化がある | 状態遷移テスト |
| コードのカバレッジを確認したい | ステートメント/デシジョンカバレッジ |
| 仕様が不十分、時間が限られている | 探索的テスト、エラー推測 |
