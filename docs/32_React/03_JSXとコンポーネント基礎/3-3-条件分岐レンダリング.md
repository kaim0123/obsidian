# 3-3. 条件分岐レンダリング（&& / 三項 / ガード節）

## 🎯 この章で学ぶこと

- 「ある条件のときだけ表示」する書き方
- `&&` と三項演算子の使い分け
- 早期return（ガード節）でスッキリ書く方法

---

## 📖 概念の説明

### 条件分岐レンダリングとは

**stateやpropsの値によって、画面に出す内容を変える**こと。

例：

- ログイン中なら「こんにちは、太郎さん」、未ログインなら「ログインしてください」
- ローディング中なら「読み込み中...」、終わったらデータを表示
- エラーがあるなら赤い枠、無いなら通常の枠

### 主な書き方は3つ

1. `&&` 演算子（「あるときだけ表示」）
2. 三項演算子 `? :`（A or B）
3. 早期return（ガード節）

---

## 💻 ① `&&` 演算子（あるときだけ表示）

### 基本

```jsx
{ isAdmin && <button>管理者メニュー</button> }
```

- `isAdmin` が `true` → ボタンが表示
- `isAdmin` が `false` → 何も表示されない

### 仕組み

JavaScriptの `&&` は「左がtruthyなら右を返す、falsyなら左を返す」。Reactは `false`、`null`、`undefined` を**何も描画しません**。

### 例：エラーメッセージ

```jsx
function LoginForm({ error }) {
  return (
    <form>
      <input type="email" />
      <input type="password" />
      {error && <p style={{ color: 'red' }}>{error}</p>}
      <button>ログイン</button>
    </form>
  );
}
```

errorが空文字や `null` ならメッセージは出ない、文字列があれば赤字で出る。

---

## ⚠️ `&&` の落とし穴：「0」の罠

```jsx
const count = 0;
return <div>{count && <p>カート: {count}件</p>}</div>;
// → 画面に「0」と表示される！
```

`0` は `falsy` なのでメッセージは出ないが、**`0`自体が描画される**。Reactは `false`/`null`/`undefined` は描画しないが、`0` は描画する。

### 対処：明示的に比較

```jsx
{count > 0 && <p>カート: {count}件</p>}
{Boolean(count) && <p>...</p>}
```

---

## 💻 ② 三項演算子（A or B）

### 基本

```jsx
{ isLogin ? <p>こんにちは</p> : <p>ログインしてください</p> }
```

`isLogin` が `true` なら左、`false` なら右。

### 例：ログイン状態の切り替え

```jsx
function Header({ user }) {
  return (
    <header>
      {user
        ? <span>こんにちは、{user.name}さん</span>
        : <a href="/login">ログイン</a>
      }
    </header>
  );
}
```

### ネストすると読みにくくなる

```jsx
// ❌ ネスト三項：読めない
{ status === 'loading'
  ? <Spinner />
  : status === 'error'
  ? <Error />
  : <Content />
}

// ✅ 早期returnで分ける
if (status === 'loading') return <Spinner />;
if (status === 'error') return <Error />;
return <Content />;
```

---

## 💻 if 文を「関数に閉じ込める」（JSX の外）

JSX の `{ }` には `if` 文は書けないが、**関数を呼んで戻り値を置く**なら使える（旧 `08-conditional` 章より）。

```jsx
function App() {
  const user = { name: '田中太郎', age: 25 };

  const renderUserInfo = () => {
    if (user.age >= 20) {
      return <p>{user.name}さんは成人です</p>;
    }
    return <p>{user.name}さんは未成年です</p>;
  };

  return <div>{renderUserInfo()}</div>;
}
```

複雑なら **早期 return** や **別コンポーネント**のほうが読みやすいことが多い。

---

## 💻 条件付き className / style

```jsx
const isActive = true;
const isError = true;

<button className={isActive ? 'active' : 'inactive'}>ボタン</button>

<p style={{ color: isError ? 'red' : 'green', fontWeight: 'bold' }}>
  {isError ? 'エラーが発生しました' : '正常に処理されました'}
</p>
```

---

## 💻 三項演算子の各枝は「1要素」

三項の true / false 側で **兄弟要素が2つ** だとエラーになる。`<>...</>` か `<div>` で包む（旧 `08-conditional` 章より）。

```jsx
// ❌ 各枝で兄弟が2つ
{isLoggedIn ? (
  <h1>ようこそ！</h1>
  <p>ログイン中です</p>
) : (
  <h1>ログインしてください</h1>
)}

// ✅ Fragment や div で包む
{isLoggedIn ? (
  <>
    <h1>ようこそ！</h1>
    <p>ログイン中です</p>
  </>
) : (
  <h1>ログインしてください</h1>
)}
```

---

## 💻 ③ 早期return（ガード節）

### 基本

「**異常なケースを先に弾いて、正常系だけ書く**」というスタイル。

```jsx
function User({ user }) {
  if (!user) return <p>ユーザーが見つかりません</p>;
  if (user.banned) return <p>このアカウントは停止中です</p>;

  // 正常系だけが続く
  return (
    <div>
      <h1>{user.name}</h1>
      <p>{user.bio}</p>
    </div>
  );
}
```

### 利点

- ネストが深くならない
- 「**この条件のときは終わり**」が明確
- 正常系のコードに集中できる

---

## 💻 使い分けの目安

| 状況 | 推奨 |
| --- | --- |
| 「あるときだけ表示」（else不要） | `&&` |
| 「Aか、Bか」 | 三項演算子 |
| 「異常なら早く抜ける」 | 早期return |
| 「3パターン以上」 | 早期return か switch |

### 3パターン以上：オブジェクトを使うパターン

```jsx
function StatusBadge({ status }) {
  const messages = {
    pending: '保留中',
    approved: '承認済み',
    rejected: '却下',
  };
  return <span>{messages[status] ?? '不明'}</span>;
}
```

---

## ❌ よくある間違い

### `&&` で 0 が出てしまう

```jsx
{messages.length && <List />}
// → 0 が画面に
```

→ ✅ `{messages.length > 0 && <List />}`

### 三項演算子で書き直す→巨大なJSX

```jsx
// ❌ 巨大すぎて読めない
{ status === 'a' ? (
   <div>A...100行</div>
) : (
   <div>B...100行</div>
)}
```

→ ✅ 別コンポーネントに切り出す。

### if文をJSXの中に書こうとする

```jsx
// ❌ JSXの中身は「式」
return (
  <div>
    {if (a) 'A'} // ダメ
  </div>
);
```

→ ✅ 三項 or 関数で囲む or 早期return。

---

## ✅ ベストプラクティス

1. **「あるときだけ」は `&&`**、ただし0に注意
2. **「AかBか」は三項**、ネストはしない
3. **「異常」は早期return**で先に弾く
4. **巨大なJSX**になったらコンポーネント切り出し
5. **明示的な比較**（`length > 0`）を癖に

---

## 🔬 実践演習

```jsx
function ItemList({ items, isLoading, error }) {
  // 以下を書く
  // - isLoading なら「読み込み中...」
  // - error なら赤字でエラー
  // - items が空なら「アイテムがありません」
  // - 通常はul + liで一覧
}
```

---

## 📝 まとめ

- `&&` = あるときだけ。0に注意
- 三項 = AかBか。ネスト禁止
- 早期return = 異常を先に弾く
- 3パターン以上は switch かオブジェクト
