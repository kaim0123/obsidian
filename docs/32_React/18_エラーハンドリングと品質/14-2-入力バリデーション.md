# 14-2. 入力バリデーション（クライアント/サーバー）

## 🎯 この章で学ぶこと

- クライアントとサーバーのバリデーションの役割分担
- zod でスキーマ検証
- ユーザーフレンドリーなエラー表示

---

## 📖 二重チェックの原則

「**サーバー側は必須、クライアント側は補助**」。

| | クライアント | サーバー |
| --- | --- | --- |
| 役割 | UX向上、即時フィードバック | データの整合性・セキュリティ |
| 不要？ | あればなお良い | 絶対必要 |

→ クライアントだけだと**改ざんで突破される**ので、サーバーで必ずチェック。

---

## 💻 zod スキーマ

クライアントとサーバーで同じ定義を使えるのがzodの強み：

```ts
// shared/schemas.ts
import { z } from 'zod';

export const userSchema = z.object({
  name: z.string()
    .min(1, '名前は必須です')
    .max(20, '20文字以内で入力してください'),
  email: z.string()
    .email('メール形式が違います'),
  password: z.string()
    .min(8, '8文字以上で入力してください')
    .regex(/[A-Z]/, '大文字を含めてください')
    .regex(/[0-9]/, '数字を含めてください'),
  age: z.number()
    .int('整数で入力してください')
    .min(0, '0以上')
    .max(150, '150以下')
    .optional(),
});

export type UserInput = z.infer<typeof userSchema>;
```

## 💻 React Hook Form + zod

```tsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { userSchema, type UserInput } from './schemas';

function UserForm() {
  const { register, handleSubmit, formState: { errors } } = useForm<UserInput>({
    resolver: zodResolver(userSchema),
    mode: 'onBlur', // フォーカスを外したらバリデーション
  });

  const onSubmit = async (data) => {
    const res = await fetch('/api/users', {
      method: 'POST',
      body: JSON.stringify(data),
    });
    if (!res.ok) { /* サーバーエラー */ }
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <label>
        名前
        <input {...register('name')} />
        {errors.name && <p>{errors.name.message}</p>}
      </label>

      <label>
        メール
        <input {...register('email')} />
        {errors.email && <p>{errors.email.message}</p>}
      </label>

      <label>
        パスワード
        <input type="password" {...register('password')} />
        {errors.password && <p>{errors.password.message}</p>}
      </label>

      <button>送信</button>
    </form>
  );
}
```

## 💻 サーバーからのエラーをフォームに反映

```tsx
const { setError } = useForm({...});

const onSubmit = async (data) => {
  const res = await fetch('/api/users', { method: 'POST', body: JSON.stringify(data) });
  if (!res.ok) {
    const errors = await res.json();
    // 例：{ field: 'email', message: '既に登録済み' }
    Object.entries(errors).forEach(([field, message]) => {
      setError(field, { message });
    });
  }
};
```

→ サーバー由来のエラー（例：メール重複）も同じUIで表示。

## 💻 ガイド付きのリアルタイム表示

### 文字数表示

```tsx
const value = watch('name'); // RHFで値を監視
<input {...register('name')} />
<p>{value.length}/20文字</p>
```

### パスワード強度

```tsx
function getStrength(password) {
  let score = 0;
  if (password.length >= 8) score++;
  if (/[A-Z]/.test(password)) score++;
  if (/[0-9]/.test(password)) score++;
  if (/[!@#$]/.test(password)) score++;
  return score;
}

<p>強度: {'★'.repeat(getStrength(password))}</p>
```

## 💻 タイミング戦略

| mode | タイミング | UX |
| --- | --- | --- |
| `onSubmit` | 送信時 | 最後にまとめて、シンプル |
| `onBlur` | フォーカス外す時 | 入力後に通知、バランス◎ |
| `onChange` | 入力ごと | リアルタイム、頻繁 |
| `onTouched` | 一度触れた後onBlur | 触れる前は出さない |

→ **`onBlur` か `onTouched` がおすすめ**。

## 💻 サーバー側でも zod

サーバー（Node.js / Next.js等）でも同じスキーマを使う：

```ts
// server/api/users.ts
import { userSchema } from '../shared/schemas';

export async function POST(request) {
  const body = await request.json();
  const result = userSchema.safeParse(body);

  if (!result.success) {
    return Response.json({ errors: result.error.flatten() }, { status: 400 });
  }

  // result.data は型安全
  await db.users.create(result.data);
  return Response.json({ ok: true });
}
```

→ クライアントとサーバーの**スキーマが同じ**＝バグを減らせる。

## ❌ よくある間違い

### クライアントだけバリデーション

→ POSTMan等で送られたら通ってしまう。**サーバー必須**。

### onChange で毎入力バリデーション

→ ユーザーがタイプしてる最中にエラーが出てうるさい。`onBlur`に。

### エラーメッセージがあいまい

```tsx
{errors.email && <p>エラーです</p>} // ❌
```

→ ✅ 何が悪かったか具体的に：「メール形式が違います」。

### サーバーエラーをアラートで出す

→ ✅ そのフィールドの近くに表示すると親切。

---

## ✅ ベストプラクティス

1. **クライアント補助 + サーバー必須**
2. **zod で同一スキーマを共有**
3. **`onBlur` か `onTouched`** でバリデーション
4. **エラーは具体的にフィールド近くで**
5. **サーバーエラーもsetErrorで統一表示**

- 各エラーをフィールド下に表示

## 📝 まとめ

- クライアントは補助、サーバーが本番
- zod + react-hook-form が定番
- onBlur/onTouched でバリデーション
- サーバーエラーも setError で統一
