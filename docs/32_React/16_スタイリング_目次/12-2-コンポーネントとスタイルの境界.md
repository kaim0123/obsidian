# 12-2. コンポーネントとスタイルの境界

## 🎯 この章で学ぶこと

- スタイルとロジックの境界をどう引くか
- 「style はpropsで切り替える」原則
- variantパターンの実装

---

## 📖 概念の説明

### スタイルとロジックを分ける理由

- ロジックは状態・イベント、スタイルは見た目だけ
- スタイルだけ変えたい時に、ロジックを触らずに済む
- 同じロジックで違うデザインを使い回せる

### ルール

1. **コンポーネントは外側のpropsで見た目を切り替える**
2. **スタイル特化のコンポーネント**を作る
3. **className/styleで上書き可能**にする（拡張性）

---

## 💻 ① variantで切り替え

```jsx
const buttonStyles = {
  primary: 'bg-blue-500 text-white',
  secondary: 'bg-gray-500 text-white',
  danger: 'bg-red-500 text-white',
};

function Button({ variant = 'primary', children }) {
  return (
    <button className={`px-4 py-2 rounded ${buttonStyles[variant]}`}>
      {children}
    </button>
  );
}

<Button variant="primary">OK</Button>
<Button variant="danger">削除</Button>
```

→ ロジックは1つ、見た目はpropsで切替。

---

## 💻 ② className を渡せるようにする

```jsx
function Button({ className = '', children }) {
  return (
    <button className={`btn ${className}`}>
      {children}
    </button>
  );
}

<Button className="bg-red-500">特殊用途</Button>
```

→ 親が個別カスタマイズできる。

---

## 💻 ③ asChild パターン（Radix UI 風）

```jsx
function Button({ asChild = false, children, ...rest }) {
  if (asChild) {
    // 子要素にpropsをマージ
    return cloneElement(children, rest);
  }
  return <button {...rest}>{children}</button>;
}

<Button asChild>
  <a href="/about">About</a>
</Button>
```

→ button のスタイルを a タグに付けたいとき便利。

## 💻 cva（class-variance-authority）

variantの組み合わせを管理するライブラリ：

```bash
npm install class-variance-authority
```

```ts
import { cva } from 'class-variance-authority';

const button = cva('px-4 py-2 rounded', {
  variants: {
    variant: {
      primary: 'bg-blue-500 text-white',
      secondary: 'bg-gray-500 text-white',
    },
    size: {
      sm: 'text-sm',
      md: 'text-md',
      lg: 'text-lg',
    },
  },
  defaultVariants: {
    variant: 'primary',
    size: 'md',
  },
});

function Button({ variant, size, ...rest }) {
  return <button className={button({ variant, size })} {...rest} />;
}
```

→ Tailwind との相性が良い。型安全に variant 管理。

---

## 💻 clsx / classnames

複数のclass名を条件付きで結合：

```bash
npm install clsx
```

```jsx
import clsx from 'clsx';

<button className={clsx(
  'px-4 py-2 rounded',
  variant === 'primary' && 'bg-blue-500',
  disabled && 'opacity-50',
)}>
  {children}
</button>
```

→ 三項のネストを avoidできる。

### tailwind-merge（Tailwindの衝突を解決）

```bash
npm install tailwind-merge
```

```jsx
import { twMerge } from 'tailwind-merge';

twMerge('px-2 py-1', 'px-4'); // → 'py-1 px-4'
```

→ 同じプロパティが重なるとき、後ろ勝ちにマージ。

## 💻 デザイントークン

スタイル定数を一元管理：

```ts
// theme.ts
export const colors = {
  primary: '#007bff',
  secondary: '#6c757d',
  danger: '#dc3545',
};

export const spacing = {
  sm: '8px',
  md: '16px',
  lg: '24px',
};
```

→ Tailwind なら `tailwind.config.js` の theme に書く。

```js
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      colors: {
        primary: '#007bff',
      },
    },
  },
};
```

→ `bg-primary` などで使える。

---

## ❌ よくある間違い

### コンポーネントにstyle直書き

```jsx
function Button() {
  return (
    <button style={{ backgroundColor: 'red', padding: 10 }}>OK</button>
  );
}
```

→ 拡張不可。propsで variant に。

### className を上書きできない

```jsx
function Button({ children }) {
  return <button className="btn">{children}</button>;
}
// 外から bg-red-500 を足したくても無理
```

→ ✅ `className` props を受け入れる。

### variant を class名で外から渡す

```jsx
<Button className="primary"> {/* "primary"が何のスタイルか不明 */}
```

→ ✅ `variant="primary"` で意味づけ。

---

## ✅ ベストプラクティス

1. **見た目はpropsで切替**（variant/size）
2. **className/styleを拡張用に受け入れる**
3. **cva + Tailwind**でvariant管理
4. **clsx**で条件付きclass
5. **デザイントークン**で一貫性

---

## 🔬 実践演習

`Card` コンポーネント：

- variant: 'default' | 'highlighted' | 'danger'
- size: 'sm' | 'md' | 'lg'
- className を受け入れる
- cva で実装

---

## 📝 まとめ

- スタイルはpropsで切替（variant）
- className を外から拡張可能に
- cva / clsx / tailwind-merge が便利
- デザイントークンで統一
