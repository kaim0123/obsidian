# 12-4. アクセシビリティ（focus/aria/キーボード）

## 🎯 この章で学ぶこと

- アクセシビリティ（a11y）の基本
- キーボード操作とフォーカス管理
- ARIA属性で意味を伝える

---

## 📖 アクセシビリティとは

「**誰もが使えるWeb**」を目指すこと。視覚障害、運動障害、年齢、一時的な怪我（マウスが使えない）など、**多様なユーザー**に配慮する。

### なぜ重要？

- 法的要件（公的サイト、企業サイト）
- 売上・利用者への影響
- SEO（検索エンジンも「見えない訪問者」）
- 開発者自身も将来お世話になる

---

## 💻 ① セマンティックHTMLを優先

「**意味のあるタグ**」を使う：

| やりがち | 推奨 |
| --- | --- |
| `<div onClick>` | `<button>` |
| `<div>タイトル</div>` | `<h1>タイトル</h1>` |
| `<span>リンク</span>` | `<a href>リンク</a>` |
| `<div className="list">` | `<ul>` `<li>` |

→ スクリーンリーダーが読み上げる、キーボードでも操作できる。

---

## 💻 ② キーボード操作

### Tabキーで移動できるか確認

ブラウザでTabキーを押して、すべての操作要素にフォーカスが行くか確認。

### 必要なときは `tabIndex`

```jsx
<div tabIndex={0} onClick={...}>
  クリックできるが、divにはデフォルトでフォーカスが来ない
</div>
```

ただし、本当は `<button>` にすべき。

### Enter / Space キー対応

```jsx
<div
  role="button"
  tabIndex={0}
  onClick={handleClick}
  onKeyDown={(e) => {
    if (e.key === 'Enter' || e.key === ' ') handleClick();
  }}
>
  仮のボタン
</div>
```

→ ですが普通は **`<button>`を使う**のが楽。

### ESCキーでモーダル閉じる

```jsx
useEffect(() => {
  const handler = (e) => { if (e.key === 'Escape') onClose(); };
  window.addEventListener('keydown', handler);
  return () => window.removeEventListener('keydown', handler);
}, [onClose]);
```

## 💻 ③ フォーカス管理

### 開いたら最初の要素にフォーカス

```jsx
const inputRef = useRef(null);

useEffect(() => {
  if (isOpen) inputRef.current?.focus();
}, [isOpen]);

<input ref={inputRef} />
```

### 閉じたら戻す

```jsx
const previousFocus = useRef(null);

function open() {
  previousFocus.current = document.activeElement;
  setOpen(true);
}

function close() {
  setOpen(false);
  previousFocus.current?.focus();
}
```

→ モーダル系は重要。

### フォーカストラップ（モーダル内に閉じ込める）

ライブラリ `focus-trap-react` などを使うと楽。

## 💻 ④ ARIA 属性

「**役割や状態を補足説明**」する。**ただしsemantic HTMLで足りるならそちらを優先**。

### よく使うARIA属性

| 属性 | 用途 |
| --- | --- |
| `aria-label` | ラベル（テキストがないとき） |
| `aria-labelledby` | 別要素のidをラベルに |
| `aria-describedby` | 説明文 |
| `aria-hidden` | スクリーンリーダーから隠す（装飾） |
| `aria-expanded` | アコーディオンの開閉状態 |
| `aria-selected` | タブの選択状態 |
| `aria-live` | 動的更新の通知 |
| `role` | 要素の役割（dialog, tablist...） |

### 例：アイコンボタン

```jsx
<button aria-label="検索">
  <SearchIcon aria-hidden="true" />
</button>
```

アイコンだけだと音声では読めない → `aria-label` で説明。

### 例：モーダル

```jsx
<div role="dialog" aria-modal="true" aria-labelledby="dialog-title">
  <h2 id="dialog-title">確認</h2>
  <p>削除しますか？</p>
</div>
```

### 例：トースト通知

```jsx
<div role="status" aria-live="polite">
  保存しました
</div>
```

→ 動的に表示されたものを音声でも通知。

## 💻 ⑤ 画像のalt

```jsx
<img src="/cat.png" alt="ねこの写真" />

{/* 装飾的な画像はalt="" */}
<img src="/decoration.png" alt="" />
```

altなしは「画像があります」とだけ読まれる。

---

## 💻 ⑥ ラベルとinput

```jsx
{/* ✅ for/htmlForで紐付け */}
<label htmlFor="email">メール</label>
<input id="email" type="email" />

{/* または囲む */}
<label>
  メール
  <input type="email" />
</label>
```

`<label>` を必ずつける。スクリーンリーダーで「メール、編集可能」と読まれる。

## 💻 ⑦ コントラスト比

文字色と背景色の差が**4.5:1以上**（通常テキスト）が推奨。

→ Chrome DevTools の「Lighthouse」や「Inspect → Color picker」で確認。

- **axe DevTools**：ブラウザ拡張で診断
- **Lighthouse**：Accessibility スコア

## ❌ よくある間違い

### div+onClick で済ませる

→ ボタンに変える。

### 色だけで状態を伝える

```jsx
<span style={{ color: 'red' }}>エラー</span>
```

→ ✅ アイコン or テキストも併用：「⚠️ エラー」。

### autoFocus を使いすぎる

→ ページ移動のたびに勝手にfocus されてうるさい。重要な場面だけ。

### ARIA を付けすぎる

→ 過剰。Semantic HTMLで足りるならそれで十分。

---

## ✅ ベストプラクティス

1. **Semantic HTML を最優先**
2. **キーボードで全機能操作可能**
3. **フォーカス管理**（開いたとき・閉じたとき）
4. **ARIA は補足**として
5. **eslint-plugin-jsx-a11y** を有効化

---

## 🔬 実践演習

モーダルを a11y 対応：

- ESC で閉じる
- 開いたら最初のinputにfocus
- 閉じたらトリガーボタンにfocus戻す
- aria-modal、aria-labelledby
- 背景にtab focus が漏れない

---

## 📝 まとめ

- semantic HTML 優先
- キーボード操作 + フォーカス管理
- ARIA は補足
- ツールで自動診断
