# コンポーネント・フックス・サービスとは

コンポーネント、フックス（Hooks）、サービスは、モダンなWeb開発でよく使われる重要な概念です。この章では、これらの概念について初心者向けに解説します。

## 📖 コンポーネントとは

**コンポーネント（Component）**は、UIの一部を表す再利用可能なコードの塊です。ReactやVue.jsなどのフロントエンドフレームワークで使われます。

### 日常生活での例え

コンポーネントは、「レゴブロック」のようなものです。

- **レゴブロック**: 小さな部品を組み合わせて大きな作品を作る
- **コンポーネント**: 小さなUI部品を組み合わせてWebアプリケーションを作る

### コンポーネントの特徴

1. **再利用可能**: 一度作ったコンポーネントを何度でも使える
2. **独立性**: 各コンポーネントが独立して動作する
3. **組み合わせ可能**: 複数のコンポーネントを組み合わせて大きなUIを作る

### Reactでのコンポーネント例

```javascript
// シンプルなコンポーネント
function Button({ text, onClick }) {
  return (
    <button onClick={onClick}>
      {text}
    </button>
  );
}

// 使用例
<Button text="クリック" onClick={() => console.log('クリックされました')} />
```

### コンポーネントの種類

#### 1. 関数コンポーネント（推奨）

```javascript
// 関数コンポーネント
function UserCard({ name, email }) {
  return (
    <div>
      <h3>{name}</h3>
      <p>{email}</p>
    </div>
  );
}

// 使用例
<UserCard name="山田太郎" email="yamada@example.com" />
```

#### 2. クラスコンポーネント（古い方法）

```javascript
// クラスコンポーネント（現在はあまり使われない）
class UserCard extends React.Component {
  render() {
    return (
      <div>
        <h3>{this.props.name}</h3>
        <p>{this.props.email}</p>
      </div>
    );
  }
}
```

### コンポーネントの階層構造

```javascript
// 親コンポーネント
function App() {
  return (
    <div>
      <Header />
      <MainContent />
      <Footer />
    </div>
  );
}

// 子コンポーネント
function Header() {
  return <header>ヘッダー</header>;
}

function MainContent() {
  return <main>メインコンテンツ</main>;
}

function Footer() {
  return <footer>フッター</footer>;
}
```

## 🎣 フックス（Hooks）とは

**フックス（Hooks）**は、Reactの関数コンポーネントで状態管理やライフサイクル処理を行うための仕組みです。

### 日常生活での例え

フックスは、「便利な道具箱」のようなものです。

- **道具箱**: 必要な道具を取り出して使う
- **フックス**: 必要な機能（状態管理など）を取り出して使う

### フックスの特徴

1. **関数コンポーネントで使える**: クラスコンポーネントを使わなくても状態管理ができる
2. **再利用可能**: カスタムフックスを作成して再利用できる
3. **シンプル**: コードが読みやすく、理解しやすい

### 主なフックス

#### 1. useState（状態管理）

```javascript
import { useState } from 'react';

function Counter() {
  // countという状態と、setCountという更新関数を取得
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>カウント: {count}</p>
      <button onClick={() => setCount(count + 1)}>
        増やす
      </button>
      <button onClick={() => setCount(count - 1)}>
        減らす
      </button>
    </div>
  );
}
```

#### 2. useEffect（副作用処理）

```javascript
import { useState, useEffect } from 'react';

function UserList() {
  const [users, setUsers] = useState([]);

  // コンポーネントが表示されたときに実行
  useEffect(() => {
    fetch('/api/users')
      .then(res => res.json())
      .then(data => setUsers(data));
  }, []); // 空の配列 = 初回のみ実行

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

#### 3. useContext（コンテキスト）

```javascript
import { createContext, useContext } from 'react';

// コンテキストを作成
const ThemeContext = createContext('light');

function App() {
  return (
    <ThemeContext.Provider value="dark">
      <Header />
    </ThemeContext.Provider>
  );
}

function Header() {
  // コンテキストから値を取得
  const theme = useContext(ThemeContext);
  return <header className={theme}>ヘッダー</header>;
}
```

### カスタムフックス

自分でフックスを作成することもできます。

```javascript
// カスタムフックス: ユーザー情報を取得する
function useUser(userId) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => {
        setUser(data);
        setLoading(false);
      });
  }, [userId]);

  return { user, loading };
}

// 使用例
function UserProfile({ userId }) {
  const { user, loading } = useUser(userId);

  if (loading) return <div>読み込み中...</div>;
  if (!user) return <div>ユーザーが見つかりません</div>;

  return (
    <div>
      <h1>{user.name}</h1>
      <p>{user.email}</p>
    </div>
  );
}
```

## 🔧 サービスとは

**サービス（Service）**は、ビジネスロジックやデータ取得などの処理を担当する層です。フロントエンドとバックエンドの両方で使われます。

### 日常生活での例え

サービスは、「専門家」のようなものです。

- **専門家**: 特定の分野の知識やスキルを持っている
- **サービス**: 特定の処理（データ取得、計算など）を担当する

### サービスの特徴

1. **責任の分離**: UIとロジックを分離する
2. **再利用可能**: 複数の場所で同じサービスを使える
3. **テストしやすい**: ロジックが独立しているため、テストが書きやすい

### フロントエンドでのサービス例

```javascript
// userService.js - ユーザー関連のAPI呼び出しを担当
class UserService {
  // ユーザー一覧を取得
  async getUsers() {
    const response = await fetch('/api/users');
    if (!response.ok) {
      throw new Error('ユーザー一覧の取得に失敗しました');
    }
    return response.json();
  }

  // 特定のユーザーを取得
  async getUser(userId) {
    const response = await fetch(`/api/users/${userId}`);
    if (!response.ok) {
      throw new Error('ユーザーの取得に失敗しました');
    }
    return response.json();
  }

  // ユーザーを作成
  async createUser(userData) {
    const response = await fetch('/api/users', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
      },
      body: JSON.stringify(userData),
    });
    if (!response.ok) {
      throw new Error('ユーザーの作成に失敗しました');
    }
    return response.json();
  }
}

// 使用例
const userService = new UserService();

// コンポーネントで使用
function UserList() {
  const [users, setUsers] = useState([]);

  useEffect(() => {
    userService.getUsers()
      .then(data => setUsers(data))
      .catch(error => console.error(error));
  }, []);

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

### バックエンドでのサービス例

```javascript
// userService.js - ビジネスロジックを担当
class UserService {
  constructor(userRepository) {
    this.userRepository = userRepository;
  }

  // ユーザーを作成（ビジネスロジックを含む）
  async createUser(userData) {
    // バリデーション
    if (!userData.name || !userData.email) {
      throw new Error('名前とメールアドレスが必要です');
    }

    // メールアドレスの重複チェック
    const existingUser = await this.userRepository.findByEmail(userData.email);
    if (existingUser) {
      throw new Error('このメールアドレスは既に使用されています');
    }

    // ユーザーを作成
    const newUser = await this.userRepository.create(userData);
    return newUser;
  }

  // ユーザーを取得
  async getUser(userId) {
    const user = await this.userRepository.findById(userId);
    if (!user) {
      throw new Error('ユーザーが見つかりません');
    }
    return user;
  }
}

// 使用例（Express.jsのルートハンドラー）
app.post('/api/users', async (req, res) => {
  try {
    const userService = new UserService(userRepository);
    const newUser = await userService.createUser(req.body);
    res.status(201).json(newUser);
  } catch (error) {
    res.status(400).json({ error: error.message });
  }
});
```

## 🔄 コンポーネント、フックス、サービスの関係

### 典型的な構造

```
コンポーネント（UI）
    ↓ フックス（状態管理）
サービス（データ取得・ビジネスロジック）
    ↓
API / データベース
```

### 実践例

```javascript
// 1. サービス（データ取得を担当）
const userService = {
  async getUsers() {
    const response = await fetch('/api/users');
    return response.json();
  }
};

// 2. カスタムフックス（状態管理とデータ取得を統合）
function useUsers() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    userService.getUsers()
      .then(data => {
        setUsers(data);
        setLoading(false);
      });
  }, []);

  return { users, loading };
}

// 3. コンポーネント（UIを表示）
function UserList() {
  const { users, loading } = useUsers();

  if (loading) return <div>読み込み中...</div>;

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

## 💡 実践例：完全なアプリケーション

### サービス層

```javascript
// services/userService.js
class UserService {
  async getUsers() {
    const response = await fetch('/api/users');
    if (!response.ok) throw new Error('取得に失敗しました');
    return response.json();
  }

  async createUser(userData) {
    const response = await fetch('/api/users', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(userData),
    });
    if (!response.ok) throw new Error('作成に失敗しました');
    return response.json();
  }
}

export const userService = new UserService();
```

### カスタムフックス

```javascript
// hooks/useUsers.js
import { useState, useEffect } from 'react';
import { userService } from '../services/userService';

export function useUsers() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    userService.getUsers()
      .then(data => {
        setUsers(data);
        setLoading(false);
      })
      .catch(err => {
        setError(err.message);
        setLoading(false);
      });
  }, []);

  const addUser = async (userData) => {
    try {
      const newUser = await userService.createUser(userData);
      setUsers([...users, newUser]);
    } catch (err) {
      setError(err.message);
    }
  };

  return { users, loading, error, addUser };
}
```

### コンポーネント

```javascript
// components/UserList.jsx
import { useUsers } from '../hooks/useUsers';

function UserList() {
  const { users, loading, error, addUser } = useUsers();

  const handleSubmit = async (e) => {
    e.preventDefault();
    const formData = new FormData(e.target);
    const userData = {
      name: formData.get('name'),
      email: formData.get('email'),
    };
    await addUser(userData);
  };

  if (loading) return <div>読み込み中...</div>;
  if (error) return <div>エラー: {error}</div>;

  return (
    <div>
      <form onSubmit={handleSubmit}>
        <input name="name" placeholder="名前" required />
        <input name="email" type="email" placeholder="メール" required />
        <button type="submit">追加</button>
      </form>

      <ul>
        {users.map(user => (
          <li key={user.id}>
            {user.name} - {user.email}
          </li>
        ))}
      </ul>
    </div>
  );
}

export default UserList;
```

## ⚠️ よくある間違いと注意点

### 1. コンポーネントにビジネスロジックを書く

```javascript
// ❌ 間違い（コンポーネントにロジックが混在）
function UserList() {
  const [users, setUsers] = useState([]);

  useEffect(() => {
    // バリデーションやビジネスロジックがコンポーネントに書かれている
    fetch('/api/users')
      .then(res => res.json())
      .then(data => {
        // 複雑な処理がコンポーネントに書かれている
        const filtered = data.filter(user => user.active);
        setUsers(filtered);
      });
  }, []);

  return <ul>...</ul>;
}

// ✅ 正しい（サービスにロジックを分離）
function UserList() {
  const { users } = useUsers(); // フックスがサービスを使う
  return <ul>...</ul>;
}
```

### 2. フックスのルールを守らない

```javascript
// ❌ 間違い（条件分岐の中でフックスを使う）
function Component({ condition }) {
  if (condition) {
    const [count, setCount] = useState(0); // エラー！
  }
  return <div>...</div>;
}

// ✅ 正しい（常に同じ順序で呼び出す）
function Component({ condition }) {
  const [count, setCount] = useState(0);
  if (condition) {
    // 条件分岐はOK
  }
  return <div>...</div>;
}
```

### 3. サービスを適切に分離しない

```javascript
// ❌ 間違い（すべての処理が1つのサービスに）
class AllService {
  getUsers() { ... }
  getProducts() { ... }
  getOrders() { ... }
  calculatePrice() { ... }
}

// ✅ 正しい（責任ごとにサービスを分ける）
class UserService {
  getUsers() { ... }
  getUser() { ... }
}

class ProductService {
  getProducts() { ... }
  getProduct() { ... }
}

class OrderService {
  getOrders() { ... }
  calculatePrice() { ... }
}
```

## 🎯 まとめ

- **コンポーネント**: UIの部品。再利用可能で、組み合わせて大きなUIを作る
- **フックス**: 関数コンポーネントで状態管理や副作用処理を行う仕組み
- **サービス**: ビジネスロジックやデータ取得を担当する層
- **責任の分離**: コンポーネント（UI）、フックス（状態管理）、サービス（ロジック）を分けることで、保守性が向上する
- **再利用性**: 適切に分離することで、コードの再利用が容易になる
