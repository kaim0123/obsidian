# 8-8. 送信フローの状態管理（送信中・成功・失敗・二重送信防止）

## 🎯 この章で学ぶこと

- 送信処理の4つの状態（idle/submitting/success/error）
- 二重送信を防ぐ実装パターン
- 楽観的更新（送信前に画面を更新）

---

## 📖 状態の遷移

```text
idle → submitting → success
                  └─ error → idle (再試行)
```

| 状態 | 意味 | UI |
| --- | --- | --- |
| **idle** | 待機中 | 通常のボタン |
| **submitting** | 送信中 | スピナー、ボタンdisabled |
| **success** | 成功 | 完了メッセージ、リダイレクトなど |
| **error** | 失敗 | エラー表示、再試行ボタン |

---

## 💻 基本実装

```jsx
function SubmitForm() {
  const [status, setStatus] = useState('idle'); // idle | submitting | success | error
  const [errorMsg, setErrorMsg] = useState('');

  async function handleSubmit(e) {
    e.preventDefault();
    if (status === 'submitting') return; // ★ 二重送信防止

    setStatus('submitting');
    setErrorMsg('');
    try {
      const data = new FormData(e.currentTarget);
      const res = await fetch('/api/contact', { method: 'POST', body: data });
      if (!res.ok) throw new Error('送信失敗');
      setStatus('success');
    } catch (err) {
      setStatus('error');
      setErrorMsg(err.message);
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="name" />
      <input name="email" />
      <button disabled={status === 'submitting'}>
        {status === 'submitting' ? '送信中...' : '送信'}
      </button>

      {status === 'success' && <p>✅ 送信完了！</p>}
      {status === 'error' && <p>❌ {errorMsg}</p>}
    </form>
  );
}
```

## 💡 二重送信を防ぐ3つの方法

### 方法1：状態フラグ（上の例）

```jsx
if (status === 'submitting') return;
```

シンプルで確実。

### 方法2：ボタンを disabled

```jsx
<button disabled={status === 'submitting'}>送信</button>
```

ユーザーがクリックできない。フラグと併用。

### 方法3：Idempotency Key（サーバ側でも）

```jsx
const idempotencyKey = useMemo(() => crypto.randomUUID(), []);

await fetch('/api/contact', {
  headers: { 'Idempotency-Key': idempotencyKey },
});
```

ネットワーク再送でも、サーバは「同じキーは1回だけ処理」する。重要な処理（決済など）に。

---

## 💡 `<form>` の `action` / `method` は基本いらない（`fetch` で送る場合）

`onSubmit` で `e.preventDefault()` して `fetch(...)` で送るなら、送信の真実は **`onSubmit` の中**にあります。  
`<form action="..." method="POST">` を残すと「ブラウザの古典送信もするの？」と読み手が迷うので、**基本は消して一箇所に集約**します。

```jsx
function onSubmit(e) {
  e.preventDefault(); // ブラウザのデフォルト送信（ページ遷移）を止める
  // fetch(...) が唯一の送信経路
}

<form onSubmit={onSubmit}>
  ...
</form>
```

---

## 💡 フォーム内のボタンは `type` を明示する

フォームの中では、`<button>` の `type` を省略すると **`submit` 扱い**になりやすく、意図しない送信が起きます。

- **送信ボタン**: `type="submit"`
- **送信以外（編集・追加・モーダルを開く等）**: `type="button"`
- **リセット**: `type="reset"`（使うなら）

```jsx
<form onSubmit={onSubmit}>
  <button type="submit">送信</button>
  <button type="button" onClick={openPreview}>プレビュー</button>
</form>
```

## 💻 ローディング中のボタン

```jsx
<button type="submit" disabled={isSubmitting}>
  {isSubmitting ? (
    <>
      <Spinner />
      <span style={{ marginLeft: 8 }}>送信中...</span>
    </>
  ) : '送信'}
</button>
```

スピナー + テキストでユーザーに動作中を伝える。

## 💡 「最新の送信だけ有効」にする（AbortController）

送信中に画面遷移・連打・別の送信が起きると、**古いレスポンスが後から返って状態が巻き戻る**ことがあります。  
1つの対策は `AbortController` で **前のリクエストを中断**して「最新だけ反映」することです。

```jsx
function SearchForm() {
  const abortRef = useRef(null);

  async function onSubmit(e) {
    e.preventDefault();
    abortRef.current?.abort?.(); // 前のリクエストを中断
    const controller = new AbortController();
    abortRef.current = controller;

    const res = await fetch('/api/search', { signal: controller.signal });
    // ...
  }
}
```

※ `AbortError` は「失敗扱いにしない」設計にすることが多いです。

## 💡 楽観的更新（Optimistic Update）

「**サーバの応答を待たずに先に画面を更新**」する手法。体感がサクサクに。

```jsx
function LikeButton({ postId, initialLiked }) {
  const [liked, setLiked] = useState(initialLiked);

  async function toggle() {
    const next = !liked;
    setLiked(next); // ★ 先に画面更新

    try {
      await fetch(`/api/posts/${postId}/like`, { method: next ? 'POST' : 'DELETE' });
    } catch {
      setLiked(!next); // 失敗したら巻き戻す
    }
  }

  return <button onClick={toggle}>{liked ? '♥' : '♡'}</button>;
}
```

→ TanStack Query なら **`onMutate`** で標準対応。 [[7-6-キャッシュ-再検証-楽観更新]]。

## 💡 React 19 の useFormStatus / useActionState

React 19から、フォーム状態を扱うフックが入りました（参考）：

```jsx
import { useActionState } from 'react';

async function submitAction(prevState, formData) {
  // ...
}

function Form() {
  const [state, formAction, isPending] = useActionState(submitAction, initial);
  return (
    <form action={formAction}>
      <input name="name" />
      <button disabled={isPending}>{isPending ? '送信中' : '送信'}</button>
    </form>
  );
}
```

将来的にはこれが標準になりそう。

## 💻 完成度の高い実装テンプレ

```jsx
function ContactForm() {
  const [status, setStatus] = useState('idle');
  const [error, setError] = useState(null);

  async function onSubmit(e) {
    e.preventDefault();
    if (status === 'submitting') return;

    setStatus('submitting');
    setError(null);

    try {
      const data = Object.fromEntries(new FormData(e.currentTarget));
      const res = await fetch('/api/contact', {
        method: 'POST',
        body: JSON.stringify(data),
        headers: { 'Content-Type': 'application/json' },
      });

      if (!res.ok) {
        const body = await res.json().catch(() => ({}));
        throw new Error(body.message ?? '送信に失敗しました');
      }

      setStatus('success');
    } catch (err) {
      setStatus('error');
      setError(err.message);
    }
  }

  if (status === 'success') {
    return <p>✅ お問い合わせを受け付けました。</p>;
  }

  return (
    <form onSubmit={onSubmit}>
      <fieldset disabled={status === 'submitting'}>
        <input name="name" required />
        <input name="email" type="email" required />
        <button>{status === 'submitting' ? '送信中...' : '送信'}</button>
      </fieldset>
      {status === 'error' && <p style={{ color: 'red' }}>{error}</p>}
    </form>
  );
}
```

`<fieldset disabled>` で**フォーム全体を無効化**。

## ❌ よくある間違い

### ボタンだけ disabled してフラグを忘れる

```jsx
<button disabled={isSubmitting}>送信</button>
// ボタン無効化だけだと、Enterキーで送信できてしまうことがある
```

→ ✅ submit ハンドラの先頭でも防御。

### finally で必ず idle に戻す

```jsx
try {
  await ...;
} finally {
  setStatus('idle'); // ❌ success のあと idle に戻すと、成功UIが消える
}
```

→ ✅ 状態遷移を明示的に。

### エラー表示が古いまま残る

→ submit のたびに `setError(null)` でクリア。

---

## ✅ ベストプラクティス

1. **status で4状態を管理**（idle/submitting/success/error）
2. **ハンドラ先頭で二重送信防止**
3. **ボタン or fieldset を disabled** に
4. **重要な処理は Idempotency Key**
5. **楽観的更新**でUXを上げる（成功率高い操作で）

---

## 🔬 実践演習

「コメント投稿フォーム」：

- 投稿中のスピナー
- 連打しても1回だけ送信
- 成功時はコメント一覧に追加（楽観的更新）
- 失敗時はメッセージを残しつつ再試行可能

---

## 📝 まとめ

- 送信フローは idle/submitting/success/error の4状態
- 二重送信防止はフラグ + disabled
- 楽観的更新で UX 向上
- 重要な処理は Idempotency Key
