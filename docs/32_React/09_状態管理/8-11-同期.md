# 8-11. 同期（複数タブ・複数端末・競合の考え方）

## 🎯 この章で学ぶこと

- 複数のタブ・端末で同じデータを扱うときの問題
- BroadcastChannel / storage event でタブ間同期
- WebSocket / Server-Sent Events で端末間リアルタイム同期
- 楽観的更新と競合解決の考え方

---

## 📖 状況別の同期手段

| 状況 | 手段 |
| --- | --- |
| 同じブラウザ・別タブ | BroadcastChannel / storage event |
| 別端末（リアルタイム） | WebSocket / SSE |
| 別端末（ポーリング） | TanStack Query の refetchInterval |
| オフライン → 復旧 | キュー → 再送 |

---

## 💻 タブ間同期：BroadcastChannel

```jsx
const channel = new BroadcastChannel('my-app');

// タブA：通知を送る
channel.postMessage({ type: 'logout' });

// タブB：受け取る
useEffect(() => {
  channel.onmessage = (e) => {
    if (e.data.type === 'logout') logout();
  };
  return () => channel.close();
}, []);
```

→ 1つのタブでログアウトすると、他のタブも自動でログアウト。

### storage event（古いブラウザ対応）

```jsx
useEffect(() => {
  function handle(e) {
    if (e.key === 'auth') {
      // 別タブで auth が変わった
    }
  }
  window.addEventListener('storage', handle);
  return () => window.removeEventListener('storage', handle);
}, []);
```

ただし localStorage 依存。

---

## 💻 リアルタイム同期：WebSocket

```jsx
function useChat(roomId) {
  const [messages, setMessages] = useState([]);

  useEffect(() => {
    const ws = new WebSocket(`wss://example.com/rooms/${roomId}`);

    ws.onmessage = (e) => {
      const msg = JSON.parse(e.data);
      setMessages((prev) => [...prev, msg]);
    };

    return () => ws.close();
  }, [roomId]);

  return messages;
}
```

`roomId` が変わると古い接続を閉じて新しい接続を張る。

### Server-Sent Events（SSE、サーバ→クライアントの一方向）

```jsx
useEffect(() => {
  const eventSource = new EventSource('/api/events');
  eventSource.onmessage = (e) => {
    const data = JSON.parse(e.data);
    setUpdates((prev) => [...prev, data]);
  };
  return () => eventSource.close();
}, []);
```

WebSocketより簡単、双方向は不要なときに。

## 💻 ポーリング（定期取得）

WebSocketが使えないなら、定期的に再取得：

```jsx
const { data } = useQuery({
  queryKey: ['notifications'],
  queryFn: () => fetch('/api/notifications').then((r) => r.json()),
  refetchInterval: 5000, // 5秒ごと
});
```

## ⚔️ 競合（コンフリクト）の考え方

複数の人が同時に同じデータを編集すると、後から保存した人が前の人を上書きする可能性。

### 解決策1：Last Write Wins（後勝ち、シンプル）

最後の更新が勝つ。多くのアプリで十分。

### 解決策2：楽観的ロック（version番号）

```jsx
// クライアント：バージョン付きで送信
PUT /api/posts/1
{ title: '新タイトル', version: 3 }

// サーバ：DBのバージョンと比較
if (db.version !== 3) return 409 Conflict;
```

→ 古いバージョンで更新しようとしたら 409。クライアントは「他の人が編集しました」と表示して再取得。

### 解決策3：CRDT（高度）

リアルタイム共同編集（Google Docsなど）に使う。**Yjs** などのライブラリ。

## 💻 楽観的更新と競合

```jsx
const queryClient = useQueryClient();

const mutation = useMutation({
  mutationFn: updatePost,
  onMutate: async (newPost) => {
    await queryClient.cancelQueries(['posts', newPost.id]);
    const previous = queryClient.getQueryData(['posts', newPost.id]);
    queryClient.setQueryData(['posts', newPost.id], newPost); // 先に画面更新
    return { previous };
  },
  onError: (err, newPost, ctx) => {
    queryClient.setQueryData(['posts', newPost.id], ctx.previous); // 巻き戻し
  },
  onSettled: (_, __, newPost) => {
    queryClient.invalidateQueries(['posts', newPost.id]); // 最終的にサーバから再取得
  },
});
```

詳しくは [[7-6-キャッシュ-再検証-楽観更新]]。

## 💻 オンライン/オフライン検出

```jsx
function useOnline() {
  const [online, setOnline] = useState(navigator.onLine);

  useEffect(() => {
    const onlineHandler = () => setOnline(true);
    const offlineHandler = () => setOnline(false);
    window.addEventListener('online', onlineHandler);
    window.addEventListener('offline', offlineHandler);
    return () => {
      window.removeEventListener('online', onlineHandler);
      window.removeEventListener('offline', offlineHandler);
    };
  }, []);

  return online;
}
```

→ オフラインの間は警告表示、オンラインに戻ったら自動再送（次節）。

## ❌ よくある間違い

### WebSocketのクリーンアップ忘れ

```jsx
useEffect(() => {
  const ws = new WebSocket(...);
  // ❌ close なし → 接続増殖
}, [roomId]);
```

→ ✅ `return () => ws.close()`。

### 同期するタイミングが多すぎてループ

タブAの変更がタブBに通知 → タブBが反応 → タブBの変更がタブAに通知…

→ 「**自分発の変更は無視**」フラグを付ける、もしくは「最終更新時刻が同じなら無視」。

### 楽観的更新を巻き戻し忘れる

→ 必ず `onError` で revert。

---

## ✅ ベストプラクティス

1. **タブ間は BroadcastChannel** が現代的
2. **リアルタイムは WebSocket、片方向はSSE**
3. **代替で TanStack Query の refetchInterval**
4. **競合は Last Write Wins から始め**、必要に応じて version
5. **オフライン検出 + キュー** で堅牢に

---

## 🔬 実践演習

「メモアプリ」で複数タブ同期：

- メモを編集すると別タブにも反映
- BroadcastChannel で同期
- ログアウトすると全タブでログアウト

---

## 📝 まとめ

- タブ間：BroadcastChannel
- リアルタイム：WebSocket / SSE
- 代替：ポーリング（refetchInterval）
- 競合：version番号 or 後勝ち
