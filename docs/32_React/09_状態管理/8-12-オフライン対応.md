# 8-12. オフライン対応（キューイング/再送/楽観UIの落とし穴）

## 🎯 この章で学ぶこと

- オフライン時の3つの問題と対処
- 操作のキューイング（後で再送）
- 楽観UIの落とし穴と巻き戻し

---

## 📖 オフラインで起こる問題

1. **データを取れない** → キャッシュから表示
2. **送信できない** → キューに溜めて後で再送
3. **オンラインに戻った時の競合** → 楽観UI を巻き戻すか確定するか

---

## 💻 オフライン検出

```jsx
const [online, setOnline] = useState(navigator.onLine);

useEffect(() => {
  const on = () => setOnline(true);
  const off = () => setOnline(false);
  window.addEventListener('online', on);
  window.addEventListener('offline', off);
  return () => {
    window.removeEventListener('online', on);
    window.removeEventListener('offline', off);
  };
}, []);

return (
  <>
    {!online && <Banner>オフラインです</Banner>}
    <App />
  </>
);
```

注意：`navigator.onLine` は **ブラウザの判断**。実際のサーバ到達性とは違う。「pingで確認」するとより正確。

## 💻 操作のキューイング

オフライン中の更新を保存しておき、オンラインに戻ったら再送：

```jsx
// シンプルなキュー実装
const queue = [];

async function tryRequest(req) {
  if (!navigator.onLine) {
    queue.push(req);
    saveQueueToStorage();
    return;
  }
  await fetch(req.url, { method: req.method, body: req.body });
}

window.addEventListener('online', async () => {
  while (queue.length > 0) {
    const req = queue.shift();
    try {
      await fetch(req.url, { method: req.method, body: req.body });
    } catch {
      queue.unshift(req); // 失敗したら戻す
      break;
    }
  }
});
```

実用的にはライブラリを使う：

- **Workbox**：Service Worker で background sync
- **TanStack Query Persist** + retry
- **Dexie.js + IndexedDB**：永続キュー

## 💻 楽観UIの落とし穴

### 落とし穴1：失敗時の巻き戻し忘れ

```jsx
async function deleteItem(id) {
  setItems((prev) => prev.filter((i) => i.id !== id)); // 先に画面更新
  try {
    await api.delete(id);
  } catch {
    // ❌ 失敗時に巻き戻しなし
  }
}
```

→ ✅ try/catch で必ず元に戻す：

```jsx
async function deleteItem(id) {
  const previous = items;
  setItems((prev) => prev.filter((i) => i.id !== id));
  try {
    await api.delete(id);
  } catch {
    setItems(previous); // 巻き戻し
    showError('削除に失敗しました');
  }
}
```

### 落とし穴2：IDの不一致

新規作成を楽観的にやると、ローカルでは仮IDだがサーバが本IDを返す。

```jsx
// 仮ID
const tempId = `temp_${Date.now()}`;
setItems([...items, { id: tempId, text }]);

// サーバから本IDが返ってきたら入れ替え
const real = await api.create({ text });
setItems((prev) => prev.map((i) => i.id === tempId ? real : i));
```

→ TanStack Query の `onMutate` / `onSuccess` でやる。

### 落とし穴3：複数の楽観更新が重なる

連続して送るときの順序保証。**キューで順次処理**。

## 💡 PWA（Progressive Web Apps）

## ❌ よくある間違い

### `navigator.onLine` を信じすぎる

→ ブラウザは「ネットに繋がってる」と思っていても実は通信できない。pingで確認する。

### キューを memory だけに置く

→ リロードで消える。**localStorage / IndexedDB**に永続化。

### オフライン中に楽観UIだけ進める

→ 失敗しても「成功した」と思ってしまう。**「未送信」マーク**をUI上で表示。

### 再送のリトライ間隔を空けない

→ 失敗したら指数バックオフ（1s, 2s, 4s, 8s…）。
