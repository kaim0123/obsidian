# 8-10. セッション管理（ログイン状態の保持と更新）

## 🎯 この章で学ぶこと

- ログイン情報をどう保持するか（メモリ / localStorage / cookie）
- セキュリティの観点（XSS、CSRF）
- アクセストークンの自動更新（リフレッシュ）

---

## 📖 概念の説明

### セッション管理 = 「誰がアクセスしているか」を記憶する

ログイン後、アプリは「**この人はログイン中**」を覚えておく必要があります。覚えるための情報を**トークン**と呼びます。

### 主な保存先と特徴

| 保存先 | 特徴 | XSS耐性 | CSRF耐性 |
| --- | --- | --- | --- |
| **memory（state）** | リロードで消える | ◎ | ◎ |
| **localStorage** | 永続化 | ❌（JSから読める） | ◎ |
| **httpOnly Cookie** | 永続化 + サーバ自動送信 | ◎ | △（CSRFトークン必須） |

### ベストプラクティス

- **アクセストークン**：メモリ（state） + 短命
- **リフレッシュトークン**：httpOnly Cookie + 長命
- localStorage はセキュリティ的に推奨されない

## 💻 シンプルな実装：state + Context

```jsx
const AuthContext = createContext(null);

function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [token, setToken] = useState(null);
  const [loading, setLoading] = useState(true);

  // 起動時に再ログイン（リフレッシュトークン使用）
  useEffect(() => {
    fetch('/api/auth/refresh', { credentials: 'include' })
      .then((r) => r.ok ? r.json() : null)
      .then((data) => {
        if (data) {
          setUser(data.user);
          setToken(data.accessToken);
        }
      })
      .finally(() => setLoading(false));
  }, []);

  async function login(email, password) {
    const res = await fetch('/api/auth/login', {
      method: 'POST',
      body: JSON.stringify({ email, password }),
      credentials: 'include',
    });
    const data = await res.json();
    setUser(data.user);
    setToken(data.accessToken);
  }

  function logout() {
    fetch('/api/auth/logout', { method: 'POST', credentials: 'include' });
    setUser(null);
    setToken(null);
  }

  return (
    <AuthContext.Provider value={{ user, token, loading, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

function useAuth() {
  return useContext(AuthContext);
}
```

## 💻 ログイン必須ページ（保護ルート）

```jsx
function ProtectedRoute({ children }) {
  const { user, loading } = useAuth();
  if (loading) return <Spinner />;
  if (!user) return <Navigate to="/login" replace />;
  return children;
}

// 使う側
<Route path="/dashboard" element={
  <ProtectedRoute><Dashboard /></ProtectedRoute>
} />
```

## 💻 APIに自動でトークンを付ける

### fetch ラッパー

```jsx
function useApi() {
  const { token } = useAuth();

  return async (url, options = {}) => {
    const res = await fetch(url, {
      ...options,
      headers: {
        'Content-Type': 'application/json',
        ...(token && { Authorization: `Bearer ${token}` }),
        ...options.headers,
      },
    });
    if (res.status === 401) {
      // 自動でリフレッシュ
    }
    return res;
  };
}
```

### axios インターセプタ

```jsx
import axios from 'axios';

const api = axios.create({ baseURL: '/api' });

api.interceptors.request.use((config) => {
  const token = getToken(); // どこかで取得
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
```

## 💻 トークンの自動更新（リフレッシュ）

```jsx
api.interceptors.response.use(
  (res) => res,
  async (err) => {
    if (err.response?.status === 401) {
      try {
        const { data } = await axios.post('/api/auth/refresh', {}, { withCredentials: true });
        setToken(data.accessToken);
        // リトライ
        err.config.headers.Authorization = `Bearer ${data.accessToken}`;
        return axios(err.config);
      } catch {
        // リフレッシュ失敗 → ログアウト
        logout();
      }
    }
    return Promise.reject(err);
  }
);
```

ユーザーは**ログアウトされずに使い続けられる**。

## 🛡️ セキュリティ注意点

### XSS（クロスサイトスクリプティング）

不正なJSが画面に注入されると、localStorageのトークンが盗まれる。

→ **localStorage にトークンを置かない**、httpOnly cookie にする。

### CSRF（クロスサイトリクエストフォージェリ）

別サイトから cookie が自動送信される攻撃。

→ **CSRFトークン**、または **SameSite=Strict** cookie。

### React の自動エスケープ

JSXで `{userInput}` は自動でエスケープされる：

```jsx
const userInput = '<script>alert("XSS")</script>';
return <div>{userInput}</div>; // 文字列として表示、実行されない
```

ただし `dangerouslySetInnerHTML` は要注意。詳しくは [[14-4-セキュリティ基礎]]。

## ❌ よくある間違い

### localStorage に JWT を保存

→ XSS 1発でアウト。**できれば httpOnly cookie**。

### ログアウトしてもトークンを消し忘れる

```jsx
function logout() {
  setUser(null); // ❌ token は残ったまま
}
```

→ ✅ トークン・ユーザー両方クリア。

### リロードでログアウトされる

→ memory 保持だけだと消える。**リフレッシュトークン**で再ログインを実装。

### ログイン状態が AuthProvider 外で取れない

→ AuthProvider をアプリ最上位に置く。

---

## ✅ ベストプラクティス

1. **アクセストークンは memory + 短命（5-15分）**
2. **リフレッシュトークンは httpOnly cookie + 長命**
3. **401で自動リフレッシュ + リトライ**
4. **保護ルートはコンポーネントで判定**
5. **ログアウト時はすべて消す**

- ログイン後はダッシュボードへ
- リロードしてもログイン状態を保つ

## 📝 まとめ

- ログイン状態は AuthContext で共有
- アクセストークンは memory、リフレッシュは cookie
- 401で自動リフレッシュ
- localStorage は XSS リスクで避ける
