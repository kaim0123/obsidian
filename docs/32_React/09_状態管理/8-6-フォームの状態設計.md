# 8-6. フォームの状態設計（入力・バリデーション・送信中）

## 🎯 この章で学ぶこと

- フォームに必要な3種類の状態
- バリデーションのタイミング
- 送信ボタンの有効/無効・送信中表示

---

## 📖 概念の説明

### フォームに必要な状態

```text
フォーム = 入力値 + エラー + ステータス
```

| 状態 | 例 |
| --- | --- |
| **入力値** | { name: '太郎', email: 'a@b.c' } |
| **エラー** | { name: '', email: 'メール形式が違います' } |
| **ステータス** | 'idle' / 'submitting' / 'success' / 'error' |

---

## 💻 最小実装：手書き

```jsx
function ContactForm() {
  const [values, setValues] = useState({ name: '', email: '' });
  const [errors, setErrors] = useState({});
  const [status, setStatus] = useState('idle');

  function validate() {
    const errs = {};
    if (!values.name) errs.name = '名前は必須です';
    if (!/^.+@.+\..+$/.test(values.email)) errs.email = 'メール形式が違います';
    return errs;
  }

  async function handleSubmit(e) {
    e.preventDefault();
    const errs = validate();
    setErrors(errs);
    if (Object.keys(errs).length > 0) return;

    setStatus('submitting');
    try {
      await fetch('/api/contact', { method: 'POST', body: JSON.stringify(values) });
      setStatus('success');
    } catch {
      setStatus('error');
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={values.name}
        onChange={(e) => setValues({ ...values, name: e.target.value })}
      />
      {errors.name && <p style={{ color: 'red' }}>{errors.name}</p>}

      <input
        value={values.email}
        onChange={(e) => setValues({ ...values, email: e.target.value })}
      />
      {errors.email && <p style={{ color: 'red' }}>{errors.email}</p>}

      <button disabled={status === 'submitting'}>
        {status === 'submitting' ? '送信中...' : '送信'}
      </button>

      {status === 'success' && <p>送信しました！</p>}
    </form>
  );
}
```

## 💡 バリデーションのタイミング

| タイミング | UX |
| --- | --- |
| **入力中** | リアルタイムだがうるさい |
| **blur（フォーカス外す）時** | 入力後に表示。バランス◎ |
| **submit時** | 最後にまとめてチェック |

→ **blurで個別バリデーション + submitで全体チェック**が一般的。

```jsx
<input
  value={values.email}
  onChange={...}
  onBlur={() => {
    if (!/^.+@.+\..+$/.test(values.email)) {
      setErrors((p) => ({ ...p, email: 'メール形式が違います' }));
    }
  }}
/>
```

## 💻 React Hook Form（実務でよく使う）

手書きはフォームが大きくなると面倒。**react-hook-form** でシンプルに。

```bash
npm install react-hook-form zod @hookform/resolvers
```

```jsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const schema = z.object({
  name: z.string().min(1, '必須です'),
  email: z.string().email('メール形式が違います'),
});

function ContactForm() {
  const { register, handleSubmit, formState: { errors, isSubmitting } } = useForm({
    resolver: zodResolver(schema),
  });

  const onSubmit = async (data) => {
    await fetch('/api/contact', { method: 'POST', body: JSON.stringify(data) });
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('name')} />
      {errors.name && <p>{errors.name.message}</p>}

      <input {...register('email')} />
      {errors.email && <p>{errors.email.message}</p>}

      <button disabled={isSubmitting}>
        {isSubmitting ? '送信中...' : '送信'}
      </button>
    </form>
  );
}
```

→ コードがすっきり。バリデーションは zod で型 + ルール。

## 💻 送信ボタンの状態

```jsx
<button
  type="submit"
  disabled={!isValid || isSubmitting}
>
  {isSubmitting ? <Spinner /> : '送信'}
</button>
```

ポイント：

- **空・エラーなら disabled**
- **送信中も disabled**（二重送信防止）
- **送信中はローディング表示**

詳しくは [[8-8-送信フローの状態管理]]。

---

## 💡 フォーム内のボタンは `type` を明示する

フォームの中では、`<button>` の `type` を省略すると送信（`submit`）扱いになりやすいので注意。

- **送信**: `type="submit"`
- **送信以外（編集/追加/プレビュー等）**: `type="button"`

---

## ❌ よくある間違い

### バリデーションをsubmitだけ

→ ユーザーが間違えても、最後まで入力してから怒られる。

### エラー文を消し忘れる

→ 直したのにエラーが消えない。`onChange` で対応するエラーを消す。

### 送信中フラグ忘れ

→ ボタン連打で多重送信。

### controlled / uncontrolled の混在

→ 警告がポンポン出る。どちらかに統一。

---

## ✅ ベストプラクティス

1. **3種類の状態（値・エラー・ステータス）**を意識
2. **大きいフォームは react-hook-form**
3. **バリデーションは zod など共通スキーマ**
4. **送信中は disabled + ローディング**
5. **クライアント検証は補助、最終はサーバ**

- パスワード（8文字以上、英数字含む）
- パスワード確認（一致チェック）

react-hook-form + zod で実装。

## 📝 まとめ

- フォーム状態 = 値 + エラー + ステータス
- 大規模なら react-hook-form
- バリデーションは blur + submit
- 送信中は disabled + ローディング
