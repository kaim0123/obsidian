# 7-5 データ取得ライブラリ（TanStack Query概観）

## 🎯 この章で学ぶこと

- データ取得ライブラリ（TanStack Query）の存在意義を理解できます
- `useQuery` でデータを取得する基本パターンを覚えます
- `useMutation` でデータを更新する基本パターンを覚えます
- 自分でfetchを書くのと、ライブラリを使うのとの違いが分かります
- いつライブラリを導入すべきかの判断ができるようになります

## 📖 概念の説明

### 自前fetchの限界

これまで `fetch` + `useState` + `useEffect` でデータ取得を書いてきました。これでも動きますが、規模が大きくなると次の問題が出てきます。

- **キャッシュがない**：同じデータを何度も取りに行く
- **再取得のロジックを毎回書く**：フォーカス時や定期的に更新したい
- **ローディング・エラーの管理が煩雑**：4状態管理が画面ごとに散らばる
- **複数の画面で同じデータを使うと二重に取る**
- **更新後の再取得を手動で書く**

これらを **解決してくれる専用ライブラリ** が、TanStack Query（旧名：React Query）や SWR です。

例えるなら、自前fetchは **手書きの帳簿**、ライブラリは **会計ソフト**。手書きでもできますが、規模が大きくなると会計ソフトを使った方が早くて間違いが少ないですよね。

### TanStack Query とは

**TanStack Query**（公式：[tanstack.com/query](https://tanstack.com/query)）は、サーバー由来の状態を専門に管理するライブラリです。主な特徴：

- 自動キャッシュ
- 自動再取得（フォーカス時、ネットワーク復旧時、間隔指定）
- ローディング・エラー状態を自動管理
- 楽観的更新サポート
- DevToolsで状態を可視化

主な登場人物：

- `QueryClient`：キャッシュを管理する司令塔
- `useQuery`：データを取得して使う
- `useMutation`：データを変更（POST/PUT/DELETE）する
- `queryKey`：キャッシュのキー（住所みたいなもの）

### useQuery と useMutation

「**読む**（query）」と「**書く**（mutation）」で関数が分かれています。

| | useQuery | useMutation |
|---|---|---|
| 主な用途 | GET | POST/PUT/DELETE |
| いつ走る？ | マウント時に自動 | `mutate()` を呼んだとき |
| キャッシュ | する | しない |
| 再取得 | サポート | しない |

### 用語の整理

- **TanStack Query**：データ取得ライブラリ
- **queryKey**：キャッシュ識別用のキー（配列）
- **stale**：「古い」データの状態（要確認）
- **fresh**：「新鮮な」データの状態（再取得不要）
- **invalidate**：キャッシュを「古い」とマークすること

## 💻 コード例

### 例1：インストールとセットアップ

```bash
npm install @tanstack/react-query
```

```jsx
// main.jsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const queryClient = new QueryClient();

createRoot(document.getElementById('root')).render(
  <QueryClientProvider client={queryClient}>
    <App />
  </QueryClientProvider>
);
```

`QueryClientProvider` でアプリ全体を包みます。これでアプリ内のどこでも `useQuery` が使えます。

### 例2：useQuery の基本

```jsx
import { useQuery } from '@tanstack/react-query';

async function fetchUsers() {
  const res = await fetch('/api/users');
  if (!res.ok) throw new Error('取得失敗');
  return res.json();
}

function UserList() {
  const { data, isLoading, error } = useQuery({
    queryKey: ['users'],          // キャッシュのキー
    queryFn: fetchUsers,           // 取得関数
  });

  if (isLoading) return <p>読み込み中...</p>;
  if (error) return <p>エラー: {error.message}</p>;
  return <ul>{data.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}
```

`useState` も `useEffect` も書いていません。**3行で取得・キャッシュ・状態管理がすべて完了** です。

### 例3：パラメータ付きのクエリ

```jsx
function UserDetail({ id }) {
  const { data, isLoading, error } = useQuery({
    queryKey: ['user', id], // idもキーに含める
    queryFn: async () => {
      const res = await fetch(`/api/users/${id}`);
      if (!res.ok) throw new Error('取得失敗');
      return res.json();
    },
  });

  if (isLoading) return <p>...</p>;
  if (error) return <p>エラー</p>;
  return <h1>{data.name}</h1>;
}
```

`queryKey` に `id` を含めると、`id` ごとに別キャッシュとして扱われます。

### 例4：キャッシュの活用

```jsx
// 同じqueryKeyを使えば、別コンポーネントでもキャッシュを共有
function Header() {
  const { data: user } = useQuery({ queryKey: ['me'], queryFn: fetchMe });
  return <p>こんにちは、{user?.name}さん</p>;
}

function Sidebar() {
  // Headerと同じキャッシュを使うのでfetchは1回だけ
  const { data: user } = useQuery({ queryKey: ['me'], queryFn: fetchMe });
  return <p>権限：{user?.role}</p>;
}
```

同じ `queryKey` なら **複数コンポーネントで使ってもfetchは1回だけ**。これがキャッシュの威力です。

### 例5：useMutation で更新

```jsx
import { useMutation, useQueryClient } from '@tanstack/react-query';

async function createUser(user) {
  const res = await fetch('/api/users', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(user),
  });
  if (!res.ok) throw new Error('作成失敗');
  return res.json();
}

function NewUserForm() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: createUser,
    onSuccess: () => {
      // 成功したらユーザー一覧キャッシュを無効化（再取得を促す）
      queryClient.invalidateQueries({ queryKey: ['users'] });
    },
  });

  const handleSubmit = (e) => {
    e.preventDefault();
    const name = e.target.name.value;
    mutation.mutate({ name });
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="name" />
      <button disabled={mutation.isPending}>
        {mutation.isPending ? '送信中...' : '追加'}
      </button>
      {mutation.isError && <p>エラー: {mutation.error.message}</p>}
    </form>
  );
}
```

`mutate()` を呼び出すとリクエストが走ります。成功時の `invalidateQueries` で、関連する一覧を自動で再取得できます。

### 例6：オプション例

```jsx
useQuery({
  queryKey: ['products'],
  queryFn: fetchProducts,
  staleTime: 5 * 60 * 1000,    // 5分間は「新鮮」として扱う（refetchしない）
  gcTime: 10 * 60 * 1000,       // 10分使われなかったらキャッシュ破棄
  refetchOnWindowFocus: true,    // ウィンドウフォーカス時に再取得（デフォルトtrue）
  retry: 2,                       // 失敗時2回リトライ
});
```

オプションで挙動を細かくチューニングできます。

### 例7：自前 useEffect との比較

```jsx
// ❌ 自前で書くと長い
function Bad() {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    fetch('/api/users', { signal: controller.signal })
      .then(r => { if (!r.ok) throw new Error('失敗'); return r.json(); })
      .then(setData)
      .catch(e => { if (e.name !== 'AbortError') setError(e); })
      .finally(() => setLoading(false));
    return () => controller.abort();
  }, []);

  if (loading) return <p>...</p>;
  if (error) return <p>{error.message}</p>;
  return <ul>{data.map(...)}</ul>;
}

// ✅ TanStack Query なら短い
function Good() {
  const { data, isLoading, error } = useQuery({
    queryKey: ['users'],
    queryFn: () => fetch('/api/users').then(r => r.json()),
  });

  if (isLoading) return <p>...</p>;
  if (error) return <p>{error.message}</p>;
  return <ul>{data.map(...)}</ul>;
}
```

**書く量が3分の1以下、しかも機能は多い** という嬉しさです。

### 例8：DevTools

```jsx
import { ReactQueryDevtools } from '@tanstack/react-query-devtools';

<QueryClientProvider client={queryClient}>
  <App />
  <ReactQueryDevtools initialIsOpen={false} />
</QueryClientProvider>
```

開発時にキャッシュの状態を可視化できる神ツール。導入を強くおすすめします。

## ❌ よくある間違い

### 1. queryKey にパラメータを含め忘れる

```jsx
// ❌ idが変わってもキャッシュキーが同じ
useQuery({
  queryKey: ['user'],
  queryFn: () => fetch(`/api/users/${id}`).then(r => r.json()),
});

// ✅ idもキーに含める
useQuery({
  queryKey: ['user', id],
  queryFn: () => fetch(`/api/users/${id}`).then(r => r.json()),
});
```

### 2. queryFn の中でエラーを throw しない

```jsx
// ❌ エラーが発生しても error として扱われない
queryFn: async () => {
  const res = await fetch('/api/users');
  return res.json(); // 4xx/5xxでもこれは成功扱いに
}

// ✅ res.okチェックで例外を投げる
queryFn: async () => {
  const res = await fetch('/api/users');
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}
```

### 3. mutate の後に invalidateQueries を呼び忘れる

```jsx
// ❌ POSTしても一覧が更新されない
useMutation({ mutationFn: createUser });
```

`onSuccess` で関連クエリを invalidate するのを忘れずに。

### 4. すべてを TanStack Query で管理しようとする

UI状態（モーダルの開閉、フォーム入力中の値など）はTanStack Queryの管轄外。**サーバー由来の状態だけ** に使いましょう。UI状態は `useState` や Zustand で。

### 5. ライブラリを入れずに頑張りすぎる

シンプルなアプリなら自前で十分ですが、画面が10を超えてくると、自前管理は破綻します。早めに導入を検討しましょう。

## ✅ ベストプラクティス

1. **サーバー状態にはTanStack Query**：UI状態と分離して管理。
2. **queryKey はパラメータも含めて配列で**：`['user', id]`、`['posts', { page, q }]`。
3. **queryFn は必ずエラーをthrow**：`res.ok`チェックを忘れない。
4. **mutation 成功時には関連 invalidate**：データの一貫性を保つ。
5. **DevToolsを入れる**：キャッシュの動きが目で見えると理解が早い。

### 発展課題

- DevToolsを入れて、キャッシュの状態を観察してみる
- 削除（DELETE）も `useMutation` で実装する
- `staleTime` を調整して、再取得の頻度を変えてみる

## 📝 まとめ

- TanStack Query はサーバー状態専用の管理ライブラリ
- `useQuery` で取得、`useMutation` で更新
- 自前fetchより圧倒的に短く、機能豊富
- `queryKey` がキャッシュの住所
- 規模が大きくなったら導入を検討
