# 7-3 ローディング/エラー/空状態（UXの型）

## 🎯 この章で学ぶこと

- データ取得画面に必要な「4つの状態」を理解できます
- それぞれの状態に最適なUI表現を学びます
- 「データが空」と「読み込み中」を混同しないための設計パターンが分かります
- スケルトンスクリーン、エラーバウンダリなど現代的なUXパターンを知ります
- 状態遷移を意識した、堅牢な画面設計ができるようになります

## 📖 概念の説明

### データ取得画面の4つの状態

非同期にデータを取得する画面には、必ず次の4つの状態があります。

1. **ローディング（loading）**：取得中。まだデータが来ていない
2. **エラー（error）**：取得に失敗した
3. **空（empty）**：取得は成功したが、結果が0件
4. **成功（success）**：データが取れて、表示できる

これらをすべて考慮するのが「**UXの型**」です。一つでも抜けていると、ユーザーは「画面が真っ白で何も起きない」「クラッシュした？」と不安になります。

例えるなら、**レストランの店員さんの対応** です。

- 注文受付 → 「ただいまお作りしております」（loading）
- 失敗 → 「申し訳ありません、品切れでした」（error）
- 結果なし → 「該当する料理は本日ありません」（empty）
- 成功 → 料理がテーブルに来る（success）

すべての場面で「いま何が起きているか」がユーザーに伝わるようにするのが大事。

### ローディングUIのパターン

**スピナー**：くるくる回るやつ。シンプルだが「いつ終わるか分からない」感じが残る
**プログレスバー**：％で進捗を見せる。ファイルアップロードなどで
**スケルトンスクリーン**：画面の骨組みだけ先に出す。見栄えがよく、現代の主流
**楽観表示**：先に結果が出るかのように見せる（後の章で扱う）

### エラーUIのポイント

- 何が起きたか
- どうすれば直るか
- 復旧手段（再試行ボタン）

を提供します。「Error」だけ出して終わりにしない。

### 空状態（empty state）の重要性

「該当データなし」のときに何も表示しないのはNG。**「結果がありません」と明示する** のが基本。場合によっては、

- 検索条件を変えるヒント
- 新規作成ボタン
- イラストや絵文字での雰囲気づくり

を入れると親切です。

### 用語の整理

- **ローディング状態**：データ取得中
- **エラー状態**：取得失敗
- **空状態（empty state）**：データはあるが0件
- **スケルトンスクリーン**：データの形をした「灰色の枠」を先に表示するUI
- **エラーバウンダリ（error boundary）**：子コンポーネントのエラーをキャッチするReact機能

## 💻 コード例

### 例1：4状態をすべて扱うコンポーネント

```jsx
import { useEffect, useState } from 'react';

function ProductList() {
  const [products, setProducts] = useState(null); // 初期値はnull（未取得）
  const [error, setError] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch('/api/products')
      .then(r => {
        if (!r.ok) throw new Error('取得失敗');
        return r.json();
      })
      .then(data => setProducts(data))
      .catch(err => setError(err))
      .finally(() => setLoading(false));
  }, []);

  // 1. ローディング
  if (loading) return <p>読み込み中...</p>;

  // 2. エラー
  if (error) return (
    <div>
      <p>エラーが発生しました：{error.message}</p>
      <button onClick={() => location.reload()}>再読み込み</button>
    </div>
  );

  // 3. 空
  if (!products || products.length === 0) {
    return <p>商品が見つかりませんでした。</p>;
  }

  // 4. 成功
  return (
    <ul>
      {products.map(p => <li key={p.id}>{p.name}</li>)}
    </ul>
  );
}
```

ポイントは **`if` で早期リターンを並べて状態ごとにUIを切り替える** こと。

### 例2：Empty を区別する重要性

```jsx
// ❌ 空とローディングを混同
function Bad() {
  const [items, setItems] = useState([]); // 初期値は空配列

  useEffect(() => {
    fetch('/api/items').then(r => r.json()).then(setItems);
  }, []);

  if (items.length === 0) return <p>データがありません</p>;
  // ↑ 取得中でも「データがありません」と出てしまう！
}
```

初期値を `null` や `undefined` にして、「未取得」と「空配列」を明確に区別しましょう。

```jsx
// ✅ nullで未取得、[]で空、要素ありで成功、と区別
function Good() {
  const [items, setItems] = useState(null);
  const [loading, setLoading] = useState(true);

  // ...

  if (loading) return <p>読み込み中</p>;
  if (!items || items.length === 0) return <p>データがありません</p>;
  return <ul>{items.map(...)}</ul>;
}
```

### 例3：スケルトンスクリーン

```jsx
function ProductSkeleton() {
  return (
    <div className="skeleton">
      <div className="skeleton-image" style={{ width: 200, height: 200, background: '#eee' }} />
      <div className="skeleton-line" style={{ width: '80%', height: 16, background: '#eee', marginTop: 8 }} />
      <div className="skeleton-line" style={{ width: '60%', height: 16, background: '#eee', marginTop: 4 }} />
    </div>
  );
}

function ProductList({ loading, products }) {
  if (loading) {
    return (
      <div>
        {[...Array(3)].map((_, i) => <ProductSkeleton key={i} />)}
      </div>
    );
  }
  // ...
}
```

「読み込み中…」と書く代わりに、データが来る場所の骨組みを表示します。**実際のレイアウトに近い形** のため、表示完了時のガタつきが少なくなります。

### 例4：エラーUIに復旧手段をつける

```jsx
function ErrorBox({ error, onRetry }) {
  return (
    <div role="alert" style={{ padding: 16, background: '#fee', border: '1px solid #f88' }}>
      <h3>エラーが発生しました</h3>
      <p>{error.message}</p>
      <button onClick={onRetry}>もう一度試す</button>
    </div>
  );
}

// 使う側
function UserList() {
  const [error, setError] = useState(null);
  const [users, setUsers] = useState(null);

  const load = () => {
    setError(null);
    fetch('/api/users').then(r => r.json()).then(setUsers).catch(setError);
  };

  useEffect(load, []);

  if (error) return <ErrorBox error={error} onRetry={load} />;
  // ...
}
```

エラーは「ただ表示する」のではなく、ユーザーに **次の行動を促す** ようにします。

### 例5：エラーバウンダリ

レンダリング中の予期しないエラー（`undefined.foo` など）をキャッチするには、**エラーバウンダリ** を使います。

```jsx
import React from 'react';

class ErrorBoundary extends React.Component {
  state = { error: null };

  static getDerivedStateFromError(error) {
    return { error };
  }

  render() {
    if (this.state.error) {
      return <p>予期しないエラー：{this.state.error.message}</p>;
    }
    return this.props.children;
  }
}

// 使い方
<ErrorBoundary>
  <App />
</ErrorBoundary>
```

ただし、エラーバウンダリは **同期エラー** だけをキャッチします。fetch などの非同期エラーは `try/catch` で自分で処理する必要があります。

### 例6：空状態を魅力的に

```jsx
function EmptyState({ title, message, actionLabel, onAction }) {
  return (
    <div style={{ textAlign: 'center', padding: 40 }}>
      <div style={{ fontSize: 48 }}>📦</div>
      <h3>{title}</h3>
      <p style={{ color: '#666' }}>{message}</p>
      {actionLabel && <button onClick={onAction}>{actionLabel}</button>}
    </div>
  );
}

// 使う側
{products.length === 0 && (
  <EmptyState
    title="商品がまだ登録されていません"
    message="最初の商品を追加してみましょう"
    actionLabel="新規追加"
    onAction={() => navigate('/products/new')}
  />
)}
```

空状態は「**次の一歩を提示するチャンス**」と捉えます。

### 例7：状態をstateMachine的にまとめる

```jsx
// 状態を明示的に1つの変数で表現
const [state, setState] = useState({ status: 'idle' });
// status: 'idle' | 'loading' | 'success' | 'error'

useEffect(() => {
  setState({ status: 'loading' });
  fetch('/api/items')
    .then(r => r.ok ? r.json() : Promise.reject(new Error(`HTTP ${r.status}`)))
    .then(data => setState({ status: 'success', data }))
    .catch(error => setState({ status: 'error', error }));
}, []);

if (state.status === 'idle') return null;
if (state.status === 'loading') return <Spinner />;
if (state.status === 'error') return <ErrorBox error={state.error} />;
if (state.data.length === 0) return <EmptyState />;
return <List items={state.data} />;
```

この書き方だと「ありえない組み合わせ」（loading=trueなのにdataがある、など）を未然に防げます。

## ❌ よくある間違い

### 1. ローディング表示を入れない

「データが来るまで真っ白」になると、ユーザーは固まったかと思います。最低でも「読み込み中」の文言を出しましょう。

### 2. 空配列を初期値にして空状態と取り違える

```jsx
const [items, setItems] = useState([]); // ❌ 未取得と空が同じ
```

`null` を初期値にして区別しましょう。

### 3. エラーメッセージが英語のまま

`Failed to fetch` をそのまま見せても、一般ユーザーには分かりません。日本語で「ネットワーク接続を確認してください」など、文脈に合わせて表示しましょう。

### 4. リトライ手段を提供しない

エラーが出たら、ユーザーは何もできずにページを離れるしかない。再試行ボタンや更新ボタンを必ず付けましょう。

### 5. すべての状態に専用UIを作って肥大化

シンプルなスピナーで十分なところに、凝ったスケルトンを作るとオーバーエンジニアリング。**画面の重要度に応じて使い分け** ましょう。

## ✅ ベストプラクティス

1. **4状態（loading/error/empty/success）を毎回意識する**：チェックリスト化すると忘れません。
2. **スケルトンスクリーンで体感速度を上げる**：実際の表示位置にUIを置く。
3. **エラーには復旧手段を**：再試行・リロード・サポート連絡先など。
4. **空状態にも価値を与える**：「次の一歩」を提示する。
5. **状態をstate machine的にまとめる**：ありえない組み合わせを排除。

## 🔬 実践演習

### お題：4状態をすべて表示するリスト

`/api/users` を取得するコンポーネントを作り、

- ローディング中：スピナー（または「読み込み中...」）
- エラー：エラーメッセージ＋再試行ボタン
- 0件：「ユーザーが見つかりません」＋追加ボタン
- 1件以上：リスト表示

の4つを実装してみましょう。それぞれの状態を意図的に再現して動作確認します。

### 発展課題

- スケルトンスクリーンを実装してみる
- 状態を `status` フィールドでまとめて、stateMachine的に書き換える

## 📝 まとめ

- データ取得画面には4状態（loading / error / empty / success）がある
- 「未取得」と「空」は別物。初期値の選び方に注意
- ローディングは「いま何が起きているか」をユーザーに伝える
- エラーは「次にどうすべきか」を示す
- 空状態は「次の一歩」を提示できる絶好の機会
