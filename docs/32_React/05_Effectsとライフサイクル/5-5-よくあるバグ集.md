# 5-5 よくあるバグ集（無限ループ、stale closure）

## 🎯 この章で学ぶこと

- `useEffect` で起こる代表的なバグの「仕組み」を理解できます
- 無限ループ（infinite loop）の原因と直し方を覚えます
- 古い値を見続けるバグ「stale closure（古いクロージャ）」が分かります
- バグを未然に防ぐためのチェック観点を持てるようになります
- ESLintや React DevTools を使った検出方法を知ります

## 📖 概念の説明

### バグ1：無限ループ

`useEffect` の中で `setState` を呼ぶと、再レンダーが起きます。再レンダーが起きると、依存配列の中身が変わっていればまた `useEffect` が走ります。これがループになると **無限ループ** です。

例えるなら、**鏡を向かい合わせに置いた合わせ鏡** のようなものです。一度始まると止まりません。ブラウザがフリーズしたり、CPUが100%に張り付いたりします。

### バグ2：stale closure（古いクロージャ）

これは少し難しい概念です。**JavaScriptの関数は、自分が作られたときの周りの変数を覚えています**。これを **クロージャ（closure）** と呼びます。

```js
function makeCounter() {
  let count = 0;
  return () => count++; // 内側の関数が外側のcountを覚えている
}
```

Reactのコンポーネントは毎レンダーごとに関数全体が再実行されます。つまり、**毎レンダーで新しい変数・新しい関数が作られている** ということ。

ところが、`useEffect` に渡した関数が「**古いレンダーで作られたまま**」だと、その中の変数も古いままになってしまいます。これが **stale closure（古いクロージャ）** です。

例えるなら、**昔の日記に書かれた住所** のようなもの。今の住所ではないので、そこに手紙を出しても届きません。

### バグ3：依存配列を「うそつき」したことによる不整合

依存配列に必要な値を入れないと、Effectは古い値を見続けます。これは無限ループの逆で、**「全然走らない」「古い値で走る」** バグになります。ESLintの `exhaustive-deps` 警告を消してしまうと、ほぼ確実に発生します。

### バグ4：propsをstateに入れたのに、更新が反映されない

`useState(props.x)` のように props を初期値として state に入れると、**初回レンダーで1回だけ** コピーされます。親から新しいpropsが来ても、子のstateは勝手には更新されません。

「子側で編集したいからstateに持つ」など理由がある場合は、propsの変化に追従して同期が必要です（例は [[5-2-依存配列の読み方]] の深掘り参照）。

### 用語の整理

- **無限ループ**：終わらない繰り返し処理
- **クロージャ**：関数が自分の外側の変数を覚えている仕組み
- **stale closure**：古い変数を覚えている関数
- **冪等性**：何回実行しても結果が同じであること

## 💻 コード例

### バグ例1：オブジェクトをstateに入れて無限ループ

```jsx
// ❌ 無限ループする
function Bad() {
  const [data, setData] = useState({});

  useEffect(() => {
    setData({ value: Math.random() }); // 毎回新しいオブジェクト
  }, [data]); // dataが「変わった」と判定されてまた走る → 無限ループ
}
```

これは「依存に入れたものを、Effectの中で毎回作り直して更新している」ためのループです。

**直し方**：そもそもこのEffectは何のために書いたのかを問い直します。多くの場合、`useEffect` 自体が不要です。

```jsx
function Good() {
  // マウント時1回だけ作るならuseStateの初期値で十分
  const [data] = useState({ value: Math.random() });
}
```

### バグ例2：依存配列を空にして「初回だけ」を狙うが、古い値を見るバグ

```jsx
// ❌ stale closureの典型例
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1); // ← 0+1, 0+1, 0+1... ずっと1のまま
    }, 1000);
    return () => clearInterval(id);
  }, []); // 空配列だからEffectは1回しか作られない
  //         → setIntervalの中の関数も初回のcount=0を覚え続ける
}
```

毎秒 `count` が増えると思いきや、**ずっと1のまま** です。これがstale closureです。

**直し方1：関数形式の更新**

```jsx
useEffect(() => {
  const id = setInterval(() => {
    setCount(c => c + 1); // ← 前回値を引数で受け取る形なら最新が見える
  }, 1000);
  return () => clearInterval(id);
}, []);
```

**直し方2：依存に入れる**（ただし毎秒タイマーが張り直される）

```jsx
useEffect(() => {
  const id = setInterval(() => setCount(count + 1), 1000);
  return () => clearInterval(id);
}, [count]); // countが変わるたびにタイマーを張り直す
```

### バグ例3：Effectの中で配列を更新して無限ループ

```jsx
// ❌ ループ
function Bad({ items }) {
  const [sorted, setSorted] = useState([]);

  useEffect(() => {
    setSorted([...items].sort()); // 毎回新しい配列
  }, [sorted]); // ← sortedを依存に入れてしまった
}
```

**直し方**：そもそも派生値はEffectで作らず、レンダリング中に計算します。

```jsx
function Good({ items }) {
  const sorted = useMemo(() => [...items].sort(), [items]);
  return <ul>{sorted.map(x => <li key={x}>{x}</li>)}</ul>;
}
```

### バグ例4：イベントハンドラ内でstale closure

```jsx
// ❌ ボタンを押すと0を表示してしまう
function Bad() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    function handle() {
      alert(count); // 古いcountを覚えている
    }
    window.addEventListener('click', handle);
    return () => window.removeEventListener('click', handle);
  }, []); // 空依存だと、handleは初回のcount=0を覚えたまま
}
```

**直し方**：依存に入れて、イベントを張り直す。

```jsx
useEffect(() => {
  function handle() {
    alert(count);
  }
  window.addEventListener('click', handle);
  return () => window.removeEventListener('click', handle);
}, [count]); // countが変わるたびに張り直す
```

または、`useRef` で最新値を保持するパターンもあります。

```jsx
function Better() {
  const [count, setCount] = useState(0);
  const countRef = useRef(count);
  countRef.current = count; // 毎レンダーで最新値に更新

  useEffect(() => {
    function handle() {
      alert(countRef.current); // 常に最新
    }
    window.addEventListener('click', handle);
    return () => window.removeEventListener('click', handle);
  }, []);
}
```

### バグ例5：「変わってないつもり」のオブジェクト依存

```jsx
// ❌ propsで毎回新しいオブジェクト
function Child({ options }) {
  useEffect(() => {
    init(options);
  }, [options]); // 親が <Child options={{a: 1}} /> なら毎レンダー走る
}
```

**直し方**：プリミティブに分解する、または `useMemo` で参照を固定する。

## ❌ よくある間違い

### 1. 「依存に入れると無限ループするから」と外す

これは99%バグの先送りです。無限ループになるのは **Effectの中で依存値を更新している** 設計の問題です。設計を見直しましょう。

### 2. 関数形式の `setState` を使わない

カウンターやタイマーで `setCount(count + 1)` と書くと、stale closureに引っかかります。`setCount(c => c + 1)` を覚えると一気に安全になります。

### 3. ESLintの警告を `disable` で消す

`// eslint-disable-next-line react-hooks/exhaustive-deps` は最後の手段です。書く前に、**設計の見直し** や **`useEffectEvent`（実験的）/`useRef`** のパターンを検討してください。

### 4. 配列・オブジェクトを依存に入れて忘れる

`[]` リテラル、`{}` リテラル、関数リテラルは毎回新しい参照になります。依存に入れたら、参照を固定する仕組みが必要です。

## ✅ ベストプラクティス

1. **無限ループのサインを覚える**：ブラウザのCPUが上がる、コンソールが大量にログを吐く、アプリがフリーズする → Effectをまず疑います。
2. **`setState(c => ...)` の関数形式を積極的に使う**：stale closureを根本的に避けられます。
3. **派生値はEffectで作らず、レンダー中に計算する**：`useMemo` も活用。
4. **ESLint `exhaustive-deps` を有効にしておく**：警告を読むクセをつけます。
5. **困ったらカスタムフックに切り出す**：Effectが複雑になったら、それは関心の分離が足りていないサインです。

## 🔬 実践演習

### お題：stale closureを再現して直す

毎秒カウントアップするタイマーを作ってみましょう。最初は `setCount(count + 1)` で書いて、stale closureで止まることを確認します。次に `setCount(c => c + 1)` に直して、正しく動くことを確認しましょう。

### 発展課題

- 親から渡された関数を依存に入れて、無限に走ってしまう状況を作り、`useCallback` で解決しましょう
- React DevToolsの「Why did this render?」機能を使って、再レンダーの原因を特定してみましょう

## 📝 まとめ

- 無限ループは「Effectの中で依存値を更新している」のが原因
- stale closureは「古いレンダー時の値を覚えている関数」が原因
- `setState(c => ...)` の関数形式が強力な味方
- 依存配列の **嘘** は未来のあなたを苦しめます
- ESLintの警告は読み飛ばさず、設計を見直すきっかけにしましょう
