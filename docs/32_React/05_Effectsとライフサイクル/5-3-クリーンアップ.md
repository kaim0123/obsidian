# 5-3 クリーンアップ（購読解除・タイマー）

## 🎯 この章で学ぶこと

- 「クリーンアップ関数」とは何かを理解できます
- なぜ後始末をしないとマズいのか（メモリリーク・重複購読）を学びます
- タイマー・イベントリスナー・WebSocketなどの典型的な後始末パターンを覚えます
- クリーンアップが走るタイミング（再実行直前・アンマウント時）を把握できます
- 「セットしたものは必ず外す」習慣を身につけられます

## 📖 概念の説明

### クリーンアップって何？

`useEffect` の中で **戻り値として関数を返すと**、Reactはその関数を「**後始末用の関数**」として覚えてくれます。これを **クリーンアップ関数（cleanup function）** と呼びます。

```jsx
useEffect(() => {
  // 何かをセットアップする
  const id = setInterval(() => console.log('tick'), 1000);

  // ↓ 戻り値の関数がクリーンアップ関数
  return () => {
    clearInterval(id); // 後始末
  };
}, []);
```

例えるなら、**ホテルにチェックインしたらチェックアウトする** ようなものです。チェックインだけして帰らなければ、部屋は永遠に使用中のまま。Reactの世界でも、開いたものは閉じる、購読したら解除する、というのが鉄則です。

### いつクリーンアップが走る？

クリーンアップ関数は、次の2つのタイミングで実行されます。

1. **次にEffectが再実行される直前**（依存配列の値が変わったとき）
2. **コンポーネントがアンマウントされるとき**（画面から消えるとき）

つまり、**前回のセットアップを片付けてから、新しいセットアップを始める** という流れです。

### なぜクリーンアップが必要？

クリーンアップを忘れると、こんな悲惨なことが起きます。

- **メモリリーク**：使っていないリソースが解放されず、ブラウザが重くなる
- **重複購読**：同じイベントに何回もリスナーが登録されて、コールバックが複数回走る
- **タイマーが止まらない**：画面から消えてもタイマーが動き続けて、消えたコンポーネントに対して `setState` を呼んでエラー
- **古いリクエストの結果が反映される**：高速に検索ワードを打つと、古いリクエストの結果が後から上書きする

特に **タイマーとイベントリスナーは要注意** です。これらは「セットしたら外す」がペアになります。

### 用語の整理

- **クリーンアップ関数**：Effectの後始末をする関数
- **メモリリーク**：使っていないメモリが解放されず溜まっていく現象
- **購読（subscription）**：イベントや更新通知を受け取る登録のこと
- **解除（unsubscribe）**：購読をやめて通知を受け取らなくすること

## 💻 コード例

### 例1：タイマーのクリーンアップ

```jsx
import { useEffect, useState } from 'react';

function Clock() {
  const [time, setTime] = useState(new Date());

  useEffect(() => {
    // 1秒ごとに現在時刻を更新するタイマーをセット
    const id = setInterval(() => {
      setTime(new Date());
    }, 1000);

    // クリーンアップ：コンポーネントが消えるときにタイマーを止める
    return () => {
      clearInterval(id);
    };
  }, []); // マウント時にだけセット、アンマウント時に止める

  return <div>{time.toLocaleTimeString()}</div>;
}
```

このクリーンアップを忘れると、`Clock` を画面から消してもタイマーは回り続けます。`setTime` が動かないコンポーネントを更新しようとして、警告やエラーになります。

### 例2：イベントリスナーのクリーンアップ

```jsx
import { useEffect, useState } from 'react';

function WindowSize() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    // ウィンドウのリサイズイベントを購読
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener('resize', handleResize);

    // クリーンアップ：イベントリスナーを外す
    return () => {
      window.removeEventListener('resize', handleResize);
    };
  }, []);

  return <p>幅：{width}px</p>;
}
```

`addEventListener` を呼んだら **必ず同じ関数を `removeEventListener` に渡す** のがポイントです。

### 例3：WebSocketの接続と切断

```jsx
import { useEffect, useState } from 'react';

function ChatRoom({ roomId }) {
  const [messages, setMessages] = useState([]);

  useEffect(() => {
    // ルームごとにWebSocketで接続
    const ws = new WebSocket(`wss://chat.example.com/${roomId}`);

    ws.onmessage = (event) => {
      setMessages(prev => [...prev, event.data]);
    };

    // クリーンアップ：接続を閉じる
    return () => {
      ws.close();
    };
  }, [roomId]); // ルームが変わったら旧接続を切って新接続を張る

  return <ul>{messages.map((m, i) => <li key={i}>{m}</li>)}</ul>;
}
```

`roomId` が変わると、まず **古いWebSocketを閉じてから**、新しいWebSocketを開きます。これがクリーンアップの典型例です。

### 例4：fetchの「結果を捨てる」パターン

```jsx
import { useEffect, useState } from 'react';

function User({ id }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    let cancelled = false; // フラグで「もう要らない」を表現

    fetch(`/api/users/${id}`)
      .then(r => r.json())
      .then(data => {
        if (!cancelled) {
          setUser(data); // キャンセルされてないときだけセット
        }
      });

    return () => {
      cancelled = true; // 古いリクエストの結果を捨てる
    };
  }, [id]);

  return <div>{user?.name}</div>;
}
```

これはfetchをキャンセルするわけではなく、「**返ってきても無視する**」アプローチです。本格的なキャンセルは `AbortController` を使います（[[../07_データ取得/7-4-AbortControllerでキャンセル]]）。

### 例5：複数のリスナーをまとめてクリーンアップ

```jsx
useEffect(() => {
  const onScroll = () => console.log('scroll');
  const onClick = () => console.log('click');

  window.addEventListener('scroll', onScroll);
  window.addEventListener('click', onClick);

  return () => {
    window.removeEventListener('scroll', onScroll);
    window.removeEventListener('click', onClick);
  };
}, []);
```

複数登録するときも、**全部分けて解除** します。

## ❌ よくある間違い

### 1. クリーンアップを書き忘れる

```jsx
// ❌ タイマーが止まらない
useEffect(() => {
  setInterval(() => console.log('tick'), 1000);
}, []);
```

これは典型的なメモリリーク。コンポーネントが何度もマウント・アンマウントされるとタイマーがどんどん増えていきます。

### 2. addEventListener と removeEventListener で違う関数を渡す

```jsx
// ❌ 毎回新しい関数なので、外せない
useEffect(() => {
  window.addEventListener('resize', () => setWidth(window.innerWidth));
  return () => {
    window.removeEventListener('resize', () => setWidth(window.innerWidth)); // 別の関数！
  };
}, []);
```

リスナーを外すには **登録したのと同じ関数の参照** を渡す必要があります。変数に入れて使い回しましょう。

### 3. クリーンアップに `async` を使う

```jsx
// ❌ クリーンアップ関数は同期である必要がある
useEffect(() => {
  return async () => {
    await api.disconnect(); // これはダメ
  };
}, []);
```

クリーンアップ関数は同期的に書きます。非同期処理が必要なら、関数の中で呼び出すだけにしましょう。

### 4. 購読系を Effect の外で書く

```jsx
// ❌ コンポーネント関数の直下に書くと毎レンダー登録
function Bad() {
  window.addEventListener('resize', handle); // 毎レンダー登録される！
  return <div />;
}
```

購読は必ず `useEffect` の中で。

## ✅ ベストプラクティス

1. **「セットしたら必ず外す」をペアで覚える**：`setInterval` ⇔ `clearInterval`、`addEventListener` ⇔ `removeEventListener`、`subscribe` ⇔ `unsubscribe`、`open` ⇔ `close`。
2. **同じ関数の参照を使う**：イベントリスナーを外すために、関数を変数に入れます。
3. **クリーンアップ関数は同期で書く**：非同期処理が必要なら中で呼び出すだけ。
4. **依存が変わるときも走ることを意識する**：マウント時だけでなく、再実行のたびに「前のを片付けて新しいのをセット」が走ります。
5. **StrictMode（開発時）でクリーンアップが正しく動くか確認**：開発時にEffectが2回走るのは、クリーンアップの正しさを試す仕組みです（次章）。

## 🔬 実践演習

### お題：マウント中だけ動くタイマー

「画面に出ている間だけ1秒ごとにカウントアップし、画面から消えたら止まる」コンポーネントを作ってみましょう。

ヒント：

- `useState` でカウントを管理
- `useEffect` の中で `setInterval`
- クリーンアップで `clearInterval`

### 発展課題

- 親コンポーネントから「タイマーを表示する／しない」を切り替えるボタンを作り、表示・非表示の切り替え時にタイマーが正しく止まることを確認しましょう
- ブラウザのタブを別のタブに切り替えたときに、タイマーがどう振る舞うか観察してみましょう

## 📝 まとめ

- `useEffect` の戻り値関数は「後始末」を書く場所です
- タイマー・リスナー・WebSocket・購読は **セットしたら外す** が鉄則
- クリーンアップは「再実行直前」と「アンマウント時」の2つのタイミングで走ります
- 忘れるとメモリリークや重複購読になります
- 「開いたら閉じる」のペアを意識する習慣をつけましょう
