# 15-1. 本番ビルドと環境変数

## 🎯 この章で学ぶこと

- `npm run build` の挙動と成果物
- 環境変数の使い分け（.env, .env.production など）
- 開発・本番で違う設定を切り替える方法

---

## 📖 開発と本番の違い

| | 開発（dev） | 本番（build） |
| --- | --- | --- |
| サーバ | Viteの開発サーバ | 静的ファイル |
| HMR | あり | なし |
| 圧縮 | なし | あり（minify） |
| ソースマップ | あり | 通常なし（設定可） |
| 速度 | 速い起動・遅い実行 | 速い実行 |
| エラー表示 | 詳細 | 抑制 |

## 💻 環境変数

### Vite の環境変数

```text
# .env
VITE_API_URL=https://api.example.com
VITE_APP_NAME=MyApp
```

```ts
// 使う側
const url = import.meta.env.VITE_API_URL;
```

ルール：

- **`VITE_` プレフィックス必須**（それ以外はクライアントに渡らない）
- **公開される**：シークレット禁止
- ビルド時に**埋め込まれる**

### 環境ごとに切り替え

```text
.env                # 共通
.env.local          # ローカル（Git管理外）
.env.development    # 開発
.env.production     # 本番
```

優先順位（後勝ち）：`.env` < `.env.[mode]` < `.env.local` < `.env.[mode].local`。

### 例

```text
# .env
VITE_APP_NAME=MyApp

# .env.development
VITE_API_URL=http://localhost:3000

# .env.production
VITE_API_URL=https://api.example.com

# .env.local (Git無視、個人設定)
VITE_DEBUG_USER=admin
```

## 💻 config.ts に集約

```ts
// src/config.ts
const config = {
  apiUrl: import.meta.env.VITE_API_URL,
  appName: import.meta.env.VITE_APP_NAME,
  isDev: import.meta.env.DEV,
  mode: import.meta.env.MODE,
};

export default config;
```

→ コード内では `config.apiUrl` で読む。`import.meta.env`を散りばめない。

## 💻 mode を分ける

```bash
# 本番モードでビルド（デフォルト）
npm run build

# ステージング
vite build --mode staging
```

```text
# .env.staging
VITE_API_URL=https://staging-api.example.com
```

## 💻 base path（サブパス配置）

```js
// vite.config.js
export default {
  base: '/app/', // / 直下じゃなく /app/ 以下に配置
};
```

```bash
npm run build
# → ビルド結果のリンクが /app/assets/... になる
```

## 💻 ビルド最適化

### code splitting

`React.lazy` で分割：

```jsx
const About = React.lazy(() => import('./pages/About'));

<Suspense fallback={<p>読込中</p>}>
  <Routes>
    <Route path="/about" element={<About />} />
  </Routes>
</Suspense>
```

→ 初期バンドルが軽くなる。

### Vite の rollupOptions

```js
// vite.config.js
export default {
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          react: ['react', 'react-dom'],
          ui: ['@mui/material'],
        },
      },
    },
  },
};
```

→ 共通ライブラリを別バンドルに。

---

## 💻 sourcemap（本番デバッグ用）

```js
// vite.config.js
export default {
  build: {
    sourcemap: true,
  },
};
```

→ Sentryなどでスタックトレースが読める。サイズ増に注意。

## ❌ よくある間違い

### secret を VITE_* に

```text
VITE_API_KEY=abc123 # ❌
```

→ ✅ サーバ側で扱う。

### `process.env.XXX` をそのまま使う

→ Viteは `import.meta.env`。`process.env`は古いCRA。

### `.env.local` をGitに含める

→ `.gitignore` に必須。シークレットや個人設定を含む。

### モードによってビルドが落ちる

→ `npm run build && npm run preview` でローカル確認してからデプロイ。

---

## ✅ ベストプラクティス

1. **`VITE_*` で環境変数**、シークレット禁止
2. **`config.ts`** で集約
3. **ローカル設定は `.env.local`**（Git無視）
4. **本番ビルドをローカルで preview** 確認
5. **code splitting** で軽量化

## 🔬 実践演習

3環境（dev / staging / production）の設定：

- 各 `.env.*` を用意
- API URLを切り替え
- `vite build --mode staging` でビルドできる
- preview で動作確認

- `npm run build` で `dist/` に成果物

- code splitting + lazy で軽量化
