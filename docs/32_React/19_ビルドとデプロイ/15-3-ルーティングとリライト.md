# 15-3. ルーティングとリライト（SPAの罠）

## 🎯 この章で学ぶこと

- SPAで「リロードすると404」が起きる理由
- リライト（rewrite）の仕組み
- 各ホスティングサービスでの設定方法

---

## 📖 SPAの罠

### 何が起きる？

```text
http://example.com/             → ✅ 表示OK
http://example.com/products      → ✅ JSが切替で表示OK
http://example.com/products （ブラウザリロード）→ ❌ 404！
```

### なぜ？

サーバ側には実際には `/products` というファイルがありません（SPAは全部 `index.html` で表示）。

サーバはリクエストを受けて：

- `/` → `index.html` を返す
- `/products` → `products.html` がない → 404

---

## 💻 解決：すべてのリクエストを `index.html` に

サーバが「**ファイルが見つからなかったら index.html を返す**」設定をする。これを **rewrite（書き換え）** と呼ぶ。

```text
/products → index.html を返す（中のJSが /products を解釈してProductsページを描画）
/users/123 → 同じく index.html
```

---

## 💻 Vercel

`vercel.json` をプロジェクト直下に作成：

```json
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

または **何も書かなくて大丈夫**（Viteプロジェクトを認識すると自動でSPA対応）。

---

## 💻 Netlify

`public/_redirects` を作成：

```text
/*    /index.html   200
```

→ すべてのパスを `/index.html` に流す。**200** が大事（301だとリダイレクト扱い）。

または `netlify.toml`：

```toml
[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

---

## 💻 Cloudflare Pages

`public/_redirects`（Netlifyと同じ形式）：

```text
/*    /index.html   200
```

---

## 💻 GitHub Pages

GitHub Pages は SPA 対応がしづらい。`public/404.html` を `index.html` のコピーにする裏技：

```bash
cp dist/index.html dist/404.html
```

または、HashRouter を使う：

```jsx
import { HashRouter } from 'react-router-dom';

<HashRouter>
  <Routes>...</Routes>
</HashRouter>
```

→ URL が `/#/products` のようにハッシュ（#）付き。SPA問題を回避。

---

## 💻 nginx

```nginx
server {
  root /var/www/dist;
  index index.html;

  location / {
    try_files $uri $uri/ /index.html;
  }
}
```

`try_files` でファイルがなければ index.html。

---

## 💻 Apache

`public/.htaccess`：

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /
  RewriteRule ^index\.html$ - [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /index.html [L]
</IfModule>
```

---

## 💻 base path とルーティング

```js
// vite.config.js
export default {
  base: '/app/',
};
```

```jsx
import { BrowserRouter } from 'react-router-dom';

<BrowserRouter basename="/app">
  <Routes>...</Routes>
</BrowserRouter>
```

→ Viteの `base` と React Routerの `basename` を**一致**させる。

---

## 💻 プロキシ（API）

開発時、APIを別サーバ（localhost:3000）で動かす：

```js
// vite.config.js
export default {
  server: {
    proxy: {
      '/api': 'http://localhost:3000',
    },
  },
};
```

→ `/api/...` のリクエストが localhost:3000 に転送。CORS問題を回避できる。

---

## ❌ よくある間違い

### リダイレクト設定なしでデプロイ

→ サブパスをリロードで404。

### 200ではなく 301 で返す

```text
/*    /index.html   301
```

→ リダイレクトループの可能性。**200** で「ブラウザは元のURLのまま」にする。

### base path のずれ

→ Vite の base と Routerの basename を揃える。

### `<a href>` だと SPA が壊れる

```jsx
<a href="/about">About</a>  // ❌ ページリロード
```

→ ✅ React Router の `<Link>`：

```jsx
<Link to="/about">About</Link>
```

---

## ✅ ベストプラクティス

1. **デプロイ先のリライト設定**を必ず
2. **status 200**で書き換え（301禁止）
3. **base path とbasename を揃える**
4. **`<Link>` を使う**（`<a>`は外部のみ）
5. **デプロイ後にリロードチェック**

---

## 🔬 実践演習

Vite + React Router プロジェクトを Vercel にデプロイ：

- `/about` ページを作成
- ブラウザで `/about` 直接開いても表示
- リロードしても 404 にならない
- 「戻る」ボタンも正常動作

---

## 📝 まとめ

- SPAは全URLが index.html に行くべき
- 各ホスティングで rewrite 設定
- Vercel/Netlify は標準対応
- GitHub Pages は HashRouter が楽
