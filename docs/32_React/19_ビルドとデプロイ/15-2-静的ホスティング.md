# 15-2. 静的ホスティング（概観）

## 🎯 この章で学ぶこと

- 静的ホスティングとは
- 主要サービス（Vercel / Netlify / GitHub Pages / Cloudflare Pages）
- それぞれのデプロイ手順

---

## 📖 静的ホスティングとは

「**ビルド後の静的ファイル（HTML/CSS/JS）をサーバに置くだけ**」のシンプルなホスティング方式。

- サーバ側のロジック不要
- 安い・速い・スケーラブル
- CDNで世界中に配信される

→ ReactのSPAは全部これに乗る（API は別途）。

---

## 💻 主要サービス比較

| サービス | 特徴 | 無料枠 |
| --- | --- | --- |
| **Vercel** | Next.js作者、超人気 | あり |
| **Netlify** | 老舗、機能豊富 | あり |
| **Cloudflare Pages** | 高速CDN、無制限帯域 | あり（手厚い） |
| **GitHub Pages** | GitHubと統合 | あり（公開リポ） |
| **AWS S3 + CloudFront** | 自由度高い | 従量課金 |
| **Firebase Hosting** | Google統合 | あり |

→ **初心者は Vercel か Netlify**、コストを抑えたいなら Cloudflare Pages。

---

## 💻 Vercel デプロイ

### 方法1：GitHub連携（推奨）

1. GitHubにpush
2. [vercel.com](https://vercel.com) でリポジトリ選択
3. 「Deploy」 → 数十秒で完了
4. 以降、push のたび自動デプロイ

設定：

- Build Command: `npm run build`
- Output Directory: `dist`
- Framework Preset: Vite

### 方法2：CLI

```bash
npm install -g vercel
vercel
```

質問に答えるだけ。

---

## 💻 Netlify デプロイ

### GitHub連携

1. [netlify.com](https://netlify.com) でリポジトリ選択
2. Build settings:
   - Build command: `npm run build`
   - Publish directory: `dist`

### CLI

```bash
npm install -g netlify-cli
netlify deploy

# 本番
netlify deploy --prod
```

---

## 💻 Cloudflare Pages

1. [pages.cloudflare.com](https://pages.cloudflare.com) でリポジトリ選択
2. Build settings:
   - Build command: `npm run build`
   - Build output directory: `dist`

帯域無制限（個人利用に強い）。

---

## 💻 GitHub Pages

```bash
npm install -D gh-pages
```

```json
// package.json
{
  "scripts": {
    "deploy": "vite build && gh-pages -d dist"
  },
  "homepage": "https://username.github.io/repo-name"
}
```

```js
// vite.config.js
export default {
  base: '/repo-name/', // サブパスに置くため
};
```

```bash
npm run deploy
```

→ `https://username.github.io/repo-name/` で公開。

## 💻 環境変数の設定

### Vercel

ダッシュボード → Project Settings → Environment Variables

- `Production` `Preview` `Development` で別々に設定可

### Netlify

Site settings → Environment variables

### CLI で

```bash
vercel env add VITE_API_URL
netlify env:set VITE_API_URL https://...
```

---

## 💻 カスタムドメイン

### Vercel / Netlify

1. ダッシュボードで「Domains」
2. 自分のドメインを追加
3. DNS設定（CNAMEまたはA）
4. 自動でHTTPS化

---

## 💻 プレビューデプロイ

PRごとに**プレビューURL**が自動生成される（Vercel/Netlify標準）。

```text
PR #42 → https://my-app-pr-42.vercel.app
```

→ レビューが楽。マージ前に動作確認。

---

## 💻 ロールバック

問題が出たら**1クリックで前のバージョンに戻せる**。

- Vercel：Deployments → 「Promote to Production」
- Netlify：Deploys → 「Publish deploy」

---

## ❌ よくある間違い

### `dist` をGitにcommit

→ 不要。`.gitignore` に追加。**ビルドは CI/Vercel側でやる**。

### 環境変数をsetせずにビルド

→ Production で `undefined`。先にダッシュボードで設定。

### base path の設定漏れ（GitHub Pages）

→ アセットが404。`vite.config.js`で `base` 指定。

### デプロイ先で 404（次節 SPA問題）

→ [[15-3-ルーティングとリライト]] を参照。

---

## ✅ ベストプラクティス

1. **GitHub連携で自動デプロイ**
2. **Vercel か Netlify** がお手軽
3. **環境変数はダッシュボード**
4. **プレビューデプロイ**でPRごとに確認
5. **ロールバック手順**を覚える

---

## 🔬 実践演習

Vite Reactアプリを：

1. GitHubにpush
2. Vercelでデプロイ
3. 環境変数（VITE_API_URL）を設定
4. PRを作ってプレビューURLを確認
5. ロールバック練習

---

## 📝 まとめ

- 静的ホスティングはSPAに最適
- Vercel / Netlify が定番、Cloudflareもおすすめ
- GitHub連携で自動デプロイ
- プレビュー + ロールバック が標準
