# 詳細ページから戻る際の状態保持方法とベストプラクティス

## 概要

検索・絞り込み機能を持つ一覧ページから詳細ページに遷移し、戻る際に検索条件や絞り込み状態を保持する方法について解説します。ユーザー体験を向上させるために重要な機能です。

## 実装方法の比較表

| 項目 | URLパラメータ | sessionStorage | router.back() | Context API/状態管理 |
|------|---------------|----------------|---------------|---------------------|
| **実装の複雑さ** | ⭐⭐ 中程度 | ⭐⭐ 中程度 | ⭐ 簡単 | ⭐⭐⭐ 複雑 |
| **状態の永続化** | ✅ あり（URLに保存） | ✅ あり（タブ単位） | ❌ なし | ❌ なし（リロードで失われる） |
| **ブックマーク可能** | ✅ 可能 | ❌ 不可 | ❌ 不可 | ❌ 不可 |
| **URL共有** | ✅ 可能 | ❌ 不可 | ❌ 不可 | ❌ 不可 |
| **ブラウザ履歴対応** | ✅ 自動対応 | ❌ 非対応 | ✅ 自動対応 | ❌ 非対応 |
| **直接URLアクセス対応** | ✅ 対応 | ❌ 非対応 | ❌ 非対応 | ❌ 非対応 |
| **タブ単位の保持** | ❌ 不可 | ✅ 可能 | ❌ 不可 | ❌ 不可 |
| **URLの長さ** | ⭐⭐ 長くなる可能性 | ⭐⭐⭐ 影響なし | ⭐⭐⭐ 影響なし | ⭐⭐⭐ 影響なし |
| **実装の柔軟性** | ⭐⭐⭐ 高い | ⭐⭐ 中程度 | ⭐ 低い | ⭐⭐⭐ 高い |
| **学習コスト** | ⭐⭐ 中程度 | ⭐⭐ 中程度 | ⭐ 低い | ⭐⭐⭐ 高い |
| **推奨度** | ⭐⭐⭐ 推奨 | ⭐⭐ 状況による | ⭐ 限定的 | ⭐⭐ 状況による |

### 推奨使用場面

| 実装方法 | 最適な使用場面 | 例 |
|----------|----------------|-----|
| **URLパラメータ** | 検索結果の共有が必要、SEOが重要 | ECサイト、ブログ、求人サイト、ニュースサイト |
| **sessionStorage** | タブ単位で状態を保持したい、URLを短く保ちたい | 管理画面、ダッシュボード、社内ツール |
| **router.back()** | シンプルな実装で十分、直接URLアクセスが想定されない | モバイルアプリ、SPA内部ナビゲーション |
| **Context API/状態管理** | 複数ページ間で状態を共有、複雑な状態管理が必要 | ダッシュボード、管理画面、複雑なフィルタリング |

## 1. URLパラメータを保持する（推奨）

### 概要

詳細ページへの遷移時に現在のクエリパラメータを引き継ぎ、戻る際に復元する方法です。URLに状態が保存されるため、ブックマークや共有が可能になります。

### メリット

- ✅ URLで状態を共有可能
- ✅ ブラウザの戻る/進むボタンで正常に動作
- ✅ 実装が比較的シンプル
- ✅ ブックマーク可能
- ✅ SEO対応
- ✅ 直接URLでアクセスしても動作する

### デメリット

- ❌ URLが長くなる可能性がある
- ❌ 機密情報はURLに含められない

### 実装例

#### Next.jsでの実装

```javascript
// pages/products/index.js - 一覧ページ
import { useRouter } from 'next/router';
import Link from 'next/link';

function ProductList() {
  const router = useRouter();
  const { category, price, search, sort } = router.query;
  const [products, setProducts] = useState([]);

  // 検索・絞り込み条件をURLパラメータから取得
  useEffect(() => {
    const fetchProducts = async () => {
      const params = new URLSearchParams();
      if (category) params.append('category', category);
      if (price) params.append('price', price);
      if (search) params.append('search', search);
      if (sort) params.append('sort', sort);

      const response = await fetch(`/api/products?${params}`);
      const data = await response.json();
      setProducts(data);
    };

    fetchProducts();
  }, [category, price, search, sort]);

  // 詳細ページへのリンク（クエリパラメータを保持）
  const getDetailLink = (productId) => {
    const query = { ...router.query, id: productId };
    return {
      pathname: '/products/[id]',
      query: query
    };
  };

  return (
    <div>
      {/* 検索・絞り込みUI */}
      <input
        placeholder="検索..."
        value={search || ''}
        onChange={(e) => {
          router.push({
            pathname: router.pathname,
            query: { ...router.query, search: e.target.value }
          });
        }}
      />

      {/* 商品リスト */}
      {products.map(product => (
        <Link key={product.id} href={getDetailLink(product.id)}>
          <div>{product.name}</div>
        </Link>
      ))}
    </div>
  );
}
```

## 2. sessionStorageを使用

### 概要

遷移前に絞り込み状態をsessionStorageに保存し、戻った際に復元する方法です。タブ単位で状態が保持されます。

### メリット

- ✅ URLが短いまま保たれる
- ✅ タブ単位で状態を保持
- ✅ 機密情報をURLに含めなくて済む
- ✅ 実装が比較的シンプル

### デメリット

- ❌ タブを閉じると状態が消える
- ❌ ブックマークやURL共有ができない
- ❌ 直接URLでアクセスした場合は動作しない
- ❌ 実装がやや複雑

### 実装例

```javascript
// hooks/useSearchState.js - カスタムフック
import { useEffect, useState } from 'react';
import { useRouter } from 'next/router';

export function useSearchState() {
  const router = useRouter();
  const [searchState, setSearchState] = useState({
    category: '',
    price: '',
    search: '',
    sort: ''
  });

  // コンポーネントマウント時にsessionStorageから復元
  useEffect(() => {
    const savedState = sessionStorage.getItem('productListState');
    if (savedState) {
      try {
        const parsed = JSON.parse(savedState);
        setSearchState(parsed);
      } catch (error) {
        console.error('Failed to parse saved state:', error);
      }
    }
  }, []);

  // 状態変更時にsessionStorageに保存
  const updateSearchState = (newState) => {
    const updated = { ...searchState, ...newState };
    setSearchState(updated);
    sessionStorage.setItem('productListState', JSON.stringify(updated));
  };

  // 詳細ページ遷移前に状態を保存
  const saveStateBeforeNavigation = () => {
    sessionStorage.setItem('productListState', JSON.stringify(searchState));
  };

  // 状態をクリア
  const clearSearchState = () => {
    sessionStorage.removeItem('productListState');
    setSearchState({
      category: '',
      price: '',
      search: '',
      sort: ''
    });
  };

  return {
    searchState,
    updateSearchState,
    saveStateBeforeNavigation,
    clearSearchState
  };
}
```

## 3. router.back()を使用

### 概要

ブラウザの履歴を利用して戻る方法です。実装が最もシンプルですが、直接URLでアクセスした場合は動作しません。

### メリット

- ✅ 実装が非常に簡単
- ✅ ブラウザの履歴をそのまま利用
- ✅ 追加の状態管理が不要

### デメリット

- ❌ 直接URLでアクセスした場合は動作しない
- ❌ 履歴がない場合は動作しない
- ❌ 状態の制御が難しい

### 実装例

```javascript
// pages/products/[id].js - 詳細ページ
import { useRouter } from 'next/router';

function ProductDetail() {
  const router = useRouter();
  const { id } = router.query;
  const [product, setProduct] = useState(null);

  useEffect(() => {
    const fetchProduct = async () => {
      const response = await fetch(`/api/products/${id}`);
      const data = await response.json();
      setProduct(data);
    };

    fetchProduct();
  }, [id]);

  // ブラウザの戻るボタンと同じ動作
  const handleBack = () => {
    if (window.history.length > 1) {
      router.back();
    } else {
      // 履歴がない場合は一覧ページに遷移
      router.push('/products');
    }
  };

  return (
    <div>
      <button onClick={handleBack}>← 一覧に戻る</button>
      {product && (
        <div>
          <h1>{product.name}</h1>
          <p>{product.description}</p>
        </div>
      )}
    </div>
  );
}
```

## 4. Context APIや状態管理ライブラリを使用

### 概要

グローバル状態として検索・絞り込み状態を管理する方法です。複数ページ間で状態を共有できますが、リロードで失われます。

### メリット

- ✅ 複数ページ間で状態を共有可能
- ✅ 状態管理が一元化される
- ✅ 実装の柔軟性が高い

### デメリット

- ❌ 実装が複雑
- ❌ リロードで状態が失われる
- ❌ ブックマークやURL共有ができない
- ❌ バンドルサイズが増加する可能性（状態管理ライブラリ使用時）

### 実装例

#### Context APIを使用

```javascript
// contexts/SearchContext.js
import { createContext, useContext, useState, useEffect } from 'react';

const SearchContext = createContext();

export function SearchProvider({ children }) {
  const [searchState, setSearchState] = useState({
    category: '',
    price: '',
    search: '',
    sort: ''
  });

  // sessionStorageと組み合わせて永続化
  useEffect(() => {
    const savedState = sessionStorage.getItem('searchState');
    if (savedState) {
      try {
        setSearchState(JSON.parse(savedState));
      } catch (error) {
        console.error('Failed to parse saved state:', error);
      }
    }
  }, []);

  useEffect(() => {
    sessionStorage.setItem('searchState', JSON.stringify(searchState));
  }, [searchState]);

  const updateSearchState = (newState) => {
    setSearchState(prev => ({ ...prev, ...newState }));
  };

  const clearSearchState = () => {
    setSearchState({
      category: '',
      price: '',
      search: '',
      sort: ''
    });
  };

  return (
    <SearchContext.Provider value={{
      searchState,
      updateSearchState,
      clearSearchState
    }}>
      {children}
    </SearchContext.Provider>
  );
}

export function useSearch() {
  const context = useContext(SearchContext);
  if (!context) {
    throw new Error('useSearch must be used within SearchProvider');
  }
  return context;
}
```

## 実装方法の選択ガイド

### 選択フローチャート

```
検索結果の共有が必要？
├─ YES → URLパラメータ（方法1）
└─ NO
    ├─ タブ単位で保持したい？
    │   ├─ YES → sessionStorage（方法2）
    │   └─ NO
    │       ├─ シンプルな実装で十分？
    │       │   ├─ YES → router.back()（方法3）
    │       │   └─ NO → Context API/状態管理（方法4）
    │       └─ 複雑な状態管理が必要？
    │           └─ YES → Context API/状態管理（方法4）
```

### 組み合わせて使用する場合

複数の方法を組み合わせることで、より柔軟な実装が可能です：

```javascript
// URLパラメータ + sessionStorageの組み合わせ例
function ProductList() {
  const router = useRouter();
  const [searchState, setSearchState] = useState({});

  // URLパラメータを優先し、なければsessionStorageから復元
  useEffect(() => {
    if (Object.keys(router.query).length > 0) {
      // URLパラメータがある場合はそれを使用
      setSearchState(router.query);
    } else {
      // なければsessionStorageから復元
      const saved = sessionStorage.getItem('searchState');
      if (saved) {
        setSearchState(JSON.parse(saved));
      }
    }
  }, []);

  // 状態変更時に両方に保存
  const updateState = (newState) => {
    const updated = { ...searchState, ...newState };
    setSearchState(updated);
    sessionStorage.setItem('searchState', JSON.stringify(updated));
    router.push({ query: updated });
  };

  return (
    // UI
  );
}
```

## よくあるエラーと対処法

### 1. URLパラメータが長すぎるエラー

**エラー内容**: URLが長すぎてブラウザやサーバーでエラーになる

**対処法**:
- 重要なパラメータのみ保持する
- パラメータを圧縮する
- POSTリクエストを使用する

```javascript
// パラメータの整理
const getEssentialParams = (query) => {
  const essential = {};
  if (query.search) essential.search = query.search;
  if (query.category) essential.category = query.category;
  // 重要でないパラメータは除外
  return essential;
};
```

### 2. sessionStorageの容量制限エラー

**エラー内容**: `QuotaExceededError`が発生する

**対処法**:
- 保存するデータサイズを制限する
- 不要なデータを削除する
- エラーハンドリングを追加する

```javascript
try {
  sessionStorage.setItem('searchState', JSON.stringify(state));
} catch (error) {
  if (error.name === 'QuotaExceededError') {
    console.warn('SessionStorage is full, clearing old data');
    sessionStorage.clear();
    sessionStorage.setItem('searchState', JSON.stringify(state));
  }
}
```

### 3. router.back()が動作しない

**エラー内容**: 履歴がない場合に動作しない

**対処法**:
- フォールバック処理を実装する
- 履歴の有無を確認する

```javascript
const handleBack = () => {
  if (window.history.length > 1) {
    router.back();
  } else {
    router.push('/products'); // フォールバック
  }
};
```

### 4. Context APIの再レンダリング問題

**エラー内容**: 不要な再レンダリングが発生する

**対処法**:
- Contextを分割する
- useMemoやuseCallbackを使用する

```javascript
// Contextを分割
const SearchStateContext = createContext();
const SearchActionsContext = createContext();

// アクションのみのContextを提供
export function SearchActionsProvider({ children }) {
  const actions = useMemo(() => ({
    updateSearchState,
    clearSearchState
  }), []);

  return (
    <SearchActionsContext.Provider value={actions}>
      {children}
    </SearchActionsContext.Provider>
  );
}
```

## まとめ

詳細ページから戻る際の状態保持には、以下の4つの方法があります：

1. **URLパラメータ（推奨）**: 最も汎用的で、SEOや共有にも対応
2. **sessionStorage**: タブ単位で保持したい場合に有効
3. **router.back()**: シンプルな実装で十分な場合に使用
4. **Context API/状態管理**: 複雑な状態管理が必要な場合に使用

プロジェクトの要件に応じて適切な方法を選択し、場合によっては複数の方法を組み合わせることで、より良いユーザー体験を提供できます。
