# 日本の電話番号の仕組みとバリデーション（正規化つき）

**想定読者:** フォームで電話番号を受け取り、**全角やハイフン混じり**の入力にも耐えつつ、**携帯と固定の違い**をざっくり正しく扱いたい人向けです。  
**このノートのゴール:** 日本の番号の「ざっくりしたルール」を押さえ、**正規化 → 検証**の実装パターンをそのまま使える形にします。

関連: [[19-リアルタイムバリデーション詳細解説]]

---

## 1. 日本の電話番号は「国内プレフィックス 0」から始まる

日本でいう「市外局番ありの書き方」は、だいたい **先頭が `0`** です（国際番号の `+81` に直すときは先頭 `0` を落とす、という話とセットで覚えると混乱しにくいです）。

大雑把に分けると次のイメージです（厳密な電気通信番号制度の全文ではなく、**フォーム実務でよく効く分類**）。

| ざっくりした種類 | 典型例（ハイフンは表示用） | 桁数の目安（数字だけ） |
|------------------|---------------------------|------------------------|
| **市外局番付き固定電話（地理番号）** | `03-1234-5678` / `06-1234-5678` / `075-123-4567` | **だいたい 10 桁**（先頭 `0` 含む） |
| **携帯電話** | `090-1234-5678` / `080-…` / `070-…` | **11 桁**（先頭 `0` 含む） |
| **050（IP 電話など）** | `050-1234-5678` | **11 桁**（固定回線「だけ」ではないことが多い） |
| **フリーダイヤル等** | `0120-123-456` | ルールは別系統（フリーダイヤルは **10 桁**が多い） |

**ポイント:** 「固定＝10桁、携帯＝11桁」は **よくある整理として実務でも通りやすい**一方で、**固定側も市外局番の長さで見た目の区切りは変わる**ので、「桁数だけ」で全てを証明するのは難しいです（後述）。

---

## 2. 固定電話：「0 から始まる 10 桁の数字」で問題ない？

### 結論（実務寄り）

- **地理番号の固定電話を想定するなら、「数字だけにしたあと 10 桁で先頭が 0」**は、**かなり多くのケースで整合します**。
- ただしこれは **厳密な制度そのものを完全に表したルールではなく、実用の近似**です。

### なぜ「厳密に全部」が難しいか

日本の地理番号は、**市外局番の長さが地域によって違う**ため、見た目は違っても **国内向けの桁の合計**が一定の範囲に収まる、という整理になります。フォームではよく、

1. **まず正規化**（全角→半角、ハイフン除去）
2. **桁数と先頭のおおまかなパターン**で弾く
3. **最終的な正しさ**は業務要件次第（「固定のみ」「携帯のみ」「050 も許す」等）

が現実的です。

### 落とし穴（要件で決める）

- **050 は 11 桁**なので、「固定は 10 桁だけ許す」方針だと **050 は通らない**（意図通りか確認）。
- **0120（フリーダイヤル）**などは体系が別なので、「一般の固定・携帯だけ受けたい」なら **別パターン**に分けるか、そもそも入力欄を分ける、が安全です。

---

## 3. 携帯番号：「0A0」から始まる 11 桁で、A は決まっている？

ここで言っている **`0A0` っぽさ**は、多くの場合 **`090` / `080` / `070` のような「0 + 2 桁の頭」**のイメージに近いです。

### 結論

- **携帯電話番号として一般的に受け取るなら、先頭 3 桁は `090` / `080` / `070` のどれか、という整理がよく使われます**。
- ただし **将来の割当や制度変更**があり得るので、**「絶対にこの 3 桁だけが正」**と断言するより、**プロダクト要件で許容プレフィックスを決める**のが安全です（厳しすぎると、将来の番号や新系統で誤判定します）。

### 参考（覚え方）

- **11 桁**で、かつ **`090` / `080` / `070` で始まる**なら「携帯っぽい」判定はかなり強いです。
- **050 は 11 桁だが、携帯ではない**ことが多い（IP 電話など）。

## 4. 正規化：全角数字を半角数字へ、全角ハイフンを半角ハイフンへ

### 4-1. まずおすすめ：`String.prototype.normalize('NFKC')`

Unicode の互換分解（NFKC）で、**全角英数字**や**互換文字**が半角寄りに寄ることが多いです。多くの「IME で全角入力された電話番号」はこれでかなり直ります。

```js
/**
 * 電話番号入力の典型的なゆらぎを寄せる（第1段）
 * - 全角数字・全角ハイフン等を半角寄りに寄せる
 */
export function normalizePhoneInput(raw) {
  return String(raw ?? "")
    .trim()
    .normalize("NFKC");
}
```

### 4-2. 保険：`－`（全角ハイフン）や長音記号まで明示的に置換したい場合

環境やフォントによって「ハイフンっぽいが別コードポイント」が混ざることがあるので、**許可したい区切り文字だけ残して他を落とす**のが堅いです。

```js
/** ハイフン類を半角 `-` に寄せる（例） */
export function normalizeHyphensLike(s) {
  return (
    s
      // よく混ざるダッシュ類を半角ハイフンへ
      .replace(/[‐‑‒–—―ー－]/g, "-")
  );
}

/** 数字以外を除去して「数字だけ」にする（検証用） */
export function digitsOnly(s) {
  return s.replace(/\D/g, "");
}
```

### 4-3. 「全角数字だけ」を明示的に置換したい場合（学習用）

NFKC で足りないケースへの保険として、**全角数字レンジ**を置換する方法もあります。

```js
/** ０１２…９ → 012…9 */
export function fullWidthDigitsToAscii(s) {
  return s.replace(/[\uFF10-\uFF19]/g, (ch) =>
    String.fromCharCode(ch.charCodeAt(0) - 0xff10 + 0x30),
  );
}
```

### 4-4. まとめて使う例（おすすめの流れ）

```js
export function normalizeJapanesePhoneForValidation(raw) {
  let s = String(raw ?? "").trim();
  s = s.normalize("NFKC");
  s = normalizeHyphensLike(s);

  // ここまで来たら、検証は digitsOnly(s) を主役にしやすい
  return s;
}
```

## 5. バリデーション例（方針別）

### 5-1. 方針：「携帯っぽい（090/080/070）だけ」11 桁

```js
export function isJapaneseMobilePhoneDigits(digits) {
  return /^(070|080|090)\d{8}$/.test(digits);
}
```

### 5-2. 方針：「固定っぽい（地理番号）」を 10 桁でざっくり

```js
/**
 * 近似ルール:
 * - 10桁
 * - 先頭0
 * - 携帯っぽい070/080/090で始まらない（050も除外したいなら追加）
 */
export function isJapaneseLandlineLike10Digits(digits) {
  if (!/^0\d{9}$/.test(digits)) return false;
  if (/^0(70|80|90)/.test(digits)) return false; // 携帯っぽい頭を除外
  return true;
}
```

### 5-3. 方針：「携帯 or 固定っぽい（050 は別扱い）」

要件が「050 も許す」なら、`050` 用に **11 桁**の分岐を足します。

### 5-4. 方針：「携帯でも固定でもどちらも OK」（同一入力欄）

**考え方は「先に桁で分岐」→「それぞれの近似ルールに通す」**です。正規化で **数字だけ** にしたあと、

1. **11 桁**なら **携帯っぽい**（`070` / `080` / `090`）かどうか  
2. **10 桁**なら **固定っぽい（地理番号の近似）**かどうか  
3. どちらでもなければエラー  

という順が読みやすく、条件も重なりにくいです。

```js
export function isJapaneseMobilePhoneDigits(digits) {
  return /^(070|080|090)\d{8}$/.test(digits);
}

/**
 * 10桁の地理番号っぽさ（近似）
 * ※ 070/080/090 で始まる10桁は「携帯の欠番」扱いにし、固定側から外す
 */
export function isJapaneseLandlineLike10Digits(digits) {
  if (!/^0\d{9}$/.test(digits)) return false;
  if (/^0(70|80|90)/.test(digits)) return false;
  return true;
}

/** 携帯（11桁） OR 固定っぽい（10桁） */
export function isJapaneseMobileOrLandlineDigits(digits) {
  return (
    isJapaneseMobilePhoneDigits(digits) || isJapaneseLandlineLike10Digits(digits)
  );
}

export function validateJapanesePhoneMobileOrLandline(raw) {
  const s = String(raw ?? "").trim().normalize("NFKC").replace(/[‐‑‒–—―ー－]/g, "-");
  const digits = s.replace(/\D/g, "");

  if (digits.length === 0) {
    return { normalized: s, digits, error: "必須です" };
  }
  if (isJapaneseMobileOrLandlineDigits(digits)) {
    return { normalized: s, digits, error: "" };
  }
  return {
    normalized: s,
    digits,
    error:
      "0 から始まる電話番号を入力してください（固定: 10 桁 / 携帯: 070・080・090 の 11 桁）",
  };
}
```

**050（IP 電話・11 桁）も同じ欄で許す**なら、分岐を 1 つ足します（プロダクト要件で決める）。

```js
export function isJapanese050PhoneDigits(digits) {
  return /^050\d{8}$/.test(digits);
}

export function isJapaneseMobileOrLandlineOr050Digits(digits) {
  return (
    isJapaneseMobilePhoneDigits(digits) ||
    isJapaneseLandlineLike10Digits(digits) ||
    isJapanese050PhoneDigits(digits)
  );
}
```

**フリーダイヤル（0120 など）も許す**なら、また別パターンが必要です（桁と頭が携帯・固定の近似と一致しないことがあるため、**許可リスト方式**に切り替えるのも手です）。

## 6. React でそのまま使うイメージ（リアルタイム向き）

```tsx
import { useMemo, useState } from "react";

function normalizeJapanesePhoneForValidation(raw: string) {
  let s = String(raw ?? "").trim().normalize("NFKC");
  s = s.replace(/[‐‑‒–—―ー－]/g, "-");
  return s;
}

function digitsOnly(s: string) {
  return s.replace(/\D/g, "");
}

function validateJapanesePhone(raw: string) {
  const normalized = normalizeJapanesePhoneForValidation(raw);
  const digits = digitsOnly(normalized);

  if (digits.length === 0) return { normalized, digits, error: "必須です" };

  // 例: 携帯のみ許可
  if (/^(070|080|090)\d{8}$/.test(digits)) {
    return { normalized, digits, error: "" };
  }

  return {
    normalized,
    digits,
    error: "携帯番号（070/080/090 から始まる 11 桁）を入力してください",
  };
}

export function MobilePhoneField() {
  const [value, setValue] = useState("");
  const [touched, setTouched] = useState(false);

  const { error } = useMemo(() => validateJapanesePhone(value), [value]);

  return (
    <div>
      <label htmlFor="tel">携帯電話</label>
      <input
        id="tel"
        inputMode="numeric"
        autoComplete="tel"
        value={value}
        onChange={(e) => setValue(e.target.value)}
        onBlur={() => setTouched(true)}
        aria-invalid={touched && error ? true : false}
        aria-describedby={touched && error ? "tel-error" : undefined}
      />
      {touched && error ? (
        <p id="tel-error" role="alert">
          {error}
        </p>
      ) : null}
    </div>
  );
}
```

**補足:** 「入力のたびに見た目も半角へ強制変換する」かどうかは UX 次第です。IME 中に変換しすぎるとストレスになるので、**検証は内部で正規化、表示はユーザー入力のまま**もよくあります。

### 6-1. 携帯・固定どちらも許可する欄の例

`validateJapanesePhone` の中身だけ **5-4 の `validateJapanesePhoneMobileOrLandline`** に差し替えれば同じ構造のまま拡張できます。

```tsx
function validateJapanesePhone(raw: string) {
  const normalized = normalizeJapanesePhoneForValidation(raw);
  const digits = digitsOnly(normalized);

  if (digits.length === 0) return { normalized, digits, error: "必須です" };

  const okMobile = /^(070|080|090)\d{8}$/.test(digits);
  const okLandline =
    /^0\d{9}$/.test(digits) && !/^0(70|80|90)/.test(digits);

  if (okMobile || okLandline) return { normalized, digits, error: "" };

  return {
    normalized,
    digits,
    error:
      "電話番号の形式が正しくありません（固定: 10 桁 / 携帯: 070・080・090 の 11 桁）",
  };
}

export function PhoneField() {
  const [value, setValue] = useState("");
  const [touched, setTouched] = useState(false);
  const { error } = useMemo(() => validateJapanesePhone(value), [value]);

  return (
    <div>
      <label htmlFor="tel2">電話番号（固定・携帯）</label>
      <input
        id="tel2"
        inputMode="tel"
        autoComplete="tel"
        value={value}
        onChange={(e) => setValue(e.target.value)}
        onBlur={() => setTouched(true)}
        aria-invalid={touched && error ? true : false}
        aria-describedby={touched && error ? "tel2-error" : undefined}
      />
      {touched && error ? (
        <p id="tel2-error" role="alert">
          {error}
        </p>
      ) : null}
    </div>
  );
}
```

## 7. まとめ

- **固定（地理番号）を雑に扱うなら「数字だけ 10 桁・先頭 0」**は **よくある近似**として強い一方、**制度の完全再現ではない**ので、**050 / 0120 などを許すか**は要件で決める。
- **携帯は 11 桁**で、実務では **`090` / `080` / `070`** を許可することが多い（ただし将来・例外は要件で調整）。
- **携帯と固定を同一欄で受ける**なら、**正規化 → 数字だけ →「11桁なら携帯」「10桁なら固定っぽい」**の順に分岐すると実装が単純（上の **5-4**）。
- **全角→半角寄せ**は **`normalize('NFKC')` が第一選択**。ハイフン類は **別コードポイントが混ざる**ので、**許容する区切りへ寄せる置換**か、最終的に **`digitsOnly` で数字だけ検証**が堅い。
