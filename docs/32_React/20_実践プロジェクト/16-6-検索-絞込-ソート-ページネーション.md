# 16-6 検索/絞込/ソート/ページネーション（一覧UXの総合）

## 🎯 この章で学ぶこと

- 一覧画面で必須となる「検索・絞込・ソート・ページネーション」を 1 つの状態として統合管理する
- URL クエリパラメータと React の状態を双方向で同期させる手法を学ぶ
- デバウンスを使った検索 UX の改善
- React Query との組み合わせで、入力に応じた再フェッチを効率化する
- 「無限スクロール」と「ページ番号」の使い分け

## 📖 概念の説明

### 一覧 UX を構成する 4 つの要素

1. **検索（Search）**: 文字列での部分一致など。例: タイトルに「買い物」を含む
2. **絞込（Filter）**: タグ、優先度、完了/未完了などの条件で絞る
3. **ソート（Sort）**: 並び順の変更
4. **ページネーション（Pagination）**: 件数が多いときの分割表示

これらは独立しているように見えて、実は密接に関係しています。例えば「検索キーワードを変えたらページは 1 に戻すべき」「ソートを変えてもキーワードは保持する」など、整合性のあるルールが必要です。

### 状態を 1 つにまとめる

ばらばらに `useState` を持つと、依存関係が複雑化します。1 つのオブジェクトにまとめて管理しましょう。

```ts
type ListQuery = {
  search: string;
  tag: string | null;
  done: "all" | "done" | "undone";
  sortBy: "createdAt" | "dueDate" | "priority";
  sortDir: "asc" | "desc";
  page: number;
  pageSize: number;
};
```

### URL クエリと同期させる利点

`/tasks?search=買い物&page=2` のように URL に状態を埋め込むと、

- リロードしても状態が保たれる
- ブラウザの「戻る」が自然に動く
- URL を共有すれば同じ画面を他人にも見せられる
- ブックマーク可能

という 4 つのご利益があります。React Router の `useSearchParams` で簡単に実現できます。

### デバウンスとは

「ユーザーが入力をやめて 300ms 経ったら検索を実行する」という遅延処理。1 文字打つたびに API を叩くとサーバが悲鳴を上げるので、必須テクニックです。

### 無限スクロール vs ページ番号

| 観点 | 無限スクロール | ページ番号 |
|------|---------------|-----------|
| 没入感 | 高い | 低い |
| 「3 ページ目に戻る」 | 困難 | 簡単 |
| 件数の見通し | 悪い | 良い |
| URL 共有 | 微妙 | 簡単 |

SNS のタイムラインは無限スクロール、業務システムはページ番号が定番です。TaskMate は業務寄りなのでページ番号を採用します。

## 💻 コード例

### URL クエリと状態を同期する

```tsx
// src/features/tasks/useListQuery.ts
import { useSearchParams } from "react-router-dom";

export type ListQuery = {
  search: string;
  tag: string | null;
  done: "all" | "done" | "undone";
  sortBy: "createdAt" | "dueDate" | "priority";
  sortDir: "asc" | "desc";
  page: number;
};

export function useListQuery(): [
  ListQuery,
  (patch: Partial<ListQuery>) => void
] {
  const [params, setParams] = useSearchParams();

  const query: ListQuery = {
    search: params.get("search") ?? "",
    tag: params.get("tag"),
    done: (params.get("done") ?? "all") as ListQuery["done"],
    sortBy: (params.get("sortBy") ?? "createdAt") as ListQuery["sortBy"],
    sortDir: (params.get("sortDir") ?? "desc") as ListQuery["sortDir"],
    page: Number(params.get("page") ?? "1"),
  };

  function update(patch: Partial<ListQuery>) {
    const next = { ...query, ...patch };
    // 検索やフィルタが変わったらページを 1 に戻す
    if ("search" in patch || "tag" in patch || "done" in patch) {
      next.page = 1;
    }
    const sp = new URLSearchParams();
    if (next.search) sp.set("search", next.search);
    if (next.tag) sp.set("tag", next.tag);
    if (next.done !== "all") sp.set("done", next.done);
    if (next.sortBy !== "createdAt") sp.set("sortBy", next.sortBy);
    if (next.sortDir !== "desc") sp.set("sortDir", next.sortDir);
    if (next.page !== 1) sp.set("page", String(next.page));
    setParams(sp, { replace: false });
  }

  return [query, update];
}
```

### デバウンスフック

```ts
// src/lib/useDebounced.ts
import { useEffect, useState } from "react";

export function useDebounced<T>(value: T, delay = 300): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return debounced;
}
```

### 検索ボックス

```tsx
function SearchBox({
  value,
  onChange,
}: {
  value: string;
  onChange: (v: string) => void;
}) {
  const [local, setLocal] = useState(value);
  const debounced = useDebounced(local, 300);

  // 親の値（URL）が外から変わったら追従
  useEffect(() => setLocal(value), [value]);

  // デバウンス後に親へ反映
  useEffect(() => {
    if (debounced !== value) onChange(debounced);
  }, [debounced]);

  return (
    <input
      type="search"
      value={local}
      onChange={(e) => setLocal(e.target.value)}
      placeholder="タスクを検索..."
      aria-label="タスクを検索"
    />
  );
}
```

### React Query との接続

```tsx
function TaskListPage() {
  const [query, update] = useListQuery();
  const { data, isFetching } = useQuery({
    queryKey: ["tasks", query],
    queryFn: () => fetchTasks(query),
    placeholderData: (prev) => prev, // ページ移動でもチラつかない
  });

  return (
    <>
      <SearchBox value={query.search} onChange={(v) => update({ search: v })} />
      <FilterBar query={query} onChange={update} />
      <SortMenu query={query} onChange={update} />
      {isFetching && <SmallSpinner />}
      <TaskTable items={data?.items ?? []} />
      <Pagination
        page={query.page}
        total={data?.total ?? 0}
        pageSize={20}
        onChange={(p) => update({ page: p })}
      />
    </>
  );
}
```

`placeholderData: (prev) => prev` は、ページ遷移時に「古いデータを表示しつつ裏で再フェッチ」するオプションです。表示が一瞬空にならず UX が向上します。

### ソートメニュー

```tsx
function SortMenu({
  query,
  onChange,
}: {
  query: ListQuery;
  onChange: (p: Partial<ListQuery>) => void;
}) {
  return (
    <div>
      <label>
        並び順:
        <select
          value={query.sortBy}
          onChange={(e) =>
            onChange({ sortBy: e.target.value as ListQuery["sortBy"] })
          }
        >
          <option value="createdAt">作成日</option>
          <option value="dueDate">期限</option>
          <option value="priority">優先度</option>
        </select>
      </label>
      <button
        onClick={() =>
          onChange({ sortDir: query.sortDir === "asc" ? "desc" : "asc" })
        }
        aria-label="並び順反転"
      >
        {query.sortDir === "asc" ? "↑" : "↓"}
      </button>
    </div>
  );
}
```

### ページネーション

```tsx
function Pagination({
  page,
  total,
  pageSize,
  onChange,
}: {
  page: number;
  total: number;
  pageSize: number;
  onChange: (page: number) => void;
}) {
  const totalPages = Math.max(1, Math.ceil(total / pageSize));
  return (
    <nav aria-label="ページネーション">
      <button onClick={() => onChange(page - 1)} disabled={page <= 1}>
        前へ
      </button>
      <span>
        {page} / {totalPages}
      </span>
      <button
        onClick={() => onChange(page + 1)}
        disabled={page >= totalPages}
      >
        次へ
      </button>
    </nav>
  );
}
```

### 無限スクロール版（おまけ）

```tsx
import { useInfiniteQuery } from "@tanstack/react-query";

function InfiniteTaskList() {
  const { data, fetchNextPage, hasNextPage } = useInfiniteQuery({
    queryKey: ["tasks-infinite"],
    queryFn: ({ pageParam = 1 }) => fetchTasks({ page: pageParam }),
    initialPageParam: 1,
    getNextPageParam: (last, all) =>
      last.items.length === 20 ? all.length + 1 : undefined,
  });

  // IntersectionObserver でリスト末尾を監視するパターンが定番
  const sentinelRef = useRef<HTMLDivElement>(null);
  useEffect(() => {
    const el = sentinelRef.current;
    if (!el || !hasNextPage) return;
    const ob = new IntersectionObserver((entries) => {
      if (entries[0].isIntersecting) fetchNextPage();
    });
    ob.observe(el);
    return () => ob.disconnect();
  }, [hasNextPage]);

  return (
    <ul>
      {data?.pages.flatMap((p) => p.items).map((t) => (
        <li key={t.id}>{t.title}</li>
      ))}
      <div ref={sentinelRef} style={{ height: 1 }} />
    </ul>
  );
}
```

## ❌ よくある間違い

### 1. 検索のたびに入力欄が空になる

URL → state の同期が下手だと起きます。`useEffect(() => setLocal(value), [value])` のような片方向の追従が大事です。

### 2. デバウンスを忘れる

入力 1 文字ごとに API を叩いて、リクエスト数百本が並ぶ事故。300ms のデバウンスで桁違いに改善します。

### 3. 検索を変えてもページが残る

「検索結果 5 件しかないのに 3 ページ目を見ている」状態。検索やフィルタ変更時はページ 1 に戻す。

### 4. queryKey に検索条件を入れ忘れる

```tsx
useQuery({ queryKey: ["tasks"], queryFn: () => fetchTasks(query) }); // ❌
```

これだと検索を変えても再フェッチされません。`["tasks", query]` のように依存をキーに含めましょう。

### 5. ページ移動時に画面が空白になる

`placeholderData: (prev) => prev` を使うか、スケルトン UI を出すなどして空白の瞬間を作らないこと。

## ✅ ベストプラクティス

1. **検索条件は 1 オブジェクトで管理する**: 個別 useState より整合性が取りやすい。
2. **URL クエリと同期する**: リロード・共有・戻るボタンが自然に動く。
3. **検索はデバウンス、ページ送りは即時**: 操作の性質によって応答速度を変える。
4. **空状態 / エラー状態を必ず描く**: 「該当なし」のメッセージがないと、ユーザーは壊れたと思います。
5. **総件数を表示する**: 「全 137 件中 1〜20 件」のように見せると安心感が出る。

## 📝 まとめ

- 一覧 UX は「検索・絞込・ソート・ページネーション」の組み合わせ
- 状態は 1 つにまとめ、URL クエリと同期させる
- デバウンスで API 連打を防ぐ
- React Query の `queryKey` には検索条件を含める
- 業務系はページ番号、SNS 系は無限スクロールが定番
