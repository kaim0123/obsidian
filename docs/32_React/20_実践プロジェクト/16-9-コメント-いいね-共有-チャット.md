# 16-9 コメント/いいね/共有/チャット（コミュニケーション機能）

## 🎯 この章で学ぶこと

- コメント・いいね・共有・チャットといった「ソーシャル機能」の典型実装
- 楽観的更新を使った「いいね」のサクサク UX
- WebSocket / Server-Sent Events を使ったリアルタイム更新の基礎
- 共有 URL（パーマリンク）と権限管理の考え方
- コミュニケーション機能特有のセキュリティ（XSS、CSRF、スパム）

## 📖 概念の説明

### コミュニケーション機能の難しさ

CRUD と違い、コミュニケーション機能には次の難しさがあります。

1. **リアルタイム性**: 相手がコメントしたら即座に表示されてほしい
2. **競合**: 同じ画面を 2 人が見ているときの整合性
3. **悪意のあるユーザーへの対処**: スパム・XSS・なりすまし
4. **見せ方の工夫**: 楽観的更新、未読カウント、タイピング表示

つまり、UI 設計・ネットワーク設計・セキュリティの 3 つを総動員します。

### リアルタイムの選択肢

| 技術 | 特徴 | 向いている用途 |
|------|------|---------------|
| ポーリング | 定期的に GET を送る | 緩い更新でよいもの |
| Server-Sent Events (SSE) | サーバ→クライアント片方向 | 通知、ライブ更新 |
| WebSocket | 双方向、低遅延 | チャット、ゲーム |

### 楽観的更新の鉄則: いいね

「いいね」を押した瞬間に♡を赤くする。サーバ応答は気にしない。失敗時のみ戻す。これがソーシャル UX の常識です。

### 共有とパーマリンク

「タスクの URL を渡せば、相手も同じ画面を見られる」という機能。権限の設計が肝心です。

- **公開リンク**: URL を知っていれば誰でも見れる
- **メンバー限定**: ログインユーザーかつメンバーのみ
- **編集権限と閲覧権限の分離**

### XSS とコメント

コメント機能は XSS の温床です。`<script>alert(1)</script>` を投稿されて、それを `dangerouslySetInnerHTML` で表示すれば即アウト。

幸い、React は標準でテキストをエスケープしてくれるので、`{comment.body}` と書いていれば安全。Markdown を許可するなら `react-markdown` + サニタイズが必須です。

## 💻 コード例

### いいね（楽観的更新）

```tsx
function LikeButton({ task }: { task: Task & { likedByMe: boolean; likeCount: number } }) {
  const qc = useQueryClient();
  const mutation = useMutation({
    mutationFn: () =>
      api(`/tasks/${task.id}/like`, {
        method: task.likedByMe ? "DELETE" : "POST",
      }),
    onMutate: async () => {
      await qc.cancelQueries({ queryKey: ["tasks"] });
      const prev = qc.getQueryData<any>(["tasks"]);
      qc.setQueryData(["tasks"], (old: any) =>
        old
          ? {
              ...old,
              items: old.items.map((t: Task & any) =>
                t.id === task.id
                  ? {
                      ...t,
                      likedByMe: !t.likedByMe,
                      likeCount: t.likedByMe ? t.likeCount - 1 : t.likeCount + 1,
                    }
                  : t
              ),
            }
          : old
      );
      return { prev };
    },
    onError: (_e, _v, ctx) => ctx?.prev && qc.setQueryData(["tasks"], ctx.prev),
    onSettled: () => qc.invalidateQueries({ queryKey: ["tasks"] }),
  });

  return (
    <button
      onClick={() => mutation.mutate()}
      aria-pressed={task.likedByMe}
      aria-label={task.likedByMe ? "いいね解除" : "いいね"}
    >
      {task.likedByMe ? "❤" : "♡"} {task.likeCount}
    </button>
  );
}
```

### コメント一覧 + 投稿

```tsx
function CommentSection({ taskId }: { taskId: string }) {
  const { data: comments } = useQuery({
    queryKey: ["comments", taskId],
    queryFn: () => api<Comment[]>(`/tasks/${taskId}/comments`),
  });
  const [body, setBody] = useState("");
  const post = useMutation({
    mutationFn: (body: string) =>
      api<Comment>(`/tasks/${taskId}/comments`, {
        method: "POST",
        body: JSON.stringify({ body }),
      }),
    onSuccess: () => {
      setBody("");
      qc.invalidateQueries({ queryKey: ["comments", taskId] });
    },
  });
  const qc = useQueryClient();

  return (
    <section aria-label="コメント">
      <ul>
        {comments?.map((c) => (
          <li key={c.id}>
            <strong>{c.authorName}</strong>
            <time dateTime={c.createdAt}>
              {new Date(c.createdAt).toLocaleString()}
            </time>
            {/* React がエスケープしてくれるので XSS 安全 */}
            <p>{c.body}</p>
          </li>
        ))}
      </ul>
      <form
        onSubmit={(e) => {
          e.preventDefault();
          if (body.trim()) post.mutate(body.trim());
        }}
      >
        <textarea
          value={body}
          onChange={(e) => setBody(e.target.value)}
          maxLength={500}
          aria-label="コメント本文"
        />
        <button disabled={post.isPending || !body.trim()}>投稿</button>
      </form>
    </section>
  );
}
```

### 共有: パーマリンクとコピーボタン

```tsx
function ShareButton({ taskId }: { taskId: string }) {
  const url = `${window.location.origin}/tasks/${taskId}`;
  const [copied, setCopied] = useState(false);

  async function copy() {
    await navigator.clipboard.writeText(url);
    setCopied(true);
    setTimeout(() => setCopied(false), 2000);
  }

  return (
    <div>
      <input readOnly value={url} aria-label="共有 URL" />
      <button onClick={copy}>{copied ? "コピーしました!" : "コピー"}</button>
    </div>
  );
}
```

### Server-Sent Events で通知を受け取る

```tsx
function useNotifications() {
  const qc = useQueryClient();
  useEffect(() => {
    const es = new EventSource("/api/notifications/stream");
    es.addEventListener("comment-added", (e) => {
      const data = JSON.parse((e as MessageEvent).data);
      qc.invalidateQueries({ queryKey: ["comments", data.taskId] });
      toast(`${data.authorName} さんがコメントしました`);
    });
    es.onerror = () => {
      // 自動再接続される。長期切断ならログを取るとよい
    };
    return () => es.close();
  }, [qc]);
}
```

### WebSocket でチャット

```tsx
function ChatRoom({ roomId }: { roomId: string }) {
  const [messages, setMessages] = useState<ChatMsg[]>([]);
  const [text, setText] = useState("");
  const wsRef = useRef<WebSocket | null>(null);

  useEffect(() => {
    const ws = new WebSocket(`wss://taskmate.example.com/rooms/${roomId}`);
    wsRef.current = ws;
    ws.onmessage = (e) => {
      const msg = JSON.parse(e.data) as ChatMsg;
      setMessages((prev) => [...prev, msg]);
    };
    ws.onclose = () => console.log("ws closed");
    return () => ws.close();
  }, [roomId]);

  function send() {
    if (!text.trim() || wsRef.current?.readyState !== WebSocket.OPEN) return;
    wsRef.current.send(JSON.stringify({ body: text }));
    setText("");
  }

  return (
    <div role="log" aria-live="polite">
      <ul>
        {messages.map((m) => (
          <li key={m.id}>
            <strong>{m.authorName}:</strong> {m.body}
          </li>
        ))}
      </ul>
      <input
        value={text}
        onChange={(e) => setText(e.target.value)}
        onKeyDown={(e) => e.key === "Enter" && send()}
        aria-label="メッセージを入力"
      />
      <button onClick={send}>送信</button>
    </div>
  );
}
```

`role="log"` と `aria-live="polite"` を付けるとスクリーンリーダーが新着メッセージを読み上げます。

### 未読数のバッジ表示

```tsx
function UnreadBadge() {
  const { data } = useQuery({
    queryKey: ["unread-count"],
    queryFn: () => api<{ count: number }>("/me/unread"),
    refetchInterval: 30_000, // 30 秒ごとに更新
  });

  if (!data || data.count === 0) return null;
  return (
    <span aria-label={`未読 ${data.count} 件`}>
      {data.count > 99 ? "99+" : data.count}
    </span>
  );
}
```

### Markdown コメントの安全な描画

```tsx
import ReactMarkdown from "react-markdown";
import rehypeSanitize from "rehype-sanitize";

function MarkdownComment({ body }: { body: string }) {
  return (
    <ReactMarkdown rehypePlugins={[rehypeSanitize]}>{body}</ReactMarkdown>
  );
}
```

`rehype-sanitize` がないと、`<script>` や `onerror` 属性が通って XSS になります。

## ❌ よくある間違い

### 1. 「いいね」をサーバ応答後に反映する

タップから 0.5 秒♡が変わらないと、現代のユーザーには遅すぎます。楽観的更新が事実上必須。

### 2. コメント本文を `dangerouslySetInnerHTML` で表示

ユーザー入力を生 HTML として扱うのは XSS の典型パターン。プレーンテキストか、サニタイズ済みの Markdown を使う。

### 3. WebSocket の close を忘れる

ページ遷移しても接続が残り続け、メモリリーク + サーバ側のコネクション枯渇に。`useEffect` のクリーンアップで `ws.close()` を必ず呼ぶ。

### 4. ポーリング間隔が短すぎる

「リアルタイム感のため」と 1 秒ごとに `/api/comments` を叩くと、サーバ費用が爆発します。SSE / WebSocket を使うか、最低 10 秒間隔を目安に。

### 5. 共有 URL の権限チェックをフロントだけで行う

URL を知っているだけで API が叩けてしまう実装はアウト。サーバ側でログイン状態 + メンバーシップを必ず確認。

## ✅ ベストプラクティス

1. **コメント表示は React のテキスト出力に任せる**: 何もしなくてもエスケープされる。
2. **Markdown を扱うときは必ずサニタイズ**: `rehype-sanitize` を入れる。
3. **WebSocket / SSE は cleanup を厳密に**: 接続漏れはサーバを殺す。
4. **未読・通知は SSE が省コスト**: 双方向不要ならポーリング・WebSocket より軽い。
5. **共有リンクは「短い URL + 権限スコープ」**: 「閲覧のみ」「編集可」を URL のトークンで分けると拡張しやすい。

## 📝 まとめ

- いいねは楽観的更新でサクサクに、コメントは XSS に注意
- リアルタイムはポーリング / SSE / WebSocket を用途で使い分ける
- WebSocket は cleanup を絶対に忘れない
- 共有 URL の権限チェックはサーバ側が本丸、フロントは UX
- アクセシビリティ（aria-live, aria-pressed）も意識する
