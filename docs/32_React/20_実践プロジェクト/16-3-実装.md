# 16-3 実装（CRUD + 認証/認可の形）

## 🎯 この章で学ぶこと

- React Query（TanStack Query）を使った CRUD 実装の典型パターンを学ぶ
- JWT を用いたログイン / トークン保存 / 認証付きリクエストの組み立てを理解する
- 「認証（誰か）」と「認可（何ができるか）」の違いを区別できる
- ProtectedRoute（ログイン必須ページ）の作り方を覚える
- 楽観的更新（Optimistic Update）の使いどころを知る

## 📖 概念の説明

### CRUD とは

C: Create（作成）、R: Read（取得）、U: Update（更新）、D: Delete（削除）の頭文字。アプリの 9 割はこの 4 つの組み合わせでできています。

### サーバ状態は React Query で

サーバから取ってきたデータを `useState` に入れて自前で管理するのは、現代では辛い道です。なぜなら、

- キャッシュ
- 再フェッチ
- ローディング/エラー表示
- 楽観的更新
- 失効・再検証

をすべて自前で書くことになるからです。React Query（現 TanStack Query）はこれを全部肩代わりしてくれます。

### 認証と認可の違い

- **認証（Authentication）**: あなたが誰かを確認する。例: メール+パスワードでログイン
- **認可（Authorization）**: あなたが何をしてよいかを判定する。例: 管理者のみ全ユーザーを見れる

混同すると、「ログインしているのに自分のデータが取れない」「他人のデータが見える」のような事故になります。

### JWT（JSON Web Token）

ログイン成功時にサーバが発行する「身分証明書」のような文字列です。フロントはこれを保存しておき、API リクエスト時に `Authorization: Bearer <token>` ヘッダで送ります。

保存場所には議論があります。

- **localStorage**: 楽だが XSS に弱い
- **httpOnly Cookie**: XSS に強いが CSRF 対策が必要
- **メモリ（変数）**: 一番安全だがリロードで消える

現代では「リフレッシュトークンは httpOnly Cookie + アクセストークンはメモリ」が主流です。学習目的では `localStorage` でも構いませんが、本番では避けましょう。

## 💻 コード例

### セットアップ: QueryClient

```tsx
// src/main.tsx
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { ReactQueryDevtools } from "@tanstack/react-query-devtools";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000, // 30 秒間はキャッシュを「新鮮」とみなす
      retry: 1,
    },
  },
});

createRoot(document.getElementById("root")!).render(
  <QueryClientProvider client={queryClient}>
    <App />
    <ReactQueryDevtools />
  </QueryClientProvider>
);
```

### API クライアント（fetch ラッパ）

```ts
// src/lib/api.ts
import { getToken } from "./auth";

export async function api<T>(
  path: string,
  init: RequestInit = {}
): Promise<T> {
  const token = getToken();
  const res = await fetch(`/api${path}`, {
    ...init,
    headers: {
      "Content-Type": "application/json",
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...init.headers,
    },
  });

  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new ApiError(res.status, body.message ?? res.statusText);
  }
  return res.json();
}

export class ApiError extends Error {
  constructor(public status: number, message: string) {
    super(message);
  }
}
```

### Read: タスク一覧を取得する

```tsx
// src/features/tasks/useTasks.ts
import { useQuery } from "@tanstack/react-query";
import { api } from "@/lib/api";
import type { Task } from "@/types";

export function useTasks(params: { search?: string; page?: number } = {}) {
  return useQuery({
    queryKey: ["tasks", params],
    queryFn: () => {
      const qs = new URLSearchParams();
      if (params.search) qs.set("search", params.search);
      if (params.page) qs.set("page", String(params.page));
      return api<{ items: Task[]; total: number }>(`/tasks?${qs}`);
    },
  });
}
```

```tsx
// 使う側
function TaskListPage() {
  const { data, isLoading, error } = useTasks({ page: 1 });

  if (isLoading) return <Spinner />;
  if (error) return <ErrorBox message={(error as Error).message} />;

  return (
    <ul>
      {data!.items.map((t) => (
        <TaskItem key={t.id} task={t} />
      ))}
    </ul>
  );
}
```

### Create: タスクを追加する（楽観的更新つき）

```tsx
// src/features/tasks/useCreateTask.ts
import { useMutation, useQueryClient } from "@tanstack/react-query";

export function useCreateTask() {
  const qc = useQueryClient();

  return useMutation({
    mutationFn: (input: { title: string }) =>
      api<Task>("/tasks", {
        method: "POST",
        body: JSON.stringify(input),
      }),

    // 楽観的更新: サーバ応答を待たず先に画面を更新する
    onMutate: async (input) => {
      await qc.cancelQueries({ queryKey: ["tasks"] });
      const prev = qc.getQueryData<{ items: Task[]; total: number }>([
        "tasks",
        {},
      ]);
      const optimistic: Task = {
        id: `tmp-${Date.now()}`,
        title: input.title,
        done: false,
        dueDate: null,
        priority: "medium",
        tags: [],
        createdAt: new Date().toISOString(),
      };
      qc.setQueryData(["tasks", {}], (old: any) => ({
        items: [optimistic, ...(old?.items ?? [])],
        total: (old?.total ?? 0) + 1,
      }));
      return { prev };
    },
    onError: (_err, _input, ctx) => {
      // 失敗したら元に戻す
      if (ctx?.prev) qc.setQueryData(["tasks", {}], ctx.prev);
    },
    onSettled: () => qc.invalidateQueries({ queryKey: ["tasks"] }),
  });
}
```

### Update / Delete

```tsx
export function useUpdateTask() {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: ({ id, ...patch }: { id: string } & Partial<Task>) =>
      api<Task>(`/tasks/${id}`, {
        method: "PATCH",
        body: JSON.stringify(patch),
      }),
    onSuccess: () => qc.invalidateQueries({ queryKey: ["tasks"] }),
  });
}

export function useDeleteTask() {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: (id: string) => api<void>(`/tasks/${id}`, { method: "DELETE" }),
    onSuccess: () => qc.invalidateQueries({ queryKey: ["tasks"] }),
  });
}
```

### 認証: ログインと AuthContext

```tsx
// src/lib/auth.tsx
import { createContext, useContext, useEffect, useState } from "react";

type AuthContextValue = {
  user: { id: string; email: string } | null;
  login: (email: string, password: string) => Promise<void>;
  logout: () => void;
};

const AuthContext = createContext<AuthContextValue | null>(null);

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<AuthContextValue["user"]>(null);

  useEffect(() => {
    const token = getToken();
    if (token) {
      api<{ id: string; email: string }>("/me")
        .then(setUser)
        .catch(() => clearToken());
    }
  }, []);

  async function login(email: string, password: string) {
    const { token, user } = await api<{ token: string; user: any }>(
      "/auth/login",
      {
        method: "POST",
        body: JSON.stringify({ email, password }),
      }
    );
    setToken(token);
    setUser(user);
  }

  function logout() {
    clearToken();
    setUser(null);
  }

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth must be used inside AuthProvider");
  return ctx;
}

// トークン保存ヘルパ（学習用に localStorage を使用）
const KEY = "taskmate_token";
export const getToken = () => localStorage.getItem(KEY);
export const setToken = (t: string) => localStorage.setItem(KEY, t);
export const clearToken = () => localStorage.removeItem(KEY);
```

### 認可: ProtectedRoute

```tsx
// src/components/ProtectedRoute.tsx
import { Navigate, useLocation } from "react-router-dom";
import { useAuth } from "@/lib/auth";

export function ProtectedRoute({ children }: { children: React.ReactNode }) {
  const { user } = useAuth();
  const location = useLocation();

  if (!user) {
    return <Navigate to="/login" state={{ from: location }} replace />;
  }
  return <>{children}</>;
}
```

```tsx
// ルーティング側
<Routes>
  <Route path="/login" element={<LoginPage />} />
  <Route
    path="/"
    element={
      <ProtectedRoute>
        <TaskListPage />
      </ProtectedRoute>
    }
  />
</Routes>
```

## ❌ よくある間違い

### 1. fetch を毎回コンポーネント内に書く

```tsx
// ❌ 悪い例
useEffect(() => {
  fetch("/api/tasks")
    .then((r) => r.json())
    .then(setTasks);
}, []);
```

これは「キャッシュなし、再取得なし、エラーハンドリングなし」のフルコンボです。React Query を使いましょう。

### 2. トークンをコンポーネントの state に持つ

リロードで消える、複数タブで同期しない、という事故が起きます。`localStorage` か Cookie に保存し、Context で読み出します。

### 3. 楽観的更新の onError でロールバックしない

「成功したように見えたのに、エラーで実は登録できていなかった」が起きます。必ず `onError` で元に戻しましょう。

### 4. `queryKey` の設計が雑

```tsx
useQuery({ queryKey: ["tasks"], ... }); // ページや検索条件が変わってもキャッシュが共有される
```

検索条件 / ページ番号などはキーに含めましょう。`["tasks", { page, search }]` のように。

### 5. 認可をフロントだけで行う

「管理者用ボタンを `if (user.role === 'admin')` で隠す」だけでは、API を直接叩かれたら終わりです。バックエンドでも必ずチェックします。フロントの認可は UX のため、バックエンドの認可がセキュリティのため。

## ✅ ベストプラクティス

1. **サーバ状態は React Query、UI 状態は useState**: この棲み分けを守ると 8 割ハッピーになれる。
2. **API クライアントを 1 箇所にまとめる**: `lib/api.ts` のような共通層を作り、トークン付与もそこで行う。
3. **mutation の onSettled で invalidateQueries**: 楽観でも失敗してもキャッシュを最終確認させる。
4. **認証状態は Context で配る、ただし更新頻度に注意**: 値が頻繁に変わると下流の再レンダーが多発します。
5. **エラーは型を分ける**: `ApiError`, `ValidationError` のように型を分けると、UI 側で出し分けやすい。

## 📝 まとめ

- CRUD は React Query の `useQuery` / `useMutation` で組むのが現代の標準
- 楽観的更新は速い UX を生むが、失敗時のロールバックを忘れない
- 認証は「あなたが誰か」、認可は「あなたが何をできるか」
- JWT は localStorage よりメモリ + httpOnly Cookie が安全。学習中は localStorage でも可
- フロントの認可は UX、バックエンドの認可がセキュリティ
