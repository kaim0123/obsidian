# 絞込み機能の実装方法とベストプラクティス

## 概要

絞込み機能の実装には主に3つの方法があります。それぞれの特徴、メリット・デメリット、使用場面を詳しく解説します。

## 実装方法の比較表

| 項目 | URLパラメータ | ローカル状態 | グローバル状態 |
|------|---------------|--------------|----------------|
| **実装の複雑さ** | ⭐⭐⭐ 複雑 | ⭐ 簡単 | ⭐⭐ 中程度 |
| **パフォーマンス** | ⭐⭐ 中程度 | ⭐⭐⭐ 高速 | ⭐⭐ 中程度 |
| **状態の永続化** | ✅ あり | ❌ なし | ✅ あり |
| **ブックマーク可能** | ✅ 可能 | ❌ 不可 | ❌ 不可 |
| **URL共有** | ✅ 可能 | ❌ 不可 | ❌ 不可 |
| **SEO対応** | ✅ 対応 | ❌ 非対応 | ❌ 非対応 |
| **リアルタイム検索** | ❌ 不向き | ✅ 向いている | ✅ 向いている |
| **コンポーネント間共有** | ❌ 困難 | ❌ 困難 | ✅ 容易 |
| **ブラウザ履歴対応** | ✅ 自動対応 | ❌ 非対応 | ❌ 非対応 |
| **学習コスト** | ⭐⭐ 中程度 | ⭐ 低い | ⭐⭐⭐ 高い |
| **バンドルサイズ** | 影響なし | 影響なし | 増加する可能性 |
| **デバッグのしやすさ** | ⭐⭐ 中程度 | ⭐⭐⭐ 簡単 | ⭐⭐ 中程度 |

### 推奨使用場面

| 実装方法 | 最適な使用場面 | 例 |
|----------|----------------|-----|
| **URLパラメータ** | 検索結果の共有が必要 | ECサイト、ブログ、求人サイト |
| **ローカル状態** | 一時的な絞込み | フォーム、モーダル、計算機 |
| **グローバル状態** | 複雑な状態管理が必要 | ダッシュボード、管理画面、ゲーム |

## 1. URLパラメータ

### 概要
URLのクエリパラメータを使用して絞込み条件を管理する方法

### 実装例

```javascript
// Next.jsでの実装例
import { useRouter } from 'next/router';
import { useEffect, useState } from 'react';

function ProductList() {
  const router = useRouter();
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(false);

  // URLパラメータから絞込み条件を取得
  const { category, price, search } = router.query;

  useEffect(() => {
    const fetchProducts = async () => {
      setLoading(true);
      const params = new URLSearchParams();
      
      if (category) params.append('category', category);
      if (price) params.append('price', price);
      if (search) params.append('search', search);

      const response = await fetch(`/api/products?${params}`);
      const data = await response.json();
      setProducts(data);
      setLoading(false);
    };

    fetchProducts();
  }, [category, price, search]);

  const updateFilter = (key, value) => {
    const query = { ...router.query };
    if (value) {
      query[key] = value;
    } else {
      delete query[key];
    }
    router.push({ pathname: router.pathname, query });
  };

  return (
    <div>
      <input
        placeholder="検索..."
        value={search || ''}
        onChange={(e) => updateFilter('search', e.target.value)}
      />
      <select
        value={category || ''}
        onChange={(e) => updateFilter('category', e.target.value)}
      >
        <option value="">すべてのカテゴリ</option>
        <option value="electronics">電子機器</option>
        <option value="clothing">衣類</option>
      </select>
      {/* 商品リストの表示 */}
    </div>
  );
}
```

### メリット
- ✅ **ブックマーク可能**: 絞込み状態をURLで共有・保存できる
- ✅ **ブラウザの戻る/進むボタン対応**: 履歴管理が自動で行われる
- ✅ **SEO対応**: 検索エンジンが絞込み状態を認識できる
- ✅ **サーバーサイドレンダリング対応**: 初期状態をサーバーで設定可能
- ✅ **状態の永続化**: ページリロード後も絞込み状態が維持される

### デメリット
- ❌ **URLが長くなる**: 複雑な絞込み条件でURLが長大になる
- ❌ **実装が複雑**: パラメータの管理とバリデーションが必要
- ❌ **パフォーマンス**: URL変更のたびにAPIリクエストが発生する可能性
- ❌ **デバウンスが困難**: リアルタイム検索には不向き

### 使用場面
- 🔍 **検索結果ページ**: ユーザーが検索条件を共有したい場合
- 🛒 **ECサイトの商品一覧**: カテゴリや価格帯での絞込み
- 📰 **ブログ・ニュースサイト**: タグやカテゴリでの絞込み
- 💼 **企業サイトの求人一覧**: 職種や勤務地での絞込み

## 2. ローカル状態

### 概要
ReactのuseStateやuseReducerを使用してコンポーネント内で絞込み状態を管理する方法

### 実装例

```javascript
import { useState, useMemo } from 'react';

function TodoList() {
  const [todos, setTodos] = useState([
    { id: 1, title: '買い物', completed: false, category: 'personal' },
    { id: 2, title: '会議', completed: true, category: 'work' },
    { id: 3, title: '運動', completed: false, category: 'health' }
  ]);

  // ローカル状態で絞込み条件を管理
  const [searchTerm, setSearchTerm] = useState('');
  const [selectedCategory, setSelectedCategory] = useState('all');
  const [showCompleted, setShowCompleted] = useState(false);

  // 絞込み処理（メモ化でパフォーマンス最適化）
  const filteredTodos = useMemo(() => {
    return todos.filter(todo => {
      const matchesSearch = todo.title.toLowerCase().includes(searchTerm.toLowerCase());
      const matchesCategory = selectedCategory === 'all' || todo.category === selectedCategory;
      const matchesCompleted = showCompleted ? todo.completed : !todo.completed;
      
      return matchesSearch && matchesCategory && matchesCompleted;
    });
  }, [todos, searchTerm, selectedCategory, showCompleted]);

  return (
    <div>
      <input
        type="text"
        placeholder="検索..."
        value={searchTerm}
        onChange={(e) => setSearchTerm(e.target.value)}
      />
      
      <select
        value={selectedCategory}
        onChange={(e) => setSelectedCategory(e.target.value)}
      >
        <option value="all">すべて</option>
        <option value="personal">個人</option>
        <option value="work">仕事</option>
        <option value="health">健康</option>
      </select>

      <label>
        <input
          type="checkbox"
          checked={showCompleted}
          onChange={(e) => setShowCompleted(e.target.checked)}
        />
        完了済みを表示
      </label>

      <ul>
        {filteredTodos.map(todo => (
          <li key={todo.id}>{todo.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

### メリット
- ✅ **実装が簡単**: useStateで簡単に実装できる
- ✅ **パフォーマンスが良い**: ローカルでの処理で高速
- ✅ **リアルタイム対応**: 入力と同時に絞込みが実行される
- ✅ **デバウンスが容易**: 簡単にデバウンスを実装できる
- ✅ **メモリ効率**: 不要なAPIリクエストがない

### デメリット
- ❌ **状態の永続化なし**: ページリロードで状態が失われる
- ❌ **共有が困難**: 絞込み状態を他のユーザーと共有できない
- ❌ **ブックマーク不可**: 特定の絞込み状態をブックマークできない
- ❌ **コンポーネント間の連携が困難**: 他のコンポーネントから状態にアクセスできない

### 使用場面
- 📝 **フォーム内の絞込み**: 入力候補の絞込み
- 🎯 **モーダル内の選択**: 一時的な絞込み
- ⚡ **リアルタイム検索**: 入力と同時に結果を表示
- 🧮 **計算機アプリ**: 一時的な条件設定

## 3. グローバル状態

### 概要
Redux、Zustand、Context APIなどでアプリケーション全体で絞込み状態を管理する方法

### 実装例（Zustand使用）

```javascript
// store/filterStore.js
import { create } from 'zustand';
import { persist } from 'zustand/middleware';

const useFilterStore = create(
  persist(
    (set, get) => ({
      // 絞込み状態
      filters: {
        search: '',
        category: 'all',
        priceRange: [0, 1000],
        sortBy: 'name',
        showInStock: true
      },
      
      // アクション
      setSearch: (search) => set(state => ({
        filters: { ...state.filters, search }
      })),
      
      setCategory: (category) => set(state => ({
        filters: { ...state.filters, category }
      })),
      
      setPriceRange: (priceRange) => set(state => ({
        filters: { ...state.filters, priceRange }
      })),
      
      setSortBy: (sortBy) => set(state => ({
        filters: { ...state.filters, sortBy }
      })),
      
      toggleInStock: () => set(state => ({
        filters: { 
          ...state.filters, 
          showInStock: !state.filters.showInStock 
        }
      })),
      
      resetFilters: () => set({
        filters: {
          search: '',
          category: 'all',
          priceRange: [0, 1000],
          sortBy: 'name',
          showInStock: true
        }
      })
    }),
    {
      name: 'filter-storage', // localStorage のキー名
    }
  )
);

export default useFilterStore;
```

```javascript
// components/ProductList.jsx
import { useFilterStore } from '../store/filterStore';
import { useMemo } from 'react';

function ProductList({ products }) {
  const { filters, setSearch, setCategory, setPriceRange } = useFilterStore();

  // 絞込み処理
  const filteredProducts = useMemo(() => {
    return products.filter(product => {
      const matchesSearch = product.name.toLowerCase().includes(filters.search.toLowerCase());
      const matchesCategory = filters.category === 'all' || product.category === filters.category;
      const matchesPrice = product.price >= filters.priceRange[0] && product.price <= filters.priceRange[1];
      const matchesStock = filters.showInStock ? product.inStock : true;
      
      return matchesSearch && matchesCategory && matchesPrice && matchesStock;
    }).sort((a, b) => {
      switch (filters.sortBy) {
        case 'price':
          return a.price - b.price;
        case 'name':
          return a.name.localeCompare(b.name);
        default:
          return 0;
      }
    });
  }, [products, filters]);

  return (
    <div>
      <input
        type="text"
        placeholder="商品を検索..."
        value={filters.search}
        onChange={(e) => setSearch(e.target.value)}
      />
      
      <select
        value={filters.category}
        onChange={(e) => setCategory(e.target.value)}
      >
        <option value="all">すべてのカテゴリ</option>
        <option value="electronics">電子機器</option>
        <option value="clothing">衣類</option>
      </select>

      <div>
        <label>
          価格範囲: {filters.priceRange[0]} - {filters.priceRange[1]}
        </label>
        <input
          type="range"
          min="0"
          max="1000"
          value={filters.priceRange[1]}
          onChange={(e) => setPriceRange([filters.priceRange[0], parseInt(e.target.value)])}
        />
      </div>

      <div>
        {filteredProducts.map(product => (
          <div key={product.id}>{product.name}</div>
        ))}
      </div>
    </div>
  );
}
```

### メリット
- ✅ **状態の永続化**: localStorage等で状態を保存できる
- ✅ **コンポーネント間の連携**: 複数のコンポーネントで状態を共有
- ✅ **複雑な状態管理**: 複数の絞込み条件を一元管理
- ✅ **デバッグが容易**: 状態の変更を追跡しやすい
- ✅ **再利用性**: 他の画面でも同じ絞込み状態を使用可能

### デメリット
- ❌ **実装が複雑**: 状態管理ライブラリの学習コスト
- ❌ **オーバーエンジニアリング**: 簡単な絞込みには過剰
- ❌ **パフォーマンス**: 不要な再レンダリングが発生する可能性
- ❌ **バンドルサイズ**: 状態管理ライブラリの追加でサイズが増加

### 使用場面
- 🛒 **ECサイト全体**: 複数ページで絞込み状態を共有
- 📊 **ダッシュボード**: 複数のウィジェットで条件を共有
- 🎮 **ゲームアプリ**: 設定やフィルターの永続化
- ⚙️ **管理画面**: 複雑な絞込み条件の管理

## 組み合わせパターン

実際のアプリケーションでは、これらを組み合わせて使用することが多いです。

### パターン1: URL + ローカル状態

```javascript
// URLで主要な絞込み、ローカルで詳細な絞込み
function HybridFilter() {
  const router = useRouter();
  const { category } = router.query; // URLパラメータ
  const [searchTerm, setSearchTerm] = useState(''); // ローカル状態
  
  // 両方を組み合わせた絞込み
  const filteredItems = useMemo(() => {
    return items.filter(item => {
      const matchesCategory = !category || item.category === category;
      const matchesSearch = !searchTerm || item.name.includes(searchTerm);
      return matchesCategory && matchesSearch;
    });
  }, [items, category, searchTerm]);
}
```

### パターン2: グローバル + URL同期

```javascript
// グローバル状態をURLと同期
function SyncedGlobalFilter() {
  const router = useRouter();
  const { setFilters, filters } = useFilterStore();
  
  // URL変更時にグローバル状態を更新
  useEffect(() => {
    if (router.isReady) {
      setFilters(router.query);
    }
  }, [router.isReady, router.query]);
  
  // グローバル状態変更時にURLを更新
  const updateFilter = (newFilters) => {
    setFilters(newFilters);
    router.push({ query: newFilters }, undefined, { shallow: true });
  };
}
```

## パフォーマンス最適化のポイント

### 1. デバウンスの実装

```javascript
// デバウンス付きのURLパラメータ更新
import { useDebouncedCallback } from 'use-debounce';

function SearchWithDebounce() {
  const router = useRouter();
  
  const debouncedUpdateURL = useDebouncedCallback((searchTerm) => {
    const query = searchTerm ? { search: searchTerm } : {};
    router.push({ pathname: router.pathname, query }, undefined, { shallow: true });
  }, 500);

  return (
    <input
      onChange={(e) => debouncedUpdateURL(e.target.value)}
      placeholder="検索..."
    />
  );
}
```

function OptimizedLocalFilter({ items }) {
  const [searchTerm, setSearchTerm] = useState('');
  
  // メモ化でパフォーマンス最適化

## まとめ

| 実装方法 | 適用場面 | 主なメリット | 主なデメリット |
|---------|---------|-------------|---------------|
| **URLパラメータ** | 検索結果、ECサイト | ブックマーク可能、SEO対応 | 実装が複雑、URLが長くなる |
| **ローカル状態** | フォーム、モーダル | 実装が簡単、高速 | 状態の永続化なし |
| **グローバル状態** | 複雑なアプリ | 状態共有、永続化 | 実装が複雑、オーバーエンジニアリング |

### 選択の指針

1. **シンプルな絞込み** → ローカル状態
2. **共有が必要な絞込み** → URLパラメータ
3. **複雑な状態管理** → グローバル状態
4. **複数の要件** → 組み合わせパターン
