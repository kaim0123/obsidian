## ⚠️ よくある注意点

### 1. `current` を書き換えても UI は自動では更新されない

画面に出す値は **`useState`** や **親からの props**、**サーバーデータ**など、React が追跡できる更新経路に載せます。 **`useRef` は UI のソースにはしない**のが原則です。

### 2. `current` が `null` になり得る

マウント前・対応する要素がない・既にアンマウント後では `null` です。 `inputRef.current?.focus()` のように **ガード**します。

### 3. レンダー中の「DOM 前提」の処理に注意

レンダー関数は **純粋に近く保つ**方がデバッグしやすいです。 DOM 読み取りや `focus()` は **イベント**・**useEffect** に寄せます。

### 4. 「再レンダーを減らしたい」だけで ref だらけにしない

隠れた状態が増えると追跡が難しくなります。まずは **`useState` で意図が読めるモデル**にし、パフォーマンスや Effect の都合で **`useRef` を足す**イメージの方が安全です。

---

## 💡 パターン: 前回の値を記録する

「表示は現在値だけでよいが、**比較のために前回だけ知りたい**」ときの典型的な形です。更新のタイミングに注意すると、`useEffect` の **終了後**に「次のレンダー用の前回」として使えます。

```jsx
import { useEffect, useRef } from 'react';

function PreviousValue({ value }) {
  const prevValueRef = useRef();

  useEffect(() => {
    prevValueRef.current = value;
  }, [value]);

  return (
    <p>
      現在値: {value} / 前回値: {prevValueRef.current}
    </p>
  );
}
```

初回レンダーでは `prevValueRef.current` が未設定になり得ます。レンダーごとの「直前の値」だけを厳密に扱いたい場合は、`useState` で覚える・カスタムフックに切り出すなど別パターンもあります。

---

## 📝 まとめ

- `useRef` は **DOM 参照**と **再レンダー不要な値の保持**の両方に使える
- **`useState` との違いは「更新で再レンダーが走るか」**
- **表示に必要な真実の源泉（source of truth）は state** に置き、補助・DOM・ID 類を ref に載せると分かりやすい

覚える順のおすすめ:

1. `ref={xxx}` で DOM をつかむ
2. `xxx.current` にアクセスする
3. `useEffect` と組み合わせてマウント後処理に使う
