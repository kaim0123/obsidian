## 1. タイマー ID を保持する

`setInterval` の戻り値は「止めるとき」に必要ですが、**画面に表示する必要はありません**。`useRef` に入れると、bセットやクリックのたびに余計な再レンダーを増やしにくいです。

```jsx
import { useRef } from 'react';

function TimerExample() {
  const timerRef = useRef(null);

  const startTimer = () => {
    if (timerRef.current != null) return;
    timerRef.current = setInterval(() => {
      console.log('実行中...');
    }, 1000);
  };

  const stopTimer = () => {
    if (timerRef.current != null) {
      clearInterval(timerRef.current);
      timerRef.current = null;
    }
  };

  return (
    <div>
      <button type="button" onClick={startTimer}>開始</button>
      <button type="button" onClick={stopTimer}>停止</button>
    </div>
  );
}
```

**本番**では、アンマウント時に必ず `clearInterval` するなど、[[5-1-useEffectの役割|useEffect のクリーンアップ]]とセットで考えると安全です。

## 2. useState と並べると挙動がはっきりする

`ref` の更新は **再レンダーを発火しません**。そのため **同じレンダー結果の JSX** の中では、`ref.current` を読んでも「最新の代入」が画面に反映されていないことがあります（デバッグで混乱しやすいポイントです）。

```jsx
import { useRef, useState } from 'react';

function CompareStateAndRef() {
  const [stateCount, setStateCount] = useState(0);
  const refCount = useRef(0);

  return (
    <div>
      <p>stateCount（再レンダーで画面更新）: {stateCount}</p>
      <p>refCount（current を書き換えても、再レンダーされない限り表示は古いまま）: {refCount.current}</p>

      <button type="button" onClick={() => setStateCount((c) => c + 1)}>
        state を +1
      </button>

      <button
        type="button"
        onClick={() => {
          refCount.current += 1;
          console.log('refCount:', refCount.current);
        }}
      >
        ref を +1（ログで確認）
      </button>
    </div>
  );
}
```

- **画面に出したい数値**は `useState`
- **裏で数えたいだけ**なら `useRef`（または別の state 更新と組み合わせる）

## 💡 よくある用途（DOM 以外）

- イベント／`useEffect` 内で参照したい **最新の props / state**（クロージャ対策のパターンの一部）
- **WebSocket** や購読ハンドラのインスタンス
- **`requestAnimationFrame`** の ID
- **「直前に実行したか」**のフラグ（Strict Mode 対策では設計の見直しが前提になることもあります → [[5-4-StrictModeで2回動く理由]]）
