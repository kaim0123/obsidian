# 6-4 404/リダイレクト/保護ルート（認可の入口）

## 🎯 この章で学ぶこと

- 「該当するページがない」場合の404ページの作り方を学びます
- リダイレクト（自動転送）の実装方法が分かります
- 「ログインしていないとアクセスできないページ」の作り方を覚えます
- 認証（authentication）と認可（authorization）の違いを理解できます
- 保護ルート（Protected Route）の典型パターンを身につけます

## 📖 概念の説明

### 認証と認可の違い

**認証（authentication）**：あなたは誰？を確認する仕組み（ログイン）。
**認可（authorization）**：その人にこれをやらせていい？を判定する仕組み（権限）。

英語の頭が同じ "auth-" なので混同されますが、意味は違います。

例えるなら、

- 認証 = 会社の入り口で **社員証を見せて本人確認**
- 認可 = 役員フロアに行ける人は **役員のみ**

ルーティングの世界では、

- ログインしていないと見られないページ → **認証が必要**
- 管理者しか開けないページ → **認可が必要**

の2種類のチェックがよく出てきます。

### 404ページとは

URLにアクセスしたけど、対応するルートが存在しないとき、ユーザーに「ページが見つかりません」と伝えるページが **404ページ** です。

react-router-dom v6では `path="*"` というワイルドカードで定義します。

### リダイレクトとは

「URLにアクセスされたら、別のURLに自動で移動させる」のがリダイレクトです。

たとえば、

- 古いURL `/old-about` から新しい `/about` へ
- 未ログインで `/dashboard` にアクセスしたら `/login` へ

react-router-dom v6では `<Navigate />` というコンポーネントを使います。

### 保護ルート（Protected Route）

「ログインしている人だけアクセスできる」「管理者だけアクセスできる」という制限をかけたルートです。

実装パターンはシンプルで、**条件をチェックして、ダメなら `<Navigate>` する** というラッパーコンポーネントを作るだけです。

### 用語の整理

- **404**：HTTPステータスコードで「Not Found」を意味する
- **リダイレクト**：URLを別のURLに転送すること
- **保護ルート**：アクセス条件のあるルート
- **認証**：本人確認
- **認可**：権限の判定

## 💻 コード例

### 例1：404ページを作る

```jsx
import { Routes, Route } from 'react-router-dom';

function NotFound() {
  return (
    <div>
      <h1>404 - ページが見つかりません</h1>
      <p>URLを確認してください。</p>
      <Link to="/">ホームに戻る</Link>
    </div>
  );
}

function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />

      {/* どのルートにもマッチしなかったら */}
      <Route path="*" element={<NotFound />} />
    </Routes>
  );
}
```

`path="*"` はワイルドカードで、他のどれにもマッチしなかったときの **最後の砦** になります。`<Routes>` の中で **一番下に書く** のがコツです。

### 例2：単純なリダイレクト

```jsx
import { Navigate } from 'react-router-dom';

<Routes>
  {/* /old-about にアクセスしたら /about に飛ばす */}
  <Route path="/old-about" element={<Navigate to="/about" replace />} />
  <Route path="/about" element={<About />} />
</Routes>
```

`replace` を付けると履歴を置き換えます（ブラウザバックで戻れない）。古いURLからの転送には `replace` を付けるのが一般的です。

### 例3：プログラム的なリダイレクト

```jsx
import { useNavigate } from 'react-router-dom';

function LoginForm() {
  const navigate = useNavigate();

  const handleSubmit = async (e) => {
    e.preventDefault();
    await api.login();
    navigate('/dashboard', { replace: true }); // ログイン後に飛ばす
  };
}
```

ボタン押下などのイベントから飛ばしたいときは `useNavigate` を使います。

### 例4：保護ルート（認証）

```jsx
// ログイン状態を取得するカスタムフック（仮）
function useAuth() {
  // 実装は localStorage や Context など環境次第
  const token = localStorage.getItem('token');
  return { isAuthenticated: !!token };
}

// 保護ルート用のラッパー
function RequireAuth({ children }) {
  const { isAuthenticated } = useAuth();
  const location = useLocation();

  if (!isAuthenticated) {
    // ログインしてないなら /login へリダイレクト
    // 戻ってきたいページの情報を渡しておく
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  return children;
}

// 使用例
function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/login" element={<Login />} />

      <Route
        path="/dashboard"
        element={
          <RequireAuth>
            <Dashboard />
          </RequireAuth>
        }
      />
    </Routes>
  );
}
```

`<RequireAuth>` でラップしたページは、ログイン中だけ表示されます。未ログインなら自動的にログインページへ。

### 例5：ログイン後に元のページへ戻す

```jsx
import { useLocation, useNavigate } from 'react-router-dom';

function Login() {
  const location = useLocation();
  const navigate = useNavigate();
  // 保護ルートが `state: { from: location }` を渡してくれていれば
  const from = location.state?.from?.pathname || '/';

  const handleLogin = async () => {
    await api.login();
    navigate(from, { replace: true }); // 元いたページへ戻す
  };

  return <button onClick={handleLogin}>ログイン</button>;
}
```

「ダッシュボードを開こうとしてログイン画面に飛ばされた」ユーザーが、ログイン後に **ちゃんとダッシュボードに戻れる** UXを実現します。

### 例6：認可（権限）チェック

```jsx
function RequireRole({ role, children }) {
  const { user } = useAuth();
  if (!user) return <Navigate to="/login" replace />;
  if (user.role !== role) return <Navigate to="/403" replace />; // 権限なし
  return children;
}

<Route
  path="/admin"
  element={
    <RequireRole role="admin">
      <AdminPanel />
    </RequireRole>
  }
/>
```

役割によるアクセス制限はこのように書けます。

### 例7：レイアウトで一括保護

```jsx
function ProtectedLayout() {
  const { isAuthenticated } = useAuth();
  if (!isAuthenticated) return <Navigate to="/login" replace />;
  return <Outlet />;
}

<Routes>
  <Route element={<ProtectedLayout />}>
    {/* この中の子ルートはすべてログイン必須 */}
    <Route path="/dashboard" element={<Dashboard />} />
    <Route path="/profile" element={<Profile />} />
    <Route path="/settings" element={<Settings />} />
  </Route>
</Routes>
```

レイアウト＋保護を兼ねるパターン。各ルートにラッパーを書かなくて済みます。

## ❌ よくある間違い

### 1. クライアント側のチェックだけで安心する

ブラウザ側のチェックは **見栄えのため** であり、**セキュリティの本丸はサーバー側** です。サーバーAPIは必ず認証・認可をチェックするようにしましょう。クライアント側のJSは簡単に書き換えられます。

### 2. `<Navigate>` を `if` より前に書く

```jsx
function RequireAuth({ children }) {
  return <Navigate to="/login" replace />; // 常にログインに飛ぶ
  if (!isAuth) return <Navigate to="/login" />; // 到達しない
}
```

条件分岐を先に書きましょう。

### 3. ログイン状態をstateに直接書く

```jsx
// ❌ 各コンポーネントで `useState(false)` してチェック
const [isAuth, setIsAuth] = useState(false);
```

認証状態は **全アプリで共有する** べき情報なので、`Context` や Zustand などのグローバル状態管理に置きましょう。

### 4. 404ルートを上に書く

```jsx
// ❌ 一番上に置くと、すべてのアクセスが404になる
<Routes>
  <Route path="*" element={<NotFound />} />
  <Route path="/" element={<Home />} /> {/* 到達しない */}
</Routes>
```

`*` は一番下に。

### 5. 戻り先を保存しない

ログイン後、いつもホームに戻すのは不便です。`location.state.from` で戻り先を保存しましょう。

## ✅ ベストプラクティス

1. **404ルートは必ず用意する**：「該当なし」を放置しないこと。
2. **認証状態はContextやストアで一元管理**：複数の `RequireAuth` で同じ判定が必要だから。
3. **戻り先を保存して復帰させる**：UX向上の定番。
4. **保護ルートはラッパー or レイアウトで実現**：再利用しやすい形に。
5. **サーバー側のチェックも忘れない**：クライアント保護は補助。

## 🔬 実践演習

### お題：ログイン必須のダッシュボード

- `/login` ページでログインボタンを押すと localStorage にトークンを保存
- `/dashboard` はログイン中だけアクセス可能
- 未ログインで `/dashboard` を開いたら `/login` に飛ばす
- ログイン後、`/dashboard` に自動で戻る

を実装してみましょう。

### 発展課題

- 役割（`admin` / `user`）を追加して、`/admin` は管理者のみアクセス可能にする
- 404ページに「もしかして：〇〇？」のような提案リンクを表示してみる

## 📝 まとめ

- `path="*"` で404ページ、`<Navigate>` でリダイレクト
- 保護ルートは「条件チェック→ダメなら `<Navigate>`」のラッパーで実現
- 認証（誰か）と認可（権限あるか）は別物
- 戻り先を `location.state` に保存すると親切
- セキュリティの本丸はサーバー側
