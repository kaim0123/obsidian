# 6-3 レイアウトとページ分割

## 🎯 この章で学ぶこと

- 「レイアウトコンポーネント」の考え方を理解できます
- ヘッダー・サイドバー・フッターを共通化する方法を覚えます
- ページごとに違うレイアウトを当てる技を学びます
- ファイル構成（`pages/` と `layouts/`）の指針が分かります
- ページ分割（コード分割）の入り口を知ります

## 📖 概念の説明

### レイアウトコンポーネントとは

ほとんどのWebアプリには、**全ページに共通する見た目の枠組み** があります。たとえば、

- 上部のナビゲーションバー（ロゴ、ログインボタン）
- 左のサイドメニュー
- 下部のフッター（コピーライト、リンク集）

これらを **毎ページのコンポーネントに書く** のは大変ですし、修正のときに全部直すことになります。そこで **レイアウトコンポーネント** という考え方が出てきます。

例えるなら、**書類のテンプレート** のようなものです。会社のロゴと住所が印刷された便箋のテンプレートを用意しておけば、本文だけ書けばすぐ手紙が完成します。

### 6-2で学んだ `<Outlet />` の活用

レイアウトコンポーネントは、ネストルートと `<Outlet />` を使って実現します。

```
<MainLayout>
  Header（共通）
  <Outlet /> ← ここにページの中身
  Footer（共通）
</MainLayout>
```

各ページは `<Outlet />` の位置にはめ込まれます。ヘッダーとフッターは書かなくていい、というわけです。

### レイアウトを使い分ける

一つのアプリでもレイアウトは複数あるのが普通です。

- **MainLayout**：通常ページ用（ヘッダー＋フッター）
- **AuthLayout**：ログイン・登録用（シンプルな枠）
- **DashboardLayout**：管理画面用（左サイドバー）

それぞれに対応するルートグループを作ります。

### ページ分割（ファイル構成）の指針

ファイルが増えてくると、構成に迷いますよね。一般的な指針はこんな感じです。

```
src/
├─ layouts/
│  ├─ MainLayout.jsx
│  ├─ AuthLayout.jsx
│  └─ DashboardLayout.jsx
├─ pages/
│  ├─ Home.jsx
│  ├─ About.jsx
│  ├─ Login.jsx
│  └─ dashboard/
│     ├─ Index.jsx
│     ├─ Users.jsx
│     └─ Settings.jsx
├─ components/   ← ボタンなど、ページをまたいで使う部品
└─ App.jsx       ← ルート定義
```

「**ページ＝1つのURL**」と考えれば `pages/` の中身がそのままURL構造に対応します。

### 用語の整理

- **レイアウトコンポーネント**：複数ページで共通する枠組み
- **ページコンポーネント**：1つのURLに対応する画面
- **コード分割（code splitting）**：必要な時だけJSを読み込む仕組み
- **遅延ロード（lazy loading）**：あとで読み込むこと

## 💻 コード例

### 例1：基本的なレイアウト分離

```jsx
// layouts/MainLayout.jsx
import { Outlet, Link } from 'react-router-dom';

export default function MainLayout() {
  return (
    <div className="main-layout">
      <header>
        <h1>マイアプリ</h1>
        <nav>
          <Link to="/">ホーム</Link>
          <Link to="/about">紹介</Link>
        </nav>
      </header>

      <main>
        <Outlet /> {/* ページ本体がここに入る */}
      </main>

      <footer>
        <small>© 2026 My Company</small>
      </footer>
    </div>
  );
}
```

```jsx
// App.jsx
import { Routes, Route } from 'react-router-dom';
import MainLayout from './layouts/MainLayout';
import Home from './pages/Home';
import About from './pages/About';

export default function App() {
  return (
    <Routes>
      <Route element={<MainLayout />}>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Route>
    </Routes>
  );
}
```

`<Route element={<MainLayout />}>` のように **path無し** にすると、「子ルート全体にこのレイアウトを適用する」ことになります。

### 例2：複数のレイアウトを使い分ける

```jsx
function App() {
  return (
    <Routes>
      {/* 通常ページはMainLayout */}
      <Route element={<MainLayout />}>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Route>

      {/* 認証系はAuthLayout（ヘッダーフッターなし） */}
      <Route element={<AuthLayout />}>
        <Route path="/login" element={<Login />} />
        <Route path="/register" element={<Register />} />
      </Route>

      {/* 管理画面はDashboardLayout（サイドバー付き） */}
      <Route path="/dashboard" element={<DashboardLayout />}>
        <Route index element={<DashboardHome />} />
        <Route path="users" element={<Users />} />
        <Route path="settings" element={<Settings />} />
      </Route>
    </Routes>
  );
}
```

ルートをグループに分けるだけで、それぞれ違うレイアウトが当たります。

### 例3：DashboardLayoutの実装

```jsx
import { Outlet, NavLink } from 'react-router-dom';

export default function DashboardLayout() {
  return (
    <div style={{ display: 'flex' }}>
      <aside style={{ width: 200, borderRight: '1px solid #ccc' }}>
        <h2>管理メニュー</h2>
        <nav>
          <NavLink to="/dashboard">トップ</NavLink>
          <NavLink to="/dashboard/users">ユーザー</NavLink>
          <NavLink to="/dashboard/settings">設定</NavLink>
        </nav>
      </aside>
      <main style={{ flex: 1, padding: 20 }}>
        <Outlet />
      </main>
    </div>
  );
}
```

サイドバーが共通で、右側だけが各ページに切り替わります。

### 例4：ページコンポーネントは中身に集中する

```jsx
// pages/Users.jsx
export default function Users() {
  return (
    <div>
      <h1>ユーザー一覧</h1>
      <table>
        {/* ... */}
      </table>
    </div>
  );
}
```

ページコンポーネントは **その画面の固有の中身だけ** に集中できます。ヘッダーやサイドバーのことは考えなくていいので、見通しが良くなります。

### 例5：コード分割（lazy loading）

ページが増えてくると、最初の読み込みが重くなります。`React.lazy` を使うと、**そのページにアクセスしたときだけ** JavaScriptを読み込めます。

```jsx
import { lazy, Suspense } from 'react';
import { Routes, Route } from 'react-router-dom';

// ページを遅延ロードする
const Home = lazy(() => import('./pages/Home'));
const About = lazy(() => import('./pages/About'));

function App() {
  return (
    <Suspense fallback={<div>読み込み中...</div>}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </Suspense>
  );
}
```

`Suspense` の `fallback` には、読み込み中に表示する内容を書きます。

### 例6：レイアウト内で共通データを取得する

```jsx
function DashboardLayout() {
  const [user, setUser] = useState(null);

  useEffect(() => {
    fetch('/api/me').then(r => r.json()).then(setUser);
  }, []);

  if (!user) return <p>読み込み中...</p>;

  return (
    <div>
      <header>こんにちは、{user.name}さん</header>
      <Outlet context={{ user }} /> {/* 子に渡せる */}
    </div>
  );
}

// 子ページ側で
import { useOutletContext } from 'react-router-dom';

function Users() {
  const { user } = useOutletContext();
  return <p>{user.role} 権限で表示中</p>;
}
```

レイアウトで取得したデータを `useOutletContext` で子に渡せます。

## ❌ よくある間違い

### 1. 各ページで毎回ヘッダーを書く

```jsx
// ❌ 全ページに同じヘッダーを書く
function Home() {
  return (
    <>
      <Header /> {/* 毎ページ書くハメに */}
      <h1>ホーム</h1>
      <Footer />
    </>
  );
}
```

レイアウトコンポーネントに切り出しましょう。

### 2. レイアウトに `<Outlet />` を書き忘れる

レイアウトを定義したのに `<Outlet />` がないと、子ページが表示されません。

### 3. レイアウトを階層で深く重ねすぎる

```jsx
// ❌ 4重5重のネストになると追いにくい
<Route element={<A />}>
  <Route element={<B />}>
    <Route element={<C />}>
      <Route element={<D />}>...
```

2〜3階層で十分なことが多いです。

### 4. 共通データの取得をページごとに重複させる

`/api/me` をページごとに何度も呼ぶより、レイアウトで1回呼んで `useOutletContext` で渡す方がスマートです。

## ✅ ベストプラクティス

1. **レイアウトとページを分けるフォルダ構成**：見通しが良くなります。
2. **`<Outlet />` で中身を流し込む発想**：レイアウト＝額縁、ページ＝絵、と覚えます。
3. **複数レイアウトを切り替えて使う**：認証系は別レイアウトにするのが定番。
4. **ページが増えたらコード分割を検討**：`React.lazy` + `Suspense`。
5. **共通データはレイアウトで取得して子に渡す**：重複fetchを防げます。

## 🔬 実践演習

### お題：3つのレイアウトを使い分ける

- 公開ページ（`/`、`/about`）→ MainLayout
- 認証ページ（`/login`、`/register`）→ AuthLayout（シンプル）
- 管理画面（`/admin/*`）→ AdminLayout（サイドバー付き）

の3つを作ってみましょう。

### 発展課題

- `React.lazy` と `Suspense` を導入して、ページごとにJSが分割されることをDevToolsのNetworkタブで確認しましょう
- AdminLayoutで `/api/me` を取得し、子ページから `useOutletContext` で受け取ってみましょう

## 📝 まとめ

- レイアウトコンポーネントは「**全ページ共通の枠組み**」を1箇所に集めるテクニック
- `<Outlet />` で子ページの位置を決めます
- 用途別に複数のレイアウトを使い分けるのが普通です
- `React.lazy` + `Suspense` でコード分割もできます
- 共通データはレイアウトで取得 → `useOutletContext` で子に渡す
