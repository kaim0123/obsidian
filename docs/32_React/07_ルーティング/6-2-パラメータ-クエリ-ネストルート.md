# 6-2 パラメータ/クエリ/ネストルート

## 🎯 この章で学ぶこと

- URLパラメータ（`/users/:id` の `:id` 部分）の取り出し方を学びます
- クエリ文字列（`?q=react&page=2`）の読み書き方法を覚えます
- ネストルート（入れ子になったルート）の書き方が分かります
- `useParams`、`useSearchParams`、`Outlet` の3つを使い分けられます
- 階層のあるURL構造を持つアプリを設計できるようになります

## 📖 概念の説明

### URLの3つの「動的な部分」

URLには「動的に変わる部分」が大きく3種類あります。

1. **パスパラメータ**：`/users/123` の `123`、`/posts/abc` の `abc` のような部分
2. **クエリ文字列**：`/search?q=react&page=2` の `?q=react&page=2` の部分
3. **ハッシュ**：`/page#section1` の `#section1` の部分（あまり使いません）

それぞれ取得方法が違います。

| 種類 | 例 | 取り出し方 |
|---|---|---|
| パスパラメータ | `/users/:id` | `useParams()` |
| クエリ文字列 | `?q=react` | `useSearchParams()` |
| ハッシュ | `#top` | `useLocation().hash` |

### パスパラメータとクエリの使い分け

「**そのリソースを特定するもの**」はパスパラメータ、「**表示の仕方を切り替えるもの**」はクエリ、と覚えると分かりやすいです。

- ユーザーのプロフィール → `/users/123` （IDは「誰のページか」を決めるのでパス）
- 商品検索 → `/products?q=シャツ&color=blue&page=2` （絞り込み条件は表示の調整なのでクエリ）

### ネストルートって何？

**ネストルート（nested routes）** とは、ルートの中にルートを入れ子で書くことです。例えば、

```
/dashboard           → ダッシュボードのトップ
/dashboard/users     → ダッシュボード配下のユーザー一覧
/dashboard/settings  → ダッシュボード配下の設定
```

このように、共通の前置きURL（`/dashboard`）と共通レイアウト（左メニューなど）を **共有** するために使います。

ネストルートの中で、子ページがどこに表示されるかを決めるのが **`<Outlet />`** です。

例えるなら、**家の間取り** のようなものです。`/dashboard` という建物の中に、リビング（`/users`）、キッチン（`/settings`）といった部屋がある。`<Outlet />` は「ここに部屋を表示します」というプレースホルダです。

### 用語の整理

- **パスパラメータ**：URLの動的な部分（`:id`）
- **クエリ文字列**：URLの `?` 以降のキー＝値の組
- **ネストルート**：入れ子になったルート定義
- **Outlet**：ネストルートの子コンポーネントが表示される場所

## 💻 コード例

### 例1：パスパラメータを使う

```jsx
import { Routes, Route, useParams, Link } from 'react-router-dom';

function UserDetail() {
  const { id } = useParams(); // URLの :id 部分を取得
  return <h1>ユーザーID: {id}</h1>;
}

function App() {
  return (
    <Routes>
      {/* :id がパラメータ。何でもマッチする */}
      <Route path="/users/:id" element={<UserDetail />} />
    </Routes>
  );
}
```

`/users/123` にアクセスすると `id` には `"123"` が入ります（**文字列なので注意**、数値が必要なら `Number(id)` で変換）。

### 例2：複数のパラメータ

```jsx
<Route path="/users/:userId/posts/:postId" element={<Post />} />

function Post() {
  const { userId, postId } = useParams();
  return <p>ユーザー{userId}の記事{postId}</p>;
}
```

複数のパラメータも `useParams` で同時に取得できます。

### 例3：クエリ文字列の読み取り

```jsx
import { useSearchParams } from 'react-router-dom';

function Search() {
  const [searchParams, setSearchParams] = useSearchParams();
  const q = searchParams.get('q') || ''; // ?q=react の値
  const page = Number(searchParams.get('page') || 1);

  return (
    <div>
      <p>検索ワード：{q}</p>
      <p>ページ：{page}</p>
    </div>
  );
}
```

`useSearchParams` は `useState` に似た形で、値の取得と更新ができます。ブラウザの `URLSearchParams` API のラッパーです。

### 例4：クエリ文字列の更新

```jsx
function SearchBox() {
  const [searchParams, setSearchParams] = useSearchParams();
  const q = searchParams.get('q') || '';

  return (
    <input
      type="text"
      value={q}
      onChange={(e) => {
        // URLが ?q=入力内容 に書き換わる
        setSearchParams({ q: e.target.value });
      }}
    />
  );
}
```

`setSearchParams` を呼ぶとURLが書き換わります。ブラウザバックも履歴として残るので、戻るボタンで前の検索条件に戻れます。

### 例5：ネストルートと `<Outlet />`

```jsx
import { Routes, Route, Outlet, Link } from 'react-router-dom';

function DashboardLayout() {
  return (
    <div>
      <h1>ダッシュボード</h1>
      <nav>
        <Link to="/dashboard">トップ</Link>{' | '}
        <Link to="/dashboard/users">ユーザー</Link>{' | '}
        <Link to="/dashboard/settings">設定</Link>
      </nav>
      <hr />

      {/* 子ルートのコンポーネントがここに表示される */}
      <Outlet />
    </div>
  );
}

function DashboardHome() { return <p>ダッシュボードのトップです</p>; }
function Users() { return <p>ユーザー一覧</p>; }
function Settings() { return <p>設定画面</p>; }

function App() {
  return (
    <Routes>
      <Route path="/dashboard" element={<DashboardLayout />}>
        {/* index は親URL（/dashboard）に完全一致したとき */}
        <Route index element={<DashboardHome />} />
        <Route path="users" element={<Users />} />
        <Route path="settings" element={<Settings />} />
      </Route>
    </Routes>
  );
}
```

`/dashboard/users` にアクセスすると、`DashboardLayout` の中の `<Outlet />` の位置に `<Users />` が描画されます。**ヘッダー部分は共通で再利用される** ということです。

`<Route index ... />` の `index` は「親パスに完全一致した時のデフォルト」を表します。

### 例6：パスパラメータ＋ネストルートの組み合わせ

```jsx
<Routes>
  <Route path="/users/:id" element={<UserLayout />}>
    <Route index element={<UserOverview />} />        {/* /users/123 */}
    <Route path="posts" element={<UserPosts />} />     {/* /users/123/posts */}
    <Route path="friends" element={<UserFriends />} /> {/* /users/123/friends */}
  </Route>
</Routes>
```

子コンポーネントでも `useParams()` を呼べば `id` が取れます。

### 例7：オプショナルなパラメータ

v6.4以降、`?` を付けるとオプショナルになります。

```jsx
<Route path="/products/:category?" element={<Products />} />
// /products でも /products/shoes でもマッチ
```

## ❌ よくある間違い

### 1. `useParams` の戻り値を数値だと思う

```jsx
const { id } = useParams();
if (id === 123) { ... } // ❌ idは "123" という文字列
```

数値比較するなら `Number(id) === 123` または `id === '123'`。

### 2. クエリの値を直接stateにコピーする

```jsx
// ❌ URL ⇔ state の二重管理になる
const [searchParams] = useSearchParams();
const [q, setQ] = useState(searchParams.get('q') || '');
```

クエリと連動するなら **stateは持たず**、`searchParams` を直接使うのがシンプルです。

### 3. ネストルートでパスの先頭にスラッシュを付ける

```jsx
// ❌ 子ルートに / を付けると絶対パスになる
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route path="/users" element={<Users />} /> {/* ✗ /users になってしまう */}
</Route>

// ✅ 相対パスで書く
<Route path="users" element={<Users />} />
```

子ルートのパスは **スラッシュなしの相対パス** で書きます。

### 4. `<Outlet />` を書き忘れる

ネストルートを使ったのに、レイアウト側に `<Outlet />` がないと、子ページが表示されません。

### 5. 末尾スラッシュの扱い

`/users` と `/users/` は別物です。`<Link to="users">`（相対）と `<Link to="/users">`（絶対）も挙動が変わります。意図して使い分けましょう。

## ✅ ベストプラクティス

1. **「特定のリソース」はパス、「表示条件」はクエリ**：使い分けの基準を持ちましょう。
2. **クエリは `useSearchParams` でURLを正とする**：stateとの二重管理を避けます。
3. **ネストルートで共通レイアウトを共有**：DRYに保てます。
4. **パスパラメータは文字列だと意識する**：数値が必要なら型変換を忘れずに。
5. **子ルートは相対パスで書く**：`/` を先頭に付けないこと。

## 🔬 実践演習

### お題：ユーザー一覧と詳細

`/users` でユーザー一覧、`/users/:id` で詳細を表示するアプリを作ってみましょう。

ヒント：

- 一覧ページで `<Link to={`/users/${user.id}`}>` を使う
- 詳細ページで `useParams()` から `id` を取得
- `id` を使って表示内容を切り替える

### 発展課題

- `/users/:id` のネストとして `/users/:id/posts`、`/users/:id/friends` を追加し、共通のサイドバーで切り替えられるようにしましょう
- 検索ページ `/search?q=...&page=...` を実装して、URLが検索条件と連動するようにしましょう

## 📝 まとめ

- パスパラメータは `useParams()`、クエリは `useSearchParams()` で取得します
- ネストルートは `<Outlet />` を使って、レイアウトと中身を分離できます
- パラメータは文字列で渡ってくるので、必要なら型変換します
- 「リソースの特定はパス、表示条件はクエリ」を意識しましょう
