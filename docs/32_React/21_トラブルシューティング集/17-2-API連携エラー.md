# 17-2 API連携エラー（失敗パターンと切り分け）

## 🎯 この章で学ぶこと

- API 連携で起きる典型的なエラーをパターン別に把握する
- ブラウザ DevTools の Network タブを使った原因切り分け方法を学ぶ
- CORS エラー / 401 / 404 / 500 / タイムアウトの読み方
- 「症状 → 仮説 → 検証 → 修正」というデバッグの作法
- ユーザーへのエラーメッセージ設計

## 📖 概念の説明

### API エラーの分類

| 種別 | HTTP ステータス | 主な原因 |
|------|----------------|---------|
| ネットワーク失敗 | なし | オフライン、CORS、DNS |
| クライアントエラー | 4xx | リクエスト側の問題 |
| サーバエラー | 5xx | サーバ側の問題 |
| タイムアウト | なし | レスポンスが返ってこない |

ステータスコードは「警察 vs 容疑者」の関係。4xx = あなたが悪い、5xx = サーバが悪い、と覚えると分かりやすいです。

### CORS とは

「あなたのオリジン（`https://app.example.com`）から、別オリジン（`https://api.example.com`）への XHR / fetch」を、ブラウザが事前許可なしには許可しない仕組み。サーバが `Access-Control-Allow-Origin` ヘッダで明示する必要があります。

これはブラウザ側の防御機構なので、サーバが対応していない限りフロントだけでは解決できません。

### デバッグの作法

1. **症状**: 何が起きたか（例: ボタンを押したらエラーメッセージ）
2. **仮説**: 何が原因か（例: 401 で認証切れ？）
3. **検証**: DevTools / ログ / curl で確認
4. **修正**: 仮説が当たったら直す。外れたら 2 へ戻る

闇雲に直すのではなく、この 4 ステップを意識します。

## 💻 コード例

### 症状: 「Failed to fetch」しか出ない

**現象**

```
TypeError: Failed to fetch
```

**主な原因**

1. ネットワーク断（オフライン）
2. CORS で弾かれた
3. URL が間違っている
4. サーバが落ちている

**切り分け**

```ts
try {
  const res = await fetch("/api/tasks");
} catch (err) {
  console.error(err); // ここで TypeError: Failed to fetch
}
```

DevTools の Network タブで該当リクエストを見ます。

- ステータスが「(failed)」: ネットワーク or CORS。Console タブで `Access-Control-Allow-Origin` 関連の警告を探す
- 何も飛んでいない: URL が壊れている、または事前にコードがクラッシュしている

**修正例（CORS の場合・サーバ側）**

```ts
// Express
app.use(cors({ origin: "https://app.example.com", credentials: true }));
```

### 症状: 401 Unauthorized

**現象**

```
GET /api/me 401
{"message":"Token expired"}
```

**主な原因**

- アクセストークンが期限切れ
- ヘッダの付け忘れ
- ログアウトした状態のままアクセス

**修正パターン: 自動リフレッシュ**

```ts
async function api<T>(path: string, init: RequestInit = {}): Promise<T> {
  let res = await fetch(path, withAuth(init));
  if (res.status === 401) {
    const ok = await tryRefreshToken();
    if (ok) res = await fetch(path, withAuth(init));
    else {
      logout();
      throw new ApiError(401, "ログインが必要です");
    }
  }
  if (!res.ok) throw new ApiError(res.status, await readMessage(res));
  return res.json();
}
```

### 症状: 404 Not Found

**現象**: `GET /api/task/abc 404`

**よくある原因**

- パスのタイポ（`tasks` と書きたかった → `task`）
- ID 部分の URL エンコード漏れ
- API バージョンが違う（`/api/v1/tasks`）

```ts
// ❌
fetch(`/api/tasks/${userInput}`); // userInput に / が入ると壊れる
// ✅
fetch(`/api/tasks/${encodeURIComponent(userInput)}`);
```

### 症状: 500 Internal Server Error

**現象**: ボタンを押したら 500 が返ってくる

**ポイント**: 5xx はクライアントの責任ではないが、報告は丁寧に行う。

```ts
if (res.status >= 500) {
  Sentry.captureMessage(`API 5xx: ${path}`, { level: "error" });
  throw new ApiError(res.status, "サーバが混み合っています。時間をおいて再度お試しください。");
}
```

ユーザーには「サーバ側で問題が発生しています」と表示し、再試行ボタンを置く。

### 症状: タイムアウト / 応答が遅い

```ts
async function apiWithTimeout<T>(path: string, ms = 10_000): Promise<T> {
  const ctrl = new AbortController();
  const t = setTimeout(() => ctrl.abort(), ms);
  try {
    const res = await fetch(path, { signal: ctrl.signal });
    return res.json();
  } finally {
    clearTimeout(t);
  }
}
```

`AbortController` でタイムアウト制御。長時間放置で無限スピナーになるのを防ぎます。

### 症状: ステータスは 200 だが JSON が壊れている

**現象**

```
SyntaxError: Unexpected token < in JSON at position 0
```

サーバが HTML（多くの場合エラーページや認証リダイレクト）を返してきています。

**切り分け**

```ts
const res = await fetch("/api/tasks");
const text = await res.text();
console.log("[debug]", text.slice(0, 200));
const data = JSON.parse(text);
```

`<!DOCTYPE html>` が見えたらリバースプロキシで API に届いていない、認証ページが返っている、などのケース。

### 症状: 同じ通信が 2 回走る

**原因**: React の StrictMode 下では、開発時のみ `useEffect` が 2 回呼ばれる仕様。

**対応**: 副作用が「冪等」（何度やっても同じ結果）になるように設計する。React Query を使えば自動的に重複は排除されます。

```tsx
useEffect(() => {
  let cancelled = false;
  fetchTasks().then((data) => {
    if (!cancelled) setTasks(data);
  });
  return () => {
    cancelled = true;
  };
}, []);
```

これで初期化時の二重実行が起きても、後続の setState が捨てられて安全。

### 症状: リクエストヘッダにトークンが付かない

```ts
// ❌ FormData なのに Content-Type を手動指定
fetch("/upload", {
  method: "POST",
  headers: { "Content-Type": "multipart/form-data" },
  body: formData,
});
```

`FormData` を渡すときは `Content-Type` を書かないのが正解（境界文字列を fetch が自動付与）。

### ユーザー向けエラーメッセージの設計

```tsx
function getUserMessage(err: unknown): string {
  if (err instanceof ApiError) {
    if (err.status === 401) return "ログインの有効期限が切れました。再度ログインしてください。";
    if (err.status === 403) return "この操作を行う権限がありません。";
    if (err.status === 404) return "対象が見つかりませんでした。";
    if (err.status >= 500) return "サーバ側で問題が発生しました。しばらくしてから再度お試しください。";
    return err.message;
  }
  if (err instanceof Error && err.name === "AbortError")
    return "通信がタイムアウトしました。ネットワーク状態をご確認ください。";
  return "予期せぬエラーが発生しました。";
}
```

技術用語（"500 Internal Server Error"）をそのまま見せず、ユーザー視点の言葉に翻訳します。

## ❌ よくある間違い

### 1. `catch` で `console.log` だけ

```ts
.catch((err) => console.log(err));
```

ユーザーには何も表示されず、ボタンを押したのに何も起きないように見えます。Toast や Alert で必ず通知。

### 2. レスポンス OK チェックを忘れる

```ts
const res = await fetch("/api/x");
return res.json(); // 4xx/5xx でも JSON.parse まで進んでしまう
```

`if (!res.ok) throw ...` を必ず挟む。

### 3. CORS エラーをフロント側で直そうとする

ヘッダはサーバ側が出すもの。フロントの fetch オプションで `mode: 'no-cors'` を付けても、レスポンスは読めなくなり何も解決しない。

### 4. リトライを無条件に行う

POST のような副作用のあるリクエストを失敗時に自動リトライすると、二重投稿が起きます。GET のみリトライ、POST はユーザー操作で再試行が原則。

### 5. エラー時に古いデータを表示し続ける

ユーザーは更新できたつもりで離脱し、後で「保存されていない」事故。エラー時はバナーで明示。

## ✅ ベストプラクティス

1. **`fetch` をラップした共通関数を 1 つ用意**: ヘッダ付与・エラー変換・ステータス判定を一括化。
2. **エラーは型で区別**: `ApiError` クラスや `code` プロパティで分岐しやすく。
3. **DevTools の Network タブを習慣化**: ペイロード・ステータス・タイミングが一目で分かる。
4. **冪等な副作用設計**: StrictMode の 2 回実行や、自動リトライにも耐える。
5. **ユーザー視点の言葉で**: 「401 Unauthorized」ではなく「ログインの期限が切れました」。

## 📝 まとめ

- API エラーは「ネットワーク / 4xx / 5xx / タイムアウト / JSON 不整合」に大別
- CORS はサーバ側問題、フロントでは直せない
- 401 はリフレッシュトークンで自動回復、500 はリトライ + 監視
- StrictMode の 2 回実行に備えて副作用は冪等に
- ユーザーには技術用語ではなく自然な日本語で

# API連携エラー基礎 - 初心者向け解説

## API連携エラーとは？

**API連携エラー**とは、フロントエンドアプリケーションがバックエンドAPIと通信する際に発生するエラーです。ネットワークの問題、サーバーエラー、認証エラー、データ形式の不一致など、様々な原因で発生します。

### 身近な例で理解する

日常生活で例えると：
- **正しいAPI連携**：電話をかけて、相手が応答し、必要な情報を聞ける
- **API連携エラー**：電話が繋がらない、相手が不在、言葉が通じないなど

---

## よくあるAPI連携エラーの種類

### 1. ネットワークエラー（Network Error）

インターネット接続がない、またはサーバーに到達できない場合に発生します。

```javascript
// エラー例
fetch('https://api.example.com/data')
  .then(response => response.json())
  .catch(error => {
    // TypeError: Failed to fetch
    console.error(error);
  });
```

**主な原因**：
- インターネット接続がない
- サーバーがダウンしている
- CORSエラー
- DNSエラー

**予防策**：

```javascript
const fetchData = async () => {
  // オンライン状態を確認
  if (!navigator.onLine) {
    setError('インターネット接続がありません');
    return;
  }

  try {
    const response = await fetch('https://api.example.com/data');
    const data = await response.json();
    setData(data);
  } catch (error) {
    if (error.name === 'TypeError') {
      setError('サーバーに接続できません');
    } else {
      setError('予期しないエラーが発生しました');
    }
  }
};
```

---

### 2. HTTPステータスエラー

サーバーからエラーレスポンスが返される場合に発生します。

| ステータスコード | 意味 | 主な原因 |
|-----------------|------|---------|
| **400** | Bad Request | リクエストの形式が不正 |
| **401** | Unauthorized | 認証が必要 |
| **403** | Forbidden | アクセス権限がない |
| **404** | Not Found | リソースが存在しない |
| **422** | Unprocessable Entity | バリデーションエラー |
| **500** | Internal Server Error | サーバー内部エラー |
| **502** | Bad Gateway | ゲートウェイエラー |
| **503** | Service Unavailable | サービス一時停止 |

```javascript
// NG: response.okを確認していない
fetch('https://api.example.com/data')
  .then(response => response.json()) // 404でもここに来る
  .then(data => setData(data));

// OK: ステータスコードを確認
fetch('https://api.example.com/data')
  .then(response => {
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }
    return response.json();
  })
  .then(data => setData(data))
  .catch(error => setError(error.message));
```

**ステータスコード別のエラーハンドリング**：

```javascript
const handleResponse = async (response) => {
  if (response.ok) {
    return response.json();
  }

  switch (response.status) {
    case 400:
      throw new Error('リクエストの形式が正しくありません');
    case 401:
      throw new Error('ログインが必要です');
    case 403:
      throw new Error('アクセス権限がありません');
    case 404:
      throw new Error('データが見つかりません');
    case 422:
      const errors = await response.json();
      throw new Error(errors.message || '入力内容に問題があります');
    case 500:
      throw new Error('サーバーエラーが発生しました');
    default:
      throw new Error(`エラーが発生しました (${response.status})`);
  }
};
```

### 3. CORSエラー（Cross-Origin Resource Sharing）

異なるオリジン（ドメイン）間でリクエストを行う際に、サーバー側で許可されていない場合に発生します。

```
Access to fetch at 'https://api.example.com/data' from origin 'http://localhost:3000'
has been blocked by CORS policy
```

**主な原因**：
- サーバー側でCORSヘッダーが設定されていない
- 許可されていないHTTPメソッドを使用
- 許可されていないヘッダーを送信

**解決方法**：

```javascript
// バックエンド側（Express.js）
const cors = require('cors');
app.use(cors({
  origin: 'http://localhost:3000',
  methods: ['GET', 'POST', 'PUT', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization']
}));

// フロントエンド側（開発時のプロキシ設定）
// vite.config.js
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'https://api.example.com',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, '')
      }
    }
  }
});
```

### 4. JSON解析エラー

サーバーから返されたレスポンスがJSON形式でない場合に発生します。

```javascript
// エラー例
// サーバーがHTMLを返した場合
fetch('https://api.example.com/data')
  .then(response => response.json()) // SyntaxError: Unexpected token < in JSON
  .catch(error => console.error(error));
```

**予防策**：

```javascript
const fetchData = async () => {
  const response = await fetch('https://api.example.com/data');

  // Content-Typeを確認
  const contentType = response.headers.get('content-type');
  if (!contentType || !contentType.includes('application/json')) {
    throw new Error('サーバーからの応答がJSON形式ではありません');
  }

  return response.json();
};
```

### 5. タイムアウトエラー

リクエストが一定時間内に完了しない場合に発生します。

```javascript
// タイムアウト付きfetch
const fetchWithTimeout = async (url, options = {}, timeout = 5000) => {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), timeout);

  try {
    const response = await fetch(url, {
      ...options,
      signal: controller.signal
    });
    clearTimeout(timeoutId);
    return response;
  } catch (error) {
    clearTimeout(timeoutId);
    if (error.name === 'AbortError') {
      throw new Error('リクエストがタイムアウトしました');
    }
    throw error;
  }
};

// 使用例
try {
  const response = await fetchWithTimeout('https://api.example.com/data', {}, 3000);
  const data = await response.json();
} catch (error) {
  console.error(error.message); // "リクエストがタイムアウトしました"
}
```

---

### 6. レースコンディション

複数のリクエストが競合し、古いリクエストの結果が新しいリクエストの結果を上書きしてしまう問題です。

```javascript
// NG: レースコンディションの問題
useEffect(() => {
  fetch(`/api/search?q=${query}`)
    .then(response => response.json())
    .then(data => setResults(data)); // 古い結果が後から来る可能性
}, [query]);

// OK: AbortControllerで古いリクエストをキャンセル
useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/search?q=${query}`, { signal: controller.signal })
    .then(response => response.json())
    .then(data => setResults(data))
    .catch(error => {
      if (error.name !== 'AbortError') {
        setError(error.message);
      }
    });

  return () => controller.abort();
}, [query]);
```

## 堅牢なAPI呼び出しの実装例

```javascript
import { useState, useEffect, useCallback } from 'react';

// カスタムフック
const useApi = (url, options = {}) => {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  const fetchData = useCallback(async () => {
    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), 10000);

    setLoading(true);
    setError(null);

    try {
      // オンライン確認
      if (!navigator.onLine) {
        throw new Error('インターネット接続がありません');
      }

      const response = await fetch(url, {
        ...options,
        signal: controller.signal
      });

      clearTimeout(timeoutId);

      // ステータスコード確認
      if (!response.ok) {
        const errorData = await response.json().catch(() => ({}));
        throw new Error(errorData.message || `HTTP error! status: ${response.status}`);
      }

      // Content-Type確認
      const contentType = response.headers.get('content-type');
      if (!contentType || !contentType.includes('application/json')) {
        throw new Error('Invalid response format');
      }

      const result = await response.json();
      setData(result);
    } catch (err) {
      if (err.name === 'AbortError') {
        setError('リクエストがタイムアウトしました');
      } else {
        setError(err.message);
      }
    } finally {
      setLoading(false);
    }

    return () => {
      clearTimeout(timeoutId);
      controller.abort();
    };
  }, [url, options]);

  return { data, loading, error, refetch: fetchData };
};

// 使用例
function UserList() {
  const { data, loading, error, refetch } = useApi('/api/users');

  useEffect(() => {
    refetch();
  }, [refetch]);

  if (loading) return <div>読み込み中...</div>;
  if (error) return <div>エラー: {error}</div>;
  if (!data) return null;

  return (
    <ul>
      {data.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

## エラーハンドリングのベストプラクティス

### 1. ユーザーフレンドリーなエラーメッセージ

```javascript
const getErrorMessage = (error, statusCode) => {
  // 技術的なメッセージをユーザー向けに変換
  const messages = {
    'Failed to fetch': 'サーバーに接続できません。インターネット接続を確認してください。',
    'Network Error': 'ネットワークエラーが発生しました。',
    401: 'セッションが切れました。再度ログインしてください。',
    403: 'この操作を行う権限がありません。',
    404: '指定されたデータが見つかりませんでした。',
    500: 'サーバーでエラーが発生しました。時間をおいて再度お試しください。'
  };

  return messages[error] || messages[statusCode] || '予期しないエラーが発生しました。';
};
```

### 2. エラー発生時のUI表示

```javascript
function ErrorMessage({ error, onRetry }) {
  return (
    <div className="error-container">
      <p className="error-message">{error}</p>
      {onRetry && (
        <button onClick={onRetry} className="retry-button">
          再試行
        </button>
      )}
    </div>
  );
}
```

### 3. ローディング状態の表示

```javascript
function DataFetcher() {
  const [state, setState] = useState({
    data: null,
    loading: true,
    error: null
  });

  // ...

  if (state.loading) {
    return <LoadingSpinner />;
  }

  if (state.error) {
    return <ErrorMessage error={state.error} onRetry={fetchData} />;
  }

  return <DataDisplay data={state.data} />;
}
```
