# 11-5. APIレスポンス型（zod等で実行時検証）

## 🎯 この章で学ぶこと

- APIから返る値を型安全に扱う
- 「型はビルド時、検証は実行時」の違い
- zod でスキーマから型を生成する流れ

---

## 📖 概念の説明

### なぜ単なる型では危険か

```ts
type User = { id: number; name: string; email: string };

const res = await fetch('/api/user');
const user: User = await res.json(); // ⚠️ 実行時には何でも入りうる
```

TypeScript の型は **コンパイル時にしか効きません**。実行時にAPIから別の形が返ってきても気づけません。

例：

- サーバ側で `name` を `firstName` に変えた
- nullが返ってきた
- 配列のはずがオブジェクト

→ 画面で `user.name` を読んで `undefined` エラー、原因が分からない。

### 解決：実行時にも検証する

**zod** などのスキーマライブラリで、**APIレスポンスを実行時にチェック**する。

---

## 💻 zod の基本

```bash
npm install zod
```

```ts
import { z } from 'zod';

// スキーマ定義
const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  email: z.string().email(),
  age: z.number().optional(),
});

// 型を自動生成
type User = z.infer<typeof UserSchema>;
// → { id: number; name: string; email: string; age?: number }
```

---

## 💻 fetch + zod 検証

```ts
async function getUser(id: number): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error('取得失敗');

  const json = await res.json();
  return UserSchema.parse(json); // 失敗すると ZodError を投げる
}
```

`parse` は

- 成功 → 型付きの値
- 失敗 → ZodError

これで「APIが想定外の形を返したらすぐ分かる」状態に。

---

## 💻 安全に試す `safeParse`

```ts
const result = UserSchema.safeParse(json);
if (!result.success) {
  console.error(result.error);
  return null;
}
const user = result.data;
```

例外を投げず、boolean で判断。

## 💻 配列の検証

```ts
const UsersSchema = z.array(UserSchema);
type Users = z.infer<typeof UsersSchema>; // User[]

const users = UsersSchema.parse(json);
```

## 💻 React Hook Form + zod

フォームバリデーションも同じスキーマで：

```tsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';

const FormSchema = z.object({
  name: z.string().min(1, '必須'),
  email: z.string().email('メール形式が違います'),
});

type FormInput = z.infer<typeof FormSchema>;

function MyForm() {
  const { register, handleSubmit, formState: { errors } } = useForm<FormInput>({
    resolver: zodResolver(FormSchema),
  });

  return (
    <form onSubmit={handleSubmit((data) => console.log(data))}>
      <input {...register('name')} />
      {errors.name && <p>{errors.name.message}</p>}
    </form>
  );
}
```

→ 詳しくは [[8-6-フォームの状態設計]]、[[14-2-入力バリデーション]]。

## 💻 TanStack Query との組み合わせ

```ts
const { data: user } = useQuery({
  queryKey: ['users', id],
  queryFn: async () => {
    const res = await fetch(`/api/users/${id}`);
    return UserSchema.parse(await res.json());
  },
});
// data は User 型
```

## 💡 OpenAPI から自動生成

サーバが OpenAPI/Swagger を提供しているなら：

```bash
# 例：openapi-typescript-codegen
npx openapi-typescript-codegen -i schema.yaml -o src/api
```

スキーマから**TypeScript型 + クライアント関数**を自動生成。

→ サーバとクライアントの型が同期できる。

---

## ❌ よくある間違い

### 型だけで実行時検証なし

```ts
const data = await res.json() as User;
```

→ APIが想定外なら気づけない。`zod` で parse。

### 全レスポンスを毎回parse（重い）

→ 大きなレスポンスでは判断。普通のサイズなら気にせず parse。

### スキーマを共通化しない

```ts
// 取得用と送信用を別々に書く
const GetUserSchema = ...;
const PostUserSchema = ...; // 微妙に違う
```

→ 共通部分は `BaseSchema.merge(extra)` で重複なく。

---

## ✅ ベストプラクティス

1. **APIレスポンスは zod で parse**
2. **`z.infer` で型を生成** → 1つの真実
3. **フォームと同じスキーマを使う**
4. **OpenAPIがあれば自動生成**
5. **エラー時のフォールバック**を用意
