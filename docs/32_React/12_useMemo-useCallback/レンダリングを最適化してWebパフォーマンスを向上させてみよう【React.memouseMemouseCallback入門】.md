## 詳しい要約

**テーマ：React.memo / useMemo / useCallback で不要な再レンダリングを防ぐ**

親コンポーネントの state が変わると子も再レンダリングされ、重い計算や関数の再生成が無駄に走る。React Developer Tools で原因を可視化しつつ、コンポーネント・値・関数をそれぞれ **メモ化** して防ぐ方法をハンズオンで解説。ただし何でもメモ化せず、ボトルネックにだけ使うのが結論。

---

### レンダリングが起きるタイミング

- ページのリロード時は全コンポーネントがレンダリングされる。
- 親で useState を使った input に入力すると、state 更新のたびに親が再レンダリングされ、**内容が変わらない子まで再レンダリング** される。これが不要なレンダリング。
- メモ化は「前と同じなら処理をスキップする」キャッシュのような考え方。

### React Developer Tools での可視化

- Chrome 拡張「React Developer Tools」を入れ、Components タブの設定で **Highlight updates when components render** を有効にすると、レンダリング箇所が枠で表示される。
- **Profiler** で記録すると、どのコンポーネントが何ミリ秒かかったか、なぜレンダリングされたか（Hook が変化、親がレンダリング等）がわかる。
- Next.js（App Router）で useState を使うには `"use client"` が必要。
- 子をフラグメント（`<>`）で囲むと、メモ化しても全部ハイライトされる表示上のバグがあるので div で囲むとよい、と補足。

### React.memo：コンポーネントのメモ化

- 子コンポーネントを `React.memo(...)` で囲むと、props が変わらない限り再レンダリングされない。
- Profiler で、memo なしの子だけがレンダリングされ、memo ありの子はスキップされることを確認。

### useMemo：値（計算結果）のメモ化

- while ループで数値を何度も倍にする重い計算 `double(count)` を親に置くと、input 入力のたびに走り、1 回約 15ms かかった。
- `useMemo(() => double(count), [count])` にすると、依存配列の `count` が変わった時（ボタン押下時）だけ計算し、入力時は **約 0.1ms** に短縮。

### useCallback：関数のメモ化

- 親で定義した `handleClick` はレンダリングのたびに新しく生成されるため、props で受け取る子は React.memo していても再レンダリングされる。
- `useCallback(() => {...}, [])` で包むと関数は初回だけ生成され、子の不要なレンダリングが消える。依存配列に頻繁に変わる値を入れると毎回生成されてしまう。

### 使いどころの注意

- 軽い処理をメモ化すると、メモリを使う分かえってパフォーマンスが落ちることがある。
- Profiler でボトルネックを特定し、本当に遅い箇所だけメモ化するのが推奨。

### まとめ

- コンポーネントは **React.memo**、計算結果は **useMemo**、関数は **useCallback** でメモ化する。
- React Developer Tools の Profiler で「どこが・なぜ・何ms」レンダリングされたかを確認できる。
- メモ化は万能ではなく、計測したボトルネックにだけ適用する。
