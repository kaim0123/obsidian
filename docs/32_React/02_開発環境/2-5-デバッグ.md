# 2-5. デバッグ（React DevTools / console / breakpoint）

## 🎯 この章で学ぶこと

- React DevTools の入れ方と使い方
- `console.log` を効果的に使う書き方
- ブラウザのbreakpointで処理を一時停止して中身を見る方法

---

## 📖 概念の説明

### デバッグとは

「**バグを見つけて直す**」作業。プログラミングの仕事の半分以上はデバッグと言われます。**「動かないときに、何が起きているか調べる力」**が一番大事。

### Reactでよく使う3つの道具

1. **React DevTools**（ブラウザ拡張）
2. **`console.log`**（プログラム的に値を見る）
3. **ブラウザのbreakpoint**（処理を一時停止して中を見る）

---

## 🛠 React DevTools

### 入れ方

ブラウザ拡張機能ストアで「React Developer Tools」を検索してインストール。

- Chrome：[Chrome ウェブストア](https://chrome.google.com/webstore)
- Firefox：[Firefox Add-ons](https://addons.mozilla.org)

### 使い方

開発者ツール（F12）を開くと、新しく **「Components」** と **「Profiler」** タブが追加されます。

#### Components タブ

- コンポーネントツリーが見える
- 選んだコンポーネントの **props/state/hooks** を覗ける
- stateを直接変えて挙動を試せる

#### Profiler タブ

- 「**どのコンポーネントが何回・どれくらい時間をかけて再レンダーしたか**」を計測
- パフォーマンス改善のときに使う（9章）

## 💻 console.log の効果的な使い方

### 基本：変数名と値を一緒に出す

```jsx
const count = 5;
const name = '太郎';

// ❌ どの値か分かりにくい
console.log(count);
console.log(name);

// ✅ オブジェクトで囲むと変数名も出る
console.log({ count, name });
// → { count: 5, name: '太郎' }
```

### 色や見出しを付ける

```jsx
console.log('%c important', 'color: red; font-weight: bold');
console.warn('これは警告');
console.error('これはエラー');
console.table([{ id: 1, name: '太郎' }, { id: 2, name: '花子' }]);
```

`console.table` は配列やオブジェクトを表形式で見られて便利。

### グループ化

```jsx
console.group('ユーザー情報');
console.log('id:', user.id);
console.log('name:', user.name);
console.groupEnd();
```

### レンダーごとに値を見る

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  console.log('Counter render', { count }); // 再レンダーごとに出る
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

→ ボタンを押すたびにログが流れ、stateの変化を追える。

## 🛑 ブラウザのbreakpoint

### 設定方法

1. F12で開発者ツールを開く
2. **Sources** タブを選ぶ
3. 該当ファイルを開く（vite経由なら `webpack://` や `vite://` 配下）
4. 行番号をクリック → 青い矢印がつく（breakpoint設定）

### 動作

- そこに処理が来ると**自動で一時停止**
- 右側のパネルで現在のスコープ・変数の値が確認できる
- F10で1行ずつ実行、F11で関数の中に入る

### コードに `debugger;` を書く方法

```jsx
function handleSubmit() {
  debugger; // ← ここで自動停止
  // 以降の処理
}
```

開発者ツールが開いていると、ここで止まります。**消し忘れに注意**（コミット前に検索して消す）。

## 💻 デバッグの考え方（コツ）

### 「思い込みを疑う」

「`count` は5のはず」を信じず、**実際にlogで確認**する。

### 「1か所ずつ確認」

```jsx
async function fetchUser() {
  console.log('1. 開始');
  const res = await fetch('/api/user');
  console.log('2. fetch完了', res.status);
  const data = await res.json();
  console.log('3. JSON変換完了', data);
  setUser(data);
  console.log('4. setUser完了');
}
```

数字を入れると、どこまで進んだか一目で分かる。

### 「最小再現コード」

バグが起きる**最小のコード**を作る。原因の絞り込みが速くなる。

## ❌ よくある間違い

### console.logを残したまま本番にデプロイ

→ 読み取られると情報漏洩のリスク。**ESLintでwarnルール**を入れる。

### alert を多用する

→ alertは画面を止めるので何回も出ると邪魔。**console.log**を使う。

### エラーが出てもメッセージを読まない

→ エラー文の最初の1行に**ほぼ答え**が書いてある。読むだけで解決することが多い。

### 「動かない」を「思い通りでない」と区別しない

→ 「Aを期待したがBになった」と言語化すると、原因が見えやすい。

---

## ✅ ベストプラクティス

1. **React DevTools** は最初に入れる
2. console.log は **`{ name1, name2 }`形式** で
3. breakpointで処理を**1行ずつ追える**ようにしておく
4. **エラー文は必ず最後まで読む**
5. **本番では console.log を消す**（コミット前にgrepで確認）

---

## 🔬 実践演習

1. React DevTools をインストール
2. CounterコンポーネントのstateをDevToolsから直接書き換える
3. `console.log({ count })` を入れてボタン連打、ログを観察
4. `debugger;` を入れて、その行で停止することを確認

---

## 📝 まとめ

- React DevTools で props/state を直接覗く
- console.log は `{ varName }` 形式が便利
- breakpoint で1行ずつ追える
- エラー文は最後まで読む。思い込みを疑う
