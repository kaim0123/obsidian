# 2-3. プロジェクト構成の見方（src配下、エントリポイント）

## 🎯 この章で学ぶこと

- Viteで作ったプロジェクトの各ファイル・フォルダの役割
- 「エントリポイント」がどこか、何をしているか
- どこに何を書くか（ルール）

---

## 📖 概念の説明

### 全体像（最小構成）

```text
my-app/
├─ public/
│  └─ vite.svg           # 静的ファイル（直接配信）
├─ src/                  # ★ここに書く
│  ├─ assets/            # 画像など
│  ├─ App.jsx            # ルートコンポーネント
│  ├─ main.jsx           # ★エントリポイント
│  ├─ App.css
│  └─ index.css
├─ index.html            # HTMLテンプレート
├─ package.json          # プロジェクト設定
├─ vite.config.js        # Vite設定
├─ .gitignore
└─ node_modules/         # 依存ライブラリ（自動生成、触らない）
```

### エントリポイント（main.jsx）

「**プログラムが最初に実行される場所**」のこと。Reactアプリの場合、`src/main.jsx` から始まります。

```jsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App.jsx';
import './index.css';

ReactDOM
  .createRoot(document.getElementById('root'))
  .render(
    <React.StrictMode>
      <App />
    </React.StrictMode>
  );
```

何をしているか：

1. `index.html` の `<div id="root">` を取得
2. `<App />` コンポーネントをそこに描画
3. `StrictMode` で開発時のチェックを有効化

### index.html

```html
<!doctype html>
<html lang="ja">
  <head>
    <meta charset="UTF-8" />
    <title>Vite + React</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
```

`<div id="root">` がReactアプリが描画される場所。`<script>` で `main.jsx` を読み込んでいます。

## 📁 各ファイル・フォルダの役割

### src/

あなたが書くコードを置く場所。基本的にここしか触りません。

### src/main.jsx（エントリポイント）

アプリの起動コード。普段は触らない。

### src/App.jsx

「ルートコンポーネント」。ここから子コンポーネントへ枝分かれします。

### src/components/（自分で作る）

再利用するパーツ（Button, Header など）を置きます。最初は `src/` 直下に書いて、増えてきたら整理。

### src/pages/ または src/features/（自分で作る）

ページや機能のかたまり。 [[10-6-ディレクトリ設計]] で扱います。

### src/assets/

画像・SVGなど。`import logo from './assets/logo.png'` のように読み込めます。

### public/

`/vite.svg` のようにそのまま公開されるファイルを置く場所。**変換されません**。

| | src/assets | public/ |
| --- | --- | --- |
| import文で読み込む | ✓ | ✗ |
| ハッシュが付く | ✓ | ✗ |
| そのままURL指定 | ✗ | ✓ |
| 用途 | 通常の画像 | favicon, robots.txt |

### vite.config.js

Viteの設定。最初は触らない。プラグイン追加などで編集する。

### package.json

依存関係・スクリプトの定義。**最重要**。

### node_modules/

インストールされたライブラリの実体。**絶対に手で編集しない**。

## 💻 簡単な追加例

### 新しいコンポーネントを作る

```text
src/
├─ App.jsx
└─ components/
   └─ Greeting.jsx
```

```jsx
// src/components/Greeting.jsx
export default function Greeting({ name }) {
  return <h1>こんにちは、{name}さん</h1>;
}
```

```jsx
// src/App.jsx
import Greeting from './components/Greeting.jsx';

export default function App() {
  return <Greeting name="太郎" />;
}
```

→ 画面に「こんにちは、太郎さん」が表示される。

## ❌ よくある間違い

### main.jsx を消したり書き換える

→ アプリが起動しなくなる。基本触らない。

### public/ にimport対象のファイルを置く

```jsx
// ❌ 動かない
import logo from '/public/logo.png';

// ✅
import logo from './assets/logo.png';
```

### 拡張子を間違える

→ `.jsx`（または`.tsx`）にしないとJSXが書けない。

### node_modulesを直接編集

→ 次の `npm install` で消える。**package.json経由で管理**する。

---

## ✅ ベストプラクティス

1. **触るのは原則 src/ だけ**
2. 機能ごとにフォルダで整理する習慣（最初は1つでもOK）
3. **画像はsrc/assets/、faviconはpublic/**
4. ファイル名はキャメルケース or パスカルケース。コンポーネントは大文字始まり
5. **エントリポイント（main.jsx）は神様**、簡単に変えない

---

## 🔬 実践演習

1. `src/components/` フォルダを作る
2. `Greeting.jsx` というコンポーネントを作って `<h1>Hello</h1>` を返すようにする
3. `App.jsx` で `Greeting` を表示する
4. `Greeting` に `name` propsを追加して、`<h1>Hello, name</h1>` と動的に表示する

---

## 📝 まとめ

- 触るのは基本 src/ だけ
- エントリポイントは src/main.jsx（普段触らない）
- index.html の `<div id="root">` にReactが描画される
- 画像はsrc/assets/、faviconなどはpublic/
