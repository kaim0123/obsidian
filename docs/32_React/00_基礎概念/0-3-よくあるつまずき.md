## 📖 概念の説明

Reactには、初心者が必ずと言っていいほど踏む4つの「落とし穴」があります。先に知っておくだけでショックが軽減します。

### つまずき① 状態（state）の更新と画面の更新がズレる

```jsx
const [count, setCount] = useState(0);

function handleClick() {
  setCount(count + 1);
  console.log(count); // ❓ 0 のまま！
}
```

**理由**：`setCount`は「次の再レンダーで値を更新する予約」をするだけ。今のレンダー内では`count`は変わらない。

→ 詳しくは [[4-1-useStateの基本]] / [[4-3-setStateの落とし穴]]

### つまずき② 再レンダーが理解できない

「同じボタンを押したのに2回画面が描かれた…なぜ？」

**理由**：Reactの開発モード（StrictMode）は、副作用のバグを早期発見するために**意図的に2回**実行することがある。本番では1回。

→ 詳しくは [[1-3-Reactのレンダーとは]] / [[5-4-StrictModeで2回動く理由]]

### つまずき③ 非同期処理で値が古い（stale closure）

```jsx
useEffect(() => {
  setInterval(() => {
    setCount(count + 1); // ❓ ずっと1のまま増えない
  }, 1000);
}, []);
```

**理由**：`useEffect`の中の`count`は、初回レンダー時の値で固まっている（古いクロージャ）。

→ 詳しくは [[5-5-よくあるバグ集]]

### つまずき④ 依存配列を間違える

```jsx
useEffect(() => {
  fetchData(userId);
}, []); // ❓ userIdが変わってもAPIが呼ばれない
```

**理由**：`useEffect`の第2引数（依存配列）にある値が変わったときだけ実行される。`userId`を入れ忘れると、変化を感知できない。

→ 詳しくは [[5-2-依存配列の読み方]]

## 💡 つまずきを早く抜けるコツ

### コツ1：エラーメッセージを必ず最後まで読む

```text
Warning: Each child in a list should have a unique "key" prop.
       ↑ これは「リストにkey属性が必要」というReactからの忠告
```

エラーは英語ですが、最初の1行を読むだけで原因が分かることが多い。

### コツ2：console.logで状態を見える化

```jsx
console.log({ count, userId, status });
```

オブジェクトで囲むと変数名と値が一緒に出て、追いやすい。

### コツ3：React DevToolsでstateを覗く

ブラウザ拡張の「React Developer Tools」を入れると、各コンポーネントのstate・propsをリアルタイムで見られる。

→ 詳しくは [[2-5-デバッグ]]

## ❌ NGパターン集

### NG① state更新後にすぐ値を読む

```jsx
setCount(count + 1);
saveToServer(count); // 古いcount
```

→ ✅ 計算した値を変数に入れて両方に使う：

```jsx
const next = count + 1;
setCount(next);
saveToServer(next);
```

### NG② オブジェクトを直接書き換える

```jsx
user.name = '新しい名前';
setUser(user); // 画面更新されない（同じ参照）
```

→ ✅ 新しいオブジェクトで置き換える：

```jsx
setUser({ ...user, name: '新しい名前' });
```

### NG③ useEffectの中でstateを読み続ける

```jsx
useEffect(() => {
  setTimeout(() => setCount(count + 1), 1000);
}, []); // count が古いまま
```

→ ✅ 関数更新を使う：

```jsx
useEffect(() => {
  setTimeout(() => setCount(c => c + 1), 1000);
}, []);
```
