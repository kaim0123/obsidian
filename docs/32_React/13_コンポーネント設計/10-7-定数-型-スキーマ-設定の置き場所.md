# 10-7. 定数・型・スキーマ・設定の置き場所ルール

## 🎯 この章で学ぶこと

- 定数・型・スキーマ・設定をどこに置くか
- マジックナンバーをなくすコツ
- zod で型とバリデーションを統一する考え方

---

## 🧾 早見：フォルダと「主に中身になるもの」

| 置き場（よくある名前） | 主な中身 | 典型例 |
|------------------------|----------|--------|
| `constants/` または `constants.ts` | **変わりにくい値**、列挙に近いラベル | ページサイズ、クエリキー、UI 制約（最大文字数） |
| `config/` または `config.ts` | **環境・機能フラグ・ビルド時設定** | ベースURL、feature flags、初期化用オブジェクト |
| `types/` / `models/` / `*.types.ts` | **型**（`type` / `interface` / `enum`） | APIレスポンス、共有ドメイン型 |
| `schemas/` / `validations/` | **実行時検証**（Zod等）＋そこから導く型 | フォーム入力、APIペイロード検証 |
| `mocks/` / `__mocks__/` | **テスト・Storybook 用**の偽データ | MSW handlers、fixtures |
| `locales/` / `i18n/` | **文言・翻訳** | 言語キーと文言マップ |
| `styles/` / `theme/` | **テーマトークン**（色・スペース） | CSS変数、`tokens.ts` |

---

## 📖 配置ルール

### ① 定数（constants）

「**変わらない値**」。マジックナンバーを名前にする。

```ts
// constants/index.ts
export const MAX_TODOS = 100;
export const DEFAULT_PAGE_SIZE = 20;
export const ACCEPTED_IMAGE_TYPES = ['image/png', 'image/jpeg'];
```

機能専用の定数は **feature 内**に：

```ts
// features/auth/constants.ts
export const PASSWORD_MIN_LENGTH = 8;
```

### ② 型（types）

```ts
// types/user.ts
export type User = {
  id: number;
  name: string;
  email: string;
};
```

機能専用は **feature 内**：

```ts
// features/products/types.ts
export type Product = { ... };
```

### ③ スキーマ（schemas、zod など）

「**実行時のバリデーション + 型**」を兼ねる。

```ts
// features/auth/schemas.ts
import { z } from 'zod';

export const loginSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

export type LoginInput = z.infer<typeof loginSchema>;
```

zodなら **1つの定義で 型 + バリデーション** が手に入る。

### ④ 設定（config）

「**環境ごとに変わる値**」。

```ts
// config.ts
export const config = {
  apiUrl: import.meta.env.VITE_API_URL,
  appName: 'My App',
  features: {
    enableBeta: import.meta.env.VITE_ENABLE_BETA === 'true',
  },
};
```

→ `.env` ファイルから読む。詳しくは [[15-1-本番ビルドと環境変数]]。

## 🧩 `mocks` / `i18n` / `theme` の置き方（補足）

### `mocks/`（テスト・Storybook専用）

- **置く**：MSW の `handlers`、固定レスポンス、Storybook の `args` 用サンプル
- **置かない**：本番コードが import する「本物の定数」（本番とテストの混同を避ける）

### `locales/` / `i18n/`

- **置く**：文言辞書、ロケール設定
- **置かない**：レイアウト用の数値（`margin: 8` など）→ theme / CSS か constants

### `styles/` / `theme/`

- **置く**：デザイントークン（色、スペース、フォントサイズ）やテーマ設定
- **置かない**：画面固有のスタイル（そのコンポーネントの近くへ）

## 💻 マジックナンバーをなくす

### Before

```jsx
if (todos.length >= 100) alert('もう追加できません');
items.slice(0, 20);
```

100、20が**何を意味するか分からない**。

### After

```ts
// constants.ts
export const MAX_TODOS = 100;
export const DEFAULT_PAGE_SIZE = 20;
```

```jsx
import { MAX_TODOS, DEFAULT_PAGE_SIZE } from '@/constants';

if (todos.length >= MAX_TODOS) alert('もう追加できません');
items.slice(0, DEFAULT_PAGE_SIZE);
```

意味が読める、変更が1か所で済む。

## 💻 Enum / Union Type

### TS の literal union（推奨）

```ts
type Status = 'idle' | 'loading' | 'success' | 'error';

const status: Status = 'loading';
```

### TS の enum（昔ながら）

```ts
enum Status {
  Idle = 'idle',
  Loading = 'loading',
}
```

→ ランタイムにオブジェクトを生成。union typeのほうが軽い。

### const + as const

```ts
export const STATUS = {
  IDLE: 'idle',
  LOADING: 'loading',
} as const;

type Status = typeof STATUS[keyof typeof STATUS];
```

→ 値も型も使える、オブジェクトリテラル感覚。

## 💻 zod スキーマで型を共有

```ts
// features/auth/schemas.ts
import { z } from 'zod';

export const loginSchema = z.object({
  email: z.string().email('メール形式が違います'),
  password: z.string().min(8, '8文字以上'),
});

export type LoginInput = z.infer<typeof loginSchema>;
```

```tsx
// LoginForm.tsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { loginSchema, type LoginInput } from './schemas';

function LoginForm() {
  const { register, handleSubmit } = useForm<LoginInput>({
    resolver: zodResolver(loginSchema),
  });

  const onSubmit = (data: LoginInput) => { /* dataは型安全 */ };
}
```

→ **1つの定義から 型・バリデーション・フォーム** が動く。

## 💻 環境変数の扱い

### Vite

```bash
# .env
VITE_API_URL=https://api.example.com
VITE_APP_NAME=MyApp
```

```ts
import.meta.env.VITE_API_URL
```

ルール：

- `VITE_` プレフィックス必須
- `.env`、`.env.local`、`.env.production` などで切替

注意：環境変数は**ビルド時に埋め込まれる**。secret は入れない。

→ [[15-1-本番ビルドと環境変数]]

---

## 💻 設定ファイルの集約

```ts
// config.ts
const config = {
  apiUrl: import.meta.env.VITE_API_URL,
  appName: import.meta.env.VITE_APP_NAME,
  features: {
    chat: import.meta.env.VITE_FEATURE_CHAT === 'true',
  },
} as const;

export default config;
```

→ コード内で `config.apiUrl` で読む。`import.meta.env` を散りばめない。

---

## 🧠 ディレクトリを増やしすぎないための合言葉

1. **最初は2〜3カ所**（例：`types`、必要なら `constants` / `schemas`）で始める
2. **同じ悩みが3回出た**らフォルダ（またはファイル）を新設
3. **1か所が肥大化**したら、テーマ（`date` / `form` / `api` など）で **ファイル分割**する

---

## ❌ よくある間違い

### マジックナンバー散在

```jsx
fetch(url, { timeout: 5000 });
if (count > 10) ...;
```

→ 名前を付けて定数化。

### 型を `any` で逃げる

```ts
function load(): any { ... }
```

→ ✅ 具体的な型。

### `.env` の secret をクライアントに

→ `VITE_API_KEY=...` のようなsecretは**バンドルに混入**する。secret はサーバ側。

### 同じ型を複数ファイルで重複定義

→ 1か所に集める。

---

## ✅ ベストプラクティス

1. **マジックナンバーは定数に**
2. **型と zod スキーマで型安全 + 検証**
3. **環境変数は config.ts に集約**
4. **secret はクライアントに置かない**
5. **共通は src/ 直下、機能専用は features/ 内**

---

## 🔬 実践演習

ユーザー登録の zod スキーマ：

- 名前（1〜20文字）
- メール（形式 + 必須）
- パスワード（8文字以上、英数記号混在）
- パスワード確認（一致）

`z.infer` で型を作って、フォームと結合する。

---

## 📝 まとめ

- 定数・型・スキーマ・設定はそれぞれ専用フォルダに
- 共通は src/ 直下、機能専用は features/ 内
- zod で型 + 検証を統一
- 環境変数は config.ts で集約
