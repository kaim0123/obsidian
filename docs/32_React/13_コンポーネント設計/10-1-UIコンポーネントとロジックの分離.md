# 10-1. UIコンポーネントとロジックの分離

## 🎯 この章で学ぶこと

- なぜUIとロジックを分けるか
- カスタムフックでロジックを切り出す
- before/after の比較

---

## 📖 概念の説明

### 「分離」とは

1つのコンポーネントに以下が混在しがち：

- 状態管理（state, useEffect）
- API呼び出し
- バリデーション
- 表示（JSX）
- スタイル

これらを**役割ごとに分ける**と、テスト・再利用・保守がしやすくなる。

### 主な分離手段

1. **カスタムフック**：ロジックを関数に
2. **Container / Presentational**：データ取得と見た目を分ける
3. **propsで切り替え**：見た目だけのコンポーネントを再利用

---

## 💻 Before：すべて1コンポーネント

```jsx
function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);
  const [search, setSearch] = useState('');

  useEffect(() => {
    setLoading(true);
    fetch('/api/users')
      .then((r) => r.json())
      .then(setUsers)
      .catch(setError)
      .finally(() => setLoading(false));
  }, []);

  const filtered = users.filter((u) => u.name.includes(search));

  if (loading) return <p>読込中</p>;
  if (error) return <p>エラー: {error.message}</p>;

  return (
    <div>
      <input value={search} onChange={(e) => setSearch(e.target.value)} />
      <ul>{filtered.map((u) => <li key={u.id}>{u.name}</li>)}</ul>
    </div>
  );
}
```

混在していて読みにくい、テストもしづらい。

---

## 💻 After：カスタムフックで分離

```jsx
// hooks/useUsers.js
function useUsers() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  useEffect(() => {
    setLoading(true);
    fetch('/api/users')
      .then((r) => r.json())
      .then(setUsers)
      .catch(setError)
      .finally(() => setLoading(false));
  }, []);

  return { users, loading, error };
}

// components/UserList.jsx
function UserList() {
  const { users, loading, error } = useUsers();
  const [search, setSearch] = useState('');

  const filtered = users.filter((u) => u.name.includes(search));

  if (loading) return <p>読込中</p>;
  if (error) return <p>エラー: {error.message}</p>;

  return (
    <div>
      <input value={search} onChange={(e) => setSearch(e.target.value)} />
      <ul>{filtered.map((u) => <li key={u.id}>{u.name}</li>)}</ul>
    </div>
  );
}
```

利点：

- `useUsers` はテストしやすい
- 別コンポーネントでも使い回せる
- UserList は表示に集中

## 💻 さらに：見た目も分離

```jsx
// components/UserListView.jsx（見た目だけ）
function UserListView({ users, search, onSearchChange }) {
  return (
    <div>
      <input value={search} onChange={(e) => onSearchChange(e.target.value)} />
      <ul>{users.map((u) => <li key={u.id}>{u.name}</li>)}</ul>
    </div>
  );
}

// components/UserList.jsx（つなぐだけ）
function UserList() {
  const { users, loading, error } = useUsers();
  const [search, setSearch] = useState('');
  const filtered = users.filter((u) => u.name.includes(search));

  if (loading) return <p>読込中</p>;
  if (error) return <p>エラー</p>;

  return <UserListView users={filtered} search={search} onSearchChange={setSearch} />;
}
```

→ `UserListView` はStorybookで見た目をプレビューしやすい。propsだけで動く。

## 💡 分離の判断基準

### カスタムフックに切り出すサイン

- 同じ useEffect / useState のセットを別コンポーネントでも使う
- ロジックが20行以上
- テストを書きたい
- 名前が「やってること」を表せる（`useFetch`, `useDebouncedValue`...）

### 見た目だけ切り出すサイン

- Storybookで見たい
- 同じ見た目で違うデータソースで使い回す
- デザイナーと共同作業

---

## ❌ よくある間違い

### 何でもカスタムフックに

```jsx
// ❌ 1か所しか使わない useState を切り出す
function useCount() {
  return useState(0);
}
```

→ 過剰。**2回以上使ってから切り出し**で十分。

### Container / Presentational を厳密に守る

→ シンプルなアプリでは混在でもOK。**規模に合わせる**。

### カスタムフックでDOM操作

```jsx
function useScroll() {
  document.getElementById('top').scrollIntoView(); // ❌
}
```

→ DOM 操作は ref 経由でコンポーネント側に。

---

## ✅ ベストプラクティス

1. **API取得・購読・タイマーはカスタムフック**
2. **見た目だけのコンポーネントは props 駆動**
3. **2回使ってから抽出**でOK
4. **名前が動詞風**（useFetch, useToggle, useDebounce）
5. **大規模になったら本格的な分離**

---

## 🔬 実践演習

カウンター + リセット + 自動増加（1秒ごと） のロジックを `useAutoCounter` カスタムフックに切り出す。

```jsx
function App() {
  const { count, reset } = useAutoCounter();
  return (
    <>
      <p>{count}</p>
      <button onClick={reset}>リセット</button>
    </>
  );
}
```

---

## 📝 まとめ

- ロジックはカスタムフックに、見た目はpropsで
- カスタムフック名は「使う動作」を表す
- 2回使うなら抽出
- 規模に合わせて分離度合いを決める
