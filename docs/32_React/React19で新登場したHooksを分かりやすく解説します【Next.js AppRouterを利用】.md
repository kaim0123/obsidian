## 動画の詳細要約

本動画は **React 19（当時はベータ）で追加・変更されたフォーム周りの API と `use()`** を、**Next.js App Router（RSC 前提）** でどう使うかに焦点を当てたハンズオン解説である。前提として、動画収録時点では本番でベータ版を使うのは避け、安定版移行後も概念はほぼ保たれるとしつつ、GitHub テンプレートを `git clone` して手を動かす流れになっている。

### RSC（React Server Components）の整理

- **クライアントコンポーネント**はブラウザ側でレンダリングする従来型のコンポーネント。**サーバーコンポーネント**はサーバーでプリレンダリングし、HTML やデータ取得済みの状態でクライアントに返す考え方。
- **Next.js App Router ではデフォルトがサーバーコンポーネント**。クライアントにしたい場合のみファイル先頭に `'use client'` を付ける。
- **React 単体では Server Actions は使えるが、RSC（オレンジ色の「サーバー専用ツリー」）そのものは Next など RSC 対応フレームワークが必要**、という区別が説明される。

### Server Actions

- `<form action={...}>` に渡す **async 関数がサーバーで実行される**仕組み。従来の REST API をクライアントから `fetch` する手間や往復を減らし、**JS が無効な環境でもフォーム送信が成立しやすい**一方、**フロントのファイルにサーバー処理が混ざる**ため役割分担が曖昧になるデメリットも触れられる。
- サーバー側の関数には **`'use server'`** が必要。インライン定義する場合はその関数ブロックに付与。
- **フォーム値は第 1 引数の `FormData`** で受け取り、`formData.get('name')` のキーは `<input name="...">` と一致させる。DB 保存などで **文字列が欲しいときは `as string` などで型を合わせる**例が出る。
- **クライアントコンポーネント内では、同じファイルに `'use server'` を置けない**。別ファイル（例: `actions.ts`）にアクションを切り出し **`export` し、呼び出し元ページの先頭に `'use server'` を置く**（※動画内の手順に沿った Next の制約の説明）というパターンが紹介される。
- 送信後に入力を空にしたい場合は **`useRef<HTMLFormElement>` で `form` に `ref` を付け、`action` 内で `await` したあと `formRef.current?.reset()`** のようにする。
- サーバーでデータを更新したあと **UI を最新にしたい場合は `revalidatePath` で該当パスを再検証**する、という使い分けが説明される。

### `useFormStatus`

- **親の `<form>` の送信中かどうか（`pending` など）を子コンポーネントから読む**ためのフック。**`<form>` の子孫として組んだボタン用コンポーネント内**で使う必要がある。
- ローディング文言の表示に加え、**`pending` 時に `disabled` や `cursor-not-allowed` 等で連打を防ぐ**デモがある。待ち時間の見せ方のため、サーバーアクション側で `setTimeout` による遅延を入れる例も出る。

### `useFormState` と `useActionState`

- サーバーアクションの戻り値を **「前回の state」と次の `form action` に紐づけて受け取る**イメージで、**`useReducer` や Redux の reducer に近い**と説明される。
- **React 19 では `useFormState` が `useActionState` にリネーム**される流れがドキュメント上で示され、**フォーム以外の `<button formAction={...}>` でも使える**ため「Form 専用」という名前が誤解を招く、という命名理由に触れられる。
- 収録当時の **Next.js 14.2 系では `useActionState` が使えず `useFormState` のみ**、**14.3 以降で `useActionState` が使える**という注記がある。`useActionState` は **pending も扱える**ため、保留中のボタン無効化には `useFormStatus` と同様の UI 制御が可能、と補足される。

### `useOptimistic`

- **楽観的 UI**：サーバーの保存完了を待たずに一覧へ即反映し、送信中などの一時状態を見せる。チャット投稿のデモで、**保留中リスト → サーバー処理後に「確定リスト」へ**という流れを疑似コードで説明。
- **クライアントコンポーネント限定**。サーバー側の永続化は別ファイルの Server Action に寄せ、`revalidatePath` で整合を取る、という構成が理想的だとされる。動画後半は DB 無しのため `setState` で疑似的に確定させる。

### `use()`（Hooks ではなく API）

- **Promise を渡すと解決済みの値までサスペンドする**。`useState` / `useEffect` でフェッチ状態を組むより **コードが単純化**できる例が、`fetch` → `use(promise)` → `map` 表示として示される。
- **ローディングは `<Suspense fallback={...}>` で担保**。非同期子をラップし、Promise 解決までフォールバックを表示する。
- **`useContext` の代替としてコンテキストを読める**ほか、`if` など条件分岐内でも呼べるという公式のニュアンスが紹介される。**サーバーコンポーネントでも使える（フックではない）**点も触れられる。
- 「サーバーでフェッチした Promise を子のクライアントコンポーネントに渡し、その中で `use` で unwrap する」といった **データストリーミング的な構成**にも言及がある。

### 締め

- 紹介した API は **RSC / Server Actions が使える環境（特に Next.js）** での利用が主軸。RSC 以降のフロントは難易度が上がるが、本動画のように **環境セットアップ → RSC/Server Actions → 各 Hook/API** の順で追うと理解の道筋が作りやすい、という趣旨で締めくくられる。
