---

## 📖 E2Eテストとは

「**End-to-End**」＝ユーザーの操作を最初から最後まで本物のブラウザで再現するテスト。

例：

- ログイン → 商品検索 → カート追加 → 決済 → 完了画面

実物に近いので**価値が高い**が、**遅い・不安定**になりがち。

```bash
npm init playwright@latest
```

```bash

npx playwright test --ui      # UIモード（おすすめ）
npx playwright test --headed  # ブラウザ表示
npx playwright codegen        # 操作を録画してコード生成
```

## 💻 基本構文

```ts
import { test, expect } from '@playwright/test';

test('ホームページが表示される', async ({ page }) => {
  await page.goto('http://localhost:5173');

  await expect(page).toHaveTitle(/My App/);
  await expect(page.getByRole('heading', { level: 1 })).toContainText('ようこそ');
});
```

---

## 💻 ログイン → ダッシュボード

```ts
test('ログインしてダッシュボードへ', async ({ page }) => {
  await page.goto('/login');

  await page.getByLabel('メール').fill('user@example.com');
  await page.getByLabel('パスワード').fill('password123');
  await page.getByRole('button', { name: 'ログイン' }).click();

  await expect(page).toHaveURL('/dashboard');
  await expect(page.getByRole('heading', { name: 'ダッシュボード' })).toBeVisible();
});
```

ロケータの探し方は RTL に近い：

- `page.getByRole(...)`
- `page.getByLabel(...)`
- `page.getByText(...)`
- `page.getByTestId(...)`

---

## 💻 セレクタの優先順位

| 推奨 | 例 |
| --- | --- |
| ◎ | `getByRole('button', { name: '送信' })` |
| ◎ | `getByLabel('メール')` |
| ○ | `getByText('続きを読む')` |
| △ | `getByTestId('submit-btn')` |
| ✗ | `locator('.btn-submit')` |

→ アクセシビリティと一致するセレクタが安定。

---

## 💻 待機

```ts
// 自動待機（推奨）
await page.getByText('完了').click(); // 表示されるまで自動で待つ

// 明示的に待つ
await expect(page.getByText('完了')).toBeVisible();
await page.waitForURL('/done');
await page.waitForLoadState('networkidle');
```

→ Playwrightは**自動待機**してくれる。`sleep` は基本不要。

## 💻 アサーション

```ts
await expect(page.getByText('成功')).toBeVisible();
```

## 💻 ログイン状態を共有

毎テストでログインするのは遅い。**事前に1度だけログインしてセッション保存**：

```ts
// global-setup.ts
import { chromium } from '@playwright/test';

export default async () => {
  const browser = await chromium.launch();
  const page = await browser.newPage();
  await page.goto('http://localhost:5173/login');
  await page.getByLabel('メール').fill('user@example.com');
  await page.getByLabel('パスワード').fill('password');
  await page.getByRole('button', { name: 'ログイン' }).click();
  await page.context().storageState({ path: 'auth.json' });
  await browser.close();
};
```

```ts
// playwright.config.ts
export default {
  globalSetup: './global-setup.ts',
  use: {
    storageState: 'auth.json',
  },
};
```

→ 各テストはログイン済みで開始。

## 💡 何をE2Eにする？

| すべき | しない |
| --- | --- |
| 重要なフロー（ログイン、決済、登録） | UIの細部 |
| 複数機能の組み合わせ | 単機能 |
| 本番に近い環境テスト | バリデーション詳細 |

→ E2E は**価値の高いシナリオに絞る**（5〜10ケース）。残りは Integration / Unit。


## ❌ よくある間違い

### 全機能を E2E でテスト

→ 遅すぎ、不安定。**Integration中心、E2Eは重要なものだけ**。

### `sleep` で待つ

→ ✅ Playwright の自動待機 / `expect.toBeVisible`。

### 不安定なセレクタ

```ts
page.locator('.btn-submit-2.large.primary'); // 壊れやすい
```

→ ✅ `getByRole`。

### テスト間で状態が漏れる

→ DBクリア、storageStateリセット。

---

## ✅ ベストプラクティス

1. **重要シナリオに絞る**
2. **getByRole / getByLabel** 優先
3. **自動待機**を活用、sleepしない
4. **storageState** でログイン共有
5. **CI で毎回実行**
