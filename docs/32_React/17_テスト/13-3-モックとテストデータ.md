# 13-3. モックとテストデータ

## 🎯 この章で学ぶこと

- vi.fn() / vi.mock() でモック
- MSW で API モック（実装に近い）
- テストデータの作り方（factory パターン）

---

## 📖 モックとは

「**実物の代わりに使う偽物**」。テストで本物のAPIや外部サービスを呼びたくないときに使う。

理由：

- API を呼ばずにテストを高速化
- 失敗するパターンを再現できる
- 副作用を出さない（メール送信、課金など）

---

## 💻 vi.fn()：関数のモック

```ts
import { vi } from 'vitest';

const mockFn = vi.fn();
mockFn(1, 2);
mockFn(3, 4);

expect(mockFn).toHaveBeenCalledTimes(2);
expect(mockFn).toHaveBeenCalledWith(1, 2);
expect(mockFn).toHaveBeenLastCalledWith(3, 4);
```

### 戻り値を設定

```ts
const mockFn = vi.fn().mockReturnValue(42);
expect(mockFn()).toBe(42);

// Promise
const mockFetch = vi.fn().mockResolvedValue({ data: 'hello' });
const data = await mockFetch();
```

### 例：propsとして渡す

```tsx
const handleSubmit = vi.fn();
render(<Form onSubmit={handleSubmit} />);

await user.click(screen.getByRole('button', { name: '送信' }));

expect(handleSubmit).toHaveBeenCalledWith({ name: '太郎' });
```

---

## 💻 vi.mock()：モジュールのモック

```ts
// services/api.ts
export async function fetchUser(id) {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}

// Component.test.tsx
vi.mock('./services/api', () => ({
  fetchUser: vi.fn().mockResolvedValue({ id: 1, name: '太郎' }),
}));
```

---

## 💻 fetch / globalThis のモック

```ts
beforeEach(() => {
  globalThis.fetch = vi.fn().mockResolvedValue({
    ok: true,
    json: async () => ({ users: [{ id: 1, name: '太郎' }] }),
  });
});

afterEach(() => {
  vi.restoreAllMocks();
});
```

→ ただし手書きはバグの温床。**MSW** がおすすめ。

## 💻 MSW（Mock Service Worker）

「**ネットワーク層**」でAPIをモック。コードを変更せずにレスポンスを差し替えられる。

```bash
npm install -D msw
```

```ts
// src/test/mocks/handlers.ts
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/users', () => {
    return HttpResponse.json([
      { id: 1, name: '太郎' },
      { id: 2, name: '花子' },
    ]);
  }),

  http.post('/api/users', async ({ request }) => {
    const body = await request.json();
    return HttpResponse.json({ id: 3, ...body }, { status: 201 });
  }),
];
```

```ts
// src/test/setup.ts
import { setupServer } from 'msw/node';
import { handlers } from './mocks/handlers';

const server = setupServer(...handlers);

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
```

```tsx
// テスト
it('ユーザー一覧を表示', async () => {
  render(<UserList />);
  expect(await screen.findByText('太郎')).toBeInTheDocument();
});
```

→ 本番のfetchがそのまま動く感覚。

### 個別テストでハンドラを上書き

```tsx
it('エラー時にメッセージ表示', async () => {
  server.use(
    http.get('/api/users', () => {
      return new HttpResponse(null, { status: 500 });
    })
  );

  render(<UserList />);
  expect(await screen.findByText('エラーが発生しました')).toBeInTheDocument();
});
```

## 💻 テストデータの作り方

### Factory 関数

```ts
// test/factories/user.ts
let id = 0;

export function createUser(overrides = {}) {
  return {
    id: ++id,
    name: `ユーザー${id}`,
    email: `user${id}@example.com`,
    age: 25,
    ...overrides,
  };
}
```

```ts
const user1 = createUser();                          // デフォルト
const admin = createUser({ name: '管理者', role: 'admin' });
```

→ 必要な部分だけ上書きできる。テストの意図が明確に。

### Faker（ランダムデータ）

```bash
npm install -D @faker-js/faker
```

```ts
import { faker } from '@faker-js/faker';

faker.person.fullName(); // → 'John Doe'
faker.internet.email();
faker.lorem.paragraph();
```

ただし**ランダム = 再現性がない** ので、シードを固定するか避ける。

## 💻 タイマーのモック

```ts
import { vi } from 'vitest';

it('3秒後にトーストが消える', () => {
  vi.useFakeTimers();

  render(<Toast message="保存しました" />);
  expect(screen.getByText('保存しました')).toBeInTheDocument();

  vi.advanceTimersByTime(3000); // 3秒進める

  expect(screen.queryByText('保存しました')).not.toBeInTheDocument();

  vi.useRealTimers();
});
```

## ❌ よくある間違い

### モックしすぎて何もテストしてない

```ts
vi.mock('./Component', () => ({ Component: () => <div /> }));
// → そのコンポーネントのテストにならない
```

→ ✅ モックは外部依存だけに。

### MSW のリセット忘れ

→ `afterEach(() => server.resetHandlers())` 必須。

### 日付の扱い

```ts
new Date()  // テスト時刻が違うと値が変わる
```

→ ✅ `vi.setSystemTime(new Date('2025-01-01'))` で固定。

### グローバル状態の汚染

→ `beforeEach`で初期化、`afterEach`でクリーンアップ。

---

## ✅ ベストプラクティス

1. **APIモックは MSW**
2. **factory** でテストデータ作成
3. **モックは最小限**、本物に近く
4. **タイマー・日時は固定**
5. **テスト間の独立性**を保つ

---

## 🔬 実践演習

ユーザー一覧コンポーネントのテスト：

- MSW で `/api/users` をモック
- 表示成功 / エラー時 / 空配列の3パターン

## 📝 まとめ

- vi.fn() で関数モック、vi.mock() でモジュール
- MSWでAPIをネットワーク層からモック
- factory でテストデータ
- タイマー・日時は固定
