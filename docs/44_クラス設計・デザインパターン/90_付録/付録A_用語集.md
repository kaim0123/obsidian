# 付録A　用語集

本教材で登場する主要用語の一覧です。

---

## あ行

| 用語 | 説明 |
|------|------|
| **アンチパターン** | よくある悪い設計のパターン。避けるべき例 |
| **アグリゲーション** | 部分が独立に存在しうる全体-部分関係 |
| **エンティティ** | ID で同一性を持つドメインオブジェクト |

## か行

| 用語 | 説明 |
|------|------|
| **カプセル化** | 内部を隠し、公開操作だけを提供すること |
| **凝集度** | 1 クラスの中身が 1 つの目的にまとまっている度合い |
| **結合度** | クラス同士の依存の強さ |
| **コンポジション** | 部分が全体の寿命に従属する全体-部分関係 |
| **Creator** | GRASP。適切な作成者がインスタンスを作る原則 |

## さ行

| 用語 | 説明 |
|------|------|
| **責務** | クラスが担当すべき仕事 |
| **集約** | 整合性を保つクラスのまとまり。ルートが窓口 |
| **継承** | 親クラスの性質を子が引き継ぐ仕組み |

## た行

| 用語 | 説明 |
|------|------|
| **デメテルの法則** | 知り合いの知り合いと直接話さない |
| **DIP** | 依存性逆転の原則。抽象に依存する |
| **ドメインモデル** | 業務を表すクラス群 |

## な行

| 用語 | 説明 |
|------|------|
| **値オブジェクト** | 値で比較する不変オブジェクト（Money 等） |
| **多態** | 同じインターフェースで異なる実装を扱うこと |

## は行

| 用語 | 説明 |
|------|------|
| **貧血モデル** | エンティティがデータ入れ物でロジックがサービスに偏る状態 |
| **Information Expert** | GRASP。情報を持つクラスが処理する原則 |
| **インターフェース** | クラスが公開する契約（操作の一覧） |
| **ISP** | インターフェース分離の原則 |
| **不変条件** | オブジェクトが常に満たすべきルール |

## ま行

| 用語 | 説明 |
|------|------|
| **メッセージ** | オブジェクト同士のやりとりの単位（メソッド呼び出し） |

## や行

| 用語 | 説明 |
|------|------|
| **ユビキタス言語** | チーム全員が共有するドメインの用語 |
| **YAGNI** | You Aren't Gonna Need It。今必要ないものは作らない |

## ら行

| 用語 | 説明 |
|------|------|
| **リポジトリ** | 集約の永続化を抽象化するパターン |
| **LSP** | リスコフの置換原則。子は親の代わりに使える |

## わ行・英語

| 用語 | 説明 |
|------|------|
| **OCP** | 開放閉鎖の原則。拡張に開き変更に閉じる |
| **SRP** | 単一責任の原則。変化の理由を 1 つに |
| **SOLID** | オブジェクト指向設計の 5 原則の頭文字 |
| **Strategy** | 振る舞いを差し替えるデザインパターン |
| **Factory** | 生成責務を集約するパターン |
| **God Class** | 何でもやる巨大クラス（神クラス） |
| **DI** | Dependency Injection。依存の注入 |
| **GRASP** | 責任分配のための設計原則集 |
