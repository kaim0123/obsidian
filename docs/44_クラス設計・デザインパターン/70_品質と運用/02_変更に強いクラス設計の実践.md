# 変更に強いクラス設計の実践

## この章の目的

**リファクタリング** を通じてクラス設計を改善する実践手順を学びます。  
Extract Class / Move Method、段階的分割、レガシーへの適用を押さえます。

---

## 1. リファクタリングのタイミング

| タイミング | 例 |
|-----------|-----|
| 機能追加の前 | 触る前に構造を整える |
| バグ修正のついで | 原因が構造にあるとき |
| テスト追加後 | 安全網がある状態で |
| レビュー指摘後 | 小さな PR で直す |

**「動いているから触らない」** より、**小さく頻繁に直す** ほうが長期的に安全です。

---

## 2. Extract Class / Move Method の考え方

Fowler のリファクタリング技法のうち、クラス設計で特に重要な2つです。

### Extract Class

1つのクラスに溜まった責務の **塊** を新クラスへ移す。

```text
  OrderService
      │
      Extract → TaxCalculator（税計算ブロック）
      Extract → DiscountApplier（割引ブロック）
```

### Move Method

メソッドが **他クラスのデータを多用** しているとき、そのクラスへ移す（Feature Envy の解消）。

```javascript
// Before: OrderService.calculateLineTotal(line)
// After:  line.subtotal()  — Expert へ移動
```

### 異なるクラスの重複したコードをなくす

同じ「段落」や計算が複数クラスにコピーされているときは、次の順で寄せます（『現場で役立つシステム設計の原則』第1章）。

1. 各クラスで重複部分を **メソッドに抽出** する（[[04_Extract_Method]]）
2. **参照関係がある** 場合 — 参照する側の呼び出しを、参照される側のメソッド呼び出しに置き換える（Move Method）
3. **参照関係がない** 場合 — 共通の置き場として新しい小さなクラスを作り、双方から呼ぶ（Extract Class）

```text
  ClassA.calcTax()  ─┐
                     ├─→ 共通なら Tax クラス（または既存ドメインオブジェクト）へ
  ClassB.calcTax()  ─┘
```

重複を「共通ユーティリティ」に逃がしすぎると、業務の関心事が見えなくなります。寄せ先はできるだけ **業務用語のクラス**（[[03_ドメインを表すクラス]]）にします。原則としての DRY は [[01_DRY_KISS_YAGNI]] を参照してください。

## 3. クラス分割の段階的な進め方

1. **テストを1本** 足す（最低限の安全網）
2. **変更理由を1つ** 選び、関連メソッドを特定
3. **新クラスを作り** フィールドとメソッドを移動
4. **呼び出し元を更新**（旧クラスは委譲で互換維持も可）
5. **テスト実行** → 次の塊へ

```text
  一気に10クラス ✗
  1責務ずつ Extract ✓
```

[[01_単一責任の原則]] と [[02_GRASP]] を参照。

## 4. レガシーコードへの適用

レガシーでは **いきなり理想設計** は危険です。

| 原則 | 内容 |
|------|------|
| 理解してから変える | 振る舞いをテストで固定 |
| 境界を守る | 新コードは新クラス、旧は薄いアダプタ |
| 絶えず小さく | 1 PR = 1 Extract |
| 触らない勇気 | 変化しない領域はそのまま |

[[03_レガシーとの向き合い方]] も参照。

---

## 5. 技術的負債との向き合い方

**技術的負債** は、設計を先送りした結果の **将来のコスト** です。

```text
  負債の可視化 → 影響・頻度で優先度 → スプリントに小さく組み込む
```

| 記録 | チケット・ADR・コメントで「なぜこうなったか」を残す |
|------|---------------------------------------------------|
| 返済 | 機能開発と **同時に** 少しずつリファクタ |

完璧を目指さず、**変化の多い箇所から** 投資します。

---

## まとめ

- リファクタは追加・修正のタイミングで小さく
- Extract Class / Move Method がクラス改善の基本
- 段階的に1責務ずつ。テストとセット
- レガシーは境界とアダプタで守りながら改善
