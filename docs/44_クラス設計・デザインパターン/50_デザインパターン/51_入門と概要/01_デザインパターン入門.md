# デザインパターン入門

## この章の目的

**デザインパターン** の全体像を学び、生成・構造・振る舞いの代表例と、  
使う／使わないタイミングの判断を押さえます。

---

## 1. デザインパターンとは何か

デザインパターンは、設計上の **繰り返し現れる問題** に対する **検証済みの解決策の型** です。  
GoF（Gang of Four）の4冊が広く知られています。

| 特徴 | 説明 |
|------|------|
| 名前 | チームで議論する共通語彙 |
| 問題 | どんな状況か |
| 解決 | クラス構成の型 |

パターンは **目的ではなく手段**。問題がなければ不要です。

---

## 2. 生成パターン（Factory / Builder / Singleton）

**オブジェクトの作り方** を整理するパターンです。

| パターン | 用途 |
|---------|------|
| **Factory** | 生成ロジックを隠し、型で作り分け |
| **Builder** | 複雑なオブジェクトを段階的に構築 |
| **Singleton** | インスタンスを1つに（乱用注意） |

```javascript
// Factory のイメージ
class PaymentFactory {
  static create(type) {
    if (type === 'CARD') return new CardPayment();
    if (type === 'BANK') return new BankPayment();
    throw new Error('未知のタイプ');
  }
}
```

Singleton はグローバル状態・テスト困難のため、**本当に1つ必要なときだけ** 使います。

---

## 3. 構造パターン（Adapter / Decorator / Composite）

**クラスの組み合わせ方** を整理するパターンです。

| パターン | 用途 |
|---------|------|
| **Adapter** | 互換性のないインターフェースを橋渡し |
| **Decorator** | 機能を層で追加（継承より柔軟） |
| **Composite** | 部分と全体を同じインターフェースで |

```text
  Adapter:  既存API → 新インターフェース
  Decorator: Coffee → MilkDecorator → SugarDecorator
  Composite: MenuItem / Menu（同じ interface）
```

---

## 4. 振る舞いパターン（Strategy / Observer / Command）

**オブジェクト間の協調・責務分配** を整理するパターンです。

| パターン | 用途 |
|---------|------|
| **Strategy** | アルゴリズムの差し替え（OCP） |
| **Observer** | 変更の通知・疎結合 |
| **Command** | 操作をオブジェクト化（Undo 等） |

[[02_開放閉鎖の原則]] の Strategy と [[03_クラス設計でよく使うパターン]] で実践します。

---

## 5. パターンを使うタイミングと使わないタイミング

### 使うとき

- 同じ構造の問題が **2回以上** 現れた
- 変化の軸がはっきりしている
- チームがパターン名で **議論できる**

### 使わないとき

- 将来かもしれない問題への先回り（YAGNI）
- 1回きりの単純な処理
- パターンのためのパターン（過剰抽象化）

```text
  問題 → 素朴な設計 → 痛みが出た → パターンで整理
```

---

## まとめ

- パターン = 名前付きの設計解。共通語彙になる
- 生成・構造・振る舞いの3分類
- Factory / Strategy / Observer がクラス設計で頻出
- 問題が先、パターンは後
