# クラス設計でよく使うパターン

## この章の目的

クラス設計で実務に頻出する **Strategy・Factory・Observer・Decorator・Repository** を、  
クラス構成の観点で学びます。

---

## 1. Strategy — 振る舞いの差し替え

**Strategy** はアルゴリズムをクラスに切り出し、コンテキストから差し替えます。

```javascript
class StandardShipping { cost(order) { return 500; } }
class ExpressShipping { cost(order) { return 1500; } }

class Shipment {
  constructor(strategy) { this.strategy = strategy; }
  shippingCost(order) { return this.strategy.cost(order); }
}
```

| 向く場面 | 支払い・配送・税・割引 |
|---------|----------------------|
| SOLID | OCP の定番実装 |

---

## 2. Factory — 生成の責務の分離

**Factory** は `new` の詳細を一か所に集め、呼び出し側を具象から解放します。

```javascript
class PaymentFactory {
  create(type, config) {
    switch (type) {
      case 'STRIPE': return new StripePayment(config);
      case 'PAYPAL': return new PayPalPayment(config);
      default: throw new Error(`未対応: ${type}`);
    }
  }
}
```

Creator（GRASP）と組み合わせ、**誰が作るか・どこで作るか** を明確にします。

---

## 3. Observer — 変更通知の疎結合化

**Observer** は状態変化を **購読者に通知** し、直接呼び出しの網を減らします。

```javascript
class Order {
  constructor() { this.listeners = []; }
  subscribe(fn) { this.listeners.push(fn); }
  confirm() {
    this.status = 'CONFIRMED';
    this.listeners.forEach(fn => fn(this));
  }
}
```

| 注意 | 通知先が多すぎると追跡困難。ドメインイベントと併用検討 |
| 関連 | [[05_ドメインイベント]] |

---

## 4. Decorator — 機能の追加と合成

**Decorator** は同じインターフェースを実装し、**ラップして機能を足す** パターンです。

```javascript
class LoggingRepository {
  constructor(inner) { this.inner = inner; }
  save(order) {
    console.log('saving', order.id);
    return this.inner.save(order);
  }
}
```

継承階層を深くせず、**実行時に層を重ねる** のに向きます。

---

## 5. Repository — 永続化の抽象化

**Repository** は集約の永続化を抽象化し、ドメインを DB から隔離します。

```javascript
interface OrderRepository {
  save(order: Order): void;
  findById(id: OrderId): Order | null;
}
```

| 役割 | ドメインは「保存・取得」の契約だけ知る |
| 実装 | `SqlOrderRepository`, `InMemoryOrderRepository` |
| 関連 | [[04_集約とリポジトリ]] |

DIP + Pure Fabrication（GRASP）の実践です。

---

## まとめ

- Strategy = 振る舞いの差し替え
- Factory = 生成の集約
- Observer = 通知の疎結合
- Decorator = ラップで機能追加
- Repository = 永続化の抽象化
