# デザインパターンの概要 — GoFの分類と用途

## はじめに

プログラムを書いていると、「前にも似たような設計をしたな」と感じることが増えてきます。このような **繰り返し現れる設計問題の、定番の解き方** をまとめたものが **デザインパターン** です。

1994年、4人の著者（Gang of Four, GoF）が『デザインパターン ― オブジェクト指向における再利用のための〜』で23個のパターンを体系化しました。現在でも設計の共通語彙として使われています。

---

## なぜデザインパターンを学ぶのか

### 1. 「車輪の再発明」を防ぐ

先人が試行錯誤の末にたどり着いた設計を、初めから使える。

### 2. チームの共通言語になる

「ここはStrategyで書こう」「Factoryを挟もう」と言うだけで、**設計の意図がチームに伝わる**。

### 3. 設計の引き出しが増える

「この問題、どう設計しよう？」のとき、**知っているパターンから選ぶ** だけで出発点ができる。

### 4. 既存のフレームワークが理解しやすくなる

多くのフレームワークはデザインパターンで構成されています（React の Observer、DI コンテナの Factory など）。パターンを知っていると **仕組みが読める** ようになります。

---

## GoFの23パターン — 3つの分類

GoFのパターンは **「何を解決するか」** で3種類に分かれます。

| 分類 | 目的 | 代表パターン |
|------|------|-------------|
| **生成（Creational）** | オブジェクトの作り方を扱う | Factory, Builder, Singleton |
| **構造（Structural）** | オブジェクトの組み合わせ方を扱う | Adapter, Decorator, Facade |
| **振る舞い（Behavioral）** | オブジェクト間のやり取りを扱う | Strategy, Observer, Command |

## 23パターン一覧（クイックリファレンス）

### 生成に関するパターン（5個）

| パターン | ひとこと |
|---------|---------|
| Abstract Factory | 関連するオブジェクト群をまとめて作る |
| Builder | 段階的に複雑なオブジェクトを組み立てる |
| Factory Method | どのクラスを作るかサブクラスに任せる |
| Prototype | 既存のオブジェクトを複製して作る |
| Singleton | インスタンスを1つだけに制限する |

### 構造に関するパターン（7個）

| パターン | ひとこと |
|---------|---------|
| Adapter | 既存の互換性のないAPIを繋ぐ変換アダプタ |
| Bridge | 抽象と実装を別々に拡張できるよう分離 |
| Composite | ツリー構造を再帰的に扱う |
| Decorator | オブジェクトを包んで機能を追加 |
| Facade | 複雑なサブシステムに簡単な窓口を用意 |
| Flyweight | 共通部分を共有してメモリ節約 |
| Proxy | 本物の代理として振る舞う |

### 振る舞いに関するパターン（11個）

| パターン | ひとこと |
|---------|---------|
| Chain of Responsibility | 処理を次々とバケツリレー |
| Command | 操作をオブジェクト化（Undo可） |
| Interpreter | 小さな言語を解釈する |
| Iterator | コレクションを順に辿る |
| Mediator | 仲介者を介してオブジェクト間の通信を整理 |
| Memento | 状態を保存・復元（Undo） |
| Observer | 状態変化を他者に通知 |
| State | 状態によって振る舞いを変える |
| Strategy | アルゴリズムを差し替え可能にする |
| Template Method | 処理の骨格だけ親、詳細を子に |
| Visitor | データ構造を変えずに処理を追加 |

## 身近な例: 普段使っているパターン

意識していないだけで、実はよく使うパターンばかりです。

### Observer（観察者）

```javascript
button.addEventListener('click', handleClick);
// イベント発火 → 登録された関数が通知される
```

### Iterator（反復子）

```javascript
for (const item of list) { /* ... */ }
// 内部構造を知らずに順番に取り出す
```

### Strategy（戦略）

```javascript
[1,3,2].sort((a,b) => a-b); // 比較方法を差し込む
```

### Factory（工場）

```javascript
JSON.parse(str); // stringからオブジェクトを作る
```

### Decorator（装飾）

```typescript
@autobind
@readonly
class MyClass { /* ... */ }
```

## よくある誤解

### 誤解1: パターンを使うほど良い設計

デザインパターンは **問題に対する解** であって、使うこと自体が目的ではありません。**問題がないのに使うと過剰設計** になります。

### 誤解2: とりあえず覚えれば使える

パターンは **「どんな問題を解くか」** を理解しないと活きません。コードの形だけ真似ても誤用になりがちです。

### 誤解3: GoFが全て

GoF以外にも、エンタープライズ向けの **PoEAA**（Repository, Unit of Work など）や、**並行処理パターン**、**関数型のパターン** など、多くの流派があります。

---

## 学び方のコツ

1. **最初は5個だけ** 完全に理解する（Strategy, Factory, Observer, Adapter, Decorator）
2. **既存のコードの中で見つける**（Reactのhooks、Node.jsのEventEmitterなど）
3. **「なぜこう書くか」を説明できる** ことを目標にする
4. **使いどころを間違えないように**（小さな問題に大きなパターンは不要）
