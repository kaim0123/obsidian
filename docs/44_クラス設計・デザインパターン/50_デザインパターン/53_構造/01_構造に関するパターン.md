# 構造に関するパターン（Structural Patterns）

## はじめに

オブジェクトを **どう組み合わせるか** を工夫するのが **構造に関するパターン** です。既存のクラスに機能を追加したり、違う形のAPIを繋いだり、複雑な仕組みに簡単な入口を作ったりするのに使います。

「小さな部品を **賢く組み合わせて** 大きな仕組みを作る」ためのパターン群です。

---

## GoFの構造パターン7種

| パターン | 目的 |
|---------|------|
| Adapter | 互換性のないAPIを繋ぐ |
| Bridge | 抽象と実装を別々に拡張 |
| Composite | ツリー構造を一様に扱う |
| Decorator | オブジェクトを包んで機能追加 |
| Facade | 複雑な仕組みに単純な窓口 |
| Flyweight | 共通部分を共有してメモリ節約 |
| Proxy | 本物の代理として振る舞う |

---

## 1. Adapter（アダプター）

### 何を解決するか

「使いたいライブラリがあるけど、インターフェースが合わない」問題。

### 使いどころ

- 古いAPIと新しいAPIを繋ぐ
- 外部ライブラリを自社の規約に合わせる
- 型の形が異なるオブジェクト同士を繋ぐ

### 例

```javascript
// 自社コードは renderJSON(data) を期待している
// しかし、使いたいライブラリは toXML() しか出せない

class XMLLibrary {
  toXML() { return '<data>...</data>'; }
}

// Adapter で JSON に見せかける
class XMLtoJSONAdapter {
  constructor(xmlLib) { this.xmlLib = xmlLib; }
  renderJSON() {
    const xml = this.xmlLib.toXML();
    return xmlToJson(xml); // 変換
  }
}
```

現実世界の **「電源プラグの変換アダプター」** そのままのイメージです。

## 2. Bridge（ブリッジ）

### 何を解決するか

「**抽象**（使う側）と **実装**（使われる側）が強く結びついていて、どちらも拡張しにくい」問題。

### 使いどころ

- 抽象階層と実装階層を **独立して拡張** したい
- クロスプラットフォーム実装を共通の抽象で使いたい

### 例: 図形 × 描画API

```typescript
// 実装側
interface Renderer {
  drawCircle(x: number, y: number, r: number): void;
}
class CanvasRenderer implements Renderer { /* ... */ }
class SVGRenderer implements Renderer { /* ... */ }

// 抽象側
class Shape {
  constructor(protected renderer: Renderer) {}
}
class Circle extends Shape {
  constructor(renderer: Renderer, private x: number, private y: number, private r: number) {
    super(renderer);
  }
  draw() { this.renderer.drawCircle(this.x, this.y, this.r); }
}

// 組み合わせ自由
new Circle(new CanvasRenderer(), 0, 0, 10).draw();
new Circle(new SVGRenderer(), 0, 0, 10).draw();
```

図形が増えても、描画方式が増えても、**片方だけに影響** します。

## 3. Composite（コンポジット）

### 何を解決するか

「**ツリー構造** を、葉（単体）も枝（集合）も **同じインターフェース** で扱いたい」問題。

### 使いどころ

- ファイルシステム（ファイル・フォルダ）
- GUI（ボタン・コンテナ）
- 組織階層

### 例

```javascript
class File {
  constructor(name, size) { this.name = name; this.size = size; }
  getSize() { return this.size; }
}

class Folder {
  constructor(name) { this.name = name; this.children = []; }
  add(child) { this.children.push(child); }
  getSize() {
    return this.children.reduce((sum, c) => sum + c.getSize(), 0);
  }
}

const root = new Folder('root');
root.add(new File('a.txt', 10));
const sub = new Folder('sub');
sub.add(new File('b.txt', 20));
root.add(sub);

console.log(root.getSize()); // 30 — FileとFolderを意識せず計算
```

## 4. Decorator（デコレーター）

### 何を解決するか

「**既存クラスを変更せずに、機能を追加** したい」問題。継承の代わりになる合成ベースの仕組み。

### 使いどころ

- ログを追加する
- キャッシュを追加する
- 認証チェックを追加する
- 入出力を圧縮・暗号化する

### 例

```javascript
class BasicCoffee {
  cost() { return 300; }
  describe() { return 'コーヒー'; }
}

class MilkDecorator {
  constructor(coffee) { this.coffee = coffee; }
  cost() { return this.coffee.cost() + 50; }
  describe() { return this.coffee.describe() + ' + ミルク'; }
}

class SugarDecorator {
  constructor(coffee) { this.coffee = coffee; }
  cost() { return this.coffee.cost() + 30; }
  describe() { return this.coffee.describe() + ' + 砂糖'; }
}

let coffee = new BasicCoffee();
coffee = new MilkDecorator(coffee);
coffee = new SugarDecorator(coffee);
console.log(coffee.describe(), coffee.cost()); // コーヒー + ミルク + 砂糖 380
```

継承ツリーを増やさずに、**必要な機能を積み重ね** られます。

## 5. Facade（ファサード）

### 何を解決するか

「**複雑なサブシステム** を使うとき、関連する多くのクラスを扱うのが大変」問題。

### 使いどころ

- ライブラリに対する **シンプルなラッパー** を作る
- 複数のAPIを呼ぶ一連の流れを1つにまとめる

### 例

```javascript
// 複雑なサブシステム
class VideoDecoder { /* ... */ }
class AudioMixer { /* ... */ }
class Subtitles { /* ... */ }
class Renderer { /* ... */ }

// Facade: 簡単な窓口
class VideoPlayer {
  play(file) {
    const video = new VideoDecoder().decode(file);
    const audio = new AudioMixer().mix(file);
    const subs = new Subtitles().load(file);
    new Renderer().render(video, audio, subs);
  }
}

new VideoPlayer().play('movie.mp4'); // 利用側はこれだけ
```

内部の複雑さを隠して、**簡単に使える入口** を提供するのがポイント。

## 6. Flyweight（フライウェイト）

### 何を解決するか

「**同じようなオブジェクトを大量に作ると、メモリが爆発** する」問題。

### 使いどころ

- テキストエディタの文字（フォント情報を共有）
- ゲームの大量の敵・弾
- アイコン・画像

### 例

```javascript
// 共有する部分（不変）
class CharacterStyle {
  constructor(font, size, color) {
    this.font = font;
    this.size = size;
    this.color = color;
  }
}

const styleCache = {};
function getStyle(font, size, color) {
  const key = `${font}-${size}-${color}`;
  if (!styleCache[key]) styleCache[key] = new CharacterStyle(font, size, color);
  return styleCache[key]; // 同じキーなら同じインスタンスを返す
}

// 固有の部分だけ個別に
class Character {
  constructor(char, style) {
    this.char = char;
    this.style = style;
  }
}
```

## 7. Proxy(プロキシ)

### 何を解決するか

「本物のオブジェクトへのアクセスを、**間に何か挟んで制御したい**」問題。

### 使いどころ

- 遅延読み込み（重い処理を後回し）
- アクセス制御（権限チェック）
- キャッシュ
- ログ

### 例: 画像の遅延読み込み

```javascript
class RealImage {
  constructor(filename) {
    this.filename = filename;
    this.load();
  }
  load() { console.log(`読み込み: ${this.filename}`); } // 重い
  display() { console.log(`表示: ${this.filename}`); }
}

class ImageProxy {
  constructor(filename) { this.filename = filename; }
  display() {
    if (!this.real) this.real = new RealImage(this.filename); // 本当に必要になってから
    this.real.display();
  }
}

const img = new ImageProxy('big.jpg'); // ここでは読み込まれない
img.display(); // 初回のみ読み込み発生
img.display(); // 2回目は再利用
```

## 構造パターンの使い分け

| 状況 | パターン |
|------|---------|
| 既存APIと合わない | Adapter |
| 抽象と実装を独立させたい | Bridge |
| ツリーを一様に扱う | Composite |
| 機能を積み重ねたい | Decorator |
| 複雑な仕組みをシンプルに見せる | Facade |
| 大量オブジェクトのメモリ節約 | Flyweight |
| アクセスに制御・遅延を入れたい | Proxy |
