# 振る舞いに関するパターン（Behavioral Patterns）

## はじめに

オブジェクト同士が **どうやってやり取りするか** を工夫するのが **振る舞いに関するパターン** です。

- アルゴリズムを差し替えたい
- 状態が変わったら他のオブジェクトに知らせたい
- 処理を次々と順番に渡したい

こうした「オブジェクト間の動き」に関わる問題を解きます。GoFの23パターンのうち11個（最多）を占めます。

---

## GoFの振る舞いパターン11種

| パターン | 目的 |
|---------|------|
| Chain of Responsibility | 処理をバケツリレー |
| Command | 操作をオブジェクト化 |
| Interpreter | 小さな言語の解釈 |
| Iterator | コレクションを順に辿る |
| Mediator | 仲介者を介して通信 |
| Memento | 状態の保存・復元 |
| Observer | 状態変化の通知 |
| State | 状態で振る舞いを変える |
| Strategy | アルゴリズムの差し替え |
| Template Method | 骨格は親、詳細は子 |
| Visitor | 構造を変えずに処理追加 |

この中でも特に使う **Strategy・Observer・Iterator・Command・State** を中心に解説します。

## 1. Strategy（戦略）

### 何を解決するか

「**アルゴリズムを実行時に切り替えたい**」問題。if/switchの代わりになる。

### 使いどころ

- ソート方法の切り替え
- 支払い方法の切り替え
- 圧縮アルゴリズムの切り替え
- 配送業者の切り替え

### 悪い例

```javascript
function calcFee(type, amount) {
  if (type === 'creditCard') return amount * 0.03;
  if (type === 'paypal') return amount * 0.05;
  if (type === 'bank') return 200;
}
```

### Strategyパターン

```typescript
interface FeeStrategy {
  calc(amount: number): number;
}
class CreditCardFee implements FeeStrategy {
  calc(amount) { return amount * 0.03; }
}
class PayPalFee implements FeeStrategy {
  calc(amount) { return amount * 0.05; }
}
class BankFee implements FeeStrategy {
  calc() { return 200; }
}

class Payment {
  constructor(private fee: FeeStrategy) {}
  total(amount: number) { return amount + this.fee.calc(amount); }
}

new Payment(new CreditCardFee()).total(1000);
```

**OCP（開放閉鎖の原則）** を実現する代表的なパターン。

## 2. Observer（観察者）

### 何を解決するか

「**状態が変わったら、関連する複数のオブジェクトに自動で通知したい**」問題。

### 使いどころ

- GUIイベント（クリック・入力）
- pub/sub
- リアクティブプログラミング（RxJS、Vue、React）

### 例

```javascript
class Subject {
  observers = [];
  subscribe(fn) { this.observers.push(fn); }
  unsubscribe(fn) {
    this.observers = this.observers.filter(o => o !== fn);
  }
  notify(data) {
    this.observers.forEach(fn => fn(data));
  }
}

const stock = new Subject();
stock.subscribe(price => console.log(`ログ: ${price}円`));
stock.subscribe(price => { if (price > 1000) console.log('売り時！'); });

stock.notify(950);  // ログ: 950円
stock.notify(1200); // ログ: 1200円 / 売り時！
```

JavaScript の `addEventListener` や Node.js の `EventEmitter` はこのパターンです。

## 3. Iterator（反復子）

### 何を解決するか

「コレクションの **内部構造を知らずに、要素を順番に取り出したい**」問題。

### 使いどころ

- 配列・リスト・ツリーを一様にループ
- 巨大なデータをストリーム処理

### 例

JavaScriptでは `Symbol.iterator` で実現されています。

```javascript
class Range {
  constructor(start, end) { this.start = start; this.end = end; }
  [Symbol.iterator]() {
    let i = this.start;
    const end = this.end;
    return {
      next() {
        return i <= end ? { value: i++, done: false } : { done: true };
      }
    };
  }
}

for (const n of new Range(1, 5)) console.log(n); // 1 2 3 4 5
```

## 4. Command（コマンド）

### 何を解決するか

「操作を **オブジェクトとして扱いたい**」問題。Undo・キュー・ログが作りやすくなる。

### 使いどころ

- Undo/Redo
- マクロ・バッチ実行
- ジョブキュー

### 例

```javascript
class AddCommand {
  constructor(editor, text) { this.editor = editor; this.text = text; }
  execute() { this.prev = this.editor.content; this.editor.content += this.text; }
  undo() { this.editor.content = this.prev; }
}

const editor = { content: '' };
const history = [];
function run(cmd) { cmd.execute(); history.push(cmd); }
function undo() { history.pop()?.undo(); }

run(new AddCommand(editor, 'Hello ')); // content: 'Hello '
run(new AddCommand(editor, 'World')); // content: 'Hello World'
undo();                                 // content: 'Hello '
```

## 5. State（状態）

### 何を解決するか

「**状態によって振る舞いが変わる** オブジェクトを、**if文の山にせずに** 実装したい」問題。

### 使いどころ

- ワークフロー（下書き→承認待ち→公開）
- ゲームのキャラ状態（通常・ダメージ・無敵）
- ネットワーク接続状態

### 例

```javascript
class DraftState {
  publish(doc) { doc.setState(new ReviewState()); }
}
class ReviewState {
  publish(doc) { doc.setState(new PublishedState()); }
}
class PublishedState {
  publish() { console.log('既に公開済み'); }
}

class Document {
  constructor() { this.state = new DraftState(); }
  setState(s) { this.state = s; }
  publish() { this.state.publish(this); }
}

const doc = new Document();
doc.publish(); // Draft → Review
doc.publish(); // Review → Published
doc.publish(); // 既に公開済み
```

## 6. Template Method（テンプレートメソッド）

### 何を解決するか

「**処理の大枠は同じ** だけど、**一部の手順だけ違う** 場合に、共通部分と差異を分離したい」問題。

### 例

```javascript
class Recipe {
  cook() {
    this.prepare();
    this.heat();
    this.serve();
  }
  prepare() { throw new Error('実装が必要'); }
  heat() { console.log('加熱'); }
  serve() { console.log('盛り付け'); }
}

class Ramen extends Recipe {
  prepare() { console.log('麺とスープ準備'); }
}
class Curry extends Recipe {
  prepare() { console.log('野菜とルウ準備'); }
}
```

## 7. Chain of Responsibility（責任の連鎖）

### 何を解決するか

「**複数のハンドラを順番に試して、誰かが処理するまで回す**」仕組み。

### 使いどころ

- Webフレームワークのミドルウェア（Express, Koa）
- ログフィルタ
- 認可チェーン

### 例（イメージ）

```javascript
app.use(authMiddleware);
app.use(logMiddleware);
app.use(router);
// 順に呼ばれ、next() で次へ
```

## 8. その他のパターン（簡単に）

### Mediator（仲介者）

オブジェクト同士が直接通信せず、**仲介者を介して通信** する。GUIのダイアログ内のコンポーネント制御に使う。

### Memento（記念品）

オブジェクトの状態を **外部に保存し、後で復元** する。Undoの実装補助。

### Visitor（ビジター）

データ構造を変えずに、**新しい処理を追加** する。ツリー・ASTの走査に便利。

### Interpreter（インタプリタ）

**小さな言語を定義して解釈** する。正規表現エンジンのようなものに近い。

## 振る舞いパターンの使い分け

| 状況 | パターン |
|------|---------|
| アルゴリズムを差し替えたい | Strategy |
| イベントで通知したい | Observer |
| コレクションを一様に辿りたい | Iterator |
| 操作をオブジェクト化して記録したい | Command |
| 状態で振る舞いを切り替えたい | State |
| 処理骨格を共通化、細部だけ変えたい | Template Method |
| 順番に処理者を試したい | Chain of Responsibility |
