# 生成に関するパターン（Creational Patterns）

## はじめに

オブジェクト指向では `new Foo()` でオブジェクトを作りますが、実はこの **作り方** を工夫することで、コードは格段に柔軟になります。

- 作るクラスを後から変更できる
- 複雑な組み立てを分かりやすくできる
- いつ・どのように作るかを制御できる

こうした「**どう作るか**」の問題を解くのが **生成に関するパターン** です。

---

## GoFの生成パターン5種

| パターン | 目的 |
|---------|------|
| Factory Method | どのクラスを作るかサブクラスに委ねる |
| Abstract Factory | 関連するオブジェクト群をまとめて作る |
| Builder | 段階的に複雑なオブジェクトを組み立てる |
| Prototype | 既存オブジェクトの複製を作る |
| Singleton | インスタンスを1つに制限する |

---

## 1. Factory Method（ファクトリーメソッド）

### 何を解決するか

「`new` を直接書くと、どのクラスを作るかがハードコードされて、変更しにくい」問題。

### 使いどころ

- 作るクラスを、条件によって切り替えたい
- 作り方のロジックをまとめたい
- テスト時に別のクラスを差し込みたい

### 例: 通知方法の切り替え

```javascript
// 悪い例
function notify(type, message) {
  if (type === 'email') new EmailNotifier().send(message);
  if (type === 'sms') new SMSNotifier().send(message);
}

// 良い例: Factory Method
class NotifierFactory {
  static create(type) {
    if (type === 'email') return new EmailNotifier();
    if (type === 'sms') return new SMSNotifier();
    if (type === 'slack') return new SlackNotifier();
    throw new Error('unknown');
  }
}

const notifier = NotifierFactory.create('email');
notifier.send('hello');
```

new Foo() を呼ぶ場所が **1カ所にまとまる** ので、新種追加が容易になります。

## 2. Abstract Factory（抽象ファクトリー）

### 何を解決するか

「**関連する複数のオブジェクト** をまとめて、一貫した組み合わせで作りたい」問題。

### 使いどころ

- UIテーマ（ダーク用・ライト用のボタン・フォームセット）
- OS別のGUI部品
- 環境別の依存セット（本番・開発・テスト）

### 例: テーマごとのUIパーツ

```typescript
interface UIFactory {
  createButton(): Button;
  createInput(): Input;
}

class DarkThemeFactory implements UIFactory {
  createButton() { return new DarkButton(); }
  createInput() { return new DarkInput(); }
}

class LightThemeFactory implements UIFactory {
  createButton() { return new LightButton(); }
  createInput() { return new LightInput(); }
}

function render(factory: UIFactory) {
  const btn = factory.createButton();
  const input = factory.createInput();
  // どちらも同じテーマで揃う
}
```

## 3. Builder（ビルダー）

### 何を解決するか

「コンストラクタの引数が多すぎて、何を渡しているか分からない」問題。

### 使いどころ

- 引数が多いオブジェクト
- 組み立て方が段階的
- 選択可能なオプションが多い

### 悪い例（引数の地獄）

```javascript
new Pizza('medium', true, false, true, true, false, 'thin', 'tomato', 3);
// 何が何だか分からない
```

### Builder パターン

```javascript
class PizzaBuilder {
  constructor() { this.pizza = { toppings: [] }; }
  size(s) { this.pizza.size = s; return this; }
  crust(c) { this.pizza.crust = c; return this; }
  sauce(s) { this.pizza.sauce = s; return this; }
  addTopping(t) { this.pizza.toppings.push(t); return this; }
  build() { return this.pizza; }
}

const pizza = new PizzaBuilder()
  .size('medium')
  .crust('thin')
  .sauce('tomato')
  .addTopping('cheese')
  .addTopping('basil')
  .build();
```

**メソッドチェーン** で直感的に書けます。名前付き引数が使える言語（Python, Kotlin）では、Builderを使わず名前付き引数で済むことも多いです。

## 4. Prototype（プロトタイプ）

### 何を解決するか

「**既存のオブジェクトを複製** したいが、`new` して1から設定するのが面倒」問題。

### 使いどころ

- オブジェクトの生成コストが高い
- ほとんど同じ設定のオブジェクトを大量に作る
- 現在の状態を保存・復元したい

### 例

```javascript
class Shape {
  constructor(type, color, x, y) {
    this.type = type;
    this.color = color;
    this.x = x;
    this.y = y;
  }
  clone() {
    return new Shape(this.type, this.color, this.x, this.y);
  }
}

const original = new Shape('circle', 'red', 10, 20);
const copy = original.clone();
copy.x = 50; // オリジナルには影響しない
```

JavaScript では `Object.assign({}, obj)` や `structuredClone(obj)` でも実現できます。

## 5. Singleton（シングルトン）

### 何を解決するか

「**アプリ全体で1つだけ** 存在するべきオブジェクトを、どこからアクセスしても同じにしたい」問題。

### 使いどころ

- 設定（Config）
- ロガー
- DB接続プール
- キャッシュ

### 例

```javascript
class Logger {
  static #instance;
  constructor() {
    if (Logger.#instance) return Logger.#instance;
    Logger.#instance = this;
    this.logs = [];
  }
  log(msg) { this.logs.push(msg); }
}

const a = new Logger();
const b = new Logger();
console.log(a === b); // true、同じインスタンス
```

### Singletonの注意点

**Singletonはアンチパターンと言われることも多い** パターンです。

- **グローバル状態** を生むのでテストが難しい
- **依存関係が見えなくなる**（どこから使われるか分からない）
- **並行処理で事故りやすい**

現代的には、Singletonを直接書かず、**DIコンテナに「スコープ: シングルトン」として登録** することが多いです。

---

## 生成パターンの使い分け

| 状況 | 選ぶパターン |
|------|-------------|
| クラスを条件で切り替えたい | Factory Method |
| 関連するオブジェクト群をまとめて作る | Abstract Factory |
| 引数が多くて分かりにくい | Builder |
| 既存オブジェクトを複製したい | Prototype |
| 1つだけ存在させたい | Singleton（慎重に） |
