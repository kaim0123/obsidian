# 開放閉鎖の原則（OCP）

> この章は「クラス設計でどう使うか」を扱います。原則そのものの説明は 48 の [[02_OCP (開放閉鎖の原則)]] を参照してください。

## この章の目的

**開放閉鎖の原則（OCP）** を学び、拡張しやすく変更に強いクラス設計を身につけます。  
条件分岐の肥大化回避、拡張点設計、Strategy との関係を押さえます。

---

## 1. 拡張に開き、変更に閉じるとは

OCP: ソフトウェアの実体は **拡張に対しては開いて** いるべきだが、**修正に対しては閉じて** いるべきである。

```text
  新機能追加 → 既存クラスを「書き換えず」拡張で対応
  バグ修正   → 必要なら既存を直す（これは閉じる対象）
```

「一度動いたコードに触らない」ではなく、**変化の種類ごとに触る場所を減らす** ことです。

---

## 2. 条件分岐の肥大化を避ける

支払い方法が増えるたびに `if` を足すのは OCP 違反の典型です。

```javascript
// 悪い例 — 追加のたびにこの関数を変更
function pay(method, amount) {
  if (method === 'CARD') { /* ... */ }
  else if (method === 'BANK') { /* ... */ }
  else if (method === 'PAYPAY') { /* ... */ }  // また変更
}
```

新しい支払いを足すたびに **同じ関数を修正** しています。

---

## 3. 拡張点の設計

**変わりやすい箇所** にインターフェースや抽象クラスを置き、そこを拡張点にします。

```javascript
class CardPayment { pay(amount) { /* */ } }
class BankPayment { pay(amount) { /* */ } }

function checkout(payment, amount) {
  payment.pay(amount);  // 新 Payment クラスを足すだけ
}
```

| 拡張点の例 | 変化 |
|-----------|------|
| `PaymentStrategy` | 支払い手段 |
| `TaxCalculator` | 税制・地域 |
| `DiscountPolicy` | 割引ルール |

---

## 4. Strategy パターンとの関係

**Strategy** は振る舞いをクラスに切り出し、実行時に差し替えるパターンです。OCP の定番実装です。

```text
  Checkout
      │
      └── uses → PaymentStrategy
                      ├── CardStrategy
                      ├── BankStrategy
                      └── PayPayStrategy（新規追加）
```

詳細は [[03_クラス設計でよく使うパターン]] を参照。

---

## 5. OCP の実践例

割引ルールが増えるシステム:

```javascript
interface Discount {
  apply(order): Money;
}
class MemberDiscount implements Discount { /* */ }
class SeasonalDiscount implements Discount { /* */ }

class PricingService {
  constructor(discounts) { this.discounts = discounts; }
  total(order) {
    return this.discounts.reduce((sum, d) => sum.add(d.apply(order)), order.subtotal());
  }
}
```

`PricingService` は新割引追加時に **変更しない**（割引クラスを足すだけ）。

---

## まとめ

- OCP = 拡張は追加、既存の修正を最小化
- `if/else` の列は拡張点 + 多態で置き換え
- Strategy が OCP の代表パターン
- 変わる軸ごとにインターフェースを切る
