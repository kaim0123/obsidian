# リスコフの置換原則（LSP）

> この章は「クラス設計でどう使うか」を扱います。原則そのものの説明は 48 の [[03_LSP (リスコフの置換原則)]] を参照してください。

## この章の目的

**リスコフの置換原則（LSP）** を学び、継承階層の契約を守る設計判断を身につけます。  
違反の典型例と、振る舞い継承の注意点を押さえます。

---

## 1. 子クラスは親の代わりになれる

LSP: **親型の変数に子型のオブジェクトを代入しても**、プログラムの正しさが保たれるべき。

```javascript
function printArea(shape) {
  console.log(shape.area());  // Rectangle でも Square でも動くべき
}
```

子が親の **期待する振る舞いを壊す** と LSP 違反です。

---

## 2. 継承階層の契約（Contract）

契約には次が含まれます。

| 要素 | 内容 |
|------|------|
| 事前条件 | 呼び出し前に満たすべき条件（子は緩めてよい） |
| 事後条件 | 呼び出し後に保証すること（子は強めてよい） |
| 不変条件 | 常に真であるべき性質 |

```text
  親: withdraw(amount) — 残高以上は引き出せない
  子: 無制限に引き出せる → 契約違反（LSP 破壊）
```

---

## 3. LSP 違反の典型例

### 正方形と長方形

```javascript
class Rectangle {
  setWidth(w) { this.width = w; }
  setHeight(h) { this.height = h; }
}
class Square extends Rectangle {
  setWidth(w) { this.width = this.height = w; }  // 長方形の契約を破る
}
```

`Rectangle` として使うと面積計算がおかしくなります。**継承ではなく別の型 + 共通インターフェース** が安全です。

### 例外の変更

親は返す、子は例外を投げる — 呼び出し側の想定を壊します。

---

## 4. 振る舞いの継承とデータの継承

| 種類 | リスク |
|------|--------|
| データ継承 | フィールドの意図しない共有 |
| 振る舞い継承 | メソッドのオーバーライドで契約破壊 |

**継承は実装の共有手段ではなく、契約の特化手段** と捉えます。  
コード再利用だけなら **合成** を選びます（[[02_継承と多態]]）。

---

## 5. LSP を守るための設計判断

- 子を親の型として **テストで置き換え** てみる
- 「is-a」が言語レベルだけでなく **振る舞いレベル** でも成り立つか確認
- 疑わしい継承は **インターフェース + 合成** に変更
- 深い階層はフラット化を検討

```javascript
interface Shape { area(): number; }
class Rectangle implements Shape { /* */ }
class Square implements Shape { /* */ }  // 継承しない
```

---

## まとめ

- LSP = 子は親の代わりに使える（契約を守る）
- 事前・事後条件・不変条件を意識
- 正方形/長方形、例外の変更が典型違反
- 再利用目的の継承は危険。合成を検討
