# アンチパターンとの見分け

## この章の目的

クラス設計でよくある **アンチパターン** を見分け、脱出の考え方を学びます。  
良いパターンとの対比で判断眼を養います。

---

## 1. 神クラス（God Object）

**神クラス** はシステムのあらゆる処理を抱えた巨大クラスです。

| 症状 | `Application`, `Manager`, `Util` が数千行 |
|------|------------------------------------------|
| 原因 | SRP 無視、とりあえず1か所に書く |
| 脱出 | 変更理由で Extract Class、[[01_単一責任の原則]] |

```text
  God Object
      │
      ├─→ 認証ブロックを抽出 → Authenticator
      ├─→ 注文ブロックを抽出 → OrderService
      └─→ 通知ブロックを抽出 → Notifier
```

一覧は [[010Programming/44_クラス設計・デザインパターン/90_付録/付録E_よくあるアンチパターン一覧|付録E_よくあるアンチパターン一覧]] を参照。

---

## 2. スパゲッティ継承

**深く絡み合った継承階層** で、オーバーライドと `super` が追えなくなる状態です。

| 症状 | 5層以上、兄弟クラスで挙動が矛盾 |
|------|-------------------------------|
| 脱出 | 合成 + インターフェース、階層のフラット化 |

```javascript
// 危険 — 各層で speak() を上書き
class A { speak() { return 'A'; } }
class B extends A { speak() { return super.speak() + 'B'; } }
// … さらに継続
```

[[03_リスコフの置換原則]] と [[02_継承と多態]] を復習。

---

## 3. 貧血モデル（Anemic Domain Model）

エンティティがデータだけで、**ロジックがサービスに偏る** 状態です。

```javascript
class Order { get lines() { return this._lines; } }
class OrderService {
  confirm(order) { /* ルールは全部ここ */ }
}
```

| 脱出 | ルールを `Order.confirm()` へ Move Method |
| 関連 | [[01_クラス分割の基本プロセス]] |

---

## 4. 魔法の数字・魔法の文字列クラス

定数がクラス内に散在し、意味が分からない状態です。

```javascript
if (order.status === 3) { /* 3 とは？ */ }
if (user.role === 'adm') { /*  typo しやすい */ }
```

| 脱出 | 値オブジェクト・列挙型・名前付き定数 |
|------|-----------------------------------|
| 例 | `OrderStatus.CONFIRMED`, `Role.ADMIN` |

---

## 5. アンチパターンからの脱出法

1. **名前で疑う** — `Manager`, `Util`, `Helper` の肥大
2. **テストで露呈** — モック地獄、セットアップが長い
3. **小さく切る** — Extract Class / Extract Interface
4. **振る舞いを移す** — Move Method で Expert に
5. **レビューで共有** — [[05_クラス設計レビューの実践]]

```text
  気づく → 原因を言語化 → 1つずつリファクタ → テストで守る
```

---

## まとめ

- 神クラス・スパゲッティ継承・貧血モデルが三大典型
- 魔法の数値は値オブジェクト・列挙で置き換え
- SRP・合成・ドメインへのロジック移動が脱出の鍵
- レビューとテストで早期発見
