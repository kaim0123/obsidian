# クラス間の関係

## この章の目的

クラス同士を **どうつなぐか** を学びます。  
関連・集約・コンポジション・依存の違いと、結合度・クラス図の表現を押さえます。

---

## 1. 関連（Association）— オブジェクト同士の参照

**関連** は、オブジェクトが別オブジェクトを **知っている・参照している** 関係です。

```javascript
class Order {
  constructor(customer) {
    this.customer = customer;  // Order → Customer
  }
}
```

| 多重度 | 意味 | 例 |
|--------|------|-----|
| 1 | ちょうど1つ | 注文は1顧客 |
| 0..1 | 0または1 | 任意の配送先 |
| 1..* | 1つ以上 | 注文は1つ以上の明細 |
| * | 0個以上 | 顧客は0個以上の注文 |

---

## 2. 集約（Aggregation）とコンポジション（Composition）

どちらも「全体と部分」ですが、**寿命と所有** が異なります。

| 種類 | 意味 | 例 |
|------|------|-----|
| **集約** | 部分は独立に存在しうる | 大学と教授 |
| **コンポジション** | 部分は全体の一部。全体と共に生死 | 注文と明細 |

```javascript
class Order {
  constructor() {
    this.lines = [];  // Order が消えれば Line も不要 → コンポジション
  }
}
```

```text
  集約:     ◇── 部分が別生命
  コンポジション: ◆── 部分は全体に従属
```

---

## 3. 依存（Dependency）— 一時的な利用

**依存** は、メソッドの引数・戻り値・ローカル変数として **一時的に使う** 関係です。  
関連より弱い「使ったことがある」関係です。

```javascript
class ReportGenerator {
  generate(orders) {  // Order に依存（引数として）
    return orders.map(o => o.total());
  }
}
```

依存が増えると変更の波及が起きやすいので、**インターフェース越し** にします。

---

## 4. 関係の選び方と結合度への影響

| 関係 | 結合の強さ | 使うとき |
|------|-----------|---------|
| 依存 | 弱〜中 | 一時利用・ユーティリティ |
| 関連 | 中 | 長期的な参照 |
| コンポジション | 強 | 部分が全体に従属 |

```text
  結合を弱くしたい → 依存 + インターフェース
  不変条件を守りたい → コンポジション + 集約ルート
```

[[04_クラスの凝集度と結合度]] の原則と組み合わせます。

---

## 5. クラス図で関係を表現する

```text
Customer "1" ──────< "*" Order
Order "1" ◆─────── "*" OrderLine
ReportGenerator ..> Order : uses
```

| 線 | 意味 |
|----|------|
| `──` | 関連 |
| `◆──` | コンポジション |
| `..>` | 依存 |
| `"1" *"` | 多重度 |

図は [[010Programming/44_クラス設計・デザインパターン/90_付録/付録F_参考図解]] のテンプレートを使ってください。

---

## まとめ

- 関連 = 持続的な参照、依存 = 一時的な利用
- コンポジションは部分の寿命を全体に束縛
- 関係の種類は結合度に直結
- クラス図でチームと共有する
