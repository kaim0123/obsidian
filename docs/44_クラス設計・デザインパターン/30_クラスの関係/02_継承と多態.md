# 継承と多態

## この章の目的

**継承** と **多態** をクラス設計の観点で学びます。  
is-a の判断、誤用の回避、合成を選ぶ場面まで押さえます。

---

## 1. 継承（Inheritance）とは何か

**継承** は、既存クラス（親）の性質を引き継ぎ、**拡張・特化** する仕組みです。

```javascript
class Animal {
  speak() { return '...'; }
}
class Dog extends Animal {
  speak() { return 'わん'; }
}
```

| 継承で得られるもの | 注意 |
|-------------------|------|
| コードの再利用 | 親の変更が子に波及 |
| 多態の基盤 | 階層が深くなると複雑 |

詳細は [[03_継承と合成]] を参照。

---

## 2. is-a 関係の判断

継承は **「子は親の一種である」**（is-a）ときだけ使います。

| 関係 | 継承？ | 理由 |
|------|--------|------|
| 犬は動物 | OK | 真の is-a |
| 正方形は長方形 | 注意 | 数学的には is-a だが振る舞いで破綻しうる |
| 車はエンジン | NG | has-a（持っている）→ 合成 |

```text
  is-a  → 継承を検討
  has-a → 合成（フィールドで持つ）
```

---

## 3. 多態（Polymorphism）の活用

**多態** は、同じインターフェースで **異なる実装** を扱うことです。

```javascript
class CreditCardPayment {
  pay(amount) { /* カード決済 */ }
}
class BankTransferPayment {
  pay(amount) { /* 振込 */ }
}

function checkout(payment, amount) {
  payment.pay(amount);  // 具象を知らない
}
```

継承だけでなく **インターフェース実装** でも多態は実現できます（[[04_多態とインターフェース]]）。

---

## 4. 継承の誤用と深い継承階層の問題

| アンチパターン | 問題 |
|---------------|------|
| 深い階層 | どの層に何があるか分からない |
| 継承 for 再利用だけ | 振る舞いが親に縛られる |
| テンプレートメソッド乱用 | フロー変更が困難 |

```text
  Animal
    └── Mammal
          └── Pet
                └── Dog
                      └── ServiceDog  ← 5層は要注意
```

**3層を超えたら設計を見直す** 目安にします。

---

## 5. 継承より合成（Composition）を選ぶ場面

**合成** は、クラスが別クラスを **フィールドとして持つ** 関係です。

```javascript
class Car {
  constructor(engine) {
    this.engine = engine;  // has-a
  }
  start() { this.engine.ignite(); }
}
```

| 合成を選ぶ理由 |
|---------------|
| 実行時に部品を差し替えたい |
| 複数の能力を組み合わせたい（Mixin 的） |
| 親子の契約（LSP）を守るのが難しい |

**「継承は白、合成は緑」**（継承より合成を優先）が現代の定石です。

---

## まとめ

- 継承は is-a のとき。has-a は合成
- 多態で条件分岐を減らし、拡張しやすくする
- 深い継承階層は避ける
- 迷ったら合成 + インターフェース
