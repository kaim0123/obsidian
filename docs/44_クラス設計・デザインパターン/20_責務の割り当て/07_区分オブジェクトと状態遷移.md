# 区分オブジェクトと状態遷移

## この章の目的

増田亨『現場で役立つシステム設計の原則』第2章の後半 — **区分ごとの場合分けをクラス／列挙に閉じ込める** 技法を学びます。

- 区分ごとのロジックを **別クラス** に分ける
- 区分クラスを **同じ型（インターフェース）** として扱う
- インスタンス生成と **列挙型（enum）** での整理
- **区分オブジェクト** で業務ロジックを分析する
- **状態遷移ルール** をわかりやすく記述する

前提のガード節・複文の分解は 46 の [[02_Guard_Clause]]・[[03_複雑度と分岐]]、多態の一般論は [[02_継承と多態]]・42 の [[04_多態とインターフェース]] を参照してください。

---

## 1. 区分ごとのロジックを別クラスに分ける

料金種別・顧客区分のように、区分ごとに判断・計算が違うとき、巨大な if / switch に書き続けると、区分追加のたびに既存メソッドを開くことになります。

```typescript
// 悪い例: 区分のたびに switch が増える
function fee(type: string): number {
  switch (type) {
    case "adult": return 1000;
    case "child": return 500;
    case "senior": return 700;
    default: throw new Error("unknown");
  }
}
```

区分ごとにクラスを切り、**その区分固有のロジックだけ** を中に置きます。

```typescript
class AdultFee {
  yen(): number { return 1000; }
}
class ChildFee {
  yen(): number { return 500; }
}
class SeniorFee {
  yen(): number { return 700; }
}
```

---

## 2. 区分ごとのクラスを同じ「型」として扱う

使う側が具象クラス名を知らなくてよいよう、**共通の型（インターフェース）** で扱います。これがポリモーフィズムによる条件分岐の置き換えです。

```typescript
interface Fee {
  yen(): number;
}

class AdultFee implements Fee {
  yen(): number { return 1000; }
}
class ChildFee implements Fee {
  yen(): number { return 500; }
}
class SeniorFee implements Fee {
  yen(): number { return 700; }
}

function charge(fee: Fee): number {
  return fee.yen(); // 区分の if はない
}
```

新しい区分は **新クラスを追加するだけ** で、`charge` は変更しません（OCP）。

---

## 3. 区分ごとのクラスのインスタンスを生成する

どこかで「どの区分か」を決めてインスタンスを作る必要があります。生成箇所は **1か所に寄せる**（ファクトリ／マップ）と、分岐の散らばりを防げます。

```typescript
type FeeCode = "adult" | "child" | "senior";

function createFee(code: FeeCode): Fee {
  switch (code) {
    case "adult": return new AdultFee();
    case "child": return new ChildFee();
    case "senior": return new SeniorFee();
  }
}
```

生成時の分岐は残りますが、**業務ルールの本体**（金額計算など）は各クラスに閉じ込めたままです。

---

## 4. 列挙型を使えばもっとかんたん

Java の enum は定数だけでなく **メソッド（振る舞い）** を持てます。TypeScript では `enum` より、**ユニオン＋オブジェクトマップ** や **クラスを static で列挙** する書き方が実務ではよく使われます。

```typescript
// 振る舞いを持つ区分（列挙風）
const FeeType = {
  Adult: {
    code: "adult" as const,
    yen(): number { return 1000; },
  },
  Child: {
    code: "child" as const,
    yen(): number { return 500; },
  },
  Senior: {
    code: "senior" as const,
    yen(): number { return 700; },
  },
} as const;

type FeeTypeKey = keyof typeof FeeType;

function charge(key: FeeTypeKey): number {
  return FeeType[key].yen();
}
```

言語の列挙の書き方は [[05_クラスの種類の整理]] の列挙型セクションも参照してください。

---

## 5. 区分オブジェクトで分析し整理する

**区分オブジェクト** とは、区分の定義と区分ごとの判断・加工・計算を、オブジェクト（クラスや振る舞い付き列挙）にまとめたものです。

| 効果 | 説明 |
|------|------|
| 置き場所が決まる | 「子供料金のルールはどこ？」→ `ChildFee` / `FeeType.Child` |
| 影響が閉じる | 子供料金だけ変えても他区分や呼び出し側を触らない |
| 重複 switch が減る | 同じ区分分岐があちこちにコピーされにくい |

値オブジェクト（金額そのもの）と組み合わせると、`yen(): Money` のように型でも安全になります（[[04_値オブジェクトと完全コンストラクタ]]）。

---

## 6. 状態の遷移ルールをわかりやすく記述する

ステータス（下書き→確定→出荷 など）も区分の一種です。許可される遷移を if の山にせず、**遷移表** や **状態ごとの型／オブジェクト** で表します。

```typescript
type OrderStatus = "draft" | "confirmed" | "shipped" | "cancelled";

const ALLOWED: Record<OrderStatus, readonly OrderStatus[]> = {
  draft: ["confirmed", "cancelled"],
  confirmed: ["shipped", "cancelled"],
  shipped: [],
  cancelled: [],
};

function canTransit(from: OrderStatus, to: OrderStatus): boolean {
  return ALLOWED[from].includes(to);
}

function transit(from: OrderStatus, to: OrderStatus): OrderStatus {
  if (!canTransit(from, to)) {
    throw new Error(`${from} から ${to} へは遷移できません`);
  }
  return to;
}
```

関数型寄りの整理（状態ごとに型を分ける）は 42 の [[03_型でドメインを表す_DomainModelingMadeFunctional]] を参照してください。テスト観点の状態遷移は [[10_状態推移テスト]] です。

---

## まとめ

- 区分 if / switch は **クラス（または振る舞い付き列挙）** に閉じ込める
- 共通インターフェースで扱い、生成の分岐はファクトリに寄せる
- **区分オブジェクト** = 区分定義＋区分ごとの業務ロジック
- 状態遷移は **許可表や状態型** で一目でわかるようにする
