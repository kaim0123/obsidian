# クラスのカプセル化と情報隠蔽

## この章の目的

良いクラス設計の第一歩である **カプセル化** と **情報隠蔽** を学びます。  
アクセス制御、不変条件、getter/setter の落とし穴まで押さえます。

---

## 1. カプセル化の目的

**カプセル化** とは、データとそれを扱う処理をまとめ、**内部を隠して公開操作だけを提供する** ことです。

| 目的 | 効果 |
|------|------|
| 整合性の保護 | 不正な状態変更を防ぐ |
| 変更の局所化 | 内部実装を変えても外部に影響しにくい |
| 意図の明確化 | 「使ってよい操作」がはっきりする |

[[02_クラスとオブジェクト]] の銀行口座の例が典型です。残高は直接触らせず、`deposit` / `withdraw` 経由にします。

---

## 2. public / private / protected の考え方

言語によって記法は異なりますが、考え方は共通です。

| 修飾 | 誰がアクセスできるか | 設計上の意味 |
|------|---------------------|-------------|
| **private** | クラス内部のみ | 実装の詳細。自由に変更してよい |
| **protected** | クラスとサブクラス | 継承を前提とした拡張点 |
| **public** | 誰でも | クラスの **契約（API）** |

```javascript
class Order {
  #lines = [];           // private
  addLine(line) { /* */ } // public — 外部が使う入口
}
```

**デフォルトは private、必要なものだけ public** が基本です。

---

## 3. 不変条件（Invariant）をクラス内に閉じ込める

**不変条件** とは、オブジェクトが常に満たすべきルールです。

- 注文の合計は 0 未満にならない
- 口座残高は負にならない
- 生年月日は未来日にならない

```javascript
class OrderLine {
  constructor(product, quantity) {
    if (quantity <= 0) throw new Error('数量は正の数');
    this.quantity = quantity;
    this.product = product;
  }
}
```

不変条件は **クラスの境界内** で守ります。外からフィールドを直接いじられると、ルールが破られます。

---

## 4. 情報隠蔽（Parnas）— 設計判断ごとに隠す

David Parnas の **情報隠蔽** は、「データを隠す」だけでなく **変わりやすい設計判断を隠す** 考え方です。

| 隠すべきもの | 例 |
|-------------|-----|
| データ構造 | リストか配列か |
| アルゴリズム | 税計算の詳細 |
| 外部システム | DB・API の呼び方 |

```text
  外部 ──→ Order.total() ──→ [内部で税計算・丸め]
                ↑
           詳細は見えない
```

[[MOC_モジュール設計体系]] のカプセル化と同じ原則が、クラスレベルで適用されます。

---

## 5. getter/setter だけのカプセル化の落とし穴

全フィールドに getter/setter を機械的につけると、**ただの公開フィールド** と変わりません。

```javascript
// 悪い例 — カプセル化のつもりが意味がない
class User {
  getEmail() { return this.email; }
  setEmail(e) { this.email = e; }  // 検証なし
}
```

| 問題 | 対策 |
|------|------|
| 検証がない setter | ビジネスルールをメソッドに書く |
| 内部構造の露出 | コレクションは防御的コピー・不変ビュー |
| 過剰な公開 | 「外に何が必要か」から逆算する |

**「隠す」と「公開する」を意図的に設計する** ことがカプセル化の本質です。

---

## まとめ

- カプセル化は整合性・変更耐性・意図の明確化のため
- private を基本に、public は契約として最小限に
- 不変条件はクラス内で守る
- 情報隠蔽は変わりやすい設計判断ごと隠す
- getter/setter だけでは不十分。意味のある操作を公開する
