# クラスの凝集度と結合度

## この章の目的

クラス設計の物差しとして **凝集度** と **結合度** を学びます。  
42 の [[05_凝集度と結合度]] をクラス単位に当てはめ、デメテルの法則とチェックリストまで押さえます。

---

## 1. クラスの凝集度とは何か

**凝集度** は、1 つのクラスの要素が **1 つの目的にどれだけまとまっているか** を表します。

| 凝集度 | 状態 | 例 |
|--------|------|-----|
| 高い | 関連する状態と振る舞いだけ | `Order` に注文関連のみ |
| 低い | 無関係な責務が混在 | `UserManager` に認証・メール・レポート |

```text
  高凝集の Order          低凝集の MiscService
  ─────────────          ──────────────────
  ・明細管理               ・ユーザー認証
  ・合計計算               ・PDF 生成
  ・キャンセル             ・在庫更新
```

**凝集度は高いほどよい** とされます。

---

## 2. 凝集度が低いクラスの典型例

| パターン | 症状 | 対策 |
|---------|------|------|
| God Class | 何でもやる巨大クラス | 責務で分割 |
| Utils 肥大化 | 無関係な静的メソッドの集積 | ドメインごとに分離 |
| Feature Envy | 他クラスのデータを多用 | メソッドの移動（Move Method） |

```javascript
// 凝集度が低い — 注文とメールが同居
class OrderService {
  createOrder() { /* ... */ }
  sendConfirmationEmail() { /* ... */ }
  generateMonthlyReport() { /* ... */ }
}
```

メールは `EmailNotifier`、レポートは `ReportGenerator` へ分けると凝集度が上がります。

---

## 3. クラス間の結合度とは何か

**結合度** は、クラス同士が **どれだけ強く依存し合っているか** です。

| 結合度 | 例 | 問題 |
|--------|-----|------|
| 低い | インターフェース経由 | 差し替え・テストが容易 |
| 高い | 具象クラス・内部フィールド直接参照 | 変更が連鎖 |

```javascript
// 結合度が高い
class OrderService {
  constructor() {
    this.db = new MySqlConnection(); // 具象に依存
  }
}

// 結合度が低い
class OrderService {
  constructor(repository) { // 抽象に依存
    this.repository = repository;
  }
}
```

---

## 4. 知り合いの知り合いと話さない（デメテルの法則）

**デメテルの法則**（Law of Demeter）: オブジェクトは、自分・自分の部品・自分が作ったオブジェクト・引数のオブジェクト以外に **直接メッセージを送らない**。

```javascript
// 悪い例 — チェーン呼び出し（結合度が高い）
const city = order.getCustomer().getAddress().getCity();

// 良い例 — Order に委譲
const city = order.shippingCity();
```

```text
  Client → Order → Customer → Address  （NG: Client が Address まで知る）
  Client → Order.shippingCity()       （OK: Order が仲介）
```

## 5. クラス設計のチェックリスト

- [ ] クラスの要素は **1 つの責務** に関連しているか
- [ ] `Manager` / `Util` に無関係な処理が溜まっていないか
- [ ] 依存は **インターフェース** 経由か
- [ ] **メソッドチェーン**（`a.b().c().d()`）が多すぎないか
- [ ] 変更時に触るクラス数は妥当か

モジュールレベルの詳細は [[MOC_モジュール設計体系]]、メソッドレベルは [[010Programming/46_メソッド設計/00_全体像/目次|46_メソッド設計/目次]] を参照。

---

## まとめ

- **凝集度** = クラス内のまとまり（高いほどよい）
- **結合度** = クラス間の依存（低いほどよい）
- デメテルの法則で「知りすぎ」を防ぐ
- チェックリストで設計レビューに使う
