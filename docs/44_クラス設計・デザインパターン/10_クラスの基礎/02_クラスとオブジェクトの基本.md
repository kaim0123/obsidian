# クラスとオブジェクトの基本

## この章の目的

クラス設計の土台となる **クラス・オブジェクト・状態・振る舞い・メッセージ** を整理します。  
クラス図の読み方の入門も押さえ、以降の章で使う用語を揃えます。

---

## 1. クラスとは何か（設計図としての型）

**クラス** はオブジェクトの **設計図（型）** です。  
どんな状態を持ち、どんな振る舞いができるかを定義します。

```javascript
class Order {
  constructor(id) {
    this.id = id;
    this.lines = [];
  }
  addLine(product, quantity) { /* ... */ }
  total() { /* ... */ }
}
```

クラスは **実体ではなく定義** です。同じ設計図から何個でもオブジェクトを作れます。  
詳細な解説は [[02_クラスとオブジェクト]] を参照。

---

## 2. オブジェクトとは何か（インスタンス）

**オブジェクト**（インスタンス）は、クラスから作られた **実体** です。

```javascript
const order1 = new Order('ORD-001');
const order2 = new Order('ORD-002');
```

`order1` と `order2` は別オブジェクトですが、同じ `Order` クラスの振る舞いを持ちます。

| 用語 | 意味 |
|------|------|
| インスタンス化 | クラスからオブジェクトを作ること |
| インスタンス | 作られたオブジェクトそのもの |

---

## 3. 状態（フィールド）と振る舞い（メソッド）

オブジェクトは **状態** と **振る舞い** の組み合わせです。

| 要素 | 役割 | 例 |
|------|------|-----|
| フィールド（状態） | オブジェクトが覚えているデータ | `id`, `lines` |
| メソッド（振る舞い） | オブジェクトができること | `addLine()`, `total()` |

```text
  Order オブジェクト
  ┌─────────────────┐
  │ 状態: id, lines │
  │ 振る舞い:       │
  │   addLine()     │
  │   total()       │
  └─────────────────┘
```

クラス設計では「**このデータは誰が変更してよいか**」「**この処理はどのクラスに置くか**」を決めます。

---

## 4. メッセージと協調（オブジェクト同士のやりとり）

オブジェクトは **メッセージ**（メソッド呼び出し）で協調します。  
呼び出し側は相手の **内部実装を知らず**、公開された振る舞いだけを使います。

```javascript
const order = new Order('ORD-001');
const price = catalog.priceOf(product);  // Catalog に問い合わせ
order.addLine(product, 2);               // Order に依頼
const total = order.total();             // Order に問い合わせ
```

```text
  Client ──total()──→ Order
  Order  ──priceOf()──→ Catalog
```

「知り合いの知り合いと直接話さない」原則（デメテルの法則）は [[04_クラスの凝集度と結合度]] で詳述します。

---

## 5. クラス図の読み方（入門）

UML のクラス図は、クラスと関係を視覚化します。

```text
┌─────────────┐         ┌─────────────┐
│   Order     │────────>│  OrderLine  │
├─────────────┤  1..*   ├─────────────┤
│ - id        │         │ - quantity  │
│ + addLine() │         │ + subtotal()│
│ + total()   │         └─────────────┘
└─────────────┘
```

| 記号 | 意味 |
|------|------|
| `-` | private（内部用） |
| `+` | public（外部から使える） |
| `──>` | 関連（参照関係） |
| `1..*` | 1 対多 |

図は完璧を目指さず、**議論と設計のたたき台** として使います。詳細は [[010Programming/44_クラス設計・デザインパターン/90_付録/付録F_参考図解]] を参照。

---

## まとめ

- **クラス** = 設計図、**オブジェクト** = 実体（インスタンス）
- 状態（フィールド）と振る舞い（メソッド）をひとまとめにする
- オブジェクトはメッセージで協調し、内部詳細を隠す
- クラス図は関係を共有するための道具
