# Object Calisthenics で OO を体得する

> - 本番コードへの永久適用ではなく、癖を入れ替える筋トレであること
> - vault 内の関連技法への対応

---

## 1. なぜ過激な規則か

OO の説明を聞いても、else だらけ・プリミティブ多用・巨大クラスの書き癖は残りやすいです。**意図的に極端な制約**を短期間課すと、別の設計（小さなオブジェクト・Tell Don't Ask・値オブジェクト）へ手が動くようになります。

本番に9つ全部を永遠に適用する必要はありません。学習・スパイク・勉強会向けです。

---

## 2. 9つの規則

| # | 規則（意訳） | 意図・vault での続き |
|---|--------------|----------------------|
| 1 | **メソッドのインデントは1段まで** | ネストをやめ、早期 return・抽出へ（[[02_Guard_Clause]]・[[04_Extract_Method]]） |
| 2 | **else を使わない** | 分岐の結びつきを弱める（[[02_Guard_Clause]]・[[07_区分オブジェクトと状態遷移]]） |
| 3 | **プリミティブと文字列を包む** | 値オブジェクト（[[04_値オブジェクトと完全コンストラクタ]]） |
| 4 | **ファーストクラスコレクション** | コレクション専用クラス（[[06_オブジェクトの種類の整理]]） |
| 5 | **1行にドットは1つ** | デメテル／メッセージの連鎖を避ける（[[02_デメテルの法則]]・Tell Don't Ask） |
| 6 | **略語を使わない** | 名前で意図を伝える（[[03_命名とクラス構成]]） |
| 7 | **エンティティを小さく保つ** | クラス・パッケージを小さく（[[01_サイズと抽象度]]・[[04_クラスの凝集度と結合度]]） |
| 8 | **インスタンス変数は2つまで** | 関心事を分割し巨大クラスを防ぐ |
| 9 | **getter／setter を安易に置かない** | データクラス化を避け、振る舞いに閉じる（[[05_Tell_Dont_Askと貧血モデルの回避]]） |

> [!tip] 使い方
> 「全部守れ」より、今の臭いが強い規則を **1〜2個だけ** 2週間試す、でも十分な筋トレになります。

---

## 3. 増田本とのつながり

| Calisthenics | 増田本・既存ノートで既に扱っていること |
|--------------|----------------------------------------|
| 3・4 | 値オブジェクト・コレクションオブジェクト（第1〜2章系） |
| 2・区分 | else を消し区分オブジェクトへ（第2章） |
| 9 | データとロジックの一体・貧血回避（第3章） |
| 全体 | 小さくまとめ、組み立てやすくする |

学びの進め方（既存コード改善 → 体得 → 書籍）は [[06_オブジェクト指向設計の学び方]]。チームへの導入は [[06_オブジェクト指向設計の教え方]]。

---

## まとめ

- Object Calisthenics は OO らしい書き方を体に入れるための過激な制約  
- 本番の絶対ルールではなく、期間限定のエクササイズ  
- 各規則は値オブジェクト・ガード節・Tell Don't Ask・小さなクラスとつながる
