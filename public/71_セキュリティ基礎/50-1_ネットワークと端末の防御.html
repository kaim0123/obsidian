    50 運用・監視・インシデント

    ネットワークと端末の防御

    データはどうやって届き、その通り道のどこに「門番」を置けば守れるのか。このページでは、ファイアウォール・IDS/IPS・WAF の役割と配置、DDoS 対策、VPN や HTTPS による通信の暗号化、メールのなりすまし対策、そして PC やサーバーそのもの（エンドポイント）を守る技術までを、1枚の地図として整理します。

    もとにしたノート：50_運用・監視・インシデント/01_ネットワーク・アプリ・エンドポイントの防御（知識地図4章）、02_ネットワークセキュリティ（基礎講座第4回）

    ひとことで言うと

    守りは「1枚の壁」ではなく 何枚も重ねた関所 です。入口で通信を選別する ファイアウォール、怪しい動きを見張る IDS/IPS、Web アプリへの攻撃を見抜く WAF、通り道を暗号化する VPN・HTTPS、そして突破されたときの最後の砦として 端末（エンドポイント）側の EDR・パッチ・バックアップ を組み合わせます。

    1.まず知っておきたい「データの届き方」

    ネットワークの守りを理解するには、データがどんな形で、何を目印に届くのか を知っておく必要があります。宅配便にたとえると分かりやすくなります。

    パケット＝荷物

    ネットワークを流れるデータの小さな塊。中身のほかに「送り主・宛先・ポート番号」などの伝票が付いています。

    IP アドレス＝住所

    どのコンピュータ宛てかを示す番号（例：192.168.1.1）。建物の住所にあたります。

    ポート番号＝部屋番号

    同じコンピュータの中で どのアプリ宛てか を示す番号（0〜65535）。同じ建物でも部屋が違えば届け先が違います。

    1.1 よく使うポート番号

    ポートサービスひとこと
    22SSHサーバーへのリモート接続（暗号化あり）
    25SMTPメール送信
    80HTTPWeb サイト（暗号化なし）
    443HTTPSWeb サイト（暗号化あり）
    3306 / 5432MySQL / PostgreSQLデータベース。外部に公開してはいけない 代表例
    3389RDPWindows のリモートデスクトップ。狙われやすい

    攻撃者は ポートスキャン（どの部屋のドアが開いているかを片っ端から叩いて調べる行為）で、動いているサービスを探します。だから「使わないポートは閉じる」が守りの基本になります。

    1.2 TCP/IP の主なプロトコル

    プロトコル とは通信の「お約束（手順や形式のルール）」のことです。インターネットの事実上の標準は TCP/IP と呼ばれるプロトコル群です。

    プロトコル層役割例
    IPネットワーク層パケットに宛先の IP アドレスを付けて届ける192.168.1.1
    TCPトランスポート層届いたかを確認し、順番も保証する「書留」のような通信Web（HTTPS）、メール
    UDPトランスポート層確認なしで速い「普通郵便」のような通信動画配信、DNS
    ICMPネットワーク層エラー通知や疎通確認ping コマンド

    1.3 OSI 参照モデルと「どの層で守るか」

    通信を 7つの層 に分けて考える枠組みが OSI 参照モデル です。セキュリティの会話では「L3（ネットワーク層）〜 L7（アプリケーション層）」という言い方がよく出てきます。どの層を見る装置かで、防げる攻撃が変わります。

    層名前主な機能TCP/IP での例セキュリティ対策の例
    7アプリケーションWeb・メールなどHTTP, SMTPWAF、入力検証
    6プレゼンテーションデータ形式の変換TLS（ここに置く説明もある）暗号化
    5セッション通信の確立・維持—セッション管理
    4トランスポート端から端までの通信TCP, UDPポート制御
    3ネットワーク経路選択（ルーティング）IPファイアウォール、VPN
    2データリンク同じネットワーク内の通信EthernetMAC フィルタ
    1物理ケーブル・電波—物理的な入室管理

    2.守りの配置図 — 何がどこを守っているか

    個々の装置を学ぶ前に、全体の配置を見ておきましょう。インターネットから社内の大事なデータベースまで、通信は いくつもの関所 を通り抜けます。お城でいえば、堀・城門・見張り櫓・本丸の門と、内側に行くほど守りが固くなる構造です。

    ポイントは3つです。

    • 外側の装置ほど大雑把で速く、内側ほど細かく重い。DDoS 対策やファイアウォールが「量」と「宛先」でふるい落とし、WAF が HTTP の「中身」まで調べます。
    • IDS は通り道の横 で通信のコピーを見張るだけ、IPS は通り道の上 に置いて実際に止めます（3章）。
    • 公開するサーバー（Web・メール）と、絶対に公開しないサーバー（DB）を別ゾーンに分ける。この中間地帯が DMZ です（2.3）。

    3.ファイアウォール — 城の門番

    ファイアウォール（FW） は、ネットワークの入口・出口で通信を見張り、許可された通信だけを通す 仕組みです。お城の門番のように「通っていいもの」と「止めるもの」を、主に IP アドレス・ポート番号・プロトコル で判断します。

    3.1 4つのタイプ

    タイプ見る層しくみ長所短所
    パケットフィルタリング型L3/L4IP・ポート・プロトコルごとに許可／拒否速い・シンプルパケットの中身は見ない
    ステートフルインスペクション型L3/L4通信の「状態（今つながっている会話か）」も記憶して判断不正なパケットを弾きやすい。現在もっとも広く使われるアプリの中身は見ない
    アプリケーション型（プロキシ型）L7HTTP などの中身まで検査細かい制御ができる処理が重い
    次世代ファイアウォール（NGFW）L3〜L7アプリの識別（「これは Zoom」）、ユーザー ID 連携、TLS を復号しての検査、IPS 機能内蔵、マルウェア検知1台で多機能高価・設定が複雑になりやすい

    NGFW の代表的な製品には Palo Alto Networks、Cisco Firepower、Fortinet、Check Point などがあります。

    3.2 ルールの書き方の例

    パケットフィルタリングのルールは「上から順に照らし合わせ、最後に それ以外はすべて拒否」と書くのが基本です。

    ○ 必要なものだけ許可し、最後に全拒否 
    送信元：どこでも → 宛先ポート 443  → 許可（HTTPS）
送信元：どこでも → 宛先ポート 80   → 許可（HTTP）
送信元：どこでも → 宛先ポート 3306 → 拒否（DB を外部に公開しない）
上記以外                          → すべて拒否

    ステートフル型なら「内側から始めた HTTPS 接続への返事だけ を自動で通す」ことができます。返り道のルールを手で書かなくてよいので、設定ミスが減り安全性も上がります。外から突然届いた「返事のふりをしたパケット」は拒否されます。

    3.3 DMZ — 「見せてよい部屋」と「金庫」を分ける

    DMZ（DeMilitarized Zone、非武装地帯） は、インターネットと社内ネットワークの 中間に置く特別なネットワーク です。銀行にたとえると、DMZ は誰でも入れる「窓口ロビー」、内部ネットワークは「金庫室」です。

    • Web サーバーやメールサーバーは、インターネットに公開しないと仕事になりません → DMZ に置く
    • DB サーバーは 絶対に公開してはいけない → 内部ネットワークに置き、内部ファイアウォールの奥で守る
    • もし DMZ の Web サーバーが乗っ取られても、内部ファイアウォールがもう一枚の壁になる

    AWS などのクラウドでも、公開用サブネットと非公開サブネットを分けるという同じ考え方が使われます。

    4.IDS・IPS — 見張り番と自動シャッター

    ファイアウォールは「どこ宛てか」で判断しますが、正規のポート（443 など）を通ってくる攻撃は見抜けません。そこで 通信の流れの中に怪しいパターンがないか を調べるのが IDS・IPS です。

    IDS（Intrusion Detection System：侵入検知システム）

    • 不審な通信を 検知して警告する（通信そのものは止めない）
    • たとえるなら 火災報知器、または防犯カメラ＋警報
    • 通信の コピー を受け取って監視する。通り道に置かなくてよい

    IPS（Intrusion Prevention System：侵入防止システム）

    • 不審な通信を 検知してブロックする
    • たとえるなら 自動消火設備、または防犯カメラ＋自動シャッター
    • 通り道の上に置く（インライン配置）。全通信を通過させて検査する

    4.1 怪しさを見抜く2つの方式

    方式しくみ得意苦手
    シグネチャ型（ルールベース）既知の攻撃パターン（シグネチャ＝指名手配写真）と照合する。例：「この文字列パターンは SQL インジェクション」既知の攻撃を確実に見つけるゼロデイ攻撃（まだ対策が知られていない新手の攻撃）には無力
    アノマリ型（異常検知）「いつもの通信」を学習し、そこから外れたものを怪しむ。例：いつも日本からログインする人が突然海外から未知の攻撃にも反応できる誤検知（正常な通信を攻撃と見なす）が多い

    よくある誤解：「IPS を入れれば IDS はいらない？」

    IPS は止められる反面、誤検知すると正常な業務通信まで止めてしまう リスクがあります。そのため、誤検知が心配なルールは IDS（警告だけ）で様子を見る、という使い分けもされます。検知結果をどう集めて分析するかは セキュリティ監視とツール で扱います。

    5.WAF — Web アプリ専用の検査官

    通常のファイアウォールは「443 番（HTTPS）は許可」と判断した時点で、その中身はノーチェックで通します。ところが SQL インジェクションや XSS などの Web アプリへの攻撃は、正規の HTTPS 通信の中身に紛れてやってきます。

    WAF（Web Application Firewall） は、HTTP リクエストの 中身（URL・パラメータ・ヘッダーなど） まで調べて、Web アプリ特有の攻撃をブロックする L7 の装置です。空港でいえば、ファイアウォールが「搭乗券の行き先チェック」、WAF が「手荷物の X 線検査」です。

    WAF が検知・ブロックする主な攻撃

    • SQL インジェクション
    • XSS（クロスサイトスクリプティング）
    • CSRF
    • ディレクトリトラバーサル
    • SSRF
    • 不審なボット・スクレイピング
    • DDoS 攻撃の一部（アプリ層）

    WAF の3つの提供形態

    • クラウド型：DNS の向き先を変えるだけで導入しやすい（Cloudflare、AWS WAF など）
    • アプライアンス型：専用機器をネットワークに設置（Fortinet、Imperva など）
    • ソフトウェア型：サーバーにソフトを入れる（ModSecurity など）

    5.1 例：AWS WAF でできること

    1. IP アドレスのブロック：特定の IP や国からのアクセスを拒否する
    2. マネージドルール：AWS が用意した攻撃パターン（SQL インジェクション対策、XSS 対策、既知の悪意ある IP リストなど）をまとめて適用する
    3. レートリミット：同じ IP からの大量リクエストを止める（DDoS 対策）
    4. カスタムルール：「この URL は日本の IP からだけ許可」など独自ルールを追加する

    WAF は「後付けの盾」であって、アプリの修正の代わりではない

    WAF はパターンで見抜くため、すり抜ける攻撃もあります。SQL インジェクションや XSS は、まずアプリ側（プレースホルダ、エスケープ）で根本的に防ぎ、WAF はその外側にもう一枚重ねる 多層防御 の一層と考えます。詳しくは インジェクションと暗号化の不備、72_Web脆弱性対策 で。

    5.2 FW・IDS/IPS・WAF の比較

    装置見るもの動作守るものたとえ
    ファイアウォールIP・ポート・プロトコル（L3/L4）許可／拒否ネットワーク全体城門の門番
    IDS通信の流れのパターン検知して警告ネットワーク全体火災報知器
    IPS通信の流れのパターン検知して遮断ネットワーク全体自動消火設備
    WAFHTTP の中身（L7）検知して遮断Web アプリ手荷物検査

    6.DDoS 攻撃と CDN — 「数の暴力」から可用性を守る

    DoS（Denial of Service）攻撃 は、大量のリクエストを送りつけてサービスを止める攻撃です。DDoS（Distributed DoS） は、それを 乗っ取った大量の PC（ボット）から一斉に 行うものです。お店の入口に何万人ものサクラが押し寄せ、本当のお客さんが入れなくなる状態をイメージしてください。ボットにされた PC の持ち主は、多くの場合気づいていません。CIA 三原則でいえば 可用性 への攻撃です（CIA三原則）。

    種類狙い例主な対策
    ボリューム型回線（帯域）を大量のパケットで埋めるUDP フラッド、ICMP フラッドクラウド型 DDoS 対策、CDN で吸収
    プロトコル型TCP の仕組みを悪用してサーバーの資源を枯らすSYN フラッド：接続の開始だけ大量に送り、完了させずに「接続待ち」で詰まらせるDDoS 対策サービス、FW
    アプリケーション型少ない通信で重い処理を起こさせるHTTP フラッド、SlowlorisWAF、レートリミット

    ノートには、2023年に ChatGPT が DDoS 攻撃で数時間停止した例や、Google Cloud が 2.54Tbps 規模の攻撃を防いだと公表した例が挙げられています。

    6.1 DDoS への対策

    • クラウド型 DDoS 対策サービス（もっとも効果的）：AWS Shield（Standard は無料で一般的な DDoS を自動防御、Advanced は有料で大規模攻撃とサポート付き）、Cloudflare（DNS を経由させるだけで保護）
    • CDN（Content Delivery Network）：コンテンツを世界各地のサーバー（エッジ）にコピーして配る仕組み。本来は高速化のためですが、攻撃をエッジで吸収し、本番サーバー（オリジン）への直撃を減らす 効果があります。WAF 機能を持つものも多い（Cloudflare、Akamai、AWS CloudFront など）
    • レートリミット：同じ IP からの大量リクエストを制限
    • IP ブロックリスト：既知の攻撃元 IP を拒否
    • Anycast ルーティング：同じ宛先を世界中の拠点で受け、攻撃を分散させる

    7.通り道を暗号化する — VPN・HTTPS・Wi-Fi

    ネットワークの途中では、通信を 盗み見（盗聴） されたり 書き換え（改ざん） られたりする危険があります。中身が見えない封筒に入れて送るのが暗号化です。

    7.1 VPN — インターネット上の「専用トンネル」

    VPN（Virtual Private Network） は、インターネットの上に 暗号化されたトンネル（仮想の専用線） を作る技術です。

    • リモートアクセス VPN：在宅・外出先の端末から社内ネットワークへ安全につなぐ（端末 → 暗号化トンネル → VPN サーバー → 社内）
    • サイト間 VPN：本社と支社など、拠点同士をインターネット経由でつなぐ
    • 代表的なプロトコル：IPsec、OpenVPN、WireGuard

    なお VPN 機器自体の脆弱性は、ランサムウェアの侵入口として頻繁に狙われます（脆弱性管理とランサムウェア対策）。

    7.2 HTTPS ができあがるまでの4ステップ

    HTTPS は、Web の通信（HTTP）を TLS（旧称 SSL）で暗号化したものです。

    1. TLS ハンドシェイク：ブラウザ「接続したい」→ サーバー「使える暗号方式はこれ」と、お互いの能力をすり合わせる
    2. 証明書の提示：サーバーが認証局（CA）発行の デジタル証明書（身分証明書）を送り、ブラウザが CA の署名を確かめる
    3. 鍵の交換：公開鍵暗号の仕組みで、この通信だけに使う セッション鍵（共通鍵） を安全に共有する
    4. 暗号化通信：以降はセッション鍵（AES など）で HTTP のデータを暗号化してやり取りする

    よくある誤解：「鍵マークがあれば安全なサイト」

    HTTPS が守るのは 通り道 だけです。フィッシングサイトも普通に HTTPS 化できます。鍵マークは「途中で盗み見されない」ことの印であって、「相手が信用できる」ことの印ではありません。

    7.3 Wi-Fi の暗号化方式

    方式状態説明
    WEP危険最初期の方式。短時間で解読できてしまう
    WPA非推奨WEP の改良版だが、現在は不十分
    WPA2一般的AES 暗号。2017年に公表された KRACK 攻撃への対策としてパッチ適用が必須
    WPA3推奨より強い暗号。パスワードの総当たり（オフライン辞書攻撃）に強い
    オープン暗号化なしカフェなどの公共 Wi-Fi。VPN なしで機密情報を扱うのは危険

    公共 Wi-Fi を使うときの基本

    • 銀行や社内システムなど機密性の高い操作は避けるか、VPN を使う
    • 「自動接続」はオフにする
    • 自宅・オフィスの Wi-Fi は WPA2 以上（できれば WPA3）にする

    8.メールのなりすまし対策 — SPF・DKIM・DMARC

    メールは仕組み上、差出人を偽るのが簡単 です。封筒の裏に好きな差出人を書けるのと同じです。そこで、受け取った側が「本当にそのドメインから来たか」を確かめる3つの仕組みを組み合わせます。

    仕組み正式名称何を確かめるかどうやって
    SPFSender Policy Framework送ってきたサーバーの IP が正規かDNS に「このドメインのメールはこの IP から送る」と登録しておく
    DKIMDomainKeys Identified Mail途中で改ざんされていないか送信側がメールにデジタル署名（封印）を付け、受信側が検証する
    DMARCDomain-based Message Authentication, Reporting and ConformanceSPF/DKIM に失敗したメールをどう扱うか「拒否／隔離／報告」の方針を DNS で宣言する
    1. 送信者が example.com からメールを送る
    2. 受信側が SPF を確認：「この IP は example.com の正規サーバーか？」
    3. 受信側が DKIM を確認：「署名は正しいか？ 改ざんされていないか？」
    4. DMARC の方針に従って、拒否／隔離（迷惑メールフォルダ）／受信 を決める

    組織としては、自社ドメインに SPF・DKIM・DMARC を設定 し、自社を名乗るなりすましメールが出回るのを防ぎます。

    9.エンドポイントの防御 — 最後の砦は端末そのもの

    エンドポイント とは、PC・サーバー・スマートフォンなど、ネットワークの「端」につながる個々の端末のことです。ネットワークの関所をすり抜けた攻撃（メール添付や USB メモリ経由など）は、最終的に端末で動きます。だから端末自体にも守りが必要です。

    9.1 端末を守る技術

    技術説明
    アンチウイルスソフト既知のマルウェアの「指名手配写真（シグネチャ）」と照合して検知・駆除
    EDR（Endpoint Detection and Response）端末上の ふるまい（プロセスの起動、ファイル変更、通信）を記録・監視し、未知の脅威も検知。侵入後の調査・対応まで支援
    ディスク暗号化端末を紛失・盗難されても中身を読まれないようにする（BitLocker、FileVault など）
    改ざん検知（FIM）File Integrity Monitoring。重要なファイルや設定の不正な変更を検知する

    アンチウイルス

    • 検知：既知パターン（シグネチャ）
    • 未知の脅威：弱い
    • 調査機能：限定的

    たとえ：指名手配写真を持った警備員

    EDR

    • 検知：ふるまい分析＋シグネチャ
    • 未知の脅威：強い
    • 調査機能：詳細なタイムラインと原因分析

    たとえ：館内の全カメラ録画＋「挙動不審」に気づく警備員

    9.2 端末の運用・管理

    項目説明
    パッチ管理OS やアプリの脆弱性修正（パッチ）を定期的に当てる。古いままの端末は、穴の開いた扉を放置しているのと同じ
    バックアップとリカバリランサムウェアなどから復旧する手段。3-2-1 ルール：コピーを3つ、2種類の媒体に、1つは離れた場所（オフサイト・オフライン）に
    ログ管理端末の操作履歴を記録し、インシデント調査に使う（セキュアな運用とログ出力）
    SBOMSoftware Bill of Materials。ソフトに含まれる部品（ライブラリ）の一覧表。食品の原材料表示のようなもので、サプライチェーン攻撃や脆弱性の影響調査に役立つ

    実務でのポイント：端末防御の3点セット

    EDR ＋ パッチ ＋ バックアップ。EDR で異変に気づき、パッチで侵入口を減らし、バックアップで最悪の事態から戻れるようにします。

    9.3 インシデント対応チーム — CSIRT と PSIRT

    組織正式名称役割
    CSIRT（シーサート）Computer Security Incident Response Team組織全体のセキュリティ事故に対応する「消防隊」
    PSIRT（ピーサート）Product Security Incident Response Team自社 製品 の脆弱性に対応するチーム（製品を作るベンダー企業向け）

    インシデント対応は「準備 → 検知・分析 → 封じ込め → 根絶 → 復旧 → 事後対応（教訓）」の流れで進みます。詳しくは セキュリティ監視とツール と セキュアな運用とログ出力 で扱います。

    10.マルウェアとフィッシング — 守りをすり抜けてくる敵

    マルウェア は「malicious（悪意ある）＋ software」の造語で、悪意を持って作られたソフトの総称です。

    種類ふるまい
    ランサムウェアファイルを暗号化して「身代金」を要求。被害がもっとも大きいマルウェアの一つで、IPA「情報セキュリティ10大脅威（組織編）」でも上位の常連。VPN 機器の脆弱性やメール添付から侵入
    スパイウェアユーザーの行動や情報をこっそり集めて送信。キー入力を記録する キーロガー を含むことも
    ボット攻撃者に遠隔操作される。DDoS 攻撃の「兵隊」に使われる
    ワームネットワークを通じて 人の操作なしに自己増殖 する（例：2017年の WannaCry は世界中で大規模に感染）
    トロイの木馬正規ソフトを装って侵入し、内部で裏口を開く。無料ソフトやクラック版に混入しやすい
    アドウェア広告を強制表示。単体では軽微だが、スパイウェアと組み合わさることも
    バックドア攻撃者が後で入るための「裏口」。長期間気づかれずに潜むことがある

    10.1 感染経路と対策

    主な感染経路

    • メールの添付・リンク（最多）：「請求書.pdf.exe」のような偽装、Office マクロの悪用
    • Web サイト（ドライブバイダウンロード）：見るだけで感染。正規サイトが改ざんされて罠になることも
    • USB メモリ：拾った・もらった USB を挿すだけで感染
    • ソフトのインストール：クラック版、偽のアップデート通知、サプライチェーン攻撃
    • 脆弱性の悪用：パッチ未適用の OS や VPN 機器・ルーター

    対策（多層で）

    • 端末：アンチウイルス・EDR、OS とソフトを最新に、不審な添付や USB を開かない
    • ネットワーク：FW・WAF・IDS、怪しいサイトを止める DNS フィルタリング、メールのマルウェアスキャン
    • 復旧：定期バックアップをオフライン・別ネットワークに保管し、復旧手順を事前にテスト
    • 人：フィッシング訓練などの教育、最小権限で被害範囲を限定、報告フローの整備

    10.2 フィッシングとソーシャルエンジニアリング

    技術の壁を越えるいちばん簡単な方法は「人をだます」ことです。代表的な手口と見分け方をまとめます。

    • ビジネスメール詐欺（BEC）：経営者や取引先になりすまして送金を指示する（「至急！社長の〇〇です。△△に送金してください」）
    • スピアフィッシング：特定の人・組織を狙い撃ち。SNS などで名前・役職・業務を調べ、本物らしいメールを送る
    • スミッシング：SMS で「荷物が届いています」などと送り、偽サイトへ誘導。宅配業者・銀行・行政サービスを装うことが多い
    チェックポイント確認のしかた
    送信元アドレスドメインが微妙に違わないか（arnaz0n.co.jp など）
    リンクの URLクリック前にマウスを乗せて実際の行き先を確認
    焦らせる文言「今すぐ」「24時間以内」「アカウント停止」
    日本語の不自然さ機械翻訳っぽい表現や誤字
    添付ファイル.exe・.zip・マクロ付き Office ファイルに注意

    脅威の種類の全体像は さまざまな脅威と対策の基本 も参照してください。

    11.アプリ層と組織全体の守り方（つながりの整理）

    ノートの「知識地図」では、ネットワーク・端末に加えて、アプリケーションと組織全体のモデルまでを1つの地図にしています。ここでは要点と、詳しく扱うページへの道案内をまとめます。

    11.1 アプリケーションの守り

    • Web アプリはインターネットに直接さらされるため、攻撃の主要な標的。代表的な脆弱性は SQL インジェクション（入力に SQL 文の一部を混ぜて DB を操る。例：' OR '1'='1）と XSS（他人のブラウザで悪意あるスクリプトを動かす）→ インジェクションと暗号化の不備
    • ビジネスロジックの欠陥：URL を直接打つと他人のデータが見える（権限チェック漏れ）、クーポンが無限に使える（レート制限なし）、決済前に発送してしまう（ワークフローの欠陥）→ 脅威モデリング・コードレビュー・ペネトレーションテストで見つける
    • 実装レベルでは バッファオーバーフロー（想定以上のデータでメモリを壊す）や RCE（リモートから任意のコードを実行させる）も重大。Java・Python などメモリ保護のある言語では起きにくいが、C/C++ では今も重要

    ログイン状態を保つ セッション ID は Cookie で渡されるため、Cookie の属性設定が大切です。

    Set-Cookie: sessionid=abc123; HttpOnly; Secure; SameSite=Strict
    属性効果
    HttpOnlyJavaScript から Cookie を読めなくする → XSS によるセッション窃取を防ぐ
    SecureHTTPS のときだけ Cookie を送る → 暗号化なし通信での漏洩を防ぐ
    SameSite他サイトからのリクエストに Cookie を付けない → CSRF を軽減

    開発プロセスでは、DevSecOps（開発 Dev・セキュリティ Sec・運用 Ops を一体化）と シフトレフト（セキュリティ対策を工程の早い段階＝左側へ移す）が鍵です。

    コード作成 → 静的解析（SAST）→ 依存関係スキャン（SCA）→ テスト → デプロイ → 動的解析（DAST）
   ↑ なるべく左側で問題を見つける ＝ シフトレフト

    11.2 組織全体のモデルと統合プラットフォーム

    モデル考え方弱点
    境界防御社内は「安全な城」、外は「敵地」。ファイアウォールで境界を守る内部からの脅威に弱い。クラウド時代は境界があいまい
    多層防御物理 → ネットワーク → 端末 → アプリ → データ → 人 と何層も重ね、1層破られても次で止める（今も有効な基本の考え方）
    ゼロトラスト社内・社外を問わず「一切信頼しない」。毎回認証・認可・検証し、最小権限を徹底導入・運用が複雑

    ゼロトラストの実装要素として、ユーザー（管理者か）・端末（社給 PC か、パッチは最新か）・場所（海外か）・リスク（ログイン失敗の多さ、普段と違う時間帯）に応じてアクセスを動的に判断する 動的アクセス制御（Conditional Access） があります。例：「海外からの管理者ログインには MFA を追加要求」「パッチ未適用の端末は社内リソースへのアクセスを拒否」。

    また、拠点ごとにバラバラに置いていた FW・VPN・プロキシを、クラウド上でまとめて提供する SASE（Secure Access Service Edge）という考え方も広がっています。SASE は SWG（Web 通信のフィルタ）、CASB（クラウドサービス利用の監視・制御）、FWaaS（クラウド型ファイアウォール）、ZTNA（ゼロトラスト型のアクセス）などを束ねたものです。SIEM・XDR・SOAR などの監視側の基盤は 次のページ で扱います。

    考え方の詳細は 深層防御、ゼロトラスト を参照してください。

    12.まとめ

    このページの要点

    • ファイアウォール は IP・ポートで通信を選ぶ門番。必要なものだけ許可し、最後に全拒否。公開サーバーは DMZ、DB は内部に分ける
    • IDS は検知して警告（火災報知器）、IPS は検知して遮断（自動消火）。方式はシグネチャ型（既知に強い）とアノマリ型（未知に強いが誤検知多め）
    • WAF は HTTP の中身を見る Web アプリ専用の検査官。ただしアプリ側の修正の代わりにはならない
    • DDoS は可用性への攻撃。クラウド型対策サービス・CDN・レートリミットで吸収・分散する
    • 通り道は VPN・HTTPS・WPA2/3 で暗号化、メールは SPF・DKIM・DMARC でなりすましを防ぐ。鍵マーク＝安全なサイトではない
    • 端末は EDR ＋ パッチ ＋ バックアップ（3-2-1）。どの層も「1枚で完璧」はなく、重ねて守る

    13.理解度チェック

    Q1. ファイアウォールで 443 番ポートを許可している Web サイトに、SQL インジェクション攻撃が来ました。ファイアウォールで止められますか？

    基本的に止められません。 一般的なファイアウォール（パケットフィルタリング型・ステートフル型）は IP・ポートしか見ないので、443 番への正規の HTTPS 通信として通してしまいます。HTTP の中身を検査する WAF や、アプリ側のプレースホルダなどで防ぎます。

    Q2. IDS と IPS の違いを「動作」と「置き場所」の2点で説明してください。

    動作：IDS は検知して警告するだけ（通信は止めない）、IPS は検知してブロックする。置き場所：IDS は通信のコピーを受け取って横から監視、IPS は通り道の上（インライン）に置いて全通信を通過させる。IPS は誤検知すると正常な通信も止めてしまう点に注意します。

    Q3. なぜ DB サーバーを Web サーバーと同じ DMZ に置いてはいけないのですか？

    DMZ はインターネットに公開する前提のゾーンで、そこにあるサーバーは攻撃を受けやすいからです。DB を内部ネットワークに置き、内部ファイアウォールで「Web/AP サーバーからの必要な通信だけ」を通すようにすれば、Web サーバーが乗っ取られてもう一枚の壁で DB を守れます（多層防御）。

    Q4. アンチウイルスと EDR の一番の違いは何ですか？

    アンチウイルスは 既知のパターン（シグネチャ） と照合するため未知の脅威に弱い一方、EDR は端末上の ふるまい を記録・分析するので未知の脅威にも気づきやすく、侵入後に「いつ・何が起きたか」のタイムライン調査もできます。
