    脆弱性管理とランサムウェア対策

    2026年に国内で最も多く使われた侵入口は、VPN 機器やリモートデスクトップの「すでに知られている穴」でした。このページでは、その穴をふさぎ続ける運用である 脆弱性管理 と、穴から入ってくる代表的な攻撃である ランサムウェア の手口・止め方・バックアップ・初動対応を、初めての人にも分かるように順を追って解説します。

    もとにしたノート：50_運用・監視・インシデント / 07_脆弱性管理（境界機器・パッチ運用）、08_ランサムウェア対策

    ひとことで言うと

    脆弱性管理 は「家じゅうの窓と扉を一覧にして、壊れた鍵を期限までに直し続けること」。ランサムウェア は、その壊れた鍵から入り込み、家財に鍵をかけて「開けてほしければ金を払え」と脅す泥棒です。泥棒には決まった段取りがあるので、どこか1段で止めれば被害は大きく減ります。そして最後の砦が「泥棒に壊されないバックアップ」です。

    1.なぜ今、脆弱性管理が大事なのか

    脆弱性（ぜいじゃくせい） とは、ソフトウェアや機器の「弱点」「穴」のことです。脆弱性管理 とは、自分たちが持っている IT 資産（パソコン・サーバー・ネットワーク機器・クラウドサービスなど）の脆弱性を見つけ、優先度をつけ、期限内に直し続ける 運用 のことを指します。一度やれば終わりではなく、毎月・毎週まわし続ける仕事です。

    このページで特に注目するのは、境界機器 です。境界機器とは、会社のネットワークとインターネットの「境目」に立つ機器のことで、VPN 装置（社外から社内に安全につなぐための装置）、ファイアウォール（通信の門番）、ファイル転送製品などが当てはまります。家にたとえると 玄関や勝手口 にあたり、インターネットのどこからでも直接たたける場所にあるため、真っ先に狙われます。

    VPN が約5割

    2026年上半期の国内ランサムウェア被害で、経路が分かったもののうち VPN 機器が約5割、RDP が4分の1（警察庁）。

    脆弱性の悪用 31%

    世界の漏洩でも、入口は 脆弱性の悪用（31%） が、盗まれた認証情報を初めて上回りました（Verizon DBIR 2026）。

    悪用までが早い

    脆弱性が公表されてから悪用されるまでの期間が短くなり、悪用ツールも 自動化 されています。

    ライブラリ（プログラムの部品）の古さについては 安全でない設計・設定ミス・古い部品 で扱いました。このページでは、境界機器 と 組織としての運用 を中心に見ていきます。

    2.脆弱性管理のサイクル

    脆弱性管理は、次の5つのステップをぐるぐる回す仕事です。病院の健康診断にたとえると「受診者の名簿を作る → 最新の病気の情報を集める → 重症の人から診る → 治療する → 治ったか・合併症がないか確かめる」という流れです。

    2.1 資産の把握 ― 持っているものを全部知る

    持っていることを知らない機器は直せません。家の窓の数を知らなければ、どれが開けっぱなしかも分からないのと同じです。

    • 機器・OS・ミドルウェア・SaaS の一覧を作ります。この一覧を管理する仕組みを CMDB（構成管理データベース）と呼びます。バージョンとサポート期限 も一緒に記録します。
    • ASM（Attack Surface Management：攻撃対象領域の管理）で、インターネットから見えている自社の資産を 外から定期的にスキャン します。泥棒の目線で自分の家を外から一周してみるイメージで、忘れられた検証用サーバーや古い VPN が見つかります。
    • ソフトウェアは SBOM（ソフトウェア部品表）で中身を把握します。食品の原材料表示のように「どの部品が入っているか」の一覧です。

    2.2 脆弱性情報の収集 ― どこから「穴の情報」を得るか

    情報源内容
    ベンダーのセキュリティアドバイザリ使っている製品のメーカーが出す公式情報。メール通知に登録 しておく
    JVN ／ JPCERT/CC の注意喚起国内向けの脆弱性情報と、悪用が確認されたものについての注意喚起
    CISA KEV（Known Exploited Vulnerabilities）米国 CISA が公開する、実際に悪用が確認された 脆弱性の一覧。優先度の判断で最も役に立つ
    EPSSその脆弱性が今後30日以内に悪用される確率の予測値

    用語メモ：CVE は脆弱性1つ1つに付く通し番号、CVSS は脆弱性の深刻度を 0〜10 点で表す採点方式です（→ セキュリティの専門用語）。

    2.3 優先度の判断 ― 「悪用されているか」「外から届くか」

    脆弱性は毎日たくさん見つかります。CVSS の点数だけで「7点以上は全部すぐ直す」と決めると、対応すべきものが多すぎて回りません。そこで重く見るのが次の2点です。

    • 実際に悪用されているか（KEV に載っている、JPCERT/CC の注意喚起が出ている）
    • インターネットから届く場所にあるか（玄関の鍵なのか、奥の部屋の引き出しの鍵なのか）
    条件対応期限の例
    KEV 掲載または注意喚起あり、かつ インターネットに公開された機器48〜72 時間以内
    CVSS 9.0 以上で外部公開7日以内
    CVSS 7.0 以上30日以内
    それ以外通常の定期メンテナンスで

    期限は組織ごとに決めます。大事なのは決めて終わりにせず、SLA（約束した対応期限）として守れているかを測る ことです。「KEV 掲載の脆弱性を期限内に直せた割合」のように数字で追いかけます。

    2.4 修正・緩和 ― すぐ直せないときの応急処置

    • 業務の都合でパッチ（修正プログラム）をすぐ当てられないときは、緩和策 をとります。たとえば、管理画面を外部から見えなくする、該当する機能を止める、接続元の IP アドレスを制限する、などです。鍵の交換が届くまで、とりあえずドアにチェーンをかけておくイメージです。
    • サポートが終わった製品（EOL：End of Life） には、もうパッチが出ません。更新計画を立てて置き換えます。2026年のタイムズカーの事例では、サポートが終わった Java フレームワーク Seasar2 を使っていたという指摘がありました（ただし漏洩との因果関係は未確認です）。

    2.5 確認と侵害痕跡の調査 ― 見落とされやすい最後の一手

    パッチを当てても、すでに入られているかもしれない

    脆弱性が公表される前から悪用されていた場合、パッチで穴をふさいでも、攻撃者が作ったアカウントやバックドア（裏口）は家の中に残ります。鍵を替えても、泥棒が作った合鍵や開けておいた窓はそのまま、という状態です。境界機器の重大な脆弱性に対応したら、次も行います。

    • ベンダーや JPCERT/CC が公開している IoC（Indicator of Compromise：侵害の痕跡） と自社のログ・機器を照らし合わせる
    • 機器に保存されていた 認証情報（VPN アカウント、LDAP 連携のパスワードなど）をリセット する
    • 見覚えのない管理者アカウントや設定変更がないか確かめる

    3.ゼロデイへの考え方

    ゼロデイ脆弱性 とは、メーカーもまだ把握しておらず、修正パッチが存在しない（修正までの猶予が「0日」の）脆弱性のことです。2026年の KDDI の事例では、ベンダーも把握していないゼロデイ脆弱性が使われました（5/16 に被害が始まり、6/17 に把握）。

    ゼロデイは、どれだけパッチ運用を頑張っても 防げません。だからこそ「入られる前提」の備えが必要です。

    届くデータを小さくする

    入られても持ち出せる量を減らす。→ 最小権限とデータ最小化

    異常を早く見つける

    ログと監視で、侵入後の怪しい動きに気づく。→ ログ不足・SSRF・例外処理

    境界機器を減らす

    VPN をインターネットに公開しない ZTNA への移行も選択肢。→ ゼロトラスト

    実務でのポイント

    とはいえ、2026年の被害の多くはゼロデイでは ありません。警察庁のまとめでは、ランサムウェアの主な入口は 放置された既知の脆弱性と漏えいした認証情報 でした。まずは「知られている穴を期限内にふさぐ」が最優先で、ゼロデイ対策はその上に重ねるものです。

    4.ランサムウェアとは

    ランサムウェア は、組織のデータを暗号化して（鍵をかけて）使えなくし、元に戻すことと引き換えに身代金（ransom）を要求する攻撃です。IPA「情報セキュリティ10大脅威」組織編で何年も 1位 が続いています。2026年上半期の国内被害は 123件 で、半期として過去最多でした（警察庁）。

    「侵入 → 社内に広がる → バックアップを壊す → 暗号化と窃取 → 脅迫」という段取りのある攻撃。どこか1段で止めれば被害は大きく減る。

    4.1 いまのランサムウェアの特徴

    特徴内容
    二重恐喝暗号化する前にデータを盗み、「払わなければ公開する」と脅す。バックアップから戻せても、漏洩は残る
    ノーウェアランサム暗号化すらせず、盗んだデータの公開だけで脅す手口
    RaaS（Ransomware as a Service）ランサムウェアの開発者と、実際に攻撃する実行役（アフィリエイト）が分業する「ビジネス」。侵入口を売る「アクセスブローカー」もいる
    人が操作する攻撃自動で広がるワームではなく、攻撃者が社内ネットワークを手作業で調べ、AD（社内の利用者・権限をまとめて管理する Active Directory）やバックアップを狙う
    ゼロデイは不要主な入口は 放置された既知の脆弱性と漏えいした認証情報（警察庁）

    よくある誤解：「バックアップがあれば大丈夫」

    二重恐喝やノーウェアランサムでは、データはすでに 盗まれて います。バックアップで業務は戻せても、情報漏洩はなかったことにできません。窃取（持ち出し）に気づく仕組み も必要です。

    5.侵入経路と、各段階で止める対策

    5.1 侵入経路（2026年上半期・警察庁）

    経路が判明した有効回答36件の内訳です。

    経路件数
    VPN 機器18件（約50%）
    リモートデスクトップ（RDP）9件
    その他9件

    VPN と RDP だけで約4分の3 を占めます。RDP（Remote Desktop Protocol）は、離れた場所から Windows の画面を操作する仕組みです。どちらも「社外から社内に入る扉」なので、ここが壊れていると直接入られます。一方、メールの添付ファイルからの感染は減っています。

    5.2 攻撃の段取りと止めどころ

    段階攻撃者がすること止める対策
    1. 初期侵入VPN の脆弱性を突く、漏れた ID でログイン、公開 RDP に総当たりパッチ SLA（2章）、VPN に MFA（多要素認証）、RDP をインターネットに出さない、使っていないアカウントの削除
    2. 横展開認証情報を盗んで AD の管理者権限を取る管理者アカウントの階層分離（Tier モデル）、LAPS（端末ごとに異なるローカル管理者パスワードを自動管理する仕組み）、最小権限、ネットワーク分割
    3. 防御の無効化EDR（端末の不審な動きを検知・対応するソフト）を止め、バックアップや VSS（Windows のシャドウコピー）を削除するEDR の改ざん防止機能、バックアップを別の認証基盤・別アカウントに置く
    4. 窃取クラウドストレージなどへ大量に送る外向き通信の監視・制限（ログとモニタリング）、DLP（情報の持ち出しを検知・防止する仕組み）
    5. 暗号化一斉に暗号化して脅迫文を置くイミュータブル（書き換え不可）なバックアップから復元（DR 訓練と RTO・RPO の話）

    段階ごとに別の守りを重ねる考え方は 深層防御 そのものです。1枚の壁に頼らず、何枚もの網を張っておけば、どれかに引っかかります。

    6.バックアップの考え方

    ランサムウェアは バックアップも狙います。本番システムと同じ AD 権限で消せるバックアップは、泥棒が合鍵で開けられる金庫と同じで、ないのと同じ です。

    3

    コピーを 3つ 持つ（本番＋バックアップ2つ）

    2

    2種類 の媒体に保存する

    1

    1

    1つはオフラインか書き換え不可（イミュータブル）にする

    0

    復元テストでエラー0 を確かめる

    6.2 そのほかの大事な点

    • 認証を分ける：バックアップの管理は、本番の AD とは別のアカウントや別のクラウドアカウントで行う。本番の管理者権限が奪われても、バックアップには手が届かないようにする。
    • 復元にかかる時間を測る：全台を戻すのに何日かかるかを知らないと、RTO（目標復旧時間：何時間以内に戻すかの目標）は絵に描いた餅になる。
    • クラウド事業者が被害に遭うこともある：2026年には IDCF クラウドの基盤そのものが被害を受け、495の組織に影響した。事業者のバックアップとは別に、自分たちでもバックアップを持つ。
    ✕ 危ないバックアップ 
    本番サーバー ──(同じドメイン管理者で)──▶ バックアップサーバー
→ 管理者権限を奪われた時点で、バックアップも一緒に削除・暗号化される
    ○ 壊されにくいバックアップ 
    本番サーバー ──(別アカウント・別認証基盤)──▶ 書き換え不可の保管先（別の場所）
→ 本番が乗っ取られても、保持期間中は誰にも消せない ＋ 定期的に復元テスト

    7.被害に遭ったときの初動と、被害の実態

    7.1 初動の4ステップ

    1. ネットワークから切り離す。ただし 電源は切らない。メモリ上に残っている証拠が消えてしまうため。
    2. 被害範囲を確かめ、認証情報を一斉にリセット する（特に AD の管理者と VPN）。
    3. 経営層・法務と相談する。警察と JPCERT/CC に相談 し、個人情報が含まれていれば 個人情報保護委員会に報告 する。
    4. 身代金は 支払わないのが原則。支払っても復号できる保証はなく、データの公開も止まらない。

    よくある誤解：「とりあえず電源を落とせば安全」

    電源を切ると、攻撃者がどう動いたかを示すメモリ上の証拠が失われます。広がりを止めたいなら、まず LAN ケーブルを抜く・Wi-Fi を切る などで通信を断ちます。

    復旧期間48件中、1か月以内に戻ったのは23件。13件は公表時点でも復旧中

    10.まとめ

    このページの要点

    • 2026年の最大の入口は VPN・RDP と既知の脆弱性・漏れた認証情報。ゼロデイが主役ではない
    • 脆弱性管理は 資産の把握 → 情報収集 → 優先度 → 修正 → 痕跡調査 のサイクルを回し続ける運用
    • 優先度は CVSS の点数より KEV（悪用実績）とインターネット公開の有無 を重視し、期限（SLA）を測る
    • パッチを当てたら終わりではなく、すでに侵入されていないか を確かめ、認証情報をリセットする
    • ランサムウェアは段取りのある攻撃。どこか1段で止める 多層防御が効く
    • バックアップは 書き換え不可・認証を分離・復元テスト済み が条件。ただし二重恐喝があるので、窃取の検知も必要

    11.理解度チェック

    Q1. CVSS 7.5 の社内専用サーバーの脆弱性と、KEV に載っている VPN 機器の脆弱性。先に直すべきはどちら？

    VPN 機器のほうです。 KEV に載っている＝実際に悪用されている、かつ VPN はインターネットから直接届く境界機器です。優先度は点数だけでなく「悪用されているか」「外から届くか」で判断し、例では 48〜72 時間以内の対応にあたります。

    Q2. 境界機器の重大な脆弱性にパッチを当てました。これで対応完了と言えますか？

    言えません。 公表前から悪用されていた場合、攻撃者が作ったアカウントやバックドアが残っている可能性があります。IoC との照合、機器に保存されていた認証情報（VPN アカウントや LDAP 連携パスワード）のリセット、見覚えのない管理者アカウントや設定変更の確認まで行って完了です。

    Q3. 毎日バックアップを取っています。これでランサムウェアへの備えは十分ですか？

    不十分なことが多いです。 ①本番と同じ管理者権限で消せるバックアップは攻撃者に削除される、②復元テストをしていないと本当に戻せるか・何日かかるか分からない、③二重恐喝ではデータがすでに盗まれているので、戻せても漏洩は残る――の3点を確認しましょう。書き換え不可・認証の分離・復元テストに加え、外向き通信の監視で窃取に気づく仕組みも必要です。

    Q4. ランサムウェアに感染した端末を見つけました。最初にすることは？

    ネットワークから切り離します（電源は切らない）。 電源を切るとメモリ上の証拠が消えてしまいます。そのうえで被害範囲を確かめ、AD 管理者や VPN の認証情報をリセットし、経営層・法務、警察・JPCERT/CC に相談します。
