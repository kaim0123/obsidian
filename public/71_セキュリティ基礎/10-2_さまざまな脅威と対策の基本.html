    10 基本概念

    さまざまな脅威と対策の基本

    マルウェア、不正侵入、DDoS、設定ミス、Web アプリの脆弱性、サプライチェーン攻撃、パスワード攻撃、なりすまし、フィッシング、ソーシャルエンジニアリング――セキュリティで最初に押さえるべき「脅威」と「脆弱性」の全体像を、何が起きるのか → なぜ危険なのか → どう防ぐのか の順に整理します。

    もとにしたノート：10_基本概念/02_セキュリティの脅威と対策の基礎（知識地図1章）

    ひとことで言うと

    攻撃は大きく 「機械を狙う攻撃（技術的脅威）」「弱点（脆弱性）」「人を狙う攻撃」 の3つに整理できます。脅威 × 脆弱性 → 被害 という関係なので、攻撃手法と、それが成功してしまう弱点の両方を見ることが大切です。そして防御は、技術（ファイアウォール・暗号化・パッチ）と人（教育・確認手順）の 両方を何層にも 重ねます。

    1.脅威とは何か — 脆弱性とセットで考える

    脅威（Threat）とは、システムや情報に害を与えようとする行為や主体のことです。相手は外部のハッカーとは限りません。設定ミスや古いソフトウェアのように、意図せずに生まれた弱点も攻撃の入口になります。

    概念意味例
    脅威攻撃そのもの、または攻撃者マルウェア、フィッシング、内部犯行
    脆弱性攻撃が成功しやすい弱点未修正のバグ、弱いパスワード、設定ミス

    2.技術的脅威 — コンピュータやネットワークを直接狙う

    2.1 マルウェア（Malware）

    悪意のあるソフトウェアの総称です（malicious ＋ software）。利用者が気づかないうちに入り込み、情報を盗む・壊す・遠隔操作する、などを行います。病気にたとえると、種類ごとに「うつり方」と「症状」が違う病原体のようなものです。

    種類概要特徴
    ウイルス他のプログラムに寄生して増える実行ファイルへの感染が典型
    ワームネットワーク経由で単独で広がる人の操作なしに広がる
    トロイの木馬正規のソフトのふりをして侵入する裏口（バックドア）の設置などに使われる
    ランサムウェアデータを暗号化して身代金を要求する企業の被害が増加傾向
    スパイウェア行動をこっそり監視・収集するキーロガーを含むことも
    アドウェア不要な広告を表示する他のマルウェアの入口にもなる
    ルートキットOS の深い部分に潜んで検知を逃れる除去が難しい
    ボットネット感染した端末を遠隔操作するネットワークDDoS 攻撃の発射元になりやすい
    キーロガーキーボード入力を記録するパスワードの窃取に直結

    主な感染経路

    • 添付ファイル付きのメール
    • 不正なサイトからのダウンロード
    • 脆弱性のあるソフトウェア
    • USB メモリなどの外部メディア

    対策の基本

    • ウイルス対策ソフト
    • OS・アプリを最新に更新する
    • 不審なリンク・添付ファイルを開かない
    • 最小権限の原則（感染しても被害を広げない）

    2.2 ハッキング（不正侵入）

    許可なくシステムやネットワークに 侵入し、データを盗んだり操作したりする行為です。入口は外からとは限りません。

    • 外部からの侵入：公開サーバーの脆弱性、弱い認証情報（ID・パスワード）の悪用
    • 内部からの不正：権限を持つアカウントの悪用、退職者のアカウントの放置

    対策 パッチ管理、多要素認証（MFA）、アクセス権限の最小化、ログ監視

    2.3 DDoS 攻撃（Distributed Denial of Service）

    多数の端末から 同時に大量のリクエストを送りつけ、サービスを使えなくする攻撃です。CIA のうち 可用性を狙います。お店の入口に大勢のサクラを並ばせて、本当のお客さんが入れないようにするイメージです。

    • 例：EC サイトがアクセス不能になり売上を失う、政府のサイトが停止する
    • 乗っ取った端末の群れ（ボットネット）を使った大規模な攻撃が多い

    対策 CDN・DDoS 緩和サービス、レート制限（一定時間あたりのリクエスト数の上限）、冗長構成、インシデント対応計画

    2.4 フィッシング（Phishing）※概要

    本物の連絡を装って、パスワードや個人情報をだまし取る手口です。技術というより「人をだます」攻撃ですが、もっとも頻繁に使われる入口のひとつです。種類は 5章 で詳しく見ます。

    3.脆弱性 — 攻撃者が突く「弱点」

    脆弱性（Vulnerability）は、システムや運用の 設計・実装・設定上の弱点です。攻撃者はここを突いてきます。弱点がどこにあるかで、いくつかの種類に分けられます。

    3.1 ソフトウェア・アーキテクチャの脆弱性

    種類説明
    未パッチの既知脆弱性修正プログラムは出ているのに、適用されていない状態（CVE などで公開されている）
    ゼロデイ脆弱性まだ修正がなく、すでに攻撃に使われ始めている弱点
    不適切な設計最初からセキュリティを考えていない構成（例：パスワードを平文＝そのままの文字で保存）
    セキュリティコントロールの欠如認証・暗号化・ログなど、必要な防御がそもそも実装されていない

    ハードウェア・低レイヤー系

    • CPU の脆弱性：Spectre、Meltdown など、プロセッサの設計に起因する問題
    • ファームウェアの脆弱性：BIOS/UEFI など OS より下の層の弱点。更新が難しく、影響が大きい

    アプリケーション実装の典型

    • バッファオーバーフロー：想定より多くのデータを書き込んでメモリを壊し、任意のコードを実行されてしまう
    • コマンドインジェクション：ユーザーの入力が OS コマンドに混ざり、サーバー上でコマンドが実行される

    3.2 設定ミスによる脆弱性

    ソフトウェア自体にバグがなくても、運用の設定を誤るだけで穴が開きます。クラウド環境では特に多く見られます。立派な金庫を買っても、扉を開けっぱなしにしていたら意味がない、という状態です。

    設定ミス何が起きるか
    不適切なアクセス権限必要以上の人・サービスがデータに触れる
    過剰な権限設定乗っ取られた1つのアカウントから全体が乗っ取られる
    暗号化の不備通信や保存データが平文のまま漏洩する
    不要なサービスの有効化使っていないポートや機能が攻撃される面を広げる
    セキュリティ機能の無効化ファイアウォール・ログ・MFA などをオフにしたまま運用する

    対策 セキュリティベースライン（守るべき設定の基準）、設定の定期監査、Infrastructure as Code（設定をコードで管理）による標準化

    3.3 Web アプリケーションの脆弱性

    ブラウザ経由で攻撃される代表的な弱点です。OWASP Top 10 などで整理されています（→ OWASP Top 10 とは）。

    脆弱性概要被害の例
    SQL インジェクションSQL 文に悪意のある入力を混ぜるデータベース全体の漏洩・改ざん
    クロスサイトスクリプティング（XSS）他のユーザーのブラウザで悪意のあるスクリプトを動かすセッションの窃取、偽画面の表示
    クロスサイトリクエストフォージェリ（CSRF）ログイン中のユーザーに、意図しない操作をさせる勝手な送金、設定変更
    セッションハイジャック他人のセッション ID（ログイン状態を表す番号）を奪ってなりすますアカウントの乗っ取り
    ディレクトリトラバーサル../ などで本来見られないファイルを読む設定ファイル・ソースコードの漏洩
    オープンリダイレクト任意の外部 URL へ飛ばせてしまうリダイレクトフィッシングサイトへの誘導

    たとえば SQL インジェクションは、入力値を SQL 文に文字列としてつなげてしまうことで起きます。

    ✕ 入力をそのまま連結（SQL インジェクションの原因） 
    // name に「' OR '1'='1」を入れられると、全件が返ってしまう
const sql = "SELECT * FROM users WHERE name = '" + name + "'";
db.query(sql);
    ○ パラメータ化クエリ（プレースホルダ） 
    // 入力は「値」としてだけ扱われ、SQL の命令として解釈されない
db.query("SELECT * FROM users WHERE name = ?", [name]);

    対策 入力値の検証・エスケープ、パラメータ化クエリ、CSRF トークン、安全なセッション管理。詳しくは 72_Web脆弱性対策 のノートで扱っています。

    3.4 サプライチェーン攻撃

    自分たちが直接書いていない 外部の部品・ライブラリ・ツールを経由した攻撃です。料理にたとえると、自分の調理が完璧でも、仕入れた食材が傷んでいれば食中毒は起きる、ということです。

    攻撃の形説明
    依存ライブラリの脆弱性npm、PyPI などの古い・脆弱なパッケージを使っている
    OSS の脆弱性オープンソースの既知の脆弱性が未修正のまま本番で使われている
    パッケージのハイジャック正規のパッケージ名に似せた、悪意のあるパッケージが公開される
    バージョン汚染依存関係の解決ミスで、意図しない（危険な）バージョンが入る

    対策 SBOM（ソフトウェア部品表）の管理、依存関係の定期スキャン、信頼できるレジストリだけを使う。詳しくは サプライチェーンと整合性の不備 と サプライチェーン攻撃と2026年の事例 へ。

    4.認証情報を狙う攻撃

    パスワードやログイン情報は、多くの攻撃にとっての「鍵」です。鍵を手に入れれば、壁を壊さずに正面から入れてしまいます。

    4.1 パスワードに対する攻撃

    攻撃仕組み対策のヒント
    ブルートフォースすべての組み合わせを総当たりで試すアカウントロック、レート制限
    辞書攻撃よく使われるパスワードのリストで試す複雑なパスワード、パスワードマネージャ
    パスワードスプレーよくある少数のパスワードを、多数のアカウントに試すMFA、ログ監視
    クレデンシャルスタッフィング他のサイトで漏れた ID・パスワードの使い回しを試すMFA、漏洩パスワードの検知
    リプレイ攻撃盗聴した認証情報をそのまま再利用するワンタイムパスワード、タイムスタンプ
    レインボーテーブルハッシュ値の事前計算表からパスワードを逆算するソルト付きハッシュ（bcrypt など）
    キーロギング入力を記録するマルウェアで盗む端末の保護、MFA
    ショルダーハック肩越しに入力をのぞき見る画面の向き、プライバシーフィルター

    ポイント：表の多くに「MFA」が出てくる理由

    パスワードは「知っていれば誰でも使える」証拠なので、どこかで漏れたら終わりです。多要素認証（MFA）でスマホなど「持っているもの」を組み合わせれば、パスワードだけ盗まれても突破されにくくなります。辞書攻撃・スプレー・使い回し・キーロギングのどれにも効くのはこのためです。

    4.2 なりすまし（スプーフィング）

    送信元や通信相手を偽装して、相手をだます手口です。差出人欄を書き換えた手紙のようなものです。

    種類説明
    メールスプーフィング送信者アドレス（From）を偽装する
    DNS スプーフィングDNS（ドメイン名を IP アドレスに変換する仕組み）の応答を偽造し、偽サイトへ誘導する
    セッションハイジャック正規ユーザーのセッションを奪い、本人になりすます

    対策 SPF / DKIM / DMARC（送信元を確かめるメール認証技術）、HTTPS、安全な Cookie 設定、短いセッション有効期限

    5.人を狙う攻撃 — フィッシングとソーシャルエンジニアリング

    5.1 フィッシングの種類

    人間の心理を利用する攻撃です。種類によって入口が違います。

    種類概要例
    メールフィッシング不特定多数に大量に送るメール「荷物の確認」「口座の確認」
    スピアフィッシング特定の個人・組織を狙った、作り込んだメール役職者を名指しした偽メール
    スミッシング（SMS フィッシング）ショートメッセージ経由偽の配送通知のリンク
    ヴィッシング（ボイスフィッシング）電話で個人情報を聞き出す偽の銀行・サポート窓口
    フォーミング偽の Web フォームで情報を集める偽のログインページ
    QR コードフィッシングQR コードからフィッシングサイトへ誘導する駐車場やイベントの偽 QR

    共通の対策

    • メールや SMS の URL を直接クリックしない
    • 公式アプリやブックマークからアクセスする
    • 不審な連絡は、電話など 別の経路 で本人・本物に確認する

    5.2 ソーシャルエンジニアリング

    人の信頼や心理を操って、情報やアクセス権を引き出す手口の総称です。フィッシングとも重なります。技術的な防御を固めても、人がドアを開けてしまえば入られてしまいます。

    手法説明
    プリテキスティング標的を事前に調べ、信頼できる人物のふりをする（口実を作る）
    ベイト攻撃無料ソフトや落とし物の USB メモリなど「おいしい餌」で感染させる
    ビジネスメール詐欺（BEC）経営者や取引先を装い、送金や情報の開示を求める
    ウォーターホール攻撃標的がよく訪れるサイトを先に乗っ取り、そこから感染させる（水飲み場で獲物を待つイメージ）

    対策 セキュリティ教育、送金や機密開示の二重確認プロセス、いつもと違う依頼は電話など別の経路で確認

    よくある誤解：「技術対策をすれば人の問題は関係ない」

    マルウェア対策ソフトや最新のファイアウォールがあっても、社員が偽の指示に従って送金してしまえば防げません。技術と人の両方に対策が必要です。

    7.対策の柱 — セキュリティの仕組みを組み込む

    脅威を理解したら、組織やシステムに 防御の仕組みを組み込みます。ここでは3本の柱を紹介します。

    7.1 セキュリティ技術の導入と管理

    ファイアウォール

    許可された通信だけを通し、境界を守る。建物の門番。

    IDS / IPS

    侵入検知・防止システム。不審な通信や攻撃のパターンを見つけて知らせる（IDS）・止める（IPS）。防犯センサー。

    EDR

    エンドポイント（PC・サーバー）上で、マルウェアや異常な動きを検知する。各部屋の見回り役。

    入れて終わりではなく、ルールの定期的な見直し、ログの集約、インシデント時の連携まで運用することが重要です。詳しくは ネットワークと端末の防御 へ。

    7.2 暗号化の実装

    対象目的
    通信の暗号化（TLS）ネットワーク上での盗み見を防ぐ
    保存データの暗号化ディスクの紛失や漏洩のときに情報を守る
    鍵管理暗号の強さは、鍵をどれだけ安全に管理できるかで決まる

    注意：暗号化だけでは不十分

    暗号化しても、誰でも復号できる設定なら意味がありません。誰が復号できるか（アクセス制御）もセットで設計しましょう。金庫を買っても、鍵を机の上に置いていたら守れないのと同じです。

    7.3 脆弱性管理

    脆弱性は毎日のように新しく見つかるので、一度対処したら終わりではなく、継続的なプロセスとして回します。

    1. 資産の把握 — 何がネットワークにつながっているかを知る（知らない機器は守れない）
    2. スキャン・評価 — 既知の脆弱性を見つけ、重要度を判定する
    3. パッチ適用・緩和 — 修正できない場合は回避策（WAF、ネットワークの分離など）で守る
    4. 検証 — 修正後に、本当に直ったか再テストする
    5. 記録・報告 — 対応の履歴と、残っているリスクを見える化する

    重要度の判定に使う CVE や CVSS などの用語は次の セキュリティの専門用語、運用の詳細は 脆弱性管理とランサムウェア対策 で扱います。

    8.まとめ

    • 脅威と脆弱性はセット：攻撃手法と、それが成功してしまう弱点の両方を見る。
    • 脅威は 技術的脅威・弱点（脆弱性）・人を狙う攻撃 の3つで整理できる。
    • 技術と人の両方：マルウェア対策だけではフィッシングや詐欺は防げない。
    • 防御は多層で：ファイアウォール＋パッチ＋教育＋監視を組み合わせる。
    • 継続が前提：一度設定したら終わりではなく、更新・監査を続ける。

    9.理解度チェック

    Q1. 他のサイトから漏れた ID とパスワードを、別のサイトで試す攻撃は何？ 有効な対策は？

    クレデンシャルスタッフィングです。パスワードの使い回しを狙います。利用者側はサイトごとに違うパスワードを使うこと、サービス側は MFA や漏洩パスワードの検知が有効です。

    Q2. ソフトウェアにバグはないのに、クラウドのストレージが誰でも読める状態だった。これは何の脆弱性？

    設定ミスによる脆弱性（不適切なアクセス権限）です。設定の基準（ベースライン）を決め、定期的に監査し、Infrastructure as Code で設定を標準化するのが対策です。

    Q3. 「社長からの急ぎの送金依頼メール」にどう対応すべき？

    ビジネスメール詐欺（BEC）の典型的な手口の可能性があります。メールに返信するのではなく、電話など別の経路で本人に確認し、送金は二重確認のプロセスを通します。
