    60 サーバー・ネットワークセキュリティ

    ネットワーク機器への管理アクセス

    ルータやスイッチ自体が乗っ取られると、ACL も VPN もすべて書き換えられてしまいます。このページでは「機器にログインする入口」をどう守るかを、Cisco IOS（シスコのルータ・スイッチの OS）の設定コマンドとともに学びます。管理方法の種類と暗号化の有無、password と secret の違い、ログインの保護（最小文字数・総当たり対策・自動切断・特権レベル）、SSH の設定、ファイル転送と copy コマンドを順に扱います。

    もとにしたノート：60_サーバー・ネットワークセキュリティ/06_ネットワーク機器への管理アクセス（パスワード・SSH・ファイル転送）

    ひとことで言うと

    機器の入口は「暗号化する」「強く保存する」「何度も試させない」「放置させない」「接続元を絞る」で守ります。リモート管理は Telnet・HTTP ではなく SSH・HTTPS、パスワードは password ではなく secret（ハッシュ保存）を使い、login block-for・exec-timeout・access-class を組み合わせます。

    このページは、60-1 サーバーセキュリティの基本 と 60-2 SSHの安全な運用 を読んでいると理解しやすいです。サーバー（Linux）側の SSH の運用や、SSH そのものの仕組みは 60-2 で扱います。

    1.管理方法の種類

    ネットワーク機器（スイッチ、ルータ、AP〔無線アクセスポイント〕、WLC〔無線 LAN コントローラ〕）を設定・監視する方法には、次のものがあります。

    方法接続方法暗号化特徴
    コンソール機器のコンソールポートにケーブルを直接つなぐ―（直接接続）初期設定や障害時に使う。1台ずつ、その場で作業する必要がある
    Telnetネットワーク経由で CLI（文字で操作する画面）にログイン（TCP 23）されない（平文）パスワードなども平文で流れる
    SSHネットワーク経由で CLI にログイン（TCP 22）されるTelnet の代わりに使う
    HTTPWeb ブラウザで管理画面（GUI）へ（TCP 80）されないログイン情報を盗聴される恐れ
    HTTPSWeb ブラウザで管理画面へ（TCP 443）される（TLS）GUI 管理の推奨方式
    クラウド管理機器がインターネット経由でクラウドに接続し、ダッシュボードから一括管理（例：Cisco Meraki）される各拠点のスイッチや AP の設定・監視をまとめて行える

    管理者の認証には、機器に登録したローカルのユーザーや、TACACS+ / RADIUS の AAA サーバを使います（60-7 AAA）。

    関連して、混同しやすいものもあります。

    • TFTP：ファイルを転送するプロトコル（UDP 69）。設定ファイルや IOS イメージのコピーに使いますが、機器の管理方法ではありません。
    • SNMP：機器の監視に使うプロトコル。SNMPv1/v2c はコミュニティ名（パスワードのような合言葉）が平文で送られます。SNMPv3 は認証・暗号化に対応しています。

    1.1 暗号化の有無で整理

    用途暗号化されない暗号化される
    CLI（リモート）TelnetSSH
    GUI（Web）HTTPHTTPS
    監視SNMPv1 / v2cSNMPv3（authPriv）

    1.2 HTTPS による Web 管理の設定

    SW1(config)# ip http secure-server          ← HTTPS（TLS）を有効化
SW1(config)# no ip http server              ← 暗号化されないHTTPは無効化
SW1(config)# ip http authentication local   ← ローカルユーザーで認証
SW1(config)# username admin privilege 15 secret Cisco123!
    SW1# show ip http server status

HTTP server port: 80
...
HTTP secure server status: Enabled
HTTP secure server port: 443

    HTTPS（TLS）の仕組みそのものは 20-4 HTTPSとTLS証明書 で解説しています。

    1.3 クラウド管理

    クラウド管理（Cisco Meraki など）では、機器はインターネット経由でクラウドに接続し、設定を受け取ります。管理者は Web ブラウザでクラウドのダッシュボードにログインし、各拠点のスイッチや AP をまとめて設定・監視できます。拠点に IT 担当者がいなくても、機器をつなぐだけで設定が反映される（ゼロタッチプロビジョニング）のが利点です。一方、管理はインターネット接続とクラウドサービスに依存します。

    2.IOS のモードとログインの入口

    IOS には、できることの異なる「モード」があり、入口ごとに認証をかけられます。

    守るべき入口は次の 3 つです。

    入口設定場所用途
    コンソールline con 0ケーブルで機器に直接接続する（IP アドレス不要）
    vty（仮想端末）line vty 0 4（機種により 0 15）Telnet/SSH でネットワーク経由で接続する
    特権EXECモードenable secretenable で設定変更ができるモードに入る

    3.ラインのパスワード：password と login

    ライン（コンソールや vty などの入口）にパスワードを設定するには、password と login の両方が必要です。password だけでは「パスワードを持っている」だけで、確認は行われません。login を設定して初めてパスワードが要求されます。

    Router(config)# line con 0
Router(config-line)# password cisco123
Router(config-line)# login
Router(config-line)# exit

    コンソール接続時の動作は次のとおりです。

    User Access Verification

Password:          ← 入力した文字は表示されない
Router>

    つまり、コンソールにパスワードをかける手順は line con 0 → password cisco123 → login です。似たコマンドと混同しないようにしましょう。

    • line vty 0 4 → password ... → login はリモート接続用のラインで、コンソールには影響しません。
    • enable secret は特権EXECモードに入るときのパスワードで、コンソールに接続した時点では要求されません。
    • username admin secret ... はローカルユーザーを作るだけで、ラインに login local を設定しないと使われません。

    3.1 ユーザー名とパスワードで認証する（login local）

    Router(config)# username admin secret Cisco!2026
Router(config)# line con 0
Router(config-line)# login local          ← ローカルユーザーのデータベースで認証
Router(config-line)# line vty 0 4
Router(config-line)# login local
    User Access Verification

Username: admin
Password:
Router>
    ラインの設定認証の方法
    loginそのラインの password で認証（ユーザー名なし）
    login localusername で作成したローカルユーザーで認証
    （AAA 使用時）login authentication ... / defaultAAA の方法リストで認証（60-7 AAA）

    4.password と secret（平文・タイプ7・ハッシュ）

    IOS のパスワード保存方式は「password＝平文（またはタイプ7）、secret＝ハッシュ」と覚えます。ハッシュは元に戻せない変換で、保存されたものを見られてもパスワードそのものは分かりにくくなります（考え方は 73 パスワードの安全な保存）。

    コマンド保存形式安全性
    enable password XXX平文（タイプ0）低い。show running-config でそのまま見える
    enable secret XXXハッシュ（タイプ5＝MD5、8＝PBKDF2-SHA256、9＝scrypt）高い。復元が困難
    username U password XXX平文（タイプ0）低い
    username U secret XXXハッシュ（タイプ5/8/9）高い
    line ... password XXX平文（タイプ0）低い
    上記の平文 ＋ service password-encryptionタイプ7低い（簡単に復号できる）

    4.1 enable password と enable secret の両方を設定した場合

    Router(config)# enable password cisco
Router(config)# enable secret Str0ng!Pass

    このとき enable で使えるのは enable secret の方だけです。enable secret が存在すると enable password は無視されます。両方を順番に入力する仕組みも、どちらでも入れる仕組みもありません。実務では enable secret だけを使います。

    Router# show running-config | include enable
enable secret 9 $9$8hG7bW2yQ0n7yE$Zk0p...（ハッシュ値）
enable password cisco          ← 平文で見えてしまう（しかも使われない）

    4.2 service password-encryption

    Router(config)# service password-encryption

    設定ファイル内の平文のパスワード（line の password、enable password、username ... password）を、弱い方式（タイプ7）で暗号化して表示するコマンドです。

    ! 実行前
line vty 0 4
 password cisco123
! 実行後
line vty 0 4
 password 7 0822455D0A16544541
    • 目的は「肩越しにのぞかれても読めない」程度です。タイプ7は解読ツールで簡単に元に戻せます。
    • 通信は暗号化しません（通信の暗号化は SSH や VPN の役目）。
    • ログインの動作は変わりません。
    • 強い保護が必要なら enable secret や username ... secret を使います。

    ローカルユーザーのパスワードをハッシュで保存するのは username admin secret Cisco!2026 です。username admin password ... は平文で保存され、service password-encryption を使っても弱いタイプ7になるだけです。

    Router# show running-config | include username
username admin secret 9 $9$nhEmQVczB7dqsO$X.HsgL6x1il0RxkOSSvyQYwucySCt7qFm4v7pqCxkKM

    5.パスワードの最小文字数：security passwords min-length

    Router(config)# security passwords min-length 10
Router(config)# enable secret short
% Password too short - must be at least 10 characters. Password configuration failed
    • グローバル設定のコマンドです。
    • これ以降に設定するパスワード（enable secret、username、line の password など）に適用されます。
    • すでに設定されている短いパスワードは自動では変わらないので、設定し直す必要があります。

    似たコマンドとの違いも押さえておきます。

    • service password-encryption … 表示を隠すだけで、長さは制限しません。
    • enable secret 10 … 特権EXECモードのパスワードを「10」にしてしまうコマンドです。
    • exec-timeout 10 0 … 10 分無操作で切断する line の設定です。

    6.ブルートフォース対策：login block-for

    ブルートフォース（総当たり攻撃）は、パスワードを片っ端から試す攻撃です。IOS では次のコマンドで、ログイン失敗が続いたら一定時間ログインを受け付けないようにできます。

    Router(config)# login block-for 120 attempts 3 within 60

    読み方は次のとおりです。

    login block-for 120   attempts 3   within 60
                 │            │           │
                 │            │           └─ 失敗を数える期間（秒）：60秒以内に
                 │            └──────────── 失敗回数：3回失敗したら
                 └───────────────────────── 禁止する時間（秒）：120秒間ログインを受け付けない

    「60 秒以内に 3 回失敗したら、その後 120 秒間ログインを受け付けない」は login block-for 120 attempts 3 within 60 です。数字の位置を逆にした login block-for 60 attempts 3 within 120 では意味が変わってしまうので注意しましょう。

    • グローバル設定のコマンドです。総当たり攻撃の速度を大きく落とせます。
    • ブロック中（quiet mode）は管理者もログインできなくなります。そこで、管理用 PC のアドレスだけはブロックの対象外にする login quiet-mode access-class を組み合わせることがあります。
    Router(config)# access-list 5 permit 192.168.100.0 0.0.0.255
Router(config)# login quiet-mode access-class 5
Router# show login
     A login delay of 1 seconds is applied.
     Quiet-Mode access list 5 is applied.
     Router enabled to watch for login Attacks.
     If more than 3 login failures occur in 60 seconds or less,
     logins will be disabled for 120 seconds.

    Web アプリでのアカウントロックなど、ログインへの攻撃と対策の考え方は 73 ログイン機能への攻撃と対策 も参考になります。

    7.無操作セッションの自動切断：exec-timeout

    Router(config)# line con 0
Router(config-line)# exec-timeout 5 0      ← 5分0秒
Router(config)# line vty 0 4
Router(config-line)# exec-timeout 5 0
    設定意味
    exec-timeout 5 05 分（「分 秒」の順）
    exec-timeout 0 55 秒（順番を間違えた例）
    exec-timeout 0 0タイムアウト無効（切断しない）。本番では非推奨
    （未設定）デフォルトは10 分
    • line（line con 0、line vty 0 4）の中で設定します。
    • ログインしたまま放置された画面を他人に操作される危険を防ぎます。
    • 検証環境では 0 0 にすることもありますが、本番環境では避けます。
    • login block-for はログイン失敗による制限で、無操作セッションの切断とは別物です。

    8.特権レベル（0〜15）

    レベル内容
    0logout、enable、disable、exit、help など、ごく一部のコマンドのみ
    1ユーザーEXECモード（Router>）。確認用の一部のコマンドだけ使える
    2〜14カスタマイズ用。管理者が使えるコマンドを割り当てて使う
    15特権EXECモード（Router#）。すべてのコマンドを実行できる。enable で入るレベル

    特権EXECモードの特権レベルは 15 です。

    Router(config)# username operator privilege 5 secret Op3rator!Pass
Router(config)# privilege exec level 5 show running-config
Router# show privilege
Current privilege level is 15

    ユーザーごとに特権レベルを割り当てると、「オペレーターには確認用のコマンドだけを許可する」といった制御ができます。これは認可（何をしてよいか）の一種で、71 最小権限 の考え方そのものです。より細かく、多数の機器で一元的に制御したい場合は、AAA の認可（TACACS+ など）を使います（60-7 AAA）。

    9.SSH の設定（Telnet を使わない理由）

    Telnet ではなく SSH を使う主な理由は、通信内容が暗号化されるためです。Telnet はパスワードを含むすべての通信を平文で送るので、盗聴されるとユーザー名やパスワードがそのまま読まれてしまいます。

    Telnet（TCP 23）:  PC ── "admin" "cisco123" "show run" ──> ルータ   ← 盗聴すれば丸見え
SSH   （TCP 22）:  PC ── "x9#Fq0...暗号文..." ────────────> ルータ   ← 読めない

    次のような理由は、SSH を使う理由としては誤りです。

    誤った理由正しくは
    通信速度が速い速度は理由ではない。暗号化処理の分むしろわずかに負荷が増える
    設定が不要逆。ホスト名・ドメイン名・RSA 鍵などの設定が必要
    IP アドレスがなくても接続できるSSH も Telnet も IP で通信する。IP なしで接続するならコンソールケーブル

    9.1 SSH の設定手順

    Router(config)# hostname R1                          ! ① ホスト名（デフォルトの Router では鍵を作れない）
R1(config)# ip domain-name example.com               ! ② ドメイン名（①②から鍵の名前が決まる）
R1(config)# crypto key generate rsa modulus 2048     ! ③ RSA鍵の生成（SSHv2には768ビット以上）
R1(config)# ip ssh version 2                         ! ④ SSHv2を使う（推奨）
R1(config)# username admin secret Cisco!2026         ! ⑤ ローカルユーザーの作成
R1(config)# line vty 0 4
R1(config-line)# login local                         ! ⑥ ローカルユーザーで認証
R1(config-line)# transport input ssh                 ! ⑦ vtyへの接続をSSHだけに（Telnetを禁止）
R1(config-line)# exec-timeout 5 0

    確認は次のように行います。

    R1# show ip ssh
SSH Enabled - version 2.0
Authentication methods:publickey,keyboard-interactive,password
Authentication timeout: 120 secs; Authentication retries: 3
...
R1# show ssh
Connection Version Mode Encryption  Hmac         State           Username
0          2.0     IN   aes256-ctr  hmac-sha2-256 Session started admin

    さらに、vty への接続元を管理用ネットワークに限定するには access-class を使います（60-8 ACL の「vty への ACL 適用：access-class」）。

    9.2 SSH と Telnet の比較

    ネットワーク機器をリモートから管理するには、Telnet か SSH を使います。

    項目TelnetSSH
    ポートTCP 23TCP 22
    暗号化なし（パスワードもコマンドも平文）あり
    推奨使わない使う（SSHv2）

    9.3 各コマンドの意味

    鍵を作るときの出力も含めた例です。

    R1(config)# hostname R1                                  ! ① 初期値の Router 以外にする
R1(config)# ip domain-name example.com                   ! ② ドメイン名
R1(config)# crypto key generate rsa modulus 2048         ! ③ RSA鍵の作成
The name for the keys will be: R1.example.com
% The key modulus size is 2048 bits
% Generating 2048 bit RSA keys, keys will be non-exportable...[OK]
R1(config)# username admin secret Str0ngPass!            ! ④ ローカルユーザー
R1(config)# ip ssh version 2                             ! ⑥ SSHv2に限定（推奨）
R1(config)# line vty 0 4
R1(config-line)# login local                             ! ⑤ ローカルユーザーで認証
R1(config-line)# transport input ssh                     ! ⑤ SSHだけ許可（Telnet禁止）
    手順コマンドなぜ必要か
    ①hostnameRSA 鍵の名前が「ホスト名.ドメイン名」で作られるため、初期値の Router のままでは鍵を作れない
    ②ip domain-name同上。鍵の名前にドメイン名が必要
    ③crypto key generate rsaSSH の暗号化に使う RSA 鍵を作成する。鍵を作ると SSH が有効になる。SSHv2 には 768 ビット以上（推奨は 2048 ビット）が必要
    ④username ... secret ...ログインに使うローカルユーザーを作成
    ⑤line vty 0 4 → login local、transport input sshVTY でローカルユーザー認証を使い、接続方式を SSH だけにする
    ⑥ip ssh version 2脆弱性のある SSHv1 を使わせず、SSHv2 だけを受け付ける（グローバル設定）

    SSH の有効化に関係ないコマンド

    • ip http server：Web ブラウザで機器を管理するための HTTP サーバを有効にする。SSH とは無関係です。
    • service password-encryption：設定ファイル内のパスワードを簡易的に暗号化（タイプ7）して表示する。推奨される設定ですが、SSH の有効化には不要です。

    似たコマンドの役割の違いも整理しておきます。

    コマンドモード役割
    ip ssh version 2グローバル設定SSH のバージョンを v2 に限定
    transport input sshline vty接続方式を SSH だけにする（Telnet を禁止）。バージョンは指定しない
    crypto key generate rsaグローバル設定RSA 鍵の作成。バージョンを固定するものではない
    ip domain-nameグローバル設定ドメイン名の設定。RSA 鍵の作成に必要

    9.4 SSH の確認

    R1# show ip ssh
SSH Enabled - version 2.0
Authentication methods:publickey,keyboard-interactive,password
Authentication timeout: 120 secs; Authentication retries: 3
    表示意味
    SSH Enabled - version 2.0SSHv2 だけを受け付ける（ip ssh version 2 設定済み）
    SSH Enabled - version 1.99v1 と v2 の両方を受け付ける状態（既定。v1.99 は「v1 互換の v2」の意味）
    SSH Disabled - version 1.99RSA 鍵がなく SSH が無効

    接続中の SSH セッションは show ssh で確認できます。

    10.ファイル転送プロトコルの比較

    設定ファイルのバックアップや IOS イメージ（機器の OS ファイル）の入れ替えには、ファイル転送プロトコルを使います。

    プロトコルトランスポート/ポート認証暗号化特徴・用途
    TFTPUDP 69なしなし機能が少なく軽い。IOS イメージや設定ファイルのコピーによく使われる。ディレクトリ一覧などの機能はない
    FTPTCP 20/21ユーザー名・パスワードなし（パスワードも平文）制御用とデータ用の 2 つのコネクション
    SCPTCP 22（SSH 上）ありありSSH の仕組みで認証・暗号化しながらコピー
    SFTPTCP 22（SSH 上）ありありSSH 上のファイル転送。ディレクトリ操作も可能
    HTTPTCP 80（任意）なしWeb 閲覧。ファイル取得もできるが安全ではない
    HTTPSTCP 443（任意）あり

    安全性で整理すると次のようになります。

     TFTP  ── 認証なし・暗号化なし   （信頼できるネットワーク内に限る）
 FTP   ── 認証あり・暗号化なし   （パスワードが盗聴されうる）
 SCP / SFTP ── 認証あり・暗号化あり（推奨）

    TFTP は認証も暗号化もないので、使う場所は信頼できるネットワーク内に限ります。

    11.FTP の 2 つのコネクション

    FTP は制御用とデータ転送用の 2 つのコネクション（通信の通り道）を使います。

    コネクションポート用途
    制御用サーバの TCP 21（常に）ログイン、コマンドのやり取り（ls、get、put など）
    データ用（アクティブモード）サーバの TCP 20 から クライアントへファイルの中身やディレクトリ一覧の転送
    データ用（パッシブモード）クライアントからサーバが指定したポートへ同上
     
     アクティブモード                              パッシブモード
 クライアント           サーバ                  クライアント           サーバ
     |--- 制御 → TCP 21 -->|                      |--- 制御 → TCP 21 -->|
     |   PORT (待ち受けポート通知)                 |   PASV            |
     |<-- データ TCP 20 から接続 ---|              |<-- 「ポート5xxxxへ」-|
     |   (サーバ→クライアント方向に                |--- データ → 5xxxx -->|
     |    接続されるのでFWで止まりやすい)           | (どちらもクライアントから接続
                                                  |  するのでFWを越えやすい)

    アクティブモードではサーバからクライアントへ接続しに来るため、クライアント側のファイアウォール（FW）で止まりやすくなります。パッシブモードはどちらの接続もクライアントから始めるので、FW を越えやすいのが特徴です。

    12.Cisco IOS でのファイルのコピー

    copy コマンドは copy <コピー元> <コピー先> の順に書きます。

    コマンド動作
    copy running-config tftp現在の設定（RAM）を TFTP サーバへバックアップ。実行後にサーバのアドレスとファイル名を聞かれる
    copy tftp running-configTFTP サーバのファイルを現在の設定に読み込む（マージする）（コピー元とコピー先が逆）
    copy running-config startup-config現在の設定を NVRAM（電源を切っても消えないメモリ）に保存（再起動後も設定が残る）
    show running-config現在の設定を画面に表示するだけで、保存はしない
    copy tftp flash:TFTP サーバから IOS イメージなどをフラッシュへコピー
    copy scp: flash:SCP で暗号化しながらフラッシュへコピー
    copy flash: ftp:FTP サーバへコピー

    12.1 running-config と startup-config

    名前場所内容
    running-configRAM現在動作中の設定。設定変更は即座にここへ反映される。再起動で消える

    ここまでの設定をまとめると、次のようになります。

!

 login local

    14.よくある誤解

    14.1 パスワード・ログインの保護

    • SSH を使う理由は速度でも設定の簡単さでもなく「暗号化」です。SSH はむしろ設定が必要です（hostname、ip domain-name、RSA 鍵、ユーザー、transport input ssh）。
    • enable password と enable secret の両方がある場合、使えるのは secret だけです。「どちらでも入れる」「両方を順番に入力する」ということはありません。
    • service password-encryption は通信を暗号化しないし、強力でもない（タイプ7は簡単に復号可能）です。
    • password だけでは認証されません。login が必要です。username を作っても login local がないと使われません。
    • vty の設定はコンソールに影響しません。enable secret はコンソール接続時点では要求されません。
    • username ... password は平文です。ハッシュにしたいなら username ... secret を使います。
    • security passwords min-length は既存のパスワードを変えません。
    • login block-for X attempts Y within Z：X＝禁止時間、Z＝失敗を数える期間です。数字の位置に注意しましょう。
    • exec-timeout は「分 秒」の順です。0 5 は 5 秒、0 0 は無効、デフォルトは 10 分です。
    • 特権EXEC は 15。1 はユーザーEXEC、0 はごく一部のみ、2〜14 はカスタマイズ用です。

    14.2 管理方法（コンソール・HTTP/HTTPS など）

    • コンソール接続は 1 台ずつ、その場で作業する方法で、一括管理ではありません。
    • Telnet は 1 台ずつ CLI にログインする方法で、通信は暗号化されません。Web ブラウザでは使いません。
    • TFTP はファイル転送のプロトコルで、機器の管理方法ではありません。
    • HTTP（ip http server）は暗号化されないため、ログイン情報を盗聴される恐れがあります。暗号化するのは HTTPS（ip http secure-server）です。
    • SNMPv1 は監視用のプロトコルで、コミュニティ名が平文で送られます。

    14.3 SSH・ファイル転送

    • TFTP＝UDP 69・認証なしです。「TCP 20/21・ユーザー名とパスワードで認証」は FTP。暗号化するのは SFTP/SCP で、TFTP も FTP も暗号化しません。Web 閲覧は HTTP/HTTPS です。
    • バックアップは copy running-config tftp（コピー元→コピー先）。copy tftp running-config は逆向きでマージ、copy running-config startup-config は NVRAM への保存、show running-config は表示のみです。
    • SSH に必要なのは ip domain-name と crypto key generate rsa（ホスト名とユーザーは別途）。ip http server、service password-encryption は SSH の有効化に不要です。
    • SSHv2 だけを許可するのは ip ssh version 2（グローバル設定）。transport input ssh は接続方式（Telnet 禁止）、crypto key generate rsa は鍵の作成、ip domain-name はドメイン名です。
    • FTP の制御は TCP 21。20 はアクティブモードのデータ用です。UDP 69 は TFTP、TCP 22 は SSH（SFTP・SCP も 22）です。
    • 暗号化して安全にコピーするなら SCP。TFTP は認証も暗号化もなし、FTP はパスワードも平文、HTTP も暗号化されません。

    15.まとめ

    15.1 パスワード・ログインの保護

    • password＝平文/タイプ7、secret＝ハッシュ（5/8/9）。enable も username も secret を使う。
    • ラインは password ＋ login、またはローカルユーザー ＋ login local。
    • SSH の必須設定：hostname、ip domain-name、crypto key generate rsa、ローカルユーザー、transport input ssh。
    • security passwords min-length、login block-for、exec-timeout の書式と意味。
    • 特権レベル 15＝特権EXEC、1＝ユーザーEXEC。

    15.2 管理方法

    • 管理方法：コンソール（直接）、Telnet/SSH（CLI）、HTTP/HTTPS（GUI）、クラウド管理（Meraki）。
    • 暗号化なし：Telnet、HTTP。暗号化あり：SSH、HTTPS。
    • HTTPS は ip http secure-server。HTTP は no ip http server で無効化。
    • 管理者認証：ローカルユーザー、または TACACS+/RADIUS（AAA）。

    15.3 SSH・ファイル転送

    • SSH の設定：hostname → ip domain-name → crypto key generate rsa（SSHv2 は 768 ビット以上）→ username → line vty（login local、transport input ssh）→ ip ssh version 2。
    • show ip ssh：version 2.0＝v2 のみ、1.99＝v1/v2 両対応。
    • TFTP（UDP 69、認証・暗号化なし）／FTP（TCP 20/21、認証あり・暗号化なし）／SCP・SFTP（TCP 22、認証・暗号化あり）。
    • FTP は制御 21・データ 20（アクティブ）。パッシブはクライアントから接続するので FW を越えやすい。
    • copy <元> <先>。running（RAM）→ startup（NVRAM）で保存。

    16.理解度チェック

    Q1. コンソールに password cisco123 だけを設定しました。接続時にパスワードは聞かれますか？

    聞かれません。ラインでパスワードを確認させるには login も必要です（ローカルユーザーで認証するなら login local）。

    Q2. enable password cisco と enable secret Str0ng!Pass の両方がある場合、enable で使えるのはどちらですか？

    enable secret だけです。secret があると enable password は無視されます。しかも enable password は設定ファイルに平文で残るので、使わないのが基本です。

    Q3. service password-encryption を設定すれば、Telnet の通信も安全になりますか？

    なりません。設定ファイル上の平文パスワードを弱いタイプ7で隠すだけで、通信は暗号化しません。通信を守るには SSH を使います。

    Q4. 「60 秒以内に 3 回失敗したら 120 秒間ログインを禁止する」設定を書いてください。

    login block-for 120 attempts 3 within 60 です。block-for の後が禁止時間、within の後が失敗を数える期間です。

    Q5. exec-timeout 0 5 と書いたら、何分で切断されますか？

    5 分ではなく 5 秒です。exec-timeout は「分 秒」の順なので、5 分にするなら exec-timeout 5 0 です。

    Q6. IOS で SSH を使うために、ホスト名とユーザーのほかに必要な設定は何ですか？

    ip domain-name と crypto key generate rsa です。RSA 鍵の名前が「ホスト名.ドメイン名」で作られ、鍵を作ると SSH が有効になります。v2 だけにするなら ip ssh version 2、Telnet を禁止するなら vty で transport input ssh を設定します。

    Q7. 設定を暗号化しながらフラッシュへコピーしたいとき、TFTP・FTP・SCP のどれを使いますか？

    SCP です（copy scp: flash:）。TFTP（UDP 69）は認証も暗号化もなく、FTP（TCP 20/21）は認証はあってもパスワードが平文で流れます。

    Q8. 設定を変更したあと、再起動しても残すにはどうしますか？

    copy running-config startup-config で RAM 上の running-config を NVRAM の startup-config に保存します。保存しないと再起動で消えます。
