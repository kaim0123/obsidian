    60 サーバー・ネットワークセキュリティ

    AAA（RADIUS・TACACS+・802.1X）

    機器が 100 台あると、管理者アカウントを 1 台ずつ作ったり消したりするのは大変です。AAA は「誰か（認証）」「何をしてよいか（認可）」「何をしたか（アカウンティング）」をまとめて管理する考え方で、AAA サーバに任せれば 1 か所で一元管理できます。このページでは、AAA の 3 つの機能、TACACS+ と RADIUS の違い、IOS での設定と方法リストの評価の仕方、そして LAN のポートを認証で守る 802.1X を解説します。

    もとにしたノート：60_サーバー・ネットワークセキュリティ/07_AAA（RADIUS・TACACS+・802.1X）

    ひとことで言うと

    AAA＝認証（誰か）→認可（何をしてよいか）→アカウンティング（何をしたか）。機器の管理者には TACACS+（TCP 49・本文全体を暗号化・コマンド単位の認可）、ネットワークの利用者には RADIUS（UDP 1812/1813・パスワードだけ暗号化・802.1X や VPN）を使います。方法リストの最後には、サーバに届かないときの予備として local を入れます。

    このページは、60-6 ネットワーク機器への管理アクセス と 73 認証と認可の違い を読んでいると理解しやすいです。

    1.AAA の 3 つの機能

    AAA は、アクセスを管理する 3 つの機能の頭文字です。

    機能問い例
    認証（Authentication）あなたは誰かユーザー名とパスワードで本人確認
    認可（Authorization）何をしてよいかこのユーザーは show だけ、あのユーザーは configure も可
    アカウンティング（Accounting）何をしたか誰が、いつログインし、どのコマンドを実行したかを記録
     
     ユーザー ──①ログイン──> [ルータ] ──②「この人は本物？」──────> [AAAサーバ]
                                 <──③認証OK───────────────────
          ──④コマンド──> [ルータ] ──⑤「このコマンドを許可する？」─> （認可）
                                 <──⑥許可/拒否─────────────────
                         [ルータ] ──⑦「誰が何をしたか」の記録──> （アカウンティング）

    「ログインしたユーザーが、どのコマンドを実行できるかを制御する」のは認可（Authorization）です。なお、暗号化は AAA の要素ではありません。認証と認可の違いそのものは 73 認証と認可の違い でくわしく扱っています。アカウンティングで残した記録は、60-5 ログ監査と侵入の検知 のような監査にも使えます。

    なぜ AAA サーバを使うのか

    機器が 100 台あると、ローカルユーザーを 100 台それぞれで作成・変更・削除しなければなりません。AAA サーバ（例：Cisco ISE）を使えば、ユーザーを一元管理でき、退職者のアカウントの無効化も 1 か所で確実に行えます。

    2.TACACS+ と RADIUS

    機器（ルータ、スイッチ、WLC など）と AAA サーバの間の通信には、TACACS+ か RADIUS を使います。

    項目TACACS+RADIUS
    開発・標準Cisco が開発IETF の標準（オープン）
    トランスポートTCP 49UDP 1812（認証/認可）、1813（アカウンティング）（古い実装では 1645/1646）
    暗号化の範囲パケットの本文全体を暗号化パスワードだけを暗号化
    AAA の扱い認証・認可・アカウンティングを個別に扱える認証と認可をまとめて扱う
    コマンドごとの認可できる基本的にできない
    主な用途ネットワーク機器にログインする管理者の認証とコマンド制御ネットワークを利用するユーザーの認証（無線 LAN の 802.1X、有線 802.1X、VPN 接続）

    覚え方は次のとおりです。

    TACACS+ … TCP / 全体暗号化 / Cisco / 機器の管理者（デバイス管理）
RADIUS  … UDP / パスワードだけ / IETF標準 / ネットワーク利用者（ネットワークアクセス）

    取り違えやすいポイント

    TACACS+ の特徴は「TCP（49 番）を使い、パケットの本文全体を暗号化する」ことです。「UDP でパスワードだけ暗号化」は RADIUS の特徴です。また、どちらも「IEEE が定めたオープンな標準」ではありません（TACACS+ は Cisco 開発、RADIUS は IETF 標準）。TACACS+ や RADIUS は「無線 LAN の暗号化方式」でもありません。それは WPA2/WPA3 のことです。

    3.IOS での AAA 設定と方法リスト

    R1(config)# username admin secret Local!Backup1          ! サーバ障害時の予備のローカルユーザー
R1(config)# aaa new-model                                 ! ① AAAを有効化（すべての始まり）
R1(config)# tacacs server TAC1                            ! ② TACACS+サーバの定義
R1(config-server-tacacs)# address ipv4 192.168.100.10
R1(config-server-tacacs)# key T@cacsKey
R1(config-server-tacacs)# exit
R1(config)# aaa authentication login default group tacacs+ local    ! ③ 認証の方法リスト
R1(config)# aaa authorization exec default group tacacs+ local      ! （認可）
R1(config)# aaa accounting commands 15 default start-stop group tacacs+   ! （アカウンティング）

    方法リストは「どの方法で、どの順番で認証するか」を並べたリストです。

    3.1 方法リストの評価

    aaa authentication login default group tacacs+ local は、認証方法を左から順に試します。ただし「次へ進む」のは前の方法が使えない（エラー・無応答）ときだけです。

    ログイン要求
   │
   v
[TACACS+サーバに問い合わせ]
   │
   ├─ 応答あり：認証成功 ──────> ログイン許可
   ├─ 応答あり：認証失敗（PASS/FAIL の FAIL）──> ログイン拒否（ここで終了。local は試さない）
   └─ 応答なし（サーバ停止・到達不能＝ERROR）
          │
          v
     [ローカルユーザー（local）で認証]
          ├─ 成功 ─> ログイン許可
          └─ 失敗 ─> ログイン拒否

    この設定の読み方として、正しいもの・誤ったものを並べると次のようになります。

    解釈正誤
    TACACS+ サーバに到達できない場合にローカルユーザーで認証する◯
    TACACS+ とローカルの両方で成功する必要がある✕（予備であって二重認証ではない）
    TACACS+ でパスワードが間違っていた場合にローカルで再認証✕（サーバが「失敗」を返したらそこで終了）
    ローカルを優先し、ないユーザーだけ TACACS+✕（書いた順＝TACACS+ が優先）

    AAA サーバが故障したり、ネットワークが切れたりしたときに誰もログインできなくなるのを防ぐため、最後に local を入れるのが一般的で、そのためにローカルユーザーを作っておきます。

    4.802.1X（ポートベースの認証）

    802.1X は、LAN のポート（有線ならスイッチのポート、無線なら AP との接続）を、認証に成功した端末にだけ開放する仕組みです。3 つの役割があります。

    役割担当する機器内容
    サプリカント（要求者）PC などの端末（802.1X クライアントソフト）認証を受ける側
    オーセンティケータ（認証者）スイッチ、無線 AP/WLC端末と RADIUS サーバの間で認証のやり取りを中継し、結果に応じてポートを開く
    認証サーバRADIUS サーバ（例：Cisco ISE）ユーザー情報を持ち、実際に認証を判断する

    EAPoL（EAP over LAN）は、端末とスイッチの間で認証のやり取りを運ぶための形式です。スイッチはその中身（EAP）を RADIUS に載せ替えてサーバへ中継します。ノートの図は次のとおりです。

     [PC]                        [スイッチ]                       [RADIUSサーバ / ISE]
 サプリカント               オーセンティケータ                  認証サーバ
    │  ── EAPoL（EAP over LAN）──>  │  ── RADIUS（EAPを中継）──>  │
    │  <────────────────────────── │  <──────────────────────── │
    │                               │      Access-Accept / Reject │
    │                     認証成功ならポートを開放
    │                     （成功するまでは EAPoL 以外は通さない）

    有線 LAN の 802.1X で、PC を接続されたスイッチの役割はオーセンティケータです。DHCP サーバは 802.1X の 3 つの役割に含まれません。

    認証に成功するまで、スイッチのポートは認証用の通信（EAPoL）以外を通さないので、許可されていない端末を LAN につないでも通信できません。無線 LAN のエンタープライズモードも同じ仕組みで、オーセンティケータが無線 AP/WLC になります。

    SW(config)# aaa new-model
SW(config)# radius server ISE
SW(config-radius-server)# address ipv4 192.168.100.20 auth-port 1812 acct-port 1813
SW(config-radius-server)# key R@diusKey
SW(config)# aaa authentication dot1x default group radius
SW(config)# dot1x system-auth-control
SW(config)# interface g0/1
SW(config-if)# switchport mode access
SW(config-if)# authentication port-control auto
SW(config-if)# dot1x pae authenticator

    802.1X と組み合わせて使うスイッチのポート保護（ポートセキュリティなど）は 60-9 L2セキュリティ で扱います。

    5.よくある誤解

    • 「どのコマンドを実行できるか」は認可です。認証（本人確認）、アカウンティング（記録）と区別しましょう。暗号化は AAA の要素ではありません。
    • TACACS+＝TCP 49・全体暗号化・Cisco、RADIUS＝UDP 1812/1813・パスワードのみ暗号化・IETF 標準。逆に覚えてしまいがちなので注意します。「IEEE 標準」も誤りです。
    • TACACS+ や RADIUS は無線 LAN の暗号化方式ではありません（それは WPA2/WPA3）。
    • 方法リストの local は「サーバに到達できないときの予備」です。サーバが「認証失敗」と答えたら local は試しません。両方での認証でも、ローカル優先でもありません。
    • 802.1X でスイッチはオーセンティケータです。サプリカントは端末、認証サーバは RADIUS。DHCP サーバは無関係です。

    6.まとめ

    • AAA＝認証（誰か）→認可（何をしてよいか）→アカウンティング（何をしたか）。AAA サーバの例は Cisco ISE。
    • TACACS+ は機器管理者のコマンド制御向け、RADIUS はネットワーク利用者（802.1X、VPN）の認証向け。
    • aaa new-model で開始。方法リストは左から順、次へ進むのはエラー（無応答）時のみ。最後に local。
    • 802.1X の 3 役割：サプリカント・オーセンティケータ・認証サーバ。認証前は EAPoL のみ通過。

    7.理解度チェック

    Q1. 「ログインしたユーザーが show だけ使えて configure は使えない」ように制御するのは、AAA のどの機能ですか？

    認可（Authorization）です。認証は「誰か」の確認、アカウンティングは「何をしたか」の記録です。

    Q2. TCP 49 を使い、パケットの本文全体を暗号化するのは TACACS+ と RADIUS のどちらですか？

    TACACS+ です。RADIUS は UDP 1812/1813 を使い、暗号化するのはパスワードだけです。

    Q3. 管理者ごとに実行できるコマンドを細かく制御したいとき、どちらのプロトコルが向いていますか？

    TACACS+ です。認証・認可・アカウンティングを個別に扱え、コマンドごとの認可ができます。RADIUS は認証と認可をまとめて扱い、コマンド単位の認可は基本的にできません。

    Q4. aaa authentication login default group tacacs+ local で、TACACS+ サーバがパスワード誤りとして「失敗」を返しました。local で再認証されますか？

    されません。次の方法へ進むのは、サーバが無応答・到達不能（ERROR）のときだけです。サーバが FAIL を返したら、そこでログイン拒否になります。

    Q5. 方法リストの最後に local を入れておくのはなぜですか？

    AAA サーバの故障やネットワーク断のときに、誰も機器にログインできなくなるのを防ぐためです。そのために予備のローカルユーザーを作っておきます。

    Q6. 有線 LAN の 802.1X で、PC がつながっているスイッチの役割は何ですか？

    オーセンティケータです。端末（サプリカント）と RADIUS サーバ（認証サーバ）の間で認証のやり取りを中継し、結果に応じてポートを開きます。

    Q7. 802.1X が有効なポートに、許可されていない PC をつなぐとどうなりますか？

    認証に成功するまで EAPoL 以外の通信は通らないので、LAN で通信できません。
