    60 サーバー・ネットワークセキュリティ

    L2セキュリティ（ポートセキュリティ・DHCPスヌーピング・DAI）

    スイッチ（レイヤー2）は、社内の端末が直接つながる場所です。社内に入り込んだ攻撃者や不正な機器は、まず L2 の仕組みを悪用します。このページでは、MAC フラッディング・DHCP スタベーション／スプーフィング・ARP スプーフィング・VLAN ホッピングなどの攻撃と、ポートセキュリティ・DHCP スヌーピング・DAI・BPDU ガードなどの対策機能を対応させて学びます。

    もとにしたノート：60_サーバー・ネットワークセキュリティ/09_L2セキュリティ（ポートセキュリティ・DHCPスヌーピング・DAI）

    ひとことで言うと

    攻撃ごとに効く機能が決まっています。MAC をあふれさせる攻撃にはポートセキュリティ、偽 DHCP サーバには DHCP スヌーピング（正規サーバ側だけ trusted）、偽 ARP には DAI（DHCP スヌーピングの表と照合）、VLAN ホッピングにはアクセス固定・DTP 無効・ネイティブ VLAN 変更、不正スイッチには BPDU ガードを使います。

    このページは、スイッチと MAC アドレステーブルの基本（11_コンピューターサイエンスの「16ルーターとスイッチとハブとNAT」のノート）と 10-6 DHCPとNTP を読んでいると理解しやすいです。

    1.L2 攻撃と対策の対応表

    攻撃手口被害主な対策
    MAC フラッディング送信元 MAC を次々に変えた大量のフレームで MAC アドレステーブルをあふれさせるスイッチがハブのようにフラッディング → 盗聴ポートセキュリティ（学習できる MAC 数の制限）
    DHCP スタベーション偽の MAC で大量の DHCPDISCOVER → アドレスを使い切らせる正規の端末が IP をもらえない（DoS）DHCP スヌーピング（レート制限）、ポートセキュリティ
    DHCP スプーフィング偽の DHCP サーバとして応答し、偽のゲートウェイ/DNS を配る通信を攻撃者経由にされる（中間者攻撃）DHCP スヌーピング（untrusted ポートのサーバ応答を破棄）
    ARP スプーフィング「ゲートウェイの IP は自分の MAC だ」という偽 ARP を送る通信を攻撃者に引き寄せる（中間者攻撃）DAI（ダイナミック ARP インスペクション）
    VLAN ホッピング（スイッチスプーフィング）DTP で交渉してトランクを作る全 VLAN にアクセスアクセスポートに固定・DTP 無効（switchport nonegotiate）
    VLAN ホッピング（ダブルタギング）外側にネイティブ VLAN、内側に標的 VLAN のタグを付ける別の VLAN へフレームを送り込むネイティブ VLAN を未使用 VLAN に変更
    不正なスイッチの接続（STP 操作）PortFast のポートで BPDU を送るルートブリッジの乗っ取りなどBPDU ガード

    中間者攻撃とは、通信の間に割り込んで、内容を盗み見たり書き換えたりする攻撃です。DTP はスイッチ同士がトランク（複数 VLAN を運ぶ回線）を自動で作るための交渉プロトコル、STP はループを防ぐプロトコルで、BPDU はその制御フレームです。

    2.MAC フラッディングとポートセキュリティ

    2.1 MAC フラッディング

    スイッチは MAC アドレステーブルを使って、宛先 MAC のあるポートだけにフレームを転送します。テーブルの容量には上限があります。

    攻撃者がランダムな送信元MACのフレームを大量に送る
  aa:01 → ... aa:02 → ... aa:03 → ... （数万個）
           │
           v
  MACアドレステーブルが満杯 → 新しい宛先を学習できない
           │
           v
  宛先不明のフレーム（ユニキャストフラッディング）を全ポートへ送る ＝ ハブ状態
           │
           v
  攻撃者のポートにも他人の通信が届く → 盗聴できる

    「送信元 MAC アドレスを次々に変えた大量のフレームで、MAC アドレステーブルをあふれさせる」のが MAC フラッディングです。対策はポートセキュリティで、1 つのポートで学習できる MAC アドレスの数を制限します。

    2.2 ポートセキュリティの基本

    ポートセキュリティは、スイッチのポートに接続できる端末を MAC アドレスで制限する機能です。許可する MAC アドレスや、その数を制限します。許可していない MAC アドレスの端末がつながると違反として扱います。

    SW(config)# interface g0/1
SW(config-if)# switchport mode access                          ! ① アクセスポートにする（必須）
SW(config-if)# switchport port-security                        ! ② 機能を有効化（必須）
SW(config-if)# switchport port-security maximum 2              ! 許可するMACの数（デフォルト1）
SW(config-if)# switchport port-security mac-address sticky     ! 学習したMACを設定に自動追加
SW(config-if)# switchport port-security violation restrict     ! 違反時の動作（デフォルト shutdown）
    • ポートセキュリティを使うには、ポートをアクセスポート（switchport mode access）にして、switchport port-security で機能を有効にする必要があります（DTP の dynamic モードのままではコマンドが拒否されます）。
    • 許可する数は switchport port-security maximum で指定します。デフォルトは 1 です。
    • 静的に登録するなら switchport port-security mac-address 0011.2233.4455 とします。

    2.3 sticky

    switchport port-security mac-address sticky は、ポートで学習した MAC アドレスを、許可するアドレスとして running-config に自動で追加します。1 台ずつ手動で登録する手間が省けます。

    SW# show running-config interface g0/1
interface GigabitEthernet0/1
 switchport mode access
 switchport port-security
 switchport port-security mac-address sticky
 switchport port-security mac-address sticky 0011.2233.4455    ← 自動で追加された
    • running-config に書き込まれるので、copy running-config startup-config で保存すれば再起動後も維持されます（保存しなければ再起動で消えます）。
    • 許可する数とは無関係です（数は maximum）。
    • err-disabled からの自動復旧とは無関係です（それは errdisable recovery）。
    • MAC アドレステーブルのエージング（保持時間）とは無関係です。

    2.4 違反時の動作（violation モード）

    モードポートフレームログ（syslog/SNMP）違反カウンタ
    shutdown（デフォルト）停止（err-disabled）破棄出す増える
    restrict止めない破棄出す増える
    protect止めない破棄出さない増えない

    覚え方は「ポートを止めるか」「ログを出すか」の 2 軸です。

                ポートを止める   ログを出す
shutdown         ◯              ◯
restrict         ✕              ◯
protect          ✕              ✕

    なお、sticky は違反時の動作ではなく、学習した MAC を設定に保存する機能です。

    2.6 err-disabled からの復旧

    shutdown モードで違反すると、ポートは err-disabled（エラーで自動停止した状態）になります。

    %PM-4-ERR_DISABLE: psecure-violation error detected on Gi0/1, putting Gi0/1 in err-disable state
%PORT_SECURITY-2-PSECURE_VIOLATION: Security violation occurred, caused by MAC address 00aa.bbcc.ddee on port GigabitEthernet0/1.

    手動での復旧手順は次のとおりです。

    ① 原因を取り除く（許可していない端末を外す、または許可設定を見直す）
② SW(config)# interface g0/1
   SW(config-if)# shutdown          ← いったん管理的に無効にする
   SW(config-if)# no shutdown       ← 有効にすると err-disabled が解除される
    • no shutdown だけでは復旧しません。先に shutdown が必要です。
    • clear mac address-table は MAC アドレステーブルを消すだけで、err-disabled は解除されません。
    • 自動復旧（errdisable recovery）を設定していなければ、自動では復旧しません。
    • 原因を取り除かずに復旧させると、すぐにまた違反になります。

    自動復旧の設定は次のとおりです。

    SW(config)# errdisable recovery cause psecure-violation
SW(config)# errdisable recovery interval 300         ! 300秒後に自動復旧（デフォルトも300秒）

    3.DHCP スタベーションと DHCP スプーフィング

    DHCP は、端末に IP アドレスやゲートウェイ・DNS を自動で配る仕組みです（10-6 DHCPとNTP）。この仕組みを悪用した 2 段構えの攻撃があります。

    【ステップ1：DHCPスタベーション（枯渇攻撃）】
 攻撃者 ── DHCPDISCOVER（偽MAC #1）──> 正規DHCPサーバ  → 10.0.0.10 を貸し出す
        ── DHCPDISCOVER（偽MAC #2）──>                → 10.0.0.11 を貸し出す
        ── ...（数百〜数千回）       ──>                → アドレスプールが空に
 → 正規の端末がアドレスをもらえない（DoS）

【ステップ2：DHCPスプーフィング（偽DHCPサーバ）】
 新しいPC ── DHCPDISCOVER ──> （正規サーバは枯渇して応答できない）
 攻撃者   ── DHCPOFFER：IP=10.0.0.50, GW=攻撃者のIP, DNS=攻撃者のIP ──> 新しいPC
 → PCの通信はすべて攻撃者を経由する（中間者攻撃）

    「偽の MAC アドレスで大量の DHCPDISCOVER を送り、アドレスを使い切らせる」のが DHCP スタベーションです。偽の DHCP サーバとして応答するのは DHCP スプーフィングで、スタベーションはその準備にもなります。

    対策は DHCP スヌーピング（偽サーバの遮断、DHCP メッセージのレート制限）とポートセキュリティ（1 ポートの偽 MAC の数を制限）です。

    4.DHCP スヌーピング

    4.1 仕組み

    DHCP スヌーピングは、スイッチのポートを trusted（信頼） と untrusted（非信頼） に分け、untrusted ポートから届いた DHCP サーバの応答（OFFER/ACK など）を破棄します。

    ポート設定理由
    正規の DHCP サーバにつながるポート（アップリンクなど）trustedサーバの応答を受け付けるため
    一般ユーザーの PC がつながるポートuntrusted（デフォルトのまま）不正な DHCP サーバがつながっても、その応答を破棄できる
    • すべて trusted にすると、不正な DHCP サーバを防げません。
    • DHCP スヌーピングを有効にすると、デフォルトですべて untrusted になります。どのポートも trusted にしないと、正規のサーバの応答も届かなくなります。

    さらに、DHCP スヌーピングは「どのポートの、どの MAC アドレスに、どの IP アドレスが割り当てられたか」を記録したバインディングテーブルを作ります。これが DAI などで使われます。

    SW# show ip dhcp snooping binding
MacAddress          IpAddress        Lease(sec)  Type           VLAN  Interface
------------------  ---------------  ----------  -------------  ----  --------------------
00:11:22:33:44:55   10.0.10.21       86250       dhcp-snooping   10    GigabitEthernet0/1
00:11:22:33:44:66   10.0.10.22       86100       dhcp-snooping   10    GigabitEthernet0/3
Total number of bindings: 2

    4.2 設定

    SW(config)# ip dhcp snooping                         ! ① 機能の有効化（グローバル）
SW(config)# ip dhcp snooping vlan 10                 ! ② 対象のVLANを指定（これがないとどのVLANでも動かない）
SW(config)# interface g0/24
SW(config-if)# ip dhcp snooping trust                ! ③ 正規のDHCPサーバの方向のポートだけ trusted
SW(config)# interface range g0/1 - 23
SW(config-if-range)# ip dhcp snooping limit rate 10  ! （任意）untrustedポートのDHCPメッセージを毎秒10個に制限＝スタベーション対策
    SW# show ip dhcp snooping
Switch DHCP snooping is enabled
DHCP snooping is configured on following VLANs:
10
...
Interface                  Trusted    Allow option    Rate limit (pps)
-----------------------    -------    ------------    ----------------
GigabitEthernet0/24        yes        yes             unlimited
GigabitEthernet0/1         no         no              10

    DHCP スヌーピングを動かすには、ip dhcp snooping に加えて「ip dhcp snooping vlan 10 のように対象の VLAN を指定する」ことが必要です。次の設定では代わりになりません。

    設定なぜ代わりにならないか
    すべてのポートで ip dhcp snooping trust不正な DHCP サーバを防げない。trust は正規サーバ側のポートだけ
    ip arp inspection vlan 10DAI の設定。DHCP スヌーピングを働かせるものではない
    switchport port-securityポートセキュリティの設定。別の機能

    補足

    レート制限を超えたポートは err-disabled になります（errdisable recovery cause dhcp-rate-limit で自動復旧可能）。

    5.ダイナミック ARP インスペクション（DAI）

    5.1 ARP スプーフィング（ARP ポイズニング）

    ARP は、IP アドレスから MAC アドレスを調べる仕組みです。端末は結果を ARP キャッシュに覚えておきますが、偽の応答で書き換えられてしまうことがあります。

    正常:   PC-A の ARPキャッシュ   10.0.10.1（GW） → GWのMAC（00:aa:...:01）

攻撃:   攻撃者 ── 偽のARP応答「10.0.10.1 は 00:bb:...:99（攻撃者のMAC）です」──> PC-A
        PC-A の ARPキャッシュ   10.0.10.1（GW） → 攻撃者のMAC   ← 書き換えられた
        → PC-A がゲートウェイに送るつもりのフレームは攻撃者に届く（中間者攻撃）

    5.2 DAI の仕組み

    DAI は、untrusted ポートで受信した ARP に書かれた「IP アドレスと MAC アドレスの組み合わせ」を、DHCP スヌーピングのバインディングテーブルと照合し、一致しなければ破棄します。

    受信したARP： 送信元IP 10.0.10.1 / 送信元MAC 00:bb:...:99（Gi0/2）
バインディングテーブル： 10.0.10.1 と 00:bb:...:99 の組み合わせは存在しない
→ 破棄＋ログ

    DAI が照合に使えるのはバインディングテーブルだけで、ほかの表では代わりになりません。

    表DAI の参照先になるか
    DHCP スヌーピングのバインディングテーブル◯ IP と MAC の対応が記録されている
    MAC アドレステーブル✕ スイッチの転送用の表。MAC とポートの対応で、IP アドレスとの対応は記録されていない
    ルーティングテーブル✕ ルータが宛先ネットワークへの経路を決める表
    NAT テーブル✕ アドレス変換の対応表

    そのため、DAI を使うには先に DHCP スヌーピングを有効にしておく必要があります（静的 IP の機器は ARP ACL で許可します）。

    SW(config)# ip dhcp snooping
SW(config)# ip dhcp snooping vlan 10
SW(config)# ip arp inspection vlan 10                ! DAIを有効化
SW(config)# interface g0/24
SW(config-if)# ip dhcp snooping trust
SW(config-if)# ip arp inspection trust               ! アップリンクは DAI でも trusted
    SW# show ip arp inspection vlan 10
 Vlan     Configuration    Operation   ACL Match          Static ACL
 ----     -------------    ---------   ---------          ----------
   10     Enabled          Active

    6.VLAN ホッピングとその対策

    VLAN ホッピングは、本来アクセスできない別の VLAN の通信に入り込む攻撃で、2 つの手口があります。

    6.1 スイッチスプーフィング

    攻撃者PC ── DTP「トランクにしよう」──> スイッチのポート（dynamic auto/desirable のまま）
         <── トランク成立 ──
→ 攻撃者PCがすべてのVLANのフレームを送受信できる

    対策は、端末用のポートをアクセスポートに固定し、DTP を無効にすることです。

    SW(config)# interface range g0/1 - 23
SW(config-if-range)# switchport mode access
SW(config-if-range)# switchport nonegotiate     ! DTPフレームを送らない

    6.2 ダブルタギング（二重タグ）

    ネイティブ VLAN は、トランク上でタグを付けずに送る VLAN です。この性質を悪用します。

    攻撃者（VLAN 1 = ネイティブVLANのアクセスポート）
  送信フレーム: [外側タグ VLAN1][内側タグ VLAN20][データ]
      │
  SW1: 外側タグ＝ネイティブVLAN(1) → トランクではネイティブVLANはタグなしで送るので「外側タグを外す」
      │  トランク上: [内側タグ VLAN20][データ]
      v
  SW2: VLAN20 のタグ付きフレームとして受信 → VLAN20 の被害者へ転送
  ※ 一方向の攻撃（応答は返ってこない）

    対策は、トランクのネイティブ VLAN を、どの端末も使っていない未使用の VLAN に変更することです。

    SW(config)# vlan 999
SW(config-vlan)# name UNUSED_NATIVE
SW(config)# interface g0/24
SW(config-if)# switchport mode trunk
SW(config-if)# switchport trunk native vlan 999
SW(config-if)# switchport nonegotiate

    対策として有効なもの・逆効果なものを整理します。

    対策判定
    端末用ポートをアクセスに固定し DTP を無効◯
    ネイティブ VLAN を未使用の VLAN に変更◯
    ネイティブ VLAN をデフォルトの VLAN 1 のまま✕ VLAN 1 は初期状態で全ポートが所属しており、攻撃に利用されやすい
    すべてのポートをトランクにする✕ 端末が複数 VLAN の通信にアクセスできてしまう

    その他のベストプラクティスとして、未使用のポートは shutdown して未使用 VLAN に割り当てる、VLAN 1 を業務に使わない、といった運用もあります。

    7.BPDU ガード

    BPDU ガードは、PortFast（端末用ポートをすぐ使える状態にする設定）を設定したポートで BPDU（STP の制御フレーム）を受信したら、ポートを err-disabled にして停止する機能です。不正なスイッチの接続や STP の乗っ取りを防ぎます。

    SW(config-if)# spanning-tree portfast
SW(config-if)# spanning-tree bpduguard enable

    8.機能の比較まとめ

    機能何を防ぐか見るもの
    ポートセキュリティ許可されていない端末の接続、MAC フラッディング送信元 MAC アドレス・MAC の数
    DHCP スヌーピング不正な DHCP サーバ、DHCP スタベーションDHCP メッセージの種類と受信ポート（trusted/untrusted）
    BPDU ガードPortFast ポートへのスイッチ接続BPDU の受信
    ダイナミック ARP インスペクションARP のなりすましARP の IP/MAC の組とバインディングテーブル

    ポートそのものを「認証に成功した端末にだけ開く」なら、60-7 AAA の 802.1X と組み合わせます。L3 での通信制御は 60-8 ACL で扱いました。

    9.よくある誤解

    • MAC で端末を制限するのはポートセキュリティです。DHCP スヌーピング・BPDU ガード・DAI と機能を混同しないようにしましょう。
    • 違反時のデフォルトは shutdown（err-disabled）。restrict＝止めない・ログあり、protect＝止めない・ログなし。sticky は違反モードではありません。
    • sticky は「学習した MAC を running-config に追加」する機能です。数の制限（maximum、デフォルト 1）、自動復旧（errdisable recovery）、エージングとは無関係で、保存しないと再起動で消えます。
    • err-disabled は shutdown → no shutdown で戻します。no shutdown だけ、clear mac address-table では戻りません。自動復旧は設定しない限り行われません。
    • DHCP スヌーピングの trusted は正規の DHCP サーバ側だけ。全部 trusted は無意味で、どこも trusted にしないと正規の応答も届きません。
    • DHCP スヌーピングは ip dhcp snooping だけでは動きません。ip dhcp snooping vlan が必要です。ip arp inspection vlan は DAI の設定です。
    • DAI の参照先は DHCP スヌーピングのバインディングテーブルです（MAC アドレステーブルには IP の情報がありません）。
    • MAC フラッディング（テーブルをあふれさせる）、ARP スプーフィング（IP のなりすまし）、DHCP スタベーション（アドレス枯渇）、DHCP スプーフィング（偽サーバ）、VLAN ホッピング（別 VLAN への侵入）を区別しましょう。
    • VLAN ホッピング対策は「アクセス固定＋DTP 無効」「ネイティブ VLAN を未使用 VLAN に」。VLAN 1 のまま・全ポートトランクは逆効果です。

    10.まとめ

    • ポートセキュリティ：switchport mode access → switchport port-security → maximum（既定 1）／mac-address sticky／violation {shutdown|restrict|protect}（既定 shutdown）。
    • err-disabled の復旧：原因除去 → shutdown → no shutdown。自動は errdisable recovery cause psecure-violation。確認は show port-security interface、show interfaces status。
    • DHCP スヌーピング：ip dhcp snooping → ip dhcp snooping vlan X → 正規サーバ側に ip dhcp snooping trust。limit rate でスタベーション対策。バインディングテーブルを作る。
    • DAI はバインディングテーブルを参照 → DHCP スヌーピングが前提。
    • VLAN ホッピング：スイッチスプーフィング（DTP）とダブルタギング（ネイティブ VLAN）。

    11.理解度チェック

    Q1. 送信元 MAC を次々に変えた大量のフレームでスイッチを「ハブ状態」にする攻撃と、その対策は？

    MAC フラッディングです。MAC アドレステーブルがあふれると宛先不明のフレームが全ポートに流れ、盗聴できるようになります。対策はポートセキュリティで、1 ポートで学習できる MAC の数を制限します。

    Q2. ポートセキュリティの違反モードで、ポートは止めないがログは出すのはどれですか？

    restrict です。shutdown（デフォルト）はポートを止めてログも出し、protect は止めずログも出しません。sticky は違反モードではありません。

    Q3. err-disabled になったポートを手動で戻す手順は？

    まず原因（許可していない端末など）を取り除き、インターフェースで shutdown → no shutdown を実行します。no shutdown だけや clear mac address-table では戻りません。

    Q4. DHCP スヌーピングで trusted にすべきポートはどこですか？

    正規の DHCP サーバにつながるポート（アップリンクなど）だけです。全部 trusted にすると偽サーバを防げず、どこも trusted にしないと正規サーバの応答も届きません。

    Q5. ip dhcp snooping を設定したのに動きません。何が足りない可能性が高いですか？

    対象 VLAN の指定（ip dhcp snooping vlan 10 など）です。これがないとどの VLAN でも動きません。

    Q6. DAI が ARP の正しさを判断するときに参照する表は何ですか？

    DHCP スヌーピングのバインディングテーブルです。IP と MAC の対応が記録されているのはこの表だけで、MAC アドレステーブルには IP の情報がありません。そのため DAI には DHCP スヌーピングが前提になります。

    Q7. ダブルタギングによる VLAN ホッピングを防ぐ対策は？

    トランクのネイティブ VLAN を、どの端末も使っていない未使用の VLAN（例：999）に変えることです。VLAN 1 のままにしておくと攻撃に使われやすくなります。

    Q8. 端末用（PortFast）のポートに勝手にスイッチをつながれるのを防ぐ機能は？

    BPDU ガードです。PortFast ポートで BPDU を受信したらポートを err-disabled にして止めます。
