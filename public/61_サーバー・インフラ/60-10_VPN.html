    60 サーバー・ネットワークセキュリティ

    VPN（サイト間・リモートアクセス・IPsec・GRE）

    VPN（Virtual Private Network）は、インターネットのような信頼できない回線の上に、暗号化された仮想的な専用線（トンネル）を作る技術です。このページでは、サイト間 VPN とリモートアクセス VPN の違い、IPsec が提供する 4 つのセキュリティ機能、トンネルモードとトランスポートモード、そして GRE と GRE over IPsec を解説します。

    もとにしたノート：60_サーバー・ネットワークセキュリティ/10_VPN（サイト間・リモートアクセス・IPsec・GRE）

    ひとことで言うと

    拠点同士を常時つなぐのがサイト間 VPN（主に IPsec）、個人の端末から必要なときにつなぐのがリモートアクセス VPN（主に TLS）です。IPsec は機密性・完全性・認証・リプレイ防止を提供し、サイト間 VPN では元のパケットを丸ごと暗号化するトンネルモードを使います。GRE は暗号化できない代わりにマルチキャストを運べるので、IPsec と組み合わせて使います。

    このページは、20-4 HTTPSとTLS証明書 と 60-8 ACL を読んでいると理解しやすいです。VPN の位置づけ（ネットワーク防御の全体の中で何を守るか）は 71 ネットワークと端末の防御 でも紹介しています。

    1.サイト間 VPN とリモートアクセス VPN

    項目サイト間 VPN（site-to-site VPN）リモートアクセス VPN
    つなぐもの拠点と拠点（本社⇔支社）個々の端末（在宅勤務の PC など）⇔社内
    トンネルを張る機器拠点のルータやファイアウォール同士端末の VPN クライアントソフト⇔VPN 装置（ASA/FTD など）
    接続のタイミング常時（常設）必要なときに接続
    端末の特別なソフト不要（端末は普段どおり通信するだけ）必要（Cisco Secure Client〔旧 AnyConnect〕など）または Web ブラウザ
    主なプロトコルIPsecTLS（IPsec/IKEv2 を使うこともある）

    ノートの図は次のとおりです。

    【サイト間VPN】
 本社LAN ── [R-本社] ══════ IPsecトンネル（インターネット経由・常時）══════ [R-支社] ── 支社LAN
             203.0.113.1                                              198.51.100.1
  PCは普段どおり通信するだけ。暗号化はルータが行う。

【リモートアクセスVPN】
 在宅PC（Cisco Secure Client）══ TLS（TCP 443）トンネル ══> [VPN装置(ASA/FTD)] ── 社内LAN
 出張先PC（Webブラウザ）      ══ TLS ═══════════════════> ┘

    本社と支社のルータ同士で、インターネット越しに常時トンネルを張って拠点間の LAN をつなぐのがサイト間 VPNです。似た言葉と混同しないようにしましょう。

    • VLAN：スイッチ内でネットワークを論理的に分ける技術。暗号化やインターネット越しの接続とは無関係です。
    • NAT：プライベート IP とグローバル IP を変換する技術。暗号化はしません。

    在宅勤務の社員が Cisco Secure Client や Web ブラウザで接続するリモートアクセス VPN で主に使われるのは TLS（HTTPS でも使われる暗号化の仕組み）です。TLS は Web ブラウザでも使われているため、ファイアウォールを通りやすい（TCP 443）という利点があります。次のプロトコルはリモートアクセス VPN には使えません。

    プロトコル使えない理由
    GREカプセル化するトンネルのプロトコルで、暗号化の機能がない
    Telnet機器へのリモートログイン。通信は暗号化されない
    SNMPv2c機器の監視。コミュニティ名も平文

    VPN 接続ユーザーの認証には、60-7 AAA で扱った RADIUS がよく使われます。また、VPN 機器自体の脆弱性はランサムウェアの侵入口として狙われやすいので、パッチ管理も欠かせません（71 脆弱性管理とランサムウェア対策）。

    2.IPsec が提供するセキュリティ機能

    機能内容使う技術の例
    機密性（暗号化）盗聴されても内容を読めないAES など
    完全性（改ざん検知）途中でデータが書き換えられていないか確認するハッシュ（HMAC-SHA など）
    認証通信相手が本物かを確認する事前共有キー、デジタル証明書
    リプレイ攻撃の防止盗聴したパケットを再送する攻撃を防ぐシーケンス番号

    覚え方は「機密性・完全性・認証・リプレイ防止」です。次のものは IPsec の機能ではありません。

    • IP アドレスの自動割り当て → DHCP の役割です。
    • 通信帯域の保証 → QoS の役割です。

    補足：IKE・ESP・AH

    IPsec は、鍵交換に IKE（Internet Key Exchange、UDP 500/4500）を使い、データの保護には ESP（暗号化＋完全性。IP プロトコル番号 50）または AH（完全性・認証のみで暗号化なし。番号 51）を使います。VPN で暗号化を行うのは ESP です。

    3.IPsec のモード：トンネルモードとトランスポートモード

    元のパケット:                  [元IPヘッダ][TCP/UDP][データ]

トンネルモード:   [新IPヘッダ][ESPヘッダ][元IPヘッダ][TCP/UDP][データ][ESPトレーラ/認証]
                   ↑ルータ同士の          └──────── 暗号化される範囲 ────────┘
                    グローバルアドレス       （元の送信元・宛先も隠れる）

トランスポートモード:         [元IPヘッダ][ESPヘッダ][TCP/UDP][データ][ESPトレーラ/認証]
                              ↑そのまま              └── 暗号化される範囲 ──┘
    モード暗号化の範囲新しい IP ヘッダ主な用途
    トンネルモード元の IP パケット全体（元の IP ヘッダを含む）付けるサイト間 VPN（ゲートウェイ間）
    トランスポートモードデータ部分だけ（元の IP ヘッダはそのまま）付けない端末同士の通信（ホスト間）、GRE over IPsec

    サイト間 VPN では、拠点のルータが社内のパケットをまるごと暗号化し、ルータ同士のグローバルアドレスを付けた新しいヘッダでインターネットへ送ります。受け取った相手のルータが外側のヘッダを外して復号し、元のパケットを社内へ転送します。社内のアドレスなど、元の送信元・宛先も隠せます。

    「モード」という名前が付く別の言葉と混同しないようにしましょう。

    • パッシブモード：FTP のデータ転送の方式です（60-6 ネットワーク機器への管理アクセス）。
    • モニターモード：無線 AP のモードの一つです。

    4.GRE と GRE over IPsec

    GRE（Generic Routing Encapsulation）は、パケットをカプセル化（別のパケットで包むこと）して拠点間を仮想的につなぐトンネルのプロトコルです。

    項目GRE従来の IPsec（クリプトマップ方式）
    暗号化できないできる
    マルチキャスト（OSPF などのルーティングプロトコル）運べる運べない（ユニキャストのみ）

    互いの弱点を補うため、GRE でカプセル化したうえで IPsec で暗号化する（GRE over IPsec）構成が使われます。マルチキャストは複数の相手へまとめて送る通信で、OSPF（ルータ同士が経路を教え合うプロトコル）などが使います。

    [元のOSPFパケット（マルチキャスト 224.0.0.5）]
      ↓ GREでカプセル化（ユニキャストのトンネルパケットになる）
[GREの外側IPヘッダ][GREヘッダ][元のパケット]
      ↓ IPsecで暗号化
[IPヘッダ][ESP][暗号化された GRE パケット][ESP認証]

    GRE トンネルの設定例（暗号化なし）です。

    R1(config)# interface tunnel 0
R1(config-if)# ip address 172.16.0.1 255.255.255.252
R1(config-if)# tunnel source g0/1                    ! 自分のグローバル側
R1(config-if)# tunnel destination 198.51.100.1       ! 相手のグローバルアドレス
R1(config-if)# exit
R1(config)# router ospf 1
R1(config-router)# network 172.16.0.0 0.0.0.3 area 0  ! トンネル越しにOSPFが動く
    R1# show interfaces tunnel 0
Tunnel0 is up, line protocol is up
  Hardware is Tunnel
  Internet address is 172.16.0.1/30
  Tunnel source 203.0.113.1 (GigabitEthernet0/1), destination 198.51.100.1
  Tunnel protocol/transport GRE/IP

    GRE について、次のような理解は誤りです。

    誤った理解理由
    AES で通信を暗号化するGRE は暗号化しない。AES で暗号化するのは IPsec など
    無線 LAN の認証方式無線 LAN とは無関係
    ユニキャストしか運べないGRE はマルチキャストも運べるため、トンネル越しに OSPF などを動かせる

    補足

    現在は VTI（仮想トンネルインターフェース）方式の IPsec や DMVPN など、IPsec でもルーティングプロトコルを扱える方式もあります。基本としては「GRE＝マルチキャスト可・暗号化なし、従来の IPsec＝暗号化あり・マルチキャスト不可、組み合わせて GRE over IPsec」と理解しておきましょう。

    クラウド（AWS）でのサイト間 VPN については、63_AWS の「02_サイト間VPN基本概念」のノートで扱っています。

    5.よくある誤解

    • 拠点間・常時・ルータ同士＝サイト間 VPN。個人の端末・必要なとき・クライアントソフト＝リモートアクセス VPN。VLAN や NAT は VPN ではありません。
    • IPsec の機能は機密性・完全性・認証・リプレイ防止です。IP アドレス割り当て（DHCP）や帯域保証（QoS）はしません。
    • 元の IP ヘッダごと暗号化して新ヘッダを付けるのはトンネルモード。トランスポートモードはデータ部分だけです。パッシブモード（FTP）、モニターモード（無線 AP）は無関係です。
    • リモートアクセス VPN の主なプロトコルは TLS（TCP 443 で通りやすい）。サイト間 VPN は主に IPsec です。
    • GRE は暗号化しません。また GRE はマルチキャストを運べます（ユニキャストだけではありません）。

    6.まとめ

    • サイト間 VPN＝拠点ルータ同士・常時・主に IPsec。リモートアクセス VPN＝端末から必要時・Cisco Secure Client/ブラウザ・TLS（または IPsec/IKEv2）。
    • IPsec＝機密性（AES）・完全性（ハッシュ）・認証・リプレイ防止。
    • サイト間 VPN はトンネルモード（元のパケット全体を暗号化＋新 IP ヘッダ）。
    • GRE＝カプセル化のみ・暗号化なし・マルチキャスト可 → GRE over IPsec で補完。

    7.理解度チェック

    Q1. 本社と支社のルータ同士でインターネット越しに常時トンネルを張る VPN は何と呼びますか？

    サイト間 VPN です。端末は特別なソフトなしで普段どおり通信し、暗号化はルータが行います。主に IPsec を使います。

    Q2. 在宅勤務の PC から Cisco Secure Client やブラウザで接続するリモートアクセス VPN で、主に使われるプロトコルとその利点は？

    TLS です。HTTPS と同じ TCP 443 を使うので、ファイアウォールを通りやすいという利点があります。

    Q3. IPsec が提供する 4 つのセキュリティ機能を挙げてください。

    機密性（暗号化）、完全性（改ざん検知）、認証（相手の確認）、リプレイ攻撃の防止です。IP アドレスの割り当て（DHCP）や帯域保証（QoS）は IPsec の役割ではありません。

    Q4. 元の IP ヘッダごと暗号化し、新しい IP ヘッダを付けるのはどちらのモードですか？

    トンネルモードです。サイト間 VPN で使い、社内の送信元・宛先アドレスも隠せます。トランスポートモードはデータ部分だけを暗号化し、元の IP ヘッダはそのままです。

    Q5. IPsec で実際にデータを暗号化するのは ESP と AH のどちらですか？

    ESP（IP プロトコル番号 50）です。AH（番号 51）は完全性・認証だけで暗号化はしません。鍵交換には IKE（UDP 500/4500）を使います。

    Q6. GRE だけでトンネルを作ると、どんな弱点がありますか？ どう補いますか？

    GRE は暗号化できません。そこで GRE でカプセル化したうえで IPsec で暗号化する GRE over IPsec にします。GRE はマルチキャストを運べるので、トンネル越しに OSPF などを動かせます。
