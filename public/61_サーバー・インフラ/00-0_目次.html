    サーバー・インフラ解説 — 目次

    Obsidian の「61_サーバー・インフラ」ノートをもとにした、初心者向け解説ページの入口です。書いたアプリを動かす 器（サーバー・Web サーバー・実行環境）と、それを 用意する（構築・IaC）、増やす（スケーリング・負荷分散）、守る（サーバー・ネットワークセキュリティ）方法を、EC サイト「Shop」を 1 台構成から冗長構成まで育てる流れで順に解説します。

    もとにしたノート：00_全体像/MOC_サーバー・インフラ体系、00_全体像/MOC_運用領域マップ と、10〜60 の各フォルダのノート

    1.このサイトの読み方

    ページは下の順番に並んでいて、各ページ下部の「前のページ／次のページ」で順に読み進められます。上部の「サーバー・インフラ解説」からいつでもこの目次に戻れます。各ページの最後には「まとめ」と「理解度チェック」があります。

    頭から順に読むと、1 台のサーバーに自分でアプリを公開し、本番構成まで育てられる ように並べています。共通の題材は EC サイト「Shop」（Ubuntu 24.04 ＋ Nginx ＋ Node.js API ＋ PostgreSQL）です。ネットワークや OS の理論そのものは 11_コンピューターサイエンスのノート（50 OS・並行処理、60 ネットワーク・Web）で扱っています。サーバーを守る考え方の土台は セキュリティ基礎解説（71）、アプリの脆弱性は Web脆弱性対策解説（72）、ログインの仕組みは 認証認可解説（73）と セッション管理解説（74）にあります。

    おすすめの読む順

    1. 00 全体像 — サーバー・インフラの全体像 で地図を手に入れます。61〜69 の中での位置づけもここで確認します。

    3. 20 Webサーバー・リバースプロキシ — リクエストを受けて HTTPS で返す「玄関」を Nginx で作ります。

    5. 40 構築・IaC — 手作業の構築手順を知ったうえで、Terraform・Ansible・CDK などでサーバーをコードで用意する方法を学びます。
    6. 50 スケーリング・負荷分散 — アクセスが増えても、1 台壊れても止まらない構成（ロードバランサー・オートスケーリング・CDN・冗長化）を学びます。
    7. 60 サーバー・ネットワークセキュリティ — 公開した瞬間から来る攻撃からサーバーとネットワーク機器を守る方法を学びます。

    とにかく 1 台に公開したいときは、10-4 → 10-5 → 20-2 → 20-3 → 20-4 → 30-4 → 60-2 → 60-3 の近道もあります（手順全体の地図は 40-1）。
