    10 サーバーの基礎

    DHCPとNTP

    インフラを陰で支えるネットワークサービスのうち、DHCP（IP アドレスなどの自動配布）と NTP（時刻同期）を解説します。DHCP では、アドレスを受け取る流れ（DORA）、UDP 67/68、DHCP リレー（ip helper-address）、Cisco ルータの 3 つの役割、リース更新（T1／T2）、確認コマンド、APIPA を見たときの切り分けを扱います。NTP では、時刻をそろえる理由、ストラタム、ntp server／ntp master の設定と確認、ログのタイムスタンプとの関係を扱います。

    もとにしたノート：docs/61_サーバー・インフラ/10_サーバーの基礎/06_DHCPとNTP（インフラを支えるネットワークサービス）.md

    ひとことで言うと

    DHCP は端末に IP アドレス・ゲートウェイ・DNS などを 自動で貸し出す 仕組みで、DISCOVER → OFFER → REQUEST → ACK（DORA）の 4 往復で決まります。NTP は機器の時刻を そろえる 仕組みで、ストラタムが小さいほど正確な時刻源に近く、16 は「同期していない」を表します。

    このページは 10-5 ネットワークの基本（IP・ポート・DNS・NAT）を読んでいると理解しやすいです。設定例には、ネットワーク機器で広く使われる Cisco IOS（Cisco 社のルータ・スイッチの OS）のコマンドを使います。

    1.DHCP とは何か・なぜ必要か

    DHCP（Dynamic Host Configuration Protocol） は、端末がネットワークに接続したときに、IP アドレスなどの設定を サーバから自動で受け取る 仕組みです。数百台の PC に手作業でアドレスを設定すると、手間がかかるうえ、アドレスの重複やゲートウェイ（ほかのネットワークへの出口となるルータ）の設定ミスが起きます。DHCP を使えば、これらを一元管理でき、設定ミスも減らせます。

    1.1 DHCP で配布できる主な情報

    情報Cisco IOS の ip dhcp pool 内のコマンド
    IP アドレスとサブネットマスクnetwork 192.168.1.0 255.255.255.0
    デフォルトゲートウェイdefault-router 192.168.1.1
    DNS サーバdns-server 8.8.8.8
    リース期間（アドレスを使える期間）lease 7（7 日間）
    ドメイン名domain-name example.com

    1.2 DHCP で配布しないもの（よく間違える）

    • クライアントの MAC アドレス：MAC アドレスは、NIC（ネットワークカード）に製造時に割り当てられた固有の値です。むしろ DHCP サーバは、クライアントの MAC アドレスを「誰に貸したか」の識別に使います。
    • VLAN 番号：VLAN（1 台のスイッチの中を論理的に分けたネットワーク）は、スイッチのポート設定（switchport access vlan 10 など）で決まります。端末はどの VLAN に所属しているかを意識せず、ポートに接続された VLAN の DHCP サーバ（またはリレー）からアドレスをもらいます。

    2.DHCP の動作：DORA

    クライアントがアドレスを取得するときは、4 つのメッセージをやり取りします。頭文字をとって DORA と覚えます。

    順番メッセージ送信者意味
    ①DHCPDISCOVERクライアントDHCP サーバを探す。宛先がわからないのでブロードキャスト（同じネットワーク全体への一斉送信）
    ②DHCPOFFERサーバ割り当てられる IP アドレスなどを 提案 する
    ③DHCPREQUESTクライアント提案されたアドレスを使いたいと 要求 する
    ④DHCPACKサーバ承認。これを受け取って、クライアントがアドレスを使い始める

    なぜ ③ REQUEST が必要なのか

    同じネットワークに複数の DHCP サーバがあると、クライアントは複数の OFFER を受け取ることがあります。REQUEST をブロードキャストで送り「このサーバのこのアドレスを選んだ」と知らせることで、選ばれなかったサーバは提案したアドレスを取り消せます。

    なぜ ④ ACK を受け取るまで使わないのか

    OFFER は「提案」にすぎず、まだ正式な割り当てではないからです。ACK で初めて貸し出しが確定します。サーバが拒否する場合は DHCPNAK を返します。

    3.DHCPDISCOVER のアドレスとポート

    DHCPDISCOVER の送信元・宛先は、次の組み合わせになります。

    項目値理由
    送信元 IP0.0.0.0自分のアドレスがまだないため
    宛先 IP255.255.255.255DHCP サーバの場所（アドレス）がわからないため、ローカルネットワーク全体へブロードキャスト
    送信元 MAC自分の MAC
    宛先 MACFFFF.FFFF.FFFFL2（データリンク層）のブロードキャスト
    トランスポートUDPアドレスがないと TCP の接続を張れない
    送信元ポート68（クライアント）
    宛先ポート67（サーバ）

    255.255.255.255（限定ブロードキャスト）はルータを越えません。 これが、次の章の DHCP リレーが必要になる理由です。

    紛らわしいアドレスの意味

    • 169.254.x.x：DHCP でアドレスを取得できなかったときに OS が自分で付ける APIPA アドレス（8 章）。DISCOVER の送信元ではありません。
    • 127.0.0.1：自分自身を表すループバックアドレス。ネットワークへ送信するパケットには使いません。
    • 宛先＝DHCP サーバの IP：クライアントはサーバのアドレスを知らないので、直接は送れません。

    3.1 DHCP のポート番号と TCP/UDP

    • DHCP は UDP を使い、サーバ側 67、クライアント側 68 の 2 つのポートを使います（BOOTP という前身のプロトコルから引き継いだ番号）。
    • TCP は使えません。TCP は送信前に 3 ウェイハンドシェイクで接続を確立する必要があり、アドレスを持たないクライアントにはできないからです。
    • ACL（通信を許可・拒否するルールの一覧。60-8 ACL）で DHCP を許可するときや、パケットキャプチャを読むときに、この知識が必要です。
    ! 例：インターフェースのACLでDHCPのクライアント→サーバ方向を通す
access-list 100 permit udp any eq 68 any eq 67

    4.DHCP リレー（ip helper-address）

    DHCP サーバは、本社のデータセンターなど、クライアントとは別のネットワークに置かれることがよくあります。しかし DHCPDISCOVER は 255.255.255.255 宛てのブロードキャストなので、ルータはそれを別のネットワークへ転送しません。

    そこで、ルータの クライアントが接続されている側のインターフェース に ip helper-address <DHCPサーバのIP> を設定します。ルータは受け取った DHCP のブロードキャストを ユニキャスト（1 対 1 の通信）に変換して DHCP サーバへ中継 します。この機能を DHCP リレーエージェント と呼びます。

    R1(config)# interface GigabitEthernet0/0
R1(config-if)# description to VLAN10 clients
R1(config-if)# ip address 192.168.10.1 255.255.255.0
R1(config-if)# ip helper-address 10.1.1.100

    ポイント

    • 設定する場所は クライアント側（ブロードキャストを受け取る側） のインターフェース。サーバ側ではありません。
    • 指定するのは DHCP サーバの IP アドレスそのもの。DNS でサーバ名を調べる機能ではありません。
    • リレーするとき、ルータは受信インターフェースのアドレス（giaddr）をメッセージに入れます。サーバはそれを見て、どのサブネット用のプールから貸し出すかを決めます。

    5.Cisco ルータの 3 つの DHCP の役割

    Cisco ルータは、DHCP に関して次の 3 つのどの役割にもなれます。コマンドと役割の対応はよく問われます。

    役割意味コマンド設定場所
    DHCP サーバルータ自身がアドレスを貸し出すip dhcp pool <名前>（＋ip dhcp excluded-address）グローバル設定
    DHCP リレーブロードキャストを別ネットワークのサーバへ中継ip helper-address <サーバIP>クライアント側インターフェース
    DHCP クライアントインターフェースが DHCP でアドレスを取得するip address dhcpインターフェース（例：ISP 側）

    5.1 DHCP サーバの設定例

    R1(config)# ip dhcp excluded-address 192.168.1.1 192.168.1.10
R1(config)# ip dhcp pool LAN
R1(dhcp-config)# network 192.168.1.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.1.1
R1(dhcp-config)# dns-server 8.8.8.8
R1(dhcp-config)# lease 7
R1(dhcp-config)# exit
    • ip dhcp excluded-address 192.168.1.1 192.168.1.10 は、192.168.1.1〜192.168.1.10 をクライアントへの割り当て対象から除外 します。ルータ自身（デフォルトゲートウェイ）、サーバ、プリンタなど、手動で設定するアドレスと重複しないようにするためです。
    • excluded-address は プールの外（グローバル設定モード） で設定します。プールの中ではありません。
    • 割り当てる範囲は network コマンドで指定します。excluded-address は「この範囲だけ割り当てる」という意味ではなく、逆に除外 です。
    • lease 7 はリース期間 7 日（Cisco の既定は 1 日）。lease 0 8 なら 0 日 8 時間です。

    5.2 DHCP クライアントの設定例（ISP 側インターフェース）

    R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip address dhcp
R1(config-if)# no shutdown

R1# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0     192.168.1.1     YES manual up                    up
GigabitEthernet0/1     203.0.113.25    YES DHCP   up                    up

    Method 列が DHCP になっていれば、DHCP でアドレスを取得しています。

    6.リース期間と更新（T1 / T2）

    DHCP のアドレスは「永久に与える」のではなく、リース期間 の間だけ「貸し出す」ものです。使われなくなったアドレスは期限切れで回収され、別の端末に再利用できます。

    クライアントは期限が切れる前に自動的に更新するので、通常は同じアドレスを使い続けられます。PC を再起動しなくても、リース期間の途中で自動で更新します。

    1. リース開始：ACK を受け取ってアドレスを使い始めます。
    2. 50% 経過（T1）：貸してくれたサーバへ、ユニキャストで DHCPREQUEST（更新）を送ります。
    3. 87.5% 経過（T2）：T1 で更新できなかったら、どのサーバでもよいのでブロードキャストで DHCPREQUEST を送ります。
    4. 100%（期限切れ）：アドレスを使えなくなり、DISCOVER からやり直します。
    タイミング名前動作
    50% 経過T1（更新 / Renewal）アドレスを貸してくれた サーバに直接（ユニキャスト） 更新を要求
    87.5% 経過T2（再バインド / Rebinding）T1 で更新できなかった場合、どのサーバでもよいのでブロードキャスト で要求
    100%期限切れアドレスを使えなくなる。DISCOVER からやり直し

    最初に更新を要求するのは 50%（T1） です。87.5%（T2）は「T1 で失敗したときの 2 回目のチャンス」です。

    重複検出の仕組みと覚え方

    Cisco IOS の DHCP サーバは、アドレスを貸す前にそのアドレスへ ping を送り、応答があれば「誰かが手動で使っている」と判断します。そのアドレスは conflict に記録して貸し出しません。覚え方は「binding＝誰に何を貸したか、pool＝プールの使用状況、conflict＝重複」です。

    8.APIPA（169.254.0.0/16）とトラブルシューティング

    Windows の PC で ipconfig を実行して、IP アドレスが 169.254.x.x になっていたら、DHCP サーバからアドレスを取得できなかった ことを示します。

    C:\> ipconfig

イーサネット アダプター イーサネット:
   自動構成 IPv4 アドレス. . . . . . . : 169.254.10.20
   サブネット マスク . . . . . . . . . : 255.255.0.0
   デフォルト ゲートウェイ . . . . . . :
    • DHCP に失敗すると、OS が 169.254.0.0/16 から自動でアドレスを付けます。これを APIPA（Automatic Private IP Addressing、リンクローカルアドレス）と呼びます。
    • DHCP サーバが配るアドレスではありません。
    • 手動で設定することも技術的には可能ですが、この範囲のアドレスは通常「自動設定の失敗」を示します。
    • IPv4 のアドレスです（IPv6 のリンクローカルは fe80::/10）。
    • デフォルトゲートウェイが設定されないため、同じネットワーク内の、同じく APIPA の端末同士としか通信できません。

    8.1 APIPA を見たときの確認手順

    1. ケーブル・スイッチポートの状態（物理層、show interfaces status）
    2. スイッチポートの VLAN 設定（正しい VLAN に所属しているか）
    3. DHCP サーバの状態（サービスが動いているか、プールが枯渇していないか：show ip dhcp pool）
    4. サーバが別ネットワークなら、ルータの ip helper-address の設定（設定場所・サーバ IP が正しいか）

    9.DHCP のひっかけポイント・よくある誤解

    ✕ 誤解◯ 実際
    DORA の順番で REQUEST と OFFER を入れ替えた並びDISCOVER → OFFER → REQUEST → ACK。クライアントが使い始めるのは ACK を受け取ってから
    ip helper-address はルータを DHCP サーバにする設定サーバにするのは ip dhcp pool
    ip helper-address はインターフェースが DHCP でアドレスを取得する設定それは ip address dhcp
    ip helper-address に DNS 名を書いてサーバを探すDHCP サーバの IP アドレスを直接指定する
    excluded-address は「その範囲だけ割り当てる」設定逆に除外する。割り当て範囲は network。通信の拒否は ACL の役割で、DHCP サーバのアドレス登録でもない
    DHCP でクライアントの MAC アドレスや VLAN 番号も配るMAC は NIC 固有の値、VLAN 番号はスイッチポートで決まる。どちらも配布しない
    最初のリース更新は 87.5%。または期限切れ後や再起動時だけ更新する最初は 50%（T1）でユニキャスト。87.5% は T2 で、ブロードキャストで任意のサーバに要求する
    DISCOVER の宛先は DHCP サーバの IP。送信元は 169.254.x.x や 127.0.0.1送信元は 0.0.0.0、宛先は 255.255.255.255。サーバの IP は知らないので宛先にならない
    DHCP は TCP、または 53 番や 69 番UDP 67（サーバ）/ 68（クライアント）。TCP は使えない。53 は DNS、69 は TFTP
    show ip dhcp pool で個々のクライアントの対応が見える見えるのは binding。conflict は重複の記録、show arp は ARP テーブル
    169.254.x.x は「正常に取得した」アドレス、または IPv6DHCP 失敗のサイン。IPv4 のアドレス

    9.1 DHCP で押さえておくポイント

    • DORA（DISCOVER → OFFER → REQUEST → ACK）。DISCOVER は 0.0.0.0 → 255.255.255.255 のブロードキャスト。
    • ブロードキャストはルータを越えない → 別ネットワークのサーバには クライアント側インターフェースに ip helper-address。
    • サーバ＝ip dhcp pool、リレー＝ip helper-address、クライアント＝ip address dhcp。
    • ip dhcp excluded-address はグローバル設定で、割り当てから 除外 する範囲。
    • 配布する情報：IP／マスク、デフォルトゲートウェイ（default-router）、DNS サーバ（dns-server）、リース期間（lease）。
    • リース更新：T1＝50%（ユニキャストで元のサーバへ）、T2＝87.5%（ブロードキャスト）。
    • UDP、サーバ 67 / クライアント 68。
    • 確認：binding（貸出先）、pool（使用状況）、conflict（重複）。
    • 169.254.0.0/16（APIPA）＝DHCP 失敗。

    10.NTP：なぜ時刻同期が必要か

    NTP（Network Time Protocol） は、ネットワーク機器の 時刻を同期 させるプロトコルです（UDP 123）。

    機器ごとに時刻がずれていると、障害時に複数の機器のログを突き合わせても、どの出来事が先に起きたのか がわからなくなります。たとえば「R1 のインターフェースがダウンした」ログと「SW1 で STP（スイッチ間のループを防ぐ仕組み）のトポロジ変更が起きた」ログのどちらが原因でどちらが結果かは、時刻が正しくそろっていないと判断できません。そのほか、証明書の有効期限の確認、認証（時刻を使うもの）、課金・監査ログなどにも正確な時刻が必要です。

    時刻を配る側を NTP サーバ、受け取る側を NTP クライアント と呼びます。

    11.ストラタム（stratum）

    NTP は 階層構造 になっていて、その階層を ストラタム という値で表します。

    • 値が小さいほど、原子時計や GPS などの正確な時刻源に近い。
    • 時刻源（ストラタム 0）に直接つながるサーバがストラタム 1。
    • NTP サーバを 1 段経由するごとに 1 ずつ大きくなる。つまり、自分のストラタム＝同期先のストラタム＋1。
    • ストラタム 16 は「同期していない」 状態を表す（最も信頼性が高い、ではない）。
    • ストラタムが小さいサーバほど正確な時刻を持つと判断され、同期先として優先されます。
    • ストラタムは時刻源からの距離（階層）であり、暗号化の強さとは関係ありません（NTP の認証は別の機能）。

    12.NTP の設定

    R1(config)# ntp server 10.1.1.1          ! 10.1.1.1 から時刻を取得（R1はNTPクライアント）
R1(config)# clock timezone JST 9         ! タイムゾーン（表示用）

SW1(config)# ntp server 192.168.1.1      ! R1から時刻を取得

R2(config)# ntp master 3                 ! R2自身を時刻源（NTPサーバ）にする（ストラタム3）
    コマンドモード意味
    ntp server <IP>グローバル設定このルータが NTP クライアント として、指定したサーバから時刻を取得・同期する
    ntp master [ストラタム]グローバル設定このルータを信頼できる時刻源（NTP サーバ）にする（外部の時刻源がない場合など）
    clock set 10:00:00 1 April 2026特権 EXEC時刻を手動で設定する
    logging host <IP>グローバル設定Syslog（ログを別のサーバへ送る仕組み）の送信先（NTP とは無関係）

    ntp server を設定したルータの役割

    そのルータは 10.1.1.1 に対しては クライアント です。「10.1.1.1 に時刻を提供する」のではありません。ただし同期した後は、そのルータ自身もほかの機器（上の例の SW1 など）へ時刻を提供できます（クライアント兼サーバ）。

    • stratum 3 → このルータ自身 のストラタム
    • reference is 10.1.1.1 → 同期先

    このルータがストラタム 3 なら、同期先の 10.1.1.1 は ストラタム 2 です（自分＝サーバ＋1）。このルータから時刻を取得する機器はストラタム 4 になります。

    R1# show ntp associations

  address         ref clock       st   when   poll reach  delay  offset   disp
*~10.1.1.1        192.0.2.1        2     45     64   377  2.000   0.500  1.000
 * sys.peer, # selected, + candidate, - outlyer, x falseticker, ~ configured
    • * が付いた行が、実際の同期先（sys.peer）です。
    • st 列で、同期先の候補それぞれのストラタムを確認できます（ここでは 10.1.1.1 が 2）。

    14.NTP とログのタイムスタンプ

    NTP で時刻をそろえても、それだけではログに日時は付きません。ログに日時を付けるのは service timestamps log datetime msec です（66_可観測性の「Syslog（ログ転送の標準プロトコル）」のノートで詳しく扱っています）。「NTP で正しい時刻」＋「service timestamps でログに日時を付ける」 の両方がそろって、複数機器のログを時系列で突き合わせられます。

    15.NTP のひっかけポイント・よくある誤解

    ✕ 誤解◯ 実際
    時刻同期は SNMP・Syslog・TFTP で行う時刻同期は NTP。SNMP は監視、Syslog はログ送信、TFTP はファイル転送
    ntp server 10.1.1.1 は「10.1.1.1 に時刻を提供する」「10.1.1.1 から 時刻を取得する（自分はクライアント）」。自分をサーバにするのは ntp master
    ログの送信先や時刻の手動設定も ntp コマンドで行うログの送信先は logging host、時刻の手動設定は特権 EXEC の clock set
    ストラタムは大きいほど正確小さいほど正確
    ストラタム 16 は最も信頼性が高い「同期していない」状態
    ストラタムは暗号化の強さ時刻源からの距離（階層）
    show ntp status の stratum は同期先の値自分自身 の値。同期先はそれより 1 小さい
    ntp server だけでログに日時が付くservice timestamps が必要

    15.1 NTP で押さえておくポイント

    • NTP は UDP 123。時刻をそろえる目的は、ログの時系列の突き合わせ。
    • ntp server <IP> でクライアント、ntp master で時刻源。同期後はクライアント兼サーバになれる。
    • ストラタム：小さいほど正確、1 段ごとに＋1、16＝非同期。
    • 確認：show ntp status（自分のストラタム・同期状態・同期先）、show ntp associations（同期先候補とそのストラタム）。

    16.まとめ

    • DHCP は IP／マスク・ゲートウェイ・DNS・リース期間などを自動で貸し出す。MAC アドレスや VLAN 番号は配らない。
    • DORA の 4 往復で決まり、ACK で使用開始。DISCOVER は 0.0.0.0:68 → 255.255.255.255:67 の UDP ブロードキャスト。
    • ブロードキャストはルータを越えないので、クライアント側インターフェースに ip helper-address。
    • リース更新は T1＝50%（ユニキャスト）、T2＝87.5%（ブロードキャスト）。169.254.x.x は DHCP 失敗のサイン。
    • NTP（UDP 123）で時刻をそろえ、service timestamps でログに日時を付けると、複数機器のログを時系列で突き合わせられる。
    • ストラタムは小さいほど正確、1 段ごとに＋1、16 は非同期。

    次の 10-7 非機能要件を支えるサーバー では、DHCP・NTP に加えて DNS・ログ・監視・バックアップなど、運用を支えるほかのサーバーを見渡します。

    17.理解度チェック

    Q1. DHCP でアドレスを取得するときの 4 つのメッセージを順番に答えてください。クライアントがアドレスを使い始めるのはどの時点ですか？

    DISCOVER → OFFER → REQUEST → ACK（DORA）です。OFFER は提案にすぎないので、ACK を受け取った時点で使い始めます。

    Q2. DHCPDISCOVER の送信元 IP・宛先 IP・プロトコルとポートは？

    送信元は 0.0.0.0（まだアドレスがない）、宛先は 255.255.255.255（サーバの場所を知らないのでブロードキャスト）です。プロトコルは UDP で、送信元ポート 68、宛先ポート 67 です。アドレスがないと TCP の接続を張れないため UDP を使います。

    Q3. DHCP サーバが別のネットワークにあります。ルータのどこに、何を設定しますか？

    クライアントが接続されている側（ブロードキャストを受け取る側）のインターフェースに、ip helper-address <DHCPサーバのIP> を設定します。ルータはブロードキャストをユニキャストに変えてサーバへ中継し、giaddr（受信インターフェースのアドレス）を入れるので、サーバはどのプールから貸すかを決められます。

    Q4. ip dhcp excluded-address 192.168.1.1 192.168.1.10 の意味と、設定するモードは？

    192.168.1.1〜192.168.1.10 を割り当て対象から 除外 する設定です（ゲートウェイやサーバなど手動設定のアドレスと重ならないようにするため）。プールの中ではなく、グローバル設定モードで設定します。割り当て範囲そのものは network で指定します。

    Q5. リース期間 8 日のクライアントが、最初に更新を要求するのはいつ、どの方法ですか？

    50% の T1（4 日経過時）に、貸してくれたサーバへユニキャストで DHCPREQUEST を送ります。失敗したら 87.5% の T2（7 日経過時）にブロードキャストで任意のサーバへ要求し、それでもだめなら期限切れで DISCOVER からやり直します。

    Q6. PC の ipconfig で 169.254.10.20 と表示されました。何が起きていて、何を確認しますか？

    DHCP でアドレスを取得できず、OS が APIPA アドレスを自分で付けた状態です。ケーブル・スイッチポートの状態、ポートの VLAN 設定、DHCP サーバの状態（サービス稼働・プール枯渇）、別ネットワークならルータの ip helper-address の順に確認します。

    Q7. show ntp status に stratum 3, reference is 10.1.1.1 と出ました。10.1.1.1 と、このルータから時刻を取る機器のストラタムは？

    表示の stratum 3 はこのルータ自身の値です。同期先の 10.1.1.1 は 1 小さいストラタム 2、このルータから時刻を取る機器は 1 大きいストラタム 4 になります。

    Q8. 全機器に ntp server を設定したのに、ログに日時が付きません。何が足りませんか？

    service timestamps log datetime msec が必要です。NTP は時刻をそろえるだけで、ログに日時を付けるのは service timestamps の役割です。両方そろって、複数機器のログを時系列で突き合わせられます。
