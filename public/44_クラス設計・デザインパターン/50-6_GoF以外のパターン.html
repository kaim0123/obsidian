    GoF以外のパターン — 設計パターンの全体マップ

    「デザインパターン」と聞くと GoF の23個が思い浮かびますが、パターン集はそれだけではありません。業務システム・DDD・マイクロサービス・並行処理・関数型・React・API・テストと、分野ごとに名前のついた定石があります。9つの分類を地図として一覧します。

    もとにしたノート：55_GoF以外のパターン/01_設計パターン_補足

    ひとことで言うと

    パターンは GoF の23個だけではありません。業務システムなら エンタープライズパターン、ドメインの表現なら DDD パターン、クラウドなら マイクロサービスパターン というように、扱う問題の分野ごとに別のパターン集 があります。名前を知っておくと、資料や会話で出てきたときに「どの分野の話か」が分かります。

    1.このページで扱うこと

    このページは、GoF 以外も含めた 設計パターンの全体マップ です。各パターンの詳しい中身は扱わず、どんな分類があり、それぞれに何が含まれるか を一覧します。詳しく解説している他の章のページがあれば、リンクで案内します。

    #分類特徴
    ①GoF デザインパターン（23個）最も有名なパターン集
    ②エンタープライズパターン（Martin Fowler）業務システムでは GoF 以上に使われることもある
    ③DDD パターンDomain-Driven Design で体系化された
    ④マイクロサービスパターンクラウド時代によく使われる
    ⑤並行処理パターン複数の処理を同時に進めるときの定石
    ⑥関数型パターン厳密にはパターンというより、関数型で繰り返し現れる設計イディオム
    ⑦React でよく使われる UI パターンコンポーネントの組み立て方の定石
    ⑧API 設計パターンAPI の形式・ページングなどの定石
    ⑨テストパターンテストデータやテストダブルの作り方の定石

    2.① GoF デザインパターン（23個）

    最も有名なパターン集です。生成・構造・振る舞いの3つに分類されます（詳しくは GoFパターンの概要）。

    生成（5）

    • Factory Method
    • Abstract Factory
    • Builder
    • Prototype
    • Singleton

    構造（7）

    • Adapter
    • Bridge
    • Composite
    • Decorator
    • Facade
    • Flyweight
    • Proxy

    振る舞い（11）

    • Chain of Responsibility
    • Command
    • Interpreter
    • Iterator
    • Mediator
    • Memento
    • Observer
    • State
    • Strategy
    • Template Method
    • Visitor

    3.② エンタープライズパターン（Martin Fowler）

    Martin Fowler が『エンタープライズアプリケーションアーキテクチャパターン』（PoEAA）でまとめた、業務システム向けのパターンです。データベースとのやり取りや業務ロジックの置き方を扱い、業務システムでは GoF 以上に使われることもあります。

    代表例：

    Repository Unit of Work Identity Map Data Mapper Active Record Table Data Gateway Row Data Gateway Service Layer Domain Model Transaction Script Lazy Load Identity Field Optimistic Offline Lock Pessimistic Lock

    関連ページ：41章：MVC（Active Record）、41章：DI・IoC・Composition Root（Unit of Work）、42章：コアドメインとサブドメイン（Transaction Script と Domain Model の使い分け）

    4.③ DDD パターン

    Domain-Driven Design（ドメイン駆動設計）（業務の知識＝ドメインを中心にソフトウェアを設計する手法）で体系化されたパターンです。クラスの形を決める 戦術的 なもの（Entity・Value Object など）と、システムの境界を決める 戦略的 なもの（Bounded Context など）が混ざっています。

    Entity Value Object Aggregate Aggregate Root Repository Domain Service Domain Event Factory Specification Bounded Context Ubiquitous Language Anti-Corruption Layer

    関連ページ：42章：エンティティと値オブジェクト、42章：集約とリポジトリ、42章：ドメインイベント、42章：境界づけられたコンテキスト、42章：戦略的設計とユビキタス言語、この章の 値オブジェクトと完全コンストラクタ

    5.④ マイクロサービスパターン

    システムを小さなサービスに分けて動かす マイクロサービス で、クラウド時代によく使われます。サービス間の通信・障害への備え・データの整合性などを扱います。

    API Gateway Backend for Frontend (BFF) Saga Circuit Breaker Retry Bulkhead CQRS Event Sourcing Outbox Pattern Service Discovery Strangler Fig Sidecar Ambassador

    関連ページ：41章：BFFとAPIゲートウェイ（API Gateway・BFF・Circuit Breaker）、41章：データ所有権とSAGA（Saga・Outbox）、41章：CQRS（CQRS・Event Sourcing）、41章：モノリスとマイクロサービス（Strangler Fig）、41章：横断的関心事と認証認可（Sidecar）

    6.⑤ 並行処理パターン

    複数の処理を同時に（並行して）進めるときの定石です。スレッドの使い方や、イベントの受け取り方を扱います。

    Producer–Consumer Reactor Proactor Half-Sync/Half-Async Thread Pool Leader-Follower Active Object Actor Model Read-Copy-Update (RCU)

    7.⑥ 関数型パターン

    厳密には「デザインパターン」というより、関数型で繰り返し現れる設計イディオム（よく使われる書き方の型）です。

    Pure Function Function Composition Higher-Order Function Currying Partial Application Immutability Pipeline Lazy Evaluation Pattern Matching Functor Applicative Monad Monoid Fold Catamorphism

    関連ページ：42章：関数型と純粋関数、この章の 関数型で置き換わるパターン（GoF パターンが関数でどう書けるか）

    8.⑦ React でよく使われる UI パターン

    React でコンポーネント（画面の部品）を組み立てるときの定石です。

    Container / Presentational Compound Components Custom Hooks Render Props Higher-Order Component (HOC) Provider Pattern State Reducer Controlled Component Uncontrolled Component

    9.⑧ API 設計パターン

    API の形式や、一覧の分割取得（ページング）、同じリクエストの二重実行を防ぐ工夫などの定石です。

    REST GraphQL gRPC Backend for Frontend (BFF) API Gateway HATEOAS Pagination Cursor Pagination Idempotency Key

    BFF と API Gateway は ④ マイクロサービスパターンにも出てきます。分類は排他的ではなく、同じパターンが複数の分野にまたがることがあります（Repository も ② と ③ の両方にあります）。

    10.⑨ テストパターン

    テストデータの用意の仕方や、本物の代わりに使う部品（テストダブル）の種類です。

    Test Data Builder Object Mother Test Fixture Fake Mock Stub Spy Dummy Page Object

    関連ページ：テストしやすいクラス設計

    11.よくある誤解

    誤解1：「デザインパターン＝GoF の23個」

    GoF は最も有名なパターン集ですが、その1つにすぎません。業務システムではエンタープライズパターンや DDD パターンの方がよく使われることもあり、クラウドならマイクロサービスパターンが中心になります。

    誤解2：「ここにあるパターンは全部覚えるべき」

    このページは地図です。全部を覚える必要はなく、自分が扱う分野のパターンから、問題に出会ったときに調べれば十分です。名前を見たときに「どの分野の話か」が分かるだけでも、資料が読みやすくなります。

    12.まとめ

    • パターン集は GoF だけではなく、分野ごと にある
    • ① GoF（23個）、② エンタープライズ（Fowler）、③ DDD、④ マイクロサービス、⑤ 並行処理、⑥ 関数型、⑦ React の UI、⑧ API 設計、⑨ テスト
    • 業務システムでは、エンタープライズパターンが GoF 以上に使われる こともある
    • 関数型パターンは、厳密にはパターンというより 設計イディオム
    • 同じパターン（Repository・BFF・API Gateway など）が複数の分類に現れることもある

    次は、GoF のパターンが関数や言語機能でどう簡単になるかを 関数型で置き換わるパターン で見ます。
