    10 クラスの基礎

    クラスとオブジェクトの基本 — 設計図・実体・状態・振る舞い・メッセージ

    クラス設計の土台になる用語 ── クラス・オブジェクト・状態・振る舞い・メッセージ ── を整理します。あわせて UML のクラス図の読み方の入門も押さえ、以降のページで使う言葉をそろえます。

    もとにしたノート：10_クラスの基礎/02_クラスとオブジェクトの基本

    ひとことで言うと

    クラス は設計図、オブジェクト はそこから作られた実体です。オブジェクトは 状態（フィールド） と 振る舞い（メソッド） をひとまとめに持ち、メッセージ（メソッド呼び出し）で互いに協調します。呼び出し側は相手の内部を知らず、公開された振る舞いだけを使います。

    1.このページで扱うこと

    • クラスとは何か：設計図としての型
    • オブジェクトとは何か：インスタンス
    • 状態（フィールド）と振る舞い（メソッド）
    • メッセージと協調：オブジェクト同士のやりとり
    • クラス図の読み方（入門）

    パラダイム（考え方の枠組み）としてのオブジェクト指向の解説は 42章：オブジェクト指向とクラス にあります。このページでは、クラス設計で使う用語をそろえることに絞ります。

    2.クラスとは何か（設計図としての型）

    クラス はオブジェクトの 設計図（型） です。どんな状態を持ち、どんな振る舞いができるかを定義します。

    class Order {
  constructor(id) {
    this.id = id;
    this.lines = [];
  }
  addLine(product, quantity) { /* ... */ }
  total() { /* ... */ }
}

    クラスは 実体ではなく定義 です。同じ設計図から何個でもオブジェクトを作れます。constructor は、オブジェクトを作るときに最初に呼ばれる初期化用のメソッドです。詳しい解説は 42章：オブジェクト指向とクラス を見てください。

    3.オブジェクトとは何か（インスタンス）

    オブジェクト（インスタンス）は、クラスから作られた 実体 です。

    const order1 = new Order('ORD-001');
const order2 = new Order('ORD-002');

    order1 と order2 は別オブジェクトですが、同じ Order クラスの振る舞いを持ちます。

    用語意味
    インスタンス化クラスからオブジェクトを作ること（new Order(...)）
    インスタンス作られたオブジェクトそのもの

    4.状態（フィールド）と振る舞い（メソッド）

    オブジェクトは 状態 と 振る舞い の組み合わせです。

    要素役割例
    フィールド（状態）オブジェクトが覚えているデータid, lines
    メソッド（振る舞い）オブジェクトができることaddLine(), total()
     
      Order オブジェクト
  ┌─────────────────┐
  │ 状態: id, lines │
  │ 振る舞い:       │
  │   addLine()     │
  │   total()       │
  └─────────────────┘

    クラス設計で決めること

    クラス設計では「このデータは誰が変更してよいか」「この処理はどのクラスに置くか」を決めます。

    5.メッセージと協調（オブジェクト同士のやりとり）

    オブジェクトは メッセージ（メソッド呼び出し）で協調します。呼び出し側は相手の 内部実装を知らず、公開された振る舞いだけを使います。

    const order = new Order('ORD-001');
const price = catalog.priceOf(product);  // Catalog に問い合わせ
order.addLine(product, 2);               // Order に依頼
const total = order.total();             // Order に問い合わせ

    「知り合いの知り合いと直接話さない」原則（デメテルの法則）は、凝集度と結合度 で詳しく扱います。

    6.クラス図の読み方（入門）

    UML（統一モデリング言語：設計を図で表すための共通の記法）の クラス図 は、クラスと関係を視覚化します。

    記号意味
    -private（内部用）
    +public（外部から使える）
    ──>関連（参照関係）
    1..*1 対多

    図は完璧を目指さず、議論と設計のたたき台 として使います。詳しくは 参考図解 を見てください。

    7.よくある誤解

    誤解1：「クラスとオブジェクトは同じもの」

    クラスは 定義（設計図）、オブジェクトはそこから作った 実体 です。1つのクラスから何個でもオブジェクトを作れ、order1 と order2 は同じ振る舞いを持つ別々のオブジェクトです。

    誤解2：「メソッドを呼ぶには、相手の中身を知っている必要がある」

    メッセージを送る側は、相手の 公開された振る舞い だけを知っていれば十分です。order.total() を呼ぶとき、合計をどう計算しているかを知る必要はありません。むしろ知らなくて済むように作るのがクラス設計です。

    誤解3：「クラス図は全部の要素を正確に書かなければならない」

    図は完璧を目指すものではなく、議論と設計のたたき台 です。話したいクラスと関係だけを描けば十分です。

    8.まとめ

    • クラス = 設計図、オブジェクト = 実体（インスタンス）
    • 状態（フィールド）と振る舞い（メソッド）をひとまとめにする
    • オブジェクトはメッセージで協調し、内部詳細を隠す
    • クラス図は関係を共有するための道具
