    90 付録

    参考図解 — クラス図・関係図・継承階層のテンプレート

    クラス設計の議論で使える図のテンプレート集です。クラス図の基本、関連と多重度、依存、継承と実装、パッケージ内の配置、Strategy パターンの構造を、図と、そのまま転記できる ASCII 図（文字だけで描いた図）のセットで並べました。設計レビューやホワイトボードでの打ち合わせに使ってください。

    もとにしたノート：90_付録/付録F_参考図解

    ひとことで言うと

    クラスの図は 箱（クラス） と 線の種類 で読みます。実線は関連、黒い菱形はコンポジション、点線矢印は依存（一時利用）、白い三角は実装・継承 です。継承は浅く保ち、迷ったらインターフェース + 実装にします。

    1.このページで扱うこと

    クラス設計の議論で使える ASCII 図のテンプレート です。Obsidian のコードブロックやホワイトボードにそのまま転記できます。各節では、まず図で形を確認し、その下に転記用の ASCII 図を置いています。

    • クラス図（基本）：クラス名・属性・操作と、可視性の記号
    • 関連（Association）：多重度の読み方
    • 依存（Dependency）：点線矢印と、実線 + 三角
    • 継承と実装：浅い継承と、インターフェース + 実装
    • パッケージ（モジュール内配置）
    • Strategy パターン（構造）

    使い方

    これらの図は UML（統一モデリング言語：設計を図で表すための共通の書き方）のクラス図を簡略にしたものです。関係の種類そのものは クラス間の関係、クラスの基本は クラスとオブジェクトの基本 で説明しています。DDD 寄りの図は DDD早見表と参考図解（42章） にもあります。

    2.クラス図（基本）

    1つのクラスを3段の箱で表します。上からクラス名、属性（フィールド）、操作（メソッド）です。

    記号意味
    -private（クラスの中だけで使える）
    +public（外から使える）
    #protected（自分と子クラスで使える）

    転記用テンプレート

    ┌─────────────────┐
│     Order       │
├─────────────────┤
│ - id: OrderId   │
│ - status        │
│ - lines: Line[] │
├─────────────────┤
│ + addLine()     │
│ + confirm()     │
│ + total()       │
└─────────────────┘

    属性はすべて private（-）で、外からは public（+）の操作だけを使う、というカプセル化の形が図から読み取れます（カプセル化と情報隠蔽）。

    3.関連（Association）

    関連 は、あるクラスが別のクラスを継続的に知っている（参照を持っている）関係です。線の両端に、相手がいくつあるかを表す 多重度 を書きます。

    黒い菱形の コンポジション は、部分（OrderLine）が全体（Order）の寿命に従属する関係です。注文が消えれば明細も消えます。

    多重度読み方
    1ちょうど1
    0..10または1
    1..*1以上
    *0以上

    転記用テンプレート

    Customer "1" ──────< "*" Order
     │                    │
     │                    │ 1
     │                    ◆─────── "*" OrderLine
     │                    （コンポジション）
     └──────────────────────────┘

    4.依存（Dependency）

    依存 は、メソッドの引数や処理の中で一時的に相手を使う関係です。関連より弱いつながりです。

    点線矢印 ..>

    依存（一時利用）。

    実線 + 三角

    実装・継承。

    転記用テンプレート

    PlaceOrderController ..> Order : uses
Order ..> Inventory : canFulfill
OrderService ──→ OrderRepository <<interface>>
                      △
                      │ implements
               SqlOrderRepository

    OrderService はインターフェースだけを知り、DB を使う具体的な SqlOrderRepository を知りません。これが依存性逆転の原則（DIP）の形です（インターフェースと抽象化）。

    5.継承と実装

    白い三角の矢印は、子クラスから親クラス（またはインターフェース）へ向けて描きます。

    転記用テンプレート

            <<interface>>
      PaymentStrategy
       △           △
       │           │
  CardPayment   BankPayment


      Animal
        △
        │
       Dog

    継承は 浅く。疑わしければ、次のようにインターフェース + 実装にします。

          <<interface>>
         Shape
       △     △
       │     │
  Rectangle  Square

    正方形（Square）を長方形（Rectangle）の子クラスにすると、「幅だけ変える」といった長方形の約束を正方形が守れず、置き換えたときに壊れる有名な例があります。そこで両方を Shape の実装として並べます（リスコフの置換原則、継承より合成）。

    6.パッケージ（モジュール内配置）

    パッケージの中で、クラスをどのフォルダに置き、どちら向きに依存させるかを表します。

    転記用テンプレート

      ┌─────────────────────────────────────┐
  │  order パッケージ                    │
  │  ┌─────────┐    ┌────────────────┐ │
  │  │ domain  │    │ infrastructure │ │
  │  │ Order   │←───│ SqlOrderRepo   │ │
  │  └─────────┘    └────────────────┘ │
  └─────────────────────────────────────┘
         ↑ 依存の向きは内側へ

    この図は、モジュールの境界の内側で使います（モジュールの境界そのものは モジュール設計の全体像（43章））。クラスの配置の考え方は 命名とクラス構成 も参照してください。

    7.Strategy パターン（構造）

    Strategy は、同じインターフェースの裏で振る舞いを差し替えるパターンです。呼び出し側はインターフェースだけを使います。

    転記用テンプレート

      CheckoutService
        │
        │ uses
        ▼
  PaymentStrategy <<interface>>
     △      △      △
     │      │      │
   Card   Bank  Invoice

    実際のコードと、生成を受け持つ Factory との組み合わせは ケーススタディ、パターンそのものは 振る舞いパターン で扱っています。

    8.よくある誤解

    誤解1：「クラス図は UML の記法を正確に守らないと意味がない」

    このページのテンプレートは、議論のための簡略な図です。ホワイトボードやコードブロックに素早く描いて、関係の種類（関連・依存・実装）と依存の向きが伝われば十分役に立ちます。

    誤解2：「矢印の向きは、処理やデータが流れる向き」

    クラス図の矢印は「誰が誰を知っているか（依存しているか）」の向きです。パッケージの図では、データは domain から保存されていくように見えても、矢印は infrastructure から domain に向きます。

    誤解3：「正方形は長方形の一種なので、継承で表すのが自然」

    日常の言葉では「一種」でも、長方形の操作（幅だけを変える）を正方形は守れません。継承は浅くし、疑わしければ Shape のようなインターフェース + 実装にします。

    9.まとめ

    • クラス図はクラス名・属性・操作の3段。- private、+ public、# protected
    • 関連は実線と多重度（1、0..1、1..*、*）、コンポジションは黒い菱形
    • 点線矢印 ..> は依存（一時利用）、実線 + 三角は実装・継承
    • 継承は浅く。疑わしければインターフェース + 実装
    • パッケージ内の依存の向きは内側（domain）へ。Strategy は呼び出し側がインターフェースだけを使う
