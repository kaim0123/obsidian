    Object Calisthenics — 9つの過激な規則でオブジェクト指向を体得する

    Jeff Bay の「オブジェクト指向エクササイズ（9規則）」の内容と意図を紹介します。本番コードにずっと当てはめるルールではなく、書き癖を入れ替えるための「筋トレ」であること、そして各規則が値オブジェクト・ガード節・Tell, Don't Ask・小さなクラスなど、ほかのページの技法とどうつながるかを整理します。

    もとにしたノート：10_クラスの基礎/06_Object_CalisthenicsでOOを体得する

    ひとことで言うと

    Object Calisthenics（オブジェクト指向の柔軟体操）は、OO らしい書き方を体に入れるための 過激な制約 です。本番の絶対ルールではなく 期間限定のエクササイズ で、各規則は値オブジェクト・ガード節・Tell, Don't Ask・小さなクラスとつながっています。

    1.このページで扱うこと

    • Jeff Bay の オブジェクト指向エクササイズ（9規則） の内容と意図
    • 本番コードへの永久適用ではなく、癖を入れ替える筋トレ であること
    • 各規則と、このサイト・ノートの関連技法との対応

    増田亨『現場で役立つシステム設計の原則』第10章の「ちょっと過激なコーディング規則」に相当する内容です。出典は Jeff Bay「Object Calisthenics」（『ThoughtWorks アンソロジー』所収）。学び方の文脈は 42章のノート『06_オブジェクト指向設計の学び方』にあります。コレクション規則は オブジェクトの種類の整理 でも触れています。

    2.なぜ過激な規則か

    OO（オブジェクト指向）の説明を聞いても、else だらけ・プリミティブ多用・巨大クラス の書き癖は残りやすいです。プリミティブ とは、number や string のような言語に最初からある基本の型のことです。

    意図的に極端な制約 を短期間課すと、別の設計（小さなオブジェクト・Tell, Don't Ask・値オブジェクト）へ手が動くようになります。

    本番の絶対ルールではない

    本番に9つ全部を永遠に適用する必要はありません。学習・スパイク（短期間の技術的な試作）・勉強会向けです。

    3.9つの規則

    #規則（意訳）意図・続きを学ぶページ
    1メソッドのインデントは1段までネストをやめ、早期 return・抽出へ（場合分けのロジックを整理する：Guard Clause・Extract Method）
    2else を使わない分岐の結びつきを弱める（場合分けのロジックを整理する：Guard Clause、区分オブジェクトと状態遷移）
    3プリミティブと文字列を包む値オブジェクト（値オブジェクトと完全コンストラクタ）
    4ファーストクラスコレクションコレクション専用クラス（オブジェクトの種類の整理）
    51行にドットは1つデメテル／メッセージの連鎖を避ける（48_原則 のノート『02_デメテルの法則』、凝集度と結合度、Tell, Don't Ask）
    6略語を使わない名前で意図を伝える（命名とクラス構成）
    7エンティティを小さく保つクラス・パッケージを小さく（46_メソッド設計 のノート『01_サイズと抽象度』、凝集度と結合度）
    8インスタンス変数は2つまで関心事を分割し巨大クラスを防ぐ
    9getter／setter を安易に置かないデータクラス化を避け、振る舞いに閉じる（Tell, Don't Ask と貧血モデル）

    用語を少し補います。早期 return（ガード節）は、条件に合わないときに先に return して、残りの処理のネストを浅くする書き方です。ファーストクラスコレクション は、配列などのコレクションを、それだけを持つ専用クラスで包むことです。インスタンス変数 は、オブジェクトごとに持つフィールドのことです。

    使い方

    「全部守れ」より、今の臭いが強い規則を 1〜2個だけ 2週間試す、でも十分な筋トレになります。

    4.増田本とのつながり

    Calisthenics増田本・既存ノートで既に扱っていること
    3・4値オブジェクト・コレクションオブジェクト（第1〜2章系）→ 値オブジェクトと完全コンストラクタ、オブジェクトの種類の整理
    2・区分else を消し区分オブジェクトへ（第2章）→ 区分オブジェクトと状態遷移
    9データとロジックの一体・貧血回避（第3章）→ Tell, Don't Ask と貧血モデル、業務ロジックをデータと一体にする
    全体小さくまとめ、組み立てやすくする

    学びの進め方（既存コード改善 → 体得 → 書籍）は 42章のノート『06_オブジェクト指向設計の学び方』、チームへの導入は 42章のノート『06_オブジェクト指向設計の教え方』にあります（どちらも解説ページはまだありません）。

    5.よくある誤解

    誤解1：「9つの規則は本番コードで常に守るべきコーディング規約」

    Object Calisthenics は 期間限定のエクササイズ です。学習・スパイク・勉強会で極端な制約を課し、書き癖を入れ替えるのが目的で、本番に9つ全部を永遠に適用する必要はありません。

    誤解2：「やるなら9つ全部を同時に守らないと意味がない」

    今の臭いが強い規則を 1〜2個だけ 2週間試すだけでも、十分な筋トレになります。たとえば else だらけなら規則2、プリミティブ多用なら規則3から始めます。

    誤解3：「規則そのものに意味があり、守れていれば良い設計になる」

    大事なのは規則の 意図 です。各規則は値オブジェクト・ガード節・Tell, Don't Ask・小さなクラスといった技法につながっていて、制約をきっかけにそれらへ手が動くようになることが狙いです。

    6.まとめ

    • Object Calisthenics は OO らしい書き方を体に入れるための過激な制約
    • 本番の絶対ルールではなく、期間限定のエクササイズ
    • 各規則は値オブジェクト・ガード節・Tell, Don't Ask・小さなクラスとつながる
