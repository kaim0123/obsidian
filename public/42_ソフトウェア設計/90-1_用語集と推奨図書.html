    90 付録

    用語集と推奨図書 — 用語を引き、次に読む本を選ぶ

    この教材に出てくる主な用語を五十音順にまとめ、それぞれを詳しく説明しているページへリンクしました。後半では、ソフトウェア設計をさらに深く学ぶための書籍・オンライン資料と、学ぶ順序を紹介します。読んでいて分からない言葉が出てきたときの「辞書」として使ってください。

    もとにしたノート：付録A_用語集 / 付録G_推奨図書

    1.このページで扱うこと

    • 用語集：教材に登場する主要用語の一言説明と、その用語を解説しているページ
    • 推奨図書・学習リソース：分野別（入門・オブジェクト指向・DDD・リファクタリング・アーキテクチャ）の書籍と、オンライン資料
    • 学習の順序：この教材のあと、どの順番で関連分野へ進むとよいか

    使い方

    用語集の説明は「一言」だけです。意味をしっかり理解したいときは、右の列の「解説ページ」を開いてください。基本用語そのものの考え方は設計の階層と基本用語でまとめて説明しています。

    4.学習の順序（本教材群との対応）

    この教材は「思想とパラダイム」を扱います。そこから具体的な分割、コード、システム全体へと広げ、最後に専門書で深めるのがおすすめの順番です。

    1. 本教材（ソフトウェア設計） … 思想とパラダイム（ソフトウェア設計の全体像から）
    2. モジュール設計・クラス設計 … 具体的な分割
    3. メソッド設計・リファクタリング … コードレベル
    4. アーキテクチャ … システム全体（41章）
    5. DDD 原典・Clean Architecture … 専門書で深化

    歴史の流れ（どの考え方がいつ生まれたか）から読みたい場合はソフトウェア設計年表も参考にしてください。

    5.よくある誤解

    誤解1：「用語の一言説明を覚えれば理解したことになる」

    用語集の説明は思い出すための手がかりにすぎません。たとえば「凝集度」は、なぜ高いほうがよいのか、どう測るのかまで分かって初めて設計に使えます。解説ページで例と一緒に確認してください。

    誤解2：「いきなり原典（Evans の DDD 本など）から読むべき」

    原典は内容が濃く、前提知識がないと挫折しやすい本です。学習の順序のとおり、考え方と具体的な分割を一通り押さえてから、最後に専門書で深めるほうが身につきます。

    6.まとめ

    • 用語集は「一言説明」と「解説ページ」のセット。分からない言葉は解説ページで例と一緒に確認する
    • 推奨図書は 入門・総合 → オブジェクト指向 → DDD → リファクタリング・レガシー → アーキテクチャ・分散 の分野別に整理されている
    • 学習の順序は 思想とパラダイム → 具体的な分割 → コードレベル → システム全体 → 専門書
