    60 思想・美徳

    情報隠蔽は正義 — パルナスの規則と「REST API な人」

    「隠蔽」と聞くと悪いことに聞こえますが、ソフトウェア工学の 情報隠蔽 は「利用者に必要な情報だけを見せ、それ以外は見せない」という 良い設計の原則 です。ゆるコンピューター科学ラジオの「プリンシプルオブライフ」第2回は、経費精算・Stripe の API・「本心が見えない人」を例に、この原則と パルナスの規則 を人生に読み替えます。

    もとにしたノート：02感情がない人はAPIとして優れているし、情報隠ぺいは正義【プリンシプルオブライフ2】27

    ひとことで言うと

    情報隠蔽 ＝ 提供する情報の最小化 です。経理部の中身を知らなくても領収書を出せば経費精算できるように、決まった窓口（インターフェース）だけを見せて中身を隠す と、利用者は 知らなくてよいことを知らずに済み、しかも 安全 になります。これを規則にしたのが パルナスの規則（モジュールの利用者には必要な情報だけを与え、それ以外は見せない）です。

    1.このページで扱うこと

    もとのノートは YouTube 動画のクリップです。このページでは「詳しい要約」を中心に、次の順で解説します。

    1. 導入：本心が見えない人は REST API に近い（逆張りの問いかけ）
    2. 情報隠蔽とは：半導体回のブラックボックスとの違い、経費精算の例と2つのメリット
    3. パルナスの規則：情報隠蔽のための規則
    4. API・Stripe・REST：ソフトウェアでの具体例
    5. 人間を REST API と呼ぶ：ステートレス・冪等性・パルナスの規則で人を評する
    6. 番組自身も情報隠蔽 と、まとめ（用語の言い換え）

    情報隠蔽をコードの単位ごとにどう使うかは、ほかの章で詳しく扱っています。設計全般は カプセル化と情報隠蔽（42章）、モジュール単位は 43章 と 深いモジュールと浅いモジュール、クラス単位は 44章、メソッド単位は 46章の情報隠蔽 を参照してください。

    2.シリーズの位置づけ

    「プリンシプルオブライフ」第2回です。前回（銀の弾丸はない）に続き、ノートでは『The Pragmatic Programmer』由来とされる原則を人生訓に読み替えます（タネ本の食い違いについては 第1回のページの補足 を参照）。

    今回のテーマは 情報隠蔽（information hiding）。「隠す＝悪」という一般的な印象（公文書改ざん、強権国家など）とは逆に、エンジニアリングの文脈では 正義 だ、という主張です。

    3.オープニング：本心が見えない人＝REST API

    にこやかに振る舞うけれど腹の内が読めない人——ポーカーフェイス、お調子者、ふられたのに笑っているように見える人など——を、内部構造が見えず、情報隠蔽が完璧な存在 として称賛するところから話が始まります。そういう人は、

    • パルナスの規則 を満たしている
    • ステートレス（前の状態を引きずらない）で、ある程度 冪等性（同じ依頼を何度しても同じ結果になる性質）がある
    • アーキテクチャとして REST API に近い

    → だから「付き合いづらい」のではなく、設計として優れている、という逆張りです。用語の意味は後の節で順に説明します。

    4.半導体回とのつながり（ブラックボックス）

    未公開の半導体まとめ回では、モジュール化・ブラックボックス（全加算器のように「入力がこう入ればこう出る。中身は気にしない」もの）を雑に語っていました。それをより正確に言うソフトウェア工学の用語が 情報隠蔽 です。

    半導体回で触れたこと今回の emphasis（強調点）
    中身を 気にしなくていい（利用者の負荷軽減）中身を 公開しない（境界の設計）

    なお「オープンソース＝正義」とは別のレイヤーの話（規模が違う）として切り分けています。ソースコードを公開するかどうかではなく、部品と部品の境界で何を見せるか の話です。

    5.情報隠蔽の2つのメリット（経費精算の例）

    水野さんは経理・会計・確定申告を理解していませんが、経費精算はできます。

    • 領収書を決まった手続きで渡す → 「受け取りました」→ しばらくして払い戻し
    • 経理部は内部のフロー（書類がどこを回るか、決裁、銀行での処理など）を 一切説明しない

    これが情報隠蔽の具体例です。ここから2つのメリットが読み取れます。

    1. 知る必要のないことを知らなくてよい

    経費精算のために会計を学ばなくてよい。決算公告・貸借対照表（会社の財産と借金の一覧表）まで追いかけていたら、一生本業に戻れません。

    2. 安全である

    素人が PL/BS（損益計算書・貸借対照表）を触ると、粉飾や誤記のリスクがあります。行政文書を訓練を受けた有資格者が書くのと同じ構造です。

    大企業の社員や、税理士に決算を丸投げする中小企業の経営者も、専門の内側が隠蔽されたモジュール として、その機能を使っている、という話です。

    6.パルナスの規則（Parnas's Law）

    オブジェクト指向などで 情報隠蔽のための規則 として語られるものです。モジュール（ひとまとまりの機能を持つプログラムの部品）について、次のように言います。

    パルナスの規則

    モジュールの利用者には、その利用に 必要な情報だけ を与え、それ以外は 一切見せない。

    • 「ブラックボックス＝悪」ではなく、必要な情報だけが出ている のが良い設計です。
    • 経理部は、領収書という決まった入力でお金が返ってくる → パルナスの規則を満たしている。
    • 大企業の分業に対する「歯車の一つにすぎない」という批判の裏返しとして、知らなくていいことを知らないままにできる のは合理的だ、という視点も示されます。

    （半導体回の振り返りとして、「リスナーにはブラックボックスという印象だけが残り、本題が消えた」というメタな話もあります。）

    モジュールの境界の決め方は 深いモジュールと浅いモジュール（43章）も参考になります。

    7.API・Stripe・REST の例

    ゆるコンピューター科学ラジオのサポーター決済に使っている Stripe（オンライン決済サービス）を例に、API を説明します。

    用語説明経費精算でいうと
    API（Application Programming Interface）巨大な内部実装を隠し、「こうリクエストを送ればこう返る」という 窓口 だけを公開したもの。顧客情報の取得なども、マニュアルどおりにサーバーへ送ればデータが返る。中で何が起きているかは分からない＝情報隠蔽経理部の窓口
    REST API決まった URL・フォーマットで送ると、成功のレスポンスかエラーが返ってくる API「領収書を渡すと、お金かエラーが返る」

    API そのものの考え方は APIとは、REST は RESTの考え方、冪等性は レート制限と冪等性（いずれも45章）で詳しく扱っています。

    8.人間を REST API と呼ぶ（本題の抽象化）

    ここで冒頭の「本心が見えない人」を再定義します。

    API の性質人に当てはめると
    情報隠蔽内部の感情・本音は隠蔽されているが、決まった振る舞い（リクエスト）に対して適切な応答 を返す
    ステートレスその場の気分で急に切れない（飲み会でも、いつもと同じように返してくれる安心感）
    冪等性同じリクエストを何度送っても、同じ種類の正しい応答が返る（外さない）
    パルナスの規則余計な本音を見せず、付き合いに必要な情報だけを出す → 付き合いやすい 側面もある

    「REST API だから褒めるべき」「サイコパスではなく REST API と呼んでほしい」など、エンジニア用語で人を評するジョークが続きます。ただし「人間を手段（道具）として見るのは行き過ぎ」という自己ツッコミもあります。

    9.このラジオ自身も情報隠蔽

    • リスナーには 楽しむために必要な話だけ を喋り、収録準備や台本づくりの苦労など 余計な情報は出さない → 番組の設計もパルナスの規則に沿っている、というメタな話。
    • 水野さんは聞かれたことにだけ的確に返し、余計なことをしない → 優れたラジオパーソナリティ API、というネタ。

    10.回の締め：用語の言い換え

    • 情報隠蔽 は悪い響きですが、実態は 「提供情報の最小化」 に近いものです（認知負荷が下がり、安全性が上がる）。
    • モジュール化の本質は情報隠蔽。不要な情報を与えないことが、パルナスの規則を守る設計です。
    • 締めでは「情報開示こそ正義」との水掛け論は避け、隠蔽は正義 として回を閉じます。サポーター向けの「REST API 名」などのネタにも触れています。

    11.よくある誤解

    誤解1：「情報隠蔽は、何かをごまかす悪いことだ」

    日常語の「隠蔽」（公文書改ざんなど）とは別物です。ソフトウェアの情報隠蔽は 利用者に必要な情報だけを見せる設計 で、利用者は余計なことを覚えずに済み（認知負荷の低下）、内部を壊されることもない（安全性の向上）、という利点があります。「提供情報の最小化」と言い換えると誤解が減ります。

    誤解2：「ブラックボックスは中身が分からないから悪い」

    パルナスの規則の立場では、必要な情報だけが出ているブラックボックスこそ良い設計 です。経理部の中身を知らなくても経費精算ができるのは、窓口（領収書を出せばお金かエラーが返る）がはっきりしているからです。

    誤解3：「情報隠蔽は、ソースコードを公開しない（クローズドにする）ことだ」

    動画でも「オープンソース＝正義」とは別レイヤーの話として切り分けています。情報隠蔽は、コードが公開されているかどうかではなく、部品同士の境界で何を見せ、何を見せないか の話です。オープンソースのライブラリも、使う側には決まった API だけを見せています。

    12.まとめ

    • 情報隠蔽：利用者に必要な情報だけを見せ、内部は隠す設計原則。メリットは「知らなくてよいことを知らずに済む」と「安全」。
    • パルナスの規則：モジュールの利用者には利用に必要な情報だけを与え、それ以外は一切見せない。
    • API / REST API：決まった窓口にリクエストを送れば、成功かエラーが返る。中身は見えない＝情報隠蔽。経理部の窓口と同じ構造。
    • 人生への読み替え：本心が見えない人は、ステートレスで冪等で、パルナスの規則を守る「REST API な人」。付き合いやすい面もある（ただし人を手段にするのは行き過ぎ）。
    • 情報隠蔽は「提供情報の最小化」。隠蔽は正義。
