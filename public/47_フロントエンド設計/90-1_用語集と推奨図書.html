    ひとことで言うと

    2.1 あ行

    用語説明解説ページ
    アイランドアーキテクチャ（Islands Architecture）静的 HTML の中で、対話が必要な部分（島）だけを JavaScript で動かす構成レンダリング方式（41）
    アクセシビリティ（a11y）障害の有無や利用環境に関係なく、誰もが UI を操作・理解できることアクセシビリティを部品設計に組み込む
    依存ルール「どの層・どのフォルダがどこを import してよいか」の決まり。Lint で自動検査する依存ルールの自動検査
    イミュータブル（不変）状態を直接書き換えず、新しい値を作って置き換えること。変更検知と予測可能性の土台UI は状態の関数と単方向データフロー
    エラー境界（Error Boundary）子コンポーネントの描画エラーを捕まえ、代わりのフォールバック UI を表示する仕組みエラー境界とフォールバック UI

    Lint は、コードを実行せずに書き方の問題を見つけるツール（ESLint など）のことです。

    6.よくある誤解

    誤解1：「用語集の説明だけ読めば、その言葉は分かったことになる」

    用語集は1行の早見表です。たとえば「派生状態は state として持たない」と覚えても、なぜ持つと困るのか（同じデータの「正」が2か所になり食い違う）は SSOT と派生状態 を読まないと分かりません。用語集は「解説ページ」の列から本文へ進む入口として使ってください。

    誤解2：「フロントエンドは変化が速いので、本を読むより最新の記事だけ追えばよい」

    ライブラリの書き方は数年で変わりますが、「状態の正を1か所に置く」「部品の公開面を小さくする」といった考え方は長く使えます。付録C が勧めるのは、書籍で考え方を、オンラインリソースで最新の実践を 補う組み合わせです。

    誤解3：「推奨図書は上から全部読まないといけない」

    まず入門の1〜2冊で全体像をつかみ、あとは今扱っているテーマ（状態、フォルダ構成、品質など）に合わせてテーマ別から選べば十分です。各資料の「47 の対応」列で、どのページと一緒に読むとよいかが分かります。

    7.まとめ

    • 用語集は、47章の用語を五十音順・英字順に並べた早見表。各語の「解説ページ」から本文へ進む
    • 推奨図書は、入門（『フロントエンドの知識地図』『Frontend Architecture for Design Systems』）で全体像をつかみ、テーマ別から選ぶ
    • 書籍で考え方を、Web の公式ドキュメント（React・TanStack Query・Testing Library・WAI-ARIA APG・web.dev など）で最新の実践を補う
    • 学習は「知識地図 → 変遷 → 状態とフォルダの置き方 → RADIO で1つ設計」の順がおすすめ
