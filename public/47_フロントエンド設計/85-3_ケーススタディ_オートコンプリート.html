    85 ケーススタディ

    ケーススタディ：オートコンプリート — デバウンス・競合・combobox

    検索ボックスに入力すると候補が出る オートコンプリート を、RADIO テンプレート に沿って設計します。小さな部品ですが、汎用部品としての Props 設計、デバウンス、リクエストの競合、キャッシュ、combobox パターンのアクセシビリティと、設計判断が詰まっています。

    もとにしたノート：03_ケーススタディ_オートコンプリート

    ひとことで言うと

    汎用部品は 何を検索するかを知らない ようにし、取得関数を Props で受け取ります。デバウンス でリクエストを減らし、AbortController と「最新の query か」の確認で 古い応答が後から表示される競合 を防ぎます。a11y は combobox パターン：フォーカスは input に置いたまま、選択中の候補は aria-activedescendant で伝えます。

    1.このページで扱うこと

    検索ボックスに入力すると候補が出る オートコンプリート を、RADIO テンプレート に沿って設計します。

    • R：要件（機能・非機能・a11y・再利用）
    • A：汎用部品と利用側の分け方
    • D：状態の種類と置き場所
    • I：サーバー API とコンポーネントの Props
    • O：デバウンス、競合（レースコンディション）、キャッシュ、combobox パターン、自作かライブラリか

    2.R — 要件

    種類内容
    機能入力に応じて候補を最大 10 件表示 / 矢印キーで選択 / Enter で確定
    非機能入力がもたつかない。サーバーへの無駄なリクエストを減らす
    a11yキーボードだけで操作でき、スクリーンリーダーが候補数と選択中の候補を読み上げる
    再利用商品検索・ユーザー検索など、複数画面で使う汎用部品にする

    3.A — 全体構成

      Autocomplete（汎用部品：UI と操作）
   ├─ input（combobox）
   └─ listbox
        └─ option × N
         ▲
         │ fetchSuggestions(query) を Props で受け取る
  ProductSearch（利用側：何を検索するかを知っている）

    汎用部品は 何を検索するかを知らない ようにします。取得関数を Props で受け取ることで、商品検索にもユーザー検索にも使えます（Props はコンポーネントの公開 API）。

    4.D — データモデル

    状態種類置き場所
    入力中の文字列 queryUI 状態Autocomplete 内の local state
    候補一覧サーバー状態query をキーにキャッシュ
    開閉 isOpenUI 状態local state
    選択中の候補 activeIndexUI 状態local state

    isOpen は「候補が 1 件以上あり、フォーカスがある」から 派生（ほかの状態から計算で求めること）できるなら state にしません（SSOT と派生状態）。

    5.I — インターフェース

    5.1 サーバー API

    GET /suggestions?q=<query>&limit=10  → { items: { id: string; label: string }[] }

    5.2 コンポーネントの Props

    type AutocompleteProps<T> = {
  label: string;
  fetchSuggestions: (query: string, signal: AbortSignal) => Promise<T[]>;
  getOptionLabel: (item: T) => string;
  onSelect: (item: T) => void;
  minChars?: number;   // 既定 2
  debounceMs?: number; // 既定 200
};

    <T> はジェネリクス（候補の型を使う側が決められる仕組み）です。signal を受け取るのは、古いリクエストを取り消せるようにするためです。

    6.O — 最適化と深掘り

    6.1 デバウンス

    1 文字ごとにリクエストすると無駄が多いので、入力が止まってから一定時間後 にだけ取得します。これを デバウンス と呼びます。

    function useDebouncedValue<T>(value: T, ms: number) {
  const [v, setV] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setV(value), ms);
    return () => clearTimeout(id);
  }, [value, ms]);
  return v;
}

    デバウンスをカスタムフックに切り出す書き方は、32_React のノート『10-3-カスタムフック』で扱っています。

    6.2 競合（レースコンディション）

    レースコンディション とは、複数の処理の終わる順番によって結果が変わってしまう不具合です。「ap」の応答が「apple」の応答より 後に 返ってくると、古い候補が表示されてしまいます。

      入力: a → ap → apple
  応答:           apple の結果 ✓ → ap の結果（遅れて到着）✗ ← これを表示してはいけない

    対策は 2 つあり、併用できます。

    対策方法
    取り消す新しい入力のたびに AbortController.abort() で前のリクエストを止める
    無視する応答に対応する query が最新の query と一致するときだけ反映する

    AbortController は、送信中の fetch を途中で取り消すためのブラウザの仕組みです。サーバー状態ライブラリで query をキーにすれば、キーの切り替えで古い結果が表示されない仕組みを任せられます。

    6.3 キャッシュ

    同じ query を打ち直したときは、キャッシュから即座に表示します。候補は変化が遅いので、数分のキャッシュで十分なことが多いです。

    6.4 アクセシビリティ（combobox パターン）

    WAI-ARIA Authoring Practices の combobox パターン（入力欄と候補リストを組み合わせた部品の、標準的な作り方）に従います（アクセシビリティを部品設計に組み込む）。

    要素属性
    inputrole="combobox"、aria-expanded、aria-controls（listbox の id）、aria-activedescendant（選択中 option の id）、aria-autocomplete="list"
    候補の箱role="listbox"
    候補role="option"、aria-selected
    件数のお知らせaria-live="polite" の領域に「5 件の候補」

    フォーカスは input に置いたまま、aria-activedescendant で選択中の候補を伝えるのがポイントです。こうすると、矢印キーで候補を選んでいる間も文字を打ち続けられます。

    キー動作
    ↓ / ↑候補を移動
    Enter確定
    Escape閉じる（もう一度で入力を消す）

    6.5 自作か、ライブラリか

    自作する

    • 要件が特殊で既存部品に合わない
    • 学習目的

    ライブラリ（Headless UI・Downshift など）を使う

    • a11y を確実に満たしたい
    • 開発時間を優先したい

    a11y の細部は抜けやすいので、実務では 振る舞いは Headless なライブラリ、見た目は自分たちのデザインシステム という分担がよく選ばれます（コンポーネントパターンの比較）。Headless とは、見た目を持たず振る舞い（キーボード操作・ARIA 属性など）だけを提供する部品のことです。

    7.よくある誤解

    誤解1：「デバウンスすれば古い候補が表示される問題も防げる」

    デバウンスはリクエストの数を減らすだけです。 送ったリクエストの応答がどの順で返るかは保証されないので、AbortController で前のリクエストを取り消すか、最新の query と一致する応答だけを反映する対策が別に必要です。

    誤解2：「矢印キーで候補を選ぶなら、フォーカスを候補に移すべき」

    combobox パターンでは、フォーカスは input に置いたままにします。 選択中の候補は aria-activedescendant で支援技術に伝えます。こうすれば、候補を選びながら入力も続けられます。

    誤解3：「汎用部品なら、検索 API の呼び出しも部品の中に書いておくと便利」

    汎用部品は何を検索するかを知らないようにします。 API を中に書くと、その検索専用の部品になってしまいます。取得関数を Props で受け取れば、商品検索にもユーザー検索にも使えます。

    8.まとめ

    • 汎用部品は 何を検索するかを知らない。取得関数を Props で受け取る
    • デバウンスでリクエストを減らし、AbortController と「最新の query か」の確認で競合を防ぐ
    • 候補は query をキーにしたサーバー状態としてキャッシュする
    • a11y は combobox パターン：フォーカスは input、選択は aria-activedescendant
