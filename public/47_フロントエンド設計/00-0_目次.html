    フロントエンド設計解説 — 目次

    Obsidian の「47_フロントエンド設計」ノートをもとにした解説ページの入口です。ブラウザ上の UI を「どう部品に分け、状態とデータをどう流し、コードをどこに置くか」——フレームワークに依存しないフロントエンドの設計判断を、コンポーネント・状態・ディレクトリ構成・デザインシステム・サーバーとの境界・品質・スケールまで、全32ページで解説します。

    もとにしたノート：MOC_フロントエンド設計体系 と、10〜90 の各フォルダのノート

    1.このサイトの読み方

    ページは MOC のフォルダ構成（設計の関心事ごと：基礎 → コンポーネント → 状態 → ディレクトリ → デザインシステム → サーバーとの境界 → 品質 → スケール）と同じ順番に並んでいます。各ページの下にある「前のページ／次のページ」で順に読み進められ、上部の「フロントエンド設計解説」からいつでもこの目次に戻れます。どのページも単体で読めるように書いてあるので、気になるテーマから読んでもかまいません。

    47 章の骨格は、2025 年時点で論点とされる 4 本柱（コンポーネントの境界 / 状態の置き場所 / ディレクトリ・モジュール構成 / デザインシステム、Feature-Sliced Design の解説より）です。そこに Godbolt『Frontend Architecture for Design Systems』と bulletproof-react の機能別構成を加え、演習は GreatFrontEnd の RADIO で組み立てます。SSR/CSR などのレンダリング方式や BFF は アーキテクチャ解説（41）、凝集・結合などモジュール分割の一般論は モジュール設計解説（43）が本拠地です。

    はじめて学ぶなら

    まず 全体像 で地図を手に入れ、10 基礎 → 20 コンポーネント設計 → 30 状態の順に進むのがおすすめです。

    フロントエンド設計の全体像

    フロントエンド設計とは、4本柱と骨格資料（FSD・Godbolt・bulletproof-react・RADIO）、フォルダと問いの一覧、新しいノートの置き場所、他章との分担

    フロントエンド設計の変遷

    jQuery 時代の課題、コンポーネント指向、State Driven UI、Atomic Design、単方向データフロー、SSOT、Feature First / FSD、Server State 管理、7つの思想の関係

    3.10 基礎

    フロントは何を設計するのか。

    10-1

    フロントエンド設計とは

    フロントエンドの責務、設計で決める4本柱、設計と実装の線引き、設計が必要になる理由、小さく始めて育てる進め方

     10-2

    UI = f(state) と単方向データフロー

    命令的 UI と宣言的 UI、UI = f(state)、props で下へ・イベントで上へ、双方向バインディングとの比較、設計判断への効き方

    4.20 コンポーネント設計

    画面をどう部品に分けるか。

    20-1

    コンポーネントの分割粒度と境界

    分割の目的、分割のサイン、境界の4つの軸、大きすぎ・細かすぎの目安、props のバケツリレーと children、共通化のタイミング

     20-2

    Props はコンポーネントの公開 API

    Props は契約、利用者の言葉での命名、variant、判別可能なユニオン、制御・非制御、children とスロット、Props が多いときの見直し

     20-3

    コンポーネントパターンの比較

    Container-Presentational、Render Props / HOC、カスタムフック、Compound Components、Headless UI、比較と選び方

     20-4

    Atomic Design

    Atoms〜Pages の5段階、役立つ場面、フォルダ構成にしたときの破綻、汎用部品の中だけで使う現実的な使い方、判断のポイント

     20-5

    画面関心事の分割とドメイン連動

    画面の関心事の混在、部品と画面の分割、タスクベースのインターフェース、視覚表現と論理構造を揃える、表示判断はドメイン寄り

    5.30 状態とデータフロー

    状態をどこに持ち、どう流すか。

    30-1

    状態の分類と置き場所

    分類が必要な理由、6種類の状態と真の持ち主、置き場所の判断フロー、colocation（近くに置く）、種類ごとの置き場所と向き不向き、よくある判断ミス

     30-2

    Single Source of Truth と派生状態

    SSOT、派生状態を保存せず描画時に計算する、ID だけ持って導出する、状態の形のチェックリスト、サーバーデータと SSOT

    6.40 ディレクトリ・モジュール構成

    コードをどこに置き、依存の向きをどう守るか。

    40-1

    ディレクトリ構成の方式比較

    構成が決めること（凝集・依存の向き・削除のしやすさ）、Layer型、Feature型、Atomic Design型、FSD、比較表、選び方と移行

     40-2

    Feature-Sliced Design

    layer・slice・segment の3段構造、6つの層の役割、entity と feature の区別、import のルールと @x 記法、公開 API、向く場面・向かない場面

     40-3

    bulletproof-react の構成

    トップレベルの構成、feature フォルダの中身、機能どうしを import しない、共有→機能→アプリの一方向、barrel ファイルの扱い、FSD との比較

     40-4

    依存ルールの自動検査

    自動検査が必要な理由、ツール比較、import/no-restricted-paths、eslint-plugin-boundaries、dependency-cruiser、Steiger、導入の進め方

    7.50 デザインシステム・スタイリング

    見た目をどう一貫させるか。

    50-1

    デザインシステムの構成要素

    4層構成、デザイントークン（プリミティブ→セマンティック）、共通部品の優先度と実装の3つの選択肢、Storybook とドキュメント、ガバナンス

     50-2

    スタイリング方式の比較

    CSS がグローバルなことで起きる問題、BEM、CSS Modules、ランタイム型・ゼロランタイム CSS-in-JS、Tailwind、比較表、混在させるときのルール

    8.60 サーバーとの境界

    サーバーとどうつなぎ、何をどちらが受け持つか。

    60-1

    フロントとサーバーの責務分担

    クライアントは信用しない原則、バリデーションの二重化とスキーマ共有、権限の出し分けとサーバー側認可、データ整形の置き場所、RSC・Server Actions で動く境界

     60-2

    API レイヤと型の共有

    手書きの型の問題、唯一の契約の置き場所、OpenAPI + コード生成、tRPC、Zod、GraphQL Code Generator、方式の比較、API レイヤの責務

    9.70 品質

    テスト・アクセシビリティ・性能・エラー処理を設計に組み込む。

    70-1

    テストしやすいコンポーネントと構成

    Testing Trophy、テストしにくいコンポーネントの特徴、純粋関数・フック・表示へのロジック分離、MSW、どこまでテストするかの判断

     70-2

    アクセシビリティを部品設計に組み込む

    共通部品で a11y を作り込む理由、WCAG 2.2 AA、ネイティブ要素優先、APG のパターン、フォーカス設計、Headless UI の判断、仕組みで守る

     70-3

    パフォーマンスを設計で作り込む

    Core Web Vitals（LCP / INP / CLS）、設計で決まる部分と後で直せる部分、送る JS を減らす、再レンダリング範囲の設計、領域確保、画像、パフォーマンス予算

     70-4

    エラー境界とフォールバック UI

    真っ白な画面の原因、エラーの分類、Error Boundary の置き場所、Suspense との組み合わせと空状態、リトライ UI、監視

    10.80 スケールと組織

    コードとチームが大きくなったらどうするか。

    80-1

    モノレポとパッケージ分割

    モノレポとポリレポの比較、pnpm workspaces・Turborepo・Nx の役割分担、apps と packages の切り方、共有 UI パッケージの設計、よくある失敗

     80-2

    マイクロフロントエンドの判断

    マイクロフロントエンドとは、採る・やめるの判断の順番、統合方式の比較（ビルド時・Module Federation・iframe・Web Components・サーバー合成）、横断の約束ごと

     80-3

    フロントエンドの規約と ADR

    規約を機械に守らせる手段、人が決める規約の書き方、ADR とは、ADR のテンプレート、フロントエンドで ADR にすべき判断

    11.85 ケーススタディ

    RADIO（要件 → 全体構成 → データモデル → インターフェース → 最適化）で組み立てる設計演習。

    85-1

    RADIO テンプレート

    RADIO の5段階と順番の意味、各段階で問うこと、記入テンプレート、使うときのコツ

     85-2

    ケーススタディ：ニュースフィード

    要件と全体構成、データモデル、カーソルページネーション、無限スクロール、仮想化、楽観的更新、feed パターンの a11y

     85-3

    ケーススタディ：オートコンプリート

    汎用部品の Props 設計、状態の置き場所、デバウンス、レースコンディション、キャッシュ、combobox パターンの a11y、自作かライブラリか

     85-4

    ケーススタディ：管理画面の一覧とフォーム

    URL 状態・サーバー状態・フォーム状態の使い分け、URL を真実の源にする、スキーマでの検証と型、保存の流れ、FSD でのディレクトリ配置
