    30 状態とデータフロー

    SSOT と派生状態 — 同じ情報を 2 か所に持たない

    状態の「置き場所」を決めたら、次に問題になるのは 状態の形 です。このページでは、同じ情報を 2 か所に持たない（Single Source of Truth, SSOT）という原則と、そこから導かれる 派生状態（derived state） の考え方を学びます。重複や矛盾を許す形にすると、同期のバグが必ず生まれます。

    もとにしたノート：02_Single_Source_of_Truthと派生状態

    ひとことで言うと

    情報の正しい値を持つ場所は 1 か所だけ にし、計算で出せる値は 保存せず描画時に計算 します。オブジェクトのコピーではなく ID を持って導出 し、boolean の組み合わせより 取りうる値の集合 で状態を表します。サーバーデータの SSOT はキャッシュ 1 か所で、そこからさらにコピーしません。

    1.このページで扱うこと

    状態の分類と置き場所 で「どこに置くか」を決めた後の、「どんな形で持つか」の話です。

    • SSOT（Single Source of Truth）とは

    2.SSOT とは

    Single Source of Truth（信頼できる唯一の情報源） は、ある情報の 正しい値を持つ場所を 1 か所だけ にする原則です。フロントエンドでは Flux / Redux（2014〜2015年）の文脈で広く知られるようになりました（経緯は 設計の変遷）。

      SSOT なし                         SSOT あり
  ─────────                         ─────────
  [ヘッダー] userName = "田中"       [ユーザー状態] name = "田中"
  [設定画面] userName = "田中"            │
  [サイドバー] userName = "Tanaka" ←ずれた  ├→ ヘッダー（読むだけ）
                                          ├→ 設定画面（読むだけ）
                                          └→ サイドバー（読むだけ）

    コピーが複数あると、どれかを更新し忘れた瞬間に画面が矛盾 します。1 か所にしておけば、更新は 1 回で済み、矛盾は原理的に起きません。

    3.派生状態 — 計算で出せる値は保存しない

    派生状態 とは、他の状態から計算で求められる値です。SSOT を守るには、派生状態を 別の state として保存せず、描画のたびに計算 します。

    ✕ 悪い例：合計を別の state に持つ（items と total がずれうる） 
    const [items, setItems] = useState<Item[]>([]);
const [total, setTotal] = useState(0);
useEffect(() => {
  setTotal(items.reduce((sum, i) => sum + i.price * i.qty, 0));
}, [items]);
    ◯ 良い例：描画時に計算する（items だけが真実） 
    const [items, setItems] = useState<Item[]>([]);
const total = items.reduce((sum, i) => sum + i.price * i.qty, 0);

    悪い例は、

    • 1 回余計に描画が走る（items 更新 → 描画 → effect → total 更新 → 再描画）
    • effect を書き忘れる・条件を間違えると ずれる

    という問題があります（useEffect は描画の後に実行される処理です）。計算が重い場合だけ メモ化（同じ入力の計算結果を覚えておく最適化）で結果をキャッシュします。キャッシュは状態ではなく、計算の最適化です。

    4.派生状態の典型例

    元の状態派生状態よくある誤り
    明細の配列合計金額・件数合計を別 state にする
    一覧 + 検索語絞り込み後の一覧絞り込み結果を別 state にする
    入力値入力が有効か（エラー有無）isValid を別 state にする
    一覧 + 選択中 ID選択中のオブジェクト選択中オブジェクトのコピーを持つ
    サーバーの注文データ表示用に整形した値整形後のデータをストアに保存する

    特に 「選択中のオブジェクトをコピーして持つ」 は頻出の誤りです。ID だけを持ち、表示時に一覧から引きます。

    ✕ 悪い例：一覧が更新されても selected は古いまま 
    const [selected, setSelected] = useState<Product | null>(null);
    ◯ 良い例：ID だけ持ち、オブジェクトは導出する 
    const [selectedId, setSelectedId] = useState<string | null>(null);
const selected = products.find((p) => p.id === selectedId) ?? null;

    5.状態の形を決めるチェックリスト

    React 公式ドキュメント「Choosing the State Structure」の原則は、フレームワークに関係なく使えます。

    原則意味
    関連する状態はまとめる常に一緒に変わる値（x と y など）は 1 つのオブジェクトに
    矛盾する組み合わせを作らないisSending と isSent を別々に持つより status: 'idle' | 'sending' | 'sent'
    冗長な状態を持たない計算で出せる値は保存しない（このページの 3.）
    重複を持たない同じデータを 2 か所に置かない（このページの 2.）
    深い入れ子を避ける正規化（ID で参照する平らな形）を検討する

    「矛盾する組み合わせ」は、boolean を増やすほど起きます。たとえば isSending と isSent が両方 true という、ありえない状態が作れてしまいます。状態を 取りうる値の集合 として設計すると防げます（有限の状態の扱いは 36_状態管理 の 70_複雑なフロー）。

    ✕ 悪い例：boolean を 2 つ持つ（矛盾した組み合わせが作れる） 
    const [isSending, setIsSending] = useState(false);
const [isSent, setIsSent] = useState(false);
    ◯ 良い例：取りうる値の集合で持つ 
    const [status, setStatus] = useState<'idle' | 'sending' | 'sent'>('idle');

    6.サーバーデータと SSOT

    サーバー状態の 真実はサーバー にあります。フロントの SSOT は「サーバー状態のキャッシュ 1 か所」です。

      サーバー（真実）
      │ 取得
      ▼
  サーバー状態キャッシュ（フロントでの唯一のコピー）
      │ 読むだけ
      ├→ 一覧画面
      └→ 詳細画面

    やってはいけないのは、キャッシュから さらにローカル state やストアにコピー することです。編集フォームの初期値のように「コピーして編集したい」場合は、フォームの状態 として明示的に分け、送信後はキャッシュを 無効化（古いと印を付けて取り直させること）して取り直します。

    7.向く場面・向かない場面

    SSOT と派生の徹底が向く例外を検討してよい
    同じデータを複数画面で表示する計算が非常に重く、メモ化でも足りない
    金額・件数などずれると困る値編集中の下書き（意図的なコピー）
    一覧と詳細が連動する画面オフライン対応で一時的に複製が必要

    例外を作るときは 「これは意図的なコピーで、同期ルールはこう」 と明記します。

    8.よくある誤解

    誤解1：「合計や絞り込み結果も state にしておけば速い」

    かえって遅く、ずれやすくなります。 effect で別 state を更新すると描画が 1 回余計に走り、書き忘れればずれます。描画時に計算し、重い場合だけメモ化します。メモ化は状態ではなく計算の最適化です。

    誤解2：「選択中の商品はオブジェクトごと state に入れるのが自然」

    ID だけを持ちます。 オブジェクトをコピーすると、一覧が更新されても選択中のコピーは古いままになります。ID から一覧を引けば、常に最新の値が表示されます。

    誤解3：「SSOT なのだから、どんなコピーも禁止」

    意図的なコピーは許されます。 編集中の下書きやオフライン対応など、例外を検討してよい場面があります。その場合は「意図的なコピーで、同期ルールはこう（送信後はキャッシュを無効化して取り直す など）」と明記します。

    9.まとめ

    • 情報の正しい値を持つ場所は 1 か所だけ（SSOT）
    • 計算で出せる値は 保存せず描画時に計算 する。重ければメモ化
    • オブジェクトのコピーではなく ID を持って導出 する
    • boolean の組み合わせより 取りうる値の集合 で状態を表す
    • サーバーデータの SSOT はキャッシュ 1 か所。さらにコピーしない
