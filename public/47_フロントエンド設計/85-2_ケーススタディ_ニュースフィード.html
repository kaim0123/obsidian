    85 ケーススタディ

    ケーススタディ：ニュースフィード — 無限スクロールと楽観的更新

    SNS のタイムラインのような ニュースフィード を、RADIO テンプレート に沿って設計します。無限スクロール・カーソルページネーション・仮想化・楽観的更新・feed パターンのアクセシビリティを、47 の各ページの知識を組み合わせて使います。

    もとにしたノート：02_ケーススタディ_ニュースフィード

    ひとことで言うと

    フィードは サーバー状態が主役 で、クライアント状態はほとんど持ちません。新着が増え続けるデータなので カーソルページネーション、続きの読み込みは IntersectionObserver、大量件数は 仮想化、いいねは 楽観的更新 + 失敗時のロールバック で作ります。

    1.このページで扱うこと

    SNS のタイムラインのような ニュースフィード を、RADIO テンプレート に沿って設計します。

    • R：要件（機能・非機能・a11y・範囲外）
    • A：全体構成（コンポーネントの分け方、サーバー状態とクライアント状態）
    • D：データモデル（Post・User・FeedPage）
    • I：サーバー API とカーソルページネーション、コンポーネントの Props
    • O：無限スクロール、仮想化、楽観的更新、アクセシビリティ、エラー

    2.R — 要件

    種類内容
    機能投稿の一覧を新しい順に表示 / 下までスクロールすると続きを読み込む / いいねできる
    非機能モバイル中心。数百件スクロールしてもカクつかない。初期表示が速い
    a11yキーボードで投稿間を移動でき、スクリーンリーダーで読める
    範囲外投稿の作成・コメント・リアルタイム通知

    3.A — 全体構成

      FeedPage（ページ）
   └─ Feed（一覧・読み込み制御）          ← サーバー状態を購読
       ├─ FeedItem × N（1 件の表示）       ← Props だけで描画
       │    └─ LikeButton（いいね）        ← 楽観的更新
       └─ LoadMoreSentinel（末尾の目印）   ← 見えたら次ページを取得
    • サーバー状態：投稿一覧（サーバー状態ライブラリでキャッシュ）
    • クライアント状態：ほぼ無し（スクロール位置はブラウザ・ライブラリに任せる）
    • レンダリング：最初のページは SSR、以降は CSR で追加取得

    Feed はデータ取得と読み込み制御、FeedItem は表示だけ、と責務を分けます（コンポーネントの分割粒度と境界、32_React のノート『10-2-Container-Presentational』）。

    4.D — データモデル

    エンティティ主なフィールド置き場所
    Postid, author, body, createdAt, likeCount, likedByMeサーバー状態（ページ単位のキャッシュ）
    User（作者）id, name, avatarUrlPost に埋め込み（表示専用）
    FeedPageitems: Post[], nextCursorサーバー状態

    likeCount は サーバーが真実の源 です。クライアントは楽観的に書き換えますが、最終的にはサーバーの値に合わせます（SSOT と派生状態）。

    5.I — インターフェース

    5.1 サーバー API

    GET  /feed?cursor=<opaque>&limit=20
  → { items: Post[], nextCursor: string | null }
POST /posts/:id/like     DELETE /posts/:id/like

    <opaque> は、クライアントが中身を解釈しない「続きの位置を表す目印の文字列」という意味です。オフセット方式ではなくカーソル方式 にします。

    方式長所短所
    オフセット（?page=3）任意のページに飛べる読んでいる間に新着が入ると、重複・抜けが起きる
    カーソル（?cursor=...）新着が入っても重複しない任意ページへのジャンプはできない

    フィードは先頭に新着が増え続けるので、カーソル方式が向きます。ページネーションの方式そのものは 45章：ページネーション・フィルタ・ソート でも扱っています。

    5.2 コンポーネントの Props

    type FeedItemProps = {
  post: Post;
  onLikeToggle: (postId: string) => void;
};

    FeedItem はデータ取得を知らず、Props だけで描画します（Props はコンポーネントの公開 API）。

    6.O — 最適化と深掘り

    6.1 無限スクロール

    末尾の目印（sentinel）が画面に入ったら次ページを取得します。スクロールイベントを監視するより、IntersectionObserver（要素が画面に入った・出たをブラウザが通知してくれる API）のほうが軽量です。

    function LoadMoreSentinel({ onVisible }: { onVisible: () => void }) {
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => {
    const el = ref.current;
    if (!el) return;
    const io = new IntersectionObserver(([e]) => e.isIntersecting && onVisible());
    io.observe(el);
    return () => io.disconnect();
  }, [onVisible]);
  return <div ref={ref} aria-hidden="true" />;
}

    6.2 仮想化

    数百件を DOM に全部置くとメモリと描画が重くなります。見えている範囲だけ DOM を作る仮想化（TanStack Virtual など）を使います（パフォーマンスを設計で作り込む）。

    仮想化する

    • 数百件以上になる
    • 行の高さがおおむね計算できる

    仮想化しない

    • 数十件で止まる
    • ブラウザの「ページ内検索」を必ず効かせたい

    6.3 楽観的更新（いいね）

    楽観的更新 とは、サーバーの応答を待たずに「たぶん成功する」と見込んで先に表示を変えるやり方です。押した瞬間に表示を変え、失敗したら元に戻します。

      クリック → キャッシュの likedByMe / likeCount を即書き換え → POST
            成功: サーバーの値で上書き
            失敗: 書き換え前に戻してトースト表示
    1. クリック — キャッシュの likedByMe / likeCount を即書き換え、POST を送る
    2. 成功 — サーバーの値で上書き（真実の源はサーバー）
    3. 失敗 — 書き換え前に戻してトースト（画面の隅に短く出る通知）を表示

    6.4 アクセシビリティ

    • 一覧は role="feed"、各投稿は <article> とし、aria-setsize / aria-posinset で位置を伝える（WAI-ARIA の feed パターン）
    • 読み込み中は aria-busy="true" を付ける
    • いいねボタンは aria-pressed で状態を伝える（アクセシビリティを部品設計に組み込む）

    6.5 エラー

    次ページの取得失敗は一覧全体を壊さず、末尾に「再読み込み」ボタンを出します（エラー境界とフォールバック UI）。

    7.よくある誤解

    誤解1：「ページネーションは ?page=N で十分」

    新着が増え続けるフィードでは、オフセット方式は重複・抜けが起きます。 読んでいる間に先頭へ新着が入ると、次のページの範囲がずれるからです。「この投稿の後ろから」で取るカーソル方式にします。一方、総件数が必要で任意ページに飛ぶ管理画面の一覧ではオフセット方式が向きます（管理画面の一覧とフォーム）。

    誤解2：「楽観的更新ならサーバーの値は気にしなくてよい」

    真実の源はサーバーです。 楽観的更新は表示を先回りして変えるだけで、成功したらサーバーの値で上書きし、失敗したら書き換え前に戻します。

    誤解3：「無限スクロールはスクロールイベントで末尾を判定すればよい」

    スクロールイベントは頻繁に発火して重くなりがちです。 末尾に目印（sentinel）を置き、IntersectionObserver で「画面に入った」ことを通知してもらうほうが軽量です。

    8.まとめ

    • フィードは サーバー状態が主役。クライアント状態はほとんど持たない
    • 新着が増え続けるデータには カーソルページネーション
    • 無限スクロールは IntersectionObserver、大量件数は 仮想化
    • いいねは 楽観的更新 + 失敗時のロールバック
    • role="feed" と aria-busy で読み込み中の状態を伝える
