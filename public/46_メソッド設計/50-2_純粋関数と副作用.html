    50 副作用と状態

    純粋関数と副作用 — 予測できてテストしやすい関数を書く

    同じ引数で呼んだのに、呼ぶたびに結果が変わる関数は、読むのもテストするのも大変です。このページでは、純粋関数 と 副作用 の意味、副作用の種類、テストしやすい関数の書き方、依存を引数で渡す方法、並行処理との関係を学びます。最後に、実務でよく作る共通処理を「純粋関数」と「副作用」に仕分けた例を見ます。

    もとにしたノート：02_純粋関数と副作用、05_共通処理と純粋関数・副作用の仕分け

    ひとことで言うと

    純粋関数 は「同じ入力なら常に同じ出力を返し、戻り値以外で外に影響しない」関数です。DB・HTTP・時刻・乱数・グローバル変数といった 副作用 は、なくすのではなく 処理の境界（外側）に押し出し、計算や判定の核を純粋関数にすると、テストしやすく並行処理にも強いコードになります。

    1.このページで扱うこと

    このページは、純粋関数 と 副作用 を理解し、テストしやすいメソッドの書き方を学ぶページです。

    • 純粋関数とは何か（同じ入力 → 同じ出力）
    • 副作用の種類（I/O・グローバル状態・例外・時刻）
    • 副作用を境界に押し出して、テストしやすくする書き方
    • 依存を引数で明示する方法
    • 並行処理との関係

    関数型の設計原則としての一般論は 42章：関数型と純粋関数 にまとめています。このページは メソッドを書くときの判断 に焦点を当てます。

    2.純粋関数とは — 同じ入力 → 同じ出力

    純粋関数（Pure Function）とは、次の2つを満たす関数です。

    1. 同じ入力に対し、常に同じ出力 を返す
    2. 副作用がない（戻り値以外に外部へ影響しない）

    副作用 とは、戻り値を返す以外に、関数の外の状態を読んだり変えたりすることです（ファイルへの書き込み、画面表示、グローバル変数の変更など）。

    ◯ 純粋関数 
    function add(a, b) {
  return a + b;
}

function calculateTotal(items) {
  return items.reduce((sum, i) => sum + i.price * i.qty, 0);
}

    純粋関数は 予測可能 で、テストが最も簡単 です。引数を渡して、戻り値を確かめるだけで済むからです。

    3.副作用の種類（I/O・グローバル状態・例外・時刻）

    副作用例
    I/Oファイル読み書き、DB、HTTP
    グローバル状態モジュール変数の変更、シングルトン
    例外throw（議論の余地あり）
    時刻・乱数Date.now(), Math.random()

    I/O（Input/Output）は、ファイル・DB・ネットワークなど、プログラムの外とのデータの出し入れのことです。シングルトン は、プログラム全体で1つだけ存在するオブジェクトで、実質的にグローバル変数と同じ働きをします。

    ✕ 副作用あり：同じ入力でも出力が変わる、または外に影響する 
    function createId() {
  return Date.now().toString();  // 時刻依存
}

function saveOrder(order) {
  db.insert(order);  // I/O
}

    4.テストしやすい関数の書き方

    副作用を境界に押し出し、核を純粋関数にします。

    ✕ 悪い例：計算と I/O が全部混在 
    function processOrder(order) {
  const total = order.items.reduce(/* ... */);
  db.save({ ...order, total });
  email.send(order.customer);
}
    ◯ 良い例：計算は純粋、I/O は外 
    function calculateOrderTotal(items) {
  return items.reduce((s, i) => s + i.price * i.qty, 0);
}

function processOrder(order, db, email) {
  const total = calculateOrderTotal(order.items);
  db.save({ ...order, total });
  email.send(order.customer);
}

    calculateOrderTotal だけを取り出して、入力と出力 でテストできます。DB やメールの準備は要りません。

    5.依存を引数で明示する

    依存性注入（DI：Dependency Injection。使う部品を中で作らず、外から渡してもらうこと）のメソッド版です。副作用の源を 引数 で渡します。

    ◯ 時刻依存を引数化する 
    function isExpired(deadline, now = Date.now()) {
  return now > deadline;
}

// テスト
isExpired(futureDate, fixedTimestamp);  // 固定時刻でテスト

    グローバルな db や config を直接参照せず、引数またはコンストラクタで渡すとテストが容易です（→ テストしやすいメソッド設計）。

    6.並行処理との関係

    副作用と 共有 mutable 状態（複数の処理から同時に書き換えられる変数）は、並行処理でバグの温床になります。

    ✕ 危険：グローバルカウンタ 
    let count = 0;
function increment() {
  count++;  // 競合状態
}
    ◯ 安全：純粋関数 ＋ 新しい値を返す 
    function increment(count) {
  return count + 1;
}

    競合状態（レースコンディション）とは、複数の処理が同じデータを同時に読み書きして、実行のタイミング次第で結果が変わってしまう状態です。純粋関数は共有された状態を触らないので スレッドセーフ（同時に呼ばれても壊れない）で、並行処理と相性が良いです。

    この考え方は Functional Core, Imperative Shell で実践します。

    7.実務例：共通処理を純粋関数と副作用に仕分ける

    ここからは実務の例です。業務アプリ（例：Supabase を使った社内システム）で共通化することが多い処理を挙げ、それぞれが純粋関数として書けるか、副作用を伴うかを仕分けます。Supabase は、データベース・認証・ファイル保存などをまとめて提供するサービスです。

    7.1 共通化することが多い処理

    • 認証・認可：Supabase Auth、権限チェック、ロール判定
    • API層：Supabase へのアクセスをラップした共通関数
    • UIコンポーネント：ボタン、フォーム、テーブル、モーダルなど
    • フォーム処理：バリデーション、送信、エラー表示
    • ユーティリティ：日付・金額・文字列・UUID・CSV・PDF などの共通関数
    • 通知：トースト表示、メール送信、Slack/LINE 通知
    • ファイル処理：Supabase Storage へのアップロード・ダウンロード
    • 監査ログ：誰がいつ何を変更したかの記録
    • マスタデータ取得：部署・社員・役職・都道府県などの共通取得処理
    • 型定義：共通の TypeScript 型や Zod スキーマ（Zod は入力の形を検証するライブラリ）
    • 定数・設定：ルート、権限名、環境設定、エラーメッセージ

    7.2 純粋関数にできる共通処理

    ユーティリティ系の共通処理の多くは、引数だけから結果を決められるので 純粋関数 として書けます。

    共通処理純粋関数副作用
    日付フォーマット○
    金額フォーマット○
    電話番号フォーマット○
    郵便番号フォーマット○
    ファイルサイズ表示○
    UUID 生成（ランダム）○
    ランダム文字列生成○
    Base64 変換○
    JSON 変換○
    CSV⇔JSON 変換○
    XML⇔JSON 変換○
    ハッシュ化○
    暗号化・復号○
    バリデーション○
    権限判定（引数のみ）○
    ページネーション計算○
    ソート○
    フィルタ○
    検索条件生成○
    定数取得○
    Enum 変換○
    エラーメッセージ生成○
    URL 生成○
    • UUID（重複しないランダムな ID）やランダム文字列は、呼ぶたびに違う値になるので副作用です
    • 「権限判定」は、ユーザーやロールを引数で受け取る 場合に純粋です。中で DB やセッションを読みにいくと副作用になります
    • ハッシュ化や暗号化でも、中で乱数（ソルトや初期化ベクトル）を作る実装は副作用を持ちます。乱数を引数で受け取れば、残りを純粋にできます
    • ソートは、JavaScript の sort() のように 元の配列を書き換える 書き方をすると純粋ではなくなります（→ 引数の破壊的変更とイミュータブル）

    7.3 副作用になるもの

    次のものは 外部世界とのやり取り なので副作用です。これらを共通化した関数は、境界（外側）に置きます。

    分類副作用になる処理
    データベースCRUD、SELECT、INSERT、UPDATE、DELETE、Transaction
    APIfetch、axios、GraphQL、RPC
    ファイルUpload、Download、S3 保存、削除、PDF 保存、Excel 保存
    メールメール送信、添付送信
    通知LINE 通知、Slack 通知、Push 通知、Toast 表示
    認証ログイン、ログアウト、JWT 発行、Cookie 保存、Session 保存
    ログconsole.log、ファイルログ、DB ログ
    キャッシュRedis、LocalStorage、SessionStorage、Cookie
    ReactuseEffect、DOM 操作、state 更新、Router 遷移
    環境環境変数取得、現在時刻取得、Math.random()

    DB の SELECT（読み込み）も、いつ呼ぶかで結果が変わる ので副作用の側に入ります。読み込むだけでも、外の世界に依存しているからです。同じ「いつ・何回」の物差しで3つに分ける考え方は アクション・計算・データ で扱います。

    8.よくある誤解

    誤解1：「副作用は悪いものだから、なくすべき」

    違います。 DB への保存やメール送信がなければ、プログラムは何の役にも立ちません。目標は副作用をなくすことではなく、境界に押し出して、核を純粋関数にする ことです。

    誤解2：「データを読むだけなら副作用ではない」

    読むだけでも、外の状態に依存すれば純粋ではありません。 Date.now()・環境変数・DB の SELECT は、呼ぶタイミングで結果が変わります。値を引数で受け取るようにすると、その関数は純粋になります。

    誤解3：「共通化したユーティリティは全部純粋関数」

    違います。 UUID 生成やランダム文字列生成、ログ出力、トースト表示も共通処理としてよく作られますが、副作用です。共通化するときは、どちらの仲間かを意識して置き場所を分けます。

    9.まとめ

    • 純粋関数 ＝ 同じ入力 → 同じ出力、副作用なし
    • 副作用 は I/O・グローバル状態・時刻・乱数など。境界に押し出す
    • 依存（時刻・DB・設定）を 引数で明示 し、テスト容易性を上げる
    • 並行処理では、共有状態を触らない純粋関数が安全
    • 実務の共通処理は、フォーマット・変換・バリデーションなどは純粋関数、DB・API・ファイル・通知・認証・ログ・キャッシュ・環境の取得は副作用、と仕分けられる
