    40 本体の書き方

    段落と説明用の変数 — 抽出する前に効く読みやすさの基本

    長いメソッドを見ると、すぐに小さなメソッドへ分けたくなります。でもその前に、もっと手軽で効く方法があります。このページでは、処理のまとまりごとに 段落（空行） を入れること、目的ごとに変数を用意する（説明用の変数）こと、1つの変数を使い回す 破壊的代入 を避けることを学び、段落 → 説明用変数 → メソッド抽出という安全な進め方を紹介します。

    もとにしたノート：05_段落と説明用の変数

    ひとことで言うと

    まず 空行で段落を分けて 手順を見せ、次に 目的ごとに名前の付いた変数 を用意して意図を語らせます。1つの変数の意味を途中で変える 破壊的代入 は避けます。意図が見えてきたら、そのまとまりを Extract Method でメソッドに閉じ込めます。

    1.このページで扱うこと

    長いメソッドを いきなり抽出する前 に効く、読みやすさの基本を学びます。

    • 処理のまとまりごとに 段落（空行） を分ける
    • 目的ごとに変数を用意する（説明用の変数の導入）
    • 1つの変数を使い回す 破壊的代入 を避ける

    増田亨『現場で役立つシステム設計の原則』第1章「プログラムの変更が楽になる書き方」、および Fowler『リファクタリング』の Introduce Explaining Variable（説明用変数の導入）に相当する内容です。抽出そのものは Extract Method、長さと抽象度は サイズと抽象度 を参照してください。

    2.長いメソッドは「段落」に分ける

    処理の 意味のまとまり ごとに空行を入れると、メソッド全体の手順が見えます。文章を段落に分けるのと同じ考え方です。

    ✕ 悪い例：段落がなく、ステップが一塊に見える 
    function itemPrice(quantity: number, unitPrice: number, taxRate: number): number {
  let price = quantity * unitPrice;
  if (price < 3000) price += 500;
  price = price * taxRate;
  return price;
}
    ◯ 良い例：段落で「基本価格 → 送料 → 税込」が読める 
    function itemPrice(quantity: number, unitPrice: number, taxRate: number): number {
  let price = quantity * unitPrice;

  if (price < 3000) {
    price += 500; // 送料
  }

  price = price * taxRate;
  return price;
}

    2.1 段落をまたがない

    同じ関心事の処理を、別の関心事の段落のあいだに挟まないようにします。

    ✕ 悪い例：送料判定と加算のあいだに税計算が割り込む 
    function itemPrice(quantity: number, unitPrice: number, taxRate: number): number {
  let price = quantity * unitPrice;
  const needsPostage = price < 3000;

  price = price * taxRate;

  if (needsPostage) price += 500;
  return price;
}

    送料の判定と加算が離れているので、読み手は「送料」の話を頭に置いたまま税計算を読むことになります。

    抽出のサイン

    段落の見出しコメント（// --- 送料 ---）が増えてきたら、Extract Method の候補です。

    3.目的ごとに変数を用意する

    1つの変数に何度も代入し直し、意味を変えていく書き方を 破壊的代入 と呼びます。読み手は「いまこの変数は何を表しているか」を常に追跡しなければなりません。

    ✕ 悪い例：price の意味が途中で変わる 
    function itemPrice(quantity: number, unitPrice: number, taxRate: number): number {
  let price = quantity * unitPrice; // 数量 × 単価
  if (price < 3000) price += 500;   // 送料込み
  price = price * taxRate;          // 税込
  return price;
}
    ◯ 良い例：目的ごとに変数を分ける（説明用の変数） 
    function itemPrice(quantity: number, unitPrice: number, taxRate: number): number {
  const basePrice = quantity * unitPrice;

  const shippingCost = basePrice < 3000 ? 500 : 0;

  const total = (basePrice + shippingCost) * taxRate;
  return total;
}
    ねらい効果
    変数名が意図を語るコメントなしでも手順が追える
    代入が少ない「いつ変わったか」の追跡が不要になる
    const で固定しやすい意図しない上書きを防げる

    const は、一度入れた値を再代入できない変数の宣言です（let は再代入できます）。

    オブジェクトや配列の中身を書き換える話は 引数の破壊的変更とイミュータブル で扱います。ここでは ローカル変数の使い回し に焦点を当てています。

    4.段落 → 説明用変数 → メソッド抽出、の順

    現場では次の順で進めると安全です。

    1. 段落 でまとまりを見せる
    2. 目的ごとの変数 で意図を名前にする
    3. まとまりを メソッドに抽出 する（Extract Method）
    4. 重複があれば クラス側へ寄せる（44章のクラス分割）
    ◯ 抽出後のイメージ 
    function itemPrice(quantity: number, unitPrice: number, taxRate: number): number {
  const basePrice = quantity * unitPrice;
  const shippingCost = shippingCostFor(basePrice);
  return (basePrice + shippingCost) * taxRate;
}

function shippingCostFor(basePrice: number): number {
  return basePrice < 3000 ? 500 : 0;
}

    メソッドを短く保つ話は サイズと抽象度、業務の関心事ごとの小さなクラスは 44章：ドメインを表すクラス・44章：値オブジェクトと完全コンストラクタ を参照してください。

    5.よくある誤解

    誤解1：「空行は見た目だけの問題で、設計とは関係ない」

    違います。 段落は処理の意味のまとまりを示し、どこを抽出すればよいかの手がかりになります。同じ関心事を別の段落のあいだに挟まないことも大切です。

    誤解2：「変数を増やすとコードが長くなるので、使い回した方がよい」

    逆です。 1つの変数の意味が途中で変わると、読み手は「いま何を表しているか」を追い続けなければなりません。目的ごとに名前を付けた変数の方が、コメントなしでも手順が追えます。

    誤解3：「長いメソッドは、まずメソッドに分割すべき」

    いきなり分割しなくても構いません。 段落と説明用の変数で意図を見えるようにしてから抽出すると、どこで切るべきかがはっきりし、安全に進められます。

    6.まとめ

    • 段落 で処理のステップを見せる。関心事をまたいで挟まない
    • 説明用の変数 で目的を名前にし、破壊的代入を避ける
    • 段落・変数で意図が見えたら、Extract Method で閉じ込める
