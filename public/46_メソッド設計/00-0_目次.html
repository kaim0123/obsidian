    メソッド設計解説 — 目次

    Obsidian の「46_メソッド設計」ノートをもとにした解説ページの入口です。1つの関数・メソッドを「どう切り出し、どんな形にし、中身をどう書くか」——いちばん小さな単位の設計を、責務と分割・シグネチャ・本体の書き方・副作用と状態・契約とエラー・品質と運用まで、全38ページで解説します。

    もとにしたノート：MOC_メソッド設計体系 と、10〜90 の各フォルダのノート

    1.このサイトの読み方

    ページは MOC のフォルダ構成（メソッドの構成要素別：責務 → シグネチャ → 本体 → 副作用 → 契約とエラー）と同じ順番に並んでいます。各ページの下にある「前のページ／次のページ」で順に読み進められ、上部の「メソッド設計解説」からいつでもこの目次に戻れます。どのページも単体で読めるように書いてあるので、気になるテーマから読んでもかまいません。

    46 章の骨格は McConnell『Code Complete』第7章「高品質なルーチン」と Martin『Clean Code』第3章「関数」で、そこに Ousterhout『A Philosophy of Software Design』（深いメソッド・エラーが起きない設計）、Fowler『リファクタリング』第2版、Normand『Grokking Simplicity』（アクション／計算／データ）の視点を加えています。クラスの責務や GoF は クラス設計・デザインパターン解説（44）、モジュール単位の分割は モジュール設計解説（43）が本拠地です。

    はじめて学ぶなら

    まず メソッド設計の全体像 で地図を手に入れ、10 メソッドの基礎 → 20 責務と分割の順に進むのがおすすめです。

    歴史から理解したいなら

    メソッド設計の変遷 で、goto の時代から構造化・OOP・関数型まで、ルールが生まれた順にたどります。

    今日のコードを直したいなら

    Guard Clause・Extract Method・チェックリスト から。すぐ使える技法です。

    おすすめの読む順

    もとの教材（全8部・25章）の学習順です。各フォルダの後半にある「深掘り」ページ（20-5、30-4、40-4・40-5、50-5・50-6、60-3・60-4）は、慣れてきてから読み返してもかまいません。

    3.10 メソッドの基礎

    メソッドとは何か、なぜ設計するのか。

    10-1

    メソッド設計を学ぶ理由

    クラス設計・モジュール設計との違い、巨大な main から関数へ、メソッド設計が解決する問題、今日からできる最初の一歩

     10-2

    関数とメソッドの基本

    関数とメソッドの違い、サブルーチン、構造化プログラミング、引数・戻り値・副作用、呼び出し関係の読み方

    4.20 責務と分割

    どこで切るか、何を1つにまとめるか。

    20-1

    メソッドの分割

    1関数に全部書く問題、段階的詳細化、同じ抽象度のステップ、粒度の判断、分割ワークショップ

     20-2

    関心の分離と単一責任

    関数レベルの関心の分離、1メソッド1変更理由、オーケストレーション関数と詳細関数、名前で責任を表す

     20-3

    KISS・DRY・YAGNI

    3原則のメソッドでの使い方、原則同士の衝突、変更理由で判断するコツ、判断ワークショップ

     20-4

    Extract Method

    抽出候補になる長い関数のパターン、抽出の手順、Replace Temp with Query、抽出しすぎの落とし穴

     20-5

    深いメソッドと浅いメソッド

    深さ（コストと利益）、一緒にすべきサイン・分けるべきサイン、良い分割と悪い分割、Clean Code との付き合い方

    5.30 シグネチャ設計

    外からどう見えるか。名前・引数・戻り値。

    30-1

    命名

    動詞＋目的語、is/has/can/should の boolean、意図が伝わる名前、業務の用語、検索しやすい名前、命名規約

     30-2

    引数の設計

    引数の数の目安、Parameter Object、フラグ引数の問題、出力引数を避ける、Introduce Parameter Object

     30-3

    情報隠蔽

    関数レベルの情報隠蔽、公開 API と内部ヘルパーの線引き、戻り値・引数で内部表現を漏らさない

     30-4

    戻り値の設計

    番兵値を避ける、boolean、null・Optional、例外と Result 型、空のコレクション、複数の値、Promise

    6.40 本体の書き方

    中身をどう読ませるか。長さ・ネスト・分岐・ループ。

    40-1

    サイズと抽象度

    関数は小さく、1関数1抽象度、20行の目安とその限界、構造のコメントは抽出のサイン、クラスも小さく

     40-2

    Guard Clause

    ネストした if の問題、早期 return、else をなくす、if-else のままでよい対称的な分岐

     40-3

    複雑度と分岐

    循環的複雑度の測り方と目安、ポリモーフィズム・ルックアップへの置き換え、CI の閾値、区分の if と複文

     40-4

    ループとコレクション処理

    Replace Loop with Pipeline、map・filter・find・some の使い分け、reduce の乱用、ループが向く場面、非同期

     40-5

    段落と説明用の変数

    空行で段落に分ける、説明用の変数、破壊的代入を避ける、段落 → 変数 → 抽出の進め方

    7.50 副作用と状態

    何を変えるか。状態変更・I/O・純粋さ。

    50-1

    CQS

    Command と Query の分離、getter に副作用を入れない理由、lazy 初期化などの例外、CQRS との違い

     50-2

    純粋関数と副作用

    純粋関数の定義、副作用の種類、副作用を境界に押し出す、依存の引数化、共通処理の仕分け

     50-3

    Functional Core, Imperative Shell

    核は純粋・外縁だけ I/O、Core と Shell の境界、ユースケース層での実践、OOP と FP の役割分担

     50-4

    オブジェクトのメソッド

    状態に対する操作としてのメソッド、Tell, Don't Ask、貧血モデル、ドメインルールの配置

     50-5

    アクション・計算・データ

    3分類の定義と見分け方、伝染のルール、暗黙的な入出力、計算を取り出す手順

     50-6

    引数の破壊的変更とイミュータブル

    破壊的な配列メソッド、ES2023 の toSorted など、コピーオンライト、防御的コピー、浅い・深いコピー、readonly

    8.60 契約とエラー

    失敗をどう扱うか。前提条件・例外・null。

    60-1

    Design by Contract

    事前条件・事後条件・不変条件、Fail Fast、先頭での前提チェック、Guard Clause との関係

     60-2

    エラー処理

    例外を使う場面・使わない場面、try-catch を境界に集める、分かりやすいエラーメッセージ、null の扱い

     60-3

    エラーが起きない設計にする

    エラーを定義からなくす・隠す・まとめる・クラッシュさせる、4技法の使い分けとやりすぎの注意

     60-4

    null・undefined・Result型

    10億ドルの過ち、strictNullChecks、null と undefined の統一、?. と ??、例外と Result 型、neverthrow

    9.70 品質と運用

    70-1

     70-3

    コードレビューで見るポイント

     70-4
