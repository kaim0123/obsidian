    90 付録

    用語集と推奨図書 — 用語を引き、次に読む本を選ぶ

    この教材（メソッド設計）に出てくる主な用語を五十音順にまとめ、それぞれを詳しく説明しているページへリンクしました。後半では、メソッド設計をさらに深く学ぶための書籍・オンライン資料、関連する章、学ぶ順序を紹介します。読んでいて分からない言葉が出てきたときの「辞書」として使ってください。

    もとにしたノート：付録A_用語集、付録G_推奨図書

    ひとことで言うと

    用語集は「一言説明」と「解説ページ」のセットです。分からない言葉は一言説明で思い出し、しっかり理解したいときは解説ページを開きます。教材で技法を身につけたら、Clean Code 第3章で関数ルールを復習し、Refactoring を技法カタログとして手元に置くのがおすすめです。

    1.このページで扱うこと

    • 用語集：教材に登場する主要用語の一言説明と、その用語を解説しているページ
    • 推奨図書・学習リソース：入門〜中級、中級〜上級、関数型・副作用の書籍と、オンライン資料、関連する章
    • 学習のすすめ方：この教材のあと、どの順番で本を読むとよいか

    使い方

    用語集の説明は「一言」だけです。意味をしっかり理解したいときは、右の列の「解説ページ」を開いてください。メソッド設計の基本用語は 関数とメソッドの基本 でもまとめて説明しています。

    あわせて メソッド設計の全体像、設計レビューの実践 も読み返すと、学んだ技法をレビューの場で使う感覚がつかめます。

    4.よくある誤解

    誤解1：「用語の一言説明を覚えれば理解したことになる」

    用語集の説明は思い出すための手がかりにすぎません。たとえば「CQS」は、なぜ読む操作と書く操作を分けるのか、分けないと何が困るのかまで分かって初めて設計に使えます。解説ページで例と一緒に確認してください。

    誤解2：「CQS と CQRS は同じもの」

    名前は似ていますが、範囲が違います。CQS は1 つのメソッドを「読む」か「書く」かのどちらかにする原則、CQRS はシステム全体で読み取り用と書き込み用のモデルを分ける設計です。メソッド設計で主に扱うのは CQS です。

    誤解3：「推奨図書は全部読んでから実践する」

    学習のすすめ方のとおり、まず本教材で技法を身につけ、実際のコードで使いながら Clean Code や Refactoring を必要な箇所から参照するほうが身につきます。Refactoring は通読するより「カタログ」として引く本です。

    5.まとめ

    • 用語集は「一言説明」と「解説ページ」のセット。分からない言葉は解説ページで例と一緒に確認する
    • 入門〜中級の必読は Clean Code・Refactoring・Code Complete・『現場で役立つシステム設計の原則』
    • 中級〜上級はレガシー改善（Feathers）、実装パターン（Beck）、DbC・CQS の原典（Meyer）。関数型の視点は Atencio・Wlaschin の本で補う
    • 学ぶ順序は「本教材で技法 → Clean Code 第3章 → Refactoring のカタログ → 変遷で歴史」
