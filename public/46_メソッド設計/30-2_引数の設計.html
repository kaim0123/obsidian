    30 シグネチャ設計

    引数の設計 — 少なく、まとめて、書き換えない

    引数が増えるほど、呼ぶ側は「何をどの順番で渡すか」を覚えなければなりません。このページでは、引数の数の目安、関連する引数をまとめる Parameter Object、フラグ引数の問題、出力引数の回避、そして引数リストを段階的に直すリファクタリングの手順を解説します。

    もとにしたノート：02_引数の設計

    ひとことで言うと

    引数は 0〜2 個が理想 で、3 個以上なら Parameter Object にまとめることを検討します。boolean の フラグ引数 は関数を分けるサイン、結果は引数を書き換えず 戻り値で返す のが基本です。

    1.このページで扱うこと

    引数の数・形・意味 を設計します。

    • 引数の数 — 0〜2 が理想、3 以上は要検討
    • Parameter Object — 引数の塊をオブジェクトにまとめる
    • フラグ引数（boolean の引数）の問題
    • 出力引数（引数を書き換えて結果を返す）の回避
    • 引数リストのリファクタリング実践（Introduce Parameter Object）

    2.引数の数 — 0〜2 が理想、3 以上は要検討

    Clean Code では 引数は少ないほどよい とされます。

    引数の数評価
    0（niladic）理想。状態を持つメソッドや、コンテキストが明確なとき
    1（monadic）よくある
    2（dyadic）許容範囲
    3 以上要検討 — Parameter Object を検討

    niladic・monadic・dyadic は、それぞれ「引数0個・1個・2個」を表す英語です。

    ✕ 3 引数以上 → オブジェクト化を検討 
    function createUser(name, email, age, address, phone) { /* ... */ }

    引数が多いと、呼ぶ側で 順番を間違えやすく、どの値が何を意味するのかも呼び出しの行だけでは読み取れません。

    3.Parameter Object — 引数の塊をオブジェクト化

    Parameter Object は、関連する引数を 1 つのオブジェクトにまとめるパターンです。

    ✕ Before：6 個の引数 
    function sendInvoice(to, subject, body, cc, bcc, template) { /* ... */ }
    ◯ After：1 つのオブジェクトで受け取る 
    function sendInvoice(options) {
  const { to, subject, body, cc, bcc, template } = options;
  /* ... */
}

// または型・クラスで
class InvoiceMailOptions {
  constructor(to, subject, body) { /* ... */ }
}

    シグネチャが安定する

    引数を追加しても、関数のシグネチャ（名前・引数・戻り値の形）の変更が少なくて済む

    名前付きで呼べる

    { to, subject } のように名前を書いて渡せるので、順番を間違えない

    検証を集約できる

    バリデーション（値が正しいかの確認）を 1 か所に集められる

    4.フラグ引数（boolean）の問題

    フラグ引数 は、1 つの関数が 2 つの異なる処理 をしていることを示すサインです。

    ✕ 悪い例：フラグで分岐 
    function render(report, isHtml) {
  if (isHtml) { /* HTML 出力 */ }
  else { /* テキスト出力 */ }
}
    ◯ 良い例：関数を分ける 
    function renderHtml(report) { /* ... */ }
function renderText(report) { /* ... */ }

    呼ぶ側の render(report, true) を見ても、true が何を意味するのか分かりません。分けた関数なら、名前だけで何をするかが分かります。

    フラグ引数は SRP 違反 の兆候です。SRP（単一責任の原則）は「1 つのモジュールは変更する理由を 1 つだけ持つべき」という原則です（→ 関心の分離と単一責任、44章：単一責任の原則）。

    5.出力引数（副作用で値を返す）の回避

    出力引数 とは、引数として渡したオブジェクトを 関数内で変更 して結果を返す手法です。

    ✕ 悪い例：出力引数（C 言語的） 
    function fillResult(input, result) {
  result.total = input.price * input.qty;
}
    ◯ 良い例：戻り値で返す 
    function calculateTotal(input) {
  return input.price * input.qty;
}

    戻り値で返すほうが 読みやすく・テストしやすい です。複数の値を返したいときは、オブジェクトや配列で返します（→ 戻り値の設計）。引数を書き換えることの問題は 引数の破壊的変更とイミュータブル でも扱います。

    6.引数リストのリファクタリング実践

    Introduce Parameter Object（引数オブジェクトの導入）は、Martin Fowler の『リファクタリング』にある技法です。手順は次のとおりです。

    1. 3 個以上の関連する引数を特定する
    2. 新しいクラスまたは型を定義する
    3. 引数を 1 つのオブジェクトに置き換える
    4. 呼び出し側を更新する
    5. テストで振る舞いが同じことを確認する
    // 段階的に
function search(query, page, pageSize, sortBy, sortOrder) { /* ... */ }

// → SearchCriteria オブジェクトへ
function search(criteria) {
  const { query, page, pageSize, sortBy, sortOrder } = criteria;
}

    詳細は ルール早見表とリファクタリング技法 を参照してください。

    7.よくある誤解

    誤解1：「引数を全部 1 つのオブジェクトに詰めれば解決」

    まとめるのは「関連する」引数です。 無関係な値を 1 つの options に押し込むと、関数が何を必要としているのかがかえって見えなくなります。意味のあるまとまり（SearchCriteria など）として名前を付けられるかで判断します。

    誤解2：「boolean 引数は 1 個だけなら問題ない」

    1 個でも、関数の中で 2 つの処理に分岐している なら関数を分けるサインです。呼ぶ側の true / false だけでは意味が読み取れない点も同じです。

    誤解3：「出力引数を使えば複数の値を返せて便利」

    複数の値は オブジェクトや配列を戻り値で返せます。出力引数は、呼ぶ側から見て「渡した値が書き換わる」ことが分かりにくく、テストもしにくくなります。

    8.まとめ

    • 引数は 0〜2 が理想。3 以上は Parameter Object を検討
    • フラグ引数 は関数分割のサイン（SRP 違反の兆候）
    • 出力引数より戻り値。複数値はオブジェクトや配列で返す
    • Introduce Parameter Object で段階的に改善し、テストで確認する
