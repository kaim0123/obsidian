    IDプロバイダとSSOプロバイダ

    IDプロバイダ（IdP） は「この人は本人です」と証明するサービス、SSOプロバイダ は「一度のログインで複数のサービスを使えるようにする」サービスです。このページでは、両者の基本概念と違いを初心者向けに整理し、Auth0・AWS Cognito・Okta・Microsoft Entra ID などのおすすめサービスと選び方のガイドまでを見ていきます。

    もとにしたノート：30_フェデレーション/04_IDプロバイダとSSOプロバイダとは

    このページで分かること

    • IDプロバイダ（IdP）の役割：ユーザー情報の管理・認証・認証情報の発行
    • SSOプロバイダの役割：一元認証・セッション管理・ユーザー管理
    • 両者の違いと関係（SSOプロバイダ ＝ IDプロバイダ ＋ セッション管理機能）
    • 個人開発・スタートアップ向け、エンタープライズ向け、中小企業向けのおすすめサービス
    • 用途別の選び方と、選ぶときに確認するポイント

    1.IDプロバイダ（IdP）とは

    1.1 基本概念

    IDプロバイダ（Identity Provider、IdP） は、ユーザーの身元（アイデンティティ）を管理し、認証を行うサービスです。認証 とは「ログインしようとしているのは本当にその人か」を確かめることです（認証と認可の違いは 認証と認可の違い を参照してください）。

    1.2 簡単な例え

    IDプロバイダ ＝ 身分証明書を発行する役所

    • ユーザーが「私は○○です」と証明するための情報を管理します
    • ログイン時に「本当にその人か？」を確認（認証）します
    • 確認が取れたら「この人は○○です」という証明書（トークン）を発行します

    トークン は、認証が済んだことを示す「デジタルな証明書」のようなデータです。くわしくは トークンベース認証：Bearer と JWT で説明しています。

    1.3 IDプロバイダの役割

    1. ユーザー情報の管理
      • ユーザー名、メールアドレス、パスワードなどの基本情報
      • プロフィール情報、権限情報など
    2. 認証（Authentication）
      • ユーザーが正しい本人かどうかを確認します
      • パスワード、多要素認証（MFA）（パスワードに加えてスマホの確認コードなど、別の種類の要素も使う認証）などで確認します
    3. 認証情報の発行
      • 認証が成功したら、トークンや証明書を発行します
      • 他のサービスが「この人は認証済みです」と判断できるようにします

    1.4 代表的なIDプロバイダ

    MicrosoftMicrosoftアカウントでログイン
    FacebookFacebookアカウントでログイン

    AppleApple IDでログイン
    AWS CognitoAWSが提供するIDプロバイダ

    2.SSOプロバイダとは

    2.1 基本概念

    SSOプロバイダ（Single Sign-On Provider） は、一度ログインすれば複数のアプリケーションやサービスに自動的にログインできるようにするサービスです。SSO（シングルサインオン）そのものの考え方は シングルサインオン（SSO）とアイデンティティプロトコル で図つきで説明しています。

    2.2 簡単な例え

    SSOプロバイダ ＝ 共通の入場券

    • 一度入場券を買えば、複数の施設に入れます
    • 各施設で個別にチケットを買う必要がありません

    2.3 SSOプロバイダの役割

    1. 一元認証
      • 1つのアカウントで複数のサービスにアクセスできます
      • ユーザーは1つのパスワードだけ覚えれば済みます
    2. セッション管理
      • ログイン状態（セッション）を管理します
      • 複数のサービス間でセッションを共有します
    3. ユーザー管理
      • 複数のサービスで共通のユーザー情報を管理します
      • 一元的にユーザーの追加・削除・権限変更ができます

    2.4 SSOの仕組み

    ユーザーは SSO プロバイダで一度だけログインし、発行されたトークンを各アプリが確認することで、アプリごとのログインが不要になります。

    ユーザー → SSOプロバイダでログイン
    ↓
認証成功 → SSOトークン発行
    ↓
アプリケーションA → SSOトークンを確認 → 自動ログイン OK
アプリケーションB → SSOトークンを確認 → 自動ログイン OK
アプリケーションC → SSOトークンを確認 → 自動ログイン OK

    図の SP（Service Provider：サービスプロバイダー） は、IdP を信頼して認証を任せる「実際に使うアプリ側」のことです。SAML を使った SSO の具体的なやり取りは SSO の仕組み（SAML の場合）、プロトコルの違いは SAML・OAuth・OIDCの違い を参照してください。

    2.5 代表的なSSOプロバイダ

    Google WorkspaceGoogleのSSOサービス

    3.IDプロバイダとSSOプロバイダの違い

    3.1 主な違い

    項目IDプロバイダ（IdP）SSOプロバイダ
    主な目的ユーザーの身元を証明複数サービスへの一元ログイン
    対象主に1つのサービス複数のサービス
    機能認証（Authentication）認証 ＋ セッション共有
    使用例GoogleアカウントでWebサイトにログイン企業内の複数システムに1回のログインでアクセス

    3.2 実際の関係

    多くの場合、SSOプロバイダはIDプロバイダの機能も含んでいます。

    • SSOプロバイダ ＝ IDプロバイダ ＋ セッション管理機能
    • SSOプロバイダは、IDプロバイダとしても機能します

    3.3 具体例

    IDプロバイダの例

    ユーザー → Googleアカウントでログイン
    ↓
認証成功 → Googleトークン発行
    ↓
WebサイトA → Googleトークンを確認
           → ログイン OK

    SSOプロバイダの例

    ユーザー → Oktaでログイン
    ↓
認証成功 → Oktaトークン発行
    ↓
社内システムA → Oktaトークンを確認 → 自動ログイン OK
社内システムB → Oktaトークンを確認 → 自動ログイン OK
社内システムC → Oktaトークンを確認 → 自動ログイン OK

    4.おすすめのIDプロバイダ

    価格・無料枠・機能はノート作成時点の情報です。変わることがあるので、最新の内容は各サービスの公式サイトで確認してください。

    以下の SDK は、各プログラミング言語から機能を呼び出すためのライブラリ一式のこと、エコシステム は、同じ会社のサービス群とその周辺ツールのことです。

    4.1 個人開発・スタートアップ向け

    1. Auth0

    特徴：開発者向け、柔軟なカスタマイズ

    メリット

    • 無料プランあり（月7,000ユーザーまで）
    • 豊富なドキュメントとサンプルコード
    • 多くの認証方式をサポート（OAuth 2.0、OpenID Connect、SAML）
    • 多言語SDKが充実

    デメリット

    • 無料プランには機能制限あり
    • 有料プランは高額

    価格：無料プランあり、有料は月$240〜
    おすすめ度：★★★★★

    2. AWS Cognito

    特徴：AWSエコシステムとの統合が容易

    メリット

    • AWSサービスと簡単に統合
    • 無料枠が充実（月50,000ユーザーまで）
    • スケーラブル（利用者が増えても対応しやすい）
    • コストパフォーマンスが良い

    デメリット

    • AWSの知識が必要
    • UIのカスタマイズが限定的

    価格：無料枠あり、従量課金
    おすすめ度：★★★★☆

    Cognito の構成要素やメリット・デメリットは AWS Cognito：複数の方式をまとめて提供するサービス でも説明しています。

    3. Firebase Authentication

    特徴：Googleが提供、モバイルアプリ向け

    メリット

    • 無料プランあり
    • モバイルアプリとの統合が簡単
    • Googleサービスとの連携が容易

    デメリット

    • 主にモバイルアプリ向け
    • カスタマイズの自由度が低い

    価格：無料プランあり
    おすすめ度：★★★★☆

    4. Supabase Auth

    特徴：オープンソース、PostgreSQLベース

    • 無料プランあり

    デメリット

    6.選び方のガイド

    6.1 用途別の選び方

    用途候補（優先順）
    個人開発・スタートアップ 1. Auth0 － 柔軟性と開発者体験を重視
    2. AWS Cognito － AWSを使用している場合
    3. Supabase Auth － オープンソースを好む場合
    中小企業 1. JumpCloud － コストパフォーマンス重視
    2. Okta － 機能の充実度を重視
    3. Microsoft Azure AD － Microsoft環境を使用している場合
    大企業・エンタープライズ 1. Okta － 最も包括的な機能
    2. Microsoft Azure AD － Microsoft環境を使用している場合
    3. Ping Identity － 高いカスタマイズ性が必要な場合

    社内システムのログインを「OIDC ＋ 社内 IdP」で組む考え方は 社内システム向け認証方式の選び方 で詳しく説明しています。

    6.2 選択のポイント

    1. 予算

    • 無料プランで始められるか
    • ユーザー数に応じたコスト
    • 隠れたコスト（サポート、追加機能など）

    2. 統合の容易さ

    • 使用しているアプリケーションとの統合
    • SDKやAPIの充実度
    • ドキュメントの質

    3. セキュリティ要件

    • 必要なセキュリティ機能（MFA、条件付きアクセスなど）
    • コンプライアンス要件（法律や業界ルールで求められる基準）への対応
    • 監査ログ（誰がいつ何をしたかの記録）の機能

    4. スケーラビリティ

    • ユーザー数の増加に対応できるか
    • パフォーマンス
    • グローバル展開への対応

    5. サポート

    • サポートの質と応答速度
    • コミュニティの活発さ
    • ドキュメントの充実度

    7.まとめ

    • IDプロバイダ：ユーザーの身元を証明するサービスです（ユーザー情報の管理・認証・トークンの発行）。
    • SSOプロバイダ：複数サービスへの一元ログインを実現するサービスです（一元認証・セッション管理・ユーザー管理）。
    • 多くの場合、SSOプロバイダ ＝ IDプロバイダ ＋ セッション管理機能 で、SSOプロバイダは IdP としても機能します。
    • 選び方：用途、予算、統合の容易さ、セキュリティ要件を考慮します。

    個人開発やスタートアップでは Auth0 や AWS Cognito がおすすめです。エンタープライズでは Okta や Microsoft Azure AD が強力です。

    8.理解度チェック

    Q1. IDプロバイダ（IdP）の3つの役割は何ですか？

    ① ユーザー情報の管理（ユーザー名・メールアドレス・パスワード・権限など）、② 認証（パスワードや MFA で本人か確認）、③ 認証情報の発行（トークンや証明書を発行し、他のサービスが「認証済み」と判断できるようにする）です。

    Q2. IDプロバイダとSSOプロバイダの違いを一言で説明してください。

    IDプロバイダは「ユーザーの身元を証明する」サービス、SSOプロバイダは「一度のログインで複数のサービスに入れるようにする」サービスです。多くの場合、SSOプロバイダは IdP の機能にセッション管理（複数サービス間でのログイン状態の共有）を加えたものです。

    Q3. 「共通の入場券」の例えは、SSOプロバイダのどんな性質を表していますか？

    一度入場券を買えば複数の施設に入れて、施設ごとにチケットを買う必要がない、という性質です。SSO では一度ログインすれば、アプリごとにログインし直す必要がありません。

    Q4. AWS を中心に開発している個人開発の Next.js アプリと、Microsoft 365 を使っている大企業の社内システム群では、それぞれ何が候補になりますか？

    前者は AWS Cognito（AWS サービスと統合しやすく、無料枠が充実）、後者は Microsoft Azure AD（Entra ID）（Office 365 と完全統合、条件付きアクセスあり）が候補です。どちらも最終的には予算・統合の容易さ・セキュリティ要件・スケーラビリティ・サポートを比べて決めます。
