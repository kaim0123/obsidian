    モジュール設計解説 — 目次

    Obsidian の「43_モジュール設計」ノートをもとにした解説ページの入口です。コードを「どこで区切り、どうつなぎ、どこに置くか」——モジュール・パッケージ単位の設計を、凝集と結合・分割の仕方・つなぎ方・パッケージ原則・構成と実装・品質と運用まで、全41ページで解説します。

    もとにしたノート：MOC_モジュール設計体系 と、10〜90 の各フォルダのノート

    1.このサイトの読み方

    ページは MOC のフォルダ構成と同じ順番に並んでいます。各ページの下にある「前のページ／次のページ」で順に読み進められ、上部の「モジュール設計解説」からいつでもこの目次に戻れます。どのページも単体で読めるように書いてあるので、気になるテーマから読んでもかまいません。

    43 章の骨格は『Clean Architecture』第4部（コンポーネントの原則）で、そこに Ousterhout『A Philosophy of Software Design』の「深いモジュール」と、Khononov『Balancing Coupling in Software Design』の「結合の強度・距離・変動性」を加えています。凝集・結合・カプセル化の一般論や DDD は ソフトウェア設計解説（42）、レイヤード・ヘキサゴナル・マイクロサービスなどのアーキテクチャスタイルは アーキテクチャ解説（41）が本拠地です。

    はじめて学ぶなら

    まず モジュール設計の全体像 で地図を手に入れ、10 モジュールの基礎 → 20 凝集と結合（20-1・20-2）の順に進むのがおすすめです。

    歴史から理解したいなら

    モジュール設計年表 で、情報隠蔽からモジュラーモノリスまで「分割の軸」がどう変わってきたかを先に押さえます。

    結合を深く学びたいなら

    バランス結合 から 20-4〜20-7 へ。強度・距離・変動性の3つの次元で結合を評価する考え方です。

    おすすめの読む順

    もとの教材（全8部・22章）の学習順です。各フォルダの後半にある「深掘り」ページは、慣れてきてから読み返してもかまいません。

    1. はじめに — 学ぶ理由 → モジュールの基本概念
    2. 設計の土台 — 凝集度 → 結合度 → カプセル化と情報隠蔽
    3. モジュールの切り方 — 分割の基本プロセス → ドメインに基づく設計 → 技術的関心事による分割
    4. モジュールのつなぎ方 — インターフェース → 依存関係の管理 → データの受け渡しと共有
    5. 設計パターンと構造 — レイヤード → ヘキサゴナル → マイクロサービスとモノリス
    6. 品質を保つための実践 — テストしやすさ → 変更に強い設計 → 命名とディレクトリ構成
    7. チーム開発と運用 — チームで設計を守る → モジュール設計の進化
    8. 総合演習 — ケーススタディ → モジュール設計レビュー

    モジュール設計という分野の地図と、その歴史。

    00-1

    モジュール設計の全体像

    区切り・つなぎ・置き場所、骨格になる3冊、扱う範囲、フォルダ構成と読む順、教材の学習順、他章との分担

    モジュール設計年表

    手続き分割、Parnas の情報隠蔽、高凝集・低結合、パッケージ設計原則、DDD、ヘキサゴナル／クリーン、マイクロサービス、モジュラーモノリス、分割軸の進化

    3.10 モジュールの基礎

    モジュールとは何か、なぜ設計するのか、何を隠すのか。

    10-1

    モジュール設計を学ぶ理由

    複雑になるときに起きること、動くコードと育てられるコード、変更の局所化、チーム分担

     10-2

    モジュールの基本概念

    モジュールとは、関数・クラス・パッケージ・サービスとの関係、責務、境界、インターフェースと実装の分離、フラクタルなモジュール化

     10-3

    カプセル化と情報隠蔽

    公開すべきもの・隠すべきもの、内部表現の変更を安全にする、Leaky Abstraction、ディレクトリと言語機能での表現

     10-4

    深いモジュールと浅いモジュール

    コストと利益、情報漏洩、時間的分解、パススルーメソッド、エラーを定義からなくす、レッドフラグ

    4.20 凝集と結合

    モジュールの良し悪しを測る2つのものさしと、結合を3つの次元で評価するバランス結合。

    20-1

    凝集度

    低凝集で起きる問題、凝集の7レベルと機能的凝集、1文説明による分割、チェックリスト

     20-2

    結合度

    密結合の問題、6種類の結合と見分け方、疎結合の原則、生成による結合と DI、疎結合にしすぎるコスト

     20-3

    バランス結合

    結合はなくせない、知識の流れ、統合強度・距離・変動性、バランスの式、改善の優先順位、レビューでの問い

     20-4

    統合強度

    侵入・機能・モデル・契約の4段階、機能結合の3つの度合い、契約結合を作るパターン、コナーセンスとの対応

     20-5

    距離と変動性

    距離の要因、ライフサイクル結合、変動性とサブドメイン、本質的・偶発的・推測される変動性

     20-6

    結合と複雑性

    クネビンの5領域、複雑さ＝認知負荷、線形と複雑な相互作用、局所的・大域的な複雑さ

     20-7

    結合の再均衡化と実践

    変更のベクトル、再均衡化の手順、成長の限界、フラクタルなモジュール性、4つの規模での実践

    5.30 分割の仕方

    どこで区切るか。業務（ドメイン）で分けるか、技術で分けるか。

    30-1

    モジュール分割の基本プロセス

    要件から責務の抽出、名詞と動詞、変化の理由、分割しすぎ・不足の見分け方、60分ワークショップ

     30-2

    ドメインに基づく設計

    技術中心とドメイン中心、ユビキタス言語とモジュール名、集約とトランザクション境界、境界づけられたコンテキスト

     30-3

    技術的関心事による分割

    関心事の分離、3層、横断的関心事（ログ・認証・エラー処理）、インフラとドメインの分離

     30-4

    機能別とレイヤー別

    水平分割と垂直分割、規模による使い分け、機能の境界の見つけ方、公開 API の絞り方、構成の進化パターン

     30-5

    Screaming Architecture

    業務を叫ぶ構成、フレームワークは道具、バックエンド・フロントエンドの構成例、実務的な妥協点

    6.40 つなぎ方

    区切ったモジュールをどうつなぐか。公開面・依存の向き・データの渡し方。

    40-1

    モジュール間インターフェース

    入出力と契約、最小限の公開面、命名、後方互換、所有権と DIP、小さなポート、TypeScript での実現

     40-2

    依存関係の管理

    依存の方向、循環依存の解消、DIP、依存グラフの読み方、Composition Root、DI コンテナとサービスロケーター

     40-3

    データの受け渡しと共有

    ID・DTO・コマンド、DTO・値オブジェクト・エンティティ、共有データベースの落とし穴、イベント連携、整合性

     40-4

    疎結合・DIP・DIの整理

    4つの概念の役割分担、4段階で直す例、処理の流れと依存の方向、インターフェースの置き場所、DI の実例とやりすぎ注意

    7.50 パッケージ原則

    『Clean Architecture』のコンポーネント原則。何をまとめ（凝集）、どうつなぐか（結合）。

    50-1

    パッケージ設計の原則

    REP・CCP・CRP と ADP・SDP・SAP の概観、安定性と抽象度、規模別の実践、npm パッケージでの例

     50-2

    凝集の3原則

    REP・CCP・CRP、テンションダイアグラム、成長段階による重点の移り変わり、症状と対策

     50-3

    結合の3原則と循環依存

    ADP と循環の断ち切り方、SDP と不安定度、SAP と苦痛ゾーン・無駄ゾーン、CI での確かめ方

     50-4

    npmパッケージとモノレポ

    pnpm workspaces、exports によるカプセル化、パッケージの切り方と依存ルール、Turborepo と Nx

    8.60 構成と実装

    名前とディレクトリ、アーキテクチャスタイルのモジュール構成への落とし込み、言語のモジュール機構。

    60-1

    命名とディレクトリ構成

    名前が表す責務、1ディレクトリ＝1モジュール、公開範囲の制限、命名規則とチームでの統一

     60-2

    レイヤードのモジュール構成

    4層の責務、レイヤー違反の典型例、メリット・デメリット、ドメインごとに層を繰り返す構成

     60-3

    ヘキサゴナルのモジュール構成

    コアと外部の分離、ポートの設計（Driving / Driven）、アダプタの役割、テストしやすさ

     60-4

    マイクロサービスとモノリス

    比較、モジュール境界とサービス境界、モジュラーモノリス、いつ分けるか、過剰分割のリスク、モノリスファースト

     60-5

    言語のモジュール機構

    ESM と CommonJS、moduleResolution、paths とサブパスインポート、barrel ファイルの功罪

    9.70 品質と運用

    設計をテスト・変更・チーム・レビュー・自動検査で守り、育てる。

    70-1

    テストしやすいモジュール設計

    テスト容易性、モック・スタブが必要になる理由、副作用の局所化、テストの境界、症状から見る設計の問題

     70-2

    変更に強いモジュール設計

    モジュール単位の OCP、拡張点と YAGNI、後方互換性、リファクタリングしやすい構造、技術的負債

     70-3

    チームで設計を守る

    合意形成、レビューの観点、1ページの設計ルール、静的解析・CI・CODEOWNERS、設計負債の可視化

     70-4

    モジュール設計の進化

    段階的な分割と Strangler Fig、リファクタリングのタイミング、境界の見直し、レガシーと ACL

     70-5

    モジュール設計レビュー

    進め方と参加者、チェックリスト、良い設計・悪い設計の比較、改善提案の4要素

     70-6

    依存ルールの自動検査

    dependency-cruiser、eslint-plugin-boundaries、Nx、ArchUnit 系、既存コードへの段階的導入

    10.80 ケーススタディ

    ここまでの考え方を、小規模 Web アプリと業務システムに当てはめる総合演習。

    80-1

    ケーススタディ

    小規模 Web アプリ（要件・モジュール候補・依存・公開 API）、業務システム（業務ルールの分割・チーム分担・外部連携・設計ミスと修正）

    11.90 付録

    引き直すための用語集・チェックリスト・図解。

    90-1

    用語集と推奨図書

    五十音順の用語集と解説ページへのリンク、推奨書籍、オンラインリソース、学習の順序

     90-2

    チェックリストとアンチパターン

    8分類の総合チェックリスト、変更シナリオ（What-If）、アンチパターン10個の症状と対策

     90-3

    参考図解

    設計の階層、高凝集・低結合、レイヤード、ヘキサゴナル、依存グラフ、データの渡し方、イベント連携、ディレクトリ
