    90 付録

    用語集と推奨図書 — 用語を引き、次に読む本を選ぶ

    この教材（モジュール設計）に出てくる主な用語を五十音順にまとめ、それぞれを詳しく説明しているページへリンクしました。後半では、モジュール設計をさらに深く学ぶための書籍・オンライン資料、関連する章、学ぶ順序を紹介します。読んでいて分からない言葉が出てきたときの「辞書」として使ってください。

    もとにしたノート：90_付録/付録A_用語集 / 付録E_推奨図書

    ひとことで言うと

    用語集は「一言説明」と「解説ページ」のセットです。分からない言葉は一言説明で思い出し、しっかり理解したいときは解説ページを開きます。教材を一通り読んだら、Clean Architecture → DDD → レガシー改善の順で専門書に進むのがおすすめです。

    1.このページで扱うこと

    • 用語集：教材に登場する主要用語の一言説明と、その用語を解説しているページ
    • 推奨図書・学習リソース：書籍、オンライン資料、関連する章
    • 学習の順序：この教材のあと、どの順番で専門書や関連分野へ進むとよいか

    使い方

    用語集の説明は「一言」だけです。意味をしっかり理解したいときは、右の列の「解説ページ」を開いてください。モジュール設計の基本用語は モジュールの基本概念 でまとめて説明しています。

    4.学習の順序（推奨）

    1. 本教材（モジュール設計）を一通り（モジュール設計の全体像から）
    2. Clean Architecture で依存ルールを整理
    3. DDD 書籍 でドメイン分割を深掘り
    4. レガシー書籍 で実プロジェクトに適用
    5. 44_クラス設計・デザインパターン へ

    歴史の流れから読みたい場合は モジュール設計年表 も参考にしてください。

    5.よくある誤解

    誤解1：「用語の一言説明を覚えれば理解したことになる」

    用語集の説明は思い出すための手がかりにすぎません。たとえば「凝集度」は、なぜ高いほうがよいのか、どう見分けるのかまで分かって初めて設計に使えます。解説ページで例と一緒に確認してください。

    誤解2：「いきなり DDD の原典から読むべき」

    原典は内容が濃く、前提知識がないと挫折しやすい本です。学習の順序のとおり、本教材を一通り読み、Clean Architecture で依存ルールを整理してから DDD 書籍へ進むほうが身につきます。

    6.まとめ

    • 用語集は「一言説明」と「解説ページ」のセット。分からない言葉は解説ページで例と一緒に確認する
    • 推奨図書は Clean Architecture・DDD（Evans / Vernon）・レガシーコード改善・Building Microservices が中心
    • オンラインでは martinfowler.com、c4model.com、依存チェックツールのドキュメントが役立つ
    • 本教材 → Clean Architecture → DDD → レガシー → クラス設計 の順で深める
