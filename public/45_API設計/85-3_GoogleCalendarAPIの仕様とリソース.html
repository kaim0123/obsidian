    Google Calendar API の仕様とリソース — 実在の API で用語と構造を読む

    カレンダーの標準仕様 RFC 5545 は抽象的で、そのまま実装に落とすのは大変です。そこで、RFC 5545 を実装に落とし込んだ Google Calendar API を教材にして、ユーザー・カレンダーリスト・カレンダー・イベント・設定・ACL の意味と関係、各リソースの JSON とプロパティ、イベントの拡張フィールド6つを読み解きます（Qiita の4回シリーズの Step1）。

    ひとことで言うと

    Google Calendar API は 「ユーザー → カレンダーリスト → カレンダー → イベント」 という所有の流れに、設定（ユーザーと 1:1） と ACL（カレンダーへの権限付与） が加わった構造です。各リソースは共通して kind・etag・id を持ち、etag で楽観的排他制御を、ACL の scope と role で権限を、recurrence などの組み合わせで繰り返し予定の例外までを表します。

    2.なぜ Google Calendar API を教材にするのか

    カレンダーを開発するなら、インターネットの標準仕様に合わせて作るのが望ましいです。カレンダーの標準仕様は RFC 5545（iCalendar 形式を定めた文書）で定義されていて、開発する上で一度は目を通す必要があります。

    ただし RFC 5545 は抽象的な部分が多く、読んでもピンとこず、そこから実装に落とすのは難しいです。そこで、RFC 5545 を実装に落とし込んだ Google Calendar API を手本にして学びます。本家の API の説明だけでは量が多くてわかりにくいので、1つずつ理解していきます。

    3.用語と関係性

    3.1 用語

    要素説明
    ユーザーGoogle カレンダーを利用する主体。1アカウントにつき1つ
    カレンダーリストユーザーが左側ペインに登録しているカレンダーの一覧。表示・非表示や色・通知設定など、ユーザー固有のメタデータ（付帯情報）を管理する
    カレンダーイベント（予定）を格納するコンテナ。タイムゾーン、説明文、既定の通知設定などを保持する
    イベント単発予定、または繰り返し予定の個別インスタンス（1回分）。開始・終了時刻、参加者、リマインダーなどを含む
    設定ユーザー全体の環境設定（週の開始曜日、既定のリマインダー方法など）。1ユーザーにつき1件
    ACLカレンダーへのアクセス権を表すルール（owner / writer / reader）。ユーザーやグループ単位で付与する。ACL は Access Control List の略

    「カレンダー」と「カレンダーリスト」の違いがポイントです。カレンダー は予定の入れ物そのもので、共有されれば複数のユーザーから同じものが見えます。カレンダーリスト は「自分の画面にそのカレンダーをどう表示するか」という、ユーザーごとの情報です。

    3.2 関係性

    関係意味
    ユーザー → カレンダーリスト1ユーザーが複数のカレンダーリストエントリを持つ
    カレンダーリスト → カレンダー1エントリは1つのカレンダーを参照する
    カレンダー → イベント1カレンダーに複数のイベントが属する
    ユーザー → 設定ユーザーごとに1件の設定情報が紐づく（1:1）
    ユーザー ⇢ ACLユーザーやグループに ACL ルールが複数紐づく（点線）
    ACL ⇢ カレンダー各 ACL ルールが対象カレンダーへのアクセス権を定義する（点線）
    • 実線は 所有 や 1:N の構造的な関係を示します
    • 点線は アクセス権付与 のような「強制ではないが関連する」関係を示します。ACL は「所有」ではなく「権限付与」の関係です

    4.各リソースの JSON とプロパティ

    ここからはリソースごとに JSON を見ていきます。どのリソースも共通して次の3つを持ちます。

    共通プロパティ意味
    kindリソース種別を表す固定文字列（例：calendar#calendar）
    etagバージョンタグ。変更のたびに変わり、変更検出や 楽観的排他制御（更新時に「自分が読んだときから変わっていないか」を確かめ、変わっていたら更新を拒む方式）に使う
    idリソースの一意な識別子

    4.1 カレンダー

    {
  "kind": "calendar#calendar",               // リソース種別: カレンダーリソースを表す固定文字列
  "etag": "\"XpAbC1234yz\"",                // バージョン管理用タグ（例: 変更ごとに自動生成される ETag）
  "id": "primary",                          // カレンダーID（"primary" はメインカレンダー、セカンダリなら "xxx@group.calendar.google.com"）
  "summary": "Team Project Calendar",       // カレンダー名（例: チーム用プロジェクトカレンダー）
  "description": "カンファレンスや締め切りを共有するためのチーム用カレンダーです。",
                                            // 説明文（例: 用途や対象を記載）
  "location": "Tokyo Headquarters",         // 所在地（フリーフォーム、例: 本社所在地）
  "timeZone": "Asia/Tokyo",                 // IANA タイムゾーン名（例: Asia/Tokyo）
  "conferenceProperties": {
    "allowedConferenceSolutionTypes": [
      "hangoutsMeet",   // Google Meet を有効化
      "eventHangout"    // イベントハングアウト（旧 Hangouts）を有効化
    ]
  }
}
    プロパティ型／値例説明
    kindstring "calendar#calendar"リソース種別を示す固定文字列
    etagstring "\"XpAbC1234yz\""現バージョンを示すエンティティタグ（変更検出・楽観的排他制御用）
    idstring "primary"カレンダーの一意識別子（主に API 呼び出し時のキー）
    summarystring "Team Project Calendar"カレンダー名（タイトル）
    descriptionstring "カンファレンスや締め切りを共有するチーム用カレンダー"カレンダーの詳細説明
    locationstring "Tokyo Headquarters"カレンダーの所在地情報（フリーフォーム＝自由記述）
    timeZonestring "Asia/Tokyo"カレンダーの既定のタイムゾーン（IANA 名：Asia/Tokyo のような「地域/都市」形式の標準名）
    conferencePropertiesobject会議リンク機能に関する設定オブジェクト
    └ allowedConferenceSolutionTypesstring[] ["hangoutsMeet","eventHangout"]使用を許可する会議ソリューション（Google Meet など）の種類リスト

    4.2 カレンダーリスト

    {
  "kind": "calendar#calendarListEntry",                // リソース種別：カレンダーリストエントリ
  "etag": "\"LmNoP5678qrs\"",                         // バージョン管理用タグ
  "id": "team-shifts@example.com",                     // カレンダーID（グループカレンダーなど）
  "summary": "Team Shifts",                            // カレンダーリスト上の表示名
  "description": "部署の勤務シフトを管理するカレンダー",   // カレンダーの詳細説明
  "location": "Tokyo Office",                          // 場所
  "timeZone": "Asia/Tokyo",                            // タイムゾーン
  "summaryOverride": "My Shifts",                      // ユーザーが上書きしたカレンダー名
  "colorId": "7",                                      // 色ID（colorsリソース参照）
  "backgroundColor": "#9ae2f1",                        // 背景色
  "foregroundColor": "#000000",                        // 文字色
  "hidden": false,                                     // 非表示フラグ
  "selected": true,                                    // 左ペインで選択中かどうか
  "accessRole": "writer",                              // 自分に付与された権限（owner/writer/reader/...）
  "defaultReminders": [
    {
      "method": "popup",                               // リマインダー方法
      "minutes": 30                                    // イベント開始30分前
    }
  ],
  "notificationSettings": {
    "notifications": [
      {
        "type": "eventCreation",                       // イベント作成通知
        "method": "email"                              // 通知方法
      },
      {
        "type": "eventChange",                         // イベント変更通知
        "method": "popup"                              // 通知方法
      }
    ]
  },
  "primary": false,                                    // プライマリカレンダーかどうか
  "deleted": false,                                    // リストエントリが削除済みかどうか
  "conferenceProperties": {
    "allowedConferenceSolutionTypes": [
      "hangoutsMeet",                                  // Google Meet
      "eventHangout"                                   // イベントハングアウト
    ]
  }
}

    カレンダーの情報に加えて、ユーザーごとの見え方 を表す項目が並びます。

    プロパティ意味
    summaryOverrideユーザーが上書きしたカレンダー名
    colorId・backgroundColor・foregroundColor色 ID（colors リソースを参照）・背景色・文字色
    hidden・selected非表示フラグ・左ペインで選択中かどうか
    accessRole自分に付与された権限（owner / writer / reader など）
    defaultReminders既定のリマインダー（方法と何分前か）
    notificationSettings通知の種類（イベント作成・変更など）と方法
    primary・deletedプライマリ（メイン）カレンダーかどうか・リストエントリが削除済みかどうか

    4.3 設定

    {
  "kind": "calendar#setting",               // リソース種別: 設定リソースを表す固定文字列
  "etag": "\"ZmNoEnEtAg0123\"",             // バージョン管理用タグ（例: 設定変更ごとに変わる ETag）
  "id": "timeZone",                         // 設定キー: ユーザーのタイムゾーンを示す設定 ID
  "value": "Asia/Tokyo"                     // 設定値: IANA タイムゾーン名
}
    プロパティ型／値例説明
    kindstring "calendar#setting"リソース種別を示す固定文字列
    etagstring "\"ZmNoEnEtAg0123\""リソースのバージョンを表す ETag。変更検出や楽観的排他制御に利用
    idstring "timeZone"設定項目を識別するキー（例：autoAddHangouts、weekStart、timeZone）
    valuestring "Asia/Tokyo"設定値。設定 ID によって文字列／数値／JSON 形式などが異なる

    設定は「1つの大きな JSON」ではなく、id（設定キー）と value の組 を1件ずつ持つ形です。

    4.4 ACL

    {
  "kind": "calendar#aclRule",             // リソース種別: ACLルール
  "etag": "\"AbCdEf123456\"",             // バージョン管理用ETag（変更ごとに変わるタグ）
  "id": "rule_123abc",                    // このACLエントリの一意ID
  "scope": {
    "type": "user",                       // 対象タイプ: user (特定ユーザー)
    "value": "alice@example.com"          // 対象ユーザーのメールアドレス
  },
  "role": "writer"                        // 付与する権限: writer (読み書き可)
}
    プロパティ型／値例説明
    kindstring "calendar#aclRule"リソース種別を示す固定文字列
    etagstring "\"AbCdEf123456\""リソースのバージョンを示す ETag
    idstring "rule_123abc"この ACL ルールの一意識別子
    scope.typestring "user"ルール適用対象のタイプ（user / group / domain / default）
    scope.valuestring "alice@example.com"user / group / domain の場合の識別子
    rolestring "writer"付与する権限レベル（owner / writer / reader / …）

    scope.value の詳細

    scope.value は scope.type に応じて次のような形式・意味を持ちます。

    scope.typevalue の形式意味例
    userメールアドレス文字列特定ユーザーを対象alice@example.com
    groupGoogle グループのメール特定グループ（Google グループ）を対象dev-team@example.com
    domainドメイン名（ホスト部のみ）ドメイン内のすべてのユーザーを対象example.com
    default―（省略または空文字）未認証ユーザーを含む全員に公開（公開権）※フィールド自体が返却されない
    • user / group：値は実際に存在するユーザー／グループのメールアドレスである必要があります。グループは G Suite／Google Workspace のグループを指します
    • domain：自社ドメイン全体にアクセスを許可したいときに使います。たとえば example.com とすると @example.com のユーザー全員が対象です
    • default：認証不要でカレンダーを公開したい（全世界に公開する）場合に使います。value フィールドは返却されず、scope オブジェクトは { "type": "default" } だけになります

    「誰に（scope）」「どの権限を（role）」の組で表すのが ACL の基本形です。RBAC など他の方式との比較は 73章：RBAC・ABAC・ACLの使い分け を参照してください。

    5.イベントの拡張フィールド6つ

    イベントのプロパティのうち、recurrence・recurringEventId・originalStartTime・iCalUID・transparency・visibility の6つは、カレンダーらしい難しさを持つ項目です。1つずつ詳しく見ます。

    5.1 recurrence（繰り返しルール）

    • 型：string[]
    • 例：["RRULE:FREQ=WEEKLY;BYDAY=MO,WE,FR"]（毎週 月・水・金）
    • 説明：iCalendar 標準の繰り返しルールを表す文字列の配列です
      • RRULE:（必須）で繰り返しの頻度や曜日を指定します
      • EXDATE: で除外日、RDATE: で追加日を指定できます
    • 用途：毎週○曜日や毎月○日などの繰り返し予定を定義し、events.instances メソッドで個々のインスタンス（1回分ずつの予定）を取得します

    5.2 recurringEventId（シリーズの親の id）

    • 型：string
    • 例："evt_master_678"
    • 説明：繰り返しシリーズのマスターイベント（元のイベント）の id です。このフィールドが存在する場合、そのイベントは 例外インスタンス（時間変更やキャンセルされた回）であることを示します
    • 用途：例外インスタンスをマスターイベントと紐づけて管理するために使います

    5.3 originalStartTime（例外の元の開始時刻）

    • 型：object
    {
  "dateTime": "2025-05-20T09:00:00Z",
  "timeZone": "UTC"
}
    • 説明：例外インスタンスの「もともとの開始時刻」を保持するオブジェクトです
    • 用途：変更前の予定日時を把握したいときに使います。UI での表示や履歴の記録にも役立ちます

    5.4 iCalUID（外部カレンダーと共通の ID）

    • 型：string（例："abcd12345@google.com"）
    • 説明：iCalendar 標準仕様に基づく UID です。Google Calendar がイベントを外部カレンダーと同期する際に使われます
    • 用途：Outlook や Apple カレンダーなどとのイベント同期で、一貫性を保つために使われます

    5.5 transparency（予定ありか空きか）

    • 型：string
    "opaque"       // 予定あり（ブロック）
"transparent"  // 空き時間扱い
    • 説明：Free/Busy 情報（その時間が空いているか埋まっているかの情報）における、ブロック状態の制御設定です
    • 用途：会議のスケジュール候補を表示する際に、他の予定と重ならない時間帯を探すロジックで使われます

    5.6 visibility（公開レベル）

    • 型：string
    "default"      // カレンダー既定に従う
"public"       // 誰でも詳細を閲覧可
"private"      // 詳細を隠して「予定あり」のみ表示
"confidential" // より制限された公開レベル
    • 説明：イベントの公開レベルを制御するための設定です
    • 用途：他ユーザーにどこまで情報を見せるか（または見せないか）を制御し、機密性を保ちつつ共有できます

    6.よくある誤解

    誤解1：「カレンダーとカレンダーリストは同じもの」

    カレンダーは予定の入れ物そのもの（タイムゾーンや説明を持つ）で、カレンダーリストは「あるユーザーが自分の画面でそれをどう見るか」（表示名の上書き・色・表示/非表示・自分の権限）です。1つの共有カレンダーに対して、ユーザーの数だけカレンダーリストのエントリがあります。

    誤解2：「ACL はカレンダーの持ち主を表す」

    ACL は「所有」ではなく 権限付与 の関係です。scope（user・group・domain・default）に role（owner・writer・reader）を与えるルールの集まりで、だから関係図では点線で描かれます。

    誤解3：「繰り返し予定は、全部の回を1件ずつ保存している」

    基本はマスターイベントに recurrence（RRULE など）を1つ持たせるだけです。個々の回は events.instances で展開して取得し、時間変更やキャンセルがあった回だけが recurringEventId・originalStartTime を持つ例外インスタンスになります。

    7.まとめ

    • 抽象的な RFC 5545 を学ぶかわりに、それを実装した Google Calendar API を手本にする
    • 「ユーザー → カレンダーリスト → カレンダー → イベント」と、設定（1:1）・ACL（権限付与）の関係をまず押さえる
    • 各リソースは kind・etag・id を共通で持ち、etag による楽観的排他制御が設計上のポイント
    • ACL は scope（user / group / domain / default）と role（owner / writer / reader）の組
    • 繰り返し予定は recurrence・recurringEventId・originalStartTime の組み合わせで例外まで表現する。iCalUID は外部同期、transparency は空き時間探し、visibility は公開範囲に使う

    次は、この仕様をもとにテーブルを作り、API を実装する Google Calendar API を実装する です。
