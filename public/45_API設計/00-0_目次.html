    API設計解説 — 目次

    Obsidian の「45_API設計」ノートをもとにした解説ページの入口です。Web API を「使いやすく・変更しやすく・堅牢に」設計する方法を、APIの基礎・HTTP・リソース設計・実践的な設計・互換性・セキュリティ・ドキュメントとテスト・APIスタイル・ケーススタディまで、全42ページで解説します。

    もとにしたノート：MOC_API設計体系 と、10〜90 の各フォルダのノート

    1.このサイトの読み方

    ページは MOC のフォルダ構成と同じ順番に並んでいます。各ページの下にある「前のページ／次のページ」で順に読み進められ、上部の「API設計解説」からいつでもこの目次に戻れます。どのページも単体で読めるように書いてあるので、気になるテーマから読んでもかまいません。

    45 章の骨格は『Web API: The Good Parts』の流れ（エンドポイント → レスポンス → HTTP を活かす → 変更しやすく → 堅牢に）です。そこに Microsoft・Zalando・Google の API ガイドラインの項目（エラー形式・ページネーション・長時間処理・バージョニング）と、REST 以外の API スタイル（GraphQL・gRPC・Webhook）を加えています。認証方式そのものは 認証認可（73）、Cookie・トークンは セッション管理（74）、CORS・XSS・CSRF は Web脆弱性対策（72）が本拠地です。

    はじめて学ぶなら

    まず API設計の全体像 で地図を手に入れ、APIとは → 20 HTTPの土台 → 30 リソース設計の順に進むのがおすすめです。

    すぐ設計に使いたいなら

    URLとリソースの設計・エラー設計・チェックリスト を手元に置いて使います。

    REST 以外も知りたいなら

    REST以外のAPIスタイル から 80-2〜80-4 の GraphQL へ進みます。

    API設計の全体像

    API設計を一言で、対象・目的・前提、設計階層の中の位置、8つの基本テーマの関係と要点、学習のすすめ方、フォルダごとのページ一覧、他章が本拠地のテーマ

    3.10 APIの基礎

    APIとは何か、何を目指して設計するか。

    10-1

    APIとは

    APIの定義（窓口・約束事）、Web・ライブラリ・OS API、内部APIと外部公開API、システム統合とAPI連携の違い、疎結合と情報隠蔽、APIエコノミー

     10-2

    API設計を学ぶ理由とゴール

    「動くAPI」と「使われ続けるAPI」、設計がないと起きること、使いやすさ・予測可能性・一貫性、長く使える形、安全な窓口、8テーマの地図

     10-3

    一貫性

    一貫性がないときの問題、揃えるべき項目（命名・日時・ID・レスポンス形式・真偽値）、APIガイドラインを1枚に、チェックリスト

     10-4

    API設計の原則

    予測可能性、最小の驚き、契約としてのAPI、組み立て部品としてのAPI、REST・GraphQL・gRPCの比較、設計プロセスとライフサイクル、ベストプラクティス

    4.20 HTTPの土台

    Web API が乗っている通信の約束事。

    20-1

    HTTPの基本

    リクエストとレスポンスの往復、メソッド・ヘッダー・ステータスコード、URLの読み方、ステートレス、HTTPS、アプリ間連携の4つの約束事、HTTPとREST

     20-2

    リクエストとレスポンス

    構成要素、リクエストライン、ヘッダーの役割、ボディとJSON、レスポンスの読み方、エラー処理の基本、curl・fetch・開発者ツールでの観察

     20-3

    ステータスコード

    2xx・4xx・5xx の大分類、よく使う11コード、原因ごとの選び方、ステータスとエラーボディの役割分担、チェックリスト

     20-4

    JSONとデータ形式

    JSONの型と入れ子、XML・CSV・YAML との比較、JSON Schema によるバリデーション、データ形式選択のポイント

    5.30 リソース設計

    REST の考え方で、URL・メソッド・ボディを設計する。

    30-1

    RESTの考え方

    RESTとは、リソースと表現、4大原則、URLは名詞で操作はHTTPメソッド、リトライと冪等性、RESTの利点と限界、RPC風・GraphQLとの関係

     30-2

    URLとリソースの設計

    リソースの洗い出し、コレクションと単一リソース、ネストしたリソース、命名規則、よくある URL 設計の間違い

     30-3

    HTTPメソッドと操作の表現

    GET・POST・PUT・PATCH・DELETE、PUT と PATCH の違い、冪等性と安全性、CRUD の典型パターン、GET に副作用を持たせない理由

     30-4

    ボディの設計

    JSON を基本とする理由、data/meta のラップ形式、snake_case と camelCase、日時・ID・金額の型と形式、作成・更新リクエスト

     30-5

    APIとドメイン設計

    ドメインの名詞とリソース、ユビキタス言語、集約と API 境界、内部モデルを晒さない DTO、導出結果か生データか

    6.40 実践的な設計

    エラー・一覧・検索など、実務で必ず出てくる設計。

    40-1

    エラー設計

    エラー設計の目的、機械可読な code、message とフィールド単位の details、request_id とログ調査、チェックリスト

     40-2

    ページネーション・フィルタ・ソート

    オフセット方式、カーソル方式、フィルタとソートのクエリ設計、方式の選び方と limit 上限・total・ソート順の固定

     40-3

    検索と複合操作

    検索 API、バルク操作（部分成功・上限・冪等性）、非同期ジョブ API（202 Accepted）、ファイルアップロード、動詞的操作の扱い方

    7.50 互換性と進化

    公開した API を壊さずに育てる。

    50-1

    バージョニング

    URLパス・ヘッダ・クエリの3方式、選び方とルール例、Deprecation と Sunset の告知、CHANGELOG の書き方

     50-2

    後方互換性

    安全な変更と破壊的変更、バージョンアップの判断、内部・パートナー・公開APIでの方針の違い

     50-3

    APIの進化と運用

    完璧を目指さない進め方、利用状況の指標、request_id による調査、レガシーAPIの段階的な置き換え、廃止と移行支援

     50-4

    発展性のあるAPI開発

    単純なことをかんたんにできるAPIから始める、動かしながら育てる、利用側との共同作業、中核APIのセット、複合サービスとBFF

    8.60 セキュリティと信頼性

    API として守るべきこと（認証方式・脆弱性の詳細は 72〜74 章）。

    60-1

    認証

    API Key・Bearer Token・Session Cookie・Basic 認証、OAuth 2.0 / OIDC の概要、認証情報をURLに載せない理由、401 の返し方、多層防御

     60-2

    認可

    401 と 403 の違い、リソース所有者チェック（403 と 404 の使い分け）、RBAC とスコープ、最小権限の原則

     60-3

    レート制限と冪等性

    429・Retry-After、冪等とは、二重処理の3つの入り口、Idempotency-Key、Webhook・キューの受け取り方、一意制約で先に席を取る

     60-4

    APIセキュリティの全体像

    API を守る7つの手法、レート制限の単位、CORS、SQL／NoSQLインジェクション、WAF、VPN、CSRF、XSS、多層防御

    9.70 ドキュメントとテスト

    設計を書き残し、確かめ、チームで守る。

    70-1

    OpenAPIとドキュメント

    ドキュメントが設計の一部である理由、OpenAPI の基本、スキーマ定義とレビュー、サンプルの書き方、実装とのズレを防ぐ方法

     70-2

    APIのテスト

    契約テスト、正常系・異常系・境界値・冪等性、テストピラミッド、モックサーバー、回帰テストと破壊的変更の検知

     70-3

    チームでAPI設計を守る

    API設計ガイドライン、設計レビューとコードレビューの違い、Spectral・openapi-diff による自動チェック、クライアントとの合意形成

     70-4

    API設計レビューの実践

    レビューの進め方と役割、チェックリスト、良いAPI・悪いAPIの比較、改善提案の書き方、次の学習ステップ

    10.80 APIスタイル

    REST 以外の選択肢と、GraphQL の入門。

    80-1

    REST以外のAPIスタイル

    GraphQL、RPC風API、Webhook、gRPC、WebSocket、スタイルの選び方と混在のリスク

     80-2

    GraphQLの基本

    GraphQLとは、オーバーフェッチとアンダーフェッチ、スキーマとスカラー型、クエリ・ミューテーション・サブスクリプション、変数・エイリアス・フラグメント

     80-3

    RESTとGraphQLの違い

    基本的な違い、具体例での比較、エンドポイントとバージョニング、エラーハンドリング、キャッシュ、ベストプラクティス、使い分け

     80-4

    GraphQLをはじめよう

    ブログアプリの実践例、サーバーとクライアントの選択肢、Apollo Server と React のハンズオン、FAQ、次のステップ
