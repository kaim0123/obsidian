    ひとことで言うと

    API のリソース構造（ユーザー・カレンダー・イベント・ACL）は、ほぼそのままテーブルに落とせます。実装では 本家のレスポンスを見て、必要な項目だけに絞った自前のレスポンスを設計 し、DB に無い項目はテーブル追加かサービス層のデフォルト値で補います。時間は tstzrange で持ち、範囲は [start, end)（右端排他）で統一、取り出すときは lower()／upper() で分解します。

    2.テーブル設計（Step2）

    Step1 で学んだ API の仕様をもとに、テーブルを設計します。設計図は dbdiagram（テキストで ER 図を描けるツール）で作っています。

    テーブル役割
    usersユーザー（email は一意、locale の既定は Asia/Tokyo）
    user_settings既定リマインダー・勤務時間・カラーテーマ・通知設定（jsonb）
    calendarsカレンダー（owner_id・summary・color・visibility）

    ① カレンダーにイベントを登録する：tstzrange('開始', '終了') で時間範囲を入れます。

    開区間・閉区間の話が大事

    範囲を指定するときは、一般的に [start, end)（右端排他） にします。開始時刻は含み、終了時刻は含まない、という意味です。記事の筆者は「今回、間違って開区間で入れています。最初は気づかないが、後々痛い目を見るので気をつけましょう」と注意しています（開区間・閉区間の解説は筆者の別記事にあります）。

    ② 指定期間中のイベントを一覧取得する：範囲の重なり演算子 &&（2つの範囲が少しでも重なれば真）で絞り込みます。

WHERE calendar_id = 1
  AND time_range && tstzrange('2025-05-01 00:00:00+09', '2025-05-31 23:59:59+09');

    補足：PostgreSQL の範囲の書き方

    PostgreSQL の tstzrange(a, b) は、3つ目の引数を省略すると '[)'（右端排他）になります。出力の ["…","…") の [ と ) がその印です。一方、検索条件の '2025-05-31 23:59:59+09' のように「月末の最後の1秒」で終わりを書くと、23:59:59 から 24:00 までのすき間が漏れます。終わりは翌月1日 0:00 にして右端排他で書く（tstzrange('2025-05-01 00:00:00+09', '2025-06-01 00:00:00+09', '[)')）と、境界の取りこぼしがなくなります。

    ③ 繰り返しイベントを登録する（毎週・毎月など）：RRULE:FREQ=WEEKLY;BYDAY=MO（毎週月曜）を recurrence_rule に入れます。RRULE は難しいので、筆者は別途記事にして理解を深めたいとしています。

    5.4 実装の構成（層ごとの役割）

    層内容
    mainEcho を起動し、環境変数から DSN（DB への接続文字列）を組んで Bun で PostgreSQL に接続。repository → service → controller を組み立ててルートを登録する
    controllerGET /calendars を登録。クエリの user_id を DTO にバインドし、0 なら 400。service の結果を CalendarResponse DTO に変換して 200 で返す
    dtoCalendarResponse・ReminderResponse・NotificationResponse などレスポンス用の構造体と ListCalendarsRequest。DTO（Data Transfer Object）は層の間でデータを受け渡すためだけの入れ物
    serviceカレンダー一覧と、そのユーザーの user_settings を取得し、既定リマインダー・通知設定を設定から埋める。会議プロパティや hidden=false・selected=true・accessRole=owner・primary=true・deleted=false は固定のデフォルト値
    repositoryBun の NewSelect() で calendars 全件、user_settings を user_id で取得
    modelCalendar（DB に無い項目は bun:"-"）と UserSettings（jsonb 列をマップや構造体で受ける）

func (c *CalendarController) ListCalendars(ctx echo.Context) error {
    // リクエストパラメータのバインディング
    req := new(dto.ListCalendarsRequest)
    if err := ctx.Bind(req); err != nil {
        return ctx.JSON(http.StatusBadRequest, map[string]string{"error": "invalid request parameters"})
    }

    // バリデーション
    if req.UserID == 0 {
        return ctx.JSON(http.StatusBadRequest, map[string]string{"error": "user_id is required"})
    }

    // サービス層の呼び出し
    calendars, err := c.service.ListCalendars(ctx.Request().Context(), req.UserID)
    if err != nil {
        return ctx.JSON(http.StatusInternalServerError, map[string]string{"error": err.Error()})
    }

    // レスポンスの変換
    response := make([]dto.CalendarResponse, len(calendars))
    for i, calendar := range calendars {
        response[i] = convertToCalendarResponse(calendar)
    }

    return ctx.JSON(http.StatusOK, response)
}

// convertToCalendarResponse converts a model.Calendar to CalendarResponse
func convertToCalendarResponse(calendar *model.Calendar) dto.CalendarResponse {
    reminders := make([]dto.ReminderResponse, len(calendar.DefaultReminders))
    for i, r := range calendar.DefaultReminders {
        reminders[i] = dto.ReminderResponse{
            Method:  r.Method,
            Minutes: r.Minutes,
        }
    }

    notifications := make([]dto.NotificationResponse, len(calendar.NotificationSettings.Notifications))
    for i, n := range calendar.NotificationSettings.Notifications {
        notifications[i] = dto.NotificationResponse{
            Type:    n.Type,
            Method:  n.Method,
            Enabled: n.Enabled,
        }
    }

    return dto.CalendarResponse{
        ID:                   calendar.ID,
        Summary:              calendar.Summary,
        Description:          calendar.Description,
        Color:                calendar.Color,
        Visibility:           calendar.Visibility,
        SummaryOverride:      calendar.SummaryOverride,
        Hidden:               calendar.Hidden,
        Selected:             calendar.Selected,
        AccessRole:           calendar.AccessRole,
        DefaultReminders:     reminders,
        NotificationSettings: dto.NotificationSettingsResponse{Notifications: notifications},
        Primary:              calendar.Primary,
        Deleted:              calendar.Deleted,
        ConferenceProperties: dto.ConferenceResponse{
            AllowedConferenceSolutionTypes: calendar.ConferenceProperties.AllowedConferenceSolutionTypes,
        },
    }
}

    settingsRepo repository.UserSettingsRepository
}

func NewCalendarService(
    calendarRepo repository.CalendarRepository,
    settingsRepo repository.UserSettingsRepository,
) CalendarService {
    return &calendarService{
        calendarRepo: calendarRepo,
        settingsRepo: settingsRepo,
    }
}

func (s *calendarService) ListCalendars(ctx context.Context, userID int64) ([]*model.Calendar, error) {
    calendars, err := s.calendarRepo.List(ctx)
    if err != nil {
        return nil, err
    }

    // ユーザー設定の取得
    settings, err := s.settingsRepo.GetByUserID(ctx, userID)
    if err != nil {
        return nil, err
    }

    // レスポンスデータの整形
    for _, calendar := range calendars {
        // ユーザー設定からデフォルトのリマインダー設定を取得
        reminders := make([]model.Reminder, 0)
        for method, minutes := range settings.DefaultReminders {
            reminders = append(reminders, model.Reminder{
                Method:  method,
                Minutes: minutes,
            })
        }
        calendar.DefaultReminders = reminders

        // ユーザー設定から通知設定を取得
        calendar.NotificationSettings = settings.NotificationSettings

        // 会議プロパティ
        calendar.ConferenceProperties = model.ConferenceProperties{
            AllowedConferenceSolutionTypes: []string{"hangoutsMeet", "eventHangout"},
        }

        // その他のデフォルト値
        calendar.Hidden = false
        calendar.Selected = true
        calendar.AccessRole = "owner"
        calendar.Primary = true
        calendar.Deleted = false
    }

    return calendars, nil
}

// ConvertToEventsResponse converts a calendar and its events to ListEventsResponse
func ConvertToEventsResponse(calendar *model.Calendar, events []*model.CalendarEvent) ListEventsResponse {
    items := make([]EventResponse, len(events))
    for i, event := range events {
        // デフォルト値を設定
        status := "confirmed"
        if event.Status != "" {
            status = event.Status
        }

        transparency := "opaque"
        if event.Transparency != "" {
            transparency = event.Transparency
        }

        // オーガナイザー情報が空の場合のデフォルト値
        organizerEmail := "system@example.com"
        organizerName := "System"
        if event.OrganizerEmail != "" {
            organizerEmail = event.OrganizerEmail
            organizerName = event.OrganizerName
        }

        items[i] = EventResponse{
            ID:          event.EventID,
            Status:      status,
            Summary:     event.EventSummary,
            Description: event.EventDesc,
            Start: TimeInfo{
                DateTime: event.StartTime.Format(time.RFC3339),
            },
            End: TimeInfo{
                DateTime: event.EndTime.Format(time.RFC3339),
            },
            Location: event.Location,
            Creator: Person{
                Email:       organizerEmail,
                DisplayName: organizerName,
            },
            Organizer: Person{
                Email:       organizerEmail,
                DisplayName: organizerName,
            },
            Transparency: transparency,
        }
    }

    // カレンダーのアクセス権限が空の場合のデフォルト値
    accessRole := "reader"
    if calendar.AccessRole != "" {
        accessRole = calendar.AccessRole
    }

    return ListEventsResponse{
        CalendarID:  calendar.ID,
        Summary:     calendar.Summary,
        Description: calendar.Description,
        AccessRole:  accessRole,
        Items:       items,
    }
}

    List(ctx context.Context, calendarID int64) ([]*model.CalendarEvent, error)

type eventRepository struct {
    db *bun.DB
}

func NewEventRepository(db *bun.DB) EventRepository {
    return &eventRepository{db: db}
}

func (r *eventRepository) List(ctx context.Context, calendarID int64) ([]*model.CalendarEvent, error) {
    var events []*model.CalendarEvent
    accessRoleCase := fmt.Sprintf("CASE WHEN c.owner_id = %d THEN 'owner' ELSE 'reader' END AS access_role", calendarID)

    err := r.db.NewSelect().
        TableExpr("calendars AS c").
        ColumnExpr("c.id AS calendar_id").
        ColumnExpr("c.summary").
        ColumnExpr("c.description").
        ColumnExpr(accessRoleCase).
        ColumnExpr("e.id AS event_id").
        ColumnExpr("e.status").
        ColumnExpr("e.title AS summary").
        ColumnExpr("e.description").
        ColumnExpr("e.location").
        ColumnExpr("lower(e.time_range) AS start_time").
        ColumnExpr("upper(e.time_range) AS end_time").
        ColumnExpr("u.email AS organizer_email").
        ColumnExpr("u.display_name AS organizer_name").
        ColumnExpr("e.transparency").
        Join("LEFT JOIN events e ON e.calendar_id = c.id").
        Join("LEFT JOIN users u ON u.id = e.organizer_id").
        Where("c.id = ?", calendarID).
        Order("start_time ASC").
        Scan(ctx, &events)
    return events, err
}

    ここが重要：範囲型は lower()／upper() で分解する

    ColumnExpr("lower(e.time_range) AS start_time").
ColumnExpr("upper(e.time_range) AS end_time").

    notificationSettings.notifications が nullseed の {"email": true} が構造体の形（notifications 配列）と合わない保存する JSON の形とモデルの形をそろえる。空なら [] を返す（ボディの設計）

    8.よくある誤解

    誤解1：「本家（Google）のレスポンスを、そのまま全部まねすべき」

    本家は世界中の多様な利用者に向けて、汎用性とパフォーマンス（差分同期・ページネーションなど）を考えて作られています。自分のアプリには重すぎることが多いので、本家を参考にしつつ、必要な項目だけに絞った自前のレスポンスを設計 するのが現実的です。この記事でも kind・etag・nextPageToken・nextSyncToken・htmlLink などを外しています。

    誤解2：「時間の範囲は、終わりも含めて [start, end] で持てばわかりやすい」

    終わりを含めると、10:00〜11:00 と 11:00〜12:00 の予定が 11:00 で「重なる」と判定されてしまいます。[start, end)（右端排他） で統一すれば、連続する予定が重ならず、すき間もできません。Google Calendar の終日イベントの end.date が翌日になるのも同じ考え方です。

    誤解3：「DB に列が無い項目はレスポンスに出せない」

    DB に無い項目は、テーブルに列を追加する（Step3 の ALTER TABLE）か、サービス層でデフォルト値を入れる（hidden=false、transparency=opaque など）かで補えます。どちらにするかは、その値がユーザーごとに変わるかどうかで決めます。

    9.まとめ

    • API のリソース構造（ユーザー・カレンダー・イベント・ACL）は、ほぼそのままテーブルに落とし込める
    • 時間は tstzrange、重なり判定は &&、範囲は右端排他 [start, end) で統一する。繰り返しは RRULE ＋自己参照（recurring_event_id）で表す
    • 本家のレスポンスを見て、ページネーション・同期トークンなどを外した必要最低限の形にする
    • DB に無い項目は、テーブル追加かサービス層のデフォルト値で補う
    • controller／service／repository／model に分けて責務を整理し、DTO を層ごとに分ける。空値のデフォルトは変換処理で補う
    • 範囲型は lower()／upper() で開始・終了に分解する
