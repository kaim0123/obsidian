    90 付録

    用語集と推奨図書 — 用語を引き、次に読む資料を選ぶ

    この教材（API設計）に出てくる主な用語を五十音順にまとめ、それぞれを詳しく説明しているページへリンクしました。後半では、API設計をさらに深く学ぶための書籍・オンライン資料・関連ノートと、おすすめの学習の順序を紹介します。読んでいて分からない言葉が出てきたときの「辞書」として使ってください。

    もとにしたノート：90_付録/付録A_用語集 / 付録G_推奨図書

    ひとことで言うと

    用語集は「一言説明」と「解説ページ」のセットです。分からない言葉は一言説明で思い出し、しっかり理解したいときは解説ページを開きます。本で深めるなら、HTTP の基礎 → Web API: The Good Parts → OpenAPI で手を動かす → API Design Patterns の順に進むと、この教材の内容とつながりやすくなります。

    1.このページで扱うこと

    • 用語集：教材に登場する API 設計の主要用語の一言説明と、その用語を解説しているページ
    • 推奨図書・学習リソース：書籍、オンラインリソース、関連するノート（教材）
    • 学習の順序：初心者がどの順で資料に触れると理解が積み上がりやすいか

    使い方

    用語集の説明は「一言」だけです。意味をしっかり理解したいときは、右の列の「解説ページ」を開いてください。認証・セッション・Web の脆弱性まわりの用語は、それぞれ 認証認可（73章）、セッション管理（74章）、Web脆弱性対策（72章） でも詳しく扱っています。

    4.学習の順序（推奨）

    まずこの教材で HTTP と API の全体像をつかみ、そのあと本や仕様で深めていく順序です。

    1. この教材の 10 APIの基礎・20 HTTPの土台 で、HTTP と API の全体像をつかむ
    2. Web API: The Good Parts で REST の勘所を押さえる
    3. OpenAPI で手を動かし、ドキュメント駆動（仕様を先に書いてから作る進め方）を体験する（OpenAPIとドキュメント、OpenAPI記述例）
    4. API Design Patterns で実務のパターンを蓄積する
    5. ケーススタディ（TODO APIのケーススタディ ほか）で通しの設計を体験し、クラス設計（44章） へ進む

    5.よくある誤解

    誤解1：「用語の一言説明を覚えれば理解したことになる」

    一言説明は思い出すための手がかりです。たとえば「冪等性」は、どのメソッドが冪等で、なぜ決済などで冪等性キーが必要になるのかまで分かって初めて使えます。説明がピンとこない用語は、解説ページを開いて例と一緒に確認してください。

    誤解2：「いきなり分厚いパターン本や仕様書から読むべき」

    推奨の順序では、HTTP と API の全体像 → REST の勘所 → OpenAPI で手を動かす → パターン集、と土台から積み上げます。HTTP のステータスコードやメソッドの意味があいまいなままパターンだけ覚えても、使いどころが分かりません。

    6.まとめ

    • 用語集は「一言説明」で思い出し、「解説ページ」で理解を深める辞書として使う
    • 土台は HTTP（HTTP の教科書・MDN）、REST の勘所は Web API: The Good Parts、パターンは API Design Patterns・RESTful Web APIs、認可は OAuth 2 in Action、進化と互換性は Building Microservices
    • 仕様・標準は OpenAPI Specification と RFC 9457、実務ルールの例は Microsoft・Zalando のガイドライン
    • この教材 → The Good Parts → OpenAPI → API Design Patterns → ケーススタディ → クラス設計 の順に進む
